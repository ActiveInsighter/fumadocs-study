# 栈与队列总结

这一模块从最基础的：

```text
Stack = LIFO
Queue = FIFO
```

一路扩展到了：

- 容器适配器；
- 栈与队列互相模拟；
- 括号匹配；
- 字符串消除；
- 后缀表达式求值；
- 单调队列；
- 优先队列；
- Top K。

真正需要形成的能力不是背 API，而是：

> **根据“元素应该以什么顺序被访问”来选择数据结构。**

---

# 1. 栈与队列的核心区别

栈：

```text
后进先出
Last In, First Out
```

队列：

```text
先进先出
First In, First Out
```

如果依次加入：

```text
1, 2, 3
```

栈取出：

```text
3, 2, 1
```

队列取出：

```text
1, 2, 3
```

所以两者本质上是：

> **对同一批元素施加不同的访问顺序约束。**

---

# 2. 为什么说 Stack / Queue 是抽象数据类型

学习栈和队列时，很容易把它们想成：

```text
一种具体数组
一种具体链表
```

但真正更准确的是：

> 栈与队列描述的是“允许哪些操作”，并不强制唯一底层实现。

例如栈只要求：

```text
push
pop
top
```

它可以由：

- 数组；
- 动态数组；
- deque；
- 链表；

实现。

所以“栈”首先是一种：

```text
访问规则
```

而不是某一种固定内存布局。

---

# 3. C++ 中的 stack / queue 为什么叫容器适配器

C++：

```cpp
std::stack
std::queue
```

并不是直接定义一种新的底层存储结构。

它们会在已有容器上：

```text
限制接口
```

例如底层 `deque` 原本支持：

```text
头部插入
尾部插入
头部删除
尾部删除
```

包装成 `stack` 后，只开放：

```text
栈顶相关操作
```

这种设计叫：

> **Container Adaptor**

默认底层通常使用：

```cpp
deque
```

---

# 4. 一个常见面试陷阱：栈内存一定连续吗

答案：

> 不一定。

因为栈只是抽象接口。

如果底层使用：

```cpp
vector
```

元素通常连续。

如果底层使用：

```cpp
deque
```

就不能简单认为所有元素在一整块连续内存中。

所以：

```text
“栈的元素是否连续”
```

取决于底层容器，而不是“Stack”这个抽象本身。

---

# 5. 为什么 stack 不提供普通迭代器

栈要求：

```text
只能操作 top
```

如果允许：

```text
任意访问中间元素
```

就破坏了栈的抽象。

因此即使底层容器支持迭代，`std::stack` 也会故意隐藏。

这体现了一个重要设计原则：

> **抽象数据类型不仅提供能力，也主动限制不应该使用的能力。**

# 6. 第一类题：数据结构模拟

本模块首先练习：

```text
用栈实现队列
用队列实现栈
```

这两题不是工程上的推荐实现，而是在强迫我们理解：

```text
LIFO
和
FIFO
```

之间究竟如何转换。

---

# 7. 用栈实现队列：两次反转

使用：

```text
stackIn
stackOut
```

新元素进入：

```text
stackIn
```

需要队头时，如果 `stackOut` 为空，就把 `stackIn` 全部倒过去。

例如：

```text
输入顺序：
1 2 3
```

进入 stackIn：

```text
3 2 1
```

倒进 stackOut：

```text
1 2 3
```

两次 LIFO 反转后恢复 FIFO。

核心规则：

> **stackOut 不为空时，绝对不要再搬 stackIn。**

因为 output 栈中的元素一定更早进入队列。

---

# 8. 双栈队列为什么是均摊 O(1)

某一次 `pop` 可能需要把很多元素：

```text
stackIn -> stackOut
```

看起来是：

$$
O(n)
$$

但每个元素一生最多：

1. 入 `stackIn` 一次；
2. 从 `stackIn` 出一次；
3. 入 `stackOut` 一次；
4. 从 `stackOut` 出一次。

每个元素只承担常数次操作。

所以一系列操作总成本：

$$
O(n)
$$

均摊到每次：

$$
O(1)
$$

这是“均摊复杂度”的经典例子。

---

# 9. 用队列实现栈：循环旋转

一个队列就够。

每次 push 新元素：

```text
先入队尾
然后把前面的所有旧元素
依次移到队尾
```

于是新元素最终来到：

```text
queue.front()
```

这样：

```text
front = stack.top
```

从 front 到 back 的顺序始终等于：

```text
栈顶 -> 栈底
```

核心是维护这个不变量。

---

# 10. 模拟题真正训练什么

这两题的核心不是：

```text
会不会写 push / pop
```

而是：

> **能不能通过有限接口重新组织元素访问顺序。**

这是学习抽象数据类型最直接的方法之一。

---

# 11. 第二类题：匹配问题

典型：

```text
有效的括号
```

为什么用栈？

因为嵌套结构满足：

> 最后打开的结构必须最先关闭。

例如：

```text
([{}])
```

闭合顺序：

```text
{
[
(
```

对应：

```text
LIFO
```

---

# 12. 有效括号的三类失败情况

必须完整理解：

### 左括号太多

扫描结束：

```text
stack 非空
```

### 右括号太多

出现右括号时：

```text
stack 已经空
```

### 类型错误

当前右括号与：

```text
最近未闭合左括号
```

不匹配。

---

# 13. 压“期望右括号”的技巧

遇到：

```text
(
```

不要存 `(`，可以直接存：

```text
)
```

遇到：

```text
[
```

存：

```text
]
```

于是右括号到来时只需要：

```text
当前字符 == 栈顶期望？
```

这种思维很值得推广：

> **栈里不一定保存过去发生了什么，也可以保存未来应该发生什么。**

---

# 14. 栈为什么适合系统中的嵌套结构

常见真实应用：

- 函数调用；
- 递归；
- 语法分析；
- 括号匹配；
- HTML / XML 标签；
- 路径进入与返回；
- 撤销操作。

共同特征：

> 当前任务完成后，最先返回的是最近进入但尚未完成的任务。

这就是栈。

---

# 15. 第三类题：消除 / 归约

典型：

```text
删除字符串中的所有相邻重复项
```

每次新字符到来，只需问：

```text
它是否和最近一个未被消除的字符相同？
```

所以：

```text
stack.top
```

就是唯一需要检查的位置。

---

# 16. 为什么删除后产生的新匹配会自动处理

例如：

```text
abba
```

读取：

```text
a -> [a]
b -> [a,b]
b -> [a]
a -> []
```

中间 `bb` 删除后，外层两个 `a` 自动通过栈顶再次相遇。

所以栈天然适合：

> **局部消除后可能产生连锁反应的问题。**

---

# 17. 字符串本身也可以模拟栈

如果结果容器支持：

```text
back
push_back
pop_back
```

就可以直接把它当栈。

例如：

```cpp
string result;
```

这样最终结果本身就是正确顺序，不再需要：

```text
stack -> 弹出 -> reverse
```

这是一种很实用的实现优化。

---

# 18. 第四类题：表达式求值

典型：

```text
逆波兰表达式
```

规则：

```text
数字 -> push

运算符 ->
    b = pop
    a = pop
    push(a op b)
```

为什么使用栈？

因为运算符需要的是：

> 最近生成、尚未被使用的两个操作数。

---

# 19. 为什么操作数顺序一定要记清

第一次弹出：

```text
b
```

第二次弹出：

```text
a
```

计算：

$$
a\ operator\ b
$$

对于：

```text
+
*
```

顺序写反可能暂时看不出问题。

但：

$$
a-b\ne b-a
$$

$$
a/b\ne b/a
$$

所以这是表达式栈题最常见错误。

---

# 20. 逆波兰表达式的更深层含义

后缀表达式实际上对应：

> **表达式树的后序遍历。**

例如：

```text
2 1 + 3 *
```

对应：

```text
      *
     / \
    +   3
   / \
  2   1
```

后序遍历：

```text
2 1 + 3 *
```

栈在做的事情，就是：

```text
把一个已经完整的局部子树
归约成一个值
```

再继续参与更高层计算。

---

# 21. 第五类题：单调队列

典型：

```text
滑动窗口最大值
```

普通 Queue 只能维护：

```text
进入顺序
```

但我们还想：

```text
O(1) 查询当前最大值
```

所以引入：

> **Monotonic Queue**

---

# 22. 单调队列保存的不是全部窗口元素

这是最重要的理解。

队列只保存：

> **仍然有机会成为当前或未来窗口最大值的候选。**

如果新元素：

```text
比队尾更大
```

那么旧队尾：

- 更小；
- 更早过期。

它以后永远不可能成为最大值。

所以可以永久淘汰。

---

# 23. 最大值单调队列的两个删除方向

使用 deque。

### 队头删除

处理：

```text
已经离开窗口的元素
```

### 队尾删除

处理：

```text
已经失去竞争力的元素
```

于是队列中：

```text
下标有效
值单调递减
```

所以：

```text
front 永远是当前最大值
```

---

# 24. 单调队列为什么是 O(n)

虽然内部有：

```text
while pop_back
```

但每个元素：

```text
最多入队一次
最多出队一次
```

所以所有队列操作总量：

$$
O(n)
$$

不是：

$$
O(n^2)
$$

这类“元素只进出一次”的复杂度分析非常常见。

---

# 25. 单调队列不是固定模板

需要明确：

> 单调队列是一种“维护单调候选集合”的思想，不是一套永远不变的 push/pop API。

不同题目可能：

- 存值；
- 存下标；
- 存二元组；
- 维护递增；
- 维护递减。

真正不变的是：

```text
淘汰以后永远不可能成为答案的候选
```

---

# 26. 第六类题：优先队列 / Heap

典型：

```text
前 K 个高频元素
```

首先：

```text
Hash Map 统计频次
```

然后要解决：

```text
从 m 个候选中找 score 最大的 K 个
```

这就是：

> **Top K**

问题。

---

# 27. Priority Queue 为什么“披着队列外衣”

普通 Queue：

```text
按进入时间决定谁先出来
```

Priority Queue：

```text
按优先级决定谁先出来
```

底层通常使用：

> **Heap**

所以它只是接口形式像队列，逻辑上并不是 FIFO。

---

# 28. 什么是堆

堆通常是一棵：

> 完全二叉树。

大根堆：

$$
parent\ge children
$$

堆顶是：

```text
最大值
```

小根堆：

$$
parent\le children
$$

堆顶是：

```text
最小值
```

重要的是：

> 堆并不是完整排序结构，它只保证父子之间的局部顺序。

---

# 29. 为什么“前 K 大”反而使用小根堆

如果只维护大小为：

$$
K
$$

的候选集合。

目标：

```text
保留最大的 K 个
```

那么每次超出容量时，应该淘汰：

```text
当前 K+1 个候选里最小的
```

所以需要：

```text
小根堆
```

堆顶就是：

> 当前 Top K 中最弱的候选。

---

# 30. Top K 的重要口诀

```text
找最大的 K 个
→ 维护大小 K 的小根堆

找最小的 K 个
→ 维护大小 K 的大根堆
```

注意这是：

```text
固定 K 候选堆
```

的情况。

如果把所有数据都放入堆再取答案，则使用方向可能不同。

---

# 31. 前 K 高频元素为什么是 O(n log k)

先统计频次：

$$
O(n)
$$

设不同元素数量为：

$$
m
$$

每个候选进行一次大小不超过 $k$ 的堆操作：

$$
O(\log k)
$$

因此：

$$
O(m\log k)
$$

最坏可写为：

$$
O(n\log k)
$$

比完整排序：

$$
O(n\log n)
$$

在 $k$ 较小时更有优势。

---

# 32. 栈、队列、deque、priority_queue 怎么区分

| 结构 | 核心访问规则 | 常见用途 |
| --- | --- | --- |
| Stack | 最近加入先处理 | 匹配、递归、表达式、消除 |
| Queue | 最早加入先处理 | BFS、层序、调度 |
| Deque | 两端都能操作 | 单调队列、双端状态 |
| Priority Queue | 优先级最高先处理 | Top K、动态极值、调度 |
| Monotonic Queue | 队列内部保持单调候选 | 滑动窗口极值 |

---

# 33. 怎样判断该用 Stack

出现这些关键词时优先考虑：

```text
最近
嵌套
匹配
回退
撤销
相邻消除
表达式
后序归约
```

核心问题：

> 当前元素是不是只需要和“最近未完成元素”发生关系？

如果是，Stack 很可能合适。

---

# 34. 怎样判断该用普通 Queue

关键词：

```text
按顺序
先到先处理
一层一层
最短步数
广度
任务排队
```

典型：

```text
BFS
层序遍历
消息处理
```

---

# 35. 怎样判断该用 Deque

如果普通队列不够，因为需要：

```text
从队头删除
从队尾也删除
```

或者：

```text
维护区间候选
```

就考虑：

```text
deque
```

滑动窗口最大值就是最经典例子。

---

# 36. 怎样判断该用 Priority Queue

关键词：

```text
最大
最小
第 K 大
第 K 小
Top K
每次取当前最优
动态维护最值
```

优先考虑：

```text
Heap / Priority Queue
```

---

# 37. 单调队列与优先队列的区别

两者都能维护最大值，但机制不同。

### 单调队列

利用：

```text
元素按时间顺序进入、过期
```

主动删除永远不会成为答案的候选。

滑动窗口极值：

$$
O(n)
$$

### Priority Queue

不依赖这种特殊顺序关系。

更通用，但通常：

$$
O(\log n)
$$

每次更新。

所以：

> 能利用“窗口顺序 + 永久淘汰”时，单调队列更强。

---

# 38. 栈和递归的关系

每次函数调用都会保存：

- 参数；
- 局部变量；
- 返回地址；
- 调用上下文。

最近调用的函数：

```text
最先返回
```

因此系统调用结构天然是：

```text
Stack
```

递归可以理解为：

> **由系统帮你维护的一套隐式栈。**

---

# 39. BFS 和队列的关系

BFS 要保证：

```text
距离起点更近的节点
先于更远的节点被处理
```

新发现的节点放队尾。

老节点从队头处理。

所以访问顺序：

```text
FIFO
```

这正是 Queue。

# 41. 一套完整的结构选择流程

遇到题目时，可以这样问。

```text
我要访问哪个元素？
       ↓
最近加入的？
 ├─ 是 → Stack
 └─ 否
       ↓
最早加入的？
 ├─ 是 → Queue
 └─ 否
       ↓
需要两端操作？
 ├─ 是 → Deque
 └─ 否
       ↓
每次需要当前最大 / 最小 / Top K？
 ├─ 是 → Priority Queue / Heap
 └─ 否
       ↓
是滑动窗口极值且可淘汰弱候选？
 └─ 是 → Monotonic Queue
```

# 42. 复杂度判断中的三个高频陷阱

## 陷阱一：看到嵌套 while 就认为 O(n²)

单调队列里虽然有：

```text
for + while
```

但每个元素最多进出一次。

所以：

$$
O(n)
$$

---

## 陷阱二：双栈队列某次 pop 是 O(n)，就认为所有 pop 都 O(n)

单次最坏：

$$
O(n)
$$

但均摊：

$$
O(1)
$$

---

## 陷阱三：Top K 直接把所有元素排序

如果只需要：

```text
K 个
```

不一定需要知道所有元素完整顺序。

可以用堆把：

$$
O(n\log n)
$$

优化到：

$$
O(n\log k)
$$

# 43. 三个非常重要的“不变量”

## 双栈模拟队列

```text
stackOut 中所有元素
都比 stackIn 中元素更早入队
```

---

## 单队列模拟栈

```text
queue.front -> back
=
stack.top -> bottom
```

---

## 单调队列

```text
队列下标仍在窗口内
并且对应值保持单调
```

数据结构题如果能先说清“不变量”，代码往往就不会乱。

# 44. 为什么这些题都与“顺序”有关

回顾整个模块：

### 括号

```text
最近打开的先关闭
```

### 重复项

```text
最近保留的先比较
```

### RPN

```text
最近生成的操作数先使用
```

### Queue

```text
最早进入的先处理
```

### Sliding Window

```text
最早过期 + 最强候选
```

### Top K

```text
按优先级决定保留谁
```

所以这整个模块可以统一为：

> **不同数据结构，本质上是在规定“谁应该先被访问”。**

# 45. 学习栈与队列的最终目标

不要只记：

```text
push

```

更应该做到看到题目后能快速判断：

### 题目关注“最近”还是“最早”？

### 是否存在嵌套 / 回退 / 连锁消除？

### 是否需要窗口中持续维护极值？

### 是否只需要前 K 个，而非完整排序？

# 46. 最终总结

栈与队列最基础：

```text
Stack → LIFO
Queue → FIFO
```

但实际算法中会进一步发展出：

```text
Stack
  ├─ 匹配
  ├─ 消除
  ├─ 表达式
  └─ 递归 / 回退

Queue
  ├─ BFS
  ├─ 调度
  └─ 层序

Deque
  └─ 单调队列 / 窗口极值

Priority Queue
  └─ Heap / Top K
```

这一模块最值得带走的五条结论：

1. **最近未完成状态 → Stack。**
2. **按到达顺序处理 → Queue。**
3. **窗口极值且能永久淘汰弱候选 → Monotonic Deque。**
4. **动态最大最小 / Top K → Heap / Priority Queue。**
5. **先确定访问顺序，再决定数据结构。**

当你不再从“这题是不是栈题”出发，而是从：

> **“题目要求谁先被处理？”**

出发时，栈与队列这整个模块就真正串起来了。
