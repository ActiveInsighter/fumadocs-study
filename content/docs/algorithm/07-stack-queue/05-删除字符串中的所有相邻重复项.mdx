# 1047. 删除字符串中的所有相邻重复项

<Cards>
  <Card title="题目" href="https://leetcode.cn/problems/remove-all-adjacent-duplicates-in-string/">
    LeetCode 1047 · Remove All Adjacent Duplicates In String
  </Card>
</Cards>

给定一个只包含小写字母的字符串 `s`。

每次可以选择两个相邻且相同的字符并删除它们。

这个过程会反复进行，直到不能再删除。

返回最终字符串。

例如：

```text
输入：
"abbaca"

输出：
"ca"
```

消除过程：

```text
abbaca
 ↓
aaca
 ↓
ca
```

<Callout type="info" title="本题为什么适合栈">
每次要判断的是：

> 当前字符是否和“最近一个还没有被消除的字符”相同？

这个“最近未消除字符”正好就是栈顶。
</Callout>

---

# 1. 为什么直接扫描删除不够好

一种直觉做法是：

```text
从左到右找相邻重复字符
找到后删除
再重新检查
```

问题在于删除后，原本不相邻的字符会变成相邻。

例如：

```text
abba
```

先删除：

```text
bb
```

得到：

```text
aa
```

此时又要继续删除。

如果每次删除后都重新扫描，可能产生大量重复工作。

---

# 2. 栈如何处理“连锁消除”

依次读取字符。

### 如果栈为空

当前字符直接入栈。

### 如果当前字符和栈顶不同

说明当前字符暂时无法消除。

入栈。

### 如果当前字符和栈顶相同

这两个字符应该一起删除。

因此：

```text
栈顶 pop
当前字符不入栈
```

这就完成一次消除。

---

## 3. 示例：`abbaca`

初始：

```text
stack = []
```

读取 `a`：

```text
[a]
```

读取 `b`：

```text
[a, b]
```

读取第二个 `b`：

```text
top == b
```

消除：

```text
[a]
```

读取 `a`：

```text
top == a
```

再次消除：

```text
[]
```

读取 `c`：

```text
[c]
```

读取 `a`：

```text
[c, a]
```

最终结果：

```text
ca
```

---

# 4. 为什么连锁反应会自动处理

考虑：

```text
abba
```

过程：

```text
a -> [a]
b -> [a, b]
b -> [a]
a -> []
```

删除中间的 `bb` 后，外层的两个 `a` 自动变成：

```text
当前字符 a
与栈顶 a
```

于是立即继续消除。

所以栈天然可以处理：

> 删除后产生的新相邻关系。

---

# 5. 标准显式栈解法

```cpp
class Solution {
public:
    string removeDuplicates(string s) {
        stack<char> st;

        for (char c : s) {
            if (
                !st.empty() &&
                st.top() == c
            ) {
                st.pop();
            } else {
                st.push(c);
            }
        }

        string result;

        while (!st.empty()) {
            result.push_back(st.top());
            st.pop();
        }

        reverse(result.begin(), result.end());

        return result;
    }
};
```

---

## 6. 为什么最后要反转

栈顶是：

```text
最后保留下来的字符
```

如果直接不断：

```cpp
result.push_back(st.top());
```

取出的顺序是从后往前。

例如栈逻辑内容：

```text
c a
```

栈顶：

```text
a
```

弹出顺序：

```text
a c
```

所以还需要：

```cpp
reverse(...)
```

恢复原顺序。

# 7. 更推荐：直接用 string 模拟栈

C++ 的 `string` 本身就支持：

```cpp
push_back
pop_back
back
empty
```

这几乎就是一个栈所需的全部接口。

所以可以直接把结果字符串当栈。

```cpp
class Solution {
public:
    string removeDuplicates(string s) {
        string result;

        for (char c : s) {
            if (
                !result.empty() &&
                result.back() == c
            ) {
                result.pop_back();
            } else {
                result.push_back(c);
            }
        }

        return result;
    }
};
```

这个版本更短，而且不需要最后反转。

---

# 8. 为什么“结果字符串”可以作为栈

在扫描过程中：

```text
result
```

始终表示：

> 已扫描前缀经过完整消除后的最终状态。

当前字符只可能与：

```text
result 最后一个字符
```

形成新的相邻重复对。

所以只需要查看：

```cpp
result.back()
```

这正是栈顶。

---

## 9. 一个非常重要的不变量

处理到任意位置时：

> `result` 中不存在相邻重复字符。

为什么？

因为每加入一个新字符前，都先检查它是否与末尾相同。

### 相同

直接把末尾删掉。

### 不同

新字符加入后，也不会形成重复对。

所以不变量始终成立。

---

# 10. 正确性解释

设当前已处理前缀经过完整消除后为：

```text
R
```

现在读到新字符：

```text
c
```

只有两种情况。

### `R` 为空，或末尾不是 `c`

那么：

```text
R + c
```

不会产生新的相邻重复。

所以直接保留。

### `R` 末尾是 `c`

那么新字符和末尾字符构成一对：

```text
cc
```

必须消除。

删除末尾，并不加入当前 `c`。

之后若产生更早的连锁反应，实际上在之前的栈状态中已经被正确维护。

所以算法正确。

---

# 11. 时间复杂度

每个字符最多：

```text
入栈一次
出栈一次
```

因此总时间复杂度：

$$
O(n)
$$

空间复杂度：

$$
O(n)
$$

因为最坏情况下完全没有重复：

```text
abcdefg...
```

所有字符都会被保留。

---

# 12. 为什么不是 O(n²)

虽然会发生多次：

```text
pop
```

但每个字符一旦被 pop，就永远不会再次进入栈。

因此所有 push 和 pop 的总次数：

$$
O(n)
$$

这是一类非常典型的：

> 每个元素最多进出一次，因此整体线性。

---

# 13. 和“有效的括号”有什么联系

两道题都依赖：

```text
栈顶 = 最近未完成状态
```

### 有效括号

栈顶表示：

```text
最近未闭合的括号 / 期望右括号
```

### 相邻重复项删除

栈顶表示：

```text
最近未被消除的字符
```

所以栈真正适合的是：

> 需要持续访问“最近尚未处理完成的元素”。

---

# 14. 为什么不适合 Queue

假设：

```text
abba
```

处理最后一个 `a` 时，需要比较的是：

```text
最近保留下来的 a
```

也就是最后加入的数据。

队列只能看到最早加入的数据。

所以 FIFO 不符合需求。

---

# 15. 这类题的通用模型

可以抽象成：

```text
扫描当前元素 x
      ↓
和栈顶 top 比较
      ↓
满足消除 / 合并条件？
 ├─ 是 → pop / merge
 └─ 否 → push
```

这类模式经常出现在：

- 相邻重复消除；
- 碰撞模拟；
- 字符串化简；
- 路径化简；
- 某些表达式归约。

---

# 16. 如果是“连续 k 个相同字符删除”怎么办

例如题目要求：

> 连续 $k$ 个相同字符就全部删除。

这时只保存字符本身已经不够。

可以在栈中保存：

```text
(字符, 当前连续次数)
```

例如：

```cpp
vector<pair<char, int>> st;
```

遇到相同字符：

```text
count + 1
```

达到：

$$
k
$$

时：

```text
整个栈顶状态弹出
```

这是本题的自然推广。

---

# 17. 常见错误

### 错误一：只删除原字符串中最初相邻的重复字符

删除会产生新的相邻关系，必须继续处理。

---

### 错误二：栈为空时访问 `top`

必须先判断：

```cpp
!st.empty()
```

---

### 错误三：显式 stack 取结果时忘记反转

栈弹出顺序与原顺序相反。

---

### 错误四：把字符串每次 `erase`

中间删除可能引发大量字符移动。

最坏容易退化成：

$$
O(n^2)
$$

栈方法只需：

$$
O(n)
$$

  ### Java

```java
class Solution {
    public String removeDuplicates(String s) {
        StringBuilder stack = new StringBuilder();

        for (char c : s.toCharArray()) {
            int n = stack.length();

            if (
                n > 0 &&
                stack.charAt(n - 1) == c
            ) {
                stack.deleteCharAt(n - 1);
            } else {
                stack.append(c);
            }
        }

        return stack.toString();
    }
}
```

class Solution:

            else:
                stack.append(c)

        return ''.join(stack)

func removeDuplicates(s string) string {

}

# 20. 本题总结

本题的核心可以浓缩成一句话：

> **栈顶保存“最近一个还没有被消除的字符”。**

每读一个新字符：

```text
和栈顶相同 → 消除
和栈顶不同 → 保留
```

这样删除造成的连锁反应会被自动处理。

更进一步：

```text
如果结果容器本身支持 back / push_back / pop_back
```

就可以直接把结果容器当栈，减少一层数据结构转换。
