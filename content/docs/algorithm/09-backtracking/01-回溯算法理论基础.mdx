# 回溯算法理论基础

回溯（Backtracking）是一类**在有限候选空间中进行系统搜索**的方法。它不断做出选择、深入搜索；当当前选择无法继续得到合法答案时，再撤销这个选择并尝试下一条分支。

<Callout title="先记住一句话">

**回溯 = 深度优先搜索决策树 + 状态恢复。** 其中“递归”只是最常见的实现方式，不是回溯本身。

</Callout>

![回溯算法大纲](https://file1.kamacoder.com/i/algo/20210219192050666.png)

## 1. 回溯到底在做什么？

假设一道题要求从若干候选项中构造一个答案。每一步都有若干种可选决策，于是整个求解过程可以抽象成一棵**状态空间树（State Space Tree）**：

- **节点**：当前已经做出的选择，也就是当前状态。
- **边**：做出一个新的选择。
- **树的宽度**：当前层可选择的候选数量。
- **树的深度**：一个完整答案需要做多少步决策。
- **叶子节点**：一个完整解，或者一个已经无法继续扩展的状态。

![回溯算法理论基础](https://file1.kamacoder.com/i/algo/20210130173631174.png)

回溯算法通常按照深度优先的顺序遍历这棵树：先沿一条路径走到底，再回到最近的分叉点继续尝试。

```text title="最核心的搜索过程"
选择一个候选
  ↓
修改当前状态
  ↓
递归搜索下一层
  ↓
撤销刚才的修改
  ↓
尝试下一个候选
```

<Callout type="warn" title="递归 ≠ 回溯">

递归是一种程序控制方式；回溯是一种搜索策略。很多回溯写成递归，但并不是所有递归都是回溯。例如二叉树求高度可以使用递归，却不需要“尝试选择并撤销选择”。

判断一段代码是不是典型回溯，关键看它是否存在**多分支选择 + 深入搜索 + 状态恢复**。

</Callout>

## 2. 为什么回溯经常看起来像“暴力枚举”？

因为它的本质确实是**有组织地枚举候选解**。

若每层平均有 $b$ 个选择，搜索深度为 $d$，最坏情况下搜索树节点数可达到：

$$
1+b+b^2+\cdots+b^d=O(b^d)
$$

所以回溯通常不是依靠“降低复杂度数量级”取胜，而是依靠以下两点让搜索在实际数据上可接受：

1. **结构化枚举**：避免重复生成同一个候选解。
2. **剪枝（Pruning）**：一旦发现当前分支不可能产生合法答案，立即停止继续向下搜索。

例如，当题目要求“从 $n$ 个数中选 $k$ 个数”时，如果当前还差 $r$ 个数，但剩余候选不足 $r$ 个，那么这个分支已经不可能完成，可以直接剪掉。

<Callout title="复杂度分析时不要只写一个 O(2^n)">

不同回溯问题的状态空间并不相同：子集常见为 $O(2^n)$，全排列常见为 $O(n!)$，而棋盘搜索可能呈现更复杂的指数规模。应先判断“每层有多少选择、最多有多少层”，再估计搜索树大小。

</Callout>

## 3. 回溯常见的五类问题

| 类型 | 关注点 | 典型状态空间 | 关键区别 |
| --- | --- | --- | --- |
| 组合 | 从候选中选若干个元素 | 选择树 | 通常不关心选择顺序 |
| 排列 | 安排元素的先后次序 | 排列树 | 顺序不同通常视为不同答案 |
| 子集 | 决定每个元素选或不选 | 二叉/多叉决策树 | 每个中间状态都可能是答案 |
| 切割 | 决定在哪里切分字符串/数组 | 切割树 | 每条边往往表示一段区间 |
| 棋盘 | 在二维空间逐步放置/填写 | 约束搜索树 | 合法性判断与剪枝非常重要 |

### 组合和排列最容易混淆

组合不强调顺序，例如：

$$
\{1,2\}=\{2,1\}
$$

而排列强调顺序，因此：

$$
[1,2]\ne[2,1]
$$

这会直接影响搜索方式：

- **组合问题**通常使用 `startIndex` 一类参数，让下一层只从当前位置之后继续选择，从而避免顺序不同但元素相同的重复结果。
- **排列问题**通常需要 `used` 数组，表示哪些元素已经被当前路径使用；下一层仍可从整个候选集合中挑选未使用元素。

## 4. 一道回溯题真正需要设计的 5 个东西

把任何回溯题拆成下面五个对象，代码就会清晰很多。

### ① 当前路径 `path`

表示已经做出的选择。例如组合问题中的 `[1, 3]`，排列问题中的 `[2, 1]`，或者 N 皇后中已经放好的若干个皇后位置。

### ② 候选集合 `choices`

当前状态下还能做哪些选择。它可能由一个起始下标、一个 `used` 数组、一个棋盘合法性判断，或者剩余目标值共同决定。

### ③ 终止条件 `isGoal`

判断当前路径什么时候构成一个答案。例如路径长度等于 $k$、字符串已经被切到末尾、棋盘已经处理完最后一行。

### ④ 约束条件 `isValid`

判断某个候选是否允许被选择。例如不能重复使用元素、当前数字不能让和超过目标值、皇后不能同行同列同斜线。

### ⑤ 状态恢复 `undo`

递归返回之后，将状态恢复到“做出当前选择之前”的样子，使兄弟分支互不干扰。

因此，一个回溯问题可以抽象成：

$$
\text{状态} + \text{候选} + \text{选择} + \text{约束} + \text{撤销}
$$

## 5. 回溯三部曲

### 第一步：确定递归函数的含义

函数参数通常不是一开始就能完全确定。更可靠的方式是先问：**下一层搜索需要知道哪些信息？**

常见参数包括：

- `startIndex`：组合、子集、切割问题中表示下一层从哪里继续。
- `used`：排列或树层去重时记录使用状态。
- `remain`：目标和问题中记录剩余需要凑出的值。
- `row / col`：棋盘问题中记录搜索位置。

### 第二步：确定终止条件

终止条件通常对应搜索树中的某类节点：

```text title="终止条件"
if (当前状态已经构成答案) {
    保存答案;
    return;
}
```

但要注意：**并不是所有回溯题都只在叶子节点收集答案。**

例如子集问题中，每个搜索节点都代表一个合法子集，因此往往进入递归函数后就先保存当前路径。

### 第三步：横向枚举，纵向递归，返回后撤销

```text title="回溯核心框架"
backtracking(状态) {
    if (满足终止条件) {
        收集答案;
        return;
    }

    for (当前层的每一个候选) {
        if (候选不合法) continue;

        做选择;
        backtracking(下一层状态);
        撤销选择;
    }
}
```

可以把它记成：

> **for 循环负责横向枚举，递归负责纵向深入，撤销负责回到分叉点。**

## 6. “撤销选择”为什么不能省？

假设当前路径是：

```text
[1]
```

我们先选择 `2`，递归探索：

```text
[1, 2]
```

这条分支搜索结束后，如果不删除 `2`，下一次再选择 `3` 时就会得到：

```text
[1, 2, 3]
```

但正确的兄弟分支应该是：

```text
[1, 3]
```

所以回溯的本质之一就是维护下面这个不变量：

> **开始处理某个兄弟分支时，共享状态必须与处理前一个兄弟分支之前完全一致。**

在数组路径中，最常见的成对操作就是：

```text
path.push(x);   // 做选择
backtrack();    // 深入
path.pop();     // 撤销选择
```

棋盘、哈希表、计数数组等共享状态同理：修改了什么，递归回来后就恢复什么。

## 7. 剪枝：不是“少写几层递归”，而是提前证明无解

剪枝的核心逻辑是：

> **如果可以证明当前状态的所有后继都不可能产生答案，就不再展开这个节点。**

常见剪枝依据有：

- **剩余数量不足**：组合问题中剩余候选无法凑够所需元素。
- **数值越界**：正整数求和问题中当前和已经超过目标值。
- **局部非法**：N 皇后中新皇后已经与之前皇后冲突。
- **重复状态**：同一树层中相同数值只保留一个入口。
- **排序后的单调性**：数组排序后，如果当前候选已经过大，后续更大的候选也无需尝试，可以直接 `break`。

剪枝本身不会改变答案集合，只会减少无意义的搜索节点。

## 8. 两种最重要的“去重”不要混淆

后续做组合总和、子集 II、全排列 II 时，经常会遇到重复元素。此时一定要区分：

### 树枝去重

控制的是**同一条路径里某个元素能不能重复使用**。

例如排列问题中，一个下标已经被当前路径选择，就不能再次选择，通常使用 `used[i]`。

### 树层去重

控制的是**同一个父节点下面，相同数值是否可以作为多个等价入口**。

例如排序后数组为 `[1, 1, 2]`，如果同一层先选择第一个 `1` 与选择第二个 `1` 会生成完全相同的答案集合，就应该只保留一个入口。

<Callout type="warn" title="高频错误">

“同层去重”和“同路径去重”解决的是两个不同问题。很多回溯代码能通过大部分样例、却在重复元素测试上出错，根源就是把这两个概念混在了一起。

</Callout>

## 9. 一张图判断该怎么写

遇到新题时，先画出前两三层搜索树，不必一上来写代码。重点标注：

1. 一个节点代表什么状态？
2. 从这个节点能做哪些选择？
3. 下一层候选范围是否缩小？
4. 哪些节点已经可以收集答案？
5. 哪些分支可以提前判定无解？
6. 递归返回后，需要恢复哪些变量？

如果这六个问题已经明确，代码通常只是在把搜索树翻译成程序。

## 10. 回溯模板应该怎么记？

不要机械背函数签名，更推荐记住下面这个结构：

```text title="通用回溯模板"
function backtrack(state):
    if state is a solution:
        record(state)
        return

    for choice in available_choices(state):
        if choice is invalid:
            continue

        apply(choice)       // 做选择
        backtrack(newState) // 进入下一层
        undo(choice)        // 撤销选择
```

其中真正随题目变化的只有四部分：

- `solution`：什么时候收集答案；
- `available_choices`：这一层可以选什么；
- `invalid`：什么情况不能继续；
- `apply / undo`：选择会修改哪些状态。

## 11. 学习回溯时的推荐顺序

建议按“搜索结构逐渐复杂”的顺序学习：

```text
组合
  ↓
组合剪枝
  ↓
组合总和 / 电话号码组合
  ↓
分割问题
  ↓
子集
  ↓
带重复元素的去重
  ↓
排列
  ↓
棋盘问题（N 皇后 / 数独）
```

前面的题目主要训练**搜索树与模板**，中间的题目训练**去重和剪枝**，最后的棋盘题训练**复杂状态维护与约束搜索**。

## 12. 本篇结论

回溯最值得掌握的不是一段固定代码，而是一种建模方式：

- 把问题抽象成**有限状态空间树**；
- 用 `for` 枚举同层选择，用递归深入下一层；
- 每次选择之后，都明确知道如何**恢复现场**；
- 用终止条件决定何时收集答案；
- 用约束和数学条件尽早**剪枝**；
- 遇到重复元素时，分清**树枝去重**和**树层去重**。

只要能把题目的搜索树画清楚，后面的组合、切割、子集、排列、N 皇后和数独，本质上都只是这套框架的不同变体。

## 13. 代码模板（多语言）

为了让模板本身可以直接运行和改写，下面以最经典的“从 `nums` 中选择 `k` 个元素”为骨架。它完整展示了**终止 → 横向枚举 → 做选择 → 递归 → 撤销**这五个动作，并加入了“剩余元素数量不足”的基础剪枝。

### C++

```cpp title="C++"
#include <vector>
using namespace std;

vector<vector<int>> result;
vector<int> path;

void backtracking(const vector<int>& nums, int k, int startIndex) {
    if (static_cast<int>(path.size()) == k) {
        result.push_back(path);
        return;
    }

    int need = k - static_cast<int>(path.size());
    int lastStart = static_cast<int>(nums.size()) - need;

    for (int i = startIndex; i <= lastStart; ++i) {
        path.push_back(nums[i]);          // 做选择
        backtracking(nums, k, i + 1);     // 进入下一层
        path.pop_back();                  // 撤销选择
    }
}
```

### Python

```python title="Python"
result = []
path = []


def backtracking(nums, k, start_index):
    if len(path) == k:
        result.append(path.copy())
        return

    need = k - len(path)
    last_start = len(nums) - need

    for i in range(start_index, last_start + 1):
        path.append(nums[i])                   # 做选择
        backtracking(nums, k, i + 1)           # 进入下一层
        path.pop()                              # 撤销选择
```

### Java

```java title="Java"
import java.util.ArrayList;
import java.util.List;

class BacktrackingTemplate {
    private final List<List<Integer>> result = new ArrayList<>();
    private final List<Integer> path = new ArrayList<>();

    void backtracking(int[] nums, int k, int startIndex) {
        if (path.size() == k) {
            result.add(new ArrayList<>(path));
            return;
        }

        int need = k - path.size();
        int lastStart = nums.length - need;

        for (int i = startIndex; i <= lastStart; i++) {
            path.add(nums[i]);                  // 做选择
            backtracking(nums, k, i + 1);       // 进入下一层
            path.remove(path.size() - 1);       // 撤销选择
        }
    }
}
```

### Go

```go title="Go"
package backtracking

var result [][]int
var path []int

func search(nums []int, k int, startIndex int) {
    if len(path) == k {
        snapshot := append([]int(nil), path...)
        result = append(result, snapshot)
        return
    }

    need := k - len(path)
    lastStart := len(nums) - need

    for i := startIndex; i <= lastStart; i++ {
        path = append(path, nums[i])       // 做选择
        search(nums, k, i+1)               // 进入下一层
        path = path[:len(path)-1]          // 撤销选择
    }
}
```
