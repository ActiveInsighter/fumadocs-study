# 回溯算法阶段总结（一）：组合型搜索的统一框架

前五篇已经覆盖了回溯最重要的一组基础模型：

- 回溯算法的通用框架；
- 同一集合中选 $k$ 个元素；
- 组合问题的边界剪枝；
- 同时受到“个数”和“总和”约束的组合；
- 多个不同集合之间的组合。

如果只记住每道题的代码，这些题看起来像五套写法；如果把它们统一抽象成**搜索树**，本质上只是在改变四件事：

$$
\boxed{\text{状态} + \text{本层候选} + \text{终止条件} + \text{剪枝条件}}
$$

<Callout title="这一阶段真正要形成的能力">

看到一道回溯题时，不要先背模板，而要先回答：

1. 每一层递归表示什么？
2. 当前节点还能选择哪些元素？
3. 为什么这些选择不会产生重复答案？
4. 什么情况下已经得到答案？
5. 什么情况下可以证明后续不可能得到答案？

只要这五个问题明确，代码通常只是把搜索树翻译出来。

</Callout>

## 1. 回溯到底在遍历什么？

回溯不是一种神秘的“递归技巧”，而是对一棵隐式搜索树做深度优先遍历。

在搜索树中：

- **节点**：当前已经做出的选择，即当前状态；
- **边**：下一步可以做出的一个选择；
- **树枝**：从当前状态尝试某个候选；
- **叶子或中间节点**：可能对应一个完整答案；
- **回溯**：递归返回后撤销刚才的选择，恢复父节点状态。

因此经典模板：

```cpp
void backtracking(/* 状态 */) {
    if (/* 终止条件 */) {
        result.push_back(path);
        return;
    }

    for (/* 当前层的所有合法选择 */) {
        path.push_back(choice);       // 做选择
        backtracking(/* 新状态 */);  // 进入下一层
        path.pop_back();              // 撤销选择
    }
}
```

可以用一句话概括：

> `for` 循环负责横向枚举兄弟节点，递归负责纵向深入下一层，撤销操作负责回到父节点继续搜索。

## 2. 为什么回溯能替代任意层 for 循环？

假设要从 $n$ 个数中选 $k$ 个数。

当 $k=2$ 时可以写两层循环；当 $k=3$ 时可以写三层循环。但题目中的 $k$ 是变量，我们无法在编译前决定需要写多少层循环。

递归恰好可以把“循环层数”变成运行时状态：

$$
\text{递归深度}=\text{已经选择的元素个数}
$$

因此，组合型回溯可以看成：

> 用递归动态生成任意深度的嵌套循环。

这也是回溯最直观的价值之一。

## 3. 第一类：同一集合中选元素

以 `77. 组合` 为代表：

```text
候选集合：[1, 2, 3, ..., n]
目标：选择 k 个不同元素
```

这类题的核心状态是 `startIndex`。

### 为什么需要 `startIndex`？

如果已经选择了 `2`，下一层仍然从 `1` 开始遍历，就会产生：

```text
[2, 1]
```

而 `[1, 2]` 与 `[2, 1]` 对组合来说是同一个答案。

因此我们规定：

$$
\text{下一层只能从当前元素之后继续选择}
$$

也就是：

```cpp
backtracking(i + 1);
```

这实际上是在搜索树层面规定一个**单调的选择顺序**，从根源上消除排列型重复。

<Callout type="info" title="startIndex 的真正含义">

`startIndex` 不是为了“记住递归到了哪里”，而是为了限定**当前层允许选择的候选区间**。

它解决的是：同一集合中的组合如何避免回头选择。

</Callout>

## 4. 第二类：同一集合 + 数量约束 + 总和约束

`216. 组合总和 III` 在普通组合的基础上增加：

$$
|path|=k
$$

以及：

$$
\sum path=n
$$

所以状态中除了 `startIndex`，还要维护当前和 `sum`。

这时终止条件不再只是“选够 $k$ 个”：

```cpp
if (path.size() == k) {
    if (sum == n) result.push_back(path);
    return;
}
```

这说明一个非常重要的规律：

> **递归深度限制**与**答案合法条件**是两件不同的事。

达到固定深度时必须停止搜索，但只有同时满足目标和才收集答案。

## 5. 第三类：多个不同集合之间做组合

`17. 电话号码的字母组合` 与前面的组合题有本质区别。

例如输入 `"23"`：

$$
2\rightarrow\{a,b,c\}
$$

$$
3\rightarrow\{d,e,f\}
$$

答案来自：

$$
\{a,b,c\}\times\{d,e,f\}
$$

这里每一层处理的是**一个新的候选集合**，所以不需要 `startIndex`。

需要的状态是：

$$
index=\text{当前处理到 digits 的哪个位置}
$$

代码形态也变成：

```cpp
for (char ch : letterMap[digits[index] - '0']) {
    path.push_back(ch);
    backtracking(index + 1);
    path.pop_back();
}
```

### `startIndex` 与 `index` 对比

| 状态 | 解决的问题 | 下一层如何变化 |
| --- | --- | --- |
| `startIndex` | 同一集合组合，避免回头选 | 通常传 `i + 1` |
| `index` | 多个集合按顺序逐层选择 | 通常传 `index + 1` |

<Callout type="warn" title="不要根据变量名套模板">

二者都可能是整数下标，但语义完全不同。判断使用哪一个，要看**下一层的候选集合从哪里来**。

</Callout>

## 6. 剪枝：不是少写几层，而是证明某棵子树无解

回溯本质上仍然是搜索。优化的关键不是改变 DFS，而是尽早证明：

$$
\text{从当前状态继续搜索不可能得到合法答案}
$$

一旦证明，就可以整棵子树不再访问。

### 6.1 候选数量不足

在 `77. 组合` 中，假设：

- 还需要选择 $r$ 个元素；
- 从当前位置到末尾只剩 $m$ 个元素。

若：

$$
m<r
$$

那么当前起点以及之后更晚的起点都不可能完成答案。

若当前已经选择 `path.size()` 个元素，则还需要：

$$
k-path.size()
$$

个元素。

因此 `i` 的上界可以收紧为：

$$
i\le n-(k-|path|)+1
$$

对应代码：

```cpp
for (int i = startIndex;
     i <= n - (k - path.size()) + 1;
     ++i) {
    // ...
}
```

### 6.2 当前和已经过大

在所有候选值均为正数时，如果：

$$
sum>target
$$

后面无论再选什么，和只会继续增大，因此当前子树必然无解。

这是一类**单调性剪枝**。

### 6.3 更强的上下界剪枝

如果剩余必须再选 $r$ 个数，可以进一步计算：

- 理论最小还能增加多少；
- 理论最大还能增加多少。

若当前和加上“最小可能增量”都已经超过目标，或加上“最大可能增量”仍达不到目标，都可以直接返回。

这类剪枝的本质都是：

$$
\text{利用剩余搜索空间的上下界证明无解}
$$

## 7. 固定深度与不固定深度

这一点会直接影响终止条件。

### 固定深度

例如：

- `77. 组合`：必须选 $k$ 个；
- `216. 组合总和 III`：必须选 $k$ 个；
- `17. 电话号码的字母组合`：必须处理完所有数字。

所以搜索树深度提前已知。

### 不固定深度

下一篇 `39. 组合总和` 中，每个元素可以重复使用，题目又没有规定必须选多少个数。

此时递归深度由当前选择决定，只能通过目标状态，例如：

$$
sum=target
$$

来结束一条成功路径。

这会是组合型回溯从“固定层数”走向“状态驱动终止”的重要一步。

## 8. 一张表串起前五篇

| 题型 | 每层从哪里选 | 元素可重复使用 | 递归深度 | 关键状态 |
| --- | --- | --- | --- | --- |
| 77. 组合 | 同一集合 | 否 | 固定为 $k$ | `startIndex` |
| 77. 组合剪枝 | 同一集合 | 否 | 固定为 $k$ | `startIndex` + 剩余数量 |
| 216. 组合总和 III | `1...9` | 否 | 固定为 $k$ | `startIndex` + `sum` |
| 17. 电话号码字母组合 | 每层不同集合 | 不涉及同一元素复用 | 固定为数字个数 | `index` |

真正值得记忆的不是四套代码，而是：

$$
\boxed{\text{下一层允许选择什么？}}
$$

因为这个问题直接决定了：

- 是否需要 `startIndex`；
- 下一层传 `i`、`i+1` 还是 `index+1`；
- 是否需要 `used` 数组；
- 是否会产生重复答案。

## 9. 回溯三部曲：建议每题都手写一遍

### ① 定义递归函数的状态

问自己：为了唯一描述“当前搜索到了哪里”，必须知道哪些信息？

常见状态包括：

```text
startIndex
index
当前和 sum
剩余目标 remain
used 数组
当前切割位置
```

不要为了套模板把所有状态都塞进去。

### ② 明确终止与收集条件

分别判断：

```text
什么时候必须停止？
什么时候当前状态已经是一个答案？
```

二者有时相同，有时不同。

### ③ 写清单层搜索逻辑

明确：

1. 当前层候选范围；
2. 做选择；
3. 下一层状态如何变化；
4. 撤销选择。

只要这一层逻辑正确，递归会自动把它扩展到整棵树。

## 10. 最常见的五类错误

### 错误一：忘记撤销状态

```cpp
path.push_back(x);
backtracking(...);
// 忘记 path.pop_back()
```

这样兄弟节点会继承上一个分支留下的状态。

### 错误二：`i` 和 `i + 1` 机械套用

它们分别代表：

```text
i     → 当前元素下一层仍可再次使用
i + 1 → 当前元素下一层不可再使用
```

具体使用哪一个，必须由题意决定。

### 错误三：把组合写成排列

如果每一层都从 `0` 开始枚举同一个集合，很容易同时得到：

```text
[1, 2]
[2, 1]
```

组合问题通常需要通过单调索引限制顺序。

### 错误四：只看到“返回”，没有看到“剪枝证明”

剪枝不是为了让代码“看起来更快”，而是必须能够说明为什么被删除的子树一定没有答案。

### 错误五：共享状态与参数状态混在一起

例如 `sum` 可以写成：

```cpp
sum += candidates[i];
backtracking(..., sum, ...);
sum -= candidates[i];
```

也可以直接传值：

```cpp
backtracking(..., sum + candidates[i], ...);
```

两种都可以，但要清楚哪些状态需要显式回溯，哪些状态由函数参数天然隔离。

## 11. 做题时的快速检查表

看到新的回溯题，可以按下面顺序检查：

```text
1. 答案是组合、排列、子集、切割，还是棋盘状态？
2. 能否画出前两三层搜索树？
3. 每一层代表什么？
4. 当前层的候选集合是什么？
5. 下一层允许再次选当前元素吗？
6. 是否需要 startIndex / index / used？
7. 什么时候收集答案？
8. 什么时候必须停止？
9. 是否存在“剩余数量不足”“当前和过大”等必无解条件？
10. 做选择后，哪些共享状态必须撤销？
```

<Callout title="阶段结论">

组合型回溯最重要的统一认识是：

$$
\boxed{\text{回溯}=\text{DFS 搜索树}+\text{状态恢复}}
$$

而不同题目的差异，主要集中在：

$$
\boxed{\text{候选集合如何变化，以及同一个元素下一层还能不能再选}}
$$

下一篇 `39. 组合总和` 会首次引入“同一个元素可以无限重复选择”的组合模型，这会让递归参数从 `i+1` 变成 `i`。

</Callout>
