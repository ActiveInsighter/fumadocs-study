# 回溯算法总结：从搜索树到统一解题框架

学完前面的组合、切割、子集、排列、去重、行程和棋盘问题之后，真正应该留下来的并不是 20 多份相似代码，而是一套能够迁移到新题上的**搜索树建模方法**。

回溯可以概括成一句话：

$$
\boxed{\text{在所有可能的选择序列中进行深度优先搜索，并在不可能成功时尽早剪枝}}
$$

它通常不是一种“高效枚举算法”，而是一种**系统地组织暴力搜索**的方法。

<Callout title="这篇总结只需要记住一个核心模型">

面对一道回溯题，先不要想模板，而是回答四个问题：

$$
\boxed{\text{状态} + \text{选择} + \text{约束} + \text{目标}}
$$

- **状态**：当前已经做了哪些决定？
- **选择**：当前还能尝试哪些候选？
- **约束**：哪些候选已经不合法？
- **目标**：什么时候得到一个答案？答案是在叶子节点，还是所有节点？

这四项一旦确定，递归参数、`for` 循环范围、终止条件和剪枝位置基本都会自然出现。

</Callout>

## 1. 回溯到底是什么？

递归描述的是：

> **函数如何进入下一层。**

回溯描述的是：

> **从下一层返回以后，如何恢复进入之前的状态，再尝试另一个选择。**

典型过程是：

```text
做选择
  ↓
进入下一层递归
  ↓
返回上一层
  ↓
撤销选择
  ↓
尝试下一个候选
```

所以回溯往往写成：

```cpp
void backtracking(...) {
    if (满足目标) {
        保存答案;
        return;
    }

    for (候选 : 当前层可选集合) {
        if (候选不合法) continue;

        做选择;
        backtracking(...);
        撤销选择;
    }
}
```

真正重要的不是背这个模板，而是知道代码中的每一部分分别对应搜索树的什么位置。

## 2. 搜索树：理解所有回溯题的统一语言

把递归展开以后，一道回溯题几乎都可以画成一棵树：

```text
                 当前状态
              /     |     \
           选择 A  选择 B  选择 C
            /         ...       \
        下一层状态            下一层状态
```

因此可以形成一个非常稳定的对应关系：

| 代码结构 | 搜索树含义 |
| --- | --- |
| 一次递归调用 | 当前树节点 |
| `for` 循环 | 横向枚举当前节点的孩子 |
| 递归调用 | 纵向进入下一层 |
| `path.push_back(...)` | 沿树枝做出选择 |
| `path.pop_back()` | 从树枝返回时撤销选择 |
| `continue / break / return` | 剪掉不需要搜索的分支 |
| `result.push_back(path)` | 收集满足条件的节点 |

原资料在组合问题中给出的搜索树非常典型：

![77. 组合搜索树](https://file1.kamacoder.com/i/algo/20201118152928844.png)

这张图体现了整个回溯专题最重要的一句话：

$$
\boxed{\text{for 循环负责横向选择，递归负责纵向深入，回溯负责恢复状态}}
$$

## 3. 为什么递归可以替代任意层数的 for 循环？

假设要从 $n$ 个数中选择 $k$ 个数。

如果 $k=2$，可以写两层循环；如果 $k=3$，可以写三层循环。

但当 $k$ 是输入时，我们无法预先写死循环层数。

回溯的作用就是：

$$
\boxed{\text{用递归深度动态表示 for 循环的嵌套层数}}
$$

例如路径长度为 $d$，就表示已经完成了前 $d$ 层选择。

当：

$$
|path|=k
$$

说明已经完成 $k$ 次决策，得到一个组合。

这也是为什么很多组合题的终止条件直接写成：

```cpp
if (path.size() == k) {
    result.push_back(path);
    return;
}
```

## 4. `startIndex` 的本质：不是模板变量，而是“下一层候选范围”

初学时最容易把 `startIndex` 当成组合题专属模板参数。

其实它表达的是：

> **进入下一层以后，候选集合从哪里开始？**

如果一个集合中的元素只能向右继续选，那么需要：

```cpp
backtracking(i + 1);
```

如果当前元素允许重复使用，那么可能是：

```cpp
backtracking(i);
```

如果每层来自完全不同的集合，则根本不需要 `startIndex`。

如果是排列，则每层都要重新从 `0` 开始枚举，只能用 `used` 判断哪些下标已经在当前路径里。

<Callout type="info" title="判断 startIndex 的正确问题">

不要问：

```text
这是不是组合题？
```

而应该问：

```text
进入下一层以后，哪些候选仍然允许被选择？
```

`startIndex` 只是这个答案的一种编码方式。

</Callout>

## 5. 组合问题：答案通常在固定深度的节点

### 5.1 基础组合

`77. 组合` 的特点是：

```text
同一个集合中选择 k 个不同位置
顺序不重要
不能重复使用同一元素
```

因此：

```cpp
for (int i = startIndex; i <= n; ++i) {
    path.push_back(i);
    backtracking(i + 1);
    path.pop_back();
}
```

答案位于深度为 $k$ 的节点。

### 5.2 组合剪枝：剩余候选不够就立即停止

原资料给出了剪枝后的搜索树：

![77. 组合剪枝](https://file1.kamacoder.com/i/algo/20201118153133458.png)

如果当前已经选择：

$$
|path|
$$

个元素，还需要：

$$
r=k-|path|
$$

个。

当从 `i` 到 `n` 剩余元素个数不足 $r$ 时：

$$
n-i+1<r
$$

这条分支必然失败。

整理可得循环上界：

$$
i\le n-(k-|path|)+1
$$

于是：

```cpp
for (int i = startIndex;
     i <= n - (k - path.size()) + 1;
     ++i) {
    ...
}
```

这体现了回溯剪枝最常见的模式：

$$
\boxed{\text{如果剩余资源连最低需求都满足不了，就不要进入下一层}}
$$

### 6.1 固定数量 + 固定目标和

$$

$$

以及：

$$




## 7. 多个集合之间做组合：层号比 startIndex 更重要

`17. 电话号码的字母组合` 和前面的组合题有本质差异。

例如输入：

```text

```

第一层只能从：

```text
abc
```

中选，第二层只能从：

```text

```

中选。

所以它不是“同一个集合继续向右选”，而是：

$$

即多个集合的笛卡尔积。

## 8. 切割问题：把“切割线”当成选择

`131. 分割回文串` 看起来是字符串题，但搜索树结构与组合问题几乎相同。

当前从 `startIndex` 开始，枚举下一刀切在哪里：

```text
[startIndex ... i]
```

如果这一段满足回文条件，就把它加入路径，再从：

```cpp
i + 1
```

继续切剩余字符串。

原资料搜索树：

![131. 分割回文串](https://file1.kamacoder.com/i/algo/20201118202448642.png)

因此切割问题可以统一理解为：

$$
\boxed{\text{枚举下一段的右端点}}
$$

这里的 `startIndex` 同时承担两个作用：

1. 当前剩余字符串的左边界；
2. 下一层允许继续切割的位置。

## 9. 子集问题：答案不只在叶子，而在整棵树

组合问题往往只收集满足指定长度的节点。

子集问题完全不同：

> 每一个搜索状态本身都是一个合法子集。

原资料搜索树：

![78. 子集](https://file1.kamacoder.com/i/algo/20201118202544339.png)

因此 `78. 子集` 通常一进入递归就收集：

```cpp
result.push_back(path);
```

然后继续向下扩展。

这可以概括为：

$$
\boxed{\text{组合题常收集指定深度节点；子集题收集搜索树中的所有合法节点}}
$$

所以很多子集模板甚至不需要显式终止条件——当 `startIndex == nums.size()` 时，`for` 循环自然不会继续。

## 10. 去重：必须先分清“树层”和“树枝”

这是整个回溯专题最容易混乱的部分。

### 10.1 `40. 组合总和 II`：同层相同值只能开启一次分支

输入中允许存在相同数值，但每个下标只能使用一次，而且最终组合不能重复。

原资料中的去重搜索树：

![40. 组合总和 II 去重](https://file1.kamacoder.com/i/algo/2020111820220675.png)

排序以后：

```cpp
if (i > startIndex && candidates[i] == candidates[i - 1]) {
    continue;
}
```

这里跳过的是：

$$
\boxed{\text{同一父节点下，由相同数值开启的重复分支}}
$$

而同一条树枝上仍然可以出现两个值相同但下标不同的元素，只要题意允许。

### 10.2 `90. 子集 II`：同样是树层去重

原资料搜索树：

![90. 子集 II](https://file1.kamacoder.com/i/algo/2020111217110449.png)

它和 `40. 组合总和 II` 的去重本质完全一致：

```text
排序
+
同一层跳过相邻重复值
```

区别只在于答案收集位置：

```text
组合总和 II → 满足目标和才收集
子集 II     → 每个合法节点都收集
```

### 10.3 `491. 非递减子序列`：不能为了去重破坏原顺序

原资料搜索树：

![491. 非递减子序列](https://file1.kamacoder.com/i/algo/20201112170832333.png)

这道题不能直接把数组排序，因为“子序列”要求保留原数组相对顺序。

原资料还给出了一个未排序例子：

![未排序数组上的同层去重](https://file1.kamacoder.com/i/algo/2020111316440479.png)

因此应当在**每一层**维护一个集合：

```cpp
unordered_set<int> usedThisLevel;
```

表示：

> 当前父节点已经让哪些数值开启过分支。

<Callout title="去重问题最稳定的判断流程">

先判断：**重复的是值还是下标？**

再判断：**重复限制发生在同一条路径，还是同一个父节点的不同分支？**

如果需要同层去重，判断能不能排序；若排序会破坏原序，则使用本层 `Set` / 值域数组。

最后才决定写 `used`、相邻元素判断还是本层集合。

</Callout>

## 11. 排列问题：每一层候选都重新从 0 开始

### 11.1 全排列

排列中顺序有意义：

$$
[1,2]\ne[2,1]
$$

所以不能像组合那样只往右搜索。

原资料搜索树：

![46. 全排列](https://file1.kamacoder.com/i/algo/20201112170304979.png)

每一层都需要：

```cpp
for (int i = 0; i < nums.size(); ++i)
```

然后使用：

```cpp
used[i]
```

判断某个下标是否已经出现在当前路径中。

因此组合与排列最重要的差异可以写成：

```text
组合：候选范围不断向右缩小
排列：候选范围每层重新从整个数组开始，再排除已使用下标
```

### 11.2 全排列 II

输入存在重复元素时，还要额外避免同层相同值重复开启分支。

原资料搜索树：

![47. 全排列 II](https://file1.kamacoder.com/i/algo/20201112171930470.png)

对于排序后的数组，最常用条件是：

```cpp
if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) {
    continue;
}
```

`!used[i - 1]` 表示前一个相同元素已经在**当前层**完成过一棵分支，现在又回到了同一个父节点，因此当前相同值不应再次开启重复分支。

原资料分别画出了两种思路：

![47. 全排列 II：树层去重](https://file1.kamacoder.com/i/algo/20201112172230434.png)

![47. 全排列 II：树枝方向判断](https://file1.kamacoder.com/i/algo/20201112172327967.png)

实践中优先选择树层去重，因为它能更早地消除重复分支。

## 12. `used` 数组与本层 `Set`：它们解决的问题并不完全相同

### `used[i]`

通常表示：

```text
下标 i 是否已经出现在当前路径中
```

典型用于排列。

在排序数组中，它还可以辅助判断当前相同元素属于“同层重复”还是“同枝使用”。

### 本层 `Set`

通常表示：

```text
当前父节点下，哪些值已经开启过分支
```

例如 `491. 非递减子序列`。

本层 `Set` 的生命周期应当只覆盖当前递归层：

```cpp
void dfs(...) {
    unordered_set<int> usedThisLevel;

    for (...) {
        ...
    }
}
```

如果把它错误地设计成所有层共享，就会把合法的树枝也一起剪掉。

## 13. 图搜索的拓展：重新安排行程

`332. 重新安排行程` 说明了回溯并不限于数组或字符串。

原资料将一个例子展开成搜索树：

![332. 重新安排行程搜索树](https://file1.kamacoder.com/i/algo/2020111518065555.png)

本质仍然是：

```text
当前机场 = 状态
尚未使用的机票 = 候选
每张机票只能用一次 = 约束
使用全部机票 = 目标
```

只不过这一次“候选集合”来自图的出边，而不是数组中的下一个元素。

如果还要求字典序最小，则候选边的组织方式也会影响效率。

所以这道题最值得迁移的经验是：

$$
\boxed{\text{回溯模板的核心不是数组，而是“状态 + 可恢复的选择”}}
$$

## 14. 棋盘问题：递归层表示“下一个待决策位置”

### 14.1 N 皇后

N 皇后可以把：

```text
第 row 行
```

看成递归层。

这一层的候选就是当前行所有列：

```cpp
for (int col = 0; col < n; ++col)
```

原资料的搜索树：

![51. N 皇后](https://file1.kamacoder.com/i/algo/20201118225433127.png)

如果某列与已有皇后发生：

- 同列冲突；
- 主对角线冲突；
- 副对角线冲突；

就剪掉该分支。

当：

$$
row=n
$$

说明每一行都已经成功放置一个皇后，得到一个完整解。

### 14.2 解数独

数独看起来比 N 皇后“二维”得多，但搜索树仍然可以统一成一维层次：

$$
\boxed{\text{每一层处理一个尚未填写的空格}}
$$

原资料搜索树的一部分：

![37. 解数独](https://file1.kamacoder.com/i/algo/2020111720451790.png)

对于一个空格，候选值最多是：

$$
\{1,2,\dots,9\}
$$

但行、列、九宫格约束会不断缩小候选集合。

如果某个空格没有任何合法数字，当前分支立即失败。

如果所有空格都填完，则整个搜索成功。

因此不需要把“二维递归”当成一种新的递归类型；它仍然只是：

```text
选下一个待决策位置
→ 枚举合法值
→ 递归
→ 失败则撤销
```

## 15. 一张表判断题型

| 问题模型 | 下一层候选范围 | 是否需要 `startIndex` | 是否需要 `used` | 答案通常在哪里 |
| --- | --- | --- | --- | --- |
| 同集合组合 | 当前下标右侧 | 是 | 否 | 指定深度 / 满足条件节点 |
| 可重复组合 | 当前下标及右侧 | 是，递归可传 `i` | 否 | 满足目标条件节点 |
| 多集合组合 | 下一组候选 | 否，用层号 | 否 | 最后一层 |
| 字符串切割 | 当前切割点之后 | 是 | 否 | 切完整个字符串 |
| 子集 | 当前下标右侧 | 是 | 否 | 所有合法节点 |
| 排列 | 每层整个数组 | 否 | 是 | 深度为 $n$ 的节点 |
| 重复元素组合/子集 | 同集合向右 | 是 | 可选 | 同层需要去重 |
| 重复元素排列 | 每层整个数组 | 否 | 是 | 同层还要去重 |
| N 皇后 | 当前行所有列 | 否 | 用列/对角线状态更自然 | 放完所有行 |
| 数独 | 当前空格所有合法数字 | 否 | 行列宫占用表 | 填完所有空格 |

<Callout title="看到新题时，不要先匹配题名，要匹配搜索模型">

两道题即使名字完全不同，只要：

```text
递归层代表同一种决策
候选范围变化方式相同
约束结构相同
答案收集位置相同
```

它们往往就是同一个回溯模型。

</Callout>

## 16. 剪枝的本质：证明某棵子树不可能产生答案

回溯本身是暴力搜索，性能主要依赖两件事：

1. 搜索树本来有多大；
2. 能提前剪掉多少无效子树。

常见剪枝可以归纳为以下几类。

### 可行性剪枝

当前选择已经违反硬约束时，立即停止。

例如：

```text
N 皇后发生列 / 对角线冲突
数独数字与行 / 列 / 宫冲突
递增子序列加入了更小的数
```

这种剪枝通常最基本，也最安全。

### 数量边界

如果剩余候选数量已经不足以完成目标，就不继续搜索。

例如 `77. 组合`：

$$
\text{剩余候选数}<k-|path|
$$

则整棵子树不可能产生长度为 $k$ 的组合。

### 数值边界

当候选具有单调性时，可以根据最小可能值、最大可能值或当前累计值判断是否还有机会达到目标。

例如正数数组排序以后：

```cpp
if (sum + candidates[i] > target) break;
```

因为后面的数只会更大。

### 去重剪枝

如果同一个父节点已经用某个值开启过分支，再用相同值开启一次只会生成重复答案，就可以跳过。

这就是“树层去重”。

### 候选顺序

改变候选尝试顺序有时不会改变理论最坏复杂度，但会显著改变实际搜索量。

例如数独中优先选择候选数字最少的空格（MRV）：

```text
先解决最受约束的位置
```

往往能更早暴露矛盾，从而提前回溯。

## 17. `continue`、`break`、`return` 到底怎么选？

这三个关键字对应不同强度的剪枝。

### `continue`

当前候选不合法，但后面的候选仍可能合法：

```cpp
if (当前 i 不合法) continue;
```

只剪掉一个孩子。

### `break`

当前候选以及后面所有候选都不可能合法：

```cpp
if (排序后当前值已经过大) break;
```

剪掉当前层剩余的一整段兄弟分支。

### `return`

从当前状态出发整棵子树都已经没有继续搜索的意义：

```cpp
if (当前累计值已经超过上限) return;
```

或者题目只需要一个解，已经成功找到：

```cpp
if (dfs(...)) return true;
```

<Callout type="info" title="break 能成立通常需要单调性">

如果后面的候选不一定比当前候选更差，就不能因为当前候选失败而直接 `break`。

所以在总和类问题里，经常先排序再利用：

$$
 a_i\le a_{i+1}\le\cdots
$$

建立这种单调性。

</Callout>

## 18. 复杂度：不要只背“回溯是指数级”

回溯复杂度最容易写得过于粗糙。

更准确的分析方式是分成：

$$
\boxed{\text{搜索状态数} \times \text{每个状态的处理成本} + \text{输出成本}}
$$

而空间复杂度要区分：

- 递归栈；
- 当前路径；
- 辅助状态；
- 最终答案集合。

### 18.1 子集

$n$ 个互不相同元素一共有：

$$
2^n
$$

个子集。

仅遍历状态数量可以看作 $O(2^n)$；如果真的把每个子集复制到结果中，所有答案的总元素数量为：

$$
\sum_{k=0}^{n}k\binom nk=n2^{n-1}
$$

因此显式生成全部子集时更准确的时间复杂度是：

$$
O(n2^n)
$$

不计输出数组，额外空间主要来自递归栈和路径：

$$
O(n)
$$

### 18.2 排列

$n$ 个互不相同元素有：

$$
n!
$$

个排列。

每个排列长度为 $n$，因此仅把所有答案写出来就至少需要：

$$
\Omega(n\cdot n!)
$$

所以生成全部排列通常写作：

$$
O(n\cdot n!)
$$

额外空间不计输出时为：

$$
O(n)
$$

用于递归路径和 `used`。

### 18.3 固定大小组合

如果只生成大小为 $k$ 的组合，答案数量为：

$$
\binom nk
$$

每个答案复制成本为 $O(k)$，因此仅输出答案就需要：

$$
\Omega\left(k\binom nk\right)
$$

使用 $O(2^n)$ 作为宽松上界没有错，但在题目要求更精确时，应优先结合：

$$
\binom nk
$$

分析。

### 18.4 N 皇后

如果每一行最多选择一个尚未使用的列，那么忽略对角线带来的进一步剪枝，候选规模可以粗略看成：

$$
n\cdot(n-1)\cdot\ldots\cdot1=n!
$$

所以常见的搜索上界写作：

$$
O(n!)
$$

实际节点数会因为对角线约束显著减少。

如果合法性判断每次扫描棋盘，还要乘上相应检查成本；使用列和两条对角线占用表后，可以把一次冲突判断降到 $O(1)$。

### 18.5 数独

如果初始有 $m$ 个空格，每个空格最宽松地看最多尝试 9 个数字，则一个非常粗的上界是：

$$
O(9^m)
$$

但这只是最坏情况下的搜索树上界。

真实搜索会受到：

- 行约束；
- 列约束；
- 宫约束；
- 候选顺序；
- MRV 等启发式；

大幅剪枝。

递归深度至多为：

$$
m
$$

因此不计棋盘本身和输出，递归栈为 $O(m)$。

## 19. DFS 和回溯到底是什么关系？

二者经常一起出现，但侧重点不同。

### DFS

强调：

```text
按深度优先顺序遍历状态空间
```

### 回溯

强调：

```text
尝试一个选择以后，如果后续失败，恢复状态并尝试其他选择
```

因此：

$$
\boxed{\text{回溯搜索通常使用 DFS 的遍历顺序，并显式维护“做选择 / 撤销选择”}}
$$

二叉树 DFS 不一定需要显式撤销状态；而排列、N 皇后、数独等题通常需要。

## 20. 为什么有些回溯代码看不到 `pop_back()`？

因为“回溯”不一定表现为手动撤销容器。

例如参数按值传递：

```cpp
dfs(path + x);
```

下一层操作的是新状态，函数返回以后旧状态天然存在。

或者状态通过函数局部变量表达，也可能不需要显式恢复。

但从逻辑上依然发生了：

```text
进入新状态
→ 搜索
→ 返回旧状态
```

所以判断是不是回溯，不应该只看代码里有没有：

```cpp
pop_back()
```

而应该看搜索状态是否会沿一条路径不断做选择，并在失败后恢复到父状态。

## 21. 一套真正通用的回溯分析流程

以后遇到新的回溯题，可以严格按下面顺序分析。

### 第一步：定义搜索状态

问自己：

```text
递归函数进入这一层时，我已经确定了什么？
```

例如：

```text
已经选择的组合
已经切好的字符串片段
已经放置的皇后
已经填写的数独空格
```

### 第二步：定义这一层的候选集合

问：

```text
当前还能做哪些选择？
```

这一步直接决定 `for` 循环范围。

### 第三步：定义下一层状态如何变化

问：

```text
选了候选 i 以后，下一层还能选什么？
```

它决定：

```text
i + 1
还是 i
还是重新从 0 枚举
还是进入下一组候选
```

### 第四步：确定答案收集位置

问：

```text
答案只在叶子节点？
指定深度？
满足某个数值条件时？
还是每个搜索节点都是答案？
```

### 第五步：列出所有硬约束

例如：

```text
不能重复使用下标
和不能超过 target
必须递增
不能同列/同对角线
必须满足行列宫
```

先保证正确性，再考虑优化。

### 第六步：寻找可以证明无解的边界

把每个约束进一步问成：

```text
能不能在进入下一层之前就知道一定失败？
```

如果能，就形成剪枝。

### 第七步：最后再考虑去重与性能

去重时必须明确：

```text
去的是同层重复，还是路径内重复？
```

性能分析则区分搜索量、状态维护成本和输出成本。

## 22. 回溯题最常见的错误清单

做题或调试时，可以按这个顺序检查。

### 错误 1：没有明确递归层代表什么

如果说不清：

```text
第 depth 层到底在决定什么？
```

后面的参数设计通常都会混乱。

### 错误 2：`startIndex` 机械套模板

尤其是：

- 可重复组合忘记传 `i`；
- 排列错误使用 `startIndex`；
- 多集合组合错误地把层号写成 `startIndex`。

### 错误 3：做选择后没有恢复状态

典型表现：

```cpp
path.push_back(x);
dfs(...);
// 忘了 path.pop_back()
```

下一棵兄弟子树就会继承错误状态。

### 错误 4：把树层去重写成全局去重

这会误删合法路径。

### 错误 5：为了相邻去重直接排序，但排序破坏题意

典型就是子序列问题。

### 错误 6：能 `break` 的地方只写 `continue`

结果仍然正确，但会多搜索大量不可能成功的候选。

### 错误 7：不能 `break` 的地方却写了 `break`

如果没有单调性，这会直接漏解。

### 错误 8：只看最终答案，不检查搜索树

当回溯代码出错时，最有效的方法往往不是盯代码，而是手画前两三层搜索树。

<Callout title="调试回溯最有效的三个变量">

打印：

```text
当前递归层 / startIndex
当前 path
当前尝试的候选 i
```

然后观察：

```text
候选范围是否正确？
路径是否正确恢复？
同层重复是否真的被跳过？
```

绝大多数回溯 Bug 都能在搜索树前几层暴露出来。

</Callout>

## 23. 最终统一模板

最后可以把整个专题压缩为下面这份“思维模板”：

```text
backtracking(state):
    如果当前 state 已经形成答案:
        按题意收集 / 返回

    计算当前层 candidates

    for candidate in candidates:
        如果 candidate 违反约束:
            continue / break

        做选择，更新 state

        backtracking(next_state)

        撤销选择，恢复 state
```

真正需要根据题目改变的只有五件事：

$$
\boxed{
\text{state}
+\text{candidates}
+\text{constraints}
+\text{goal}
+\text{restore}
}
$$

这比记住任何一道题的代码都更重要。

## 24. 回溯专题知识地图

原资料最终将整个专题汇总为一张知识图：

![回溯算法专题知识地图](https://file1.kamacoder.com/i/algo/20211030124742.png)

学完这一专题后，建议把所有题目再按下面这条主线重新过一遍：

```text
组合
  ↓
组合剪枝
  ↓
加入总和约束
  ↓
允许重复选择
  ↓
多个集合之间组合
  ↓
字符串切割
  ↓
子集（收集所有节点）
  ↓
重复元素与树层去重
  ↓
排列（每层重新遍历全部候选）
  ↓
图上的路径选择
  ↓
棋盘上的约束满足搜索
```

这条主线背后的变化其实始终只有三件事：

1. **递归层表示什么决策；**
2. **下一层还能选择哪些候选；**
3. **哪些约束能够提前剪枝。**

<Callout title="回溯专题最终结论">

不要把回溯理解成一段固定代码。

应该把它理解成：

$$
\boxed{
\text{把问题展开成搜索树}
\rightarrow
\text{定义每层选择}
\rightarrow
\text{维护路径状态}
\rightarrow
\text{利用约束剪枝}
}
$$

当你能独立画出搜索树的前两三层时，绝大多数回溯题已经解决了一半。

</Callout>
