# 递归的时间与空间复杂度

递归代码通常很短，但“代码短”绝不意味着“运行成本低”。

分析递归时必须同时回答两个不同问题：

1. **时间复杂度**：整个递归过程中一共执行了多少次调用、多少工作？
2. **空间复杂度**：任意时刻最多有多少层递归调用同时压在调用栈中？

这两者一个关注**总调用量**，一个关注**最大同时存活深度**。

<Callout title="最关键的区别" type="info">
递归树可能有指数级数量的节点，但调用栈只保存从根到当前节点的一条路径。因此“总递归次数”和“递归深度”绝不能混为一谈。
</Callout>

---

## 1. 经典例子：朴素递归斐波那契

斐波那契数列定义为：

$$
F_0=0,\qquad F_1=1
$$

以及：

$$
F_n=F_{n-1}+F_{n-2}\quad(n\ge2)
$$

最自然的递归实现是：

```cpp
long long fib(int n) {
    if (n <= 1) {
        return n;
    }

    return fib(n - 1) + fib(n - 2);
}
```

代码只有几行，但效率很差。

---

## 2. 时间复杂度：先看递归树总节点数

当计算 `fib(5)` 时，调用过程可以抽象成一棵递归树：

![递归空间复杂度分析](https://file1.kamacoder.com/i/algo/20210305093200104.png)

其中：

- `fib(5)` 会调用 `fib(4)` 和 `fib(3)`；
- `fib(4)` 又会调用 `fib(3)` 和 `fib(2)`；
- 大量相同子问题被反复计算。

递推式是：

$$
T(n)=T(n-1)+T(n-2)+O(1)
$$

它的增长速度与斐波那契数本身同阶，更精确地说可写成：

$$
T(n)=\Theta(\varphi^n)
$$

其中黄金比例：

$$
\varphi=\frac{1+\sqrt5}{2}\approx1.618
$$

在算法学习中，为了突出它属于指数级，常给一个较宽松的上界：

$$
O(2^n)
$$

<Callout title="为什么常说 O(2^n)" type="tip">
每个非叶节点最多分裂成两个递归调用，所以用满二叉树可得到 $O(2^n)$ 的简单上界；严格地说，朴素斐波那契的调用次数是 $\Theta(\varphi^n)$。
</Callout>

---

## 3. 为什么它会慢：重复子问题

例如 `fib(5)` 中，`fib(3)` 会被计算多次。

继续展开后，`fib(2)`、`fib(1)` 等会被重复得更多。

真正的问题不是“用了递归”，而是：

> 同一个状态被重复求解。

这也是动态规划和记忆化搜索要解决的核心问题。

---

## 4. 不要依赖某台电脑的固定耗时

原始实验中，较大的 $n$ 会迅速使运行时间暴涨。这能直观说明指数复杂度的可怕，但绝不能把某台机器上的毫秒数当作普遍规律。

实际耗时会受到：

- CPU；
- 编译优化；
- 编程语言；
- 函数调用成本；
- 系统负载；
- 编译器实现等因素影响。

真正具有可迁移性的结论是：

$$
\Theta(\varphi^n)
$$

会随着 $n$ 增长呈指数级爆炸。

---

## 5. 朴素递归斐波那契的空间复杂度为什么不是指数级

这是最容易混淆的地方。

虽然递归树有大量节点，但这些节点**不会全部同时存在于调用栈**。

程序执行时会沿一条路径不断深入：

```text
fib(n)
  └─ fib(n-1)
      └─ fib(n-2)
          └─ ...
              └─ fib(1)
```

到达叶子后，再逐层返回，然后处理其他分支。

因此峰值空间取决于树的高度，而不是总节点数。

![递归空间复杂度分析](https://file1.kamacoder.com/i/algo/20210305094749554.png)

最大递归深度约为：

$$
n
$$

每层只保存常数级信息，所以：

$$
S(n)=O(n)
$$

于是朴素递归斐波那契是：

| 指标 | 复杂度 |
| --- | ---: |
| 时间 | $\Theta(\varphi^n)$，常写上界 $O(2^n)$ |
| 递归栈空间 | $O(n)$ |

<Callout title="必须掌握" type="warning">
递归树“节点总数”决定时间量级；递归树“最大深度”通常决定调用栈空间量级。
</Callout>

---

## 6. 一个实用近似公式

如果每层递归栈帧需要 $g(n)$ 级别的额外空间，最大递归深度是 $d(n)$，在各层空间近似同阶时，可以粗略估计：

$$
S(n)=O(g(n)\cdot d(n))
$$

最常见的是每层只用常数空间：

$$
g(n)=O(1)
$$

于是：

$$
S(n)=O(d(n))
$$

但这只是一个方便的分析模板，不应机械套用。如果不同层分配的数据规模不同，应把当前调用链上同时存活的空间求和。

---

## 7. 把双分支递归改成单分支递归

可以携带前两个斐波那契数，使每次递归只进入一个子问题：

```cpp
long long fibTail(long long first, long long second, int n) {
    if (n <= 0) return 0;
    if (n <= 2) return 1;

    if (n == 3) {
        return first + second;
    }

    return fibTail(second, first + second, n - 1);
}
```

每次只调用一次：

$$
T(n)=T(n-1)+O(1)
$$

所以：

$$
T(n)=O(n)
$$

递归深度仍然约为 $n$：

$$
S(n)=O(n)
$$

因此：

| 实现 | 时间 | 辅助空间 |
| --- | ---: | ---: |
| 朴素双递归 | $\Theta(\varphi^n)$ | $O(n)$ |
| 单分支递归 | $O(n)$ | $O(n)$ |

时间大幅下降了，但栈空间没有下降。

---

## 8. 尾递归不等于一定是 $O(1)$ 栈空间

上面的单分支写法看起来像尾递归。

某些语言或编译器可能进行**尾调用优化**，把当前栈帧复用，从而降低栈空间。

但不能在所有环境中默认这一点：

- C++ 标准并不保证尾调用优化；
- Java 一般不做通用尾递归消除；
- Python 也不进行尾递归优化。

因此在普通算法分析中，若没有明确保证优化，应仍按：

$$
O(n)
$$

调用栈空间计算。

## 9. 迭代斐波那契：时间 O(n)，空间 O(1)

实际上完全不需要递归栈：

```cpp
long long fibIterative(int n) {
    if (n <= 1) {
        return n;
    }

    long long prev2 = 0;
    long long prev1 = 1;

    for (int i = 2; i <= n; ++i) {
        long long current = prev1 + prev2;
        prev2 = prev1;
        prev1 = current;
    }

    return prev1;
}
```

只保存最近两个状态，因此：

$$
T(n)=O(n)
$$

$$
S(n)=O(1)
$$

![递归的空间复杂度分析](https://file1.kamacoder.com/i/algo/20210305095227356.png)

<Callout title="代码简洁 ≠ 性能最优" type="info">
递归往往能让定义和代码非常自然，但是否使用递归，要结合时间复杂度、栈深度以及可读性一起判断。
</Callout>

## 10. 记忆化搜索：消除重复计算

另一种思路是保留递归形式，但缓存已经求过的状态：

```cpp
long long fibMemo(int n, vector<long long>& memo) {
    if (n <= 1) {
        return n;
    }

    if (memo[n] != -1) {
        return memo[n];
    }

    memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
    return memo[n];
}
```

每个 $n$ 只真正计算一次，因此时间复杂度降为：

$$
O(n)
$$

缓存数组需要：

$$
O(n)
$$

递归栈最深也是：

$$
O(n)
$$

所以总体辅助空间仍为：

$$
O(n)
$$

这体现了一个非常重要的优化思想：

> 用空间换时间。

## 11. 递归二分查找：时间和空间都是对数级吗

递归二分查找如下：

```cpp
int binarySearch(
    const vector<int>& nums,
    int left,
    int right,
    int target
) {
    if (left > right) {
        return -1;
    }

    int mid = left + (right - left) / 2;

    if (nums[mid] == target) {
        return mid;
    }

    if (nums[mid] > target) {
        return binarySearch(nums, left, mid - 1, target);
    }

    return binarySearch(nums, mid + 1, right, target);
}
```

每次只进入一个子区间，而且区间长度减半。

递推式：

$$
T(n)=T(n/2)+O(1)
$$

因此：

$$
T(n)=O(\log n)
$$

递归深度满足：

$$
\frac{n}{2^h}\approx1
$$

所以：

$$
h=O(\log n)
$$

每层只需要常数空间，因此：

$$
S(n)=O(\log n)
$$

---

## 12. 为什么数组本身不会在每一层都复制

在上面的 C++ 函数中：

```cpp
const vector<int>& nums
```

是引用参数。

每次递归只传递对同一数组的引用，以及新的 `left`、`right` 值，并不会复制完整数组。

所以每层额外空间仍是：

$$
O(1)
$$

如果错误地写成按值传递：

```cpp
int binarySearch(vector<int> nums, ...)
```

每次调用都可能复制整个数组，这不仅增加空间，也增加时间成本。

<Callout title="语言细节会影响复杂度" type="warning">
分析函数参数时必须知道它究竟是引用、指针、共享对象，还是完整复制。不能仅凭参数“看起来是数组”就判断空间复杂度。
</Callout>

## 13. 迭代二分查找把辅助空间降到 O(1)

同样的二分查找可以不用递归：

```cpp
int binarySearchIterative(const vector<int>& nums, int target) {
    int left = 0;
    int right = static_cast<int>(nums.size()) - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;

        if (nums[mid] == target) {
            return mid;
        }

        if (nums[mid] < target) {
            left = mid + 1;
        } else {
            right = mid - 1;
        }
    }

    return -1;
}
```

时间复杂度仍然是：

$$
O(\log n)
$$

但不再需要递归调用栈，所以辅助空间为：

$$
O(1)
$$

---

## 14. 二叉树递归：空间看树高，不直接看节点总数

例如深度优先遍历：

```cpp
void dfs(TreeNode* node) {
    if (node == nullptr) return;

    dfs(node->left);
    dfs(node->right);
}
```

假设树共有 $n$ 个节点。

每个节点访问一次，所以时间复杂度：

$$
O(n)
$$

但递归栈只和树高 $h$ 有关：

$$
O(h)
$$

若树接近平衡：

$$
h=O(\log n)
$$

若退化成链：

$$
h=O(n)
$$

因此同一段 DFS 代码的最坏空间复杂度是：

$$
O(n)
$$

而在平衡树上则约为：

$$
O(\log n)
$$

---

## 15. 分支数多，并不意味着栈空间等于总节点数

假设一个函数每次递归调用两个子问题：

```cpp
solve(left);
solve(right);
```

通常执行顺序是：

1. 先深入 `left`；
2. `left` 完全返回；
3. 再深入 `right`。

因此左右两棵子树不会把全部栈帧同时压入调用栈。

空间主要看：

$$
\text{根到最深叶子的最大路径长度}
$$

也就是递归深度。

---

## 16. 标准分析流程

### 写出递推式或递归树

先确定每次调用产生几个子问题，子问题规模是多少。

### 求总调用量

它决定时间复杂度的重要部分。

### 求最大递归深度

不要拿“总节点数”代替“最大深度”。

### 判断每层栈帧大小

检查局部数组、复制参数、临时容器等是否随问题规模增长。

### 分别给出时间与空间复杂度

不要只写一个“大 O”就结束。

---

## 17. 高频模型速查

| 递归模型 | 时间复杂度 | 栈空间 |
| --- | ---: | ---: |
| `solve(n - 1)` | $O(n)$ | $O(n)$ |
| 单次 `solve(n / 2)` | $O(\log n)$ | $O(\log n)$ |
| 两次 `solve(n / 2)`，每层常数工作 | $O(n)$ | $O(\log n)$ |
| 朴素 Fibonacci | $\Theta(\varphi^n)$ | $O(n)$ |
| 平衡二叉树 DFS | $O(n)$ | $O(\log n)$ |
| 最坏退化树 DFS | $O(n)$ | $O(n)$ |

注意第三行特别能说明：

$$
\text{总调用次数}\ne\text{最大调用深度}
$$

例如：

$$
T(n)=2T(n/2)+O(1)
$$

总节点数是 $O(n)$，但树高只有 $O(\log n)$，所以若每层栈空间为常数，则递归栈仍是 $O(\log n)$。

## 18. 多语言实现：迭代斐波那契

### C++

```cpp
long long fibonacci(int n) {
    if (n <= 1) {
        return n;
    }

    long long prev2 = 0;
    long long prev1 = 1;

    for (int i = 2; i <= n; ++i) {
        long long current = prev1 + prev2;
        prev2 = prev1;
        prev1 = current;
    }

    return prev1;
}
```

### Java

```java
static long fibonacci(int n) {
    if (n <= 1) {
        return n;
    }

    long prev2 = 0;
    long prev1 = 1;

    for (int i = 2; i <= n; ++i) {
        long current = prev1 + prev2;
        prev2 = prev1;
        prev1 = current;
    }

    return prev1;
}
```

### Python

```python
def fibonacci(n: int) -> int:
    if n <= 1:
        return n

    prev2 = 0
    prev1 = 1

    for _ in range(2, n + 1):
        current = prev1 + prev2
        prev2 = prev1
        prev1 = current

    return prev1
```

## 总结

分析递归时，最好把下面两句话分开记：

> **时间复杂度看整棵递归树完成了多少总工作。**

> **调用栈空间看任意时刻最长有多少层递归同时存在。**

因此，朴素斐波那契虽然需要指数级数量的调用：

$$
\Theta(\varphi^n)
$$

但最大调用栈深度只有：

$$
O(n)
$$

而递归二分查找每次规模减半，所以时间和栈空间都为：

$$
O(\log n)
$$

进一步改成迭代二分后，时间仍是：

$$
O(\log n)
$$

辅助空间却可以降为：

$$
O(1)
$$

这正体现了递归分析最重要的原则：**总工作量与最大递归深度是两个独立维度。**
