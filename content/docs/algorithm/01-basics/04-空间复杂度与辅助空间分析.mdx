# 空间复杂度与辅助空间分析

时间复杂度回答的是：**输入规模增大时，算法需要做多少工作？**

空间复杂度回答的是：**输入规模增大时，算法运行过程中额外占用的内存如何增长？**

通常记为：

$$
S(n)=O(f(n))
$$

和时间复杂度一样，我们关心的是增长数量级，而不是精确到多少字节。

<Callout title="先分清三个概念" type="info">
“程序文件有多大”“某次运行实际用了多少 MB”“空间复杂度是多少”是三个不同问题。算法分析主要讨论内存需求随输入规模 $n$ 的增长趋势。
</Callout>

---

## 1. 空间复杂度到底统计什么

一个程序运行时可能占用：

- 输入数据本身；
- 局部变量；
- 动态申请的数组、链表、哈希表等；
- 函数调用栈；
- 语言运行时和容器内部维护的额外结构。

算法题中常见两种统计口径。

### 总空间复杂度

把输入自身所占空间也计入。

例如输入一个长度为 $n$ 的数组，即使算法完全原地处理，总空间也至少是：

$$
O(n)
$$

### 辅助空间复杂度

只统计**算法为了完成计算额外申请的空间**。

因此，同一个原地数组算法经常会说：

$$
O(1)\text{ extra space}
$$

也就是辅助空间为 $O(1)$。

<Callout title="刷题时最常用的口径" type="tip">
LeetCode、面试和竞赛里说“空间复杂度”时，经常实际上指辅助空间。遇到严格讨论时，要说明自己采用的是哪一种口径。
</Callout>

---

## 2. 为什么不能把大 O 当成精确内存

空间复杂度只描述增长趋势。

即使两段程序都是 $O(n)$，它们实际内存仍可能差很多，例如：

```cpp
vector<int> a(n);        // 大约存 n 个 int
vector<long long> b(n);  // 每个元素通常更大
```

两者辅助空间都是：

$$
O(n)
$$

但常数因子不同。

此外，真实内存还受到以下因素影响：

- 对象头、指针和容器元数据；
- 内存对齐；
- 容器容量通常大于当前元素数量；
- 分配器实现；
- 垃圾回收器；
- 编译器优化；
- 操作系统和语言运行时。

因此，空间复杂度适合做**数量级判断**，内存限制则还要进一步估算实际字节数。

---

## 3. $O(1)$ 空间：空间不随 $n$ 增长

看下面的代码：

```cpp
int sum = 0;
for (int i = 0; i < n; ++i) {
    sum += i;
}
```

无论 $n$ 多大，始终只额外使用少量变量：

```text
sum
 i
 n
```

所以辅助空间复杂度是：

$$
O(1)
$$

注意这里循环执行了 $n$ 次，但**循环次数和空间复杂度没有直接关系**。

<Callout title="常见误区" type="warning">
“有一层 for 循环，所以空间是 $O(n)$”是错误的。只有当循环过程中累计保留的内存随 $n$ 增长时，空间复杂度才会增长。
</Callout>

---

## 4. $O(n)$ 空间：保存长度与输入规模成正比的数据

例如：

```cpp
vector<int> a(n);

for (int i = 0; i < n; ++i) {
    a[i] = i;
}
```

数组保存 $n$ 个元素，因此：

$$
S(n)=O(n)
$$

这里后面的循环并没有继续累计申请 $n$ 份空间，所以整体仍然是 $O(n)$，而不是 $O(n^2)$。

---

## 5. 多个数组的空间复杂度可以直接相加吗

可以先写出总量，再保留最高阶。

```cpp
vector<int> a(n);
vector<int> b(n);
vector<int> c(2 * n);
```

总元素数量约为：

$$
n+n+2n=4n
$$

所以：

$$
S(n)=O(4n)=O(n)
$$

如果还有一个 $n\times n$ 的二维数组：

```cpp
vector<vector<int>> dp(n, vector<int>(n));
```

那么：

$$
S(n)=O(n^2)
$$

此时即使另外还有若干 $O(n)$ 数组，整体仍取最高阶：

$$
O(n^2+n)=O(n^2)
$$

---

## 6. 循环里申请空间，要看“是否同时存在”

这一点非常重要。

### 情况 A：每轮申请后立即释放

```cpp
for (int i = 0; i < n; ++i) {
    vector<int> temp(n);
    // 使用 temp
}
```

如果 `temp` 在每轮结束后销毁，那么任意时刻最多只有一个长度为 $n$ 的数组存在。

因此峰值辅助空间是：

$$
O(n)
$$

而不是 $O(n^2)$。

### 情况 B：每轮都保存下来

```cpp
vector<vector<int>> all;

for (int i = 0; i < n; ++i) {
    all.push_back(vector<int>(n));
}
```

最终保留 $n$ 个长度为 $n$ 的数组：

$$
n\times n=n^2
$$

所以：

$$
O(n^2)
$$

<Callout title="空间分析看峰值，而不是累计申请量" type="tip">
时间复杂度会累计每次操作；空间复杂度通常关注程序运行过程中某个时刻同时存活的最大内存量。
</Callout>

---

## 7. 顺序执行的两段代码，不一定空间相加

考虑：

```cpp
{
    vector<int> a(n);
    // ...
}

{
    vector<int> b(n * n);
    // ...
}
```

如果第一段结束后 `a` 已经释放，第二段才申请 `b`，峰值空间约为：

$$
\max(O(n),O(n^2))=O(n^2)
$$

而不是把两者机械相加后再分析。

只有两个结构在同一时间都存在时，才需要同时计入峰值。

## 8. 递归为什么会占额外空间

每次函数调用通常需要一个栈帧，用来保存：

- 参数；
- 局部变量；
- 返回地址；
- 某些寄存器状态等。

例如：

```cpp
void dfs(int n) {
    if (n == 0) return;
    dfs(n - 1);
}
```

递归调用链为：

```text
dfs(n)
  └─ dfs(n-1)
      └─ dfs(n-2)
          └─ ...
              └─ dfs(0)
```

最大同时存在约 $n$ 层栈帧。

若每层占用常数空间：

$$
O(1)
$$

总栈空间就是：

$$
O(n)
$$

---

## 9. $O(\log n)$ 空间最常见在哪里

典型场景是“每次问题规模减半”的递归。

例如递归二分查找：

```cpp
int binarySearch(const vector<int>& nums, int left, int right, int target) {
    if (left > right) return -1;

    int mid = left + (right - left) / 2;

    if (nums[mid] == target) return mid;

    if (nums[mid] > target) {
        return binarySearch(nums, left, mid - 1, target);
    }

    return binarySearch(nums, mid + 1, right, target);
}
```

每次递归把搜索区间缩小为原来的一半。

若递归深度为 $h$：

$$
\frac{n}{2^h}\approx 1
$$

因此：

$$
h\approx \log_2n
$$

每层栈帧是 $O(1)$，所以：

$$
S(n)=O(\log n)
$$

## 10. 参数传递会不会复制整个数组

这取决于语言和函数签名。

### C++：按引用传递

```cpp
void solve(const vector<int>& nums) {
    // ...
}
```

不会在每次调用时复制整个 `vector` 数据。

### C++：按值传递

```cpp
void solve(vector<int> nums) {
    // ...
}
```

这会构造参数副本。若递归深度很大，内存与时间成本都会明显增加。

因此不要只看到“参数里有一个长度为 $n$ 的数组”，就立即断言每层递归是 $O(n)$；必须先判断参数究竟是复制还是共享/引用。

## 11. 原地算法（in-place）是什么意思

所谓原地算法，通常表示算法只使用常数级或很少的额外空间，并直接修改输入结构。

例如原地交换数组元素：

```cpp
void reverseArray(vector<int>& nums) {
    int left = 0;
    int right = static_cast<int>(nums.size()) - 1;

    while (left < right) {
        swap(nums[left], nums[right]);
        ++left;
        --right;
    }
}
```

辅助空间只有几个变量：

$$
O(1)
$$

即使输入数组本身占 $O(n)$，我们通常仍称它为空间复杂度 $O(1)$ 的原地算法——这里指的是**辅助空间**。

---

## 12. 返回结果本身算不算额外空间

这也取决于题目口径。

例如要求返回一个长度为 $n$ 的新数组：

```cpp
vector<int> buildSquares(const vector<int>& nums) {
    vector<int> result(nums.size());
    // ...
    return result;
}
```

如果把输出数组计入，则至少需要：

$$
O(n)
$$

有些题目会明确说：

> 返回结果所需空间不计入额外空间。

此时分析的是除了输出之外的辅助空间。

<Callout title="答题建议" type="info">
遇到“空间复杂度是多少”这类问题，最好补一句：若不计返回结果，辅助空间为……；若计入输出，总空间为……。
</Callout>

## 13. 容器容量与实际内存

以动态数组为例，`size()` 和 `capacity()` 并不一定相同。

```cpp
vector<int> nums;
for (int i = 0; i < n; ++i) {
    nums.push_back(i);
}
```

为了避免每次插入都重新分配，动态数组通常会按一定倍数扩容。因此真实容量可能暂时大于 $n$。

但只要容量仍与 $n$ 同数量级：

$$
capacity=O(n)
$$

空间复杂度依然是：

$$
O(n)
$$

大 O 不关心这种常数倍差异。

## 14. 如何把复杂度换算成内存数量级

在竞赛和 OJ 中，还需要估算是否超过内存限制。

例如一个包含 $10^7$ 个 `int` 的连续数组。

若一个 `int` 按 4 Byte 估算：

$$
10^7\times4\text{ B}=4\times10^7\text{ B}
$$

约为几十 MB。

如果是：

$$
10^8
$$

个 `int`，内存就会上升到数百 MB 的量级。

<Callout title="复杂度与工程估算要配合" type="warning">
$O(n)$ 只说明增长趋势。若 $n=10^8$，即使是线性空间也可能直接 MLE（Memory Limit Exceeded）。
</Callout>

## 15. 分析空间复杂度的标准流程

### 找出随输入规模增长的数据结构

例如数组、矩阵、哈希表、队列、递归栈等。

### 判断这些空间是否会同时存在

空间复杂度看峰值，不要把已经释放的内存重复累计。

### 分析递归最大深度

递归时尤其要算调用栈。

### 判断参数是否复制

按值、按引用、切片复制、字符串不可变等语言行为可能改变空间使用。

### 最后保留最高阶

例如：

$$
O(n^2+n+1)=O(n^2)
$$

## 16. 常见空间复杂度速查

| 代码特征 | 辅助空间复杂度 |
| --- | ---: |
| 固定数量标量变量 | $O(1)$ |
| 长度为 $n$ 的数组 | $O(n)$ |
| $n\times n$ 矩阵 | $O(n^2)$ |
| 深度为 $n$ 的递归 | $O(n)$ |
| 每次规模减半的单支递归 | $O(\log n)$ |
| BFS 最坏保存一层大量节点 | 取决于最大队列规模 |
| 哈希表保存 $n$ 个元素 | $O(n)$ |
| 原地双指针 | 通常 $O(1)$ |

## 17. 多语言示例：原地反转数组



```cpp tab="C++"
void reverseArray(vector<int>& nums) {
    int left = 0;
    int right = static_cast<int>(nums.size()) - 1;

    while (left < right) {
        swap(nums[left], nums[right]);
        ++left;
        --right;
    }
}
```



```java tab="Java"
static void reverseArray(int[] nums) {
    int left = 0;
    int right = nums.length - 1;

    while (left < right) {
        int temp = nums[left];
        nums[left] = nums[right];
        nums[right] = temp;
        left++;
        right--;
    }
}
```



```python tab="Python"
def reverse_array(nums: list[int]) -> None:
    left = 0
    right = len(nums) - 1

    while left < right:
        nums[left], nums[right] = nums[right], nums[left]
        left += 1
        right -= 1
```

以上实现都只额外使用常数个变量，所以辅助空间为：

$$
O(1)
$$

## 总结

空间复杂度的核心不是“程序一共申请过多少内存”，而是：

> **输入规模为 $n$ 时，程序运行期间同时需要保留的最大额外空间如何增长。**

分析时重点检查：

- 动态数组、矩阵和哈希表等容器；
- 是否同时存活；
- 递归调用栈深度；
- 参数是否发生复制；
- 输出空间是否计入。

最常见的数量级仍然是：

$$
O(1),\quad O(\log n),\quad O(n),\quad O(n^2)
$$

掌握空间复杂度之后，再分析递归就不能只看“递归调用了多少次”，还必须看**最大同时存在多少层调用栈**。这正是下一篇的重点。
