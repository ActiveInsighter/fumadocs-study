# 图论理论基础

图论研究的核心不是“画图”，而是描述**对象之间的连接关系**。

只要一个问题中出现了“节点”和“节点之间的关系”，就应该警觉它可能可以抽象成图：城市与道路、用户与关注关系、课程与先修关系、网页与超链接、服务器与网络连接，甚至二维网格里的岛屿，都可以转换成图论问题。

<Callout type="info" title="这一篇要建立的主线">

先不要急着记 DFS、BFS、Dijkstra 等算法。图论学习最重要的第一步，是先回答四个问题：

**图是什么 → 图有哪些性质 → 图怎样存进程序 → 不同存储方式适合什么算法。**

后面的搜索、并查集、最小生成树、拓扑排序、最短路，本质上都是在这套表示之上继续工作。

</Callout>

## 1. 图到底是什么

一个图通常记作：

$$
G=(V,E)
$$

其中：

- $V$ 是顶点集合（Vertex Set）；
- $E$ 是边集合（Edge Set）。

如果有 $n$ 个顶点、$m$ 条边，通常写成：

$$
|V|=n,\qquad |E|=m
$$

例如：

```text
V = {1, 2, 3, 4}
E = {(1,2), (1,3), (3,4)}
```

表示图中有四个节点，并存在三条连接关系。

<Cards>
  <Card title="顶点 Vertex">
    表示问题中的对象，例如城市、课程、用户、网格中的陆地格子。
  </Card>
  <Card title="边 Edge">
    表示对象之间的关系，例如道路、依赖、关注、可达关系。
  </Card>
  <Card title="权值 Weight">
    如果一条边还带有距离、时间、费用等数值，就称为带权边。
  </Card>
</Cards>

一个图可以只有一个节点，也可以没有任何节点或边。算法题中更常见的是有限图，即 $V$、$E$ 都是有限集合。

## 2. 有向图、无向图与带权图

### 2.1 有向图

如果边具有方向，例如 $u$ 可以到 $v$，但不一定能从 $v$ 回到 $u$，就是**有向图**。

记作：

$$
u \to v
$$

![](https://file1.kamacoder.com/i/algo/20240510195737.png)

在程序中，一条有向边 `u v` 通常只加入一个方向：

```cpp
graph[u].push_back(v);
```

### 2.2 无向图

如果边没有方向，$u$ 与 $v$ 的连接是双向的，就是**无向图**。

记作：

$$
u-v
$$

![](https://file1.kamacoder.com/i/algo/20240510195451.png)

使用邻接表时，一条无向边通常需要存两次：

```cpp
graph[u].push_back(v);
graph[v].push_back(u);
```

<Callout type="warn" title="无向边不是两条不同的边">

数学上，$u-v$ 仍然只是一条无向边；只是为了方便程序从任意一端枚举邻居，邻接表会把它分别记录在 `graph[u]` 和 `graph[v]` 中。

因此无向图虽然邻接表中会出现 $2m$ 个邻接项，但边数仍然是 $m$。

</Callout>

### 2.3 带权图

如果每条边还有一个权值 $w$，可以写成：

$$
u \xrightarrow{w} v
$$

![](https://file1.kamacoder.com/i/algo/20240510195821.png)

例如道路问题中：

- 节点：城市；
- 边：道路；
- 权值：道路长度。

这类图是 Dijkstra、Bellman-Ford、Floyd、Prim、Kruskal 等算法的基础。

---

## 3. 度：一个节点连接了多少条边

### 3.1 无向图中的度

无向图中，与节点 $v$ 相连的边数称为该节点的**度**，记作：

$$
\deg(v)
$$

例如下图中，节点 4 的度为 5，节点 6 的度为 3。

![](https://file1.kamacoder.com/i/algo/20240511115029.png)

无向图有一个非常重要的结论——**握手定理**：

$$
\sum_{v\in V}\deg(v)=2|E|
$$

原因很简单：每条无向边都有两个端点，因此在所有节点度数之和中恰好被统计两次。

由此还能得到：**度数为奇数的节点个数一定是偶数。**

### 3.2 有向图中的入度和出度

有向图中需要区分：

- **出度**：从该节点出发的边数；
- **入度**：指向该节点的边数。

例如：

![](https://file1.kamacoder.com/i/algo/20240511115235.png)

图中节点 3 的入度为 2、出度为 1；节点 1 的入度为 0、出度为 2。

对整个有向图，有：

$$
\sum_{v\in V}\operatorname{indeg}(v)=|E|
$$

以及：

$$
\sum_{v\in V}\operatorname{outdeg}(v)=|E|
$$

因为每条有向边都恰好贡献一次入度和一次出度。

<Callout title="度在算法里有什么用">

“度”不是纯理论概念。

- 拓扑排序会持续寻找入度为 $0$ 的节点；
- 欧拉路径与欧拉回路会直接判断节点度数；
- 邻接表中 `graph[u].size()` 往往就对应某种出度或无向图中的度。

</Callout>

## 4. 路径、环与简单路径

如果依次经过：

$$
v_0,v_1,v_2,\dots,v_k
$$

并且相邻节点之间都有边，就形成一条路径。

### 路径长度

在无权图中，通常把经过的边数称为路径长度：

$$
\text{length}=k
$$

在带权图中，“路径代价”通常是经过边的权值之和：

$$
\operatorname{cost}=\sum_{i=0}^{k-1} w(v_i,v_{i+1})
$$

### 简单路径

如果一条路径中没有重复顶点，就称为**简单路径**。

这个概念对“枚举所有路径”尤其重要。若图中存在环而又允许无限重复走环，那么路径数量可能无限，因此题目通常会限定：

- 图是 DAG（有向无环图）；或
- 只允许简单路径；或
- 每个节点只能访问一次。

### 环

如果一条路径最终回到起点，就形成环。

后面很多问题都在检测环：

- 有向图拓扑排序失败意味着存在环；
- 并查集可以检测无向图加边时是否形成环；
- DFS 的递归栈可以检测有向图中的环。

## 5. 连通性：节点之间能不能到达

图论里经常问的不是“有没有直接边”，而是：**能不能经过若干条边最终到达。**

这就是连通性的核心。

### 5.1 无向图中的连通图

如果无向图中任意两个节点之间都存在路径，则称为**连通图**。

![](https://file1.kamacoder.com/i/algo/20240511102351.png)

如果至少存在两个节点无法互相到达，就不是连通图：

![](https://file1.kamacoder.com/i/algo/20240511102449.png)

例如图中节点 1 无法到达节点 4，因此整个图非连通。

### 5.2 有向图中的强连通

有向图中，“$u$ 能到 $v$”和“$v$ 能到 $u$”是两件不同的事。

因此有向图要求任意两个节点都能够**相互到达**时，才称为**强连通图**。

下面这个图看起来节点之间都有连接，但并不是强连通图：

![](https://file1.kamacoder.com/i/algo/20240511104531.png)

例如节点 1 可以到节点 5，但节点 5 无法沿有向边返回节点 1。

下面这样的图才满足强连通：

![](https://file1.kamacoder.com/i/algo/20240511113101.png)

<Callout type="info" title="不要把弱连接看成强连通">

有向图中判断强连通时，不能把箭头忽略掉。

“画面上连在一起”不等于“沿边方向可以互相到达”。

</Callout>

## 6. 连通分量与强连通分量

### 6.1 连通分量

无向图中的**极大连通子图**称为一个连通分量。

![](https://file1.kamacoder.com/i/algo/20240511111559.png)

图中：

- 节点 `1、2、5` 构成一个连通分量；
- 节点 `3、4、6` 构成另一个连通分量。

关键在“**极大**”。

例如只取节点 `3、4`，虽然两者相互可达，但还能加入节点 `6` 而保持连通，因此 `{3,4}` 不是一个完整的连通分量。

### 6.2 强连通分量

有向图中的**极大强连通子图**称为强连通分量（Strongly Connected Component，SCC）。

![](https://file1.kamacoder.com/i/algo/20240511112951.png)

理解“强连通分量”时同时检查两个条件：

1. 子图内部任意两点可以相互到达；
2. 已经不能继续加入更多节点并保持这一性质。

<Callout title="为什么连通分量非常重要">

后面的“岛屿数量”本质上就是：把陆地格子看成节点，相邻陆地之间连边，然后统计这个无向图有多少个连通分量。

因此很多看似是二维矩阵的问题，实际就是图论中的连通性问题。

</Callout>

## 7. 图怎样存进程序

最常见的三种方式是：

1. 边集（Edge List）；
2. 邻接矩阵（Adjacency Matrix）；
3. 邻接表（Adjacency List）。

它们没有绝对优劣，关键取决于后续算法需要进行什么操作。

## 8. 边集：直接保存每一条边

最直接的方式，就是把每条边保存下来。

例如：

![](https://file1.kamacoder.com/i/algo/20240511112951.png)

可以把每条有向边保存成：

```text
from  to
6     7
7     8
...
```

示意图：

![](https://file1.kamacoder.com/i/algo/20250110114348.png)

带权图则保存：

```cpp
struct Edge {
    int u;
    int v;
    int w;
};

vector<Edge> edges;
```

### 优点

- 结构非常直接；
- 遍历“所有边”方便；
- 很适合 Kruskal、Bellman-Ford 一类以边为核心的算法。

### 缺点

如果想从节点 $u$ 快速找到所有邻居，就必须扫描大量边。

因此它通常不适合作为 DFS / BFS 的主要存储结构。

<Callout type="info" title="记忆方式">

**边集擅长“枚举所有边”，邻接表擅长“枚举某个点的邻居”。**

这句话对后续算法选型非常有用。

</Callout>

---

## 9. 邻接矩阵

邻接矩阵使用二维数组表示节点之间的连接关系。

如果图有 $n$ 个节点，就申请一个 $n\times n$ 的矩阵。

例如：

$$
graph[u][v]=1
$$

表示存在边 $u\to v$。

如果是带权图，则可以写成：

$$
graph[u][v]=w
$$

表示从 $u$ 到 $v$ 的边权为 $w$。

![](https://file1.kamacoder.com/i/algo/20240222110025.png)

无向图的矩阵关于主对角线对称：

$$
graph[u][v]=graph[v][u]
$$

### 复杂度

| 操作 | 邻接矩阵 |
| --- | ---: |
| 空间 | $O(V^2)$ |
| 判断 $u$ 与 $v$ 是否直接相连 | $O(1)$ |
| 枚举节点 $u$ 的所有邻居 | $O(V)$ |
| 遍历整张图的潜在边位置 | $O(V^2)$ |

### 适合什么情况

邻接矩阵更适合：

- 顶点数不大；
- 图非常稠密；
- 经常需要快速判断任意两点是否直接相连；
- Floyd 这类天然基于矩阵状态的算法。

### 常见初始化陷阱

带权图中不能简单把“没有边”统一记为 `0`，因为边权本身可能就是 `0`。

最短路中更常见的初始化是：

```cpp
const long long INF = 4e18;
vector<vector<long long>> graph(n + 1, vector<long long>(n + 1, INF));

for (int i = 1; i <= n; ++i) {
    graph[i][i] = 0;
}
```

此时：

- `0` 表示节点到自身距离；
- `INF` 表示当前没有已知边；
- 实际权值填真实值。

## 10. 邻接表

邻接表只保存**实际存在的边**。

![](https://file1.kamacoder.com/i/algo/20240223103713.png)

例如：

```cpp
vector<vector<int>> graph(n + 1);

graph[1].push_back(3);
graph[1].push_back(5);
graph[2].push_back(4);
```

则 `graph[u]` 中保存从节点 $u$ 可以直接到达的所有邻居。

### 复杂度

对邻接表来说：

| 操作 | 邻接表 |
| --- | ---: |
| 空间 | $O(V+E)$ |
| 枚举节点 $u$ 的邻居 | $O(\deg(u))$ |
| 判断 $u$ 与 $v$ 是否直接相连 | 一般为 $O(\deg(u))$ |
| DFS / BFS 遍历整张图 | $O(V+E)$ |

有向图中，$\deg(u)$ 在这里通常更准确地理解为出度。

对于无向图，每条边会被存入两个节点的邻接表，因此所有邻接项总数是 $2E$，但复杂度仍记作：

$$
O(V+E)
$$

因为常数 $2$ 在渐进复杂度中会被忽略。

### 为什么邻接表最常见

现实算法题中大量图是稀疏图：

$$
E\ll V^2
$$

这时邻接表既节省空间，又能快速枚举当前节点的邻居，因此特别适合：

- DFS；
- BFS；
- 拓扑排序；
- Dijkstra 堆优化；
- Prim 堆优化；
- 大量连通性问题。

---

## 11. 三种存储方式怎么选

| 需求 | 更自然的选择 | 原因 |
| --- | --- | --- |
| 高频判断任意两点是否有边 | 邻接矩阵 | 查询 $O(1)$ |
| 稀疏图 DFS / BFS | 邻接表 | 枚举邻居高效 |
| Kruskal | 边集 | 需要按边权排序全部边 |
| Bellman-Ford | 边集 | 核心操作是反复松弛所有边 |
| Floyd | 邻接矩阵 | 状态本身就是任意两点距离 |
| 拓扑排序 | 邻接表 + 入度数组 | 一边删点，一边更新邻居入度 |

<Callout type="warn" title="不要把“存储结构”背成固定模板">

例如最短路不是永远使用邻接表：

- Dijkstra 堆优化通常使用邻接表；
- Bellman-Ford 很适合直接保存边集；
- Floyd 通常使用距离矩阵。

真正应该记住的是：**算法每一步需要高效执行什么操作。**

</Callout>

## 12. DFS 与 BFS 是“搜索方式”，不是某种图结构

图的遍历主要有两类基础方法：

- 深度优先搜索 DFS；
- 广度优先搜索 BFS。

它们并不是图专属算法。

在二叉树中：

- 递归式的前序 / 中序 / 后序遍历，本质上体现了 DFS；
- 层序遍历，本质上就是 BFS。

到了图论中，只是“孩子节点”变成了“邻接节点”。

### DFS 的直觉

沿着一个方向不断向深处搜索，走不下去后再回退。

典型工具：

- 递归调用栈；
- 显式栈。

### BFS 的直觉

先访问距离起点一层的节点，再访问下一层。

典型工具：

- 队列。

如果用邻接表存图，那么一次完整 DFS / BFS 通常都是：

$$
O(V+E)
$$

因为每个节点和每条边只需要被有限次访问。

## 13. 一个很重要的树与图关系

树可以看作一种特殊的无向图。

对于一个有 $V$ 个节点的无向图，下面三个性质中任意两个成立，都能推出第三个：

1. 图连通；
2. 图无环；
3. 边数为 $V-1$。

因此树满足：

$$
E=V-1
$$

这也是为什么“图论”和“二叉树 / 树”之间有大量相似的搜索思想。

但图与树相比多了一个关键风险：**图可能存在环。**

树中从父节点一路向下天然不会回到之前节点，而一般图的 DFS / BFS 经常必须维护 `visited`，否则可能在环中无限往返。

## 14. 做图论题时先做这张抽象表

拿到题目后，可以先把自然语言转换成下面这几个字段：

| 问题 | 你要写出的答案 |
| --- | --- |
| 节点是什么？ | 城市 / 课程 / 格子 / 用户…… |
| 边是什么？ | 道路 / 依赖 / 相邻 / 关注…… |
| 有向还是无向？ | 是否允许反向走 |
| 是否带权？ | 距离 / 时间 / 成本…… |
| $V$ 多大？ | 决定空间能否用 $O(V^2)$ |
| $E$ 多大？ | 判断图是稀疏还是稠密 |
| 核心操作是什么？ | 枚举邻居 / 枚举边 / 任意两点查询 |
| 要求什么答案？ | 连通性 / 路径 / 最短路 / 环 / 排序…… |

很多所谓“不会图论题”，其实是还没有完成从题目语义到图模型的转换。

## 15. 易错点速查

- [ ] 无向边是否加入了两个方向？
- [ ] 顶点编号是 `0 ~ n-1` 还是 `1 ~ n`？
- [ ] 邻接矩阵空间 $O(V^2)$ 是否会爆内存？
- [ ] 带权图中的“无边”是否错误地用 `0` 表示？
- [ ] 有向图是否误按无向图理解连通性？
- [ ] “连通子图”是否真的满足“极大”才称为连通分量？
- [ ] 图中存在环时，遍历是否维护了访问状态？
- [ ] 后续算法需要枚举邻居还是枚举所有边？

## 16. 多语言建图模板

下面用一个最常见的模型收尾：

- $n$ 个节点，编号 `1 ~ n`；
- $m$ 条带权有向边；
- 每条输入为 `u v w`；
- 使用邻接表保存 `(邻居, 权值)`。

如果题目是无向图，只需要把反向边也加入邻接表。

```cpp tab="C++" tab-group="graph-basic-adjacency-list"
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;

    vector<vector<pair<int, int>>> graph(n + 1);

    for (int i = 0; i < m; ++i) {
        int u, v, w;
        cin >> u >> v >> w;
        graph[u].push_back({v, w});

        // 无向图：
        // graph[v].push_back({u, w});
    }

    for (int u = 1; u <= n; ++u) {
        for (auto [v, w] : graph[u]) {
            cout << u << " -> " << v << " (" << w << ")\n";
        }
    }

    return 0;
}
```

```java tab="Java"
import java.io.*;
import java.util.*;

public class Main {
    static class Edge {
        int to, weight;

        Edge(int to, int weight) {
            this.to = to;
            this.weight = weight;
        }
    }

    public static void main(String[] args) throws Exception {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());

        int n = Integer.parseInt(st.nextToken());
        int m = Integer.parseInt(st.nextToken());

        List<List<Edge>> graph = new ArrayList<>(n + 1);
        for (int i = 0; i <= n; ++i) {
            graph.add(new ArrayList<>());
        }

        for (int i = 0; i < m; ++i) {
            st = new StringTokenizer(br.readLine());
            int u = Integer.parseInt(st.nextToken());
            int v = Integer.parseInt(st.nextToken());
            int w = Integer.parseInt(st.nextToken());

            graph.get(u).add(new Edge(v, w));

            // 无向图：
            // graph.get(v).add(new Edge(u, w));
        }

        StringBuilder out = new StringBuilder();
        for (int u = 1; u <= n; ++u) {
            for (Edge e : graph.get(u)) {
                out.append(u)
                   .append(" -> ")
                   .append(e.to)
                   .append(" (")
                   .append(e.weight)
                   .append(")\n");
            }
        }

        System.out.print(out);
    }
}
```

```go tab="Go"
package main

import (
    "bufio"
    "fmt"
    "os"
)

type Edge struct {
    to     int
    weight int
}

func main() {
    in := bufio.NewReader(os.Stdin)
    out := bufio.NewWriter(os.Stdout)
    defer out.Flush()

    var n, m int
    fmt.Fscan(in, &n, &m)

    graph := make([][]Edge, n+1)

    for i := 0; i < m; i++ {
        var u, v, w int
        fmt.Fscan(in, &u, &v, &w)

        graph[u] = append(graph[u], Edge{to: v, weight: w})

        // 无向图：
        // graph[v] = append(graph[v], Edge{to: u, weight: w})
    }

    for u := 1; u <= n; u++ {
        for _, e := range graph[u] {
            fmt.Fprintf(out, "%d -> %d (%d)\n", u, e.to, e.weight)
        }
    }
}
```

## 总结

图论基础可以压缩成一条非常清晰的知识链：

```text
图 G=(V,E)
   ↓
有向 / 无向 / 带权
   ↓
度、路径、环、连通性
   ↓
连通分量 / 强连通分量
   ↓
边集 / 邻接矩阵 / 邻接表
   ↓
DFS / BFS / 并查集 / 最短路 / 最小生成树 / 拓扑排序
```

真正进入算法题后，最重要的不是背定义，而是能快速判断：

> **节点是什么？边是什么？图怎么存？接下来我要高效完成什么操作？**

只要这四个问题回答清楚，大部分图论算法都会更容易理解。
