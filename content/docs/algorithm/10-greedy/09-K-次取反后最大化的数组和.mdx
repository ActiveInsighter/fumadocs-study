# 1005. K 次取反后最大化的数组和

[LeetCode 1005. K 次取反后最大化的数组和](https://leetcode.cn/problems/maximize-sum-of-array-after-k-negations/)

给定整数数组 `nums` 和整数 $k$。

每次操作可以选择任意下标 $i$，把：

$$
nums[i]
$$

变成：

$$
-nums[i]
$$

一共必须执行恰好 $k$ 次，允许多次选择同一个位置。

要求操作结束后数组元素和最大。

例如：

```text
nums = [2, -3, -1, 5, -4]
k = 2
```

把 $-4$ 和 $-3$ 取反：

```text
[2, 3, -1, 5, 4]
```

数组和为：

$$
2+3-1+5+4=13
$$

答案为 `13`。

<Callout type="info" title="这道题其实用了两次贪心">
第一阶段：优先把绝对值大的负数变成正数；第二阶段：如果操作次数仍有剩余，就让绝对值最小的元素承担不可避免的符号损失。
</Callout>

## 1. 一次取反到底会让总和变化多少

设某个元素当前为 $x$。

取反前对总和的贡献是：

$$
x
$$

取反后变成：

$$
-x
$$

因此总和变化量为：

$$
(-x)-x=-2x
$$

于是：

- 若 $x<0$，则 $-2x>0$，取反会让总和增加；
- 若 $x>0$，则 $-2x<0$，取反会让总和减少；
- 若 $x=0$，取反没有任何影响。

对于负数：

$$
x=-a,\quad a>0
$$

取反带来的收益为：

$$
2a=2|x|
$$

因此越“负得厉害”，也就是绝对值越大，取反收益越大。

这直接给出第一层贪心。

## 2. 第一层贪心：优先翻转绝对值最大的负数

如果有多个负数，例如：

```text
[-8, -3, -1, 5]
```

只允许取反一次。

分别选择：

- $-8\to8$，总和增加 $16$；
- $-3\to3$，总和增加 $6$；
- $-1\to1$，总和增加 $2$。

显然应该优先处理 $-8$。

所以如果还存在负数并且 $k>0$，应该按照：

$$
|nums[i]|
$$

从大到小处理负数。

一种非常方便的实现方式是：

```cpp
sort(nums.begin(), nums.end(), [](int a, int b) {
    return abs(a) > abs(b);
});
```

此后从左到右扫描，遇到负数且还有操作次数就取反。

## 3. 为什么要按“绝对值”排序，而不是按数值排序

考虑：

```text
[-10, -2, 3]
k = 1
```

普通升序确实也是：

```text
[-10, -2, 3]
```

看起来没问题。

但本题后续还有一个非常重要的目标：

> 所有有价值的负数都处理完以后，需要快速找到绝对值最小的元素。

如果按绝对值降序排列：

```text
[-10, 3, -2]
```

则最后一个元素天然满足：

$$
|nums[n-1]|=\min_i|nums[i]|
$$

这样第一阶段和第二阶段都可以使用同一个排序结果。

因此排序标准应统一为：

$$
|a|>|b|
$$

## 4. 第二层贪心：剩余操作只看奇偶性

假设所有值得处理的负数都已经变成正数，但：

$$
k>0
$$

因为允许对同一个元素重复取反，所以对某个数 $x$：

```text
x -> -x -> x -> -x -> ...
```

每两次操作会完全抵消：

$$
-(-x)=x
$$

所以剩余操作次数真正有影响的只有：

$$
k\bmod 2
$$

### 若剩余 $k$ 为偶数

所有剩余操作都可以两两抵消，总和不变。

### 若剩余 $k$ 为奇数

最终一定有一个元素会多被取反一次。

此时我们必须承受一次损失。

若把正数 $x$ 变成 $-x$，总和会减少：

$$
2x
$$

为了让损失最小，应该选择：

$$
|x|
$$

最小的元素。

因此第二层贪心是：

> **若剩余操作次数为奇数，翻转绝对值最小的元素。**

而由于数组已经按照绝对值降序排序，这个元素就是：

```cpp
nums.back()
```

## 5. 如果数组里有 `0` 会发生什么

考虑：

```text
nums = [3, -1, 0, 2]
k = 3
```

先把 $-1$ 变成 $1$，消耗一次操作：

```text
[3, 1, 0, 2]
k = 2
```

剩余两次本来就可以互相抵消。

即使剩余的是奇数次也完全没关系，因为可以一直翻转 $0$：

$$
0\to0
$$

所以：

> **只要数组中存在 $0$，所有多余操作都可以被零无损吸收。**

这其实也自动包含在“翻转绝对值最小元素”这一规则中，因为：

$$
|0|=0
$$

是可能的最小绝对值。

## 6. 完整样例：`[-2, 5, 0, 2, -2]`，`k = 3`

按照绝对值降序排列后，可以得到：

```text
[5, -2, 2, -2, 0]
```

具体相同绝对值之间的顺序不重要。

### 第一次扫描

遇到负数 $-2$：

$$
-2\to2
$$

此时：

$$
k=2
$$

### 第二个负数

再把另一个 $-2$ 变成 $2$：

$$
k=1
$$

数组已经全部非负：

```text
[5, 2, 2, 2, 0]
```

### 还剩一次操作

由于：

$$
k\bmod2=1
$$

必须再取反一次。

绝对值最小的元素是 $0$，于是：

$$
0\to0
$$

最终总和：

$$
5+2+2+2+0=11
$$

没有任何损失。

## 7. 为什么第一阶段的顺序一定正确：交换论证

假设有两个负数：

$$
-a,\ -b
$$

并且：

$$
a\ge b>0
$$

如果只剩一次取反机会。

翻转 $-a$ 得到的收益是：

$$
2a
$$

翻转 $-b$ 得到的收益是：

$$
2b
$$

因为：

$$
a\ge b
$$

所以：

$$
2a\ge2b
$$

因此任何“先翻绝对值较小负数”的方案，都可以把这次操作交换到绝对值较大的负数上，结果不会更差。

不断进行这种交换，就一定能把某个最优方案变成：

> 按绝对值从大到小翻转负数。

这就是第一层贪心的正确性来源。

## 8. 为什么第二阶段一定翻绝对值最小的元素

假设经过第一阶段后，数组已经没有值得继续翻转的负数。

如果剩余奇数次操作，那么最终必须有某个元素发生一次净取反。

设选择元素 $x$，损失为：

$$
2|x|
$$

要让总和最大，就是让损失最小，因此需要最小化：

$$
|x|
$$

于是：

$$
x=\operatorname*{argmin}_{v\in nums}|v|
$$

这是第二层贪心的严格依据。

## 9. 标准四步算法

### 按绝对值从大到小排序

```cpp
sort(nums.begin(), nums.end(), [](int a, int b) {
    return abs(a) > abs(b);
});
```

排序后，绝对值最小的元素位于末尾。

### 优先把负数变成正数

```cpp
for (int& x : nums) {
    if (x < 0 && k > 0) {
        x = -x;
        --k;
    }
}
```

### 处理剩余奇数次操作

```cpp
if (k % 2 == 1) {
    nums.back() = -nums.back();
}
```

偶数次可以互相抵消，不需要真的模拟。

### 求最终数组和

```cpp
return accumulate(nums.begin(), nums.end(), 0);
```

完整 C++ 实现：

```cpp
class Solution {
public:
    int largestSumAfterKNegations(vector<int>& nums, int k) {
        sort(nums.begin(), nums.end(), [](int a, int b) {
            return abs(a) > abs(b);
        });

        for (int& x : nums) {
            if (x < 0 && k > 0) {
                x = -x;
                --k;
            }
        }

        if (k % 2 == 1) {
            nums.back() = -nums.back();
        }

        return accumulate(nums.begin(), nums.end(), 0);
    }
};
```

时间复杂度主要来自排序：

$$
O(n\log n)
$$

额外空间复杂度取决于排序实现；从算法本身的辅助变量来看为：

$$
O(1)
$$

## 10. 用“收益最大化”统一理解两层贪心

本题可以把每次取反理解成对总和施加一个变化量。

对于负数 $x<0$：

$$
\Delta=-2x=2|x|>0
$$

所以第一阶段是在所有**正收益操作**中优先选择收益最大的。

当不存在正收益操作以后，如果还必须执行奇数次净操作，那么对任意非负数 $x$：

$$
\Delta=-2x\le0
$$

此时第二阶段是在所有**不可避免的负收益操作**中选择损失最小的。

因此可以把本题记成：

```text
先赚最多的收益，再承担最小的损失。
```

这比死记“绝对值排序”更容易迁移到其他贪心问题。

## 11. 为什么不需要真的执行剩余的所有操作

假设第一阶段结束后：

```text
k = 1000001
```

如果还写：

```cpp
while (k--) {
    nums.back() = -nums.back();
}
```

虽然在本题约束下未必超时，但逻辑上完全没有必要。

因为：

$$
(-1)^{k}
$$

只取决于 $k$ 的奇偶性。

因此剩余操作可以压缩成：

```cpp
if (k % 2 == 1) {
    nums.back() = -nums.back();
}
```

这类“重复反复操作只看奇偶性”的结构，在位运算、状态翻转、灯泡开关、符号变换等题目中非常常见。

## 12. 常见错误

### 错误 1：优先翻转绝对值最小的负数

对于负数，取反收益是：

$$
2|x|
$$

所以应该先处理绝对值最大的负数。

### 错误 2：剩余操作每次都找当前最小“数值”

真正要最小化的是取反损失：

$$
2|x|
$$

所以看的是绝对值，而不是普通数值大小。

### 错误 3：忘记必须恰好执行 $k$ 次

不能在所有负数转正后直接结束。

若剩余次数为奇数，最终仍必须有一个元素的符号发生变化。

### 错误 4：忽略同一个下标可以重复操作

正因为允许重复选择同一元素，才有：

$$
2\text{ 次取反}=\text{不变}
$$

从而剩余次数只看奇偶性。

### 错误 5：错误处理 `0`

`0` 不是特殊麻烦，反而是最理想的“操作吸收器”：

$$
-0=0
$$

绝对值排序后的统一逻辑已经自动处理它。

## 13. 另一种做法：普通升序 + 重新找最小绝对值

也可以先普通升序：

```cpp
sort(nums.begin(), nums.end());
```

然后从左到右把负数取反。

但负数转正以后，数组原来的有序性可能被破坏，因此若还有奇数次操作，需要额外找一次：

$$
\min_i |nums[i]|
$$

时间复杂度仍可以做到：

$$
O(n\log n)
$$

但代码逻辑不如“绝对值降序”统一。

所以学习阶段更推荐：

```text
绝对值降序 -> 翻负数 -> 最后元素吸收剩余奇数次
```

## 14. 一页记忆模板

```text
1. 按 |nums[i]| 从大到小排序
2. 还有 k 且 nums[i] < 0：翻成正数，k--
3. 若 k 为奇数：翻转绝对值最小的元素
4. 求和
```

对应两个贪心原则：

$$
\boxed{\text{优先获得最大的正收益}}
$$

$$
\boxed{\text{若损失不可避免，就让损失最小}}
$$

## 15. 其他语言版本

下面均采用“按绝对值降序 + 负数优先取反 + 剩余奇数次翻转最小绝对值”的统一实现。

### Java

```java
import java.util.Arrays;

class Solution {
    public int largestSumAfterKNegations(int[] nums, int k) {
        Integer[] values = Arrays.stream(nums).boxed().toArray(Integer[]::new);

        Arrays.sort(values, (a, b) -> Integer.compare(Math.abs(b), Math.abs(a)));

        for (int i = 0; i < values.length && k > 0; i++) {
            if (values[i] < 0) {
                values[i] = -values[i];
                k--;
            }
        }

        if ((k & 1) == 1) {
            int last = values.length - 1;
            values[last] = -values[last];
        }

        int sum = 0;
        for (int x : values) {
            sum += x;
        }
        return sum;
    }
}
```

import "sort"

func largestSumAfterKNegations(nums []int, k int) int {
    abs := func(x int) int {
        if x < 0 {
            return -x
        }
        return x
    }

    sort.Slice(nums, func(i, j int) bool {
        return abs(nums[i]) > abs(nums[j])
    })

    for i := 0; i < len(nums) && k > 0; i++ {
        if nums[i] < 0 {
            nums[i] = -nums[i]
            k--
        }
    }

    if k%2 == 1 {
        nums[len(nums)-1] = -nums[len(nums)-1]
    }

    sum := 0
    for _, x := range nums {
        sum += x
    }
    return sum
}

static int absInt(int x) {
    return x < 0 ? -x : x;

static int compare(const void* a, const void* b) {

    int y = *(const int*)b;
    return absInt(y) - absInt(x);

        sum += nums[i];
