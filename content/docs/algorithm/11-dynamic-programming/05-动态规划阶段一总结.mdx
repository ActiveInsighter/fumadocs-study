# 动态规划阶段一总结

完成前四篇之后，我们已经接触了动态规划最核心的几种基本形态：

- **递推型计数**：斐波那契数；
- **路径方案计数**：爬楼梯；
- **最优化型 DP**：使用最小花费爬楼梯；
- **空间压缩**：当当前状态只依赖少量历史状态时，用常数变量替代完整数组。

这些题本身并不难，但它们真正的价值不是“会写一道简单题”，而是建立一套以后面对复杂动态规划时仍然能使用的分析流程。

<Callout type="info" title="这一阶段真正要掌握的不是公式">
如果只记住 `dp[i] = dp[i - 1] + dp[i - 2]`，遇到稍微变形的题目就会失效。真正应该掌握的是：**状态代表什么、当前状态从哪些前驱状态转移而来，以及这些前驱如何合并。**
</Callout>

## 1. 四篇内容之间的关系

先把已经学习的题目放在同一张表中比较：

| 问题 | `dp` 的含义 | 状态转移 | 聚合方式 | 目标类型 |
| --- | --- | --- | --- | --- |
| 斐波那契数 | 第 $i$ 个斐波那契数 | `dp[i-1]`、`dp[i-2]` | 相加 | 数值递推 |
| 爬楼梯 | 到达第 $i$ 阶的方案数 | `dp[i-1]`、`dp[i-2]` | 相加 | 计数 |
| 最小花费爬楼梯 | 到达位置 $i$ 的最小花费 | `dp[i-1]`、`dp[i-2]` | 取最小值 | 最优化 |

可以发现，三道题的“图结构”非常相似：

$$
i-2\longrightarrow i,
\qquad
i-1\longrightarrow i
$$

真正变化的是**状态语义**与**合并方式**。

如果求方案数，来自不同前驱的方案互不重复，就做加法：

$$
dp[i]=dp[i-1]+dp[i-2]
$$

如果求最小代价，就在多个候选来源中取最优：

$$
dp[i]=\min(\text{candidate}_1,\text{candidate}_2)
$$

这正是以后识别动态规划题型时最重要的观察之一。

## 2. 动态规划五步法应该怎样真正使用

### 2.1 第一步：定义状态

先写一句完整的话：

> `dp[...]` 表示什么？

例如：

$$
dp[i]=\text{到达第 }i\text{ 阶楼梯的方案数}
$$

或者：

$$
dp[i]=\text{到达位置 }i\text{ 时的最小总花费}
$$

状态定义一旦改变，初始化、转移方程和最终答案的位置都可能改变。

<Callout type="warning" title="不要先写转移公式，再强行解释 dp">
很多错误代码表面上是边界问题，实际上根源是 `dp[i]` 从来没有被精确定义。建议在草稿上先写状态定义，再写任何公式。
</Callout>

### 2.2 第二步：寻找当前状态的所有直接来源

思考“最后一步”。

以爬楼梯为例，到达第 $i$ 阶的最后一步只有：

- 从 $i-1$ 走一步；
- 从 $i-2$ 走两步。

于是自然得到：

$$
dp[i]=dp[i-1]+dp[i-2]
$$

这个思维方式以后会扩展成：

- 网格 DP：最后一步来自上方或左方；
- 背包 DP：当前物品选或不选；
- 股票 DP：今天持有或不持有；
- 字符串 DP：最后两个字符相同还是不同。

### 2.3 第三步：初始化必须服从状态语义

初始化不是“模板”。

例如经典爬楼梯可以定义：

$$
dp[1]=1,\qquad dp[2]=2
$$

然后从 $i=3$ 开始递推。

但如果为了统一组合计数模型，也可以引入：

$$
dp[0]=1
$$

此时它更像一个**空方案的计数单位元**，用于保证：

$$
dp[i]=\sum dp[i-j]
$$

在边界处仍然成立。

因此：

> `dp[0] = 1` 不一定表示现实中“真的存在一种走 0 阶的方法”，有时它是为了让状态转移在组合计数中保持统一。

这两种定义都可以正确，但必须保持定义、初始化和遍历范围一致。

### 2.4 第四步：遍历顺序由依赖关系决定

如果：

$$
dp[i]\leftarrow dp[i-1],dp[i-2]
$$

那么自然从小到大遍历。

以后进入背包问题后，遍历方向会直接决定“一个物品能否被重复使用”。所以现在要建立一个习惯：

> 不要背“正序还是倒序”，先画清楚状态依赖。

### 2.5 第五步：手推一个小样例

比如爬楼梯：

| $i$ | 1 | 2 | 3 | 4 | 5 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| $dp[i]$ | 1 | 2 | 3 | 5 | 8 |

如果程序输出：

```text
1 2 3 5 8
```

说明至少这一组状态与预期一致。

如果程序错误，打印 DP 表通常比盯着代码猜更有效。

## 3. 动态规划调试：三个必须回答的问题

当代码无法通过样例时，依次检查：

1. **状态定义是否明确？**
2. **手工推导出的 DP 表是什么？**
3. **程序实际打印出的 DP 表与手推结果从哪里开始不同？**

例如：

```cpp
for (int i = 0; i <= n; ++i) {
    cout << "dp[" << i << "] = " << dp[i] << '\n';
}
```

第一处不一致的位置通常就是问题发生的位置。

可能的原因包括：

- 初始化错误；
- 下标错位；
- 遍历起点错误；
- 状态转移漏掉某个来源；
- 把“到达当前状态的代价”和“离开当前状态的代价”混淆。

## 4. 从“爬楼梯”继续推广

经典问题规定每次只能走 $1$ 或 $2$ 阶。

如果改成：

> 每次可以走 $1,2,\dots,m$ 阶，问到达第 $n$ 阶有多少种不同走法？

那么到达第 $i$ 阶的最后一步可以是任意 $j$：

$$
1\le j\le m
$$

只要：

$$
i-j\ge 0
$$

就可以从第 $i-j$ 阶走到第 $i$ 阶。

因此：

$$
\boxed{
 dp[i]=\sum_{j=1}^{m} dp[i-j]
}
$$

其中只累加合法下标。

一种统一实现是：

```cpp
long long climbStairsGeneral(int n, int m) {
    vector<long long> dp(n + 1, 0);
    dp[0] = 1;

    for (int i = 1; i <= n; ++i) {
        for (int step = 1; step <= m; ++step) {
            if (i >= step) {
                dp[i] += dp[i - step];
            }
        }
    }

    return dp[n];
}
```

这里的外层枚举“总高度”，内层枚举“最后一步走多少阶”。

后面学习完全背包时，会发现它本质上还可以理解为一种**排列型完全背包计数问题**。

<Callout type="tip" title="提前记住：循环顺序将决定组合还是排列">
以后在完全背包计数问题中，如果先遍历容量、再遍历物品，往往是在统计排列；如果先遍历物品、再遍历容量，往往是在统计组合。爬楼梯进阶版会再次用到这个结论。
</Callout>

## 5. 空间压缩到底在压什么

如果完整状态转移为：

$$
dp[i]=f(dp[i-1],dp[i-2])
$$

计算 `dp[i]` 时，更早的：

$$
dp[i-3],dp[i-4],\dots
$$

已经不会再次使用。

因此没有必要保存整个数组，只需要维护最近两个状态。

以爬楼梯为例：

```cpp
int climbStairs(int n) {
    if (n <= 2) return n;

    int prev2 = 1;
    int prev1 = 2;

    for (int i = 3; i <= n; ++i) {
        int cur = prev1 + prev2;
        prev2 = prev1;
        prev1 = cur;
    }

    return prev1;
}
```

空间复杂度由：

$$
O(n)
$$

降低为：

$$
O(1)
$$

但要注意：

> 空间压缩不是新的算法，它只是利用“当前状态只依赖有限历史状态”这一事实，删除不再需要的数据。

## 6. 第一阶段常见误区

### 误区一：看到递推就说是动态规划

递推只是表达状态之间的关系。

动态规划更强调：

- 子问题存在重叠；
- 每个状态只计算一次；
- 结果被保存并重复利用。

### 误区二：把递归和动态规划混为一谈

朴素递归可能大量重复计算。

例如斐波那契递归树中：

$$
F(n-2)
$$

会被反复求解。

记忆化搜索和递推 DP 都是在消除这种重复计算。

### 误区三：把 `dp[0] = 1` 当成永远正确的模板

它只在状态语义允许时成立。

不同题目中：

$$
dp[0]
$$

可能等于 $0$、$1$、$+\infty$、$-\infty$，甚至根本不需要定义。

### 误区四：只会写二维数组，不理解依赖

能否压缩空间，不取决于“题目是不是二维”，而取决于：

> 当前状态到底还需要哪些历史信息？

下一篇“不同路径”会第一次系统看到二维 DP 如何压成一维 DP。

## 7. 第一阶段知识地图

```text
动态规划基础
│
├─ 状态定义
│  └─ dp[...] 到底代表什么
│
├─ 状态转移
│  ├─ 计数：sum
│  └─ 最优化：min / max
│
├─ 初始化
│  └─ 必须由状态定义推出
│
├─ 遍历顺序
│  └─ 保证依赖状态已经计算
│
├─ 手工推导
│  └─ 用于验证模型与调试
│
└─ 空间压缩
   └─ 删除未来不再依赖的历史状态
```

## 8. 进入下一阶段前的自测

如果下面的问题都能独立回答，就可以继续学习二维网格 DP：

- 为什么爬楼梯的转移方程是相加，而最小花费爬楼梯是取最小值？
- 为什么状态定义不同会导致初始化不同？
- `dp[0] = 1` 在组合计数中可能具有什么数学意义？
- 为什么空间压缩后仍然是同一个动态规划？
- 当程序答案错误时，应该怎样通过手推和打印 DP 表定位问题？

下一阶段将从一维递推进入二维状态。最典型的入口就是“不同路径”：

$$
dp[i][j]=dp[i-1][j]+dp[i][j-1]
$$

它会第一次把“状态依赖关系”清晰地画在二维网格上。
