# 编辑距离系列总结

从“判断子序列”一路到“编辑距离”，表面上题目越来越复杂，但核心结构其实始终没有变化：

$$
\boxed{
\text{研究两个字符串前缀之间的关系}
}
$$

真正变化的是：

- 状态保存的是“长度 / 方案数 / 最小代价”中的哪一种；
- 允许执行哪些操作；
- 当前字符相等或不等时，可以从哪些前驱状态转移。

<Callout type="info" title="这一组题的真正主线">
不要把四道题当成四套模板。它们本质上是同一个二维前缀 DP 框架，在不同操作集合和不同优化目标下的四种实例。
</Callout>

## 1. 统一坐标系：两个前缀

几乎所有这类题都可以把状态写成：

$$
\boxed{
dp[i][j]
=
\text{字符串 }A\text{ 前 }i\text{ 个字符与字符串 }B\text{ 前 }j\text{ 个字符的某种最优信息}
}
$$

于是当前只需要比较：

$$
A[i-1]
\quad\text{和}\quad
B[j-1]
$$

这两个最后字符。

二维表的三个经典前驱方向是：

```text
          dp[i-1][j]
              ↓
dp[i][j-1] -> dp[i][j]
             ↖
       dp[i-1][j-1]
```

它们分别意味着：

- 丢掉 / 不使用第一个字符串末尾字符；
- 丢掉 / 不使用第二个字符串末尾字符；
- 同时处理两个末尾字符。

不同题目的核心差别，就是**允许哪几条边，以及每条边代表什么**。

# 一、判断子序列：只问“能否按顺序匹配”

## 2. 题目模型

给定：

```text
s
t
```

判断 `s` 是否是 `t` 的子序列。

从操作角度看，本题可以理解为：

> 只能从 `t` 中删除字符，能不能最终得到 `s`？

因此它是编辑距离系列中最简单的“单侧删除”模型。

## 3. DP 状态

一种常见定义是：

$$
\boxed{
dp[i][j]
=
 s[0\ldots i-1]
\text{ 与 }
 t[0\ldots j-1]
\text{ 的最长公共子序列长度}
}
$$

但由于只关心 `s` 是否完整匹配，也可以使用更针对性的转移：

如果：

$$
s[i-1]=t[j-1]
$$

则当前字符可以匹配：

$$
\boxed{dp[i][j]=dp[i-1][j-1]+1}
$$

否则只能跳过 `t[j-1]`：

$$
\boxed{dp[i][j]=dp[i][j-1]}
$$

最终判断：

$$
\boxed{dp[n][m]=n}
$$

## 4. 它为什么是“编辑距离入门”

因为允许的操作只有：

```text
删除 t 中字符
```

没有：

- 删除 `s`；
- 插入；
- 替换。

所以状态转移只有非常有限的方向。

# 二、不同的子序列：从“能不能”升级为“有多少种”

## 5. 题目模型

给定字符串 `s` 和 `t`，求 `s` 的子序列中有多少个等于 `t`。

这道题仍然只有一个基本动作：

```text
使用或不使用 s 中当前字符
```

但目标从布尔判断变成了：

$$
\boxed{\text{计数}}
$$

## 6. 状态定义

定义：

$$
\boxed{
dp[i][j]
=
 s\text{ 前 }i\text{ 个字符中形成 }t\text{ 前 }j\text{ 个字符的方案数}
}
$$

### 字符相等

如果：

$$
s[i-1]=t[j-1]
$$

当前字符有两个选择。

#### 使用 `s[i-1]`

它匹配 `t[j-1]`：

$$
dp[i-1][j-1]
$$

#### 不使用 `s[i-1]`

继续在更短的 `s` 中寻找完整的 `t[0\ldots j-1]`：

$$
dp[i-1][j]
$$

因此：

$$
\boxed{dp[i][j]=dp[i-1][j-1]+dp[i-1][j]}
$$

### 字符不等

当前 `s[i-1]` 无法参与匹配，只能跳过：

$$
\boxed{dp[i][j]=dp[i-1][j]}
$$

<Callout type="tip" title="这道题最关键的思想">
字符相等不意味着“必须使用”。计数型 DP 经常需要同时统计“选”和“不选”的方案，这也是它比普通子序列判断更难的原因。
</Callout>

# 三、两个字符串的删除操作：从计数转向最小代价

## 7. 题目模型

允许：

```text
删除 word1 中字符
删除 word2 中字符
```

目标是：

$$
\boxed{\text{让两个字符串相同所需的最少删除次数}}
$$

这一次两个字符串都能动，因此二维状态开始真正表现出“对称编辑”的结构。

## 8. 直接删除 DP

定义：

$$
\boxed{
dp[i][j]
=
word1\text{ 前 }i\text{ 个字符与 }word2\text{ 前 }j\text{ 个字符变得相同的最少删除次数}
}
$$

如果字符相同：

$$
\boxed{dp[i][j]=dp[i-1][j-1]}
$$

如果字符不同：

- 删除 `word1[i-1]`；
- 删除 `word2[j-1]`。

所以：

$$
\boxed{
dp[i][j]
=
1+\min(dp[i-1][j],dp[i][j-1])
}
$$

## 9. 它与 LCS 的等价关系

假设：

$$
L=LCS(word1,word2)
$$

最终最理想的策略就是把两个字符串都删成同一个最长公共子序列。

因此：

$$
\boxed{
\text{最少删除次数}
=
|word1|+|word2|-2L
}
$$

这揭示了一个非常重要的互补思想：

$$
\boxed{
\text{最少删掉多少}
\Longleftrightarrow
\text{最多保留多少}
}
$$

# 四、编辑距离：允许插入、删除、替换

## 10. 题目模型

标准编辑距离允许三类操作：

```text
插入
删除
替换
```

目标是：

$$
\boxed{\text{把 }word1\text{ 变为 }word2\text{ 的最少编辑次数}}
$$

这是这一组题里最完整的模型。

## 11. 状态定义

$$
\boxed{
dp[i][j]
=
\text{把 }word1\text{ 前 }i\text{ 个字符变为 }word2\text{ 前 }j\text{ 个字符的最少操作数}
}
$$

### 字符相等

$$
\boxed{dp[i][j]=dp[i-1][j-1]}
$$

### 字符不等

有三种候选：

#### 删除

$$
\boxed{dp[i-1][j]+1}
$$

#### 插入

$$
\boxed{dp[i][j-1]+1}
$$

#### 替换

$$
\boxed{dp[i-1][j-1]+1}
$$

因此：

$$
\boxed{
dp[i][j]
=
1+
\min\left(
dp[i-1][j],
dp[i][j-1],
dp[i-1][j-1]
\right)
}
$$

# 五、四类问题放到同一张表里

## 12. 统一比较

| 问题 | 状态目标 | 允许的核心操作 | 字符相等时 | 字符不等时 |
|---|---|---|---|---|
| 判断子序列 | 最长已匹配长度 / 可达性 | 单侧跳过 | 左上 $+1$ | 左侧 |
| 不同的子序列 | 方案数 | 选 / 不选源字符 | 左上 + 上方 | 上方 |
| 两字符串删除 | 最小删除次数 | 双侧删除 | 左上 | `min(上,左)+1` |
| 编辑距离 | 最小编辑次数 | 插入 / 删除 / 替换 | 左上 | `min(上,左,左上)+1` |

这张表值得反复对照。

真正应该记住的是：

> 每一项转移都必须能解释成一种合法操作，而不是因为“这类题公式就是这样”。

# 六、三个方向分别代表什么

## 13. 上方、左侧、左上角的统一解释

设当前状态为：

$$
dp[i][j]
$$

### 上方 `dp[i-1][j]`

意味着第一个字符串少考虑一个字符。

常见语义：

```text
删除第一个字符串当前字符
跳过第一个字符串当前字符
不选择第一个字符串当前字符
```

### 左侧 `dp[i][j-1]`

意味着第二个字符串少考虑一个字符。

常见语义：

```text
删除第二个字符串当前字符
向第一个字符串插入第二个字符串当前字符
跳过第二个字符串当前字符
```

### 左上角 `dp[i-1][j-1]`

意味着两个当前字符一起被处理。

常见语义：

```text
两个字符直接匹配
替换一个字符
两个字符一起参与某种关系
```

<Callout type="info" title="二维字符串 DP 的核心阅读方法">
看到一个转移式时，不要先看 `min`、`max` 或 `+1`。先问它来自“上、左、左上”哪一个方向，再把这个方向翻译成题目的具体操作，理解会稳定得多。
</Callout>

# 七、为什么这些状态都喜欢多开一行一列

## 14. 空前缀统一边界

如果使用：

$$
dp[i][j]
=
\text{前 }i\text{ 个字符与前 }j\text{ 个字符}
$$

那么：

```text
i = 0
```

自然代表第一个字符串为空；

```text
j = 0
```

自然代表第二个字符串为空。

这使很多边界含义非常直接。

例如编辑距离：

$$
\boxed{dp[i][0]=i}
$$

因为长度为 $i$ 的字符串变空串，要删除 $i$ 次。

而：

$$
\boxed{dp[0][j]=j}
$$

因为空串变成长为 $j$ 的字符串，要插入 $j$ 次。

“前缀长度”定义因此通常比直接用字符下标更加稳定。

# 八、目标类型决定用 `min`、`max` 还是加法

## 15. 三类最常见目标

字符串 DP 不只是转移方向不同，**聚合操作**也取决于问题问什么。

### 最优化：求最大

例如：

- 最长公共子序列；
- 最长重复子数组。

常见形式：

$$
\boxed{\max(\cdots)}
$$

### 最优化：求最小

例如：

- 最少删除次数；
- 编辑距离。

常见形式：

$$
\boxed{\min(\cdots)}
$$

### 计数

例如不同的子序列：

$$
\boxed{\text{方案数相加}}
$$

所以面对新题时应先确认：

```text
这是可行性？
最大值？
最小值？
还是方案数？
```

这会直接决定 DP 值的数学意义。

# 九、从“操作集合”反推状态转移

## 16. 一个通用推导流程

以后遇到两个字符串的 DP，可以按以下顺序推导。

### 第一步：定义两个前缀

先尝试：

$$
A[0\ldots i-1]
\quad\text{和}\quad
B[0\ldots j-1]
$$

### 第二步：明确 `dp[i][j]` 保存什么

例如：

- 能不能做到；
- 最长长度；
- 最少操作；
- 方案数量。

### 第三步：比较末尾字符

分成：

$$
A[i-1]=B[j-1]
$$

和：

$$
A[i-1]\ne B[j-1]
$$

### 第四步：枚举“最后一步”

问自己：

```text
最后一步如果删除 A 的字符，之前是什么状态？
最后一步如果删除 B 的字符，之前是什么状态？
最后一步如果替换，之前是什么状态？
如果当前字符不使用，应该退到哪个前缀？
```

### 第五步：根据目标聚合

- 最小代价：`min`；
- 最大长度：`max`；
- 方案数：相加；
- 可行性：逻辑或。

这套流程比记忆任何单一题目的模板更可靠。

# 十、编辑距离与最长公共子序列的关系

## 17. 删除距离可以直接由 LCS 得到

如果只允许删除，两个字符串最终相同的最长可能长度，就是 LCS。

所以：

$$
\boxed{
D_{delete}(A,B)
=
|A|+|B|-2\cdot LCS(A,B)
}
$$

但标准 Levenshtein 编辑距离还允许一次替换。

替换的代价是 $1$，而如果用“删除 + 插入”模拟替换，需要 $2$ 次。

因此一般情况下：

$$
\boxed{
D_{edit}(A,B)
\le
D_{delete}(A,B)
}
$$

例如：

```text
A = "a"
B = "b"
```

只允许双侧删除：

$$
D_{delete}=2
$$

标准编辑距离：

$$
D_{edit}=1
$$

因为直接替换即可。

所以不能简单用 LCS 公式替代标准编辑距离。

# 十一、从最短路径角度统一编辑类问题

## 18. DP 网格其实是一张 DAG

把：

$$
(i,j)
$$

看成节点。

每一种允许操作就是一条有向边：

```text
(i-1,j)   -> (i,j)
(i,j-1)   -> (i,j)
(i-1,j-1) -> (i,j)
```

如果每条边有代价，那么“最少编辑次数”就是 DAG 上的最短路径。

如果每条边代表一种选择并要统计方案，那么就是 DAG 上的路径计数。

如果边上代表匹配贡献并要求最大值，就会得到 LCS 一类问题。

因此这几类题可以统一理解为：

$$
\boxed{
\text{在二维前缀状态图上做不同的路径聚合}
}
$$

这个视角非常适合迁移到：

- 带权编辑距离；
- 序列对齐；
- DNA / 蛋白质序列相似度；
- diff 工具；
- 拼写纠错；
- OCR / ASR 输出纠错。

# 十三、编辑距离模板代码

## 20. 二维模板

```cpp
int editDistance(const string& a, const string& b) {
    int n = a.size();
    int m = b.size();

    vector<vector<int>> dp(n + 1, vector<int>(m + 1));

    for (int i = 0; i <= n; ++i) dp[i][0] = i;
    for (int j = 0; j <= m; ++j) dp[0][j] = j;

    for (int i = 1; i <= n; ++i) {
        for (int j = 1; j <= m; ++j) {
            if (a[i - 1] == b[j - 1]) {
                dp[i][j] = dp[i - 1][j - 1];
            } else {
                dp[i][j] = 1 + min({
                    dp[i - 1][j],
                    dp[i][j - 1],
                    dp[i - 1][j - 1]
                });
            }
        }
    }

    return dp[n][m];
}
```

## 21. 一维模板

```cpp
int editDistance(const string& a, const string& b) {
    const string *longer = &a, *shorter = &b;
    if (a.size() < b.size()) {
        swap(longer, shorter);
    }

    int n = longer->size();
    int m = shorter->size();

    vector<int> dp(m + 1);
    for (int j = 0; j <= m; ++j) dp[j] = j;

    for (int i = 1; i <= n; ++i) {
        int diagonal = dp[0];
        dp[0] = i;

        for (int j = 1; j <= m; ++j) {
            int top = dp[j];

            if ((*longer)[i - 1] == (*shorter)[j - 1]) {
                dp[j] = diagonal;
            } else {
                dp[j] = 1 + min({top, dp[j - 1], diagonal});
            }

            diagonal = top;
        }
    }

    return dp[m];
}
```

```go
func minDistance(a, b string) int {
    n, m := len(a), len(b)
    dp := make([][]int, n+1)

    for i := 0; i <= n; i++ {
        dp[i] = make([]int, m+1)
        dp[i][0] = i
    }
    for j := 0; j <= m; j++ {
        dp[0][j] = j
    }

    min3 := func(x, y, z int) int {
        if x > y { x = y }
        if x > z { x = z }
        return x
    }

    for i := 1; i <= n; i++ {
        for j := 1; j <= m; j++ {
            if a[i-1] == b[j-1] {
                dp[i][j] = dp[i-1][j-1]
            } else {
                dp[i][j] = 1 + min3(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
            }
        }
    }

    return dp[n][m]
}
```

```javascript
        for (let j = 1; j <= m; j++) {
            if (a[i - 1] === b[j - 1]) {
                dp[i][j] = dp[i - 1][j - 1];
            } else {
                dp[i][j] = 1 + Math.min(
                    dp[i - 1][j],
                    dp[i][j - 1],
                    dp[i - 1][j - 1]
                );
            }
        }
    }

    return dp[n][m];
}
```

# 十五、最后形成一套统一思维

## 22. 不要背题，背“问题结构”

这组题可以浓缩成四个问题：

### 问题一：`dp[i][j]` 的数学含义是什么？

它必须明确对应两个前缀。

### 问题二：当前末尾字符相等时，是否要使用它们？

- 有的题必须用；
- 有的题可以用也可以不用；
- 有的题只需要无代价对齐。

### 问题三：当前字符不等时，允许什么操作？

- 单侧跳过；
- 双侧删除；
- 插入；
- 替换。

### 问题四：多种合法方案如何合并？

- 可行性：`or`；
- 计数：`+`；
- 最大收益：`max`；
- 最小代价：`min`。

最终可以把整个编辑距离系列统一为：

$$
\boxed{
\text{二维前缀状态}
+
\text{末尾字符关系}
+
\text{合法操作集合}
+
\text{目标聚合方式}
}
$$

一旦能用这四部分独立推导状态转移，就已经真正掌握了这一整类字符串动态规划，而不只是记住某一道题的答案。
