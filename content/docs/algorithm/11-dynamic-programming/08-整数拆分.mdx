# 整数拆分

> LeetCode 343：Integer Break

给定一个正整数 $n$，将它拆分为**至少两个正整数**之和，使这些整数的乘积最大，返回能够得到的最大乘积。

例如：

```text
n = 2
```

只能拆成：

$$
2=1+1
$$

所以答案为：

$$
1\times1=1
$$

再如：

```text
n = 10
```

最优拆分为：

$$
10=3+3+4
$$

最大乘积：

$$
3\times3\times4=36
$$

<Callout type="info" title="这道题的难点在“状态语义必须严格”">
很多写法都能 AC，但如果 `dp[i]` 的定义、初始化和递推公式彼此矛盾，就很难迁移到更复杂题目。这道题特别适合训练“状态定义是否自洽”。
</Callout>

## 1. 最直观的问题：到底拆成几份

对于 $n$，我们并不知道最优方案要拆成：

- 2 份；
- 3 份；
- 4 份；
- ……

暴力枚举所有整数拆分方案会产生大量重复子问题。

例如考虑 $10$：

```text
10 = 1 + 9
10 = 2 + 8
10 = 3 + 7
10 = 4 + 6
...
```

当我们尝试 `3 + 7` 时，又需要知道数字 7 拆分后的最大乘积；尝试其他更大数字时，同样会不断重复计算这些子问题。

因此可以把“小整数的最优拆分”保存起来，逐步构造更大的答案。

## 2. 状态定义

定义：

$$
\boxed{dp[i]=\text{将整数 }i\text{ 拆成至少两个正整数后能够得到的最大乘积}}
$$

这里有两个关键限制：

1. 必须拆；
2. 至少拆成两个正整数。

因此，例如：

$$
dp[2]=1
$$

因为：

$$
2=1+1
$$

而不能说：

$$
dp[2]=2
$$

因为那等价于“不拆 2”。

这一点会直接影响后面的状态转移。

## 3. 状态转移从哪里来

对于整数 $i$，先切出一个正整数 $j$：

$$
i=j+(i-j)
$$

接下来，对右半部分 $i-j$ 有两种选择。

### 情况一：右半部分不再拆

直接得到两部分：

$$
j\quad\text{和}\quad i-j
$$

乘积为：

$$
\boxed{j(i-j)}
$$

### 情况二：右半部分继续拆

因为：

$$
dp[i-j]
$$

已经表示“把 $i-j$ 拆分后的最大乘积”，所以这一方案得到：

$$
\boxed{j\cdot dp[i-j]}
$$

于是，对每一个切分位置 $j$，都需要比较：

$$
j(i-j)
$$

与：

$$
j\cdot dp[i-j]
$$

最终：

$$
\boxed{
dp[i]=\max_{1\le j<i}
\left\{
 j(i-j),\;j\cdot dp[i-j]
\right\}
}
$$

程序中写成：

```cpp
dp[i] = max(dp[i], max(j * (i - j), j * dp[i - j]));
```

## 4. 为什么必须同时比较两种情况

这是本题最容易卡住的地方。

有人会问：既然已经有 `dp[i - j]`，为什么不直接：

```cpp
dp[i] = max(dp[i], j * dp[i - j]);
```

原因是：

> `dp[i-j]` 强制要求 $i-j$ 至少再拆一次，但最优方案未必希望它继续拆。

例如：

$$
i=4,\quad j=2
$$

如果右侧的 2 不继续拆：

$$
2\times2=4
$$

如果强制使用：

$$
dp[2]=1
$$

则只能得到：

$$
2\times1=2
$$

显然漏掉了最优解。

所以必须同时考虑：

$$
\boxed{j(i-j)}
$$

和：

$$
\boxed{j\cdot dp[i-j]}
$$

<Callout type="tip" title="一个非常通用的 DP 习惯">
当状态本身带有“必须执行某个操作”的约束时，转移时一定要分清：当前子结构是“直接使用”，还是“继续进入 DP 状态”。这类差异常常决定状态定义是否正确。
</Callout>

## 5. 初始化为什么只需要 dp[2] = 1

根据定义：

$$
dp[i]=\text{整数 }i\text{ 被拆分后的最大乘积}
$$

那么：

- `dp[0]`：没有意义；
- `dp[1]`：无法拆成至少两个正整数，没有意义；
- `dp[2]`：可以拆成 $1+1$，最大乘积为 1。

因此最自然的初始化是：

$$
\boxed{dp[2]=1}
$$

然后从：

$$
i=3
$$

开始递推即可。

```cpp
vector<int> dp(n + 1, 0);
dp[2] = 1;
```

## 6. 遍历顺序

转移中需要：

$$
dp[i-j]
$$

由于：

$$
i-j<i
$$

所以只要让 $i$ 从小到大遍历，就能保证依赖状态已经求出。

```cpp
for (int i = 3; i <= n; ++i) {
    ...
}
```

内部枚举第一段长度：

```cpp
for (int j = 1; j < i; ++j) {
    ...
}
```

事实上，由于 $j$ 与 $i-j$ 在“直接拆成两段”的情形下具有对称性，可以只枚举到：

$$
\left\lfloor\frac{i}{2}\right\rfloor
$$

于是：

```cpp
for (int j = 1; j <= i / 2; ++j) {
    ...
}
```

即可覆盖所有必要情况。

## 7. 手工推导 dp 数组

从最小状态开始：

$$
dp[2]=1
$$

### $i=3$

切出 $j=1$：

$$
1\times2=2
$$

继续拆右侧：

$$
1\times dp[2]=1
$$

因此：

$$
dp[3]=2
$$

### $i=4$

$j=1$：

$$
\max(1\times3,1\times dp[3])=3
$$

$j=2$：

$$
\max(2\times2,2\times dp[2])=4
$$

因此：

$$
dp[4]=4
$$

继续推导到 10：

| $i$ | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| $dp[i]$ | 1 | 2 | 4 | 6 | 9 | 12 | 18 | 27 | 36 |

## 8. 动态规划标准实现

```cpp
class Solution {
public:
    int integerBreak(int n) {
        vector<int> dp(n + 1, 0);
        dp[2] = 1;

        for (int i = 3; i <= n; ++i) {
            for (int j = 1; j <= i / 2; ++j) {
                dp[i] = max(
                    dp[i],
                    max(j * (i - j), j * dp[i - j])
                );
            }
        }

        return dp[n];
    }
};
```

### 时间复杂度

外层遍历到 $n$，内层最多遍历 $i/2$：

$$
O(n^2)
$$

### 空间复杂度

使用长度为 $n+1$ 的数组：

$$
O(n)
$$

## 9. 为什么 `dp[i-j] * dp[j]` 容易让定义失真

一种常见写法是：

```cpp
dp[i] = max(dp[i], dp[j] * dp[i - j]);
```

如果仍然把：

$$
dp[x]
$$

定义为“必须拆分 $x$ 后的最大乘积”，这就会有问题。

因为这等价于：

- 强制 $j$ 再拆一次；
- 强制 $i-j$ 再拆一次。

但最优方案不一定要求两边都继续拆。

例如 $i=4$：

最优是：

$$
4=2+2
$$

得到：

$$
2\times2=4
$$

如果使用严格定义：

$$
dp[2]=1
$$

那么：

$$
dp[2]\times dp[2]=1
$$

显然错误。

有些代码之所以能使用 `dp[j] * dp[i-j]`，是因为它把状态偷偷改成：

> `dp[i]` 表示数字 $i$ “可以不拆也可以拆”时能获得的最大乘积。

于是会初始化：

```cpp
dp[1] = 1;
dp[2] = 2;
dp[3] = 3;
```

这套状态本身也可以构造出正确算法，但它已经不是题目原义下的 `dp[i]` 了。

<Callout type="warning" title="AC 不代表状态定义就是严谨的">
动态规划最重要的是“定义—初始化—转移”三者一致。为了让公式运行而人为塞入 `dp[2]=2`，如果又声称 `dp[2]` 表示“把 2 拆开后的最大乘积”，逻辑就是矛盾的。
</Callout>

## 10. 数学视角：为什么最优方案倾向于拆成 3

这道题还有一个著名的数学解法：

> 当 $n$ 足够大时，尽可能多拆出 3；如果最后剩下 4，则保留 $2+2$，不要拆成 $3+1$。

这个结论不是经验，而可以逐步证明。

### 10.1 不应该保留大于等于 5 的整数块

设某一块为：

$$
x\ge5
$$

如果把它拆成：

$$
3+(x-3)
$$

乘积变为：

$$
3(x-3)
$$

比较它与原来的 $x$：

$$
3(x-3)>x
$$

等价于：

$$
2x>9
$$

当：

$$
x\ge5
$$

必然成立。

所以最优方案中不会保留 $5$ 或更大的整数块，它们继续拆会更优。

### 10.2 为什么优先拆 3，而不是一直拆 2

对于总和为 6：

拆成三个 2：

$$
2\times2\times2=8
$$

拆成两个 3：

$$
3\times3=9
$$

所以：

$$
3+3
$$

优于：

$$
2+2+2
$$

这说明在保持总和相同的情况下，3 通常比 2 更高效。

### 10.3 为什么不能留下 1

如果最后出现：

$$
3+1
$$

乘积只有：

$$
3\times1=3
$$

而改成：

$$
2+2
$$

乘积为：

$$
2\times2=4
$$

因此：

$$
\boxed{3+1\rightarrow2+2}
$$

更优。

所以贪心策略为：

- 当 $n>4$ 时，不断拆出 3；
- 最后剩下 $2$、$3$ 或 $4$，直接乘到答案中。

## 11. 贪心实现

```cpp
class Solution {
public:
    int integerBreak(int n) {
        if (n == 2) return 1;
        if (n == 3) return 2;

        int ans = 1;

        while (n > 4) {
            ans *= 3;
            n -= 3;
        }

        return ans * n;
    }
};
```

例如：

```text
n = 10
```

拆分过程：

$$
10\rightarrow3+7\rightarrow3+3+4
$$

结果：

$$
3\times3\times4=36
$$

### 复杂度

循环每次减少 3：

$$
O(n)
$$

额外空间：

$$
O(1)
$$

如果进一步利用幂运算，也可以把主要计算写成接近常数次的数学公式，但在算法学习中，理解上述证明比追求这一点更重要。

## 12. DP 与数学法该怎么选

| 维度 | 动态规划 | 数学 / 贪心 |
| --- | --- | --- |
| 思路通用性 | 很强 | 依赖本题结构 |
| 是否需要数学证明 | 较少 | 必须证明 |
| 时间复杂度 | $O(n^2)$ | $O(n)$ |
| 空间复杂度 | $O(n)$ | $O(1)$ |
| 学习价值 | 训练状态定义与转移 | 训练数学优化思维 |

如果目标是学习动态规划，本题首先应该掌握 DP。

数学方法更适合作为第二视角，用来理解：

> 有些 DP 题存在更深层的数学结构，最终可以从“枚举最优子结构”进一步化简成规律。

## 13. 高频错误总结

### 错误一：忘记“至少拆成两个整数”

不能直接返回 $n$ 本身。

例如：

$$
n=3
$$

答案不是 3，而是：

$$
1\times2=2
$$

### 错误二：只使用 `j * dp[i-j]`

会漏掉“右边不继续拆”的情况。

必须同时比较：

$$
j(i-j)
$$

与：

$$
j\cdot dp[i-j]
$$

### 错误三：状态定义和初始化互相矛盾

如果定义：

$$
dp[2]=\text{拆分 2 后的最大乘积}
$$

那么就必须有：

$$
dp[2]=1
$$

不能为了递推方便写成 2，又继续沿用原来的定义。

### 错误四：直接记“拆 3”但不知道为什么

如果没有证明，就很难处理变形题。

至少应该理解三点：

1. $x\ge5$ 时继续拆更优；
2. $3+3$ 优于 $2+2+2$；
3. 不能留下 1，$3+1$ 应改为 $2+2$。

## 14. 这道题带来的状态设计启发

本题最值得迁移的经验不是具体公式，而是：

> **一个量究竟允许“不操作”，还是必须“至少操作一次”，会直接改变 DP 状态的语义。**

类似区别在很多题中都会出现：

- 股票题中“持有 / 不持有”的状态；
- 背包题中“恰好装满 / 至多装满”；
- 子序列题中“必须以当前位置结尾 / 可以在任意位置结尾”；
- 路径题中“可达 / 不可达”。

状态定义越精确，转移就越自然。

## 15. 一句话总结

动态规划核心转移：

$$
\boxed{
dp[i]=\max_{1\le j<i}
\left\{
 j(i-j),\;j\cdot dp[i-j]
\right\}
}
$$

数学规律则可以概括为：

> **尽量拆成 3，但不要留下 1；若最后剩 4，就保留成 $2+2$。**

下一篇“不同的二叉搜索树”会出现一个非常经典的新结构：**枚举根节点，把左右两个独立子问题的方案数相乘**。

```go tab="Go"
func integerBreak(n int) int {
    dp := make([]int, n+1)
    dp[2] = 1

    for i := 3; i <= n; i++ {
        for j := 1; j <= i/2; j++ {
            direct := j * (i - j)
            split := j * dp[i-j]
            if direct > dp[i] {
                dp[i] = direct
            }
            if split > dp[i] {
                dp[i] = split
            }
        }
    }

    return dp[n]
}
```

```rust tab="Rust"
impl Solution {
    pub fn integer_break(n: i32) -> i32 {
        let n = n as usize;
        let mut dp = vec![0i32; n + 1];
        dp[2] = 1;

        for i in 3..=n {
            for j in 1..=i / 2 {
                let direct = (j * (i - j)) as i32;

    }
```
