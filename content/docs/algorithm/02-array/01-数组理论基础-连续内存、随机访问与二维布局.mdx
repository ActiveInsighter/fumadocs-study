# 数组理论基础：连续内存、随机访问与二维布局

数组是算法学习中最基础的数据结构之一。很多数组题思路并不复杂，真正容易出错的地方往往是：**下标、边界、元素移动和内存模型**。

最重要的一句话是：

> **数组是由一组相同类型元素构成，并按照固定顺序存放的数据结构。对于传统连续数组，元素在内存中连续排列。**

![算法通关数组](https://file1.kamacoder.com/i/algo/%E7%AE%97%E6%B3%95%E9%80%9A%E5%85%B3%E6%95%B0%E7%BB%84.png)

<Callout title="先记住两个核心性质" type="info">
1. 常见数组下标从 `0` 开始；
2. 连续数组支持 $O(1)$ 随机访问，但在中间插入、删除通常需要移动元素。
</Callout>

---

## 1. 为什么数组可以 $O(1)$ 随机访问

设数组首地址为 $B$，每个元素占 $w$ 字节，那么第 $i$ 个元素的地址可以直接计算：

$$
\operatorname{addr}(a[i]) = B + i\cdot w
$$

因此访问 `a[i]` 不需要从头遍历到第 $i$ 个位置，而是通过一次地址计算直接定位。

所以数组随机访问的时间复杂度为：

$$
O(1)
$$

这也是数组与链表最本质的差异之一：链表节点通常不连续，访问第 $i$ 个节点往往需要逐个跳转。

---

## 2. 为什么数组中间插入和删除通常是 $O(n)$

连续布局带来快速随机访问，也带来了“必须保持连续”的约束。

例如删除下标为 `3` 的元素：

![算法通关数组1](https://file1.kamacoder.com/i/algo/%E7%AE%97%E6%B3%95%E9%80%9A%E5%85%B3%E6%95%B0%E7%BB%841.png)

为了继续保持逻辑上的连续顺序，后面的元素通常要向前移动。

若长度为 $n$，删除位置为 $i$，最多需要移动约：

$$
n-i-1
$$

个元素，因此中间删除的最坏复杂度为：

$$
O(n)
$$

同理，在中间插入一个元素时，为了腾出位置，后面的元素也可能整体后移，因此通常也是 $O(n)$。

<Callout title="“删除数组元素”到底是什么意思？" type="warning">
对固定长度的原生数组来说，物理容量不会因为删除一个元素而自动缩短。算法题中所谓“删除”，经常只是覆盖、移动有效元素，并维护新的逻辑长度。
</Callout>

## 3. 固定数组与动态数组不是一回事

以 C++ 为例：

```cpp
int a[10];
std::array<int, 10> b;
std::vector<int> c;
```

它们都可以用下标访问，但语义并不完全相同。

| 结构 | 长度是否可动态变化 | 元素是否连续 | 随机访问 |
| --- | --- | --- | --- |
| 原生数组 `T a[N]` | 否 | 是 | $O(1)$ |
| `std::array<T, N>` | 否 | 是 | $O(1)$ |
| `std::vector<T>` | 是 | 是 | $O(1)$ |

`vector` 是**动态数组容器**。它维护一块连续存储空间，当容量不足时会申请更大的空间并搬迁原有元素。

因此：

- `push_back` 通常是摊还 $O(1)$；
- 某次扩容可能需要搬移 $O(n)$ 个元素；
- 中间插入、删除仍通常需要 $O(n)$ 的移动。

## 4. 下标从 0 开始为什么很自然

如果数组首地址就是第一个元素地址，那么：

$$
\operatorname{addr}(a[0]) = B + 0\cdot w = B
$$

第 $i$ 个下标本质上就是“相对于首地址偏移了多少个元素”。

因此从地址计算角度看，0 起始下标非常自然。

当然，“数组必须从 0 开始”不是数学定律，而是绝大多数主流语言采用的约定。

## 5. 二维数组到底是什么

二维数组可以理解为“按行和列组织的一组元素”：

![二维数组](https://file1.kamacoder.com/i/algo/20240606105522.png)

但“二维数组在内存中是否整体连续”要看语言和具体数据结构，不能一概而论。

### C++ 原生二维数组

例如：

```cpp
int a[2][3] = {
    {0, 1, 2},
    {3, 4, 5}
};
```

这里 6 个 `int` 按行连续存放。

若一个 `int` 占 4 字节，则相邻元素地址通常相差 4 字节。

![数组内存](https://file1.kamacoder.com/i/algo/20210310150641186.png)

对于一个 $R\times C$ 的按行存储二维数组，元素 `a[i][j]` 相对首元素的线性偏移量为：

$$
i\cdot C+j
$$

因此地址可写成：

$$
B + (iC+j)w
$$

这就是“行优先存储”。

---

## 6. Java 的 `int[][]` 为什么不同

Java 中：

```java
int[][] a = {
    {1, 2, 3},
    {4, 5, 6}
};
```

`a` 更接近“数组的数组”：外层数组保存对各行数组的引用，各行是独立对象。

因此各行没有必要彼此紧挨着存放。

![Java 二维数组示意](https://file1.kamacoder.com/i/algo/20201214111631844.png)

这也解释了为什么 Java 可以自然构造不规则二维数组：

```java
int[][] a = new int[3][];
a[0] = new int[2];
a[1] = new int[5];
a[2] = new int[1];
```

三行长度完全可以不同。

<Callout title="不要把语法外观和物理内存布局混为一谈" type="tip">
`a[i][j]` 这种写法在多种语言里都存在，但底层实现可能完全不同。做算法题时先关注抽象语义；涉及缓存局部性、性能或底层实现时，再分析真实布局。
</Callout>

## 7. 数组最常见的复杂度模型

| 操作 | 典型复杂度 |
| --- | ---: |
| 按下标读取/修改 | $O(1)$ |
| 遍历全部元素 | $O(n)$ |
| 在末尾追加（容量足够） | $O(1)$ |
| 动态数组尾插 | 摊还 $O(1)$ |
| 中间插入 | $O(n)$ |
| 中间删除 | $O(n)$ |
| 在无序数组中按值查找 | $O(n)$ |
| 在有序数组中二分查找 | $O(\log n)$ |

数组题的核心往往不是“会不会定义数组”，而是如何利用它的连续性和下标特征设计更高效的算法，例如：

- 二分查找；
- 双指针；
- 滑动窗口；
- 前缀和；
- 差分；
- 模拟矩阵。

## 8. 一个小实验：观察连续地址

### C++

```cpp
#include <iostream>
using namespace std;

int main() {
    int a[2][3] = {{0, 1, 2}, {3, 4, 5}};

    for (int i = 0; i < 2; ++i) {
        for (int j = 0; j < 3; ++j) {
            cout << &a[i][j] << ' ';
        }
        cout << '\n';
    }
}
```

C++ 原生二维数组中，这些地址会按元素大小连续递增。

### Java

```java
public class Main {
    public static void main(String[] args) {
        int[][] a = {{0, 1, 2}, {3, 4, 5}};

        System.out.println(a[0]);
        System.out.println(a[1]);
    }
}
```

打印出的内容不是可用于证明物理连续性的真实元素地址。Java 对象布局由 JVM 管理。

### Python

```python
a = [[0, 1, 2], [3, 4, 5]]

print(id(a[0]))
print(id(a[1]))
```

Python 的二维列表同样是“列表中保存对象引用”的模型，不应把它理解为 C/C++ 原生二维数组那样的一整块连续整数内存。

---

## 9. 本篇小结

理解数组时，最值得建立的是下面这条因果链：

> **连续存储 → 可以通过偏移量直接寻址 → 随机访问 $O(1)$ → 为维持顺序，中间插入删除通常需要移动元素 → $O(n)$。**

之后学习二分查找、双指针、滑动窗口和前缀和时，很多代码细节都会建立在这套数组模型之上。
