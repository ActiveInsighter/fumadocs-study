# 双指针法总结

双指针并不是一种独立的数据结构。

它更像是一种：

> **通过两个位置变量之间的相对关系，减少重复扫描、表达区间状态或定位目标位置的算法技巧。**

在前面的题目中，双指针已经出现在：

- 数组；
- 字符串；
- 链表；
- nSum；
- 环检测。

这些题表面差异很大，但底层可以统一成几类非常稳定的模型。

---

## 1. 双指针的本质

最重要的并不是：

```text
代码里出现了两个变量
```

而是：

> **两个指针承担不同职责，或者维持某种稳定关系。**

常见关系包括：

```text
读 / 写
左 / 右
前 / 后
快 / 慢
固定距离
不同速度
```

只要能利用这种关系减少重复工作，就可能形成双指针优化。

---

# 2. 第一类：快慢指针——读写分离

最典型题目：

- 移除元素；
- 删除重复项；
- 移动零；
- 去除多余空格。

核心结构：

```text
fast = 读取原数据
slow = 写入有效数据
```

模板：

```cpp
int slow = 0;

for (int fast = 0; fast < n; ++fast) {
    if (当前元素应该保留) {
        a[slow++] = a[fast];
    }
}
```

---

## 3. 快慢指针为什么能把 $O(n^2)$ 降成 $O(n)$

很多“删除”问题的暴力做法是：

```text
发现一个无效元素
      ↓
把后面所有元素整体前移
```

假设每删除一次都要移动 $O(n)$ 个元素，那么总复杂度可能达到：

$$
O(n^2)
$$

快慢指针则改成：

```text
每个元素只读一次
每个有效元素最多写一次
```

所以：

$$
O(n)
$$

这其实就是：

> **原地过滤（in-place filter）**

---

## 4. 快慢指针最重要的不变量

以“移除元素”为例：

在每轮处理前：

> `[0, slow)` 中已经全部是正确保留的元素。

`fast` 扫描到一个合法元素时：

```cpp
a[slow++] = a[fast];
```

这个不变量继续成立。

因此 `slow` 最终往往同时表示：

```text
新数组长度
```

这也是很多快慢指针题的共同特征。

---

# 5. 第二类：相向双指针——从两端逼近

典型题目：

- 反转字符串；
- 回文判断；
- 有序数组两数之和；
- 三数之和；
- 四数之和。

模板：

```cpp
int left = 0;
int right = n - 1;

while (left < right) {
    // 根据两端状态做操作

    ...
}
```

两个指针：

```text
left  →
       ← right
```

不断向中间逼近。

---

## 6. 反转类相向双指针

反转字符串中：

```text
left / right
```

处理的是一对镜像位置。

每轮：

```cpp
swap(a[left], a[right]);
++left;
--right;
```

镜像关系：

$$
i\leftrightarrow n-1-i
$$

时间复杂度：

$$
O(n)
$$

空间复杂度：

$$
O(1)
$$

---

## 7. 查询类相向双指针

在有序数组中，如果要寻找：

$$
a[left]+a[right]=target
$$

利用排序的单调性：

### 和太小

$$
sum<target
$$

需要增大和：

```cpp
++left;
```

### 和太大

$$
sum>target
$$

需要减小和：

```cpp
--right;
```

所以排序把“二维枚举”转化成了：

```text
一次线性收缩
```

这就是三数之和、四数之和的核心基础。

---

# 8. 第三类：扩张型读写指针——从后往前

典型题目：

- 替换数字；
- 替换空格；
- 某个字符扩张成多个字符。

如果一个原元素会变成多个目标元素，例如：

```text
'1' -> "number"
```

从前往后写会覆盖还没有处理的原数据。

因此更好的方法是：

```text
先统计最终长度
      ↓
扩容
      ↓
old 指向原末尾
new 指向新末尾
      ↓
从后往前填充
```

---

## 9. 为什么扩张问题从后往前

假设原数组：

```text
[a][1][b]
```

把 `1` 替换成 6 个字符。

如果从前往后，需要反复把后面的：

```text
b
```

往右搬。

但如果先扩容，然后从尾部写：

```text
旧数据尚未处理部分始终在左边
新写入区域始终在右边
```

所以不会覆盖未读数据。

可以记成经验：

```text
压缩 → 从前往后
扩张 → 从后往前
```

这条规律非常实用。

---

# 10. 第四类：链表前后边界双指针

典型题目：

- 反转链表；
- 链表相交。

这类题不一定体现“速度快慢”，而是两个指针负责：

```text
已处理区域
未处理区域
```

例如反转链表：

```text
pre = 已反转部分
cur = 未处理部分
```

每轮：

```text
保存 next
      ↓
cur.next = pre
      ↓
pre 前进
cur 前进
```

核心不是“两根指针移动”，而是：

> **用两个指针维护链表处理边界。**

---

# 11. 第五类：固定距离双指针

典型题目：

> 删除链表倒数第 $N$ 个节点。

思想：

```text
fast 先走若干步
      ↓
slow 再开始走
      ↓
两者保持固定距离
      ↓
fast 到边界时
slow 自动定位目标
```

这是“倒数位置”转化为“正向距离”的经典方法。

---

## 12. 为什么固定距离可以找倒数位置

如果：

```text
fast 比 slow 领先 k 步
```

那么 fast 到链表尾部时：

```text
slow 距离尾部仍然是 k
```

所以问题：

```text
找倒数第 k 个节点
```

可以转化成：

```text
制造两个指针之间 k 的间距
```

这是一个非常通用的思想。

---

# 13. 第六类：速度差双指针

典型题目：

- 环形链表；
- 环形链表 II；
- 快乐数的 Floyd 判环。

定义：

```text
slow 每次走 1
fast 每次走 2
```

如果存在环，fast 会在环中追上 slow。

因为相对速度：

$$
2-1=1
$$

每轮 fast 相对 slow 前进一个节点。

最终必然相遇。

---

## 14. Floyd 判环的两个阶段

### 第一阶段：判断是否有环

```text
slow = 1 步
fast = 2 步
```

若相遇：

```text
有环
```

---

### 第二阶段：寻找入口

相遇后：

```text
p1 = head
p2 = meeting
```

两者每次各走 1 步。

再次相遇：

```text
环入口
```

数学关系：

设：

- 头到入口：$x$；
- 入口到相遇点：$y$；
- 相遇点回入口：$z$。

相遇时：

$$
x+y+n(y+z)=2(x+y)
$$

推出：

$$
x=(n-1)(y+z)+z
$$

所以从：

```text
head
```

和：

```text
meeting
```

同时走 $x$ 步，最终位置相同。

---

# 15. 第七类：路径补偿双指针

链表相交的“换头法”也是一个非常漂亮的双指针模型。

两个链表：

```text
A 长度 = a + c
B 长度 = b + c
```

其中：

```text
c = 公共尾部长度
```

让：

```text
pA 走 A 再走 B
pB 走 B 再走 A
```

两者路径长度分别：

$$
a+c+b+c
$$

和：

$$
b+c+a+c
$$

完全相同。

于是长度差自动抵消。

本质上是：

> **通过重新安排两个指针的路径，让它们最终拥有相同剩余距离。**

---

# 16. 第八类：nSum 中的双指针降维

三数之和：

$$
a+b+c=0
$$

固定：

$$
a
$$

之后变成：

$$
b+c=-a
$$

然后使用有序数组双指针。

复杂度：

$$
O(n^3)\rightarrow O(n^2)
$$

---

## 17. 四数之和

四数之和：

$$
a+b+c+d=target
$$

固定：

$$
a,b
$$

剩余：

$$
c+d=target-a-b
$$

再次使用双指针。

复杂度：

$$
O(n^4)\rightarrow O(n^3)
$$

所以通用结构：

```text
nSum
 ↓ 固定一个数
(n-1)Sum
 ↓
...
 ↓
2Sum
 ↓
双指针
```

---

## 18. 双指针为什么可以减少一层循环

暴力搜索常见形式：

```text
固定一个位置
再枚举另一个位置
```

如果数组有序，就可以通过：

```text
当前结果偏小 / 偏大
```

直接判断：

```text
应该移动左端还是右端
```

于是原本：

$$
O(n^2)
$$

的“两层组合枚举”可以压缩成：

$$
O(n)
$$

的一次指针扫描。

这就是双指针常说的：

> **在一个循环中完成两个循环的工作。**

---

# 19. 双指针依赖的三种信息

双指针并不是任何题都能套。

通常需要至少一种结构信息。

### 1. 单调性

例如有序数组：

```text
left 右移 → 值变大
right 左移 → 值变小
```

---

### 2. 相对距离

例如：

```text
fast 比 slow 领先 N
```

---

### 3. 已处理 / 未处理边界

例如：

```text
slow 左边已经全部合法
fast 负责扫描剩余部分
```

如果题目中找不到这些结构关系，双指针可能就不是自然解法。

---

# 20. 双指针题最重要的是“不变量”

很多双指针 bug 都不是语法问题，而是：

```text
自己不知道每个指针究竟代表什么
```

建议做题时明确写出不变量。

例如移除元素：

> `[0, slow)` 全部为已保留元素。

反转链表：

> `pre` 指向已反转部分，`cur` 指向未处理部分。

删除倒数节点：

> `fast` 与 `slow` 始终保持固定距离。

三数之和：

> 在当前有序区间中，`left/right` 包围全部尚可能形成答案的候选。

只要不变量明确，代码就会稳定很多。

---

# 21. 常见双指针移动方式

可以把移动方式总结成四种。

### 同向同速

```text
fast →
slow →
```

但初始距离不同。

典型：

```text
删除倒数第 N 个节点
```

---

### 同向不同职责

```text
fast = 读
slow = 写
```

典型：

```text
移除元素
```

---

### 相向移动

```text
left →
      ← right
```

典型：

```text
反转
nSum
回文
```

---

### 同向不同速度

```text
slow = 1
fast = 2
```

典型：

```text
Floyd 判环
```

# 22. 本模块题目速查表

| 题目 | 双指针类型 | 核心关系 | 时间 |
| --- | --- | --- | ---: |
| 移除元素 | 快慢 / 读写 | `fast` 读，`slow` 写 | $O(n)$ |
| 反转字符串 | 相向 | 镜像交换 | $O(n)$ |
| 替换数字 | 后向读写 | 扩容后从尾填充 | $O(n)$ |
| 翻转字符串里的单词 | 快慢 + 相向 | 压缩 + 区间反转 | $O(n)$ |

| 删除倒数第 N 个节点 | 固定距离 | fast 领先 slow | $O(n)$ |
| 链表相交 | 路径补偿 | A+B 与 B+A | $O(m+n)$ |
| 环形链表 II | 速度差 | 1 步 / 2 步 | $O(n)$ |
| 三数之和 | 排序 + 相向 | 固定 1 个，双指针 2Sum | $O(n^2)$ |
| 四数之和 | 排序 + 相向 | 固定 2 个，双指针 2Sum | $O(n^3)$ |

# 23. 与哈希法如何选择

双指针和哈希表经常能解决相似问题。

例如两数之和。

### 哈希

适合：

```text
数组未排序
需要原始下标
快速查询补数
```

平均：

$$
O(n)
$$

额外空间：

$$
O(n)
$$

### 排序 + 双指针

适合：

```text
只关心数值组合
允许改变顺序或复制后排序
希望 O(1) 额外搜索空间
```

时间：

$$
O(n\log n)
$$

所以并不存在：

```text
双指针一定优于哈希
```

或：

```text
哈希一定优于双指针
```

应根据题目输出要求选择。

---

# 24. 为什么三数之和更适合双指针

三数之和要求：

```text
所有不重复三元组
```

如果使用哈希：

```text
找到答案并不难
```

真正麻烦的是：

```text
稳定去重
```

排序之后：

```text
相同数字聚在一起
```

于是：

```text
固定值去重
左右值去重
```

都变得非常自然。

所以双指针不仅降低复杂度，还解决了：

> **结果去重的结构化问题。**

---

# 25. 数组删除类题为什么应警惕 erase

例如：

```cpp
for (...) {
    if (...) {
        vector.erase(...);
    }
}
```

看起来只有一层循环。

但 `erase` 本身可能需要移动后续元素：

$$
O(n)
$$

所以整体可能变成：

$$
O(n^2)
$$

遇到：

```text
原地删除 / 过滤
```

应该优先考虑：

```text
快慢指针覆盖
```

而不是频繁真正删除。

---

# 26. 字符串变长问题为什么反向处理

如果原地扩张：

```text
1 个元素 → 多个元素
```

前向写入会影响尚未处理的数据。

因此：

```text
先扩容
再从后往前
```

这类技巧在：

- 替换空格；
- 替换数字；
- 某些编码转义；

中都非常通用。

---

# 27. 链表双指针与数组双指针的差异

数组支持：

```text
随机访问
```

所以指针通常就是：

```text
下标
```

链表只能：

```text
next
```

向后走。

所以链表双指针更关注：

- 距离；
- 速度；
- 路径；
- 节点引用；
- 已处理 / 未处理边界。

这也是为什么链表中的双指针技巧更“抽象”。

---

# 28. 面试时如何检查双指针代码

可以按下面顺序检查。

### 1. 每个指针的语义是什么？

例如：

```text
slow 指向哪里？
fast 指向哪里？
```

---

### 2. 循环条件是什么？

```text
left < right
fast != null
fast.next != null
```

边界写错是最常见 bug。

---

### 3. 哪些情况下移动哪个指针？

不要写成：

```text
每轮全部无脑移动
```

很多题必须根据条件移动。

---

### 4. 移动之前有没有破坏信息？

链表尤其要问：

```text
改 next 之前是否保存了原 next？
```

---

### 5. 循环结束时指针在哪里？

例如：

```text
slow 是长度？
slow 是目标节点？
slow 是目标前驱？
pre 是新头？
```

只有明确终态，返回值才不会错。

---

# 29. 双指针常见错误总表

| 错误 | 常见后果 |
| --- | --- |
| 指针语义不明确 | 移动条件混乱 |
| `left < right` / `<=` 写错 | 漏解或重复处理 |
| 快慢间距差 1 | 链表定位错误 |
| 链表先改 `next` 再保存后继 | 断链 |
| 扩张字符串从前往后写 | 覆盖未处理数据 |
| nSum 去重层级错误 | 漏解或重复答案 |
| 忘记排序就用左右指针 | 移动方向失去依据 |

---

# 30. 一套统一识别流程

遇到新题，可以按下面思路判断：

```text
是否需要原地过滤？
 └─ 是 → 快慢指针（读 / 写）

是否需要处理两端？
 └─ 是 → 相向双指针

是否要求倒数位置？
 └─ 是 → 固定距离双指针

是否存在环 / 重复轨迹？
 └─ 是 → 快慢速度差

是否是字符串扩张？
 └─ 是 → 扩容 + 后向双指针

是否是有序 nSum？
 └─ 是 → 固定若干元素 + 2Sum 双指针
```

# 31. 双指针与滑动窗口的关系

滑动窗口其实也可以看作双指针。

定义：

```text
left
right
```

共同维护一个区间：

$$
[left,right]
$$

区别在于：

- 普通相向双指针往往从两端向中间；
- 滑动窗口通常两个指针都向右。

其本质仍然是：

> 用两个边界变量表示当前有效区间。

所以从更广义上看：

```text
滑动窗口也是双指针思想的一个分支。
```

---

# 32. 双指针学习的真正目标

真正掌握双指针，不是记：

```text
left
right
slow
fast
```

这些变量名。

而是能回答：

### 为什么需要两个位置？

### 它们分别表示什么？

### 它们之间保持什么关系？

### 为什么某种条件下只移动其中一个？

### 为什么不会漏掉答案？

### 为什么总移动次数是线性的？

如果这些问题都能解释，说明真正理解了双指针。

---

## 33. 最终总结

双指针可以统一成一句话：

> **用两个位置之间的关系，把重复搜索转化为一次受控扫描。**

常见模型：

```text
读 / 写          → 原地过滤
左 / 右          → 反转、回文、nSum
旧尾 / 新尾      → 原地扩张
pre / cur        → 链表边界
固定间距         → 倒数位置
不同速度         → 环检测
路径补偿         → 链表相交
```

最值得记住的不是某一道题，而是下面这个判断：

```text
如果暴力算法中有两层扫描，
能否让第二个位置不再每次从头搜索，
而是利用上一次的位置继续移动？
```

如果答案是“可以”，那么双指针往往就是把复杂度降下来的关键。
