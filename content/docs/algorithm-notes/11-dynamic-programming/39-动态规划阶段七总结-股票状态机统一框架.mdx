# 动态规划阶段七总结：股票状态机统一框架

前面几篇已经连续解决了股票系列中的四类典型问题：

- 可以进行任意多次交易；
- 最多完成两笔交易；
- 最多完成 $k$ 笔交易；
- 可以无限交易，但卖出后存在一天冷冻期。

这些题看起来规则不同，但真正的核心只有一句话：

> **把“当前处于什么交易阶段”编码成状态，然后只允许合法状态之间发生转移。**

股票问题因此非常适合用“状态机动态规划”统一理解。

<Callout type="info" title="股票 DP 的真正难点">
难点通常不在计算，而在于：状态是否完整、状态之间是否互斥、一次转移是否对应合法的买卖动作。
</Callout>

## 1. 先统一一个最重要的概念：状态不是“今天必须做了什么”

设：

$$
dp[i][j]
$$

表示第 $i$ 天结束时处于状态 $j$ 能获得的最大现金。

例如“持有股票状态”并不意味着第 $i$ 天一定刚刚买入。

它可能来自：

1. 前一天已经持有，今天什么也不做；
2. 前一天不持有，今天执行买入。

因此股票 DP 中最常见的形式都是：

$$
\text{今天的某个状态}
=
\max(\text{昨天保持该状态},\text{昨天其他状态转移而来})
$$

这也是理解整个股票系列的第一把钥匙。

## 2. 无限次交易：最基础的两状态模型

对于 LeetCode 122「买卖股票的最佳时机 II」，每天只需要区分：

- `hold`：结束时持有股票；
- `cash`：结束时不持有股票。

定义：

$$
dp[i][0]=\text{第 }i\text{ 天结束时持股的最大现金}
$$

$$
dp[i][1]=\text{第 }i\text{ 天结束时不持股的最大现金}
$$

### 2.1 持股状态

今天持股有两种来源：

- 昨天已经持股；
- 昨天不持股，今天买入。

所以：

$$
\boxed{
dp[i][0]
=
\max(dp[i-1][0],\;dp[i-1][1]-prices[i])
}
$$

### 2.2 不持股状态

今天不持股也有两种来源：

- 昨天已经不持股；
- 昨天持股，今天卖出。

因此：

$$
\boxed{
dp[i][1]
=
\max(dp[i-1][1],\;dp[i-1][0]+prices[i])
}
$$

### 2.3 与“只能交易一次”的根本区别

如果只能完成一次交易，那么买入时不能携带历史交易利润：

$$
\boxed{
dp[i][0]=\max(dp[i-1][0],-prices[i])
}
$$

而允许无限交易后，买入可以建立在此前已获得的利润上：

$$
\boxed{
dp[i][0]=\max(dp[i-1][0],dp[i-1][1]-prices[i])
}
$$

<Callout type="warning" title="不要只背代码差一项">
`-prices[i]` 与 `dp[i-1][1]-prices[i]` 的区别，本质是“这次买入前能不能已经完成过交易”。这比记住递推式本身更重要。
</Callout>

## 3. 最多两笔交易：交易阶段必须进入状态

当题目把交易次数限制为最多两笔，仅仅记录“持有 / 不持有”已经不够。

因为：

```text
第一次买入后的持有
```

和：

```text
第二次买入后的持有
```

虽然都叫“持有股票”，但剩余可执行交易次数不同，因此未来决策不同。

于是可以定义五个状态：

| 状态 | 含义 |
| --- | --- |
| 0 | 尚未进行操作 |
| 1 | 第一次买入后 |
| 2 | 第一次卖出后 |
| 3 | 第二次买入后 |
| 4 | 第二次卖出后 |

对应转移：

$$
\boxed{
dp[i][1]
=
\max(dp[i-1][1],dp[i-1][0]-prices[i])
}
$$

$$
\boxed{
dp[i][2]
=
\max(dp[i-1][2],dp[i-1][1]+prices[i])
}
$$

$$
\boxed{
dp[i][3]
=
\max(dp[i-1][3],dp[i-1][2]-prices[i])
}
$$

$$
\boxed{
dp[i][4]
=
\max(dp[i-1][4],dp[i-1][3]+prices[i])
}
$$

## 4. 从两笔交易推广到最多 $k$ 笔交易

LeetCode 188 的本质，就是把上一题的两组“买入 / 卖出”推广到 $k$ 组。

因此总状态数为：

$$
\boxed{2k+1}
$$

其中：

- $0$：尚未操作；
- 奇数状态：第若干次买入后；
- 偶数状态：第若干次卖出后。

于是有统一模板。

### 4.1 奇数状态：买入

若 $j$ 为奇数：

$$
\boxed{
dp[i][j]
=
\max(dp[i-1][j],dp[i-1][j-1]-prices[i])
}
$$

### 4.2 偶数状态：卖出

若 $j$ 为偶数且 $j>0$：

$$
\boxed{
dp[i][j]
=
\max(dp[i-1][j],dp[i-1][j-1]+prices[i])
}
$$

于是“两次交易”只是 $k=2$ 的特殊情况。

## 5. 冷冻期：交易次数没变，时间约束变了

LeetCode 309 与无限次交易的区别并不是交易次数，而是：

> 卖出后的下一天不能买。

因此必须让 DP 记住“当前不持股到底处于哪一种时间阶段”。

一种清晰的状态拆分是：

| 状态 | 含义 |
| --- | --- |
| 0 | 持有股票 |
| 1 | 不持股，且可以买入 |
| 2 | 今天刚卖出 |
| 3 | 今天处于冷冻期 |

对应核心关系：

$$
\boxed{
dp[i][0]
=
\max(
 dp[i-1][0],
 dp[i-1][1]-prices[i],
 dp[i-1][3]-prices[i]
)
}
$$

$$
\boxed{
dp[i][1]
=
\max(dp[i-1][1],dp[i-1][3])
}
$$

$$
\boxed{
dp[i][2]=dp[i-1][0]+prices[i]
}
$$

$$
\boxed{
dp[i][3]=dp[i-1][2]
}
$$

<Callout type="info" title="什么时候应该增加状态？">
只要题目增加的规则会影响“下一天允许执行哪些动作”，就应该考虑把这段额外信息编码进状态，而不是强行修改原来的两状态转移。
</Callout>

## 6. 四道题真正变化的是什么

<Tabs items={["无限交易", "两笔交易", "k 笔交易", "冷冻期"]}>
<Tab value="无限交易">

只需要记录当前是否持股：

```text
持股 ↔ 不持股
```

买入时可以携带此前交易利润。

</Tab>
<Tab value="两笔交易">

必须额外记录已经进行到第几次买卖：

```text
未操作 → 买1 → 卖1 → 买2 → 卖2
```

</Tab>
<Tab value="k 笔交易">

将“两笔交易”的状态链推广：

```text
0 → 买1 → 卖1 → 买2 → 卖2 → ... → 买k → 卖k
```

状态总数为 $2k+1$。

</Tab>
<Tab value="冷冻期">

交易次数不限，但卖出产生额外时间约束，因此需要区分不同“不持股”状态。

</Tab>
</Tabs>

## 7. 股票 DP 的统一建模方法

遇到新的股票题，可以依次问四个问题。

### 7.1 一天结束时需要记住哪些信息？

最基础的是：

```text
是否持股
```

如果未来合法操作还依赖其他信息，就继续扩展：

```text
已经完成多少笔交易？
今天是不是刚卖出？
现在是不是冷冻期？
```

### 7.2 每个状态能从哪里来？

对每一个状态，始终问：

> 今天结束时处于这个状态，昨天可能处于哪些状态？

而不是直接凭感觉写公式。

### 7.3 转移时发生了什么动作？

股票题的动作只有三类：

```text
不操作
买入：现金 - prices[i]
卖出：现金 + prices[i]
```

后续若有手续费，再在买入或卖出的一侧扣一次即可。

### 7.4 最终答案落在哪个状态？

通常结束时不持有股票一定不会比持有更差。

因为持股状态意味着最后一股股票还没有兑现。

但如果“不持有”被拆成多个子状态，则需要从合法终止状态中取最大值。

## 8. 一张表比较四种模型

| 问题 | 关键限制 | 状态数量 | 核心变化 |
| --- | --- | ---: | --- |
| 股票 II | 无限次交易 | 2 | 买入可继承历史利润 |
| 股票 III | 最多 2 笔 | 5 | 记录第几次买卖 |
| 股票 IV | 最多 $k$ 笔 | $2k+1$ | 将交易阶段参数化 |
| 冷冻期 | 卖出后隔一天才能买 | 3 或 4 | 记录卖出后的时间阶段 |

这张表比单独背四套代码更重要。

## 9. 为什么股票问题天然适合状态机

股票交易具有明确的离散状态：

```text
未持股
持股
第一次买入后
第一次卖出后
冷冻中
……
```

而每天只会发生少量合法动作。

因此可以把问题理解成一个有向图：

```text
状态 = 节点
合法操作 = 边
边上的收益/代价 = 买卖产生的现金变化
```

动态规划所做的事情，就是沿时间轴逐天推进，在每个状态中保留能够到达该状态的最大现金。

这也是“状态机 DP”最典型的应用。

## 10. 常见错误

<Cards>
<Card title="把状态理解成当天动作">
“第一次买入状态”表示到今天为止已经完成第一次买入且尚未卖出，不代表今天一定执行了买入。
</Card>
<Card title="只看持有/不持有，不看交易阶段">
存在交易次数限制时，同样是持股，第一次买入后和第二次买入后的未来权限并不相同。
</Card>
<Card title="冷冻期仍硬套两个状态">
一旦卖出会影响下一天能否买入，就必须让状态保存这一时间信息。
</Card>
<Card title="同一天连续使用更新后的值却没有验证合法性">
空间压缩后要特别注意新值是否会被同一天后续转移再次使用，从而隐式完成多次动作。
</Card>
</Cards>

## 11. 一套通用检查清单

写股票 DP 时，可以逐项检查：

1. `dp` 的每个状态是否描述完整？
2. 状态是“当前处于某阶段”，还是“今天做了某动作”？
3. 买入是否应该携带以前的利润？
4. 是否有限制交易次数？
5. 是否存在冷冻期、手续费等附加条件？
6. 每条转移是否只完成一个合法动作？
7. 初始化是否允许了不可能出现的状态？
8. 最终答案应该取哪个或哪些“不持股状态”？

<Callout type="tip" title="真正需要记忆的不是四套模板">
记住“限制条件决定状态信息，状态信息决定转移”。掌握这一点后，股票系列中的大多数变体都只是给状态机增加或删除约束。
</Callout>

## 12. 阶段结论

到这里，股票 DP 已经从简单两状态扩展到：

```text
持有状态
    ↓
交易阶段状态
    ↓
带时间约束的状态
```

可以把整个阶段压缩成下面三个问题：

$$
\boxed{
\text{现在是什么状态？}
}
$$

$$
\boxed{
\text{昨天哪些状态能合法到达这里？}
}
$$

$$
\boxed{
\text{这条边对应买、卖还是不操作？}
}
$$

只要这三件事没有写错，股票类动态规划通常就已经完成了大半。
