# 背包问题总结

背包问题不是某一道题，而是一整类动态规划模型。

前面的学习已经覆盖：

- 01 背包；
- 完全背包；
- 多重背包；
- 能否装满；
- 最大价值；
- 方案计数；
- 最少物品数；
- 组合数与排列数。

如果只记某一道题的递推式，很容易在题目稍微变形时失去方向。更稳定的方法是先回答四个问题：

1. **每种物品能使用多少次？**
2. **`dp[j]` 到底表示什么？**
3. **目标是最大值、可达性、方案数还是最小值？**
4. **当前状态能不能在本轮继续使用刚更新出的状态？**

<Callout type="info" title="背包题真正难点">
递推公式通常并不复杂。真正决定代码是否正确的，是 **状态语义 + 初始化 + 遍历顺序**。特别是一维滚动数组中，容量正序与倒序直接决定同一个物品能否重复使用。
</Callout>

## 1. 三类基础背包的关系

原资料中的关系图：

![常见背包问题关系图](https://file1.kamacoder.com/i/algo/20230310000726.png)

三类模型最核心的区别只有一个：

| 模型 | 第 $i$ 种物品最多使用次数 | 一维 DP 的典型容量遍历 |
| --- | ---: | --- |
| 01 背包 | $1$ 次 | 倒序 |
| 完全背包 | 无限次 | 正序 |
| 多重背包 | $s_i$ 次 | 枚举数量 / 拆成 01 背包 |

可以写成统一约束：

$$
0\le x_i\le s_i
$$

其中：

- 01 背包：$s_i=1$；
- 完全背包：$s_i=+\infty$；
- 多重背包：$s_i$ 为有限正整数。

因此三类背包并不是彼此独立的算法，而是对 **物品使用次数约束** 的三种情况。

## 2. 背包题仍然遵循动态规划五步法

面对任何背包题，都可以依次检查：

1. 确定 `dp` 数组及下标含义；
2. 推导状态转移；
3. 设计初始化；
4. 确定遍历顺序；
5. 手算一个小样例验证。

其中最值得形成条件反射的是第 1、3、4 步。

原因是：**同一个递推式，在状态语义或初始化不同的情况下，可以表示完全不同的问题。**

例如：

```cpp
dp[j] += dp[j - w];
```

既可能是在统计组合数，也可能是在统计排列数。真正决定含义的是循环顺序。

## 3. 第一类：最大价值 / 最大可装重量

### 3.1 最大价值

最经典定义：

$$
\boxed{dp[j]=\text{容量不超过 }j\text{ 时可以获得的最大价值}}
$$

若当前物品重量为 $w_i$，价值为 $v_i$：

$$
\boxed{dp[j]=\max(dp[j],dp[j-w_i]+v_i)}
$$

这个式子表达的是两个选择：

```text
不选当前物品：dp[j]
选择当前物品：dp[j - w_i] + v_i
```

### 3.2 最大可装重量

若“价值”本身就等于重量，例如「分割等和子集」或「最后一块石头的重量 II」，则可以定义：

$$
\boxed{dp[j]=\text{容量 }j\text{ 内最多能装进去的总重量}}
$$

转移：

$$
\boxed{dp[j]=\max(dp[j],dp[j-a_i]+a_i)}
$$

这和最大价值背包完全同构，只是：

$$
v_i=a_i
$$

### 典型题型

- 分割等和子集；
- 最后一块石头的重量 II；
- 一和零；
- 标准 01 背包。

## 4. 第二类：能否恰好装满

如果只关心目标容量是否可达，可以直接使用布尔状态：

$$
\boxed{dp[j]=\text{容量 }j\text{ 是否能够被恰好构造}}
$$

初始化：

$$
\boxed{dp[0]=true}
$$

转移：

$$
\boxed{dp[j]=dp[j]\lor dp[j-w_i]}
$$

这里 `dp[0] = true` 表示：

> 什么都不选时，恰好组成总和 $0$ 有一种合法状态。

这个“空状态”是所有可达性转移的起点。

## 5. 第三类：装满背包有多少种方案

若定义：

$$
\boxed{dp[j]=\text{恰好组成 }j\text{ 的方案数}}
$$

则最经典的状态转移为：

$$
\boxed{dp[j]+=dp[j-w_i]}
$$

初始化仍然是：

$$
\boxed{dp[0]=1}
$$

这里不是说“有一个物品重量为 0”，而是说：

> 构造总和 $0$ 有一种方式——什么都不选。

这是一切方案计数的乘法单位 / 加法起点。

### 典型题型

- 目标和；
- 零钱兑换 II；
- 组合总和 IV；
- 爬楼梯进阶版。

## 6. 第四类：装满背包最少需要多少件物品

定义：

$$
\boxed{dp[j]=\text{恰好构造 }j\text{ 所需的最少物品数}}
$$

转移：

$$
\boxed{dp[j]=\min(dp[j],dp[j-w_i]+1)}
$$

初始化必须特别注意：

$$
dp[0]=0
$$

其余位置初始化成一个足够大的值：

$$
dp[j]=+\infty,\quad j>0
$$

因为一开始除了容量 0，没有任何容量是已知可达的。

### 典型题型

- 零钱兑换；
- 完全平方数。

<Callout type="warning" title="最大值与最小值的初始化不能照抄">
求最大值时，很多题可以初始化为 0；求最小值时，如果也全部初始化为 0，`min` 会永远保留 0，从而彻底失去状态语义。
</Callout>

## 7. 01 背包：为什么容量必须倒序

一维 01 背包：

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = V; j >= weight[i]; --j) {
        dp[j] = max(dp[j], dp[j - weight[i]] + value[i]);
    }
}
```

容量从大到小：

$$
V,V-1,\dots,w_i
$$

这样计算 `dp[j]` 时：

```text
dp[j - weight[i]]
```

仍然是“上一轮物品”的状态。

也就是说当前第 $i$ 件物品不会在同一轮被重复使用。

### 如果正序会发生什么

假设只有一件物品：

```text
重量 = 2
价值 = 3
容量 = 4
```

正序时：

```text
dp[2] = 3
```

继续更新：

```text
dp[4] = dp[2] + 3 = 6
```

但这里的 `dp[2]` 已经使用过当前物品，于是等价于把同一件物品用了两次。

因此：

$$
\boxed{\text{01 背包一维 DP：容量必须倒序}}
$$

## 8. 完全背包：为什么容量正序

完全背包允许同一种物品重复使用。

因此我们恰恰希望：

```text
dp[j - weight[i]]
```

可以是本轮刚刚更新出来的状态。

典型写法：

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = weight[i]; j <= V; ++j) {
        dp[j] = max(dp[j], dp[j - weight[i]] + value[i]);
    }
}
```

因此：

$$
\boxed{\text{完全背包一维 DP：容量通常正序}}
$$

可以把这一点直接记成：

```text
倒序：禁止本轮重复使用当前物品
正序：允许本轮重复使用当前物品
```

## 9. “先物品还是先容量”不能只靠背包类型判断

对于纯最大价值完全背包：

```text
先物品后容量
```

或者：

```text
先容量后物品
```

在很多情况下都可以得到同一个最大值。

但一旦题目要求 **计数**，两层循环的先后顺序会改变答案的数学含义。

## 10. 组合数：外层遍历物品

例如硬币：

```text
[1, 2]
```

目标：

```text
3
```

如果：

```text
1 + 2
2 + 1
```

被视为同一种方案，那么求的是组合数。

完全背包计数组合：

```cpp
dp[0] = 1;

for (int coin : coins) {
    for (int j = coin; j <= amount; ++j) {
        dp[j] += dp[j - coin];
    }
}
```

外层固定物品后，方案天然按照物品种类逐步扩展，不会因为顺序不同重复计数。

典型题：**零钱兑换 II**。

因此：

$$
\boxed{\text{组合数：外层物品，内层容量}}
$$

## 11. 排列数：外层遍历容量

如果：

```text
1 + 2
```

和：

```text
2 + 1
```

算两个不同方案，那么求的是排列数。

写法：

```cpp
dp[0] = 1;

for (int j = 1; j <= target; ++j) {
    for (int num : nums) {
        if (j >= num) {
            dp[j] += dp[j - num];
        }
    }
}
```

当外层固定“当前总和 $j$”时，内层枚举最后一个元素，相同元素集合的不同顺序会分别进入状态。

典型题：

- 组合总和 IV；
- 爬楼梯进阶版。

因此：

$$
\boxed{\text{排列数：外层容量，内层物品}}
$$

## 12. 求最少个数时，循环顺序为什么通常没那么敏感

例如零钱兑换：

$$
dp[j]=\min(dp[j],dp[j-c]+1)
$$

我们只关心最小值，不关心不同顺序产生了多少条路径。

因此对于完全背包型的最少个数问题，只要保证容量按正序以允许重复取同一物品，常见的两种外层顺序都能得到最终最小值。

例如：

- 零钱兑换；
- 完全平方数。

但从代码可读性和迁移性考虑，仍应按照状态语义选择最自然的顺序，而不是依赖“碰巧都能过”。

## 13. 多重背包放到这个框架里怎么看

多重背包只是增加了：

$$
0\le x_i\le s_i
$$

可以有三种常见处理：

### 方法一：枚举当前物品数量

$$
dp[j]
=
\max_{0\le k\le s_i}
\left(dp_{old}[j-kw_i]+kv_i\right)
$$

### 方法二：逐件展开成 01 物品

若某物品最多 $s_i$ 件，就拆成 $s_i$ 个独立 01 物品。

### 方法三：二进制拆分

把：

$$
s_i
$$

拆成若干个：

$$
1,2,4,\dots,r
$$

组成的 01 物品块，将物品数从 $O(s_i)$ 降为：

$$
O(\log s_i)
$$

因此多重背包最终也能回到 01 背包的框架中。

## 14. 一个统一的判断流程

看到“选择若干元素，使总和 / 容量满足某个条件”时，可以按以下顺序判断。

### 第一步：识别容量

容量可能是：

- 重量；
- 金额；
- 总和；
- 字符串长度；
- 0 的数量；
- 1 的数量；
- 两维甚至多维资源。

### 第二步：识别物品使用次数

```text
最多一次   → 01 背包
无限次     → 完全背包
最多 k 次  → 多重背包
```

### 第三步：识别目标

```text
最大价值       → max
是否可达       → bool / OR
方案数         → +=
最少个数       → min
```

### 第四步：判断是否区分顺序

只有方案计数尤其需要问：

```text
[1, 2]
```

和：

```text
[2, 1]
```

是否算不同方案。

- 不区分：组合；
- 区分：排列。

### 第五步：最后再决定循环顺序

这一步不是背模板，而是让循环顺序服务于题目的状态语义。

## 15. 高频模板速查

### 01 背包最大价值

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = V; j >= weight[i]; --j) {
        dp[j] = max(dp[j], dp[j - weight[i]] + value[i]);
    }
}
```

### 完全背包最大价值

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = weight[i]; j <= V; ++j) {
        dp[j] = max(dp[j], dp[j - weight[i]] + value[i]);
    }
}
```

### 01 背包方案数

```cpp
dp[0] = 1;

for (int x : nums) {
    for (int j = target; j >= x; --j) {
        dp[j] += dp[j - x];
    }
}
```

### 完全背包组合数

```cpp
dp[0] = 1;

for (int x : nums) {
    for (int j = x; j <= target; ++j) {
        dp[j] += dp[j - x];
    }
}
```

### 完全背包排列数

```cpp
dp[0] = 1;

for (int j = 1; j <= target; ++j) {
    for (int x : nums) {
        if (j >= x) {
            dp[j] += dp[j - x];
        }
    }
}
```

### 完全背包最少个数

```cpp
vector<int> dp(target + 1, INF);
dp[0] = 0;

for (int x : nums) {
    for (int j = x; j <= target; ++j) {
        dp[j] = min(dp[j], dp[j - x] + 1);
    }
}
```

## 16. 最容易混淆的几个结论

<Callout type="warning" title="不要把这些规则机械化">
“01 背包倒序、完全背包正序”主要针对 **一维压缩后的容量循环**。二维 DP 中每一层明确读取上一层状态时，并不存在同一行重复使用当前物品的问题。
</Callout>

### 误区 1：看到“完全背包”就固定先物品后容量

错。方案计数时，还必须判断求组合还是排列。

### 误区 2：`dp[0] = 1` 是固定模板

错。它只适用于方案计数等特定状态语义。

### 误区 3：递推公式一样，问题就一样

错。初始化和遍历顺序可能让同一个公式表达完全不同的含义。

### 误区 4：所有背包都只有一维容量

错。「一和零」就是典型二维容量：

$$
(m,n)
$$

分别代表最多允许使用的 `0` 和 `1` 数量。

## 18. 最终总结

把整个背包专题压缩成一句话：

> **先判断一个物品允许使用几次，再确定 `dp` 的含义与目标函数，最后通过循环顺序控制状态是否允许重复使用以及是否区分排列顺序。**

四类最常见状态转移可以归纳为：

$$
\boxed{
\begin{aligned}
\text{最大值：}&\quad dp[j]=\max(dp[j],dp[j-w]+v)\\
\text{可达性：}&\quad dp[j]=dp[j]\lor dp[j-w]\\
\text{方案数：}&\quad dp[j]+=dp[j-w]\\
\text{最小个数：}&\quad dp[j]=\min(dp[j],dp[j-w]+1)
\end{aligned}}
$$

真正需要理解的不是四条公式本身，而是：

$$
\boxed{\text{这些状态为什么可以从那里转移过来}}
$$

只要这个问题能回答清楚，背包题的绝大多数变形就不再需要死记模板。
