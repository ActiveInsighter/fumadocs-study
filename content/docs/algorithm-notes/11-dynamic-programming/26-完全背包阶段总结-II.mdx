# 完全背包阶段总结 II

到这里，完全背包中最容易混淆的一组问题已经基本覆盖：

- 零钱兑换 II；
- 组合总和 IV；
- 爬楼梯进阶版；
- 零钱兑换；
- 完全平方数。

它们看起来题意差异很大，但真正决定代码结构的核心只有两件事：

1. **`dp[j]` 到底表示什么；**
2. **题目是否区分元素选择顺序。**

<Callout type="info" title="这一阶段真正要掌握的不是五道题，而是三种模型">
完全背包在这一阶段可以归纳为：组合计数、排列计数、最小值。只要先判断属于哪一类，状态定义、初始化和遍历顺序就会清晰很多。
</Callout>

## 1. 完全背包的共同前提

无论是哪一类题，只要属于完全背包，都具有同一个最关键的特征：

> 每种物品可以重复使用任意次。

因此在一维 DP 中，容量通常必须：

$$
\boxed{\text{从小到大遍历}}
$$

因为当前轮刚刚更新出的状态，需要继续参与后续容量的转移，从而实现“同一物品重复使用”。

例如物品重量为 `2`：

```text
dp[2] -> dp[4] -> dp[6]
```

后面的状态可以使用当前轮已经更新的前面状态，因此相当于重复选择重量 `2` 的物品。

这正是完全背包和 01 背包最根本的区别之一。

## 2. 三类问题总览

| 类型 | 典型题 | `dp[j]` 含义 | 核心转移 | 外层循环 |
| --- | --- | --- | --- | --- |
| 组合计数 | 零钱兑换 II | 凑成 `j` 的组合数 | `dp[j] += dp[j-item]` | 物品 |
| 排列计数 | 组合总和 IV、爬楼梯进阶 | 凑成 `j` 的排列数 | `dp[j] += dp[j-item]` | 容量 |
| 最小值 | 零钱兑换、完全平方数 | 凑成 `j` 的最少物品数 | `dp[j] = min(...)` | 两者均可 |

三类题最值得注意的是：

> **计数型问题中，循环顺序本身具有组合学意义；最值问题中，循环顺序通常不会改变最终最优值。**

## 3. 组合计数：为什么必须先物品后容量

典型题：零钱兑换 II。

状态：

$$
\boxed{dp[j]=\text{凑成金额 }j\text{ 的组合数量}}
$$

转移：

$$
\boxed{dp[j]\mathrel{+}=dp[j-coin]}
$$

初始化：

$$
\boxed{dp[0]=1}
$$

因为“什么都不选”是一种合法的空组合。

循环结构：

```cpp
for (int coin : coins) {
    for (int j = coin; j <= amount; ++j) {
        dp[j] += dp[j - coin];
    }
}
```

为什么必须先遍历物品？

假设：

```text
coins = [1, 2]
amount = 3
```

组合意义下：

```text
1 + 2
```

和：

```text
2 + 1
```

属于同一种组合。

当硬币放在外层时，会按固定物品顺序逐步加入，因此不会把同一组选法的不同排列重复统计。

所以：

$$
\boxed{\text{组合数：物品外层，容量内层}}
$$

## 4. 排列计数：为什么必须先容量后物品

典型题：

- 组合总和 IV；
- 爬楼梯进阶版。

状态仍然可以写成：

$$
dp[j]=\text{组成 }j\text{ 的方案数量}
$$

转移也是：

$$
\boxed{dp[j]\mathrel{+}=dp[j-item]}
$$

但这里：

```text
1 + 2
```

与：

```text
2 + 1
```

必须被视为两种不同方案。

所以要对每一个目标容量 `j`，重新枚举“最后一步选哪个物品”：

```cpp
for (int j = 1; j <= target; ++j) {
    for (int item : items) {
        if (j >= item) {
            dp[j] += dp[j - item];
        }
    }
}
```

这样当计算 `dp[3]` 时：

- 最后一步选 `1`，会从 `dp[2]` 转移；
- 最后一步选 `2`，会从 `dp[1]` 转移。

于是不同末尾选择所对应的不同序列都能够被计入。

因此：

$$
\boxed{\text{排列数：容量外层，物品内层}}
$$

## 5. 一个最容易混淆的结论

很多人会记成：

> 完全背包一定是“先物品再容量”。

这是不准确的。

真正固定的是：

$$
\boxed{\text{一维完全背包的容量方向通常为正序}}
$$

至于谁在外层，取决于题目是否区分顺序。

可以这样记：

### 不区分顺序

例如：

```text
1 + 2
2 + 1
```

算同一种。

那么：

$$
\boxed{\text{物品外层}}
$$

### 区分顺序

上面的两种要分别计算。

那么：

$$
\boxed{\text{容量外层}}
$$

## 6. 最小值问题为什么两种循环都可以

典型题：

- 零钱兑换；
- 完全平方数。

状态：

$$
\boxed{dp[j]=\text{凑成 }j\text{ 所需的最少物品数}}
$$

转移：

$$
\boxed{dp[j]=\min(dp[j],dp[j-item]+1)}
$$

这里不需要统计“到底有多少种排列”。

例如：

```text
1 + 2
2 + 1
```

虽然顺序不同，但都使用了两个物品。

对于最小值来说，只关心：

$$
\min(2,2)=2
$$

因此外层先物品或先容量都可以，只要所有合法转移都能被覆盖，并且容量保持完全背包要求的正序即可。

## 7. 三类问题的初始化为什么不同

### 计数问题

使用：

$$
\boxed{dp[0]=1}
$$

含义是：

> 凑成 0 有一种方法——什么都不选。

如果把它写成 `0`，所有后续状态都无法产生第一种合法方案。

### 最小值问题

使用：

$$
\boxed{dp[0]=0}
$$

因为凑出 0 不需要任何物品。

其他位置初始化为：

$$
+\infty
$$

表示尚未找到合法方案。

<Callout type="warning" title="不要背初始化值，要背状态语义">
`dp[0]` 是 0 还是 1，不是由“这是背包题”决定，而是由 `dp[j]` 的数学含义决定。
</Callout>

## 9. 组合总和 IV 与爬楼梯进阶为什么本质相同

组合总和 IV 中：

```text
nums = [1, 2, 3]
target = 4
```

每次可以选择 `1`、`2` 或 `3`，并且顺序不同算不同方案。

爬楼梯进阶中，如果每次最多可以走 `m` 步，那么允许的步长是：

$$
1,2,\dots,m
$$

登上第 `n` 阶，本质就是从这些“物品”中反复选择，使总和为 `n`。

所以两题都属于：

$$
\boxed{\text{完全背包排列计数}}
$$

状态转移完全相同：

$$
\boxed{dp[j]=\sum dp[j-item]}
$$

## 10. 零钱兑换与完全平方数为什么本质相同

零钱兑换中的物品：

```text
coins = [1, 2, 5, ...]
```

完全平方数中的物品：

$$
1,4,9,16,\dots
$$

两者都是：

- 物品无限；
- 恰好凑出目标；
- 求最少物品数量。

因此统一写成：

$$
\boxed{dp[j]=\min(dp[j],dp[j-item]+1)}
$$

区别仅仅在于“物品集合从哪里来”。

## 11. 一张表记住循环顺序

| 问题目标 | 外层 | 内层 | 容量方向 |
| --- | --- | --- | --- |
| 组合数 | 物品 | 容量 | 正序 |
| 排列数 | 容量 | 物品 | 正序 |
| 最小值 | 二者均可 | 二者均可 | 正序 |

可以压缩成一句话：

$$
\boxed{\text{组合物品外，排列容量外，完全背包容量正序}}
$$

对于最值题，再补一句：

$$
\boxed{\text{最值通常不依赖组合 / 排列顺序}}
$$

## 12. 什么时候不能机械套这个规律

以上规律适用于当前学习阶段中最典型的一维完全背包模型，但真正做题时仍要先检查：

- 状态是否只依赖更小容量；
- 物品是否真的可以无限使用；
- 是否要求恰好装满；
- 是否存在额外维度；
- 是否有负数、零或其他特殊约束；
- 是否统计顺序不同的序列。

如果状态设计发生变化，循环结构也可能随之变化。

所以最稳妥的流程始终是：

```text
题意
  ↓
状态定义
  ↓
状态转移
  ↓
初始化
  ↓
遍历顺序
  ↓
手推验证
```

## 13. 一套判断流程

看到一个“凑数”问题时，可以按下面顺序判断。

### 第一步：物品能否重复使用

如果每种只能用一次：

$$
\boxed{01\text{ 背包}}
$$

如果每种可以无限使用：

$$
\boxed{\text{完全背包}}
$$

### 第二步：题目求什么

如果求方案数量，则继续判断是否区分顺序。

如果求最少 / 最大，则进入最值型 DP。

### 第三步：方案数是否区分顺序

不区分：

$$
\boxed{\text{组合}}
$$

区分：

$$
\boxed{\text{排列}}
$$

### 第四步：据此决定循环结构

这样就不会陷入“背模板但不知道为什么”的状态。

## 14. 三个通用模板

### 组合计数模板

```cpp
vector<long long> dp(target + 1, 0);
dp[0] = 1;

for (int item : items) {
    for (int j = item; j <= target; ++j) {
        dp[j] += dp[j - item];
    }
}
```

### 排列计数模板

```cpp
vector<long long> dp(target + 1, 0);
dp[0] = 1;

for (int j = 1; j <= target; ++j) {
    for (int item : items) {
        if (j >= item) {
            dp[j] += dp[j - item];
        }
    }
}
```

### 最小数量模板

```cpp
const int INF = target + 1;
vector<int> dp(target + 1, INF);
dp[0] = 0;

for (int item : items) {
    for (int j = item; j <= target; ++j) {
        dp[j] = min(dp[j], dp[j - item] + 1);
    }
}
```

## 15. 常见误区总结

### 误区一：只记“完全背包正序”

正序只能解决“一个物品能否重复使用”的问题。

它不能告诉你外层应该是物品还是容量。

### 误区二：认为所有方案数都一样

组合数和排列数的递推式可能一模一样：

$$
dp[j]\mathrel{+}=dp[j-item]
$$

真正区分它们的是循环顺序。

### 误区三：把 `dp[0]` 当固定模板

计数题常见：

$$
dp[0]=1
$$

最小值题常见：

$$
dp[0]=0
$$

必须根据状态含义推导。

### 误区四：看到“组合总和”就默认是组合

题目名称可能包含“组合”，但如果顺序不同算不同答案，那么算法意义上统计的是排列。

例如组合总和 IV 就是典型例子。

## 16. 本阶段知识网络

学完这一部分后，应能够从以下三个方向迁移：

### 方向一：输入物品集合

例如：

```text
coins = [...] 
nums = [...]
```

直接根据题意把这些值当作物品。

### 方向二：隐式生成物品集合

例如完全平方数：

$$
1^2,2^2,\dots
$$

物品并未直接作为数组输入，但可以从数学结构中生成。

### 方向三：动作本身就是物品

例如爬楼梯：

```text
走 1 步
走 2 步
...
走 m 步
```

每一种动作都可以视为一种“物品”。

这是背包思想真正强大的地方：很多题并不会直接写出“背包”两个字。

## 17. 复习检查清单

学完这一阶段后，可以检查自己是否能立即回答：

- 为什么完全背包容量正序？
- 01 背包为什么容量倒序？
- 为什么零钱兑换 II 是组合数？
- 为什么组合总和 IV 是排列数？
- 为什么两者递推式一样但循环顺序不同？
- 为什么零钱兑换与完全平方数外层顺序都可以？
- 为什么计数题 `dp[0] = 1`？
- 为什么最小值题其他状态要初始化为无穷大？
- 为什么爬楼梯进阶可以转化为完全背包？

如果这些问题都能从状态定义出发解释，而不是只凭记忆回答，说明这一阶段已经真正掌握。

## 18. 本阶段总结

完全背包这一阶段最重要的结论不是某一段代码，而是以下逻辑链：

$$
\boxed{\text{是否可重复使用}\rightarrow\text{背包类型}}
$$

$$
\boxed{\text{求什么}\rightarrow\text{状态语义与初始化}}
$$

$$
\boxed{\text{是否区分顺序}\rightarrow\text{外层循环}}
$$

$$
\boxed{\text{完全背包}\rightarrow\text{容量正序}}
$$

把这些关系真正建立起来之后，零钱兑换 II、组合总和 IV、爬楼梯进阶、零钱兑换、完全平方数就不再是五道独立题，而是同一套完全背包框架下的三种典型分支。
