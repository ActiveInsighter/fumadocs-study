# 完全背包阶段总结

这一阶段最重要的收获，不是再记住几个背包模板，而是建立一套能在新题中自行判断的框架。

从 **目标和**、**一和零** 到 **完全背包**、**零钱兑换 II**，问题表面上差异很大，但它们最终都可以被拆成几个核心问题：

1. 每个物品能使用几次？
2. 背包容量有几个维度？
3. 状态记录的是最大值、可行性还是方案数？
4. 方案是否区分选择顺序？
5. 当前状态能否在同一轮使用刚刚更新过的状态？

只要这几个问题判断清楚，大部分背包 DP 的循环方向和状态转移都会自然确定。

<Callout type="info" title="真正需要记住的不是模板，而是模板为什么成立">
01 背包容量倒序、完全背包容量正序、组合计数物品在外层、排列计数容量在外层，这些规则都不是经验口诀，而是在控制“一个状态允许从哪些前驱状态转移”。
</Callout>

## 1. 先统一背包问题的三个维度

背包题可以从三个维度快速分类。

### 1.1 物品使用次数

| 类型 | 每种物品可使用次数 | 一维容量遍历 |
| --- | --- | --- |
| 01 背包 | 至多一次 | 倒序 |
| 完全背包 | 无限次 | 正序 |
| 多重背包 | 有限多次 | 拆分或专门优化 |

最根本的区别在于：

- 01 背包不能让本轮刚更新的状态再次使用当前物品；
- 完全背包必须允许本轮刚更新的状态继续使用当前物品。

因此一维数组压缩后：

```text
01 背包：      j 从大到小
完全背包：    j 从小到大
```

### 1.2 状态目标

同样是背包，`dp[j]` 的含义可能完全不同：

| 问题目标 | 常见状态含义 | 常见转移形式 |
| --- | --- | --- |
| 最大价值 | 容量 `j` 下能取得的最大值 | `max(...)` |
| 是否可达 | 能否恰好组成 `j` | `or / bool` |
| 方案数量 | 恰好组成 `j` 的方案数 | `+=` |
| 最少数量 | 组成 `j` 所需最少物品数 | `min(...)` |

所以看到背包题时，不要直接套：

```cpp
dp[j] = max(dp[j], ...);
```

而应先问：

> `dp[j]` 到底代表什么？

### 1.3 是否区分顺序

对于方案计数问题，还必须继续判断：

- `{1, 2}` 与 `{2, 1}` 是否算同一种方案？
- 如果不区分，是组合；
- 如果区分，是排列。

这决定两层循环的顺序。

## 2. 目标和：把符号选择转成 01 背包计数

设数组总和为：

$$
sum
$$

所有加正号的元素和为：

$$
P
$$

所有加负号的元素绝对值之和为：

$$
N
$$

题目要求：

$$
P-N=target
$$

同时：

$$
P+N=sum
$$

两式相加：

$$
2P=sum+target
$$

因此：

$$
\boxed{P=\frac{sum+target}{2}}
$$

问题便转化为：

> 从数组中选择若干个数，每个数最多使用一次，使其和恰好为 $P$，一共有多少种选择方式？

这就是 **01 背包计数问题**。

状态：

$$
dp[j]=\text{和为 }j\text{ 的子集数量}
$$

转移：

$$
\boxed{dp[j]+=dp[j-num]}
$$

容量倒序：

```cpp
for (int num : nums) {
    for (int j = bag; j >= num; --j) {
        dp[j] += dp[j - num];
    }
}
```

![目标和的 DP 状态变化](https://file1.kamacoder.com/i/algo/20210125120743274-20230310132918821.jpg)

### 为什么 `0` 值特殊

若 `num = 0`，则：

$$
dp[j]+=dp[j]
$$

也就是：

$$
dp[j]\leftarrow 2dp[j]
$$

因为一个 $0$ 可以选择“加号”或“减号”，两种选择都不会改变总和，却会形成两种不同表达式。

这也是为什么目标和题中 `0` 会导致方案数成倍增长。

## 3. 一和零：容量不一定只有一个维度

“一和零”最容易被误判成某种特殊背包，其实它仍然是标准 01 背包，只是容量有两个维度：

- `m`：最多允许使用多少个 `0`；
- `n`：最多允许使用多少个 `1`。

对于字符串 `s`，统计：

$$
zero(s),\quad one(s)
$$

它相当于一个物品，需要同时消耗两种资源。

状态：

$$
\boxed{dp[i][j]=\text{最多使用 }i\text{ 个 0 和 }j\text{ 个 1 时，能选出的最大字符串数量}}
$$

转移：

$$
\boxed{dp[i][j]=\max\left(dp[i][j],\ dp[i-zero][j-one]+1\right)}
$$

由于每个字符串只能使用一次，所以两个容量维度都必须倒序：

```cpp
for (const string& s : strs) {
    int zero = ...;
    int one = ...;

    for (int i = m; i >= zero; --i) {
        for (int j = n; j >= one; --j) {
            dp[i][j] = max(dp[i][j], dp[i - zero][j - one] + 1);
        }
    }
}
```

![一和零的二维容量 DP](https://file1.kamacoder.com/i/algo/20210120111201512-20230310132936011.jpg)

<Callout type="warning" title="二维容量不等于二维 DP 的“物品维度”">
这里的两个维度分别代表两种资源容量，而不是“物品编号 + 背包容量”。判断状态维度时，要根据状态真正需要记录的信息，而不是看到二维数组就机械套模板。
</Callout>

## 4. 从 01 背包到完全背包：为什么容量方向反过来

### 01 背包

一维状态下：

```cpp
for (int item = 0; item < n; ++item) {
    for (int j = bagWeight; j >= weight[item]; --j) {
        dp[j] = max(dp[j], dp[j - weight[item]] + value[item]);
    }
}
```

必须倒序，因为：

$$
dp[j-weight_i]
$$

必须是“尚未使用当前物品”的旧状态。

### 完全背包

每种物品可以重复使用，所以恰恰希望：

$$
dp[j-weight_i]
$$

已经包含当前物品产生的新状态。

因此容量正序：

```cpp
for (int item = 0; item < n; ++item) {
    for (int j = weight[item]; j <= bagWeight; ++j) {
        dp[j] = max(dp[j], dp[j - weight[item]] + value[item]);
    }
}
```

可以把两者概括成：

$$
\boxed{\text{倒序 = 禁止当前物品重复使用}}
$$

$$
\boxed{\text{正序 = 允许当前物品重复使用}}
$$

这比死记“01 倒序、完全正序”更容易迁移到新题。

## 5. 纯完全背包：两层循环为什么可以交换

对于只求最大价值的纯完全背包：

```cpp
for (int item = 0; item < n; ++item) {
    for (int j = weight[item]; j <= bagWeight; ++j) {
        ...
    }
}
```

与：

```cpp
for (int j = 0; j <= bagWeight; ++j) {
    for (int item = 0; item < n; ++item) {
        ...
    }
}
```

通常都可以得到相同最优值。

原因是“最大值”只关心最终能达到的最优结果，不关心方案形成的顺序。

但一旦题目改成 **方案计数**，循环顺序就会直接改变计数对象。

## 6. 零钱兑换 II：组合数为什么必须物品在外层

零钱兑换 II 中：

- 每种硬币无限使用；
- 要求恰好凑出 `amount`；
- 问组合数量；
- 不区分硬币顺序。

状态：

$$
dp[j]=\text{凑出金额 }j\text{ 的组合数量}
$$

初始化：

$$
\boxed{dp[0]=1}
$$

转移：

$$
\boxed{dp[j]+=dp[j-coin]}
$$

正确顺序：

```cpp
for (int coin : coins) {
    for (int j = coin; j <= amount; ++j) {
        dp[j] += dp[j - coin];
    }
}
```

这里外层遍历硬币，相当于给每种组合规定了一个统一的生成顺序，因此：

```text
1 + 2
2 + 1
```

不会被重复统计。

## 7. 组合与排列：完全背包中最重要的循环顺序

### 求组合数

不区分元素顺序：

```cpp
for (int item : items) {
    for (int j = item; j <= target; ++j) {
        dp[j] += dp[j - item];
    }
}
```

即：

$$
\boxed{\text{物品在外，容量在内}}
$$

### 求排列数

区分元素顺序：

```cpp
for (int j = 1; j <= target; ++j) {
    for (int item : items) {
        if (j >= item) {
            dp[j] += dp[j - item];
        }
    }
}
```

即：

$$
\boxed{\text{容量在外，物品在内}}
$$

下一篇“组合总和 IV”就是这一规则最典型的应用。

## 8. 为什么 `dp[0] = 1` 在计数题里如此常见

对于：

$$
dp[j]+=dp[j-x]
$$

这类计数转移，如果 `dp[0]=0`，那么第一种合法方案永远无法出现。

把 `dp[0]=1` 理解成：

> 达到总和 0 有一种空方案——什么都不选。

它不是“为了代码好写而强行设置”，而是计数 DP 中的乘法单位元思想：

- 有一个前驱方案；
- 再加入当前元素；
- 就产生一个新方案。

因此：

$$
\boxed{dp[0]=1}
$$

通常是“恰好组成某个总和”的方案计数问题的自然边界条件。

## 9. 一张表判断常见背包变形

| 题型 | 使用次数 | 目标 | 容量方向 | 两层循环重点 |
| --- | --- | --- | --- | --- |
| 01 背包最大价值 | 一次 | 最大值 | 倒序 | 物品外层 |
| 分割等和子集 | 一次 | 是否可达 / 最大可达和 | 倒序 | 物品外层 |
| 目标和 | 一次 | 方案数 | 倒序 | 物品外层 |
| 一和零 | 一次 | 最大数量 | 两维都倒序 | 物品外层 |
| 完全背包最大价值 | 无限 | 最大值 | 正序 | 两种顺序通常都可 |
| 零钱兑换 II | 无限 | 组合数 | 正序 | **物品外层** |
| 组合总和 IV | 无限 | 排列数 | 正序 | **容量外层** |

## 10. 背包题的统一判断流程

以后遇到背包类题目，可以按下面的顺序判断。

### 第一步：找“物品”和“容量”

问自己：

> 每次选择的对象是什么？限制资源是什么？

### 第二步：判断物品能否重复使用

- 一次：01 背包；
- 无限次：完全背包；
- 有限多次：多重背包。

### 第三步：定义 `dp`

明确它保存的是：

- 最大值；
- 最小值；
- 是否可行；
- 方案数量。

### 第四步：确定初始化

尤其注意：

- 最大值问题通常从 `0` 开始；
- 最小值问题常初始化为 `INF`；
- 方案计数常见 `dp[0] = 1`。

### 第五步：判断容量遍历方向

问自己：

> 当前物品在这一轮能不能再次被使用？

- 不能：倒序；
- 能：正序。

### 第六步：如果是计数，再判断组合还是排列

- 不区分顺序：物品外层；
- 区分顺序：容量外层。

<Callout type="info" title="背包 DP 最核心的一句话">
循环顺序不是实现细节，而是在规定“一个状态允许依赖哪些已经计算出的状态”，因此它本身就是状态转移定义的一部分。
</Callout>

## 11. 高频易错点

### 错误一：看到“无限使用”就只记正序

正序只解决“同一物品能否重复使用”，并没有解决组合与排列问题。

### 错误二：看到“方案数”就统一写 `dp[j] += dp[j-x]`

递推式相同，不代表循环顺序相同。

### 错误三：不先定义 `dp`

如果不知道 `dp[j]` 究竟表示“最多”“恰好”“方案数”还是“是否可达”，初始化和转移都容易写错。

### 错误四：二维状态一律理解成“物品 × 容量”

像“一和零”中的二维数组表示的是两种资源容量，而不是物品维度。

### 错误五：只背结论，不理解覆盖关系

真正决定正序和倒序的是：

> 本轮更新后的状态，是否允许继续参与本轮后续状态的计算。

## 12. 阶段总结

这一阶段可以压缩成四条最值得长期记忆的原则：

$$
\boxed{\text{01 背包：容量倒序}}
$$

$$
\boxed{\text{完全背包：容量正序}}
$$

$$
\boxed{\text{组合计数：物品外层}}
$$

$$
\boxed{\text{排列计数：容量外层}}
$$

但最终目标并不是背住这四句话，而是能解释它们为什么成立。

当你能从“状态依赖关系”推导出循环方向时，背包问题才真正从模板题变成了可以迁移的方法论。
