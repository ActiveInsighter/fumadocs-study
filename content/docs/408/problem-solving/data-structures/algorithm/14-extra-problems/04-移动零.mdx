# 283. 移动零

[LeetCode 283：移动零](https://leetcode.cn/problems/move-zeroes/)

给定整数数组 `nums`，需要把所有 `0` 移动到数组末尾，同时满足两个要求：

- **非零元素的相对顺序不能改变**；
- 必须在原数组上操作，不能额外复制一份完整数组。

例如：

```text
输入： [0, 1, 0, 3, 12]
输出： [1, 3, 12, 0, 0]
```

这里真正重要的并不是“把 0 搬到后面”，而是：

> **稳定地保留所有非零元素，再把剩余位置统一补成 0。**

## 一、先把问题转化成“移除元素”

如果暂时忽略数组末尾必须填 `0` 这个要求，本题就变成：

> 把数组中所有非零元素按原来的顺序放到前面。

例如：

```text
[0, 1, 0, 3, 12]
```

只保留非零元素：

```text
[1, 3, 12, ?, ?]
```

然后把剩余位置填成 `0`：

```text
[1, 3, 12, 0, 0]
```

这和“移除指定元素”的双指针模型几乎完全相同。

## 二、方法一：快慢指针覆盖

定义两个指针：

- `fast`：负责扫描整个数组；
- `slow`：表示“下一个非零元素应该写入的位置”。

当 `nums[fast] != 0` 时，把它写入 `nums[slow]`，随后 `slow++`。

### 关键不变量

在扫描过程中始终维持：

```text
[0, slow)      已处理好的非零元素
[slow, fast)   已扫描但不再关心的区域
[fast, n)      尚未扫描
```

并且 `[0, slow)` 中的元素顺序与原数组一致。

### 示例推演

以：

```text
nums = [0, 1, 0, 3, 12]
```

为例。

初始：

```text
slow = 0
fast = 0
```

`nums[0] = 0`，跳过：

```text
[0, 1, 0, 3, 12]
 slow
 fast
```

`fast = 1`，发现 `1` 非零，于是：

```text
nums[slow] = nums[fast]
```

数组变为：

```text
[1, 1, 0, 3, 12]
```

然后 `slow = 1`。

继续扫描后最终得到：

```text
[1, 3, 12, 3, 12]
          ↑
         slow
```

前 `slow = 3` 个位置已经是正确答案中的全部非零元素。

最后把 `[slow, n)` 全部赋值为 `0`：

```text
[1, 3, 12, 0, 0]
```

### C++ 实现

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int slow = 0;

        for (int fast = 0; fast < nums.size(); ++fast) {
            if (nums[fast] != 0) {
                nums[slow++] = nums[fast];
            }
        }

        while (slow < nums.size()) {
            nums[slow++] = 0;
        }
    }
};
```

### 复杂度

整个数组最多被线性扫描两次，因此：

$$
T(n)=O(n)
$$

只使用常数级变量：

$$
S(n)=O(1)
$$

## 三、为什么这种写法一定保持相对顺序

假设所有非零元素按照原数组中的出现顺序是：

```text
x1, x2, x3, ..., xm
```

`fast` 从左到右扫描，因此它遇到这些元素的顺序一定也是：

```text
x1 -> x2 -> x3 -> ... -> xm
```

而 `slow` 同样只会从左到右依次写入，所以最终前半部分一定是：

```text
[x1, x2, x3, ..., xm]
```

因此这是一个**稳定压缩**过程。

> [!TIP]
> 只要题目要求“删除某类元素，同时保持其他元素相对顺序”，都可以优先想到这种快慢指针模型。

## 四、方法二：遇到非零元素就交换

还可以让 `slow` 指向当前应该放非零元素的位置，遇到非零元素时直接交换：

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int slow = 0;

        for (int fast = 0; fast < nums.size(); ++fast) {
            if (nums[fast] != 0) {
                swap(nums[slow], nums[fast]);
                ++slow;
            }
        }
    }
};
```

这段代码的含义是：

- `[0, slow)` 始终保存已经排好的非零元素；
- `[slow, fast)` 中逐渐积累被交换出来的 `0`；
- 最终所有 `0` 自然留在后半部分。

例如：

```text
[0, 1, 0, 3, 12]
```

扫描到 `1` 时：

```text
[1, 0, 0, 3, 12]
```

扫描到 `3` 时：

```text
[1, 3, 0, 0, 12]
```

扫描到 `12` 时：

```text
[1, 3, 12, 0, 0]
```

## 五、覆盖法与交换法怎么选

| 方法 | 核心操作 | 是否需要最后补 0 | 时间复杂度 | 空间复杂度 |
| --- | --- | --- | --- | --- |
| 覆盖法 | 非零元素向前覆盖 | 需要 | $O(n)$ | $O(1)$ |
| 交换法 | 非零元素与 `slow` 位置交换 | 不需要 | $O(n)$ | $O(1)$ |

两种方法都正确。

覆盖法更容易从“移除元素”模板迁移；交换法代码更短，而且不需要第二轮补零。

不过交换法可能产生一些没有必要的自交换，例如：

```cpp
swap(nums[i], nums[i]);
```

如果希望进一步减少无意义交换，可以写成：

```cpp
if (slow != fast) {
    swap(nums[slow], nums[fast]);
}
```

## 六、容易犯的错误

### 错误 1：直接排序

排序确实可以让 `0` 集中到一端，但会破坏非零元素的相对顺序。

本题要求的是：

```text
[0, 3, 0, 1]
```

变成：

```text
[3, 1, 0, 0]
```

而不是：

```text
[1, 3, 0, 0]
```

因此不能靠排序解决。

### 错误 2：每遇到一个 0 就删除并整体左移

这种模拟方式在最坏情况下会反复搬移大量元素。

如果数组长度为 $n$，时间复杂度可能退化为：

$$
O(n^2)
$$

双指针可以把它降到：

$$
O(n)
$$

### 错误 3：覆盖后忘记把尾部置零

例如覆盖后可能得到：

```text
[1, 3, 12, 3, 12]
```

前半部分虽然正确，但后半部分仍保留旧数据。

因此覆盖法必须补上：

```cpp
while (slow < nums.size()) {
    nums[slow++] = 0;
}
```

## 七、双指针模板总结

这类题可以抽象为：

```text
fast：寻找“应该保留”的元素
slow：维护“有效区间”的末尾
```

通用框架：

```cpp
int slow = 0;
for (int fast = 0; fast < n; ++fast) {
    if (元素应该保留) {
        nums[slow++] = nums[fast];
    }
}
```

本题中条件就是：

```cpp
nums[fast] != 0
```

因此它与“移除元素”“数组去重”“稳定过滤”等问题拥有相同的算法骨架。
