# 库函数使用原则与复杂度意识

写算法题时，一个很常见的问题是：

> 能不能直接调用标准库？

答案既不是“任何时候都可以”，也不是“刷题必须全部手写”。

真正需要培养的是两种能力：

- **知道库函数内部解决了什么问题**；
- **知道调用它会给整个算法带来什么复杂度**。

<Callout title="一条最实用的原则" type="info">
如果某个库函数直接替你完成了题目真正想考察的核心算法，学习阶段最好自己实现；如果它只是辅助步骤，而且你清楚它的语义与复杂度，就应该放心使用。
</Callout>

---

## 1. 为什么“能 AC”不等于“学会了”

假设题目要求“反转字符串中的单词”。

如果语言直接提供了：

1. 按空格切分；
2. 自动过滤空字符串；
3. 反转单词数组；
4. 自动拼接；

那么几行代码就能得到答案。

这当然可能是正确程序，但如果这道题原本是为了训练：

- 字符串原地处理；
- 双指针；
- 空格规范化；
- 区间反转；

那么大量调用高级字符串 API 会绕过真正的训练目标。

所以刷题阶段首先应该问：

> **题目究竟想让我掌握什么？**

---

## 2. 第一类：核心能力就是这个操作——建议自己实现

典型场景包括：

- 二分查找题直接调用 `lower_bound` 找答案；
- 排序算法学习题直接调用 `sort`；
- KMP 学习题直接调用字符串查找 API；
- 手写堆题直接调用优先队列完成全部核心逻辑；
- 翻转字符串综合题全部交给 `split + reverse + join`。

如果题目本身就在考该算法，则直接调用高级库函数会失去训练意义。

<Callout title="判断标准" type="tip">
把这个库函数删掉以后，如果题目最关键的算法部分也一起消失了，那么学习阶段通常应该自己实现。
</Callout>

---

## 3. 第二类：库函数只是工具——通常应该直接使用

例如二分查找题中：

```cpp
int mid = left + (right - left) / 2;
```

如果你需要：

```cpp
std::max(a, b)
```

完全没有必要重新手写一个 `max`。

同样，解决图论、动态规划、搜索等题目时，经常可以合理使用：

- `vector`；
- `queue`；
- `stack`；
- `set` / `unordered_set`；
- `map` / `unordered_map`；
- `priority_queue`；
- `min`、`max`、`swap`。

这些工具通常不是题目本身的考点，而是为了让你更专注于核心算法。

---

## 4. 第三类：比赛与工程代码——更重视可靠性和表达力

当目标从“训练某个算法”变为：

- 正式比赛；
- 面试现场解决综合问题；
- 工程开发；
- 生产代码；

标准库往往应该优先使用。

因为成熟库函数通常具有：

- 更充分的测试；
- 更清晰的语义；
- 更少的边界错误；
- 很好的通用性能；
- 更低的维护成本。

工程代码里为了证明“我会手写排序”而自己重写排序器，通常并不是好习惯。

---

## 5. 使用库函数之前必须知道复杂度

库函数不是“免费操作”。

例如 C++ 中：

```cpp
std::vector<int> nums;
```

如果在序列中间执行：

```cpp
nums.insert(nums.begin(), x);
```

为了给新元素腾位置，后面的元素通常需要整体移动，因此一次操作可能是：

$$
O(n)
$$

如果它又出现在执行 $n$ 次的循环里：

```cpp
for (int i = 0; i < n; ++i) {
    nums.insert(nums.begin(), i);
}
```

总复杂度就会达到：

$$
O(n^2)
$$

代码表面只有两三行，但隐藏工作量非常大。

---

## 6. 字符串 `insert` / `erase` 为什么容易制造 $O(n^2)$

考虑：

```cpp
for (int i = 0; i < n; ++i) {
    s.erase(s.begin());
}
```

每次删除第一个字符后，后面的字符通常都要前移。

如果当前字符串长度依次为：

$$
n,n-1,n-2,\ldots,1
$$

总移动量约为：

$$
n+(n-1)+(n-2)+\cdots+1
$$

根据等差数列求和：

$$
\frac{n(n+1)}{2}
$$

所以总时间复杂度是：

$$
O(n^2)
$$

<Callout title="代码短不代表复杂度低" type="warning">
复杂度必须分析库函数真正做的工作，而不能只数你写了多少行代码。
</Callout>

---

## 7. 常见容器操作复杂度速查

下面给出算法题中常见操作的典型复杂度。具体保证仍应以所用语言和标准库文档为准。

| 操作 | 典型复杂度 |
| --- | ---: |
| `vector[i]` 随机访问 | $O(1)$ |
| `vector.push_back()` | 摊还 $O(1)$ |
| `vector` 中间插入/删除 | $O(n)$ |
| `deque` 首尾插入删除 | $O(1)$ |
| `list` 已知迭代器位置插入/删除 | $O(1)$ |
| `map` 查找/插入/删除 | $O(\log n)$ |
| `unordered_map` 平均查找/插入 | 平均 $O(1)$，最坏可退化 |
| `priority_queue.push()` | $O(\log n)$ |
| `priority_queue.pop()` | $O(\log n)$ |
| 堆顶访问 | $O(1)$ |
| 一般比较排序 | $O(n\log n)$ |

“摊还 $O(1)$”也需要理解：单次动态扩容可能是 $O(n)$，但一系列尾插操作平均下来仍可达到摊还常数级。

## 8. `sort` 可以用吗

要看题目考什么。

### 情况 A：题目考排序算法本身

例如：

> 实现快速排序 / 归并排序 / 堆排序。

那么直接写：

```cpp
sort(nums.begin(), nums.end());
```

显然绕开了考点。

### 情况 B：排序只是解题前处理

例如三数之和常见思路是：

1. 排序；
2. 枚举第一个数；
3. 双指针寻找另外两个数。

这时排序只是工具，直接使用标准库排序非常合理。

若排序复杂度为：

$$
O(n\log n)
$$

双指针阶段为：

$$
O(n^2)
$$

因此总体复杂度仍由较高阶项主导：

$$
O(n^2)
$$

---

## 9. 二分查找：什么时候自己写，什么时候用 `lower_bound`

如果你正在学习：

- 左闭右闭区间；
- 左闭右开区间；
- 第一个大于等于目标的位置；
- 最后一个小于目标的位置；

建议自己写二分。

因为二分查找最难的往往不是公式，而是**区间不变量**。

但在综合题中，如果你已经熟悉二分原理，需要快速寻找第一个满足条件的位置：

```cpp
auto it = lower_bound(nums.begin(), nums.end(), target);
```

通常更安全、更清晰。

关键在于你应该知道它对随机访问有序区间执行的比较次数是对数量级：

$$
O(\log n)
$$

---

## 10. 哈希表 API 很方便，但不要忘记最坏情况

例如：

```cpp
unordered_map<int, int> count;
count[x]++;
```

平均情况下，单次查找或插入常写作：

$$
O(1)
$$

所以处理 $n$ 个元素常得到平均：

$$
O(n)
$$

但哈希表的理论最坏情况可能发生大量碰撞，操作退化到线性级别。

算法题通常接受“平均 $O(1)$”的分析，但应该知道这是**平均/期望意义上的性质**，而不是所有情况下绝对常数时间。

---

## 11. Python 中尤其要警惕“高级语法隐藏成本”

例如：

```python
s = s[1:]
```

看起来只是一个切片表达式，但通常会创建新字符串，成本与切片长度相关。

如果在循环中反复这样做：

```python
while s:
    s = s[1:]
```

总复制字符数量为：

$$
n+(n-1)+\cdots+1=O(n^2)
$$

同理，经常需要注意：

- 字符串拼接；
- 列表切片；
- `in` 在列表中的线性查找；
- `pop(0)` 导致整体移动；
- 深层复制。

因此“Python 一行代码完成”并不意味着底层只做一次操作。

---

## 12. Java 中也要注意容器的具体实现

例如：

```java
ArrayList<Integer> list = new ArrayList<>();
list.add(0, value);
```

在头部插入元素时，后面的元素需要移动，一次操作通常为：

$$
O(n)
$$

如果频繁在首部插入，则应考虑是否需要：

```java
Deque<Integer>
```

而不是机械使用 `ArrayList`。

这说明真正重要的不是“会不会调用 API”，而是：

> **数据结构与你要执行的操作是否匹配。**

---

## 13. 什么时候应该研究源码或实现原理

并不是所有库函数都需要背源码。

算法学习中至少应掌握：

- 它提供什么语义；
- 时间复杂度；
- 空间复杂度；
- 是否复制数据；
- 是否可能使迭代器/引用失效；
- 边界行为；
- 适用于什么数据结构。

例如使用动态数组时，需要理解扩容可能导致：

- 重新分配更大缓冲区；
- 搬迁已有元素；
- 原指针或迭代器失效。

不需要背每一行实现代码，但必须知道这些算法层面的后果。

---

## 14. 面试时应该怎样处理库函数

面试中可以遵循这样的策略：

### 先确认考点

如果面试官明确要求“实现某算法”，就不要用等价库函数绕过它。

### 说明你使用的操作复杂度

例如：

> 我这里用哈希表记录出现次数，平均查询和插入为 $O(1)$，因此这一阶段平均为 $O(n)$。

这比只写出代码更能体现算法意识。

### 如果担心库函数掩盖细节，可主动说明

例如：

> 这里我先调用标准排序；如果需要，我也可以手写归并排序实现。

### 不要为了“炫技”重复造轮子

如果库函数不是考点，优先写清晰、正确、可靠的实现。

---

## 15. 一个判断库函数能不能用的四问法

每次准备调用一个高级 API 时，快速问自己：

### 问题一：它是不是题目的核心考点？

是 → 学习阶段优先自己实现。

### 问题二：我知道它的时间复杂度吗？

不知道 → 先查清楚再用。

### 问题三：它会不会偷偷复制或移动大量数据？

会 → 必须纳入复杂度分析。

### 问题四：它是否让代码显著更清晰，而没有掩盖核心算法？

是 → 通常值得使用。

这四问足以覆盖绝大多数刷题场景。

## 16. 示例：低效地删除字符串中的空格

一种容易写出的方案是不断 `erase`：

```cpp
for (int i = 0; i < static_cast<int>(s.size());) {
    if (s[i] == ' ') {
        s.erase(s.begin() + i);
    } else {
        ++i;
    }
}
```

若大量空格出现在前部，每次删除都可能搬移后续字符，因此最坏可能达到：

$$
O(n^2)
$$

更好的思路是使用双指针一次覆盖：

```cpp
int slow = 0;
for (int fast = 0; fast < static_cast<int>(s.size()); ++fast) {
    if (s[fast] != ' ') {
        s[slow++] = s[fast];
    }
}
s.resize(slow);
```

整个扫描只需：

$$
O(n)
$$

这正体现了“会调用库函数”和“理解库函数代价”的差别。

## 17. 示例：不要把复杂度分析停在 API 名称上

假设：

```cpp
for (int x : nums) {
    if (find(v.begin(), v.end(), x) != v.end()) {
        // ...
    }
}
```

如果：

- `nums` 长度为 $n$；
- `v` 长度也为 $n$；
- `find` 在线性容器上为 $O(n)$；

那么整体是：

$$
O(n)\times O(n)=O(n^2)
$$

如果业务语义允许把 `v` 改成哈希集合，则平均查找可能变成：

$$
O(1)
$$

总复杂度有机会下降到平均：

$$
O(n)
$$

所以真正需要思考的是“操作复杂度 × 调用次数”。

## 18. 多语言示例：线性时间移除目标元素

下面用一个典型双指针例子说明：即使语言提供删除 API，当题目考察原地数组处理时，自己实现一次线性覆盖通常更符合训练目标。

### C++

```cpp
int removeElement(vector<int>& nums, int val) {
    int slow = 0;

    for (int fast = 0; fast < static_cast<int>(nums.size()); ++fast) {
        if (nums[fast] != val) {
            nums[slow++] = nums[fast];
        }
    }

    return slow;
}
```

### Java

```java
static int removeElement(int[] nums, int val) {
    int slow = 0;

    for (int fast = 0; fast < nums.length; fast++) {
        if (nums[fast] != val) {
            nums[slow++] = nums[fast];
        }
    }

    return slow;
}
```

### Python

```python
def remove_element(nums: list[int], val: int) -> int:
    slow = 0

    for fast in range(len(nums)):
        if nums[fast] != val:
            nums[slow] = nums[fast]
            slow += 1

    return slow
```

时间复杂度为：

$$
O(n)
$$

额外空间为：

$$
O(1)
$$

## 总结

库函数本身既不是“作弊”，也不是“越少用越厉害”。

真正成熟的使用原则是：

- **核心考点**：为了训练能力，优先自己实现；
- **辅助工具**：明确语义与复杂度后放心调用；
- **比赛与工程**：优先可靠、清晰、经过充分测试的标准实现；
- **任何场景**：都必须把库函数真实成本纳入复杂度分析。

最后记住一句话：

> **标准库能替你写代码，但不能替你做复杂度分析。**

当你能看到 `insert`、`erase`、切片、排序、哈希表、堆这些 API 时，立即想到它们背后的数据结构和复杂度，才真正具备了稳定解决算法问题的基础能力。
