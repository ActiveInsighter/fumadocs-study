# 递归算法的时间复杂度与快速幂

很多人看到递归代码，会下意识认为复杂度是 $O(\log n)$。这是错误的。

递归只是**程序结构**，并不能决定复杂度。真正决定时间复杂度的是：

1. 每一层产生多少个递归调用；
2. 参数规模如何缩小；
3. 每次调用除了递归之外还做多少工作。

<Callout title="核心原则" type="info">
分析递归复杂度，不要数代码行，而要写出递推关系，或者画出递归树。
</Callout>

本文用一个经典问题贯穿全过程：

> 计算 $x^n$。

---

## 1. 最直接的循环：$O(n)$

最朴素的方法是连续乘 $n$ 次：

```cpp
long long powerLinear(long long x, long long n) {
    long long result = 1;
    for (long long i = 0; i < n; ++i) {
        result *= x;
    }
    return result;
}
```

执行的乘法次数与 $n$ 成正比，因此：

$$
T(n)=\Theta(n)
$$

这里没有递归，但它为后续比较提供了基准。

---

## 2. 递归并不会自动变成 $O(\log n)$

把循环机械改成递归：

```cpp
long long powerRecursive(long long x, long long n) {
    if (n == 0) {
        return 1;
    }
    return powerRecursive(x, n - 1) * x;
}
```

每次只把 $n$ 减少 1，因此递推式为：

$$
T(n)=T(n-1)+O(1)
$$

展开：

$$
\begin{aligned}
T(n)
&=T(n-1)+O(1)\\
&=T(n-2)+2O(1)\\
&=\cdots\\
&=T(0)+nO(1)
\end{aligned}
$$

所以：

$$
T(n)=O(n)
$$

<Callout title="第一个重要结论" type="warning">
是否使用递归，与复杂度是 $O(n)$ 还是 $O(\log n)$ 没有直接关系。关键看参数每次减少多少。
</Callout>

---

## 3. 把问题规模减半，就一定是 $O(\log n)$ 吗？

不一定。

下面这段代码看起来每次都把 $n$ 变成 $n/2$：

```cpp
long long powerWrong(long long x, long long n) {
    if (n == 0) return 1;
    if (n == 1) return x;

    if (n % 2 == 1) {
        return powerWrong(x, n / 2)
             * powerWrong(x, n / 2)
             * x;
    }

    return powerWrong(x, n / 2)
         * powerWrong(x, n / 2);
}
```

很多人会马上判断：每次 $n/2$，所以是 $O(\log n)$。

问题在于：**每一层不是调用一次，而是调用两次。**

递推式是：

$$
T(n)=2T\left(\frac n2\right)+O(1)
$$

---

## 4. 用递归树理解重复计算

当 $n=16$ 时，可以把递归调用画成一棵近似满二叉树。

![递归算法的时间复杂度](https://file1.kamacoder.com/i/algo/20201209193909426.png)

第 0 层有：

$$
1
$$

个调用，第 1 层有：

$$
2
$$

个，第 2 层有：

$$
4
$$

个……

如果树高约为：

$$
\log_2n
$$

那么总节点数近似为：

$$
1+2+4+\cdots+2^{\log_2n}
$$

利用等比数列：

$$
1+2+4+\cdots+2^k=2^{k+1}-1
$$

令：

$$
k=\log_2n
$$

则：

$$
2^{\log_2n}=n
$$

所以总调用次数是：

$$
O(n)
$$

![递归树与节点数量](https://file1.kamacoder.com/i/algo/20200728195531892.png)

因此：

$$
T(n)=2T\left(\frac n2\right)+O(1)=O(n)
$$

---

## 5. 为什么这段代码有严重重复计算

注意：

```cpp
powerWrong(x, n / 2) * powerWrong(x, n / 2)
```

两个递归调用计算的是**完全相同的值**。

假设：

$$
t=x^{\lfloor n/2\rfloor}
$$

只要计算一次 $t$，后面复用即可。

这就是优化的关键。

---

## 6. 快速幂：真正的 $O(\log n)$

优化后的递归写法：

```cpp
long long fastPow(long long x, long long n) {
    if (n == 0) {
        return 1;
    }

    long long half = fastPow(x, n / 2);

    if (n % 2 == 0) {
        return half * half;
    }

    return half * half * x;
}
```

此时每一层只产生**一个**递归调用，所以递推式变成：

$$
T(n)=T\left(\frac n2\right)+O(1)
$$

不断展开：

$$
\begin{aligned}
T(n)
&=T(n/2)+O(1)\\
&=T(n/4)+2O(1)\\
&=T(n/8)+3O(1)\\
&=\cdots
\end{aligned}
$$

经过 $k$ 层后：

$$
\frac{n}{2^k}=1
$$

于是：

$$
2^k=n
$$

$$
k=\log_2n
$$

因此：

$$
T(n)=O(\log n)
$$

<Callout title="真正决定复杂度的变化" type="tip">
优化前：每层分裂成两个子问题。优化后：每层只有一个子问题。虽然两者都把参数缩小为一半，复杂度却分别是 $O(n)$ 和 $O(\log n)$。
</Callout>

---

## 7. 快速幂为什么成立

它利用了指数的二进制拆分性质。

当 $n$ 为偶数：

$$
x^n=x^{n/2}\cdot x^{n/2}
$$

因此：

$$
x^n=(x^{n/2})^2
$$

当 $n$ 为奇数：

$$
x^n=x^{\lfloor n/2\rfloor}\cdot x^{\lfloor n/2\rfloor}\cdot x
$$

所以每次都可以把指数规模缩小一半。

例如：

$$
x^{13}
$$

由于：

$$
13=(1101)_2=8+4+1
$$

所以：

$$
x^{13}=x^8x^4x
$$

只需要不断平方即可快速构造这些幂。

---

## 8. 迭代版快速幂

递归并不是快速幂的必要条件。利用二进制，可以写成迭代形式。

```cpp
long long fastPowIterative(long long x, long long n) {
    long long result = 1;

    while (n > 0) {
        if (n & 1LL) {
            result *= x;
        }
        x *= x;
        n >>= 1;
    }

    return result;
}
```

每次右移一位，相当于：

$$
n\leftarrow\left\lfloor\frac n2\right\rfloor
$$

循环次数就是二进制位数：

$$
O(\log n)
$$

空间复杂度则是：

$$
O(1)
$$

而递归版由于调用栈深度为 $O(\log n)$，空间复杂度为：

$$
O(\log n)
$$

---

## 9. 递归复杂度的三个基本模型

### 模型一：每次规模减 1

$$
T(n)=T(n-1)+O(1)
$$

通常得到：

$$
O(n)
$$

典型例子：

- 递归遍历链表；
- 线性递归求和；
- 上面的朴素递归幂。

### 模型二：每次规模减半，只递归一次

$$
T(n)=T(n/2)+O(1)
$$

得到：

$$
O(\log n)
$$

典型例子：

- 二分查找；
- 快速幂。

### 模型三：每次分裂成两个一半规模子问题

$$
T(n)=2T(n/2)+O(n)
$$

得到：

$$
O(n\log n)
$$

典型例子：归并排序。

如果层外工作只是 $O(1)$：

$$
T(n)=2T(n/2)+O(1)
$$

则通常是：

$$
O(n)
$$

这正是前面错误快速幂写法的情况。

---

## 10. 从递归树看“深度”和“节点数”

递归分析最容易混淆两个概念：

- **递归深度**：从根到最深叶子的长度；
- **递归调用总数**：整棵递归树所有节点数量。

对于：

$$
T(n)=2T(n/2)+O(1)
$$

深度确实只有：

$$
O(\log n)
$$

但第 $i$ 层有：

$$
2^i
$$

个调用，所以总节点数为：

$$
1+2+4+\cdots+n=O(n)
$$

<Callout title="高频误区" type="warning">
递归深度是 $O(\log n)$，不代表总时间复杂度一定是 $O(\log n)$。时间复杂度通常取决于整棵递归树的总工作量。
</Callout>

---

## 11. 如何快速写出递推式

看到递归函数时，可以按三步分析。

### 数一层会递归几次

例如有两个 `solve(n / 2)`：

$$
a=2
$$

看每个子问题缩小到多少

例如：

$$
\frac nb
quad\text{且}\quad b=2
$$

计算当前层的非递归工作

记作：

$$
f(n)
$$

于是递推式写成：

$$
T(n)=aT\left(\frac nb\right)+f(n)
$$

这也是分治算法分析最常见的形式。

---

## 12. 主定理的直观用法

对于：

$$
T(n)=aT\left(\frac nb\right)+f(n)
$$

递归树每层子问题的总规模由：

$$
n^{\log_ba}
$$

这个量控制。

几个最重要的例子：

| 递推式 | 结果 |
| --- | --- |
| $T(n)=T(n/2)+O(1)$ | $O(\log n)$ |
| $T(n)=2T(n/2)+O(1)$ | $O(n)$ |
| $T(n)=2T(n/2)+O(n)$ | $O(n\log n)$ |
| $T(n)=2T(n/2)+O(n^2)$ | $O(n^2)$ |

在算法基础阶段，不必立刻死记主定理全部形式，先学会用递归树理解这些典型情况更重要。

---

## 13. 时间复杂度与空间复杂度要分开看

递归版快速幂：

$$
T(n)=O(\log n)
$$

而调用栈深度也是：

$$
O(\log n)
$$

因此辅助空间复杂度为：

$$
O(\log n)
$$

迭代版快速幂虽然时间仍是：

$$
O(\log n)
$$

但只使用固定数量变量，因此辅助空间为：

$$
O(1)
$$

这说明：

> 同样的时间复杂度，并不代表空间复杂度也相同。

---

## 14. 负指数与边界问题

如果问题扩展为计算实数意义上的 $x^n$，且允许：

$$
n<0
$$

可以利用：

$$
x^n=\frac1{x^{-n}}
$$

但工程实现时需要特别注意最小整数溢出。

例如 32 位有符号整数：

$$
-2^{31}
$$

取相反数后：

$$
2^{31}
$$

超出 `int` 正数范围。

因此一般先把指数转成更宽的整数类型，例如 `long long` 或 `long`。

---

## 15. 常见错误总结

### 错误一：只要参数每次除 2，就是 $O(\log n)$

错误。还要看每一层产生几个递归分支。

### 错误二：把两个相同递归调用写两遍

```cpp
solve(n / 2) + solve(n / 2)
```

如果两次结果完全相同，通常应该先保存：

```cpp
auto t = solve(n / 2);
return t + t;
```

### 错误三：只看递归深度，不看总节点数

深度和总调用数是两回事。

### 错误四：只分析时间，不分析栈空间

递归函数还要关注最大递归深度和栈溢出风险。

---

## 16. 一页速记

| 代码特征 | 典型递推式 | 复杂度 |
| --- | --- | --- |
| `solve(n - 1)` | $T(n)=T(n-1)+O(1)$ | $O(n)$ |
| 单次 `solve(n / 2)` | $T(n)=T(n/2)+O(1)$ | $O(\log n)$ |
| 两次 `solve(n / 2)` | $T(n)=2T(n/2)+O(1)$ | $O(n)$ |
| 两个一半问题 + 线性合并 | $T(n)=2T(n/2)+O(n)$ | $O(n\log n)$ |
| 快速幂 | $T(n)=T(n/2)+O(1)$ | $O(\log n)$ |

<Callout title="最值得记住的一句话" type="tip">
分析递归时，先写 $T(n)$ 的递推式。递推式一旦正确，复杂度判断通常就已经完成了一半。
</Callout>

## 17. 多语言实现

### C++

```cpp
long long fastPow(long long x, long long n) {
    if (n == 0) {
        return 1;
    }

    long long half = fastPow(x, n / 2);
    long long result = half * half;

    if (n & 1LL) {
        result *= x;
    }

    return result;
}

long long fastPowIterative(long long x, long long n) {
    long long result = 1;

    while (n > 0) {
        if (n & 1LL) {
            result *= x;
        }
        x *= x;
        n >>= 1;
    }

    return result;
}
```

### Java

```java
static long fastPow(long x, long n) {
    if (n == 0) {

    long result = 1;

        if ((n & 1L) != 0) {

    }

```

### Python

```python
def fast_pow(x: int, n: int) -> int:
    if n == 0:
        return 1

    half = fast_pow(x, n // 2)
    result = half * half

    if n & 1:
        result *= x

    return result


def fast_pow_iterative(x: int, n: int) -> int:
    result = 1

    while n > 0:
        if n & 1:
            result *= x
        x *= x
        n >>= 1

    return result
```

## 总结

递归复杂度分析的核心不是“代码看起来递归了几层”，而是研究整棵递归树的总工作量。

对于快速幂，真正的优化并不只是把：

$$
n\to\frac n2
$$

而是把两个相同子问题合并成一次计算，使递推式从：

$$
T(n)=2T(n/2)+O(1)
$$

变为：

$$
T(n)=T(n/2)+O(1)
$$

于是时间复杂度从：

$$
O(n)
$$

降为：

$$
O(\log n)
$$

这也是学习分治、归并排序、二分查找和动态规划时非常重要的一种思想：**不要重复求解同一个子问题。**
