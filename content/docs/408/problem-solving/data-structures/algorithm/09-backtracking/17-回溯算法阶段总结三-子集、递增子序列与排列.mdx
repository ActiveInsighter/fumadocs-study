# 回溯算法阶段总结三：子集、递增子序列与排列

这一阶段连续解决了四类高度相似、但状态设计明显不同的问题：

```text
90. 子集 II
491. 非递减子序列
46. 全排列
47. 全排列 II
```

如果只记代码，很容易出现这样的混乱：

```text
什么时候需要排序？
什么时候用 startIndex？
什么时候必须用 used？
什么时候用 Set？
重复元素到底是“树层去重”还是“树枝不能重复”？
```

真正稳定的方法，是把它们全部还原为同一个问题：

> **搜索树中的一个节点代表什么？一条树枝保存什么状态？同一树层允许出现哪些候选？答案分布在树上的什么位置？**

<Callout title="这一阶段最重要的四个关键词">

$$
\boxed{
\text{候选范围}
+\text{路径状态}
+\text{树层去重}
+\text{答案位置}
}
$$

只要这四件事能说清楚，大多数回溯题都不需要死背模板。

</Callout>

## 1. 子集 II：在“整棵树收集答案”上加入树层去重

`90. 子集 II` 的输入允许重复元素。

原资料中的搜索树：

![90. 子集 II](https://file1.kamacoder.com/i/algo/2020111217110449-20230310133150714.png)

它仍然属于标准子集模型：

```text
下一层只能继续向右选
```

所以候选范围由：

```cpp
startIndex
```

控制。

与普通子集相比，只多了一个要求：

```text
相同数值不能在同一树层重复开启分支
```

排序后可以写成：

```cpp
if (i > startIndex && nums[i] == nums[i - 1]) {
    continue;
}
```

### 为什么只去同层，不去同枝？

例如：

```text
nums = [1,2,2]
```

同一路径中选择两个 `2`：

```text
[2,2]
```

是合法子集。

但根节点分别用两个 `2` 开始：

```text
[] → 第一个 2
[] → 第二个 2
```

会得到重复的 `[2]`。

因此原则是：

$$
\boxed{\text{树层去重，树枝允许重复值}}
$$

## 2. 递增子序列：看起来像子集 II，却不能排序

`491. 非递减子序列` 也要从数组中选若干元素，也要去重，所以非常容易照搬 `90. 子集 II`。

原资料中的搜索树：

![491. 非递减子序列](https://file1.kamacoder.com/i/algo/20201112170832333-20230310133155209.png)

但两题有一个决定性差异：

```text
子集：只关心选了哪些值
子序列：还必须保持原数组相对顺序
```

所以 `491` **不能排序**。

一旦排序：

```text
原数组信息被破坏
```

你求出的就不再是原数组的子序列。

因此无法依赖：

```cpp
nums[i] == nums[i - 1]
```

来完成同层去重，而要为**每一层**单独记录本层已经选择过哪些值：

```cpp
unordered_set<int> usedThisLevel;
```

或者利用题目值域较小，用数组充当集合。

<Callout type="info" title="一个非常重要的判断顺序">

遇到重复元素问题，不要先问：

```text
我要不要排序？
```

应该先问：

```text
排序会不会破坏题目的语义？
```

如果原始相对顺序有意义，就不能为了方便去重而排序。

</Callout>

## 3. 从子集切换到排列：候选范围发生根本改变

`46. 全排列` 是这一阶段真正的模型切换点。

原资料中的搜索树：

![46. 全排列](https://file1.kamacoder.com/i/algo/20201112170304979-20230310133201250.png)

组合 / 子集问题中：

```text
[1,2]
```

和：

```text
[2,1]
```

通常被视作相同选择，因此只向右搜索。

排列则完全不同：

$$
(1,2)\ne(2,1)
$$

所以当第一步选择 `2` 后，下一层仍然可能选择它左边尚未使用的 `1`。

这意味着：

```text
startIndex 失效
```

每一层都必须重新遍历：

```cpp
for (int i = 0; i < nums.size(); ++i)
```

然后用：

```cpp
used[i]
```

记录这个数组下标是否已经出现在当前路径中。

所以：

$$
\boxed{
\text{组合/子集：startIndex 控制候选区间}
}
$$

而：

$$
\boxed{
\text{排列：used 控制当前路径的可用下标}
}
$$

## 4. `used[i]` 本质上不是“去重数组”

这是非常容易产生的误解。

在普通全排列中没有重复值，但仍然需要：

```cpp
used[i]
```

所以它的首要职责根本不是“去掉重复答案”。

`used[i]` 真正表示：

```text
下标 i 对应的元素是否已经被当前排列路径占用
```

它是：

$$
\boxed{\text{树枝状态}}
$$

例如：

```text
path = [2,1]
used = [T,T,F]
```

表示当前排列前两个位置已经使用了下标 `0`、`1`，下一步只能使用下标 `2`。

这与“这一层某个值是否已经尝试过”完全是两件事。

## 5. 全排列 II：`used` 模型上再叠加同层去重

`47. 全排列 II` 同时拥有两个约束：

```text
排列：同一下标不能在一条路径中重复使用
重复值：同一树层不能用相同数值重复开分支
```

原资料中的搜索树：

![47. 全排列 II](https://file1.kamacoder.com/i/algo/20201112171930470-20230310133206398.png)

标准写法：

```cpp
if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) {
    continue;
}

if (used[i]) {
    continue;
}
```

两条判断不要混在一起背。

### 第一条

```cpp
nums[i] == nums[i - 1] && !used[i - 1]
```

解决：

```text
同一树层，相同值重复开分支
```

### 第二条

```cpp
used[i]
```

解决：

```text
同一树枝，同一个下标被重复使用
```

这就是为什么“排列去重”比“组合去重”多了一个 `used` 维度。

## 6. 树层与树枝：回溯去重的核心坐标系

可以把整棵搜索树想象成两个方向。

### 纵向：树枝

代表：

```text
当前正在构造的一个具体答案
```

例如排列路径：

```text
[] → [1] → [1,2] → [1,2,3]
```

### 横向：树层

代表：

```text
在同一个父状态下，当前这个位置可以尝试哪些候选
```

例如：

```text
当前 path = [1]
下一位可能选择 2 / 3 / 4 ...
```

很多去重题真正需要删除的是：

> **同一父状态下，由相同值产生的等价子树。**

所以通常是**树层去重**，而不是禁止树枝上出现相同数值。

## 7. 两种全排列 II 去重写法为什么都能工作？

标准写法是：

```cpp
if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) {
    continue;
}
```

原资料还给出了：

```cpp
if (i > 0 && nums[i] == nums[i - 1] && used[i - 1]) {
    continue;
}
```

这两种写法都能为每一种**值排列**保留一条代表性的“重复元素下标排列”，所以都能得到正确结果。

但它们删除重复的时机不同。

### `!used[i - 1]`：树层去重

原资料中的树形结构：

![47. 全排列 II：树层去重](https://file1.kamacoder.com/i/algo/20201112172230434-20230310133211392.png)

它直接在同一个父节点下拒绝第二个相同候选。

因此：

```text
重复子树越早被删除
搜索越紧凑
```

### `used[i - 1]`：对重复下标施加树枝顺序限制

原资料中的树形结构：

![47. 全排列 II：树枝顺序限制](https://file1.kamacoder.com/i/algo/20201112172327967-20230310133216389.png)

它不会在浅层立刻删除所有重复候选，而是约束相同值对应下标在一条路径中的使用顺序。

最终仍能唯一化值排列，但通常会展开更多无效节点。

因此实践中更推荐：

```cpp
!used[i - 1]
```

它与“树层去重”的统一框架最一致。

## 8. 四道题的状态设计总表

| 题目 | 顺序是否重要 | 能否排序 | 下一层候选范围 | 树枝状态 | 树层去重 | 收集位置 |
| --- | --- | --- | --- | --- | --- | --- |
| `90. 子集 II` | 否 | 可以 | `[startIndex,n)` | `path` | 排序 + 相邻跳重 | 每个节点 |
| `491. 非递减子序列` | 原相对顺序重要 | **不能** | `[startIndex,n)` | `path` | 每层 `Set` / 值域数组 | 长度 $\ge 2$ 的节点 |
| `46. 全排列` | 是 | 无必要 | `[0,n)` | `path + used` | 不需要 | 深度 $n$ 的叶子 |
| `47. 全排列 II` | 是 | 可以 | `[0,n)` | `path + used` | 排序 + `!used[i-1]` | 深度 $n$ 的叶子 |

这张表比背四套模板更重要。

## 9. 如何从题意判断该用 `startIndex` 还是 `used`？

先问一个问题：

> **选择一个较靠后的元素后，后续还能不能回来选择它左边尚未选择的元素？**

### 不能

例如：

```text
组合
子集
子序列
切割
```

一般都有天然的“向后推进”关系：

```cpp
backtracking(i + 1)
```

因此使用：

```text
startIndex
```

### 能

例如排列：

```text
先选 nums[5]
下一步仍可能选 nums[1]
```

那么候选区间不能单向缩小，需要每层重新遍历整个数组，再用：

```text
used
```

记录当前路径占用了哪些位置。

## 10. 如何判断“去重”应该放在哪里？

再问一个问题：

> **重复答案是由“同一路径内部”造成的，还是由“同一父节点下的多个等价候选”造成的？**

多数重复元素回溯题中，真正的问题是后者。

例如：

```text
根节点选择第一个 2
根节点选择第二个 2
```

如果两者后续能产生相同答案集合，那么第二棵子树就是冗余的。

所以正确思路通常是：

$$
\boxed{\text{同一树层只保留一个等价候选代表}}
$$

而不是粗暴地规定：

```text
相同值永远只能出现一次
```

## 11. 回溯题的答案为什么有时在节点，有时只在叶子？

这取决于“当前路径什么时候已经是一个合法答案”。

### 子集

每一个路径都代表一个合法子集：

```text
[]
[1]
[1,2]
[1,2,3]
```

所以：

```text
整棵树的节点都收集
```

### 非递减子序列

长度达到 `2` 就已经是合法答案，所以：

```text
满足长度条件的中间节点也收集
```

### 全排列

只有当：

```text
path.size() == nums.size()
```

所有位置都填满时才是完整答案，所以：

```text
只收集叶子节点
```

<Callout title="答案位置其实由题目定义决定">

不要机械记：

```text
组合在叶子
子集在节点
```

而应该判断：

```text
当前 path 是否已经满足题目要求？
```

满足就可以收集；不满足就继续搜索。

</Callout>

## 12. 复杂度：先从“答案空间”出发

回溯问题很难脱离具体题目给出一个统一复杂度。

最可靠的方法是先估计：

```text
最多有多少个候选答案？
每个答案复制 / 验证需要多少成本？
搜索过程中还有多少额外节点？
```

### 12.1 子集

一个有 $n$ 个不同元素的集合共有：

$$
2^n
$$

个子集。

如果需要把每个子集复制到结果中，所有输出元素总量为：

$$
\sum_{k=0}^{n}k\binom{n}{k}
=
 n2^{n-1}
$$

因此包含输出构造成本时，常写为：

$$
\boxed{O(n2^n)}
$$

辅助递归深度最多为：

$$
O(n)
$$

### 12.2 全排列

$n$ 个互不相同元素共有：

$$
n!
$$

个排列。

每个结果长度为 $n$，复制结果至少需要：

$$
O(n)
$$

所以包含输出构造成本时：

$$
\boxed{O(n\cdot n!)}
$$

而不是把 $n\cdot n!$ “简化”为 $O(n!)$。

辅助空间仍为：

$$
O(n)
$$

### 12.3 含重复元素的全排列

如果不同值出现次数为：

$$
c_1,c_2,\dots,c_m
$$

不同答案数量为：

$$
\frac{n!}{c_1!c_2!\cdots c_m!}
$$

重复越多，实际输出和搜索树越小。

但最坏情况仍是所有元素不同，所以最坏时间复杂度仍按：

$$
O(n\cdot n!)
$$

计算。

## 13. 不要把“指数级”当成精确复杂度

回溯经常被概括为：

```text
指数级搜索
```

这作为直觉没有问题，但它不是所有题目的精确表达。

例如：

```text
子集：2^n
全排列：n!
固定长度组合：C(n,k)
```

而：

$$
n!
$$

甚至比任意固定底数的：

$$
c^n
$$

增长得更快。

所以分析回溯复杂度时，优先描述**搜索空间的真实组合结构**，比笼统写“指数级”更准确。

## 14. 四类最常见的“去重工具”

### 工具一：`startIndex`

它主要不是用来处理重复值，而是避免组合 / 子集中的**顺序重复**。

例如：

```text
[1,2]
```

生成以后，不再回头生成：

```text
[2,1]
```

### 工具二：排序 + 相邻元素判断

适用于：

```text
允许重排输入
且相同值需要做同层去重
```

典型：

```text
40. 组合总和 II
90. 子集 II
47. 全排列 II
```

### 工具三：每层 `Set`

适用于不能排序，但仍需要同层按值去重的情况。

典型：

```text
491. 非递减子序列
```

### 工具四：`used[i]`

主要用于：

```text
排列问题中记录当前树枝已经使用的下标
```

不要把它和“本层 Set”混为一谈。

## 15. 一套统一的读题流程

以后看到新的回溯题，可以按这个顺序分析。

### 第一步：确定 `path` 的语义

问：

```text
path 当前代表什么？
```

可能是：

```text
一个组合
一个切割方案
一个子集
一个排列前缀
```

### 第二步：确定候选集合

问：

```text
下一步可以从哪里选？
```

- 只能向右：考虑 `startIndex`；
- 可以回头选未使用元素：考虑 `used`；
- 图 / 棋盘问题：候选可能由位置和规则动态生成。

### 第三步：确定答案收集位置

问：

```text
什么时候当前 path 已经是合法答案？
```

不要先套“叶子收集”或“节点收集”。

### 第四步：确定同层是否存在等价候选

问：

```text
同一个父状态下，两个候选是否会生成相同答案集合？
```

如果会，就做树层去重。

### 第五步：判断能否排序

排序不能破坏题目语义。

如果不能排序，再考虑：

```text
Set
值域数组
哈希表
```

### 第六步：写出选择与撤销的成对状态

典型结构：

```cpp
选择;
修改状态;

backtracking(...);

恢复状态;
撤销选择;
```

这一步决定了回溯状态是否正确。

## 16. 一个统一伪代码框架

```text
backtracking(state):
    if 当前状态已经形成答案:
        收集答案

    建立“本层状态”（如果需要树层去重）

    for candidate in 当前层候选:
        if candidate 不合法:
            continue

        if candidate 与本层已搜索候选等价:
            continue

        做选择
        更新树枝状态

        backtracking(newState)

        恢复树枝状态
        撤销选择
```

不同题目的差别，本质上只是下面几项不同：

```text
候选如何产生
合法性如何判断
本层如何去重
状态如何更新
什么时候收集答案
```

## 17. 常见混淆一次性解决

### “同一个值出现两次，是不是一定要跳过第二次？”

不是。

要看它们是否位于**同一树层**。

同一树枝上的重复值有时正是合法答案所需要的，例如：

```text
[1,1,2]
```

### “有重复元素是不是一定先排序？”

不是。

只有排序不破坏题意时才能排序。

`491` 就不能排序。

### “用了 `used` 就不需要 `startIndex` 吗？”

不是语法规则，而是题型决定。

排列通常用 `used`，因为每层需要从整个候选集选择。

组合 / 子集通常用 `startIndex`，因为候选范围只能向后推进。

### “去重是在递归前还是递归后？”

通常在**进入重复子树之前**就跳过最有效。

也就是：

```text
尽量早剪掉等价分支
```

这也是 `47. 全排列 II` 中推荐树层去重写法的原因。

## 19. 本阶段结论

这一阶段最大的提升，不是又多会了四道题，而是建立了一个更精确的回溯坐标系：

$$
\boxed{
\text{横向看树层候选与去重}
\quad+
\text{纵向看树枝状态与回溯}
}
$$

再结合：

$$
\boxed{
\text{startIndex 决定“向后选”}
\quad+
\text{used 决定“当前路径哪些位置已占用”}
}
$$

就可以把子集、子序列、组合和排列统一起来。

接下来遇到更复杂的回溯题时，仍然沿用同样的方法：

```text
先画搜索树
→ 定义 path
→ 定义候选范围
→ 区分树层与树枝
→ 找到剪枝 / 去重条件
→ 最后才写代码
```

这才是回溯算法真正可迁移的能力。
