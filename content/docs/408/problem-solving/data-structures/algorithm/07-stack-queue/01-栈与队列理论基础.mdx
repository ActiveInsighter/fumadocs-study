# 栈与队列理论基础

栈（Stack）与队列（Queue）都属于非常基础的线性数据结构。

它们最大的区别，不在于“能存什么”，而在于：

> **元素以什么顺序被访问。**

最核心的两条规则：

```text
栈：后进先出 LIFO
队列：先进先出 FIFO
```

原始示意图：

![栈与队列基本结构](https://file1.kamacoder.com/i/algo/20210104235346563.png)

<Callout type="info" title="为什么这两种结构如此重要">
很多算法并不需要随机访问全部元素，而只关心：

- “最后加入的元素”
- “最早加入的元素”

当访问顺序受到严格约束时，栈和队列能用非常简单的接口表达复杂过程。
</Callout>

---

# 1. 栈：后进先出

栈遵循：

> Last In, First Out，LIFO。

可以把它想象成一摞盘子：

```text
最后放上去的盘子
最先被拿走
```

例如依次压入：

```text
1
2
3
```

栈结构：

```text
top
 ↓
 3
 2
 1
```

第一次弹出：

```text
3
```

第二次弹出：

```text
2
```

原始示意图：

![栈的后进先出](https://file1.kamacoder.com/i/algo/20210104235434905.png)

---

## 2. 栈的基本操作

典型接口：

### `push(x)`

把元素压入栈顶。

### `pop()`

删除栈顶元素。

### `top()`

读取栈顶元素。

### `empty()`

判断栈是否为空。

### `size()`

获取栈中元素个数。

如果底层实现合适，这些操作通常都是：

$$
O(1)
$$

---

# 3. 队列：先进先出

队列遵循：

> First In, First Out，FIFO。

可以类比排队：

```text
先来的人先离开
后来的人排在后面
```

例如依次入队：

```text
1
2
3
```

逻辑结构：

```text
front               back
  ↓                   ↓
  1       2           3
```

第一次出队：

```text
1
```

第二次出队：

```text
2
```

---

## 4. 队列的基本操作

典型接口：

### `push(x)`

把元素加入队尾。

### `pop()`

删除队头元素。

### `front()`

读取队头元素。

### `back()`

读取队尾元素。

### `empty()`

判断是否为空。

### `size()`

获取元素数量。

这些基本操作通常也是：

$$
O(1)
$$

---

# 5. 栈和队列的关键区别

| 特性 | 栈 | 队列 |
| --- | --- | --- |
| 顺序 | 后进先出 | 先进先出 |
| 插入位置 | 栈顶 | 队尾 |
| 删除位置 | 栈顶 | 队头 |
| 常见关键词 | 最近、撤销、匹配、嵌套 | 按顺序、层次、任务调度 |
| 图搜索常见用途 | DFS | BFS |

一句话记忆：

```text
Stack：最后来的先处理
Queue：最早来的先处理
```

---

# 6. C++ 中的 `stack` 和 `queue` 是什么

C++ 标准库中的：

```cpp
std::stack
std::queue
```

并不是普通意义上直接存储元素的“独立底层容器”。

它们属于：

> **容器适配器（container adaptor）**

也就是说：

> 它们在某个底层容器之上，限制接口，只暴露符合栈或队列语义的操作。

这点非常重要。

---

## 7. 什么叫容器适配器

假设底层是一个功能丰富的容器：

```text
deque
```

它本身可以：

- 从头插入；
- 从尾插入；
- 从头删除；
- 从尾删除；
- 随机访问某些位置。

但 `stack` 只允许：

```text
push
pop
top
```

于是它把底层容器“包装”成一个栈。

也就是说：

```text
底层容器
   ↓
限制接口
   ↓
得到 Stack 语义
```

这就是“适配器”的含义。

---

# 8. `std::stack` 默认底层是什么

标准库中的：

```cpp
std::stack<T>
```

默认底层容器通常是：

```cpp
std::deque<T>
```

也就是：

```cpp
std::stack<
    T,
    std::deque<T>
>
```

概念上等价。

为什么 `deque` 合适？

因为栈需要：

```text
尾部插入
尾部删除
读取尾部
```

这些操作在 `deque` 中都可以高效完成。

---

## 9. 栈也可以换底层容器

例如使用 `vector`：

```cpp
std::stack<
    int,
    std::vector<int>
> st;
```

或者使用 `deque`：

```cpp
std::stack<
    int,
    std::deque<int>
> st;
```

只要底层容器支持栈适配器所需要的操作即可。

原资料中的底层结构示意图：

![栈可以适配不同底层容器](https://file1.kamacoder.com/i/algo/20210104235459376.png)

---

# 10. `std::queue` 默认底层是什么

`std::queue<T>` 默认也通常使用：

```cpp
std::deque<T>
```

因为普通队列需要：

```text
尾部插入
头部删除
读取头部
读取尾部
```

而 `deque` 恰好非常适合这些操作。

---

## 11. 为什么 `vector` 不适合作为普通 queue 的底层

如果使用普通动态数组模拟队列：

```text
从尾部 push
从头部 pop
```

那么从头部删除后，后面的元素通常都要向前移动。

一次头删可能达到：

$$
O(n)
$$

因此普通 `vector` 并不适合作为队列的直接底层。

而 `deque` 支持高效的双端插入和删除。

---

# 12. 什么是 `deque`

`deque` 是：

> double-ended queue，双端队列。

它允许在：

```text
头部
尾部
```

都进行高效插入和删除。

可以理解为：

```text
front ← [ ... 元素 ... ] → back
```

所以：

### 如果只开放一端

就能模拟：

```text
Stack
```

### 如果一端入、一端出

就能模拟：

```text
Queue
```

---

# 13. 为什么 `stack` 不提供迭代器

普通容器如：

```cpp
vector
list
set
map
```

通常可以遍历。

但：

```cpp
stack
```

刻意限制了访问方式。

它只允许：

```text
访问栈顶
```

如果允许任意遍历：

```text
访问中间元素
```

就会破坏“栈”的抽象。

所以标准 `std::stack`：

> **不提供普通迭代器接口。**

同理：

```cpp
std::queue
```

也不会让你随意遍历内部所有元素。

<Callout type="tip" title="抽象比实现更重要">
即使底层容器本身支持随机访问或迭代，容器适配器也会故意隐藏这些能力。

这就是“只暴露合法操作”的抽象设计。
</Callout>

---

# 14. 栈的典型应用

栈特别适合处理：

> **最近加入、但还没有完成处理的对象。**

---

## 15. 括号匹配

例如：

```text
({[]})
```

遇到左括号：

```text
push
```

遇到右括号：

```text
检查栈顶是否匹配
```

最后：

```text
栈必须为空
```

为什么适合栈？

因为：

> 最后出现的左括号，应该最先被对应的右括号关闭。

这正是：

```text
LIFO
```

---

## 16. 表达式求值

后缀表达式：

```text
2 1 + 3 *
```

遇到数字：

```text
入栈
```

遇到运算符：

```text
弹出最近两个操作数
计算
结果重新入栈
```

因为运算符操作的是：

> 最近尚未被消费的值。

所以栈非常自然。

---

## 17. 函数调用栈

程序函数调用也天然形成栈结构：

```text
main
 └─ f
     └─ g
         └─ h
```

最晚调用的 `h`：

```text
最先返回
```

符合：

```text
LIFO
```

递归本质上也依赖调用栈。

---

## 18. 单调栈

如果问题需要寻找：

```text
左侧 / 右侧第一个更大元素
左侧 / 右侧第一个更小元素
```

通常可以使用：

```text
单调栈
```

它仍然是栈，但额外维护：

```text
栈中元素单调递增或递减
```

这属于后续更高级的栈应用。

---

# 19. 队列的典型应用

队列适合：

> **按照到达顺序依次处理任务。**

---

## 20. BFS

图和树的广度优先搜索：

```text
先访问离起点 1 步的节点
再访问 2 步
再访问 3 步
```

这天然需要：

```text
先进先出
```

所以 BFS 使用队列。

典型结构：

```cpp
queue<Node*> q;

q.push(start);

while (!q.empty()) {
    auto cur = q.front();
    q.pop();

    for (auto next : neighbors(cur)) {
        q.push(next);
    }
}
```

---

## 21. 层序遍历

二叉树层序遍历：

```text
第 1 层
第 2 层
第 3 层
...
```

也是典型队列应用。

父节点先进入队列：

```text
它的孩子后进入
```

所以父节点总是先被处理。

---

## 22. 任务调度和缓冲区

例如：

```text
请求到达服务器
```

可以先进入：

```text
Queue
```

然后按顺序处理。

实际系统里：

- 消息队列；
- 打印队列；
- 网络缓冲区；
- 生产者消费者模型；

都大量使用队列思想。

---

# 23. 双端队列与普通队列

普通队列限制：

```text
一端入
另一端出
```

双端队列 `deque` 允许：

```text
两端都可以入
两端都可以出
```

所以 deque 的能力更强。

它常用于：

- 单调队列；
- 滑动窗口最大值；
- 双端 BFS；
- 作为 stack / queue 的底层容器。

---

# 24. 优先队列并不是普通 FIFO 队列

C++ 中：

```cpp
priority_queue
```

虽然名字里有 queue，但它的出队规则不是：

```text
最早进入先出
```

而是：

```text
优先级最高的元素先出
```

默认：

```cpp
最大元素优先
```

所以它的逻辑更接近：

> **堆（Heap）**

而不是普通队列。

这一点非常容易混淆。

---

## 25. 三者区别

| 结构 | 谁先出来 | C++ 常见类型 |
| --- | --- | --- |
| 栈 | 最后进入 | `stack` |
| 队列 | 最先进入 | `queue` |
| 优先队列 | 优先级最高 | `priority_queue` |

---

# 26. 为什么算法题经常“用一种结构模拟另一种”

例如：

```text
用栈实现队列
用队列实现栈
```

现实工程里通常不会这么写。

这些题的目标不是让你以后真的这样实现，而是在考：

> **你是否真正理解 LIFO 与 FIFO 的行为差异。**

通过受限接口模拟另一种访问顺序，可以验证你是否理解数据结构本质。

---

# 27. 栈和队列的复杂度

在常见实现下：

| 操作 | Stack | Queue |
| --- | ---: | ---: |
| 插入 | $O(1)$ | $O(1)$ |
| 删除 | $O(1)$ | $O(1)$ |
| 查看可访问端 | $O(1)$ | $O(1)$ |
| 随机访问 | 不支持 | 不支持 |

需要注意：

> `std::stack` / `std::queue` 的复杂度由底层容器对应操作决定。

---

# 28. 为什么不支持随机访问反而是优点

看起来：

```text
不能访问中间元素
```

像是一种限制。

但这种限制有好处。

它使代码语义非常明确：

### 用 Stack

就是在表达：

```text
只关心最近加入的未处理元素
```

### 用 Queue

就是在表达：

```text
严格按照进入顺序处理
```

限制接口可以减少错误使用。

这也是抽象数据类型的重要价值。

```cpp
#include <deque>
using namespace std;

deque<int> dq;

dq.push_back(10);

int first = dq.front();
int last = dq.back();

dq.pop_front();
dq.pop_back();
```

  </Tab>

```cpp
#include <queue>
using namespace std;

priority_queue<int> pq;

pq.push(10);
pq.push(30);
pq.push(20);

int maxValue = pq.top(); // 30
pq.pop();
```

# 30. 如何根据题意判断使用哪一种

可以先看题目的“访问顺序”。

### 需要最近加入的元素

例如：

```text
括号
撤销
表达式
DFS
最近状态
```

考虑：

```text
Stack
```

---

### 需要最早加入的元素

例如：

```text
BFS
层序遍历
任务排队
```

考虑：

```text
Queue
```

---

### 需要两端都操作

例如：

```text
窗口
双端状态
```

考虑：

```text
Deque
```

---

### 每次要最大 / 最小元素

考虑：

```text
Priority Queue / Heap
```

## 32. 本节总结

最基本的两条：

```text
Stack = LIFO
Queue = FIFO
```

更重要的是：

1. C++ 的 `stack` 和 `queue` 属于**容器适配器**。
2. 它们通过限制底层容器接口来表达严格的数据访问规则。
3. 默认底层通常使用 `deque`。
4. Stack 适合“最近未完成”的问题。
5. Queue 适合“按到达顺序处理”的问题。
6. `priority_queue` 的本质是堆，不是普通 FIFO 队列。
7. 学习栈与队列时，重点不是 API，而是理解“访问顺序为什么符合题目过程”。
