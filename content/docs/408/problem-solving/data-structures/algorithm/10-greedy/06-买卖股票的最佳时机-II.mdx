# 122. 买卖股票的最佳时机 II

[LeetCode 122. 买卖股票的最佳时机 II](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-ii/)

给定数组 `prices`，其中 `prices[i]` 表示第 $i$ 天一支股票的价格。你可以进行任意多次买卖，但任意时刻最多只能持有一股股票。求能够获得的最大利润。

例如：

```text
prices = [7, 1, 5, 3, 6, 4]
```

一种最优交易方式是：

```text
第 1 天以 1 买入，第 2 天以 5 卖出，利润 4
第 3 天以 3 买入，第 4 天以 6 卖出，利润 3
```

总利润为：

$$
4+3=7
$$

<Callout type="info" title="题目真正特殊的地方">
本题允许进行任意多次交易，而且没有手续费、冷冻期、交易次数上限等额外限制。正是这些条件，使得一个完整交易区间可以被无损拆成若干个相邻日收益。
</Callout>

## 1. 最容易陷入的思路：寻找谷底和峰顶

直觉上，我们会想：

1. 找一个尽可能低的价格买入；
2. 找后面的高点卖出；
3. 再继续寻找下一组低点和高点。

这种思路并没有错，但它会让问题变成“什么时候才算真正的谷底”“什么时候应该卖出”的判断题。

例如：

```text
[1, 2, 3, 4, 5]
```

到底应该：

```text
1 -> 5
```

还是：

```text
1 -> 2
2 -> 3
3 -> 4
4 -> 5
```

从实际交易动作看，两种方案不同；但从最终利润看，它们完全一样。

这正是本题最关键的突破口：

> **我们不需要真正恢复一套“最漂亮”的买卖方案，只需要计算最大利润。**

## 2. 核心转化：一段利润可以拆成每天的利润

假设第 $a$ 天买入，第 $b$ 天卖出，其中 $a<b$。

这一笔交易的利润是：

$$
prices[b]-prices[a]
$$

在中间插入相邻项：

$$
prices[b]-prices[a]
$$

$$
=\bigl(prices[a+1]-prices[a]\bigr)
+\bigl(prices[a+2]-prices[a+1]\bigr)
+\cdots
+\bigl(prices[b]-prices[b-1]\bigr)
$$

也就是说，一个跨度很多天的交易利润，完全等于这段区间内所有**相邻两天价格差**之和。

令：

$$
\Delta_i=prices[i]-prices[i-1]
$$

那么任意一笔从第 $a$ 天到第 $b$ 天的交易，都可以写成：

$$
prices[b]-prices[a]
=\sum_{i=a+1}^{b}\Delta_i
$$

原问题于是从“选择买卖点”转化成：

> **哪些相邻日收益 $\Delta_i$ 值得加入答案？**

## 3. 为什么只收集正利润就够了

观察任意一天的价格变化：

- 若 $\Delta_i>0$，说明从第 $i-1$ 天持有到第 $i$ 天可以获得正收益；
- 若 $\Delta_i=0$，对利润没有影响；
- 若 $\Delta_i<0$，持有这一段只会损失利润。

因为题目允许我们在需要时卖出，又允许以后重新买入，所以没有任何理由强迫自己跨过一段负收益。

因此最优答案就是：

$$
\boxed{
\text{answer}
=\sum_{i=1}^{n-1}\max\bigl(prices[i]-prices[i-1],0\bigr)
}
$$

这就是本题的贪心策略。

<Callout type="success" title="一句话记忆">
只要今天比昨天贵，就把这段上涨利润收下；只要今天不比昨天贵，就不让这段变化进入答案。
</Callout>

## 4. 一个容易困惑的问题：这真的符合交易规则吗

考虑连续上涨：

```text
[1, 2, 3, 4, 5]
```

贪心会计算：

$$
(2-1)+(3-2)+(4-3)+(5-4)=4
$$

有人会问：

> 这是不是意味着每天都“先卖出再买入”？题目不是说不能同时参与多笔交易吗？

并不冲突。

因为：

$$
(2-1)+(3-2)+(4-3)+(5-4)=5-1
$$

数学上的“逐日收集利润”，只是对最终利润的**分解方式**，并不要求程序真的构造四笔独立持仓。

你完全可以把这段连续上涨解释为：

```text
第 0 天买入
第 4 天卖出
```

结果仍然是 $4$。

<Callout type="warning" title="利润分解 ≠ 必须逐日交易">
贪心代码是在计算等价利润，而不是模拟真实交易日志。理解这一点后，就不会纠结“同一天卖出后是否还能买入”等实现细节。
</Callout>

## 5. 用完整样例走一遍

```text
prices = [7, 1, 5, 3, 6, 4]
```

相邻日差值为：

| 天数变化 | 计算 | 日收益 | 是否收集 |
| --- | ---: | ---: | --- |
| $0\to1$ | $1-7$ | $-6$ | 否 |
| $1\to2$ | $5-1$ | $4$ | 是 |
| $2\to3$ | $3-5$ | $-2$ | 否 |
| $3\to4$ | $6-3$ | $3$ | 是 |
| $4\to5$ | $4-6$ | $-2$ | 否 |

所以：

$$
answer=4+3=7
$$

对应交易区间自然就是：

```text
1 -> 5
3 -> 6
```

## 6. 贪心正确性的两种理解

### 6.1 正收益独立选择

因为任意交易利润都能拆成相邻日差值，所以最终利润只是这些 $\Delta_i$ 的和。

对每个 $\Delta_i$：

- 正数加入，只会让总利润增大；
- 负数加入，只会让总利润减小；
- $0$ 加不加入都一样。

于是每个相邻区间的最优决定互不冲突：

$$
\Delta_i>0 \Rightarrow \text{选择}
$$

$$
\Delta_i\le 0 \Rightarrow \text{舍弃}
$$

所有局部选择叠加后，就是全局最大值。

### 6.2 把连续上涨段压缩成一笔交易

设某段价格严格不下降：

$$
p_a\le p_{a+1}\le\cdots\le p_b
$$

收集这段所有正增量得到：

$$
(p_{a+1}-p_a)+(p_{a+2}-p_{a+1})+\cdots+(p_b-p_{b-1})
$$

中间项全部抵消：

$$
=p_b-p_a
$$

因此贪心收集整个上涨坡，等价于在坡底买入、坡顶卖出。

而不同上涨坡之间夹着下降区间。下降区间不应该持仓，因此每个上涨坡都可以独立贡献最大利润。

这就给出了一个更直观的最优结构：

> **每个连续上涨区间都完整收下，下降区间全部跳过。**

## 7. 贪心代码为什么只需要一行核心逻辑

### 从第二天开始扫描

相邻收益需要比较：

```text
prices[i] - prices[i - 1]
```

所以第一组差值从 $i=1$ 开始。

### 只保留正收益

```cpp
max(prices[i] - prices[i - 1], 0)
```

负收益直接视为 $0$，表示这一段不参与交易。

### 累加所有正收益

```cpp
profit += max(prices[i] - prices[i - 1], 0);
```

扫描结束后就是全局最大利润。

C++ 实现：

```cpp
class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int profit = 0;

        for (int i = 1; i < static_cast<int>(prices.size()); ++i) {
            profit += max(prices[i] - prices[i - 1], 0);
        }

        return profit;
    }
};
```

时间复杂度：

$$
O(n)
$$

额外空间复杂度：

$$
O(1)
$$

## 8. 为什么“找全局最低点，再找最高点”会出错

考虑：

```text
[1, 5, 2, 8]
```

如果只做一次交易：

```text
1 -> 8
```

利润是：

$$
8-1=7
$$

但本题允许多次交易，所以可以：

```text
1 -> 5   利润 4
2 -> 8   利润 6
```

总利润：

$$
4+6=10
$$

因此本题和“最多只能交易一次”的股票问题有本质区别。

<Callout type="info" title="先辨认交易约束">
看到股票题，不要先背代码。首先检查：最多几次交易？有没有手续费？有没有冷冻期？能否同时持有多股？约束一变，贪心结论就可能立即失效。
</Callout>

## 9. 本题为什么可以贪心，而其他股票题往往不行

当前贪心成立依赖几个非常强的条件：

| 条件 | 本题 | 对贪心的作用 |
| --- | --- | --- |
| 交易次数 | 不限 | 可以把上涨区间任意拆分 |
| 手续费 | 无 | 每一段正收益都值得单独收集 |
| 冷冻期 | 无 | 卖出后不会影响之后重新买入 |
| 持仓数 | 最多一股 | 状态简单，收益可按一条价格序列分解 |

例如一旦每次交易要收手续费 $fee$，你就不能简单地把所有正增量都收下。

假设：

```text
[1, 2, 3]
fee = 1
```

逐段交易可能产生多次手续费，而合并成一笔交易只交一次手续费。此时相邻日收益已经不再彼此独立。

所以这道题最值得迁移的思维不是“股票题就把正数加起来”，而是：

> **当一个全局收益可以精确拆成互不冲突的局部收益时，尝试逐个选择所有正贡献。**

## 10. 与动态规划的统一视角

本题也可以用股票问题的经典状态定义：

- $dp[i][0]$：第 $i$ 天结束时持有股票的最大现金；
- $dp[i][1]$：第 $i$ 天结束时不持有股票的最大现金。

状态转移为：

$$
dp[i][0]
=\max\bigl(dp[i-1][0],\ dp[i-1][1]-prices[i]\bigr)
$$

$$
dp[i][1]
=\max\bigl(dp[i-1][1],\ dp[i-1][0]+prices[i]\bigr)
$$

初始化：

$$
dp[0][0]=-prices[0],\qquad dp[0][1]=0
$$

最终答案是：

$$
dp[n-1][1]
$$

因为最后一天如果仍持有股票，这一股还没有兑现成最终利润。

### 为什么贪心和 DP 会得到同一个结果

动态规划保留“持有 / 不持有”两个状态，逐日比较买卖行为；贪心则利用本题的特殊结构，进一步把状态压缩成：

```text
今天涨了 -> 收下涨幅
今天没涨 -> 不收
```

所以可以把二者理解为：

> DP 是通用状态模型；贪心是利用无限交易、无额外成本这一特殊条件后的进一步化简。

## 11. 如果题目要求恢复交易区间怎么办

虽然求最大利润时不需要记录买卖点，但也可以从价格走势恢复一组最简交易方案。

思路是：

1. 找到一段上涨趋势的起点，作为买入日；
2. 一直走到上涨趋势结束；
3. 在该段最高点卖出；
4. 继续寻找下一段上涨趋势。

例如：

```text
[7, 1, 5, 3, 6, 4]
```

得到：

```text
买 1 -> 卖 5
买 3 -> 卖 6
```

而对：

```text
[1, 2, 3, 4, 5]
```

最简方案是：

```text
买 1 -> 卖 5
```

虽然贪心计算过程把利润拆成 $4$ 个相邻增量，但它们可以重新合并成一个上涨区间。

## 12. 常见错误

### 错误 1：只允许一笔交易

如果使用“记录历史最低价，计算当前最大差值”的写法，求的是最多一次交易的版本，不是本题。

### 错误 2：所有差值都累加

例如：

```text
[5, 1, 6]
```

若把所有差值都相加：

$$
(1-5)+(6-1)=1
$$

但正确答案显然是：

$$
6-1=5
$$

下降段应该直接舍弃。

### 错误 3：认为必须精确找局部最低点和局部最高点

找峰谷可以做，但不是计算答案所必需的。只累加正增量更短、更稳定，也更能体现问题本质。

### 错误 4：忽略约束变化

“所有正差值相加”只适用于当前这个无限交易、无手续费、无冷冻期的模型，不能无条件迁移到整个股票系列。

## 13. 这一题真正训练的贪心思维

这道题的价值在于一个非常重要的转化：

> **不要总从原问题给出的“大动作”出发，可以尝试把总收益拆成最小粒度的局部贡献。**

原问题描述的是：

```text
一次买入 -> 若干天后卖出
```

但利润可以改写为：

```text
每天相邻价格差的总和
```

一旦拆开以后，每个局部增量只有三种情况：

```text
正贡献 -> 要
零贡献 -> 无所谓
负贡献 -> 不要
```

于是原本看起来需要寻找买卖时机的问题，变成了一次线性扫描。

这类技巧在很多问题中都很重要：

- 把区间收益拆成相邻差分；
- 把总成本拆成单步增量；
- 把全局目标写成若干局部贡献之和；
- 判断这些局部贡献是否能够彼此独立选择。

如果可以，就很可能存在简单贪心。

## 14. 其他语言版本

下面均采用“累加所有正相邻差值”的 $O(n)$ 贪心实现。

### Java

```java
class Solution {
    public int maxProfit(int[] prices) {
        int profit = 0;

        for (int i = 1; i < prices.length; i++) {
            profit += Math.max(prices[i] - prices[i - 1], 0);
        }

        return profit;
    }
}
```


```go
func maxProfit(prices []int) int {
    profit := 0

    for i := 1; i < len(prices); i++ {

            profit += diff
        }
    }

    return profit
}
```
