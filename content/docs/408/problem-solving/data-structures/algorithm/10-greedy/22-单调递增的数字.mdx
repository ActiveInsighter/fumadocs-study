# 738. 单调递增的数字

[LeetCode 738. Monotone Increasing Digits](https://leetcode.cn/problems/monotone-increasing-digits/)

给定一个非负整数 $n$，要求找到满足下面两个条件的**最大整数** $x$：

1. $x\le n$；
2. $x$ 的十进制各位数字单调不减。

若：

$$
x=d_0d_1\cdots d_{m-1}
$$

那么所谓单调递增，实际要求的是：

$$
d_0\le d_1\le\cdots\le d_{m-1}
$$

例如：

```text
输入：10
输出：9

输入：1234
输出：1234

输入：332
输出：299
```

这里最值得研究的是：

```text
332 -> 299
```

为什么不是 `329`？为什么不是 `288`？为什么一定要从右往左处理？

这几个问题正是本题贪心策略的核心。

---

## 1. 暴力为什么不是正确方向

最直接的想法是从 $n$ 开始不断减一：

```text
n, n - 1, n - 2, ...
```

直到找到第一个各位数字单调不减的数。

单次检查一个整数需要扫描它的十进制位。若数字位数为 $m$，单次检查复杂度为：

$$
O(m)
$$

最坏情况下可能检查接近 $n$ 个数，因此总复杂度大致为：

$$
O(nm)
$$

题目给出的 $n$ 可以达到 $10^9$，这种方法没有利用十进制数字结构。

真正需要解决的问题不是：

> “一个数是不是单调递增？”

而是：

> **一旦某两位破坏了单调性，怎样一次修改就跳过一大批不可能成为答案的数字？**

这才是贪心切入点。

---

## 2. 从最简单的两位数开始

先看：

```text
98
```

因为：

$$
9>8
$$

所以 `98` 本身不合法。

想构造一个小于 `98` 的最大合法整数。

如果十位仍然保持 `9`，那么个位必须满足：

$$
9\le d_1
$$

但个位最大也只能是 $9$，而 `99 > 98`，所以不可能继续保留十位的 `9`。

因此十位必须减一：

```text
9 -> 8
```

一旦高位已经变小，后面的低位就应该尽可能大。

十进制单个数字最大是 $9$，于是得到：

```text
89
```

因此最基本的局部操作是：

> 当发现 $d_{i-1}>d_i$ 时，把 $d_{i-1}$ 减一，并把从 $i$ 开始的后缀最终全部设成 $9$。

可以写成：

$$
d_{i-1}\leftarrow d_{i-1}-1
$$

以及：

$$
d_i,d_{i+1},\ldots,d_{m-1}\leftarrow 9
$$

<Callout type="info" title="为什么后缀一定取 9？">
一旦某个更高位已经被减小，整个整数就已经严格小于原数。在此前提下，想让结果尽可能大，后面的每一位自然都应该取允许的最大值 $9$。
</Callout>

---

## 3. 真正的难点：一次减一可能引发连锁反应

如果只有 `98`，问题很简单。

但看：

```text
332
```

从左向右观察，第一次发现：

```text
3 > 2
```

如果只处理后两位，可能得到：

```text
329
```

但此时：

```text
3 > 2
```

前两位又不满足单调不减。

这说明：

> **修改右侧高位后，可能破坏它和更左边数字之间的关系。**

`332` 的正确变化过程是：

```text
332
 ↓
329
 ↓
299
```

也就是：

1. 最右侧出现下降：`3 > 2`，把中间的 `3` 减成 `2`；
2. 此时前两位变成 `3 > 2`，继续向左修复；
3. 第一位从 `3` 减为 `2`；
4. 从第一次需要放弃的后缀开始全部填 `9`。

最终：

```text
299
```

因此遍历方向已经呼之欲出。

---

## 4. 为什么必须从右向左扫描

设数字字符串为：

```text
d0 d1 d2 ... d(m-1)
```

我们需要检查所有相邻关系：

$$
d_{i-1}\le d_i
$$

如果从右向左扫描，那么当发现：

$$
d_{i-1}>d_i
$$

并执行：

$$
d_{i-1}\leftarrow d_{i-1}-1
$$

下一轮循环恰好会检查：

$$
d_{i-2}\le d_{i-1}
$$

也就是说，**减一造成的连锁影响会自然地继续向左传播**。

这与 `332` 完全一致：

```text
索引： 0 1 2
数字： 3 3 2
          ↑
先检查 1 和 2

3 3 2
  ↓
3 2 2

下一轮自然检查 0 和 1：

3 2 2
↓
2 2 2
```

真正输出时，并不是 `222`，而是把受影响后缀尽可能增大：

```text
299
```

### 如果从左向右会怎样

问题在于修改位置位于当前索引的左侧：

```text
d[i - 1]--
```

而左向右扫描已经“经过”了更左边的比较位置。

修改后如果产生新的下降，就需要回头重新检查，逻辑会明显复杂。

所以本题的关键不是简单的：

> “倒序写起来方便。”

而是：

> **状态影响方向向左，因此扫描方向也应该从右向左，让每次修改产生的新问题恰好由下一次循环处理。**

---

## 5. 为什么不能发现下降就立刻把当前位改成 9

一种常见写法是：

```text
发现 d[i - 1] > d[i]
→ d[i - 1]--
→ d[i] = 9
```

但仅修改当前位仍然不够。

例如：

```text
1234543
```

一旦某个更高位被减小，从那个位置之后的所有低位都应该尽可能大。

如果只改局部一位，会留下不必要的小数字。

因此最稳妥的做法是记录一个边界 `flag`：

```text
flag = 从哪里开始最终全部填 9
```

每次发现下降：

```cpp
flag = i;
digits[i - 1]--;
```

全部逆向扫描结束后统一执行：

```cpp
for (int i = flag; i < digits.size(); ++i) {
    digits[i] = '9';
}
```

这样把“处理连锁下降”和“最大化后缀”拆成两个清晰阶段。

---

## 6. `flag` 到底表示什么

初始时：

```cpp
flag = digits.size();
```

表示暂时不存在需要改成 `9` 的后缀。

只要发现：

$$
d_{i-1}>d_i
$$

就说明：

> 从位置 $i$ 开始，原来的后缀已经不值得保留。

于是：

```cpp
flag = i;
```

继续向左扫描时，可能出现新的下降，`flag` 还会进一步左移。

例如：

```text
332
```

过程如下：

| 当前比较 | 修改前 | 操作 | `flag` |
| --- | --- | --- | ---: |
| $d_1>d_2$ | `332` | $d_1:3\to2$ | 2 |
| $d_0>d_1$ | `322` | $d_0:3\to2$ | 1 |

逆向扫描结束后：

```text
222
```

但 `flag = 1`，所以索引 $1$ 之后全部改成 `9`：

```text
299
```

<Callout type="info" title="flag 的本质">
`flag` 不是“最后一次修改的位置”，而是最终答案中**最大化后缀的起点**。它不断左移，直到所有可能的连锁下降都被消除。
</Callout>

### 从右向左检查相邻数字

对：

$$

$$

若成立，说明当前位置破坏单调性。

执行：

## 9. 正确性：为什么“减一 + 后缀全 9”一定最优

本题需要同时证明两件事：

1. 结果合法；
2. 所有合法且不超过 $n$ 的整数中，它最大。

### 9.1 为什么必须降低某个高位

假设在位置 $i$ 出现：

$$
d_{i-1}>d_i
$$

如果我们坚持保留前缀直到 $d_{i-1}$ 都不变，那么为了满足单调性，后面一位至少需要：

$$
d_i'\ge d_{i-1}
$$

但原数字该位是 $d_i<d_{i-1}$。

若把这一位抬高到 $d_{i-1}$ 或更大，在前面所有位完全相同的情况下，整个新数字会超过原数 $n$。

所以：

> 在某次下降无法通过原后缀修复时，必须让某个更高位变小。

为了尽量大，最优选择当然是：

$$
d_{i-1}\leftarrow d_{i-1}-1
$$

而不是减二、减三。

### 9.2 为什么后缀必须全部取 9

一旦某个高位已经严格小于原数字，对后缀而言，“不超过 $n$”的限制已经自动满足。

此时目标只剩：

> 尽可能增大整个结果。

十进制每一位最大为 $9$，所以后缀最优显然是：

$$
99\cdots9
$$

### 9.3 为什么逆序扫描能保证最终单调

若修改：

$$
d_{i-1}\leftarrow d_{i-1}-1
$$

唯一可能新破坏的关系是：

$$
d_{i-2}\le d_{i-1}
$$

而从右向左扫描时，下一步正好就会检查这一对。

因此所有“向左传播”的冲突都会被逐层消掉。

扫描结束后，`flag` 左侧已经满足单调性；`flag` 右侧全部为 $9$，自然也满足：

$$
d_{flag-1}\le9
$$

因此最终整体合法。

于是得到：

$$
\boxed{\text{结果既合法，又是在所有不超过 }n\text{ 的合法整数中最大的}}
$$

## 10. 一个更抽象的理解：高位优先

十进制整数的大小比较，本质上是字典序比较。

例如：

```text
299
```

一定大于：

```text
288
```

因为从最高位开始，第一个不同的位置：

```text
9 > 8
```

后面更低位已经不重要。

因此本题的目标可以理解为：

> 在满足单调约束且不超过原数的前提下，让高位尽可能保持原值；一旦某个高位不得不降低，就只降低最少的 1，然后把低位全部拉到最大。

这也是为什么贪心策略如此自然。

局部目标是：

$$
\boxed{\text{高位尽量不变；必须变时只减 1}}
$$

后缀目标是：

$$
\boxed{\text{一旦高位已变小，低位全部取最大值 9}}
$$

两个局部原则合在一起，就是全局最大值。

## 11. C++ 推荐实现

```cpp
class Solution {
public:
    int monotoneIncreasingDigits(int n) {
        string digits = to_string(n);
        int flag = digits.size();

        for (int i = digits.size() - 1; i > 0; --i) {
            if (digits[i - 1] > digits[i]) {
                --digits[i - 1];
                flag = i;
            }
        }

        for (int i = flag; i < digits.size(); ++i) {
            digits[i] = '9';
        }

        return stoi(digits);
    }
};
```

这段代码最重要的三行是：

```cpp
if (digits[i - 1] > digits[i]) {
    --digits[i - 1];
    flag = i;
}
```

以及最后：

```cpp
for (int i = flag; i < digits.size(); ++i) {
    digits[i] = '9';
}
```

不要把它们记成模板，要理解：

```text
发现下降
   ↓
高位必须让步
   ↓
只减 1
   ↓
后缀已经失去保留价值
   ↓
最终全部填 9
```

## 12. 复杂度分析

设十进制数字长度为 $m$。

第一次从右向左扫描一次：

$$
O(m)
$$

第二次把后缀写成 `9`，最多再扫描一次：

$$
O(m)
$$

因此总时间复杂度：

$$
O(m)
$$

由于：

$$
m=\lfloor\log_{10}n\rfloor+1
$$

也可以写成：

$$
O(\log n)
$$

字符串需要保存 $m$ 位数字，所以额外空间复杂度为：

$$
O(m)
$$

如果只讨论题目上限，$m$ 很小；但从算法分析角度仍应按输入位数记为 $O(m)$。

## 13. 常见错误

### 错误一：从左向右扫描后不回退

例如：

```text
332
```

得到：

```text
329
```

却没有发现前面又出现：

```text
3 > 2
```

根因是修改会向左传播。

### 错误二：只把一个位置改成 9

只做：

```text
d[i] = 9
```

不能保证后面所有位达到最大。

正确逻辑是：

```text
从 flag 开始全部改成 9
```

### 错误三：高位直接减很多

例如 `98` 若从 `9` 直接降到 `7`，得到 `79`，虽然合法，但显然不是最大。

所以被迫降低时只应：

$$
-1
$$

### 错误四：把“单调递增”误解成严格递增

本题允许相等：

$$
d_i\le d_{i+1}
$$

所以：

```text
112233
```

是合法的。

### 错误五：担心 `1000 -> 0999`

字符串中确实可能暂时产生前导 `0`：

```text
0999
```

但转回整数就是：

```text
999
```

不影响答案。

## 14. 与其他贪心题的联系

这道题虽然没有排序、区间或资源分配，但依然是典型贪心。

它体现的是另一类非常重要的策略：

> **高位优先 + 发生冲突时最小幅度退让 + 后缀最大化。**

这类思路常出现在：

- 构造最大/最小整数；
- 字典序最优；
- 删除若干位数字；
- 数位约束；
- 单调栈式数字构造。

与前面的区间贪心不同，这里维护的不是几何边界，而是：

```text
还能保留多长的最优前缀
```

一旦前缀的某一位必须让步，后缀就转而追求局部最大。

## 15. 一页记忆

<Callout type="info" title="核心结论">
遇到 $d_{i-1}>d_i$：让左边数字减一；因为修改可能继续破坏更左侧关系，所以必须从右向左扫描；一旦某个高位已经减小，后面的数字全部设成 $9$ 才能使结果最大。
</Callout>

```text
目标：
<= n 的最大单调不减整数

扫描：
从右向左

冲突：
digits[i - 1] > digits[i]

处理：
digits[i - 1]--
flag = i

结束：
digits[flag ... end] = 9
```

最终可压缩为：

$$
\boxed{\text{逆序找下降，左位减一，后缀填 9}}
$$

## 16. 其他语言版本

下面都采用同一套“逆序扫描 + `flag` 标记后缀”的实现。

<Tabs items={['Java', 'Python', 'Go', 'Rust', 'JavaScript', 'TypeScript', 'C', 'C#']}>
<Tab value="Java">

```java
class Solution {
    public int monotoneIncreasingDigits(int n) {
        char[] digits = String.valueOf(n).toCharArray();
        int flag = digits.length;

        for (int i = digits.length - 1; i > 0; --i) {
            if (digits[i - 1] > digits[i]) {
                digits[i - 1]--;
                flag = i;
            }
        }

        for (int i = flag; i < digits.length; ++i) {
            digits[i] = '9';
        }

        return Integer.parseInt(new String(digits));
    }
}
```

```python
class Solution:
    def monotoneIncreasingDigits(self, n: int) -> int:
        digits = list(str(n))
        flag = len(digits)

        for i in range(len(digits) - 1, 0, -1):
            if digits[i - 1] > digits[i]:
                digits[i - 1] = str(int(digits[i - 1]) - 1)
                flag = i

        for i in range(flag, len(digits)):
            digits[i] = '9'

        return int(''.join(digits))
```

```go
import "strconv"

func monotoneIncreasingDigits(n int) int {
    digits := []byte(strconv.Itoa(n))
    flag := len(digits)

    for i := len(digits) - 1; i > 0; i-- {
        if digits[i-1] > digits[i] {
            digits[i-1]--
            flag = i
        }
    }

    for i := flag; i < len(digits); i++ {
        digits[i] = '9'
    }

    ans, _ := strconv.Atoi(string(digits))
    return ans
}
```

```rust
impl Solution {
    pub fn monotone_increasing_digits(n: i32) -> i32 {
        let mut digits = n.to_string().into_bytes();
        let mut flag = digits.len();

        for i in (1..digits.len()).rev() {
            if digits[i - 1] > digits[i] {
                digits[i - 1] -= 1;
                flag = i;
            }
        }

        for digit in digits.iter_mut().skip(flag) {
            *digit = b'9';
        }

        digits
            .into_iter()
            .fold(0, |ans, d| ans * 10 + (d - b'0') as i32)
    }
}
```
