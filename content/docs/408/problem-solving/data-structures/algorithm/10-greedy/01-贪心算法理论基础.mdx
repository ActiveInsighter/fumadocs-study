# 贪心算法理论基础

贪心算法（Greedy Algorithm）是一类**在每个决策阶段都选择当前看来最优方案，并希望这些局部最优选择最终构成全局最优解**的算法思想。

它往往没有像二叉树遍历、回溯搜索那样固定的代码模板。真正困难的地方不是“怎么写代码”，而是判断：

> **当前这个局部最优选择，为什么不会破坏未来获得全局最优解的可能性？**

下面先给出整个贪心专题的知识结构。

![贪心算法大纲](https://file1.kamacoder.com/i/algo/20210917104315.png)

<Callout type="info" title="核心结论">
贪心算法的关键不是“每次取最大”或“每次取最小”，而是设计一种**不会后悔的局部选择规则**。只要能够证明按照这个规则做出的选择始终可以出现在某个最优解中，就有机会使用贪心。
</Callout>

## 1. 什么是“局部最优推出全局最优”

设一个问题需要连续做 $n$ 次决策，第 $i$ 次决策选择动作 $a_i$，最终得到解：

$$
S=(a_1,a_2,\ldots,a_n)
$$

贪心算法不会枚举所有可能的 $S$，而是在第 $i$ 步只根据当前状态选择一个“最优”的 $a_i$：

$$
a_i=\operatorname*{arg\,best}_{a\in C_i} f_i(a)
$$

其中：

- $C_i$：当前阶段所有可行选择；
- $f_i(a)$：衡量当前选择优劣的局部评价函数；
- `best` 可能表示最大、最小、最早、最晚、最短、最远等不同含义。

例如从若干张钞票中固定拿 $10$ 张，目标是让总金额最大。此时每一步都拿当前面额最大的钞票，不会影响之后继续拿剩余最大面额，因此“每次拿最大”能够得到全局最大金额。

但这并不意味着“看见最大值就拿”就是贪心的通用套路。

例如 **0-1 背包** 中，一个物品要么完整选择、要么完全不选。若简单地每次选择价值最大的物品或单位重量价值最高的物品，都可能错过真正的最优组合。这类问题通常需要动态规划来同时保留多个可能状态。

## 2. 贪心为什么有时正确、有时错误

从理论上看，一个问题适合使用贪心，通常意味着它具有下面两个重要性质。

### 2.1 贪心选择性质

**存在一个全局最优解，其中包含当前按照贪心规则做出的选择。**

这句话非常重要。

贪心不是要求“当前选择看起来最好”就结束，而是要说明：即使真正的最优解原本没有这样选，也可以经过某种交换、替换或调整，把它变成包含当前贪心选择的另一个最优解，而且目标值不会变差。

这就是许多贪心证明中常见的**交换论证**。

### 2.2 最优子结构

做出当前选择后，剩余问题仍然可以看成一个规模更小的同类最优化问题。

如果原问题的最优解可以写成：

$$
\text{当前选择}+\text{剩余子问题的最优解}
$$

那么我们就可以不断重复同样的贪心过程。

<Callout type="warn" title="不要把“最优子结构”当成贪心的充分条件">
动态规划同样经常具有最优子结构。真正区分贪心和动态规划的关键在于：贪心会尽早做出一个不可撤销的选择，而动态规划会同时保留多个状态，等待后续信息再决定哪个状态真正最优。
</Callout>

## 3. 贪心与动态规划到底有什么区别

两者都经常解决“最优值”问题，但思考方式完全不同。

| 对比项 | 贪心 | 动态规划 |
| --- | --- | --- |
| 决策方式 | 当前直接选择一个最优方案 | 同时保留多个可能状态 |
| 是否回头 | 通常不回退、不修改已经完成的选择 | 可以通过状态转移间接比较不同历史方案 |
| 核心难点 | 找到并证明贪心策略 | 设计状态、状态转移与初始化 |
| 常见复杂度 | 通常较低，常见为 $O(n)$ 或 $O(n\log n)$ | 常见为 $O(n^2)$、$O(nm)$ 等 |
| 典型问题 | 区间调度、跳跃游戏、部分股票问题 | 背包、编辑距离、最长公共子序列 |

可以把二者理解成：

- **贪心：现在就决定，而且以后不后悔。**
- **动态规划：先把有希望的方案都记下来，之后再比较。**

所以判断一道题能不能贪心，本质上是在判断：

> **有没有足够强的结构，使我们现在就能安全地排除其他选择？**

## 4. 做题时如何发现贪心策略

贪心没有一个看到题目就能机械套用的公式，但可以建立一套非常实用的分析流程。

<Steps>
<Step>

### 第一步：先明确“全局目标”

先不要急着写代码，要明确最终到底在优化什么，例如：

- 最大收益；
- 最少操作次数；
- 最多选择多少个对象；
- 最小总距离；
- 最少需要多少资源。

如果连全局目标都没有准确抽象出来，就很难设计局部策略。

</Step>

<Step>

### 第二步：寻找可能的局部最优规则

常见候选规则包括：

- 每次选择最小/最大值；
- 每次选择最早结束的区间；
- 每次尽可能扩大当前覆盖范围；
- 每次优先处理约束最强的对象；
- 每次让当前代价最小；
- 排序后按照某个维度逐个处理。

注意：这些只是**候选策略**，不是正确性的证明。

</Step>

<Step>

### 第三步：主动寻找反例

不要只找能证明自己策略“看起来对”的样例，而要刻意构造让它失败的数据。

可以尝试：

- 极端大值与极端小值；
- 相同元素大量出现；
- 局部最优与长期收益发生冲突；
- 排序维度改变后出现不同结果；
- 边界规模，如 $n=1$、$n=2$。

如果很容易找到反例，说明贪心策略有问题；如果反复构造仍找不到反例，再尝试证明它。

</Step>

<Step>

### 第四步：证明“这一步不会后悔”

常用方法是交换论证或反证法：证明任意最优解都可以调整成采用当前贪心选择的最优解。

一旦这一步成立，再把问题缩小到剩余部分继续处理。

</Step>
</Steps>

## 5. 最实用的正确性证明：交换论证

交换论证是算法题中非常常见的贪心证明方式。

假设：

- 贪心算法第一步选择 $g$；
- 某个最优解第一步选择 $o$；
- $g\neq o$。

我们尝试把最优解中的 $o$ 替换成 $g$。

如果替换后：

1. 解仍然合法；
2. 目标值不会更差；

那么就得到一个**同样最优、但第一步与贪心算法一致**的解。

接下来把第一步固定，继续对剩余问题重复这个过程，就可以逐步说明贪心算法得到的整个解都是最优的。

可以把证明结构记成：

$$
\text{任意最优解}
\xrightarrow{\text{交换}}
\text{包含贪心选择的最优解}
\xrightarrow{\text{缩小问题}}
\text{继续贪心}
$$

### 一个典型直觉：区间调度

若目标是在一条时间轴上选择尽可能多的互不重叠区间，一个经典贪心策略是：**每次选择结束时间最早的区间**。

为什么不是“持续时间最短”或“开始时间最早”？

因为结束得越早，就越能给后续区间留下空间。即使某个最优解第一项不是结束最早的区间，也可以把它替换成结束最早的区间；由于新选择只会更早结束，不会减少后面能够安排的区间数量。

这里的“替换后不会更差”，就是贪心正确性的核心。

## 6. 反例为什么如此重要

很多错误贪心策略在普通样例上都能得到正确结果，因此“手算几个例子没错”并不能证明算法正确。

例如找零钱时，硬币面额为：

$$
\{1,3,4\}
$$

现在要凑出金额 $6$。

如果每次选择不超过剩余金额的最大硬币：

$$
6\rightarrow4\rightarrow1\rightarrow1
$$

需要 $3$ 枚硬币。

但最优方案是：

$$
6\rightarrow3\rightarrow3
$$

只需要 $2$ 枚硬币。

因此，“每次拿最大硬币”并不是任意硬币系统下都成立的贪心策略。

<Callout type="error" title="一个非常重要的习惯">
设计出贪心策略后，第一反应不要是“怎么实现”，而应该是“怎样把它构造死”。如果你能快速找到反例，就及时换思路；如果始终找不到，再进入证明阶段。
</Callout>

## 7. 排序为什么经常和贪心一起出现

很多贪心问题的代码结构都类似：

$$
\text{排序} + \text{一次线性扫描}
$$

原因是原问题中的候选对象往往没有天然决策顺序，而排序可以人为建立一种顺序，使“当前最优选择”变得容易判断。

例如：

- 按右端点排序：常用于区间选择；
- 按左端点排序：常用于区间合并；
- 按身高、位置等多关键字排序：常用于重建类问题；
- 按绝对值排序：可能用于优先处理贡献最大的元素。

若排序复杂度为 $O(n\log n)$，扫描复杂度为 $O(n)$，则整体复杂度通常为：

$$
O(n\log n)+O(n)=O(n\log n)
$$

所以做贪心题时，一旦你发现“应该优先处理某一类元素”，就应该立即思考：**能否通过排序把这种优先级显式化？**

## 8. 常见误区

### 误区一：局部最优看起来合理，所以一定正确

错误。局部最优只是候选策略，必须通过反例检验或正确性证明。

### 误区二：贪心就是每次选最大或最小

错误。真正的贪心规则可能是：最早结束、最远覆盖、最小损失、最大边际收益等。

### 误区三：只要能排序，就是贪心

错误。排序只是建立处理顺序，排序后仍可能需要动态规划、双指针或其他算法。

### 误区四：能用贪心就一定不能用动态规划

错误。有些问题两者都能做，只是贪心利用了更强的结构，因此状态更少、复杂度更低。

### 误区五：通过测试用例就说明证明不重要

工程刷题时可以先实现再验证，但如果想稳定掌握贪心，就必须逐渐形成“交换后为什么不会变差”的证明意识。这样遇到变形题时才不会只靠感觉猜策略。

## 9. 一套更适合刷题的贪心思维框架

把整套流程压缩成下面五个问题：

1. **全局目标是什么？**
2. **如果现在只能做一次决定，我会优先选谁？**
3. **这个选择会不会堵死未来更好的方案？**
4. **能不能构造反例把这个策略推翻？**
5. **能不能用交换论证说明“换成我的选择也不会更差”？**

如果第 4 步找不到反例，并且第 5 步能够讲清楚，贪心策略通常就比较可靠。

<Callout type="success" title="学习建议">
贪心题真正应该积累的不是一段万能代码，而是“局部最优规则”的类型和证明方式。后续做题时，建议给每道题额外记录两句话：**局部最优是什么？为什么它能推出全局最优？**
</Callout>

## 10. 通用实现骨架

贪心算法没有真正统一的代码模板，下面的代码只展示最常见的结构：**排序建立决策顺序，然后在线性扫描中不断接受当前安全的局部最优选择**。



### C++


```cpp
#include <algorithm>
#include <vector>
using namespace std;

int greedy(vector<int>& nums) {
    // 1. 根据贪心规则建立处理顺序
    sort(nums.begin(), nums.end());

    int answer = 0;

    // 2. 逐个考察候选对象
    for (int x : nums) {
        // 3. 判断当前选择是否满足贪心条件
        if (/* x 可以被安全选择 */) {
            // 4. 接受当前局部最优选择，并更新状态
            ++answer;
        }
    }

    return answer;
}
```
