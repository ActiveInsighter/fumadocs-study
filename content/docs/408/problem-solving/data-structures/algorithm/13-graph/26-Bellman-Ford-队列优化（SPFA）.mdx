# Bellman-Ford 队列优化（SPFA）

> **卡码网 94. 城市间货物运输 I**
>
> 有向带权图中允许负权边，但保证不存在负权回路。求城市 $1$ 到城市 $n$ 的最低运输成本；不可达输出 `unconnected`。

[题目链接（ACM 模式）](https://kamacoder.com/problempage.php?pid=1152)

标准 Bellman-Ford 的核心是反复扫描全部边：

$$
dist[v]=\min(dist[v],dist[u]+w)
$$

它正确，但会做大量无效工作。队列优化的出发点是：

> **只有某个顶点的最短距离刚刚变小，它的出边才有必要重新检查。**

这就是 Bellman-Ford 的队列优化版本，中文资料中常称 **SPFA**。

<Callout type="info" title="先记住本质">

SPFA 没有更换松弛公式，只更换了“哪些边现在值得被松弛”的调度方式。

- 标准 Bellman-Ford：周期性扫描全部边；
- SPFA：只处理距离刚发生变化的顶点的出边。

</Callout>

---

## 1. 为什么全边扫描会浪费

原资料中的初始状态：

![Bellman-Ford 初始状态](https://file1.kamacoder.com/i/algo/20240328104119.png)

源点为 `1`：

$$
dist[1]=0
$$

其余点：

$$
dist[v]=+\infty
$$

此时真正可能成功松弛的，只能是从 `1` 出发的边。像 `4 -> 6`、`5 -> 3` 之类的边，连起点都尚不可达，扫描它们没有意义。

于是可以把“距离刚更新、但变化还没有向外传播”的顶点保存起来。

---

## 2. 队列中的顶点表示什么

若边 $u\rightarrow v$ 权值为 $w$，且：

$$
dist[u]+w<dist[v]
$$

就更新：

$$
dist[v]=dist[u]+w
$$

此时 `v` 的出边可能继续产生新的松弛，所以把 `v` 放入队列。

因此队列中的点表示：

> **这个点刚获得了更优距离，新的信息还没有沿它的出边传播。**

这也是为什么 SPFA 常用邻接表：出队一个点后，只访问它自己的出边。

## 3. 初始化

```cpp
vector<long long> dist(n + 1, INF);
vector<bool> inQueue(n + 1, false);

dist[1] = 0;
q.push(1);
inQueue[1] = true;
```

## 4. 从源点开始传播

从 `1` 出发有：

```text
1 -> 2，权值 1
1 -> 3，权值 5
```

所以：

$$
dist[2]=1,
\qquad
dist[3]=5
$$

两个点都获得了更优距离，因此入队：

![节点 2 和 3 入队](https://file1.kamacoder.com/i/algo/20240411115544.png)

队列变成：

```text
2, 3
```

## 5. 处理节点 2

从 `2` 出发：

```text
2 -> 5，权值 2
2 -> 4，权值 -3
```

于是：

$$
dist[5]=1+2=3
$$

$$
dist[4]=1-3=-2
$$

更新后的两个点继续入队：

![处理节点 2 后的状态](https://file1.kamacoder.com/i/algo/20240412110348.png)

注意，负权边完全可以正常松弛；SPFA 和 Bellman-Ford 一样允许负权边。

## 6. 没有出边的点会自然结束

节点 `3` 当前没有出边，因此出队后什么也不做：

![节点 3 无出边](https://file1.kamacoder.com/i/algo/20240412110420.png)

这体现出队列优化的价值：没有新的信息，就不做无意义的全图扫描。

---

## 7. 节点 4 更新终点

`4 -> 6` 的权值为 $4$：

$$
dist[6]=-2+4=2
$$

因此 `6` 入队：

![节点 4 更新节点 6](https://file1.kamacoder.com/i/algo/20240412110445.png)

但此时的 `dist[6]=2` 还不是“永久确定值”。未来如果发现更短路径，`6` 仍然可以再次被更新。

---

## 8. 为什么要用 inQueue 去重

继续处理 `5`：

```text
5 -> 3，权值 1
5 -> 6，权值 -2
```

得到：

$$
dist[3]=\min(5,3+1)=4
$$

$$
dist[6]=\min(2,3-2)=1
$$

原资料示意：

![节点 5 更新节点 3 与 6](https://file1.kamacoder.com/i/algo/20240729161116.png)

此时 `6` 已经在队列中等待处理，所以不需要再放一个 `6` 进去。因为它真正出队时，会读取数组中最新的：

```cpp
dist[6]
```

因此入队逻辑应写成：

```cpp
if (!inQueue[v]) {
    q.push(v);
    inQueue[v] = true;
}
```

出队后则必须：

```cpp
inQueue[u] = false;
```

否则以后即使 `u` 再次变短，也无法重新进入队列。

---

## 9. 队列为什么最终会清空

最终 `6`、`3` 出队后，如果再也没有任何成功松弛，就不会产生新的入队：

![所有有效松弛完成](https://file1.kamacoder.com/i/algo/20240411115424.png)

算法结束的真正原因是：

> **所有最短距离都已经稳定，没有新的“变化”需要传播。**

在题目保证不存在源点可达负权回路时，这一过程一定会停止。

## 10. 标准 C++ 模板

```cpp
#include <bits/stdc++.h>
using namespace std;

struct Edge {
    int to;
    long long weight;
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;

    vector<vector<Edge>> graph(n + 1);
    for (int i = 0; i < m; ++i) {
        int u, v;
        long long w;
        cin >> u >> v >> w;
        graph[u].push_back({v, w});
    }

    const long long INF = numeric_limits<long long>::max() / 4;
    vector<long long> dist(n + 1, INF);
    vector<bool> inQueue(n + 1, false);
    queue<int> q;

    dist[1] = 0;
    q.push(1);
    inQueue[1] = true;

    while (!q.empty()) {
        int u = q.front();
        q.pop();
        inQueue[u] = false;

        for (const auto& e : graph[u]) {
            int v = e.to;
            long long candidate = dist[u] + e.weight;

            if (candidate < dist[v]) {
                dist[v] = candidate;

                if (!inQueue[v]) {
                    q.push(v);
                    inQueue[v] = true;
                }
            }
        }
    }

    if (dist[n] == INF) cout << "unconnected\n";
    else cout << dist[n] << '\n';
}
```

因为能够进入队列的顶点一定曾从源点可达，所以扫描其出边时，`dist[u]` 不会是 `INF`。

---

## 11. 正确性为什么成立

假设某条边 $u\rightarrow v$ 未来能够让 `dist[v]` 变短，那么前提必然是 `dist[u]` 获得了一个更优值。

只要 `dist[u]` 被更新，`u` 就会进入队列；当它出队时，会扫描所有出边，其中自然包括 $u\rightarrow v$。

所以队列优化不会漏掉真正有机会产生新答案的松弛。

换句话说：

$$
\text{dist[u] 变化}
\Rightarrow
\text{u 的出边值得重查}
$$

而没有变化的点，其出边立即重查通常没有价值。

---

## 12. 它不是普通 BFS

<Callout type="warning" title="队列 ≠ BFS">

普通 BFS 在无权图 / 等权图中按层推进，第一次到达某个点就能确定最短距离。

SPFA 中边权可以不同甚至为负，因此：

- 一个点可以被更新多次；
- 一个点可以多次入队；
- 出队不代表最短距离永久确定；
- 队列顺序不等于距离从小到大。

</Callout>

所以 SPFA 更准确地说是一种 **标签修正算法**，而不是“带权 BFS”。

---

## 13. inQueue 不是 visited

普通 BFS 常见：

```cpp
visited[v] = true;
```

并永久不再访问。

SPFA 不能这样做。

这里的 `inQueue[v]` 只表示：

```text
v 此刻是否正在队列中
```

出队后必须恢复为 `false`，因为未来它可能通过另一条路径再次变短。

---

## 14. 为什么有正权环不会死循环

原资料中的环结构：

![存在环的图](https://file1.kamacoder.com/i/algo/20240412111849.png)

有环不等于会无限更新。

若环权总和：

$$
W_{cycle}\ge 0
$$

继续绕环不会让路径越来越短，因此所有 `dist` 最终都会稳定，队列也会清空。

真正会让更新永远继续的是：

$$
W_{cycle}<0
$$

也就是负权回路。下一篇会专门处理这个问题。

---

## 15. 时间复杂度为什么不稳定

若顶点 `u` 被出队 $k_u$ 次，那么它的出边就会被扫描 $k_u$ 次。总工作量更接近：

$$
\sum_{u\in V}k_u\cdot outdeg(u)
$$

因此性能取决于图结构和更新顺序。

原资料给出的稠密图示意：

![稠密图示意](https://file1.kamacoder.com/i/algo/20240416104138.png)

在极端构造下，大量顶点会反复入队，复杂度仍可退化为：

$$
O(VE)
$$

所以不能把 SPFA 写成固定的 $O(E)$。

<Callout type="warning" title="算法选择">

- 边权全部非负：优先堆优化 Dijkstra；
- 有负权边且需要稳定上界：Bellman-Ford 更容易分析；
- 数据较稀疏、更新范围通常较小：可以尝试 SPFA；
- 不要认为 SPFA 一定比 Bellman-Ford 快。

</Callout>

---

## 16. 与 Dijkstra 的根本区别

| 特征 | Dijkstra | SPFA |
| --- | --- | --- |
| 负权边 | 不支持 | 支持 |
| 核心思想 | 贪心定点 | 反复标签修正 |
| 顶点可再次变短 | 一般不会 | 可以 |
| 常用容器 | 最小堆 | FIFO 队列 |
| 最坏复杂度 | $O((V+E)\log V)$ | 可退化到 $O(VE)$ |

Dijkstra 的关键是：

> 当前全局最小的未确定距离可以永久确定。

SPFA 没有这个性质，所以一个点可能反复被更新。

---

## 17. 高频易错点

1. **起点入队却忘记 `inQueue[start] = true`**：状态语义不一致。
2. **出队后不清除 `inQueue[u]`**：以后该点即使变短也无法再次入队。
3. **把 `inQueue` 当永久 visited**：会漏掉后续更短路径。
4. **认为一个点只入队一次**：错误，SPFA 允许重复改进。
5. **认为有环就死循环**：只有负权回路才可能导致距离无限下降。
6. **认为 SPFA 永远更快**：最坏复杂度仍是 $O(VE)$。
7. **边权非负还强行 SPFA**：多数情况下堆优化 Dijkstra 更合适。

---

## 18. 最终记忆框架

把队列理解成“待传播的变化”即可：

$$
\text{dist[v] 变小}
\rightarrow
\text{v 的出边可能受影响}
\rightarrow
\text{v 入队}
\rightarrow
\text{出队后继续松弛}
$$

模板中的四个动作：

```text
1. source 入队
2. u 出队，并令 inQueue[u] = false
3. 松弛 u 的所有出边
4. v 变短且当前不在队列 → v 入队
```

````code-tabs
```java label="Java"
import java.io.*;
import java.util.*;

public class Main {
    static class Edge {
        int to;
        long weight;
        Edge(int to, long weight) {
            this.to = to;
            this.weight = weight;
        }
    }

    public static void main(String[] args) throws Exception {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());
        int n = Integer.parseInt(st.nextToken());
        int m = Integer.parseInt(st.nextToken());

        List<List<Edge>> graph = new ArrayList<>();
        for (int i = 0; i <= n; ++i) graph.add(new ArrayList<>());

        for (int i = 0; i < m; ++i) {
            st = new StringTokenizer(br.readLine());
            int u = Integer.parseInt(st.nextToken());
            int v = Integer.parseInt(st.nextToken());
            long w = Long.parseLong(st.nextToken());
            graph.get(u).add(new Edge(v, w));
        }

        long INF = Long.MAX_VALUE / 4;
        long[] dist = new long[n + 1];
        Arrays.fill(dist, INF);
        boolean[] inQueue = new boolean[n + 1];
        Queue<Integer> q = new ArrayDeque<>();

        dist[1] = 0;
        q.offer(1);
        inQueue[1] = true;

        while (!q.isEmpty()) {
            int u = q.poll();
            inQueue[u] = false;

            for (Edge e : graph.get(u)) {
                long candidate = dist[u] + e.weight;
                if (candidate < dist[e.to]) {
                    dist[e.to] = candidate;
                    if (!inQueue[e.to]) {
                        q.offer(e.to);
                        inQueue[e.to] = true;
                    }
                }
            }
        }

        System.out.println(dist[n] == INF ? "unconnected" : dist[n]);
    }
}
```

from collections import deque
from math import inf

n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v, w = map(int, input().split())
    graph[u].append((v, w))

dist = [inf] * (n + 1)
in_queue = [False] * (n + 1)
q = deque([1])

dist[1] = 0
in_queue[1] = True

while q:
    u = q.popleft()
    in_queue[u] = False

    for v, w in graph[u]:
        candidate = dist[u] + w
        if candidate < dist[v]:
            dist[v] = candidate
            if not in_queue[v]:
                q.append(v)
                in_queue[v] = True

print("unconnected" if dist[n] == inf else dist[n])
````
