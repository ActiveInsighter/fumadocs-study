# 377. 组合总和 IV

[LeetCode 377：组合总和 IV](https://leetcode.cn/problems/combination-sum-iv/)

给定一个由**互不相同的正整数**组成的数组 `nums` 和目标整数 `target`，求所有元素之和恰好为 `target` 的有序序列数量。

例如：

```text
nums = [1, 2, 3]
target = 4
```

合法序列包括：

```text
1 + 1 + 1 + 1
1 + 1 + 2
1 + 2 + 1
2 + 1 + 1
1 + 3
3 + 1
2 + 2
```

因此答案为：

$$
7
$$

<Callout type="warning" title="题名叫“组合总和”，本质却是在数排列">
本题明确规定顺序不同的序列算不同答案，因此 `1 + 3` 与 `3 + 1` 必须分别计数。真正决定 DP 模型的是题意，而不是题目名称。
</Callout>

## 1. 先判断：组合还是排列

数学意义上：

### 组合

只关心选了哪些元素，不关心顺序。

```text
1 + 3
3 + 1
```

视为同一种方案。

### 排列

关心元素出现顺序。

```text
1 + 3
3 + 1
```

视为两种不同方案。

本题显然属于第二种情况，因此我们真正要求的是：

$$
\boxed{\text{和为 target 的有序序列数量}}
$$

## 2. 为什么是完全背包

把 `nums` 中每个数看成一种物品：

- 物品重量：数字本身；
- 背包容量：`target`；
- 每种数字可以重复使用无限次。

因此首先确定：

$$
\boxed{\text{完全背包}}
$$

但它和“零钱兑换 II”不同：

- 零钱兑换 II 求**组合数**；
- 组合总和 IV 求**排列数**。

这正是本题最重要的考点。

## 3. 状态定义

定义：

$$
\boxed{dp[i]=\text{元素和恰好为 }i\text{ 的有序序列数量}}
$$

最终答案：

$$
\boxed{dp[target]}
$$

## 4. 状态转移：把某个数放在序列最后

假设当前希望构造和为 $i$ 的序列，并选择 `num` 作为最后一个元素。

那么前面的序列之和必须是：

$$
i-num
$$

所有和为 $i-num$ 的有序序列，在末尾追加 `num` 后，都能得到一个和为 $i$ 的新序列。

因此：

$$
\boxed{dp[i]+=dp[i-num]}
$$

对所有满足：

$$
num\le i
$$

的 `num` 累加即可。

从递推关系看：

$$
dp[i]=\sum_{num\in nums,\ num\le i}dp[i-num]
$$

这其实已经非常接近一个“广义爬楼梯”模型：

> 走到第 $i$ 阶时，最后一步可以是 `nums` 中任意一个允许的步长。

## 5. 为什么 `dp[0] = 1`

初始化：

$$
\boxed{dp[0]=1}
$$

其余：

$$
dp[i]=0\quad(i>0)
$$

`dp[0] = 1` 表示：

> 组成总和 0 有一个空序列。

它是所有非空序列产生的起点。

例如 `nums` 中有数字 $3$，计算 `dp[3]` 时：

$$
dp[3]+=dp[0]
$$

这对应序列：

```text
[3]
```

如果 `dp[0] = 0`，那么任何由单个数字直接组成目标值的方案都无法产生，随后所有状态也都会保持为 0。

<Callout type="info" title="不要把 dp[0] = 1 当成技巧">
在计数型 DP 中，空方案通常是构造非空方案的单位元素。它和组合数学中“空集合是一种选择”具有相同思想。
</Callout>

## 6. 本题最关键：为什么容量必须在外层

标准写法：

```cpp
for (int i = 1; i <= target; ++i) {
    for (int num : nums) {
        if (i >= num) {
            dp[i] += dp[i - num];
        }
    }
}
```

这里：

- 外层遍历目标和 `i`；
- 内层遍历最后一个数字 `num`。

为什么？

因为我们是在枚举：

> 和为 $i$ 的序列，最后一个元素可以是谁？

例如：

```text
nums = [1, 2, 3]
target = 4
```

计算 `dp[4]` 时：

- 最后一个元素为 `1`：前面必须是和为 `3` 的序列；
- 最后一个元素为 `2`：前面必须是和为 `2` 的序列；
- 最后一个元素为 `3`：前面必须是和为 `1` 的序列。

因此：

$$
dp[4]=dp[3]+dp[2]+dp[1]
$$

已知：

$$
dp[1]=1
$$

$$
dp[2]=2
$$

$$
dp[3]=4
$$

所以：

$$
dp[4]=4+2+1=7
$$

## 7. 手推整个 DP 数组

初始：

```text
dp = [1, 0, 0, 0, 0]
```

### 计算 `dp[1]`

只能以 `1` 结尾：

$$
dp[1]=dp[0]=1
$$

```text
dp = [1, 1, 0, 0, 0]
```

### 计算 `dp[2]`

可以以 `1` 或 `2` 结尾：

$$
dp[2]=dp[1]+dp[0]=1+1=2
$$

对应：

```text
1 + 1
2
```

### 计算 `dp[3]`

可以以 `1`、`2`、`3` 结尾：

$$
dp[3]=dp[2]+dp[1]+dp[0]
$$

$$
=2+1+1=4
$$

对应：

```text
1 + 1 + 1
1 + 2
2 + 1
3
```

### 计算 `dp[4]`

$$
dp[4]=dp[3]+dp[2]+dp[1]
$$

$$
=4+2+1=7
$$

## 8. 为什么“物品外层”会变成组合数

如果错误地写成：

```cpp
for (int num : nums) {
    for (int i = num; i <= target; ++i) {
        dp[i] += dp[i - num];
    }
}
```

这会按照数字种类逐个处理。

当处理到 `2` 时，由 `1` 和 `2` 组成的方案只能以固定的“种类顺序”生成，因此：

```text
1 + 2
```

会被统计，而：

```text
2 + 1
```

不会再次作为另一种顺序产生。

所以得到的是：

$$
\boxed{\text{组合数}}
$$

而不是本题要求的排列数。

## 9. 与零钱兑换 II 的对照

这是完全背包中最值得放在一起比较的一组题。

| 对比项 | 零钱兑换 II | 组合总和 IV |
| --- | --- | --- |
| 元素能否重复使用 | 可以 | 可以 |
| 背包类型 | 完全背包 | 完全背包 |
| 求什么 | 组合数 | 排列数 |
| 是否区分顺序 | 否 | 是 |
| 容量方向 | 正序 | 正序 |
| 外层循环 | 物品 | 容量 |
| 内层循环 | 容量 | 物品 |

它们的状态转移甚至完全一样：

$$
dp[i]+=dp[i-num]
$$

真正改变答案含义的是循环顺序。

<Callout type="warning" title="递推公式相同，不代表是同一道 DP">
状态定义、初始化、循环方向和循环嵌套顺序都是 DP 的组成部分。只看转移公式，会错过背包计数题最关键的区别。
</Callout>

## 10. 从“最后一步”视角理解排列计数

本题还有一个比“背包模板”更直观的理解方式：**最后一步 DP**。

假设目标为 $i$。

任何合法序列都有一个最后元素。

若最后元素是 `num`，那么删掉它之后，前面的部分必须是一个和为：

$$
i-num
$$

的合法序列。

所以按照最后元素分类：

$$
dp[i]
=
\sum_{num\le i} dp[i-num]
$$

不同的最后元素天然对应不同排列，因此不会丢失顺序信息。

这也是为什么外层应该按 `i = 1,2,...,target` 递增计算。

## 11. 与爬楼梯的关系

经典爬楼梯中，每次可以走 $1$ 或 $2$ 阶：

$$
dp[i]=dp[i-1]+dp[i-2]
$$

如果每次允许走的步数变为：

```text
nums = [1, 3, 5]
```

那么：

$$
dp[i]=dp[i-1]+dp[i-3]+dp[i-5]
$$

这和组合总和 IV 完全同构。

因此本题可以理解成：

> 给定任意步长集合 `nums`，走到第 `target` 阶有多少种有序走法？

这也是一个非常重要的迁移关系。

## 12. C++ 实现

```cpp
class Solution {
public:
    int combinationSum4(vector<int>& nums, int target) {
        vector<unsigned long long> dp(target + 1, 0);
        dp[0] = 1;

        for (int i = 1; i <= target; ++i) {
            for (int num : nums) {
                if (i >= num) {
                    dp[i] += dp[i - num];
                }
            }
        }

        return static_cast<int>(dp[target]);
    }
};
```

### 复杂度

设：

$$
n=|nums|
$$

时间复杂度：

$$
\boxed{O(n\cdot target)}
$$

空间复杂度：

$$
\boxed{O(target)}
$$

## 13. 关于整数溢出

这类方案计数增长非常快。

例如当 `nums` 中包含多个较小数字时，`dp[i]` 会呈现近似指数级增长。

因此在实际工程中最好使用更宽的整数类型：

```cpp
unsigned long long
```

或者根据题目要求使用任意精度整数。

在 LeetCode 题目中，题目通常会保证最终答案符合指定返回类型，但在中间状态上仍应注意语言的整数范围和测试数据约束。

## 14. 为什么 `nums` 必须是正整数

题目限制 `nums` 中都是正整数，这一点并不是无关紧要的。

如果允许 `0`：

```text
nums = [0, 1]
```

那么任何合法序列都可以无限插入 `0`：

```text
1
0 + 1
0 + 0 + 1
...
```

方案数会变成无限。

如果允许负数，也可能通过正负数循环不断产生新的序列，例如：

```text
1, -1, 1, -1, ...
```

因此“所有元素均为正整数”保证了状态图按总和严格向前推进，DP 才是有限且良定义的。

## 15. 高频错误

### 错误一：看到题名“组合”就写组合数模板

必须以题意为准。本题顺序不同算不同答案，所以是排列计数。

### 错误二：物品放在外层

这会去掉顺序差异，算成组合数。

### 错误三：`dp[0] = 0`

没有基础空序列，所有后续方案都无法生成。

### 错误四：容量倒序

完全背包允许同一个数字重复使用，因此目标和必须正序推进。

### 错误五：把 DP 用来输出所有序列

本题只求数量，所以 DP 很合适。

如果题目要求真正列举每一种序列，则通常需要回溯 / DFS 等枚举方法。

## 16. 一眼识别模板

看到：

- 每个数字可以重复使用；
- 要恰好凑成目标和；
- 求方案数量；
- 顺序不同算不同方案；

快速判断：

$$
\boxed{\text{完全背包排列计数}}
$$

模板：

```cpp
vector<long long> dp(target + 1, 0);
dp[0] = 1;

for (int sum = 1; sum <= target; ++sum) {
    for (int x : nums) {
        if (sum >= x) {
            dp[sum] += dp[sum - x];
        }
    }
}
```

核心口诀虽然可以写成：

```text
排列：容量在外，物品在内
```

但更应该理解成：

> 对每一个目标和，枚举“最后放入哪个元素”。

## 18. 小结

本题最值得掌握的不是某一行代码，而是三个判断：

1. 数字可以无限使用，因此属于完全背包；
2. 顺序不同算不同方案，因此求的是排列数；
3. 为了保留顺序，必须先遍历目标和，再枚举最后一个数字。

最终模板：

$$
\boxed{dp[i]+=dp[i-num]}
$$

并配合：

$$
\boxed{\text{容量外层，物品内层}}
$$

把它与“零钱兑换 II”的组合计数放在一起理解，就能真正掌握完全背包计数题中循环顺序的本质。
