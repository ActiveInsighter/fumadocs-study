# 动态规划阶段六总结：从打家劫舍到股票状态机

这一阶段包含四个非常有代表性的问题：

1. 打家劫舍；
2. 打家劫舍 II；
3. 打家劫舍 III；
4. 买卖股票的最佳时机。

表面上，它们从数组一路变成环、二叉树和股票交易，题型差异很大。

但从动态规划角度看，这一阶段真正训练的是同一个能力：

$$
\boxed{
\text{根据约束设计“足够描述未来决策”的状态}
}
$$

<Callout type="info" title="这一阶段的核心升级">
前面的很多 DP 只需要回答“处理到第 $i$ 个位置时最优值是多少”。从这一阶段开始，单纯记录位置往往已经不够，还需要继续记录“当前选择状态”。这正是后面股票系列、树形 DP、状态机 DP 的基础。
</Callout>

## 1. 打家劫舍：最经典的“选或不选”

给定数组 `nums`，不能同时选择相邻元素，求最大元素和。

定义：

$$
dp[i]=\text{考虑下标 }0\sim i\text{ 的房屋时能获得的最大金额}
$$

处理第 $i$ 间房时只有两个选择。

### 不偷第 $i$ 间

收益为：

$$
dp[i-1]
$$

### 偷第 $i$ 间

那么第 $i-1$ 间不能偷：

$$
dp[i-2]+nums[i]
$$

于是：

$$
\boxed{
dp[i]=\max(dp[i-1],dp[i-2]+nums[i])
}
$$

这类模型可以抽象成：

$$
\boxed{
\text{当前位置选 / 不选，并且选择会限制相邻状态}
}
$$

## 2. 打家劫舍 II：环形结构如何破环

当数组首尾相邻后，普通线性递推不能直接套用。

关键约束是：

$$
\text{第 }0\text{ 间和第 }n-1\text{ 间不能同时选择}
$$

因此任何合法最优解一定落在以下两个范围之一：

$$
[0,n-2]
$$

或：

$$
[1,n-1]
$$

于是：

$$
\boxed{
answer=\max(rob(0,n-2),rob(1,n-1))
}
$$

这是一种非常通用的技巧：

> 当“环”只在首尾额外产生一个冲突时，可以通过枚举首尾关系，把环拆成若干线性问题。

### “考虑某个区间”不等于“必须选择端点”

例如在区间 $[0,n-2]$ 中，动态规划仍然可以选择不偷第 $0$ 间。

所以这里的区间只是在限定候选集合，而不是强制选择边界元素。

## 3. 打家劫舍 III：从数组 DP 到树形 DP

当房屋结构变成二叉树时，约束变为：

$$
\boxed{
\text{父节点和子节点不能同时选择}
}
$$

这时已经没有“前一个下标”“前两个下标”的概念。

对每个节点真正需要记录的是：

$$
dp_0(u)=\text{不偷节点 }u\text{ 时的最大收益}
$$

$$
dp_1(u)=\text{偷节点 }u\text{ 时的最大收益}
$$

于是：

$$
\boxed{
dp_1(u)=u.val+dp_0(L)+dp_0(R)
}
$$

$$
\boxed{
dp_0(u)=\max(dp_0(L),dp_1(L))+\max(dp_0(R),dp_1(R))
}
$$

因为父节点依赖左右孩子已经算好的状态，所以必须使用后序遍历。

![打家劫舍 III](https://file1.kamacoder.com/i/algo/20210129181331613.jpg)

### 树形 DP 的本质

树形 DP 并不神秘。

它依然只有三件事：

1. 定义状态；
2. 从子问题得到当前状态；
3. 按依赖方向遍历。

只不过“下标递推”被“树边递推”替代了。

## 4. 买卖股票的最佳时机：真正进入状态机 DP

股票问题不能只记录：

$$
\text{前 }i\text{ 天最大利润}
$$

因为同样处理到第 $i$ 天时，**手中是否持有股票**会直接影响下一天能做什么。

因此必须加入状态维度：

$$
dp[i][0]=\text{第 }i\text{ 天持有股票的最大现金}
$$

$$
dp[i][1]=\text{第 }i\text{ 天不持有股票的最大现金}
$$

对于最多一次交易：

$$
\boxed{
dp[i][0]=\max(dp[i-1][0],-prices[i])
}
$$

$$
\boxed{
dp[i][1]=\max(dp[i-1][1],dp[i-1][0]+prices[i])
}
$$

![买卖股票的最佳时机](https://file1.kamacoder.com/i/algo/20210224225642465.png)

这里最关键的不是公式，而是理解：

> `dp[i][0]` 的“0”并不是某一种操作，而是系统的一种状态。

今天可以什么都不做，也可以发生买入，只要一天结束时“持有股票”，最终都属于这个状态。

## 5. 四道题的统一视角

| 问题 | 结构 | 主要约束 | 核心状态 |
| --- | --- | --- | --- |
| 打家劫舍 | 线性数组 | 相邻不能同时选 | 前 $i$ 个位置的最优值 |
| 打家劫舍 II | 环形数组 | 首尾也相邻 | 拆成两个线性区间 |
| 打家劫舍 III | 二叉树 | 父子不能同时选 | 每个节点偷 / 不偷 |
| 股票 I | 时间序列 | 最多一次买卖 | 每天持有 / 不持有 |

看起来是四类问题，实际上都在处理：

$$
\boxed{
\text{某个选择会限制下一步允许进入的状态}
}
$$

这就是状态机思维。

## 6. “选 / 不选”与“持有 / 不持有”有什么区别

打家劫舍中，第 $i$ 个位置的选择通常只影响附近位置。

而股票中，“持有”状态可能持续很多天：

```text
买入 → 持有 → 持有 → 持有 → 卖出
```

因此股票 DP 更适合画成状态转移图。

单次交易可以理解为：

```text
            买入
不持有  ---------->  持有
  ^                   |
  |                   |
  +-------------------+
            卖出
```

不过要注意，本题的“再次买入”受到交易次数限制，因此持有状态的买入来源不是任意“不持有状态”。

## 7. 为什么状态设计比递推公式更重要

很多 DP 学习者喜欢先背：

```text
dp[i] = max(...)
```

但真正困难的问题通常不是写 `max`，而是回答：

> `dp` 到底表示什么？

一个好的状态必须满足两点。

### 条件一：能完整描述未来决策需要的信息

打家劫舍 III 如果只返回“子树最大收益”，父节点就不知道孩子到底偷没偷。

因此必须返回两个状态。

### 条件二：状态数量尽量少

如果某个信息不会影响未来，就不需要放进状态。

例如普通打家劫舍不需要记录“第 $i$ 间到底偷没偷”的完整历史，只需要维护能推导下一步的最优结果。

<Callout type="success" title="判断状态够不够用">
可以问自己一句：只知道当前 `dp` 状态，能不能不回头查看完整历史，就正确决定下一步？如果不能，说明状态中缺少信息。
</Callout>

## 8. 结构发生变化时，先判断依赖关系

这一阶段展示了三种典型结构。

### 线性序列

依赖前面的状态：

```text
左 → 右
```

### 树

父节点依赖孩子：

```text
叶子 → 根
```

因此使用后序遍历。

### 环

无法直接确定线性起点，因此先破环，再复用线性 DP。

这说明动态规划的遍历顺序不是模板规定的，而是由：

$$
\boxed{
\text{状态依赖方向}
}
$$

决定。

## 9. 这一阶段最值得掌握的四个模板

### 模板一：相邻不能同时选

$$
\boxed{
dp[i]=\max(dp[i-1],dp[i-2]+value[i])
}
$$

典型题：打家劫舍。

### 模板二：环形相邻冲突

$$
\boxed{
answer=\max(solve(0,n-2),solve(1,n-1))
}
$$

典型题：打家劫舍 II。

### 模板三：树上选 / 不选

```text
返回 [不选当前节点, 选择当前节点]
```

典型题：打家劫舍 III。

### 模板四：时间序列上的状态机

```text
位置 i + 当前状态 state
```

典型题：股票问题。

## 10. 常见误区集中整理

### 误区一：把“考虑范围”当成“必须选择”

打家劫舍 II 中，考虑 `[0, n - 2]` 不代表必须偷第 $0$ 间。

### 误区二：树形 DP 只返回一个最大值

父节点需要知道孩子“偷”和“不偷”分别是多少，只返回最大值会丢失必要信息。

### 误区三：股票中的“持有”就是今天买入

持有是一种状态，可以从前一天延续。

### 误区四：先写递推式，再猜状态含义

正确顺序应该是：

1. 明确状态含义；
2. 枚举当前状态的所有合法来源；
3. 再写递推公式。

$$
\boxed{

}
$$

## 12. 阶段总结

这一阶段可以压缩成四句话：

1. **线性 DP**：当前位置的选择受到相邻位置约束；
2. **环形 DP**：通过分类讨论打破首尾耦合；
3. **树形 DP**：节点状态依赖孩子，使用后序遍历自底向上计算；
4. **状态机 DP**：仅记录位置不够时，再增加“当前所处状态”这一维。

真正需要形成的能力不是记住四道题，而是看到一个新问题时能够主动寻找：

$$
\boxed{
\text{状态是什么？状态之间如何合法转移？}
}
$$

一旦这两件事清楚，动态规划的大部分递推式都会自然出现。
