# 爬楼梯

> LeetCode 70：Climbing Stairs

有一段共 $n$ 级的楼梯，每次可以向上走 **1 级或 2 级**，问到达第 $n$ 级一共有多少种不同的走法。

例如 $n=3$ 时，共有三种：

```text
1 + 1 + 1
1 + 2
2 + 1
```

这道题与斐波那契数的递推形式完全相同，但比斐波那契更重要的一点是：**递推公式需要我们自己从题意中推导出来。**

<Callout type="info" title="核心思维">
做计数型 DP 时，一个非常高频的思路是问：**到达当前状态的最后一步可能是什么？** 然后把所有互不重叠的来源方案数相加。
</Callout>

## 1. 从“最后一步”推导状态转移

假设已经到达第 $i$ 级台阶。

最后一步只有两种可能：

1. 从第 $i-1$ 级走 1 步上来；
2. 从第 $i-2$ 级走 2 步上来。

除此之外不存在第三种最后一步。

因此，如果：

$$
dp[i]=\text{到达第 }i\text{ 级台阶的方法数}
$$

那么：

$$
dp[i]=dp[i-1]+dp[i-2]
$$

为什么可以直接相加？

因为“最后走 1 级”和“最后走 2 级”这两类方案**互不重叠**，并且覆盖了所有可能方案。

这实际上使用了计数问题中最基本的分类加法原理。

## 2. 动态规划五步分析

### 2.1 状态定义

定义：

$$
dp[i]=\text{到达第 }i\text{ 级台阶的不同方法数}
$$

最终答案就是：

$$
dp[n]
$$

### 2.2 状态转移

到达第 $i$ 级只能来自第 $i-1$ 或第 $i-2$ 级：

$$
dp[i]=dp[i-1]+dp[i-2]
$$

这也是本题最关键的一步。

### 2.3 初始化

如果完全按照题意，$n$ 是正整数，那么最直接的初始化是：

$$
dp[1]=1
$$

$$
dp[2]=2
$$

于是从 $i=3$ 开始递推即可。

### 2.4 遍历顺序

因为当前状态依赖较小下标：

$$
dp[i-1],\quad dp[i-2]
$$

所以必须从小到大计算。

### 2.5 手工推导

![](https://file1.kamacoder.com/i/algo/20210105202546299.png)

当 $n=5$ 时：

| $i$ | 1 | 2 | 3 | 4 | 5 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| $dp[i]$ | 1 | 2 | 3 | 5 | 8 |

从这里可以发现：

$$
1,2,3,5,8,\dots
$$

本质上就是从斐波那契数列平移得到的序列。

具体地：

$$
dp[n]=F(n+1)
$$

但做题时不建议先背这个结论，而应该从“最后一步”推导转移。

## 3. 标准二维？不需要，一维状态就够了

本题未来的决策只关心“当前到达了第几级”，不需要额外记录其他信息。

因此状态只需要一个维度：

```text
dp[i]
```

标准实现：

```cpp
class Solution {
public:
    int climbStairs(int n) {
        if (n <= 2) return n;

        vector<int> dp(n + 1);
        dp[1] = 1;
        dp[2] = 2;

        for (int i = 3; i <= n; ++i) {
            dp[i] = dp[i - 1] + dp[i - 2];
        }

        return dp[n];
    }
};
```

### 复杂度

状态数量为 $n$，每个状态只做一次加法：

$$
O(n)
$$

完整数组需要：

$$
O(n)
$$

## 4. 最容易混淆的问题：`dp[0]` 到底应该是多少？

这道题经常出现两种写法：

### 写法 A：从题意直接定义

定义：

$$
dp[i]=\text{到达第 }i\text{ 级的方法数},\qquad i\ge1
$$

初始化：

$$
dp[1]=1,\qquad dp[2]=2
$$

从 $i=3$ 开始递推。

这种写法完全不需要讨论 `dp[0]`。

### 写法 B：把空方案作为一种方案

也可以定义：

$$
dp[0]=1
$$

理解为：到达“距离为 0”的目标，有一种空操作方案——什么都不做。

于是：

$$
dp[1]=dp[0]=1
$$

并且统一使用：

$$
dp[i]=dp[i-1]+dp[i-2]
$$

这种定义在后面的背包计数问题中尤其常见，因为 `dp[0]=1` 往往代表：

> **凑出总和 0 有一种方案：什么都不选。**

<Callout type="warning" title="不要争论 dp[0] 的“唯一正确值”">
`dp[0]` 的数值取决于你的状态语义和递推设计。只要定义、初始化和转移彼此一致，两种体系都可以正确。真正错误的是“没有明确状态含义，却机械记住 dp[0]=0 或 dp[0]=1”。
</Callout>

### 两种定义对比

| 体系 | 初始化 | 起始循环 | 优点 |
| --- | --- | --- | --- |
| 题意直观型 | `dp[1]=1, dp[2]=2` | `i=3` | 容易理解 |
| 空方案型 | `dp[0]=1, dp[1]=1` | `i=2` | 公式统一，方便推广到背包计数 |

## 5. 为什么可以压缩空间

因为：

$$
dp[i]=dp[i-1]+dp[i-2]
$$

当前状态只需要前两个状态。

因此可以直接使用两个变量：

```cpp
class Solution {
public:
    int climbStairs(int n) {
        if (n <= 2) return n;

        int prev2 = 1; // dp[1]
        int prev1 = 2; // dp[2]

        for (int i = 3; i <= n; ++i) {
            int cur = prev1 + prev2;
            prev2 = prev1;
            prev1 = cur;
        }

        return prev1;
    }
};
```

此时：

$$
T(n)=O(n)
$$

$$
S(n)=O(1)
$$

<Callout type="tip" title="学习阶段建议">
完整 `dp` 数组更容易观察状态变化；滚动变量更节省空间。先确保你能清楚解释数组版，再写压缩版。
</Callout>

## 6. 为什么这题和斐波那契“公式一样、含义不同”

两道题都有：

$$
dp[i]=dp[i-1]+dp[i-2]
$$

但状态含义完全不同。

<Tabs items={["斐波那契数", "爬楼梯"]}>
<Tab value="斐波那契数">

$$
dp[i]=\text{第 }i\text{ 个斐波那契数}
$$

递推公式是题目定义直接给出的。

</Tab>
<Tab value="爬楼梯">

$$
dp[i]=\text{到达第 }i\text{ 级台阶的方法数}
$$

递推公式来自对“最后一步”的分类讨论。

</Tab>
</Tabs>

这说明一个非常重要的事实：

> **动态规划不能只背转移公式。相同公式可以对应完全不同的问题。状态语义才是核心。**

## 7. 推广：一次可以爬 1 到 $m$ 级

如果每次不再只允许走 1 或 2 级，而是允许：

$$
1,2,3,\dots,m
$$

那么到达第 $i$ 级的最后一步可以来自：

$$
i-1,i-2,\dots,i-m
$$

因此：

$$
dp[i]=\sum_{k=1}^{m}dp[i-k]
$$

其中只累加满足：

$$
i-k\ge0
$$

的状态。

采用“空方案”定义：

$$
dp[0]=1
$$

代码可以写成：

```cpp
long long climbStairs(int n, int m) {
    vector<long long> dp(n + 1, 0);
    dp[0] = 1;

    for (int i = 1; i <= n; ++i) {
        for (int step = 1; step <= m; ++step) {
            if (i - step >= 0) {
                dp[i] += dp[i - step];
            }
        }
    }

    return dp[n];
}
```

时间复杂度：

$$
O(nm)
$$

空间复杂度：

$$
O(n)
$$

## 8. 从爬楼梯进一步看“完全背包”

把每一种可走步长看成一种“物品”：

```text
1, 2, ..., m
```

目标是恰好凑出总台阶数 $n$。

因为每种步长可以重复使用，所以它具有**完全背包**特征。

更重要的是：

```text
1 + 2
```

与：

```text
2 + 1
```

在爬楼梯中是两种不同走法。

因此本题统计的是**排列数**，而不是组合数。

这会直接影响完全背包的一维遍历顺序：

- 先遍历容量，再遍历物品：更容易统计排列；
- 先遍历物品，再遍历容量：更容易统计组合。

后面的背包章节会系统展开这一点。

<Callout type="info" title="提前建立联系">
“爬楼梯”不仅是线性 DP，也可以从完全背包角度重新理解。能够用两套模型解释同一道题，是判断是否真正理解 DP 的好方法。
</Callout>

## 9. 递归、记忆化与递推

同样可以从递归角度定义：

$$
f(n)=f(n-1)+f(n-2)
$$

### 朴素递归

```cpp
int climbStairs(int n) {
    if (n <= 2) return n;
    return climbStairs(n - 1) + climbStairs(n - 2);
}
```

会出现大量重复计算，时间复杂度近似：

$$
O(2^n)
$$

### 记忆化搜索

```cpp
class Solution {
private:
    vector<int> memo;

    int dfs(int n) {
        if (n <= 2) return n;
        if (memo[n] != -1) return memo[n];

        return memo[n] = dfs(n - 1) + dfs(n - 2);
    }

public:
    int climbStairs(int n) {
        memo.assign(n + 1, -1);
        return dfs(n);
    }
};
```

每个状态只计算一次：

$$
O(n)
$$

这再次说明：递归关系本身不是性能问题，真正的问题是**同一个子问题是否被重复求解**。

## 10. 常见错误

### 错误一：把不同顺序当成同一种方案

本题中：

```text
1 + 2
2 + 1
```

必须算作两种不同方法。

因此它是“有顺序”的计数问题。

### 错误二：状态含义与初始化不匹配

如果定义：

$$
dp[i]=\text{到达第 }i\text{ 级的方法数},\quad i\ge1
$$

却又随手写 `dp[0]=0`，再从 `i=2` 套统一公式，就会得到：

$$
dp[2]=dp[1]+dp[0]=1
$$

显然错误。

不是 `dp[0]=0` 这个数字本身“绝对错误”，而是它与当前递推体系不一致。

### 错误三：只看到“像斐波那契”就直接套

真正应该先做的是：

1. 定义 `dp[i]`；
2. 枚举最后一步；
3. 推出状态转移。

如果以后允许一次走 1、2、3 级，递推就会自然变成：

$$
dp[i]=dp[i-1]+dp[i-2]+dp[i-3]
$$

而不是继续机械套二项斐波那契。

## 11. 一套通用的“最后一步”分析法

遇到计数型问题，可以尝试依次问：

1. `dp[i]` 表示什么？
2. 最后一次操作有哪几种可能？
3. 每一种最后操作对应哪个前驱状态？
4. 这些类别是否互斥？
5. 是否覆盖全部方案？

如果答案都是明确的，那么通常可以写出：

$$
dp[i]=\sum \text{所有合法前驱状态的方案数}
$$

这个思路会在路径计数、背包计数、字符串划分等问题中不断出现。

## 13. 本题总结

本题最重要的不是记住：

$$
dp[i]=dp[i-1]+dp[i-2]
$$

而是理解它为什么成立：

$$
\boxed{\text{最后一步走 1 级}\;\cup\;\text{最后一步走 2 级}}
$$

两类方案互不重叠且覆盖全部情况，因此方案数相加。

这就是很多计数型动态规划最常见的推导方式：

> **先定义当前状态，再从“最后一次决策”反推它来自哪些前驱状态。**
