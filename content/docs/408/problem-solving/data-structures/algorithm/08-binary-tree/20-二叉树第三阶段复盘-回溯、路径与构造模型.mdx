# 二叉树第三阶段复盘：回溯、路径与构造模型

这一阶段的题目开始从“会遍历二叉树”进入“**利用递归状态解决真实问题**”。

前面已经掌握了前序、中序、后序、层序遍历，以及深度、节点数、平衡性等基础问题；这一阶段进一步训练了六个非常重要的能力：

1. 识别递归中的隐式回溯；
2. 根据父子关系判断特殊节点；
3. 用遍历顺序控制“最左、最深”等答案；
4. 判断递归函数到底需不需要返回值；
5. 根据遍历序列切分区间并构造二叉树；
6. 从数组区间递归构造具有特定性质的树。

<Callout title="这一阶段真正要掌握的不是六道题，而是六种模型" type="info">

如果只记题解，很容易换个题面就不会；如果把每道题抽象成“状态、遍历顺序、返回值、区间”的模型，后续二叉搜索树、回溯、递归构造题都会明显顺畅很多。

</Callout>

## 1. 模型一：递归中为什么天然带着回溯

典型问题：**二叉树的所有路径**。

从根节点走向叶子节点，本质上是在维护一条“当前路径”。

假设路径状态为：

```text
1 -> 2 -> 5
```

当 `5` 处理完成后，下一步不能继续沿着这条路径去访问 `2` 的另一个分支，而必须恢复到：

```text
1 -> 2
```

这就是回溯。

### 1.1 显式回溯

如果用数组保存路径：

```cpp
path.push_back(node->val);
traversal(node->left, path, result);
path.pop_back();
```

其中：

```cpp
path.pop_back();
```

就是非常明确的“撤销选择”。

### 1.2 隐式回溯

如果参数按值传递：

```cpp
traversal(node->left, path + "->", result);
```

那么子递归拿到的是一个新的字符串。

子递归结束后，当前调用栈中的 `path` 根本没有被修改，因此不需要手动恢复。

这仍然属于回溯，只不过“恢复现场”由**值语义和函数调用栈**替你完成了。

<Callout title="识别回溯的关键" type="idea">

不要只盯着代码里有没有 `pop_back()`。

只要一个算法存在：

```text
做选择 → 深入一个分支 → 返回 → 尝试另一个分支
```

它就具有回溯结构。

</Callout>

## 2. 模型二：判断一个节点，有时必须看它的父节点

典型问题：**左叶子之和**。

叶子节点的定义很简单：

```text
node->left == nullptr
&&
node->right == nullptr
```

但这只能判断“它是不是叶子”，不能判断“它是不是左叶子”。

因为“左”不是节点自身的属性，而是它与父节点之间的关系。

因此判断左叶子最自然的方法是站在父节点上看：

```cpp
if (node->left != nullptr
    && node->left->left == nullptr
    && node->left->right == nullptr) {
    // node->left 是左叶子
}
```

也就是说，很多树问题并不是只观察一个节点，而是观察一个局部结构：

```text
父节点
  ↓
当前节点
  ↓
左右孩子
```

### 2.1 一个很实用的分类

做“判断某类节点”的题时，可以先问：

```text
这个性质只由节点自身决定吗？
```

如果不是，再继续问：

```text
它依赖父节点？
依赖孩子？
还是依赖更大的路径状态？
```

例如：

| 问题 | 判断需要的信息 |
| --- | --- |
| 是否叶子节点 | 当前节点 + 左右孩子 |
| 是否左叶子 | 父节点 + 当前节点 + 当前节点孩子 |
| 当前深度 | 根到当前节点的路径 |
| 是否平衡 | 左右子树高度 |

这其实是在训练**状态应该放在哪里**。

## 3. 模型三：遍历顺序本身可以决定答案的优先级

典型问题：**找树左下角的值**。

目标可以拆成两个条件：

```text
1. 深度最大
2. 在这一深度中最靠左
```

如果使用层序遍历，最后一层第一个节点就是答案，思路非常直接。

如果使用递归，则可以利用：

```text
前序遍历 + 左子树优先
```

当第一次到达一个更深的叶子节点时，就记录它。

由于始终先访问左边：

```text
同一深度中最先遇到的节点 = 最左节点
```

这说明遍历顺序不仅决定“访问次序”，有时还可以替代额外的比较逻辑。

<Callout title="一个很重要的解题意识" type="info">

遇到“最左、最右、第一个、最后一个”这样的限定词时，不要立刻想着增加复杂状态。

先考虑：**能不能通过遍历顺序，让目标答案天然最先或最后被访问到？**

</Callout>

## 4. 模型四：递归函数什么时候需要返回值

这是二叉树递归中最容易混淆、也最值得系统总结的一点。

可以把常见情况分为三类。

### 4.1 搜完整棵树：通常不依赖返回值做短路

例如收集所有根到叶子的路径：

```text
我要把所有答案都找出来
```

即使已经找到一条合法路径，其他分支也必须继续搜索。

因此常见形式是：

```cpp
void traversal(...)
```

通过引用参数、成员变量或外部容器收集结果。

### 4.2 只需找到一条可行路径：适合返回 `bool`

例如路径总和：

```text
是否存在一条根到叶子的路径，使节点和等于 targetSum？
```

只要任意一条路径成功，就已经可以结束：

```cpp
if (traversal(node->left, count)) return true;
if (traversal(node->right, count)) return true;
```

这种写法的本质是**短路搜索**。

逻辑上相当于：

```text
leftSuccess OR rightSuccess
```

### 4.3 当前节点状态依赖左右子树结果：必须接住返回值

例如：

- 平衡二叉树；
- 完全二叉树节点数量；
- 最大深度；
- 树形动态规划中的大量问题。

结构通常是：

```cpp
left = traversal(node->left);
right = traversal(node->right);
return combine(left, right);
```

这是典型的后序思想：

```text
先得到左
再得到右
最后计算当前节点
```

### 4.4 一张判断表

| 需求 | 常见返回形式 | 原因 |
| --- | --- | --- |
| 收集全部结果 | `void` + 外部结果容器 | 不能提前结束 |
| 判断是否存在一个解 | `bool` | 找到后立即短路 |
| 求节点数量/高度/最值 | 数值 | 父节点依赖子问题结果 |
| 构造一棵树 | `TreeNode*` | 返回当前子树根节点 |

## 5. 模型五：构造二叉树 = 确定根 + 划分左右区间

这一阶段第一次真正进入“构造树”。

典型问题：

- 前序 + 中序构造二叉树；
- 后序 + 中序构造二叉树。

整个模型可以压缩成一句话：

> **用前序/后序确定根，用中序确定左右子树的范围。**

例如后序遍历：

```text
左 → 右 → 根
```

因此当前区间的最后一个元素就是根。

中序遍历：

```text
左 → 根 → 右
```

因此根在中序中的位置天然把节点分成左、右两棵子树。

### 5.1 为什么中序特别关键

只有前序与后序时，你能找到根，却通常无法知道剩余节点分别属于左子树还是右子树。

例如：

```text
前序：1 2
后序：2 1
```

可能是：

```text
  1
 /
2
```

也可能是：

```text
1
 \
  2
```

两棵树的前序、后序完全相同。

而中序提供了明确的左右边界。

## 6. 模型六：数组构树优先传区间，不要反复复制数组

典型问题：**最大二叉树**。

其规则是：

```text
区间最大值 → 当前根
最大值左侧 → 左子树
最大值右侧 → 右子树
```

这和“遍历序列构树”有一个完全相同的工程技巧：

```text
不要每层递归创建新的子数组
而是传递原数组的左右下标
```

推荐把区间统一成：

```text
[left, right)
```

那么空区间就是：

```cpp
if (left >= right) return nullptr;
```

不需要额外判断左右区间是否存在。

### 6.1 为什么区间不变量如此重要

假设你约定：

```text
[left, right)
```

那么它在整个递归过程中都必须保持一致。

例如最大值位置为 `maxIndex`：

```text
左子树：[left, maxIndex)
右子树：[maxIndex + 1, right)
```

构造类题最常见的 bug 往往不是递归思想不会，而是：

```text
+1 / -1 写错
根节点被重复放进子区间
漏掉边界节点
空区间终止条件和区间定义不一致
```

因此“先声明区间语义，再写递归”是非常值得形成习惯的做法。

## 7. 把六类题统一成一个递归视角

现在回头看这一阶段的题，可以发现它们并不零散。

所有递归都在回答三个问题：

### 1. 当前函数到底负责什么

例如：

```text
处理以 node 为根的子树
判断当前子树是否存在目标路径
构造某个数组区间对应的子树
```

### 2. 当前层需要哪些状态

可能是：

```text
当前深度
当前路径
剩余目标值
数组左右边界
```

### 3. 子问题返回后，当前层要做什么

可能是：

```text
回溯状态
合并左右结果
短路返回
把返回的子树接到左右孩子
```

一旦这三个问题清楚，大多数二叉树递归都可以自然写出来。

## 8. 一张总表：看到题目特征应该想到什么

| 题目特征 | 优先联想到的模型 |
| --- | --- |
| 根到叶子的路径 | DFS + 路径状态 + 回溯 |
| 找一条满足条件的路径 | `bool` 返回值 + 短路 |
| 找全部满足条件的路径 | 搜完整棵树 + 结果容器 |
| 最左、最右 | 遍历顺序控制优先级 |
| 最大深度处的节点 | 深度状态 + DFS/BFS |
| 当前节点依赖左右结果 | 后序遍历 |
| 根据数组构树 | 区间递归 |
| 给出中序 + 另一遍历 | 根定位 + 中序切割 |
| 节点属性依赖父子关系 | 从父节点观察局部结构 |

## 9. 高频错误清单

<Callout title="写代码前先检查这些点" type="warning">

- 把“叶子节点”误当成“左叶子”；
- 需要寻找一条路径时，没有利用返回值提前结束；
- 路径状态修改后忘记回溯；
- 把深度和高度混为一谈；
- 构造树时区间定义前后不统一；
- 前序/后序中作为根的元素又被递归子区间重复使用；
- 每层递归复制 `vector`，造成没有必要的时间和空间开销；
- 只记某一道题的代码，而没有明确递归函数的语义。

</Callout>

## 10. 阶段总结

这一阶段可以浓缩成四句话：

```text
路径问题：想状态与回溯。
存在性问题：想返回值与短路。
父节点依赖子树：想后序。
构造问题：想根节点与区间切分。
```

如果这些模型已经能够脱离具体题目复述出来，就说明二叉树递归正在从“会模仿代码”进入“能自己设计递归函数”的阶段。
