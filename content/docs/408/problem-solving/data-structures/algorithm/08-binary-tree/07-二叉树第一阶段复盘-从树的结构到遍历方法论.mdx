# 二叉树第一阶段复盘：从树的结构到遍历方法论

到这里，我们已经完成了二叉树学习中最基础、也最重要的一段：

```text
树的结构
  ↓
递归遍历
  ↓
显式栈迭代
  ↓
统一迭代
  ↓
队列层序遍历
  ↓
遍历过程中修改树结构
```

真正应该带走的不是六篇文档里的若干段代码，而是一套稳定的判断流程：

> **先判断问题属于哪类遍历，再明确“什么时候处理节点”，最后选择最自然的数据结构实现。**

<Callout title="阶段目标" type="idea">

学完这一阶段，至少要做到：

- 看见一段遍历代码，能立刻说出它的访问顺序；
- 能独立写出一种递归遍历和一种迭代遍历；
- 能解释 DFS 为什么常用栈、BFS 为什么常用队列；
- 能区分“访问节点”和“处理节点”；
- 当算法会修改 `left/right` 时，知道必须重新检查后续遍历语义。

</Callout>

## 1. 二叉树的最小知识骨架

一棵普通二叉树中，每个节点最多有两个孩子：

```text
        node
       /    \
    left    right
```

典型 C++ 定义：

```cpp title="TreeNode"
struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;

    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};
```

构造函数：

```cpp
TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
```

表示创建节点时同时完成成员初始化。

因此可以直接写：

```cpp
TreeNode* node = new TreeNode(9);
```

而不必再手动逐个赋值。

## 2. 不要把“二叉树”和“二叉搜索树”混为一谈

普通二叉树只限制每个节点最多有两个孩子，并不要求节点值有序。

二叉搜索树（BST）额外满足典型顺序关系：

```text
左子树 < 当前节点 < 右子树
```

更严格地说，这个关系应对整棵左右子树成立，而不仅仅是直接孩子。

平衡搜索树又是在搜索树基础上限制高度，使查找、插入、删除不容易退化成链表。

红黑树属于一种**自平衡二叉搜索树**。很多标准库有序容器会使用红黑树或其他平衡搜索树实现。

<Callout title="概念层级" type="info">

可以把关系粗略理解为：

```text
二叉树
└── 二叉搜索树 BST
    └── 自平衡二叉搜索树
        ├── AVL 树
        └── 红黑树
```

它们不是互相独立的四种概念，而是逐层增加约束。

</Callout>

## 3. 前序、中序、后序到底在区分什么

三个名字描述的并不是“孩子先访问谁”这么简单，而是：

> **当前节点的处理动作，相对于左右子树递归，发生在什么时候。**

| 遍历 | 顺序 | 当前节点何时处理 |
| --- | --- | --- |
| 前序 | 中 → 左 → 右 | 进入节点后立刻处理 |
| 中序 | 左 → 中 → 右 | 左子树完成后处理 |
| 后序 | 左 → 右 → 中 | 两棵子树都完成后处理 |

最小递归模板：

<Tabs groupId="tree-traversal-review" items={['前序', '中序', '后序']}>
<Tab value="前序">

```cpp
void dfs(TreeNode* root) {
    if (root == nullptr) return;

    process(root);
    dfs(root->left);
    dfs(root->right);
}
```

</Tab>
<Tab value="中序">

```cpp
void dfs(TreeNode* root) {
    if (root == nullptr) return;

    dfs(root->left);
    process(root);
    dfs(root->right);
}
```

</Tab>
<Tab value="后序">

```cpp
void dfs(TreeNode* root) {
    if (root == nullptr) return;

    dfs(root->left);
    dfs(root->right);
    process(root);
}
```

</Tab>
</Tabs>

这里真正值得背的是：

```text
process(root) 放在哪里？
```

## 4. 递归三步法必须形成肌肉记忆

面对一棵树的递归题，推荐每次都先回答三件事。

### ① 函数是干什么的？

例如：

```cpp
int getDepth(TreeNode* root)
```

应该先用一句自然语言定义：

```text
返回以 root 为根的子树深度。
```

函数语义一旦清楚，后续递归关系才容易写对。

### ② 什么时候停止？

最常见：

```cpp
if (root == nullptr) return ...;
```

但不同问题的返回值不同：

- 返回深度：空节点返回 `0`；
- 返回布尔值：空节点可能返回 `true`；
- 返回节点：空节点返回 `nullptr`。

### ③ 当前这一层做什么？

只思考：

```text
假设左右子树的答案已经知道，当前节点如何得到自己的答案？
```

这就是树形递归最核心的“相信递归”思想。

## 5. 递归其实就是系统替你维护栈

递归调用：

```cpp
dfs(root->left);
```

系统需要记录：

- 当前函数参数；
- 局部变量；
- 返回地址；
- 下一步继续执行的位置。

这些信息被放进调用栈。

所以“把递归改成迭代”的本质通常不是重新发明算法，而是：

> **把系统隐式维护的调用栈，改成程序员显式维护的 `stack`。**

这也是为什么 DFS 与栈天然契合。

## 6. 迭代前序最容易理解

前序：

```text
中 → 左 → 右
```

因为栈是后进先出，所以压栈顺序要反过来：

```text
先右，后左
```

这样左孩子才会先弹出。

```cpp title="前序迭代核心模板"
vector<int> preorderTraversal(TreeNode* root) {
    vector<int> result;
    if (root == nullptr) return result;

    stack<TreeNode*> st;
    st.push(root);

    while (!st.empty()) {
        TreeNode* node = st.top();
        st.pop();

        result.push_back(node->val);

        if (node->right) st.push(node->right);
        if (node->left) st.push(node->left);
    }

    return result;
}
```

一句话记忆：

```text
想先访问谁，就后压谁。
```

## 7. 为什么中序迭代和前序长得不一样

中序要求：

```text
左 → 中 → 右
```

但是刚遇到节点时还不能处理它，必须先一路深入左边。

因此中序通常写成：

```cpp title="中序迭代核心模板"
while (cur != nullptr || !st.empty()) {
    if (cur != nullptr) {
        st.push(cur);
        cur = cur->left;
    } else {
        cur = st.top();
        st.pop();

        process(cur);
        cur = cur->right;
    }
}
```

这里栈保存的是：

```text
已经到达，但还不能处理，必须等左子树结束的节点。
```

这比机械背模板更重要。

## 8. 后序迭代为什么通常最绕

后序要求：

```text
左 → 右 → 中
```

一个节点必须等**两棵子树都结束**之后才能处理。

所以传统迭代写法需要额外判断：

```text
右子树到底访问过没有？
```

这也是后序比前序、中序更难直接模拟的根本原因。

一个经典简化思路是先构造：

```text
中 → 右 → 左
```

再整体逆序，得到：

```text
左 → 右 → 中
```

这本质上是利用序列的对称性降低实现复杂度。

## 9. 统一迭代法解决的到底是什么问题

传统迭代中：

- 前序比较自然；
- 中序需要 `cur + stack`；
- 后序又是另一套逻辑。

统一迭代法的目标是让三种遍历共享同一种机械框架。

它通过一个“标记”区分：

```text
第一次遇到节点：安排它未来的访问顺序
再次遇到节点：现在真正处理它
```

可以把这个思想理解为：

```text
访问节点 != 处理节点
```

这句话非常重要。

很多树题中，你已经“看见”某个节点，但真正的统计、判断、修改必须等到某个时机才能发生。

## 10. DFS 与 BFS：不是两份模板，而是两种搜索策略

### DFS

典型特点：

```text
沿一条分支尽可能深入，再回溯。
```

常用：

- 递归；
- `stack`。

### BFS

典型特点：

```text
先处理距离当前起点更近的一层，再进入下一层。
```

常用：

- `queue`。

二叉树层序遍历就是 BFS 最标准的实例。

## 11. 层序遍历的核心不是 queue，而是层边界

普通 BFS：

```cpp
while (!q.empty()) {
    TreeNode* node = q.front();
    q.pop();
    ...
}
```

如果题目还需要识别“这一层”，必须在每轮开始时固定：

```cpp
int size = q.size();
```

然后只处理这 `size` 个节点：

```cpp
for (int i = 0; i < size; ++i) {
    ...
}
```

<Callout title="为什么不能直接在循环条件里使用 q.size()？" type="warning">

因为处理当前层时会不断把下一层节点加入队列，`q.size()` 会发生变化。

提前保存 `size`，实际上是在这一刻给队列划出一道边界：

```text
[ 当前层固定的 size 个节点 | 后面新加入的下一层节点 ]
```

</Callout>

## 12. 一套层序模板为什么能解决很多题

只要有当前层的：

```text
size
第 i 个节点
当前层结果 level
```

就能直接派生出很多问题：

| 题型 | 当前层需要做的事情 |
| --- | --- |
| 普通层序 | 收集所有节点 |
| 右视图 | 取 `i == size - 1` |
| 层平均值 | 求和后除以 `size` |
| 每层最大值 | 维护本层最大值 |
| 最大深度 | 每完成一层 `depth++` |
| 最小深度 | 第一次遇到叶子时返回层数 |

所以层序遍历应当学成一个**框架**，而不是六七道互不相关的题。

## 13. 翻转二叉树第一次引入“修改结构”的风险

前面的遍历主要是：

```text
读节点
```

翻转二叉树开始变成：

```text
改节点的 left / right
```

局部操作只有：

```cpp
swap(node->left, node->right);
```

但它带来了一个非常重要的规律：

> **只要遍历过程中修改了树结构，就必须重新确认后续访问的指针是否仍表示原来的子树。**

这就是普通递归中序在翻转二叉树中容易出错的原因。

原本：

```text
left = L
right = R
```

执行交换后：

```text
left = R
right = L
```

如果还机械地“递归 right”，就可能再次进入已经处理过的原左子树。

## 14. 翻转二叉树把前六篇串在了一起

翻转二叉树可以用：

- 前序递归；
- 后序递归；
- 显式栈 DFS；
- 统一迭代法；
- 队列 BFS。

为什么这么多方法都能做？

因为题目真正要求的只有：

```text
每个非空节点恰好执行一次左右孩子交换。
```

只要一种遍历能够覆盖所有节点，而且修改结构不会破坏待访问集合，它就可以完成任务。

这个结论比背任何一种写法都更有价值。

## 15. 递归和迭代到底怎么选

不要简单理解成“递归一定差”或“迭代一定好”。

### 递归的优势

- 与树的递归定义高度一致；
- 代码短；
- 正确性更容易证明；
- 面试中通常更快写出。

### 递归的风险

当树高度很大时，调用栈深度可能达到：

$$
O(h)
$$

极端链状树中：

$$
h = n
$$

此时可能触发栈溢出。

### 迭代的优势

- 显式控制内存；
- 不依赖语言调用栈深度；
- 更适合需要精细控制遍历状态的问题。

### 实战建议

```text
先用最自然的方法保证正确
        ↓
再根据深度、性能、工程限制考虑是否改迭代
```

算法题里，递归通常是理解树问题最重要的基础能力之一。

## 16. Morris 遍历：知道它解决什么即可

普通递归或显式栈遍历通常需要额外的栈空间。

Morris Traversal 会临时利用树中的空指针建立“线索”，从而在某些遍历中把额外空间降低到：

$$
O(1)
$$

它的价值主要在于：

```text
不用递归
不用显式栈
仍能完成遍历
```

但实现明显更复杂，而且会临时修改树结构。

当前阶段不建议把 Morris 当主模板。先把递归、普通迭代、统一迭代和层序遍历真正掌握，再把 Morris 当作进阶内容。

## 17. 高频易错点总表

| 易错点 | 根本原因 | 修正方式 |
| --- | --- | --- |
| 前序压栈先左后右，结果顺序反了 | 忘记栈是 LIFO | 想先访问谁，就后压谁 |
| 中序刚到节点就处理 | 没理解“左子树必须先完成” | 栈保存待处理祖先 |
| 层序把下一层混入当前层 | `q.size()` 在变化 | 每层开始先固定 `size` |
| 最小深度遇到单个空孩子就返回 | 叶子定义错误 | 左右孩子都空才是叶子 |
| 翻转树中序递归重复处理 | 交换后指针含义变了 | 修改结构后重新确认后继 |
| 会递归但不会迭代 | 只背代码，没有理解调用栈 | 手动模拟一次递归栈 |
| 能 AC 但说不出遍历顺序 | 节点处理时机不清楚 | 每次标注“中/左/右” |

## 18. 第一阶段必须手写出的模板

建议至少在不看资料的情况下写出下面四种。

### ① 递归遍历

```cpp
void dfs(TreeNode* root) {
    if (root == nullptr) return;
    // process(root) 放在不同位置决定前 / 中 / 后序
}
```

### ② 前序显式栈

```cpp
stack<TreeNode*> st;
st.push(root);

while (!st.empty()) {
    TreeNode* node = st.top();
    st.pop();

    process(node);
    if (node->right) st.push(node->right);
    if (node->left) st.push(node->left);
}
```

### ③ 中序显式栈

```cpp
TreeNode* cur = root;
stack<TreeNode*> st;

while (cur != nullptr || !st.empty()) {
    if (cur != nullptr) {
        st.push(cur);
        cur = cur->left;
    } else {
        cur = st.top();
        st.pop();
        process(cur);
        cur = cur->right;
    }
}
```

### ④ 按层 BFS

```cpp
queue<TreeNode*> q;
q.push(root);

while (!q.empty()) {
    int size = q.size();

    for (int i = 0; i < size; ++i) {
        TreeNode* node = q.front();
        q.pop();

        process(node);
        if (node->left) q.push(node->left);
        if (node->right) q.push(node->right);
    }
}
```

## 19. 做树题时的标准决策流程

可以把下面这套流程真正固定下来：

```text
① 题目是在“收集信息”，还是“修改结构”？
        ↓
② 当前节点的信息依赖子树结果吗？
        ↓
③ process 应该发生在进入节点、左子树后，还是两棵子树后？
        ↓
④ 需要深度优先，还是逐层信息？
        ↓
⑤ DFS：递归还是显式栈？
   BFS：是否需要固定层 size？
        ↓
⑥ 如果修改 left/right，后续指针含义是否变化？
        ↓
⑦ 最后再写代码和复杂度
```

<Callout title="最重要的转变" type="success">

从现在开始，不要再把树题理解成：

```text
“我应该套哪个模板？”
```

而要改成：

```text
“我什么时候需要当前节点的信息？
我需要保存哪些尚未完成的状态？”
```

当这两个问题能回答清楚时，递归、栈和队列只是实现手段。

</Callout>

## 20. 自测清单

完成这一阶段后，可以用下面的问题检验自己是否真的掌握。

- 为什么前序迭代要先压右孩子？
- 中序迭代中的栈到底保存了什么？
- 为什么后序比前序更难直接迭代？
- 统一迭代法为什么需要“标记”？
- 为什么 BFS 天然使用队列？
- 为什么按层 BFS 必须提前保存 `size`？
- 为什么翻转二叉树前序和后序都可以？
- 为什么直接套递归中序会出错？
- 修改 `left/right` 后，为什么必须重新检查遍历顺序？
- 递归的额外空间为什么通常与树高 $h$ 有关？

如果这些问题都能不看代码解释清楚，说明二叉树遍历已经不再是“模板记忆”，而开始变成真正可迁移的算法能力。

## 21. 下一阶段会进入什么

接下来通常会从“遍历框架”进入“利用递归返回值解决性质问题”，例如：

```text
对称二叉树
最大深度 / 最小深度
完全二叉树节点个数
平衡二叉树
二叉树所有路径
路径总和
```

这些题会越来越强调：

```text
当前节点如何利用左右子树的结果，得到自己的结果？
```

也就是从“会遍历”进一步走向“会设计树形递归”。
