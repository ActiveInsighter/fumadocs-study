# 二叉树第二阶段复盘：从“遍历”走向“递归状态设计”

前一阶段解决的是：**如何遍历一棵二叉树**。

这一阶段更进一步，开始解决：

> **遍历到一个节点以后，到底应该计算什么、返回什么、维护什么状态？**

从 [对称二叉树](./08-对称二叉树-把“一棵树”转化为“两棵树的镜像比较”) 到 [二叉树的所有路径](./13-二叉树的所有路径-从递归遍历真正理解回溯)，题目表面差异很大，但背后可以归纳成几类非常稳定的递归模型：

```text
比较两个位置        → 双指针递归
向下寻找最优路径    → 深度 / BFS
从子树收集信息      → 后序遍历
利用树的结构性质    → 剪枝 / 数学优化
维护根到当前节点状态 → 前序 + 回溯
```

<Callout title="这一阶段最重要的变化" type="idea">

不要再把二叉树题理解成“背前序、中序、后序模板”。

真正成熟的做法是：

1. 先定义递归函数的**语义**；
2. 再判断当前节点需要的是“父节点传下来的信息”，还是“左右子树返回的信息”；
3. 最后由信息流方向决定遍历方式。

</Callout>


## 2. 对称二叉树：递归对象不一定只有一个节点

在普通遍历中，我们常写：

```cpp
void dfs(TreeNode* node)
```

但判断对称时，真正需要比较的是**两个位置**：

```cpp
bool compare(TreeNode* left, TreeNode* right)
```

这带来一个重要认知：

> 递归函数的参数，应由“当前子问题需要什么状态”决定，而不是机械地永远只传一个 `root`。

对称二叉树比较的是镜像位置：

```text
左子树的左孩子  ↔  右子树的右孩子
左子树的右孩子  ↔  右子树的左孩子
```

即：

$$
compare(L,R)
=
compare(L.left,R.right)
\land
compare(L.right,R.left)
$$

当然，在递归之前还要先处理空节点和值不相等的情况。

### 2.1 从对称树自然迁移到相同的树

LeetCode 100「相同的树」只需把镜像对应改成同侧对应：

$$
compare(p,q)
=
compare(p.left,q.left)
\land
compare(p.right,q.right)
$$

```cpp title="相同的树"
bool isSameTree(TreeNode* p, TreeNode* q) {
    if (p == nullptr && q == nullptr) return true;
    if (p == nullptr || q == nullptr) return false;
    if (p->val != q->val) return false;

    return isSameTree(p->left, q->left)
        && isSameTree(p->right, q->right);
}
```

于是可以看到：

| 问题 | 左侧递归 | 右侧递归 |
| --- | --- | --- |
| 对称二叉树 | `left->left` 对 `right->right` | `left->right` 对 `right->left` |
| 相同的树 | `p->left` 对 `q->left` | `p->right` 对 `q->right` |

这两题真正区别的不是“递归写法”，而是**节点之间的对应关系**。

## 3. 最大深度：前序求深度，后序求高度

这是二叉树里非常重要的一组概念。

### 3.1 深度是什么

某节点的深度描述：

```text
根节点 → 当前节点
```

也就是信息从父节点向子节点传递。

因此，如果在递归参数里携带当前深度：

```cpp
void dfs(TreeNode* node, int depth)
```

那么这是典型的**前序思维**。

```cpp
void getDepth(TreeNode* node, int depth) {
    if (node == nullptr) return;

    result = max(result, depth);  // 当前节点先处理
    getDepth(node->left, depth + 1);
    getDepth(node->right, depth + 1);
}
```

### 3.2 高度是什么

某节点的高度描述：

```text
当前节点 → 最深叶子节点
```

当前节点自己的高度必须等左右孩子的高度算完以后才能得到：

$$
H(u)=1+\max(H(u.left),H(u.right))
$$

因此这是天然的**后序思维**：

```cpp
int getHeight(TreeNode* node) {
    if (node == nullptr) return 0;

    int left = getHeight(node->left);
    int right = getHeight(node->right);

    return 1 + max(left, right);
}
```

而根节点的高度恰好等于整棵树的最大深度。

<Callout title="判断前序还是后序的实用问题" type="info">

问自己一句：

- “答案是父节点告诉孩子的吗？” → 更像前序；
- “答案是孩子算完以后告诉父节点的吗？” → 更像后序。

这比死记遍历顺序更有用。

</Callout>

## 4. 最小深度：`min` 不是把 `max` 换掉那么简单

最大深度可以直接写：

$$
1+\max(L,R)
$$

但最小深度不能无条件写成：

$$
1+\min(L,R)
$$

原因是题目要求终点必须是**叶子节点**。

例如：

```text
    1
     \
      2
       \
        3
```

根节点左子树为空，因此：

```text
leftDepth = 0
rightDepth = 2
```

如果直接取：

```text
min(0, 2) + 1 = 1
```

就错误地把“没有路径”当成了“长度为 0 的有效叶子路径”。

正确递推应分情况：

$$
D(u)=
\begin{cases}
1, & u\text{ 是叶子}\cr
1+D(u.right), & u.left=\varnothing\cr
1+D(u.left), & u.right=\varnothing\cr
1+\min(D(u.left),D(u.right)), & \text{左右孩子都存在}
\end{cases}
$$

这类错误背后有一个非常通用的教训：

> **数值 `0` 有时代表一个合法答案，有时代表“这个分支不存在”。合并子问题之前，一定要搞清返回值的语义。**

## 5. 完全二叉树节点数：算法优化来自“识别特殊结构”

普通二叉树统计节点最直接：

$$
N(u)=1+N(u.left)+N(u.right)
$$

时间复杂度是：

$$
O(n)
$$

但完全二叉树额外具有结构性质。

从一个节点分别沿：

```text
一直向左
一直向右
```

若得到的高度相同，则该子树一定是满二叉树。

假设高度按节点数计为 $h$，满二叉树节点数为：

$$
2^h-1
$$

于是可以直接返回，不再继续递归整棵子树。

```cpp
int countNodes(TreeNode* root) {
    if (root == nullptr) return 0;

    TreeNode* left = root->left;
    TreeNode* right = root->right;
    int leftDepth = 0;
    int rightDepth = 0;

    while (left != nullptr) {
        left = left->left;
        ++leftDepth;
    }

    while (right != nullptr) {
        right = right->right;
        ++rightDepth;
    }

    if (leftDepth == rightDepth) {
        return (2 << leftDepth) - 1;
    }

    return 1 + countNodes(root->left) + countNodes(root->right);
}
```

这里真正应该学习的是：

> 当输入对象有额外结构约束时，不要只把它当成普通对象暴力处理。

完全二叉树、二叉搜索树、平衡树等题目，优化往往就来自这些结构性质。

## 6. 平衡二叉树：后序遍历 + 失败状态向上传播

判断平衡树时，每个节点需要知道左右子树高度：

$$
|H_L-H_R|\le 1
$$

所以应该先得到：

```text
左子树高度
右子树高度
```

再判断当前节点。

这天然是后序遍历。

更巧妙的是，我们可以用一个特殊值表示：

```text
这棵子树已经不平衡
```

例如用 `-1`：

```cpp
int getHeight(TreeNode* node) {
    if (node == nullptr) return 0;

    int left = getHeight(node->left);
    if (left == -1) return -1;

    int right = getHeight(node->right);
    if (right == -1) return -1;

    if (abs(left - right) > 1) return -1;

    return 1 + max(left, right);
}
```

于是 `-1` 不再只是一个数字，而是一个**状态信号**。

### 6.1 为什么这种写法很重要

递归返回值可以同时承担两种职责：

```text
正常情况 → 返回高度
异常情况 → 返回失败标记
```

这是一种非常常见的递归设计：

```text
把状态封装进返回值，逐层向上传播
```

以后会在：

- 验证 BST；
- 最近公共祖先；
- 路径搜索；
- 图搜索剪枝；

等问题中反复遇到。

## 7. 二叉树所有路径：第一次真正看见“递归状态”

求根到叶子的所有路径时，单纯知道当前节点不够。

还需要维护：

```text
从根到当前节点走过的路径
```

例如：

```text
        1
       / \
      2   3
       \
        5
```

访问 `5` 时：

```text
path = [1, 2, 5]
```

如果 `path` 是共享可变数组，那么向下搜索与返回上一层必须成对出现：

```cpp
path.push_back(child->val);
traversal(child, path, result);
path.pop_back();
```

也就是：

```text
做选择
  ↓
递归
  ↓
撤销选择
```

这就是回溯最核心的结构。

<Callout title="递归与回溯的关系" type="warning">

递归是一种控制流程；回溯是一种状态恢复策略。

不是所有递归都需要显式回溯，但只要多个递归分支共享并修改同一份状态，就必须认真考虑如何恢复状态。

</Callout>

## 8. 为什么“短代码”有时反而不适合学习

下面这段代码非常简洁：

```cpp
int maxDepth(TreeNode* root) {
    if (root == nullptr) return 0;
    return 1 + max(maxDepth(root->left), maxDepth(root->right));
}
```

但如果还没有建立递归语义，它会掩盖三件事：

```text
maxDepth(root) 到底代表什么？
为什么一定要先算左右子树？
为什么这里对应后序思想？
```

因此学习阶段建议遵循：

```text
先写展开版
    ↓
明确每个变量语义
    ↓
确认遍历顺序
    ↓
最后再压缩代码
```

代码越短，不代表越容易理解。

## 9. 栈还是队列：不要靠题目名字判断

### 栈

更适合：

- DFS；
- 模拟前中后序；
- 需要沿一条分支不断深入的问题。

### 队列

更适合：

- BFS；
- 层序遍历；
- 求离根最近的满足条件节点；
- 按层统计。

但“用了队列”不等于“一定是层序遍历”。

例如对称二叉树迭代法可以把两个待比较节点成对压入队列。此时队列只是一个**待处理任务容器**，并没有“逐层处理”的语义。

判断是不是层序遍历，关键要看：

```text
算法是否显式维护同一层的边界？
```

典型代码是：

```cpp
int size = queue.size();
while (size--) {
    ...
}
```

## 10. 一套可迁移的二叉树分析流程

面对新题，不妨固定按下面的顺序思考。

<h3>先写一句话定义递归函数</h3>
    例如：“返回以 `root` 为根的子树高度”或“判断 `p` 与 `q` 两棵子树是否相同”。
  <h3>确定当前节点需要哪些信息</h3>
    是父节点传来的深度、路径，还是左右子树返回的高度、数量、真假状态？
  <h3>确定空节点返回什么</h3>
    `0`、`true`、`false`、`nullptr`、`-1` 的语义必须明确。
  <h3>写出递推关系</h3>
    先用自然语言或数学式写清“左右子问题的答案如何组成当前答案”。
  <h3>再决定遍历顺序</h3>
    父传子通常偏前序，子传父通常偏后序，需要最近层则考虑 BFS。
  <h3>最后考虑剪枝和结构性质</h3>
    是否能提前结束？是否是完全二叉树、BST 等特殊结构？
  ## 11. 高频易错点总表

| 易错点 | 错误直觉 | 正确理解 |
| --- | --- | --- |
| 对称二叉树 | 比较左子树和右子树是否“相同” | 比较的是镜像位置 |
| 最大深度 | 深度、高度完全一样 | 根节点处数值可相同，但信息方向不同 |
| 最小深度 | 直接 `min(left,right)+1` | 空孩子不是有效叶子路径 |
| 完全二叉树节点数 | 所有树只能 $O(n)$ 遍历 | 可利用满二叉树结构剪枝 |
| 平衡二叉树 | 每个节点反复单独求高度 | 后序一次返回高度并传播失败状态 |
| 所有路径 | DFS 自动等于回溯 | 共享状态修改后必须恢复 |
| 队列 | 使用队列就是层序遍历 | 容器和遍历语义不是一回事 |

## 12. 把几道题统一成“信息流”

这一阶段最值得建立的最终视角是：

```text
对称二叉树
两个节点之间横向比较

最大深度（前序）
depth 从父节点向孩子传

最大深度（后序）/ 平衡树
height 从孩子向父节点传

完全二叉树节点数
子树规模向父节点传，并利用结构剪枝

所有路径
path 随递归向下扩展，回退时恢复
```

所以二叉树递归，本质上是在设计：

$$
\text{状态如何沿树的边传播}
$$

只要把信息流搞清楚，很多题目的遍历顺序会自然确定。

## 13. 阶段自测

在继续下一组题之前，建议确保自己能独立回答：

- 为什么对称二叉树需要同时递归两个节点？
- 为什么最大深度既能用前序也能用后序？
- 为什么最小深度不能直接使用 `min(left, right)`？
- 为什么平衡二叉树更适合后序？
- `-1` 在平衡树递归中为什么可以充当失败标记？
- 完全二叉树为什么能够比普通二叉树更快统计节点？
- 什么情况下递归必须配合回溯？
- 为什么“使用队列”和“层序遍历”不是同一个概念？

如果这些问题都能不看代码解释清楚，那么你已经从“会套遍历模板”进入了“会设计树形递归”的阶段。
