# 二叉树总结：从遍历顺序到 BST 的完整解题框架

二叉树专题真正需要掌握的，不是把几十道题的代码分别背下来，而是形成一套可以迁移到新题的判断流程：

```text
先判断树有没有特殊性质
→ 再判断问题需要“向下传信息”还是“向上收集信息”
→ 决定 DFS / BFS
→ 决定前序 / 中序 / 后序
→ 最后才写递归参数、返回值和终止条件
```

学完整个专题以后，看到一道新题，应该能够先判断它属于哪种模型，再从模型中推出实现，而不是从记忆里搜索某段代码。

<Callout title="这一章最终只需要沉淀四个核心模型" type="success">

1. **遍历模型**：前序、中序、后序、层序分别在什么时候使用。
2. **递归模型**：当前节点需要什么信息，又应该向父节点返回什么信息。
3. **结构模型**：构造、修改、路径、公共祖先，本质都是“当前节点与左右子树如何协作”。
4. **BST 模型**：利用大小关系剪枝，或利用中序遍历得到有序序列。

只要这四个模型足够熟练，大多数二叉树题都能从原理推导出来。

</Callout>

## 1. 第一原则：先问“当前节点什么时候处理”

所谓前序、中序、后序，本质上并不是三个需要死记的模板，而是：

> **当前节点的处理动作，发生在两个递归调用的什么位置。**

<Cards>
  <Card title="前序：中 → 左 → 右">当前节点先做决定，再把结果或约束传给孩子。</Card>
  <Card title="中序：左 → 中 → 右">当前节点夹在左右子树之间处理，BST 中尤其重要。</Card>
  <Card title="后序：左 → 右 → 中">先得到左右子树答案，再在当前节点汇总。</Card>
  <Card title="层序：一层一层处理">问题天然与“层、距离、最先到达”有关时优先考虑 BFS。</Card>
</Cards>

这比“某题固定属于某种遍历”更重要，因为同一道题经常可以有不止一种实现。

### 1.1 什么时候自然想到前序

如果当前节点要先做事情，再进入孩子，前序往往最顺手。

典型场景：

- 翻转二叉树：先交换当前节点左右孩子；
- 构造二叉树：先确定当前根，再构造左右子树；
- 路径搜索：进入节点时把当前节点加入路径；
- 向下传递深度、路径和、区间等状态。

可以把它理解为：

```text
父节点先产生状态
↓
状态继续传向子节点
```

### 1.2 什么时候自然想到后序

如果当前节点的答案依赖左右子树的答案，就应该先递归，再处理当前节点。

典型场景：

- 最大深度 / 节点高度；
- 最小深度；
- 平衡二叉树；
- 节点数量；
- 最近公共祖先；
- 各种“左右子树返回信息，然后当前节点合并”的问题。

抽象成公式就是：

```text
left = solve(node.left)
right = solve(node.right)
answer = merge(left, right, node)
```

这就是后序遍历最本质的结构。

### 1.3 什么时候自然想到中序

普通二叉树中，中序只是三种 DFS 顺序之一；但在 BST 中，它拥有特殊意义：

```text
BST + 中序遍历 = 有序序列
```

因此下面这些问题几乎都可以先把 BST 想象成一个有序数组：

- 验证 BST；
- 最小绝对差；
- 众数；
- 第 $k$ 小元素；
- 两节点差值；
- 累加树。

<Callout title="BST 的条件反射" type="idea">

看到二叉搜索树，先同时想两个视角：

```text
方向性：目标比当前值小 → 只走左边；比当前值大 → 只走右边
有序性：中序遍历 → 从小到大；反向中序 → 从大到小
```

很多 BST 题的最优解都来自这两个性质，而不是来自更复杂的数据结构。

</Callout>

## 2. 第二原则：分清“深度”和“高度”

这是二叉树递归中最容易混淆、却又极其重要的一组概念。

### 深度

一个节点的深度强调：

```text
根节点 → 当前节点
```

因此更适合**从上向下**传递。

例如：

```cpp
traversal(node, depth)
```

进入下一层时：

```cpp
depth + 1
```

这类写法天然接近前序遍历与回溯。

### 高度

一个节点的高度强调：

```text
当前节点 → 最远叶子
```

当前节点必须先知道左右子树的高度：

```text
leftHeight
rightHeight
```

再计算：

```text
height = max(leftHeight, rightHeight) + 1
```

因此高度天然适合后序遍历。

### 深度

关注“从根走到这里有多远”。

```text
根
↓
父节点把 depth 传给子节点
↓
当前节点使用 depth
```

常见写法：前序 + 回溯。

### 高度

关注“从这里向下还能走多远”。

```text
左子树返回高度 ┐
               ├→ 当前节点计算自己的高度
右子树返回高度 ┘
```

常见写法：后序 + 返回值。

最大深度之所以既能用前序也能用后序，是因为：

> 根节点的高度，数值上就等于整棵树的最大深度。

但“平衡二叉树”必须频繁比较子树高度，因此后序模型更加自然。

## 3. 第三原则：递归函数到底应该“返回什么”

很多人写二叉树递归时，最难的不是终止条件，而是不知道函数应该返回 `void`、`bool`、整数、节点指针，还是别的状态。

一个很实用的判断方式是：

> **父节点需要从当前子树得到什么信息？**

| 父节点需要的信息 | 常见返回值 | 典型问题 |
| --- | --- | --- |
| 什么也不需要，只想遍历 | `void` | 遍历、路径收集 |
| 是否找到目标 | `bool` | 路径总和、搜索 |
| 子树高度 | `int` | 最大深度、平衡树 |
| 子树节点数量 | `int` | 统计节点 |
| 修改后的子树根 | `TreeNode*` | 插入、删除、修剪 |
| 子树中找到的目标节点 | `TreeNode*` | 最近公共祖先 |

这张表比背每一道题的代码更值得记忆。

### 3.1 返回 `bool`：通常意味着可以短路

例如判断是否存在一条满足条件的路径：

```text
左子树找到 → 直接返回 true
右子树找到 → 直接返回 true
都没找到 → false
```

此时我们只需要**找到一条成功路径**，不需要完整遍历整棵树。

### 3.2 返回节点指针：常常意味着“递归结果就是新结构”

BST 的插入、删除、修剪都大量使用：

```cpp
node->left = recursion(node->left);
node->right = recursion(node->right);
return node;
```

这里返回值并不是附属信息，而是：

> **这棵子树经过操作以后，新的根节点是谁。**

理解这一点以后，删除节点与修剪 BST 会清晰很多。

## 4. DFS 与 BFS：不要把所有树题都强行递归

二叉树常见遍历方式可以从数据结构角度统一理解：

```text
DFS → 栈
BFS → 队列
```

递归调用栈本质上也是栈，所以递归 DFS 与显式栈 DFS 在思想上是一致的。

### 4.1 更适合 DFS 的题

- 子树高度；
- 路径搜索；
- 构造树；
- 修改树；
- BST 中序题；
- 最近公共祖先。

### 4.2 更适合 BFS 的题

只要题目明显围绕“层”，优先想到队列：

- 层序遍历；
- 每层最大值；
- 每层平均值；
- 右视图；
- 最小深度；
- 最底层最左值。

BFS 的核心模板只有一个关键点：

```cpp
int size = queue.size();
```

必须在处理当前层之前固定本层节点数。之后循环 `size` 次，才能准确区分层与层。

## 5. 普通二叉树属性题：优先寻找“左右子树返回值”

这一类题可以看成一个统一模型：

```text
当前节点答案
= f(左子树答案, 右子树答案, 当前节点信息)
```

### 5.1 最大深度

```text
max(leftHeight, rightHeight) + 1
```

### 5.2 节点个数

```text
leftCount + rightCount + 1
```

### 5.3 是否平衡

先得到：

```text
leftHeight
rightHeight
```

如果：

```text
|leftHeight - rightHeight| > 1
```

当前子树就不平衡。

为了避免重复计算，通常用一个特殊返回值（例如 `-1`）表示“这棵子树已经不平衡”，让失败状态直接向上传播。

### 5.4 最小深度为什么不能直接套 `min`

这是整个二叉树专题最值得反复复习的边界问题之一。

如果一个节点只有左孩子：

```text
    1
   /
  2
```

右边空节点返回深度 `0`，但根节点到这个空指针并不是“根到叶子的合法路径”。

因此不能写成：

```text
min(leftDepth, rightDepth) + 1
```

必须先排除空子树对应的非法候选路径。

<Callout title="属性题真正的难点通常不在递推公式" type="warning">

很多错误不是 `max`、`min`、加法写错，而是：

> **把一个不符合题目定义的分支也当成了合法候选。**

所以写递推式之前，要先确认“哪些结果有资格参与比较”。

</Callout>

## 6. 路径问题：递归与回溯其实是一体的

只要题目要求：

```text
根 → 某个节点
或
根 → 叶子
```

就应该立刻想到“路径状态”。

典型模式：

进入当前节点，把它加入路径或累计状态。

如果到达目标位置，处理当前完整路径。

递归进入孩子。

返回父节点之前，撤销当前节点造成的状态修改。

例如：

```cpp
path.push_back(node->val);
traversal(node->left);
traversal(node->right);
path.pop_back();
```

这里的 `pop_back()` 就是回溯。

因此：

> **回溯不是一种突然出现的新算法，而是 DFS 在共享状态上的“恢复现场”。**

这也为后面的回溯算法专题做好了铺垫。

## 7. 构造二叉树：先确定根，再切分左右问题

构造类问题通常都是前序思维：

```text
先构造当前节点
→ 再递归构造左子树
→ 再递归构造右子树
```

典型题目包括：

- 中序 + 后序构造二叉树；
- 前序 + 中序构造二叉树；
- 最大二叉树；
- 有序数组构造平衡 BST。

这些题虽然题面不同，但结构几乎完全相同：

```text
1. 找当前根
2. 找分割点
3. 切左区间
4. 切右区间
5. 递归构造
```

真正容易出错的通常是区间边界。

<Callout title="构造题的边界纪律" type="info">

如果决定使用左闭右开区间 `[left, right)`，就从头到尾都坚持左闭右开；如果使用左闭右闭 `[left, right]`，也必须始终一致。

绝大多数构造题的 bug，本质上都是“区间定义变了但自己没发现”。

</Callout>

## 8. 修改二叉树：返回值往往比原地操作更重要

### 翻转二叉树

只需要访问每个节点并交换左右孩子：

```text
swap(left, right)
```

重点是确认交换动作不会让后续遍历漏掉节点。

### 合并二叉树

递归状态从：

```text
一个节点
```

扩展为：

```text
一对节点
```

这类“同时操作两棵树”的模式还会用于：

- 判断两棵树是否相同；
- 镜像比较；
- 子树匹配。

### BST 插入、删除、修剪

这些题最值得记住的写法是：

```cpp
node->left = operation(node->left);
node->right = operation(node->right);
return node;
```

因为递归调用返回的是：

> **操作完成以后，这个位置应该挂上的新子树根节点。**

一旦接受这种视角，删除与修剪就不再需要手动维护复杂的父指针。

## 9. BST 第一大武器：利用大小关系只走一边

普通二叉树没有顺序性质，所以查找一个值最坏要访问所有节点，时间复杂度为 $O(n)$。

BST 中，若目标值为 `target`：

```text
target < node.val → 左子树
target > node.val → 右子树
target = node.val → 找到
```

因此搜索路径只会向一个方向继续。

若 BST 高度为 $h$，搜索、插入等操作通常为：

$$
O(h)
$$

平衡 BST 中：

$$
h=O(\log n)
$$

最坏退化为链表时：

$$
h=O(n)
$$

这说明 BST 的性能关键不只是“它是搜索树”，还取决于**树高是否健康**。

## 10. BST 第二大武器：中序遍历把树在线变成有序数组

这是 BST 题最重要的统一视角。

假设中序遍历得到：

```text
[a1, a2, a3, ..., an]
```

满足：

```text
a1 < a2 < a3 < ... < an
```

于是很多树问题可以直接转化为数组问题。

| BST 问题 | 等价的有序数组问题 |
| --- | --- |
| 验证 BST | 是否严格递增 |
| 最小绝对差 | 相邻元素最小差 |
| 众数 | 连续相同值计数 |
| 第 $k$ 小 | 有序序列第 $k$ 项 |
| 累加树 | 从右向左做后缀和 |

### `pre` 指针为什么高频出现

中序遍历时维护：

```cpp
TreeNode* pre = nullptr;
```

那么 `pre` 就是有序序列中的前一个元素。

因此很多问题只需要处理相邻关系：

```text
pre ↔ cur
```

不需要真的把整棵树存进数组。

空间上也就从显式保存 $O(n)$ 个元素，变成只保存遍历栈和常数状态。

## 11. 反向中序：BST 不只能从小到大

普通中序：

```text
左 → 中 → 右
```

得到：

```text
小 → 大
```

反向中序：

```text
右 → 中 → 左
```

得到：

```text
大 → 小
```

累加树就是最典型的例子。

维护累加和：

```text
sum = 已经访问过的所有更大节点值之和
```

每访问当前节点：

```text
sum += node.val
node.val = sum
```

所以这道题本质不是“神奇地修改一棵树”，而是：

> **对 BST 的有序序列从右向左做后缀累加。**

## 12. 最近公共祖先：普通树与 BST 要分开看

### 12.1 普通二叉树 LCA：左右子树向上汇报

对当前节点：

```text
左子树找到目标 → left != null
右子树找到目标 → right != null
```

如果：

```text
left != null && right != null
```

说明两个目标分别位于当前节点两侧，当前节点就是最近公共祖先。

这是后序遍历“左右信息汇合”的代表题。

### 12.2 BST LCA：利用区间方向

设两个目标值排序后为：

```text
[p, q]，p <= q
```

当前节点为 `x`：

```text
x < p → 两个目标都在右边
x > q → 两个目标都在左边
p <= x <= q → 当前节点就是分叉点
```

所以 BST 版本不需要把整棵树都搜索一遍。

<Callout title="同一个题型，树的性质可能彻底改变解法" type="success">

普通二叉树 LCA 的关键是**后序汇报**；BST LCA 的关键是**有序区间定位**。

做题前先识别树的性质，往往比选择遍历模板更重要。

</Callout>

## 13. 完全二叉树：特殊结构可以带来更快的计数

普通二叉树统计节点数需要访问每个节点：

$$
O(n)
$$

完全二叉树则可以利用满二叉树结构。

如果从当前节点一路向左得到深度 `leftDepth`，一路向右得到深度 `rightDepth`，并且：

```text
leftDepth == rightDepth
```

当前子树一定是满二叉树。

高度为 $h$ 的满二叉树节点数为：

$$
2^h-1
$$

于是可以直接计算，不再继续遍历这棵满子树。

这道题提供了一个非常重要的思维：

> **如果输入结构比普通情况更强，就应该主动寻找能否利用这些额外条件剪枝或直接计算。**

## 14. 一张决策表：拿到新题先怎么判断

| 题目特征 | 第一反应 | 常见实现 |
| --- | --- | --- |
| 问“每一层” | BFS | 队列 + 固定本层 `size` |
| 问子树高度/数量/状态 | 后序 | 左右返回结果后合并 |
| 问根到叶子的路径 | 前序 + 回溯 | 向下传路径状态 |
| 构造一棵树 | 前序思维 | 先建根，再递归左右 |
| 修改后可能换根 | 返回 `TreeNode*` | 接住递归返回的新子树根 |
| BST 查找/插入/LCA | 比较大小 | 每次只走一个方向 |
| BST 验证/差值/众数 | 中序 | 看成有序序列 |
| BST 累加类 | 反向中序 | 从大到小维护累计状态 |
| 两棵树比较/合并 | 双节点递归 | `solve(node1, node2)` |
| 两目标从子树汇合 | 后序 | LCA 模型 |

## 15. 一套真正可执行的“二叉树解题流程”

### 第一步：识别树的性质

先确认它是：

```text
普通二叉树 / 完全二叉树 / 二叉搜索树 / 平衡树 / 其他特殊树
```

不要浪费题目给出的结构条件。

### 第二步：明确递归函数的语义

不要先写代码。先用一句中文定义：

> `solve(node)` 到底表示什么？

例如：

```text
返回以 node 为根的子树高度
返回修剪后子树的新根
返回当前子树中找到的目标节点
```

### 第三步：确定父节点需要什么返回值

父节点如果需要子树结果，就设计返回值；如果只需要遍历并修改全局状态，可以使用 `void`。

### 第四步：写清终止条件

常见是：

```text
node == null
```

但不要机械返回 `0` 或 `false`，必须确认这个值在当前问题语义里是否合理。

### 第五步：决定当前节点的处理时机

```text
先处理当前节点 → 前序倾向
左右回来后处理 → 后序倾向
BST 有序问题 → 中序倾向
按层处理 → BFS
```

### 第六步：检查状态是否需要回溯

如果进入孩子前修改了一个共享状态：

```text
path
sum
count
```

回到父节点以后是否需要恢复？

### 第七步：最后再考虑迭代写法和复杂度

先保证模型正确，再决定是否使用栈、队列或其他优化。

## 16. 高频错误清单

<Accordions type="multiple">
<Accordion title="错误 1：只比较父子节点来验证 BST">

BST 是全局约束，不是局部约束。

一个右子树深处的节点也必须大于祖先节点。最稳定的做法是中序递增检查，或者递归传递合法上下界。

</Accordion>
<Accordion title="错误 2：最小深度直接写 min(left, right) + 1">

空子树并不代表合法的根到叶子路径。只有真正到达叶子节点的路径才参与最小值比较。

</Accordion>
<Accordion title="错误 3：路径题 push 以后忘记 pop">

如果 `path` 是共享容器，返回父节点前必须恢复现场，否则兄弟分支会继承错误状态。

</Accordion>
<Accordion title="错误 4：构造题区间规则前后不一致">

`[left, right]` 与 `[left, right)` 都可以，但不能在递归过程中混用。

</Accordion>
<Accordion title="错误 5：删除 / 修剪 BST 后没有接住递归返回值">

子树根节点可能改变，所以应使用：

```cpp
node->left = operation(node->left);
```

而不是只调用 `operation(node->left)` 后忽略返回值。

</Accordion>
<Accordion title="错误 6：看到 BST 仍然暴力遍历整棵树">

先检查能否利用大小关系只走一个方向，或利用中序有序性把问题转成序列问题。

</Accordion>
<Accordion title="错误 7：把递归顺序背成固定答案">

真正要判断的是数据依赖：当前节点需要先处理，还是必须先拿到左右子树结果。

</Accordion>
</Accordions>

## 18. 面试前 10 分钟应该复习什么

如果时间非常有限，不必重新刷完整个专题。快速确认下面这些问题能否不看答案直接解释：

- 为什么最大深度适合后序，而路径问题经常适合前序？
- 为什么最小深度不能机械使用 `min(left, right) + 1`？
- 为什么 BST 中序遍历天然有序？
- `pre` 指针在验证 BST、最小差、众数中分别代表什么？
- 为什么二叉树路径问题经常伴随回溯？
- 为什么构造树通常体现前序思想？
- 为什么删除 / 修剪 BST 时递归函数最好返回新的子树根？
- 普通二叉树 LCA 与 BST LCA 的核心差异是什么？
- BFS 中为什么要提前保存当前层的 `size`？
- 看到一道新题时，能否先说清楚递归函数的语义，再开始写代码？

如果这些问题都能解释清楚，说明掌握的已经不是“题目答案”，而是整套二叉树方法论。

## 19. 通用 DFS 骨架：用同一个模板检查递归思路

下面的代码不是某一道具体题的答案，而是一个用于检查递归结构的通用骨架。真正做题时，应根据“父节点需要什么信息”修改返回值和单层逻辑。

### C++

```cpp title="C++ · 通用 DFS 骨架"
Result dfs(TreeNode* node) {
    // 1. 终止条件
    if (node == nullptr) {
        return baseResult;
    }

    // 2. 如果需要前序处理，写在这里
    processBeforeChildren(node);

    // 3. 递归左右子树
    Result left = dfs(node->left);

    // 如果需要中序处理，写在这里
    processBetweenChildren(node);

    Result right = dfs(node->right);

    // 4. 如果需要后序处理，在左右结果回来后合并
    return merge(node, left, right);
}
```

<Callout title="最后的判断标准" type="idea">

真正掌握二叉树，不是看到题目后能背出某份代码，而是能在动手前回答：

```text
这棵树有什么性质？
当前节点需要从父节点拿到什么？
父节点又需要从当前子树拿到什么？
当前节点应该在递归前、中间还是递归后处理？
状态是否需要回溯？
有没有结构性质可以剪枝？
```

这些问题回答清楚以后，代码通常只是把思路翻译出来。
