# 二叉树第四阶段复盘：BST 有序性与树上信息汇合

这一阶段出现了一个非常重要的转折：我们不再只把所有题都当作“普通二叉树遍历”，而是开始根据**树本身的结构性质**选择算法。

这一组内容覆盖：

- 合并二叉树；
- 二叉搜索树中的搜索；
- 验证二叉搜索树；
- 二叉搜索树的最小绝对差；
- 二叉搜索树中的众数；
- 普通二叉树的最近公共祖先。

表面上是六道不同题，实际上可以浓缩成三种核心能力：

```text
同时操作两棵树
BST → 中序有序序列
左右子树返回信息 → 当前节点合并
```

<Callout title="这一阶段的真正分水岭" type="info">

之前很多题只需要问：

> “我应该用前序、中序、后序还是层序？”

从这里开始，还必须先问：

> **这棵树有没有额外性质可以利用？**

如果题目给的是 BST，却仍然完全按照普通二叉树暴力处理，往往就是把简单题做复杂了。

</Callout>

## 1. 模型一：同时递归两棵树

典型问题：**合并二叉树**。

以前递归函数通常只处理一个节点：

```cpp
traversal(root)
```

而合并二叉树变成：

```cpp
traversal(root1, root2)
```

核心并没有改变，只是当前状态从“一棵树的一个节点”扩展成了“两棵树的一对节点”。

当前层只需要处理四种组合：

| `root1` | `root2` | 处理方式 |
| --- | --- | --- |
| 空 | 空 | 返回空 |
| 非空 | 空 | 返回 `root1` |
| 空 | 非空 | 返回 `root2` |
| 非空 | 非空 | 合并当前值，再递归左右孩子 |

这是一类非常值得记住的模式：

> **当题目要求比较、合并、判断两棵树时，递归参数往往天然就是两个节点。**

它还会出现在：

- 判断两棵树是否相同；
- 对称二叉树；
- 子树匹配；
- 同时比较两棵树结构。

## 2. BST 最重要的等价视角：中序遍历就是有序序列

二叉搜索树满足：

```text
左子树所有值 < 当前节点 < 右子树所有值
```

因此中序遍历：

```text
左 → 中 → 右
```

得到的是严格递增序列；如果某类 BST 定义允许重复值，则对应为非递减序列。

这条性质几乎贯穿整个 BST 章节。

<Callout title="BST 的第一反应" type="success">

看到二叉搜索树时，优先同时建立两个视角：

```text
树结构视角：可以根据大小关系选择方向
有序数组视角：中序遍历会在线产生有序序列
```

很多题会在这两个视角之间自由切换。

</Callout>

## 3. 二叉搜索树中的搜索：利用方向性剪枝

普通二叉树寻找一个值，最坏情况下只能遍历整棵树：

$$
O(n)
$$

但 BST 中，假设当前节点值为 `x`，目标值为 `t`：

```text
t < x → 只可能在左子树
t > x → 只可能在右子树
t = x → 已找到
```

因此搜索可以只沿一条路径进行。

平衡 BST 中，树高约为：

$$
O(\log n)
$$

所以搜索也可以达到：

$$
O(\log n)
$$

最坏退化成链表时仍然是：

$$
O(n)
$$

这里最重要的不是复杂度数字，而是**利用结构性质主动排除不可能的分支**。

## 4. 验证 BST：不能只比较父子节点

一个高频错误是只检查：

```text
left.val < root.val < right.val
```

这只能保证局部父子关系，不能保证整棵子树满足 BST 条件。

例如：

```text
       10
      /  \
     5    15
         /  \
        6    20
```

虽然：

```text
5 < 10 < 15
6 < 15 < 20
```

但 `6` 位于 `10` 的右子树中，却小于 `10`，因此整棵树非法。

验证 BST 有两种非常重要的思路。

<Tabs groupId="validate-bst-model" items={['中序递增', '上下界约束']}>
<Tab value="中序递增">

把 BST 看成在线生成的有序序列：

```text
pre < cur
```

只要中序过程中出现：

```text
cur <= pre
```

就可以立即判错。

</Tab>
<Tab value="上下界约束">

给每个节点传递一个合法区间：

```text
(lower, upper)
```

进入左子树：

```text
(lower, root.val)
```

进入右子树：

```text
(root.val, upper)
```

这样祖先约束就会一直传到深层节点。

</Tab>
</Tabs>

这两种方法分别训练：

```text
遍历顺序产生的全局性质
递归参数传递的全局约束
```

## 5. `pre` 指针：BST 中序题的高频状态

从“验证 BST”开始，一个非常重要的变量反复出现：

```cpp
TreeNode* pre;
```

它表示：

> **中序遍历中刚刚访问过的前一个节点。**

这个状态之所以强大，是因为中序序列有序，很多全局问题都可以转化为“只比较相邻元素”。

### 5.1 验证 BST

比较：

```text
pre.val < cur.val
```

### 5.2 最小绝对差

比较：

```text
cur.val - pre.val
```

### 5.3 众数

比较：

```text
cur.val == pre.val ?
```

并维护当前连续段长度。

这三题的核心状态可以放在一张表里：

| 问题 | 中序过程中关心什么 | 主要状态 |
| --- | --- | --- |
| 验证 BST | 是否严格递增 | `pre` |
| 最小绝对差 | 相邻差值 | `pre + result` |
| 众数 | 相同值连续次数 | `pre + count + maxCount + result` |

## 6. 为什么有序序列只需要比较相邻元素

“最小绝对差”是理解 BST 有序性的最佳例子。

中序序列设为：

$$
a_1<a_2<\cdots<a_n
$$

原问题要求：

$$
\min_{i\ne j}|a_i-a_j|
$$

但在有序序列中，最小差一定来自相邻元素：

$$
\min_{1\le i<n}(a_{i+1}-a_i)
$$

因为任意跨越多个元素的差：

$$
a_j-a_i
$$

都可以写成若干个相邻差之和：

$$
a_j-a_i
=
(a_{i+1}-a_i)+\cdots+(a_j-a_{j-1})
$$

所以它不可能比其中每一个相邻差都更小。

这就是典型的：

```text
利用有序性，把“任意两点关系”压缩成“相邻关系”
```

## 7. 众数：把频率统计变成连续段统计

普通二叉树求众数通常需要：

```text
哈希表：value -> frequency
```

而 BST 的中序序列有序，相同值会连续出现：

```text
1, 1, 2, 3, 3, 3, 5
```

于是频率统计变成了连续段计数。

只需要维护：

```text
pre      上一个节点
count    当前连续值出现次数
maxCount 当前最大频率
result   当前所有众数
```

最巧妙的地方是可以一遍遍历在线维护结果：

```text
count < maxCount  → 不处理
count = maxCount  → 当前值加入 result
count > maxCount  → 更新 maxCount，清空旧 result，再加入当前值
```

这是一种很通用的“在线维护最优解集合”技巧。

## 8. 不要用危险哨兵值替代状态

验证 BST 时，有人喜欢写：

```cpp
long long preValue = LLONG_MIN;
```

某些题的数据范围下这确实可行，但更通用、更稳健的写法是：

```cpp
TreeNode* pre = nullptr;
```

然后显式判断：

```cpp
if (pre != nullptr) {
    ...
}
```

本质上是在区分：

```text
“前一个节点不存在”
```

和：

```text
“前一个节点的值恰好非常小”
```

<Callout title="一个通用工程习惯" type="warning">

如果你的算法需要人为选一个“绝对不可能出现”的数值作为初始值，一定要检查数据范围。

能用 `null`、布尔状态、可选类型等方式表达“尚未初始化”，通常更可靠。

</Callout>

## 9. 普通二叉树 LCA：从“有序性”切换回“信息汇合”

到了最近公共祖先，题目重新回到普通二叉树。

此时 BST 的大小关系全部失效：

```text
不能根据节点值决定向左还是向右
```

真正有效的是后序信息汇合：

```text
left  = 左子树返回的候选节点
right = 右子树返回的候选节点
```

如果：

```text
left != null && right != null
```

说明 `p`、`q` 第一次在当前节点的两侧汇合，当前节点就是 LCA。

如果只有一边非空，就把这一边的结果继续向上传递。

这道题把“递归返回值”提升到了新的层次：

> 返回值不是最终答案本身，而是**供父节点继续决策的信息**。

## 10. 三类递归返回值，现在应该彻底分清

前面已经接触过很多递归题，现在可以把它们统一成三类。

### 10.1 返回“数值状态”

例如：

```text
最大深度
节点个数
子树高度
```

形式：

```cpp
int left = dfs(root->left);
int right = dfs(root->right);
return combine(left, right);
```

### 10.2 返回“是否成功”

例如路径总和：

```cpp
if (dfs(root->left)) return true;
if (dfs(root->right)) return true;
return false;
```

它适合存在性搜索，可以短路。

### 10.3 返回“候选节点 / 子树答案”

例如 LCA：

```cpp
TreeNode* left = dfs(root->left);
TreeNode* right = dfs(root->right);
```

父节点再根据两边候选进行合并。

<Callout title="递归设计的核心不是模板，而是返回语义" type="idea">

写任何递归前，先完整说出一句话：

> `dfs(node)` 返回什么？

只要这句话模糊，后面的终止条件、单层逻辑、返回值几乎一定会混乱。

</Callout>

## 11. 一张总表：看到题目特征时应该想到什么

| 题目特征 | 优先想到 |
| --- | --- |
| 同时比较或合并两棵树 | 双节点递归 / 成对入队 |
| BST 中查找某值 | 利用大小关系只走一个方向 |
| 验证 BST | 中序严格递增 / 上下界 |
| BST 上求相邻关系 | 中序 + `pre` |
| BST 上统计重复值 | 中序连续段计数 |
| 当前节点依赖左右子树结果 | 后序遍历 |
| 两个目标在树上寻找汇合点 | LCA 的候选值向上传递 |
| 找到一个成功分支即可 | 布尔返回 + 短路 |

## 12. 普通二叉树、BST、平衡树、完全二叉树不要混淆

随着类型越来越多，最容易出现的是概念串线。

### 12.1 二叉搜索树 BST

强调的是**值的有序关系**：

```text
左子树 < 根 < 右子树
```

它不保证树一定平衡。

### 12.2 平衡二叉树

强调的是**高度差**。

通常要求每个节点左右子树高度差不超过 1。

它并不天然具备搜索树的有序性。

### 12.3 平衡二叉搜索树

它同时满足：

```text
BST 的值有序性质
+
平衡树的高度约束
```

典型目标是让搜索、插入、删除都尽量保持：

$$
O(\log n)
$$

### 12.4 完全二叉树

强调的是**节点位置**：

```text
除最后一层外都满
最后一层从左向右连续
```

它和 BST 的值大小关系没有必然联系。

### 12.5 堆

堆通常是一棵完全二叉树，同时满足父子之间的堆序关系。

例如大根堆：

```text
父节点 >= 子节点
```

但这并不是 BST 的：

```text
左 < 根 < 右
```

所以：

> **堆不是“平衡二叉搜索树”。**

## 13. 一张结构对比表

| 结构 | 主要约束 | 中序一定有序？ | 高度一定较小？ |
| --- | --- | --- | --- |
| 普通二叉树 | 无额外约束 | 否 | 否 |
| 二叉搜索树 | 左小右大 | 是 | 否 |
| 平衡二叉树 | 左右高度受限 | 否 | 是 |
| 平衡二叉搜索树 | BST + 平衡 | 是 | 是 |
| 完全二叉树 | 节点位置连续 | 否 | 是，数量级为 $O(\log n)$ |
| 堆 | 完全二叉树 + 父子堆序 | 否 | 是，数量级为 $O(\log n)$ |

这里尤其要注意：

```text
“平衡”描述形状
“搜索树”描述值的有序关系
“完全”描述节点填充位置
“堆”描述完全性 + 父子优先级
```

这些是不同维度的性质。

## 14. 这一阶段最容易犯的错误

<Cards>
  <Card title="BST 仍然两边都搜">明明可以利用值大小只走一个方向，却把 BST 当普通二叉树遍历。</Card>
  <Card title="验证 BST 只看父子">忽略祖先对深层节点的约束。</Card>
  <Card title="忘记中序有序">最小绝对差、众数等题没有利用中序序列的结构。</Card>
  <Card title="pre 更新时机错误">`pre` 必须在中序访问“当前节点”之后再更新。</Card>
  <Card title="众数刷新答案时不清空">出现更高频率后，旧众数已经失效。</Card>
  <Card title="LCA 只会背四行代码">没有定义递归返回语义，换一个树上信息汇合问题就不会。</Card>
</Cards>

## 15. 从这一阶段提炼出的两套通用框架

### 15.1 BST 框架

```text
先问：能否利用左右大小关系剪枝？
再问：中序遍历转成有序序列后，问题是否更简单？
最后问：是否能在线处理，从而不保存完整数组？
```

典型演化：

```text
BST
→ 中序有序
→ 只关心相邻节点
→ 用 pre 在线处理
→ O(n) 时间 + O(h) 递归栈
```

### 15.2 后序信息汇合框架

```text
left = dfs(leftChild)
right = dfs(rightChild)
answer = merge(root, left, right)
```

典型问题：

```text
高度
平衡性
最近公共祖先
树形 DP
```

它们共同的本质是：

> 当前节点的答案依赖左右子树已经计算好的信息。

## 16. 阶段复盘：六道题之间其实是一条知识链

可以把这一阶段串成一条完整路线：

<Steps>

### 1. 合并二叉树

学会同时维护两棵树的一对节点。

### 2. BST 搜索

第一次充分利用“左小右大”做方向性剪枝。

### 3. 验证 BST

理解 BST 是全局约束，并建立“中序严格递增”的等价视角。

### 4. 最小绝对差

把树问题彻底转换为有序数组上的相邻差问题。

### 5. 众数

进一步利用有序性，把哈希频率统计降成连续段计数。

### 6. 最近公共祖先

离开 BST 有序性，转而训练后序返回值和树上信息汇合。

</Steps>

这条路线非常重要，因为它说明：

```text
算法并不是“题型 -> 固定模板”
而是“结构性质 -> 状态设计 -> 遍历方式”
```

## 17. 最终自测

如果这一阶段真正掌握，应该能够不看代码回答下面的问题：

1. 为什么 BST 搜索通常只需要进入一棵子树？
2. 为什么只比较父节点和左右孩子不能验证 BST？
3. 为什么 BST 的中序遍历有序？
4. 为什么最小绝对差只需比较中序相邻节点？
5. 为什么众数可以不使用哈希表？
6. `pre` 在 BST 中序题里究竟表示什么？
7. 为什么 LCA 要同时接住左右子树返回值？
8. 为什么 `left != null && right != null` 时当前节点就是 LCA？
9. “存在性短路搜索”和“后序信息合并”有什么根本区别？
10. 平衡二叉树、完全二叉树、BST、堆分别约束什么？

<Callout title="阶段结论" type="success">

这一阶段最重要的升级是：

```text
看到 BST → 想有序性
看到父节点依赖左右结果 → 想后序
看到多棵树 → 想成对状态
```

当这些反应能够自然出现时，二叉树已经开始从“题目集合”变成一套可迁移的算法模型。

</Callout>
