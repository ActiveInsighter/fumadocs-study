# 链表理论基础：节点、指针与增删查复杂度

链表是一种非常基础的线性数据结构。

如果说数组的核心是：

> **连续存储 + 下标访问**

那么链表的核心就是：

> **节点分散存储 + 指针/引用连接**

理解这两个差异，后面的反转链表、删除节点、快慢指针、链表相交、环形链表等题目就会自然很多。

---

## 1. 什么是链表

单链表中的每个节点通常包含两部分：

```text
┌─────────┬─────────┐
│  data   │  next   │
└─────────┴─────────┘
```

其中：

- `data` / `val`：保存节点的数据；
- `next`：保存下一个节点的地址或引用。

最后一个节点没有后继，因此：

```text
next = null
```

链表入口通常由 `head` 指向：

![单链表结构](https://file1.kamacoder.com/i/algo/20200806194529815.png)

可以抽象为：

```text
head
 ↓
[1 | •] → [3 | •] → [5 | •] → null
```

<Callout title="链表真正保存的是什么" type="info">
链表并不要求节点彼此存放在相邻地址。它只要求每个节点能够找到自己的后继节点。
</Callout>

---

## 2. 为什么链表不需要连续内存

数组中的第 $i$ 个元素可以由公式直接定位：

$$
addr(i)=base+i\times w
$$

链表则不同。

要找第 $i$ 个节点，通常只能从头结点出发：

```text
head → 第 1 个 → 第 2 个 → ... → 第 i 个
```

节点实际可能散布在不同地址：

![链表节点在内存中的分散存储](https://file1.kamacoder.com/i/algo/20200806194613920.png)

因此随机访问第 $i$ 个节点的复杂度为：

$$
O(i)
$$

最坏情况下：

$$
O(n)
$$

这正是链表用“查询性能”换“连接灵活性”的体现。

## 3. 三种常见链表

<Cards>
  <Card title="单链表" description="每个节点只保存 next，只能沿一个方向向后遍历。" />
  <Card title="双链表" description="每个节点同时保存 prev 与 next，可以双向遍历。" />
  <Card title="循环链表" description="尾节点重新连接到前面的节点，不再以 null 作为终点。" />
</Cards>

### 3.1 单链表

```text
A → B → C → null
```

只知道当前节点时，可以访问后继节点，但不能直接访问前驱节点。

### 3.2 双链表

双链表每个节点包含：

```text
prev + data + next
```

结构示意：

![双链表](https://file1.kamacoder.com/i/algo/20200806194559317.png)

抽象为：

```text
null ← A ⇄ B ⇄ C → null
```

优点是已知当前节点时，可以同时向前、向后移动。

代价是每个节点需要额外保存一个前驱指针。

### 3.3 循环链表

普通单链表：

```text
A → B → C → null
```

循环链表：

```text
A → B → C
↑       ↓
└───────┘
```

![循环链表](https://file1.kamacoder.com/i/algo/20200806194629603.png)

循环链表常用于：

- 循环队列思想；
- 轮转调度；
- 约瑟夫问题；
- 需要首尾循环访问的结构。

## 4. 链表节点应该会自己写

刷题平台往往已经给出 `ListNode`，容易让人忽略节点本身的定义。

C++ 中典型写法：

```cpp
struct ListNode {
    int val;
    ListNode* next;

    ListNode(int x) : val(x), next(nullptr) {}
};
```

创建节点：

```cpp
ListNode* node = new ListNode(5);
```

此时：

```text
node->val  = 5
node->next = nullptr
```

如果没有自定义构造函数，也可以分开初始化：

```cpp
ListNode* node = new ListNode;
node->val = 5;
node->next = nullptr;
```

但必须确保成员变量被正确赋值，尤其不要留下未初始化的指针。

<Callout title="现代 C++ 细节" type="info">
新代码中通常优先使用 `nullptr`，而不是旧式的 `NULL`。算法题里两者常都能看到，但 `nullptr` 类型语义更明确。
</Callout>

## 5. 链表插入为什么可以做到 $O(1)$

假设已有：

```text
A → B
```

现在已知节点 `A`，要在 `A` 与 `B` 之间插入 `X`：

```text
A → X → B
```

只需要修改两个连接关系。

<Steps>
  <Step>
    让新节点 `X.next` 指向原来的 `B`。
  </Step>
  <Step>
    再让 `A.next` 指向 `X`。
  </Step>
</Steps>

代码：

```cpp
x->next = a->next;
a->next = x;
```

对应原图：

![链表插入节点](https://file1.kamacoder.com/i/algo/20200806195134331-20230310121503147.png)

修改指针本身只涉及常数次操作，所以：

$$
O(1)
$$

### 但有一个重要前提

这里说的是：

> **已经找到插入位置之后**。

如果题目要求“在第 $k$ 个节点后插入”，而你只有 `head`，那么首先还要从头遍历寻找第 $k$ 个节点：

$$
O(k)
$$

因此整个操作最坏仍为：

$$
O(n)
$$

---

## 6. 删除节点也一样：改指针是 $O(1)$，找节点可能是 $O(n)$

假设：

```text
C → D → E
```

现在要删除 `D`，并且已经拿到了前驱节点 `C`。

只需要：

```cpp
C->next = D->next;
```

结果：

```text
C → E
```

![链表删除节点](https://file1.kamacoder.com/i/algo/20200806195114541-20230310121459257.png)

如果使用 C++ 手动管理内存，还应释放被移除节点：

```cpp
ListNode* temp = c->next;
c->next = temp->next;
delete temp;
```

但 Java、Python、JavaScript 等带垃圾回收机制的语言通常不需要手动 `free/delete`。

### 必须区分两个时间复杂度

#### 已知前驱节点

修改连接：

$$
O(1)
$$

#### 只知道“删除第 $k$ 个节点”

先遍历找到它的前驱：

$$
O(n)
$$

所以“链表删除一定是 $O(1)$”是不严谨的。

## 7. 为什么链表题经常使用虚拟头结点

考虑删除真正的头结点：

```text
head → A → B → C
```

如果要删除 `A`，只能特殊处理：

```cpp
head = head->next;
```

但删除中间节点时通常写：

```cpp
prev->next = prev->next->next;
```

也就是说，“删除头部”和“删除中间”代码不统一。

于是引入虚拟头结点 `dummy`：

```text
dummy → A → B → C
```

令：

```cpp
dummy->next = head;
```

这样即使删除原来的 `A`，它现在也有前驱 `dummy`。

所有删除都可以统一成：

```cpp
prev->next = prev->next->next;
```

最后返回：

```cpp
return dummy->next;
```

<Callout title="虚拟头结点的价值" type="info">
它不会让算法复杂度变好，但能显著减少头结点特判，使链表增删代码更统一、更不容易错。
</Callout>

## 8. 链表为什么不适合随机访问

数组：

```text
想找 a[1000]
→ 地址公式直接计算
```

链表：

```text
想找第 1000 个节点
→ 必须沿 next 逐个走过去
```

因此：

| 操作 | 数组 | 单链表 |
| --- | ---: | ---: |
| 按位置随机访问 | $O(1)$ | $O(n)$ |
| 顺序遍历 | $O(n)$ | $O(n)$ |
| 已知位置后插入 | 通常 $O(n)$ 移动 | $O(1)$ 改连接 |
| 已知前驱后删除 | 通常 $O(n)$ 移动 | $O(1)$ 改连接 |
| 内存布局 | 连续 | 可分散 |
| 每个元素额外指针开销 | 无 | 有 |

![链表与数组性能对比](https://file1.kamacoder.com/i/algo/20200806195200276.png)

### 这里最容易被表格误导的地方

“链表插入 $O(1)$”并不意味着任何位置插入都比数组快。

如果需要先通过下标寻找位置：

```text
寻找位置 O(n)
+ 改指针 O(1)
```

总复杂度仍然是：

$$
O(n)
$$

链表真正占优势的场景是：

> 已经持有目标位置附近的节点引用，并且频繁进行连接修改。

## 9. 链表的空间开销为什么更高

假设每个节点只存一个 32 位整数：

```text
int val
```

在 64 位环境下，一个指针往往还需要 8 字节：

```text
int val   → 4 字节
next      → 8 字节
```

再考虑内存对齐后，一个节点实际大小还可能进一步增加。

因此链表为了获得动态连接能力，需要支付额外指针空间和节点分配成本。

这也是为什么在真实工程中，“理论上插入快”并不意味着链表一定比动态数组性能更好。

数组连续内存通常具有更好的 CPU Cache 局部性。

## 10. 链表操作最重要的是“先保存，再断链”

链表修改最危险的问题之一是：

> 你把唯一通往后续节点的指针覆盖掉了。

例如想删除：

```text
prev → cur → next
```

如果后续仍然需要 `cur->next`，就应先保存：

```cpp
ListNode* next = cur->next;
```

再修改：

```cpp
prev->next = next;
```

同理，反转链表时：

```cpp
cur->next = prev;
```

会覆盖原来的后继关系，所以必须提前保存：

```cpp
ListNode* next = cur->next;
cur->next = prev;
```

<Callout title="链表题第一原则" type="warning">
任何一次修改 `next` 之前，都先确认：原来的 `next` 后面还需不需要访问。如果需要，必须先保存。
</Callout>

## 11. 指针变量与节点本身不是一回事

这是初学链表时最重要的概念之一。

假设：

```cpp
ListNode* p = head;
```

然后：

```cpp
p = p->next;
```

只是让变量 `p` 改为指向下一个节点，链表结构本身没有变化。

但如果写：

```cpp
p->next = p->next->next;
```

这才是在修改节点中的 `next` 字段，因此链表结构发生变化。

可以把它们区分成：

```text
p = ...        改“指针变量指向谁”
p->next = ...  改“节点连接到谁”
```

如果这个概念没分清，后面的链表反转会非常容易混乱。

## 12. 为什么链表题经常出现双指针

虽然链表不能随机访问，但指针可以同时沿链表移动，并维护不同的相对关系。

典型技巧包括：

### 前后指针

用于反转链表：

```text
prev ← cur    next → ...
```

### 快慢指针

例如：

```text
slow 每次走 1 步
fast 每次走 2 步
```

可以用于：

- 判断是否有环；
- 寻找环入口；
- 找链表中点。

### 固定间距双指针

让 `fast` 先走 $n$ 步，再让 `slow` 与 `fast` 同时移动。

可以用于：

- 删除倒数第 $n$ 个节点；
- 寻找距尾部固定距离的位置。

所以链表模块虽然底层数据结构简单，但会成为“双指针思想”的重要训练场。

## 13. 链表题的通用检查清单

写完链表代码后，可以逐项检查：

1. 空链表 `head == null` 是否处理；
2. 只有一个节点时是否正确；
3. 是否可能删除头结点；
4. 是否需要虚拟头结点；
5. 改 `next` 前是否保存了后继；
6. 是否存在空指针解引用；
7. 循环条件是否会漏最后一个节点；
8. C/C++ 中移除节点后是否需要释放内存；
9. 返回的是原 `head`，还是新的 `dummy->next`；
10. 指针移动与链表结构修改是否混淆。

这张清单能覆盖大量链表题的低级错误。

## 14. 什么时候更适合数组，什么时候更适合链表

### 更偏向数组

- 高频随机访问；
- 数据访问远多于插删；
- 希望缓存局部性更好；
- 元素数量相对稳定。

### 更偏向链表

- 节点数量动态变化；
- 经常在已知节点附近插入、删除；
- 不需要按下标高频随机访问；
- 需要通过节点连接表达特殊结构。

不过在真实工程中，数据结构选择还要考虑：

- 内存分配成本；
- Cache 命中率；
- 对象开销；
- 并发模型；
- 实际访问模式。

不能只依据渐进复杂度机械判断。
