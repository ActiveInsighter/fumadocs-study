# 移除元素：原地覆盖与快慢指针

题目：LeetCode 27「移除元素」。

给定整数数组 `nums` 和整数 `val`，要求**原地**移除所有等于 `val` 的元素，并返回剩余元素的数量。

题目并不要求真的缩短底层数组，而只要求：

> 返回值为 `k` 时，`nums[0..k-1]` 中保存所有未被删除的元素。

例如：

```text
nums = [0, 1, 2, 2, 3, 0, 4, 2]
val  = 2

处理后前 5 个位置可以是：
[0, 1, 3, 0, 4]

返回：5
```

---

## 1. 为什么数组里的元素不能像链表节点一样“直接删掉”

数组的核心特征是：**元素在逻辑上按下标连续排列，在典型实现中底层存储也是连续的。**

假设有：

```text
下标： 0  1  2  3  4
数组：[A, B, C, D, E]
```

如果删除中间的 `C`，那么为了仍然满足：

```text
[A, B, D, E]
```

后面的元素就必须整体向左移动：

```text
D -> 下标 2
E -> 下标 3
```

所以数组中的“删除”通常不是把中间某个存储单元凭空拿掉，而是：

1. 覆盖要删除的位置；
2. 更新逻辑长度。

<Callout title="数组删除与链表删除的本质区别" type="info">
链表删除节点通常只需要修改相邻节点之间的链接；数组删除中间元素往往需要搬移后续元素。正因如此，这道题才适合用“覆盖”而不是物理删除来思考。
</Callout>

---

## 2. 暴力做法：遇到目标值就整体左移

最直观的方案是：

- 从左到右扫描；
- 若发现 `nums[i] == val`；
- 将后面所有元素向左移动一位。

![移除元素：暴力左移](https://file1.kamacoder.com/i/algo/27.%E7%A7%BB%E9%99%A4%E5%85%83%E7%B4%A0-%E6%9A%B4%E5%8A%9B%E8%A7%A3%E6%B3%95.gif)

代码：

```cpp
int removeElement(vector<int>& nums, int val) {
    int size = nums.size();

    for (int i = 0; i < size; ++i) {
        if (nums[i] == val) {
            for (int j = i + 1; j < size; ++j) {
                nums[j - 1] = nums[j];
            }

            --i;
            --size;
        }
    }

    return size;
}
```

### 为什么删除后要 `--i`

例如：

```text
[2, 2, 3]
 ^
 i = 0
```

删除第一个 `2` 后变成：

```text
[2, 3, ...]
 ^
 i = 0
```

原来下标 `1` 的第二个 `2` 已经移动到了下标 `0`。

如果此时循环直接执行 `i++`，就会跳过它。

因此必须先：

```cpp
--i;
```

让下一轮仍然检查当前位置。

### 复杂度

最坏情况下，每删除一个元素都需要搬移后面大量元素：

$$
(n-1)+(n-2)+\cdots+1
$$

根据等差数列求和：

$$
\frac{n(n-1)}{2}=O(n^2)
$$

因此：

- 时间复杂度：$O(n^2)$；
- 额外空间复杂度：$O(1)$。

---

## 3. 更好的思路：不要删除，只保留需要的元素

暴力法的问题在于：

> 每遇到一个目标值，就把后面大量元素整体搬一次。

实际上我们并不关心“删除”动作本身。

真正需要的是：

> 把所有 `!= val` 的元素依次放到数组前部。

这就自然得到**快慢指针**。

---

## 4. 快慢指针的含义

定义两个位置：

- `fast`：扫描原数组；
- `slow`：下一个应该写入保留元素的位置。

可以把它理解为：

```text
fast：负责读
slow：负责写
```

### 核心不变量

在每一轮开始时：

> `nums[0..slow-1]` 已经保存了 `nums[0..fast-1]` 中所有不等于 `val` 的元素。

这句话就是整个算法正确性的核心。

<Steps>
<Step>

### 快指针遇到要删除的元素

若：

```cpp
nums[fast] == val
```

这个元素不需要保留，因此什么都不写：

```text
fast 向前走
slow 不动
```

</Step>

<Step>

### 快指针遇到应该保留的元素

若：

```cpp
nums[fast] != val
```

就把这个元素写到 `slow` 所指的位置：

```cpp
nums[slow] = nums[fast];
++slow;
```

然后继续扫描。

</Step>

<Step>

### 扫描结束

当 `fast` 到达数组末尾时，`slow` 恰好等于保留下来的元素数量。

因此返回：

```cpp
return slow;
```

</Step>
</Steps>

## 6. C++ 标准写法

```cpp
class Solution {
public:
    int removeElement(vector<int>& nums, int val) {
        int slow = 0;

        for (int fast = 0; fast < nums.size(); ++fast) {
            if (nums[fast] != val) {
                nums[slow] = nums[fast];
                ++slow;
            }
        }

        return slow;
    }
};
```

### 复杂度

整个数组只扫描一次：

$$
T(n)=an+b
$$

因此：

$$
T(n)=O(n)
$$

只使用 `slow`、`fast` 等常数个变量：

$$
S(n)=O(1)
$$

---

## 7. 为什么它是“原地”算法

有些同学会疑惑：

> 明明写了 `nums[slow] = nums[fast]`，这算不算新建数组？

不算。

“原地”通常指：

> 算法没有再申请一个与输入规模 $n$ 成比例的辅助数组。

当前方案只修改原数组本身，并额外使用常数个变量，因此额外空间仍为：

$$
O(1)
$$

---

## 8. 这个写法会保持元素相对顺序

对于：

```text
nums = [5, 2, 7, 2, 9]
val  = 2
```

快慢指针得到：

```text
[5, 7, 9]
```

原本保留下来的元素顺序：

```text
5 -> 7 -> 9
```

没有改变。

这种性质称为**稳定保序**。

---

## 9. 如果题目明确说“顺序可以改变”，还能更进一步

LeetCode 27 明确允许：

> 元素顺序可以改变。

那么当数组中 `val` 很少时，可以使用**相向双指针**：

- `left` 从左找待删除元素；
- `right` 从右找一个可以保留的元素；
- 用右边元素覆盖左边元素；
- 缩小右边界。

```cpp
class Solution {
public:
    int removeElement(vector<int>& nums, int val) {
        int left = 0;
        int right = static_cast<int>(nums.size()) - 1;

        while (left <= right) {
            if (nums[left] == val) {
                nums[left] = nums[right];
                --right;
            } else {
                ++left;
            }
        }

        return left;
    }
};
```

### 这种写法有什么特点

它仍然是：

- 时间复杂度：$O(n)$；
- 额外空间复杂度：$O(1)$。

但它**不会保持原有相对顺序**。

例如：

```text
[1, 2, 3, 4], val = 2
```

可能得到：

```text
[1, 4, 3]
```

而不是：

```text
[1, 3, 4]
```

因此使用前必须先看题目是否要求稳定顺序。

<Callout title="一道题，两种双指针" type="warning">
若必须保持元素相对顺序，使用“快慢指针”；若不要求保持顺序，可以考虑“首尾交换/覆盖”的相向双指针。不要只背模板，要先看题目对顺序的约束。
</Callout>

## 10. 快慢指针为什么能把两层循环变成一层

暴力法实际上在做两件事：

1. 找出哪些元素应该保留；
2. 把它们移动到正确位置。

快慢指针把这两个职责拆开：

```text
fast：决定“保不保留”
slow：决定“写到哪里”
```

于是每个元素最多被读取一次、写入一次。

整体工作量从可能的：

$$
O(n^2)
$$

下降为：

$$
O(n)
$$

这是一种非常重要的算法优化思想：

> 当某个循环反复执行“数组搬移”时，考虑能否改成一次扫描 + 覆盖写入。

## 11. 常见错误

### 错误一：把 `slow` 每轮都加一

错误：

```cpp
for (int fast = 0; fast < nums.size(); ++fast) {
    if (nums[fast] != val) {
        nums[slow] = nums[fast];
    }
    ++slow;
}
```

这会让 `slow` 不再表示“有效元素个数”。

正确做法是：

> 只有真正写入一个保留元素时，`slow` 才增加。

---

### 错误二：认为必须真正删除数组尾部

本题只要求返回新长度 `k`。

因此只要保证：

```text
nums[0..k-1]
```

正确即可。

无需处理：

```text
nums[k..n-1]
```

---

### 错误三：忽略空数组

对于：

```text
nums = []
```

循环不会执行：

```cpp
slow == 0
```

直接返回 `0` 即可。

---

### 错误四：相向双指针里覆盖后立即 `left++`

如果：

```cpp
nums[left] = nums[right];
```

右端拿过来的元素仍然可能等于 `val`。

因此最稳妥的写法是：

```cpp
if (nums[left] == val) {
    nums[left] = nums[right];
    --right;
} else {
    ++left;
}
```

让当前位置重新判断。

## 12. 这一题真正应该掌握什么

这道题不是单纯记住一段代码，而是建立三个概念。

### ① 数组删除本质是覆盖

数组中间删除元素往往意味着搬移或覆盖，而不是像链表一样断开节点。

### ② 双指针可以让“读”和“写”解耦

```text
fast：扫描输入
slow：构造结果前缀
```

这种思想会反复出现在：

- 删除排序数组中的重复项；
- 移动零；
- 原地筛选；
- 字符串压缩；
- 链表节点筛选。

### ③ 是否要求保持相对顺序会影响算法设计

稳定快慢指针：

$$
O(n)
$$

相向覆盖：

$$
O(n)
$$

复杂度相同，但行为不同。
