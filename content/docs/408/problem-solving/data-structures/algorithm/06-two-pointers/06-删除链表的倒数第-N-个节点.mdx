# 19. 删除链表的倒数第 N 个节点

<Cards>
  <Card title="题目" href="https://leetcode.cn/problems/remove-nth-node-from-end-of-list/">
    LeetCode 19 · Remove Nth Node From End of List
  </Card>
</Cards>

给定链表 `head` 和整数 `n`，删除链表的倒数第 $n$ 个节点，并返回新的头节点。

例如：

![删除链表的倒数第 N 个节点](https://file1.kamacoder.com/i/algo/20210510085957392.png)

```text
head = [1, 2, 3, 4, 5]
n = 2
```

要删除：

```text
4
```

结果：

```text
1 -> 2 -> 3 -> 5
```

题目还要求进一步思考：

> 能否只扫描链表一次？

<Callout type="info" title="本题的核心">
倒数位置不好直接定位，但可以制造两个指针之间的固定距离：

> **让 fast 永远比 slow 领先固定步数。**

当 fast 到达末尾时，slow 就自动落到目标附近。
</Callout>

---

## 1. 两趟扫描当然可以做

最直接的方法：

### 第一趟

计算链表长度：

$$
L
$$

### 第二趟

要删除倒数第 $n$ 个节点，等价于删除正数第：

$$
L-n+1
$$

个节点。

找到它的前驱即可删除。

这种方法时间复杂度仍然是：

$$
O(L)
$$

但需要扫描两次。

题目希望进一步做到：

```text
一趟扫描
```

这就需要快慢指针。

---

# 2. 倒数第 N 个节点如何转成“固定距离”

假设目标节点是倒数第 $n$ 个节点。

如果有两个指针：

```text
fast
slow
```

并且始终保持：

```text
fast 比 slow 多走 n 步
```

那么：

当 `fast` 到达链表尾节点时，`slow` 会落在倒数第 $n$ 个节点。

但删除节点还需要：

> 找到目标节点的前一个节点。

因此最好再多制造一步距离。

---

## 3. 为什么常见解法让 fast 先走 `n + 1` 步

我们希望最终：

```text
slow -> 待删除节点的前一个节点
```

这样删除只需：

```cpp
slow->next = slow->next->next;
```

所以：

```text
fast 和 slow
```

之间应保持：

$$
n+1
$$

个 `next` 距离。

这就是为什么经典写法是：

```text
fast 先走 n + 1 步
然后 fast、slow 同时走
```

---

## 4. 为什么虚拟头节点非常重要

如果要删除的是原链表头：

```text
1 -> 2 -> 3
n = 3
```

目标节点就是：

```text
1
```

它没有真实前驱。

如果没有虚拟头节点，就必须单独写：

```text
如果删除 head ...
```

加入：

```cpp
ListNode* dummy = new ListNode(0, head);
```

结构变成：

```text
dummy -> 1 -> 2 -> 3
```

这样即使删除原头节点 `1`，它也有统一的前驱：

```text
dummy
```

因此所有情况都能用同一套逻辑处理。

## 8. 删除节点

此时：

```text

```

只需：

```cpp

```


# 9. 推荐写法一：明确走 `n + 1` 步

```cpp
class Solution {
public:
    ListNode* removeNthFromEnd(
        ListNode* head,
        int n
    ) {
        ListNode dummy(0, head);

        ListNode* fast = &dummy;
        ListNode* slow = &dummy;

        for (int i = 0; i < n + 1; ++i) {
            fast = fast->next;
        }

        while (fast != nullptr) {
            fast = fast->next;
            slow = slow->next;
        }

        slow->next = slow->next->next;

        return dummy.next;
    }
};
```

这个版本逻辑非常直接：

```text
间距 = n + 1
fast 到 null
slow 正好在待删节点前驱
```

---

# 10. 推荐写法二：fast 先走 n 步，再看 fast->next

还有一种很常见的等价写法。

先让：

```cpp
fast
```

领先：

$$
n
$$

步。

然后：

```cpp
while (fast->next != nullptr)
```

同步移动。

当循环结束时：

```text
fast 停在尾节点
slow 停在待删除节点前驱
```

代码：

```cpp
class Solution {
public:
    ListNode* removeNthFromEnd(
        ListNode* head,
        int n
    ) {
        ListNode dummy(0, head);

        ListNode* fast = &dummy;
        ListNode* slow = &dummy;

        for (int i = 0; i < n; ++i) {
            fast = fast->next;
        }

        while (fast->next != nullptr) {
            fast = fast->next;
            slow = slow->next;
        }

        slow->next = slow->next->next;

        return dummy.next;
    }
};
```

这两个版本都正确。

---

## 11. 两种写法不要混着记

### 写法 A

```text
fast 先走 n + 1 步
while (fast != null)
```

### 写法 B

```text
fast 先走 n 步
while (fast.next != null)
```

两者本质相同。

最容易出错的是：

```text
先走 n 步
却又 while(fast != null)
```

这样 slow 最后会落到待删除节点本身，而不是它的前驱。

所以应把“领先距离”和“终止位置”配套理解。

<Callout type="warning" title="不要死记 n 还是 n+1">
关键不是数字，而是最终你希望 slow 停在哪里：

- 想停在目标节点：间距一种写法；
- 想停在目标前驱：再多留一步。

删除单链表节点通常希望拿到前驱，因此要围绕“slow 最终指向前驱”来设计距离。
</Callout>

## 12. 用长度关系推导一次

设真实链表长度为：

$$
L
$$

引入虚拟头节点后，从 `dummy` 到 `null` 一共有：

$$
L+1
$$

步。

如果 fast 比 slow 领先：

$$
n+1
$$

步。

当 fast 走到 `null` 时，slow 走了：

$$
(L+1)-(n+1)=L-n
$$

步。

从 dummy 出发走：

$$
L-n
$$

步，恰好到达正数第：

$$
L-n
$$

个真实节点，也就是倒数第 $n$ 个节点的前驱。

因此数学关系完全吻合。

## 13. 示例推演

链表：

```text
dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> null
```

删除倒数第：

$$
2
$$

个节点。

fast 先走：

$$
3
$$

步：

```text
slow
 ↓
dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> null
                  ↑
                 fast
```

然后同步移动：

```text
slow -> 1
fast -> 4
```

```text
slow -> 2
fast -> 5
```

```text
slow -> 3
fast -> null
```

现在：

```text
slow -> 3 -> 4 -> 5
```

删除：

```text
4
```

即可。

## 14. 为什么快慢指针只扫描一次

虽然 fast 先单独走若干步，之后两个指针一起走，但每个指针都只沿链表向后。

没有回退。

总步数仍然是线性级别：

$$
O(L)
$$

不是：

$$
O(2L)
$$

意义上的更高复杂度。

常数 2 在渐近复杂度中忽略。

---

## 15. 时间复杂度

每个指针最多走：

$$
O(L)
$$

步。

因此：

$$
O(L)
$$

额外只使用：

```text
dummy
fast
slow
```

常数个节点 / 指针。

空间复杂度：

$$
O(1)
$$

## 16. 删除原头节点为什么也无需特判

例如：

```text
1 -> 2
n = 2
```

目标是删除：

```text
1
```

引入：

```text
dummy -> 1 -> 2
```

最终：

```text
slow = dummy
```

然后：

```cpp
slow->next = slow->next->next;
```

等价于：

```text
dummy -> 2
```

最后返回：

```cpp
dummy.next
```

即：

```text
2
```

所以虚拟头节点把“删除头节点”统一成了普通删除操作。

## 17. 虚拟头节点的真正意义

虚拟头节点并不是只为这道题服务。

它的本质作用是：

> **给真实头节点也人为制造一个前驱。**

于是所有“需要操作前驱”的情况都统一了。

常见场景：

- 删除节点；
- 插入头部；
- 合并链表；
- 分区链表；
- 两两交换；
- 删除倒数节点。

这是链表题最重要的技巧之一。

---

## 18. 为什么单链表删除必须找到前驱

对于数组：

```text
知道下标 i
```

就可以操作 `nums[i]`。

但单链表节点只保存：

```text
next
```

没有：

```text
prev
```

如果想把：

```text
A -> B -> C
```

中的 `B` 删除，需要修改：

```text
A.next = C
```

所以真正必须找到的是：

```text
B 的前驱 A
```

这就是本题为什么让 slow 停在待删除节点前一个位置。

---

## 19. 双指针的本质：固定间距

本题的双指针并不是为了：

```text
一快一慢找环
```

而是为了维持：

```text
固定距离
```

这种技巧很常见。

如果：

```text
fast 永远领先 slow k 步
```

那么当 fast 到某个边界时，slow 就自动对应到“距离该边界 k 步”的位置。

这可以解决：

- 倒数第 $k$ 个节点；
- 删除倒数第 $k$ 个节点；
- 链表中点；
- 固定窗口大小；
- 一些滑动窗口结构。

---

## 20. 和“链表中点”有什么联系

如果：

```text
fast 每次走 2 步
slow 每次走 1 步
```

那么 fast 到末尾时，slow 到中点。

这是：

```text
速度差
```

型双指针。

而本题：

```text
fast 和 slow 速度相同
但初始间距固定
```

属于：

```text
距离差
```

型双指针。

两者都是“利用相对位置关系定位目标”。

---

## 21. 常见错误

### 错误一：不用 dummy，忘了处理删除头节点

这是最常见的边界问题。

---

### 错误二：fast 领先步数与循环条件不匹配

例如：

```text
先走 n
while fast != null
```

通常会让 slow 多走一步。

---

### 错误三：让 slow 停在目标节点本身

单链表删除需要前驱。

应该确保最终：

```text
slow.next = 待删除节点
```

---

### 错误四：返回原 `head`

如果删除的就是原头节点，原 `head` 已经不再是新链表头。

必须返回：

```cpp
dummy.next
```

---

## 22. C++ 内存释放说明

LeetCode 环境中常见写法：

```cpp
slow->next = slow->next->next;
```

即可通过。

如果在需要手动管理内存的真实 C++ 场景中，可以：

```cpp
ListNode* target = slow->next;

slow->next = target->next;

delete target;
```

这样能显式释放被删除节点。

## 23. 一眼识别本题

看到：

```text

要求一趟扫描
```

立刻想到：

```text

```


```text

```

或者：

```text

```

## 25. 本题总结

这道题的核心不是“倒着数”，而是：

> **通过快慢指针把“倒数位置”转换成“固定间距”。**

完整思维链：

```text
要找倒数第 N 个
      ↓
链表无法从后往前
      ↓
让 fast 领先 slow
      ↓
两个指针保持固定距离
      ↓
fast 到末尾
      ↓
slow 自动定位
```

删除时再加一个关键技巧：

```text
使用 dummy
让 slow 停在目标前驱
```

最终模板：

```text
dummy
fast / slow
fast 先走 n
while fast.next:
    fast = fast.next
    slow = slow.next

slow.next = slow.next.next
```

这是链表“双指针定位倒数位置”的经典模板。
