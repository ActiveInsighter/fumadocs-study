# 哈希表总结

这一章从最基础的哈希函数与冲突处理，一直练到了：

- 频次统计；
- 集合交集；
- 状态判重；
- 补数查找；
- 组合计数；
- 排序 + 双指针的 nSum。

真正需要带走的并不是某几个容器 API，而是：

> **看到题目后，能判断“我要快速查询什么”，再选择最合适的数据结构。**

---

## 1. 哈希表最核心的作用

哈希表最典型的用途是：

> **快速判断某个 key 是否出现过，或者快速找到 key 对应的信息。**

理想情况下：

- 查询：平均 $O(1)$；
- 插入：平均 $O(1)$；
- 删除：平均 $O(1)$。

它本质上是在建立：

$$
key\rightarrow information
$$

映射。

---

## 2. 三类最常见的“哈希结构”

算法题里最常见的是：

```text
数组
Set
Map
```

它们都可以承担“快速查询”的作用，但适用场景不同。

---

## 3. 数组：值域小而固定

当 key 满足：

```text
范围固定
范围很小
下标可以直接映射
```

优先考虑数组。

例如：

```text
'a' ~ 'z'
0 ~ 1000
ASCII
```

映射：

$$
index=c-'a'
$$

就可以让：

```cpp
record[index]
```

直接保存频次或状态。

### 典型题目

- 有效的字母异位词；
- 查找常用字符；
- 赎金信。

---

## 4. 为什么数组往往比通用 Map 更好

若值域只有 26 个字符，却使用：

```cpp
unordered_map<char, int>
```

虽然也能做，但需要：

- 计算哈希；
- 管理桶；
- 处理潜在冲突；
- 保存额外结构信息。

而数组：

```cpp
int record[26];
```

更加直接。

所以不要机械地认为：

> “哈希题就必须使用 `unordered_map`。”

数组本身也可以承担哈希映射。

---

## 5. Set：只关心“有没有”

当题目只需要回答：

```text
某个 key 是否出现过？
```

可以考虑 Set。

### 典型题目

#### 两个数组的交集

需要：

```text
某个值是否存在
```

而答案还必须去重。

#### 快乐数

需要：

```text
当前状态以前是否出现过
```

如果重复，就说明进入循环。

所以 Set 很适合：

```text
存在性判断
状态判重
去重
```

---

## 6. Map：需要 key 对应额外信息

如果仅知道：

```text
key 是否存在
```

还不够，而是需要：

```text
key 对应什么
```

则使用 Map。

例如：

```text
值 -> 下标
和 -> 出现次数
前缀和 -> 出现次数
字符 -> 频次
```

### 典型题目

#### 两数之和

保存：

```text
元素值 -> 下标
```

#### 四数相加 II

保存：

```text
两数和 -> 出现次数
```

---

## 7. 一句话判断 Set 和 Map

可以直接记：

```text
只回答“有 / 没有” → Set

还要回答“在哪里 / 几次 / 对应什么” → Map
```

这是最实用的区别。

---

## 8. C++ 中有序容器与哈希容器

### Set 家族

| 容器 | 常见底层结构 | 有序 | 重复 | 查询 |
| --- | --- | --- | --- | --- |
| `set` | 红黑树 | 是 | 否 | $O(\log n)$ |
| `multiset` | 红黑树 | 是 | 是 | $O(\log n)$ |
| `unordered_set` | 哈希表 | 否 | 否 | 平均 $O(1)$ |

### Map 家族

| 容器 | 常见底层结构 | key 有序 | key 重复 | 查询 |
| --- | --- | --- | --- | --- |
| `map` | 红黑树 | 是 | 否 | $O(\log n)$ |
| `multimap` | 红黑树 | 是 | 是 | $O(\log n)$ |
| `unordered_map` | 哈希表 | 否 | 否 | 平均 $O(1)$ |

如果题目：

```text
不需要有序
只追求快速查找
```

通常优先考虑：

```cpp
unordered_set
unordered_map
```

---

## 9. 频次数组的三种核心操作

这一章中多次使用长度为 26 的数组，但不同题目的数学关系并不相同。

---

### 9.1 做差归零

有效的字母异位词：

$$
count_s(c)-count_t(c)=0
$$

模式：

```text
一边 +1
一边 -1
最后全部为 0
```

适合判断：

```text
两个多重集合是否完全相等
```

---

### 9.2 逐元素取最小值

查找常用字符：

$$
count_{common}(c)
=
\min_i count_i(c)
$$

适合：

```text
多个多重集合求交集
```

---

### 9.3 供给减需求

赎金信：

$$
count_{magazine}(c)
-
count_{ransom}(c)
\ge 0
$$

模式：

```text
先加库存
再减需求
出现负数立即失败
```

适合：

```text
资源是否足够
```

---

## 10. 三道频次题的统一视角

| 题目 | 数学关系 | 核心操作 |
| --- | --- | --- |
| 有效的字母异位词 | $A=B$ | 做差归零 |
| 查找常用字符 | $A\cap B\cap\cdots$ | 逐项取 `min` |
| 赎金信 | $A\supseteq B$ | 供给减需求 |

这说明：

> **频次数组不是一种固定模板，而是把字符集合转成向量后做数学运算。**

---

## 11. 状态判重模型

快乐数体现的是另一类非常重要的哈希思想：

```text
状态 -> 是否访问过
```

如果一个过程是确定性转移：

$$
x_{k+1}=f(x_k)
$$

而某个状态重复：

$$
x_i=x_j
$$

则之后轨迹也会重复。

所以：

```text
重复状态 → 成环
```

可以使用：

```cpp
unordered_set<State>
```

这种模型广泛用于：

- 图搜索；
- BFS / DFS；
- 游戏状态；
- 模拟；
- 数字迭代；
- 字符串变换。

---

## 12. 补数查找模型

两数之和是最经典的“补数”问题。

原式：

$$
x+y=target
$$

变形：

$$
y=target-x
$$

遍历当前元素 $x$ 时，只需查询：

```text
target - x 是否出现过
```

如果还需要它的下标，就保存：

```text
值 -> 下标
```

模板：

```cpp
for (int i = 0; i < n; ++i) {
    int need = target - nums[i];

    if (need 在 Map 中) {
        返回答案;
    }

    Map[nums[i]] = i;
}
```

---

## 13. 为什么“两数之和”强调先查后存

因为：

```text
同一个元素不能使用两次
```

先查后存保证：

> Map 中只有当前位置之前的元素。

因此查询到的 complement 一定来自另一个下标。

这种“在线查询历史”的思想非常重要。

---

## 14. 计数型 Map

四数相加 II 使用：

```text
两数和 -> 出现次数
```

当题目问：

```text
多少种方案
多少个组合
出现多少次
```

Map 的 value 往往应该保存：

```text
count
```

经典模板：

```cpp
++freq[key];
```

之后：

```cpp
answer += freq[need];
```

---

## 15. Meet-in-the-Middle

四数相加 II：

$$
a+b+c+d=0
$$

可以拆成：

$$
a+b=-(c+d)
$$

把 4 个变量分成：

```text
2 + 2
```

然后：

```text
左半组合 → 哈希统计
右半组合 → 查询互补值
```

把：

$$
O(n^4)
$$

降到：

$$
O(n^2)
$$

这类方法称为：

> Meet-in-the-Middle。

---

## 16. 哈希不是万能答案

三数之和和四数之和虽然也可以尝试哈希，但去重会非常麻烦。

这两题更适合：

```text
排序 + 双指针
```

原因：

- 同一个数组；
- 返回不重复数值组合；
- 排序后重复值聚在一起；
- 双指针可以利用单调性；
- 去重逻辑清晰。

所以：

> **能用哈希，不等于应该用哈希。**

---

## 17. 两数之和、三数之和、四数之和如何区分

### 两数之和

要求：

```text
返回原始下标
```

排序会破坏原始位置关系。

推荐：

```text
哈希 Map
```

时间：

$$
O(n)
$$

---

### 三数之和

要求：

```text
返回不重复三元组
```

推荐：

```text
排序 + 双指针
```

时间：

$$
O(n^2)
$$

---

### 四数之和

要求：

```text
返回不重复四元组
```

推荐：

```text
排序 + 两层固定 + 双指针
```

时间：

$$
O(n^3)
$$

---

## 18. 四数相加 II 为什么反而更快

虽然也是“四个数”，但它：

```text
来自四个独立数组
只统计组合数量
不要求值去重
```

因此可以分组统计：

$$
(a+b)+(c+d)=0
$$

时间复杂度：

$$
O(n^2)
$$

所以题名相似不代表算法相似。

关键要看：

```text
数据来自哪里
返回什么
是否去重
是否需要下标
```

---

## 19. 一套完整的数据结构选择流程

遇到题目时，可以按下面的顺序判断。

```text
我需要快速查询什么？
        ↓
key 的值域小而连续吗？
 ├─ 是 → 数组
 └─ 否
        ↓
只需要判断存在性吗？
 ├─ 是 → Set
 └─ 否
        ↓
需要额外保存信息
        ↓
Map
```

然后再继续问：

```text
题目是不是要求不重复组合？
        ↓
       是
        ↓
排序后是否能利用单调性？
        ↓
       是
        ↓
考虑排序 + 双指针
```

## 20. 哈希题的五类高频模型

可以把这一章归纳成五类。

### 模型一：频次统计

```text
key -> 次数
```

典型：

- 异位词；
- 赎金信；
- 公共字符。

---

### 模型二：存在性查询

```text
key -> 是否出现
```

典型：

- 两个数组的交集。

---

### 模型三：状态判重

```text
state -> 是否访问过
```

典型：

- 快乐数。

---

### 模型四：信息映射

```text
key -> 下标 / 位置 / 其他信息
```

典型：

- 两数之和。

---

### 模型五：组合计数

```text
组合值 -> 出现次数
```

典型：

- 四数相加 II。

---

## 21. 高频判断：数组、Set、Map 到底选谁

### 选数组

当：

```text
key 范围小
key 连续
值域确定
```

例如：

```text
26 个字母
1001 个整数
```

---

### 选 Set

当：

```text
只关心有没有
不需要额外 value
```

---

### 选 Map

当：

```text
除了 key，还要保存额外信息
```

比如：

```text
下标
次数
首个位置
最后位置
状态
```

---

## 22. 不要忽略值域大小

假设只有三个 key：

```text
1
100000000
999999999
```

虽然数组下标查询也是 $O(1)$，但为了这三个元素开接近：

$$
10^9
$$

规模的数组显然浪费。

因此：

> 数组是否合适，不只看访问复杂度，还要看值域是否稠密。

---

## 23. 哈希复杂度中的“平均 O(1)”

对于：

```cpp
unordered_map
unordered_set
```

常说查询平均：

$$
O(1)
$$

但这不是绝对最坏界。

如果大量 key 发生严重冲突，性能可能退化。

因此更严谨的说法是：

> 在哈希函数合理、负载因子受控的情况下，平均查询、插入、删除为 $O(1)$。

---

## 24. 排序 + 双指针的统一框架

三数之和与四数之和可以统一成：

```text
nSum
 ↓ 固定一个数
(n-1)Sum
 ↓
...
 ↓
2Sum
```

而有序数组上的 `2Sum`：

```text
left < right

sum < target → left++
sum > target → right--
sum = target → 记录 + 去重
```

所以双指针的真正基础是：

> **排序后的单调性。**

---

## 25. 为什么去重要分层

三数之和：

```text
a 去重
b 去重
c 去重
```

四数之和：

```text
a 去重
b 去重
c 去重
d 去重
```

但要注意：

> 去重的是“答案组合”，不是禁止组合内部出现相同数字。

例如：

```text
[-1, -1, 2]
[0, 0, 0]
[0, 0, 0, 0]
```

都可以是合法答案。

## 26. 本章题目速查表

| 题目 | 核心结构 | 关键映射 | 复杂度 |
| --- | --- | --- | --- |
| 有效的字母异位词 | 数组 | 字符 → 频次差 | $O(n)$ |
| 查找常用字符 | 数组 | 字符 → 最小公共频次 | $O(\sum n_i)$ |
| 两个数组的交集 | Set / 数组 | 元素 → 是否存在 | $O(n+m)$ |
| 快乐数 | Set | 状态 → 是否访问 | 近似 $O(\log n)$ |
| 两数之和 | Map | 值 → 下标 | $O(n)$ |
| 四数相加 II | Map | 两数和 → 次数 | $O(n^2)$ |
| 赎金信 | 数组 | 字符 → 剩余库存 | $O(n+m)$ |
| 三数之和 | 排序 + 双指针 | 无显式哈希 | $O(n^2)$ |
| 四数之和 | 排序 + 双指针 | 无显式哈希 | $O(n^3)$ |

## 27. 做题时的五个自问

看到一道新题，先问：

### 第一问

> 我要快速查询什么？

---

### 第二问

> 查询对象的值域是否足够小？

决定：

```text
数组 or 通用哈希结构
```

---

### 第三问

> 我只需要知道“有没有”，还是还要额外信息？

决定：

```text
Set or Map
```

---

### 第四问

> 题目是否要求计数？

如果要求：

```text
多少次 / 多少种 / 多少组
```

通常需要：

```text
Map<key, count>
```

---

### 第五问

> 题目是否要求返回所有不重复组合？

如果是，并且排序后能利用单调性，那么应优先考虑：

```text
排序 + 双指针
```

## 28. 最终决策树

```text
               需要快速查询
                    │
                    ▼
          key 值域小且连续？
             /            \
           是              否
           │               │
           ▼               ▼
         数组          只关心存在？
                        /       \
                      是         否
                      │          │
                      ▼          ▼
                     Set        Map
                                 │
                                 ▼
                    value 是什么信息？
                    ├─ 下标
                    ├─ 次数
                    ├─ 状态
                    └─ 其他映射
```

如果题目进一步是：

```text
同一数组
求不重复组合
排序后有单调性
```

则考虑跳出哈希框架，转向：

```text
排序 + 双指针
```

## 29. 这一章真正应该形成的能力

不是看到题名就背模板，而是能完成下面这条推理链：

```text
题目要求什么？
      ↓
我要快速查什么？
      ↓
key 是什么？
      ↓
需要 value 吗？
      ↓
值域是否适合数组？
      ↓
是否存在重复 / 去重问题？
      ↓
哈希还是排序 + 双指针？
```

这套判断方法比记住某个 `unordered_map` API 更重要。

---

## 30. 本章总结

哈希表可以概括为一句话：

> **把“查找”问题转化为“映射”问题。**

对刷题最重要的四条结论：

1. **值域小而固定，用数组。**
2. **只关心有没有，用 Set。**
3. **还需要附加信息，用 Map。**
4. **若问题核心变成“不重复组合”，排序 + 双指针往往比哈希更自然。**

把这四条真正掌握后，哈希表章节就不再是一组零散题目，而会变成一套稳定的题型识别框架。
