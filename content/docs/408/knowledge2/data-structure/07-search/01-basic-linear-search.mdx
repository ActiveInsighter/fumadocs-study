查找问题的核心是：**给定关键字，在查找表中确定目标记录是否存在，并尽量减少关键字比较次数、地址探测次数或外存访问次数。**

408 中，本章通常沿三条主线考查：

| 主线 | 典型结构 | 最常考内容 |
| --- | --- | --- |
| 线性表查找 | 顺序查找、折半查找、分块查找 | 适用条件、判定树、ASL |
| 树形查找 | BST、AVL、红黑树、B 树、B+ 树 | 树高、结点性质、插入删除 |
| 散列表查找 | 哈希表 | 冲突处理、装填因子、成功/失败 ASL |

<Callout type="info" title="本章统一做题思路">

遇到查找题，先判断 **“数据是否有序、能否随机访问、是否允许动态插删、数据是否在外存”**，再选择查找结构。不要脱离前提单独背复杂度。

</Callout>

## 1. 查找的基本概念

### 1.1 查找表

**查找表**是由同一类型的数据元素构成的集合，常见操作包括：

* 查询某个关键字是否存在；
* 取得满足条件的记录；
* 插入记录；
* 删除记录。

若查找过程中主要进行查询，不改变集合内容，通常称为**静态查找表**；若还需要频繁插入、删除，则属于**动态查找表**。

> 静态与动态描述的是**操作集合**，不是说数据一定存放在某种特定物理存储结构中。

### 1.2 关键字

**关键字（Key）**是记录中用于查找的数据项。

例如学生记录：

```text
<学号, 姓名, 成绩>
```

若按学号查询，则学号是关键字。

若一个关键字能够唯一标识一条记录，可称为**主关键字**；若不能唯一标识，可能一次查到多条记录。

### 1.3 查找成功与查找失败

* **查找成功**：表中存在关键字等于目标值的记录；
* **查找失败**：搜索过程结束后仍未找到目标关键字。

408 计算 ASL 时，成功和失败往往要**分别计算**，二者的状态空间和概率分布通常不同，不能直接混为一个平均值。

### 1.4 平均查找长度 ASL

平均查找长度（Average Search Length，ASL）用于衡量一次查找平均需要进行多少次关键操作。

一般形式为：

$$
ASL=\sum_{i=1}^{n}P_iL_i
$$

其中：

* $P_i$：第 $i$ 种查找情况出现的概率；
* $L_i$：该情况下的查找长度。

若各情况等概率，则：

$$
ASL=\frac{\sum L_i}{\text{情况数}}
$$

### 1.5 “查找长度”到底数什么

不同查找结构的计数对象可能不同：

| 结构 | 常见计数对象 |
| --- | --- |
| 顺序查找、折半查找 | 关键字比较次数 |
| BST / AVL / B 树 | 访问结点数或关键字比较次数，按题意 |
| 散列表 | 探测的散列地址数或关键字比较次数，按题意 |

<Callout type="warn" title="ASL 最常见失分点">

先看题目如何定义“查找长度”。特别是散列表失败查找，若按探测地址数计数，**最终探测到空位置的那一次也必须计入**。

</Callout>

### 2.1 顺序查找

顺序查找（Sequential Search）的思想是：

> 从表的一端开始，依次比较记录的关键字，直到找到目标，或所有候选记录都被检查完。

普通实现：

```c
int SequentialSearch(int A[], int n, int key) {
    for (int i = 0; i < n; ++i) {
        if (A[i] == key) {
            return i;
        }
    }
    return -1;
}
```

其复杂度为：

| 情况 | 时间复杂度 |
| --- | --- |
| 最好 | $O(1)$ |
| 最坏 | $O(n)$ |
| 平均 | $O(n)$ |

若 $n$ 个元素成功查找概率相同，并从第一个元素开始比较，则：

$$
ASL_{\text{成功}}
=\frac{1+2+\cdots+n}{n}
=\frac{n+1}{2}
$$

对于上述**无哨兵**实现，查找失败需要检查全部 $n$ 个元素，因此：

$$
ASL_{\text{失败}}=n
$$

顺序查找的适用限制最少：

* 表可以有序，也可以无序；
* 顺序存储、链式存储都能使用；
* 数据规模较小时实现简单。

### 2.2 带哨兵的顺序查找

教材中还常见“把目标关键字临时放到哨兵位置”的写法，用哨兵避免循环中反复检查数组边界。

以 1 基数组为例，可把 `A[0]` 作为哨兵：

```c
int SearchSeq(int A[], int n, int key) {
    A[0] = key;
    int i = n;

    while (A[i] != key) {
        --i;
    }

    return i;   // 0 表示查找失败
}
```

若把与哨兵的最后一次关键字比较也计入，则查找失败的查找长度为：

$$
n+1
$$

因此：

<Callout type="warn" title="顺序查找失败 ASL 不是永远等于 n">

无哨兵实现按正文代码计数时失败为 $n$ 次；经典哨兵实现若把最终与哨兵的比较计入，则失败为 $n+1$ 次。考试必须服从题目给出的算法和计数口径。

</Callout>

### 2.3 折半查找的前提

折半查找（Binary Search）需要同时满足两个核心条件：

1. **关键字有序**；
2. 能高效随机访问中间位置，通常采用**顺序存储**。

因此：

* 有序数组非常适合折半查找；
* 普通单链表即使有序，也不能高效进行标准折半查找，因为定位中点本身不是 $O(1)$。

<Callout type="warn" title="折半查找的两个条件缺一不可">

“有序”只保证可以排除一半元素；“随机访问”才保证找到中点足够快。普通链表上机械地使用折半思想，整体复杂度不会自然变成 $O(\log n)$。

</Callout>

### 2.4 折半查找过程

设当前闭区间为：

$$
[low,high]
$$

中点通常写为：

$$
mid=low+\left\lfloor\frac{high-low}{2}\right\rfloor
$$

然后比较 `key` 与 `A[mid]`：

* `key == A[mid]`：成功；
* `key < A[mid]`：令 $high=mid-1$；
* `key > A[mid]`：令 $low=mid+1$。

迭代实现：

```c
int BinarySearch(int A[], int n, int key) {
    int low = 0;
    int high = n - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;

        if (A[mid] == key) {
            return mid;
        }
        if (A[mid] < key) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }

    return -1;
}
```

推荐写成：

```c
mid = low + (high - low) / 2;
```

而不是：

```c
mid = (low + high) / 2;
```

原因是前者避免了 `low + high` 可能发生的整数溢出。

递归实现：

```c
int BinarySearchRecursive(int A[], int low, int high, int key) {
    if (low > high) {
        return -1;
    }

    int mid = low + (high - low) / 2;

    if (A[mid] == key) {
        return mid;
    }
    if (A[mid] < key) {
        return BinarySearchRecursive(A, mid + 1, high, key);
    }
    return BinarySearchRecursive(A, low, mid - 1, key);
}
```

每次比较后，剩余规模约减半：

$$
T(n)=T(n/2)+O(1)
$$

因此：

$$
T(n)=O(\log_2 n)
$$

### 2.5 折半查找判定树

<InlineSvg src="/images/data-structure/search/array/figure-002.svg" alt="数组 10、20、30、40、50、60 对应的折半查找判定树" />

折半查找的比较过程可以表示为一棵**判定树**：

* 每个内部圆结点对应表中一个元素，即一次可能成功的关键字比较；
* 根结点对应第一次选取的 `mid`；
* 左子树对应目标更小；
* 右子树对应目标更大。

例如有序表：

```text
10 20 30 40 50 60
```

若采用：

```c
mid = (low + high) / 2;
```

并进行整数向下取整，则第一次比较 `30`。

随后：

* 左区间 `[10, 20]` 的根为 `10`；
* 右区间 `[40, 50, 60]` 的根为 `50`。

<Callout type="warn" title="偶数个元素时判定树不唯一">

若题目采用不同的 `mid` 规则，偶数长度区间可能选择左中点或右中点，从而得到不同判定树。**必须严格按照题目指定的中点规则构造。**

</Callout>

### 2.6 判定树高度、成功 ASL 与失败 ASL

对于 $n>0$ 个元素，折半查找判定树的最大成功比较次数为：

$$
\left\lfloor\log_2 n\right\rfloor+1
$$

也可写成：

$$
\left\lceil\log_2(n+1)\right\rceil
$$

若某元素所在判定树层数为 $l_i$，则成功查找该元素需要比较 $l_i$ 次。

等概率成功查找时：

$$
ASL_{\text{成功}}
=\frac{\sum_{i=1}^{n}l_i}{n}
$$

失败查找不能直接沿用成功结点的平均值。判定树中可把每个“查到空区间”的位置看成一个**失败结点**。对于含 $n$ 个成功结点的二叉判定树，失败区间共有：

$$
n+1
$$

个。

若各失败区间等概率，则应对这些失败路径的比较次数单独求平均。

> **判定树手算步骤**
>
> 1. 按题目 `mid` 规则画出成功结点；
> 2. 需要失败 ASL 时，再补出 $n+1$ 个失败区间；
> 3. 写出每个成功/失败状态对应的比较次数；
> 4. 最后按给定概率加权。

### 2.7 分块查找

<InlineSvg src="/images/data-structure/search/array/figure-003.svg" alt="分块查找的索引表与数据块" />

分块查找又称**索引顺序查找**，介于顺序查找和折半查找之间。

它把查找表划分成若干块，并为每块建立索引项。典型要求是：

> **块内可以无序，但块间必须有序。**

若索引保存“每块最大关键字”，则应满足：

```text
第 1 块所有关键字 < 第 2 块所有关键字 < 第 3 块所有关键字 < ...
```

查找分两步：

1. 在索引表中确定目标可能属于哪一块；
2. 在目标块内部顺序查找。

因此：

$$
ASL_{\text{分块}}
=
ASL_{\text{索引}}
+
ASL_{\text{块内}}
$$

假设有 $b$ 块，每块 $s$ 个元素：

$$
n=bs
$$

若索引表采用顺序查找、各块和块内元素等概率，则成功 ASL 近似为：

$$
ASL
=\frac{b+1}{2}+\frac{s+1}{2}
$$

代入 $b=n/s$：

$$
ASL
=\frac{n/s+s}{2}+1
$$

当：

$$
s\approx\sqrt n
$$

时，两部分代价较均衡，此时 ASL 为 $O(\sqrt n)$ 量级。

若索引表本身有序并用折半查找，则查找复杂度可理解为：

$$
O(\log b+s)
$$

### 2.8 三种线性表查找方法对比

| 方法 | 关键字要求 | 存储结构要求 | 典型复杂度 | 主要特点 |
| --- | --- | --- | --- | --- |
| 顺序查找 | 无序也可 | 顺序、链式均可 | $O(n)$ | 限制少 |
| 折半查找 | 必须有序 | 适合随机访问的顺序表 | $O(\log n)$ | 比较次数少 |
| 分块查找 | 块间有序、块内可无序 | 通常配合索引 | 介于两者之间 | 折中方案 |

## 3. 树形查找

### 3.1 BST、AVL 与红黑树的查找主线

<InlineSvg src="/images/data-structure/search/tree/figure-001.svg" alt="二叉搜索树中查找关键字 35 的路径" />

二叉搜索树 BST 满足：

* 左子树所有关键字小于根关键字；
* 右子树所有关键字大于根关键字；
* 左、右子树也分别是二叉搜索树。

因此搜索过程不断执行：

```text
与当前结点比较
├─ 相等：成功
├─ 更小：进入左子树
└─ 更大：进入右子树
```

查找代价与树高 $h$ 同阶：

$$
T=O(h)
$$

于是：

| 结构 | 最坏树高 | 最坏查找复杂度 | 原因 |
| --- | --- | --- | --- |
| 普通 BST | $O(n)$ | $O(n)$ | 可能退化成链 |
| AVL | $O(\log n)$ | $O(\log n)$ | 严格限制平衡因子 |
| 红黑树 | $O(\log n)$ | $O(\log n)$ | 用颜色规则限制最长路径 |

例如按升序依次向普通 BST 插入：

```text
1, 2, 3, 4, 5, ...
```

可能退化成单链形态，从而使查找复杂度退化到：

$$
O(n)
$$

### 3.2 为什么还需要 B 树与 B+ 树

AVL、红黑树虽然保证对数级树高，但它们仍是**二叉树**：一个结点最多只有两个孩子。

当数据位于磁盘等外存中时，真正昂贵的通常不是 CPU 中的一次关键字比较，而是一次**磁盘页 I/O**。

因此外存索引更希望：

> 一个结点一次装入很多关键字和孩子指针，用更大的分支因子换取更低的树高。

这就是 B 树与 B+ 树的核心动机。

<Callout type="info" title="从二叉平衡树过渡到 B 树">

BST / AVL / 红黑树关注“如何避免二叉树过高”；B 树 / B+ 树进一步通过**多路分支**显著降低外存索引层数。

</Callout>
