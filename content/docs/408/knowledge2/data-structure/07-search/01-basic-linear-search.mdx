查找的核心目标是：**给定一个关键字，在查找表中确定是否存在与之匹配的记录，并尽可能减少比较或探测次数。**

408 对本章的考查主要集中在以下三条主线：

1. **线性表上的查找**：顺序查找、折半查找、分块查找。
2. **树形查找**：BST、AVL、红黑树，以及重点考查的 B 树和 B+ 树。
3. **散列表查找**：散列函数、冲突处理、装填因子，以及成功/失败的平均查找长度 ASL。

其中，**B 树的阶数与结点性质、B 树与 B+ 树的区别、开放定址法的探测过程、散列表 ASL 的计算**是选择题和综合题中的重点。

## 1. 查找的基本概念

### 1.1 查找表

**查找表**是由同一类型的数据元素构成的集合，主要操作包括：

* 查询某个关键字是否存在；
* 获取满足条件的记录；
* 插入记录；
* 删除记录。

如果查找过程中只进行查询，一般称为**静态查找表**；如果还需要频繁插入、删除，则属于**动态查找表**。

### 1.2 关键字

**关键字 Key** 是数据元素中用于唯一或部分标识记录的数据项。

例如一条学生记录：

```text
<学号, 姓名, 成绩>
```

如果通过学号进行查找，则学号就是关键字。

### 1.3 平均查找长度 ASL

平均查找长度 Average Search Length，简称 **ASL**，是衡量查找效率的重要指标。

其本质是查找过程中**关键字比较次数或地址探测次数的数学期望**：

$$
ASL=\sum_{i=1}^{n}P_iL_i
$$

其中：

$$
P_i
$$

表示第 $i$ 种查找请求出现的概率，

$$
L_i
$$

表示对应请求需要进行的比较或探测次数。

如果各种查找请求等概率，则 ASL 就是所有查找长度的算术平均值。

> **408 易错点**
>
> “查找长度”究竟统计**比较次数**还是**探测次数**，要依据题目和算法而定。
>
> 散列表题中通常按“访问了多少个散列地址”计算，**最后访问到空位置的那一次也要计入查找失败的探测次数**。

## 2. 线性表上的查找

### 2.1 顺序查找

顺序查找 Sequential Search 的思想最直接：

> 从线性表的一端开始，依次比较每个元素的关键字，直到找到目标，或者整个表都被检查完毕。

### 算法实现

```c
int SequentialSearch(int A[], int n, int value) {
    for (int i = 0; i < n; i++) {
        if (A[i] == value) {
            return i;
        }
    }

    return -1;
}
```

### 时间复杂度

| 情况   | 时间复杂度    |
| ---- | -------- |
| 最好情况 | $O(1)$ |
| 最坏情况 | $O(n)$ |
| 平均情况 | $O(n)$ |

当表中有 $n$ 个元素，并且每个元素被成功查找到的概率相同时，第 $i$ 个元素的查找长度为 $i$，因此：

$$
ASL_{\text{成功}}
=
\frac{1+2+\cdots+n}{n}
=
\frac{n+1}{2}
$$

对于上面的普通无哨兵实现，查找失败时需要检查全部 $n$ 个元素：

$$
ASL_{\text{失败}}=n
$$

### 特点

顺序查找的优点是限制少：

* 表可以有序，也可以无序；
* 顺序存储和链式存储都可以使用；
* 算法简单。

缺点是：

* 当数据规模较大时效率低；
* 平均仍需要线性数量级的比较。

### 2.2 折半查找

折半查找 Binary Search 的前提是：

> **查找表必须按关键字有序，并且需要能够随机访问中间元素，因此通常用于顺序存储结构。**

它不能直接高效应用于普通单链表，因为链表无法在 $O(1)$ 时间内访问中间位置。

### 核心思想

设当前查找区间为：

$$
[low,high]
$$

每次取中间位置：

$$
mid=
low+\left\lfloor
\frac{high-low}{2}
\right\rfloor
$$

将目标值与：

$$
A[mid]
$$

比较。

如果：

$$
key=A[mid]
$$

则查找成功。

如果：

$$
key<A[mid]
$$

则继续在左半区间查找。

如果：

$$
key>A[mid]
$$

则继续在右半区间查找。

<InlineSvg src="/images/data-structure/search/array/figure-001.svg" alt={"在有序数组中折半查找 23 的过程"} />

### 迭代实现

```c
int BinarySearch(int A[], int n, int value) {
    int low = 0;
    int high = n - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;

        if (A[mid] == value) {
            return mid;
        } else if (A[mid] < value) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }

    return -1;
}
```

这里使用：

```c
mid = low + (high - low) / 2;
```

而不是直接使用：

```c
mid = (low + high) / 2;
```

可以避免在整数范围有限时：

$$
low+high
$$

发生溢出。

### 递归实现

```c
int BinarySearchRecursive(
    int A[],
    int low,
    int high,
    int value
) {
    if (low > high) {
        return -1;
    }

    int mid = low + (high - low) / 2;

    if (A[mid] == value) {
        return mid;
    } else if (A[mid] < value) {
        return BinarySearchRecursive(
            A,
            mid + 1,
            high,
            value
        );
    } else {
        return BinarySearchRecursive(
            A,
            low,
            mid - 1,
            value
        );
    }
}
```

### 时间复杂度

每次比较都会把剩余查找范围缩小约一半，因此：

$$
T(n)=T(n/2)+O(1)
$$

于是：

$$
T(n)=O(\log_2 n)
$$

所以：

| 情况   | 时间复杂度           |
| ---- | --------------- |
| 最好情况 | $O(1)$        |
| 最坏情况 | $O(\log_2 n)$ |
| 平均情况 | $O(\log_2 n)$ |

### 2.3 折半查找判定树

折半查找的整个比较过程可以表示成一棵**判定树**。

判定树中的：

* 每个圆结点对应一次成功比较；
* 根结点是第一次比较的元素；
* 左子树表示目标关键字较小；
* 右子树表示目标关键字较大。

例如有序数组：

```text
[10, 20, 30, 40, 50, 60]
```

若中点采用：

```c
mid = (low + high) / 2;
```

即偶数个元素时选择左中点，则第一次选择：

```text
30
```

随后：

* 左区间 `[10,20]` 选择 `10`；
* 右区间 `[40,50,60]` 选择 `50`。

最终得到：

<InlineSvg src="/images/data-structure/search/array/figure-002.svg" alt={"数组 10、20、30、40、50、60 对应的折半查找判定树"} />

### 判定树与复杂度

折半查找判定树是一棵近似平衡的二叉树。

对于长度为 $n$ 的有序表，判定树高度约为：

$$
\left\lfloor \log_2 n \right\rfloor+1
$$

因此最坏查找比较次数为：

$$
O(\log_2 n)
$$

> **易错点：偶数个元素时根不唯一**
>
> 如果算法规定向下取整，则选左中点；如果规定向上取整，则可能选右中点。
>
> 两种方式形成的判定树可能不同，但都属于合法的折半查找过程。考试时应严格按照题目给出的 `mid` 计算规则构造。

### 2.4 分块查找

分块查找又称**索引顺序查找**。

它介于顺序查找与折半查找之间。

基本思想是把线性表分成若干块，并建立一个索引表。

通常要求：

> **块内元素可以无序，但块与块之间必须有序。**

例如如果采用“每块最大关键字”作为索引项，则需要满足：

```text
第 1 块中的所有关键字
<
第 2 块中的所有关键字
<
第 3 块中的所有关键字
...
```

<InlineSvg src="/images/data-structure/search/array/figure-003.svg" alt={"分块查找的索引表与数据块"} />

### 查找过程

分块查找分两步。

**第一步：查索引表**

确定目标关键字可能位于哪个块。

索引表通常可以：

* 顺序查找；
* 折半查找。

**第二步：查块内元素**

由于块内通常无序，因此在目标块中进行顺序查找。

所以可以把总查找长度理解为：

$$
ASL_{\text{分块}}
=
ASL_{\text{索引}}
+
ASL_{\text{块内}}
$$

假设共 $b$ 块，每块约有 $s$ 个元素：

$$
n=bs
$$

如果索引表采用顺序查找，则在等概率条件下大致有：

$$
ASL
\approx
\frac{b+1}{2}
+
\frac{s+1}{2}
$$

当块大小与块数都在：

$$
\sqrt n
$$

量级时，可以获得较好的折中效果。

### 三种线性查找方法对比

| 方法   | 数据要求       | 存储要求    | 典型复杂度         |
| ---- | ---------- | ------- | ------------- |
| 顺序查找 | 无序也可       | 顺序、链式均可 | $O(n)$      |
| 折半查找 | 必须有序       | 适合顺序存储  | $O(\log n)$ |
| 分块查找 | 块间有序、块内可无序 | 通常顺序存储  | 介于两者之间        |

## 3. 树形查找

### 3.1 BST、AVL 与红黑树中的查找

二叉搜索树 BST 满足：

* 左子树中的所有关键字小于根；
* 右子树中的所有关键字大于根；
* 左、右子树仍然分别是二叉搜索树。

因此查找过程为：

1. 从根结点开始；
2. 若关键字相等，查找成功；
3. 若目标更小，进入左子树；
4. 若目标更大，进入右子树；
5. 到达空指针仍未找到，则查找失败。

<InlineSvg src="/images/data-structure/search/tree/figure-001.svg" alt={"二叉搜索树中查找关键字 35 的路径"} />

查找效率取决于树高：

| 树   | 平均时间复杂度       | 最坏时间复杂度       | 原因        |
| --- | ------------- | ------------- | --------- |
| BST | $O(\log n)$ | $O(n)$      | 可能退化为链表   |
| AVL | $O(\log n)$ | $O(\log n)$ | 严格控制平衡    |
| 红黑树 | $O(\log n)$ | $O(\log n)$ | 保证树高为对数量级 |

普通 BST 如果依次插入：

```text
1, 2, 3, 4, 5, ...
```

可能退化为：

```text
1
 \
  2
   \
    3
     \
      ...
```

此时查找复杂度退化为：

$$
O(n)
$$

AVL 和红黑树的意义之一就是限制树高，从而保证查找效率。
