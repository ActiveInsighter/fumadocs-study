查找的目标是：**根据给定关键字，在查找表中确定目标记录是否存在，并尽量减少比较或探测次数。**

本章的三条主线是：

1. 线性表查找：顺序查找、折半查找、分块查找；
2. 树形查找：BST、AVL、红黑树、B 树、B+ 树；
3. 散列查找：散列函数、冲突处理、装填因子与 ASL。

> **真题标签｜2010 第 9 题、2015 第 7 题、2016 第 9 题、2023 第 8 题、2024 第 5 题、2025 第 7 题：顺序查找、折半查找与分块查找**
>
> 高频考法集中在适用条件、折半查找判定树、比较次数和分块查找过程。

## 7.1.1 查找表与关键字

**查找表**是由同一类型数据元素构成的集合，典型操作包括：

- 查询记录是否存在；
- 获取满足条件的记录；
- 插入记录；
- 删除记录。

若查找过程中只进行查询，通常称为**静态查找表**；若还需要频繁插入和删除，则属于**动态查找表**。

关键字 `Key` 是用于标识记录的数据项。例如：

```text
<学号, 姓名, 成绩>
```

若按学号查找，则“学号”就是关键字。能唯一标识记录的关键字可称为**主关键字**；不能唯一标识记录的字段也可作为查找条件，但可能对应多条记录。

## 7.1.2 平均查找长度 ASL

平均查找长度（Average Search Length，ASL）用于衡量查找过程平均需要进行多少次关键字比较或地址探测。

一般写为：

$$
ASL=\sum_{i=1}^{n}P_iL_i
$$

其中：

- $P_i$：第 $i$ 种查找请求出现的概率；
- $L_i$：该请求对应的查找长度。

若各请求等概率，则 ASL 就是各查找长度的算术平均值。

> **易错点｜“查找长度”统计什么**
>
> 不同算法口径不同。顺序/折半查找通常统计关键字比较次数；散列表通常统计访问的散列地址数。散列失败查找中，**最后访问到用于确认失败的空槽也要计入探测次数**。

## 7.1.3 顺序查找

顺序查找从线性表一端开始，依次比较关键字，直到找到目标或检查完全部元素。

```c
int sequentialSearch(int A[], int n, int key) {
    for (int i = 0; i < n; ++i) {
        if (A[i] == key) return i;
    }
    return -1;
}
```

它的适用范围很广：

- 表可以有序，也可以无序；
- 顺序存储和链式存储都可使用；
- 不要求随机访问。

复杂度为：

| 情况 | 时间复杂度 |
| --- | ---: |
| 最好 | $O(1)$ |
| 平均 | $O(n)$ |
| 最坏 | $O(n)$ |

若 $n$ 个元素等概率被成功查找，则：

$$
ASL_{\text{成功}}
=\frac{1+2+\cdots+n}{n}
=\frac{n+1}{2}
$$

对普通无哨兵实现，失败时需比较全部 $n$ 个元素：

$$
ASL_{\text{失败}}=n
$$

### 哨兵思想

若数组预留位置 `A[0]`，可把待查关键字放入该位置作为哨兵，再从表尾向前查找：

```c
int searchWithSentinel(int A[], int n, int key) {
    A[0] = key;
    int i = n;
    while (A[i] != key) --i;
    return i;   // i==0 表示失败
}
```

哨兵的作用是减少循环中的边界判断，**不会改变顺序查找的渐进复杂度**。

## 7.1.4 折半查找的适用条件

折半查找（Binary Search）有两个关键前提：

1. 查找表按关键字有序；
2. 能够高效随机访问中间位置。

因此它最适合**有序顺序表**。普通单链表虽然可以保持有序，但每次寻找中点都需要沿指针移动，不能直接获得数组版本的高效折半查找。

设当前闭区间为：

$$
[low,high]
$$

常用中点为：

$$
mid=low+\left\lfloor\frac{high-low}{2}\right\rfloor
$$

迭代实现：

```c
int binarySearch(int A[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (A[mid] == key) return mid;
        if (A[mid] < key) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}
```

使用：

```c
low + (high - low) / 2
```

而不是直接写：

```c
(low + high) / 2
```

可以规避极端情况下 `low + high` 的整数溢出问题。

每次比较后，待查区间规模约缩小一半：

$$
T(n)=T(n/2)+O(1)
$$

因此：

$$
T(n)=O(\log_2 n)
$$

## 7.1.5 折半查找判定树

折半查找过程可表示成一棵判定树：

- 根结点：第一次比较的元素；
- 左子树：目标关键字更小；
- 右子树：目标关键字更大；
- 成功查找的比较次数等于相应结点所在层数（根按第 1 层计）。

例如有序表：

```text
10 20 30 40 50 60
```

若规定：

```c
mid = (low + high) / 2
```

整数除法向下取整，则第一次比较 `30`，后续左右区间继续按相同规则选中点。

长度为 $n$ 的折半查找判定树高度为：

$$
\lfloor\log_2 n\rfloor+1
$$

所以最坏成功比较次数不超过该数量级。

> **易错点｜偶数个元素时中点并不唯一**
>
> 向下取整通常选左中点，向上取整可能选右中点。两种规则都会得到合法判定树，但具体形状、某些元素的比较次数可能不同。考试时必须服从题目给出的 `mid` 规则。

### 成功与失败查找在判定树中的对应

成功查找对应判定树中的内部结点；失败查找可理解为落到某个“不存在的区间”。若题目要求失败 ASL，不要直接套成功查找层数，而应按题目给出的判定树或失败区间逐一统计。

## 7.1.6 分块查找

分块查找又称**索引顺序查找**。它把表分成若干块，并建立索引表。

核心要求通常是：

> **块内可以无序，但块间必须有序。**

若每个索引项保存该块最大关键字，则需满足：

```text
第 1 块全部关键字 < 第 2 块全部关键字 < ...
```

查找分两步：

1. 在索引表中确定目标可能所在块；
2. 在目标块内顺序查找。

因此可写成：

$$
ASL_{\text{分块}}
=ASL_{\text{索引}}+ASL_{\text{块内}}
$$

若共有 $b$ 块，每块约 $s$ 个元素，且：

$$
n=bs
$$

索引表采用顺序查找、各块及块内位置等概率时，可近似写为：

$$
ASL\approx\frac{b+1}{2}+\frac{s+1}{2}
$$

当 $b$ 与 $s$ 都在 $\sqrt n$ 量级时，可以取得较好的折中。

若索引表本身有序且采用折半查找，则索引阶段可降为 $O(\log b)$，但块内仍通常需要顺序查找。

## 7.1.7 三种线性表查找对比

| 方法 | 数据要求 | 存储要求 | 典型复杂度 | 关键考点 |
| --- | --- | --- | ---: | --- |
| 顺序查找 | 无特殊要求 | 顺序、链式均可 | $O(n)$ | ASL、哨兵 |
| 折半查找 | 必须有序 | 适合顺序存储 | $O(\log n)$ | 判定树、比较次数 |
| 分块查找 | 块间有序、块内可无序 | 常配合索引表 | 介于两者之间 | 两阶段 ASL |

> **考场判断顺序**
>
> 先问“是否有序”，再问“是否能随机访问”。有序但不能高效随机访问，并不意味着适合折半查找。

## 7.1.8 BST、AVL 与红黑树中的查找回顾

二叉搜索树（BST）的有序性决定了查找方向：

- $key$ 等于当前结点关键字：成功；
- $key$ 更小：进入左子树；
- $key$ 更大：进入右子树；
- 到达空指针：失败。

查找复杂度本质上取决于树高 $h$：

$$
T=O(h)
$$

因此：

| 结构 | 平均查找 | 最坏查找 | 原因 |
| --- | ---: | ---: | --- |
| BST | $O(\log n)$ | $O(n)$ | 可能退化成链 |
| AVL | $O(\log n)$ | $O(\log n)$ | 严格限制高度差 |
| 红黑树 | $O(\log n)$ | $O(\log n)$ | 通过较宽松平衡性质限制树高 |

若普通 BST 按递增序列插入：

```text
1, 2, 3, 4, 5, ...
```

可能退化为单支链，导致查找时间退化到 $O(n)$。AVL 和红黑树的核心价值之一，就是通过维护平衡性质让树高保持在对数量级。
