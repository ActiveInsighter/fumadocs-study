## 12. 本章高频易错点

### 12.1 顺序查找与折半查找

* 顺序查找对有序性、存储方式要求最低，平均时间为 $O(n)$；
* 若表本身有序，顺序查找可在遇到“大于目标”的关键字时提前失败，但最坏复杂度仍是 $O(n)$；
* 折半查找必须建立在**有序表**上，并且需要高效随机访问中间位置；
* 普通链表即使有序，也不适合直接实现高效的标准折半查找；
* 元素个数为偶数时，取左中点还是右中点会改变具体判定树形状和部分结点的比较次数；
* 折半查找有 $n+1$ 个失败区间；外部失败结点本身不等于“额外一次关键字比较”，要看题目对层数和查找长度的定义；
* 分块查找的 $s\approx\sqrt n$ 优化结论依赖“索引顺序查找 + 块内顺序查找”等前提。

### 12.2 B 树

$m$ 阶 B 树最先记住：

$$
\text{最多 }m\text{ 棵子树}
$$

因此一个结点最多有：

$$
m-1
$$

个关键字。

除根结点外的普通结点至少有：

$$
\left\lceil\frac m2\right\rceil
$$

棵子树，因此至少有：

$$
\left\lceil\frac m2\right\rceil-1
$$

个关键字。根结点是特殊情况：若不是叶层结点，至少有 2 棵子树；若整棵树只有根，则根可以只保存 1 到 $m-1$ 个关键字。

插入的核心链条：

```text
定位叶结点
→ 插入关键字
→ 溢出则分裂
→ 中间关键字上移
→ 必要时向根继续传播
```

删除的核心链条：

```text
删除关键字
→ 结点下溢？
├─ 否：结束
└─ 是：兄弟够借？
   ├─ 是：借关键字并经父结点调整
   └─ 否：与兄弟合并，必要时向上继续处理
```

### 12.3 B+ 树

B+ 树不要只背阶数公式，应先抓住结构本质：

```text
内部结点：索引
叶结点：保存完整数据/记录指针
叶结点之间：按关键字有序链接
```

因此：

* 查找实际记录最终必须到达叶结点；
* 内部结点出现的关键字可以在叶结点再次出现；
* 顺序遍历叶链非常适合范围查询；
* “$k$ 个关键字对应 $k$ 还是 $k+1$ 棵子树”存在教材口径差异，阶数题必须先读题设定义再计算。

### 12.4 散列表

散列表中最容易混淆的两个角色：

```text
散列函数
→ 决定初始散列地址

冲突处理方法
→ 初始位置冲突后决定下一步去哪里
```

开放定址删除不能把槽位直接恢复为普通空槽，通常需要 `DELETED` 墓碑，否则可能提前截断其他元素的探测路径。查找遇到墓碑要继续，只有遇到真正 `EMPTY` 才能据此判定失败。

双散列若希望探测遍历全部槽位，常要求第二散列得到的步长与表长互素：

$$
\gcd(H_2(key),m)=1
$$

ASL 的平均对象必须分清：

```text
成功 ASL
→ 对已存元素的成功查找长度求平均

失败 ASL
→ 对题目规定的可能初始地址/失败入口求平均
```

若失败查找必须访问一个空槽才能确认不存在，则**最后访问空槽的那一次也计入查找长度**。

### 12.5 一眼排错表

| 看到的说法 | 判断 |
| --- | --- |
| “折半查找只要有序即可高效使用” | 错，还要求能高效定位中点 |
| “折半失败外部结点的层号就是关键字比较次数” | 不一定，要看层号定义；外部结点本身通常不做关键字比较 |
| “$m$ 阶 B 树每个结点最多 $m$ 个关键字” | 错，最多 $m-1$ 个 |
| “B+ 树的关键字数和孩子数关系只有一种教材定义” | 错，题目应先明确采用哪种口径 |
| “B+ 树查找命中内部结点关键字即可取得记录” | 通常错，记录查找需到叶结点 |
| “开放定址删除后直接置空” | 错，可能破坏探测链 |
| “开放定址查找遇到 DELETED 就可以失败” | 错，必须继续探测 |
| “失败 ASL 的分母永远等于散列表长度” | 错，要看初始地址值域/题设状态 |
| “散列表最坏查找一定是 $O(1)$” | 错，严重冲突可退化为 $O(n)$ |
| “拉链法装填因子不能大于 1” | 错，拉链法允许 $\alpha>1$ |

## 13. 查找方法总表

| 方法 | 核心思想 | 主要前提/结构 | 典型平均性能 | 408 高频考点 |
| --- | --- | --- | --- | --- |
| 顺序查找 | 逐个比较 | 无特殊要求 | $O(n)$ | 成功/失败 ASL、哨兵 |
| 折半查找 | 每次排除约一半 | 有序顺序表 | $O(\log n)$ | 判定树、比较次数、失败结点 |
| 分块查找 | 先查索引，再查块内 | 块间有序 | 介于顺序与折半之间 | 分块方式、ASL |
| BST | 利用左小右大 | 二叉搜索树 | 取决于树高 | 查找路径、插入删除 |
| AVL | 严格控制高度差 | 平衡 BST | $O(\log n)$ | LL/RR/LR/RL 调整 |
| 红黑树 | 维持近似平衡 | 红黑树 | $O(\log n)$ | 性质、高度上界 |
| B 树 | 多路平衡查找 | 多路平衡树 | $O(\log n)$ | 阶、关键字界、分裂合并 |
| B+ 树 | 内部索引、叶层存数据并串链 | 多路平衡树 | $O(\log n)$ | 与 B 树比较、范围查询 |
| 散列表 | 关键字直接映射地址 | 散列函数 + 冲突处理 | 平均接近 $O(1)$ | 探测序列、ASL、装填因子 |

### 13.1 结构选择的统一思路

遇到“应该选择什么查找结构”类题，可以按需求逐层判断：

```text
数据规模小 / 无序 / 结构简单
→ 顺序查找

有序 + 顺序存储 + 静态查询多
→ 折半查找

动态有序集合，主要在内存中
→ BST / AVL / 红黑树

数据量大、外存 I/O 成本高
→ B 树 / B+ 树

只关心按 key 精确查询，且可接受无序存储
→ 散列表
```

<Callout type="info" title="复杂度相同，不代表适用场景相同">

AVL、红黑树、B/B+ 树的渐近查找复杂度都可写成 $O(\log n)$，但 AVL 更强调严格平衡，红黑树更适合频繁动态更新，B/B+ 树则通过高分支数降低外存访问层数。

</Callout>

<Callout type="info" title="本章最终复习顺序">

建议最后按 **折半查找判定树 → 分块查找前提 → B 树容量与分裂合并 → B+ 树定义口径与叶链 → 散列表建表/探测 → 成功与失败 ASL** 的顺序复习。

计算题统一遵循：

```text
先写题设口径
→ 再还原结构或路径
→ 逐个写出比较/探测次数
→ 最后求平均或复杂度
```

这样可以把“概念记得对但套错定义”的失分压到最低。

</Callout>
