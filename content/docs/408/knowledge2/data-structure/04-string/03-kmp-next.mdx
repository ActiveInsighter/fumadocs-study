KMP 是字符串章节的核心考点。难点通常不是算法整体，而是：

- 前缀、后缀的定义；
- `next` 到底采用哪一种教材约定；
- 失配后 `i`、`j` 如何变化；
- 经典 `next` 与 LPS / 前缀函数如何区分。

> **真题标签｜2015 第 8 题、2019 第 9 题：KMP 失配跳转与字符比较过程**
>
> 这类题最常考“失配后主串指针是否变化”“模式串应该跳到哪里”以及总字符比较次数。

---

## 4.3.1 KMP 的核心目标

Knuth、Morris、Pratt 提出的 KMP 算法要解决：

> 当模式串在第 `j` 位失配时，如何利用模式串自身结构，直接确定新的 `j`，而不让主串指针 `i` 回退。

假设已经有：

```text
T: ... a b a b a X ...
P:     a b a b a Y
```

前 5 个字符已经成功匹配，而：

```text
X != Y
```

此时已知主串这一段的具体内容，所以没有必要重新从更早的主串位置验证相同字符。

KMP 只需要判断：

```text
模式串前面已经匹配的部分中，有没有一个后缀同时也是模式串前缀？
```

若有，就把这个可复用部分直接对齐。

---

## 4.3.2 真前缀与真后缀

### 前缀

从字符串首字符开始的连续子串。

例如：

```text
abcdabc
```

前缀包括：

```text
a
ab
abc
abcd
abcda
abcdab
abcdabc
```

### 真前缀

**不等于字符串本身**的前缀。

因此 `abcdabc` 的真前缀不包含完整的 `abcdabc`。

### 后缀

以字符串最后一个字符结束的连续子串。

例如 `abcdabc` 的后缀包括：

```text
c
bc
abc
dabc
cdabc
bcdabc
abcdabc
```

### 真后缀

不等于字符串本身的后缀。

> **易错点｜“前后缀”不是任意子串**
>
> 前缀必须从首字符开始，后缀必须在最后一个字符结束。

---

## 4.3.3 最长相等真前后缀为什么能用于跳转

对于：

```text
abcdabc
```

最长相等真前缀、真后缀都是：

```text
abc
```

长度为：

$$
3
$$

如果某次匹配中，已经成功匹配的模式串片段末尾正好包含这个后缀，那么该后缀对应的主串字符已经被验证过；由于它同时又等于模式串前缀，所以可以直接把模式串前缀与这段主串对齐。

这就是 KMP 失配跳转的数学依据。

---

## 4.3.4 本章统一采用的经典 `next` 定义

为避免与不同教材混乱，本章在讲解和手算时统一采用：

```text
0 基下标
next[0] = -1
```

当 `P[j]` 与 `T[i]` 失配时：

```text
j = next[j]
```

而主串位置：

```text
i 不变
```

对于 $j\ge1$，可把 `next[j]` 理解为：

> `P[0 ... j-1]` 的最长相等真前后缀长度。

注意这里研究的是：

```text
j 之前已经匹配成功的部分
```

而不是包含 `P[j]` 的整个前缀。

---

## 4.3.5 `next` 手算示例：`ababac`

模式串：

```text
P = ababac
```

逐位计算：

| `j` | `P[j]` | 研究的已匹配部分 `P[0...j-1]` | 最长相等真前后缀长度 | `next[j]` |
| ---: | :---: | --- | ---: | ---: |
| 0 | a | — | — | -1 |
| 1 | b | `a` | 0 | 0 |
| 2 | a | `ab` | 0 | 0 |
| 3 | b | `aba` | 1 | 1 |
| 4 | a | `abab` | 2 | 2 |
| 5 | c | `ababa` | 3 | 3 |

得到：

```text
next = [-1, 0, 0, 1, 2, 3]
```

以 `next[5]` 为例，只看：

```text
ababa
```

其最长相等真前后缀是：

```text
aba
```

长度为 3，因此：

```text
next[5] = 3
```

---

## 4.3.6 `next` 的稳定手算方法

短模式串选择题中，不必死背递推代码，可以稳定使用：

> 求 `next[j]` → 只研究 `P[0...j-1]` → 找最长相等真前后缀长度。

例如：

```text
P = abaabc
```

则：

```text
next = [-1, 0, 0, 1, 1, 2]
```

计算 `next[5]` 时研究：

```text
abaab
```

最长相等真前后缀为：

```text
ab
```

所以：

```text
next[5] = 2
```

> **真题标签｜2015 第 8 题**
>
> 模式串 `abaabc` 第 5 位失配时，按上述经典定义有 `next[5]=2`，因此模式串指针回到 2，而主串指针保持不变。

## 4.3.7 KMP 匹配时 `i` 与 `j` 的变化

设：

- `i`：主串当前比较位置；
- `j`：模式串当前比较位置。

若：

```text
T[i] == P[j]
```

则：

```text
i++
j++
```

若：

```text
T[i] != P[j]
```

且 `j != -1`，则：

```text
j = next[j]
```

**此时 `i` 不变。**

若：

```text
j == -1
```

表示当前主串字符连模式串首字符也无法匹配，则：

```text
i++
j++
```

使 `j` 回到 0，继续考查下一主串字符。

经典写法：

```c
while (i < n && j < m) {
    if (j == -1 || text[i] == pattern[j]) {
        ++i;
        ++j;
    } else {
        j = next[j];
    }
}
```

---

## 4.3.8 为什么 KMP 中主串指针不回退

若已经有：

```text
T[i-j ... i-1] = P[0 ... j-1]
```

那么这段主串字符已经全部被确认。

失配发生后，新的候选匹配只需要在**已匹配片段内部重新对齐模式串前缀**，无需重新检查更早的主串字符。

所以 KMP 的核心性质是：

> **失配时主串 `i` 不回退，只调整模式串 `j`。**

这也是 408 中最重要的判断依据之一。

---

## 4.3.9 KMP 匹配示例

主串：

```text
ababcabcabababd
```

模式串：

```text
ababd
```

其经典 `next`：

| index | 0 | 1 | 2 | 3 | 4 |
| ---: | :---: | :---: | :---: | :---: | :---: |
| char | a | b | a | b | d |
| `next` | -1 | 0 | 0 | 1 | 2 |

当已经匹配：

```text
abab
```

随后出现：

```text
c != d
```

此时：

```text
j = 4
next[4] = 2
```

因此：

```text
j ← 2
```

主串当前位置不变，继续用当前主串字符与 `P[2]` 比较。

## 4.3.10 LPS / 前缀函数与经典 `next` 不是同一个数组

现代算法教材和工程实现中常使用 **LPS**：

> `LPS[j]` 表示 `P[0...j]` 的最长相等真前后缀长度。

以：

```text
P = ababac
```

为例：

```text
LPS  = [0, 0, 1, 2, 3, 0]
next = [-1, 0, 0, 1, 2, 3]
```

在本章采用的经典定义下：

$$
next[j]=LPS[j-1],\qquad j\ge1
$$

因此两者虽然表达的是同一类前后缀信息，但**下标语义不同**。

> **易错点｜先认定义，再算数组**
>
> 不能看到“最长前后缀”就直接套自己背过的数组。必须先检查题目给出的初值和下标体系。

---

## 4.3.11 1 基教材中的 `next` 也可能不同

某些教材采用：

```text
1 基位序
next[1] = 0
```

并把“失配后下一次比较的模式串位置”直接记入 `next`。

例如同一个模式串在不同定义下，数组数值可能整体出现偏移。

所以遇到题目时，第一步永远是：

```text
看 next 首元素 + 看下标起点 + 看题目给出的递推或示例
```

而不是强行把所有题都转换成同一组记忆值。

---

## 4.3.12 LPS 形式的 KMP 实现

现代代码常直接构造 LPS：

```c
void ComputeLPS(const char *pattern, int m, int lps[]) {
    int len = 0;
    lps[0] = 0;

    for (int i = 1; i < m; ) {
        if (pattern[i] == pattern[len]) {
            lps[i] = ++len;
            ++i;
        } else if (len > 0) {
            len = lps[len - 1];
        } else {
            lps[i] = 0;
            ++i;
        }
    }
}
```

匹配时：

```c
int KMP(const char *text, const char *pattern) {
    int n = (int)strlen(text);
    int m = (int)strlen(pattern);

    if (m == 0)
        return 0;

    int lps[m];
    ComputeLPS(pattern, m, lps);

    int i = 0, j = 0;

    while (i < n) {
        if (text[i] == pattern[j]) {
            ++i;
            ++j;

            if (j == m)
                return i - m;
        } else if (j > 0) {
            j = lps[j - 1];
        } else {
            ++i;
        }
    }

    return -1;
}
```

这里的：

```c
j = lps[j - 1];
```

与经典 `next` 的：

```c
j = next[j];
```

在各自定义体系中表达相同思想：**利用已匹配前缀的信息完成跳转**。

---

## 4.3.13 KMP 的复杂度

构造辅助数组：

$$
O(m)
$$

扫描主串：

$$
O(n)
$$

总时间复杂度：

$$
O(n+m)
$$

辅助数组长度与模式串同阶，因此额外空间复杂度：

$$
O(m)
$$

> **真题标签｜2019 第 9 题**
>
> 若题目问字符比较次数，不要只看模式串移动次数。每一次 `T[i]` 与 `P[j]` 的实际比较都应计入。

---

## 4.3.14 本节核心结论

KMP 可以压缩为四句话：

1. 失配前已经匹配成功的信息不能浪费；
2. 模式串的相等前后缀决定下一次对齐位置；
3. 失配时主串指针 `i` 不回退；
4. 不同教材的 `next` 数值可能不同，先认定义再计算。
