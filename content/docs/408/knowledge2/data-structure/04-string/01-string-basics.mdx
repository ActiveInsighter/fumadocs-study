## 1. 串的基本概念

### 1.1 串的定义

**串（String）**&#x2060;是由零个或多个字符组成的有限序列。

若字符取自字符集 $\Sigma$，则串可以表示为：

$$
S=a_1a_2\cdots a_n,\qquad a_i\in\Sigma
$$

其中：

* $n$ 称为**串长**；
* 当 $n=0$ 时，称为**空串**；
* 串中的每个元素都是字符。

从数据结构角度看，串本质上可以理解为一种**特殊的线性表**：

* 线性表中的元素可以是任意数据类型；
* 串中的元素被限定为字符。

### 1.2 空串与空格串

这是一个常见的概念辨析。

**空串**不包含任何字符，因此长度为：

$$
0
$$

而只包含一个空格字符的串：

```text
" "
```

其长度为：

$$
1
$$

因此：

> **空串和空格串不是同一个概念。**

在 C 语言字符串中还要注意 `'\0'`。

例如：

```c
char s[] = "abc";
```

实际内存中通常存放：

```text
'a' 'b' 'c' '\0'
```

但 `'\0'` 是字符串的结束标志，并不属于字符串的逻辑内容，所以字符串 `"abc"` 的长度仍然是 3。

## 2. 与模式匹配有关的几个概念

学习字符串模式匹配之前，需要区分以下概念。

### 2.1 主串

**主串（Text / Main String）**&#x2060;是待搜索的完整字符串。

例如：

```text
ABABCABD
```

### 2.2 子串

串中任意一段**连续字符序列**称为该串的子串。

例如，在：

```text
ABABCABD
```

中：

```text
CAB
```

是一个子串。

> 子串必须连续，子序列则不一定连续，二者不要混淆。

### 2.3 模式串

**模式串（Pattern）**&#x2060;是准备在主串中查找的目标字符串。

例如：

```text
主串：ABABCABD
模式串：CAB
```

模式匹配的目标，就是寻找主串中是否存在一个子串与模式串完全相同。

### 2.4 匹配与失配

* **匹配**：当前比较的两个字符相同；
* **失配**：当前比较的两个字符不同；
* **匹配成功**：模式串中的所有字符均完成匹配；
* **匹配位置**：模式串第一次或指定一次出现时，其首字符在主串中的位置。

## 3. 串的存储结构

串的典型存储方式包括：

1. 定长顺序存储；
2. 堆分配存储；
3. 块链存储。

三种存储结构的内存布局如下：

<InlineSvg src="/images/data-structure/data-structure-strings-def-001.svg" alt="图示" />

### 3.1 定长顺序存储

定长顺序存储使用一段预先确定最大容量的连续存储空间保存字符。

需要特别注意：

> **数组容量固定，不代表字符串的逻辑长度固定。**

通常需要单独使用 `length` 保存当前串长。

```c
#define MAX_SIZE 100

typedef struct {
    char data[MAX_SIZE];
    int length;
} FixedString;
```

其中：

* `MAX_SIZE` 是最大容量；
* `length` 是当前实际串长。

其特点是：

* 字符地址连续；
* 随机访问方便；
* 实现简单；
* 最大容量受到数组大小限制。

---

### 3.2 堆分配存储

堆分配存储使用动态申请的连续空间保存字符串。

```c
typedef struct {
    char *data;
    int length;
} HeapString;
};

void initHeapString(HeapString *s, const char *str) {
    s->length = strlen(str);

    s->data = (char *)malloc((s->length + 1) * sizeof(char));

    if (s->data == NULL) {
        exit(1);
    }

    strcpy(s->data, str);
}

void freeHeapString(HeapString *s) {
    free(s->data);
    s->data = NULL;
    s->length = 0;
}
```

这里通常根据字符串的实际长度申请空间。

与固定数组相比：

| 特征     | 定长顺序存储 | 堆分配存储 |
| ------ | ------ | ----- |
| 地址是否连续 | 是      | 是     |
| 最大长度   | 预先固定   | 可动态调整 |
| 空间利用率  | 可能较低   | 较高    |
| 实现复杂度  | 较低     | 较高    |

---

### 3.3 块链存储

块链存储结合了**链表**和**顺序块**的思想。

每个结点不只保存一个字符，而是保存一组字符：

```c
#define BLOCK_SIZE 4

typedef struct StringBlock {
    char data[BLOCK_SIZE];
    struct StringBlock *next;
} StringBlock;

typedef struct {
    StringBlock *head;
    int length;
} BlockString;
};

void initBlockString(BlockString *s) {
    s->head = NULL;
    s->length = 0;
}
```

逻辑结构可以理解为：

```text
┌────────────┐    ┌────────────┐    ┌────────────┐
│ a b c d  ●─┼───→│ e f g h  ●─┼───→│ i j      ∅ │
└────────────┘    └────────────┘    └────────────┘
```

相比“一个结点保存一个字符”的普通链表，这种设计可以减少指针域占据的空间比例。

块链存储的完整实现还需要考虑：

* 插入；
* 删除；
* 块内移动；
* 新块申请；
* 空块释放；
* 销毁。

408 中通常以理解结构思想为主。

## 4. 串的基本操作

### 4.1 赋值 `Assign`

将一个串的内容复制给另一个串。

```text
S = "abc"
T ← S
```

操作后：

```text
T = "abc"
```

---

### 4.2 求长度 `Length`

返回串中的字符数。

例如：

```text
S = "Hello"
```

则：

$$
Length(S)=5
$$

---

### 4.3 比较 `Compare`

一般按字符的字典序比较两个串。

比较过程通常是：

1. 从首字符开始逐个比较；
2. 出现不同字符时，根据字符编码确定大小；
3. 如果某个串先结束，则结合前面字符是否完全相同判断大小。

---

### 4.4 连接 `Concat`

将两个串按顺序拼接。

例如：

```text
S1 = "Hello"
S2 = "World"
```

则：

```text
Concat(S1, S2) = "HelloWorld"
```

---

### 4.5 求子串 `Substr`

从指定位置开始，取得指定长度的连续字符。

例如：

```text
HelloWorld
```

取前 5 个字符可得到：

```text
Hello
```

具体起始下标是 0 还是 1，需要根据题目规定判断。

---

### 4.6 插入 `Insert`

在指定位置插入另一个串。

例如：

```text
HelloWorld
```

插入：

```text
Beautiful
```

后可以得到：

```text
HelloBeautifulWorld
```

---

### 4.7 删除 `Delete`

删除从指定位置开始的若干个字符。

---

### 4.8 替换 `Replace`

将串中的指定子串替换为另一个串。

例如：

```text
apple, banana, apple
```

将：

```text
apple
```

替换为：

```text
orange
```

可得到：

```text
orange, banana, orange
```

---

### 4.9 模式匹配 `Index`

在主串中查找模式串第一次出现的位置。

常见方法包括：

* 朴素模式匹配；
* KMP；
* BM；
* Sunday。

408 中的核心是：

> **朴素模式匹配 + KMP。**

---

### 4.10 清空 `Clear`

将字符串变为空串，并在需要时释放其动态存储空间。

## 5. 模式匹配

设：

* 主串为 `T`；
* 模式串为 `P`；
* 主串长度为 `n`；
* 模式串长度为 `m`。

模式匹配要解决的问题为：

> 在 `T` 中寻找某个与 `P` 完全相同的连续子串。

最直接的方法是朴素模式匹配，更高效的方法则是 KMP。

---

## 6. 朴素模式匹配

朴素模式匹配又称：

* 简单模式匹配；
* 暴力匹配；
* Brute Force。

### 6.1 基本思想

从主串中的每一个可能起点开始尝试匹配模式串。

如果：

```text
T[i] == P[j]
```

则继续比较下一对字符。

一旦出现失配：

```text
T[i] != P[j]
```

便放弃本轮匹配，将模式串移动到主串中的下一个可能起始位置重新比较。

---

### 6.2 匹配过程

假设：

```text
主串：abaaabc
模式串：abc
```

第一次尝试：

```text
abaaabc
abc
```

失配后，从主串下一位置重新开始。

不断重复，直到发现：

```text
abaaabc
    abc
```

匹配成功。

其本质可以概括为：

> **主串中的每一个合法起点，都可能重新与模式串从头比较。**

---

### 6.3 算法实现

```c
int simplePatternMatching(const char *mainStr, const char *pattern) {
    int n = strlen(mainStr);
    int m = strlen(pattern);

    if (n < m) {
        return -1;
    }

    for (int i = 0; i <= n - m; ++i) {
        int j;

        for (j = 0; j < m; ++j) {
            if (mainStr[i + j] != pattern[j]) {
                break;
            }
        }

        if (j == m) {
            return i;
        }
    }

    return -1;
}
```

---

### 6.4 时间复杂度

主串存在：

$$
n-m+1
$$

个可能的匹配起点。

每次最多比较：

$$
m
$$

个字符。

因此最坏时间复杂度为：

$$
O((n-m+1)m)
$$

通常记为：

$$
O(nm)
$$

### 6.5 朴素匹配为什么低效

假设已经成功比较了很多字符，最后一个字符才发生失配。

朴素算法会：

1. 丢弃此前已经获得的所有匹配信息；
2. 主串起始位置向后移动一个字符；
3. 模式串重新从头比较。

也就是说：

> **大量字符可能被重复比较。**

KMP 的核心目的，就是利用已经匹配成功的信息，避免这些无意义的重新比较。
