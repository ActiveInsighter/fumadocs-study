串是**元素类型限定为字符的线性结构**。408 对“串的存储实现”考查不深，但基本概念必须准确，因为后续朴素匹配、KMP、`next` 与 `nextval` 都建立在这些定义之上。

本节只解决三个问题：**串是什么、怎样存、有哪些基本操作**。模式匹配算法放在后续小节单独整理。

---

## 4.1.1 串的定义与基本术语

**串（String）**&#x2060;是由零个或多个字符组成的有限序列。若字符来自字符集 $\Sigma$，可写成：

$$
S=a_1a_2\cdots a_n,\qquad a_i\in\Sigma
$$

其中 $n$ 为**串长**。

- 当 $n=0$ 时，称为**空串**；
- 串中的元素只能是字符；
- 从逻辑结构上看，串可以理解为“元素类型受限的线性表”。

### 空串与空格串

空串不含任何字符：

$$
|S|=0
$$

只含一个空格字符的串：

```text
" "
```

其长度为 1，而不是 0。

> **易错点｜空串 ≠ 空格串**
>
> 空格本身也是字符，因此只要串中含有空格，它就不是空串。

---

## 4.1.2 C 字符串中的 `\0` 不属于逻辑串长

在 C 语言中，字符数组通常使用 `\0` 表示字符串结束。例如：

```c
char s[] = "abc";
```

内存中通常为：

```text
'a' 'b' 'c' '\0'
```

但字符串的逻辑内容仍是：

```text
abc
```

所以：

$$
|S|=3
$$

`\0` 是**存储约定中的结束标志**，不是逻辑串内容的一部分。

---

## 4.1.3 主串、子串与模式串

模式匹配题中最常出现三个概念。

### 主串

**主串（Text）**&#x2060;是待搜索的完整字符串，例如：

```text
ABABCABD
```

### 子串

串中任意一段**连续字符序列**称为子串。

例如在：

```text
ABABCABD
```

中，`CAB` 是子串。

> **易错点｜子串要求连续**
>
> “子串”和“子序列”不是同一概念。子序列可以不连续，子串必须连续。

### 模式串

**模式串（Pattern）**&#x2060;是准备在主串中查找的目标串。

```text
主串：ABABCABD
模式串：CAB
```

模式匹配的目标就是判断主串中是否存在一个与模式串完全相同的连续子串，并确定其位置。

---

## 4.1.4 匹配、失配与匹配成功

在字符逐位比较过程中：

- 当前两个字符相同：**匹配**；
- 当前两个字符不同：**失配**；
- 模式串所有字符均完成匹配：**匹配成功**；
- 模式串在主串中出现的起始位置：**匹配位置**。

注意题目可能使用 **0 基下标**或**1 基位序**。若题目问“位置”而不是“数组下标”，必须先判断题目约定。

## 4.1.5 串的定长顺序存储

定长顺序存储使用一段预先确定最大容量的连续空间保存字符。

```c
#define MAX_SIZE 100

typedef struct {
    char data[MAX_SIZE];
    int length;
} FixedString;
```

其中：

- `MAX_SIZE`：最大容量；
- `length`：当前实际串长。

其特点：

| 性质 | 结论 |
| --- | --- |
| 地址是否连续 | 是 |
| 随机访问 | 方便 |
| 最大长度 | 预先固定 |
| 实现复杂度 | 较低 |

> **易错点｜容量和长度不是同一概念**
>
> 数组容量固定，不代表字符串当前长度固定。

---

## 4.1.6 堆分配存储

堆分配存储使用动态申请的连续空间保存字符串。

```c
#include <stdlib.h>
#include <string.h>

typedef struct {
    char *data;
    int length;
} HeapString;

void InitHeapString(HeapString *S, const char *str) {
    S->length = (int)strlen(str);
    S->data = (char *)malloc((S->length + 1) * sizeof(char));

    if (S->data == NULL)
        exit(1);

    strcpy(S->data, str);
}

void DestroyHeapString(HeapString *S) {
    free(S->data);
    S->data = NULL;
    S->length = 0;
}
```

与定长顺序存储相比：

| 项目 | 定长顺序存储 | 堆分配存储 |
| --- | --- | --- |
| 地址是否连续 | 是 | 是 |
| 最大长度 | 预先固定 | 可按需申请 |
| 空间利用率 | 可能较低 | 通常更高 |
| 管理难度 | 较低 | 需要动态内存管理 |

## 4.1.7 块链存储

块链存储将串划分为若干块，每个结点保存多个字符，再用指针连接各块。

```c
#define BLOCK_SIZE 4

typedef struct StringBlock {
    char data[BLOCK_SIZE];
    struct StringBlock *next;
} StringBlock;

typedef struct {
    StringBlock *head;
    int length;
} BlockString;
```

可理解为：

```text
┌────────────┐    ┌────────────┐    ┌────────────┐
│ a b c d  ●─┼───→│ e f g h  ●─┼───→│ i j      ∅ │
└────────────┘    └────────────┘    └────────────┘
```

相比“一个结点只存一个字符”的普通链表，块链存储能降低指针域所占比例。

408 更重视**结构思想**，通常不要求完整实现块内移动、结点分裂与合并等细节。

---

## 4.1.8 三种存储方式怎么比较

| 存储方式 | 连续性 | 长度扩展 | 随机访问 | 典型特点 |
| --- | --- | --- | --- | --- |
| 定长顺序存储 | 连续 | 差 | 快 | 简单但容量固定 |
| 堆分配存储 | 连续 | 较好 | 快 | 动态申请、空间利用率高 |
| 块链存储 | 块内连续、块间链式 | 好 | 较差 | 兼顾扩展性与块存储 |

如果题目只问 408 常见字符串算法，通常无需深入存储实现；若问结构特点，则重点比较**连续性、扩展能力与访问方式**。

## 4.1.9 串的常用基本操作

常见抽象操作如下：

| 操作 | 含义 |
| --- | --- |
| `Assign` | 串赋值 |
| `Length` | 求串长 |
| `Compare` | 按字典序比较 |
| `Concat` | 串连接 |
| `Substr` | 求连续子串 |
| `Insert` | 插入子串 |
| `Delete` | 删除一段字符 |
| `Replace` | 替换指定子串 |
| `Index` | 查找模式串首次出现位置 |
| `Clear` | 清为空串 |

### `Compare` 的基本规则

字典序比较通常从左到右进行：

1. 找到第一对不同字符；
2. 按字符编码或题目给定顺序判断大小；
3. 若较短串的所有字符都与较长串前缀相同，则较短串通常更小。

### `Substr` 的边界

求子串时一定确认：

```text
起始位置 + 长度
```

并结合题目判断下标从 0 还是 1 开始。
