## 1. 串的定义与基本术语

### 1.1 串与串长

**串**是由零个或多个字符组成的有限序列。设字符来自字符集 $\Sigma$，则

$$
S=a_1a_2\cdots a_n,\qquad a_i\in\Sigma
$$

其中 $n$ 为**串长**。

- $n=0$：称为**空串**；
- $n>0$：串中共有 $n$ 个字符；
- 逻辑上，串仍是线性结构，只是线性表中的元素被限定为字符。

### 1.2 空串、空格串与 `\0`

三者必须分清：

| 对象 | 示例 | 逻辑长度 | 说明 |
| --- | --- | ---: | --- |
| 空串 | `""` | 0 | 不含任何字符 |
| 空格串 | `" "` | 1 | 空格本身是字符 |
| C 字符串 `"abc"` | 内存中通常为 `a b c \0` | 3 | `\0` 是结束标记，不计入逻辑长度 |

<Callout type="warn" title="空串 ≠ 空格串">
空串中没有任何字符；空格、制表符、换行符等若作为串内容出现，都属于实际字符。
</Callout>

### 1.3 子串、子序列、主串与模式串

<InlineSvg src="/images/data-structure/data-structure-strings-match-001.svg" alt="模式匹配算法核心概念 主串 (Str): 待搜索的完整字符串 A 0 B 1 A 2 B 3 C 4 A 5 B 6 D 7 模式串 (Pattern): 要在主串中查找的目标字符串 C A B 匹配结果: A 0 B 1 A 2 B 3 C 4 A 5 B 6 D 7 匹配位置: 4 核心概念: ■ 主串 (Str) 完整的待搜索字符串 示例: &quot;ABABCABD&quot; ■ 子串 (Substr) 主串中的任意连续片段 示例: &quot;CAB&quot; (位置4-6) ■ 模式串 (Patt" />

- **子串**：原串中一段**连续**字符组成的序列；
- **子序列**：保持原有相对次序，但字符不要求连续；
- **主串（text）**：被搜索的完整字符串；
- **模式串（pattern）**：希望在主串中找到的目标串。

例如主串为：

```text
ABABCABD
```

则：

- `CAB` 是子串，因为它连续出现；
- `ACD` 是子序列，但不是子串；
- 若要在该主串中查找 `CAB`，则 `ABABCABD` 是主串，`CAB` 是模式串。

模式匹配解决的问题是：

> 在主串中寻找一个与模式串完全相同的连续子串，并确定其出现位置。

### 1.4 串相等与字典序比较

两个串相等，当且仅当：

1. 长度相等；
2. 对应位置上的字符全部相等。

按字典序比较时，从左向右找第一个不同字符并比较其编码次序；若一个串是另一个串的前缀，则通常较短者更小。

例如：

```text
"abc" < "abd"
"abc" < "abcd"
```

<Callout type="info" title="逻辑结构与编码表示要分开">
408 数据结构中的“字符相等”讨论的是逻辑值是否相等；具体字符编码可能是 ASCII、Unicode 等，不属于本章模式匹配算法的核心。
</Callout>

## 2. 串的存储结构

<InlineSvg src="/images/data-structure/data-structure-strings-def-001.svg" alt="图示" />

串的存储结构常见三类：**定长顺序存储、堆分配存储、块链存储**。

### 2.1 定长顺序存储

使用固定容量的连续数组保存字符，同时记录当前逻辑长度。

```c
#define MAX_SIZE 100

typedef struct {
    char data[MAX_SIZE];
    int length;
} FixedString;
```

特点：

- 地址连续，按下标访问方便；
- 实现简单；
- 最大容量预先确定；
- 插入、删除中间字符通常需要移动后续字符；
- **数组容量固定并不意味着串长固定**，实际长度仍由 `length` 决定。

### 2.2 堆分配存储

运行时动态申请一段连续空间保存字符。

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct {
    char *data;
    int length;
} HeapString;

void initHeapString(HeapString *s, const char *str) {
    s->length = (int)strlen(str);
    s->data = (char *)malloc((s->length + 1) * sizeof(char));

    if (s->data == NULL) {
        exit(EXIT_FAILURE);
    }

    strcpy(s->data, str);
}

void destroyHeapString(HeapString *s) {
    free(s->data);
    s->data = NULL;
    s->length = 0;
}
```

与定长顺序存储相比：

| 对比项 | 定长顺序存储 | 堆分配存储 |
| --- | --- | --- |
| 物理地址 | 连续 | 连续 |
| 容量 | 预先固定 | 可按需要申请 |
| 随机访问 | 方便 | 方便 |
| 空间利用 | 可能预留过多 | 更灵活 |
| 实现复杂度 | 较低 | 需要动态申请与释放 |

<Callout type="warn" title="堆分配 ≠ 链式存储">
“堆分配”描述的是内存从堆区动态申请，得到的字符区仍可以是**连续地址**；它和链表式的非连续存储不是一回事。
</Callout>

### 2.3 块链存储

块链存储把串拆成多个链式结点，每个结点保存**一块字符**，而不是只保存一个字符。

```c
#define BLOCK_SIZE 4

typedef struct StringBlock {
    char data[BLOCK_SIZE];
    struct StringBlock *next;
} StringBlock;

typedef struct {
    StringBlock *head;
    int length;
} BlockString;
```

逻辑上可理解为：

```text
┌────────────┐    ┌────────────┐    ┌────────────┐
│ a b c d  ●─┼───→│ e f g h  ●─┼───→│ i j      ∅ │
└────────────┘    └────────────┘    └────────────┘
```

如果每个结点只保存 1 个字符，指针域的额外开销会很大；让一个结点保存多个字符可以降低指针域比例。

块链存储的理解重点：

- 适合频繁进行局部插入、删除或连接；
- 随机访问不如顺序存储直接；
- 块大小会影响空间利用率和操作复杂度；
- 408 通常考结构思想，不要求背完整工程实现。

## 3. 串的基本操作

串的抽象操作与普通线性表相似，但操作对象往往是“一个字符串片段”。

| 操作 | 典型含义 |
| --- | --- |
| `Assign(S, T)` | 将 `T` 的内容赋给 `S` |
| `Length(S)` | 返回串长 |
| `Compare(S, T)` | 按字典序比较两个串 |
| `Concat(S, T)` | 连接两个串 |
| `Substr(S, pos, len)` | 取得从 `pos` 开始、长度为 `len` 的连续子串 |
| `Insert(S, pos, T)` | 在指定位置插入 `T` |
| `Delete(S, pos, len)` | 删除指定连续片段 |
| `Replace(S, T, V)` | 将满足条件的子串 `T` 替换为 `V` |
| `Index(S, T)` | 查找模式串 `T` 在主串 `S` 中的位置 |
| `Clear(S)` | 清空串，必要时释放动态空间 |

### 3.1 操作语义比函数名更重要

教材之间函数名可能略有差异，但本质仍是：

- **取子串**：定位一段连续区间；
- **连接**：把两个串首尾拼接；
- **比较**：按字符序列判断大小；
- **匹配**：查找某个模式串出现的位置。

408 题目若直接给出操作定义，应以题设语义为准。

### 3.2 下标约定必须服从题目

`Substr`、`Index` 等操作中的位置可能从 0 开始，也可能从 1 开始。

<Callout type="warn" title="不要默认所有教材都是 0 基下标">
C/C++ 数组常用 0 基下标，但教材中的串位序、`next` 数组和伪代码可能采用 1 基下标。做题前先认清“位置”的定义。
</Callout>

## 4. 模式匹配问题

设：

- 主串为 $T$，长度为 $n$；
- 模式串为 $P$，长度为 $m$。

若采用 0 基下标，模式匹配要寻找某个起始位置 $s$，满足：

$$
T[s\ldots s+m-1]=P[0\ldots m-1]
$$

合法起点满足：

$$
0\le s\le n-m
$$

因此当 $n\ge m$ 时，一共有：

$$
n-m+1
$$

个候选起点；若 $n<m$，模式串不可能完整出现在主串中。

最常见的两种方法是：

1. **朴素模式匹配（Brute Force，BF）**；
2. **KMP**。

二者的核心区别在于：

> 失配后，是否利用了刚才已经匹配成功的信息。

## 5. 朴素模式匹配

### 5.1 基本思想

从主串的每一个合法起点出发，让模式串从头比较。

若当前起点为 $s$，就依次比较：

```text
T[s]     与 P[0]
T[s + 1] 与 P[1]
T[s + 2] 与 P[2]
...
```

一旦失配，就放弃当前起点，令 $s$ 后移一位，再让模式串从 `P[0]` 重新开始。

例如：

```text
主串：abaaabc
模式：abc
```

依次尝试不同起点，最终在：

```text
abaaabc
    abc
```

处匹配成功。

### 5.2 两指针视角

教材也常用 `i`、`j` 分别表示主串和模式串的当前比较位置。

若一轮从主串位置 `start` 开始，当失配发生在 `T[i]` 与 `P[j]` 时，朴素算法会恢复为：

```text
start = start + 1
j = 0
```

也就是说，刚才已经匹配成功的那部分信息全部被丢弃。

### 5.3 典型实现

```c
int naiveMatch(const char *text, const char *pattern) {
    int n = (int)strlen(text);
    int m = (int)strlen(pattern);

    for (int s = 0; s <= n - m; ++s) {
        int j = 0;

        while (j < m && text[s + j] == pattern[j]) {
            ++j;
        }

        if (j == m) {
            return s;
        }
    }

    return -1;
}
```

当 $n<m$ 时，循环条件不会成立，直接返回 `-1`。

## 6. 朴素匹配的复杂度与低效根源

### 6.1 最坏时间复杂度

主串共有：

$$
n-m+1
$$

个可能的起点，每个起点最多比较 $m$ 个字符，因此最坏比较规模为：

$$
O((n-m+1)m)
$$

通常简写为：

$$
O(nm)
$$

当模式串长度与主串长度同阶时，最坏情况可达到二次量级。

### 6.2 什么输入容易触发大量重复比较

典型情形是：模式串前面大量字符都能匹配，接近末尾才失配。例如：

```text
主串：aaaaaaaaaaaaaaaaab
模式：aaaaaaaab
```

如果每个候选起点都先成功比较很多个 `a` 才发现失配，那么同一批主串字符会被反复比较。

### 6.3 低效的本质

朴素算法在失配后会：

1. 丢弃刚才已经得到的匹配信息；
2. 把主串候选起点后移一位；
3. 模式串重新从首字符开始比较。

因此很多主串字符被重复验证。

<Callout type="info" title="KMP 要解决什么">
KMP 不改变“字符必须经过比较才能确认匹配”的事实，而是利用**模式串自身的前后缀结构**，在失配后直接定位下一个仍可能成功的位置，从而避免主串指针回退和大量重复比较。
</Callout>
