## 1. 串的定义与基本术语

### 1.1 串与串长

**串**是由零个或多个字符组成的有限序列。设字符来自字符集 $\Sigma$，则

$$
S=a_1a_2\cdots a_n,\qquad a_i\in\Sigma
$$

其中 $n$ 为**串长**。

- $n=0$：称为**空串**；
- $n>0$：串中共有 $n$ 个字符；
- 串中元素的逻辑类型是字符，因此串是线性结构的一种特殊情形。

### 1.2 空串、空格串与 C 字符串结束符

三者必须分清：

| 对象 | 示例 | 逻辑长度 |
| --- | --- | ---: |
| 空串 | `""` | 0 |
| 一个空格组成的串 | `" "` | 1 |
| C 字符串 `"abc"` | 内存中通常为 `a b c \0` | 3 |

C 语言中的 `\0` 用来标记字符串结束，但它**不属于字符串的逻辑内容**。

<Callout type="warn" title="空串 ≠ 空格串">
空串中没有任何字符；空格本身也是一个字符，因此只含一个空格的串长度为 1。
</Callout>

### 1.3 子串、子序列、主串与模式串

<InlineSvg src="/images/data-structure/data-structure-strings-match-001.svg" alt="模式匹配算法核心概念 主串 (Str): 待搜索的完整字符串 A 0 B 1 A 2 B 3 C 4 A 5 B 6 D 7 模式串 (Pattern): 要在主串中查找的目标字符串 C A B 匹配结果: A 0 B 1 A 2 B 3 C 4 A 5 B 6 D 7 匹配位置: 4 核心概念: ■ 主串 (Str) 完整的待搜索字符串 示例: &quot;ABABCABD&quot; ■ 子串 (Substr) 主串中的任意连续片段 示例: &quot;CAB&quot; (位置4-6) ■ 模式串 (Patt" />

- **子串**：原串中一段**连续**字符序列；
- **子序列**：保持原有相对次序，但字符不要求连续；
- **主串（text）**：被搜索的完整字符串；
- **模式串（pattern）**：希望在主串中找到的目标串。

例如主串为：

```text
ABABCABD
```

则 `CAB` 是它的子串，而 `ACD` 可以是子序列但不是子串。

模式匹配要解决的问题是：

> 在主串中寻找一个与模式串完全相同的连续子串，并确定其出现位置。

## 2. 串的存储结构

<InlineSvg src="/images/data-structure/data-structure-strings-def-001.svg" alt="图示" />

串的存储结构常见三类：**定长顺序存储、堆分配存储、块链存储**。

### 2.1 定长顺序存储

使用固定容量的连续数组保存字符，同时记录当前逻辑长度。

```c
#define MAX_SIZE 100

typedef struct {
    char data[MAX_SIZE];
    int length;
} FixedString;
```

特点：

- 地址连续，按下标访问方便；
- 实现简单；
- 最大容量预先确定；
- **数组容量固定并不意味着串长固定**，实际长度仍由 `length` 决定。

### 2.2 堆分配存储

运行时动态申请连续空间保存字符。

```c
typedef struct {
    char *data;
    int length;
} HeapString;

void initHeapString(HeapString *s, const char *str) {
    s->length = (int)strlen(str);
    s->data = (char *)malloc((s->length + 1) * sizeof(char));

    if (s->data == NULL) {
        exit(EXIT_FAILURE);
    }

    strcpy(s->data, str);
}

void destroyHeapString(HeapString *s) {
    free(s->data);
    s->data = NULL;
    s->length = 0;
}
```

与定长顺序存储相比：

| 对比项 | 定长顺序存储 | 堆分配存储 |
| --- | --- | --- |
| 物理地址 | 连续 | 连续 |
| 容量 | 预先固定 | 可按需要申请 |
| 空间利用率 | 可能浪费 | 通常更灵活 |
| 实现复杂度 | 较低 | 需要申请与释放内存 |

### 2.3 块链存储

块链存储把串拆成多个链式结点，每个结点保存**一块字符**，而不是只保存一个字符。

```c
#define BLOCK_SIZE 4

typedef struct StringBlock {
    char data[BLOCK_SIZE];
    struct StringBlock *next;
} StringBlock;

typedef struct {
    StringBlock *head;
    int length;
} BlockString;
```

逻辑上可理解为：

```text
┌────────────┐    ┌────────────┐    ┌────────────┐
│ a b c d  ●─┼───→│ e f g h  ●─┼───→│ i j      ∅ │
└────────────┘    └────────────┘    └────────────┘
```

若每个链表结点只存 1 个字符，指针域所占比例会很高；让一个结点保存多个字符可以降低这部分额外开销。

408 通常要求理解其结构思想，不要求背完整工程实现。

## 3. 串的基本操作

串的抽象操作与普通线性表相似，但操作对象往往是“一个字符串片段”。

| 操作 | 典型含义 |
| --- | --- |
| `Assign(S, T)` | 将 `T` 的内容赋给 `S` |
| `Length(S)` | 返回串长 |
| `Compare(S, T)` | 按字典序比较两个串 |
| `Concat(S, T)` | 连接两个串 |
| `Substr(S, pos, len)` | 取得从 `pos` 开始、长度为 `len` 的连续子串 |
| `Insert(S, pos, T)` | 在指定位置插入 `T` |
| `Delete(S, pos, len)` | 删除指定连续片段 |
| `Replace(S, T, V)` | 将满足条件的子串 `T` 替换为 `V` |
| `Index(S, T)` | 查找模式串 `T` 在主串 `S` 中的位置 |
| `Clear(S)` | 清空串，必要时释放动态空间 |

<Callout type="warn" title="下标约定必须服从题目">
`Substr`、`Index` 等操作中的位置可能从 0 开始，也可能从 1 开始。408 做题时先看题目定义，不要把 C/C++ 的 0 基下标默认套到所有教材记号上。
</Callout>

## 4. 模式匹配问题

设：

- 主串为 $T$，长度为 $n$；
- 模式串为 $P$，长度为 $m$。

模式匹配的目标是寻找某个位置 $s$，使得：

$$
T[s\ldots s+m-1]=P[0\ldots m-1]
$$

若只要求第一次出现的位置，则找到最靠前的合法 $s$ 即可。

最常见的两种方法是：

1. **朴素模式匹配（Brute Force）**；
2. **KMP**。

二者的核心区别在于：

> 失配后，是否利用了刚才已经匹配成功的信息。

## 5. 朴素模式匹配

### 5.1 基本思想

从主串的每一个合法起点出发，让模式串从头比较。

若当前起点为 $s$，就依次比较：

```text
T[s]     与 P[0]
T[s + 1] 与 P[1]
T[s + 2] 与 P[2]
...
```

一旦失配，就放弃当前起点，令 $s$ 后移一位，再让模式串从 `P[0]` 重新开始。

例如：

```text
主串：abaaabc
模式：abc
```

最终会在：

```text
abaaabc
    abc
```

处匹配成功。

### 5.2 典型实现

```c
int naiveMatch(const char *text, const char *pattern) {
    int n = (int)strlen(text);
    int m = (int)strlen(pattern);

    for (int s = 0; s <= n - m; ++s) {
        int j = 0;

        while (j < m && text[s + j] == pattern[j]) {
            ++j;
        }

        if (j == m) {
            return s;
        }
    }

    return -1;
}
```

若 $n<m$，循环条件自然不会成立。

### 5.3 最坏时间复杂度

主串共有：

$$
n-m+1
$$

个可能的起点，每次最多比较 $m$ 个字符，因此最坏比较规模为：

$$
O((n-m+1)m)
$$

通常简写为：

$$
O(nm)
$$

### 5.4 朴素算法低效的根源

假设某次已经匹配了很长一段，最后才失配。朴素算法会：

1. 丢弃刚才已经得到的匹配信息；
2. 主串起点后移一位；
3. 模式串重新从首字符比较。

因此很多主串字符会被重复比较。

<Callout type="info" title="KMP 要解决什么">
KMP 不改变“字符必须逐个验证”的事实，而是利用模式串自身的结构，在失配后直接找到**仍然可能成功的下一个模式位置**，从而避免主串指针回退和大量重复比较。
</Callout>
