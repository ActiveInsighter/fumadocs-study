模式匹配要解决的问题是：在主串 `T` 中寻找与模式串 `P` 完全相同的连续子串。

设：

- 主串长度为 $n$；
- 模式串长度为 $m$；
- 通常有 $m\le n$。

最直接的方法是逐个起点尝试，这就是**朴素模式匹配**。理解它为什么重复比较，是理解 KMP 的前提。

---

## 4.2.1 模式匹配问题的统一表示

设主串：

```text
T = t0 t1 t2 ... t(n-1)
```

模式串：

```text
P = p0 p1 p2 ... p(m-1)
```

若从主串位置 $s$ 开始满足：

$$
T[s+k]=P[k],\qquad 0\le k<m
$$

则模式串在主串位置 $s$ 匹配成功。

主串中合法的候选起点共有：

$$
n-m+1
$$

个。

---

## 4.2.2 朴素模式匹配的核心思想

朴素模式匹配又称：

- 简单模式匹配；
- 暴力匹配；
- Brute Force。

其策略是：

> 从主串的每一个可能起点出发，让模式串从第一个字符开始逐个比较。

若当前：

```text
T[i] == P[j]
```

则继续比较下一对字符。

一旦：

```text
T[i] != P[j]
```

就放弃当前起点，令主串尝试起点后移一位，模式串重新从首字符开始。

---

## 4.2.3 用“起点”理解失配后的回退

假设本轮匹配起点为 `start`，当前已经比较到：

```text
i = start + j
```

若发生失配，则下一轮起点变为：

```text
start + 1
```

因此若直接使用 `i`、`j` 两个指针，常见回退写法可理解为：

```text
i = i - j + 1
j = 0
```

这里不是在背公式，而是在恢复：

```text
下一候选起点 = 当前起点 + 1
```

> **易错点｜朴素算法中的主串指针可能回退**
>
> 当前已经比较了很多字符，最后失配时，主串会回到“原起点的下一位”，这就是重复比较的来源。

---

## 4.2.4 朴素匹配示例

设：

```text
主串：abaaabc
模式串：abc
```

第一次尝试：

```text
abaaabc
abc
```

失配后，模式串向右移动一个起点重新比较。

不断尝试后：

```text
abaaabc
    abc
```

匹配成功。

整个过程体现出：

```text
一个起点失败 → 模式串重新从第 0 位开始
```

而不利用前一轮已经匹配成功的信息。

---

## 4.2.5 一种直接实现

```c
#include <string.h>

int SimpleMatch(const char *text, const char *pattern) {
    int n = (int)strlen(text);
    int m = (int)strlen(pattern);

    if (m == 0)
        return 0;
    if (n < m)
        return -1;

    for (int start = 0; start <= n - m; ++start) {
        int j = 0;

        while (j < m && text[start + j] == pattern[j])
            ++j;

        if (j == m)
            return start;
    }

    return -1;
}
```

这段代码直接按“候选起点”组织，更容易看清算法本质。

---

## 4.2.6 最坏时间复杂度

候选起点最多有：

$$
n-m+1
$$

个。

每个起点最多比较 $m$ 个字符，因此最坏比较规模为：

$$
(n-m+1)m
$$

所以最坏时间复杂度：

$$
O((n-m+1)m)=O(nm)
$$

当 $m$ 与 $n$ 同阶时，最坏情况可达到平方级。

额外辅助空间通常为：

$$
O(1)
$$

---

## 4.2.7 什么样的模式容易让朴素算法很慢

最典型情况是：

> 前面大量字符都相同，最后才失配。

例如：

```text
主串：aaaaaaaaaaaaaaaaab
模式：aaaaaaaab
```

很多候选起点都会先成功比较大量 `a`，然后才失败。

朴素算法会丢弃这些已经获得的信息，从新的起点再次比较大量 `a`。

这说明它的核心浪费是：

```text
已经比较过且已经知道的字符关系，被重复计算。
```

---

## 4.2.8 从朴素匹配到 KMP：真正需要优化什么

假设模式串已经成功匹配前 $j$ 个字符：

```text
P[0 ... j-1]
```

当前在：

```text
T[i] != P[j]
```

处失配。

朴素算法会重新选择主串起点。

KMP 的关键观察是：

> 已经匹配成功的主串片段内容是确定的，而模式串自身可能存在“前缀 = 后缀”的重复结构，因此没有必要从模式串第 0 位重新开始。

所以 KMP 的目标不是“完全避免比较”，而是：

```text
利用模式串自身结构，复用已经匹配成功的信息。
```

---

## 4.2.9 朴素匹配与 KMP 的根本差别

| 项目 | 朴素匹配 | KMP |
| --- | --- | --- |
| 失配后模式串 | 通常从头开始 | 按辅助数组跳转 |
| 主串指针 | 可能回退 | 不回退 |
| 是否利用模式串结构 | 否 | 是 |
| 最坏时间复杂度 | $O(nm)$ | $O(n+m)$ |
| 辅助空间 | $O(1)$ | $O(m)$ |

> **理解句**
>
> KMP 的核心价值不是“跳得远”，而是**让主串中已经确认过的信息不再被无意义地重复比较**。

---

## 4.2.10 本节做题检查

遇到朴素模式匹配题，按以下顺序检查：

1. 主串、模式串长度分别是多少；
2. 下标从 0 还是 1 开始；
3. 当前一轮的匹配起点在哪里；
4. 失配后下一轮起点是不是只右移 1 位；
5. 题目问的是“字符比较次数”还是“尝试次数”。

尤其最后一点要区分：

```text
比较次数 ≠ 模式串移动次数
```
