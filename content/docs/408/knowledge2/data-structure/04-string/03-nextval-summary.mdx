## 18. 为什么还需要 `nextval`

经典 `next` 已经能保证 KMP 正确运行，但某些模式串中仍会出现**可以提前判定为必然失败的重复比较**。

假设模式串第 `j` 个字符与主串当前字符失配：

$$
T[i]\ne P[j]
$$

普通 `next` 会令：

```c
j = next[j];
```

若恰好还有：

$$
P[j]=P[next[j]]
$$

那么既然已经知道：

$$
T[i]\ne P[j]
$$

而新的候选字符 `P[next[j]]` 与 `P[j]` 又相同，就必然仍有：

$$
T[i]\ne P[next[j]]
$$

这次比较没有任何必要。

`nextval` 的目标就是：

> **跳过这种已经可以提前判断会再次失配的位置。**

## 19. `nextval` 的计算规则

继续采用本章经典约定：

```text
next[0] = -1
nextval[0] = -1
```

对其他位置 `j`：

- 若 `P[j] != P[next[j]]`，保留原跳转：

```text
nextval[j] = next[j]
```

- 若 `P[j] == P[next[j]]`，跳过去仍会比较同一个字符，应继续沿已经优化的路径跳：

```text
nextval[j] = nextval[next[j]]
```

可写成：

```c
if (next[j] == -1) {
    nextval[j] = -1;
} else if (pattern[j] != pattern[next[j]]) {
    nextval[j] = next[j];
} else {
    nextval[j] = nextval[next[j]];
}
```

<Callout type="info" title="next 与 nextval 的一句话区别">
`next` 回答“失配后**可以退到哪里**”；`nextval` 进一步跳过“退过去以后仍会比较同一字符”的**必然重复失配**。
</Callout>

## 20. `nextval` 手算示例

模式串：

```text
ababaa
```

经典 `next` 为：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 字符 | a | b | a | b | a | a |
| `next` | -1 | 0 | 0 | 1 | 2 | 3 |

逐项计算如下。

### 20.1 `nextval[0]`

按规定：

```text
nextval[0] = -1
```

### 20.2 `nextval[1]`

```text
next[1] = 0
P[1] = b
P[0] = a
```

字符不同，因此：

```text
nextval[1] = 0
```

### 20.3 `nextval[2]`

```text
next[2] = 0
P[2] = a
P[0] = a
```

字符相同，跳到 0 仍会重复失败，所以：

```text
nextval[2] = nextval[0] = -1
```

### 20.4 `nextval[3]`

```text
next[3] = 1
P[3] = b
P[1] = b
```

字符相同，因此：

```text
nextval[3] = nextval[1] = 0
```

### 20.5 `nextval[4]`

```text
next[4] = 2
P[4] = a
P[2] = a
```

字符相同，因此：

```text
nextval[4] = nextval[2] = -1
```

### 20.6 `nextval[5]`

<InlineSvg src="/images/data-structure/data-structure-strings-match-004.svg" alt="图示" />

```text
next[5] = 3
P[5] = a
P[3] = b
```

字符不同，因此：

```text
nextval[5] = 3
```

最终：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 字符 | a | b | a | b | a | a |
| `next` | -1 | 0 | 0 | 1 | 2 | 3 |
| `nextval` | -1 | 0 | -1 | 0 | -1 | 3 |

## 21. 模式串“右移距离”怎么求

这是 `next` / `nextval` 的高频变形题。

假设失配发生在模式串下标 `j`，跳转后的新模式下标为 $k$。由于主串当前位置不变，模式串相对于主串需要向右移动：

$$
j-k
$$

个位置。

在本章经典 0 基定义中：

- 使用普通 `next` 时，$k=next[j]$；
- 使用修正后的 `nextval` 时，$k=nextval[j]$。

所以右移距离为：

$$
j-next[j]
$$

或：

$$
j-nextval[j]
$$

当跳转值为 `-1` 时，右移距离自然为：

$$
j-(-1)=j+1
$$

### 21.1 2024 真题模型

> **真题标签**
>
> 2024 年第 6 题考查“使用修正后的 `next` 数组时，模式串一次失配后可能向右滑动的最长距离”。

模式串：

```text
aabaab
```

在本章定义下：

| 下标 `j` | 0 | 1 | 2 | 3 | 4 | 5 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 字符 | a | a | b | a | a | b |
| `next` | -1 | 0 | 1 | 0 | 1 | 2 |
| `nextval` | -1 | -1 | 1 | -1 | -1 | 1 |
| 右移距离 `j-nextval[j]` | 1 | 2 | 1 | 4 | 5 | 4 |

最大值为：

$$
5
$$

<Callout type="warn" title="不要把“新 j 的值”当成“右移距离”">
`nextval[j]` 给的是**新的模式串比较位置**；题目若问模式串右移多少位，还需要计算“原位置减新位置”。
</Callout>

## 22. 字符比较次数怎么数

另一类常见题型会问：

> KMP 匹配过程中，主串字符与模式串字符一共比较多少次？

此时不要只数 `i` 增加了几次，因为失配后：

```c
j = next[j];
```

通常会让**同一个主串字符**再次和新的模式字符比较。

### 22.1 计数原则

每执行一次：

```text
T[i] 与 P[j] 的字符相等/不等判断
```

就记一次字符比较。

而：

```text
j = next[j]
```

本身只是下标跳转，不算字符比较。

### 22.2 2019 真题模型

> **真题标签**
>
> 2019 年第 9 题考查 KMP 匹配过程中的字符比较次数。

处理这类题，建议画出每次 `(i, j)`：

1. 比较 `T[i]` 与 `P[j]`；
2. 若成功，`i++`、`j++`；
3. 若失败，只修改 `j`；
4. 继续记录下一次真正发生的字符比较；
5. 直到匹配成功或主串结束。

<Callout type="info" title="关键判断">
KMP 保证主串下标不回退，但**同一个主串字符可能被比较多次**。因此“主串扫描到第几个字符”和“总比较次数”不是同一个量。
</Callout>

## 23. 手算 `next` 的稳定方法

对于本章 0 基经典 `next`：

```text
next[0] = -1
```

求 `next[j]` 时，只研究：

```text
P[0 ... j-1]
```

步骤固定为：

1. 写出失配位置之前的字符串；
2. 找它所有真前缀与真后缀中的最长相等者；
3. 取其长度作为 `next[j]`。

例如：

```text
P = ababac
```

求 `next[5]`，只研究：

```text
ababa
```

真前缀包括：

```text
a
ab
aba
abab
```

真后缀包括：

```text
a
ba
aba
baba
```

最长相同部分为：

```text
aba
```

长度为 3，所以：

$$
next[5]=3
$$

### 23.1 长串优先用“候选长度递减”

若字符串较长，不必把所有前缀、后缀全部列出来。可以：

1. 先尝试尽可能长的候选边界；
2. 若不相等，缩短候选长度；
3. 直到找到最长相等边界或退到 0。

这与构造 `next` / LPS 的递推思想一致。

<Callout type="info" title="短模式串优先手算定义">
选择题中的模式串通常不长。与其强行在脑中运行构造代码，不如直接按“失配位置之前的最长相等真前后缀长度”求值，更稳。
</Callout>

## 24. KMP 高频易错点

### 24.1 把 LPS 与经典 `next` 当成同一数组

以：

```text
ababac
```

为例：

```text
LPS  =  0 0 1 2 3 0
next = -1 0 0 1 2 3
```

在本章定义下二者相差一个位置，不能直接互换。

### 24.2 忽略 0 基与 1 基下标差异

可能看到：

```text
next[0] = -1
```

也可能看到：

```text
next[1] = 0
```

甚至不同教材会让 `next[j]` 表示“可保留长度”或“新的比较位置”。

> **先看定义和初值，再做题。**

### 24.3 把任意公共子串当成前后缀

前缀必须从首字符开始，后缀必须到末字符结束；KMP 使用的是**真前缀、真后缀**。

### 24.4 失配时错误回退主串 `i`

KMP 的核心是利用已知匹配关系，让主串下标不回退。失配后通常修改：

```text
j
```

而不是重新改变主串起点。

### 24.5 `j` 跳转后忘记当前主串字符还没被消费

若执行：

```c
j = next[j];
```

当前 `text[i]` 通常仍要和新的 `pattern[j]` 比较，因此 `i` 不应同时自增。

### 24.6 把 `next[j]` 当成右移距离

`next[j]` 是新比较位置，不是右移量。若题目问右移距离，在本章定义下应计算：

$$
j-next[j]
$$

使用 `nextval` 时同理。

### 24.7 在 LPS 写法中机械套 `nextval`

经典 `nextval` 是建立在特定 `next` 定义上的优化。若题目直接使用 LPS / 前缀函数，应按该体系自己的回退规则处理，不能把经典 `nextval` 生搬硬套。

### 24.8 把“主串不回退”误解为“每个主串字符只比较一次”

主串下标不回退，只说明 `i` 不向左移动；同一个 `T[i]` 在 `j` 多次回退后仍可能与多个模式字符进行比较。

## 25. KMP 题的考场处理流程

遇到 `next`、`nextval`、右移距离或匹配过程题，建议固定按以下顺序：

1. **确认下标体系**：0 基还是 1 基；
2. **确认数组定义**：首值是什么，数组值代表长度还是位置；
3. **确认失配规则**：是 `j = next[j]`，还是题目给出的其他形式；
4. **逐位置计算 `next`**：优先按最长相等真前后缀推导；
5. **若要求 `nextval`**：再判断跳转后是否会比较同一字符；
6. **若问右移距离**：用“原 `j` 减新 `j`”；
7. **若问比较次数**：逐次记录真正发生的字符比较；
8. **模拟匹配**：每次失配都明确 `i` 是否移动、`j` 跳到哪里。

<Callout type="warn" title="最容易丢分的步骤">
如果题目已经给出一部分 `next` 初值，它往往就在提示采用哪一种定义。不要无视题设，直接写自己最熟悉的版本。
</Callout>

## 27. 章末速查

| 知识点 | 必记结论 |
| --- | --- |
| 空串 | 长度为 0 |
| 空格串 | 空格也是字符，长度不为 0 |
| 子串 | 必须连续 |
| 朴素匹配 | 失配后换下一个主串起点，最坏 $O(nm)$ |
| KMP | 利用模式串前后缀信息，主串指针不回退 |
| KMP 总时间 | $O(n+m)$ |
| KMP 辅助空间 | 保存数组时为 $O(m)$ |
| LPS | 当前前缀的最长相等真前后缀长度 |
| 本章经典 `next` | `next[0] = -1`；失配时 `j = next[j]` |
| 本章 `next[j]` | `P[0 ... j-1]` 的最长相等真前后缀长度 |
| `nextval` | 跳过“跳过去仍会比较同一字符”的必然重复失配 |
| 模式右移距离 | 本章定义下为 `原 j - 新 j` |
| 比较次数 | 数真正发生的 `T[i]` 与 `P[j]` 比较，不等于 `i` 的推进次数 |

### 27.1 考前最后四问

做 KMP 题前先确认：

1. 下标从 0 还是从 1 开始？
2. `next` 的第一个值是什么，数组值具体表示什么？
3. 题目求的是 LPS、`next`、`nextval`，还是右移距离？
4. 失配后当前主串字符是否还要继续比较？

这四点确认后，大多数 KMP 选择题都可以按固定步骤稳定推导。
