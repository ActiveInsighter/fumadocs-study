## 16. 为什么还需要 `nextval`

经典 `next` 已经能保证 KMP 正确运行，但某些模式串中仍可能出现**可以提前判定为必然失败的重复比较**。

假设模式串第 `j` 个字符与主串当前字符失配：

$$
T[i]\ne P[j]
$$

普通 `next` 会令：

```c
j = next[j];
```

若恰好又有：

$$
P[j]=P[next[j]]
$$

那么刚刚已经知道 `T[i] != P[j]`，而 `P[next[j]]` 与 `P[j]` 又是同一个字符，因此一定还有：

$$
T[i]\ne P[next[j]]
$$

这次比较没有必要。

`nextval` 的目标就是：

> **跳过这种已经可以提前判断会再次失配的位置。**

## 17. `nextval` 的计算规则

继续采用本章的经典约定：

```text
next[0] = -1
```

并规定：

```text
nextval[0] = -1
```

对其他位置 `j`：

- 若 `P[j] != P[next[j]]`，保留原跳转：

```text
nextval[j] = next[j]
```

- 若 `P[j] == P[next[j]]`，说明跳过去仍会比较同一个字符，应继续沿已优化的路径跳：

```text
nextval[j] = nextval[next[j]]
```

等价地，可以写成：

```c
if (next[j] == -1) {
    nextval[j] = -1;
} else if (pattern[j] != pattern[next[j]]) {
    nextval[j] = next[j];
} else {
    nextval[j] = nextval[next[j]];
}
```

<Callout type="info" title="next 与 nextval 的一句话区别">
`next` 回答“**失配后去哪里**”；`nextval` 进一步回答“**能否跳过一个已经确定还会失败的位置**”。
</Callout>

## 18. `nextval` 手算示例

模式串：

```text
ababaa
```

经典 `next` 为：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 字符 | a | b | a | b | a | a |
| `next` | -1 | 0 | 0 | 1 | 2 | 3 |

逐项计算：

### 18.1 `nextval[0]`

按规定：

```text
nextval[0] = -1
```

### 18.2 `nextval[1]`

```text
next[1] = 0
P[1] = b
P[0] = a
```

字符不同，因此：

```text
nextval[1] = 0
```

### 18.3 `nextval[2]`

```text
next[2] = 0
P[2] = a
P[0] = a
```

字符相同，跳到 0 仍会重复失败，所以：

```text
nextval[2] = nextval[0] = -1
```

### 18.4 `nextval[3]`

```text
next[3] = 1
P[3] = b
P[1] = b
```

字符相同，因此：

```text
nextval[3] = nextval[1] = 0
```

### 18.5 `nextval[4]`

```text
next[4] = 2
P[4] = a
P[2] = a
```

字符相同，因此：

```text
nextval[4] = nextval[2] = -1
```

### 18.6 `nextval[5]`

<InlineSvg src="/images/data-structure/data-structure-strings-match-004.svg" alt="图示" />

```text
next[5] = 3
P[5] = a
P[3] = b
```

字符不同，因此：

```text
nextval[5] = 3
```

最终：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 字符 | a | b | a | b | a | a |
| `next` | -1 | 0 | 0 | 1 | 2 | 3 |
| `nextval` | -1 | 0 | -1 | 0 | -1 | 3 |

## 19. 手算 `next` 的稳定方法

对于本章的 0 基经典 `next`：

```text
next[0] = -1
```

求 `next[j]` 时，只研究：

```text
P[0 ... j-1]
```

步骤固定为：

1. 写出这一段字符串；
2. 找它的最长相等真前后缀；
3. 取其长度作为 `next[j]`。

例如：

```text
P = ababac
```

求 `next[5]`，只研究：

```text
ababa
```

真前缀中有：

```text
a
ab
aba
abab
```

真后缀中有：

```text
a
ba
aba
baba
```

最长相同部分为：

```text
aba
```

长度为 3，所以：

$$
next[5]=3
$$

<Callout type="info" title="短模式串优先手算定义">
选择题中的模式串通常不长。与其强行在脑中运行构造代码，不如直接按“失配位置之前的最长相等真前后缀长度”求值，更稳。
</Callout>

## 20. KMP 高频易错点

### 20.1 把 LPS 与经典 `next` 当成同一数组

以：

```text
ababac
```

为例：

```text
LPS  =  0 0 1 2 3 0
next = -1 0 0 1 2 3
```

在本章定义下二者相差一个位置，不能直接互换。

### 20.2 忽略 0 基与 1 基下标差异

可能看到：

```text
next[0] = -1
```

也可能看到：

```text
next[1] = 0
```

甚至不同教材会让 `next[j]` 表示“长度”或“新的比较位置”。

> **先看定义和初值，再做题。**

### 20.3 把任意公共子串当成前后缀

前缀必须从首字符开始，后缀必须到末字符结束；并且 KMP 使用的是真前缀、真后缀。

### 20.4 KMP 失配时错误回退主串 `i`

KMP 的核心就是利用已知匹配关系让主串下标不回退。失配后通常修改：

```text
j
```

而不是重新改变主串起点。

### 20.5 `j` 跳转后忘记当前主串字符还没被消费

若执行：

```c
j = next[j];
```

则当前 `text[i]` 通常仍要和新的 `pattern[j]` 比较，因此 `i` 不应同时自增。

### 20.6 在 LPS 写法中机械套 `nextval`

经典 `nextval` 是建立在特定 `next` 定义上的优化。若题目直接使用 LPS / 前缀函数，就应按该体系自己的回退规则处理，不能把经典 `nextval` 数组生搬硬套。

## 21. KMP 题的考场处理流程

遇到 `next`、`nextval` 或匹配过程题，建议固定按以下顺序：

1. **确认下标体系**：0 基还是 1 基；
2. **确认数组定义**：首值是什么，数组值代表什么；
3. **确认失配规则**：是 `j = next[j]`，还是题目给出的其他形式；
4. **逐位置计算 `next`**：优先按最长相等真前后缀推导；
5. **若要求 `nextval`，再基于 `next` 优化**；
6. **模拟匹配**：每次失配时明确 `i` 是否移动、`j` 跳到哪里。

<Callout type="warn" title="最容易丢分的步骤">
如果题目已经给出一部分 `next` 初值，它往往就是在提示采用哪一种定义。不要无视题设，直接写自己最熟悉的版本。
</Callout>

## 23. 章末速查

| 知识点 | 必记结论 |
| --- | --- |
| 空串 | 长度为 0 |
| 空格串 | 空格也是字符，长度不为 0 |
| 朴素匹配 | 失配后换下一个主串起点，最坏 $O(nm)$ |
| KMP | 利用模式串前后缀信息，主串指针不回退 |
| KMP 总时间 | $O(n+m)$ |
| KMP 辅助空间 | 保存数组时为 $O(m)$ |
| LPS | 当前前缀的最长相等真前后缀长度 |
| 本章经典 `next` | `next[0] = -1`，失配时 `j = next[j]` |
| `nextval` | 跳过“跳过去仍会比较同一字符”的必然重复失配 |

### 23.1 考前最后三问

做 KMP 题前先确认：

1. 下标从 0 还是从 1 开始？
2. `next` 的第一个值是什么，数组值具体表示什么？
3. 题目求的是 LPS、`next`，还是 `nextval`？

这三点确认后，KMP 大多数题目都可以机械、稳定地推导。
