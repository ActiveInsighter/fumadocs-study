## 21. `nextval` 数组

经典 `next` 已经能够避免主串回退，但仍有进一步优化空间。

问题主要出现在：

```text
pattern[j] == pattern[next[j]]
```

这种情况。

---

## 22. 为什么还需要 `nextval`

假设模式串第 `j` 个字符已经与主串字符失配：

```text
text[i] != pattern[j]
```

按照普通 `next`：

```text
j = next[j]
```

但如果：

```text
pattern[j] == pattern[next[j]]
```

那么新的：

```text
pattern[next[j]]
```

与刚刚失败的 `pattern[j]` 是同一个字符。

既然：

```text
text[i] != pattern[j]
```

而：

```text
pattern[j] == pattern[next[j]]
```

那么必然也有：

```text
text[i] != pattern[next[j]]
```

因此再比较一次完全没有意义。

`nextval` 的作用就是：

> **直接跳过这些已经可以确定必然失败的位置。**

---

## 23. `nextval` 的计算规则

本节继续采用：

```text
next[0] = -1
```

这一经典约定。

若：

```text
pattern[j] != pattern[next[j]]
```

则：

```text
nextval[j] = next[j]
```

如果：

```text
pattern[j] == pattern[next[j]]
```

则：

```text
nextval[j] = nextval[next[j]]
```

即继续向前寻找。

---

## 24. `nextval` 代码

```c
if (next[i] == -1) {
    nextval[i] = -1;
} else {
    int k = next[i];

    while (k != -1 && pattern[i] == pattern[k]) {
        k = nextval[k];
    }

    nextval[i] = k;
}
```

其中 `while` 的含义是：

> 如果跳转后仍然会比较相同字符，就继续沿着 `nextval` 向前跳，直到找到不同字符或者到达 `-1`。

---

## 25. `nextval` 示例

模式串：

```text
ababaa
```

先得到经典 `next`：

| pattern | a  | b | a | b | a | a |
| ------- | -- | - | - | - | - | - |
| index   | 0  | 1 | 2 | 3 | 4 | 5 |
| `next`  | -1 | 0 | 0 | 1 | 2 | 3 |

接下来计算 `nextval`。

---

#### `nextval[0]`

按照规定：

```text
nextval[0] = -1
```

---

#### `nextval[1]`

有：

```text
next[1] = 0
```

比较：

```text
pattern[1] = b
pattern[0] = a
```

二者不同，因此保留：

```text
nextval[1] = 0
```

---

#### `nextval[2]`

有：

```text
next[2] = 0
```

比较：

```text
pattern[2] = a
pattern[0] = a
```

相同，因此直接继续跳：

```text
nextval[2] = nextval[0] = -1
```

---

#### `nextval[3]`

有：

```text
next[3] = 1
```

而：

```text
pattern[3] = b
pattern[1] = b
```

相同，因此：

```text
nextval[3] = nextval[1] = 0
```

---

#### `nextval[4]`

有：

```text
next[4] = 2
```

而：

```text
pattern[4] = a
pattern[2] = a
```

相同，因此：

```text
nextval[4] = nextval[2] = -1
```

---

#### `nextval[5]`

有：

```text
next[5] = 3
```

比较：

```text
pattern[5] = a
pattern[3] = b
```

不同，因此：

```text
nextval[5] = 3
```

最终得到：

| pattern   | a  | b | a  | b | a  | a |
| --------- | -- | - | -- | - | -- | - |
| index     | 0  | 1 | 2  | 3 | 4  | 5 |
| `next`    | -1 | 0 | 0  | 1 | 2  | 3 |
| `nextval` | -1 | 0 | -1 | 0 | -1 | 3 |

## 26. `next` 与 `nextval` 的本质区别

可以用一句话概括：

> **`next` 解决“失配后去哪里”，`nextval` 进一步解决“别跳到一个必然再次失配的位置”。**

因此：

```text
next
```

已经能够保证 KMP 正确工作。

而：

```text
nextval
```

只是在某些具有大量重复字符的模式串中进一步减少无效比较。

---

## 27. 手算 `next` 的稳定方法

考试中最推荐的思考方式不是死背数组，而是：

> **计算当前位置之前的字符串，其最长相等真前后缀长度。**

仍采用：

```text
next[0] = -1
```

例如求模式串：

```text
ababac
```

的：

```text
next[5]
```

第 5 位是：

```text
c
```

只观察它之前的：

```text
ababa
```

列出真前缀：

```text
a
ab
aba
abab
```

列出真后缀：

```text
a
ba
aba
baba
```

最长相同部分：

```text
aba
```

长度为：

$$
3
$$

因此：

```text
next[5] = 3
```

这种方法特别适合选择题和短模式串。

## 28. KMP 高频易错点

### 28.1 把 LPS 当成 `next`

例如：

```text
ababac
```

LPS：

```text
0 0 1 2 3 0
```

经典 `next`：

```text
-1 0 0 1 2 3
```

二者明显不同。

看到题目时不要直接套记忆中的数组。

---

### 28.2 忽略下标从 0 还是从 1 开始

不同教材可能采用：

```text
next[0] = -1
```

也可能采用：

```text
next[1] = 0
```

甚至还存在其他等价定义。

因此做题第一步应该观察题目：

> **数组首元素到底给了什么。**

---

### 28.3 把“前后缀”理解成任意子串

前缀必须：

```text
从首字符开始
```

后缀必须：

```text
以最后一个字符结束
```

都不能从中间任意截取。

---

### 28.4 忘记“真”前后缀不能包含整个串本身

任意字符串本身当然同时是自己的前缀和后缀。

如果允许使用完整字符串，则最长公共前后缀永远都是字符串本身，没有意义。

因此 KMP 讨论的是：

> **真前缀和真后缀。**

---

### 28.5 KMP 失配时错误地让主串 `i` 回退

KMP 的核心性质就是：

> **利用已知匹配信息，使主串指针不回退。**

失配通常调整的是：

```text
j
```

而不是重新计算：

```text
i
```

---

### 28.6 `nextval` 与 `next` 的适用定义混用

`nextval` 是建立在特定经典 `next` 定义基础上的优化。

若题目采用的是 LPS / 前缀函数，则通常不会再用同样形式的 `nextval`。

---

## 29. 一道 KMP 题应该怎么做

如果考试要求计算 `next`、`nextval` 或匹配过程，可以按以下顺序处理。

#### 第一步：确认下标体系

看题目是：

```text
0 基
```

还是：

```text
1 基
```

#### 第二步：确认初值

例如：

```text
next[0] = -1
```

或：

```text
next[1] = 0
```

由此判断采用哪种定义。

#### 第三步：逐位置寻找最长相等真前后缀

不要凭感觉跳。

对于每一个位置，明确对应的前缀子串。

#### 第四步：得到完整 `next`

先保证 `next` 正确，再计算 `nextval`。

#### 第五步：计算 `nextval`

检查：

```text
pattern[j]
```

与：

```text
pattern[next[j]]
```

是否相同。

相同时继续向前跳。

#### 第六步：模拟匹配

失配时：

```text
j = next[j]
```

或使用题目指定的跳转规则。

注意主串下标是否变化。

## 31. 408 章末速记

#### 串

串是：

> **字符组成的有限序列。**

空串长度：

$$
0
$$

空格串长度：

$$
\neq 0
$$

---

#### 朴素模式匹配

核心：

> **每个可能起点重新从模式串首字符开始比较。**

最坏时间复杂度：

$$
O(nm)
$$

---

#### KMP

核心：

> **利用模式串自身的前后缀信息进行失配跳转，使主串指针不回退。**

时间复杂度：

$$
O(n+m)
$$

额外空间复杂度：

$$
O(m)
$$

---

#### LPS

含义：

> **当前前缀的最长相等真前后缀长度。**

例如：

```text
ababac
```

得到：

```text
LPS = 0 0 1 2 3 0
```

---

#### 经典 `next`

本章约定：

```text
next[0] = -1
```

对于：

```text
ababac
```

有：

```text
next = -1 0 0 1 2 3
```

失配时核心操作：

```text
j = next[j]
```

---

#### `nextval`

作用：

> **避免跳转后再次比较一个已经可以确定必然失配的相同字符。**

若：

```text
pattern[j] == pattern[next[j]]
```

则进一步使用：

```text
nextval[next[j]]
```

进行跳转。

---

> **最后检查**
>
> 做 KMP 题之前，一定先问自己三个问题：
>
> 1. 下标从 0 还是 1 开始？
> 2. `next` 的第一个值是什么？
> 3. 题目求的是 `next`、LPS，还是 `nextval`？
>
> 这三个问题确认清楚后，大多数 KMP 题就只是机械计算。
