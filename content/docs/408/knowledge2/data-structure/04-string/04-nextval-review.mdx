经典 `next` 已经能保证 KMP 在线性时间内完成匹配，但某些模式串中仍可能出现**跳转后立即重复比较同一个字符**的情况。

`nextval`（修正后的 `next`）就是针对这种冗余进行进一步优化。

> **真题标签｜2024 第 6 题：修正后的 `next` / `nextval` 与模式串滑动距离**
>
> 该类题常把“跳到哪里”转换成“模式串向右滑动多少位”，需要同时理解数组值和对齐位置。

---

## 4.4.1 为什么还需要 `nextval`

假设当前发生失配：

```text
T[i] != P[j]
```

普通 `next` 会执行：

```text
j = next[j]
```

若恰好：

```text
P[j] == P[next[j]]
```

那么已经知道：

```text
T[i] != P[j]
```

又因为：

```text
P[j] == P[next[j]]
```

必然推出：

```text
T[i] != P[next[j]]
```

所以跳到 `next[j]` 后再比较一次，一定还会失败。

`nextval` 的思想就是：

> **直接跳过这个已经可以确定必然再次失配的位置。**

---

## 4.4.2 `nextval` 的计算规则

继续沿用本章经典约定：

```text
next[0] = -1
nextval[0] = -1
```

对于位置 `j`：

若：

```text
P[j] != P[next[j]]
```

则：

```text
nextval[j] = next[j]
```

若：

```text
P[j] == P[next[j]]
```

则继续沿优化链跳转：

```text
nextval[j] = nextval[next[j]]
```

可概括为：

```text
next：先找可复用前缀
nextval：再检查这个跳转位置是否会立刻重复失败
```

---

## 4.4.3 `nextval` 示例：`ababaa`

模式串：

```text
P = ababaa
```

经典 `next`：

```text
[-1, 0, 0, 1, 2, 3]
```

逐位优化。

### `j = 0`

规定：

```text
nextval[0] = -1
```

### `j = 1`

```text
next[1] = 0
P[1] = b
P[0] = a
```

不同，因此：

```text
nextval[1] = 0
```

### `j = 2`

```text
next[2] = 0
P[2] = a
P[0] = a
```

相同，跳过：

```text
nextval[2] = nextval[0] = -1
```

### `j = 3`

```text
next[3] = 1
P[3] = b
P[1] = b
```

相同，因此：

```text
nextval[3] = nextval[1] = 0
```

### `j = 4`

```text
next[4] = 2
P[4] = a
P[2] = a
```

相同，因此：

```text
nextval[4] = nextval[2] = -1
```

### `j = 5`

```text
next[5] = 3
P[5] = a
P[3] = b
```

不同，因此：

```text
nextval[5] = 3
```

最终：

| index | 0 | 1 | 2 | 3 | 4 | 5 |
| ---: | :---: | :---: | :---: | :---: | :---: | :---: |
| char | a | b | a | b | a | a |
| `next` | -1 | 0 | 0 | 1 | 2 | 3 |
| `nextval` | -1 | 0 | -1 | 0 | -1 | 3 |

---

## 4.4.4 `nextval` 的本质区别

一句话区分：

> **`next` 解决“失配后跳到哪里”；`nextval` 进一步解决“不要跳到一个必然再次失配的位置”。**

因此：

- `next` 是 KMP 正确工作的核心；
- `nextval` 是减少冗余比较的优化；
- `nextval` 并不会改变匹配结果，只影响比较过程。

---

## 4.4.5 `nextval` 的一种代码表达

```c
void BuildNextVal(const char *pattern, const int next[], int nextval[], int m) {
    nextval[0] = -1;

    for (int j = 1; j < m; ++j) {
        int k = next[j];

        while (k != -1 && pattern[j] == pattern[k])
            k = nextval[k];

        nextval[j] = k;
    }
}
```

`while` 的含义是：

```text
如果跳转到的新位置字符与刚刚失败的字符仍相同，继续向前跳。
```

---

## 4.4.6 2024 真题模型：`aabaab`

模式串：

```text
aabaab
```

在本章经典 0 基定义下：

| index | 0 | 1 | 2 | 3 | 4 | 5 |
| ---: | :---: | :---: | :---: | :---: | :---: | :---: |
| char | a | a | b | a | a | b |
| `next` | -1 | 0 | 1 | 0 | 1 | 2 |
| `nextval` | -1 | -1 | 1 | -1 | -1 | 1 |

> **真题标签｜2024 第 6 题**
>
> 题目问“使用修正后的 `next`，失配时模式串向右滑动的最长距离”。做法不是死记答案，而是找所有可能失配位置，依据 `nextval[j]` 计算模式串重新对齐后向右移动了多少位，再取最大值。

若采用 0 基位置，当 `j` 跳到 `k` 时，模式串相对右移量可理解为：

$$
j-k
$$

若 `k=-1`，则表示当前主串字符也无法继续与模式串首字符形成有效复用，对齐移动量相应更大。

## 4.4.7 KMP 题的第一步永远是认清定义

KMP 最容易错的并不是“前后缀不会算”，而是混用不同定义。

考试中常见三类表示：

1. 0 基经典 `next`，如 `next[0]=-1`；
2. 1 基教材 `next`，如 `next[1]=0`；
3. LPS / 前缀函数，首项通常为 0。

因此正式计算前必须检查：

```text
① 下标从 0 还是 1 开始？
② next 的首元素是什么？
③ 题目是否直接给出了递推定义？
④ 求的是 next、nextval 还是 LPS？
```

只要这四点没有确认，就不要直接套数组。

---

## 4.4.8 高频易错点 1：把 LPS 当成经典 `next`

例如：

```text
P = ababac
```

有：

```text
LPS  = [0, 0, 1, 2, 3, 0]
next = [-1, 0, 0, 1, 2, 3]
```

数值明显不同。

原因在于：

- `LPS[j]` 研究 `P[0...j]`；
- 本章经典 `next[j]` 研究 `P[0...j-1]`。

---

## 4.4.9 高频易错点 2：忘记“真”前后缀不能等于整个串

任意字符串本身当然既是前缀又是后缀。

如果允许使用整个串，那么“最长相等前后缀”永远是字符串本身，KMP 就失去了跳转意义。

所以讨论的一定是：

```text
真前缀 + 真后缀
```

---

## 4.4.10 高频易错点 3：失配时错误移动主串 `i`

在经典 KMP 中，若：

```text
T[i] != P[j]
```

通常操作是：

```text
j = next[j]
```

而：

```text
i 不变
```

除非已经跳到 `j == -1`，才会使 `i` 前进并重新从模式串首位开始。

> **真题标签｜2015 第 8 题**
>
> 该题最关键的信息就是：第一次失配后主串下标保持在原位置，只调整模式串下标。

---

## 4.4.11 高频易错点 4：把“模式串移动距离”当成 `next` 值

若当前失配位置为 `j`，跳到：

```text
k = next[j]
```

则模式串向右移动的量不是 `k`，而是当前对齐位置与新对齐位置之差。

在统一 0 基语义下，常可理解为：

$$
j-k
$$

因此题目问“跳到哪个下标”和问“右移多少位”，答案形式完全不同。

---

## 4.4.12 高频易错点 5：比较次数必须逐次计数

KMP 的时间复杂度是线性的，但具体题目仍可能要求：

```text
总共进行了多少次字符比较？
```

此时每一次实际执行：

```text
T[i] ?= P[j]
```

都要计数。

模式串发生一次跳转，并不等于只增加一次或不增加比较次数。

> **真题标签｜2019 第 9 题**
>
> 此类题适合画出 `i`、`j` 的变化序列，逐次记录比较，而不是只数“匹配轮数”。

---

## 4.4.13 一道 KMP 题的标准解题流程

### 第 1 步：确认下标体系

```text
0 基 / 1 基
```

### 第 2 步：确认辅助数组定义

查看：

```text
next[0] = -1 ?
next[1] = 0 ?
lps[0] = 0 ?
```

### 第 3 步：先算 `next`

对每个失配位置，寻找已经匹配部分的最长相等真前后缀。

### 第 4 步：若题目要求，再算 `nextval`

检查：

```text
P[j] == P[next[j]] ?
```

相同则继续向更早位置优化。

### 第 5 步：模拟匹配

失配时优先只调整 `j`，并记录 `i` 是否保持不变。

### 第 6 步：根据题目问法输出

题目可能问：

- 新的 `i`、`j`；
- `next` / `nextval`；
- 字符比较次数；
- 模式串滑动距离；
- 匹配起始位置。

这些量不能混为一谈。


## 4.4.15 章末速记

### 朴素匹配

核心：

> 每个候选起点都可能重新从模式串首字符开始比较。

最坏时间复杂度：

$$
O(nm)
$$

### KMP

核心：

> 利用模式串自身的前后缀信息完成失配跳转，使主串指针不回退。

时间复杂度：

$$
O(n+m)
$$

额外空间复杂度：

$$
O(m)
$$

### 经典 `next`

本章约定：

```text
next[0] = -1
```

失配时：

```text
j = next[j]
```

### `nextval`

作用：

> 跳过那些“即使跳过去，也能立刻确定仍会失配”的位置。

### 最后检查

做 KMP 题前固定问四句：

```text
下标从几开始？
next 首值是什么？
求 next / nextval / LPS 中哪一个？
题目问位置、比较次数还是滑动距离？
```

确认这四点后，大部分 KMP 题都会转化为稳定的机械计算。
