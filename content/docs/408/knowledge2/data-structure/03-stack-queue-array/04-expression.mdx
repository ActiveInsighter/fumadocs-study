表达式问题是栈最典型、最稳定的应用之一。考试常把三件事混在一起：

1. 表达式树与前 / 中 / 后序遍历；
2. 中缀表达式直接求值；
3. 中缀表达式转换为后缀，再用栈求值。

真正需要牢牢记住的是**运算符何时入栈、何时出栈，以及二元运算的左右操作数顺序**。

---

## 3.4.1 二叉表达式树

**二叉表达式树（Expression Tree）**&#x2060;用二叉树表示二元表达式：

- 叶结点通常是操作数；
- 非叶结点通常是运算符；
- 一个内部结点表示“用该运算符连接左右子表达式”。

例如：

```text
(A + B) * C
```

表达式树为：

```text
      *
     / \
    +   C
   / \
  A   B
```

越靠近叶结点的运算通常越早完成；根结点对应整个表达式最后执行的运算。

---

## 3.4.2 前缀、中缀、后缀与树遍历

对表达式树采用不同遍历：

| 遍历 | 得到的表达式 |
| --- | --- |
| 前序遍历 | 前缀表达式 |
| 中序遍历 | 中缀表达式 |
| 后序遍历 | 后缀表达式 |

以上例：

```text
前缀：* + A B C
中缀：(A + B) * C
后缀：A B + C *
```

前缀表达式又称**波兰表达式**，后缀表达式又称**逆波兰表达式**。

对于运算符元数确定的表达式，前缀 / 后缀形式通常不需要额外括号就能唯一确定运算结构。

---

## 3.4.3 后缀表达式为什么只需要一个操作数栈

后缀表达式把运算符放在对应操作数之后，因此扫描到运算符时，它需要的操作数已经出现在前面。

算法：

```text
从左到右扫描：
操作数 → 入栈
运算符 → 弹出操作数并计算 → 结果重新入栈
```

对于二元运算符 `op`：

```text
B = pop()
A = pop()
result = A op B
```

> **真题标签｜2018：后缀表达式求值**
>
> 最常见失分点是减法和除法把操作数顺序写反。第一次弹出的是右操作数 $B$，第二次弹出的是左操作数 $A$。

例如：

```text
3 5 2 * 8 - +
```

求值过程：

| 当前符号 | 操作 | 栈 |
| --- | --- | --- |
| `3` | 入栈 | `3` |
| `5` | 入栈 | `3 5` |
| `2` | 入栈 | `3 5 2` |
| `*` | $5\times2=10$ | `3 10` |
| `8` | 入栈 | `3 10 8` |
| `-` | $10-8=2$ | `3 2` |
| `+` | $3+2=5$ | `5` |

最终值为：

$$
5
$$

## 3.4.4 中缀表达式直接求值：双栈模型

中缀表达式中运算符夹在操作数之间，并且还要处理：

- 优先级；
- 结合性；
- 括号。

一种经典实现使用两个栈：

```text
操作数栈 + 运算符栈
```

执行一次二元运算时：

```text
op = 弹出运算符
B  = 弹出操作数
A  = 再弹出操作数
计算 A op B
结果压回操作数栈
```

对于 `-` 与 `/`，顺序不可颠倒。

---

## 3.4.5 中缀直接求值的扫描规则

从左到右扫描中缀表达式。

### 遇到操作数

直接压入操作数栈。

### 遇到左括号 `(`

直接压入运算符栈。左括号相当于建立一个局部优先级边界。

### 遇到右括号 `)`

不断弹出并执行运算符，直到栈顶遇到 `(`；随后把 `(` 弹出，但它不参加计算。

### 遇到普通运算符 `op`

对常见左结合运算符 `+ - * /`：

- 若运算符栈为空，直接入栈；
- 若栈顶是 `(`，直接入栈；
- 若当前运算符优先级**高于**栈顶，直接入栈；
- 否则先执行栈顶运算，直到当前运算符可以入栈。

扫描结束后，再执行运算符栈中的剩余运算。

---

## 3.4.6 中缀直接求值示例

计算：

```text
3 + (5 * 2 - 8)
```

| 步骤 | 输入 | 动作 | 运算符栈 | 操作数栈 |
| ---: | --- | --- | --- | --- |
| 1 | `3` | 操作数入栈 |  | `3` |
| 2 | `+` | 运算符入栈 | `+` | `3` |
| 3 | `(` | 左括号入栈 | `+ (` | `3` |
| 4 | `5` | 操作数入栈 | `+ (` | `3 5` |
| 5 | `*` | 运算符入栈 | `+ ( *` | `3 5` |
| 6 | `2` | 操作数入栈 | `+ ( *` | `3 5 2` |
| 7 | `-` | 先算 $5\times2$，再压 `-` | `+ ( -` | `3 10` |
| 8 | `8` | 操作数入栈 | `+ ( -` | `3 10 8` |
| 9 | `)` | 算 $10-8$，再删 `(` | `+` | `3 2` |
| 10 | 结束 | 算 $3+2$ |  | `5` |

结果：

$$
5
$$

## 3.4.7 中缀转后缀：总体结构

中缀转后缀需要：

```text
一个运算符栈 + 一个输出序列
```

扫描时只把**操作数直接输出**；运算符是否输出，要由优先级、括号和结合性共同决定。

> **真题标签｜2012、2014、2024：中缀转后缀**
>
> 对普通左结合运算符，当前运算符与栈顶优先级相同时，也必须先弹出栈顶运算符。

---

## 3.4.8 中缀转后缀的五条规则

### 规则 1：操作数

直接输出。

```text
A → 输出 A
```

### 规则 2：左括号 `(`

直接入运算符栈。

### 规则 3：右括号 `)`

不断弹出栈顶运算符并输出，直到遇到 `(`；左括号本身只弹出，不输出。

### 规则 4：普通左结合运算符

当前运算符为 `op` 时，不断弹出满足下列条件的栈顶运算符：

```text
栈顶不是 '('，并且
栈顶优先级 >= 当前 op 优先级
```

弹出后输出，直到不再满足；然后让当前 `op` 入栈。

### 规则 5：扫描结束

把剩余运算符依次弹出并输出。

---

## 3.4.9 为什么同优先级也要弹出：结合性

对于普通左结合运算符：

```text
+  -  *  /
```

例如：

```text
a - b - c
```

其含义是：

```text
(a - b) - c
```

因此第二个 `-` 到来时，第一个 `-` 必须先出栈输出。

正确后缀：

```text
ab-c-
```

若某类运算符是**右结合**，同优先级时的处理规则会不同。因此更一般的算法应把“优先级 + 结合性”一起考虑，而不能简单记成“遇到相等一定弹出”。

---

## 3.4.10 中缀转后缀完整示例

中缀：

```text
a/b+(c*d-e*f)/g
```

关键过程：

```text
a      → 输出 a
/      → 入栈
b      → 输出 b
+      → / 先出栈，再压 +
(      → 入栈
c      → 输出 c
*      → 入栈
d      → 输出 d
-      → * 先出栈，再压 -
e      → 输出 e
*      → 入栈
f      → 输出 f
)      → 依次弹出 *、-，再删除 (
/      → 入栈
g      → 输出 g
结束   → 依次弹出 /、+
```

得到：

```text
ab/cd*ef*-g/+
```

可用“表达式树后序遍历”验证其结构是否合理。

---

## 3.4.11 中缀转后缀与后缀求值的关系

可以把整个过程分成两阶段：

```text
中缀表达式
   ↓  运算符栈
后缀表达式
   ↓  操作数栈
最终数值
```

这说明两种算法虽然都用栈，但栈里保存的对象不同：

| 任务 | 栈中主要保存 |
| --- | --- |
| 中缀转后缀 | 运算符 |
| 后缀求值 | 操作数 / 中间结果 |
| 中缀直接求值 | 操作数栈 + 运算符栈 |

---

## 3.4.12 表达式题易错点清单

1. **后缀求值弹出的第一个数是右操作数。**
2. `)` 不进入后缀输出；它只触发弹栈直到 `(`。
3. `(` 也不进入最终后缀表达式。
4. 左结合运算符同优先级时，要先弹出栈顶旧运算符。
5. 中缀直接求值与中缀转后缀规则相似，但“弹出运算符”后的动作不同：前者立即计算，后者把运算符输出。
6. 表达式树中：前序对应前缀，中序对应中缀，后序对应后缀。
