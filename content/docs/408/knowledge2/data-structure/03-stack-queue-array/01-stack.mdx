栈是**操作受限的线性表**。它的考查难点通常不在定义，而在于：题目会改变 `top` 的含义、给出一串入栈出栈操作，或把栈嵌入表达式、递归、树和图算法中。

本节先把栈本身的结构与操作彻底理清，后续表达式与出栈序列问题都建立在这里。

---

## 3.1.1 栈的定义与 LIFO 特性

**栈（Stack）**&#x2060;只允许在同一端进行插入和删除：

- 允许操作的一端称为**栈顶（Top）**；
- 另一端称为**栈底（Bottom）**；
- 插入称为**入栈 / 压栈（Push）**；
- 删除称为**出栈 / 弹栈（Pop）**。

栈遵循：

> **后进先出（LIFO，Last In First Out）**。

若依次执行：

```text
push(A)
push(B)
push(C)
```

此时结构为：

```text
栈顶
 C
 B
 A
栈底
```

第一次 `pop()` 必然得到 `C`。

> **真题标签｜2015、2017、2025：栈的基本性质与操作约束**
>
> 此类题的核心不是记“后进先出”四个字，而是能够根据某一时刻的栈内顺序判断下一步允许弹出谁。

## 3.1.2 栈的抽象操作

常见 ADT 操作如下：

| 操作 | 含义 |
| --- | --- |
| `InitStack` | 初始化空栈 |
| `Push` | 元素入栈 |
| `Pop` | 删除并返回栈顶元素 |
| `GetTop` / `Peek` | 读取栈顶元素但不删除 |
| `StackEmpty` | 判断是否为空 |
| `StackFull` | 顺序栈中判断是否已满 |

栈最本质的限制是：

```text
只能直接访问当前栈顶。
```

因此即使某个元素已经在栈中，也不能越过它上方的元素直接删除它。

---

## 3.1.3 顺序栈与 `top` 的第一种常见约定

顺序栈使用连续数组保存元素，并维护栈顶位置。

本节采用最常见的约定：

```text
top 指向“当前栈顶元素”
```

于是：

- 空栈：`top == -1`；
- 第一个元素入栈后：`top == 0`；
- 栈满：`top == MAX_SIZE - 1`；
- 当前元素个数：

$$
size=top+1
$$

典型结构：

```c
#define MAX_SIZE 100

typedef struct {
    ElementType data[MAX_SIZE];
    int top;
} SeqStack;
```

初始化：

```c
void InitStack(SeqStack *S) {
    S->top = -1;
}
```

判空与判满：

```c
bool StackEmpty(SeqStack *S) {
    return S->top == -1;
}

bool StackFull(SeqStack *S) {
    return S->top == MAX_SIZE - 1;
}
```

> **易错点｜`top` 的语义比公式更重要**
>
> 有些题把 `top` 定义为“下一个可插入位置”。此时空栈常变成 `top == 0`，入栈和出栈语句也会随之改变。做题必须先读题目的指针定义，再写判空、判满和元素个数。

## 3.1.4 顺序栈入栈：先移动还是先写入

在“`top` 指向当前栈顶元素”的约定下，入栈逻辑是：

```text
判满 → top 后移 → 写入新元素
```

```c
bool Push(SeqStack *S, ElementType x) {
    if (StackFull(S))
        return false;

    S->data[++S->top] = x;
    return true;
}
```

关键是：

```c
S->data[++S->top] = x;
```

即**先令 `top` 指向新栈顶位置，再写入数据**。

时间复杂度：

$$
T(n)=O(1)
$$

---

## 3.1.5 顺序栈出栈与取栈顶

出栈逻辑：

```text
判空 → 读取当前栈顶 → top 前移
```

```c
bool Pop(SeqStack *S, ElementType *x) {
    if (StackEmpty(S))
        return false;

    *x = S->data[S->top--];
    return true;
}
```

时间复杂度：

$$
T(n)=O(1)
$$

只读取栈顶而不删除：

```c
bool GetTop(SeqStack *S, ElementType *x) {
    if (StackEmpty(S))
        return false;

    *x = S->data[S->top];
    return true;
}
```

注意 `GetTop` 不改变 `top`。

### 连续操作的快速模拟

若初始 `top=-1`，依次执行：

```text
Push(a), Push(b), Pop(), Push(c)
```

则 `top` 变化为：

```text
-1 → 0 → 1 → 0 → 1
```

栈内容最终为：

```text
栈顶 c
     a
```

这类题只要同时维护：

```text
1. top 数值
2. 栈内实际顺序
```

就不容易混乱。

## 3.1.6 另一类顺序栈约定：`top` 指向下一个空位

有些教材或程序采用：

```text
top 指向“下一个待插入位置”
```

此时通常：

- 空栈：`top == 0`；
- 元素个数：`top`；
- 栈顶元素：`data[top - 1]`；
- 入栈：先写 `data[top]`，再 `top++`；
- 出栈：先 `top--`，再读 `data[top]`。

例如：

```c
bool Push(SeqStack *S, ElementType x) {
    if (S->top == MAX_SIZE)
        return false;

    S->data[S->top++] = x;
    return true;
}

bool Pop(SeqStack *S, ElementType *x) {
    if (S->top == 0)
        return false;

    *x = S->data[--S->top];
    return true;
}
```

两套写法都正确，关键是全程保持同一语义。

## 3.1.7 链栈：为什么栈顶通常设在链表头部

栈也可以使用单链表实现，称为**链栈（Linked Stack）**。

为了让入栈与出栈都保持常数时间，通常把链表**头部**作为栈顶：

```text
head → [栈顶] → [下一元素] → ... → NULL
```

若使用带头结点的单链表：

```text
head → [头结点] → [栈顶] → ... → NULL
```

那么：

- `head->next` 指向栈顶元素；
- `head->next == NULL` 表示空栈；
- 入栈就是头插；
- 出栈就是删除第一个有效结点。

若反过来把**单链表尾部**当栈顶，则删除尾结点前通常还要寻找前驱，出栈可能退化为 $O(n)$。

---

## 3.1.8 带头结点链栈的结构与初始化

```c
typedef struct Node {
    ElementType data;
    struct Node *next;
} Node;

typedef struct {
    Node *head;
} LinkedStack;
```

初始化：

```c
bool InitStack(LinkedStack *S) {
    S->head = (Node *)malloc(sizeof(Node));
    if (S->head == NULL)
        return false;

    S->head->next = NULL;
    return true;
}
```

判空：

```c
bool StackEmpty(LinkedStack *S) {
    return S->head->next == NULL;
}
```

---

## 3.1.9 链栈入栈、出栈与取栈顶

### 入栈

```c
bool Push(LinkedStack *S, ElementType x) {
    Node *p = (Node *)malloc(sizeof(Node));
    if (p == NULL)
        return false;

    p->data = x;
    p->next = S->head->next;
    S->head->next = p;
    return true;
}
```

本质：

```text
在头结点之后头插一个新结点。
```

### 出栈

```c
bool Pop(LinkedStack *S, ElementType *x) {
    if (StackEmpty(S))
        return false;

    Node *p = S->head->next;
    *x = p->data;
    S->head->next = p->next;
    free(p);
    return true;
}
```

### 获取栈顶

```c
bool GetTop(LinkedStack *S, ElementType *x) {
    if (StackEmpty(S))
        return false;

    *x = S->head->next->data;
    return true;
}
```

三种操作的核心都只涉及头部常数个结点，因此：

$$
Push=O(1),\qquad Pop=O(1),\qquad GetTop=O(1)
$$

## 3.1.10 顺序栈与链栈比较

| 对比项 | 顺序栈 | 链栈 |
| --- | --- | --- |
| 物理存储 | 连续 | 链式、可分散 |
| 入栈 | $O(1)$ | $O(1)$ |
| 出栈 | $O(1)$ | $O(1)$ |
| 容量 | 通常预先限定 | 随结点动态增长 |
| 额外指针空间 | 不需要 | 每个结点需要指针域 |
| 缓存局部性 | 较好 | 较差 |
| 固定容量溢出 | 可能发生 | 通常只受可用内存限制 |

选择存储结构时不要只看渐进复杂度：两者基本操作都是 $O(1)$，但空间布局、容量约束和常数开销不同。

## 3.1.11 本节易错点速查

1. **先确认 `top` 指向哪里。** 不同定义对应不同空栈、满栈和元素个数公式。
2. **`Pop` 会删除栈顶，`GetTop` 不会。**
3. **链栈通常把链头作为栈顶。** 单链表尾部做栈顶会使删除尾结点变慢。
4. **栈只能操作栈顶。** 任何出栈序列判断都必须服从这一限制。
5. **数组容量与栈中元素个数不要混淆。** 在 `top=-1` 约定下，当前元素数是 `top+1`。
