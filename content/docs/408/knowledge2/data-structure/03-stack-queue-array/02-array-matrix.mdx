数组与矩阵题的核心，不是背一堆看似不同的公式，而是统一转化为：

> **目标元素之前已经顺序存放了多少个元素？**

得到元素个数后，再乘以每个元素占用的字节数，就能完成地址计算；特殊矩阵压缩存储则进一步把“二维下标”映射为“一维下标”。

## 8. 多维数组的存储与地址计算

<InlineSvg src="/images/data-structure/data-structure-array-matrix-001.svg" alt="图示" />

> **真题标签**
>
> 2021 年第 3 题涉及多维数组的存储与地址计算。

### 8.1 二维数组最终仍映射到一维连续地址

二维数组逻辑上具有“行、列”两个维度，但顺序存储时，内存地址仍按一维线性顺序排列。

设二维数组为：

```text
A[R][C]
```

并规定：

- `A[0][0]` 的首地址为 $A_0$；
- 每个元素占 $B$ 字节；
- 行、列下标都从 0 开始；
- 共 $R$ 行、$C$ 列。

地址计算的统一形式为：

$$
Addr(A[i][j])=A_0+\text{offset}(i,j)\times B
$$

真正需要推导的只有偏移量 `offset`。

### 8.2 行主序

**行主序（row-major order）**&#x2060;先存完整的第 0 行，再存第 1 行，依此类推。

在 `A[i][j]` 之前：

- 已完整经过 $i$ 行，每行 $C$ 个元素，共 $iC$ 个；
- 当前第 $i$ 行中，前面还有 $j$ 个元素。

因此：

$$
\text{offset}=iC+j
$$

从而：

$$
Addr(A[i][j])=A_0+(iC+j)B
$$

C/C++ 的普通多维数组采用行主序。

例如：

```c
int a[2][3] = {
    {1, 2, 3},
    {4, 5, 6}
};
```

实际线性顺序是：

```text
a[0][0], a[0][1], a[0][2],
a[1][0], a[1][1], a[1][2]
```

若 `a[0][0] = 0x100`，且 `sizeof(int) = 4`，则：

```text
a[0][0] -> 0x100
a[0][1] -> 0x104
a[0][2] -> 0x108
a[1][0] -> 0x10C
a[1][1] -> 0x110
a[1][2] -> 0x114
```

### 8.3 列主序

**列主序（column-major order）**&#x2060;先存完整的第 0 列，再存第 1 列。

在 `A[i][j]` 之前：

- 已完整经过 $j$ 列，每列 $R$ 个元素，共 $jR$ 个；
- 当前第 $j$ 列中，前面有 $i$ 个元素。

因此：

$$
\text{offset}=jR+i
$$

从而：

$$
Addr(A[i][j])=A_0+(jR+i)B
$$

Fortran 等语言/环境典型地采用列主序；MATLAB 的底层数组存储也采用列主序。

<Callout type="info" title="地址题不要先背公式">
行主序就数“前面完整的行 + 本行前面的元素”；列主序就数“前面完整的列 + 本列前面的元素”。这样即使下标起点、维数或题目符号变化，也能现场推导。
</Callout>


### 8.4 多维数组的统一地址公式

二维数组只是多维数组的特例。设 $d$ 维数组：

$$
A[n_1][n_2]\cdots[n_d]
$$

各维下标均从 0 开始，元素为：

$$
A[i_1][i_2]\cdots[i_d]
$$

若采用**行主序**，最后一维变化最快，则线性偏移量为：

$$
\text{offset}=i_1(n_2n_3\cdots n_d)+i_2(n_3n_4\cdots n_d)+\cdots+i_{d-1}n_d+i_d
$$

也可写成逐层“乘维长再加下标”的 Horner 形式：

$$
\text{offset}=(((i_1n_2+i_2)n_3+i_3)\cdots)n_d+i_d
$$

若每个元素占 $B$ 字节，则：

$$
Addr=A_0+\text{offset}\times B
$$

若采用**列主序**，则第一维变化最快，可按同样思想从相反方向计算。

<Callout type="info" title="多维数组现场推导法">
把当前维看成“已经完整跨过了多少个后缀子数组”。行主序中，第 $r$ 维下标每增加 1，要跨过后续各维长度之积 $n_{r+1}n_{r+2}\cdots n_d$ 个元素。
</Callout>

## 9. 特殊矩阵压缩存储的统一思想

> **真题标签**
>
> 2016 年第 4 题、2017 年第 3 题、2018 年第 3 题、2020 年第 1 题、2023 年第 3 题涉及特殊矩阵或稀疏矩阵。

某些矩阵的大量元素具有固定规律，例如：

- 关于主对角线对称；
- 某一三角区域全为同一个常量；
- 只有少数对角线可能非零；
- 绝大多数元素为 0。

如果仍保存全部 $n^2$ 个元素，会浪费空间。

压缩存储的核心是建立：

$$
(i,j)\longleftrightarrow k
$$

其中 $(i,j)$ 是原矩阵下标，$k$ 是一维压缩数组下标。

### 9.1 解题前必须写清四个约定

1. 原矩阵是 **0 基**还是 **1 基**下标；
2. 压缩数组是 **0 基**还是 **1 基**下标；
3. 按**行优先**还是**列优先**存储；
4. 实际保存的是哪个区域。

<Callout type="warn" title="常数项错 1 往往不是公式不会，而是下标体系没看清">
同一种矩阵，只要“矩阵 1 基 / 数组 0 基”改成“矩阵 0 基 / 数组 0 基”，公式中的常数项就会改变。最稳妥的方法始终是重新数“前面存了多少个元素”。
</Callout>

## 10. 对称矩阵

<InlineSvg src="/images/data-structure/data-structure-array-matrix-002.svg" alt="对称矩阵压缩存储" />
![对称矩阵按下三角区域压缩到一维数组的存储示意](/images/data-structure/data-structure-array-matrix-003.png)

### 10.1 定义与存储规模

若 $n\times n$ 矩阵满足：

$$
a_{ij}=a_{ji}
$$

则称为**对称矩阵**。

上三角与下三角包含重复信息，只保存其中一半即可。

独立元素数量为：

$$
1+2+\cdots+n=\frac{n(n+1)}{2}
$$

### 10.2 下三角按行优先存储

设：

- 原矩阵使用 1 基下标；
- 压缩数组 `B` 使用 0 基下标；
- 保存下三角区域；
- 按行优先存储。

当 $i\ge j$ 时，第 $i$ 行之前已经保存：

$$
1+2+\cdots+(i-1)=\frac{i(i-1)}{2}
$$

个元素。

在第 $i$ 行内，$a_{ij}$ 前面还有 $j-1$ 个元素，因此：

$$
k=\frac{i(i-1)}{2}+j-1
$$

当 $i<j$ 时，由对称性：

$$
a_{ij}=a_{ji}
$$

转换到下三角位置 $(j,i)$：

$$
k=\frac{j(j-1)}{2}+i-1
$$

统一写为：

$$
k(i,j)=
\begin{cases}
\dfrac{i(i-1)}{2}+j-1, & i\ge j,\\[6pt]
\dfrac{j(j-1)}{2}+i-1, & i<j.
\end{cases}
$$

### 10.3 对称矩阵题的通用处理

遇到不在实际存储三角区的元素：

1. 先利用 $a_{ij}=a_{ji}$ 把下标“翻转”到存储区；
2. 再数该位置之前已经存了多少元素。

## 11. 三角矩阵

<InlineSvg src="/images/data-structure/data-structure-array-matrix-004.svg" alt="三角矩阵压缩存储" />

### 11.1 定义

三角矩阵中，主对角线一侧的元素都等于同一个常量，最常见的是 0。

例如上三角矩阵：

```text
a11 a12 a13 a14
  0 a22 a23 a24
  0   0 a33 a34
  0   0   0 a44
```

真正需要逐个保存的上三角元素数为：

$$
\frac{n(n+1)}{2}
$$

若另一侧统一常量也需要保存，可额外用一个位置记录该常量，因此总存储单元数为：

$$
\frac{n(n+1)}{2}+1
$$

### 11.2 上三角矩阵按行优先压缩

设：

- 原矩阵 1 基；
- 压缩数组 0 基；
- 保存上三角区域；
- $i\le j$。

第 $i$ 行之前的有效元素数为：

$$
n+(n-1)+\cdots+(n-i+2)
$$

共有 $i-1$ 项，化简为：

$$
\frac{(i-1)(2n-i+2)}{2}
$$

当前行内，$a_{ij}$ 前面有：

$$
j-i
$$

个有效元素。

所以：

$$
k(i,j)=
\frac{(i-1)(2n-i+2)}{2}+(j-i)
$$

对位于统一常量区域的元素，无需真正存储每一个值，只需返回那一个公共常量。

### 11.3 下三角矩阵同理

若保存下三角并按行优先，设原矩阵使用 1 基下标、压缩数组使用 0 基下标，则对 $i\ge j$：

$$
k(i,j)=\frac{i(i-1)}{2}+j-1
$$

推导方式与对称矩阵下三角部分完全相同：

> **先数前面完整的行，再数当前行前面的有效元素。**

若三角矩阵另一侧统一为常量 $c$，则这些位置不必分别占用存储单元；访问时直接返回 $c$ 即可。

## 12. 三对角矩阵

### 12.1 定义与元素数量

三对角矩阵只有：

- 主对角线；
- 主对角线上方一条对角线；
- 主对角线下方一条对角线；

可能为非零。

因此只有满足：

$$
|i-j|\le 1
$$

的位置需要保存。

有效元素总数：

$$
n+(n-1)+(n-1)=3n-2
$$

### 12.2 1 基矩阵、0 基数组、按行优先时的映射

对于有效元素 $a_{ij}$：

$$
k=2i+j-3
$$

其中：

$$
|i-j|\le 1
$$

检查前两行：

```text
第 1 行：a11 a12          -> B[0], B[1]
第 2 行：a21 a22 a23      -> B[2], B[3], B[4]
```

最后一个有效元素 $a_{nn}$ 的下标为：

$$
k=3n-3
$$

所以数组长度为：

$$
3n-2
$$

<Callout type="info" title="三对角公式也可以现场推">
对第 $i$ 行而言，前面完整行已经贡献若干有效元素，再加上本行内的相对位置即可。只要题目改变下标起点，就重新数一次，不必死背常数项。
</Callout>

### 12.3 由压缩下标反求矩阵位置

在本节“矩阵 1 基、压缩数组 0 基、按行优先”的约定下，若已知压缩数组下标 $k$，可先求所在行：

$$
i=\left\lfloor\frac{k+1}{3}\right\rfloor+1
$$

再由正向关系 $k=2i+j-3$ 得：

$$
j=k-2i+3
$$

因此正向和反向映射可以互相校验。边界行虽然只有 2 个元素，但上述公式对合法的 $k$ 仍成立。

## 13. 稀疏矩阵

### 13.1 定义

当矩阵中绝大多数元素为 0，只有少量非零元素时，称为**稀疏矩阵（sparse matrix）**。

如果矩阵规模为 $m\times n$、非零元素数为 $t$，且 $t\ll mn$，直接保存全部 $mn$ 个元素通常浪费空间。

常见压缩结构：

1. **三元组表**；
2. **十字链表**。

### 13.2 稀疏矩阵和特殊矩阵的区别

对称矩阵、三角矩阵、三对角矩阵的非零/重复模式具有明确规律，因此可以用数学公式直接计算压缩下标。

稀疏矩阵的非零位置通常没有固定规律，所以更常直接记录：

```text
行号 + 列号 + 元素值
```

## 14. 三元组表

<InlineSvg src="/images/data-structure/data-structure-array-matrix-012.svg" alt="0 0 1 0 0 0 0 0 2 0 0 0 0 0 3 0 0 0 0 0 0 0 0 0 5 0 0 0 0 0 0 0 6 0 0 0 0 0 0 0 7 4 i j a ij 0 2 1 1 1 2 2 0 3 3 3 5 4 4 6 5 5 7 5 6 4 稀疏矩阵 三元组表" />

> **真题标签**
>
> 2017 年第 3 题涉及稀疏矩阵存储结构；2023 年第 3 题涉及相关压缩存储知识。

### 14.1 基本结构

每个非零元素保存为：

```text
(row, col, value)
```

若共有 $t$ 个非零元素，则只需要保存 $t$ 个三元组，再附加矩阵行数、列数等元数据。

三元组通常按：

1. 行号递增；
2. 同一行内列号递增；

进行排列。

### 14.2 结构体数组实现

```c
#define MAXSIZE 100

typedef struct {
    int row;
    int col;
    ElementType value;
} Triple;

typedef struct {
    int rows;
    int cols;
    int nums;
    Triple data[MAXSIZE];
} TSMatrix;
```

也可以分别用 `row[]`、`col[]`、`value[]` 三个数组保存，本质相同。

### 14.3 空间是否真的更省

若每个三元组都需要保存“行号、列号、值”三项信息，而普通矩阵只保存值，则不能只比较 $t$ 与 $mn$。粗略地说，当三项占用空间接近时，三元组表的主体空间约与 $3t$ 成正比。

因此压缩存储是否划算取决于：

- 非零元素数量 $t$；
- 行号、列号与元素值各自占用的字节数；
- 是否还要保存行/列辅助索引。

408 通常只要求理解“$t\ll mn$ 时适合压缩”，但做空间题时应按题目给出的字段大小精确计算。

### 14.4 优缺点

**优点：**

- 只保存非零元素；
- 结构简单；
- 适合遍历、输出、转置、矩阵加法等操作；
- 当矩阵非常稀疏时，空间远小于普通二维数组。

**缺点：**

- 不能像普通二维数组那样 $O(1)$ 随机定位任意 `(i,j)`；
- 查找某个具体元素通常需要在三元组序列中搜索；
- 频繁插入/删除非零元素时，顺序三元组表可能需要移动元素。

## 15. 十字链表

<InlineSvg src="/images/data-structure/data-structure-array-matrix-013.svg" alt="3 1 1 3 2 2 -1 ^ ^ 3 1 2 ^ ^ ^ 1 4 5 ^ ^ rhead chead 0 0 5 0 -1 0 0 2 0 0 0" />

### 15.1 为什么需要十字链表

如果既希望高效地：

- 按行遍历非零元素；
- 又按列遍历非零元素；
- 还要频繁插入、删除非零元素；

可以使用**十字链表（cross list）**。

每个非零元素结点同时属于：

- 一条行链表；
- 一条列链表。

### 15.2 结点结构

```c
typedef struct CrossListNode {
    int row;
    int col;
    ElementType value;

    struct CrossListNode *right;
    struct CrossListNode *down;
} CrossListNode;
```

其中：

- `right` 指向同行的下一个非零元素；
- `down` 指向同列的下一个非零元素。

整体结构可以维护：

```c
typedef struct {
    CrossListNode **rhead;
    CrossListNode **chead;

    int rows;
    int cols;
    int nums;
} CrossList;
```

- `rhead[i]`：第 `i` 行链表入口；
- `chead[j]`：第 `j` 列链表入口。

### 15.3 特点

十字链表：

- 只保存非零元素；
- 可以方便地按行遍历；
- 可以方便地按列遍历；
- 插入、删除时主要修改链接，不需要整体搬移大量三元组；
- 更适合动态稀疏矩阵。

### 15.4 三元组表与十字链表对比

| 对比项 | 三元组表 | 十字链表 |
| --- | --- | --- |
| 存储方式 | 顺序表式三元组序列 | 链式结点 |
| 保存对象 | 非零元素 | 非零元素 |
| 按行遍历 | 方便 | 方便 |
| 按列遍历 | 通常不如按行方便 | 方便 |
| 插入/删除 | 可能移动后续三元组 | 修改链接为主 |
| 指针开销 | 较少 | 每结点有 `right/down` |
| 适用场景 | 结构较稳定 | 动态变化较多 |

<Callout type="warn" title="别把“十字链表”只和图联系起来">
“十字链表”这个名称在不同知识点中可能指向不同的链式组织方式。这里讨论的是**稀疏矩阵**：每个非零结点通过 `right`、`down` 同时参与行链和列链。
</Callout>
