## 十九、最短路径

> **真题考察**
>
> * 选择题：2012 年第 7 题、2016 年第 8 题、2021 年第 8 题
> * 解答题：2009 年第 41 题、2014 年第 42 题

最短路径问题不是只问“能不能到达”，而是问：

> **在所有可达路径中，哪一条代价最小？**

408 重点掌握两类：

* **Dijkstra**：一个源点到其他顶点，即单源最短路径；
* **Floyd-Warshall**：任意两顶点之间，即全源最短路径。

若图无权或所有边权都相同，则 BFS 也可以求单源最少边数路径。

<Callout type="info" title="最短路题先识别三件事">

1. 是**单源**还是**任意顶点对**；
2. 是否存在**负权边**；
3. 只要距离，还是还要恢复**具体路径**。

这三点基本就能决定使用 BFS、Dijkstra 还是 Floyd-Warshall，以及是否需要额外的前驱矩阵/数组。

</Callout>

### 1. 松弛是最短路的核心操作

若当前已经有：

$$
dist[u]
$$

并且存在边 $u\to v$，则经过 $u$ 到达 $v$ 的候选距离为：

$$
dist[u]+w(u,v)
$$

若它更小，就更新：

$$
dist[v]
=
\min\{dist[v],\ dist[u]+w(u,v)\}
$$

这个过程称为**松弛**。松弛只会让当前估计值不增：`dist` 从“已知上界”逐步下降到真正最短距离。

## 二十、Dijkstra 算法

![Dijkstra\_Animation](/images/data-structure/data-structure-graph-operation-009.gif)

Dijkstra 用于求：

> **一个源点到其他所有顶点的最短路径。**

适用于：

* 有向图或无向图；
* 所有边权均为**非负**。

### 1. 核心贪心思想

<InlineSvg src="/images/data-structure/data-structure-graph-operation-010.svg" alt="DijkstraDemo" />

维护两类顶点：

* 最短距离已经最终确定；
* 最短距离尚未最终确定。

每一轮，从未确定顶点中选取当前 `dist` 最小的顶点 $u$。

在非负权前提下，此时 $dist[u]$ 已经不可能再被未来路径降低，因此可以把 $u$ 永久确定下来。由此还得到一个实用结论：**顶点被最终确定时的最短距离按非递减顺序出现**。

### 2. 核心数组

#### `dist[]`

$$
dist[v]
$$

表示源点 $s$ 到顶点 $v$ 的当前最短暂定距离。

初始化：

$$
dist[s]=0
$$

其余顶点：

$$
dist[v]=\infty
$$

#### `visited[]` / `final[]`

表示某顶点的最短距离是否已经最终确定。

初始均为 `false`。

若还需要恢复具体最短路径，通常再维护：

```text
prev[v]
```

记录当前最短路径中 $v$ 的前驱。

### 3. 松弛

当 $u$ 被确定后，对每个邻接点 $v$ 尝试：

$$
dist[v]
=
\min
\left(
  dist[v],
  dist[u]+w(u,v)
\right)
$$

若发生更新，同时令：

```text
prev[v] = u
```

最终若 `dist[v] = INF`，说明 $v$ 从源点不可达；若需要输出路径，则从目标点沿 `prev[]` 回溯到源点后逆序输出。

### 4. 算法过程

<InlineSvg src="/images/data-structure/data-structure-graph-operation-011.svg" alt="DijkstraAlgorithm" />

1. 初始化 `dist[]`；
2. 在全部未确定顶点中找 `dist` 最小者 $u$；
3. 将 $u$ 标记为已确定；
4. 用 $u$ 松弛所有未确定邻接点；
5. 重复，直到所有可达顶点都被确定。

```text
function Dijkstra_Simple(Graph, source):
    for each vertex v:
        dist[v] ← ∞
        visited[v] ← false

    dist[source] ← 0

    repeat |V| times:
        u ← 未访问顶点中 dist[u] 最小的顶点

        if u 不存在 or dist[u] = ∞:
            break

        visited[u] ← true

        for each neighbor v of u:
            if not visited[v]
               and dist[v] > dist[u] + w(u, v):
                dist[v] ← dist[u] + w(u, v)

    return dist
```

### 5. 为什么不能用于负权边

Dijkstra 的关键承诺是：

> 一旦某顶点成为未确定顶点中的最小 `dist`，它的距离就可以永久确定。

该结论依赖所有后续边权非负。

若存在负权边，一条“先走得较远、后来经过负权边大幅减小”的路径可能重新降低已经确定的顶点距离，于是贪心依据失效。

<Callout type="warn" title="Dijkstra 的限制是“不保证正确”，不是“每次都必错”">

某些含负权边的特例可能碰巧得到正确答案，但标准 Dijkstra 的贪心证明已经失效，因此考试中只要题目存在可参与路径的负权边，就不能把它作为通用解法。

</Callout>

### 6. 复杂度

顺序数组 + 邻接矩阵的朴素实现：

$$
O(V^2)
$$

邻接表 + 二叉堆：

$$
O((V+E)\log V)
$$

稀疏图中常简写为：

$$
O(E\log V)
$$

### 7. 手算表格方法

手算时每轮固定记录：

| 内容 | 含义 |
| --- | --- |
| 已确定集合 $S$ | 哪些顶点最短距离已经固定 |
| `dist[]` | 源点到各未确定顶点的当前最小距离 |
| 前驱 | 若题目要求恢复路径，则同步更新 |

每一轮只做两件事：

1. 选最小 `dist`；
2. 从新确定顶点向外松弛。

## 二十一、Floyd-Warshall 算法

Floyd-Warshall 用于求：

> **任意两个顶点之间的最短路径。**

它是典型的动态规划算法。

允许：

* 有向图或无向图；
* 负权边。

但若存在某个可达的**负权环**，则相关顶点对之间不存在有限最短路径，因为可以无限绕负环使路径长度继续下降。

### 1. 动态规划状态

<InlineSvg src="/images/data-structure/data-structure-graph-operation-012.svg" alt="Floyd-Warshall 逐步引入中间顶点" />

设：

$$
D^{(k)}[i][j]
$$

表示从 $v_i$ 到 $v_j$，只允许 $v_1,\ldots,v_k$ 作为中间顶点时的最短距离。

当考虑是否让 $v_k$ 作为新的中间点时，只有两种选择：

* 不经过 $v_k$；
* 经过 $v_k$。

于是：

$$
D^{(k)}[i][j]
=
\min
\left(
D^{(k-1)}[i][j],
D^{(k-1)}[i][k]+D^{(k-1)}[k][j]
\right)
$$

压缩状态后就是经典更新式：

$$
dist[i][j]
=
\min
\left(
  dist[i][j],
  dist[i][k]+dist[k][j]
\right)
$$

### 2. 初始化

通常：

$$
dist[i][i]=0
$$

若有直接边 $i\to j$：

$$
dist[i][j]=w(i,j)
$$

否则：

$$
dist[i][j]=\infty
$$

### 3. 实现

```c
for (int k = 0; k < n; ++k) {
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            if (dist[i][k] != INF && dist[k][j] != INF) {
                dist[i][j] =
                    min(dist[i][j],
                        dist[i][k] + dist[k][j]);
            }
        }
    }
}
```

最关键的循环顺序是：

> **`k` 必须放在最外层。**

因为第 $k$ 轮的语义是“允许顶点 $k$ 作为新的中间顶点”。若把 `i` 或 `j` 放在最外层，原来的动态规划阶段含义就被破坏，不能再直接视为标准 Floyd-Warshall。

若题目还要求恢复具体路径，可额外维护 `next[i][j]` 或前驱矩阵；距离矩阵只负责回答“多长”，路径矩阵负责回答“怎么走”。

### 4. 复杂度

时间复杂度：

$$
O(V^3)
$$

空间复杂度：

$$
O(V^2)
$$

### 5. 判断负权环

Floyd 执行结束后，如果出现：

$$
dist[i][i]<0
$$

说明存在从 $i$ 出发可回到 $i$ 的负权闭环，即存在负权环。

408 通常重点掌握算法过程，不必扩展到复杂负环传播判断。

### 6. Dijkstra 与 Floyd 对比

| 项目 | Dijkstra | Floyd-Warshall |
| --- | --- | --- |
| 问题类型 | 单源最短路径 | 任意顶点对最短路径 |
| 核心思想 | 贪心 + 松弛 | 动态规划 |
| 负权边 | 不允许 | 可以 |
| 负权环 | 不适用 | 相关顶点对无有限最短路 |
| 经典复杂度 | $O(V^2)$ | $O(V^3)$ |
| 典型手算 | 一轮轮更新 `dist[]` | 一轮轮允许新中间点并更新矩阵 |

## 二十二、拓扑排序

> **真题考察**
>
> * 选择题：2010 年第 8 题、2012 年第 6 题、2014 年第 7 题、2016 年第 7 题、2018 年第 7 题、2021 年第 7 题
> * 解答题：2024 年第 41 题

对一个有向图，若可以将全部顶点排列为：

$$
v_1,v_2,\ldots,v_n
$$

使得对于每条有向边：

$$
u\rightarrow v
$$

顶点 $u$ 都出现在 $v$ 之前，则该序列称为一个**拓扑序列**。

存在拓扑序列的有向图必须是：

> **DAG（Directed Acyclic Graph，有向无环图）**。

反过来，每个有限 DAG 都至少存在一个拓扑序列。

### 1. 拓扑序列不一定唯一

同一个 DAG 可能有多个合法拓扑序列。

本质原因是某些顶点之间不存在必须先后的依赖关系，因此它们可以交换相对顺序。若题目要求“拓扑序列个数”，本质上是在每一步对所有当前入度为 0 的顶点进行分支选择，并在删除对应出边后继续计数。

### 2. 拓扑排序可以检测环

若算法执行到一半后再也找不到可处理顶点，却仍有顶点没有输出，则说明剩余部分存在有向环。

因此拓扑排序不仅能给出依赖顺序，也能用于**DAG 判定**。

## 二十三、AOV 网

<InlineSvg src="/images/data-structure/data-structure-graph-operation-013.svg" alt="AOV_Network" />

AOV 是：

**Activity On Vertex Network**

即：

> **顶点表示活动，有向边表示活动之间的先后约束。**

若：

$$
u\rightarrow v
$$

表示活动 $u$ 必须先完成，活动 $v$ 才能开始。

因此 AOV 网必须是 DAG；若存在有向环，就意味着出现循环依赖，例如：

```text
A 必须先于 B
B 必须先于 C
C 又必须先于 A
```

这种依赖无法完成。

> **AOV 与拓扑排序的关系**
>
> 一个 AOV 网的拓扑序列，就是满足全部先后约束的一种活动执行次序。

## 二十四、Kahn 拓扑排序

Kahn 算法从**入度**出发。

### 1. 核心思想

当前入度为 0 的顶点表示：

> 它已经没有尚未处理的前驱，可以立即安排。

### 2. 算法过程

<InlineSvg src="/images/data-structure/data-structure-graph-operation-014.svg" alt="1 2 4 3 5 2 4 3 5 4 3 5 3 5 5 结点编号 1 2 3 4 5 初始结点度 0 1 2 2 2 1 轮后 0 2 1 2 2 轮后 1 0 2 3 轮后 0 1 4 轮后 0 5 轮后 输出 1 输出 2 输出 4 输出 3 输出 1 输出 2 输出 4 输出 3 输出 5" />

1. 统计所有顶点入度；
2. 把全部入度为 0 的顶点放入容器；
3. 取出一个顶点 $u$ 并输出；
4. 删除 $u$ 的所有出边；
5. 对每个后继 $v$ 执行 `indegree[v]--`；
6. 若某个后继入度变成 0，则加入容器；
7. 重复直到容器为空。

```text
count ← 0

将所有 indegree[v] = 0 的顶点加入队列

while 队列非空:
    u ← 出队
    输出 u
    count ← count + 1

    for each edge u → v:
        indegree[v] ← indegree[v] - 1
        if indegree[v] = 0:
            v 入队
```

最后：

* 若 `count == V`，图是 DAG；
* 若 `count < V`，图中存在有向环。

### 3. 拓扑序是否唯一

对 Kahn 算法：

* 若**每一步**恰好只有一个入度为 0 的未处理顶点，则拓扑序唯一；
* 若某一步同时存在至少两个入度为 0 的可选顶点，则至少可以交换这一轮的选择，从而得到不同拓扑序，因此不唯一。

<Callout type="warn" title="“初始只有一个零入度点”不能推出拓扑序唯一">

唯一性必须检查整个删除过程。后续某一轮只要同时出现两个以上零入度顶点，就会产生分支。

</Callout>

### 4. 复杂度

若使用邻接表：

$$
O(V+E)
$$

因为每个顶点只入队、出队常数次，每条边也只在删除时处理一次。

## 二十五、DFS + 栈求拓扑序

<InlineSvg src="/images/data-structure/data-structure-graph-operation-015.svg" alt="topological_sort_dfs" />

拓扑序也可以通过 DFS 获得。

### 1. 核心规律

对 DAG 执行 DFS：

> 一个顶点只有在它的所有后继都处理完成后，才记录自己的“完成时刻”。

若在完成时把顶点压栈，则最后按出栈顺序得到拓扑序。

也可以理解为：

> 拓扑序 = DFS **逆完成序**。

### 2. 伪代码

```text
DFS(u):
    color[u] ← GRAY

    for each edge u → v:
        if color[v] = WHITE:
            DFS(v)
        else if color[v] = GRAY:
            发现有向环

    color[u] ← BLACK
    push(stack, u)
```

全部 DFS 结束后依次弹栈即可。若不用显式栈，而是把“完成顶点”依次追加到序列末尾，则最后把该序列整体逆序，也得到同样的拓扑序。

### 3. 三色标记与判环

常用三种状态：

* `WHITE`：尚未访问；
* `GRAY`：已经进入递归，但还未退出；
* `BLACK`：已经完全处理结束。

在有向图 DFS 中，如果遇到：

$$
GRAY\rightarrow GRAY
$$

即访问到当前递归路径中的祖先，则发现回边，说明存在有向环。

### 4. 复杂度

邻接表实现：

$$
O(V+E)
$$

### 5. Kahn 与 DFS 拓扑排序对比

| 方法 | 核心依据 | 辅助结构 | 判环方式 |
| --- | --- | --- | --- |
| Kahn | 入度为 0 | 队列/栈等容器 | 输出顶点数不足 $V$ |
| DFS | 逆完成序 | 递归栈/显式栈 | 发现指向 `GRAY` 的边 |

两者最终都只能对 DAG 给出合法拓扑序；若输入可能有环，就必须把“判环”作为算法的一部分。Kahn 更适合同时处理入度和唯一性，DFS 更适合与递归、完成时间和回边判断结合。
