## 十一、图的遍历

> **真题考察**
>
> * 选择题：2012 年第 5 题、2013 年第 8 题、2015 年第 5 题、2016 年第 6 题、2020 年第 6 题

图与树的遍历最关键的区别是：图中可能存在回路，同一个顶点也可能从多条路径到达，因此必须记录访问状态。

<Callout type="info" title="DFS/BFS 的统一框架">

两种遍历都可以拆成三步：**发现顶点 → 标记已访问 → 扩展它的未访问邻接点**。区别只在于“下一步扩展谁”：DFS 由栈决定，BFS 由队列决定。

</Callout>

通常使用：

```c
visited[v]
```

若不记录访问状态，可能造成：

* 同一顶点重复访问；
* 图中存在环时无限循环。

### 1. 连通图与非连通图

若图连通，从任意一个顶点开始 DFS/BFS 都能访问全部顶点。

若图不连通，一次 DFS/BFS 只能覆盖起点所在的连通分量，因此完整遍历需要在外层再次枚举顶点：

```c
for (int v = 0; v < vertices; ++v) {
    if (!visited[v]) {
        dfs(v);   // 或 bfs(v)
    }
}
```

对于无向图，外层每启动一次新的搜索，就发现了一个新的连通分量。因此完整 DFS/BFS 中“外层启动搜索的次数”恰好等于连通分量数。

### 2. 遍历序列是否唯一

一般**不唯一**。

即使起点相同，只要邻接点的访问顺序不同，就可能得到不同的 DFS/BFS 序列。

因此做手算题时，先确认：

* 邻接矩阵按什么顶点编号扫描；
* 邻接表中邻接点按什么顺序排列；
* 题目是否明确要求“按编号从小到大访问”。

## 十二、深度优先搜索 DFS

DFS（Depth-First Search）的核心思想是：

> **沿一条分支尽可能深入，走不动后回溯到最近还有未访问邻接点的顶点。**

实现方式：

* 递归，本质上使用系统调用栈；
* 显式栈。

### 1. 基本过程

<InlineSvg src="/images/data-structure/data-structure-graph-operation-001.svg" alt="A B C D E F A B C D E F A B C D E F A B C D E F A B C D E F A B C D E F" />

1. 访问当前顶点 $v$；
2. 将 $v$ 标记为已访问；
3. 在 $v$ 的邻接点中寻找尚未访问的顶点 $u$；
4. 对 $u$ 递归 DFS；
5. 当前分支结束后回溯。

```text
function DFS(G, v, visited):
    visited[v] ← true
    process(v)

    for each neighbor u of v:
        if not visited[u]:
            DFS(G, u, visited)
```

### 2. 邻接矩阵实现

```c
int visited[MAX_VERTICES];

void dfs(int start) {
    visited[start] = 1;
    printf("%d ", start);

    for (int i = 0; i < vertices; ++i) {
        if (adjMatrix[start][i] == 1 && !visited[i]) {
            dfs(i);
        }
    }
}
```

邻接矩阵中，对每个顶点都可能扫描完整的一行，因此总时间复杂度为：

$$
O(V^2)
$$

### 3. 邻接表实现

```c
int visited[MAX_VERTICES];

void dfs(struct Graph* graph, int start) {
    visited[start] = 1;
    printf("%d ", start);

    struct Node* temp = graph->adjacencyList[start];

    while (temp) {
        int adjVertex = temp->data;

        if (!visited[adjVertex]) {
            dfs(graph, adjVertex);
        }

        temp = temp->next;
    }
}
```

邻接表中每个顶点和每条边只需处理常数次，因此：

$$
O(V+E)
$$

### 4. DFS 树与 DFS 森林

连通无向图执行 DFS 时，第一次发现新顶点所使用的边形成一棵**DFS 生成树**。

若原图不连通，对每个连通分量都会得到一棵 DFS 树，合起来称为**DFS 生成森林**。

### 5. DFS 的常见应用

DFS 常用于：

* 判断连通性、求连通分量；
* 检测环；
* 拓扑排序；
* 搜索路径、枚举方案。

若题目问“DFS 的空间复杂度”，递归调用栈在最坏情况下会包含 $V$ 个顶点，因此辅助空间上界为 $O(V)$。

## 十三、广度优先搜索 BFS

BFS（Breadth-First Search）的核心思想是：

> **从起点开始按“距离层次”向外扩展，先访问离起点近的顶点，再访问更远的顶点。**

BFS 使用**队列**。

### 1. 基本过程

<InlineSvg src="/images/data-structure/data-structure-graph-operation-002.svg" alt="A B C D E F A B C D E F A B C D E F A B C D E F A B C D E F A B C D E F" />

1. 起点入队并标记为已访问；
2. 取出队头顶点 $v$；
3. 枚举 $v$ 的所有邻接点；
4. 对每个尚未访问的邻接点 $u$，立即标记并入队；
5. 队列为空时结束。

```text
function BFS(G, start):
    visited[start] ← true
    enqueue(Q, start)

    while Q is not empty:
        v ← dequeue(Q)
        process(v)

        for each neighbor u of v:
            if not visited[u]:
                visited[u] ← true
                enqueue(Q, u)
```

> **为什么要“入队即标记”？**
>
> 若等到出队时才标记，同一个顶点可能被不同前驱重复发现并多次入队。

### 2. 邻接矩阵实现

```c
void bfs(int start, int vertices) {
    queue q;
    int visited[MAX_VERTICES] = {0};

    q.enqueue(start);
    visited[start] = 1;

    while (q.size() > 0) {
        int currentVertex = q.dequeue();
        printf("%d ", currentVertex);

        for (int i = 0; i < vertices; ++i) {
            if (adjMatrix[currentVertex][i] == 1 && !visited[i]) {
                visited[i] = 1;
                q.enqueue(i);
            }
        }
    }
}
```

时间复杂度：

$$
O(V^2)
$$

### 3. 邻接表实现

```c
void bfs(struct Graph* graph, int start) {
    queue q;
    int visited[MAX_VERTICES] = {0};

    q.enqueue(start);
    visited[start] = 1;

    while (front != rear) {
        int currentVertex = q.dequeue();
        printf("%d ", currentVertex);

        struct Node* temp = graph->adjacencyList[currentVertex];

        while (temp) {
            int adjVertex = temp->data;

            if (!visited[adjVertex]) {
                visited[adjVertex] = 1;
                q.enqueue(adjVertex);
            }

            temp = temp->next;
        }
    }
}
```

时间复杂度：

$$
O(V+E)
$$

### 4. BFS 与无权最短路径

在**无权图**中，从源点 $s$ 执行 BFS：

> 顶点 $v$ 第一次被发现时，对应的路径就是从 $s$ 到 $v$ 的最少边数路径。

可维护：

```text
dist[s] = 0

dist[v] = dist[u] + 1
```

其中 $u$ 是第一次发现 $v$ 的前驱。

原因是 BFS 严格按照距离 $0,1,2,\ldots$ 的层次扩展。若还要恢复具体路径，可同步维护 `parent[v] = u`；从终点沿 `parent` 反向回溯即可得到一条最短路径。

<Callout type="warn" title="BFS 求的是无权最短路，不是任意带权最短路">

当每条边代价都相同（通常视为 1）时，“最少边数”才等价于“最短距离”。若边权不同，即使全部为正，也不能直接用普通 BFS 代替 Dijkstra。

</Callout>

## 十四、DFS 与 BFS 对比

| 项目 | DFS | BFS |
| --- | --- | --- |
| 核心结构 | 栈 / 递归 | 队列 |
| 搜索方式 | 一条路尽量走深 | 按层向外扩展 |
| 邻接表复杂度 | $O(V+E)$ | $O(V+E)$ |
| 邻接矩阵复杂度 | $O(V^2)$ | $O(V^2)$ |
| 无权最短路径 | 不保证 | 可求最少边数路径 |
| 生成结构 | DFS 树/森林 | BFS 树/森林 |

两者都需要：

* `visited[]` 防止重复访问；
* 非连通图时增加外层顶点枚举。

> **空间直觉**
>
> * DFS 额外空间主要来自递归栈/显式栈；
> * BFS 额外空间主要来自队列；
> * 最坏情况下二者都可能达到 $O(V)$。

## 十五、最小生成树 MST

<InlineSvg src="/images/data-structure/data-structure-graph-operation-003.svg" alt="6 5 9 9 9 3 2 2 8 9 9 8 7 4 6 1 3 9 10 20 5" />

> **真题考察**
>
> * 选择题：2012 年第 8 题、2015 年第 6 题、2020 年第 7 题、2023 年第 6 题
> * 解答题：2017 年第 42 题、2018 年第 42 题

最小生成树（Minimum Spanning Tree，MST）讨论的是：

> **连通无向带权图**中，用最小总权值连接全部顶点。

设：

$$
G=(V,E)
$$

若选择边集 $T\subseteq E$，使 $(V,T)$：

* 包含全部顶点；
* 连通；
* 无环；

则 $(V,T)$ 是一棵生成树。

若有 $V$ 个顶点，则任意生成树都恰有：

$$
V-1
$$

条边。

生成树总权值：

$$
w(T)=\sum_{e\in T}w(e)
$$

总权值最小者就是 MST。

从“生成树”本身还能得到两个经常用于判断的等价特征：对含 $V$ 个顶点的无向图，若一个子图**连通且恰有 $V-1$ 条边**，则它一定无环；若**无环且恰有 $V-1$ 条边**，则它一定连通。

### 1. MST 的常见结论

* MST 可能不唯一；
* 即使 MST 不唯一，所有 MST 的总权值相同；
* 若所有边权互不相同，则 MST 一定唯一；
* 反过来，“MST 唯一”并不要求所有边权都不同；
* 连通图的 MST 有 $V-1$ 条边；
* 若图不连通，则不存在覆盖全部顶点的一棵生成树，只能得到最小生成森林。

### 2. 割性质

把顶点集合划分为两个非空部分称为一个**割**。

连接割两侧顶点的边称为横切边。

MST 的核心贪心依据之一是：

> 对任意割，取该割上一条最小权横切边，这条边是**安全边**：至少存在一棵 MST 包含它。

若某个割上的最小权横切边还是**唯一最小**，那么这条边必然出现在每一棵 MST 中。Prim 算法正是不断利用割性质。

### 3. 环性质

若一个环中某条边**严格重于该环中的其他所有边**，则这条边不可能出现在任何 MST 中。

Kruskal“选边但不能成环”的思路可以结合这一性质理解。注意“并列最重”时不能简单断言某一条边一定不能进入 MST。

## 十六、Prim 算法

Prim 的视角是：

> **从一个顶点开始，不断把新的顶点并入当前生成树。**

设当前已进入生成树的顶点集合为 $T$，尚未进入的是 $V-T$。

每一步都选择连接 $T$ 与 $V-T$ 的最小权边。

### 1. 算法过程

1. 任取一个顶点加入 $T$；
2. 在所有“树内—树外”横切边中找最小权边 $(u,v)$；
3. 把该边和树外端点加入生成树；
4. 更新其他树外顶点到当前集合 $T$ 的最小连接代价；
5. 重复，直到全部顶点进入 $T$。

### 2. `lowcost[]` 的含义

朴素 Prim 常维护：

$$
lowcost[v]
$$

表示：

> 当前顶点集合 $T$ 到树外顶点 $v$ 的最小**单边连接代价**。

它与 Dijkstra 的 `dist[v]` 非常容易混淆：

* Prim 的 `lowcost[v]`：树内任意顶点到 $v$ 的最小边权；
* Dijkstra 的 `dist[v]`：源点到 $v$ 的整条路径长度。

当新顶点 $u$ 加入生成树后，对仍在树外的邻接点 $v$ 更新：

$$
lowcost[v]=\min\{lowcost[v],\,w(u,v)\}
$$

如果题目还要求输出具体 MST，应同时维护 `parent[v]`，记录当前使 `lowcost[v]` 取得最小值的树内顶点。

### 3. 正确性直觉

当前 $T$ 与 $V-T$ 构成一个割。

Prim 每次选择这个割上的最小权横切边，因此依据割性质，这条边是安全的。

### 4. 复杂度

邻接矩阵 + 顺序查找最小值的朴素实现：

$$
O(V^2)
$$

所以在经典 408 比较中，Prim 常被认为更适合**稠密图**。

若使用邻接表 + 优先队列，可做到更适合稀疏图的实现。

> **手算技巧**
>
> 每轮只需要盯住两类信息：哪些顶点已经进树、每个树外顶点通过哪条边最便宜地接入当前树。

## 十七、Kruskal 算法

Kruskal 的视角是：

> **不从某个顶点向外长，而是把全部边按权值从小到大尝试加入。**

### 1. 算法过程

<InlineSvg src="/images/data-structure/data-structure-graph-operation-004.svg" alt="PrimDemo_Reversed" />
<InlineSvg src="/images/data-structure/data-structure-graph-operation-005.svg" alt="PrimAlgorithm" />

<InlineSvg src="/images/data-structure/data-structure-graph-operation-007.svg" alt="KruskalAlgorithm" />
<InlineSvg src="/images/data-structure/data-structure-graph-operation-008.svg" alt="a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 2 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 2 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 2 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 2 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 2 a b h i c g f d 4 8 11 8 7 2 1" />

1. 将所有边按权值非递减排序；
2. 初始时每个顶点自成一个连通分量；
3. 依次考察边 $(u,v)$；
4. 若 $u,v$ 属于不同分量，则加入该边；
5. 合并两个分量；
6. 若 $u,v$ 已在同一分量，则加入该边会成环，舍弃；
7. 选中 $V-1$ 条边后结束。

### 2. 为什么使用并查集

Kruskal 的核心判断不是“这条边权值小不小”，而是：

> **加入这条边会不会成环？**

若：

$$
Find(u)=Find(v)
$$

说明两点已经位于同一棵当前生成树中，加入 $(u,v)$ 会形成环，应舍弃。

否则：

$$
Find(u)\ne Find(v)
$$

可以选择该边，并执行：

```text
Union(u, v)
```

因此 Kruskal 的并查集维护的是“**当前已经通过已选边连成的分量**”，不是原图本身的连通分量。

### 3. 复杂度

主要开销来自边排序：

$$
O(E\log E)
$$

并查集若采用按秩合并和路径压缩，操作开销近似常数，因此总体通常写为：

$$
O(E\log E)
$$

所以 Kruskal 常用于**稀疏图**。

### 4. 等权边与多棵 MST

当存在若干相同权值的可选边时，不同的合法选择可能生成不同 MST。

但只要都满足最小总权值，它们仍然都是正确答案。

因此手算时不要把“边集合唯一”误当成“MST 必须唯一”。

## 十八、Prim 与 Kruskal 对比

| 对比 | Prim | Kruskal |
| --- | --- | --- |
| 贪心视角 | 扩张顶点集合 | 按边权从小到大选边 |
| 每轮选择 | 当前割上的最小权边 | 当前最小且不成环的边 |
| 防环方式 | 新边连接树内与树外 | 判断两端是否已连通 |
| 常用辅助结构 | `lowcost[]`、优先队列 | 边排序、并查集 |
| 经典适用场景 | 稠密图 | 稀疏图 |
| 常见复杂度 | $O(V^2)$ | $O(E\log E)$ |

<Callout type="warn" title="Prim、Kruskal、Dijkstra 三者不要混">

* **Prim**：求 MST，比较“当前树怎样用一条边接入新顶点最便宜”；
* **Kruskal**：求 MST，比较“全局当前最小边能否在不成环的前提下加入”；
* **Dijkstra**：求最短路径，比较“源点到哪个未确定顶点的**整条路径**最短”。

Prim 和 Dijkstra 都会维护一个不断扩大的顶点集合，但数组中“最小值”的物理意义完全不同。

</Callout>
