## 十一、图的遍历

> **真题考察**
>
> * 选择题：2012 年第 5 题、2013 年第 8 题、2015 年第 5 题、2016 年第 6 题、2020 年第 6 题

图与树的遍历最大的区别是：

> 图中可能存在环，因此必须记录顶点是否已经访问。

常使用数组：

```c
visited[v]
```

防止：

* 重复访问；
* 在环中无限循环。

## 十二、深度优先搜索 DFS

DFS 的思想可以概括为：

> **能往深处走就继续往深处走，无路可走时再回溯。**

DFS 通常使用：

* 递归；
* 或显式栈。

### 1. 基本过程

1. 访问当前顶点 $v$；
2. 将 $v$ 标记为已访问；
3. 找到一个尚未访问的邻接顶点 $u$；
4. 对 $u$ 继续执行 DFS；
5. 当前分支结束后回溯。

<InlineSvg src="/images/data-structure/data-structure-graph-operation-001.svg" alt={"A B C D E F A B C D E F A B C D E F A B C D E F A B C D E F A B C D E F"} />

伪代码：

```text
function DFS(G, v, visited):
    visited[v] ← true
    process(v)

    for each neighbor u of v:
        if not visited[u]:
            DFS(G, u, visited)
```

### 2. 邻接矩阵实现

```c
int visited[MAX_VERTICES];

void dfs(int start) {
    visited[start] = 1;
    printf("%d ", start);

    for (int i = 0; i < vertices; ++i) {
        if (adjMatrix[start][i] == 1 && !visited[i]) {
            dfs(i);
        }
    }
}
```

邻接矩阵需要扫描当前顶点对应的整行，因此每个顶点寻找邻接点需要 $O(V)$。

整个遍历的时间复杂度为

$$
O(V^2)
$$

### 3. 邻接表实现

```c
int visited[MAX_VERTICES];

void dfs(struct Graph* graph, int start) {
    visited[start] = 1;
    printf("%d ", start);

    struct Node* temp = graph->adjacencyList[start];

    while (temp) {
        int adjVertex = temp->data;

        if (!visited[adjVertex]) {
            dfs(graph, adjVertex);
        }

        temp = temp->next;
    }
}
```

每个顶点和每条边只需要处理常数次，因此时间复杂度为

$$
O(V+E)
$$

### 4. 非连通图

如果图不连通，从一个顶点出发只能遍历其所在连通分量。

完整遍历需要：

```c
for (int v = 0; v < vertices; ++v) {
    if (!visited[v]) {
        dfs(v);
    }
}
```

每执行一次新的 DFS，就相当于发现了一个新的连通分量。

## 十三、广度优先搜索 BFS

BFS 的思想可以概括为：

> **先访问距离起点 1 条边的顶点，再访问距离 2 条边的顶点，逐层向外扩展。**

BFS 使用**队列**实现。

#### 1. 基本过程

1. 起点入队并标记为已访问；
2. 取出队头顶点；
3. 访问其所有未访问邻接点；
4. 将这些邻接点标记为已访问并入队；
5. 队列为空时结束。

<InlineSvg src="/images/data-structure/data-structure-graph-operation-002.svg" alt={"A B C D E F A B C D E F A B C D E F A B C D E F A B C D E F A B C D E F"} />

伪代码：

```text
function BFS(G, start):
    visited[start] ← true
    enqueue(Q, start)

    while Q is not empty:
        v ← dequeue(Q)
        process(v)

        for each neighbor u of v:
            if not visited[u]:
                visited[u] ← true
                enqueue(Q, u)
```

> **易错点**
>
> BFS 一般在**入队时**立即标记已访问，而不是出队时才标记，否则一个顶点可能被重复入队。

#### 2. 邻接矩阵实现

```c
void bfs(int start, int vertices) {
    queue q;
    int visited[MAX_VERTICES] = {0};

    q.enqueue(start);
    visited[start] = 1;

    while (q.size() > 0) {
        int currentVertex = q.dequeue();

        printf("%d ", currentVertex);

        for (int i = 0; i < vertices; ++i) {
            if (adjMatrix[currentVertex][i] == 1 && !visited[i]) {
                q.enqueue(i);
                visited[i] = 1;
            }
        }
    }
}
```

时间复杂度为

$$
O(V^2)
$$

#### 3. 邻接表实现

```c
void bfs(struct Graph* graph, int start) {
    queue q;
    int visited[MAX_VERTICES] = {0};

    q.enqueue(start);
    visited[start] = 1;

    while (front != rear) {
        int currentVertex = q.dequeue();

        printf("%d ", currentVertex);

        struct Node* temp = graph->adjacencyList[currentVertex];

        while (temp) {
            int adjVertex = temp->data;

            if (!visited[adjVertex]) {
                q.enqueue(adjVertex);
                visited[adjVertex] = 1;
            }

            temp = temp->next;
        }
    }
}
```

时间复杂度为

$$
O(V+E)
$$

## 十四、DFS 与 BFS 对比

| 项目      | DFS        | BFS        |
| ------- | ---------- | ---------- |
| 核心数据结构  | 栈 / 递归     | 队列         |
| 遍历特点    | 优先向深处搜索    | 按层搜索       |
| 邻接表复杂度  | $O(V+E)$ | $O(V+E)$ |
| 邻接矩阵复杂度 | $O(V^2)$ | $O(V^2)$ |
| 无权图最短路径 | 不保证        | 可以求最少边数路径  |
| 生成树     | 深度优先生成树    | 广度优先生成树    |

对于无权图，BFS 从源点出发第一次访问到顶点 $v$ 时，对应路径就是源点到 $v$ 的最少边数路径。

## 十五、最小生成树 MST

> **真题考察**
>
> * 选择题：2012 年第 8 题、2015 年第 6 题、2020 年第 7 题、2023 年第 6 题
> * 解答题：2017 年第 42 题、2018 年第 42 题

最小生成树适用于**连通无向带权图**。

<InlineSvg src="/images/data-structure/data-structure-graph-operation-003.svg" alt={"6 5 9 9 9 3 2 2 8 9 9 8 7 4 6 1 3 9 10 20 5"} />

设

$$
G=(V,E)
$$

若选取边集

$$
T\subseteq E
$$

使得子图 $(V,T)$：

* 包含全部顶点；
* 连通；
* 无环；

则它是一棵生成树。

有 $V$ 个顶点的生成树一定有

$$
V-1
$$

条边。

生成树权值为

$$
w(T)=\sum_{(u,v)\in T}w(u,v)
$$

权值最小的生成树称为**最小生成树**。

> **注意**
>
> 最小生成树可能不唯一，但所有最小生成树的总权值一定相同。

## 十六、Prim 算法

Prim 的思想是：

> **不断扩大已经进入生成树的顶点集合。**

假设已经加入生成树的顶点集合为 $T$，其余顶点为

$$
V-T
$$

每一步从所有一端位于 $T$、另一端位于 $V-T$ 的边中，选取权值最小的一条。

这些边称为横切边。

#### 1. 算法过程

1. 任取一个顶点加入集合 $T$；
2. 找出连接 $T$ 与 $V-T$ 的最小权边；
3. 将该边和新的顶点加入生成树；
4. 重复，直到包含全部顶点。

<InlineSvg src="/images/data-structure/data-structure-graph-operation-004.svg" alt={"PrimDemo_Reversed"} />

Prim 的正确性基于最小生成树的**割性质**：

> 对任意割，其最小权横切边一定存在于某棵最小生成树中。

<InlineSvg src="/images/data-structure/data-structure-graph-operation-005.svg" alt={"PrimAlgorithm"} />

以下图为例，从顶点 `a` 开始执行 Prim，可以逐步选出 `ab`、`bc`、`ci`、`cf`、`fg`、`gh`、`cd`：

<InlineSvg src="/images/data-structure/data-structure-graph-operation-006.svg" alt={"a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 "} />

#### 2. Prim 的理解重点

Prim 每次比较的不是“全图最小边”，而是：

> **当前生成树与外部顶点之间的最小边。**

即比较

$$
u\in T,\qquad v\in V-T
$$

的所有边。

#### 3. 复杂度

邻接矩阵的朴素 Prim 算法：

$$
O(V^2)
$$

因此通常更适合**稠密图**。

若使用邻接表和优先队列，可进一步优化。

## 十七、Kruskal 算法

Kruskal 的思想是：

> **从全图权值最小的边开始选，只要不会形成环就加入。**

#### 1. 算法过程

1. 将所有边按权值从小到大排序；
2. 初始化生成森林，每个顶点自成一个连通分量；
3. 按顺序考察每条边；
4. 若边的两个端点当前属于不同连通分量，则加入；
5. 合并这两个连通分量；
6. 当选中 $V-1$ 条边时结束。

<InlineSvg src="/images/data-structure/data-structure-graph-operation-007.svg" alt={"KruskalAlgorithm"} />

在同一示例中，Kruskal 可以依次选择 `hg`、`ic`、`gf`、`ab`、`cf`、`cd`、`ah`：

<InlineSvg src="/images/data-structure/data-structure-graph-operation-008.svg" alt={"a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 2 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 2 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 2 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 2 a b h i c g f d 4 8 11 8 7 2 1 6 7 4 14 2 a b h i c g f d 4 8 11 8 7 2 1"} />

判断是否形成环通常使用**并查集**：

* 两个端点属于同一集合 → 加入后产生环 → 舍弃；
* 属于不同集合 → 可以加入，并执行合并。

#### 2. 复杂度

主要开销来自对边进行排序：

$$
O(E\log E)
$$

因此 Kruskal 通常更适合**稀疏图**。

## 十八、Prim 与 Kruskal 对比

| 对比     | Prim             | Kruskal        |
| ------ | ---------------- | -------------- |
| 贪心对象   | 顶点集合逐步扩展         | 边逐步加入          |
| 每次选择   | 当前割上的最小边         | 全局当前最小合法边      |
| 防止成环方式 | 新边必须连接树内与树外      | 判断两端是否属于同一连通分量 |
| 常用辅助结构 | `lowcost[]`、优先队列 | 排序、并查集         |
| 更适合    | 稠密图              | 稀疏图            |
| 朴素复杂度  | $O(V^2)$       | $O(E\log E)$ |

> **易错点**
>
> Prim 和 Dijkstra 的执行形式很像，但目标完全不同：
>
> * Prim 比较的是“连接树内外的**一条边权值**”；
> * Dijkstra 比较的是“源点到某顶点的**完整路径长度**”。
