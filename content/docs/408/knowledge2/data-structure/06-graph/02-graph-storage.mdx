图的存储结构决定了“找邻接点、判断是否有边、求度、遍历图”等操作的代价。408 不只考结构长什么样，更常考**某种存储方式下某个操作的复杂度**。

> **真题标签｜2013 第 7 题、2016 第 7 题、2024 第 4 题、2026 第 6 题；2011 第 41 题、2015 第 42 题、2018 第 42 题、2021 第 41 题、2023 第 41 题、2024 第 41 题：图的存储与基本操作**
>
> 重点掌握邻接矩阵的行列含义、邻接表中无向边的“双份存储”、邻接多重表与十字链表的使用场景。

## 6.2.1 四种核心存储结构

| 存储结构 | 典型适用对象 | 边的保存方式 | 核心优势 |
| --- | --- | --- | --- |
| 邻接矩阵 | 稠密图 | 二维矩阵元素 | 判断两点是否直接相邻为 $O(1)$ |
| 邻接表 | 稀疏图 | 每个顶点维护邻接链 | 枚举邻接点高效 |
| 邻接多重表 | 无向图 | 每条无向边只建一个边结点 | 删除/修改边方便，避免重复保存 |
| 十字链表 | 有向图 | 每条弧同时挂入出边链和入边链 | 同时查入边、出边方便 |

## 6.2.2 邻接矩阵

设图有 $n$ 个顶点，建立 $n\times n$ 的矩阵 $A$。

对于无权图：

$$
A[i][j]=
\begin{cases}
1,& v_i\text{ 到 }v_j\text{ 有边}\
0,& \text{否则}
\end{cases}
$$

### 无向图

有：

$$
A[i][j]=A[j][i]
$$

因此矩阵关于主对角线对称；若不含自环，则主对角线全为 0。

### 有向图

若存在：

$$
v_i\rightarrow v_j
$$

则：

$$
A[i][j]=1
$$

**行表示从谁出发，列表示到谁结束。**

所以对有向图：

- 第 $i$ 行非零元素个数 = $v_i$ 的出度；
- 第 $i$ 列非零元素个数 = $v_i$ 的入度。

### 带权图

带权图可令：

$$
A[i][j]=
\begin{cases}
w(i,j),& (i,j)\in E\\
\infty,& (i,j)\notin E
\end{cases}
$$

最短路径算法中通常还令：

$$
A[i][i]=0
$$

> **易错点｜“无边”不能总用 0**
>
> 若边权本身可能为 0，则用 0 表示“不存在边”会产生歧义。最短路径问题通常用 `INF` 表示不可达。

### 复杂度

| 操作 | 邻接矩阵复杂度 |
| --- | ---: |
| 空间 | $O(V^2)$ |
| 判断 $u,v$ 是否直接相邻 | $O(1)$ |
| 枚举 $u$ 的所有邻接点 | $O(V)$ |
| 求无向图某顶点的度 | $O(V)$ |
| 求有向图某顶点入度/出度 | $O(V)$ |

因此邻接矩阵通常更适合**稠密图**。

## 6.2.3 邻接表

邻接表为每个顶点维护一条邻接链表。

典型定义：

```c
#define MAXV 100

typedef struct ArcNode {
    int adjvex;
    int weight;
    struct ArcNode *next;
} ArcNode;

typedef struct {
    int data;
    ArcNode *first;
} VNode;

typedef struct {
    VNode vertices[MAXV];
    int vexnum, arcnum;
} ALGraph;
```

### 有向图

弧：

$$
u\rightarrow v
$$

通常只在 $u$ 的出边链表中保存一个指向 $v$ 的边结点。

因此：

- $u$ 的链表长度可以直接得到出度；
- 求某个顶点的入度需要检查所有顶点的出边链表。

若要从普通邻接表求某点入度，最坏情况下要扫描：

- 顶点表：$O(V)$；
- 全部边结点：$O(E)$。

所以标准复杂度写为：

$$
O(V+E)
$$

> **真题提示｜2026 第 6 题**
>
> $O(V+E)$ 与 $O(\max(V,E))$ 在渐进意义上等价，但复习和书写算法复杂度时优先写标准形式 $O(V+E)$。

### 无向图

一条无向边：

$$
\{u,v\}
$$

通常需要保存两个边表结点：

- $u$ 的邻接表中存 $v$；
- $v$ 的邻接表中存 $u$。

因此虽然边结点数约为 $2E$，空间复杂度仍为：

$$
O(V+E)
$$

### 邻接表操作复杂度

| 操作 | 复杂度 |
| --- | ---: |
| 空间 | $O(V+E)$ |
| 枚举 $u$ 的邻接点 | $O(d(u))$ |
| 判断 $u,v$ 是否相邻 | 一般 $O(d(u))$ |
| 无向图求 $u$ 的度 | $O(d(u))$，链长即度数 |
| 有向图求 $u$ 的出度 | $O(d^+(u))$ |
| 有向图求 $u$ 的入度 | 一般 $O(V+E)$ |

邻接表通常更适合**稀疏图**。

## 6.2.4 邻接矩阵与邻接表怎么选

| 对比 | 邻接矩阵 | 邻接表 |
| --- | --- | --- |
| 空间 | $O(V^2)$ | $O(V+E)$ |
| 判定一条边是否存在 | 快，$O(1)$ | 需查邻接链 |
| 枚举邻接点 | 需扫描整行 | 只扫实际邻接点 |
| 稠密图 | 更合适 | 边结点很多 |
| 稀疏图 | 浪费空间 | 更合适 |
| 有向图求出度 | 扫描一行 | 链表长度 |
| 有向图求入度 | 扫描一列 | 普通邻接表不方便 |

> **遍历序列不只由图本身决定**
>
> 对同一张图，若邻接表中邻接点保存顺序不同，DFS/BFS 序列也可能不同。手工模拟时必须严格服从题目给出的矩阵列顺序、邻接表链结点顺序或“按编号从小到大”等规则。

## 6.2.5 邻接多重表

邻接多重表主要用于**无向图**。

普通邻接表会把一条无向边保存两次。邻接多重表让每条边只建立一个边结点，同时把这个边结点挂入两个端点各自的关联边链中。

边结点常见字段：

```text
ivex   一个端点
jvex   另一个端点
ilink  沿 ivex 顶点继续找下一条关联边
jlink  沿 jvex 顶点继续找下一条关联边
mark   可选访问标志
info   可选权值等信息
```

最关键的是：

> `ilink` 与 `jlink` 并不是“固定方向的下一条边”，而是分别沿当前边的两个端点继续连接各自的下一条关联边。

优势：

- 每条无向边只存一次；
- 删除一条边时不必同步修改两份边结点；
- 适合频繁进行边级别的增删改操作。

## 6.2.6 十字链表

十字链表主要用于**有向图**，相当于把邻接表与逆邻接表结合起来。

顶点结点常保存：

- `firstout`：第一条出边；
- `firstin`：第一条入边。

弧结点常保存：

- `tailvex`：弧尾；
- `headvex`：弧头；
- `tlink`：下一条具有相同弧尾的弧；
- `hlink`：下一条具有相同弧头的弧。

因此同一个弧结点同时属于：

- 弧尾的出边链；
- 弧头的入边链。

## 6.2.7 存储结构记忆口诀

> **存储结构速记**
>
> - 稠密图、频繁判边 → 邻接矩阵；
> - 稀疏图、频繁枚举邻接点 → 邻接表；
> - 无向图希望“一条边只存一次” → 邻接多重表；
> - 有向图希望同时高效查入边和出边 → 十字链表。
