顺序表通过“物理相邻”直接体现逻辑次序；链表则把逻辑关系显式写进结点的链接域。

单链表的核心认识只有一句：

> **结点地址可以分散，但每个结点通过 `next` 指向自己的直接后继。**

因此，链表不需要为中间插入腾出连续空间，但也失去了按下标直接定位的能力。

---

## 2.2.1 单链表结点与链式存储

典型结点定义：

```c
typedef struct Node {
    ElementType data;
    struct Node *next;
} Node;
```

每个结点由两部分组成：

```text
[data | next]
```

其中：

- `data`：数据域；
- `next`：指针域，保存直接后继结点的地址。

一个普通单链表可表示为：

```text
[a1 | •] → [a2 | •] → [a3 | NULL]
```

链式存储的主要特点：

- 结点在物理地址上不必连续；
- 逻辑次序由 `next` 决定；
- 不能根据逻辑位置直接计算某个结点的地址；
- 已经取得相关结点指针时，局部插入、删除通常只需改少量指针。

> **易错点｜链表不等于“堆上对象”**
>
> 链表结点经常通过 `malloc` / `new` 动态申请，但链式结构的定义条件是**通过链接信息表示逻辑关系**，并不是“结点必须在堆上”。静态数组也可以模拟链表。

## 2.2.2 头指针、头结点与首元结点

这三个概念必须严格区分。

采用带头结点的单链表：

```text
head
 ↓
[头结点] → [a1] → [a2] → ... → NULL
            ↑
          首元结点
```

### 头指针

`head` 是保存链表起始地址的指针变量。

### 头结点

人为放在第一个数据结点之前的辅助结点。通常不属于线性表的有效数据元素。

### 首元结点

真正保存 $a_1$ 的第一个数据结点。

因此带头结点时：

```c
head          // 指向头结点
head->next    // 指向首元结点
```

### 为什么常引入头结点

头结点最大的价值不是“多存一个结点”，而是**统一边界处理**：

- 空表与非空表更容易统一；
- 在首元结点之前插入，不必单独修改头指针；
- 删除首元结点可与删除其他结点统一为“删除某前驱的后继”。

> **高频辨析**
>
> 头结点是可选的辅助结点；头指针是访问链表的入口；首元结点才保存线性表的第一个有效元素。

## 2.2.3 初始化与判空

创建带头结点的空单链表：

```c
Node *InitList(void) {
    Node *head = (Node *)malloc(sizeof(Node));
    if (head == NULL)
        return NULL;

    head->next = NULL;
    return head;
}
```

空表：

```text
head → [头结点] → NULL
```

判空：

```c
bool Empty(Node *head) {
    return head->next == NULL;
}
```

注意：

```c
head == NULL
```

表示头指针本身无效；而对于已初始化的带头结点链表：

```c
head->next == NULL
```

才表示线性表为空。

## 2.2.4 头插法与尾插法建立链表

### 头插法

每次把新结点插到头结点之后：

```c
bool PushFront(Node *head, ElementType e) {
    Node *s = (Node *)malloc(sizeof(Node));
    if (s == NULL)
        return false;

    s->data = e;
    s->next = head->next;
    head->next = s;
    return true;
}
```

若输入顺序为：

```text
1 2 3 4
```

连续头插后的链表为：

```text
4 → 3 → 2 → 1
```

因此头插法建立链表通常会**逆转输入次序**。

每次插入只修改常数个指针：

$$
O(1)
$$

### 尾插法

若希望保持输入次序，应维护尾指针：

```c
Node *BuildByTail(void) {
    Node *head = (Node *)malloc(sizeof(Node));
    if (head == NULL)
        return NULL;

    head->next = NULL;
    Node *tail = head;

    ElementType x;
    while (ReadElement(&x)) {
        Node *s = (Node *)malloc(sizeof(Node));
        if (s == NULL)
            break;

        s->data = x;
        s->next = NULL;

        tail->next = s;
        tail = s;
    }

    return head;
}
```

维护 `tail` 后，每次尾插为：

$$
O(1)
$$

若每次都从头寻找尾结点，单次尾插为 $O(n)$；连续建立 $n$ 个结点可能退化为 $O(n^2)$。

## 2.2.5 按位查找：为什么链表不是随机存取

要取得第 `pos` 个数据结点，只能从首元结点沿 `next` 逐步前进：

```c
Node *GetElem(Node *head, int pos) {
    if (pos < 1)
        return NULL;

    Node *p = head->next;
    int i = 1;

    while (p != NULL && i < pos) {
        p = p->next;
        ++i;
    }

    return p;
}
```

最坏情况下访问第 $n$ 个结点需要经过前面 $n-1$ 个结点，因此：

$$
T(n)=O(n)
$$

这正是链表与顺序表最根本的性能差异之一：

```text
顺序表：首地址 + 下标 → 直接定位
单链表：只能沿 next 一步一步走
```

## 2.2.6 按值查找

```c
Node *LocateElem(Node *head, ElementType e) {
    Node *p = head->next;

    while (p != NULL) {
        if (p->data == e)
            return p;
        p = p->next;
    }

    return NULL;
}
```

普通单链表按值查找同样需要线性扫描：

$$
O(n)
$$

因此“链式存储插入删除快”并不意味着“链表查找也快”。

---

## 2.2.7 已知结点后的插入：两条语句的顺序必须正确

已知 `p` 指向已有结点，要把新结点 `s` 插入 `p` 之后：

```text
插入前：p → q
插入后：p → s → q
```

核心代码：

```c
s->next = p->next;
p->next = s;
```

其逻辑是：

1. 先让 `s` 记住 `p` 原来的后继；
2. 再让 `p` 改为指向 `s`。

> **易错点｜不能先丢失旧后继**
>
> 指针修改题最重要的检查规则是：**即将被覆盖的链接是否已经保存？**
>
> 若先错误地覆盖 `p->next`，又没有别的变量保存旧后继地址，就可能导致后半段链表丢失。

已知 `p` 后的插入只改常数个指针：

$$
O(1)
$$

## 2.2.8 按逻辑位置插入：真正的总复杂度

若要“在第 `pos` 个位置插入”，带头结点时应先找到第 `pos-1` 个结点作为前驱。

```c
bool ListInsert(Node *head, int pos, ElementType e) {
    if (pos < 1)
        return false;

    Node *p = head;
    int i = 0;

    while (p != NULL && i < pos - 1) {
        p = p->next;
        ++i;
    }

    if (p == NULL)
        return false;

    Node *s = (Node *)malloc(sizeof(Node));
    if (s == NULL)
        return false;

    s->data = e;
    s->next = p->next;
    p->next = s;
    return true;
}
```

这里必须把复杂度拆开：

```text
寻找前驱：O(n)
真正插入：O(1)
总体：    O(n)
```

> **408 高频结论**
>
> “链表插入是 $O(1)$”必须带前提：**相关结点或前驱结点已经得到**。只给出逻辑位置时，通常还要遍历链表。

## 2.2.9 删除后继结点

已知 `p`，删除其直接后继 `q`：

```text
删除前：p → q → r
删除后：p ─────→ r
```

```c
bool DeleteAfter(Node *p, ElementType *e) {
    Node *q = p->next;
    if (q == NULL)
        return false;

    if (e != NULL)
        *e = q->data;

    p->next = q->next;
    free(q);
    return true;
}
```

已知前驱 `p` 后，删除为：

$$
O(1)
$$

---

## 2.2.10 按位置删除

删除第 `pos` 个数据结点，需要先找到第 `pos-1` 个结点：

```c
bool ListDelete(Node *head, int pos, ElementType *e) {
    if (pos < 1)
        return false;

    Node *p = head;
    int i = 0;

    while (p->next != NULL && i < pos - 1) {
        p = p->next;
        ++i;
    }

    if (p->next == NULL)
        return false;

    Node *q = p->next;

    if (e != NULL)
        *e = q->data;

    p->next = q->next;
    free(q);
    return true;
}
```

复杂度仍然是：

$$
O(n)
$$

因为主要时间花在寻找前驱结点。

## 2.2.11 清空与销毁：释放前必须保存后继

清空链表时，需要逐结点释放：

```c
void ClearList(Node *head) {
    Node *p = head->next;
    head->next = NULL;

    while (p != NULL) {
        Node *next = p->next;
        free(p);
        p = next;
    }
}
```

关键顺序：

```text
先保存 p->next
→ 再 free(p)
→ 再移动到保存好的 next
```

错误写法：

```c
free(p);
p = p->next;   // 错：释放后继续解引用 p
```

因为 `free(p)` 之后，原结点空间已经不能继续合法访问。

若还要销毁头结点：

```c
void DestroyList(Node **head) {
    if (head == NULL || *head == NULL)
        return;

    ClearList(*head);
    free(*head);
    *head = NULL;
}
```

## 2.2.12 单链表操作复杂度总览

| 操作 | 条件 | 时间复杂度 |
| --- | --- | ---: |
| 按位访问 | 只知道位置 | $O(n)$ |
| 按值查找 | 普通无序链表 | $O(n)$ |
| 头插 | 已有头结点 | $O(1)$ |
| 尾插 | 维护尾指针 | $O(1)$ |
| 尾插 | 不维护尾指针 | $O(n)$ |
| 在 `p` 后插入 | 已知 `p` | $O(1)$ |
| 按位置插入 | 需要寻找前驱 | $O(n)$ |
| 删除 `p` 的后继 | 已知 `p` | $O(1)$ |
| 按位置删除 | 需要寻找前驱 | $O(n)$ |
| 清空链表 | 释放全部数据结点 | $O(n)$ |

> **本节结论**
>
> 单链表用“**显式指针链接**”换取灵活的局部结构修改；代价是不能随机访问，并且每个结点都需要额外保存链接信息。
