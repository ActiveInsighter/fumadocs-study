学完顺序表和各种链表后，真正需要建立的是一套统一的分析框架：

> **题目给了什么定位信息？需要先找什么？真正修改数据结构时要改什么？最终复杂度由哪一步主导？**

## 17. 顺序表与链表综合比较

### 17.1 核心对比

| 比较项 | 顺序表 | 单链表 |
| --- | --- | --- |
| 物理存储 | 连续 | 不要求连续 |
| 逻辑关系表示 | 主要由存储位置体现 | 由 `next` 链接体现 |
| 按位访问 | $O(1)$ | $O(n)$ |
| 按值查找 | $O(n)$ | $O(n)$ |
| 已知相关结点后的插入 | 仍可能移动元素 | 通常 $O(1)$ |
| 已知前驱后的删除 | 仍可能移动元素 | $O(1)$ |
| 按逻辑位置插入 | $O(n)$ | $O(n)$ |
| 按逻辑位置删除 | $O(n)$ | $O(n)$ |
| 空间局部性 | 通常较好 | 通常较差 |
| 每元素链接开销 | 无 | 有指针域 |
| 容量变化 | 可能扩容并搬移 | 增删结点较灵活 |
| 典型空间浪费 | 预留容量 | 指针域、分配开销 |

### 17.2 复杂度为什么会不同

顺序表与链表的差异可以拆成两个问题：

```text
如何找到目标位置？
        +
找到后怎样修改结构？
```

例如“在第 $i$ 个位置插入”：

- 顺序表：位置可直接计算为 $O(1)$，但要移动后续元素，整体 $O(n)$；
- 单链表：修改链接本身是 $O(1)$，但要先找第 $i-1$ 个结点，整体 $O(n)$。

因此，看到相同的最终复杂度时，也要理解两种结构的**瓶颈来源不同**。

### 17.3 如何选择结构

通常可按访问模式判断：

- **大量随机访问**：顺序表通常更合适；
- **频繁在已知结点附近插入、删除**：链表通常更方便；
- **规模固定、结构简单、强调缓存局部性**：顺序表更占优势；
- **规模变化明显且难以预估**：链表在容量管理上更灵活。

实际运行性能还受到缓存、内存分配、数据大小等因素影响，不能只凭渐进复杂度机械判断。

<Callout type="info" title="复杂度判断的关键前提">
看到“链表插入 / 删除是 $O(1)$”时，必须检查题目是否已经给出目标结点或前驱结点。若还要从表头寻找逻辑位置，总复杂度通常仍为 $O(n)$。
</Callout>

## 18. 408 高频易错点

### 18.1 “链表插入、删除一定是 $O(1)$”——错误

例如：

> 在单链表的第 $i$ 个位置插入元素。

必须先找到第 $i-1$ 个结点，因此：

$$
O(n)+O(1)=O(n)
$$

### 18.2 “顺序表随机访问 $O(1)$，所以查值也是 $O(1)$”——错误

- 已知位置求元素：$O(1)$；
- 已知值找位置：普通顺序表通常 $O(n)$。

### 18.3 头结点不等于首元结点

```text
head -> [头结点] -> [a1] -> [a2] -> ...
```

因此：

```c
head->next
```

才是首元结点。

### 18.4 指针覆盖前必须保留仍需使用的旧链接

正确：

```c
s->next = p->next;
p->next = s;
```

核心原则：

> **覆盖一个指针之前，先判断旧地址是否还需要继续使用。**

### 18.5 释放结点后不能再通过它访问后继

正确：

```c
q = p->next;
free(p);
p = q;
```

错误：

```c
free(p);
p = p->next;
```

后者读取了已经释放对象中的内容。

### 18.6 循环链表不能机械使用 `NULL` 作为遍历终点

普通单链表常见：

```c
while (p != NULL)
```

带头结点循环单链表通常判断：

```c
p != head
```

具体终止条件必须与题目定义的循环结构一致。

### 18.7 顺序表 / 链表与栈区 / 堆区不是定义关系

不能把二者定义成：

```text
顺序表一定在栈上
链表一定在堆上
```

真正的区别是：

```text
顺序表：数据元素连续存储
链表：通过链接信息表达逻辑次序
```

### 18.8 双向链表与单链表的“已知当前结点删除”不同

双向链表中当前结点 `p` 自带 `prev`，因此在边界条件处理正确时可直接修改：

```c
p->prev->next = p->next;
p->next->prev = p->prev;
```

单链表只给出 `p` 时通常无法直接得到其前驱。

### 18.9 逻辑位置、结点地址与前驱结点不能混为一谈

题目给出的定位信息不同，复杂度可能完全不同：

| 已知信息 | 单链表常见代价 |
| --- | --- |
| 第 $i$ 个逻辑位置 | 通常先遍历，$O(n)$ |
| 当前结点 `p` | 可直接访问后继 |
| 当前结点的前驱 `pre` | 插入 / 删除后继通常 $O(1)$ |
| 尾指针 `tail` | 尾部相关操作可能显著加速 |

## 19. 链表算法设计高频模型

链表是 408 算法设计题的重要载体。题目经常要求：

- 时间复杂度 $O(n)$；
- 辅助空间复杂度 $O(1)$；
- 不允许把所有结点地址存入数组；
- 必须在原链表上修改链接。

优先考虑以下工具：

```text
快慢指针
长度对齐
原地逆置
头插 / 尾插
拆分 + 逆置 + 交叉合并
值域标记
```

### 19.1 单链表原地逆置

原链表：

```text
head -> a1 -> a2 -> a3 -> NULL
```

逆置后：

```text
head -> a3 -> a2 -> a1 -> NULL
```

迭代实现：

```c
void Reverse(Node *head) {
    Node *prev = NULL;
    Node *p = head->next;

    while (p != NULL) {
        Node *next = p->next; // 先保存后继
        p->next = prev;       // 当前链接反向
        prev = p;             // prev 前进
        p = next;             // p 前进
    }

    head->next = prev;
}
```

复杂度：

$$
T(n)=O(n),\qquad S(n)=O(1)
$$

记忆主线：

```text
保存后继 -> 反转当前指针 -> 两个工作指针前进
```

### 19.2 查找倒数第 $k$ 个结点

使用快慢双指针，让两者保持固定距离：

1. `fast` 与 `slow` 都从首元结点出发；
2. `fast` 先走 $k$ 步；
3. 若不足 $k$ 步便遇到 `NULL`，说明 $k$ 越界；
4. 两指针同步前进；
5. `fast == NULL` 时，`slow` 指向倒数第 $k$ 个结点。

```c
Node *FindKthFromEnd(Node *head, int k) {
    if (head == NULL || k <= 0) return NULL;

    Node *fast = head->next;
    Node *slow = head->next;

    for (int i = 0; i < k; ++i) {
        if (fast == NULL) return NULL;
        fast = fast->next;
    }

    while (fast != NULL) {
        fast = fast->next;
        slow = slow->next;
    }

    return slow;
}
```

复杂度：

$$
T(n)=O(n),\qquad S(n)=O(1)
$$

> **真题标签**
>
> 2009 年第 42 题是经典的“倒数第 $k$ 个结点”问题，核心就是一次扫描中的双指针间距控制。

### 19.3 两个无环单链表的第一个公共结点

若两个无环单链表相交，从第一个公共结点开始，后续结点必然全部共享：

```text
A: a1 -> a2 ------\
                   -> c1 -> c2 -> NULL
B: b1 -> b2 -> b3 /
```

之所以不能“相交后再分叉”，是因为单链表中的一个结点只有一个 `next`。

**长度对齐法：**

1. 求两个链表长度 $m,n$；
2. 长链先走 $|m-n|$ 步；
3. 两指针同步前进；
4. 第一次满足 `pa == pb` 的结点就是第一个公共结点。

注意比较的是**结点地址**，不是数据域是否相等。

复杂度：

$$
T(m,n)=O(m+n),\qquad S(m,n)=O(1)
$$

> **真题标签**
>
> 2012 年第 42 题考查两个单链表共享后缀 / 寻找公共结点。

### 19.4 两个有序链表合并

若两个链表本身已经有序，可使用双指针逐步取出较小（或较大）结点，不需要额外复制数据。

以两个升序链表合并为升序链表为例：

```text
pa 指向 A 当前结点
pb 指向 B 当前结点
       ↓
比较 pa->data 与 pb->data
       ↓
取较小结点接到结果链表尾部
       ↓
对应指针前进
```

两个指针都只单向前进，因此：

$$
T(m,n)=O(m+n)
$$

若要求“两个升序链表合并成降序链表”，可以在比较过程中把选出的较小结点不断**头插**到结果链表，从而在一次扫描中完成逆序组织。

### 19.5 绝对值去重：用值域换时间

若链表中数据的绝对值范围较小，可以用辅助标记数组记录某个绝对值是否出现。

```text
扫描链表
  ↓
取 abs(data)
  ↓
未出现：标记并保留
已出现：删除当前结点
```

若值域上界为 $M$：

$$
T(n)=O(n),\qquad S(M)=O(M)
$$

> **真题标签**
>
> 2015 年第 41 题考查链表按绝对值去重，典型思路是使用辅助标记结构换取线性时间。

### 19.6 链表重排：拆分 + 逆置 + 交叉合并

原线性表：

$$
L=(a_1,a_2,\ldots,a_n)
$$

目标：

$$
L'=(a_1,a_n,a_2,a_{n-1},a_3,a_{n-2},\ldots)
$$

高效做法：

```text
① 快慢指针找到中点
② 将后半段断开
③ 原地逆置后半段
④ 前半段与逆置后的后半段交叉合并
```

每一阶段都只需要线性扫描，且只使用常数个指针：

$$
T(n)=O(n),\qquad S(n)=O(1)
$$

> **真题标签**
>
> 2019 年第 41 题是这一模型的代表题。若每次都从头寻找“最后一个结点”，整体会退化为 $O(n^2)$；先逆置后半段可将总时间降为 $O(n)$。

## 20. 本章复杂度速查与复习主线

### 20.1 复杂度速查

| 结构 | 操作 | 时间复杂度 |
| --- | --- | --- |
| 顺序表 | 按位访问 | $O(1)$ |
| 顺序表 | 按值查找 | $O(n)$ |
| 顺序表 | 一般位置插入 | $O(n)$ |
| 顺序表 | 一般位置删除 | $O(n)$ |
| 单链表 | 按位访问 | $O(n)$ |
| 单链表 | 按值查找 | $O(n)$ |
| 单链表 | 已知前驱后插入 | $O(1)$ |
| 单链表 | 已知前驱后删除 | $O(1)$ |
| 单链表 | 按位置插入 | $O(n)$ |
| 单链表 | 按位置删除 | $O(n)$ |
| 单链表 | 原地逆置 | $O(n)$ |
| 单链表 | 查倒数第 $k$ 个结点 | $O(n)$ |
| 双向链表 | 已知当前结点后删除 | $O(1)$ |

### 20.2 结构总览

```text
线性表
|
|-- 顺序存储：顺序表
|   |-- 连续地址
|   |-- 随机访问 O(1)
|   |-- 插入通常需要后移
|   `-- 删除通常需要前移
|
`-- 链式存储：链表
    |-- 单链表
    |   |-- 头结点
    |   |-- 插入 / 删除
    |   `-- 查找 / 遍历
    |
    |-- 双向链表
    |   |-- prev
    |   `-- next
    |
    |-- 循环链表
    |   `-- 首尾形成环
    |
    `-- 静态链表
        `-- 数组 + 游标
```

### 20.3 做题时固定问自己五个问题

1. **题目给的是逻辑位置、当前结点、前驱结点还是尾指针？**
2. **目标结点能否直接得到，还是必须先遍历？**
3. **真正修改结构时要移动元素，还是只修改指针 / 游标？**
4. **修改指针之前，有没有旧链接还需要保存？**
5. **总复杂度由“查找位置”还是“修改结构”主导？**

<Callout type="info" title="本章最终目标">
不要把线性表复习成一组孤立代码。真正掌握的标志是：看到一个操作后，能立刻判断**需要先找什么、会改哪些位置、是否会丢链接、总复杂度是多少**。
</Callout>
