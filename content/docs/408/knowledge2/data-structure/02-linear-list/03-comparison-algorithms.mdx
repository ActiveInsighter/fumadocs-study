## 11. 顺序表与链表综合比较

| 比较项        | 顺序表      | 单链表      |
| ---------- | -------- | -------- |
| 物理存储       | 连续       | 不要求连续    |
| 逻辑关系表示     | 物理次序直接体现 | 指针体现     |
| 按位访问       | `O(1)`   | `O(n)`   |
| 按值查找       | `O(n)`   | `O(n)`   |
| 已知操作位置后的插入 | 可能移动元素   | 修改指针即可   |
| 已知前驱后的删除   | 可能移动元素   | `O(1)`   |
| 按逻辑位置插入    | `O(n)`   | `O(n)`   |
| 按逻辑位置删除    | `O(n)`   | `O(n)`   |
| 空间局部性      | 较好       | 通常较差     |
| 指针额外开销     | 无        | 有        |
| 容量扩展       | 可能涉及重新分配 | 较灵活      |
| 空间利用       | 预分配可能浪费  | 每结点有指针开销 |

> **如何选择**
>
> * 需要大量随机访问：优先考虑顺序表；
> * 经常在已知位置附近插入和删除：链表更合适；
> * 数据规模固定且希望结构简单：顺序表方便；
> * 表长经常变化且难以预估：链表更灵活。
>
> 实际性能还会受到缓存局部性、内存分配和具体访问模式等因素影响。

## 12. 408 高频易错点

### 12.1 “链表插入删除一定是 O(1)”错误

只有已经拿到相关结点或前驱结点时，真正修改指针的过程才是 `O(1)`。

如果题目说：

> 在单链表的第 \(i\) 个位置插入元素。

首先需要找到第 \(i-1\) 个结点，因此总体通常为 `O(n)`。

---

### 12.2 顺序表“随机访问 O(1)”不等于“查值 O(1)”

已知逻辑位置：

```text
求第 i 个元素
```

可以直接定位，为 `O(1)`。

但已知值：

```text
查找值为 x 的元素
```

普通顺序表仍需要逐个比较，为 `O(n)`。

---

### 12.3 头结点不等于首元结点

带头结点链表：

```text
head → [头结点] → [a1] → [a2] → ...
```

因此：

```c
head
```

指向头结点，而：

```c
head->next
```

才指向首元结点。

---

### 12.4 插入时不能丢失原后继

正确：

```c
s->next = p->next;
p->next = s;
```

如果先：

```c
p->next = s;
```

再错误地使用新的 `p->next` 寻找旧后继，就可能破坏链表。

---

### 12.5 删除前必须保存需要继续访问的信息

例如清空链表：

```c
q = p->next;
free(p);
p = q;
```

不能：

```c
free(p);
p = p->next;
```

因为 `p` 指向的空间已经释放。

---

### 12.6 循环链表不能机械使用 NULL 判断结束

普通单链表：

```c
while (p != NULL)
```

循环单链表则往往需要判断：

```c
p != head
```

或者：

```c
p != start
```

具体取决于题目给出的链表结构。

---

### 12.7 顺序表和链表不由栈区、堆区决定

以下说法都不严谨：

```text
顺序表一定存在栈上。
链表一定存在堆上。
```

真正区别是：

```text
顺序表：元素地址连续。
链表：结点通过链接信息建立逻辑顺序。
```

## 13. 链表算法设计高频模型

链表是 408 算法设计题的重要载体。

除了基本插入、删除外，应掌握以下典型模型。

### 13.1 单链表逆置

原链表：

```text
head → a1 → a2 → a3 → NULL
```

逆置后：

```text
head → a3 → a2 → a1 → NULL
```

可以使用三个指针：

```c
void Reverse(Node *head) {
    Node *prev = NULL;
    Node *p = head->next;

    while (p != NULL) {
        Node *next = p->next;

        p->next = prev;

        prev = p;
        p = next;
    }

    head->next = prev;
}
```

时间复杂度：

```text
O(n)
```

额外空间复杂度：

```text
O(1)
```

核心思想：

```text
保存后继 → 反转指针 → 三个指针整体向后移动
```

---

### 13.2 查找倒数第 k 个结点

典型方法是**快慢指针**。

1. `fast` 先向前移动 \(k\) 个结点；
2. `slow` 从第一个数据结点开始；
3. 两个指针同时向后移动；
4. 当 `fast` 到达链尾时，`slow` 即位于倒数第 \(k\) 个结点。

思想本质是维持两个指针之间固定的距离。

时间复杂度：

```text
O(n)
```

额外空间复杂度：

```text
O(1)
```

---

### 13.3 两个链表寻找公共结点

两个无环单链表如果相交，从第一个公共结点开始，其后续结点一定完全相同。

因此结构只能类似：

```text
A: a1 → a2 ─┐
             ├→ c1 → c2 → NULL
B: b1 → b2 → b3 ┘
```

不可能：

```text
先相交 → 再分叉
```

因为一个单链表结点只有一个 `next` 指针。

常见解法：

1. 分别计算两个链表长度；
2. 让较长链表先走长度差；
3. 两个指针再同步前进；
4. 第一次指向同一结点的位置就是第一个公共结点。

时间复杂度：

```text
O(m+n)
```

额外空间复杂度：

```text
O(1)
```

这里判断公共结点必须比较**结点地址是否相同**，而不是只比较数据值是否相等。

## 15. 本章复习主线

复习线性表时建议按照下面的逻辑建立完整知识框架：

```text
线性表
│
├── 逻辑结构
│   └── 一对一的前驱、后继关系
│
├── 顺序存储
│   ├── 连续内存
│   ├── 随机访问 O(1)
│   ├── 插入移动
│   └── 删除移动
│
└── 链式存储
    ├── 单链表
    │   ├── 头结点
    │   ├── 插入
    │   ├── 删除
    │   └── 查找
    │
    ├── 双向链表
    │   ├── prev
    │   └── next
    │
    ├── 循环链表
    │   └── 首尾相连
    │
    └── 静态链表
        └── 数组 + 游标
```

最终应能够回答三个核心问题：

1. **数据元素的逻辑关系是什么？**
2. **这种逻辑关系在内存中如何表示？**
3. **这种表示方式会怎样影响访问、查找、插入和删除的复杂度？**

把这三点真正理解后，线性表相关的选择题和算法设计题就可以统一起来分析。
