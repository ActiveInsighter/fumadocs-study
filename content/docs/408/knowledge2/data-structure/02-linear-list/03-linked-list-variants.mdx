单链表只有一个 `next` 指针，因此访问前驱不方便、尾部也以 `NULL` 结束。为适应不同操作需求，可以改变链接方式，形成双向链表、循环链表和静态链表。

学习这些变体时，不应重新死记一套代码，而要始终抓住：

> **增加了什么链接信息？因此哪些操作变方便？同时付出了什么额外空间或维护成本？**

---

## 2.3.1 双向链表的结点结构

双向链表在每个结点中同时保存前驱和后继：

```c
typedef struct DNode {
    ElementType data;
    struct DNode *prev;
    struct DNode *next;
} DNode;
```

结构可抽象为：

```text
... ⇄ [prev | data | next] ⇄ ...
```

相比单链表：

- 可以沿 `next` 向后访问；
- 可以沿 `prev` 向前访问；
- 已知当前结点时，可直接得到其前驱；
- 删除当前结点时，不必再从链表头寻找前驱。

代价是：

- 每个结点多一个指针域；
- 插入、删除时必须同时维护两个方向的链接。

## 2.3.2 双向链表插入：四条关系必须同时成立

若要在结点 `p` **之后**插入新结点 `s`：

```text
插入前：... ⇄ p ⇄ q ⇄ ...
插入后：... ⇄ p ⇄ s ⇄ q ⇄ ...
```

假设 `p` 不是尾结点，一种直观写法是：

```c
s->next = p->next;
s->prev = p;
p->next->prev = s;
p->next = s;
```

完成后应同时满足：

```text
p.next = s
s.prev = p
s.next = q
q.prev = s
```

检查双向链表代码时，可以逐条验证这四个关系，而不是只看语句顺序。

> **真题标签｜2023 年选择题：双向链表插入**
>
> 题目可能故意先执行 `s->next = p->next; p->next = s;`，再询问剩余两条语句。此时要根据“当前指针已经变成什么”推导，而不能机械背固定四行代码。

### 在 `p` 之前插入

若插到 `p` 前：

```c
s->prev = p->prev;
s->next = p;
p->prev->next = s;
p->prev = s;
```

本质仍是建立四条双向关系。

## 2.3.3 双向链表删除

删除已知结点 `p`：

```text
删除前：... ⇄ a ⇄ p ⇄ b ⇄ ...
删除后：... ⇄ a ⇄ b ⇄ ...
```

若 `p` 既不是特殊头哨兵也不是尾哨兵：

```c
p->prev->next = p->next;
p->next->prev = p->prev;
free(p);
```

已知 `p` 时，真正修改链接为：

$$
O(1)
$$

这正是双向链表相对单链表的一个重要优势：**不需要再寻找 `p` 的前驱**。

> **易错点**
>
> 只修改 `next` 或只修改 `prev` 都会破坏结构。双向链表的局部操作必须保证两个方向相互一致。

## 2.3.4 循环单链表

普通单链表最后一个结点满足：

```c
tail->next == NULL
```

而循环单链表让尾部重新指向链表前部。

若采用带头结点的循环单链表，常见结构是：

```text
        ┌──────────────────────┐
        ↓                      │
head → [H] → [a1] → [a2] → [an]
        ↑                      │
        └──────────────────────┘
```

尾结点满足：

```c
tail->next == head
```

空表通常满足：

```c
head->next == head
```

因此普通链表的：

```c
while (p != NULL)
```

不能机械搬到循环链表中，否则循环永远不会遇到 `NULL`。

带头结点循环单链表的一种遍历方式：

```c
for (Node *p = head->next; p != head; p = p->next) {
    /* 处理 p */
}
```

---

## 2.3.5 尾指针在循环单链表中的价值

若只保存头指针：

- 访问首元结点方便；
- 找尾结点仍可能需要 $O(n)$。

若只保存尾指针 `tail`，且尾结点指向头部，则：

```c
tail           // 尾结点
tail->next     // 头结点（带头结点时）
tail->next->next // 首元结点
```

因此循环单链表中维护尾指针，常常可以同时高效访问表头和表尾附近位置。

这类题要先画出：

```text
tail → ?
```

再根据循环关系判断，不要凭普通单链表经验作答。

## 2.3.6 循环双链表

循环双链表把首尾两个方向都接起来。

采用头结点 `head` 时，空表常初始化为：

```c
head->next = head;
head->prev = head;
```

非空时满足：

```c
head->next->prev == head;
head->prev->next == head;
```

可以把头结点看成一个哨兵，它的：

- `next` 指向首元结点；
- `prev` 指向尾结点。

这样首尾边界可以和中间结点采用更统一的插入、删除逻辑。

判空：

```c
bool Empty(DNode *head) {
    return head->next == head;
}
```

---

## 2.3.7 循环链表的终止条件

循环链表题最容易错在“什么时候停”。

常见终止条件取决于题目给出的结构：

| 结构 | 常见遍历终止条件 |
| --- | --- |
| 普通单链表 | `p == NULL` |
| 带头结点循环单链表 | `p == head` |
| 从任意结点 `start` 出发遍历一圈 | 再次回到 `start` |
| 循环双链表 | 根据头哨兵或起点判断 |

> **真题标签｜循环链表**
>
> 选择题经常把普通链表的 `NULL` 结束条件混入循环链表选项。先确认题目是“带头结点 / 不带头结点”“保存头指针 / 尾指针”，再判断终止条件。

## 2.3.8 静态链表：用数组下标模拟指针

静态链表使用数组保存结点，但仍然通过“链接信息”组织逻辑次序。

```c
#define MAXSIZE 100

typedef struct {
    ElementType data;
    int next;
} SNode;

SNode list[MAXSIZE];
```

这里：

- `data` 保存数据；
- `next` 不保存真实地址，而保存**下一个结点的数组下标**；
- 这种下标通常称为**游标**。

例如：

```text
list[2].next = 5
```

表示逻辑上：

```text
下标 2 的结点 → 下标 5 的结点
```

若约定：

```c
next == -1
```

表示链尾，则遍历仍然像链表一样沿游标前进。

---

## 2.3.9 静态链表到底属于“数组”还是“链表”

这个问题要区分物理实现和逻辑组织：

```text
物理存储：数组
逻辑链接：游标（下标）
```

因此静态链表的本质是：

> **用连续数组作为结点池，用数组下标模拟指针，按链式方式组织逻辑关系。**

修改链表逻辑关系时通常只改游标，不需要像普通顺序表那样搬移大量数据元素。

## 2.3.10 顺序表与链表的系统比较

| 比较项 | 顺序表 | 单链表 |
| --- | --- | --- |
| 物理存储 | 连续 | 不要求连续 |
| 逻辑关系表示 | 由物理次序直接体现 | 由指针显式表示 |
| 按位访问 | $O(1)$ | $O(n)$ |
| 普通按值查找 | $O(n)$ | $O(n)$ |
| 已知相关位置后的局部插入 | 仍可能搬移元素 | 改指针即可，通常 $O(1)$ |
| 已知前驱后的删除 | 仍可能搬移元素 | $O(1)$ |
| 按逻辑位置插入 | $O(n)$ | $O(n)$，主要耗时在找前驱 |
| 按逻辑位置删除 | $O(n)$ | $O(n)$，主要耗时在找前驱 |
| 每个元素额外指针空间 | 无 | 有 |
| 空间局部性 | 通常较好 | 通常较差 |
| 扩容 | 可能重新分配连续空间 | 按结点分配更灵活 |

### 如何选择

优先考虑顺序表：

- 高频随机访问；
- 主要进行遍历和查找；
- 元素个数较稳定；
- 重视缓存局部性。

优先考虑链表：

- 表长变化频繁；
- 经常在**已经定位到的结点附近**插入或删除；
- 不要求随机访问；
- 难以预估连续空间需求。

> **不要把选择标准简化为“插删多就一定链表”**
>
> 如果每次插删前都要从表头线性寻找目标位置，查找代价仍然可能是 $O(n)$。实际选择应同时考虑**定位代价 + 修改代价 + 空间局部性**。

---

## 2.3.11 三类链表的能力对比

| 结构 | 后继 | 前驱 | 是否首尾相连 | 典型优势 |
| --- | --- | --- | --- | --- |
| 单链表 | `next` | 不能直接获得 | 否 | 结构最简单、指针开销较小 |
| 双向链表 | `next` | `prev` | 否 | 已知当前结点时前后移动方便 |
| 循环链表 | 取决于单向 / 双向 | 取决于结构 | 是 | 适合周期性遍历、首尾统一处理 |
| 静态链表 | 游标 `next` | 通常无 | 视实现而定 | 无真实指针时模拟链式结构 |

> **本节结论**
>
> 链表变体不是新的逻辑结构，而是对“链接信息”的不同设计。多保存一个方向、增加首尾连接或把地址换成游标，都会改变可直接获得的信息与操作成本。
