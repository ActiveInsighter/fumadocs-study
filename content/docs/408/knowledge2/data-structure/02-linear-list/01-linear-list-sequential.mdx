线性表是数据结构中最基本的**线性结构**。本章真正要掌握的不是某一段固定代码，而是两条主线：

> **同一种线性逻辑结构，可以使用顺序存储或链式存储；存储方式不同，会直接改变访问、插入、删除和空间利用的代价。**

本节先建立线性表的逻辑模型，再集中讨论顺序表。

---

## 2.1.1 线性表的定义与逻辑关系

**线性表（Linear List）**&#x2060;是由零个或多个**同类型数据元素**组成的有限序列：

$$
L=(a_1,a_2,\ldots,a_i,\ldots,a_n)
$$

其中：

- $n$ 为线性表长度；
- $n=0$ 时称为空表；
- $a_1$ 为首元素，$a_n$ 为尾元素；
- 对任意 $1<i<n$，$a_i$ 有唯一直接前驱 $a_{i-1}$ 和唯一直接后继 $a_{i+1}$。

因此，线性表的核心关系是：

```text
一对一的前驱—后继关系
```

需要特别区分：

- **逻辑结构**描述元素之间“谁在谁前面”；
- **存储结构**描述这些元素在存储器中“怎样放、怎样表示关系”。

线性表本身并不要求物理地址连续。

---

## 2.1.2 线性表的抽象操作

408 中常见的线性表基本操作可以统一理解为 ADT 层面的接口：

| 操作 | 含义 |
| --- | --- |
| `InitList` | 初始化空表 |
| `DestroyList` | 销毁线性表及其占用资源 |
| `Length` | 求表长 |
| `Empty` | 判断是否为空 |
| `GetElem` | 按逻辑位置取得元素 |
| `LocateElem` | 按值或条件查找元素 |
| `ListInsert` | 在指定逻辑位置插入元素 |
| `ListDelete` | 删除指定逻辑位置的元素 |
| `Traverse` | 按逻辑次序访问所有元素 |

这些操作描述的是“**要做什么**”。底层使用顺序表还是链表，决定“**怎样做以及复杂度是多少**”。

---

## 2.1.3 顺序存储的核心思想

**顺序表（Sequential List）**&#x2060;用一段地址连续的存储空间依次保存线性表元素。

若：

- 第一个元素 $a_1$ 的地址为 $LOC(a_1)$；
- 每个元素占 $l$ 个存储单元；

则第 $i$ 个元素的地址为：

$$
LOC(a_i)=LOC(a_1)+(i-1)l
$$

这条地址公式说明了顺序表最重要的性质：

> **只要知道首地址、元素大小和逻辑位置，就能直接计算目标元素地址。**

因此顺序表支持**随机存取（Random Access）**，按位访问时间复杂度为 $O(1)$。

> **真题标签｜2023 年选择题：顺序表随机存取**
>
> 判断顺序表能否在常数时间取得第 $i$ 个元素，关键就是能否由地址公式直接定位，而不是顺序扫描前 $i-1$ 个元素。

---

## 2.1.4 顺序表的静态实现与动态实现

### 静态顺序表

使用固定长度数组：

```c
#define MAXSIZE 100

typedef struct {
    ElementType data[MAXSIZE];
    int length;
} SeqList;
```

其中：

- `data` 保存元素；
- `length` 保存当前有效元素数；
- `MAXSIZE` 是最大容量。

初始化：

```c
void InitList(SeqList *L) {
    L->length = 0;
}
```

静态顺序表结构简单，但容量上限在创建时已经确定。

### 动态顺序表

若希望容量可以增长，可以把连续空间动态申请：

```c
typedef struct {
    ElementType *data;
    int length;
    int capacity;
} SeqList;
```

动态扩容的本质通常是：

```text
申请更大的连续区域
→ 复制原有元素
→ 释放旧区域
→ 更新首地址与容量
```

因此动态顺序表虽然“容量可增长”，但仍然必须满足**当前元素位于一段连续地址空间**这一顺序存储条件。

> **易错点｜顺序表不等于“栈上数组”**
>
> 顺序表可以使用栈区数组、静态数组，也可以使用堆上动态数组。判断顺序存储的依据是**元素是否连续存放**，而不是内存属于栈区还是堆区。

---

## 2.1.5 逻辑位置与数组下标

线性表通常按“第 1 个、第 2 个……”描述逻辑位置，而 C 数组下标从 0 开始。

因此：

| 逻辑位置 | C 数组下标 |
| ---: | ---: |
| 第 1 个元素 | `data[0]` |
| 第 2 个元素 | `data[1]` |
| 第 `pos` 个元素 | `data[pos - 1]` |

这是顺序表代码中最常见的边界错误来源。

例如长度为 $n$ 的顺序表：

- 合法访问 / 删除位置：$1\le pos\le n$；
- 合法插入位置：$1\le pos\le n+1$。

---

## 2.1.6 顺序表的按位访问与按值查找

### 按位访问

已知逻辑位置 `pos`：

```c
bool GetElem(SeqList L, int pos, ElementType *e) {
    if (pos < 1 || pos > L.length)
        return false;

    *e = L.data[pos - 1];
    return true;
}
```

由地址公式直接定位，因此：

$$
T(n)=O(1)
$$

### 按值查找

已知元素值 `e`，普通无序顺序表必须逐个比较：

```c
int LocateElem(SeqList L, ElementType e) {
    for (int i = 0; i < L.length; ++i) {
        if (L.data[i] == e)
            return i + 1;
    }
    return 0;
}
```

最坏情况下需要扫描整个表：

$$
T(n)=O(n)
$$

> **高频辨析**
>
> “顺序表支持随机存取”只说明**按位置访问**可以做到 $O(1)$，并不意味着普通顺序表“按值查找”也是 $O(1)$。

---

## 2.1.7 顺序表插入：先腾位置，再写元素

若长度为 $n$，要在第 $i$ 个逻辑位置插入新元素，则原来的第 $i$ 到第 $n$ 个元素都要向后移动一位。

```c
bool ListInsert(SeqList *L, int pos, ElementType e) {
    if (L->length == MAXSIZE)
        return false;

    if (pos < 1 || pos > L->length + 1)
        return false;

    for (int i = L->length; i >= pos; --i) {
        L->data[i] = L->data[i - 1];
    }

    L->data[pos - 1] = e;
    ++L->length;
    return true;
}
```

### 为什么必须从后向前移动

假设要在中间插入：

```text
原表：a1 a2 a3 a4
          ↑ 在 a2 前插入 x
```

正确移动方向是：

```text
a4 后移 → a3 后移 → a2 后移 → 写入 x
```

若从前向后搬移，前面的赋值可能覆盖后面尚未保存的旧元素。

### 插入移动次数

在第 $i$ 个位置插入时，需要移动：

$$
n-i+1
$$

个元素。

若 $n+1$ 个插入位置等概率出现，平均移动次数为：

$$
\frac{1}{n+1}\sum_{i=1}^{n+1}(n-i+1)
=\frac{n}{2}
$$

所以一般位置插入的平均时间复杂度为：

$$
O(n)
$$

边界情况：

- 表尾插入：移动 0 个元素，若容量足够则为 $O(1)$；
- 表头插入：移动 $n$ 个元素，为 $O(n)$。

> **真题标签｜2026 年选择题：表头 / 表尾插入删除的移动**
>
> 顺序存储中，在保持元素相对次序不变的前提下，表头插入与表头删除都会导致原有元素整体移动；表尾插入和表尾删除不需要搬移其他元素。

---

## 2.1.8 顺序表删除：先保存，再前移覆盖

删除第 `pos` 个元素：

```c
bool ListDelete(SeqList *L, int pos, ElementType *e) {
    if (pos < 1 || pos > L->length)
        return false;

    *e = L->data[pos - 1];

    for (int i = pos; i < L->length; ++i) {
        L->data[i - 1] = L->data[i];
    }

    --L->length;
    return true;
}
```

删除第 $i$ 个元素，需要移动：

$$
n-i
$$

个元素。

若 $n$ 个删除位置等概率出现，平均移动次数为：

$$
\frac{1}{n}\sum_{i=1}^{n}(n-i)
=\frac{n-1}{2}
$$

因此一般位置删除为：

$$
O(n)
$$

边界情况：

- 删除尾元素：无需移动，为 $O(1)$；
- 删除首元素：移动 $n-1$ 个元素，为 $O(n)$。

---

## 2.1.9 顺序表的空间特性与局部性

顺序表不需要为每个元素保存额外指针，因此数据本身的存储密度较高。

同时，连续存储还带来良好的**空间局部性**：顺序访问 `data[i]` 时，后续元素通常位于相邻地址，CPU Cache 更容易一次加载多个相邻元素。

但顺序存储也有代价：

- 固定容量可能造成预留空间浪费；
- 动态扩容可能需要重新申请空间并复制元素；
- 中间位置插入、删除通常需要搬移大量元素。

因此顺序表更适合：

- 经常按下标访问；
- 以遍历、查找为主；
- 中间插入删除较少；
- 希望利用连续内存和缓存局部性的场景。

---

## 2.1.10 顺序表复杂度速查

| 操作 | 时间复杂度 | 原因 |
| --- | ---: | --- |
| 求长度 | $O(1)$ | `length` 直接记录 |
| 按位访问 | $O(1)$ | 地址可直接计算 |
| 普通按值查找 | $O(n)$ | 最坏需线性扫描 |
| 表头插入 | $O(n)$ | 原元素整体后移 |
| 表尾插入 | $O(1)$ | 容量足够时无需移动 |
| 一般位置插入 | $O(n)$ | 平均移动约 $n/2$ 个元素 |
| 表头删除 | $O(n)$ | 剩余元素整体前移 |
| 表尾删除 | $O(1)$ | 无需移动其他元素 |
| 一般位置删除 | $O(n)$ | 平均移动约 $(n-1)/2$ 个元素 |

> **本节结论**
>
> 顺序表用“**连续地址**”换取“**随机访问**”；代价是中间位置插入、删除时必须维持连续且有序的存储布局，因此往往需要搬移元素。
