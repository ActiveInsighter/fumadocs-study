线性表是 408 数据结构中最基础的线性结构，也是后续学习栈、队列、串等内容的基础。

本章最重要的不是死记代码，而是始终沿着下面这条主线分析：

> **逻辑结构相同 → 存储方式不同 → 基本操作的实现和复杂度不同**

| 实现 | 物理存储 | 按位访问 | 按逻辑位置插入、删除 | 主要额外开销 |
| --- | --- | --- | --- | --- |
| **顺序表** | 地址连续 | $O(1)$ | 通常 $O(n)$ | 预留容量 |
| **链表** | 不要求连续 | $O(n)$ | 通常 $O(n)$，找到相关结点后修改链接为 $O(1)$ | 指针 / 游标 |

<Callout type="info" title="本章复习重点">
重点掌握：**顺序表元素移动次数、单链表指针修改顺序、头指针/头结点/首元结点、双向链表、循环链表，以及链表算法设计**。
</Callout>

## 1. 线性表的基本概念

<InlineSvg src="/images/data-structure/data-structure-linearlist-def-001.svg" alt="线性表 Linear List L = (a₁, a₂, a₃, ..., aᵢ, aᵢ₊₁, ..., aₙ) a₁ a₂ a₃ ... aᵢ aᵢ₊₁ ... aₙ 当前元素 前驱 后继 线性表特点： 个数有限： 表中元素个数是确定的有限值 类型相同： 所有元素数据类型一致，占用相同存储空间 逻辑有序： 元素间存在先后顺序，有前驱和后继关系" />

### 1.1 定义

**线性表（Linear List）**&#x2060;是由零个或多个**相同数据类型的数据元素组成的有限序列**，可记为：

$$
L=(a_1,a_2,\ldots,a_i,a_{i+1},\ldots,a_n)
$$

其中：

- $n$ 为线性表长度；
- $n=0$ 时称为空表；
- $a_1$ 为第一个数据元素，$a_n$ 为最后一个数据元素。

在线性表中：

- $a_1$ 没有直接前驱；
- $a_n$ 没有直接后继；
- 对 $1<i<n$，$a_i$ 的直接前驱为 $a_{i-1}$，直接后继为 $a_{i+1}$。

因此，线性表的逻辑特点可以概括为：

> **除首、尾元素外，每个元素都有唯一的直接前驱和唯一的直接后继。**

### 1.2 三个基本特征

线性表具有以下基本特征：

1. **有穷性**：元素个数有限；
2. **同类型性**：各数据元素属于同一数据类型；
3. **有序性**：元素之间存在确定的逻辑先后次序。

这里的“有序”是指**存在先后关系**，并不是说元素值按照从小到大或从大到小排列。

<Callout type="warn" title="高频易错：逻辑有序 ≠ 按关键字有序">
线性表中的“有序序列”强调元素具有第 1 个、第 2 个、……这样的逻辑次序；它与排序中的“递增/递减有序”不是同一个概念。
</Callout>

## 2. 线性表的存储与基本操作

### 2.1 顺序存储与链式存储

<InlineSvg src="/images/data-structure/data-structure-linearlist-def-002.svg" alt="1 2 3 4 5 1 3 2 物 理 地 址 逐 渐 增 大 顺序表 链表 5 4 物 理 地 址 逐 渐 增 大" />

同一个线性表逻辑结构可以采用不同的存储方式。

**顺序存储：**

```text
[a1][a2][a3][a4]...
```

特点：逻辑上相邻的元素在物理地址上也相邻。

**链式存储：**

```text
[a1 | next] -> [a2 | next] -> [a3 | next] -> ...
```

特点：结点物理地址不要求连续，通过链接信息维持逻辑次序。

<Callout type="warn" title="存储结构与栈区/堆区没有必然联系">
判断顺序表和链表的依据，是**元素是否连续存储、逻辑关系如何表示**，而不是对象位于进程的栈区还是堆区。顺序表可以动态申请在堆中，链式结构也可以使用静态数组和游标模拟。
</Callout>

### 2.2 线性表的抽象操作

<InlineSvg src="/images/data-structure/data-structure-linearlist-def-003.svg" alt="图示" />

| 操作 | 含义 |
| --- | --- |
| `InitList` | 初始化空线性表 |
| `Insert` | 在指定逻辑位置插入元素 |
| `Delete` | 删除指定逻辑位置的元素 |
| `LocateElem` | 按值或条件定位元素 |
| `GetElem` | 获取指定逻辑位置上的元素 |
| `SetElem` | 修改指定位置元素的值 |
| `Length` | 返回表长 |
| `IsEmpty` | 判断是否为空表 |
| `ClearList` | 清空线性表 |
| `Traverse` | 按逻辑次序访问全部元素 |

这些操作描述的是**ADT 层面的功能**。同一操作在顺序表和链表中的实现方式可能完全不同。

## 3. 顺序表的存储原理

<InlineSvg src="/images/data-structure/data-structure-linearlist-sequential-001.svg" alt="a 1 a i a 2 a n Sequential List A Index 0 1 i-1 n-1 Memory Address LOC(A) LOC(A) + sizeof(Elem) LOC(A) + (i-1) x sizeof(Elem) Maxsize - 1 LOC(A) + (n-1) x sizeof(Elem) LOC(A) + (Maxsize-1) x sizeof(Elem)" />

### 3.1 地址计算公式

**顺序表（Sequential List）**&#x2060;用一组地址连续的存储单元依次保存线性表中的元素。

设：

- 表首地址为 $LOC(A)$；
- 每个元素占用 $sizeof(Elem)$ 个字节；
- $a_i$ 是第 $i$ 个数据元素。

则：

$$
LOC(a_i)=LOC(A)+(i-1)\times sizeof(Elem)
$$

这正是顺序表能够**随机访问（Random Access）**&#x2060;的根本原因：已知首地址、元素大小和逻辑位置，即可直接计算目标元素地址。

> **真题标签**
>
> 2023 年第 1 题考查顺序表按位访问与其他操作的复杂度；2026 年相关选择题继续考查顺序表头部插入、删除导致的元素移动。

### 3.2 顺序表的优缺点

**优点：**

- 按位访问为 $O(1)$；
- 不需要为每个元素附加指针域，存储密度较高；
- 连续存储通常具有较好的空间局部性，有利于 CPU Cache；
- 结构简单，便于实现。

**缺点：**

- 中间插入、删除通常需要移动大量元素；
- 静态顺序表必须预先给定最大容量；
- 动态扩容时可能需要重新申请空间并搬移已有元素；
- 预留过大可能浪费空间，预留过小又可能频繁扩容。

## 4. 顺序表的定义、初始化与扩容

<InlineSvg src="/images/data-structure/data-structure-linearlist-sequential-002.svg" alt="图示" />

### 4.1 静态顺序表

```c
#define MAXSIZE 100

typedef struct {
    ElementType data[MAXSIZE];
    int length;
} SeqList;
```

初始化：

```c
void InitList(SeqList *L) {
    L->length = 0;
}
```

其中：

- `data` 保存数据元素；
- `length` 表示当前有效元素个数；
- `MAXSIZE` 表示最大容量。

### 4.2 逻辑位置与数组下标

408 题目通常把线性表的第一个元素称为“第 1 个元素”，即逻辑位置从 1 开始；C 数组下标则从 0 开始。

因此：

```text
第 1 个元素     <-> data[0]
第 pos 个元素   <-> data[pos - 1]
第 n 个元素     <-> data[n - 1]
```

<Callout type="warn" title="最常见的代码错误：差 1">
写顺序表代码前，先明确“题目中的位置从 1 开始，数组下标从 0 开始”。插入第 `pos` 个位置时写入 `data[pos - 1]`；删除第 `pos` 个元素时，被删元素同样是 `data[pos - 1]`。
</Callout>

### 4.3 动态顺序表

顺序表也可以使用动态内存实现：

```c
#define INIT_CAPACITY 10

typedef struct {
    ElementType *data;
    int length;
    int capacity;
} DynamicSeqList;
```

初始化时申请一段连续空间：

```c
bool InitDynamicList(DynamicSeqList *L) {
    L->data = (ElementType *)malloc(
        INIT_CAPACITY * sizeof(ElementType)
    );

    if (L->data == NULL) {
        return false;
    }

    L->length = 0;
    L->capacity = INIT_CAPACITY;
    return true;
}
```

动态顺序表改变的是**容量管理方式**，并没有改变“元素连续存储”的本质。

## 5. 顺序表的访问与查找

### 5.1 按位访问

获取第 `pos` 个元素：

```c
bool GetElem(SeqList L, int pos, ElementType *e) {
    if (pos < 1 || pos > L.length) {
        return false;
    }

    *e = L.data[pos - 1];
    return true;
}
```

因为可以直接由下标定位，时间复杂度为：

$$
O(1)
$$

### 5.2 按值查找

```c
int LocateElem(SeqList L, ElementType e) {
    for (int i = 0; i < L.length; ++i) {
        if (L.data[i] == e) {
            return i + 1;
        }
    }

    return 0;
}
```

普通顺序表只能逐个比较，时间复杂度为：

$$
O(n)
$$

<Callout type="warn" title="随机访问 O(1) 不等于按值查找 O(1)">
**随机访问**解决的是“已知第几个元素，如何取得它”；**按值查找**解决的是“值为 $x$ 的元素在哪里”。普通无序顺序表按值查找仍需线性扫描。
</Callout>

## 6. 顺序表的插入

<InlineSvg src="/images/data-structure/data-structure-linearlist-sequential-003.svg" alt="顺序表插入过程图解：在位置 3 插入元素 99 步骤1：初始状态 10 20 30 40 50 1 2 3 4 5 6 7 length = 5 插入位置 pos=3 步骤2：从尾部开始，向后移动元素 10 20 30 40 50 50 移动 10 20 30 40 40 50 移动 10 20 30 30 40 50 移动 步骤3：插入新元素并更新长度 10 20 99 30 40 50 新元素 99 length = 6 关键要点： 1. 检查插入位置合法性：1 ≤ po" />

### 6.1 合法插入位置

长度为 $n$ 的线性表共有 $n+1$ 个合法插入位置：

$$
1\le pos\le n+1
$$

其中：

- `pos = 1`：表头插入；
- `pos = n + 1`：表尾插入。

### 6.2 插入算法

在第 `pos` 个位置插入新元素 `e` 时，原来从该位置开始的元素必须整体后移一位。

```c
bool Insert(SeqList *L, int pos, ElementType e) {
    if (L->length == MAXSIZE ||
        pos < 1 ||
        pos > L->length + 1) {
        return false;
    }

    for (int i = L->length; i >= pos; --i) {
        L->data[i] = L->data[i - 1];
    }

    L->data[pos - 1] = e;
    ++L->length;
    return true;
}
```

移动方向必须是：

```text
从后向前
```

原因是若从前向后移动，会先覆盖仍未备份的后续元素。

### 6.3 插入时元素移动次数

若原表长度为 $n$，在第 $i$ 个位置插入，则需要移动：

$$
n-i+1
$$

个元素。

| 情况 | 移动次数 | 时间复杂度 |
| --- | ---: | --- |
| 表尾插入 | $0$ | $O(1)$ |
| 表头插入 | $n$ | $O(n)$ |
| 一般位置 | $n-i+1$ | $O(n)$ |

若题目假设 $n+1$ 个插入位置**等概率**，平均移动次数为：

$$
\frac{1}{n+1}\sum_{i=1}^{n+1}(n-i+1)
=\frac{n}{2}
$$

所以平均时间复杂度仍为：

$$
O(n)
$$

## 7. 顺序表的删除

<InlineSvg src="/images/data-structure/data-structure-linearlist-sequential-004.svg" alt="图示" />

### 7.1 合法删除位置

长度为 $n$ 的非空顺序表，合法删除位置满足：

$$
1\le pos\le n
$$

### 7.2 删除算法

```c
bool Delete(SeqList *L, int pos, ElementType *e) {
    if (pos < 1 || pos > L->length) {
        return false;
    }

    if (e != NULL) {
        *e = L->data[pos - 1];
    }

    for (int i = pos; i < L->length; ++i) {
        L->data[i - 1] = L->data[i];
    }

    --L->length;
    return true;
}
```

删除后，为填补空位，后续元素应从前向后依次前移。

### 7.3 删除时元素移动次数

删除第 $i$ 个元素，需要移动：

$$
n-i
$$

个元素。

| 情况 | 移动次数 | 时间复杂度 |
| --- | ---: | --- |
| 删除尾元素 | $0$ | $O(1)$ |
| 删除首元素 | $n-1$ | $O(n)$ |
| 一般位置 | $n-i$ | $O(n)$ |

若 $n$ 个删除位置等概率，平均移动次数为：

$$
\frac{1}{n}\sum_{i=1}^{n}(n-i)
=\frac{n-1}{2}
$$

## 8. 顺序表操作与复杂度速查

### 8.1 其他基本操作

判空：

```c
bool IsEmpty(SeqList L) {
    return L.length == 0;
}
```

清空：

```c
void ClearList(SeqList *L) {
    L->length = 0;
}
```

求长度：

```c
int Length(SeqList L) {
    return L.length;
}
```

对于固定数组实现，将 `length` 置为 0 即完成**逻辑清空**。数组单元中原来的比特内容可能仍然存在，但已经不再属于线性表的有效元素。

### 8.2 复杂度总表

| 操作 | 顺序表时间复杂度 | 原因 |
| --- | --- | --- |
| 按位访问 | $O(1)$ | 地址可直接计算 |
| 按值查找 | $O(n)$ | 一般需要线性扫描 |
| 表头插入 | $O(n)$ | 需要移动原有元素 |
| 表尾插入 | $O(1)$ | 容量充足时无须移动 |
| 一般位置插入 | $O(n)$ | 查位置为 $O(1)$，移动为 $O(n)$ |
| 删除尾元素 | $O(1)$ | 无须移动其他元素 |
| 一般位置删除 | $O(n)$ | 需要前移后续元素 |
| 判空、求长度 | $O(1)$ | 直接读取成员变量 |

<Callout type="info" title="顺序表一页记忆">
顺序表最核心的两句话：**按位访问快，因为能算地址；中间插删慢，因为要搬元素。**
</Callout>
