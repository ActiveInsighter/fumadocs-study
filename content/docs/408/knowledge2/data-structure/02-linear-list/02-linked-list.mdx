链表与顺序表具有相同的线性逻辑结构，但链表不要求各数据结点在物理地址上连续，而是依靠**链接信息**表示前驱、后继关系。

> **链表题的核心不是记整段代码，而是始终知道：修改某个指针之前，旧链接是否还需要继续使用。**

## 9. 链式存储与单链表基础

### 9.1 链式存储的基本思想

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-001.svg" alt="a 1 a 2 a n Linked List L header node NULL" />
<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-002.svg" alt="data next" />
<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-004.svg" alt="图示" />

单链表的每个结点通常包含：

- 数据域 `data`；
- 指向后继结点的指针域 `next`。

```c
typedef struct Node {
    ElementType data;
    struct Node *next;
} Node;
```

逻辑结构可以表示为：

```text
[a1 | •] -> [a2 | •] -> [a3 | •] -> ... -> NULL
```

链表结点**经常**通过 `malloc` / `new` 动态申请，但“动态申请”不是链表的定义条件；链式逻辑也可以使用对象池、静态数组、游标等方式实现。

### 9.2 链表的优缺点

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-003.svg" alt="图示" />

**优点：**

- 不要求整表占据连续空间；
- 表长可以较灵活地变化；
- 已知相关结点后，插入、删除通常只需修改常数个链接；
- 插删时不需要整体搬移大量数据元素。

**缺点：**

- 不支持按下标直接随机访问；
- 查找第 $i$ 个结点通常需要从链头遍历；
- 每个结点需要额外保存指针等链接信息；
- 结点通常较分散，空间局部性一般不如连续数组。

## 10. 头指针、头结点与首元结点

### 10.1 三个概念

带头结点的单链表：

```text
head
  |
  v
[头结点] -> [a1] -> [a2] -> ... -> NULL
```

- **头指针**：`head`，指向链表起始结点；
- **头结点**：人为增加在首元结点之前的辅助结点，通常不保存线性表有效数据；
- **首元结点**：真正保存 $a_1$ 的第一个数据结点。

采用头结点后：

```c
head->next
```

才指向首元结点。

### 10.2 为什么常用头结点

引入头结点可以：

- 统一空表与非空表的处理；
- 统一首元结点与其他结点的插入、删除；
- 减少对“第一个数据结点”的特殊分支判断。

### 10.3 初始化与判空

```c
Node *InitList(void) {
    Node *head = (Node *)malloc(sizeof(Node));

    if (head == NULL) {
        return NULL;
    }

    head->next = NULL;
    return head;
}
```

判空：

```c
bool IsEmpty(Node *head) {
    return head != NULL && head->next == NULL;
}
```

<Callout type="warn" title="head == NULL 与空表不是一回事">
对于已经正确创建的带头结点链表，`head == NULL` 表示头指针本身无效；`head->next == NULL` 才表示线性表中没有数据结点。
</Callout>

## 11. 单链表的查找与遍历

### 11.1 按位查找

链表不能根据下标直接计算目标结点地址，因此查找第 `pos` 个数据结点必须从前向后走。

```c
Node *GetElem(Node *head, int pos) {
    if (head == NULL || pos < 1) {
        return NULL;
    }

    Node *p = head->next;
    int i = 1;

    while (p != NULL && i < pos) {
        p = p->next;
        ++i;
    }

    return p;
}
```

最坏时间复杂度：

$$
O(n)
$$

### 11.2 按值查找

```c
int LocateElem(Node *head, ElementType value) {
    Node *p = head->next;
    int pos = 1;

    while (p != NULL) {
        if (p->data == value) {
            return pos;
        }

        p = p->next;
        ++pos;
    }

    return 0;
}
```

时间复杂度同样为：

$$
O(n)
$$

因此链表的典型特点是：

> **按位访问慢，但找到位置后修改链接快。**

## 12. 单链表的插入

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-005.svg" alt="p q p q n p q n" />

### 12.1 已知结点 `p`，在其后插入 `s`

插入前：

```text
p -> q
```

插入后：

```text
p -> s -> q
```

核心代码：

```c
void InsertNodeAfter(Node *p, Node *s) {
    s->next = p->next;
    p->next = s;
}
```

正确顺序是：

```text
① s 先接住 p 原来的后继
② p 再改为指向 s
```

<Callout type="warn" title="先保留旧链接，再改原指针">
若先执行 `p->next = s`，之后又错误地从 `p->next` 获取旧后继，就会丢失原链接。链表题中任何一次指针覆盖前，都要先问：“被覆盖的地址以后还用不用？”
</Callout>

已知 `p` 时，真正插入只修改常数个指针：

$$
O(1)
$$

### 12.2 头插法

带头结点时，在表头插入就是在头结点后插入：

```c
bool InsertAtHead(Node *head, ElementType value) {
    Node *s = (Node *)malloc(sizeof(Node));
    if (s == NULL) return false;

    s->data = value;
    s->next = head->next;
    head->next = s;
    return true;
}
```

单次头插为 $O(1)$。

若按输入顺序不断执行头插，则最终链表中的数据次序通常与输入次序**相反**。

### 12.3 尾插法

若没有维护尾指针，每次尾插都需要先找到尾结点：

```c
bool InsertAtTail(Node *head, ElementType value) {
    Node *tail = head;

    while (tail->next != NULL) {
        tail = tail->next;
    }

    Node *s = (Node *)malloc(sizeof(Node));
    if (s == NULL) return false;

    s->data = value;
    s->next = NULL;
    tail->next = s;
    return true;
}
```

单次尾插最坏为：

$$
O(n)
$$

若始终维护尾指针 `tail`，则尾插可降为：

$$
O(1)
$$

因此用尾插法**批量建表**时，应维护尾指针，避免总复杂度退化为 $O(n^2)$。

### 12.4 按逻辑位置插入

要在第 `pos` 个数据位置插入新元素，需要先找到第 `pos-1` 个数据结点；对于带头结点链表，`pos=1` 时前驱就是头结点。

```c
bool InsertAtPos(Node *head, int pos, ElementType value) {
    if (pos < 1) {
        return false;
    }

    Node *p = head;
    int i = 0;

    while (p != NULL && i < pos - 1) {
        p = p->next;
        ++i;
    }

    if (p == NULL) {
        return false;
    }

    Node *s = (Node *)malloc(sizeof(Node));
    if (s == NULL) {
        return false;
    }

    s->data = value;
    s->next = p->next;
    p->next = s;
    return true;
}
```

总复杂度通常为：

$$
O(n)
$$

因为瓶颈在**查找前驱**，不是最后两次指针赋值。

## 13. 单链表的删除、清空与销毁

### 13.1 删除 `p` 的后继结点

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-006.svg" alt="p q p q p p→next ≠ NULL 时 p→next = q→next free(q);" />

```c
bool DeleteAfter(Node *p) {
    if (p == NULL || p->next == NULL) {
        return false;
    }

    Node *q = p->next;
    p->next = q->next;
    free(q);
    return true;
}
```

已知前驱 `p` 时，删除后继只需常数次操作：

$$
O(1)
$$

### 13.2 删除第 `pos` 个数据结点

```c
bool DeleteAtPos(Node *head, int pos, ElementType *value) {
    if (head == NULL || pos < 1) {
        return false;
    }

    Node *p = head;
    int i = 0;

    while (p->next != NULL && i < pos - 1) {
        p = p->next;
        ++i;
    }

    if (p->next == NULL) {
        return false;
    }

    Node *q = p->next;

    if (value != NULL) {
        *value = q->data;
    }

    p->next = q->next;
    free(q);
    return true;
}
```

复杂度：

- 查找前驱：$O(n)$；
- 修改指针、释放结点：$O(1)$；
- 总体：$O(n)$。

### 13.3 已知当前结点 `p`，能否 $O(1)$ 删除？

在**单链表**中，如果只给出当前结点 `p`，通常拿不到它的前驱，因此不能直接做常规“前驱跨过 `p`”删除。

若 `p` **不是尾结点**，可以使用“复制后继数据”的技巧：

```c
bool DeleteCurrent(Node *p) {
    if (p == NULL || p->next == NULL) {
        return false;
    }

    Node *q = p->next;
    p->data = q->data;
    p->next = q->next;
    free(q);
    return true;
}
```

从逻辑数据序列看，相当于删除了 `p` 原来代表的元素；但实际释放的是后继结点 `q`。若题目强调**结点身份/地址**，则不能机械使用这一技巧。

### 13.4 清空单链表

```c
void ClearList(Node *head) {
    if (head == NULL) return;

    Node *p = head->next;
    head->next = NULL;

    while (p != NULL) {
        Node *q = p->next;
        free(p);
        p = q;
    }
}
```

必须先保存：

```c
q = p->next;
```

再释放 `p`。否则 `free(p)` 后再访问 `p->next` 属于未定义行为。

## 14. 双向链表

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-007.svg" alt="^ a1 a2 a3 prev data next head DNode" />

### 14.1 结点结构

单链表只能方便地获得后继。若经常需要访问前驱，可为每个结点增加 `prev` 指针：

```c
typedef struct DNode {
    ElementType data;
    struct DNode *prev;
    struct DNode *next;
} DNode;
```

双向链表的优点：

- 可向前、向后遍历；
- 已知结点后能直接得到其前驱；
- 已知当前结点时，删除自身通常不必重新从表头找前驱。

代价：

- 每个结点多一个指针域；
- 插入、删除时需要维护更多链接。

### 14.2 在结点 `p` 之前插入 `s`

原结构：

```text
... <-> pre <-> p <-> ...
```

插入后：

```text
... <-> pre <-> s <-> p <-> ...
```

```c
s->prev = p->prev;
s->next = p;
p->prev->next = s;
p->prev = s;
```

可按四句话记忆：

```text
s 找前驱
s 找后继
原前驱找 s
原后继 p 找 s
```

### 14.3 在结点 `p` 之后插入 `s`

若 `p` 不是尾结点，典型操作为：

```c
s->next = p->next;
s->prev = p;
p->next->prev = s;
p->next = s;
```

> **真题标签**
>
> 2023 年第 2 题直接考查双向链表插入时四个指针关系的补全。遇到此类题，最稳妥的方法是先画出 `p`、`s` 与原后继三个结点，再逐条检查正向和反向链接。

### 14.4 删除结点 `p`

```c
p->prev->next = p->next;
p->next->prev = p->prev;
free(p);
```

若没有头尾哨兵结点，还必须额外处理首结点、尾结点等边界情况。

<Callout type="warn" title="双链表要维护两个方向">
只改 `next` 不改 `prev`，或只改 `prev` 不改 `next`，都会破坏双向链表结构。每次插删后都应检查“前驱的后继”和“后继的前驱”是否一致。
</Callout>

## 15. 循环链表

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-009.svg" alt="a 1 a 2 a n head a 2 a 1 a 3 ^ head 循环单链表 循环双链表" />

### 15.1 循环单链表

循环链表让链尾重新连接到链表前部，而不是以 `NULL` 作为普通终点。

带头结点的循环单链表常见形式：

```text
head -> a1 -> a2 -> ... -> an
 ^                       |
 |_______________________|
```

尾结点满足：

```c
tail->next == head
```

遍历时不应机械使用：

```c
while (p != NULL)
```

而应根据结构判断是否回到头结点：

```c
Node *p = head->next;

while (p != head) {
    /* 处理 p */
    p = p->next;
}
```

### 15.2 循环双链表

带头结点的循环双链表在空表时常初始化为：

```c
head->next = head;
head->prev = head;
```

因此判空可写为：

```c
head->next == head
```

非空时通常满足：

```c
head->next->prev == head;
head->prev->next == head;
```

循环双链表可以从任一结点沿 `next` 或 `prev` 方向持续循环。

### 15.3 尾指针的意义

若循环单链表只保存尾指针 `rear`，则：

- 尾结点：`rear`；
- 头结点（若带头结点）：`rear->next`；
- 首元结点：`rear->next->next`。

因此在某些需要频繁访问表头和表尾的场景中，保存尾指针比只保存头指针更方便。

## 16. 静态链表

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-008.svg" alt="2 b 5 a 1 d -1 c 3 0 1 2 3 4 5 6 静态链表示例 a b c d ^ 对应的单链表" />

### 16.1 用数组下标模拟指针

静态链表使用数组保存结点，再用数组下标作为“游标”模拟指针：

```c
#define MAXSIZE 100

typedef struct {
    ElementType data;
    int next;
} SNode;

SNode list[MAXSIZE];
```

其中：

- `data` 保存数据；
- `next` 保存后继结点在数组中的下标；
- `next` 又称**游标**。

例如：

```text
list[2].next = 5
```

表示 `list[2]` 的逻辑后继是：

```c
list[5]
```

原资料采用：

```text
next == -1
```

表示链表结束。

### 16.2 静态链表的本质

静态链表可以概括为：

> **物理上是数组，逻辑上按链表方式连接。**

因此：

- 结点槽位物理上连续存在；
- 有效元素的逻辑次序由游标决定；
- 修改逻辑关系时主要修改游标，无须像普通顺序表一样整体移动后续元素。

它适用于不便使用真实指针、但仍希望利用链式逻辑的场景。
