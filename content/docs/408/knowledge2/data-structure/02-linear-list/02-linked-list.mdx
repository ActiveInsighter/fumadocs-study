链表与顺序表具有相同的线性逻辑结构，但链表不要求数据结点在物理地址上连续，而是依靠**链接信息**表示元素之间的先后关系。

> **链表题的核心不是背整段代码，而是始终知道：当前指针指向谁、改完以后谁还需要被访问、旧链接会不会丢。**

## 9. 链式存储与单链表基础

### 9.1 链式存储的基本思想

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-001.svg" alt="a 1 a 2 a n Linked List L header node NULL" />
<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-002.svg" alt="data next" />
<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-004.svg" alt="图示" />

单链表的每个结点通常包含两部分：

- 数据域 `data`：保存当前元素；
- 指针域 `next`：保存直接后继结点的地址。

```c
typedef struct Node {
    ElementType data;
    struct Node *next;
} Node;
```

逻辑结构可以表示为：

```text
[a1 | •] -> [a2 | •] -> [a3 | •] -> ... -> NULL
```

链表结点**经常**通过 `malloc` / `new` 动态申请，但“动态申请”不是链表的定义条件。链式逻辑也可以通过对象池、静态数组、游标等方式实现。

### 9.2 链表的优缺点

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-003.svg" alt="图示" />

**优点：**

- 不要求整表占据一段连续空间；
- 表长变化较灵活；
- 已知相关结点后，插入和删除通常只需修改常数个链接；
- 插删时不需要整体搬移后续数据元素。

**缺点：**

- 不支持按下标直接随机访问；
- 查找第 $i$ 个结点通常需要从链头逐结点遍历；
- 每个结点需要额外保存指针等链接信息；
- 结点通常较分散，空间局部性一般不如连续数组。

<Callout type="info" title="判断复杂度时先区分“找结点”和“改链接”">
链表的插入 / 删除本身可能只需 $O(1)$，但如果题目只给出逻辑位置，还必须先从表头找到相关结点，总复杂度通常仍是 $O(n)$。
</Callout>

## 10. 头指针、头结点与首元结点

### 10.1 三个概念

带头结点的单链表：

```text
head
  |
  v
[头结点] -> [a1] -> [a2] -> ... -> NULL
```

- **头指针**：`head`，保存链表起始结点的地址；
- **头结点**：人为增加在首元结点之前的辅助结点，通常不属于线性表的有效数据；
- **首元结点**：真正保存 $a_1$ 的第一个数据结点。

采用头结点后：

```c
head->next
```

才指向首元结点。

### 10.2 带头结点与不带头结点

| 情况 | 空表表示 | 插入第一个数据结点时 |
| --- | --- | --- |
| 带头结点 | `head->next == NULL` | 与普通位置操作更容易统一 |
| 不带头结点 | `head == NULL` | 通常需要修改头指针本身 |

引入头结点的主要价值是：

- 统一空表与非空表的处理；
- 统一首元结点与其他结点的插入、删除；
- 减少针对“第一个数据结点”的特殊分支。

### 10.3 初始化与判空

```c
Node *InitList(void) {
    Node *head = (Node *)malloc(sizeof(Node));

    if (head == NULL) {
        return NULL;
    }

    head->next = NULL;
    return head;
}
```

判空：

```c
bool IsEmpty(Node *head) {
    return head != NULL && head->next == NULL;
}
```

<Callout type="warn" title="head == NULL 与空表不是一回事">
对于已经正确创建的带头结点链表，`head == NULL` 表示头指针本身无效；`head->next == NULL` 才表示线性表中没有数据结点。
</Callout>

## 11. 单链表的查找与遍历

### 11.1 按位查找

链表不能像顺序表那样根据下标直接计算目标结点地址，因此查找第 `pos` 个数据结点需要沿 `next` 逐步前进。

```c
Node *GetElem(Node *head, int pos) {
    if (head == NULL || pos < 1) {
        return NULL;
    }

    Node *p = head->next;
    int i = 1;

    while (p != NULL && i < pos) {
        p = p->next;
        ++i;
    }

    return p;
}
```

最坏时间复杂度：

$$
O(n)
$$

### 11.2 按值查找

```c
int LocateElem(Node *head, ElementType value) {
    Node *p = head->next;
    int pos = 1;

    while (p != NULL) {
        if (p->data == value) {
            return pos;
        }

        p = p->next;
        ++pos;
    }

    return 0;
}
```

普通单链表按值查找同样需要线性扫描：

$$
O(n)
$$

### 11.3 遍历时的工作指针

遍历时常用一个临时指针 `p`：

```c
for (Node *p = head->next; p != NULL; p = p->next) {
    /* 处理 p->data */
}
```

只移动工作指针不会改变链表结构；真正修改 `next` 才会改变逻辑关系。

> **单链表的典型特征：按位访问慢，但找到相关位置后改链接快。**

## 12. 单链表的插入与建表

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-005.svg" alt="p q p q n p q n" />

### 12.1 已知结点 `p`，在其后插入 `s`

插入前：

```text
p -> q
```

插入后：

```text
p -> s -> q
```

核心代码：

```c
void InsertNodeAfter(Node *p, Node *s) {
    s->next = p->next;
    p->next = s;
}
```

顺序必须保证：

```text
① s 先接住 p 原来的后继
② p 再改为指向 s
```

<Callout type="warn" title="先保存旧链接，再覆盖原指针">
任何一次指针覆盖前，都先问：“被覆盖的旧地址之后还需不需要？”如果还需要，就必须先保存或让新结点接住它。
</Callout>

已知 `p` 时，真正插入只修改常数个指针：

$$
O(1)
$$

### 12.2 头插法

带头结点时，在表头插入就是在头结点后插入：

```c
bool InsertAtHead(Node *head, ElementType value) {
    Node *s = (Node *)malloc(sizeof(Node));
    if (s == NULL) return false;

    s->data = value;
    s->next = head->next;
    head->next = s;
    return true;
}
```

单次头插为 $O(1)$。

若输入序列为：

```text
1, 2, 3, 4
```

依次头插后链表为：

```text
4 -> 3 -> 2 -> 1
```

因此头插法批量建表会使结点次序与输入次序相反。

### 12.3 尾插法与尾指针

若没有维护尾指针，每次尾插都要先遍历到尾结点：

```c
bool InsertAtTail(Node *head, ElementType value) {
    Node *tail = head;

    while (tail->next != NULL) {
        tail = tail->next;
    }

    Node *s = (Node *)malloc(sizeof(Node));
    if (s == NULL) return false;

    s->data = value;
    s->next = NULL;
    tail->next = s;
    return true;
}
```

单次最坏复杂度为：

$$
O(n)
$$

若批量建表时始终维护尾指针 `tail`：

```c
tail->next = s;
tail = s;
```

则每次尾插可降为 $O(1)$，建立 $n$ 个结点的总时间为 $O(n)$，而不是 $O(n^2)$。

### 12.4 按逻辑位置插入

在第 `pos` 个数据位置插入新元素，需要先找到其前驱。对于带头结点单链表，`pos=1` 时前驱就是头结点。

```c
bool InsertAtPos(Node *head, int pos, ElementType value) {
    if (head == NULL || pos < 1) {
        return false;
    }

    Node *p = head;
    int i = 0;

    while (p != NULL && i < pos - 1) {
        p = p->next;
        ++i;
    }

    if (p == NULL) {
        return false;
    }

    Node *s = (Node *)malloc(sizeof(Node));
    if (s == NULL) {
        return false;
    }

    s->data = value;
    s->next = p->next;
    p->next = s;
    return true;
}
```

复杂度分解：

$$
O(n)+O(1)=O(n)
$$

瓶颈是**查找前驱**，不是最后两次指针赋值。

## 13. 单链表的删除、清空与销毁

### 13.1 删除 `p` 的后继结点

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-006.svg" alt="p q p q p p→next ≠ NULL 时 p→next = q→next free(q);" />

```c
bool DeleteAfter(Node *p) {
    if (p == NULL || p->next == NULL) {
        return false;
    }

    Node *q = p->next;
    p->next = q->next;
    free(q);
    return true;
}
```

已知前驱 `p` 时，删除其后继只需常数次操作：

$$
O(1)
$$

### 13.2 删除第 `pos` 个数据结点

```c
bool DeleteAtPos(Node *head, int pos, ElementType *value) {
    if (head == NULL || pos < 1) {
        return false;
    }

    Node *p = head;
    int i = 0;

    while (p->next != NULL && i < pos - 1) {
        p = p->next;
        ++i;
    }

    if (p->next == NULL) {
        return false;
    }

    Node *q = p->next;

    if (value != NULL) {
        *value = q->data;
    }

    p->next = q->next;
    free(q);
    return true;
}
```

其中：

- 查找前驱：$O(n)$；
- 修改链接并释放结点：$O(1)$；
- 总体：$O(n)$。

### 13.3 只给当前结点 `p`，能否 $O(1)$ 删除？

在单链表中，如果只给出当前结点 `p`，通常无法直接得到它的前驱，因此不能执行常规的“让前驱跨过 `p`”。

若 `p` **不是尾结点**，可以把后继结点的数据复制到 `p`，再删除后继：

```c
bool DeleteCurrent(Node *p) {
    if (p == NULL || p->next == NULL) {
        return false;
    }

    Node *q = p->next;
    p->data = q->data;
    p->next = q->next;
    free(q);
    return true;
}
```

这个技巧从“数据序列”角度实现了删除，但实际释放的是后继结点 `q`。因此若题目关心**结点身份、地址或外部指针引用**，不能机械套用。

### 13.4 清空与销毁的区别

清空：保留头结点，只删除全部数据结点。

```c
void ClearList(Node *head) {
    if (head == NULL) return;

    Node *p = head->next;
    head->next = NULL;

    while (p != NULL) {
        Node *q = p->next;
        free(p);
        p = q;
    }
}
```

必须先保存：

```c
q = p->next;
```

再执行 `free(p)`，否则释放后再访问 `p->next` 属于未定义行为。

若要**销毁整张带头结点链表**，清空数据结点后还需要释放头结点本身，并让外部头指针失效或置空。

## 14. 双向链表

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-007.svg" alt="^ a1 a2 a3 prev data next head DNode" />

### 14.1 结点结构与优势

```c
typedef struct DNode {
    ElementType data;
    struct DNode *prev;
    struct DNode *next;
} DNode;
```

与单链表相比，双向链表多保存一个前驱指针 `prev`，因此：

- 可以向前、向后遍历；
- 已知当前结点后，可以 $O(1)$ 得到直接前驱；
- 已知当前结点时，删除自身通常不必重新从表头查找前驱。

代价是：

- 每个结点多一个指针域；
- 插入、删除时必须同步维护前后两个方向的链接。

### 14.2 在结点 `p` 之前插入 `s`

原结构：

```text
... <-> pre <-> p <-> ...
```

插入后：

```text
... <-> pre <-> s <-> p <-> ...
```

```c
s->prev = p->prev;
s->next = p;
p->prev->next = s;
p->prev = s;
```

可以按“新结点先找两边，再让两边找新结点”记忆：

```text
s 找前驱
s 找后继
原前驱找 s
原后继 p 找 s
```

### 14.3 在结点 `p` 之后插入 `s`

若 `p` 不是尾结点：

```c
s->next = p->next;
s->prev = p;
p->next->prev = s;
p->next = s;
```

> **真题标签**
>
> 2023 年第 2 题直接考查双向链表插入时四个指针关系的补全。遇到这类题，先画出 `p`、`s` 与原后继三个结点，再逐条检查正向与反向链接最稳妥。

### 14.4 删除结点 `p`

若 `p` 的前驱和后继均存在：

```c
p->prev->next = p->next;
p->next->prev = p->prev;
free(p);
```

若没有头尾哨兵结点，还必须额外处理首结点、尾结点等边界情况。

<Callout type="warn" title="双链表每次都要检查两个方向">
插删后至少检查两件事：**前驱的 `next` 是否正确，后继的 `prev` 是否正确。** 只修改一个方向会破坏双向链表的一致性。
</Callout>

## 15. 循环链表

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-009.svg" alt="a 1 a 2 a n head a 2 a 1 a 3 ^ head 循环单链表 循环双链表" />

### 15.1 循环单链表

循环链表把普通链表的“尾部终止”改成“重新连回链表前部”。

带头结点的循环单链表常见形式：

```text
head -> a1 -> a2 -> ... -> an
 ^                       |
 |_______________________|
```

尾结点满足：

```c
tail->next == head
```

遍历时不能机械写：

```c
while (p != NULL)
```

而应根据结构判断是否重新回到头结点：

```c
Node *p = head->next;

while (p != head) {
    /* 处理 p */
    p = p->next;
}
```

### 15.2 循环双链表

带头结点的循环双链表在空表时常初始化为：

```c
head->next = head;
head->prev = head;
```

因此判空条件为：

```c
head->next == head
```

非空时通常满足：

```c
head->next->prev == head;
head->prev->next == head;
```

循环双链表的头结点同时充当首尾之间的连接点，因此很多边界操作可以统一处理。

### 15.3 尾指针的意义

若循环单链表只保存尾指针 `rear`，则：

- 尾结点：`rear`；
- 头结点（若带头结点）：`rear->next`；
- 首元结点：`rear->next->next`。

因此在需要同时频繁访问表头与表尾的场景中，保存尾指针往往比只保存头指针更方便。

## 16. 静态链表

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-008.svg" alt="2 b 5 a 1 d -1 c 3 0 1 2 3 4 5 6 静态链表示例 a b c d ^ 对应的单链表" />

### 16.1 用数组下标模拟指针

静态链表使用数组保存结点，再用数组下标作为“游标”模拟指针：

```c
#define MAXSIZE 100

typedef struct {
    ElementType data;
    int next;
} SNode;

SNode list[MAXSIZE];
```

其中：

- `data` 保存数据；
- `next` 保存后继结点在数组中的下标；
- `next` 又称**游标**。

例如：

```text
list[2].next = 5
```

表示 `list[2]` 的逻辑后继是：

```c
list[5]
```

原资料采用：

```text
next == -1
```

表示链表结束。实际实现中结束标记也可以采用其他约定，必须以题目给出的定义为准。

### 16.2 静态链表的本质

静态链表可以概括为：

> **物理上是数组，逻辑上按链表方式连接。**

因此：

- 所有结点槽位在数组中物理连续；
- 有效元素的逻辑次序由游标决定；
- 插删主要修改游标，无须像普通顺序表那样整体移动后续元素；
- 不使用真实指针，但仍保留链式组织的思想。

它适合不便使用真实指针、但希望利用链式逻辑的场景。

<Callout type="info" title="链表操作统一检查法">
写完任何链表插删代码后，依次检查：**旧后继是否保存、所有链接是否连通、边界结点是否处理、被删除结点是否正确释放、是否误用已释放指针。**
</Callout>
