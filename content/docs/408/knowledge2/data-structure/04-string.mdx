## 1. 串的基本概念

### 1.1 串的定义

**串（String）**是由零个或多个字符组成的有限序列。

若字符取自字符集 $\Sigma$，则串可以表示为：

$$
S=a_1a_2\cdots a_n,\qquad a_i\in\Sigma
$$

其中：

* $n$ 称为**串长**；
* 当 $n=0$ 时，称为**空串**；
* 串中的每个元素都是字符。

从数据结构角度看，串本质上可以理解为一种**特殊的线性表**：

* 线性表中的元素可以是任意数据类型；
* 串中的元素被限定为字符。

### 1.2 空串与空格串

这是一个常见的概念辨析。

**空串**不包含任何字符，因此长度为：

$$
0
$$

而只包含一个空格字符的串：

```text
" "
```

其长度为：

$$
1
$$

因此：

> **空串和空格串不是同一个概念。**

在 C 语言字符串中还要注意 `'\0'`。

例如：

```c
char s[] = "abc";
```

实际内存中通常存放：

```text
'a' 'b' 'c' '\0'
```

但 `'\0'` 是字符串的结束标志，并不属于字符串的逻辑内容，所以字符串 `"abc"` 的长度仍然是 3。

## 2. 与模式匹配有关的几个概念

<InlineSvg src="/images/data-structure/data-structure-strings-match-001.svg" alt={"模式匹配算法核心概念 主串 (Str): 待搜索的完整字符串 A 0 B 1 A 2 B 3 C 4 A 5 B 6 D 7 模式串 (Pattern): 要在主串中查找的目标字符串 C A B 匹配结果: A 0 B 1 A 2 B 3 C 4 A 5 B 6 D 7 匹配位置: 4 核心概念: ■ 主串 (Str) 完整的待搜索字符串 示例: \"ABABCABD\" ■ 子串 (Substr) 主串中的任意连续片段 示例: \"CAB\" (位置4-6) ■ 模式串 (Patt"} />

学习字符串模式匹配之前，需要区分以下概念。

### 2.1 主串

**主串（Text / Main String）**是待搜索的完整字符串。

例如：

```text
ABABCABD
```

### 2.2 子串

串中任意一段**连续字符序列**称为该串的子串。

例如，在：

```text
ABABCABD
```

中：

```text
CAB
```

是一个子串。

> 子串必须连续，子序列则不一定连续，二者不要混淆。

### 2.3 模式串

**模式串（Pattern）**是准备在主串中查找的目标字符串。

例如：

```text
主串：ABABCABD
模式串：CAB
```

模式匹配的目标，就是寻找主串中是否存在一个子串与模式串完全相同。

### 2.4 匹配与失配

* **匹配**：当前比较的两个字符相同；
* **失配**：当前比较的两个字符不同；
* **匹配成功**：模式串中的所有字符均完成匹配；
* **匹配位置**：模式串第一次或指定一次出现时，其首字符在主串中的位置。

## 3. 串的存储结构

串的典型存储方式包括：

1. 定长顺序存储；
2. 堆分配存储；
3. 块链存储。

三种存储结构的内存布局如下：

<InlineSvg src="/images/data-structure/data-structure-strings-def-001.svg" alt={"图示"} />

### 3.1 定长顺序存储

定长顺序存储使用一段预先确定最大容量的连续存储空间保存字符。

需要特别注意：

> **数组容量固定，不代表字符串的逻辑长度固定。**

通常需要单独使用 `length` 保存当前串长。

```c
#define MAX_SIZE 100

typedef struct {
    char data[MAX_SIZE];
    int length;
} FixedString;
```

其中：

* `MAX_SIZE` 是最大容量；
* `length` 是当前实际串长。

其特点是：

* 字符地址连续；
* 随机访问方便；
* 实现简单；
* 最大容量受到数组大小限制。

---

### 3.2 堆分配存储

堆分配存储使用动态申请的连续空间保存字符串。

```c
typedef struct {
    char *data;
    int length;
} HeapString;
};

void initHeapString(HeapString *s, const char *str) {
    s->length = strlen(str);

    s->data = (char *)malloc((s->length + 1) * sizeof(char));

    if (s->data == NULL) {
        exit(1);
    }

    strcpy(s->data, str);
}

void freeHeapString(HeapString *s) {
    free(s->data);
    s->data = NULL;
    s->length = 0;
}
```

这里通常根据字符串的实际长度申请空间。

与固定数组相比：

| 特征     | 定长顺序存储 | 堆分配存储 |
| ------ | ------ | ----- |
| 地址是否连续 | 是      | 是     |
| 最大长度   | 预先固定   | 可动态调整 |
| 空间利用率  | 可能较低   | 较高    |
| 实现复杂度  | 较低     | 较高    |

---

### 3.3 块链存储

块链存储结合了**链表**和**顺序块**的思想。

每个结点不只保存一个字符，而是保存一组字符：

```c
#define BLOCK_SIZE 4

typedef struct StringBlock {
    char data[BLOCK_SIZE];
    struct StringBlock *next;
} StringBlock;

typedef struct {
    StringBlock *head;
    int length;
} BlockString;
};

void initBlockString(BlockString *s) {
    s->head = NULL;
    s->length = 0;
}
```

逻辑结构可以理解为：

```text
┌────────────┐    ┌────────────┐    ┌────────────┐
│ a b c d  ●─┼───→│ e f g h  ●─┼───→│ i j      ∅ │
└────────────┘    └────────────┘    └────────────┘
```

相比“一个结点保存一个字符”的普通链表，这种设计可以减少指针域占据的空间比例。

块链存储的完整实现还需要考虑：

* 插入；
* 删除；
* 块内移动；
* 新块申请；
* 空块释放；
* 销毁。

408 中通常以理解结构思想为主。

## 4. 串的基本操作

### 4.1 赋值 `Assign`

将一个串的内容复制给另一个串。

```text
S = "abc"
T ← S
```

操作后：

```text
T = "abc"
```

---

### 4.2 求长度 `Length`

返回串中的字符数。

例如：

```text
S = "Hello"
```

则：

$$
Length(S)=5
$$

---

### 4.3 比较 `Compare`

一般按字符的字典序比较两个串。

比较过程通常是：

1. 从首字符开始逐个比较；
2. 出现不同字符时，根据字符编码确定大小；
3. 如果某个串先结束，则结合前面字符是否完全相同判断大小。

---

### 4.4 连接 `Concat`

将两个串按顺序拼接。

例如：

```text
S1 = "Hello"
S2 = "World"
```

则：

```text
Concat(S1, S2) = "HelloWorld"
```

---

### 4.5 求子串 `Substr`

从指定位置开始，取得指定长度的连续字符。

例如：

```text
HelloWorld
```

取前 5 个字符可得到：

```text
Hello
```

具体起始下标是 0 还是 1，需要根据题目规定判断。

---

### 4.6 插入 `Insert`

在指定位置插入另一个串。

例如：

```text
HelloWorld
```

插入：

```text
Beautiful
```

后可以得到：

```text
HelloBeautifulWorld
```

---

### 4.7 删除 `Delete`

删除从指定位置开始的若干个字符。

---

### 4.8 替换 `Replace`

将串中的指定子串替换为另一个串。

例如：

```text
apple, banana, apple
```

将：

```text
apple
```

替换为：

```text
orange
```

可得到：

```text
orange, banana, orange
```

---

### 4.9 模式匹配 `Index`

在主串中查找模式串第一次出现的位置。

常见方法包括：

* 朴素模式匹配；
* KMP；
* BM；
* Sunday。

408 中的核心是：

> **朴素模式匹配 + KMP。**

---

### 4.10 清空 `Clear`

将字符串变为空串，并在需要时释放其动态存储空间。

## 5. 模式匹配

设：

* 主串为 `T`；
* 模式串为 `P`；
* 主串长度为 `n`；
* 模式串长度为 `m`。

模式匹配要解决的问题为：

> 在 `T` 中寻找某个与 `P` 完全相同的连续子串。

最直接的方法是朴素模式匹配，更高效的方法则是 KMP。

---

## 6. 朴素模式匹配

朴素模式匹配又称：

* 简单模式匹配；
* 暴力匹配；
* Brute Force。

### 6.1 基本思想

从主串中的每一个可能起点开始尝试匹配模式串。

如果：

```text
T[i] == P[j]
```

则继续比较下一对字符。

一旦出现失配：

```text
T[i] != P[j]
```

便放弃本轮匹配，将模式串移动到主串中的下一个可能起始位置重新比较。

---

### 6.2 匹配过程

假设：

```text
主串：abaaabc
模式串：abc
```

第一次尝试：

```text
abaaabc
abc
```

失配后，从主串下一位置重新开始。

不断重复，直到发现：

```text
abaaabc
    abc
```

匹配成功。

其本质可以概括为：

> **主串中的每一个合法起点，都可能重新与模式串从头比较。**

---

### 6.3 算法实现

```c
int simplePatternMatching(const char *mainStr, const char *pattern) {
    int n = strlen(mainStr);
    int m = strlen(pattern);

    if (n < m) {
        return -1;
    }

    for (int i = 0; i <= n - m; ++i) {
        int j;

        for (j = 0; j < m; ++j) {
            if (mainStr[i + j] != pattern[j]) {
                break;
            }
        }

        if (j == m) {
            return i;
        }
    }

    return -1;
}
```

---

### 6.4 时间复杂度

主串存在：

$$
n-m+1
$$

个可能的匹配起点。

每次最多比较：

$$
m
$$

个字符。

因此最坏时间复杂度为：

$$
O((n-m+1)m)
$$

通常记为：

$$
O(nm)
$$

### 6.5 朴素匹配为什么低效

假设已经成功比较了很多字符，最后一个字符才发生失配。

朴素算法会：

1. 丢弃此前已经获得的所有匹配信息；
2. 主串起始位置向后移动一个字符；
3. 模式串重新从头比较。

也就是说：

> **大量字符可能被重复比较。**

KMP 的核心目的，就是利用已经匹配成功的信息，避免这些无意义的重新比较。

---

## 7. KMP 算法

> **真题考察**
>
> * 2015 年第 8 题
> * 2019 年第 9 题
> * 2024 年第 6 题

KMP 由 Knuth、Morris、Pratt 提出。

它解决的核心问题是：

> 当模式串发生失配时，如何根据模式串自身已经匹配的部分，直接决定模式串应该跳到哪里，而不是让主串重新回退。

---

## 8. 理解 KMP 的关键：前缀与后缀

### 8.1 前缀

字符串的**前缀**是从字符串首字符开始的一段连续子串。

以：

```text
abcdabc
```

为例，前缀包括：

```text
a
ab
abc
abcd
abcda
abcdab
abcdabc
```

### 8.2 真前缀

不等于字符串本身的前缀称为**真前缀**。

因此 `abcdabc` 的真前缀包括：

```text
a
ab
abc
abcd
abcda
abcdab
```

---

### 8.3 后缀

字符串的后缀是以最后一个字符结束的一段连续子串。

例如：

```text
abcdabc
```

的后缀包括：

```text
c
bc
abc
dabc
cdabc
bcdabc
abcdabc
```

### 8.4 真后缀

不等于字符串本身的后缀称为**真后缀**。

---

### 8.5 最长相等真前后缀

对于：

```text
abcdabc
```

可以发现：

```text
abc
```

既是其真前缀，也是其真后缀。

<InlineSvg src="/images/data-structure/data-structure-strings-match-002.svg" alt={"前后缀概念图解 - 字符串 \"abcdabc\" a b c d a b c 0 1 2 3 4 5 6 前缀 (Prefix): 从字符串开头开始的子串 a \"a\" (长度1) a b \"ab\" (长度2) a b c \"abc\" (长度3) a b c d \"abcd\" (长度4) 后缀 (Suffix): 到字符串末尾结束的子串 c \"c\" (长度1) b c \"bc\" (长度2) a b c \"abc\" (长度3) d a b c \"dabc\" (长度4) 关键发现：相"} />

于是其最长相等真前后缀长度为：

$$
3
$$

这个“最长相等真前后缀”的信息，就是 KMP 失配跳转的依据。

---

## 9. KMP 为什么不需要让主串指针回退

假设某次已经完成：

```text
T: ... a b a b a X ...
P:     a b a b a Y
```

前面的若干字符已经证明相等：

```text
T[i-j \ldots i-1]
=
P[0 \ldots j-1]
```

如果此时：

```text
T[i] != P[j]
```

朴素算法会改变主串起点。

而 KMP 注意到：

> 已经匹配成功的那一段主串内容是确定的，因此可以利用模式串自身的前后缀关系，直接判断下一次模式串应该从哪个位置继续比较。

因此：

* 主串位置 `i` 通常不回退；
* 只调整模式串位置 `j`。

这也是理解 KMP 最重要的一句话：

> **KMP 的本质不是“不比较”，而是利用已知匹配信息避免主串回退和重复比较。**

## 10. 三套容易混淆的定义

KMP 最容易错的地方不是算法思想，而是不同教材对数组的定义不同。

常见的有：

1. LPS；
2. 经典 `next`；
3. `nextval`。

做题前必须首先判断题目采用哪种定义。

---

## 11. LPS 数组

LPS 是：

**Longest Proper Prefix which is also Suffix**

即：

> 一个前缀子串的最长相等真前缀与真后缀的长度。

设模式串为：

```text
ababac
```

其每个前缀对应的 LPS 为：

| 下标   | 0   | 1    | 2     | 3      | 4       | 5        |
| ---- | --- | ---- | ----- | ------ | ------- | -------- |
| 字符   | a   | b    | a     | b      | a       | c        |
| 当前前缀 | `a` | `ab` | `aba` | `abab` | `ababa` | `ababac` |
| LPS  | 0   | 0    | 1     | 2      | 3       | 0        |

例如：

```text
ababa
```

最长相等真前后缀为：

```text
aba
```

因此：

$$
LPS[4]=3
$$

---

## 12. 经典 `next` 数组

本章采用一种常见的 **0 基下标经典 `next` 定义**：

```text
next[0] = -1
```

当模式串的第 `j` 个字符发生失配时，根据：

```text
j = next[j]
```

确定新的模式串比较位置。

对于：

```text
ababac
```

可以得到：

| pattern | a  | b | a | b | a | c |
| ------- | -- | - | - | - | - | - |
| index   | 0  | 1 | 2 | 3 | 4 | 5 |
| LPS     | 0  | 0 | 1 | 2 | 3 | 0 |
| `next`  | -1 | 0 | 0 | 1 | 2 | 3 |

在这一约定下：

$$
next[0]=-1
$$

而对于：

$$
j\geq1
$$

可以把 `next[j]` 理解为：

> `pattern[0 ... j-1]` 的最长相等真前后缀长度。

因此：

```text
pattern = ababac
```

计算 `next[5]` 时，只研究 `c` 之前的部分：

```text
ababa
```

它的最长相等真前后缀为：

```text
aba
```

长度为：

$$
3
$$

所以：

$$
next[5]=3
$$

---

## 13. `next` 与 LPS 的关系

这是非常重要的易错点。

仍然以：

```text
ababac
```

为例：

```text
LPS  = [0, 0, 1, 2, 3, 0]
next = [-1, 0, 0, 1, 2, 3]
```

可以看出，在本章采用的经典定义下，`next` 可以理解为将前缀信息向右错开一位，并令：

```text
next[0] = -1
```

即：

$$
next[j]=LPS[j-1],\qquad j\geq1
$$

> **易错点**
>
> `LPS[j]` 与 `next[j]` 的含义不同，不能看到数字后直接互换。
>
> 做题必须先根据题目给出的：
>
> * 初值；
> * 下标；
> * 数组定义；
>
> 判断采用的是哪一种规则。

---

## 14. 使用 `next` 进行失配跳转

设：

* `i`：主串当前比较位置；
* `j`：模式串当前比较位置。

若：

```text
text[i] == pattern[j]
```

则：

```text
i++;
j++;
```

若失配：

```text
text[i] != pattern[j]
```

则根据 `next[j]` 调整模式串位置。

经典写法可表示为：

```c
if (j == -1 || text[i] == pattern[j]) {
    ++i;
    ++j;
} else {
    j = next[j];
}
```

其中当：

```text
j == -1
```

时，意味着模式串第一个字符也无法与当前主串字符匹配，此时主串向后移动一位，并令：

```text
j = 0
```

重新开始比较。

## 15. KMP 匹配示例

例如：

```text
主串：ababcabcabababd
模式串：ababd
```

模式串：

| index | 0  | 1 | 2 | 3 | 4 |
| ----- | -- | - | - | - | - |
| char  | a  | b | a | b | d |
| next  | -1 | 0 | 0 | 1 | 2 |

当已经匹配：

```text
abab
```

随后遇到：

```text
c != d
```

时，并不让主串回退。

根据：

```text
next[4] = 2
```

直接令：

```text
j = 2
```

也就是利用已经匹配成功的：

```text
ab
```

继续尝试。

这正是 KMP 比朴素匹配高效的根本原因。

## 16. 使用 LPS 实现 KMP

现代程序设计中经常直接采用 LPS，而不是教材中的经典 `next`。

需要再次强调：

```text
lps[0] = 0
```

与：

```text
next[0] = -1
```

属于两种不同定义。

---

## 17. LPS 的构造

```c
void computeLPS(const char *pattern, int m, int lps[]) {
    int len = 0;

    lps[0] = 0;

    for (int i = 1; i < m; ) {
        if (pattern[i] == pattern[len]) {
            lps[i] = len + 1;
            ++len;
            ++i;
        } else if (len > 0) {
            len = lps[len - 1];
        } else {
            lps[i] = 0;
            ++i;
        }
    }
}
```

其中 `len` 表示当前已经找到的最长相等真前后缀长度。

当：

```text
pattern[i] == pattern[len]
```

时，可在已有相等前后缀基础上继续延长。

因此：

```c
lps[i] = len + 1;
```

如果失配但：

```text
len > 0
```

则并不直接归零，而是利用已经计算出的 LPS：

```c
len = lps[len - 1];
```

继续寻找更短的候选前后缀。

---

## 18. 完整 KMP 实现

```c
int KMP(const char *text, const char *pattern) {
    int n = strlen(text);
    int m = strlen(pattern);

    if (m == 0) {
        return 0;
    }

    int lps[m];

    computeLPS(pattern, m, lps);

    int i = 0;
    int j = 0;

    while (i < n) {
        if (text[i] == pattern[j]) {
            ++i;
            ++j;

            if (j == m) {
                return i - m;
            }
        } else if (j > 0) {
            j = lps[j - 1];
        } else {
            ++i;
        }
    }

    return -1;
}
```

KMP 中非常值得注意的是：

```c
j = lps[j - 1];
```

发生时：

```text
i 不变
```

即：

> **主串当前字符继续参与下一轮比较。**

---

## 19. KMP 的时间复杂度

构造模式串辅助数组的时间复杂度为：

$$
O(m)
$$

扫描主串的时间复杂度为：

$$
O(n)
$$

因此总时间复杂度为：

$$
O(n+m)
$$

如果保存长度为 `m` 的 LPS 或 `next` 数组，则额外空间复杂度为：

$$
O(m)
$$

## 20. 朴素匹配与 KMP 对比

| 项目        | 朴素匹配      | KMP                   |
| --------- | --------- | --------------------- |
| 失配后模式串    | 从头开始      | 根据前后缀跳转               |
| 主串指针      | 可能回退      | 不需要回退                 |
| 是否利用模式串结构 | 否         | 是                     |
| 最坏时间复杂度   | $O(nm)$ | $O(n+m)$            |
| 辅助空间      | $O(1)$  | $O(m)$              |
| 408 重点    | 理解过程      | `next`、`nextval`、匹配过程 |

## 21. `nextval` 数组

经典 `next` 已经能够避免主串回退，但仍有进一步优化空间。

问题主要出现在：

```text
pattern[j] == pattern[next[j]]
```

这种情况。

---

## 22. 为什么还需要 `nextval`

假设模式串第 `j` 个字符已经与主串字符失配：

```text
text[i] != pattern[j]
```

按照普通 `next`：

```text
j = next[j]
```

但如果：

```text
pattern[j] == pattern[next[j]]
```

那么新的：

```text
pattern[next[j]]
```

与刚刚失败的 `pattern[j]` 是同一个字符。

既然：

```text
text[i] != pattern[j]
```

而：

```text
pattern[j] == pattern[next[j]]
```

那么必然也有：

```text
text[i] != pattern[next[j]]
```

因此再比较一次完全没有意义。

`nextval` 的作用就是：

> **直接跳过这些已经可以确定必然失败的位置。**

---

## 23. `nextval` 的计算规则

本节继续采用：

```text
next[0] = -1
```

这一经典约定。

若：

```text
pattern[j] != pattern[next[j]]
```

则：

```text
nextval[j] = next[j]
```

如果：

```text
pattern[j] == pattern[next[j]]
```

则：

```text
nextval[j] = nextval[next[j]]
```

即继续向前寻找。

---

## 24. `nextval` 代码

```c
if (next[i] == -1) {
    nextval[i] = -1;
} else {
    int k = next[i];

    while (k != -1 && pattern[i] == pattern[k]) {
        k = nextval[k];
    }

    nextval[i] = k;
}
```

其中 `while` 的含义是：

> 如果跳转后仍然会比较相同字符，就继续沿着 `nextval` 向前跳，直到找到不同字符或者到达 `-1`。

---

## 25. `nextval` 示例

模式串：

```text
ababaa
```

先得到经典 `next`：

| pattern | a  | b | a | b | a | a |
| ------- | -- | - | - | - | - | - |
| index   | 0  | 1 | 2 | 3 | 4 | 5 |
| `next`  | -1 | 0 | 0 | 1 | 2 | 3 |

接下来计算 `nextval`。

---

#### `nextval[0]`

按照规定：

```text
nextval[0] = -1
```

---

#### `nextval[1]`

有：

```text
next[1] = 0
```

比较：

```text
pattern[1] = b
pattern[0] = a
```

二者不同，因此保留：

```text
nextval[1] = 0
```

---

#### `nextval[2]`

有：

```text
next[2] = 0
```

比较：

```text
pattern[2] = a
pattern[0] = a
```

相同，因此直接继续跳：

```text
nextval[2] = nextval[0] = -1
```

---

#### `nextval[3]`

有：

```text
next[3] = 1
```

而：

```text
pattern[3] = b
pattern[1] = b
```

相同，因此：

```text
nextval[3] = nextval[1] = 0
```

---

#### `nextval[4]`

有：

```text
next[4] = 2
```

而：

```text
pattern[4] = a
pattern[2] = a
```

相同，因此：

```text
nextval[4] = nextval[2] = -1
```

---

#### `nextval[5]`

有：

```text
next[5] = 3
```

比较：

```text
pattern[5] = a
pattern[3] = b
```

不同，因此：

```text
nextval[5] = 3
```

最终得到：

| pattern   | a  | b | a  | b | a  | a |
| --------- | -- | - | -- | - | -- | - |
| index     | 0  | 1 | 2  | 3 | 4  | 5 |
| `next`    | -1 | 0 | 0  | 1 | 2  | 3 |
| `nextval` | -1 | 0 | -1 | 0 | -1 | 3 |

## 26. `next` 与 `nextval` 的本质区别

可以用一句话概括：

> **`next` 解决“失配后去哪里”，`nextval` 进一步解决“别跳到一个必然再次失配的位置”。**

因此：

```text
next
```

已经能够保证 KMP 正确工作。

而：

```text
nextval
```

只是在某些具有大量重复字符的模式串中进一步减少无效比较。

---

## 27. 手算 `next` 的稳定方法

考试中最推荐的思考方式不是死背数组，而是：

> **计算当前位置之前的字符串，其最长相等真前后缀长度。**

仍采用：

```text
next[0] = -1
```

例如求模式串：

```text
ababac
```

的：

```text
next[5]
```

第 5 位是：

```text
c
```

只观察它之前的：

```text
ababa
```

列出真前缀：

```text
a
ab
aba
abab
```

列出真后缀：

```text
a
ba
aba
baba
```

最长相同部分：

```text
aba
```

长度为：

$$
3
$$

因此：

```text
next[5] = 3
```

这种方法特别适合选择题和短模式串。

## 28. KMP 高频易错点

### 28.1 把 LPS 当成 `next`

例如：

```text
ababac
```

LPS：

```text
0 0 1 2 3 0
```

经典 `next`：

```text
-1 0 0 1 2 3
```

二者明显不同。

看到题目时不要直接套记忆中的数组。

---

### 28.2 忽略下标从 0 还是从 1 开始

不同教材可能采用：

```text
next[0] = -1
```

也可能采用：

```text
next[1] = 0
```

甚至还存在其他等价定义。

因此做题第一步应该观察题目：

> **数组首元素到底给了什么。**

---

### 28.3 把“前后缀”理解成任意子串

前缀必须：

```text
从首字符开始
```

后缀必须：

```text
以最后一个字符结束
```

都不能从中间任意截取。

---

### 28.4 忘记“真”前后缀不能包含整个串本身

任意字符串本身当然同时是自己的前缀和后缀。

如果允许使用完整字符串，则最长公共前后缀永远都是字符串本身，没有意义。

因此 KMP 讨论的是：

> **真前缀和真后缀。**

---

### 28.5 KMP 失配时错误地让主串 `i` 回退

KMP 的核心性质就是：

> **利用已知匹配信息，使主串指针不回退。**

失配通常调整的是：

```text
j
```

而不是重新计算：

```text
i
```

---

### 28.6 `nextval` 与 `next` 的适用定义混用

`nextval` 是建立在特定经典 `next` 定义基础上的优化。

若题目采用的是 LPS / 前缀函数，则通常不会再用同样形式的 `nextval`。

---

## 29. 一道 KMP 题应该怎么做

如果考试要求计算 `next`、`nextval` 或匹配过程，可以按以下顺序处理。

#### 第一步：确认下标体系

看题目是：

```text
0 基
```

还是：

```text
1 基
```

#### 第二步：确认初值

例如：

```text
next[0] = -1
```

或：

```text
next[1] = 0
```

由此判断采用哪种定义。

#### 第三步：逐位置寻找最长相等真前后缀

不要凭感觉跳。

对于每一个位置，明确对应的前缀子串。

#### 第四步：得到完整 `next`

先保证 `next` 正确，再计算 `nextval`。

#### 第五步：计算 `nextval`

检查：

```text
pattern[j]
```

与：

```text
pattern[next[j]]
```

是否相同。

相同时继续向前跳。

#### 第六步：模拟匹配

失配时：

```text
j = next[j]
```

或使用题目指定的跳转规则。

注意主串下标是否变化。

## 31. 408 章末速记

#### 串

串是：

> **字符组成的有限序列。**

空串长度：

$$
0
$$

空格串长度：

$$
\neq 0
$$

---

#### 朴素模式匹配

核心：

> **每个可能起点重新从模式串首字符开始比较。**

最坏时间复杂度：

$$
O(nm)
$$

---

#### KMP

核心：

> **利用模式串自身的前后缀信息进行失配跳转，使主串指针不回退。**

时间复杂度：

$$
O(n+m)
$$

额外空间复杂度：

$$
O(m)
$$

---

#### LPS

含义：

> **当前前缀的最长相等真前后缀长度。**

例如：

```text
ababac
```

得到：

```text
LPS = 0 0 1 2 3 0
```

---

#### 经典 `next`

本章约定：

```text
next[0] = -1
```

对于：

```text
ababac
```

有：

```text
next = -1 0 0 1 2 3
```

失配时核心操作：

```text
j = next[j]
```

---

#### `nextval`

作用：

> **避免跳转后再次比较一个已经可以确定必然失配的相同字符。**

若：

```text
pattern[j] == pattern[next[j]]
```

则进一步使用：

```text
nextval[next[j]]
```

进行跳转。

---

> **最后检查**
>
> 做 KMP 题之前，一定先问自己三个问题：
>
> 1. 下标从 0 还是 1 开始？
> 2. `next` 的第一个值是什么？
> 3. 题目求的是 `next`、LPS，还是 `nextval`？
>
> 这三个问题确认清楚后，大多数 KMP 题就只是机械计算。
