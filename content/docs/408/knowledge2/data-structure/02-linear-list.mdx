线性表是数据结构中最基础的线性结构之一。它描述元素之间的**一对一前驱—后继关系**。

顺序表和链表具有相同的逻辑结构，但采用不同的物理存储方式，因此它们在**随机访问、插入删除、空间开销和缓存局部性**等方面存在明显差异。

<InlineSvg src="/images/data-structure/data-structure-linearlist-001.svg" alt={"线性表及其顺序存储与链式存储"} />

| 存储方式 | 核心特点       | 按位访问   | 插入、删除            | 额外空间  |
| ---- | ---------- | ------ | ---------------- | ----- |
| 顺序表  | 元素连续存储     | `O(1)` | 通常 `O(n)`        | 较少    |
| 链表   | 通过指针建立逻辑关系 | `O(n)` | 已知操作位置后通常 `O(1)` | 需要指针域 |

> **408 复习重点**
>
> 线性表本身的定义通常不是难点。真正需要重点掌握的是：
>
> * 顺序表的插入、删除和复杂度；
> * 单链表中指针的修改顺序；
> * 头结点、头指针、首元结点的区别；
> * 双向链表和循环链表；
> * 链表算法设计，如逆置、倒数第 $k$ 个结点、公共结点等。
>
> 特别注意：所谓“链表插入、删除是 `O(1)`”通常有一个重要前提——**已经找到了相关结点或前驱结点**。如果还需要从头查找位置，总复杂度仍可能是 `O(n)`。

## 1. 线性表的定义与基本操作

### 1.1 线性表的定义

<InlineSvg src="/images/data-structure/data-structure-linearlist-def-001.svg" alt={"线性表 Linear List L = (a₁, a₂, a₃, ..., aᵢ, aᵢ₊₁, ..., aₙ) a₁ a₂ a₃ ... aᵢ aᵢ₊₁ ... aₙ 当前元素 前驱 后继 线性表特点： 个数有限： 表中元素个数是确定的有限值 类型相同： 所有元素数据类型一致，占用相同存储空间 逻辑有序： 元素间存在先后顺序，有前驱和后继关系"} />

**线性表（Linear List）**是由**零个或多个具有相同数据类型的数据元素组成的有限序列**。

记为：

$$
L=(a_1,a_2,\ldots,a_i,a_{i+1},\ldots,a_n)
$$

其中：

* $n$ 为线性表的长度；
* 当 $n=0$ 时，称为空表；
* $a_1$ 是第一个数据元素；
* $a_n$ 是最后一个数据元素。

在线性表中：

* $a_1$ 没有前驱；
* $a_n$ 没有后继；
* 对于中间元素 $a_i$，其直接前驱为 $a_{i-1}$，直接后继为 $a_{i+1}$。

线性表具有三个基本特征：

1. **元素个数有限**；
2. **元素数据类型相同**；
3. **元素之间存在确定的逻辑次序**。

这里讨论的是元素之间的**逻辑关系**，并不要求它们在物理内存中一定连续。

---

### 1.2 顺序表与链表

线性表可以采用两类典型存储方式：

* **顺序存储**：形成顺序表；
* **链式存储**：形成链表。

<InlineSvg src="/images/data-structure/data-structure-linearlist-def-002.svg" alt={"1 2 3 4 5 1 3 2 物 理 地 址 逐 渐 增 大 顺序表 链表 5 4 物 理 地 址 逐 渐 增 大"} />

#### 顺序表

顺序表要求元素存储在一段**地址连续的存储区域**中。

因此：

* 逻辑上相邻的元素在物理上也相邻；
* 可以根据首地址和元素下标直接计算地址；
* 支持随机访问。

#### 链表

链表的结点通过指针或游标保存后继关系。

因此：

* 逻辑上相邻的结点在物理地址上不要求连续；
* 通常不能通过下标直接定位某个结点；
* 插入、删除时无需像顺序表一样整体移动大量元素。

> **易错点：存储结构与“栈区 / 堆区”没有必然联系**
>
> 顺序表的定义依据是**元素地址连续**，链表的定义依据是**通过链接信息维护逻辑关系**。
>
> 顺序表既可以位于栈区，也可以位于堆区或静态存储区；链表结点也不一定必须通过 `malloc` 动态申请。

---

### 1.3 线性表的抽象操作

<InlineSvg src="/images/data-structure/data-structure-linearlist-def-003.svg" alt={"图示"} />

常见基本操作如下。

| 操作           | 含义           |
| ------------ | ------------ |
| `InitList`   | 初始化一个空线性表    |
| `Insert`     | 在指定位置插入新元素   |
| `Delete`     | 删除指定位置的元素    |
| `LocateElem` | 根据元素值或条件查找元素 |
| `GetElem`    | 获取指定逻辑位置上的元素 |
| `SetElem`    | 修改指定位置元素的值   |
| `Length`     | 返回线性表长度      |
| `IsEmpty`    | 判断线性表是否为空    |
| `ClearList`  | 清空线性表        |
| `Traverse`   | 按顺序访问所有元素    |

这些都是**逻辑层面的操作**。顺序表和链表会采用完全不同的底层实现。

## 2. 顺序表

### 2.1 顺序表的存储结构

**顺序表（Sequential List）**使用一段连续的存储空间依次保存线性表中的数据元素。

假设：

* 顺序表首地址为 `LOC(A)`；
* 每个元素占用的空间为 `sizeof(Elem)`；
* $a_i$ 是第 $i$ 个数据元素。

则 $a_i$ 的地址为：

$$
LOC(a_i)=LOC(A)+(i-1)\times sizeof(Elem)
$$

<InlineSvg src="/images/data-structure/data-structure-linearlist-sequential-001.svg" alt={"a 1 a i a 2 a n Sequential List A Index 0 1 i-1 n-1 Memory Address LOC(A) LOC(A) + sizeof(Elem) LOC(A) + (i-1) x sizeof(Elem) Maxsize - 1 LOC(A) + (n-1) x sizeof(Elem) LOC(A) + (Maxsize-1) x sizeof(Elem)"} />

这就是顺序表可以进行**随机访问**的根本原因。

只要知道：

* 首地址；
* 元素大小；
* 下标；

就可以直接计算目标元素的地址，而不需要逐个访问前面的元素。

---

### 2.2 顺序表的特点

#### 优点

* **随机访问效率高**：按位置访问为 `O(1)`；
* **存储密度高**：不需要额外保存指针；
* **空间局部性好**：相邻元素物理地址连续，有利于 CPU Cache；
* **结构简单**：操作时无需维护指针关系。

#### 缺点

* **插入和删除可能需要移动大量元素**；
* 静态数组需要提前确定最大容量；
* 动态扩容时可能需要重新分配空间并复制数据；
* 若预留空间过大，会造成空间浪费。

---

### 2.3 顺序表的定义与初始化

下面使用固定长度数组实现顺序表：

```c
#define MAXSIZE 100

typedef struct {
    ElementType data[MAXSIZE];
    int length;
} SeqList;
```

其中：

* `data` 保存数据元素；
* `length` 保存当前有效元素个数；
* `MAXSIZE` 表示顺序表最大容量。

初始化：

```c
void InitList(SeqList *L) {
    L->length = 0;
}
```

<InlineSvg src="/images/data-structure/data-structure-linearlist-sequential-002.svg" alt={"图示"} />

> **逻辑位置与数组下标**
>
> 408 题目通常将线性表的第一个元素称为“第 1 个元素”，即逻辑位置从 1 开始。
>
> C 数组下标从 0 开始，因此：
>
> * 第 1 个元素对应 `data[0]`；
> * 第 `pos` 个元素对应 `data[pos - 1]`。
>
> 这是顺序表代码中最容易出现的下标错误之一。

---

### 2.4 顺序表的插入

若要在第 `pos` 个位置插入新元素 `e`，原来从该位置开始的元素都需要向后移动一位。

<InlineSvg src="/images/data-structure/data-structure-linearlist-sequential-003.svg" alt={"顺序表插入过程图解：在位置 3 插入元素 99 步骤1：初始状态 10 20 30 40 50 1 2 3 4 5 6 7 length = 5 插入位置 pos=3 步骤2：从尾部开始，向后移动元素 10 20 30 40 50 50 移动 10 20 30 40 40 50 移动 10 20 30 30 40 50 移动 步骤3：插入新元素并更新长度 10 20 99 30 40 50 新元素 99 length = 6 关键要点： 1. 检查插入位置合法性：1 ≤ po"} />

```c
bool Insert(SeqList *L, int pos, ElementType e) {
    if (L->length == MAXSIZE ||
        pos < 1 ||
        pos > L->length + 1) {
        return false;
    }

    for (int i = L->length; i >= pos; --i) {
        L->data[i] = L->data[i - 1];
    }

    L->data[pos - 1] = e;
    ++L->length;

    return true;
}
```

#### 插入位置是否合法

长度为 $n$ 的顺序表共有 $n+1$ 个合法插入位置：

$$
1\leq pos\leq n+1
$$

例如一个长度为 5 的顺序表，可以：

* 在第 1 个位置插入；
* 在第 6 个位置插入，即尾插。

#### 元素移动次数

若在第 $i$ 个位置插入，需要移动：

$$
n-i+1
$$

个元素。

因此：

| 情况   |      移动次数 | 时间复杂度  |
| ---- | --------: | ------ |
| 尾部插入 |         0 | `O(1)` |
| 头部插入 |     $n$ | `O(n)` |
| 平均情况 | 约 $n/2$ | `O(n)` |

> **易错点**
>
> 元素一定要**从后向前移动**。
>
> 如果从前向后移动，尚未保存的元素可能会被后面的赋值覆盖。

---

### 2.5 顺序表的删除

删除第 `pos` 个元素后，需要将后面的元素全部向前移动一位。

<InlineSvg src="/images/data-structure/data-structure-linearlist-sequential-004.svg" alt={"图示"} />

```c
bool Delete(SeqList *L, int pos, ElementType *e) {
    if (pos < 1 || pos > L->length) {
        return false;
    }

    *e = L->data[pos - 1];

    for (int i = pos; i < L->length; ++i) {
        L->data[i - 1] = L->data[i];
    }

    --L->length;

    return true;
}
```

合法删除位置满足：

$$
1\leq pos\leq n
$$

若删除第 $i$ 个元素，需要移动：

$$
n-i
$$

个元素。

| 情况       |          移动次数 | 时间复杂度  |
| -------- | ------------: | ------ |
| 删除最后一个元素 |             0 | `O(1)` |
| 删除第一个元素  |       $n-1$ | `O(n)` |
| 平均情况     | 约 $(n-1)/2$ | `O(n)` |

---

### 2.6 顺序表的查找

#### 按值查找

在线性表中顺序扫描，寻找第一个值等于 `e` 的元素：

```c
int LocateElem(SeqList L, ElementType e) {
    for (int i = 0; i < L.length; ++i) {
        if (L.data[i] == e) {
            return i + 1;
        }
    }

    return 0;
}
```

时间复杂度为 `O(n)`。

#### 按位查找

顺序表支持随机访问，因此获取第 `pos` 个元素不需要遍历：

```c
bool GetElem(SeqList L, int pos, ElementType *e) {
    if (pos < 1 || pos > L.length) {
        return false;
    }

    *e = L.data[pos - 1];
    return true;
}
```

时间复杂度为 `O(1)`。

> **408 高频区分**
>
> * **按位查找**：已知“第几个元素”，顺序表为 `O(1)`；
> * **按值查找**：已知元素值，需要扫描，普通顺序表为 `O(n)`。
>
> “顺序表支持随机访问”并不意味着“所有查找都是 `O(1)`”。

---

### 2.7 其他基本操作

#### 判空

```c
bool IsEmpty(SeqList L) {
    return L.length == 0;
}
```

#### 清空

```c
void ClearList(SeqList *L) {
    L->length = 0;
}
```

对于固定数组实现，只需要将有效长度置为 0。

数组中的旧内容可能仍存在于物理存储中，但从线性表的逻辑意义上已经不存在。

#### 获取长度

```c
int Length(SeqList L) {
    return L.length;
}
```

---

### 2.8 顺序表复杂度总结

| 操作     | 时间复杂度  |
| ------ | ------ |
| 按位访问   | `O(1)` |
| 按值查找   | `O(n)` |
| 头部插入   | `O(n)` |
| 尾部插入   | `O(1)` |
| 一般位置插入 | `O(n)` |
| 删除尾元素  | `O(1)` |
| 删除一般位置 | `O(n)` |
| 求长度    | `O(1)` |

## 3. 链表

### 3.1 链式存储的基本思想

线性表的**链式表示**通过一组结点保存数据。

每个结点不仅保存数据，还保存用于表示逻辑关系的链接信息。

对于单链表，每个结点包括：

* 数据域 `data`；
* 后继指针域 `next`。

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-001.svg" alt={"a 1 a 2 a n Linked List L header node NULL"} />

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-002.svg" alt={"data next"} />

单链表最重要的特征是：

> **结点之间通过指针建立逻辑关系，物理地址不要求连续。**

链表结点在实际程序中经常通过 `malloc` 或 `new` 动态申请，但这不是链表的定义条件。结点也可以来自静态数组、对象池或其他存储管理机制。

---

### 3.2 链表的优缺点

#### 优点

* 不要求整体连续的存储空间；
* 表长可以灵活变化；
* 已知相关结点后，插入和删除通常只需要修改指针；
* 不需要像顺序表一样移动大量元素。

#### 缺点

* 不支持真正的随机访问；
* 查找第 $i$ 个结点通常需要从前向后遍历；
* 每个结点需要额外保存指针；
* 结点物理位置通常较分散，缓存局部性往往不如连续数组。

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-003.svg" alt={"图示"} />

连续数组中相邻元素地址相邻，因此顺序访问通常具有较好的空间局部性。

链表结点则可能分散在不同位置，访问下一个结点需要根据指针取得其地址。

> **易错点**
>
> “数组一定在栈上、链表一定在堆上”是错误的。
>
> 数组可以动态申请到堆中，链表也可以使用静态数组模拟。
>
> 判断顺序存储和链式存储的依据是**元素之间如何建立物理和逻辑关系**，而不是变量位于哪个内存区域。

## 4. 单链表

### 4.1 单链表结点定义

```c
typedef struct Node {
    int data;
    struct Node *next;
} Node;
```

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-004.svg" alt={"图示"} />

其中：

* `data` 保存数据；
* `next` 保存下一个结点的地址。

`data` 的类型可以根据需要换成其他类型。

例如：

```c
typedef struct Node {
    ElementType data;
    struct Node *next;
} Node;
```

---

### 4.2 头指针、头结点和首元结点

这是 408 中非常容易混淆的一组概念。

假设链表采用带头结点的形式：

```text
head
 ↓
[头结点] → [a1] → [a2] → ... → NULL
```

#### 头指针

`head` 是指向链表起始位置的指针。

#### 头结点

人为增加在第一个数据结点之前的辅助结点。

通常不保存有效数据。

#### 首元结点

真正保存线性表第一个数据元素 $a_1$ 的结点。

采用头结点后：

```c
head->next
```

才指向首元结点。

引入头结点的主要作用是：

* 统一空表和非空表的操作；
* 统一首元结点和其他结点的插入、删除处理；
* 减少特殊情况判断。

---

### 4.3 初始化

创建一个带头结点的空单链表：

```c
Node *InitList(void) {
    Node *head = (Node *)malloc(sizeof(Node));

    if (head == NULL) {
        exit(1);
    }

    head->next = NULL;

    return head;
}
```

空表结构为：

```text
head
 ↓
[头结点] → NULL
```

---

### 4.4 判空

```c
bool IsEmpty(Node *head) {
    return head->next == NULL;
}
```

注意：

```c
head == NULL
```

和

```c
head->next == NULL
```

含义不同。

对于已经正常初始化的带头结点链表：

* `head == NULL` 通常表示头指针本身无效；
* `head->next == NULL` 才表示线性表为空。

## 5. 单链表的插入

### 5.1 在结点后插入

假设：

* `p` 指向某个已有结点；
* `s` 指向待插入的新结点。

希望将 `s` 插入 `p` 之后。

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-005.svg" alt={"p q p q n p q n"} />

原结构：

```text
p → q
```

插入后：

```text
p → s → q
```

核心代码：

```c
void InsertNodeAfter(Node *p, Node *s) {
    s->next = p->next;
    p->next = s;
}
```

> **必须掌握指针修改顺序**
>
> 应先执行：
>
> ```c
> s->next = p->next;
> ```
>
> 再执行：
>
> ```c
> p->next = s;
> ```
>
> 如果先把 `p->next` 修改为 `s`，原来的后继结点地址可能丢失。

如果直接插入一个值：

```c
bool InsertValueAfter(Node *p, int value) {
    Node *s = (Node *)malloc(sizeof(Node));

    if (s == NULL) {
        return false;
    }

    s->data = value;
    s->next = p->next;
    p->next = s;

    return true;
}
```

已知 `p` 后插的核心操作只修改常数个指针，因此为 `O(1)`。

---

### 5.2 头插

带头结点时，在首元结点之前插入，本质上就是在头结点后插入：

```c
bool InsertAtHead(Node *head, int value) {
    return InsertValueAfter(head, value);
}
```

单次头插为 `O(1)`。

如果不断读取新元素并使用头插法建立链表，则最终元素顺序通常与输入顺序**相反**。

---

### 5.3 尾插

如果没有维护尾指针，需要先遍历到尾结点：

```c
bool InsertAtTail(Node *head, int value) {
    Node *tail = head;

    while (tail->next != NULL) {
        tail = tail->next;
    }

    return InsertValueAfter(tail, value);
}
```

寻找尾结点需要 `O(n)`。

因此不维护尾指针时，单次尾插整体为 `O(n)`。

如果额外维护：

```c
Node *tail;
```

则尾插可以做到 `O(1)`。

---

### 5.4 按位置插入

在第 `pos` 个数据位置插入：

```c
bool InsertAtPos(Node *head, int pos, int value) {
    if (pos < 1) {
        return false;
    }

    Node *p = head;
    int i = 0;

    while (p != NULL && i < pos - 1) {
        p = p->next;
        ++i;
    }

    if (p == NULL) {
        return false;
    }

    Node *s = (Node *)malloc(sizeof(Node));

    if (s == NULL) {
        return false;
    }

    s->data = value;
    s->next = p->next;
    p->next = s;

    return true;
}
```

虽然实际插入只需要修改两个指针，但查找第 `pos-1` 个结点需要遍历。

因此按位置插入总体通常是 `O(n)`。

> **核心结论**
>
> * 已知前驱结点：插入 `O(1)`；
> * 只知道逻辑位置：通常需要先查找，总体 `O(n)`。

## 6. 单链表的删除

### 6.1 删除某结点的后继结点

假设 `p` 指向已有结点，希望删除 `p` 的直接后继 `q`。

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-006.svg" alt={"p q p q p p→next ≠ NULL 时 p→next = q→next free(q);"} />

```c
bool DeleteAfter(Node *p) {
    Node *q = p->next;

    if (q == NULL) {
        return false;
    }

    p->next = q->next;
    free(q);

    return true;
}
```

已知前驱结点 `p` 后，删除为 `O(1)`。

---

### 6.2 删除第 pos 个结点

删除第 `pos` 个数据结点，需要先找到其前驱结点。

```c
bool DeleteAtPos(Node *head, int pos, int *value) {
    if (pos < 1) {
        return false;
    }

    Node *p = head;
    int i = 0;

    while (p->next != NULL && i < pos - 1) {
        p = p->next;
        ++i;
    }

    if (p->next == NULL) {
        return false;
    }

    Node *q = p->next;

    if (value != NULL) {
        *value = q->data;
    }

    p->next = q->next;
    free(q);

    return true;
}
```

复杂度：

* 找前驱：`O(n)`；
* 修改指针和释放结点：`O(1)`；
* 总体：`O(n)`。

## 7. 单链表的查找、遍历与清空

### 7.1 按值查找

```c
int LocateElem(Node *head, int value) {
    Node *p = head->next;
    int pos = 1;

    while (p != NULL) {
        if (p->data == value) {
            return pos;
        }

        p = p->next;
        ++pos;
    }

    return 0;
}
```

时间复杂度为 `O(n)`。

---

### 7.2 按位查找

链表无法根据下标直接计算目标结点地址。

查找第 `pos` 个数据结点必须从前向后遍历：

```c
Node *GetElem(Node *head, int pos) {
    if (pos < 1) {
        return NULL;
    }

    Node *p = head->next;
    int i = 1;

    while (p != NULL && i < pos) {
        p = p->next;
        ++i;
    }

    return p;
}
```

时间复杂度为 `O(n)`。

因此：

> **链表不支持随机访问。**

---

### 7.3 清空单链表

需要逐个释放数据结点。

```c
void ClearList(Node *head) {
    Node *p = head->next;
    Node *q;

    head->next = NULL;

    while (p != NULL) {
        q = p->next;
        free(p);
        p = q;
    }
}
```

这里必须先保存：

```c
q = p->next;
```

然后才能：

```c
free(p);
```

否则释放 `p` 后再访问 `p->next` 属于非法访问。

## 8. 双向链表

单链表只能方便地访问后继结点。

如果经常需要访问前驱，可以在每个结点中增加一个前驱指针。

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-007.svg" alt={"^ a1 a2 a3 prev data next head DNode"} />

双向链表结点：

```c
typedef struct DNode {
    ElementType data;
    struct DNode *prev;
    struct DNode *next;
} DNode;
```

每个结点包含：

* 数据域 `data`；
* 前驱指针 `prev`；
* 后继指针 `next`。

---

### 8.1 双向链表的特点

优点：

* 可以向前遍历；
* 可以向后遍历；
* 已知某结点后，可以直接获得其前驱；
* 删除当前结点时，不需要再从头寻找其前驱。

缺点：

* 每个结点需要额外保存一个指针；
* 插入和删除时需要维护更多链接关系。

---

### 8.2 在结点 p 前插入 s

原来：

```text
... ⇄ pre ⇄ p ⇄ ...
```

插入后：

```text
... ⇄ pre ⇄ s ⇄ p ⇄ ...
```

代码：

```c
s->prev = p->prev;
s->next = p;
p->prev->next = s;
p->prev = s;
```

四个链接关系都必须维护正确。

可以理解为：

1. `s` 找到自己的前驱；
2. `s` 找到自己的后继；
3. 原前驱指向 `s`；
4. `p` 的前驱改为 `s`。

---

### 8.3 删除结点 p

原来：

```text
... ⇄ prev ⇄ p ⇄ next ⇄ ...
```

删除后：

```text
... ⇄ prev ⇄ next ⇄ ...
```

核心代码：

```c
p->prev->next = p->next;
p->next->prev = p->prev;
free(p);
```

若链表没有使用特殊的头尾哨兵结点，还应注意首结点、尾结点等边界条件。

> **易错点**
>
> 双向链表修改某一方向的指针后，通常还需要同步修改反方向的指针。
>
> 只修改 `next` 而忘记修改 `prev` 会破坏双向链表结构。

## 9. 循环链表

**循环链表（Circular Linked List）**是一类首尾相接的链表。

其核心特点是：

> 链表尾部不再以普通的 `NULL` 作为唯一结束形式，而是通过指针重新连接到链表前部。

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-009.svg" alt={"a 1 a 2 a n head a 2 a 1 a 3 ^ head 循环单链表 循环双链表"} />

循环链表可以分为：

| 类型     | 特点               |
| ------ | ---------------- |
| 单向循环链表 | 尾结点的 `next` 指向头部 |
| 双向循环链表 | 首尾双向连接，可以双向循环    |

---

### 9.1 循环单链表

若采用带头结点的循环单链表，常见结构为：

```text
head → a1 → a2 → ... → an
 ↑                    ↓
 └────────────────────┘
```

此时尾结点满足：

```c
tail->next == head
```

而不是：

```c
tail->next == NULL
```

因此遍历时不能继续使用普通单链表的：

```c
while (p != NULL)
```

而应该根据具体结构判断是否重新回到头结点。

例如：

```c
Node *p = head->next;

while (p != head) {
    /* 处理 p */
    p = p->next;
}
```

---

### 9.2 循环双链表

循环双链表通常满足：

```c
head->next->prev == head;
head->prev->next == head;
```

若为空表并采用头结点，则常见初始化形式为：

```c
head->next = head;
head->prev = head;
```

因此判空可以写为：

```c
head->next == head
```

循环双链表可以从任意结点向前或向后不断移动。

---

### 9.3 真题考查

原资料整理的相关真题包括：

* 选择题：2016 年第 1 题、2016 年第 2 题、2021 年第 1 题、2023 年第 2 题、2024 年第 1 题、2026 年第 2 题；
* 解答题：2009 年第 42 题、2012 年第 42 题、2015 年第 41 题、2019 年第 41 题。

循环链表考查时尤其注意：

* 遍历终止条件；
* 首尾结点关系；
* 空表条件；
* 尾指针的利用。

## 10. 静态链表

**静态链表**使用数组来模拟链式结构。

<InlineSvg src="/images/data-structure/data-structure-linearlist-linked-008.svg" alt={"2 b 5 a 1 d -1 c 3 0 1 2 3 4 5 6 静态链表示例 a b c d ^ 对应的单链表"} />

结点定义：

```c
#define MAXSIZE 100

typedef struct {
    ElementType data;
    int next;
} SNode;

SNode list[MAXSIZE];
```

其中：

* `data` 保存数据；
* `next` 不再保存真实内存地址；
* `next` 保存**下一个结点在数组中的下标**。

因此 `next` 又称为**游标**。

例如：

```text
下标 2 的结点：
next = 5
```

表示其逻辑后继位于：

```c
list[5]
```

资料中使用：

```text
next == -1
```

表示链表结束。

---

### 10.1 静态链表的本质

静态链表：

* 物理上使用数组；
* 逻辑上按照链表方式连接。

因此修改逻辑关系时只需要修改游标，而不需要像普通顺序表一样移动大量元素。

其主要意义在于：

> 在不适合或不允许使用真实指针的环境中，用数组下标模拟链式结构。

## 11. 顺序表与链表综合比较

| 比较项        | 顺序表      | 单链表      |
| ---------- | -------- | -------- |
| 物理存储       | 连续       | 不要求连续    |
| 逻辑关系表示     | 物理次序直接体现 | 指针体现     |
| 按位访问       | `O(1)`   | `O(n)`   |
| 按值查找       | `O(n)`   | `O(n)`   |
| 已知操作位置后的插入 | 可能移动元素   | 修改指针即可   |
| 已知前驱后的删除   | 可能移动元素   | `O(1)`   |
| 按逻辑位置插入    | `O(n)`   | `O(n)`   |
| 按逻辑位置删除    | `O(n)`   | `O(n)`   |
| 空间局部性      | 较好       | 通常较差     |
| 指针额外开销     | 无        | 有        |
| 容量扩展       | 可能涉及重新分配 | 较灵活      |
| 空间利用       | 预分配可能浪费  | 每结点有指针开销 |

> **如何选择**
>
> * 需要大量随机访问：优先考虑顺序表；
> * 经常在已知位置附近插入和删除：链表更合适；
> * 数据规模固定且希望结构简单：顺序表方便；
> * 表长经常变化且难以预估：链表更灵活。
>
> 实际性能还会受到缓存局部性、内存分配和具体访问模式等因素影响。

## 12. 408 高频易错点

### 12.1 “链表插入删除一定是 O(1)”错误

只有已经拿到相关结点或前驱结点时，真正修改指针的过程才是 `O(1)`。

如果题目说：

> 在单链表的第 $i$ 个位置插入元素。

首先需要找到第 $i-1$ 个结点，因此总体通常为 `O(n)`。

---

### 12.2 顺序表“随机访问 O(1)”不等于“查值 O(1)”

已知逻辑位置：

```text
求第 i 个元素
```

可以直接定位，为 `O(1)`。

但已知值：

```text
查找值为 x 的元素
```

普通顺序表仍需要逐个比较，为 `O(n)`。

---

### 12.3 头结点不等于首元结点

带头结点链表：

```text
head → [头结点] → [a1] → [a2] → ...
```

因此：

```c
head
```

指向头结点，而：

```c
head->next
```

才指向首元结点。

---

### 12.4 插入时不能丢失原后继

正确：

```c
s->next = p->next;
p->next = s;
```

如果先：

```c
p->next = s;
```

再错误地使用新的 `p->next` 寻找旧后继，就可能破坏链表。

---

### 12.5 删除前必须保存需要继续访问的信息

例如清空链表：

```c
q = p->next;
free(p);
p = q;
```

不能：

```c
free(p);
p = p->next;
```

因为 `p` 指向的空间已经释放。

---

### 12.6 循环链表不能机械使用 NULL 判断结束

普通单链表：

```c
while (p != NULL)
```

循环单链表则往往需要判断：

```c
p != head
```

或者：

```c
p != start
```

具体取决于题目给出的链表结构。

---

### 12.7 顺序表和链表不由栈区、堆区决定

以下说法都不严谨：

```text
顺序表一定存在栈上。
链表一定存在堆上。
```

真正区别是：

```text
顺序表：元素地址连续。
链表：结点通过链接信息建立逻辑顺序。
```

## 13. 链表算法设计高频模型

链表是 408 算法设计题的重要载体。

除了基本插入、删除外，应掌握以下典型模型。

### 13.1 单链表逆置

原链表：

```text
head → a1 → a2 → a3 → NULL
```

逆置后：

```text
head → a3 → a2 → a1 → NULL
```

可以使用三个指针：

```c
void Reverse(Node *head) {
    Node *prev = NULL;
    Node *p = head->next;

    while (p != NULL) {
        Node *next = p->next;

        p->next = prev;

        prev = p;
        p = next;
    }

    head->next = prev;
}
```

时间复杂度：

```text
O(n)
```

额外空间复杂度：

```text
O(1)
```

核心思想：

```text
保存后继 → 反转指针 → 三个指针整体向后移动
```

---

### 13.2 查找倒数第 k 个结点

典型方法是**快慢指针**。

1. `fast` 先向前移动 $k$ 个结点；
2. `slow` 从第一个数据结点开始；
3. 两个指针同时向后移动；
4. 当 `fast` 到达链尾时，`slow` 即位于倒数第 $k$ 个结点。

思想本质是维持两个指针之间固定的距离。

时间复杂度：

```text
O(n)
```

额外空间复杂度：

```text
O(1)
```

---

### 13.3 两个链表寻找公共结点

两个无环单链表如果相交，从第一个公共结点开始，其后续结点一定完全相同。

因此结构只能类似：

```text
A: a1 → a2 ─┐
             ├→ c1 → c2 → NULL
B: b1 → b2 → b3 ┘
```

不可能：

```text
先相交 → 再分叉
```

因为一个单链表结点只有一个 `next` 指针。

常见解法：

1. 分别计算两个链表长度；
2. 让较长链表先走长度差；
3. 两个指针再同步前进；
4. 第一次指向同一结点的位置就是第一个公共结点。

时间复杂度：

```text
O(m+n)
```

额外空间复杂度：

```text
O(1)
```

这里判断公共结点必须比较**结点地址是否相同**，而不是只比较数据值是否相等。

复习线性表时建议按照下面的逻辑建立完整知识框架：

```text
线性表
│
├── 逻辑结构
│   └── 一对一的前驱、后继关系
│
├── 顺序存储
│   ├── 连续内存
│   ├── 随机访问 O(1)
│   ├── 插入移动
│   └── 删除移动
│
└── 链式存储
    ├── 单链表
    │   ├── 头结点
    │   ├── 插入
    │   ├── 删除
    │   └── 查找
    │
    ├── 双向链表
    │   ├── prev
    │   └── next
    │
    ├── 循环链表
    │   └── 首尾相连
    │
    └── 静态链表
        └── 数组 + 游标
```

最终应能够回答三个核心问题：

1. **数据元素的逻辑关系是什么？**
2. **这种逻辑关系在内存中如何表示？**
3. **这种表示方式会怎样影响访问、查找、插入和删除的复杂度？**

把这三点真正理解后，线性表相关的选择题和算法设计题就可以统一起来分析。
