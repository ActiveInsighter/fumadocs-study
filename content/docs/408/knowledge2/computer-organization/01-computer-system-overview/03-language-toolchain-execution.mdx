408 越来越强调 **高级语言程序与机器级执行之间的联系**。必须清楚每个转换阶段“输入是什么、输出是什么、谁来完成”。

## 1.3.1 三个语言层次

### 机器语言

机器语言由 ISA 定义，是处理器能够直接识别和执行的指令形式。

特点：

- 通常以二进制编码表示；
- 与具体 ISA 密切相关；
- 对人不友好；
- 不同 ISA 的机器代码通常不能直接互用。

### 汇编语言

汇编语言使用助记符表示机器指令，例如：

```asm
add eax, ebx
```

特点：

- 与具体 ISA 紧密相关；
- 比机器码更易阅读；
- 必须经 **汇编器（Assembler）** 转成目标机器代码。

### 高级语言

高级语言用更强的抽象表达算法，例如：

```c
c = a + b;
```

特点：

- 更接近算法和问题描述；
- 可维护性、可移植性更高；
- 需要编译器、解释器或运行时系统才能最终借助机器指令执行。

> **真题标签｜2015 年第 12 题：硬件能够直接执行的语言**
>
> CPU 直接执行的是 **机器语言程序**。汇编程序必须先汇编，高级语言程序也必须经过相应转换或由运行时环境执行。

## 1.3.2 编译型程序的典型转换链

以 C 程序为例，典型过程为：

```text
源程序 .c
   ↓ 预处理
预处理文件 .i
   ↓ 编译
汇编程序 .s
   ↓ 汇编
目标文件 .o
   ↓ 链接
可执行文件
   ↓ 装载
进程地址空间中的程序
   ↓
CPU 执行机器指令
```

不同语言和工具链细节可能不同，但 408 通常围绕以上 C 工具链考查。

## 1.3.3 预处理

预处理器主要完成：

- 宏展开；
- 头文件包含；
- 条件编译等。

例如：

```bash
gcc -E hello.c -o hello.i
```

预处理是 C/C++ 中非常典型的独立阶段，并不是所有高级语言都必须存在完全相同的预处理步骤。

## 1.3.4 编译

编译器把高级语言程序转换为较低级表示，常见流程包括：

- 词法 / 语法分析；
- 语义分析；
- 中间表示；
- 优化；
- 目标代码生成。

在常见 GCC 流程中，可生成汇编文件：

```bash
gcc -S hello.c -o hello.s
```

此阶段的核心是 **从高级语言语义映射到目标机器可以实现的操作**。

## 1.3.5 汇编

汇编器把汇编程序转成目标文件：

```bash
gcc -c hello.s -o hello.o
```

目标文件中通常不只有机器代码，还可能包含：

- 符号表；
- 重定位信息；
- 代码段、数据段等信息。

因此“目标文件”不等于“可以直接独立运行的最终程序”。

## 1.3.6 链接

链接器把一个或多个目标文件以及所需库组合起来，生成最终可执行文件。

```text
目标文件 A ─┐
目标文件 B ─┼→ 链接 → 可执行文件
库文件     ─┘
```

链接阶段最重要的两个任务：

1. **符号解析**：确定函数、全局变量等符号实际对应谁；
2. **重定位**：确定代码和数据最终地址并修正相关引用。

例如：

```bash
gcc hello.o -o hello
```

## 1.3.7 装载与执行

运行可执行文件后，操作系统加载器会建立进程运行所需要的地址空间，把程序需要的代码和数据映射到内存，并完成必要的运行时准备。

随后 CPU 从程序入口开始执行机器指令：

```text
取指 → 译码 → 执行 → 写回 / 更新状态 → 下一条指令
```

这说明：

> **“编译完成”与“程序开始运行”不是同一个阶段。**

编译工具链负责生成可执行程序，操作系统负责装载并建立运行环境，CPU 最终执行机器指令。

## 1.3.8 GCC 命令的易错点

`gcc` 常作为 **编译驱动程序**，会自动调用预处理器、编译器、汇编器和链接器。

常见命令：

| 命令 | 主要停止阶段 | 典型输出 |
| --- | --- | --- |
| `gcc -E hello.c -o hello.i` | 预处理后 | `.i` |
| `gcc -S hello.c -o hello.s` | 编译后 | `.s` |
| `gcc -c hello.c -o hello.o` | 汇编后 | `.o` |
| `gcc hello.o -o hello` | 链接后 | 可执行文件 |

> **易错点｜命令只有一个 `gcc`，不代表只有一个处理阶段**
>
> 例如 `gcc -c hello.c -o hello.o` 会由驱动程序组织多个内部阶段，直到生成目标文件为止。

## 1.3.9 编译与解释的边界

不要把“解释型语言”理解成“CPU 直接执行高级语言”。解释器或虚拟机本身也是机器程序，最终仍需由处理器执行机器指令。

因此最稳妥的结论是：

- **机器语言**：处理器直接执行；
- **汇编语言**：需要汇编；
- **高级语言**：需要编译、解释或其他运行时机制；
- 无论路径如何，最终的硬件执行仍落实到 ISA 所定义的机器级操作。
