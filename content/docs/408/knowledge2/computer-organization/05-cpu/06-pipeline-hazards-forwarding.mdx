流水线能理想运行的前提是：

1. 同一周期不会争抢唯一硬件资源；
2. 消费者需要的数据能及时得到；
3. 下一条正确指令地址能及时确定。

这三条分别对应：

- **结构冒险**；
- **数据冒险**；
- **控制冒险**。

> **真题标签｜流水线冒险**
>
> 原资料索引：选择题 2010 第 19 题、2016 第 19 题、2019 第 18 题、2023 第 19 题、2024 第 19 题；解答题 2012 第 44 题、2014 第 44 题。

## 5.6.1 结构冒险：资源不够

当多条指令在同一周期争用同一硬件资源时发生。

典型例子：

- IF 与 MEM 同时访问单端口统一存储器；
- 两条指令同时需要唯一 ALU；
- 寄存器堆端口数不足。

处理方式：

### 增加/分离资源

例如：

- 指令 Cache 与数据 Cache 分离；
- 增加寄存器堆端口；
- 增加功能单元。

### Stall

让其中一条指令暂停，等待资源可用。

## 5.6.2 三种数据相关

### RAW：Read After Write

```text
前指令：写 X
后指令：读 X
```

后指令必须读到前指令产生的**新值**。

也叫“写后读”，属于**真数据相关**。

### WAR：Write After Read

```text
前指令：读 X
后指令：写 X
```

也叫“读后写”，属于名称相关。

### WAW：Write After Write

```text
前指令：写 X
后指令：写 X
```

也叫“写后写”，属于名称相关。

> **经典五级顺序流水线的关键结论**
>
> 在顺序发射、顺序执行、顺序写回的经典五级流水线中，主要真正形成冒险的是 **RAW**。WAR、WAW 更常见于乱序执行、多发射等复杂处理器。

## 5.6.3 无 Forwarding 时为什么要停顿

例：

```asm
I1: ADD R1, R2, R3
I2: SUB R4, R1, R5
```

若：

- `I2` 在 ID 阶段读取 `R1`；
- `I1` 直到 WB 才把新 `R1` 写回寄存器堆；

那么 `I2` 必须等到能读到正确值。

若题目规定寄存器堆同一周期支持“**先写后读**”，则生产者 WB 与消费者 ID 可以出现在同一周期；若没有这一规定，必须按题设处理。

> **流水线题绝不能脱离题设默认值**
>
> 分支在哪一级判定、寄存器何时读写、旁路从哪里接、存储器是否分离，都会改变最终时序图。

## 5.6.4 Forwarding / Bypassing

数据前递不等结果先写回寄存器堆，而是从流水线中间直接送给后续指令。

例如：

```asm
I1: ADD R1, R2, R3
I2: SUB R4, R1, R5
```

`I1` 在 EX 结束时已经得到 ALU 结果。若 `I2` 下一拍进入 EX，可直接通过：

```text
EX/MEM → EX
```

把结果送入 `I2` 的 ALU 输入。

常见旁路：

- `EX/MEM → EX`；
- `MEM/WB → EX`；
- 某些实现还提供 Store 数据、分支比较等专用旁路。

## 5.6.5 Load-Use：有前递也可能要停 1 拍

例：

```asm
I1: LOAD R1, 0(R2)
I2: ADD  R3, R1, R4
```

关键时间：

- `I2` 在 EX 阶段需要 `R1`；
- `I1` 的 Load 数据通常到 MEM 阶段结束才得到。

因此紧邻的消费者下一拍进入 EX 时，数据还没准备好。

经典五级流水通常需要插入 **1 个气泡**。

记忆：

> **普通 ALU → ALU 的 RAW 常能靠前递消掉；紧邻 Load-Use 常仍需 Stall 1 拍。**

## 5.6.6 Store 指令也要检查数据依赖

例如：

```asm
I1: ADD R1, R2, R3
I2: STORE R1, 0(R4)
```

虽然 `STORE` 不写通用寄存器，但它**读取 `R1` 作为待写入存储器的数据**。

因此依然存在：

```text
I1 写 R1 → I2 读 R1
```

即 RAW。

是否需要停顿取决于实现是否提供把结果前递到 Store 数据输入端的旁路。

## 5.6.7 综合数据相关示例

```asm
I1: LOAD  R1, [a]
I2: LOAD  R2, [b]
I3: ADD   R1, R2
I4: STORE R1, [x]
```

相关关系：

- `I2 → I3`：`R2` 的 RAW；
- `I3 → I4`：`R1` 的 RAW；
- `I1` 与 `I3` 都写 `R1`，存在 WAW 名称相关，但经典顺序五级流水通常不会发生实际写回次序颠倒。

分析时先做“读写集合表”：

| 指令 | 读 | 写 |
| --- | --- | --- |
| I1 | 地址相关寄存器 | `R1` |
| I2 | 地址相关寄存器 | `R2` |
| I3 | `R1`,`R2` | `R1` |
| I4 | `R1`、地址相关寄存器 | 主存 |

再判断结果**何时产生**、消费者**何时需要**。

## 5.6.8 控制冒险

分支/跳转会让下一 PC 不确定。

```asm
100: ADD R1, R2, R3
104: BEQ R1, R0, 200
108: SUB R4, R5, R6
112: MUL R7, R8, R9
...
200: OR R10, R11, R12
```

若 `BEQ` 到 EX 才确定是否跳转，那么 `108`、`112` 可能已经被顺序取入。

如果最终跳转，这些错误路径指令必须被**冲刷 Flush**。

### 常见处理办法

- **阻塞**：分支结果确定前不继续发射有效指令；
- **静态/动态分支预测**：提前猜 Taken/Not Taken；
- **预测失败冲刷**：清除错误路径指令；
- **延迟分支**：由编译器把可安全执行的指令填入延迟槽（经典思想）。

## 5.6.9 分支罚时怎么计入性能

若每条指令平均分支比例为 $f_b$，错误预测率为 $p_m$，每次预测失败损失 $P$ 个周期，则由错误预测引入的平均 CPI 增量可写成：

$$
\Delta CPI_{branch}=f_b\cdot p_m\cdot P
$$

总 CPI 可写为：

$$
CPI=1+\Delta CPI_{data}+\Delta CPI_{struct}+\Delta CPI_{branch}+\cdots
$$

题目若直接给“每多少条指令有一次停顿”，也可直接折算平均停顿周期。

## 5.6.10 流水线综合题固定步骤

```text
① 写出每条指令读哪些寄存器、写哪些寄存器
② 标出结果最早在哪一级末尾产生
③ 标出消费者在哪一级需要该值
④ 判断可用哪条 Forwarding 路径
⑤ 若来不及，插 Stall / Bubble
⑥ 遇到分支，确定分支结果在哪一级产生
⑦ 按题设处理阻塞、预测和 Flush
⑧ 检查 IF/MEM 等结构资源是否冲突
⑨ 画完整时空图并统计总周期
```

最后再计算总时间或 CPI，最不容易漏。
