本节优先级低于数据通路、中断和流水线，但要建立清晰的并行层次：

> **流水线/超标量解决单核内部的指令级并行；SIMD 解决数据级并行；多核/MIMD 解决线程或任务级并行。**

> **真题标签｜多处理器与并行**
>
> 原资料索引：2022 第 22 题等。

## 5.8.1 并发与并行

### 并发 Concurrency

多个任务在一段时间内都在推进，不要求同一时刻真正同时执行。

单核 CPU 通过时间片切换也能实现并发。

### 并行 Parallelism

多个任务在同一时刻真正执行，通常需要：

- 多个物理核心；
- 多个处理器；
- SIMD 执行单元；
- GPU 等并行硬件。

## 5.8.2 Flynn 分类

Flynn 根据：

- 指令流数量；
- 数据流数量；

将体系结构分为：

| | 单数据流 | 多数据流 |
| --- | --- | --- |
| 单指令流 | SISD | SIMD |
| 多指令流 | MISD | MIMD |

### SISD

Single Instruction Stream, Single Data Stream。

传统单处理器串行执行模型可视为 SISD。

### SIMD

Single Instruction Stream, Multiple Data Stream。

同一条操作同时作用于多组数据，例如：

```text
ADD
├─ a1 + b1
├─ a2 + b2
├─ a3 + b3
└─ a4 + b4
```

适合：

- 向量；
- 矩阵；
- 图像；
- 多媒体；
- 科学计算。

### MISD

Multiple Instruction Stream, Single Data Stream。

通用计算机中很少见，可在某些特殊容错/流水结构中作为抽象模型理解。

### MIMD

Multiple Instruction Stream, Multiple Data Stream。

多个处理单元执行不同指令、处理不同数据。现代多核 CPU、多处理器服务器通常属于 MIMD。

## 5.8.3 SIMD 与 SIMT

SIMT（Single Instruction, Multiple Threads）常用来描述 GPU 的线程执行模型。

与传统 SIMD 相比，SIMT 更强调每个线程拥有自己的：

- 寄存器状态；
- 程序状态；
- 线程上下文。

同一 warp/wavefront 中线程通常同步推进相同指令。如果线程分支条件不同：

```c
if (condition) {
    A();
} else {
    B();
}
```

可能出现**分支分歧**，硬件需要分路径执行后再汇合。

因此不能理解为：

> 同一 warp 中每个线程可在同一时刻随意执行完全不同的机器指令。

## 5.8.4 多核处理器

多核处理器在同一芯片或封装内集成多个处理核心。

每个物理核心通常具有：

- 自己的架构寄存器状态；
- 取指、译码与执行流水线；
- 执行单元；
- 私有 L1 Cache；
- 某些实现中私有 L2。

更高层 Cache 可能由多个核心共享。

> **易错点**
>
> “每个核心拥有完全独立的所有 Cache”不一定成立，Cache 层级和共享方式属于具体微架构设计。

## 5.8.5 物理核心、逻辑处理器与 SMT

SMT（Simultaneous Multithreading）让一个物理核心同时维护多个硬件线程上下文。

例如：

```text
4 个物理核心 × 每核 2 路 SMT = 8 个逻辑处理器
```

不同硬件线程通常需要各自的部分体系结构状态，例如：

- PC；
- 通用寄存器；
- 状态寄存器；
- 异常/中断相关状态。

但多个逻辑线程会共享大量执行资源，例如：

- ALU/FPU；
- Load/Store 单元；
- Cache；
- 调度资源；
- 访存带宽。

所以 SMT 的核心是：

> **复制/维护多份线程状态，复用同一物理核心的大量执行资源，提高资源利用率和吞吐量。**

因此：

```text
8 个逻辑处理器 ≠ 8 个完整物理核心
```

## 5.8.6 共享内存多处理器

多个处理器/核心共享统一物理内存空间：

```text
Core 1 ─┐
Core 2 ─┼─ 互联 ─ 共享主存
Core 3 ─┘
```

优点：

- 线程可以通过共享变量通信；
- 编程模型直观。

同时也必须面对：

- 同步与互斥；
- 共享内存带宽；
- Cache 一致性；
- 互联扩展性；
- 负载均衡。

## 5.8.7 为什么“加核心”不会线性提速

若程序中存在不可并行的串行部分，即使并行部分无限加速，总体加速也有限。

若串行比例为 $s$，并行部分在 $p$ 个处理单元上理想均分，则可用 Amdahl 思想理解：

$$
S(p)=\frac{1}{s+\frac{1-s}{p}}
$$

当 $p\rightarrow\infty$：

$$
S_{\max}=\frac{1}{s}
$$

这说明性能还受：

- 串行部分；
- 通信同步；
- Cache/内存带宽；
- 负载不均衡；

等限制。

这条公式不是本章最核心考点，但有助于理解“核数翻倍，性能不一定翻倍”。

## 5.8.8 本章易错点总表

| 易错说法 | 正确理解 |
| --- | --- |
| 数据通路就是 ALU | 还包括寄存器、MUX、总线等 |
| ALU 能保存结果 | ALU 通常是组合逻辑，结果要写入状态元件 |
| `Rin` 是读寄存器 | `Rin` 表示写入，`Rout` 表示读出 |
| PC 必须是一个名字叫 PC 的寄存器 | PC 是体系结构功能，具体实现可不同 |
| `CF` 与 `OF` 一样 | CF 主要反映无符号进位，OF 反映有符号溢出 |
| 微程序就是普通软件 | 微程序位于控制器内部控制存储器 |
| 微命令就是微指令 | 一条微指令可包含多个微命令 |
| 中断时硬件自动保存所有通用寄存器 | 经典 408 口径通常是硬件保断点、软件保现场 |
| 外部中断与异常完全一样 | 外中断通常异步，异常通常同步 |
| 中断屏蔽就是关闭所有中断 | 屏蔽字可选择性屏蔽某些中断源 |
| 流水线降低单条指令延迟 | 核心收益是提高吞吐率 |
| 多周期处理器就是流水线 | 多周期不要求多条指令重叠 |
| 五级流水中 WAR/WAW 都会导致停顿 | 经典顺序五级主要关注 RAW |
| 有 Forwarding 就无需 Stall | 紧邻 Load-Use 常仍需停顿 |
| 超标量 = 超流水 | 前者同拍多发射，后者流水段更细 |
| SIMD = MIMD | SIMD 同指令多数据，MIMD 多指令多数据 |
| 逻辑核心 = 完整物理核心 | SMT 逻辑线程共享大量执行资源 |

## 5.8.9 CPU 综合题总主线

遇到 CPU 大题，可固定按以下顺序：

```text
① 读懂机器指令语义
       ↓
② 明确源操作数、目的操作数
       ↓
③ 写 RTL 微操作
       ↓
④ 沿数据通路找源、目的、ALU、MAR/MDR
       ↓
⑤ 推导控制信号
       ↓
⑥ 判断寄存器何时读、结果何时产生
       ↓
⑦ 若有流水线：判断结构/数据/控制冒险
       ↓
⑧ 按 Forwarding、Stall、Flush 重排时序
       ↓
⑨ 若有异常/中断：判断断点、现场、返回位置
```

全章可以压缩成一句：

> **CPU 在控制器产生的时序控制信号驱动下，让数据沿数据通路在寄存器、ALU 和存储系统之间有序流动；流水线让多条指令的这些操作重叠，而异常/中断机制负责在特殊事件出现时安全改变控制流。**
