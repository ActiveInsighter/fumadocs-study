流水线的核心思想只有一句：

> **把一条指令的执行拆成多个阶段，让多条指令处于不同阶段并行推进。**

它主要提高的是**吞吐率**，而不是让一条单独指令的端到端延迟必然显著下降。

## 5.5.1 经典五级流水

```text
IF → ID → EX → MEM → WB
```

| 阶段 | 英文 | 主要功能 |
| --- | --- | --- |
| IF | Instruction Fetch | 取指、形成顺序下一 PC |
| ID | Instruction Decode | 译码、读取源寄存器、扩展立即数 |
| EX | Execute | ALU 运算、地址计算、比较、分支判断 |
| MEM | Memory | Load/Store 数据访存 |
| WB | Write Back | 将 ALU/Load 结果写回寄存器 |

### IF

- PC 给出指令地址；
- 读取指令；
- 计算顺序下一 PC；
- 结果送入 `IF/ID` 流水段寄存器。

### ID

- 译码；
- 读取源寄存器；
- 生成控制信息；
- 对立即数做扩展。

经典模型中常规定：

> **寄存器在 ID 阶段读取。**

### EX

可执行：

- 算术逻辑运算；
- Load/Store 有效地址计算；
- 分支比较；
- 分支目标地址形成。

### MEM

- Load：读取数据存储器；
- Store：写数据存储器。

普通 ALU 指令即使不需要真正访存，也可能在统一五级结构中“经过”这一流水时隙。

### WB

把最终结果写入目的寄存器。Store 和大多数分支无需写回通用寄存器。

## 5.5.2 为什么需要流水段寄存器

典型五级流水之间有：

- `IF/ID`；
- `ID/EX`；
- `EX/MEM`；
- `MEM/WB`。

作用：

1. 在时钟边沿锁存上一阶段输出；
2. 在下一周期为下一级提供稳定输入；
3. 隔离不同流水段，使多条指令能同时存在于流水线中。

流水段寄存器会带来额外延迟，因此流水线级数并非越多越好。

## 5.5.3 单周期、多周期与流水线

### 单周期处理器

每条指令在一个时钟周期内完成。

缺点：

> 时钟周期必须覆盖**最慢指令的最长组合路径**。

因此简单指令也要等待同样长的周期。

### 多周期处理器

一条指令被拆成多个较短周期，不同指令可以使用不同数量的周期。

传统多周期模型通常仍是：

> 一条指令完成后，下一条才开始。

### 流水线处理器

允许多条指令的不同阶段重叠。

对比：

| 结构 | 一条指令是否拆阶段 | 多条指令是否重叠 |
| --- | --- | --- |
| 单周期 | 否 | 否 |
| 多周期 | 是 | 通常否 |
| 流水线 | 是 | 是 |

## 5.5.4 理想流水时空图

四条指令的理想五级流水：

| 指令 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| I1 | IF | ID | EX | MEM | WB | | | |
| I2 | | IF | ID | EX | MEM | WB | | |
| I3 | | | IF | ID | EX | MEM | WB | |
| I4 | | | | IF | ID | EX | MEM | WB |

可以看到：

- 流水线先经历**填充**；
- 稳态时理想情况下每拍完成一条；
- 最后还要经历**排空**。

## 5.5.5 流水线时钟周期

若 $k$ 个流水段的组合逻辑延迟为：

$$
t_1,t_2,\ldots,t_k
$$

流水段寄存器开销为 $t_r$，则时钟周期通常取：

$$
T_c=\max(t_1,t_2,\ldots,t_k)+t_r
$$

若题目忽略流水段寄存器开销：

$$
T_c=\max(t_1,t_2,\ldots,t_k)
$$

因此性能常由**最慢流水段**限制。

## 5.5.6 完成 $n$ 条指令的理想时间

理想 $k$ 段流水线：

$$
T_{\text{pipe}}=(k+n-1)T_c
$$

其中：

- 前 $k$ 拍用于首条任务通过全部阶段；
- 此后理想情况下每增加一个任务只多 1 拍。

## 5.5.7 吞吐率

吞吐率：

$$
TP=\frac{n}{T_{\text{pipe}}}
$$

于是：

$$
TP=\frac{n}{(k+n-1)T_c}
$$

当 $n$ 很大时：

$$
TP_{\max}\rightarrow\frac{1}{T_c}
$$

这就是“理想稳态每个时钟周期完成一条”的数学表达。

## 5.5.8 加速比

若非流水方式每个任务需要 $kT_c$，完成 $n$ 个任务：

$$
T_{\text{serial}}=nkT_c
$$

则理想加速比：

$$
S=\frac{T_{\text{serial}}}{T_{\text{pipe}}}
=\frac{nk}{k+n-1}
$$

当 $n\rightarrow\infty$：

$$
S\rightarrow k
$$

即理想 $k$ 段流水线的极限加速比趋近 $k$。

## 5.5.9 流水线效率

若把 $k$ 个流水段看作 $k$ 份硬件资源：

$$
E=\frac{S}{k}
$$

理想且任务数足够多时：

$$
E\rightarrow1
$$

实际效率会被以下因素拉低：

- 段延迟不均衡；
- 结构冒险；
- 数据冒险；
- 控制冒险；
- Cache Miss；
- 分支预测错误；
- 流水段寄存器开销。

## 5.5.10 CPI 与停顿周期

理想标量流水线稳态：

$$
CPI_{\text{ideal}}\approx1
$$

若每条指令平均引入 $s$ 个停顿周期：

$$
CPI_{\text{actual}}=CPI_{\text{ideal}}+s
$$

更一般地：

$$
CPI_{\text{actual}}
=1+\frac{\text{总停顿周期数}}{\text{完成指令数}}
$$

这条公式非常适合把：

- Load-Use 停顿；
- 分支罚时；
- Cache Miss 罚时；

统一折算进性能题。

> **核心结论**
>
> 流水线的性能优势来自“重叠”，不是凭空减少每个逻辑操作的工作量。实际题目一定要把停顿和冲刷加回总周期数。
