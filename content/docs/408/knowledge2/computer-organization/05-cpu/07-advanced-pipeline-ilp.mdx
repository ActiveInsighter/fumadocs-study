经典五级流水线的理想状态是：

> **每拍发射 1 条、每拍完成约 1 条。**

高级处理器进一步追求**指令级并行（ILP, Instruction-Level Parallelism）**：在同一时间处理更多彼此独立的指令。

> **真题标签｜高级流水**
>
> 原资料索引：2017 第 17 题等；现行考纲还要求掌握超标量与动态流水线的基本概念。

## 5.7.1 超标量 Superscalar

核心：

> **一个时钟周期可以发射多条指令。**

处理器通常配置多个功能单元，例如：

- 多个整数 ALU；
- Load/Store 单元；
- 乘除法单元；
- 浮点/向量单元。

若每周期最多发射 $w$ 条指令，则理论最优吞吐能力高于单发射处理器，但实际受数据相关、结构资源、分支预测等限制。

### 关键特征

- 并行性主要由**硬件动态发现**；
- 需要检查同拍指令之间的数据和资源依赖；
- 常与乱序执行、分支预测、寄存器重命名等技术结合。

## 5.7.2 超流水线 Superpipeline

核心：

> **把原有流水段进一步细分，从而缩短单段组合逻辑延迟，提高时钟频率。**

例如：

```text
5 级 → 10 级 → 更深流水
```

好处：

- 单个时钟周期可以更短；
- 频率可以更高。

代价：

- 流水段寄存器数量增加；
- 分支预测失败需要冲刷更多阶段；
- 冒险控制更加复杂；
- 单条指令延迟未必降低。

> **区分**
>
> 超标量是“**同一拍发更多条**”；超流水是“**把每条指令切得更细、提高拍速**”。

## 5.7.3 VLIW

VLIW（Very Long Instruction Word）把多个可并行执行的操作由**编译器提前打包**进一条超长指令。

抽象格式：

```text
| ALU op | MUL op | LOAD/STORE op | BRANCH op |
```

最大特点：

> **并行性主要由编译器静态发现，而不是由硬件每次运行时动态调度。**

与超标量对比：

| 技术 | 谁主要发现并行性 | 运行时硬件复杂度 |
| --- | --- | --- |
| 超标量 | 硬件 | 高 |
| VLIW | 编译器 | 相对低 |

## 5.7.4 动态流水与乱序执行：只掌握基本概念

当某条较早指令因为数据未准备好而等待时，如果后面的独立指令已经具备执行条件，处理器可以让后者先执行，这就是**动态调度/乱序执行**的基本思想。

对比：

```text
严格顺序执行：
I1 等待 → 后面都跟着等

动态执行：
I1 等待
I2 与 I1 无关 → 可先执行
I3 依赖 I1 → 继续等待
```

这样可以减少功能部件空闲，提高 ILP。

## 5.7.5 为什么乱序执行会出现 WAR/WAW 风险

经典顺序五级流水中，读写发生顺序固定，因此 WAR、WAW 通常不会造成实际冒险。

一旦允许指令乱序执行：

- 后面的写操作可能越过前面的读操作 → WAR；
- 后面的写操作可能比前面的写操作更早完成 → WAW。

因此高级处理器常使用**寄存器重命名**消除名称相关。

例如：

```asm
I1: R1 ← R2 + R3
I2: R4 ← R1 + R5
I3: R1 ← R6 + R7
```

`I1` 与 `I3` 都写架构寄存器 `R1`，逻辑上存在 WAW 名称相关。硬件可在内部把它们映射到不同物理寄存器，等提交时再保证架构状态按程序顺序可见。

> **408 掌握层级**
>
> 重点理解“为什么动态调度能提高并行性、为什么会引出 WAR/WAW、寄存器重命名用来消除名称相关”，不必把复杂实现细节当成本章主线。

## 5.7.6 顺序提交与精确异常

现代乱序处理器虽然内部执行顺序可能变化，但需要保证程序看到的体系结构结果符合规定顺序。

一个重要目标是实现**精确异常**：发生异常时，体系结构状态应表现得像：

- 异常指令之前的指令都已完成；
- 异常指令及之后的指令尚未产生不可撤销的架构效果。

因此“内部乱序”不等于“程序语义乱序”。

## 5.7.7 四种技术快速对比

| 技术 | 核心做法 | 主要目的 |
| --- | --- | --- |
| 普通流水 | 阶段重叠 | 提高吞吐率 |
| 超流水 | 进一步细分流水段 | 提高时钟频率 |
| 超标量 | 同拍发射多条指令 | 提高每拍吞吐 |
| VLIW | 编译器静态打包多个操作 | 用编译期并行降低动态调度压力 |
| 动态/乱序流水 | 就绪指令可越过阻塞指令执行 | 隐藏等待、提高 ILP |

> **易错点**
>
> “流水线更深”“每拍发更多条”“允许后指令先执行”是三种不同维度的优化，不要混为一谈。
