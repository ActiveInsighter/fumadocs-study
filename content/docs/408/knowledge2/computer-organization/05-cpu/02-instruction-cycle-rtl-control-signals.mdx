这一节解决 CPU 综合题最核心的问题：

> **一条机器指令在 CPU 里究竟分几步完成，每一步有哪些数据传送，又需要哪些控制信号？**

> **真题标签｜数据通路与控制信号**
>
> 原资料索引：2022 第 43 题、2026 第 44 题；数据通路综合题还涉及 2013 第 44 题、2015 第 43 题等。

## 5.2.1 三个“周期”不要混淆

### 时钟周期

CPU 最基本的时序单位，由时钟边沿推动寄存器状态更新。

### 机器周期 / CPU 周期

完成某个相对完整的基本操作所需的一段时间，通常包含若干时钟周期。不同教材定义略有差异，做题以题设为准。

### 指令周期

从取出一条指令开始，到完成该指令并准备处理下一条指令为止的全部时间。

典型层级关系：

```text
指令周期
└─ 一个或多个机器周期
   └─ 一个或多个时钟周期
```

不同指令的指令周期不一定相同。

## 5.2.2 指令周期的逻辑阶段

从功能上可把一条指令概括为：

```text
取指 → 译码 → 取操作数 → 执行 → 访存（若需要）→ 写回 → 检查异常/中断
```

有些教材按“取指周期、间址周期、执行周期、中断周期”划分；现代流水线又常按 `IF/ID/EX/MEM/WB` 描述。两者只是**观察粒度不同**，核心都是把一条指令拆成有先后关系的微操作。

## 5.2.3 RTL：把“硬件动作”写成可推导的语言

RTL（Register Transfer Language，寄存器传送语言）用来描述 CPU 内部的数据传送和微操作。

常见写法：

| RTL | 含义 |
| --- | --- |
| `R1 ← R2` | `R2` 内容送入 `R1` |
| `R1 ← R2 + R3` | ALU 计算后写入 `R1` |
| `MAR ← PC` | PC 的值送入 MAR |
| `MDR ← M[MAR]` | 从主存读数据到 MDR |
| `M[MAR] ← MDR` | 将 MDR 数据写入主存 |

若多个微操作之间没有资源冲突，可以在同一拍并行完成：

```text
MAR ← PC, PC ← PC + 4
```

逗号表示“可并行”，不是简单的书写装饰。

> **易错点**
>
> 两个微操作能否同拍执行，必须同时满足数据依赖和数据通路资源条件。RTL 写得出来，不代表硬件一定支持同拍完成。

## 5.2.4 典型取指 RTL

一种典型抽象：

```text
T0: MAR ← PC
T1: MDR ← M[MAR], PC ← PC + Δ
T2: IR  ← MDR
T3: Decode(IR)
```

其中 $\Delta$ 取决于：

- 主存按字节还是按字编址；
- 指令字长；
- 指令是否定长。

因此不要机械背 `PC ← PC + 1` 或 `PC ← PC + 4`。

## 5.2.5 单总线数据通路为什么要暂存器

单总线结构中，同一时刻通常只能有**一个源部件驱动内部总线**。

若 ALU 要计算：

$$
R_1+R_2
$$

但 ALU 两个输入都需要来自寄存器，常见实现是：

```text
T0: Y  ← R1
T1: Z  ← Y + R2
T2: R3 ← Z
```

其中 `Y/Z/T` 等内部寄存器用于解决：

- ALU 同时需要两个输入；
- 单总线同拍不能同时传两路源数据；
- ALU 输出需要在下一拍稳定保存。

因此数据通路题中看到暂存寄存器，不应认为它“多余”。

## 5.2.6 控制信号怎么从 RTL 推出来

常见命名：

- `Rout`：寄存器内容驱动总线；
- `Rin`：总线数据写入寄存器；
- `MemR`：主存读；
- `MemW`：主存写；
- `ALUop`：指定 ALU 功能；
- `MUXop`：控制多路选择器。

例如：

```text
MAR ← PC
```

需要：

```text
PCout, MARin
```

若：

```text
Z ← Y + MDR
```

则至少需要：

- 让 `Y`、`MDR` 成为 ALU 的两个输入；
- `ALUop = ADD`；
- 允许 `Z` 在时钟边沿锁存结果。

> **高频易错点**
>
> `Rout` 是**读出/驱动数据通路**，`Rin` 是**写入/锁存**。

## 5.2.7 完整示例：`ADD R0, (R1)`

设指令语义为：

$$
R0\leftarrow R0+M[R1]
$$

一种典型多周期实现如下。

### 取指

```text
C1: MAR ← PC
C2: MDR ← M[MAR]
C3: IR  ← MDR
C4: PC  ← PC + Δ
C5: Decode(IR)
```

### 取存储器操作数

```text
C6: MAR ← R1
C7: MDR ← M[MAR]
```

### 运算与写回

若采用单总线并有暂存器 `T`、结果寄存器 `Z`：

```text
C8 : T  ← R0
C9 : Z  ← T + MDR
C10: R0 ← Z
```

对应控制信号可从每条 RTL 直接反推，而不应死背表格。

## 5.2.8 数据通路综合题的固定解法

遇到“补连线、写控制信号、判断端点”的题，按以下顺序：

```text
① 先翻译指令语义
② 列出源操作数、目的操作数
③ 写 RTL 微操作
④ 确认每拍谁上总线
⑤ 判断是否经过 ALU / 移位器 / MUX
⑥ 判断是否需要 MAR/MDR 访存
⑦ 再写 Rout、Rin、ALUop、MemR/MemW 等控制信号
⑧ 最后检查是否有同拍资源冲突
```

### 一个非常实用的检查表

对每个时钟周期逐项问：

- **源**是谁？
- **目的**是谁？
- 是否经过 **ALU**？
- ALU 做什么？
- 是否访问**主存**？
- 是否需要**暂存器**？
- 同一总线是否被两个部件同时驱动？

只要先把 RTL 写对，控制信号通常就不难。
