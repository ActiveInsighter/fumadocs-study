### 5.10.1 中断的基本思想

**中断**使 CPU 可以在正常程序执行过程中，暂时转去处理某个特殊事件，然后再返回原程序继续执行。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-001.svg" alt="中断基本概念" />

典型外部事件包括：

* 键盘输入；
* 定时器；
* 磁盘完成；
* 网络设备；
* 外部硬件请求等。

---

### 5.10.2 中断与异常

408 中最稳妥的理解是：

#### 外部中断 Interrupt

来自 CPU 外部。

特点：

* 通常与当前执行的具体指令没有直接因果关系；
* **异步**；
* 通常在当前指令执行完后响应。

#### 异常 Exception

由正在执行的指令或 CPU 内部事件引起。

特点：

* 与当前指令相关；
* **同步**；
* 通常在执行当前指令过程中被检测。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-002.svg" alt="外部中断与内部异常" />

部分教材把异常称为 **内中断**，并把“中断”作为内中断和外中断的总称；另一些教材则直接把 `Interrupt` 专指外部中断。

做题时首先看题目采用哪种术语体系。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-003.svg" alt="中断分类体系" />

## 5.11 中断系统的基本概念

### 5.11.1 中断向量

**中断向量**是中断服务程序的入口地址，或能够定位入口地址的信息。

### 5.11.2 中断向量表

中断向量表把：

```text
中断类型号
```

映射到：

```text
中断处理程序入口地址
```

### 5.11.3 中断服务程序 ISR

ISR（Interrupt Service Routine）负责：

1. 保护必要现场；
2. 执行具体中断处理；
3. 恢复现场；
4. 中断返回。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-004.svg" alt="中断向量和中断服务程序" />

## 5.12 中断处理全过程

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-005.svg" alt="典型中断处理过程" />

典型流程可以概括为：

```text
外部设备提出中断请求
        ↓
CPU 完成当前指令
        ↓
判断是否允许响应
        ↓
关中断
        ↓
保存断点
        ↓
识别中断源 / 获得中断向量
        ↓
进入中断服务程序
        ↓
保护现场
        ↓
处理中断
        ↓
恢复现场
        ↓
恢复断点并中断返回
        ↓
继续原程序
```

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-006.svg" alt="中断处理中硬件与软件的分工" />

---

### 5.12.1 硬件通常完成什么

408 教材中常将下列工作归入 **中断隐指令**：

* 关中断；
* 保存断点；
* 形成中断服务程序入口地址。

这些动作由硬件自动完成。

> “中断隐指令”不是程序存储器中的普通机器指令，而是硬件在中断响应过程中自动完成的一组操作。

---

### 5.12.2 软件通常完成什么

中断服务程序负责：

* 保存通用寄存器等现场；
* 保存必要的中断屏蔽状态；
* 处理中断事件；
* 恢复现场；
* 执行中断返回指令。

不同体系结构的软硬件划分可能不同，做题时以题设数据通路和说明为准。

---

## 5.13 断点与现场

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-007.svg" alt="断点与现场的区别" />

#### 断点

为了以后能继续执行原程序而必须保存的 **程序执行位置和基本状态**。

典型包括：

* PC；
* PSW / FLAGS。

有的体系结构还自动保存其他必要状态。

#### 现场

被中断程序当前使用的 CPU 工作状态，常重点指：

* 通用寄存器；
* 地址寄存器；
* 其他 ISR 可能破坏的寄存器。

考试中常见约定：

| 内容       | 通常由谁保存 |
| -------- | ------ |
| 断点       | 硬件     |
| 通用寄存器等现场 | 中断服务程序 |
| 断点恢复     | 中断返回机制 |
| 现场恢复     | 中断服务程序 |

> **口诀**
>
> **硬件保断点，软件保现场。**

## 5.14 中断优先级

> **历年真题范围**
>
> 2011 年第 21 题、2017 年第 22 题、2021 年第 22 题等。

当多个中断请求同时出现时，需要确定 CPU 先处理谁。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-008.svg" alt="中断优先级与中断嵌套" />

中断优先级主要解决：

1. **同时请求时的响应顺序**；
2. **中断嵌套时谁可以抢占谁**。

应注意：

> **响应优先级**与**处理优先级**可以是两个不同概念。

某些系统可通过屏蔽字改变实际处理中断的优先次序。

---

## 5.15 单重中断与多重中断

### 5.15.1 单重中断

CPU 一旦进入某个 ISR，就不再响应新的可屏蔽中断，直到该 ISR 结束。

思想类似：

```text
主程序
  ↓
ISR A
  ↓
返回主程序
```

不会出现 ISR 中再进入其他 ISR。

---

### 5.15.2 多重中断

> **历年真题范围**
>
> 2011 年第 21 题、2017 年第 22 题、2021 年第 22 题。

若执行低优先级 ISR 时允许更高优先级中断打断它，就形成 **中断嵌套**。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-009.svg" alt="单重中断与多重中断" />

例如：

```text
主程序
   ↓
ISR C
   ↓ 被高优先级 B 抢占
ISR B
   ↓ 被更高优先级 A 抢占
ISR A
   ↓ 返回
ISR B
   ↓ 返回
ISR C
   ↓ 返回
主程序
```

为了实现多重中断，通常要同时解决：

* **重新开中断**；
* **设置屏蔽字，只允许更高优先级请求进入**。

## 5.16 中断屏蔽

> **历年真题范围**
>
> 2011 年第 19、21 题，2020 年第 21 题等。

每个可屏蔽中断源可以对应一个屏蔽位。

通常约定：

* `1`：屏蔽；
* `0`：允许。

所有屏蔽位组成 **中断屏蔽字**。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-010.svg" alt="中断屏蔽字" />

假设优先级：

```text
A > B > C > D
```

执行 `B` 的 ISR 时，如果只允许 `A` 抢占，可设置为：

| 中断源 | 是否屏蔽 |
| --- | ---- |
| A   | 否    |
| B   | 是    |
| C   | 是    |
| D   | 是    |

于是：

* `A` 可打断 `B`；
* `C`、`D` 必须等待。

> **易错点**
>
> 中断屏蔽字本身的核心作用是 **控制哪些中断当前可以被响应**。
> 它经常被用于实现多重中断的处理优先级。

---

### 5.16.1 可屏蔽中断与不可屏蔽中断

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-011.svg" alt="可屏蔽中断与不可屏蔽中断" />

#### 可屏蔽中断

可以通过：

* CPU 中断允许位；
* 中断控制器中的屏蔽位

暂时禁止。

典型普通外设中断属于此类。

#### 不可屏蔽中断 NMI

不能由普通中断屏蔽机制禁止。

常用于：

* 严重硬件故障；
* 电源异常；
* 某些系统级错误。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-012.svg" alt="INTR 与 NMI 信号" />

在典型 x86 模型中：

* `INTR`：可屏蔽中断；
* `NMI`：不可屏蔽中断。

---

### 5.16.2 嵌套与屏蔽不是一个概念

* **嵌套**回答：ISR 能不能被另一个 ISR 打断？
* **屏蔽**回答：哪些中断当前有资格进入？

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-013.svg" alt="中断响应与屏蔽判断流程" />

## 5.17 异常

> **历年真题范围**
>
> 2009、2012、2015、2016、2020、2021、2023、2024、2025、2026 等年份均有相关考查。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-014.svg" alt="异常与中断的关系" />

异常通常由当前指令引起，例如：

* 除零；
* 缺页；
* 非法指令；
* 地址访问越权；
* 调试断点；
* 系统调用；
* 严重机器错误。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-015.svg" alt="CPU 常见异常" />

---

### 5.17.1 Fault、Trap、Abort

这是比单纯列举异常名称更适合 408 的分类方式。

| 类型    | 特点               | 典型例子        | 处理后是否可能重新执行原指令 |
| ----- | ---------------- | ----------- | -------------- |
| Fault | 执行当前指令时发现，可修复    | 缺页、部分保护异常   | 通常可以           |
| Trap  | 指令有意或正常执行后进入处理程序 | 调试断点、系统调用   | 通常从下一条继续       |
| Abort | 严重且通常无法精确恢复      | 严重硬件错误、机器检查 | 通常不能           |

#### 缺页异常

访问的虚拟页尚未装入主存时：

```text
CPU 访问页面
   ↓
发现页表项无效
   ↓
产生缺页异常
   ↓
OS 调入页面
   ↓
修改页表
   ↓
重新执行原访问指令
```

因此缺页异常是典型的 **Fault**。

#### 除零

```c
int a = 10;
int b = 0;
int c = a / b;
```

整数除零通常触发同步异常。

#### 非法存储器访问

```c
int *p = invalid_address;
*p = 42;
```

可能引起保护类异常。

#### 机器检查

严重硬件错误可能导致机器检查类异常，属于难以恢复的情况。

## 5.18 自陷与系统调用

**自陷（Trap）**通常指程序有意识地执行特殊指令，主动把控制权交给操作系统。

典型用途：

* 系统调用；
* 调试断点；
* 软件陷阱。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-016.svg" alt="CPU 自陷机制" />

系统调用可以概括为：

```text
用户程序
   ↓
执行 syscall / trap 类指令
   ↓
产生同步异常
   ↓
CPU 切换到内核态
   ↓
进入系统调用处理程序
   ↓
OS 完成服务
   ↓
返回用户态
```

因此：

> **系统调用不是普通函数调用，它需要通过异常/陷阱机制进入内核态。**
