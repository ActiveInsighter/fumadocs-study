## 15. 外部中断与异常

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-001.svg" alt="中断基本概念" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-002.svg" alt="外部中断与内部异常" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-003.svg" alt="中断分类体系" />

> **真题考查**
>
> - 中断相关选择题：2010、2012、2013、2014、2015、2018、2019、2020、2022、2023、2024、2026 等年份多次出现
> - 解答题：2009 年第 43 题、2016 年第 44 题、2017 年第 45 题、2023 年第 46 题

异常与中断都可能改变正常指令流，但来源和时序性质不同。

| 类型 | 来源 | 与当前指令关系 | 时序性质 |
| --- | --- | --- | --- |
| 外部中断 Interrupt | CPU 外部设备或外部事件 | 通常无直接因果关系 | 异步 |
| 异常 Exception | 当前指令或 CPU 内部执行事件 | 与当前指令直接相关 | 同步 |

典型外部中断：

- 定时器；
- 键盘或网络设备；
- 磁盘 I/O 完成；
- 外部硬件请求。

典型异常：

- 除零；
- 缺页；
- 非法指令；
- 访问越权；
- 调试断点；
- 系统调用；
- 严重机器错误。

<Callout type="warning" title="先看教材术语体系">
有些教材把异常称为“内中断”，把“中断”作为内、外中断的总称；另一些资料把 Interrupt 专指外部中断。做题时应先按题目给出的术语体系判断。
</Callout>

## 16. 中断向量、中断向量表与 ISR

### 16.1 中断向量

中断向量是：

- 中断服务程序入口地址；或
- 能够据此定位入口地址的信息。

### 16.2 中断向量表

中断向量表完成：

```text
中断类型号 / 向量号
        ↓
中断处理程序入口地址
```

### 16.3 中断服务程序 ISR

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-004.svg" alt="中断向量和中断服务程序" />

ISR（Interrupt Service Routine）通常完成：

1. 保护必要现场；
2. 执行具体中断处理；
3. 恢复现场；
4. 执行中断返回。

## 17. 中断响应全过程

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-005.svg" alt="典型中断处理过程" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-006.svg" alt="中断处理中硬件与软件的分工" />

外部中断的典型流程可以抽象为：

```text
设备提出中断请求
      ↓
CPU 完成当前指令
      ↓
检查中断允许与优先级
      ↓
关中断/进入中断状态
      ↓
保存断点
      ↓
识别中断源并取得入口
      ↓
执行 ISR
      ↓
恢复现场
      ↓
中断返回
      ↓
继续原程序
```

“完成当前指令后响应”是外部中断的典型特征；异常则可能在当前指令执行过程中检测到。

### 17.1 外部中断真正被响应需要哪些条件

可把一次可屏蔽外部中断是否进入处理程序，抽象为四个条件同时满足：

```text
存在有效中断请求
      +
中断允许 / 未被屏蔽
      +
优先级仲裁允许响应
      +
到达体系结构规定的可响应时点
```

因此，“设备一提出请求，CPU 就立即跳到 ISR”通常是错误的。经典 408 模型中，外部中断通常在**当前指令执行结束后**检查并响应。

### 17.2 中断隐指令

408 教材常把以下硬件自动完成的动作统称为**中断隐指令**：

- 关中断；
- 保存断点；
- 形成/取得中断服务程序入口地址。

它不是存储在程序中的普通机器指令，而是一组硬件自动操作。

<Callout type="warning" title="检测到请求 ≠ 已经响应">
设备发出请求、CPU 采样到请求、优先级仲裁通过、保存断点并进入 ISR 是不同事件。题目问“响应时刻”时，必须看它问的是哪一步。
</Callout>

## 18. 断点、现场与软硬件分工

### 18.1 断点

断点是为了中断处理结束后能继续原程序而必须保留的**执行位置与基本处理器状态**，典型包括：

- PC；
- PSW / FLAGS；
- 某些体系结构规定的其他必要状态。

### 18.2 现场

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-007.svg" alt="断点与现场的区别" />

现场通常指被中断程序正在使用、而 ISR 可能破坏的工作状态，例如：

- 通用寄存器；
- 地址寄存器；
- 其他临时状态。

408 常见抽象分工：

| 内容 | 常见完成者 |
| --- | --- |
| 保存断点 | 硬件 |
| 形成 ISR 入口 | 硬件 |
| 保护通用寄存器等现场 | ISR 软件 |
| 恢复现场 | ISR 软件 |
| 恢复断点并返回 | 中断返回机制 |

> **高频口诀**
>
> **硬件保断点，软件保现场。**

### 18.3 “保存什么”取决于返回后必须恢复什么

判断某状态是否必须保护，可直接问：

> **若 ISR 改坏了这个状态，中断返回后原程序还能否继续得到同样的执行结果？**

- PC/返回位置必须可恢复，否则不知道回哪里；
- 条件码若会影响后续分支，也属于必须恢复的处理器状态；
- ISR 要使用的通用寄存器若原程序也在使用，通常需先保存；
- 纯粹属于 CPU 内部实现、对软件不可见且硬件可自行恢复的状态，不要求由 ISR 手工保存。

<Callout type="warning" title="这只是常见 408 抽象">
具体 CPU 可能由硬件自动保存更多状态，也可能采用不同的栈帧格式。综合题必须优先服从题设，而不是机械套口诀。
</Callout>

## 19. 中断优先级、屏蔽与嵌套

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-008.svg" alt="中断优先级与中断嵌套" />

> **真题考查**
>
> - 中断优先级/嵌套：2011 年第 21 题、2017 年第 22 题、2021 年第 22 题
> - 中断屏蔽：2011 年第 19、21 题，2020 年第 21 题等

### 19.1 响应优先级与处理优先级

多个中断同时出现时，需要决定 CPU 先响应谁，这属于**响应优先级**。

若已经进入某个 ISR，又允许更高优先级的中断打断它，则还涉及**处理优先级/嵌套关系**。

二者并不一定完全相同；屏蔽字可以改变某一时刻实际允许谁抢占谁。

### 19.2 单重中断

进入 ISR 后，不再响应新的可屏蔽中断，直到当前 ISR 返回。

```text
主程序 → ISR A → 主程序
```

### 19.3 多重中断

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-009.svg" alt="单重中断与多重中断" />

低优先级 ISR 执行时允许更高优先级中断进入：

```text
主程序
  ↓
ISR C
  ↓ 被 B 抢占
ISR B
  ↓ 被 A 抢占
ISR A
  ↓ 返回
ISR B
  ↓ 返回
ISR C
  ↓ 返回
主程序
```

实现多重中断通常需要：

1. 在保护好必要状态后**重新开中断**；
2. 设置屏蔽关系，只允许符合优先级规则的中断源进入。

### 19.4 中断屏蔽字

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-010.svg" alt="中断屏蔽字" />

若约定：

- `1`：屏蔽；
- `0`：允许；

则多个中断源的屏蔽位合起来形成中断屏蔽字。

例如优先级：

```text
A > B > C > D
```

执行 `B` 的 ISR 时若只允许 `A` 抢占，可设置：

| 中断源 | 是否屏蔽 |
| --- | --- |
| A | 否 |
| B | 是 |
| C | 是 |
| D | 是 |

### 19.5 可屏蔽中断与 NMI

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-011.svg" alt="可屏蔽中断与不可屏蔽中断" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-012.svg" alt="INTR 与 NMI 信号" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-013.svg" alt="中断响应与屏蔽判断流程" />

- **可屏蔽中断**：可以通过 CPU 中断允许位或中断控制器屏蔽位暂时禁止；
- **不可屏蔽中断 NMI**：不受普通屏蔽机制控制，常用于严重硬件或电源类事件。

<Callout type="warning" title="屏蔽 ≠ 嵌套">
**屏蔽**回答“哪些中断现在有资格进入”；**嵌套**回答“当前 ISR 能否被另一个 ISR 打断”。二者相关，但不是同一概念。
</Callout>

## 20. Fault、Trap、Abort 与系统调用

> **真题考查**
>
> - 异常相关：2009、2012、2015、2016、2020、2021、2023、2024、2025、2026 等年份均有考查

异常按可恢复性和断点语义可进一步理解为：

| 类型 | 典型特点 | 例子 | 处理后常见去向 |
| --- | --- | --- | --- |
| Fault | 执行当前指令时发现，通常可修复 | 缺页、部分保护异常 | 修复后可能重新执行原指令 |
| Trap | 指令执行后或程序主动触发 | 调试、系统调用 | 通常从后续位置继续 |
| Abort | 严重且难以精确恢复 | 严重机器错误 | 通常不能正常恢复 |

### 20.1 判断 Fault 与 Trap：看“返回后重做哪条指令”

这是比背例子更稳的判据：

- **Fault**：异常处理修复条件后，通常希望**重新执行引发异常的那条指令**；
- **Trap**：触发点本身已经完成，返回时通常从**后继指令**继续；
- **Abort**：无法保证可精确恢复，通常不讨论正常重启。

现代处理器通常努力提供**精确异常（precise exception）**：在体系结构可见状态上，看起来像“异常指令之前的都已完成，异常指令及其之后的都没有产生不可撤销结果”。这也是流水线/乱序实现仍能让操作系统正确处理异常的重要基础。

### 20.2 缺页异常

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-014.svg" alt="异常与中断的关系" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-015.svg" alt="CPU 常见异常" />

```text
访问虚拟地址
   ↓
页表表明页面不在主存
   ↓
产生缺页异常
   ↓
OS 调页并更新页表/TLB
   ↓
重新执行原访问指令
```

因此缺页是典型 Fault。

### 20.3 除零与保护异常

整数除零、非法指令、地址越权等都与当前执行指令同步发生。

### 20.4 自陷与系统调用

<InlineSvg src="/images/computer-organization/computer-organization-cpu-interrupt-016.svg" alt="CPU 自陷机制" />

用户程序执行 `syscall`、`trap` 等特殊指令，可主动进入操作系统：

```text
用户程序
   ↓
执行系统调用指令
   ↓
产生同步控制转移
   ↓
切换到内核态
   ↓
执行系统调用处理程序
   ↓
返回用户态
```

> **系统调用不是普通函数调用。**
>
> 普通函数调用仍在同一特权级内改变控制流；系统调用需要通过受控异常/陷阱机制进入内核态。

<Callout type="info" title="系统调用指令通常必须允许用户态执行">
用户程序正是通过 `syscall` / `ecall` / `trap` 等受控入口申请内核服务。因此“系统调用指令能从用户态发起”与“内核服务在内核态执行”并不矛盾；真正的权限检查和特权级切换由异常入口机制完成。
</Callout>
