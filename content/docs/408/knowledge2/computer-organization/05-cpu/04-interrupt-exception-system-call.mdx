异常与中断的共同目标是：

> **在特殊事件出现时，让 CPU 安全地离开当前控制流，进入相应处理程序，并在条件允许时恢复执行。**

> **真题标签｜异常与中断**
>
> 原资料索引：中断相关选择题在 2010、2012、2013、2014、2015、2018、2019、2020、2022、2023、2024、2026 等年份多次出现；解答题包括 2009 第 43 题、2016 第 44 题、2017 第 45 题、2023 第 46 题。中断优先级/嵌套常见于 2011 第 21 题、2017 第 22 题、2021 第 22 题。

## 5.4.1 外部中断与异常

### 外部中断 Interrupt

来自 CPU 外部，例如：

- 键盘、网卡、磁盘等 I/O 设备；
- 定时器；
- 外部硬件请求。

典型特点：

- 与当前正在执行的某条指令没有直接因果关系；
- **异步**；
- 通常在当前指令完成后检查并响应。

### 异常 Exception

由当前指令执行或 CPU 内部检测到的事件引起，例如：

- 除零；
- 非法指令；
- 缺页；
- 访问越权；
- 调试陷阱；
- 系统调用。

典型特点：

- 与当前指令有直接关系；
- **同步**。

> **术语提醒**
>
> 部分教材把异常称为“内中断”，并把“中断”作为总称；另一些资料把 `Interrupt` 专指外部中断。做题时先确认题目采用的术语体系。

## 5.4.2 中断向量、向量表与 ISR

- **中断向量**：中断服务程序入口地址，或能够定位入口地址的信息；
- **中断向量表**：从中断类型号映射到处理程序入口；
- **ISR**：Interrupt Service Routine，中断服务程序。

典型映射：

```text
中断源/类型号
      ↓
中断向量表
      ↓
ISR 入口地址
```

## 5.4.3 中断响应全过程

典型流程：

```text
设备提出请求
   ↓
CPU 完成当前指令
   ↓
判断是否允许响应
   ↓
中断响应：关中断、保存断点、形成服务程序入口
   ↓
进入 ISR
   ↓
保护现场
   ↓
处理中断事件
   ↓
恢复现场
   ↓
中断返回
   ↓
恢复原程序
```

### “中断隐指令”是什么

408 教材常把硬件自动完成的：

- 关中断；
- 保存断点；
- 形成 ISR 入口地址；

统称为**中断隐指令**。

它不是程序员编写并存放在主存中的普通机器指令，而是硬件中断响应阶段自动完成的一组动作。

## 5.4.4 硬件保断点，软件保现场

### 断点

为了以后能够恢复原控制流而必须保存的信息，核心通常是：

- PC / 返回地址；
- PSW / FLAGS 等必要处理器状态。

### 现场

被中断程序正在使用、而 ISR 可能破坏的工作状态，常包括：

- 通用寄存器；
- 地址寄存器；
- 其他软件可见寄存器。

经典 408 口径：

| 内容 | 通常由谁完成 |
| --- | --- |
| 保存断点 | 硬件 |
| 保存通用寄存器等现场 | ISR 软件 |
| 恢复现场 | ISR 软件 |
| 恢复断点并返回 | 中断返回机制 |

口诀：

> **硬件保断点，软件保现场。**

但实际体系结构可能自动保存更多内容，因此综合题必须服从题设。

## 5.4.5 中断允许、屏蔽与 NMI

### 可屏蔽中断

可以通过：

- CPU 的全局中断允许状态；
- 中断控制器中的屏蔽位；

暂时禁止响应。

### 不可屏蔽中断 NMI

普通屏蔽机制不能禁止，通常留给严重事件。

以典型 x86 术语：

- `INTR`：可屏蔽中断；
- `NMI`：不可屏蔽中断。

> **易错点**
>
> “关中断”通常指禁止可屏蔽中断，不等于所有类型的中断和异常都完全消失。

## 5.4.6 中断优先级、响应优先级与处理优先级

当多个中断同时请求时，系统必须决定先处理谁。

应区分：

- **响应优先级**：多个请求同时出现时，谁先被 CPU 响应；
- **处理优先级**：ISR 执行过程中，谁允许打断谁。

两者可能一致，也可能借助中断屏蔽字重新组织。

## 5.4.7 单重中断与多重中断

### 单重中断

进入 ISR 后不再接受新的可屏蔽中断，直到本次中断处理结束。

```text
主程序 → ISR A → 主程序
```

### 多重中断 / 中断嵌套

低优先级 ISR 执行时，允许更高优先级中断抢占：

```text
主程序
  ↓
ISR C
  ↓ 被 B 抢占
ISR B
  ↓ 被 A 抢占
ISR A
  ↓ 返回
ISR B
  ↓ 返回
ISR C
  ↓ 返回
主程序
```

实现多重中断通常需要：

1. 适当时机重新开中断；
2. 设置屏蔽字，只允许更高处理优先级的中断进入；
3. 正确保存每一层现场。

## 5.4.8 中断屏蔽字

假设处理优先级：

```text
A > B > C > D
```

执行 `B` 的 ISR 时，如果只允许 `A` 抢占，可设置：

| 中断源 | 当前是否屏蔽 |
| --- | --- |
| A | 否 |
| B | 是 |
| C | 是 |
| D | 是 |

因此屏蔽字解决的是：

> **“当前哪些中断有资格被响应”。**

它常被用来实现期望的处理中断优先级。

## 5.4.9 Fault、Trap、Abort

| 类型 | 典型特征 | 例子 | 处理后返回位置 |
| --- | --- | --- | --- |
| Fault | 当前指令执行中发现，通常可修复 | 缺页、部分保护异常 | 常重新执行原指令 |
| Trap | 指令完成后或程序主动进入 | 调试、系统调用 | 常从下一条继续 |
| Abort | 严重错误，难以精确恢复 | 严重硬件故障 | 通常不能正常恢复 |

### 缺页为什么属于 Fault

```text
访问虚拟地址
   ↓
发现页不在内存
   ↓
触发缺页异常
   ↓
OS 调页并修改页表
   ↓
重新执行原来的访存指令
```

只有重新执行原指令，才能真正完成原来那次访存。

## 5.4.10 系统调用与自陷

系统调用不是普通函数调用，它需要让用户程序安全进入内核态。

典型过程：

```text
用户态程序
   ↓
执行 syscall / trap 类指令
   ↓
产生同步陷入
   ↓
CPU 保存必要状态并切换特权级
   ↓
进入内核系统调用处理程序
   ↓
OS 完成服务
   ↓
恢复用户态执行
```

因此：

> **系统调用的“服务逻辑”由操作系统软件实现，但进入内核所依赖的陷入/特权切换机制需要体系结构和硬件支持。**

## 5.4.11 异常/中断题的稳定判断顺序

遇到题目时按以下顺序：

```text
① 事件来自 CPU 外部还是当前指令？
② 同步还是异步？
③ 能否被普通中断屏蔽？
④ 断点应该保存在哪里？
⑤ 硬件自动完成什么？软件完成什么？
⑥ 返回时是重执行原指令还是执行下一条？
⑦ 是否允许嵌套？当前屏蔽字允许谁进入？
```

这一套顺序比死记各种异常名称更可靠。
