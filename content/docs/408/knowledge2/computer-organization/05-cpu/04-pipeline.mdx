## 21. 五级指令流水线

> **真题考查**
>
> - 流水线结构选择题：2009 年第 18 题、2011 年第 18 题、2013 年第 18 题、2017 年第 19 题、2018 年第 20 题、2020 年第 17 题
> - 解答题：2012 年第 44 题

经典五级流水线：

```text
IF → ID → EX → MEM → WB
```

| 阶段 | 主要任务 |
| --- | --- |
| IF | 取指，形成顺序下一 PC |
| ID | 指令译码、读取源寄存器、扩展立即数 |
| EX | ALU 运算、有效地址计算、比较/分支判断 |
| MEM | Load/Store 访问数据存储器 |
| WB | 将 ALU 或 Load 结果写回寄存器 |

### 21.1 各阶段的关键时点

- 源寄存器通常在 **ID** 阶段读取；
- 普通 ALU 指令的结果通常在 **EX** 结束时产生；
- Load 的数据通常在 **MEM** 结束时才取得；
- 结果通常在 **WB** 写回寄存器文件。

这些“何时读、何时产生、何时写”是判断数据冒险的核心。

<Callout type="warning" title="不用某阶段 ≠ 从流水线中消失">
Store 或分支可能不需要 WB，普通 ALU 指令可能不真正访问数据存储器，但在固定五级流水结构的时序图中，这些位置通常仍占有对应时隙，只是执行空操作或传递状态。
</Callout>

## 22. 单周期、多周期与流水线处理器

### 22.1 单周期处理器

<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-001.svg" alt="单周期指令执行" />

> **真题考查**
>
> - 2016 年第 20 题、2020 年第 17 题

每条机器指令在一个时钟周期内完成。

因此时钟周期必须不短于**最慢指令的组合路径延迟**，简单指令也被迫等待同样长的周期。

### 22.2 多周期处理器

把一条指令拆成多个较短阶段，不同指令可使用不同数量周期。

传统多周期实现通常仍是：

> **一条指令结束后，下一条才开始。**

### 22.3 流水线处理器

<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-002.svg" alt="五级指令流水线物理数据通路" />

流水线允许**多条指令的不同阶段重叠执行**。

因此：

- 多周期：重点是“一条指令被拆成多拍”；
- 流水线：重点是“多条指令相互重叠”。

## 23. 流水段寄存器与时空图

<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-003.svg" alt="流水段寄存器" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-004.svg" alt="非流水与流水执行时间对比" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-005.svg" alt="流水线常规时序图" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-006.svg" alt="流水线时空图" />

五级流水线之间通常设置：

- `IF/ID`；
- `ID/EX`；
- `EX/MEM`；
- `MEM/WB`。

它们在时钟边沿锁存上一阶段输出，使不同流水段可以在下一周期并行工作。

理想时序：

| 指令 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| I1 | IF | ID | EX | MEM | WB |  |  |  |
| I2 |  | IF | ID | EX | MEM | WB |  |  |
| I3 |  |  | IF | ID | EX | MEM | WB |  |
| I4 |  |  |  | IF | ID | EX | MEM | WB |

流水线的主要收益是：

> **提高稳态吞吐率，而不是必然降低单条指令从进入到完成的延迟。**

### 23.1 延迟与吞吐率要分开

- **Latency（延迟）**：一条指令从进入流水线到完成经历多久；
- **Throughput（吞吐率）**：单位时间平均完成多少条指令。

理想 $k$ 级流水线稳定后可做到“每拍完成 1 条”，并不等于每条指令只经历 1 拍。对于基本流水线，理想稳态 CPI 约为 $1$；若超标量每拍平均完成多条指令，平均 CPI 甚至可以小于 $1$。

## 24. 三类流水线冒险

> **真题考查**
>
> - 选择题：2010 年第 19 题、2016 年第 19 题、2019 年第 18 题、2023 年第 19 题、2024 年第 19 题
> - 解答题：2012 年第 44 题、2014 年第 44 题

理想流水线要求：

1. 当前需要的硬件资源可用；
2. 当前需要的数据已产生；
3. 当前应取哪条下一指令已经确定。

对应三类冒险：

| 冒险 | 根因 | 常见处理 |
| --- | --- | --- |
| 结构冒险 | 多条指令争用同一硬件资源 | 增加资源、分离资源、阻塞 |
| 数据冒险 | 指令间存在数据依赖 | 前递、阻塞、调度 |
| 控制冒险 | 下一条正确 PC 未确定 | 阻塞、预测、冲刷、延迟分支 |

### 24.1 结构冒险

<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-007.svg" alt="流水线中的结构冒险" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-008.svg" alt="通过气泡解决结构冒险" />

例子：

- IF 与 MEM 同时访问单端口统一存储器；
- 多条指令争用唯一功能部件；
- 寄存器文件端口数不足。

常见解决：

- 指令 Cache / 数据 Cache 分离；
- 增加端口或功能单元；
- 插入 Stall。

## 25. RAW、WAR 与 WAW

判断相关时先写出每条指令的**读集合**和**写集合**。

### 25.1 RAW：Read After Write

```text
前指令：写 X
后指令：读 X
```

后指令必须看到前指令产生的新值，因此 RAW 是**真数据相关**。

### 25.2 WAR：Write After Read

```text
前指令：读 X
后指令：写 X
```

属于名称相关。

### 25.3 WAW：Write After Write

<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-009.svg" alt="流水线数据相关" />

```text
前指令：写 X
后指令：写 X
```

必须保证最终写入顺序正确，也属于名称相关。

<Callout type="warning" title="经典顺序五级流水线主要关注 RAW">
在顺序发射、顺序执行、顺序写回的经典五级流水线中，WAR 与 WAW 通常不会成为实际流水冒险；它们更常出现在乱序执行、多发射等复杂处理器中。
</Callout>

## 26. Stall、Forwarding 与 Load-Use

<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-010.svg" alt="通过流水线停顿解决数据冒险" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-011.svg" alt="ALU 结果数据前递" />

### 26.1 无前递时的 Stall

```asm
I1: ADD R1, R2, R3
I2: SUB R4, R1, R5
```

若 `I2` 在 ID 阶段读 `R1`，而 `I1` 直到 WB 才写回，则必须等待。

若题目规定寄存器文件在同一周期支持“**先写后读**”，则生产者 WB 与消费者 ID 可以落在同一周期；若题目没有这一约定，应按题设时序判断。

### 26.2 Forwarding / Bypassing

普通 ALU 指令的结果在 EX 结束时已经产生，因此可直接从流水段寄存器送给后继指令的 EX 输入，而无需等待 WB。

常见路径：

- `EX/MEM → EX`；
- `MEM/WB → EX`。

### 26.3 Load-Use 冒险

<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-012.svg" alt="Load Use 数据冒险" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-013.svg" alt="Load Use 插入一个停顿周期" />

```asm
I1: LOAD R1, 0(R2)
I2: ADD  R3, R1, R4
```

Load 的数据到 MEM 结束时才产生，而紧随其后的 `ADD` 在下一拍 EX 开始时就需要该值。

因此经典五级流水线即使具有前递，通常仍要插入 **1 个气泡**。

> **高频记忆**
>
> - 普通 ALU → 紧邻 ALU 的 RAW：前递常能消除停顿；
> - Load → 紧邻使用者：经典五级流水通常仍需停 1 拍。

### 26.4 “结果何时可用”与“使用者何时需要”

判断能否前递，本质只比较两个时间点：

```text
生产者：结果在哪一级末尾可用？
消费者：这个值在哪一级开始前必须到达？
```

若生产者来得及通过已有旁路送到消费者，就无需等待；若来不及，只能 Stall。Load-Use 之所以特殊，就是因为 Load 的数据在 MEM 末尾才到，而紧邻消费者在同一周期的 EX 开始时已经需要它。

Store 也可能成为数据相关的消费者。例如：

```asm
ADD   R1, R2, R3
STORE R1, 0(R4)
```

这里 `R1` 是待写入存储器的数据。是否需要停顿，取决于数据存储器真正在哪一级需要 Store 数据，以及是否存在到该位置的前递路径。

### 26.5 综合题判定模板

<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-014.svg" alt="包含停顿的综合流水线时序图" />

对每条指令依次列出：

```text
读哪些寄存器？
写哪些寄存器？
结果在哪一级末尾产生？
使用者在哪一级需要？
是否存在前递路径？
若没有，需停几拍？
```

## 27. 控制冒险与分支处理

<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-015.svg" alt="流水线控制冒险" />

分支或跳转改变 PC，因此在分支结果确定之前，处理器可能已经取入了错误路径上的指令。

例如：

```asm
100: ADD R1, R2, R3
104: BEQ R1, #0, 200
108: SUB R4, R5, R6
112: MUL R7, R8, R9
...
200: OR R10, R11, R12
```

若 `BEQ` 到 EX 才确定跳转，则 `108`、`112` 可能已经进入流水线；若最终跳到 `200`，这些错误路径指令必须被**冲刷（Flush）**。

常见处理：

- **阻塞**：结果确定前停止取有效指令；
- **分支预测**：提前预测 Taken / Not Taken；
- **预测失败冲刷**：清除错误路径指令，并从正确 PC 重新取指；
- **延迟分支**：由编译器把可安全执行的指令放入延迟槽（特定 ISA 的传统策略）。

分支惩罚取决于：

- 分支在哪一级判定；
- 目标地址何时形成；
- 预测策略；
- 题设是否支持提前比较或旁路。

## 28. 流水线性能计算

### 28.1 流水线时钟周期

若各段组合逻辑延迟为：

$$
t_1,t_2,\ldots,t_k
$$

流水段寄存器开销为 $t_r$，则：

$$
T_c=\max(t_1,t_2,\ldots,t_k)+t_r
$$

若忽略寄存器开销：

$$
T_c=\max(t_1,t_2,\ldots,t_k)
$$

### 28.2 理想完成时间

理想 $k$ 段流水线完成 $n$ 个任务：

$$
T=(k+n-1)T_c
$$

若存在 $s$ 个额外停顿周期，则：

$$
T=(k+n-1+s)T_c
$$

### 28.3 吞吐率

$$
TP=\frac{n}{T}
$$

理想情况下，当 $n$ 足够大：

$$
TP_{\max}\to\frac{1}{T_c}
$$

### 28.4 加速比

若同一任务在非流水结构中每个需 $kT_c$，则：

$$
S
=
\frac{nkT_c}{(k+n-1)T_c}
=
\frac{nk}{k+n-1}
$$

当 $n\to\infty$：

$$
S\to k
$$

这是**理想上限**，真实处理器还会受到流水段不均衡、冒险、Cache Miss、分支预测失败等影响。

### 28.5 效率

理想情况下可定义：

$$
E=\frac{S}{k}
$$

当任务数很大且无额外停顿时，$E$ 才趋近于 $1$。

### 28.6 实际 CPI：把各种气泡都折算成“每条指令多几拍”

稳态分析中可写成：

$$
CPI_{actual}=CPI_{ideal}+CPI_{stall}
$$

若有多类独立停顿来源，可继续拆分：

$$
CPI_{actual}
= CPI_{ideal}
+ CPI_{data}
+ CPI_{control}
+ CPI_{structure}
+ \cdots
$$

例如分支频率为 $f_b$，预测失败率为 $p_m$，每次预测失败平均损失 $P$ 个周期，则分支预测失败带来的平均 CPI 增量可近似为：

$$
\Delta CPI_{branch}=f_b\,p_m\,P
$$

若还给出 Cache Miss 频率与 Miss Penalty，也可用相同思路计算平均停顿周期。

> **性能题统一思路**
>
> 先把事件概率/频率乘以“每次额外损失周期”，得到平均每条指令增加的周期数，再代入 $CPU\ Time=IC\times CPI\times T_c$。

<Callout type="warning" title="公式使用前先读题设">
若各流水段延迟不相等、存在寄存器开销、分支惩罚或停顿周期，不可直接把“段数 $k$”当作实际加速比。
</Callout>

## 29. 超标量、超流水线与 VLIW

<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-016.svg" alt="超标量流水线" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-017.svg" alt="超流水线" />

> **真题考查**
>
> - 2017 年第 17 题等

| 技术 | 核心思想 | 并行性主要由谁发现/安排 |
| --- | --- | --- |
| 超标量 Superscalar | 一个时钟周期可发射多条独立指令 | 硬件动态判断 |
| 超流水线 Superpipeline | 把流水段进一步细分，提高可用时钟频率 | 流水结构设计 |
| VLIW | 一条超长指令中显式编码多个并行操作 | 编译器静态安排 |

### 29.1 超标量

依赖多个执行单元，在一个周期内发射或执行多条互不冲突的指令。

### 29.2 超流水线

把原来的流水段切得更细，可缩短单段组合逻辑延迟，但会增加：

- 流水段寄存器开销；
- 分支预测失败代价；
- 控制复杂度。

### 29.3 VLIW

<InlineSvg src="/images/computer-organization/computer-organization-cpu-pipeline-018.svg" alt="VLIW 超长指令字" />

编译器在编译期把能并行的操作组织到同一条超长指令中，因此硬件动态调度压力相对小，但更依赖编译器和 ISA 编码支持。

### 29.4 动态流水线与乱序执行的基本概念

当前考纲要求掌握**动态流水线的基本概念**。不必把复杂微体系结构细节背成电路，但要知道它为什么出现：

> 当前面某条指令因数据或功能单元等待而暂时不能执行时，如果后面存在与它无关、且操作数已经就绪的指令，硬件可以让后者先执行，从而减少流水线空闲。

典型思想包括：

- **动态调度**：运行时判断哪些指令已具备执行条件；
- **乱序执行**：允许后来的独立指令先进入执行单元；
- **寄存器重命名**：为不同逻辑结果分配不同物理寄存器，消除 WAR/WAW 这类名称相关；
- **按序提交**：即使中间执行次序改变，也让体系结构可见结果按程序顺序生效，以便维持精确异常。

<Callout type="info" title="乱序执行不改变程序语义">
硬件可以改变内部执行时机，但必须保证对软件可见的结果与 ISA 规定的程序顺序语义一致。RAW 真相关不能凭空消除；WAR/WAW 则可通过寄存器重命名解除名称冲突。
</Callout>
