本章讨论 **中央处理器（CPU）**。复习时不要把寄存器、控制器、中断、流水线分成彼此孤立的知识点，而应始终围绕一条主线理解：

> **一条机器指令进入 CPU 后，数据走哪条路径？谁发出控制信号？什么时候执行？发生异常或中断时怎样转移？多条指令又如何重叠执行？**

| 内容             | 复习优先级 | 核心问题                          |
| -------------- | ----- | ----------------------------- |
| CPU 功能、结构与数据通路 | 高     | 数据在哪里存、经过哪些部件、如何流动            |
| CPU 寄存器        | 高     | PC、IR、MAR、MDR、通用寄存器、状态寄存器各做什么 |
| 控制器            | 中高    | 微操作如何产生，硬布线与微程序有何区别           |
| 异常与中断          | 高     | 中断全过程、软硬件分工、屏蔽与嵌套             |
| 指令流水线          | 高     | 五级流水、时空图、三类冒险、性能计算            |
| 多处理机与多核        | 低     | Flynn 分类、物理核/逻辑核、共享存储结构       |

## 5.1 CPU 的功能和基本结构

### 5.1.1 CPU 的基本功能

冯·诺依曼计算机由 **运算器、控制器、存储器、输入设备、输出设备** 五大部分组成，其中 CPU 主要集成：

* **运算器**：完成算术运算、逻辑运算、移位、比较等数据处理；
* **控制器**：取出并解释指令，按照正确的时序产生控制信号，协调各部件工作。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-001.svg" alt="冯·诺依曼计算机基本组成" />

从现代 CPU 的实现角度，更适合把 CPU 分成：

1. **数据通路（Datapath）**
2. **控制器（Control Unit）**

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-002.svg" alt="CPU 运算部件与控制部件" />

其中：

* **数据通路**负责真正保存、传送和加工数据；
* **控制器**根据当前指令、时钟和状态信息，决定数据通路下一步做什么。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-003.svg" alt="CPU 数据通路与控制器" />

> **408 高频理解**
>
> 数据通路回答的是 **“数据怎么走”**；控制器回答的是 **“为什么现在这样走”**。

---

### 5.1.2 数据通路

> **历年真题范围**
>
> 选择题：2017 年第 19 题、2021 年第 18 题、2023 年第 18 题、2025 年第 19 题、2026 年第 20 题。
> 解答题：2013 年第 44 题、2015 年第 43 题、2026 年第 44 题。

**数据通路**是指 CPU 执行指令时，数据在 CPU 内部所经过的路径以及路径上的功能部件。

典型部件包括：

* ALU；
* 通用寄存器组；
* PC、IR、MAR、MDR 等特殊寄存器；
* 多路选择器；
* 三态门；
* 内部总线；
* 流水段寄存器等。

数据通路中的元件可分成两类。

#### 组合逻辑元件

**组合逻辑元件**的输出只取决于当前输入，不保存历史状态。

典型部件：

* ALU；
* 译码器；
* 多路选择器；
* 三态门。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-004.svg" alt="译码器、多路选择器和三态门" />

**译码器**

若有 $n$ 位输入，最多可区分：

$$
2^n
$$

种输入组合。

译码器通常将编码后的操作码、地址等转换为具体的选择信号。

**多路选择器（MUX）**

从多个输入中根据控制信号选择一路输出：

```text
Select = 0  →  选择输入 A
Select = 1  →  选择输入 B
```

**三态门**

除 `0` 和 `1` 外，还存在 **高阻态 Z**。

* 使能：输入可以驱动总线；
* 禁止：输出呈高阻态，相当于暂时与总线断开。

三态门尤其适合实现 **多个部件共享一条总线**。

#### 时序逻辑元件

时序逻辑元件具有 **存储状态** 的能力，输出与当前输入以及此前状态有关，并通常由时钟控制。

典型部件：

* 通用寄存器；
* PC；
* IR；
* MAR；
* MDR；
* 状态寄存器；
* 暂存寄存器；
* 流水段寄存器；
* 存储器。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-005.svg" alt="CPU 内部时序逻辑元件" />

> **易错点**
>
> ALU 本身是组合逻辑电路，不负责长期保存运算结果。
> 运算结果需要送入寄存器等时序逻辑元件中保存。

---

### 5.1.3 控制器

控制器本身不负责完成加法、乘法或长期保存数据，而是根据指令生成相应的 **控制信号**。

典型执行过程：

1. 根据 PC 取得下一条指令地址；
2. 从主存取出指令；
3. 将指令送入 IR；
4. 对操作码译码；
5. 根据指令功能产生微操作控制信号；
6. 控制寄存器、ALU、存储器和总线完成执行；
7. 确定下一条指令地址。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-006.svg" alt="控制器基本工作过程" />

## 5.2 CPU 中的寄存器——以 8086 为辅助理解

8086 不是本章所有结论的唯一实现，但它能帮助理解寄存器、内部数据通路和控制部件之间的关系。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-007.svg" alt="8086 CPU 基本结构" />

从抽象的数据通路角度，可以看到：

* ALU；
* 通用寄存器；
* 段寄存器；
* 指针、变址寄存器；
* FLAGS；
* IR；
* MAR、MDR 等教材抽象部件；
* 内部总线；
* 指令队列。

### 5.2.1 寄存器分类

> **历年真题范围**
>
> 选择题：2010 年第 18 题、2012 年第 24 题、2014 年第 17 题、2015 年第 23 题、2016 年第 18 题、2017 年第 18 题、2019 年第 17 题、2020 年第 12 题、2021 年第 17 题、2024 年第 25 题。
> 解答题：2015 年第 43 题、2022 年第 43 题。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-008.svg" alt="8086 寄存器分类" />

### 通用寄存器

8086 的四个典型通用寄存器为：

| 寄存器  | 名称    | 常见用途       |
| ---- | ----- | ---------- |
| `AX` | 累加器   | 算术、逻辑运算    |
| `BX` | 基址寄存器 | 基址寻址       |
| `CX` | 计数寄存器 | 循环、移位次数    |
| `DX` | 数据寄存器 | I/O、大整数运算等 |

### 段寄存器

| 寄存器  | 含义                |
| ---- | ----------------- |
| `CS` | Code Segment，代码段  |
| `DS` | Data Segment，数据段  |
| `SS` | Stack Segment，栈段  |
| `ES` | Extra Segment，附加段 |

### 指针与变址寄存器

| 寄存器  | 作用                                |
| ---- | --------------------------------- |
| `SP` | Stack Pointer，栈顶指针                |
| `BP` | Base Pointer，栈帧基址                 |
| `SI` | Source Index，源变址                  |
| `DI` | Destination Index，目的变址            |
| `IP` | Instruction Pointer，下一条指令在代码段中的偏移 |

### 状态寄存器

`FLAGS` 用于保存运算状态和控制状态。

### 教材中的特殊寄存器

* `IR`：指令寄存器；
* `MAR`：存储器地址寄存器；
* `MDR`：存储器数据寄存器；
* `T`：暂存寄存器。

> **程序员可见性**
>
> 汇编程序通常可以直接访问通用寄存器、指针/变址寄存器、段寄存器以及部分状态寄存器。
> `MAR`、`MDR`、`IR` 和内部暂存寄存器通常属于 **程序员不可见寄存器**。

### 5.2.2 段寄存器

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-009.svg" alt="8086 分段内存与段寄存器" />

8086 使用分段地址结构：

* `CS`：代码段；
* `DS`：数据段；
* `SS`：栈段；
* `ES`：附加段。

程序逻辑上常包含：

* 代码段；
* 数据段；
* 栈段；
* 附加数据段。

### 5.2.3 SP、BP 与函数栈

函数调用时，运行状态通常保存在栈中。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-010.svg" alt="BP 与 SP 在函数栈中的关系" />

在典型向低地址增长的栈中：

* `SP` 指向当前栈顶；
* `BP` 常作为当前栈帧的基准位置。

通过基址加偏移可以访问：

* 参数；
* 局部变量；
* 保存的寄存器；
* 返回地址等。

---

### 5.2.4 IP 与程序计数器

8086 中，`IP` 保存 **下一条待执行指令在当前代码段中的偏移量**。

由于采用分段寻址，真正的物理地址由 `CS:IP` 共同确定：

$$
\text{Physical Address}
=
CS\times16+IP
$$

因此，从“程序计数器负责指出下一条指令地址”这一抽象意义上，可以将 8086 的 `CS:IP` 看成 PC 功能的一种具体实现。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-011.svg" alt="8086 CS IP 取指过程" />

正常顺序执行时：

$$
IP
\leftarrow
IP+\text{当前指令长度}
$$

遇到：

* 跳转；
* 调用；
* 返回；
* 中断；
* 异常

时，则由控制转移机制修改下一条指令地址。

---

### 5.2.5 变址寄存器

`SI` 和 `DI` 常用于：

* 数组访问；
* 字符串操作；
* 变址寻址。

例如遍历 5 个 16 位元素：

```asm
; DS 已经指向数组所在的数据段
MOV CX, 5
MOV SI, 0

NEXT_ELEMENT:
    MOV AX, [SI]
    ; 对 AX 中的数据进行处理
    ADD SI, 2
    LOOP NEXT_ELEMENT
```

字符串复制的典型思路：

```asm
; DS:SI 指向源串
; ES:DI 指向目的串

MOV SI, OFFSET source
MOV DI, OFFSET dest
MOV CX, length

CLD
REP MOVSB
```

其中：

* `CLD` 清除方向标志；
* `REP MOVSB` 重复执行字节复制；
* `SI`、`DI` 随字符串指令自动变化；
* `CX` 用作重复次数。

## 5.3 状态/标志寄存器

> **历年真题范围**
>
> 选择题：2011 年第 17 题、2018 年第 19 题、2023 年第 16 题。
> 解答题：2013 年第 44 题、2017 年第 44 题、2019 年第 45 题。

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-012.svg" alt="8086 FLAGS 标志寄存器" />

8086 FLAGS 中常见的 9 个标志位可以分为：

* **条件/状态标志**

  * `CF`
  * `PF`
  * `AF`
  * `ZF`
  * `SF`
  * `OF`
* **控制标志**

  * `TF`
  * `IF`
  * `DF`

---

### 5.3.1 条件标志

| 标志   | 名称              | 含义                      |
| ---- | --------------- | ----------------------- |
| `CF` | Carry Flag      | 进位/借位                   |
| `PF` | Parity Flag     | 结果低 8 位中 `1` 的个数为偶数时置 1 |
| `AF` | Auxiliary Carry | 低 4 位向高 4 位发生进位/借位      |
| `ZF` | Zero Flag       | 结果为 0 时置 1              |
| `SF` | Sign Flag       | 结果最高位                   |
| `OF` | Overflow Flag   | 有符号运算溢出                 |

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-013.svg" alt="CPU 条件标志工作原理" />

### CF 与 OF 必须区分

这是 408 高频易错点。

| 标志   | 主要解释对象 | 判断的硬件特征         |
| ---- | ------ | --------------- |
| `CF` | 无符号数越界 | 最高位向更高位产生的进位/借位 |
| `OF` | 有符号数越界 | 有符号结果超出补码表示范围   |

CPU 的加法器 **并不知道一串二进制数究竟表示有符号数还是无符号数**。它只完成位运算并同时生成不同状态信息。

例如 8 位运算：

```text
  01111111
+ 00000001
----------
  10000000
```

得到：

* `CF = 0`
* `OF = 1`

若解释为有符号数：

```text
127 + 1
```

结果超出 8 位补码范围，因此发生溢出。

若解释为无符号数：

```text
127 + 1 = 128
```

完全合法。

---

### 5.3.2 OF 的判断

对两个 $n$ 位补码数 $A$、$B$ 做加法：

$$
C=A+B
$$

有符号加法发生溢出的条件是：

> **两个操作数同号，但结果与操作数异号。**

可以写成：

$$
\mathrm{OF}
=
A_{n-1}B_{n-1}\overline{C_{n-1}}
+
\overline{A_{n-1}}
\overline{B_{n-1}}
C_{n-1}
$$

也可以利用符号位附近的进位判断：

$$
\mathrm{OF}
=
C_{\text{in,sign}}
\oplus
C_{\text{out,sign}}
$$

即：

> **进入符号位的进位 XOR 离开符号位的进位。**

减法：

$$
A-B
$$

可以转化为补码加法：

$$
A+(-B)
$$

再按相同思想判断。

---

### 5.3.3 CF 的判断

对于 $n$ 位加法器：

$$
\mathrm{CF}=c_n
$$

其中 $c_n$ 是最高位产生的最终进位。

对于无符号减法，若需要借位，则通常通过 `CF` 反映。

---

### 5.3.4 控制标志

#### IF：Interrupt Flag

* `IF = 1`：允许响应可屏蔽外部中断；
* `IF = 0`：禁止响应可屏蔽外部中断。

它不能屏蔽 NMI。

#### TF：Trap Flag

开启单步调试机制。

设置后，处理器可在执行单条指令后产生调试异常。

#### DF：Direction Flag

控制字符串操作的地址变化方向：

* `DF = 0`：`SI`、`DI` 自动增加，按 **低地址 → 高地址** 方向；
* `DF = 1`：`SI`、`DI` 自动减小，按 **高地址 → 低地址** 方向。

## 5.4 特殊寄存器与 CPU 外部接口

### 5.4.1 暂存寄存器

在单总线数据通路中，一条内部总线同一时刻只能传送一路数据。

若 ALU 需要两个输入，可以：

1. 先把第一个操作数送入暂存寄存器 `T`；
2. 再由总线传递第二个操作数；
3. ALU 同时读取 `T` 和当前总线输入；
4. 完成运算。

### 5.4.2 指令寄存器 IR

从存储器取出的当前机器指令通常先进入 `IR`。

控制器对：

* 操作码；
* 寻址相关字段；
* 寄存器编号等

进行译码，并产生后续控制信号。

---

### 5.4.3 CPU 引脚

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-014.svg" alt="8086 CPU 外部引脚" />

8086 是 16 位处理器：

* 数据总线宽度：16 位；
* 地址空间：1 MB；
* 因而需要 20 位地址。

其低位地址线与数据线复用：

| 信号              | 含义                |
| --------------- | ----------------- |
| `AD0–AD15`      | 低 16 位地址/16 位数据复用 |
| `A16/S3–A19/S6` | 高位地址/状态复用         |

由于同一引脚在不同时刻承担地址和数据功能，需要通过 `ALE` 等信号把地址锁存下来。

典型控制信号：

| 引脚/信号   | 作用                 |
| ------- | ------------------ |
| `RD#`   | 存储器或 I/O 读         |
| `WR#`   | 存储器或 I/O 写         |
| `ALE`   | 地址锁存使能             |
| `READY` | 外设是否准备就绪           |
| `HOLD`  | 外部设备申请总线           |
| `HLDA`  | CPU 响应总线申请         |
| `INTR`  | 可屏蔽中断请求            |
| `NMI`   | 不可屏蔽中断请求           |
| `INTA#` | 中断响应               |
| `RESET` | 处理器复位；8086 中为高电平有效 |

`READY` 可用于在慢速设备访问过程中插入等待状态。

`HOLD/HLDA` 则与 DMA 等需要暂时取得系统总线控制权的机制有关。
