中央处理器这一章的知识点很多，但所有内容都可以围绕一条主线理解：

> **一条机器指令进入 CPU 后，数据存在哪里、沿什么路径流动、谁产生控制信号、什么时候完成运算，发生控制转移时又由谁修改下一条指令地址？**

<Callout type="info" title="本章统一分析框架">

遇到 CPU 结构或数据通路题，优先按以下顺序分析：

1. 找到**源操作数**与**目的位置**；
2. 判断数据经过哪些寄存器、总线、MUX 与 ALU；
3. 写出 RTL 微操作；
4. 再由 RTL 反推控制信号；
5. 若涉及中断或流水线，再判断正常控制流在何处被改变。

</Callout>

## 1. CPU 的功能与基本结构

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-001.svg" alt="冯·诺依曼计算机基本组成" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-002.svg" alt="CPU 运算部件与控制部件" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-003.svg" alt="CPU 数据通路与控制器" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-006.svg" alt="控制器基本工作过程" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-007.svg" alt="8086 CPU 基本结构" />

CPU 主要由**运算器**与**控制器**构成；从现代实现角度，更适合抽象成：

- **数据通路（Datapath）**：保存、传送和加工数据；
- **控制器（Control Unit）**：根据指令、时钟和状态信息产生控制信号，决定数据通路下一步做什么。

| 部分 | 主要职责 | 典型部件 |
| --- | --- | --- |
| 数据通路 | 数据存储、传送与运算 | ALU、寄存器组、MUX、内部总线、流水段寄存器 |
| 控制器 | 指令解释、时序组织与控制信号产生 | 指令译码器、时序部件、硬布线逻辑或微程序控制器 |

> **真题考查**
>
> - 数据通路相关选择题：2017 年第 19 题、2021 年第 18 题、2023 年第 18 题、2025 年第 19 题、2026 年第 20 题
> - 数据通路相关解答题：2013 年第 44 题、2015 年第 43 题、2026 年第 44 题

### 1.1 数据通路到底是什么

**数据通路**不是某一个部件，而是执行指令时数据在 CPU 内部经过的**路径及其上的功能部件集合**。

常见部件包括：

- ALU；
- 通用寄存器组；
- PC、IR、MAR、MDR 等专用寄存器；
- 多路选择器 MUX；
- 三态门；
- 内部总线；
- 流水段寄存器。

因此：

> **ALU 是数据通路的一部分，但“数据通路 = ALU”是错误的。**

### 1.2 一条指令在 CPU 中怎样走完

从功能角度，一条指令通常经历“取指 → 译码 → 执行 → 必要时访存 → 必要时写回”。这不是要求所有处理器都物理划成五个模块，而是一条非常实用的分析主线：

```text
PC 给出取指位置
   ↓
取出机器指令并送入 IR
   ↓
译码：确定操作、源操作数、目的位置
   ↓
执行：ALU 运算 / 有效地址计算 / 分支判断
   ↓
必要时访问数据存储器
   ↓
必要时写回寄存器，并确定后续 PC
```

不同实现的差异主要在于这些工作**如何映射到时钟周期和硬件资源**：

| 实现 | 典型特点 | 不能据此推出的结论 |
| --- | --- | --- |
| 单周期 | 一条指令一个时钟周期完成 | “时钟一定快” |
| 多周期 | 一条指令拆成若干较短周期 | “多条指令一定重叠” |
| 流水线 | 多条指令的不同阶段重叠 | “单条指令延迟一定更小” |

<Callout type="info" title="先分清 ISA 语义与 CPU 实现">
机器指令“做什么”属于 ISA 约定；一条指令要经过几级流水、控制器采用硬布线还是微程序、内部有几条总线，属于微体系结构实现。换用同一 ISA 的另一颗处理器后，机器程序通常仍应保持语义不变。
</Callout>

## 2. 组合逻辑与时序逻辑

数据通路中的元件可以先分成两类，这一分类决定了“数据能否被保存”。

### 2.1 组合逻辑元件

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-004.svg" alt="译码器、多路选择器和三态门" />

组合逻辑的输出只取决于**当前输入**，本身不保存历史状态。

常见部件：

- ALU；
- 译码器；
- 多路选择器；
- 三态门。

#### 译码器

若输入有 $n$ 位，最多可区分：

$$
2^n
$$

种输入组合。

#### 多路选择器 MUX

MUX 根据选择信号，从多个输入中选一路送到输出。例如：

```text
Select = 0  →  选择 A
Select = 1  →  选择 B
```

#### 三态门

三态门除了逻辑 `0`、`1`，还可以输出**高阻态 Z**。

- 使能时：允许该部件驱动共享总线；
- 禁止时：输出高阻，相当于暂时与总线断开。

这使得多个部件能够共享同一条总线，但同一时刻通常只能允许一个部件驱动总线。

### 2.2 时序逻辑元件

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-005.svg" alt="CPU 内部时序逻辑元件" />

时序逻辑能够保存状态，输出与当前输入、此前状态和时钟有关。

常见部件：

- 通用寄存器；
- PC、IR、MAR、MDR；
- 状态寄存器；
- 暂存寄存器；
- 流水段寄存器；
- 存储器。

<Callout type="warning" title="ALU 不保存运算结果">
ALU 通常是组合逻辑。它可以产生结果，但结果若要在后续时钟周期继续使用，必须写入寄存器或其他时序逻辑元件。
</Callout>

## 3. CPU 寄存器及程序员可见性

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-008.svg" alt="8086 寄存器分类" />

> **真题考查**
>
> - 选择题：2010 年第 18 题、2012 年第 24 题、2014 年第 17 题、2015 年第 23 题、2016 年第 18 题、2017 年第 18 题、2019 年第 17 题、2020 年第 12 题、2021 年第 17 题、2024 年第 25 题
> - 解答题：2015 年第 43 题、2022 年第 43 题

寄存器可按用途分成两类：

1. **程序员可见寄存器**：ISA 明确暴露给软件，可被机器指令直接或间接使用；
2. **程序员不可见寄存器**：主要服务于 CPU 内部实现。

常见抽象如下：

| 类别 | 典型寄存器 | 作用 |
| --- | --- | --- |
| 通用寄存器 | `R0...Rn`、x86 的 `AX/BX/...` | 保存操作数、地址或中间结果 |
| 程序计数类 | `PC`、8086 的 `CS:IP` | 确定下一条指令位置 |
| 状态寄存器 | `PSW`、`FLAGS` | 保存条件码、控制位等 |
| 内部专用寄存器 | `IR`、`MAR`、`MDR`、`T` | 取指、访存和数据通路内部暂存 |

通常：

- 通用寄存器、PC 和部分状态寄存器属于 ISA 可见状态；
- `IR`、`MAR`、`MDR`、内部暂存寄存器往往属于微体系结构内部状态。

“程序员可见”还意味着这些状态通常会影响机器程序语义，因此操作系统进行进程/线程切换时，需要保存和恢复必要的**体系结构状态**。而某些纯内部流水寄存器、暂存寄存器并不需要作为普通进程上下文长期保存。

<Callout type="warning" title="程序员可见性要看 ISA">
不要仅凭寄存器名称判断“可见/不可见”。是否对程序员可见由 ISA 决定；教材中的 `MAR/MDR/IR` 通常用于抽象数据通路，不代表每种处理器都以同名寄存器暴露给软件。
</Callout>

## 4. PC、IR、MAR、MDR 与暂存寄存器

这组寄存器是数据通路大题最常出现的对象。

### 4.1 PC：程序计数器

PC 用于形成取指地址，并表示程序当前的控制流位置。教材常把它描述为保存“下一条待取指令地址”，但具体时刻 PC 指向当前指令还是顺序下一指令，与处理器的取指更新时序有关。综合题必须服从题设。

顺序执行时常抽象为：

$$
PC \leftarrow PC + \text{指令长度}
$$

若发生：

- 条件/无条件跳转；
- 函数调用或返回；
- 异常或中断；

则由相应控制转移机制修改 PC。

### 4.2 IR：指令寄存器

IR 保存当前正在译码或执行的机器指令。控制器通常从 IR 中取出：

- 操作码；
- 寻址方式字段；
- 寄存器编号；
- 立即数或其他控制字段。

### 4.3 MAR：存储器地址寄存器

MAR 保存本次主存访问使用的地址。

例如取指的第一步通常可写作：

```text
MAR ← PC
```

### 4.4 MDR：存储器数据寄存器

MDR 保存 CPU 与主存之间正在交换的数据。

读主存：

```text
MDR ← M[MAR]
```

写主存：

```text
M[MAR] ← MDR
```

### 4.5 暂存寄存器 T

在单总线数据通路中，一条总线同一时刻往往只能承载一路源数据，因此 ALU 的一个输入常需先暂存到 `T`：

```text
T ← R1
R3 ← T + R2
```

本质是用寄存器跨时钟周期保存中间操作数。

### 4.6 访存指令的数据流：先算地址，再搬数据

Load/Store 类综合题最容易把“地址”和“数据”混在一起。可固定拆成两条链：

```text
地址链：基址/变址/位移 → ALU 计算有效地址 → MAR / 地址端
数据链：存储器数据端 ↔ MDR / 数据通路 ↔ 通用寄存器
```

例如抽象的 `LOAD R1, d(R2)`：

```text
EA  ← R2 + sign_extend(d)
MAR ← EA
MDR ← M[MAR]
R1  ← MDR
```

而 `STORE R1, d(R2)` 的关键区别是最后的数据方向相反：

```text
EA     ← R2 + sign_extend(d)
MAR    ← EA
MDR    ← R1
M[MAR] ← MDR
```

<Callout type="warning" title="MAR 放地址，MDR 放数据">
做数据通路题时，只要先问“这个量是地址还是被读写的数据”，通常就不会把 `MAR` 与 `MDR` 的职责写反。
</Callout>

## 5. 状态/标志寄存器

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-012.svg" alt="8086 FLAGS 标志寄存器" />
<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-013.svg" alt="CPU 条件标志工作原理" />

> **真题考查**
>
> - 选择题：2011 年第 17 题、2018 年第 19 题、2023 年第 16 题
> - 解答题：2013 年第 44 题、2017 年第 44 题、2019 年第 45 题

状态寄存器保存运算结果产生的条件码以及部分控制状态。以 x86/8086 的 `FLAGS` 为辅助例子，可见：

| 标志 | 含义 | 典型用途 |
| --- | --- | --- |
| `CF` | Carry Flag | 无符号进位/借位 |
| `ZF` | Zero Flag | 结果是否为 0 |
| `SF` | Sign Flag | 结果最高位 |
| `OF` | Overflow Flag | 有符号运算是否溢出 |
| `PF` | Parity Flag | 结果低 8 位中 `1` 的个数是否为偶数 |
| `AF` | Auxiliary Carry | 低半字节的进位/借位 |
| `IF` | Interrupt Flag | 是否允许响应可屏蔽中断 |
| `TF` | Trap Flag | 单步调试控制 |
| `DF` | Direction Flag | 字符串操作的地址变化方向 |

### 5.1 CF 与 OF 必须分开判断

CPU 的加法器只做位运算，并不知道当前位串要解释为有符号数还是无符号数。

- `CF` 主要反映**无符号**运算的最高位进位/借位；
- `OF` 反映**有符号补码**运算是否超出表示范围。

例如 8 位：

```text
  01111111
+ 00000001
----------
  10000000
```

若按无符号解释：$127+1=128$，合法，`CF=0`。

若按有符号补码解释：$127+1$ 超过 8 位补码最大值，因此 `OF=1`。

### 5.2 OF 的常用判断

对于 $n$ 位补码加法：

$$
C=A+B
$$

溢出条件可记为：

> **两个操作数同号，结果却与它们异号。**

逻辑表达式：

$$
\mathrm{OF}
=
A_{n-1}B_{n-1}\overline{C_{n-1}}
+
\overline{A_{n-1}}\overline{B_{n-1}}C_{n-1}
$$

也可由符号位的两个进位判断：

$$
\mathrm{OF}
=
C_{\text{in,sign}}\oplus C_{\text{out,sign}}
$$

### 5.3 IF、TF、DF

- `IF=1`：允许响应可屏蔽外部中断；`IF=0`：禁止响应可屏蔽外部中断；
- `TF`：用于单步调试；
- `DF=0`：字符串地址通常递增；`DF=1`：字符串地址通常递减。

<Callout type="warning" title="IF 不能屏蔽 NMI">
`IF` 只控制可屏蔽中断。不可屏蔽中断 NMI 不受普通中断允许位控制。
</Callout>

## 6. 8086 寄存器与分段：只作辅助理解

8086 的寄存器体系可以帮助理解 PC、栈、变址与状态寄存器，但其细节不是所有 ISA 的通则。

### 6.1 常见寄存器

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-009.svg" alt="8086 分段内存与段寄存器" />

| 寄存器 | 常见用途 |
| --- | --- |
| `AX` | 累加、算术逻辑运算 |
| `BX` | 基址相关寻址 |
| `CX` | 计数、循环、移位次数 |
| `DX` | 数据、I/O 或扩展整数运算 |
| `SP` | 栈顶指针 |
| `BP` | 栈帧基准 |
| `SI` | 源变址 |
| `DI` | 目的变址 |
| `CS/DS/SS/ES` | 代码段、数据段、栈段、附加段 |
| `IP` | 当前代码段中下一条指令的偏移 |

### 6.2 `CS:IP` 与抽象 PC

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-011.svg" alt="8086 CS IP 取指过程" />

8086 物理地址由段基址和偏移形成：

$$
\text{Physical Address}=CS\times16+IP
$$

从“决定下一条取指地址”的抽象功能看，`CS:IP` 共同实现了 PC 类功能。

### 6.3 `SP`、`BP` 与函数栈

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-010.svg" alt="BP 与 SP 在函数栈中的关系" />

在典型向低地址增长的栈中：

- `SP` 指向当前栈顶；
- `BP` 常作为当前栈帧的基准。

编译器可用“基址 + 偏移”访问参数、局部变量、保存的寄存器与返回地址。

### 6.4 `SI`、`DI` 与字符串操作

例如按字节复制：

```asm
; DS:SI 指向源
; ES:DI 指向目的
MOV SI, OFFSET source
MOV DI, OFFSET dest
MOV CX, length
CLD
REP MOVSB
```

其中 `CLD` 使方向标志清零，地址按低地址向高地址推进。

## 7. CPU 外部接口与复用总线

<InlineSvg src="/images/computer-organization/computer-organization-cpu-structure-014.svg" alt="8086 CPU 外部引脚" />

以 8086 为辅助例子：

- 数据总线宽度为 16 位；
- 地址空间为 1 MB，因此需要 20 位地址；
- `AD0–AD15` 可在不同时刻复用为低位地址线和数据线；
- `A16/S3–A19/S6` 可复用为高位地址线和状态信号。

地址/数据复用的含义是：

> **同一组物理引脚在一个总线周期的不同时段承担不同功能。**

因此常需利用 `ALE` 将地址锁存下来。

典型控制信号：

| 信号 | 作用 |
| --- | --- |
| `RD#` | 存储器或 I/O 读 |
| `WR#` | 存储器或 I/O 写 |
| `ALE` | 地址锁存使能 |
| `READY` | 慢速设备是否就绪，可用于插入等待状态 |
| `HOLD` | 外部部件申请总线控制权 |
| `HLDA` | CPU 响应总线请求 |
| `INTR` | 可屏蔽中断请求 |
| `NMI` | 不可屏蔽中断请求 |
| `INTA#` | 中断响应 |
| `RESET` | 处理器复位；8086 中为高电平有效 |

其中 `HOLD/HLDA` 常与 DMA 临时取得系统总线控制权的过程联系起来。

<Callout type="info" title="本部分最重要的抽象">
408 做题时更应关注“地址、数据、控制信号如何在 CPU 与存储器/I/O 之间传递”，不要把 8086 某个具体引脚编号误当成所有处理器都必须具备的结构。
</Callout>
