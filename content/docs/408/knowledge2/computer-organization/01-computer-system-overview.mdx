## 1. 计算机系统的层次结构

完整的计算机系统由**硬件系统**和**软件系统**共同组成。

| 层次 | 主要内容 | 作用 |
| --- | --- | --- |
| 应用软件 | 浏览器、办公软件、业务程序等 | 直接解决用户问题 |
| 系统软件 | 操作系统、编译程序、汇编程序、链接程序等 | 管理硬件并为应用提供运行环境 |
| 指令集体系结构 ISA | 指令、寄存器、数据类型、寻址方式等 | 规定软件可见的机器接口 |
| 硬件 | CPU、主存、I/O 设备等 | 真正完成计算、存储与数据传送 |

从程序员视角看，软硬件之间最重要的接口之一是 **ISA（Instruction Set Architecture，指令集体系结构）**。

### 1.1 计算机体系结构与计算机组成

二者经常一起出现，但关注点不同：

| 概念 | 核心问题 | 典型内容 |
| --- | --- | --- |
| 计算机体系结构 | **机器对程序员呈现什么功能** | 指令系统、寄存器、数据类型、寻址方式 |
| 计算机组成 | **这些功能具体怎样实现** | 数据通路、控制器、Cache、总线、存储器 |

可以记成：

> **体系结构规定“做什么”，计算机组成研究“怎么做”。**

同一种 ISA 可以由不同微体系结构实现，因此两颗处理器可能能够运行同一套机器代码，但内部结构、主频、CPI 和性能完全不同。

### 1.2 ISA、微体系结构与“软件可见”边界

做概念辨析题时，可以用一个非常实用的判断方法：

> **如果把处理器换成另一种“同 ISA、不同实现”的型号，原机器代码仍然能够正确运行，那么这个特性通常不属于 ISA。**

典型区分如下：

| 对象 | 是否通常由 ISA 规定 | 说明 |
| --- | :---: | --- |
| 机器指令及其编码 | 是 | 软件必须知道如何表示与执行指令 |
| 程序员可见寄存器 | 是 | 汇编程序直接引用 |
| 数据类型、寻址方式 | 是 | 决定指令语义 |
| Cache 容量、组相联度 | 否 | 通常属于微体系结构实现 |
| 流水线级数、乱序执行 | 否 | 通常对程序语义透明 |
| 控制器采用硬布线还是微程序 | 否 | 属于实现方式 |

<Callout type="info" title="体系结构题的快速判断">
题目问“是否属于 ISA”时，优先判断该信息是否必须暴露给机器语言程序员。**软件必须遵守的规则**偏向体系结构；**硬件如何把规则做出来**偏向计算机组成。
</Callout>

## 2. 冯·诺依曼计算机与存储程序思想

<InlineSvg src="/images/computer-organization/computer-organization-overview-structure-001.svg" alt={"存储器 运算器 控制器 输入设备 输出设备 数据流 控制流 指令流"} />

冯·诺依曼体系最核心的思想是**存储程序（Stored Program）**：

> **把程序指令和程序处理的数据都存放在存储器中，由计算机自动取出指令并执行。**

传统教材中的冯·诺依曼机通常具有以下特点：

1. 硬件由**运算器、控制器、存储器、输入设备、输出设备**五大部件组成；
2. 指令和数据以同等地位存放在存储器中；
3. 指令和数据在存储器中本质上都是二进制代码；
4. 指令通常由**操作码**和**地址码**等字段组成；
5. 程序通常按地址顺序执行，遇到转移、调用、中断等情况时改变执行顺序；
6. 经典模型常表述为**以运算器为中心**。

<Callout type="warning" title="指令和数据在存储器中没有“物理标签”">
同一串二进制位究竟被解释成“指令”还是“数据”，取决于 CPU 当前如何取用和解释它，而不是位串本身带有“这是指令”的标志。
</Callout>

### 2.1 五大部件

| 部件 | 主要任务 |
| --- | --- |
| 运算器 | 完成算术运算、逻辑运算、移位、比较等 |
| 控制器 | 取指、译码并产生控制信号，协调各部件工作 |
| 存储器 | 保存指令、操作数、中间结果和最终结果 |
| 输入设备 | 把外部信息送入计算机 |
| 输出设备 | 把计算结果送到计算机外部 |

现代处理器中，**运算器 + 控制器 + 寄存器组**共同构成 CPU 的核心结构。

### 2.2 经典模型与现代计算机

经典冯·诺依曼机强调“以运算器为中心”；现代计算机中，大量数据交换围绕主存和多级存储体系展开，各部件通常通过总线或片上互连通信，因此更常描述为**以存储器为中心**。

这两个表述对应的是不同语境：

- 题目问“经典冯·诺依曼机的基本特点”时，按经典教材表述作答；
- 题目讨论现代计算机实际组织方式时，不能认为所有数据都必须经过 ALU。

### 2.3 为什么现代计算机普遍采用二进制

二进制并不只是“书写方便”，其优势同时来自数学规则和物理实现：

1. 只有 $0$、$1$ 两种状态，运算规则简单；
2. 物理器件更容易可靠地区分两个稳定状态；
3. 二进制与布尔逻辑天然对应，便于用逻辑门实现算术和逻辑运算；
4. 在存在噪声和器件偏差时，两电平系统通常更容易留出判决裕量。

> **真题标签**
>
> **2018 年第 12 题：采用二进制的主要原因**
>
> 高频结论是“运算规则简单 + 两稳态器件易实现 + 与逻辑门电路匹配”，三者都成立。

## 3. CPU、存储器与 I/O 的基本协作

程序运行时可以把硬件行为概括为：

```text
主存保存机器指令和数据
        ↓
CPU 取出指令
        ↓
控制器译码并发出控制信号
        ↓
运算器 / 寄存器 / 存储器 / I/O 协同完成操作
        ↓
继续取下一条指令
```

CPU 执行一条机器指令时，常抽象为：

```text
取指 → 译码 → 执行
```

实际处理器还可能包含取操作数、访存、写回等阶段，并可使用流水线使多条指令的不同阶段重叠执行。

### 3.1 存储程序的基本执行链

在 408 的简化模型中，可以用下面这条链理解“程序为什么能够自动连续运行”：

```text
PC 给出下一条指令地址
        ↓
地址送入 MAR，访问主存
        ↓
取出的指令送入 IR
        ↓
控制器译码并产生控制信号
        ↓
必要时读取寄存器 / 主存操作数
        ↓
ALU 等部件执行并写回结果
        ↓
PC 指向下一条应执行的指令
```

其中：

- **PC（程序计数器）**：保存下一条待执行指令的地址或按具体机器语义更新；
- **MAR（存储器地址寄存器）**：保存本次访存所使用的地址；
- **IR（指令寄存器）**：保存当前正在译码/执行的指令；
- **MDR（存储器数据寄存器）**：在经典数据通路模型中暂存主存读写数据。

<Callout type="warning" title="PC、MAR、IR 不要混用">
**PC 负责“下一条指令在哪里”**，**MAR 负责“这一次访问存储器的地址是什么”**，**IR 负责“当前正在执行哪条指令”**。取指时 PC 的内容通常会送入 MAR，但二者职责并不相同。
</Callout>

### 3.2 I/O 设备为什么需要接口

键盘、磁盘、网卡等设备的速度、数据格式和控制方式与 CPU 内部数据通路不同，因此通常需要：

- I/O 接口或设备控制器；
- 总线或片上互连；
- 中断；
- DMA；

来完成 CPU、主存和外设之间的协调。

这些机制将在“总线与 I/O”章节继续展开。

## 4. 系统软件与应用软件

计算机软件通常分为**系统软件**和**应用软件**。

### 4.1 系统软件

系统软件直接服务于计算机系统运行，并为应用程序提供公共运行环境。

常见系统软件包括：

- 操作系统；
- 编译程序；
- 汇编程序；
- 链接程序；
- 数据库管理系统等。

### 4.2 应用软件

应用软件面向具体用户需求，例如：

- 浏览器；
- 办公软件；
- 图像处理软件；
- 游戏；
- 各类业务系统。

二者关系可以概括为：

```text
用户
 ↓
应用软件
 ↓
系统软件
 ↓
硬件
```

## 5. 机器语言、汇编语言与高级语言

<InlineSvg src="/images/computer-organization/computer-organization-overview-structure-002.svg" alt={"ProgrammingLanguageLevels"} />

程序设计语言可以按抽象层次理解为三类。

| 层次 | 示例 | 是否能被 CPU 直接执行 | 与硬件关系 |
| --- | --- | :---: | --- |
| 机器语言 | 二进制机器指令 | 是 | 与 ISA 直接相关 |
| 汇编语言 | `add eax, ebx` | 否 | 与 ISA 密切相关 |
| 高级语言 | `c = a + b;` | 否 | 抽象程度更高 |

### 5.1 机器语言

机器语言由机器指令构成，是 CPU 能直接执行的形式。

```text
10110000 01100001
```

不同 ISA 的机器指令编码通常不同，因此机器代码一般不能跨 ISA 直接运行。

### 5.2 汇编语言

汇编语言用助记符表示机器操作，例如：

```asm
add eax, ebx
```

汇编程序需要由**汇编器（Assembler）**&#x2060;转换为目标机器代码。

### 5.3 高级语言

C、C++、Java、Python 等高级语言更接近人的表达方式，例如：

```c
c = a + b;
```

高级语言不能被 CPU 直接执行。即使某种语言以“解释执行”为主，真正运行在 CPU 上的解释器、虚拟机或运行时本身也必须最终由机器指令实现。

## 6. 从源程序到可执行程序

<InlineSvg src="/images/computer-organization/computer-organization-overview-structure-003.svg" alt={"hello.c 源代码 hello.i 预处理代码 hello.s 汇编代码 hello.o 目标文件 hello (a.out) 可执行文件 预处理器 编译器 汇编器 链接器 + 库 gcc -E gcc -S gcc -c gcc / ld 加载器 → CPU 执行"} />

以典型 C 程序为例，源程序形成可执行文件通常经历：

```text
源程序
  ↓ 预处理
预处理后的源程序
  ↓ 编译
汇编程序
  ↓ 汇编
目标文件
  ↓ 链接
可执行文件
  ↓ 装载
进程地址空间中的程序
  ↓
CPU 执行机器指令
```

### 6.1 预处理

C/C++ 中的预处理器主要处理：

- 宏展开；
- 头文件包含；
- 条件编译。

例如：

```bash
gcc -E hello.c -o hello.i
```

得到预处理后的 `hello.i`。

### 6.2 编译

编译器对高级语言进行词法、语法、语义分析，并经过中间表示、优化和代码生成等过程，最终生成汇编代码或更低层目标表示。

例如：

```bash
gcc -S hello.c -o hello.s
```

### 6.3 汇编

汇编器把汇编代码翻译成**目标文件**：

```bash
gcc -c hello.s -o hello.o
```

目标文件通常不仅包含机器代码，还包含：

- 符号表；
- 重定位信息；
- 数据段信息等。

### 6.4 链接

链接器把一个或多个目标文件以及所需库文件组合成可执行文件，主要完成：

- **符号解析**；
- **重定位**。

```text
目标文件 + 库文件
       ↓
      链接
       ↓
    可执行文件
```

### 6.5 装载与执行

运行可执行文件时，操作系统的加载机制为程序建立运行所需的地址空间，并把控制权交给程序入口。

之后 CPU 不断进行取指、译码和执行。

<Callout type="warning" title="编译、汇编、链接、装载不是同一个阶段">

- **编译**：高级语言 → 汇编代码或低层目标表示；
- **汇编**：汇编代码 → 目标文件；
- **链接**：目标文件 + 库 → 可执行文件；
- **装载**：把可执行程序建立为可运行的进程映像。

题目若问某个符号何时解析、地址何时确定，必须先判断处于哪一个阶段。

</Callout>

### 6.6 GCC 是编译驱动程序

`gcc` 可以自动调用完整工具链。

例如：

```bash
gcc -c hello.c -o hello.o
```

虽然命令只有一个 `gcc`，实际仍会经过预处理、编译和汇编，只是这些步骤由驱动程序自动组织。

## 7. 衡量计算机性能：先分清“时间”和“速率”

计算机性能不能只看某一个硬件参数。408 中常见指标可以分成两类：

- **时间类**：执行时间、响应时间，越小越好；
- **速率类**：吞吐量、IPS、MIPS、FLOPS，通常越大越好。

还要先分清题目中的“时间”到底指什么：

| 时间口径 | 含义 | 是否可能包含 I/O 等待 |
| --- | --- | :---: |
| 响应时间 / 墙钟时间 | 用户从任务开始到结束实际等待的时间 | 是 |
| CPU 执行时间 | CPU 真正为该程序执行指令所花的处理时间 | 通常不计等待外设的墙钟时间 |
| 用户 CPU 时间 | 在用户态执行程序代码所耗 CPU 时间 | 否 |
| 系统 CPU 时间 | 内核为该程序提供服务所耗 CPU 时间 | 否 |

408 使用 $T_{\mathrm{CPU}}=N_{\mathrm{inst}}\times\mathrm{CPI}/f$ 时，默认分析的是 **CPU 执行时间**，不要把磁盘等待、键盘输入等墙钟等待时间直接代入该公式。

## 8. 时钟周期与主频

<InlineSvg src="/images/computer-organization/computer-organization-overview-performance-001.svg" alt={"C 0 C 1 L 1 R 1"} />
<InlineSvg src="/images/computer-organization/computer-organization-overview-performance-002.svg" alt={"原始连续模拟信号 离散数字信号 整型和分频"} />

同步数字电路依靠周期性时钟信号协调状态变化。

**时钟周期（Clock Cycle）**&#x2060;记为 $T_{\mathrm{clk}}$，是相邻同类型有效时钟边沿之间的时间。

**主频（Clock Frequency）**&#x2060;记为 $f$，表示每秒包含多少个时钟周期。

二者互为倒数：

$$
f=\frac{1}{T_{\mathrm{clk}}}
$$

$$
T_{\mathrm{clk}}=\frac{1}{f}
$$

例如，主频为 $3\,\mathrm{GHz}$：

$$
f=3\times10^9\,\mathrm{Hz}
$$

则：

$$
T_{\mathrm{clk}}
=
\frac{1}{3\times10^9}
\approx 0.333\,\mathrm{ns}
$$

<Callout type="warning" title="3 GHz 不等于每秒执行 30 亿条指令">
3 GHz 只表示每秒有约 $3\times10^9$ 个时钟周期。平均每条指令可能需要多个周期；超标量处理器也可能平均一个周期完成多条指令。
</Callout>

现代计算机中不同部件还可能处在不同**时钟域**，因此“CPU 核心主频”并不意味着所有器件都工作在同一频率。

## 9. 时钟周期、机器周期与指令周期

<InlineSvg src="/images/computer-organization/computer-organization-overview-performance-003.svg" alt={"时钟 周期 机器周期 （取指令） 机器周期 （译码） 机器周期 （执行） 机器周期 （执行） 指令周期"} />

这三个概念要分层理解。

| 概念 | 含义 | 典型关系 |
| --- | --- | --- |
| 时钟周期 | 同步数字电路的基本节拍 | 最基本时间单位 |
| 机器周期 | 完成一个相对完整基本操作所需时间 | 传统模型中常含若干时钟周期 |
| 指令周期 | 一条指令从取指到完成的全过程 | 可包含若干机器周期 |

传统非流水模型常画成：

```text
指令周期
 ├─ 取指机器周期
 ├─ 间址机器周期（可能有）
 ├─ 执行机器周期
 └─ 中断周期（可能有）
```

因此可粗略记为：

```text
指令周期
   ↓
若干机器周期
   ↓
若干时钟周期
```

但这只是传统模型的层次关系，**不能据此认为现代处理器的多条指令必须一条一条串行完成**。

流水线处理器可让不同指令重叠执行：

```text
周期    1    2    3    4    5
I1     IF   ID   EX   MEM  WB
I2          IF   ID   EX   MEM
I3               IF   ID   EX
```

<Callout type="warning" title="CPI 不等于指令周期">
“指令周期”是执行一条指令的过程概念；“CPI”是程序运行统计得到的平均周期数。二者不是同一个量。

在理想化教材模型中常见：单周期 CPU 的 CPI 为 $1$；基本流水线稳定吞吐时可近似看作 CPI 为 $1$；多周期 CPU 常有 CPI $>1$；超标量处理器平均 CPI 甚至可以小于 $1$。实际程序还会受到流水线停顿、Cache 缺失和分支预测失败等影响。
</Callout>

---

## 10. CPI 与 IPC

### 10.1 CPI

**CPI（Cycles Per Instruction）**&#x2060;表示平均每条指令消耗多少个时钟周期。

若：

- 程序执行指令数为 $N_{\mathrm{inst}}$；
- 总时钟周期数为 $N_{\mathrm{cycle}}$；

则：

$$
\mathrm{CPI}
=
\frac{N_{\mathrm{cycle}}}{N_{\mathrm{inst}}}
$$

若程序包含多类指令，第 $i$ 类有 $N_i$ 条，每条平均需要 $\mathrm{CPI}_i$ 个周期，则：

$$
\mathrm{CPI}_{\mathrm{avg}}
=
\frac{\sum_i N_i\mathrm{CPI}_i}{\sum_i N_i}
$$

若已知各类指令比例 $p_i$：

$$
\mathrm{CPI}_{\mathrm{avg}}
=
\sum_i p_i\mathrm{CPI}_i
$$

### 10.2 IPC

**IPC（Instructions Per Cycle）**&#x2060;表示平均每个时钟周期完成多少条指令。

在同一统计区间内：

$$
\mathrm{IPC}
=
\frac{N_{\mathrm{inst}}}{N_{\mathrm{cycle}}}
=
\frac{1}{\mathrm{CPI}}
$$

因此现代超标量处理器可能出现：

$$
\mathrm{IPC}>1
$$

对应：

$$
\mathrm{CPI}<1
$$

这并不矛盾，它表示平均每个周期可以完成多于一条指令。

<Callout type="info" title="CPI 是“程序 + 机器 + 运行条件”的统计量">
同一台机器执行不同程序时，指令类型比例、Cache 命中率、分支行为不同，平均 CPI 可以不同；同一个程序换到不同微体系结构上，CPI 也可能不同。因此不要把 CPI 当成只由 ISA 决定的常数。
</Callout>

---

## 11. CPU 执行时间：本章最核心公式

程序总时钟周期数为：

$$
N_{\mathrm{cycle}}
=
N_{\mathrm{inst}}\times\mathrm{CPI}
$$

CPU 执行时间为：

$$
T_{\mathrm{CPU}}
=
N_{\mathrm{inst}}
\times
\mathrm{CPI}
\times
T_{\mathrm{clk}}
$$

又因为：

$$
T_{\mathrm{clk}}=\frac{1}{f}
$$

所以：

$$
\boxed{
T_{\mathrm{CPU}}
=
\frac{N_{\mathrm{inst}}\times\mathrm{CPI}}{f}
}
$$

这是组成原理中最重要的性能关系之一。

### 11.1 三个决定因素

从公式可以直接看出：

| 因素 | 主要受什么影响 |
| --- | --- |
| 指令数 $N_{\mathrm{inst}}$ | 算法、编译器、ISA |
| 平均 CPI | ISA、微体系结构、Cache、流水线等 |
| 主频 $f$ | 电路与微体系结构实现 |

因此：

> **只比较主频不能判断程序一定谁更快。**

### 11.2 典型计算

某程序执行 $10^9$ 条指令，平均 CPI 为 $2$，CPU 主频为 $2\,\mathrm{GHz}$：

$$
T_{\mathrm{CPU}}
=
\frac{10^9\times2}{2\times10^9}
=
1\,\mathrm{s}
$$

### 11.3 多类指令可直接计算总周期数

若题目给出每类指令数量和各自 CPI，也可以先计算：

$$
N_{\mathrm{cycle}}
=
\sum_i N_i\mathrm{CPI}_i
$$

再求：

$$
T_{\mathrm{CPU}}
=
\frac{\sum_i N_i\mathrm{CPI}_i}{f}
$$

这通常比先求平均 CPI 更直接。

### 11.4 性能变化题：只比较“变化后的整条公式”

优化处理器时，一个参数变好往往会带来另一个参数变化。例如主频提高，但流水线更深导致 CPI 上升。此时必须分别计算：

$$
T_{\mathrm{old}}=\frac{N_{\mathrm{old}}\times\mathrm{CPI}_{\mathrm{old}}}{f_{\mathrm{old}}}
$$

$$
T_{\mathrm{new}}=\frac{N_{\mathrm{new}}\times\mathrm{CPI}_{\mathrm{new}}}{f_{\mathrm{new}}}
$$

再比较二者。若程序与 ISA 不变且指令条数相同，可约掉 $N$：

$$
\frac{T_{\mathrm{new}}}{T_{\mathrm{old}}}
=
\frac{\mathrm{CPI}_{\mathrm{new}}}{\mathrm{CPI}_{\mathrm{old}}}
\times
\frac{f_{\mathrm{old}}}{f_{\mathrm{new}}}
$$

<Callout type="warning" title="主频提高 20% 不等于程序快 20%">
只有其他因素保持不变时，执行时间才与主频严格成反比。题目一旦同时给出 CPI、指令数或 Cache 行为变化，就必须回到 CPU 时间公式整体比较。
</Callout>

---

## 12. 性能比较与加速比

对同一个任务，性能通常定义为执行时间的倒数：

$$
\mathrm{Performance}
=
\frac{1}{T}
$$

若机器 A 和 B 完成同一任务的时间分别为 $T_A$、$T_B$，则：

$$
\frac{\mathrm{Performance}_A}{\mathrm{Performance}_B}
=
\frac{T_B}{T_A}
$$

例如：

$$
T_A=5\,\mathrm{s},\qquad T_B=10\,\mathrm{s}
$$

则：

$$
\frac{\mathrm{Performance}_A}{\mathrm{Performance}_B}
=
\frac{10}{5}
=
2
$$

即 A 的性能是 B 的 2 倍。

<Callout type="warning" title="性能和执行时间成反比">
问“A 的性能是 B 的多少倍”时应计算 $T_B/T_A$，不能把时间比直接当成性能比。
</Callout>

若优化前时间为 $T_{\mathrm{old}}$，优化后为 $T_{\mathrm{new}}$，常用加速比：

$$
S
=
\frac{T_{\mathrm{old}}}{T_{\mathrm{new}}}
$$

## 13. IPS、MIPS 与 FLOPS

### 13.1 IPS

**IPS（Instructions Per Second）**&#x2060;表示平均每秒执行多少条机器指令：

$$
\mathrm{IPS}
=
\frac{N_{\mathrm{inst}}}{T_{\mathrm{CPU}}}
$$

结合 CPU 时间公式：

$$
\mathrm{IPS}
=
\frac{f}{\mathrm{CPI}}
$$

### 13.2 MIPS

**MIPS（Million Instructions Per Second）**&#x2060;表示每秒执行多少百万条指令：

$$
\mathrm{MIPS}
=
\frac{\mathrm{IPS}}{10^6}
=
\frac{f}{\mathrm{CPI}\times10^6}
$$

若主频直接以 MHz 为单位，则数值上也可写成：

$$
\mathrm{MIPS}
=
\frac{f_{\mathrm{MHz}}}{\mathrm{CPI}}
$$

MIPS 的局限是：不同 ISA 的“一条指令”完成的工作量可能完全不同，所以它**不适合跨 ISA 直接比较实际程序性能**。

即使是同一台机器，不同程序的平均 CPI 不同，测得的 MIPS 也可能不同。因此真正判断同一任务谁更快，应优先比较执行时间。

### 13.3 FLOPS

<InlineSvg src="/images/computer-organization/computer-organization-overview-performance-004.svg" alt={"FLOPS_units"} />

**FLOPS（Floating-point Operations Per Second）**&#x2060;表示每秒完成多少次浮点运算。

常见单位：

| 单位 | 数量级 |
| --- | ---: |
| MFLOPS | $10^6$ FLOPS |
| GFLOPS | $10^9$ FLOPS |
| TFLOPS | $10^{12}$ FLOPS |
| PFLOPS | $10^{15}$ FLOPS |
| EFLOPS | $10^{18}$ FLOPS |
| ZFLOPS | $10^{21}$ FLOPS |

<Callout type="warning" title="FLOPS 不是浮点指令数">
一条机器指令可能完成多个浮点运算，因此“浮点运算次数”和“机器指令条数”不能直接画等号。
</Callout>

## 14. 响应时间与吞吐量

### 14.1 响应时间

**响应时间（Response Time）**&#x2060;关注：

> 完成一个任务需要多长时间。

响应时间越短，单个任务完成得越快。

### 14.2 吞吐量

**吞吐量（Throughput）**&#x2060;关注：

> 单位时间内系统能完成多少个任务。

例如，服务器每秒处理 10000 个请求描述的是吞吐量。

### 14.3 为什么二者不能混用

增加处理器数量后，系统可以同时处理更多相互独立的任务：

```text
任务 A → CPU 1
任务 B → CPU 2
任务 C → CPU 3
```

总吞吐量可能显著提高，但单个任务的响应时间未必同比例缩短。

因此：

- 单任务“多久完成” → 响应时间；
- 一段时间“完成多少任务” → 吞吐量。

## 15. 机器字长、存储字长与数据通路宽度

### 15.1 机器字长

**机器字长**通常指 CPU 一次能够处理的基本二进制数据宽度，与：

- 运算器；
- 通用寄存器；
- 数据通路；

密切相关。

常见有 32 位、64 位等。

在 408 题目中，“某计算机字长为 32 位”通常首先提示：ALU 和通用寄存器处理的基本数据宽度大概率为 32 位；但若题目另外明确给出寄存器宽度、数据总线宽度或存取单位，应以题设为准。

### 15.2 存储字长

**存储字长**是一个存储单元一次能够存放的二进制位数。

### 15.3 指令字长

**指令字长**是一条机器指令编码所占的位数，可以：

- 等于机器字长；
- 小于机器字长；
- 大于机器字长；
- 固定；
- 也可以可变。

### 15.4 数据通路宽度

**数据通路宽度（Data Path Width）**&#x2060;表示某条内部或外部数据通路一次可以并行传送多少位。

若一条数据总线宽度为 64 bit，只能说明**一次并行传送的数据位宽上限**；实际带宽还取决于总线频率、每周期传输次数、协议开销、等待周期和利用率等因素。

另一个常见陷阱是“主存按字节编址，但一次存取 32 bit”。这表示：

- 每个地址仍对应 $1\,\mathrm{B}$；
- 一次主存读写可传送 $4\,\mathrm{B}$；
- **编址单位**与**一次存取的数据宽度**不是同一个概念。

<Callout type="warning" title="四种“宽度”没有必须相等的关系">

不能根据“64 位 CPU”直接推出：

- 每条指令都是 64 位；
- 每个存储字都是 64 位；
- 所有数据总线都是 64 位。

题目给出哪个宽度，就只对相应对象作判断。

</Callout>

## 16. 主存容量、寻址单位与 MAR 位数

主存容量常用二进制数量级表示：

$$
1\,\mathrm{B}=8\,\mathrm{bit}
$$

$$
1\,\mathrm{KB}=2^{10}\,\mathrm{B},\qquad
1\,\mathrm{MB}=2^{20}\,\mathrm{B},\qquad
1\,\mathrm{GB}=2^{30}\,\mathrm{B}
$$

这一类题的关键不是先背公式，而是先回答：

> **一个地址究竟对应多大的存储单元？**

若 MAR 有 $n$ 位，在教材常用的简化模型中最多可表示：

$$
2^n
$$

个不同地址，因此最多可以访问 $2^n$ 个**可寻址单元**。

### 16.1 按字节寻址

若地址空间为：

$$
128\,\mathrm{KB}
=
2^{17}\,\mathrm{B}
$$

按字节寻址时，一个地址对应 $1\,\mathrm{B}$，因此可寻址单元数为：

$$
2^{17}
$$

需要：

$$
\mathrm{MAR}=17\text{ 位}
$$

### 16.2 按字寻址

仍设总容量为 $128\,\mathrm{KB}=2^{17}\,\mathrm{B}$，若一个字为：

$$
16\,\mathrm{bit}
=
2\,\mathrm{B}
$$

并按字寻址，则可寻址字数为：

$$
\frac{2^{17}\,\mathrm{B}}{2\,\mathrm{B}}
=
2^{16}
$$

因此：

$$
\mathrm{MAR}=16\text{ 位}
$$

### 16.3 通用解题公式

先求可寻址单元数：

$$
N_{\mathrm{addr}}
=
\frac{\text{总容量}}{\text{一个寻址单位的大小}}
$$

再求地址位数：

$$
n
=
\log_2 N_{\mathrm{addr}}
$$

若已知地址位数 $n$、每个寻址单元大小为 $W$ bit，则最大容量为：

$$
C
=
2^n\times W\ \mathrm{bit}
$$

<Callout type="warning" title="看到“容量”不要立刻取 $\log_2$">
只有当“一个地址对应 1 bit”时，容量的 bit 数才可直接等同于地址单元数。408 题中最常见的是按字节寻址和按字寻址，必须先换算“可寻址单元数”。
</Callout>

---

## 17. MAR、地址总线与实际主存容量

在 408 常用的简化模型中：

- MAR 保存待访问存储单元的地址；
- MAR 位数决定可表示多少个地址；
- 地址总线宽度通常与需要传送的地址位数相匹配。

考试题若直接问“地址总线宽度与哪个寄存器最相关”，通常应答 **MAR**。但在真实系统中还可能存在地址复用、片上/片外地址宽度不同、物理地址扩展等实现，因此这里应按题目给出的简化数据通路模型作答。

若地址位数为 $n$，理论可寻址单元数为：

$$
2^n
$$

但：

> **最大可寻址范围不一定等于实际安装的主存容量。**

例如，若 CPU 可形成 32 位地址并按字节寻址，理论地址空间为：

$$
2^{32}\,\mathrm{B}
=
4\,\mathrm{GB}
$$

计算机却完全可能只安装 $1\,\mathrm{GB}$ 物理内存。

因此必须区分：

- **地址空间**：地址编码能够覆盖的范围；
- **实际主存容量**：机器实际配置的存储容量。

### 17.1 综合题的四步法

看到“字长、按字节/按字编址、地址线、MAR、MDR、主存容量”混在一起时，按下面顺序做最稳：

1. **先定编址单位**：一个地址对应 $1\,\mathrm{B}$、一个字还是其他大小；
2. **再定地址个数**：$n$ 位地址最多表示 $2^n$ 个地址；
3. **再算地址空间容量**：地址个数 $\times$ 每个编址单位大小；
4. **最后分别判断数据宽度**：MDR、数据总线、存取单位、机器字长分别依据题设，不能相互硬推。

例如：20 位地址线、按字节编址，则最大地址空间为：

$$
2^{20}\,\mathrm{B}=1\,\mathrm{MiB}
$$

若数据总线为 8 位，只能说明一次总线数据传送宽度为 $8$ bit，**不会把地址空间改成 $2^{20}\times 8$ 字节**。

## 19. 高频易错点

### 19.1 高主频不代表程序一定更快

由：

$$
T_{\mathrm{CPU}}
=
\frac{N_{\mathrm{inst}}\times\mathrm{CPI}}{f}
$$

可知执行时间同时受**指令数、CPI、主频**影响。

### 19.2 CPI 不是“某条指令的固定周期数”

CPI 通常是对某个程序、某段执行过程统计得到的平均值。程序、输入、Cache 命中情况、流水线停顿等变化，都可能使平均 CPI 发生变化。

> **真题标签**
>
> **2026 年第 20 题：不同处理器组织方式下 CPI 的默认语境**
>
> 做此类题要先看题目是否给出“理想条件”。理想化单周期/基本流水线模型与真实程序测得的平均 CPI 不能混为一谈。

### 19.3 一条指令不一定只占一个时钟周期

可能有：

$$
\mathrm{CPI}>1
$$

超标量处理器也可能有：

$$
\mathrm{CPI}<1
$$

### 19.4 MIPS 高不代表同一任务一定更快

不同 ISA 所需指令数不同。比较同一任务应优先比较：

$$
T_{\mathrm{CPU}}
$$

### 19.5 指令和数据在存储器中本质上都是二进制位串

二者区别来自 CPU 当前如何解释和使用这些位，而不是存储介质中存在两种不同“物理形式”。

### 19.6 MAR 位数由“可寻址单元数”决定

必须先判断：

- 按字节寻址；
- 按字寻址；
- 还是其他寻址单位。

### 19.7 机器字长、存储字长、指令字长和总线宽度不要混用

它们可能相等，但没有必然相等关系。

### 19.8 CPU 时间与响应时间不要混用

CPU 时间公式分析的是处理器执行工作所需时间；用户实际感受到的响应时间还可能包含 I/O、排队、调度与其他等待。题目若给的是“程序从开始到结束共用时”，先确认它是不是 CPU 执行时间。

### 19.9 编址单位与存取单位不要混用

“按字节编址”决定地址每加 $1$ 跨过多少存储空间；“一次存取 32 bit”决定一次数据传送的宽度。两者可以同时成立。

## 20. 一张主线图串联全章

程序从源代码到硬件执行：

```text
高级语言源程序
      ↓
预处理 / 编译 / 汇编 / 链接
      ↓
可执行文件
      ↓
操作系统装载
      ↓
机器指令进入执行过程
      ↓
CPU 取指、译码、执行
      ↓
运算器、存储器和 I/O 协同工作
```

性能分析则沿另一条主线：

```text
指令条数
   ×
平均 CPI
   ×
时钟周期
   ↓
CPU 执行时间
```

即：

$$
\boxed{
T_{\mathrm{CPU}}
=
N_{\mathrm{inst}}
\times
\mathrm{CPI}
\times
T_{\mathrm{clk}}
}
$$

或：

$$
\boxed{
T_{\mathrm{CPU}}
=
\frac{N_{\mathrm{inst}}\times\mathrm{CPI}}{f}
}
$$

后续的**指令系统、CPU、流水线、Cache 与存储系统性能分析**，都会反复回到这组关系。
