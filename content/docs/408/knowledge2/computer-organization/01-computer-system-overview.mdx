## 1. 计算机系统的基本组成

一个完整的计算机系统由 **硬件系统** 和 **软件系统** 共同组成。

| 部分 | 含义          | 作用                |
| -- | ----------- | ----------------- |
| 硬件 | 实际存在的物理设备   | 提供计算、存储、输入输出等基础能力 |
| 软件 | 程序、数据以及相关文档 | 通过指令控制硬件完成具体任务    |

二者并不是彼此独立的：

* **硬件是软件运行的基础**；
* **软件规定硬件完成什么任务以及如何完成任务**；
* 软件最终必须转换成硬件可以直接理解的 **机器指令** 才能运行。

从程序员角度看，软硬件之间最重要的接口之一就是 **指令集体系结构 ISA（Instruction Set Architecture）**。

### 1.1 计算机体系结构与计算机组成

这两个概念容易混淆。

| 概念      | 关注的问题           | 典型内容                |
| ------- | --------------- | ------------------- |
| 计算机体系结构 | 计算机对程序员“表现成什么样” | 指令系统、数据类型、寄存器、寻址方式等 |
| 计算机组成   | 这些功能“具体怎样实现”    | 数据通路、控制器、Cache、总线等  |

可以简单理解为：

> **体系结构规定“做什么”，计算机组成研究“怎么做”。**

同一种 ISA 可以由不同的微体系结构实现，因此可能出现 **能够运行同一套机器代码，但内部实现和性能完全不同** 的处理器。

## 2. 冯·诺依曼计算机

### 2.1 存储程序思想

冯·诺依曼提出的核心思想是 **存储程序（Stored Program）**：

> 程序的指令和程序处理的数据都以二进制形式存放在存储器中，计算机按照程序规定的顺序自动取出并执行指令。

这一思想奠定了现代通用计算机的基础。

### 2.2 冯·诺依曼机的基本特点

传统冯·诺依曼计算机具有以下基本特征：

1. 硬件系统由 **运算器、控制器、存储器、输入设备和输出设备** 五大部件组成。
2. **指令和数据以同等地位存放在存储器中**。
3. 指令和数据在存储器中本质上都是 **二进制代码**。
4. 指令通常由 **操作码** 和 **地址码** 等字段构成。
5. 经典冯·诺依曼机以 **运算器** 为中心，各部件之间的数据传送经过运算器组织。

<InlineSvg src="/images/computer-organization/computer-organization-overview-structure-001.svg" alt={"存储器 运算器 控制器 输入设备 输出设备 数据流 控制流 指令流"} />

> **易错点：指令和数据在存储器中形式上没有区别**
>
> 它们本质上都只是二进制位串。CPU 将某段二进制内容解释成“指令”还是“数据”，取决于 **当前执行过程和使用方式**，而不是这些二进制位本身带有某种特殊标记。

### 2.3 五大部件

| 部件   | 英文                        | 主要功能           |
| ---- | ------------------------- | -------------- |
| 运算器  | Arithmetic Logic Unit，ALU | 完成算术运算和逻辑运算    |
| 控制器  | Control Unit，CU           | 取指、分析指令并产生控制信号 |
| 存储器  | Memory                    | 存储程序和数据        |
| 输入设备 | Input Device              | 将外部信息送入计算机     |
| 输出设备 | Output Device             | 将处理结果送到计算机外部   |

### 2.4 运算器

运算器主要完成：

* 加、减等算术运算；
* 与、或、非、异或等逻辑运算；
* 移位；
* 比较等数据处理操作。

现代 CPU 中运算器通常还包括整数运算单元、浮点运算单元等多个执行部件。

### 2.5 控制器

控制器负责协调其他硬件部件工作，其典型过程为：

**取指 → 译码 → 产生控制信号 → 执行指令**

控制器与运算器合在一起构成 CPU 的核心部分。

### 2.6 存储器

存储器用于保存：

* 程序指令；
* 操作数；
* 中间结果；
* 最终结果。

在计算机组成原理中，通常还会进一步研究：

**寄存器 → Cache → 主存 → 辅存**

所形成的多级存储体系。

### 2.7 输入设备和输出设备

常见输入设备包括：

* 键盘；
* 鼠标；
* 摄像头；
* 网络接口等。

常见输出设备包括：

* 显示器；
* 打印机；
* 网络接口等。

I/O 设备通常不能直接按照 CPU 内部数据通路的方式工作，因此需要通过 **I/O 接口、总线、中断或 DMA** 等机制与 CPU 和存储器交换数据。

## 3. 现代计算机与经典冯·诺依曼模型

经典模型强调“以运算器为中心”，但现代计算机的数据交换大量围绕 **存储系统** 展开。

因此复习时需要区分：

* **经典冯·诺依曼结构**：教材描述中常称以运算器为中心；
* **现代计算机结构**：通常可理解为以存储器为中心，各部件通过总线或互连结构通信。

> **408 易错点**
>
> 如果题目问的是“冯·诺依曼机的基本特点”，通常按照经典教材表述判断；如果讨论现代计算机实际组织方式，则不能机械地认为所有数据都必须经过 ALU。

## 4. 计算机软件

计算机软件通常分为 **系统软件** 和 **应用软件**。

### 4.1 系统软件

系统软件直接服务于计算机系统运行，并为应用程序提供运行环境。

主要作用包括：

* 管理和控制硬件资源；
* 提供基本运行环境；
* 为应用软件提供接口和公共服务。

典型系统软件包括：

* 操作系统；
* 编译程序；
* 汇编程序；
* 链接程序；
* 数据库管理系统等。

### 4.2 应用软件

应用软件面向具体用户需求，用于解决实际问题。

例如：

* 浏览器；
* 办公软件；
* 图像处理软件；
* 游戏；
* 各类业务系统。

可以将两者的关系理解为：

```text
用户
 ↓
应用软件
 ↓
系统软件
 ↓
计算机硬件
```

## 5. 程序设计语言的层次

计算机程序主要可以从三个语言层次理解：

1. 机器语言；
2. 汇编语言；
3. 高级语言。

<InlineSvg src="/images/computer-organization/computer-organization-overview-structure-002.svg" alt={"ProgrammingLanguageLevels"} />

### 5.1 机器语言

机器语言是 **CPU 可以直接识别和执行的语言**。

其基本形式是二进制机器指令，例如：

```text
10110000 01100001
```

特点：

* 与具体 ISA 密切相关；
* 计算机可以直接执行；
* 对人类而言难以阅读和编写；
* 不同体系结构的机器代码通常不能直接通用。

### 5.2 汇编语言

汇编语言使用 **助记符** 表示机器指令。

例如：

```asm
add eax, ebx
```

与纯二进制机器代码相比，更容易阅读。

特点：

* 与特定指令集体系结构密切相关；
* 通常一条汇编指令对应一条或少量机器指令；
* 必须经过 **汇编器（Assembler）** 转换成机器代码。

### 5.3 高级语言

高级语言更加接近人的思维方式，例如：

```c
c = a + b;
```

特点：

* 抽象程度较高；
* 相比机器语言和汇编语言更容易编写、维护；
* 对具体硬件的依赖较小；
* 需要经过 **编译** 或 **解释** 才能运行。

典型高级语言包括：

* C；
* C++；
* Java；
* Python 等。

### 5.4 三种语言的关系

可以将三个层次理解为：

```text
高级语言
    ↓ 编译器
汇编语言
    ↓ 汇编器
机器语言
    ↓
CPU
```

其中机器语言是 **硬件真正直接执行的指令形式**。

> **易错点**
>
> 高级语言程序不能被 CPU 直接执行。即使是所谓“解释型语言”，最终也需要某种已经转换为机器指令的解释器、虚拟机或运行时环境在 CPU 上执行。

## 6. 从源程序到可执行程序

这一过程是理解“软件怎样最终在硬件上执行”的关键。

以 C 程序为例：

```c
int main(void) {
    return 0;
}
```

通常会经历：

**预处理 → 编译 → 汇编 → 链接 → 装载 → 执行**

<InlineSvg src="/images/computer-organization/computer-organization-overview-structure-003.svg" alt={"hello.c 源代码 hello.i 预处理代码 hello.s 汇编代码 hello.o 目标文件 hello (a.out) 可执行文件 预处理器 编译器 汇编器 链接器 + 库 gcc -E gcc -S gcc -c gcc / ld 加载器 → CPU 执行"} />

### 6.1 预处理

预处理器完成：

* 宏展开；
* 头文件包含；
* 条件编译等。

例如：

```bash
gcc -E hello.c -o hello.i
```

文件变化：

```text
hello.c
   ↓ 预处理
hello.i
```

预处理并不是所有高级语言都必须具有的独立阶段，C/C++ 中最为典型。

### 6.2 编译

编译器将预处理后的高级语言程序转换成汇编程序。

```bash
gcc -S hello.c -o hello.s
```

过程可表示为：

```text
hello.i
   ↓ 编译
hello.s
```

编译阶段通常还会进行：

* 语法分析；
* 语义分析；
* 中间代码生成；
* 代码优化；
* 目标代码生成等。

### 6.3 汇编

汇编器把汇编程序转换为 **目标文件**。

```bash
gcc -c hello.s -o hello.o
```

过程：

```text
hello.s
   ↓ 汇编
hello.o
```

目标文件中不仅包含机器代码，还可能包含：

* 符号表；
* 重定位信息；
* 数据段信息等。

### 6.4 链接

链接器将：

* 一个或多个目标文件；
* 所需要的库文件；

组合成最终的 **可执行文件**。

```bash
gcc hello.o -o hello
```

链接阶段主要完成：

* **符号解析**；
* **地址重定位**。

过程：

```text
目标文件 + 库文件
       ↓
      链接
       ↓
    可执行文件
```

### 6.5 装载和执行

当用户运行：

```bash
./hello
```

操作系统中的 **加载器（Loader）** 将可执行程序建立为进程运行所需要的地址空间，并完成必要的运行时准备。

随后 CPU 从程序入口开始不断进行：

```text
取指 → 译码 → 执行
```

最终完成整个程序。

### 6.6 GCC 是编译驱动程序

需要特别注意：

`gcc` 并不只是狭义意义上的“编译器”，它还是一个 **编译驱动程序**，能够调用完整工具链。

例如：

```bash
gcc -c hello.c -o hello.o
```

实际自动经历：

```text
hello.c
  ↓
预处理
  ↓
编译
  ↓
汇编
  ↓
hello.o
```

因此：

> 不要因为命令中只有一个 `gcc`，就认为预处理器、编译器和汇编器是同一个处理阶段。

## 8. 时钟周期

### 8.1 什么是时钟

CPU 属于同步时序电路，其中大量部件需要在统一节拍下改变状态。

计算机中通常使用 **晶体振荡器** 产生稳定的周期信号。

石英晶体具有压电特性：

* 施加电压会产生机械振动；
* 机械振动又可以产生电信号。

通过振荡电路可以得到稳定的周期信号。

<InlineSvg src="/images/computer-organization/computer-organization-overview-performance-001.svg" alt={"C 0 C 1 L 1 R 1"} />

晶振产生的原始信号需要经过整形、分频等处理，形成适合数字电路使用的稳定方波时钟。

<InlineSvg src="/images/computer-organization/computer-organization-overview-performance-002.svg" alt={"原始连续模拟信号 离散数字信号 整型和分频"} />

### 8.2 时钟周期的定义

**时钟周期（Clock Cycle）** 是相邻两个同类型有效时钟边沿之间的时间，通常记作：

$$
T_{\mathrm{clk}}
$$

它是 CPU 时序操作中的基本时间单位。

例如：

```text
↑──────↑──────↑──────↑
   Tclk    Tclk
```

### 8.3 所有部件都使用同一个时钟吗

**不一定。**

计算机中不同部件可能工作在不同频率下，例如：

* CPU 核心；
* 内存控制器；
* DRAM；
* 外设控制器。

这些部件可能属于不同的 **时钟域（Clock Domain）**。

同一个时钟域中的电路由统一时钟同步；不同的时钟域之间通信时，需要：

* 同步器；
* 握手机制；
* FIFO；
* 缓冲等方法。

## 9. 主频

**主频（Clock Frequency）** 表示 CPU 时钟每秒发生多少个周期，记为：

$$
f
$$

主频与时钟周期互为倒数：

$$
f=\frac{1}{T_{\mathrm{clk}}}
$$

因此：

$$
T_{\mathrm{clk}}=\frac{1}{f}
$$

常见单位：

| 单位  | 含义              |
| --- | --------------- |
| Hz  | 每秒 $10^0$ 个周期 |
| kHz | 每秒 $10^3$ 个周期 |
| MHz | 每秒 $10^6$ 个周期 |
| GHz | 每秒 $10^9$ 个周期 |

例如一颗主频为 $3\,\mathrm{GHz}$ 的 CPU：

$$
3\,\mathrm{GHz}=3\times10^9\,\mathrm{Hz}
$$

即每秒经历约：

$$
3\times10^9
$$

个时钟周期。

对应一个时钟周期约为：

$$
T_{\mathrm{clk}}
=
\frac{1}{3\times10^9}
\approx
0.333\,\mathrm{ns}
$$

> **易错点**
>
> “3 GHz”不意味着 CPU 每秒一定完成 30 亿条指令。
>
> 它只表示每秒存在 30 亿个 **时钟周期**。一条指令可能需要多个周期，而流水线或超标量处理器也可能平均一个周期完成多条指令。

## 10. 时钟周期、机器周期与指令周期

这三个概念是高频易混点。

<InlineSvg src="/images/computer-organization/computer-organization-overview-performance-003.svg" alt={"时钟 周期 机器周期 （取指令） 机器周期 （译码） 机器周期 （执行） 机器周期 （执行） 指令周期"} />

### 10.1 时钟周期

时钟周期是同步数字电路的基本时间单位。

通常：

$$
T_{\mathrm{clk}}=\frac{1}{f}
$$

### 10.2 机器周期

传统教材中，**机器周期** 表示 CPU 完成一个相对完整的基本操作所需要的时间。

例如：

* 一次取指；
* 一次存储器访问；
* 某个基本内部操作。

一个机器周期通常包含若干时钟周期。

### 10.3 指令周期

**指令周期（Instruction Cycle）** 是一条指令从开始取指到执行完成所经历的全过程。

传统非流水处理器中，可以近似理解为：

```text
指令周期
 ├─ 取指机器周期
 ├─ 间址机器周期（可能存在）
 ├─ 执行机器周期
 └─ 中断机器周期（可能存在）
```

因此传统模型中通常有：

```text
指令周期
    ↓
若干机器周期
    ↓
若干时钟周期
```

### 10.4 流水线处理器中的区别

现代流水线处理器会让多条指令的不同阶段 **重叠执行**。

例如：

```text
周期    1    2    3    4    5
I1     IF   ID   EX   MEM  WB
I2          IF   ID   EX   MEM
I3               IF   ID   EX
```

因此现代 CPU 的性能不能简单理解成：

> “一条指令周期 = 若干机器周期，然后一条一条串行执行”。

性能分析通常使用：

* 指令数；
* CPI；
* 时钟周期；
* 主频。

## 11. CPI

**CPI（Cycles Per Instruction）** 表示程序执行过程中 **平均每条指令所需要的时钟周期数**。

如果程序执行：

* 指令数为 $N_{\mathrm{inst}}$；
* 总时钟周期数为 $N_{\mathrm{cycle}}$；

则：

$$
\mathrm{CPI}
=
\frac{N_{\mathrm{cycle}}}
{N_{\mathrm{inst}}}
$$

### 11.1 CPI 是平均值

程序中不同类型指令所需的周期数可能不同。

若第 $i$ 类指令：

* 数量为 $N_i$；
* CPI 为 $\mathrm{CPI}_i$；

则平均 CPI 为：

$$
\mathrm{CPI}_{\mathrm{avg}}
=
\frac{
\sum_i N_i\mathrm{CPI}_i
}{
\sum_i N_i
}
$$

如果已知各类指令所占比例 $p_i$，则：

$$
\mathrm{CPI}_{\mathrm{avg}}
=
\sum_i p_i\mathrm{CPI}_i
$$

> **高频易错点**
>
> CPI 是一个 **统计性能指标**。
>
> “CPI”与“指令周期”不是同一个概念：
>
> * CPI：平均一条指令消耗几个时钟周期；
> * 指令周期：某条指令从取指到完成所经历的过程。

---

## 12. CPU 执行时间

这是本章最重要的性能公式之一。

设：

* 指令条数为 $N_{\mathrm{inst}}$；
* 平均 CPI 为 $\mathrm{CPI}$；
* 时钟周期为 $T_{\mathrm{clk}}$；

则总时钟周期数为：

$$
N_{\mathrm{cycle}}
=
N_{\mathrm{inst}}
\times
\mathrm{CPI}
$$

CPU 执行时间为：

$$
T_{\mathrm{CPU}}
=
N_{\mathrm{inst}}
\times
\mathrm{CPI}
\times
T_{\mathrm{clk}}
$$

因为：

$$
T_{\mathrm{clk}}=\frac{1}{f}
$$

所以：

$$
T_{\mathrm{CPU}}
=
\frac{
N_{\mathrm{inst}}
\times
\mathrm{CPI}
}{
f
}
$$

这是性能计算最核心的公式。

### 12.1 三个决定性能的因素

从公式可知 CPU 时间取决于：

1. **指令条数**
2. **平均 CPI**
3. **主频**

即：

```text
算法 / 编译器
    ↓
指令条数

ISA / 编译器 / CPU
    ↓
CPI

硬件实现
    ↓
主频
```

因此不能只看主频评价 CPU 性能。

### 12.2 典型计算

某程序执行 $10^9$ 条指令，平均 CPI 为 $2$，CPU 主频为 $2\,\mathrm{GHz}$。

则：

$$
T_{\mathrm{CPU}}
=
\frac{
10^9\times2
}{
2\times10^9
}
=
1\,\mathrm{s}
$$

---

## 13. IPC

**IPC（Instructions Per Cycle）** 表示平均每个时钟周期完成多少条指令。

在简单平均意义下：

$$
\mathrm{IPC}
=
\frac{1}{\mathrm{CPI}}
$$

例如：

若：

$$
\mathrm{CPI}=0.5
$$

则：

$$
\mathrm{IPC}=2
$$

即平均每个周期完成两条指令。

> **注意**
>
> CPI 小于 1 并不矛盾。现代超标量处理器可能在一个周期内同时完成多条指令，因此平均 CPI 可以低于 1。

---

## 14. IPS 与 MIPS

### 14.1 IPS

**IPS（Instructions Per Second）** 表示每秒执行的平均指令条数。

由：

$$
\mathrm{IPS}
=
\frac{N_{\mathrm{inst}}}{T_{\mathrm{CPU}}}
$$

结合 CPU 时间公式可得：

$$
\mathrm{IPS}
=
\frac{f}{\mathrm{CPI}}
$$

### 14.2 MIPS

**MIPS（Million Instructions Per Second）** 表示每秒执行多少百万条指令。

$$
1\,\mathrm{MIPS}
=
10^6\,\mathrm{IPS}
$$

因此：

$$
\mathrm{MIPS}
=
\frac{
f
}{
\mathrm{CPI}\times10^6
}
$$

### 14.3 为什么不能只用 MIPS 比较所有计算机

不同 ISA 的一条指令可以完成完全不同的工作。

例如：

```text
机器 A：完成任务需要 100 条简单指令
机器 B：完成任务需要 50 条复杂指令
```

即使 A 的 MIPS 更高，也不能保证实际程序运行时间更短。

因此：

> **MIPS 更适合在指令系统相同或程序特征相近的情况下进行粗略比较。**

真正可靠的比较指标仍然是：

$$
T_{\mathrm{CPU}}
$$

---

## 15. FLOPS

**FLOPS（Floating-point Operations Per Second）** 表示每秒能够完成多少次浮点运算。

它常用于衡量：

* GPU；
* 超级计算机；
* AI 加速器；
* 科学计算系统；

的浮点计算能力。

常用单位如下：

| 单位     |               数量级 |
| ------ | ----------------: |
| MFLOPS |    $10^6$ FLOPS |
| GFLOPS |    $10^9$ FLOPS |
| TFLOPS | $10^{12}$ FLOPS |
| PFLOPS | $10^{15}$ FLOPS |
| EFLOPS | $10^{18}$ FLOPS |
| ZFLOPS | $10^{21}$ FLOPS |

相邻单位通常相差：

$$
10^3
$$

例如：

$$
1\,\mathrm{GFLOPS}
=
10^3\,\mathrm{MFLOPS}
$$

<InlineSvg src="/images/computer-organization/computer-organization-overview-performance-004.svg" alt={"FLOPS_units"} />

> **易错点**
>
> FLOPS 中的 “OP” 是 **浮点运算次数**，而 MIPS 中的 “I” 是 **指令条数**。
>
> 一条机器指令可能完成多个浮点运算，因此二者不能直接转换。

---

## 16. 响应时间与吞吐量

衡量计算机性能时，需要区分两个不同角度。

### 16.1 响应时间

**响应时间（Response Time / Execution Time）**：

> 完成一个任务需要多长时间。

例如：

```text
程序运行完成需要 2 s
```

响应时间越短，单个任务完成得越快。

### 16.2 吞吐量

**吞吐量（Throughput）**：

> 单位时间内系统能够完成多少任务。

例如：

```text
服务器每秒可以处理 10000 个请求
```

### 16.3 二者的区别

某项优化可能：

* 提高吞吐量；
* 却不明显降低单个任务的响应时间。

例如增加多个处理器并行处理独立任务：

```text
任务 A ─→ CPU 1
任务 B ─→ CPU 2
任务 C ─→ CPU 3
```

系统每秒完成的任务数量增加，但每个任务本身的运行时间可能基本不变。

---

## 17. 字长

**机器字长（Word Length）** 通常表示计算机中 CPU 一次能够处理的基本二进制数据宽度，与：

* 运算器；
* 通用寄存器；
* 数据通路；

等结构密切相关。

例如：

* 32 位处理器；
* 64 位处理器。

常见机器字长：

```text
8 bit
16 bit
32 bit
64 bit
```

> **易错点**
>
> 以下概念不能混为一谈：
>
> * 机器字长
> * 指令字长
> * 存储字长
> * 数据总线宽度
>
> 它们在某些计算机中可能相同，但并不存在“必须相同”的关系。

---

## 18. 数据通路宽度

**数据通路宽度（Data Path Width）** 表示数据通路一次能够并行传输或处理多少位数据。

例如：

```text
64 bit 数据通路
```

表示一次传送可包含 64 位数据。

如果一次数据传输量为 $W$ bit，则多次传输时总数据量与传输次数有关。

> **注意**
>
> “总线宽度为 64 位”并不自动意味着“每个 CPU 时钟周期一定传输 64 位有效数据”。
>
> 实际带宽还与：
>
> * 总线工作频率；
> * 每周期传输次数；
> * 总线协议；
> * 等待周期；
> * 利用率；
>
> 等因素有关。

---

## 19. 主存容量与寻址范围

主存容量表示主存能够存储的最大信息量。

常用单位：

$$
1\,\mathrm{B}=8\,\mathrm{bit}
$$

$$
1\,\mathrm{KB}=2^{10}\,\mathrm{B}
$$

$$
1\,\mathrm{MB}=2^{20}\,\mathrm{B}
$$

$$
1\,\mathrm{GB}=2^{30}\,\mathrm{B}
$$

---

## 20. MAR 与地址空间

**MAR（Memory Address Register，存储器地址寄存器）** 用于保存当前要访问的存储单元地址。

如果 MAR 有 $n$ 位，则最多能够表示：

$$
2^n
$$

个不同地址。

因此：

$$
\text{最大可寻址单元数}=2^{\text{MAR 位数}}
$$

反过来：

$$
\text{MAR 位数}
=
\log_2
\left(
\text{可寻址单元数}
\right)
$$

### 20.1 按字节寻址

若地址空间大小为：

$$
128\,\mathrm{KB}
=
2^{17}\,\mathrm{B}
$$

且采用 **按字节寻址**，共有：

$$
2^{17}
$$

个可寻址单元，因此：

$$
\mathrm{MAR}=17\text{ 位}
$$

### 20.2 按字寻址

仍假设地址空间总容量为：

$$
128\,\mathrm{KB}
=
2^{17}\,\mathrm{B}
$$

若：

* 字长为 16 bit；
* 一个字为：

$$
16\,\mathrm{bit}=2\,\mathrm{B}
$$

并采用 **按字寻址**，则可寻址字数为：

$$
\frac{2^{17}\,\mathrm{B}}
{2\,\mathrm{B}}
=
2^{16}
$$

所以：

$$
\mathrm{MAR}=16\text{ 位}
$$

### 20.3 通用做法

此类题优先计算：

$$
\text{可寻址单元数}
=
\frac{
\text{地址空间总容量}
}{
\text{一个寻址单位的大小}
}
$$

然后：

$$
\mathrm{MAR\ 位数}
=
\log_2
\left(
\text{可寻址单元数}
\right)
$$

> **408 高频陷阱**
>
> 先确认究竟是：
>
> * 按字节寻址；
> * 按字寻址；
> * 还是其他大小的存储单元寻址。
>
> 不能看到“128 KB”就直接得出 MAR 为 17 位。

---

## 21. 地址总线、MAR 与实际主存容量

在典型模型中：

* MAR 位数决定 CPU 可以提供多少位存储地址；
* 地址总线宽度通常与需要传送的地址位数相关。

如果地址位数为 $n$，理论最大可寻址单元数量为：

$$
2^n
$$

但需要注意：

> **可寻址范围不一定等于实际安装的主存容量。**

例如 CPU 可以形成 32 位地址：

$$
2^{32}
$$

若按字节寻址，理论地址空间为：

$$
2^{32}\,\mathrm{B}
=
4\,\mathrm{GB}
$$

但计算机完全可能只安装：

```text
1 GB
```

实际物理内存。

因此需要区分：

* **地址空间**
* **实际主存容量**

## 22. 性能比较

通常把性能定义为执行时间的倒数：

$$
\mathrm{Performance}
=
\frac{1}{\mathrm{Execution\ Time}}
$$

若机器 A 的执行时间为 $T_A$，机器 B 为 $T_B$，则 A 相对于 B 的性能倍数为：

$$
\frac{
\mathrm{Performance}_A
}{
\mathrm{Performance}_B
}
=
\frac{T_B}{T_A}
$$

例如：

$$
T_A=5\,\mathrm{s}
$$

$$
T_B=10\,\mathrm{s}
$$

则：

$$
\frac{
\mathrm{Performance}_A
}{
\mathrm{Performance}_B
}
=
\frac{10}{5}
=
2
$$

即 A 的性能是 B 的 2 倍。

> **易错点**
>
> 性能与执行时间成 **反比**。
>
> 不要写成：
>
> $$
> \frac{T_A}{T_B}
> $$
>
> 来表示 A 相对于 B 的性能。

## 24. 高频概念对比

| 概念     | 含义             | 易错点            |
| ------ | -------------- | -------------- |
| 时钟周期   | 一个时钟节拍的时间      | 与主频互为倒数        |
| 主频     | 每秒时钟周期数        | 主频高不一定程序一定更快   |
| 机器周期   | 完成一个基本操作的时间    | 通常含若干时钟周期      |
| 指令周期   | 一条指令从取指到完成的全过程 | 不等于 CPI        |
| CPI    | 平均每条指令所需周期数    | 是统计平均指标        |
| IPC    | 平均每周期完成指令数     | 简单意义下为 CPI 的倒数 |
| IPS    | 每秒执行的指令数       | 与主频、CPI 有关     |
| MIPS   | 每秒百万条指令        | 不适合跨 ISA 直接比较  |
| FLOPS  | 每秒浮点运算次数       | 浮点运算次数不等于指令数   |
| 响应时间   | 完成单个任务需要多久     | 越小越好           |
| 吞吐量    | 单位时间完成多少任务     | 越大越好           |
| 机器字长   | CPU 基本数据处理宽度   | 不等于指令长度        |
| MAR 位数 | 地址能够表示的位数      | 先判断寻址单位        |

## 25. 408 易错点总结

### 易错点 1：高主频不代表一定高性能

由：

$$
T_{\mathrm{CPU}}
=
\frac{
N_{\mathrm{inst}}\times\mathrm{CPI}
}{
f
}
$$

可知性能同时取决于：

* 指令数；
* CPI；
* 主频。

因此只比较 GHz 没有意义。

### 易错点 2：CPI 不是指令周期

**CPI** 是平均数值。

**指令周期** 是一条指令执行过程的时间概念。

二者不能混用。

### 易错点 3：一条指令不一定只需要一个时钟周期

可能出现：

$$
\mathrm{CPI}>1
$$

在现代超标量处理器中也可能出现：

$$
\mathrm{CPI}<1
$$

### 易错点 4：机器字长、指令字长、存储字长不一定相等

不能看到“32 位 CPU”就推出：

```text
所有指令都是 32 位
所有总线都是 32 位
所有存储单元都是 32 位
```

### 易错点 5：MAR 位数取决于可寻址单元数量

公式不是简单的：

```text
容量 → 直接取 log₂
```

而是：

$$
\text{可寻址单元数}
=
\frac{
\text{容量}
}{
\text{寻址单位大小}
}
$$

再求：

$$
\log_2
$$

### 易错点 6：指令和数据在存储器中没有本质形式区别

二者都是二进制编码。

区别来自 CPU **怎样解释和使用这些二进制位**。

### 易错点 7：MIPS 高不一定程序执行得更快

不同 ISA 的单条指令完成工作量不同，因此跨 ISA 比较时：

$$
\mathrm{MIPS}
$$

并不是可靠的最终性能指标。

### 易错点 8：FLOPS 与 MIPS 不是同一种指标

* MIPS：指令数；
* FLOPS：浮点运算次数。

一条指令可能完成多个浮点运算，因此不能直接等同。

## 26. 本章知识主线

可以用下面这条主线串联整章：

```text
高级语言程序
      ↓
预处理 / 编译 / 汇编 / 链接
      ↓

      ↓

```

性能分析则沿另一条主线：

```text
指令条数
   ×
平均 CPI
   ×
时钟周期
   ↓
CPU 执行时间
```

即：

$$
\boxed{
T_{\mathrm{CPU}}
=
N_{\mathrm{inst}}
\times
\mathrm{CPI}
\times
T_{\mathrm{clk}}
}
$$

也可以写成：

$$
\boxed{
T_{\mathrm{CPU}}
=
\frac{
N_{\mathrm{inst}}
\times
\mathrm{CPI}
}{
f
}
}
$$

这两个公式是后续 **指令系统、CPU、流水线、Cache 和存储系统性能分析** 的重要基础。
