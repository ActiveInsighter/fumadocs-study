指令系统位于**软件与硬件的边界**。编译器把高级语言翻译为机器能够识别的指令，CPU 再按照指令中规定的操作码、操作数和寻址方式完成取指、译码与执行。

408 复习时建议沿着下面这条主线理解：

> **ISA 规定机器能做什么 → 指令格式规定如何编码 → 寻址方式规定操作数在哪里 → 指令语义决定执行什么操作 → CPU 数据通路真正完成这些操作。**

本章高频内容主要集中在：

* **指令格式与扩展操作码**
* **各种寻址方式与有效地址计算**
* **数据对齐与大小端**
* **汇编指令与高级语言的对应**
* **条件跳转、CALL/RET 与函数栈帧**
* **RISC 与 CISC 的基本区别**

## 1. 指令体系结构 ISA

> **真题考查**
>
> * 选择题：2017 年第 12 题、2022 年第 18 题、2025 年第 16 题、2026 年第 12、16 题

**指令体系结构**（Instruction Set Architecture，ISA）是处理器对软件提供的**抽象机器规范**，也是软件和硬件之间最重要的接口。

ISA 描述的是：

> **软件能够观察到的处理器行为，以及软件与处理器交互时必须遵守的规则。**

典型 ISA 会规定：

1. **指令集及指令语义**

   * 支持哪些指令；
   * 每条指令执行后应产生什么结果。
2. **指令格式与编码**

   * 操作码如何编码；
   * 操作数字段如何组织。
3. **软件可见寄存器**

   * 通用寄存器；
   * 程序计数器；
   * 状态寄存器；
   * 控制寄存器等。
4. **操作数与寻址方式**

   * 立即数；
   * 寄存器；
   * 内存地址等。
5. **数据类型与表示**

   * 整数；
   * 浮点数；
   * 向量数据等。
6. **内存访问行为**

   * 字节序；
   * 原子操作；
   * 多处理器环境下的软件可见内存顺序等。
7. **异常、中断和特权机制**

   * 异常状态；
   * 中断机制；
   * 特权级；
   * 系统寄存器等。

<InlineSvg src="/images/computer-organization/computer-organization-instruction-concepts-001.svg" alt={"ISA、操作系统与应用程序的抽象层次关系"} />

### 1.1 ISA 与微架构

最重要的区分是：

> **ISA 规定“做什么”，微架构规定“怎么做”。**

例如 ISA 可以规定：

```asm
ADD R1, R2
```

执行后目标寄存器应得到规定的加法结果，但 ISA 通常不会规定 CPU 内部：

* 有几级流水线；
* 有几个 ALU；
* Cache 多大；
* 是否乱序执行；
* 是否进行寄存器重命名；
* 使用什么分支预测算法；
* 一条指令内部被分解成多少微操作。

这些属于**微架构**（Microarchitecture）。

因此，不同处理器可以实现同一个 ISA，但内部结构完全不同。只要对软件表现出的行为符合 ISA，就可以运行相同的机器程序。

## 2. 指令的基本格式

> **真题考查**
>
> * 选择题：2020 年第 16 题
> * 解答题：2013 年第 44 题、2015 年第 44 题、2021 年第 43 题、2026 年第 43 题

一条机器指令本质上描述两件事情：

> **对什么对象，进行什么操作。**

所以指令通常至少包含：

* **操作码**（Opcode）
* **操作数或地址字段**

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-001.svg" alt={"instruction_format"} />

### 2.1 操作码

操作码指出 CPU 应执行什么操作，例如：

* 加法；
* 减法；
* 数据传送；
* 比较；
* 跳转；
* 函数调用；
* 输入输出等。

### 2.2 地址字段

这里的“地址”是广义概念，不一定是内存地址，也可能表示：

* 内存地址 `<addr>`
* 寄存器编号 `<reg>`
* 立即数 `<imm>`

实际解释方式由**寻址方式**决定。

## 3. 指令的分类

> **真题考查**
>
> * 选择题：2022 年第 19 题、2026 年第 17 题
> * 解答题：2010 年第 43 题、2020 年第 43 题

### 3.1 按功能分类

常见指令可分为：

| 类别        | 典型指令                        | 作用              |
| --------- | --------------------------- | --------------- |
| 数据传送      | `MOV`、`PUSH`、`POP`          | 寄存器、内存和栈之间交换数据  |
| 算术运算      | `ADD`、`SUB`、`MUL`、`DIV`     | 加减乘除            |
| 逻辑运算      | `AND`、`OR`、`XOR`、`NOT`      | 位运算             |
| 比较        | `CMP`                       | 比较并修改条件标志       |
| 控制转移      | `JMP`、`Jxx`、`CALL`、`RET`    | 改变程序执行顺序        |
| 输入输出      | `IN`、`OUT`                  | 独立 I/O 编址中的端口访问 |
| 字符串操作     | `MOVS`、`LODS`、`STOS`、`CMPS` | 批量处理内存数据        |
| 陷阱/系统调用相关 | `INT`                       | 显式产生软件异常或软件中断   |
| 控制/特权相关   | `CLI`、`STI`                 | 修改中断允许状态        |

## 4. 按地址数分类

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-003.svg" alt={"OP OP A 1 OP A 1 A 2 OP A 3 A 1 A 2 零地址 一地址 二地址 三地址"} />

| 类型    | 形式              | 典型语义                 |
| ----- | --------------- | -------------------- |
| 零地址指令 | `OP`            | 操作数通常隐含，如栈式机器        |
| 一地址指令 | `OP A1`         | 对 A1 操作，并通常写回 A1     |
| 二地址指令 | `OP A1, A2`     | A1 与 A2 运算，结果通常写回 A1 |
| 三地址指令 | `OP A3, A1, A2` | A1 与 A2 运算，结果写入 A3   |

例如二地址指令可抽象为：

$$
A_1 \leftarrow A_1\ \mathrm{op}\ A_2
$$

三地址指令可抽象为：

$$
A_3 \leftarrow A_1\ \mathrm{op}\ A_2
$$

### 4.1 为什么地址越多，操作码空间越小？

当**指令字长固定**时：

> 地址字段占用的位数越多，留给操作码的位数就越少。

因此：

* 三地址指令通常操作码较短；
* 二地址指令可使用更多操作码位；
* 一地址、零地址指令可进一步扩展操作码。

这正是**扩展操作码**的基础。

## 5. 定长指令与变长指令

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-004.svg" alt={"变长指令集 定长指令集"} />

### 5.1 定长指令

所有机器指令长度相同或高度规则化。

典型优点：

* 指令边界容易确定；
* 取指简单；
* 译码简单；
* 对流水线友好。

不足是某些指令并不需要那么多字段，因此可能浪费编码空间。

在 408 的典型抽象中，RISC 常采用这种设计思想。

### 5.2 变长指令

不同指令长度可以不同。

典型代表为 x86。

优点：

* 编码紧凑；
* 可以提供丰富的指令形式；
* 复杂指令不必被固定字长限制。

缺点：

* 确定指令边界更复杂；
* 取指和译码电路更复杂。

### 5.3 定长指令中的无效字段

如果某一固定长度指令实际只需要较少的操作数字段，剩余位置可以作为保留位、扩展字段或其他编码字段。

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-005.svg" alt={"指令长度设计的两大挑战及解决方案 问题 1：地址字段数量不统一 定长指令 · 不同指令需要的地址字段数不同 三地址指令 操作码 地址1 地址2 地址3 ← 刚好填满 二地址指令 操作码 地址1 地址2 无效字段 ← 需要填充! ✓ 解决方案：无效字段填充 指令长度保持一致(如32位) 地址字段不足时用填充值占位 填充值不影响执行,仅用于对齐 简化硬件解码逻辑 💡 定长指令的优势 • 解码简单：固定位置提取字段 • 流水线高效：指令长度可预测 • 取指快速：按固定步长即可"} />

## 6. 扩展操作码

> **真题考查**
>
> * 选择题：2017 年第 16 题、2022 年第 19 题

扩展操作码是本章非常典型的计算题。

其基本思想是：

> **地址字段越少，空出的位越多，就可以拿这些位继续扩展操作码。**

即采用：

> **定长指令字 + 可变长度操作码**

不同长度的操作码必须满足**前缀编码原则**：

> 一个较短的合法操作码不能是另一条较长操作码的前缀。

否则 CPU 读到前面的若干位时就无法判断操作码是否已经结束。

### 6.1 前缀码思想

假设：

* 三地址指令：4 位操作码；
* 二地址指令：6 位操作码；
* 一地址指令：8 位操作码。

必须保证：

* 任何 4 位完整操作码都不能成为 6 位或 8 位操作码的前缀；
* 任何 6 位完整操作码都不能成为 8 位操作码的前缀。

只有这样才能保证**唯一译码**。

---

### 6.2 典型扩展操作码例题

假设：

* 指令字长：16 位；
* 每个地址字段：4 位；
* 三地址指令：15 条；
* 二地址指令：12 条；
* 一地址指令：63 条；
* 零地址指令：16 条。

三地址格式：

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-006.svg" alt={"op A1 A2 A3 4 位 4 位 4 位 4 位"} />

4 位操作码一共有：

$$
2^4=16
$$

种编码。

三地址指令用了其中 15 个：

```text
0000 ~ 1110
```

剩下：

```text
1111
```

作为**扩展前缀**。

继续借用原来的一个地址字段，即又得到 4 位编码。

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-007.svg" alt={"【三地址】OP = 0000 ~ 1110 (15条） OP = 1111 【二地址】A1 = 0000 ~ 1011 (12条） A1 = 1111 A1= 1100 A1 = 1101 A1 = 1110 【一地址】A2 = 0000 ~ 1111 （16条） 【一地址】A2 = 0000 ~ 1110 （15条） A2 = 1111 【零地址】A2 = 0000 ~ 1111 （16条）"} />

最终可得到：

| 指令类型     | 操作码范围                   | 剩余地址字段   |
| -------- | ----------------------- | -------- |
| 三地址，15 条 | `0000 ~ 1110`           | A1、A2、A3 |
| 二地址，12 条 | `1111 0000 ~ 1111 1011` | A2、A3    |
| 一地址，63 条 | 继续扩展下一字段，其中保留一个前缀       | A3       |
| 零地址，16 条 | 最后一个扩展前缀继续使用 4 位        | 无        |

### 6.3 做扩展操作码题的稳定方法

不要硬背具体编码，直接画**编码树**：

```text
                 根
                 │
             第一层操作码
            /          \
        普通指令      扩展前缀
                        │
                    再扩展字段
                   /          \
               普通指令      扩展前缀
                                │
                              ...
```

核心只有一句：

> **某一级未被普通指令使用的编码，可以成为下一级的扩展前缀。**

## 7. 寻址方式

> **真题考查**
>
> * 选择题：2009 年第 16 题、2011 年第 16 题、2013 年第 17 题、2014 年第 17 题、2016 年第 17 题、2017 年第 15 题、2018 年第 18 题、2019 年第 17 题、2020 年第 16 题、2023 年第 17 题
> * 解答题：2010 年第 43 题、2014 年第 44 题、2019 年第 45 题、2023 年第 44 题

**寻址方式**（Addressing Mode）描述的是：

> **指令如何得到一个操作数，或者如何得到该操作数的有效地址。**

为了方便后续表达，约定：

* `A`：指令中的地址字段或位移量；
* `R`：某寄存器；
* `(R)`：寄存器 R 中保存的内容；
* `EA`：Effective Address，有效地址；
* `M[EA]`：有效地址 EA 对应内存单元中的内容。

> **易错点**
>
> 寻址方式是针对**某一个操作数**而言的，而不是整条指令只能有一种寻址方式。

例如：

```asm
MOV AX, 1234H
```

其中：

* `AX`：寄存器寻址；
* `1234H`：立即寻址。

## 8. 立即寻址

立即寻址（Immediate Addressing）把**操作数本身直接编码在指令中**。

例如：

```asm
MOV AX, 4576H
```

这里 `4576H` 就是立即数。

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-008.svg" alt={"• • • • • OP 76H 45H • • • • • 76H 45H AX MOV AX, 4576H 立即数寻址 指令存储在 text 段在内存中 AX"} />

特点：

* 不需要再通过地址去寻找操作数；
* 取得操作数速度快；
* 立即数的位数受到指令格式限制。

典型应用：

```asm
MOV AX, 5
CMP AL, 0
ADD R1, R1, #1
```

---

## 9. 寄存器寻址

操作数位于 CPU 寄存器中。

例如：

```asm
MOV AX, BX
```

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-009.svg" alt={"• • • • • OP BX • • • • • 76H 45H BX MOV AX, BX 寄存器寻址 指令存储在 text 段在内存中 AX 76H 45H AX"} />

特点：

* 不需要访问主存；
* 速度通常最快；
* 指令中只需编码寄存器编号，因此地址字段可以很短。

---

## 10. 直接寻址

直接寻址中，指令中的地址字段直接给出操作数所在的内存地址。

$$
EA=A
$$

操作数为：

$$
M[EA]
$$

例如：

```asm
MOV R1, [1000]
```

表示从地址 `1000` 对应的存储单元中读取数据。

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-010.svg" alt={"图示"} />

典型形式：

```asm
MOV AX, [0x1234]
MOV [0xB8000], AL
```

> **注意**
>
> 在现代系统中，机器程序看到的地址通常首先属于虚拟地址空间，最终访问物理内存还可能经过虚拟地址到物理地址的转换。
>
> 相关流程可结合[虚拟存储器](/docs/408/knowledge2/computer-organization/03-storage-system/03-virtual-memory-tlb/)理解。

## 11. 间接寻址

间接寻址的核心是：

> **指令给出的不是最终操作数地址，而是“保存最终地址的位置”。**

### 11.1 寄存器间接寻址

最常见形式：

$$
EA=(R)
$$

例如：

```asm
MOV R1, [R2]
```

R2 中保存的内容不是数据本身，而是数据所在的内存地址。

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-011.svg" alt={"图示"} />

例如：

```asm
MOV AX, [BX]
```

CPU 的逻辑是：

```text
读取 BX
   ↓
BX 中保存一个地址
   ↓
用该地址访问主存
   ↓
取出真正的操作数
```

这种方式非常适合实现：

* 指针；
* 链表；
* 动态数据结构。

## 12. 基址寻址

基址寻址使用：

> **基址寄存器 + 位移量**

$$
EA=(R_b)+A
$$

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-012.svg" alt={"OP R b A 基址寄存器 (R b ) + A = E 操作数 E: 指令 基址 （寻址标志） 逻辑地址 加法器 有效地址 地址 主存"} />

典型场景：

* 函数栈帧；
* 结构体成员；
* 某个数据区域中的固定偏移。

例如：

```asm
MOV AX, [BP+4]
MOV BX, [BP-2]
MOV AX, [BX+4]
```

以经典 32 位栈帧思想理解：

```text
高地址
+---------------------+
| 参数2               |
+---------------------+
| 参数1               |
+---------------------+
| 返回地址            |
+---------------------+
| 旧 BP/EBP           | ← BP/EBP
+---------------------+
| 局部变量1           |
+---------------------+
| 局部变量2           |
+---------------------+
低地址
```

因此：

```asm
MOV AX, [BP+4]     ; 访问参数
MOV BX, [BP-2]     ; 访问局部变量
```

## 13. 变址寻址

变址寻址通常把一个**可变化的索引寄存器**加入地址计算。

典型抽象：

$$
EA=A+(R_x)
$$

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-013.svg" alt={"OP ...... 基准地址 A 变址值 操作数 E: 指令 主存 ALU 有效地址 EA 变址寄存器 R x"} />

常用于：

* 数组；
* 循环；
* 表格；
* 连续数据结构。

例如：

```asm
MOV AX, [BX+SI]
MOV AL, [BX+CX]
```

现代 x86 中还经常采用更一般的形式：

$$
EA=Base+Index\times Scale+Displacement
$$

其中 `Scale` 常取：

* 1
* 2
* 4
* 8

例如：

```asm
MOV EAX, [EBX + ECX*4 + 8]
```

非常适合访问 4 字节数组元素。

### 13.1 基址寻址与变址寻址

| 基址寻址            | 变址寻址               |
| --------------- | ------------------ |
| 基址寄存器通常表示某一区域起点 | 变址寄存器通常表示元素下标或动态偏移 |
| 位移量往往较稳定        | 索引值通常随循环改变         |
| 常用于栈帧、结构体       | 常用于数组和循环           |

实际 ISA 中二者经常组合使用，不必机械地把每条机器指令只归入其中一种。

## 14. 相对寻址

相对寻址最常用于：

* 条件分支；
* 无条件跳转；
* 函数调用。

核心计算为：

$$
EA=PC+\mathrm{offset}
$$

在很多 ISA 和实际机器指令中，计算基准实际上是**已经指向下一条指令的 PC**。

因此更稳妥地写成：

$$
Target=PC_{\text{next}}+\mathrm{offset}
$$

于是：

$$
\mathrm{offset}=Target-PC_{\text{next}}
$$

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-014.svg" alt={"OP ...... A PC 指令 E: 指令 主存 ALU 有效地址 EA .text"} />

例如：

```asm
cmp eax, 0
je .L1

...

.L1:
call foo
```

机器码中通常记录的是类似：

```text
je +0x18
```

假设：

* 当前 `je` 地址：`0x1000`
* 指令长度：2 Byte
* 下一条指令地址：`0x1002`
* 位移量：`0x18`

则：

$$
Target=0x1002+0x18=0x101A
$$

相对寻址的一个重要优势是：

> 代码整体搬到其他地址后，只要指令之间的相对距离不变，许多相对跳转就不需要修改。

因此它非常有利于：

* 程序重定位；
* 位置无关代码；
* 分支指令编码。

## 15. 堆栈寻址

堆栈寻址依靠**栈指针 SP/ESP/RSP**隐含定位操作数。

常见指令：

```asm
PUSH
POP
CALL
RET
```

<InlineSvg src="/images/computer-organization/computer-organization-instruction-format-015.svg" alt={"caller BP BP SP caller BP BP SP PUSH A A caller BP BP SP PUSH B A B caller BP BP SP POP A High Address Low Address"} />

典型用途：

* 保存寄存器；
* 传递参数；
* 保存返回地址；
* 建立函数栈帧。

## 16. 寻址方式总表

| 寻址方式  | 有效地址/操作数          | 典型场景              |
| ----- | ----------------- | ----------------- |
| 立即寻址  | 操作数就在指令中          | 常量                |
| 寄存器寻址 | 操作数在寄存器中          | 快速计算              |
| 直接寻址  | `EA=A`            | 固定内存地址            |
| 寄存器间接 | `EA=(R)`          | 指针                |
| 基址寻址  | `EA=(Rb)+A`       | 栈帧、结构体            |
| 变址寻址  | `EA=A+(Rx)`       | 数组                |
| 基址变址  | Base + Index + 位移 | 数组、复杂数据结构         |
| 相对寻址  | `EA=PC+offset`    | 分支、跳转             |
| 堆栈寻址  | 由 SP 隐含指定         | PUSH、POP、CALL、RET |

> **408 做题关键**
>
> 不要只背名称。看到一道寻址题，先写出 **EA 的表达式**，再计算有效地址，最后才去主存取得操作数。
