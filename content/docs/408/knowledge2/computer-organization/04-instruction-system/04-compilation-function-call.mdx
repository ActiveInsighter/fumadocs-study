## 38. 从高级语言到机器代码

<InlineSvg src="/images/computer-organization/computer-organization-instruction-high-low-language-001.svg" alt={"预处理器 编译器 汇编器 链接器 源代码 扩展代码 汇编代码 目标文件 可执行程序"} />

> **真题考查**
>
> * 选择题：2022 年第 20 题

传统 C 程序从源文件到可执行文件可概括为：

```text
源代码
  ↓ 预处理
预处理后的源代码
  ↓ 编译
汇编代码
  ↓ 汇编
目标文件
  ↓ 链接
可执行文件
```

### 38.1 预处理

主要进行文本级处理，例如：

* 展开 `#include`；
* 宏替换 `#define`；
* 条件编译；
* 处理预处理指令。

输出仍是高级语言形式的源文本。

### 38.2 编译

在“预处理—编译—汇编—链接”的四阶段语境中，编译阶段主要把高级语言翻译为汇编代码，内部可经历：

* 词法分析；
* 语法分析；
* 语义分析；
* 中间代码生成；
* 优化；
* 目标代码生成。

<Callout type="warning" title="广义“编译”与狭义“编译”">
日常语境中“编译程序”可能泛指从源码构建出可执行文件的全过程；但考试若明确按四阶段划分，则“编译”通常特指**高级语言 → 汇编语言**这一步。
</Callout>

### 38.3 汇编

汇编器（Assembler）把汇编指令翻译为机器码，并生成目标文件。目标文件中可能仍存在尚未确定最终地址的符号引用和重定位信息。

### 38.4 链接

<InlineSvg src="/images/computer-organization/computer-organization-instruction-high-low-language-002.svg" alt={"源文件 源文件 源文件 源文件 目标文件 目标文件 目标文件 目标文件 链接器 运行库 可执行程序"} />

链接器主要完成：

1. **符号解析**：把函数、全局变量的引用与定义对应起来；
2. **重定位**：确定符号最终地址并修正相关地址字段；
3. **段合并**：把多个目标文件和库中的代码段、数据段组织成最终映像。

### 38.5 静态链接与动态链接

<InlineSvg src="/images/computer-organization/computer-organization-instruction-high-low-language-003.svg" alt={"链接方式对比 静态链接 编译时： 源代码 main.c 静态库 lib.a 可执行文件 app.exe 主程序代码 库代码副本 运行时： 独立运行 完全独立的 二进制文件 动态链接 编译时： 源代码 main.c 动态库引用 lib.so/.dll 可执行文件 app.exe 主程序代码 库引用 动态库文件 lib.so / lib.dll 运行时： 可执行文件 运行中 动态库 运行时加载 动态加载"} />

**静态链接**：把所需库代码在链接阶段合入最终可执行文件。

典型特点：

* 可执行文件通常更大；
* 库代码成为可执行文件的一部分；
* 对外部共享库的运行时依赖较少。

**动态链接**：可执行文件保留对共享库的引用，库代码在装入或运行过程中参与解析和绑定。

常见共享库形式：

* `.so`；
* `.dll`。

<Callout type="warning" title="链接 ≠ 装入">
链接解决多个目标模块之间的符号与地址组织；装入是操作系统把程序映像放入进程地址空间并准备执行。两者处于不同阶段。
</Callout>

## 39. if/else 与汇编控制流

<InlineSvg src="/images/computer-organization/computer-organization-instruction-high-low-language-004.svg" alt={"selection_structure"} />

> **真题考查**
>
> * 解答题：2010 年第 44 题、2014 年第 44 题、2019 年第 45 题、2024 年第 44 题

C：

```c
if (a > b) {
    max = a;
} else {
    max = b;
}
```

一种典型汇编结构：

```asm
cmp eax, ebx
jle else_label

mov max, eax
jmp endif_label

else_label:
mov max, ebx

endif_label:
```

可抽象为：

```text
比较
 ↓
条件跳转
 ├─ 一条路径：then
 └─ 另一条路径：else
 ↓
合流
```

做反汇编恢复高级语言题时，优先找：

1. `CMP/TEST`；
2. 条件跳转；
3. 无条件跳转；
4. 标签与合流点。

## 40. while 循环与汇编

<InlineSvg src="/images/computer-organization/computer-organization-instruction-high-low-language-005.svg" alt={"while_loop"} />

C：

```c
while (count < 10) {
    count++;
}
```

典型结构：

```asm
start:
cmp ecx, 10
jge end

inc ecx
jmp start

end:
```

控制流特征：

> **先判断，再执行循环体。**

因此循环体可能一次都不执行。

## 41. do-while 循环与汇编

<InlineSvg src="/images/computer-organization/computer-organization-instruction-high-low-language-006.svg" alt={"do_while_loop"} />

C：

```c
do {
    count++;
} while (count < 10);
```

典型结构：

```asm
start:
inc ecx
cmp ecx, 10
jl start
```

特征：

> **先执行循环体，再判断是否继续。**

因此循环体至少执行一次。

## 42. for 循环与汇编

<InlineSvg src="/images/computer-organization/computer-organization-instruction-high-low-language-007.svg" alt={"for_loop"} />

C：

```c
for (int i = 0; i < 10; i++) {
    sum += i;
}
```

典型结构：

```asm
mov ecx, 0
mov eax, 0

loop_start:
cmp ecx, 10
jge loop_end

add eax, ecx
inc ecx
jmp loop_start

loop_end:
```

对应关系：

```text
初始化
  ↓
条件判断 ←────────┐
  ↓               │
循环体            │
  ↓               │
更新表达式 ───────┘
```

<Callout type="info" title="编译器不保证保留源代码外形">
开启优化后，编译器可能展开循环、消除变量、改写分支，甚至把循环转换成不同但等价的控制流。因此考试中的“汇编对应 C”题应以给定代码和控制流为准。
</Callout>

## 43. 函数调用、caller 与 callee

<InlineSvg src="/images/computer-organization/computer-organization-instruction-high-low-language-008.svg" alt={"x86 cdecl 调用约定栈帧示意图"} />

函数调用综合题会把：

* 堆栈寻址；
* 基址寻址；
* `CALL/RET`；
* PC、SP、BP；
* 高级语言参数和局部变量

连接起来。

下面使用经典 **32 位 x86 cdecl** 模型说明原理。

> 实际参数传递和寄存器保存规则由 ISA、操作系统 ABI、调用约定和编译器优化共同决定。考试应优先服从题设。

例如：

```c
void func(void) {
    add(1, 2);
}
```

则：

* `func`：caller（调用者）；
* `add`：callee（被调用者）。

### 43.1 经典调用流程

1. caller 准备参数；
2. 执行 `CALL`；
3. `CALL` 保存返回地址并转入 callee；
4. callee 保存需要保留的旧状态；
5. 建立栈帧；
6. 为局部变量分配空间；
7. 执行函数体；
8. 按约定放置返回值；
9. 恢复栈帧和寄存器；
10. `RET` 取回返回地址；
11. caller 按调用约定清理参数或继续执行。

## 44. 经典 32 位 x86 栈帧

C：

```c
int add(int x, int y) {
    return x + y;
}
```

一种未优化的经典实现：

```asm
.globl _add
_add:
    push ebp
    mov  ebp, esp

    mov  eax, [ebp+8]
    add  eax, [ebp+12]

    mov  esp, ebp
    pop  ebp
    ret
```

建立栈帧后，可抽象为：

```text
高地址
+-------------------------+
| 第二个参数   [ebp+12]   |
+-------------------------+
| 第一个参数   [ebp+8]    |
+-------------------------+
| 返回地址     [ebp+4]    |
+-------------------------+
| 旧 EBP       [ebp]      | ← EBP
+-------------------------+
| 局部变量     [ebp-4]    |
+-------------------------+
低地址
```

因此：

```asm
mov eax, [ebp+8]
```

读取第一个参数；

```asm
add eax, [ebp+12]
```

加上第二个参数。

经典约定中返回整数值常放在：

```text
EAX
```

## 45. 函数调用示例：参数、返回值与局部变量

C：

```c
void func(void) {
    int sum = add(3, 5);
    int var = sum * 2;
}
```

经典 cdecl 风格示例：

```asm
.globl _func
_func:
    push ebp
    mov  ebp, esp

    sub  esp, 8

    push 5
    push 3
    call _add
    add  esp, 8

    mov  [ebp-4], eax

    mov  eax, [ebp-4]
    shl  eax, 1
    mov  [ebp-8], eax

    mov  esp, ebp
    pop  ebp
    ret
```

分析：

* `push 5`、`push 3`：按该调用约定把参数压栈；
* `call _add`：保存返回地址并转入 `add`；
* `add esp, 8`：caller 清理两个 4 Byte 参数；
* 返回值从 `EAX` 取得；
* `[ebp-4]`、`[ebp-8]` 访问局部变量。

### 45.1 为什么正偏移常是参数，负偏移常是局部变量？

经典栈向低地址增长，而 `EBP` 固定在当前栈帧的基准位置：

* 调用前已经压入的参数、返回地址位于较高地址 → 正偏移；
* 函数进入后向低地址分配的局部变量 → 负偏移。

这正是基址寻址：

$$
EA=EBP+offset
$$

## 46. CALL、RET 与栈帧的完整数据流

把函数调用题画成下面的时间线最稳：

```text
caller
  │
  ├─ 准备参数
  ├─ CALL
  │   ├─ 保存返回地址
  │   └─ PC ← callee
  │
callee
  ├─ 保存旧 EBP / 必要寄存器
  ├─ 建立当前栈帧
  ├─ 分配局部变量
  ├─ 执行函数体
  ├─ 返回值放到约定位置
  ├─ 恢复栈帧
  └─ RET
      └─ 返回地址 → PC
```

<Callout type="warning" title="栈帧不是函数调用的 ISA 必然形式">
`CALL/RET` 是控制转移语义；“必须使用 EBP 建立固定栈帧”是经典实现方式。优化编译器可能省略帧指针，现代 ABI 也可能优先用寄存器传参。
</Callout>

## 47. 本章高频易错点

### 47.1 地址字段不一定是内存地址

它可能是：寄存器号、立即数、位移量或地址信息。

### 47.2 寻址方式针对“某个操作数”

```asm
MOV AX, 10
```

同时包含：

* `AX`：寄存器寻址；
* `10`：立即寻址。

### 47.3 立即数与直接寻址

```asm
MOV R1, 1000
```

通常把数值 `1000` 作为操作数；

```asm
MOV R1, [1000]
```

则把 `1000` 当作内存地址。

### 47.4 寄存器寻址与寄存器间接寻址

```asm
MOV R1, R2
```

`R2` 保存数据本身；

```asm
MOV R1, [R2]
```

`R2` 保存数据地址。

### 47.5 PC 相对寻址的基准必须看题设

若取指后 PC 已指向下一条指令：

$$
Target=PC_{next}+offset
$$

### 47.6 小端不是“整个数倒序”

`0x12345678` 的小端字节排列是：

```text
78 56 34 12
```

只改变**字节之间**的顺序。

### 47.7 signed 与 unsigned 跳转不能混用

* signed：重点看 `SF/OF/ZF`；
* unsigned：重点看 `CF/ZF`。

### 47.8 CALL 不只是 JMP

`CALL` 还必须建立返回路径，例如保存返回地址。

### 47.9 对齐与大小端是两个问题

* 对齐：对象**从什么地址开始**；
* 大小端：对象内部字节**怎样排列**。

## 49. 最后记忆

* **ISA**：规定软件看见什么、机器指令做什么；微架构决定内部怎样实现。
* **指令格式**：操作码回答“做什么”，操作数字段回答“对谁做/怎么找”。
* **扩展操作码**：上层未使用前缀才能继续向下扩展。
* **寻址题**：先写 $EA$，再取操作数，再数访存。
* **相对寻址**：常见 $Target=PC_{next}+offset$，但必须服从题设。
* **小端**：低位字节放低地址；**大端**：高位字节放低地址。
* **CMP**：产生标志，不保存减法结果。
* **signed/unsigned**：同一位模式采用不同条件跳转解释。
* **CALL/RET**：一个建立返回路径，一个恢复返回控制流。
* **经典栈帧**：参数常在正偏移，局部变量常在负偏移；这只是常见 ABI 模型，不是所有机器的绝对规则。
