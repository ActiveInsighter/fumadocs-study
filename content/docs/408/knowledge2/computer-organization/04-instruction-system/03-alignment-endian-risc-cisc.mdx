这一节把三类经常混在综合题里的概念分开：

- **对齐**：对象从什么地址开始；
- **大小端**：对象内部多个字节按什么顺序存；
- **RISC/CISC**：指令集设计风格。

## 4.3.1 数据对齐的本质

若对象要求按 $K$ Byte 对齐，则其起始地址通常满足：

$$
Address\bmod K=0
$$

对齐可以降低跨越自然访问边界的概率，从而减少：

- 多次存储访问；
- 数据拼接；
- 额外硬件开销。

某些 ISA 对未对齐访问支持较弱，甚至可能触发对齐异常。

> **考试原则**
>
> 不要把某一种平台 ABI 当成 C 语言绝对规则。题目若给出数据长度或对齐规则，优先按题设。

## 4.3.2 常见自然对齐模型

典型教学模型可参考：

| 类型 | 常见大小 | 常见对齐 |
| --- | ---: | ---: |
| `char` | 1 B | 1 B |
| `short` | 2 B | 2 B |
| `int` / `float` | 4 B | 4 B |
| `long long` / `double` | 8 B | 8 B |
| 64 位指针 | 8 B | 常见 8 B |

结构体题务必按题设环境判断。

## 4.3.3 结构体 Padding 的计算

结构体布局常按如下步骤：

1. 当前偏移量从 0 开始；
2. 每个成员的起始偏移必须满足自身对齐要求；
3. 若当前偏移不满足，则插入 Padding；
4. 放入成员并增加其大小；
5. 结构体总大小通常再补到**最大成员对齐值**的整数倍。

若当前偏移为 $x$，成员要求按 $a$ 对齐，可将新偏移求为：

$$
\left\lceil\frac{x}{a}\right\rceil a
$$

> **高频易错点**
>
> 结构体大小不是成员大小简单求和；既可能有成员间 Padding，也可能有尾部 Padding。

## 4.3.4 大端与小端

假设 32 位数据：

```text
0x12345678
```

四个字节从高到低为：

```text
12 34 56 78
```

### 大端 Big-Endian

> **高位字节放低地址。**

```text
地址      内容
0x1000    12
0x1001    34
0x1002    56
0x1003    78
```

### 小端 Little-Endian

> **低位字节放低地址。**

```text
地址      内容
0x1000    78
0x1001    56
0x1002    34
0x1003    12
```

## 4.3.5 大小端只改变“字节之间”的顺序

大小端**不讨论一个字节内部 bit 的排列方式**。

所以小端的 `0x12345678` 不是把每个字节的 bit 反过来，而只是四个字节在地址中的次序为：

```text
78 56 34 12
```

x86/x86-64 通常使用小端；网络协议中的“网络字节序”通常指大端序。

## 4.3.6 综合题：地址、对齐与端序怎么串

假设：

- 一个结构体数组起始地址为 $B$；
- 每个结构体最终大小为 $S$；
- 第 $i$ 个元素的某成员偏移为 $d$。

则成员地址为：

$$
Address=B+iS+d
$$

如果该成员又是一个多字节整数，还需按端序判断其中某个字节究竟位于：

$$
Address+k
$$

的哪一个 $k$ 上。

这就是 408 常见的“结构体布局 + 数组 + 小端”组合题。

## 4.3.7 CISC 的典型思想

CISC（Complex Instruction Set Computer）经典特征：

- 指令数量较多；
- 指令功能复杂；
- 寻址方式丰富；
- 指令长度常较灵活；
- 某些指令可以直接对内存操作数进行较复杂运算；
- 经典教材常将其与微程序控制联系起来。

典型代表：x86 / x86-64。

## 4.3.8 RISC 的典型思想

RISC（Reduced Instruction Set Computer）经典特征：

- 指令形式更精简、规则；
- 寻址方式相对较少；
- 大量运算在寄存器间完成；
- 常强调 Load/Store：访存由专门装入/存储指令完成；
- 通常更利于规则流水线；
- 经典教材常将其与硬布线控制联系起来。

典型代表：MIPS、RISC-V、ARM 的很多设计。

## 4.3.9 CISC 与 RISC 对照

| 维度 | CISC 典型特征 | RISC 典型特征 |
| --- | --- | --- |
| 指令数量 | 较多 | 相对精简 |
| 单条指令功能 | 较复杂 | 较简单 |
| 编码形式 | 常更灵活 | 常更规整 |
| 寻址方式 | 较丰富 | 较少 |
| 内存操作 | 可有复杂 memory operand | 常用 Load/Store |
| 译码 | 相对复杂 | 相对规则 |
| 流水实现 | 约束更多 | 通常更直接 |

> **不要用“单条指令少 = 一定更快”判断性能。**
>
> 程序性能取决于指令条数、CPI、时钟周期以及实现质量。应回到：
>
> $$
> T_{CPU}=IC\times CPI\times T_{clock}
> $$

## 4.3.10 两组最容易混淆的概念

### 对齐 vs 大小端

- 对齐：对象**从哪里开始**；
- 大小端：对象内部字节**怎样排列**。

### ISA 风格 vs 微架构实现

- RISC/CISC 是 ISA 设计思想；
- 是否采用某种具体流水线、Cache、乱序执行等属于微架构实现。

因此不要把“RISC/CISC”直接等同于某种唯一硬件结构。
