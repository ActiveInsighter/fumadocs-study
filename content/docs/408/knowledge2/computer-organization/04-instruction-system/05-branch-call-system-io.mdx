控制转移类指令的共同点是：

> **它们可能改变 PC，从而改变下一条执行指令。**

本节重点把“比较标志”和“跳转条件”配对，并把 `CALL/RET` 与普通 `JMP` 区分开。

> **真题标签｜控制转移与异常类指令**
>
> 原资料索引：2014 第 25 题，2019 第 45 题，2020 第 18 题，2026 第 17、21 题，以及多道汇编综合题。

## 4.5.1 无条件跳转 JMP

```asm
jmp label
```

若采用 PC 相对编码：

$$
offset=Target-PC_{next}
$$

执行效果是：

$$
PC\leftarrow Target
$$

标签只存在于汇编语言层面；机器码中保存的是目标地址、偏移量或间接地址信息。

## 4.5.2 JE/JNE：只看 ZF

常见对应：

| 指令 | 条件 |
| --- | --- |
| `JE/JZ` | $ZF=1$ |
| `JNE/JNZ` | $ZF=0$ |

例如：

```asm
cmp eax, ebx
je equal
```

如果 $EAX-EBX=0$，则 ZF=1，于是跳转。

## 4.5.3 有符号比较为什么要看 SF 和 OF

有符号比较常见条件：

| 指令 | 含义 | 条件 |
| --- | --- | --- |
| `JG` | 大于 | `ZF=0` 且 `SF=OF` |
| `JL` | 小于 | `SF≠OF` |
| `JGE` | 大于等于 | `SF=OF` |
| `JLE` | 小于等于 | `ZF=1` 或 `SF≠OF` |

原因是发生有符号溢出时，单看减法结果的符号位可能误判，需要结合 OF 修正。

## 4.5.4 无符号比较为什么看 CF

无符号比较常见条件：

| 指令 | 含义 | 条件 |
| --- | --- | --- |
| `JA` | 大于 | `CF=0` 且 `ZF=0` |
| `JAE` | 大于等于 | `CF=0` |
| `JB` | 小于 | `CF=1` |
| `JBE` | 小于等于 | `CF=1` 或 `ZF=1` |

同一组 bit 既可以解释成 signed，也可以解释成 unsigned，所以：

> **CMP 本身并不知道“数据有无符号”；后续选择哪一种条件跳转，才体现比较语义。**

## 4.5.5 CALL 与 JMP 的根本区别

两者都会改变 PC，但 `CALL` 还必须保存返回位置。

典型语义：

```text
CALL target:
    保存 PC_next
    PC ← target
```

而 `JMP target` 只负责转移，不建立返回链。

## 4.5.6 RET 如何回来

在经典栈式调用模型中：

1. `CALL` 把返回地址压栈；
2. 被调函数执行；
3. `RET` 从栈中取出返回地址；
4. 返回地址送入 PC。

抽象为：

$$
PC\leftarrow M[SP]
$$

随后 SP 按返回地址长度恢复。

> **高频易错点**
>
> 返回地址通常是**CALL 后面那条指令的地址**，不是 CALL 自己的首地址。

## 4.5.7 陷阱/系统调用类指令

传统 x86 可见：

```asm
int n
```

程序显式执行后，CPU 进入异常/中断处理机制，典型过程：

```text
用户程序
  ↓ 执行陷阱/系统调用指令
保存必要状态
  ↓
转到处理入口
  ↓
执行内核服务
  ↓
恢复现场并返回
```

应区分：

- **显式陷阱**：程序主动执行某条指令；
- **执行异常**：如除 0、非法访问，在普通指令执行过程中由 CPU 检测。

二者都与当前指令执行同步，但触发原因不同。

## 4.5.8 Trap 指令与 Trap Flag 不是一回事

x86 的 TF（Trap Flag）用于单步调试控制。

因此：

- `INT` 等：一条显式软件异常/中断类指令；
- `TF`：状态标志，影响调试异常行为。

## 4.5.9 CLI 与 STI

```asm
cli
sti
```

经典 x86 中：

- `CLI`：清 IF；
- `STI`：置 IF。

IF 主要控制**可屏蔽外部中断**，不能简单说“关闭所有中断”。不可屏蔽中断 NMI 不由 IF 直接控制。

这类指令涉及系统控制，通常属于特权相关操作。

## 4.5.10 IN / OUT 与 I/O 编址

若采用**独立 I/O 编址**，CPU 可通过专门端口指令：

```asm
in  al, port
out port, al
```

若采用**统一编址 / 内存映射 I/O**，设备寄存器占用普通地址空间，可使用常规 Load/Store 或 MOV 类访存指令。

因此：

> **有没有独立 IN/OUT 指令，与 I/O 端口采用哪种编址方式密切相关。**

## 4.5.11 程序查询、中断、DMA 的层次

这部分将在 I/O 章节详细展开，此处只建立联系：

- 程序查询：CPU 主动轮询设备；
- 程序中断：设备就绪后通知 CPU；
- DMA：批量数据传输主要由 DMA 控制器接管。

不要把“`IN/OUT` 指令”与“程序查询”画等号。端口指令只是访问设备寄存器的一种手段，传送控制方式是另一维度。

## 4.5.12 字符串类指令

x86 经典字符串指令包括：

- `MOVS`：搬运；
- `LODS`：从源串加载；
- `STOS`：写入目的串；
- `CMPS`：比较。

408 优先级较低，掌握基本功能和“隐含源/目的地址寄存器”的特点即可。

## 4.5.13 控制流题固定检查表

看到一段汇编，按下面顺序：

1. 找 `CMP/TEST` 等设置标志的指令；
2. 看后续是 signed 还是 unsigned 跳转；
3. 标出所有标签和跳转边；
4. 区分条件转移与无条件转移；
5. 遇到 `CALL`，同时记录返回地址；
6. 遇到 `RET`，回到对应调用点；
7. 最后再恢复成 `if/while/for/函数调用`。
