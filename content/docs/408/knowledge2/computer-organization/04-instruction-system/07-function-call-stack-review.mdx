函数调用把本章几乎所有知识串起来：

- 基址/堆栈/相对寻址；
- `PUSH/POP/CALL/RET`；
- PC、SP、BP；
- 参数、局部变量和返回值；
- 编译器与 ABI。

## 4.7.1 caller 与 callee

若：

```c
int z = add(x, y);
```

则当前函数是 caller，被调用的 `add` 是 callee。

一次调用至少要解决：

1. 参数怎么传；
2. 返回地址放哪里；
3. callee 的局部变量放哪里；
4. 哪些寄存器要保存；
5. 返回值放哪里；
6. 谁负责恢复栈和寄存器。

这些规则由**调用约定 ABI** 决定。

## 4.7.2 经典 32 位 x86 cdecl 模型

408 常用经典模型理解过程调用。一个典型序列：

```text
caller 准备参数
  ↓
CALL
  ├─ 保存返回地址
  └─ PC ← callee
  ↓
callee 保存旧 EBP
  ↓
建立新栈帧
  ↓
分配局部变量
  ↓
执行函数体
  ↓
返回值放约定位置
  ↓
恢复栈帧
  ↓
RET
  ↓
caller 继续执行
```

> **边界说明**
>
> 这是经典教学模型，不代表所有现代 ABI 都按“参数全压栈 + EBP 固定帧指针”的方式实现。题目若给出具体汇编，以题设为准。

## 4.7.3 建立栈帧

典型函数序言：

```asm
push ebp
mov  ebp, esp
sub  esp, n
```

含义：

1. 保存 caller 的 EBP；
2. 让 EBP 固定指向当前栈帧基准；
3. ESP 向低地址移动，为局部变量留空间。

此后局部变量常通过：

$$
EA=EBP-d
$$

访问，而参数常通过：

$$
EA=EBP+d
$$

访问。

## 4.7.4 经典栈帧布局

```text
高地址
+-------------------------+
| 参数2          [EBP+12] |
+-------------------------+
| 参数1          [EBP+8]  |
+-------------------------+
| 返回地址        [EBP+4]  |
+-------------------------+
| 旧 EBP          [EBP]    | ← EBP
+-------------------------+
| 局部变量1       [EBP-4]  |
+-------------------------+
| 局部变量2       [EBP-8]  |
+-------------------------+
低地址
```

这正是基址寻址：

$$
EA=EBP+offset
$$

## 4.7.5 一个完整 add 函数

C：

```c
int add(int x, int y) {
    return x + y;
}
```

经典示例：

```asm
add:
    push ebp
    mov  ebp, esp

    mov  eax, [ebp+8]
    add  eax, [ebp+12]

    mov  esp, ebp
    pop  ebp
    ret
```

逐句：

- `[ebp+8]`：第一个参数；
- `[ebp+12]`：第二个参数；
- `EAX`：经典约定中用于返回整数结果；
- `mov esp,ebp; pop ebp`：拆除当前栈帧；
- `ret`：取回返回地址并恢复 PC。

## 4.7.6 caller 传参和清栈

经典 cdecl 示例：

```asm
push 5
push 3
call add
add  esp, 8
```

如果按从右向左压参数，那么 `3` 在最后压入，所以进入 callee 后位于离返回地址更近的位置。

`add esp,8` 表示 caller 回收两个 4 Byte 参数的栈空间。

> **不要把“caller 清栈”当成所有调用约定的绝对规则。**
>
> 不同 ABI 可由 caller 或 callee 清理，寄存器传参也非常常见。

## 4.7.7 CALL 的相对位移综合题

若 CALL 地址为 $A$，指令长度为 $L$，目标地址为 $T$，采用相对寻址，则：

$$
PC_{next}=A+L
$$

$$
offset=T-(A+L)
$$

若机器码中的多字节位移字段又采用小端存储，还要把数值按字节拆开，再按**低位字节放低地址**解释。

这就是典型的：

> **相对寻址 + 指令长度 + 补码位移 + 小端**

综合题。

## 4.7.8 递归调用为什么依赖栈

递归时，每次调用都需要一份独立的：

- 返回地址；
- 参数；
- 局部变量；
- 必要保存的寄存器状态。

栈的 LIFO 特性正好与“最后调用的函数最先返回”一致。

## 4.7.9 编译器可能省略栈帧

优化后函数可能：

- 参数主要通过寄存器传递；
- 局部变量完全驻留寄存器；
- 不使用固定 EBP/RBP 帧指针；
- 成为叶子函数，不再调用其他函数；
- 甚至被内联，不发生真正 CALL。

因此做题要以机器代码的实际行为为准，不要看到函数就强行套 `[ebp+8]`。

## 4.7.10 本章十大易错点

1. **ISA ≠ 微架构**：Cache、流水线级数、控制器实现通常不是 ISA 必然规定项。
2. **地址字段 ≠ 一定是主存地址**：也可能是立即数、寄存器号或位移。
3. **寻址方式针对操作数**：同一条指令的两个操作数可采用不同寻址方式。
4. **立即数 vs 直接寻址**：`1000` 是数值，`[1000]` 是地址语义。
5. **寄存器 vs 寄存器间接**：`R2` 是数据，`[R2]` 把 R2 当地址。
6. **PC 相对要看 PC 基准**：常用 $PC_{next}$，但最终服从题设。
7. **小端不是 bit 反序**：只改变多字节对象中字节的地址顺序。
8. **signed / unsigned 分支不同**：signed 看 SF/OF，unsigned 重点看 CF。
9. **CALL ≠ JMP**：CALL 还要建立返回路径。
10. **对齐 ≠ 端序**：一个管起始地址，一个管字节排列。

## 4.7.12 最后记忆

> **操作码告诉 CPU“做什么”，寻址方式告诉 CPU“数据在哪里”。**

> **寻址题：先求 EA，再取操作数。**

> **相对寻址：$Target=PC_{next}+offset$。**

> **小端：低位字节放低地址；大端：高位字节放低地址。**

> **CMP 只改标志，不保存差；CALL 保存返回地址并跳转；RET 取回返回地址。**
