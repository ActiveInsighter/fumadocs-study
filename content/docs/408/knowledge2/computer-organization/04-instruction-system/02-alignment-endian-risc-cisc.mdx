## 17. 数据对齐

<InlineSvg src="/images/computer-organization/computer-organization-instruction-alignment-001.svg" alt={"0x00: 0x04: 0x08: 0x0C: 0x10: 0x00: 0x04: 0x08: 0x0C: 0x10: 对齐的数据布局 char padding int (4字节) short pad double (8字节) 未对齐的数据布局 char int short double CPU 访问 int 1次内存访问 CPU 访问 int 2次内存访问 对齐优势 ✓ 单次访问获取完整数据 ✓ 硬件优化，访问速度快 未对齐问题 ✗ 需要多次内存访问 ✗ 某些架构会触发异常"} />

> **真题考查**
>
> * 选择题：2012 年第 15 题、2020 年第 14 题、2025 年第 15 题

**数据对齐**（Data Alignment）要求数据对象的起始地址满足特定倍数关系。

若某对象要求按 $K$ Byte 对齐，通常需要：

$$
Address\bmod K=0
$$

对齐的主要意义是让处理器更容易在一次或更少次数的自然访存中取得数据。若一个对象跨越总线宽度、字边界或 Cache 块等边界，可能导致：

* 多次内存访问；
* 额外的数据拼接；
* 性能下降；
* 某些 ISA 上触发未对齐访问异常。

### 17.1 常见类型的典型对齐

408 题目若未另行说明，可按题设或常见 ABI 规则理解：

| 数据类型 | 常见大小 | 常见对齐 |
| --- | ---: | ---: |
| `char` | 1 Byte | 1 Byte |
| `short` | 2 Byte | 2 Byte |
| `int` | 4 Byte | 4 Byte |
| `float` | 4 Byte | 4 Byte |
| `double` | 8 Byte | 常见 8 Byte |
| `long long` | 8 Byte | 常见 8 Byte |
| 64 位指针 | 8 Byte | 常见 8 Byte |

实际结果由 ISA、ABI 和编译器共同决定，考试必须**优先服从题设**。

C11 可用 `_Alignof` 查询当前实现的对齐要求：

```c
#include <stdint.h>
#include <stdio.h>

#define EVAL_PRINT(expr) printf("%-20s = %u\n", #expr, (unsigned)(expr));

int main(void) {
    EVAL_PRINT(_Alignof(char));
    EVAL_PRINT(_Alignof(uint8_t));
    EVAL_PRINT(_Alignof(uint16_t));
    EVAL_PRINT(_Alignof(uint32_t));
    EVAL_PRINT(_Alignof(int));
    EVAL_PRINT(_Alignof(uint64_t));
    EVAL_PRINT(_Alignof(void *));
    EVAL_PRINT(_Alignof(size_t));
    return 0;
}
```

### 17.2 结构体 Padding

<InlineSvg src="/images/computer-organization/computer-organization-instruction-alignment-002.svg" alt={"图示"} />

为使每个成员满足自己的对齐要求，编译器可能插入**填充字节**（Padding）。

典型计算步骤：

1. 从偏移 0 开始；
2. 每个成员找到第一个满足自身对齐要求的偏移；
3. 中间空出的字节就是成员间 Padding；
4. 结构体总大小通常还要补齐到**结构体对齐要求**的整数倍，因此尾部也可能有 Padding。

例如若：

```c
struct S {
    char  c;   // 1 Byte
    int   x;   // 4 Byte 对齐
    short y;   // 2 Byte 对齐
};
```

在典型规则下：

```text
偏移 0      c
偏移 1~3    Padding
偏移 4~7    x
偏移 8~9    y
偏移 10~11  尾部 Padding
```

于是结构体总大小为 12 Byte，而不是成员大小简单相加得到的 7 Byte。

<Callout type="warning" title="结构体题四件事都要看">
成员大小、成员起始偏移、成员间 Padding、结构体尾部 Padding 都可能单独设问。
</Callout>

### 17.3 对齐计算的通用公式

若当前可用偏移为 $p$，下一个成员要求按 $K$ Byte 对齐，则需要插入的填充字节数为：

$$
Padding=(K-(p\bmod K))\bmod K
$$

于是该成员的起始偏移为：

$$
p'=p+Padding
$$

在常见 ABI 中，结构体自身的对齐要求通常等于其成员中最大的对齐要求 $A_{max}$，最后总大小再向 $A_{max}$ 的整数倍上取整：

$$
Size_{struct}=\left\lceil\frac{p_{end}}{A_{max}}\right\rceil A_{max}
$$

但这些是典型规则，若题目给出特殊打包规则、`#pragma pack` 或指定 ABI，应以题设为准。

## 18. 大端与小端

> **真题考查**
>
> * 选择题：2016 年第 14 题、2018 年第 15 题、2019 年第 15 题、2020 年第 14 题、2025 年第 15 题
> * 解答题：2023 年第 44 题、2024 年第 44 题

**字节序**（Endianness）描述：

> **一个多字节数据的各个字节，按什么顺序放入连续内存地址。**

假设 32 位数：

```text
0x12345678
```

分为：

```text
0x12  0x34  0x56  0x78
高位字节              低位字节
```

### 18.1 大端序

<InlineSvg src="/images/computer-organization/computer-organization-instruction-alignment-003.svg" alt={"32位整数: 0x12345678 字节分解: 0x12 0x34 0x56 0x78 高位字节 低位字节 内存存储: 0x1000: 0x1001: 0x1002: 0x1003: 0x12 0x34 0x56 0x78 ← 低地址 ← 高地址 大端序特征 • 高位字节 → 低地址 • 低位字节 → 高地址"} />

**高位字节放低地址。**

```text
低地址        高地址
0x1000  12
0x1001  34
0x1002  56
0x1003  78
```

记忆：

> **大端：高位 → 低地址。**

### 18.2 小端序

<InlineSvg src="/images/computer-organization/computer-organization-instruction-alignment-004.svg" alt={"32位整数: 0x12345678 字节分解: 0x12 0x34 0x56 0x78 高位字节 低位字节 内存存储: 0x1000: 0x1001: 0x1002: 0x1003: 0x78 0x56 0x34 0x12 ← 低地址 ← 高地址 小端序特征 • 低位字节 → 低地址 • 高位字节 → 高地址"} />

**低位字节放低地址。**

```text
低地址        高地址
0x1000  78
0x1001  56
0x1002  34
0x1003  12
```

记忆：

> **小端：低位 → 低地址。**

### 18.3 数组中的字节序

<InlineSvg src="/images/computer-organization/computer-organization-instruction-alignment-005.svg" alt={"0x10 0x32 0x54 ox76 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x76 0x54 0x32 0x10 0x98 0xBA 0xDC 0xFE 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0xFE 0xDC 0xBA 0x98 0x1000 0x1000 0x1008 0x1008 Little Endian Big Endian"} />

字节序只决定**每个多字节元素内部**的字节排列，不会改变数组元素本身的逻辑顺序。

若题设规定：

```c
long a[2] = {
    0x76543210,
    0xFEDCBA98
};
```

并明确 `long` 为 8 Byte，则应先确定：

1. `a[0]` 占哪 8 Byte；
2. `a[1]` 紧随其后；
3. 再分别按大端或小端展开每个元素内部的字节顺序。

<Callout type="warning" title="C 语言 long 的大小不是跨平台固定值">
`long` 的实际大小受 ABI 影响。题目若给出 `long=8 Byte` 就按题设；不能只凭“64 位平台”自行推断。
</Callout>

### 18.4 字节序不改变字节内部 bit 顺序

大小端只讨论：

> **字节之间怎样排列。**

不讨论单个字节内部 `bit7 ... bit0` 的编号方式。

因此：

* 小端不是“把整个二进制串倒过来”；
* 也不是“每个字节中的 bit 倒序”。

x86/x86-64 通常采用小端；网络协议中所说的“网络字节序”通常采用大端。

### 18.5 大小端题的稳定展开法

不要凭感觉“倒序”，而应按以下步骤：

1. 先把数据按 **Byte** 切分；
2. 标出哪个是最高有效字节、哪个是最低有效字节；
3. 再按地址从低到高填写。

以 `0x12345678` 为例：

```text
字节：12 | 34 | 56 | 78
      MSB          LSB
```

* 大端低地址开始：`12 34 56 78`；
* 小端低地址开始：`78 56 34 12`。

若问某一地址中的值，就先判断它相对对象首地址的偏移，再取对应字节。若问某个 `short *`、`int *` 解引用后的数值，还要结合对象宽度和机器字节序重新组合。

## 19. CISC 与 RISC

![csic 和 risc 处理器](/images/computer-organization/computer-organization-instruction-concepts-002.png)
<InlineSvg src="/images/computer-organization/computer-organization-instruction-concepts-003.svg" alt={"图示"} />
<InlineSvg src="/images/computer-organization/computer-organization-instruction-concepts-004.svg" alt={"图示"} />

> **真题考查**
>
> * 选择题：2009 年第 17 题、2025 年第 17 题
> * 解答题：2017 年第 44 题

**CISC**（Complex Instruction Set Computer）与 **RISC**（Reduced Instruction Set Computer）是两种经典指令集设计思想。

### 19.1 CISC 的典型特点

* 指令数量较多；
* 指令功能与寻址方式较丰富；
* 指令长度常可变化；
* 一些指令可直接对内存操作数进行复杂处理；
* 译码通常更复杂；
* 经典教材常把它与微程序控制联系起来。

典型代表：x86、x86-64。

### 19.2 RISC 的典型特点

* 指令功能相对简单；
* 指令格式更规则；
* 寻址方式相对较少；
* 常强调大量寄存器与寄存器间运算；
* 常采用 **Load/Store** 思想：只有加载/存储指令直接访问内存；
* 更容易形成规则流水线；
* 经典教材常把它与硬布线控制联系起来。

典型代表：MIPS、RISC-V，ARM 体系也具有明显 RISC 传统。

### 19.3 Load/Store 是理解 RISC 的关键

以：

```c
a[i] = a[i] + 1;
```

为例，典型 Load/Store 机器会拆成：

```text
计算地址
  ↓
LOAD：内存 → 寄存器
  ↓
ADD：寄存器中运算
  ↓
STORE：寄存器 → 内存
```

而 CISC ISA 可能允许某些指令在单条指令语义中直接组合地址计算与内存操作。

### 19.4 典型对比

| 特征 | CISC | RISC |
| --- | --- | --- |
| 指令数量 | 较多 | 相对精简 |
| 指令功能 | 可较复杂 | 通常较简单 |
| 指令格式 | 常更灵活、可变长 | 通常更规则 |
| 寻址方式 | 较丰富 | 相对较少 |
| 内存操作 | 某些运算指令可直接操作内存 | 常强调 Load/Store |
| 译码 | 较复杂 | 较规则 |
| 教材典型控制方式 | 微程序 | 硬布线 |
| 流水实现 | 规则性相对较弱 | 通常更容易规则化 |

<Callout type="warning" title="这些是典型特征，不是绝对定律">
现代处理器会融合很多设计思想。因此“RISC 所有指令必定等长”“CISC 必定微程序控制”“RISC 一定比 CISC 快”都不能当成无条件结论。408 基础题应掌握教材中的**典型差异**，综合题仍以题设为准。
</Callout>

### 19.5 RISC/CISC 判断题最容易错的三点

1. **“RISC”不是简单等于“指令条数一定更少”**。核心是指令语义、格式和实现更规则、更适合流水化。
2. **一条 CISC 指令完成更多工作，不等于程序一定更快**。性能还取决于时钟周期、CPI、流水线、Cache 等。
3. **Load/Store 是最重要的识别特征之一**。典型 RISC 中算术逻辑指令主要对寄存器操作，访问内存由 Load/Store 完成。

> **复习抓手**：看到“格式规则、少寻址方式、Load/Store、多寄存器、易流水”优先想到 RISC；看到“指令语义复杂、寻址丰富、可变长、内存操作灵活”优先想到 CISC。
