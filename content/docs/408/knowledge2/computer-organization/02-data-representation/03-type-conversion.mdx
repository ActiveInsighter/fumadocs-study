## 37. 有符号整数与无符号整数转换

当相同位宽的 signed 和 unsigned 相互转换时，一个最重要的原则是：

> **位模式不变，只改变解释方式。**

<InlineSvg src="/images/computer-organization/computer-organization-representation-conversion-001.svg" alt={"SignedUnsignedConversion"} />

例如 8 位：

```text
11111111
```

若解释为无符号整数：

$$
255
$$

若解释为补码有符号整数：

$$
-1
$$

二进制位完全没有变化。

---

### 37.1 统一关系

若 $n$ 位位模式的无符号值为 $U$，补码值为 $T$。

当最高位：

$$
b_{n-1}=0
$$

时：

$$
T=U
$$

当最高位：

$$
b_{n-1}=1
$$

时：

$$
T=U-2^n
$$

反过来，负的补码整数转换为无符号解释时：

$$
U=T+2^n
$$

例如 8 位：

$$
-1
$$

对应：

$$
255
$$

因为：

$$
-1+256=255
$$

## 38. 不同位宽整数的转换

### 38.1 无符号数扩展

无符号整数从较短位宽扩展到较长位宽时，高位补 0。

例如：

```text
8 位：
10110101

扩展为 16 位：
00000000 10110101
```

这叫：

> **零扩展（Zero Extension）**

---

### 38.2 补码有符号数扩展

有符号补码扩展时，复制原符号位。

例如：

```text
8 位：
11111011
```

表示：

$$
-5
$$

扩展成 16 位：

```text
11111111 11111011
```

仍表示：

$$
-5
$$

这叫：

> **符号扩展（Sign Extension）**

#### 为什么符号扩展不改变数值

负数补码最高位权值变化了，但新增的多个 1 恰好补偿了权值变化，因此数值保持不变。

---

### 38.3 大位宽转小位宽

从更长整数转换为更短整数，从机器位模式角度通常保留低位：

```text
int:
0x12345678
```

转为 16 位后低位：

```text
0x5678
```

因此可能丢失高位信息。

## 39. 常见整数类型位宽

C 语言标准主要规定各类型的**最小范围与相对关系**，实际位宽取决于 ABI 和平台。

常见实现如下：

| 类型          | 标准至少 | 常见 32 位环境 | 常见 64 位环境 |
| ----------- | ---: | --------: | --------: |
| `char`      |  8 位 |         8 |         8 |
| `short`     | 16 位 |        16 |        16 |
| `int`       | 16 位 |        32 |        32 |
| `long`      | 32 位 |        32 |   32 或 64 |
| `long long` | 64 位 |        64 |        64 |
| `float`     |    — |        32 |        32 |
| `double`    |    — |        64 |        64 |

> **注意**
>
> “64 位计算机”不意味着 `int` 一定是 64 位。
>
> 很多常见 64 位平台中：
>
> ```text
> int = 32 位
> ```

需要固定宽度时，可使用：

```c
int32_t
uint32_t
int64_t
uint64_t
```

## 40. 整数与浮点数转换

<InlineSvg src="/images/computer-organization/computer-organization-representation-conversion-002.svg" alt={"图示"} />

整数与浮点数之间的转换需要区分两个问题：

* **范围是否足够**
* **精度是否足够**

浮点数往往有非常大的范围，但不能精确表示范围内的每一个整数。

---

## 41. 整数转浮点数

以 IEEE 754 单精度为例。

单精度：

* frac 为 23 位
* 加上隐藏位后有 24 位有效二进制精度

因此所有绝对值不超过：

$$
2^{24}
$$

的整数都可以精确表示。

例如：

$$
2^{24}=16777216
$$

可以精确表示。

但：

$$
2^{24}+1
$$

通常不能被单精度精确表示。

> **重要**
>
> 不是说大于 $2^{24}$ 的整数都不能精确表示。
>
> 例如：
>
> $$
> 2^{25}
> $$
>
> 本身仍能精确表示。
>
> 随着数值增大，可表示整数之间的间隔也会增加。

因此整数转 `float`：

* 通常不会因为 32 位 `int` 的数量级导致 `float` 范围溢出。
* 但可能发生**精度损失**。

---

## 42. 浮点数转整数

浮点数转换为整数通常需要处理两件事：

### 42.1 小数部分

整数无法保存小数部分，因此小数部分会被舍去或按照语言规定转换。

C 语言中通常是**向 0 截断**。

例如：

```text
3.9 → 3
-3.9 → -3
```

---

### 42.2 范围

如果浮点数已经超出目标整数类型的表示范围，则无法用该整数类型正常表示。

因此浮点转整数同时可能发生：

* 小数精度丢失
* 越界

---

## 43. float 与 double 转换

`float` 通常使用 IEEE 754 单精度：

```text
32 位
```

`double` 通常使用双精度：

```text
64 位
```

一般情况下：

```text
float → double
```

可以精确保留原 `float` 数值。

而：

```text
double → float
```

可能：

* 损失精度
* 数值过大时发生范围问题

## 44. C 语言中的隐式类型转换

<InlineSvg src="/images/computer-organization/computer-organization-representation-conversion-004.svg" alt={"TypeConversion"} />

当算术、比较或赋值表达式出现不同类型时，编译器可能自动完成转换。

例如：

```c
int i = 5;
float f = 2.5f;

float result = i + f;
```

计算 `i + f` 时，`i` 会转换到与 `f` 兼容的浮点类型后再进行运算。

> **易错点**
>
> C 的类型转换并不是简单的：
>
> “精度低的一律转换为精度高的。”
>
> 实际遵循整数提升和 usual arithmetic conversions 等语言规则。

---

## 45. signed 与 unsigned 混合运算

这是 408 中非常值得警惕的问题。

例如假设 32 位：

```c
int x = -1;
unsigned int y = 1;
```

比较：

```c
x < y
```

如果 `x` 被转换为 32 位 unsigned，其位模式仍然是：

```text
11111111 11111111 11111111 11111111
```

解释成无符号数后：

$$
2^{32}-1
$$

因此比较的实际上可能变成：

$$
4294967295<1
$$

结果为假。

所以：

> **signed 与 unsigned 混合时，不要凭数学直觉直接判断。先确定类型转换，再解释位模式。**

---

## 46. 显式类型转换

程序员也可以主动指定目标类型：

```c
int i = 5;
float f = 3.2f;

int result = (int)f + i;
```

其中：

```c
(int)f
```

得到：

```text
3
```

所以：

```text
result = 8
```

显式类型转换并不意味着安全，仍可能出现：

* 高位截断
* 精度损失
* 数值越界
* signed/unsigned 解释发生变化

---

## 47. 类型转换总表

| 转换                      | 位模式/数值特点 | 主要风险     |
| ----------------------- | -------- | -------- |
| 同位宽 signed → unsigned   | 位模式不变    | 数值解释改变   |
| 同位宽 unsigned → signed   | 位模式不变    | 数值解释改变   |
| 小 unsigned → 大 unsigned | 高位补 0    | 通常无损     |
| 小 signed → 大 signed     | 符号扩展     | 通常无损     |
| 大整数 → 小整数               | 高位可能丢失   | 截断       |
| `float` → `double`      | 扩展精度     | 通常无损     |
| `double` → `float`      | 精度降低     | 可能舍入或溢出  |
| 整数 → 浮点数                | 数值重新编码   | 可能损失整数精度 |
| 浮点数 → 整数                | 小数部分不能保存 | 截断、越界    |

## 48. 本章核心概念对比

### 48.1 无符号数和补码

| 项目   | unsigned       | signed 补码                 |
| ---- | -------------- | ------------------------- |
| 最高位  | 正权 $2^{n-1}$ | 负权 $-2^{n-1}$           |
| 范围   | $0\sim2^n-1$ | $-2^{n-1}\sim2^{n-1}-1$ |
| 加法器  | 相同             | 相同                        |
| 溢出判断 | Carry          | Overflow                  |
| 扩展   | 补 0            | 符号扩展                      |

---

### 48.2 浮点数的范围与精度

| 字段  | 主要决定 |
| --- | ---- |
| 符号位 | 正负   |
| 阶码  | 表示范围 |
| 尾数  | 表示精度 |

可以记成：

> **阶码管“能有多大”，尾数管“能有多准”。**

## 49. 408 高频易错点

#### 1. 最高位为 1 不一定表示负数

只有在：

> **将该位模式解释成补码有符号整数**

时，最高位 1 才说明它是负数。

无符号整数：

```text
11111111
```

是：

$$
255
$$

而不是 $-1$。

---

#### 2. 补码的最高位权值不是普通正权

$n$ 位补码最高位：

$$
-2^{n-1}
$$

而不是：

$$
2^{n-1}
$$

---

#### 3. signed 与 unsigned 转换通常不改变位模式

改变的是：

> **解释规则**

而不是重新“计算出另一串二进制”。

---

#### 4. 符号扩展不是简单补 1

只有原符号位为 1 时才补 1。

原符号位为 0 时补 0。

本质是：

> **复制符号位。**

---

#### 5. Carry 和 Overflow 不是一回事

CF 主要服务于：

> **无符号数**

OF 主要服务于：

> **补码有符号数**

例如最高位产生进位，不代表 signed 一定溢出。

---

#### 6. 同号相加变号才是补码加法溢出的典型特征

```text
正 + 正 → 负：溢出
负 + 负 → 正：溢出
正 + 负：通常不溢出
```

---

#### 7. IEEE 754 的 exp 是移码字段，不是实际指数

正常数：

$$
E=exp-Bias
$$

不能直接把 `exp` 当作指数。

---

#### 8. frac 中没有保存规格化数最高位的 1

正常数实际有效数：

$$
1.frac
$$

而不是：

$$
0.frac
$$

---

#### 9. 非规格化数没有隐藏的 1

非规格化数：

$$
0.frac
$$

并且：

$$
E=1-Bias
$$

---

#### 10. exp 全 0 不一定是 0

只有：

```text
exp  = 全 0
frac = 全 0
```

才是 0。

若：

```text
exp  = 全 0
frac ≠ 0
```

则是非规格化数。

---

#### 11. exp 全 1 不一定是无穷

```text
frac = 0 → Infinity
frac ≠ 0 → NaN
```

---

#### 12. 浮点尾数产生进位不等于浮点结果溢出

尾数可以通过右规恢复。

最终是否溢出应看：

> **规格化、舍入后最终阶码是否超出范围。**

---

#### 13. 对阶可能损失精度，但不会直接导致阶码溢出

对阶：

> 小阶尾数右移，小阶码增加到大阶码。

真正可能改变最终阶码范围的是：

* 右规
* 左规
* 舍入

---

#### 14. 右规与舍入都可能导致阶码上溢

右规：

$$
E\leftarrow E+1
$$

舍入若使：

$$
1.111\cdots
$$

变成：

$$
10.000\cdots
$$

也需要再次右规。

---

#### 15. `float` 范围很大，不等于可以精确表示所有 `int`

单精度有效精度约为 24 个二进制有效位。

因此：

$$
2^{24}+1
$$

不能被普通单精度精确区分于附近某些整数。
