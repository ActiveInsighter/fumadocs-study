乘除法硬件的共同思想是：把复杂运算拆成若干次**加/减、移位与判断**。

408 通常更关注运算过程和部件关系，而不是要求记某一种具体乘除器的全部门级实现。

## 2.4.1 二进制乘法

二进制竖式乘法与十进制相同，只是乘数每一位只有 0 或 1。

例如：

```text
       1011
     × 1110
     ======
       0000
      1011
     1011
+   1011
-----------
   10011010
```

即：

$$
11\times14=154
$$

若：

$$
b=\sum b_i2^i
$$

则：

$$
a\times b=\sum b_i(a\times2^i)
$$

所以每一位只需决定“加不加对应移位后的被乘数”。

## 2.4.2 移位加法实现乘法

最朴素算法：

```text
result = 0
循环处理乘数各位：
  若当前位为 1：result += 被乘数
  被乘数左移 1 位
  乘数右移 1 位
```

伪代码：

```c
unsigned multiply(unsigned a, unsigned b) {
    unsigned result = 0;
    while (b != 0) {
        if (b & 1) result += a;
        a <<= 1;
        b >>= 1;
    }
    return result;
}
```

它揭示了硬件乘法器的基础部件：

- 寄存器；
- 加法器；
- 移位器；
- 控制器；
- 计数器。

## 2.4.3 顺序乘法器

顺序乘法器逐位处理乘数，每个周期完成一轮：

1. 检查乘数当前位；
2. 必要时加部分积；
3. 移位；
4. 进入下一位。

优点是硬件复用程度高、结构较省；缺点是需要多个迭代周期。

## 2.4.4 阵列乘法器

阵列乘法器用大量与门产生部分积，再通过半加器/全加器网络并行累加。

与顺序乘法器相比：

| 特性 | 顺序乘法器 | 阵列乘法器 |
| --- | --- | --- |
| 硬件数量 | 较少 | 较多 |
| 并行程度 | 低 | 高 |
| 速度 | 通常较慢 | 通常较快 |
| 核心思想 | 逐位移位累加 | 并行产生、累加部分积 |

## 2.4.5 乘积位宽

两个 $n$ 位无符号整数相乘，完整乘积最多需要 $2n$ 位。

因为：

$$
(2^n-1)^2<2^{2n}
$$

因此若只保留低 $n$ 位，就可能发生高位截断。

有符号乘法也要注意目标寄存器或目标类型的位宽，不要把“硬件能得到完整双倍位宽乘积”与“程序最终保存多少位”混为一谈。

## 2.4.6 二进制除法

二进制长除法与十进制长除法类似。每一轮通常完成：

1. 形成当前部分余数；
2. 与除数比较或尝试相减；
3. 根据结果确定当前商位 0/1；
4. 移位并进入下一轮。

例如：

$$
15\div2=7\cdots1
$$

硬件常使用：

- 余数寄存器；
- 商/被除数寄存器；
- 加减器；
- 移位逻辑；
- 控制器。

通常每轮确定一位商。

## 2.4.7 恢复余数与“不恢复”思想

一种基本除法思路是“先减除数”：

- 若结果非负，商当前位记 1；
- 若结果为负，说明本轮不够减，需要恢复原余数，商当前位记 0。

改进方案可以利用后续加/减操作避免每次都立即恢复，因此称为“不恢复余数”类方法。

408 的核心是理解：

> **除法的商位判定依赖部分余数与除数的关系，整个过程由移位和加减迭代完成。**

## 2.4.8 ALU 的作用

**ALU（Arithmetic Logic Unit，算术逻辑单元）**&#x2060;通常负责：

- 加、减；
- 与、或、异或、非；
- 比较；
- 某些移位或与移位器协作；
- 生成相应状态标志。

ALU 并不是“只会加法”，但很多算术功能可以复用加法器：

```text
加法      → A + B
减法      → A + ~B + 1
比较大小  → 常可通过减法结果/标志判断
地址计算  → 加法
```

因此“补码 + 加法器 + 标志位”构成了整数运算硬件的一条核心主线。

## 2.4.9 乘除法与加减法的联系

可以把本节归纳为：

```text
加法：全加器逐位组合
减法：补码把减法转成加法
乘法：移位 + 条件加法
除法：移位 + 条件减法/恢复
```

这也是理解“为什么计算机底层大量算术最终围绕加法器展开”的关键。
