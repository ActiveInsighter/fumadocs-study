CPU 与外设之间最大的矛盾通常不是“能不能连上”，而是：

- 速度差异巨大；
- 数据格式不同；
- 控制时序不同；
- 电气特性和通信协议不同。

因此主机通常不直接操作外设本体，而是通过 **I/O 接口/设备控制器**完成适配。

> **真题标签｜I/O 接口**
>
> 原资料索引：选择题 2014 第 21 题、2017 第 21 题、2021 第 20 题。

## 6.3.1 I/O 系统的基本层次

以主机为参照：

- 外设 $\rightarrow$ 主机：输入；
- 主机 $\rightarrow$ 外设：输出。

传统简化结构：

```text
CPU / 主存
    │
系统互连
    │
I/O 接口 / 设备控制器
    │
   外设
```

其中：

- **CPU**：发命令、读状态、必要时搬运数据、处理中断；
- **I/O 接口/控制器**：缓冲、状态管理、时序协调、格式转换；
- **外设**：与现实环境或外部介质交换信息。

现代系统中，内存控制器、PCIe 根控制器等功能可能集成在 CPU/SoC 内；USB、SATA、音频等也可能由片上控制器或芯片组管理。这改变了物理实现，但不改变 408 的逻辑抽象。

## 6.3.2 I/O 软件层次

I/O 还涉及操作系统软件。典型层次可抽象为：

```text
用户层 I/O 软件
    ↓
设备独立性软件
    ↓
设备驱动程序
    ↓
中断处理程序
    ↓
I/O 控制器 / 外设
```

其中：

- 应用程序通常不直接操纵硬件寄存器；
- 驱动程序理解具体设备寄存器和命令；
- 中断处理程序处理硬件事件；
- 设备独立层向上提供相对统一的接口。

这部分与操作系统 I/O 章节会再次交叉。

## 6.3.3 I/O 接口的五类核心功能

### 数据缓冲

外设与 CPU/主存速度差距很大，接口通常设置**数据缓冲寄存器**暂存数据。

作用：

> **在“设备慢、主机快”或双方速率不完全匹配时进行速度适配。**

### 数据格式转换

例如：

- 串行 $\leftrightarrow$ 并行；
- 不同位宽之间的组织；
- 设备格式与主机可处理格式之间的转换。

### 控制与定时

接口负责把 CPU 发出的抽象读/写/启动命令转换为设备可接受的控制时序。

### 状态与错误检测

保存：

- `Ready`；
- `Busy`；
- `Done`；
- `Error` 等。

### 主机侧与设备侧通信

接口一侧面向主机互连，另一侧面向设备，因此必须在两种通信环境之间协调。

## 6.3.4 I/O 接口与设备控制器

两者侧重点不同：

- **I/O 接口**：强调主机与设备之间的信息交换接口；
- **设备控制器**：强调对某类设备的具体控制逻辑。

在具体硬件和考试语境中，两者功能常高度重合，不要因为名称不同就认为一定是两个完全独立部件。

## 6.3.5 I/O 端口不是“USB 插孔”

408 中的 **I/O 端口（I/O Port）**&#x2060;通常指：

> **I/O 接口中能够被 CPU 直接访问的寄存器。**

按用途常分为：

| 端口 | 典型内容 | 常见访问方向 |
| --- | --- | --- |
| 数据端口 | 输入/输出数据 | 读或写 |
| 状态端口 | Ready、Busy、Error、Done | 主要读 |
| 控制端口 | 启动、停止、复位、模式 | 主要写 |

> **做题时的第一反应**
>
> “CPU 访问 I/O 端口”本质上就是“CPU 读写接口内部寄存器”。

## 6.3.6 统一编址：Memory-Mapped I/O

统一编址又称 **内存映射 I/O（MMIO）**。

核心思想：

> **主存单元和设备寄存器共享同一套地址空间。**

某些地址译码到 RAM，另一些地址译码到 I/O 设备寄存器。CPU 因而可以使用普通访存类指令访问设备。

示意：

```text
统一地址空间
0x0000_0000  ─┐
              ├─ 普通主存区域
...           │
0xF000_0000  ─┼─ 某设备寄存器区域
...           │
0xFFFF_FFFF  ─┘
```

优点：

- 不需要另一套专用 I/O 指令体系；
- 普通 load/store 指令即可访问；
- 编程模型统一。

代价：

- 设备寄存器占用统一地址空间的一部分。

> **体系结构提醒**
>
> MMIO 地址虽然“长得像内存地址”，却不等于普通 RAM。真实系统常对这类区域设置特殊缓存、顺序或副作用规则；408 基础题重点只需掌握编址思想。

## 6.3.7 独立编址：Port-Mapped I/O

独立编址又称 **端口映射 I/O（PMIO）**。

系统保留两套逻辑地址空间：

- 主存地址空间；
- I/O 端口地址空间。

CPU 需要使用专用 I/O 指令访问端口。传统 x86 常用：

```asm
IN  AL, 0x60
OUT 0x3F8, AL
```

此时端口号不是普通主存地址。

## 6.3.8 MMIO 与 PMIO 对比

| 项目 | MMIO 统一编址 | PMIO 独立编址 |
| --- | --- | --- |
| 地址空间 | 主存与 I/O 共用 | 主存、I/O 分离 |
| 是否占统一地址空间 | 是 | 否 |
| 普通访存指令 | 可以使用 | 通常不用于端口 |
| 专用 I/O 指令 | 不必需 | 通常需要 |
| 典型思想 | load/store 设备寄存器 | `IN` / `OUT` |

> **速记**
>
> **统一编址：一个地址空间；独立编址：两个地址空间。**

## 6.3.9 一条完整 I/O 路径怎么读

遇到综合图时，可以按下面的顺序追踪：

```text
CPU 发出命令
→ 访问 I/O 控制/状态/数据端口
→ I/O 接口把命令转成设备动作
→ 外设准备或接收数据
→ 状态寄存器变化 / 产生中断 / 发 DMA 请求
→ 数据最终到达 CPU 或主存
```

真正区分“程序查询、中断、DMA”的关键，不在端口本身，而在：

> **设备何时通知、谁搬数据、CPU 参与到什么程度。**
