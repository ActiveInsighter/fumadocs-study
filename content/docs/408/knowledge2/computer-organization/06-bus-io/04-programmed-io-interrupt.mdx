> **真题标签｜I/O 数据传送方式**
>
> 原资料索引：I/O 方式选择题 2011 第 22 题、2023 第 22 题，解答题 2018 第 43 题。原资料还将 2009 第 43 题列入 DMA/中断定量题索引。

外设通常比 CPU 慢得多。I/O 控制方式的发展，本质是在不断减少 CPU 对“等待”和“搬运”的直接参与。

先记总框架：

| 方式 | CPU 是否忙等设备 | 数据是否经 CPU 通用寄存器逐个搬运 | 设备控制自主性 |
| --- | --- | --- | --- |
| 程序查询 | 是 | 是 | 很低 |
| 程序中断 | 否 | 是 | 较低 |
| DMA | 否 | 否 | 较高 |
| 通道 | 否 | 否 | 很高 |

## 6.4.1 程序查询：CPU 既“等”又“搬”

程序查询又称**程序轮询（Polling）**。CPU 反复读取状态端口，直到设备就绪。

典型输入流程：

```text
CPU 写控制端口启动设备
→ 反复读状态端口
→ Ready = 0：继续查询
→ Ready = 1：读数据端口
→ CPU 把数据写入主存
→ 继续下一轮
```

数据路径通常是：

```text
设备 → I/O 接口 → CPU 寄存器 → 主存
```

优点：

- 硬件简单；
- 软件逻辑直观。

缺点：

- CPU 长时间忙等待；
- 等待期间占用处理器执行时间；
- 设备越慢，浪费越明显。

> **核心判断**
>
> 看到“CPU 不断检查状态位，直到设备就绪”，就是程序查询。

## 6.4.2 程序中断：CPU 不再忙等，但仍负责搬数据

中断方式中：

1. CPU 启动 I/O；
2. CPU 转去执行其他程序；
3. 设备准备好后发出中断请求；
4. CPU 在适当边界响应中断；
5. 进入中断服务程序；
6. ISR 访问 I/O 端口并完成数据搬运；
7. 中断返回原程序。

典型输入数据路径仍是：

```text
设备 → I/O 接口 → CPU 寄存器 → 主存
```

因此中断方式解决的是：

> **CPU 不必一直等设备。**

但它没有解决：

> **数据仍要由 CPU 指令逐个/逐批搬运。**

若高速设备非常频繁地产生中断，CPU 可能耗费大量时间在：

- 中断响应；
- 现场保护与恢复；
- ISR；
- 端口读写；
- 数据搬运。

这就是为什么大块高速 I/O 更适合 DMA。

## 6.4.3 “设备准备时间”和“CPU 服务时间”必须分开

综合题常把两类时间混在一起：

### 设备时间

例如：

- 磁盘旋转/传输；
- 串口逐位发送；
- 设备内部准备数据。

这段时间设备在工作，CPU 可能可以并行执行其他程序。

### CPU 时间

例如：

- 轮询指令；
- 中断响应；
- ISR 指令；
- 访问 I/O 端口；
- 数据复制。

题目若分别问：

- “完成整个 I/O 任务经历多久”；
- “CPU 实际花了多少处理时间”；

两者不能直接画等号。

## 6.4.4 中断 I/O 的 CPU 开销模型

设：

- 设备数据率为 $R$ Byte/s；
- 每次中断处理 $q$ Byte；
- 每次中断从响应到服务完成共消耗 $C_{\text{int}}$ 个 CPU 时钟周期；
- CPU 主频为 $f_{\text{cpu}}$。

则每秒中断次数：

$$
r_{\text{int}}=\frac{R}{q}
$$

每秒用于 I/O 中断的 CPU 周期数：

$$
C_{\text{IO/s}}=r_{\text{int}}C_{\text{int}}
$$

CPU 时间占比：

$$
\eta=\frac{r_{\text{int}}C_{\text{int}}}{f_{\text{cpu}}}
$$

若求百分比，再乘 $100\%$。

> **这个模型的价值**
>
> 不必死记某一道题。只要把“每秒发生几次事件”和“每次事件花多少 CPU 周期”分开，查询、中断、DMA 的很多定量题都能统一处理。

## 6.4.5 异步串行 I/O 的帧长计算

若题目给出异步串行通信格式，应先算**线上真正发送的 bit 数**。

一般每个字符帧可能包含：

- 1 位起始位；
- $n$ 位数据；
- 可选奇偶校验位；
- 1 位或多位停止位。

若有 1 位起始位、$n$ 位数据、1 位校验、$s$ 位停止位，则每字符：

$$
L=1+n+1+s
$$

bit。

若线路速率为 $b$ bit/s，则理想字符率：

$$
r_{\text{char}}=\frac{b}{L}
$$

若设备内部准备一个字符还需要固定时间，则最终吞吐量还要比较**线路时间**和**设备准备时间**，按更慢的一侧确定。

## 6.4.6 查询与中断的典型比较

| 维度 | 程序查询 | 程序中断 |
| --- | --- | --- |
| 如何发现设备就绪 | CPU 主动读状态 | 设备主动发中断 |
| CPU 是否等待 | 忙等待 | 可做其他工作 |
| 数据搬运 | CPU | CPU |
| 硬件复杂度 | 低 | 更高 |
| 适用场景 | 简单、短时、低开销轮询 | 低中速、事件型设备 |

一句话：

> **查询：CPU“等 + 搬”；中断：CPU“不等，但仍搬”。**

## 6.4.7 中断方式与 CPU 中断机制的衔接

本章只关注 I/O 视角。CPU 章已经讨论过中断响应的处理器机制。把两章连接起来：

```text
设备事件
→ I/O 接口置状态并发中断请求
→ CPU 在允许且满足响应条件时进入中断流程
→ 执行 ISR
→ ISR 读写 I/O 端口并完成软件控制的数据传送
→ 中断返回
```

所以：

- **I/O 接口**负责把设备事件转换成主机可识别的状态/中断；
- **CPU 中断机制**负责安全改变控制流；
- **ISR**负责软件层面的设备服务和数据处理。
