## 十九、DMA 控制器

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-012.svg" alt={"DR MAR DC CR I/O 控 制 逻 辑 与块设备 的接口 CPU DMA 控制器 内存 系统总线 主机-控制器接口 块设备-控制器接口 磁盘"} />

典型 DMA 控制器包含：

| 寄存器/部件   | 作用                 |
| -------- | ------------------ |
| DR       | 数据寄存器，暂存传输数据       |
| MAR      | 主存地址寄存器，保存当前内存地址   |
| DC       | 数据计数器，记录尚未传输的数据量   |
| CR       | 命令/状态寄存器，保存工作方式和状态 |
| I/O 控制逻辑 | 与外设或 I/O 接口协调      |
| 总线控制逻辑   | 请求并控制系统总线          |

#### MAR

**MAR（Memory Address Register）**记录当前要访问的主存地址。

连续传输时，每完成一次数据传输，MAR 通常自动修改。

#### DC

**DC（Data Counter）**保存剩余数据量。

每传完一个单位：

* MAR 更新；
* DC 减少。

当 DC 达到规定终止条件时，整个 DMA 块传输完成。

#### DR

暂存当前一次传输的数据。

#### CR

保存：

* 读/写方向；
* DMA 工作方式；
* 状态；
* 控制信息等。

---

### 1. DMA 中“块传输”的含义

教材常说：

> **DMA 以数据块为单位进行传输。**

这不表示“一次总线周期把整个块全部传完”。

底层仍然是若干次总线传输。

例如：

```text
while (DC > 0) {
    传输一个数据单位;
    MAR += unit;
    DC  -= unit;
}
```

“以块为单位”的真正含义是：

> **CPU 只配置一次，DMA 控制器便可以自动完成整个数据块，而不需要 CPU 每传一个字就介入一次。**

---

### 2. 传统 DMA 控制器与现代 DMA 引擎

传统结构中，DMA 控制器可能是独立硬件模块。

DMA 请求系统总线后：

* CPU 暂时让出总线；
* DMA 成为总线主设备；
* DMA 直接组织 I/O 接口和主存之间的数据交换。

现代系统中 DMA 功能常集成在：

* 芯片组；
* SSD 控制器；
* 网卡；
* GPU；
* SoC 外设控制器

等硬件中，通常称为 **DMA Engine**。

原理仍然相同。

## 二十、DMA 的完整工作过程

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-013.svg" alt={"地址信息 数据信息 主线控制 缓冲区 1 3 2 4 5 处理器 DMA 控制器 总线 磁盘控制器 主存"} />

一次 DMA 可以概括成：

> **预处理 → DMA 传送 → 后处理**

---

### 1. 预处理

CPU 初始化 DMA 控制器。

设置：

* 外设地址；
* 主存地址；
* 传输长度；
* 传输方向；
* 工作方式。

之后 CPU 可以继续执行其他程序。

---

### 2. 外设发出 DMA 请求

当设备：

* 准备好输入数据；
* 或准备好接收输出数据；

便向 DMA 控制逻辑提出请求。

---

### 3. DMA 申请总线

DMA 控制器向：

* CPU；
* 或独立总线仲裁器

请求获得总线控制权。

---

### 4. 获得总线控制权

在传统模型中，CPU通常在完成当前总线周期后让出总线。

DMA 控制器成为总线主设备。

---

### 5. DMA 直接传输数据

DMA 控制器组织：

> **I/O 接口 ↔ 主存**

之间的数据交换。

每完成一个传输单位，自动：

* 修改 MAR；
* 修改 DC；
* 判断是否完成整个数据块。

---

### 6. DMA 释放总线

数据块完成后：

* DMA 停止本次传输；
* 释放总线控制权。

---

### 7. 后处理

DMA 控制器向 CPU 发出完成中断。

CPU 响应中断后完成：

* 检查 DMA 状态；
* 判断有无错误；
* 清除完成状态；
* 更新 I/O 请求；
* 唤醒等待进程；
* 启动下一项任务等。

> **DMA 与中断方式的核心区别**
>
> * 中断方式：设备请求 **CPU 来搬数据**；
> * DMA：设备借助 DMA 控制器请求 **总线使用权，由 DMA 搬数据**。

---

## 二十一、DMA 与 CPU 对主存的争用

CPU 和 DMA 都可能需要访问主存，因此必须协调总线或主存访问权。

传统教材主要讨论三种方法。

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-014.svg" alt={"周期挪用方式 总线分时复用 总线独占 DMA 独占总线 总线时钟周期 DMA 使用总线 CPU 使用总线"} />

---

### 1. 停止 CPU 访存 / DMA 独占一段时间

DMA 获得总线后，在一段时间内连续进行数据传输。

这段时间 CPU 不能通过被 DMA 占用的总线访问主存。

优点：

* DMA 传输效率高。

缺点：

* 对 CPU 访存影响较大。

---

### 2. 周期挪用

又称：

* Cycle Stealing；
* 周期窃取；
* 周期挪用。

DMA 每次只占用一个或少数几个总线周期。

例如：

```text
CPU CPU DMA CPU CPU DMA CPU ...
```

CPU 与 DMA 交替访问主存。

这种方式对 CPU 的影响较小，因此是 408 高频考点。

> **为什么叫“窃取”？**
>
> 原本某个主存周期可能可以供 CPU 使用，现在被 DMA 暂时拿走，所以称为“周期窃取”。

---

### 3. CPU 与 DMA 分时交替访问

如果存储器周期中本身存在可以划分的时隙，也可以预先规定：

* 某些时隙供 CPU；
* 某些时隙供 DMA。

双方按照固定方式交替访问。

---

### 4. CPU 与 DMA 谁优先

在传统 408 模型中，当 DMA 设备已经提出紧急数据传输请求时，通常：

> **DMA 的总线访问优先级高于 CPU。**

原因是高速外设的数据缓冲能力有限，如果不能及时搬运：

* 输入设备可能发生数据覆盖或溢出；
* 输出设备可能发生断流。

因此 CPU 可以短暂等待，而实时 I/O 数据往往不能无限等待。

---

## 二十二、通道方式

**通道（Channel）**是在 DMA 基础上进一步提高 I/O 系统自主能力的一种硬件。

它主要用于：

* 大型计算机；
* 具有大量 I/O 设备的系统。

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-015.svg" alt={"CPU 下达 I/O 任务 · 执行主程序 主存 数据缓冲区 · 通道程序 通道（I/O Processor） 独立执行通道程序 · 管理多个设备 又称通道处理机 下达 I/O 命令 （通道程序首地址） 结束中断 （任务完成通知） 数据 直接读写主存 设备控制器 Device Controller 设备控制器 Device Controller 设备控制器 Device Controller 磁盘 磁带 打印机 控制 中断 数据"} />

---

### 1. 通道与 DMA 的本质区别

DMA 控制器：

* 可以自动完成数据传输；
* 但自身通常不能执行复杂的 I/O 指令程序。

通道：

* 是一种专门负责 I/O 的处理部件；
* 具有一定的指令执行能力；
* 能够执行 **通道程序**；
* 可以独立组织多个设备的 I/O 操作。

因此通道又可理解为：

> **专用 I/O 处理机。**

---

### 2. 通道的工作过程

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-016.svg" alt={"CPU 通道 设备 主存 时间 ① 启动通道 下达通道程序首地址 CPU 并行执行其他程序（不参与 I/O） 通道独立工作期间，CPU 可执行其他任务 ② 依次执行通道程序中的 I/O 指令 自动控制设备完成数据传输 ③ 数据传输（设备 ↔ 主存，不经过 CPU） 数据缓冲区读/写 控制 数据 ④ 发送结束中断 通知 CPU 任务完成 响应中断 进行收尾处理 阶段 1：初始化 阶段 2：通道执行 阶段 3：数据传输 阶段 4：结束中断"} />

典型过程：

1. CPU 在主存中准备通道程序；
2. CPU 将通道程序首地址交给通道；
3. CPU 启动通道；
4. 通道独立执行通道程序；
5. 通道组织设备与主存之间的数据交换；
6. CPU 同时执行其他程序；
7. 整个 I/O 任务完成后，通道向 CPU 发出结束中断。

---

### 3. 通道程序

**通道程序（Channel Program）**存放在主存中，由通道执行。

其中可以规定：

* 操作哪个设备；
* 执行什么 I/O 操作；
* 主存地址；
* 数据长度；
* 后续通道指令位置等。

CPU：

> **只负责启动通道，而不逐条执行通道程序。**

---

## 二十三、四种 I/O 方式总对比

| 比较项目             | 程序查询     | 程序中断   | DMA        | 通道          |
| ---------------- | -------- | ------ | ---------- | ----------- |
| CPU 是否忙等待        | 是        | 否      | 否          | 否           |
| 设备就绪如何通知         | CPU 主动查询 | 中断     | DMA 请求     | 通道自行管理      |
| 实际数据谁搬           | CPU      | CPU    | DMA 控制器    | 通道控制的数据通路   |
| 数据是否需经 CPU 通用寄存器 | 是        | 是      | 否          | 否           |
| CPU 何时参与         | 全程       | 每次中断传输 | 初始化 + 完成中断 | 启动任务 + 完成中断 |
| 适合数据量            | 少量       | 少量/低中速 | 大块、高速      | 多设备复杂 I/O   |
| 硬件复杂度            | 最低       | 较低     | 较高         | 最高          |
| I/O 自主能力         | 最弱       | 较弱     | 强          | 最强          |

可以把整个发展过程理解为：

> **程序查询 → 程序中断 → DMA → 通道**

CPU 的参与程度依次降低。

## 二十四、最容易混淆的几个问题

### 1. 程序中断方式是不是数据不经过 CPU？

不是。

程序中断解决的是：

> **CPU 不需要一直等。**

但中断服务程序执行数据传送时，数据通常仍需要经过 CPU 寄存器。

---

### 2. DMA 是不是完全不需要 CPU？

不是。

DMA 仍需要 CPU：

* 初始化；
* 设置地址；
* 设置传输长度；
* 设置方向；
* 启动任务；
* 处理完成中断。

DMA 只是让 CPU：

> **不再逐个数据单位地参与搬运。**

---

### 3. DMA 是不是一次总线周期传完整个数据块？

不是。

DMA 所谓“块传输”是：

> **CPU 一次配置，DMA 自动完成整块。**

底层仍可能经历很多次主存或总线传输。

---

### 4. DMA 请求和中断请求有什么区别？

#### 中断请求

目的是：

> **让 CPU 暂停当前程序来处理事件。**

#### DMA 请求

目的主要是：

> **获得完成直接数据传输所需要的总线/存储器访问能力。**

DMA 整块完成后，又通常会：

> **通过中断通知 CPU。**

所以：

> **DMA 过程可以既有 DMA 请求，又有最终的中断请求。**

---

### 5. I/O 接口、I/O 端口、外设接口是不是一个概念？

不是。

#### I/O 接口

主机和设备之间的接口控制电路。

#### I/O 端口

I/O 接口中 CPU 可以访问的寄存器。

#### USB、SATA 等物理接口

设备实际使用的连接标准或连接形式。

---

### 6. 地址总线宽度和数据总线宽度分别决定什么？

地址总线：

> **能够表示多少个地址。**

数据总线：

> **一次能够传多少 bit 数据。**

绝不能混淆。

---

### 7. 总线周期和时钟周期是不是一个东西？

不是。

一般：

$$
T_{\text{总线周期}}
=
N
\times
T_{\text{时钟周期}}
$$

其中 $N$ 可以大于 1。

---

### 8. 提高总线频率一定能无限提高性能吗？

不能。

实际系统还受到：

* 设备响应速度；
* 信号完整性；
* 总线仲裁；
* 地址和控制开销；
* 存储器延迟；
* 协议效率

等因素限制。

因此理论带宽和实际有效带宽往往不同。

---

## 二十五、408 高频结论速记

> **总线三类信号**
>
> * 数据线：传数据；
> * 地址线：指出访问对象；
> * 控制线：控制整个传输。

> **串并行**
>
> * 并行：多位同时传；
> * 串行：逐位传，现代高速互连广泛采用。

> **总线事务**
>
> * 主设备发起；
> * 从设备响应；
> * 一次事务通常完成一次读或写。

> **突发传输**
>
> **一次寻址，多次连续数据传输。**

> **总线定时**
>
> * 同步：看时钟；
> * 异步：看握手。

> **总线带宽**
>
> $$
> B
> =
> \text{每次传输字节数}
> \times
> \text{每秒有效传输次数}
> $$

> **I/O 端口**
>
> 是 **I/O 接口内部 CPU 可以直接访问的寄存器**。

> **I/O 编址**
>
> * MMIO：统一地址空间，普通访存指令；
> * PMIO：独立 I/O 地址空间，专用 I/O 指令。

> **程序查询**
>
> CPU：**等 + 搬**。

> **程序中断**
>
> CPU：**不等，但仍然搬**。

> **DMA**
>
> CPU：**不等，也不逐个搬，只负责首尾控制**。

> **通道**
>
> 在 DMA 思想基础上进一步提高 I/O 控制自主性，能够执行 **通道程序**。

> **CPU 与 DMA 争用主存**
>
> 高频方式：**周期挪用（Cycle Stealing）**。

> **整章主线**
>
> **总线解决“如何传”，I/O 控制方式解决“谁来管、谁来搬”。**
