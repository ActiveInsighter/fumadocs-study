## 19. DMA 控制器的典型结构

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-012.svg" alt={"DR MAR DC CR I/O 控 制 逻 辑 与块设备 的接口 CPU DMA 控制器 内存 系统总线 主机-控制器接口 块设备-控制器接口 磁盘"} />

经典 DMA 控制器通常包含：

| 寄存器/部件 | 作用 |
| --- | --- |
| MAR / 地址寄存器 | 保存当前主存地址 |
| DC / 计数器 | 保存剩余传输量或当前计数 |
| DR / 数据寄存器 | 暂存当前传输数据 |
| CR / 命令状态寄存器 | 保存方向、方式、状态等控制信息 |
| I/O 控制逻辑 | 与外设协调请求和数据传输 |
| 总线控制逻辑 | 请求并获得系统互连/主存访问权 |

连续传输时可抽象为：

```text
while (DC > 0) {
    transfer_one_unit();
    MAR += unit_size;
    DC  -= 1;          // 或按题目规定的计数方式修改
}
```

<Callout type="warning" title="DMA 的“块传输”不是一个总线周期">

“DMA 以块为单位”表示 **CPU 配置一次，DMA 自动完成整块**。底层依然需要许多次总线/主存传输，不可能把整个大块在一次普通总线周期中瞬间传完。

</Callout>

现代系统中 DMA 功能常集成在 SSD、网卡、GPU、SoC 外设控制器等设备内，常称 **DMA Engine**，但考试原理相同。

## 20. DMA 的完整工作过程

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-013.svg" alt={"地址信息 数据信息 主线控制 缓冲区 1 3 2 4 5 处理器 DMA 控制器 总线 磁盘控制器 主存"} />

一次 DMA 可概括为：

> **预处理 → 请求与仲裁 → 自动传送 → 后处理。**

### 20.1 CPU 预处理

CPU 写 DMA 控制寄存器，设置：

- 外设/通道；
- 主存起始地址；
- 数据长度；
- 传输方向；
- 工作方式。

随后 CPU 可执行其他程序。

### 20.2 外设/DMA 发起请求

外设准备好输入数据，或能够接收输出数据时，向 DMA 逻辑发出请求。

DMA 再向总线仲裁逻辑申请访问主存所需的控制权。

### 20.3 获得总线或主存访问机会

在传统模型中，CPU 通常完成当前总线周期后才让出相关资源；DMA 获得控制权后成为本次事务的主设备。

### 20.4 DMA 自动传送

DMA 组织：

> **I/O 接口 ↔ 主存**

之间的数据交换，并自动修改地址和计数器。

### 20.5 结束与后处理

整块完成后，DMA：

- 释放相关总线/访问资源；
- 设置完成状态；
- 通常向 CPU 发出完成中断。

CPU 的后处理可包括：

- 检查状态或错误；
- 清除标志；
- 更新 I/O 请求；
- 唤醒等待进程；
- 启动下一项任务。

## 21. DMA 与 CPU 争用主存：三种经典方式

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-014.svg" alt={"周期挪用方式 总线分时复用 总线独占 DMA 独占总线 总线时钟周期 DMA 使用总线 CPU 使用总线"} />

CPU 和 DMA 都可能访问主存，因此必须协调主存或系统总线使用权。

### 21.1 停止 CPU 访存 / 成组传送

DMA 获得控制权后连续传输一段时间或一个数据块。

优点：DMA 效率高。

缺点：CPU 在这段时间不能通过被占用的通路访问主存，停顿明显。

### 21.2 周期挪用（Cycle Stealing）

DMA 每次只“拿走”一个或少数几个主存/总线周期：

```text
CPU  CPU  DMA  CPU  CPU  DMA  CPU ...
```

优点：

- DMA 可以及时搬数据；
- CPU 只被短暂打断访存。

“窃取”指 DMA 抢占了原本可能供 CPU 使用的存储周期。

### 21.3 CPU 与 DMA 分时交替

若存储器/互连时序允许，可预先把不同时间片分给 CPU 与 DMA，双方按固定节拍交替访问。

### 21.4 为什么 DMA 常具有较高访问优先级

在经典 408 模型中，DMA 请求往往比普通 CPU 访存更紧迫，因为设备缓冲区容量有限：

- 输入若不及时取走可能溢出；
- 输出若不及时补充可能断流。

因此题目若无相反说明，通常认为紧急 DMA 访问可使 CPU 暂时等待。

<Callout type="warning" title="CPU 停顿不等于 CPU 响应中断">

DMA 周期挪用时，CPU 可能只是因为暂时拿不到总线/主存而等待，并不意味着 CPU 执行了中断服务程序。**总线争用与中断响应是两套不同机制。**

</Callout>

## 22. DMA 请求与中断请求的区别

这两个“请求”经常同时出现在 DMA 题里，但目标完全不同。

| 项目 | DMA/总线请求 | 中断请求 |
| --- | --- | --- |
| 直接目的 | 获得数据传输所需的总线/主存访问机会 | 让 CPU 转去处理某个事件 |
| 是否必然执行 ISR | 否 | CPU 接受后会进入中断处理流程 |
| 发生时机 | DMA 需要传数据时可多次发生 | 常在 DMA 整块完成或出错后发生 |
| 数据谁搬 | DMA 控制逻辑 | 若是普通中断 I/O，则 CPU 搬；DMA 完成中断本身不搬数据 |

因此一次 DMA 可能经历：

```text
CPU 配置 DMA
    ↓
多次 DMA/总线请求与数据传输
    ↓
整块完成
    ↓
一次完成中断通知 CPU
```

> **DMA 请求是“让我用传输资源”；中断请求是“请 CPU 来处理事件”。**

## 23. 通道方式

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-015.svg" alt={"CPU 下达 I/O 任务 · 执行主程序 主存 数据缓冲区 · 通道程序 通道（I/O Processor） 独立执行通道程序 · 管理多个设备 又称通道处理机 下达 I/O 命令 （通道程序首地址） 结束中断 （任务完成通知） 数据 直接读写主存 设备控制器 Device Controller 设备控制器 Device Controller 设备控制器 Device Controller 磁盘 磁带 打印机 控制 中断 数据"} />

**通道（Channel）**是在 DMA 思想上进一步提高 I/O 自主能力的经典结构，主要出现在传统大型机和教材模型中。

### 23.1 通道与 DMA 的差异

DMA 控制器能够按 CPU 配置自动搬运数据，但通常只完成较固定的数据传送控制。

通道则具有一定的**专用指令执行能力**，能够执行存放在主存中的**通道程序**，独立组织更复杂的 I/O 操作，因此可理解为一种专用 I/O 处理部件。

### 23.2 通道工作过程

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-016.svg" alt={"CPU 通道 设备 主存 时间 ① 启动通道 下达通道程序首地址 CPU 并行执行其他程序（不参与 I/O） 通道独立工作期间，CPU 可执行其他任务 ② 依次执行通道程序中的 I/O 指令 自动控制设备完成数据传输 ③ 数据传输（设备 ↔ 主存，不经过 CPU） 数据缓冲区读/写 控制 数据 ④ 发送结束中断 通知 CPU 任务完成 响应中断 进行收尾处理 阶段 1：初始化 阶段 2：通道执行 阶段 3：数据传输 阶段 4：结束中断"} />

典型流程：

1. CPU 在主存中准备通道程序；
2. CPU 把通道程序入口或相关控制信息交给通道；
3. CPU 启动通道；
4. 通道独立执行通道程序并控制设备；
5. 数据在设备与主存之间传输；
6. CPU 同时执行其他程序；
7. I/O 任务完成后，通道向 CPU 发出结束中断。

### 23.3 通道程序

通道程序可规定：

- 操作哪个设备；
- 执行何种 I/O；
- 主存地址；
- 数据长度；
- 后续通道指令位置等。

关键点：

> **CPU 启动通道，但不逐条执行通道程序；通道自己执行。**

## 24. 四种 I/O 方式总对比

| 比较项 | 程序查询 | 程序中断 | DMA | 通道 |
| --- | --- | --- | --- | --- |
| CPU 是否忙等设备 | 是 | 否 | 否 | 否 |
| 就绪/任务推进机制 | CPU 主动查状态 | 设备中断 CPU | DMA 请求并自动传送 | 通道执行通道程序 |
| 数据谁搬 | CPU | CPU | DMA 控制逻辑 | 通道控制的数据通路 |
| 是否逐次经过 CPU 通用寄存器 | 是 | 是 | 否 | 否 |
| CPU 参与粒度 | 每个传输单位 | 每次中断 | 每个数据块首尾 | 整个 I/O 任务首尾 |
| 自主能力 | 最弱 | 较弱 | 强 | 更强 |
| 适用典型场景 | 简单/低速 | 低中速、小量事件 | 高速、大块数据 | 多设备、复杂 I/O 组织 |

可以用一句话记忆：

- 查询：**CPU 等 + CPU 搬**；
- 中断：**CPU 不等 + CPU 搬**；
- DMA：**CPU 不等 + DMA 搬，CPU 管首尾**；
- 通道：**CPU 启动任务，通道按程序组织 I/O**。

## 25. 高频易错点与整章速记

### 25.1 地址总线宽度与数据总线宽度

- 地址总线宽度：决定可编码多少地址；
- 数据总线宽度：决定一次并行传多少 bit。

### 25.2 时钟周期与总线周期

若一个总线周期需要 $N$ 个时钟周期：

$$
T_{\text{bus}}=NT_{\text{clock}}
$$

两者不必相等。

### 25.3 中断 I/O 的数据仍通常经过 CPU

程序中断解决的是**不用忙等**；中断服务程序仍通常由 CPU 从 I/O 端口取/送数据。

### 25.4 DMA 不是“完全不需要 CPU”

CPU 仍需：

- 初始化；
- 设置地址/长度/方向；
- 启动；
- 处理完成或错误中断。

DMA 只是不要求 CPU **逐个数据单位搬运**。

### 25.5 突发传输与 DMA 不是同一概念

- **突发传输**描述一次事务中连续传多个数据的总线传输组织；
- **DMA**描述由谁控制设备与主存之间的批量数据搬运。

DMA 可以使用突发传输，但二者不是同义词。

### 25.6 I/O 接口、I/O 端口与物理接口

- I/O 接口：主机与设备之间的接口控制电路；
- I/O 端口：接口中 CPU 可访问的寄存器；
- USB/SATA 等接口：现实设备连接和通信标准。

### 25.7 总线带宽公式

$$
B
=
\text{每次有效传输字节数}
\times
\text{每秒有效传输次数}
$$

做题时始终先拆成这两项。

### 25.8 本章最终主线

<Callout type="info" title="一条线串起整章">

**总线解决“如何连接、何时传、一次传多少、传多快”；I/O 接口解决“主机怎样看见并控制设备”；查询/中断/DMA/通道解决“设备准备时 CPU 是否等待，以及真正的数据由谁搬”。**

</Callout>

> **408 高频结论**
>
> - 总线三类信号：数据、地址、控制；
> - 同步定时看时钟，异步定时看握手；
> - 突发传输：一次寻址，连续传多个数据；
> - MMIO：统一地址空间 + 普通访存指令；
> - 查询：CPU 忙等；中断：CPU 不忙等但仍搬数据；
> - DMA：CPU 管首尾，DMA 负责整块数据搬运；
> - DMA “块传输”不等于一次总线周期传完整块；
> - CPU 与 DMA 争用主存时，周期挪用是经典高频方式。
