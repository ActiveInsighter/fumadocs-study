## 一、总线基础

### 1. 总线的基本概念

> **真题考查**
>
> * 选择题：2011 年第 20 题、2012 年第 21 题、2021 年第 19 题

**总线（Bus）** 是一组能够被多个部件共享的信号传输线路，用于在 CPU、主存、I/O 接口等部件之间传送 **数据、地址和控制信息**。

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-001.svg" alt={"系统总线 CPU Central Processing Unit 主存储器 Memory (DRAM) 总线控制器 Bus Controller / Chipset GPU 显卡 / Video Card SSD / 存储 外存 / Storage I/O 接口 键盘 / 鼠标 / 打印机 / 网络 数据总线 (Data Bus) 地址总线 (Address Bus) 控制总线 (Control Bus)"} />

传统计算机系统中，多个部件往往需要共享通信线路，因此总线具有两个重要特点：

* **共享性**：多个部件可以连接到同一组总线上；
* **分时性**：同一时刻通常只能有一个主设备控制某组共享总线进行一次事务。

这里的“总线”强调的是一种 **共享的信息传输通路**。现代系统中的 PCIe 等高速互连更多采用点到点连接，但在 408 体系中仍可按照总线或系统互连的基本思想理解。

## 二、总线的分类

> **真题考查**
>
> * 选择题：2010 年第 20 题、2012 年第 20 题、2013 年第 19 题、2016 年第 20 题、2017 年第 20 题

总线可以从多个相互独立的角度进行分类。

| 分类依据    | 类型             |
| ------- | -------------- |
| 传输的信息功能 | 数据总线、地址总线、控制总线 |
| 连接对象和用途 | 核内总线、系统总线、通信总线 |
| 数据传送方式  | 串行总线、并行总线      |
| 时序控制方式  | 同步总线、异步总线      |

> **易错点**
>
> 这些分类不是同一维度。
>
> 例如一条总线可以同时是：
>
> **系统总线 + 串行总线 + 某种同步或握手机制控制的总线**。
>
> 因此不能把“系统总线”“数据总线”“串行总线”等看成互斥概念。

### 1. 按传输信息的功能分类

系统总线通常包含 **数据总线、地址总线和控制总线**。

#### 数据总线

**数据总线（Data Bus）** 用于在各部件之间传输实际数据。

例如：

* CPU 从主存读取指令；
* CPU 向主存写入运算结果；
* CPU 与 I/O 接口交换数据。

数据总线宽度表示一次能够并行传输的数据位数，例如：

* 8 位；
* 16 位；
* 32 位；
* 64 位。

> **注意**
>
> 数据总线宽度与机器字长、存储字长可能存在联系，但**并不要求三者一定相等**。
>
> 做题时不能仅根据“32 位 CPU”直接推出“数据总线一定为 32 位”。

#### 地址总线

**地址总线（Address Bus）** 用于指定本次访问的目标位置，例如：

* 主存地址；
* I/O 端口地址。

如果有 $n$ 根独立地址线，则最多可以形成的不同地址数量为：

$$
2^n
$$

若系统按照字节编址，则理论地址空间为：

$$
2^n\ \text{Byte}
$$

因此：

> **地址线数量决定可表示多少个地址，而不是直接决定一次传多少数据。**

#### 控制总线

**控制总线（Control Bus）** 传送控制信号以及状态信号，例如：

* 读信号；
* 写信号；
* 中断请求；
* 中断响应；
* 总线请求；
* 总线允许；
* 时钟；
* 复位；
* 设备就绪等。

> **记忆**
>
> * 数据总线：**传什么**
> * 地址总线：**传到哪里**
> * 控制总线：**怎么传**

有些实际总线为了减少物理引脚数量，会采用 **地址/数据线复用**：同一组物理线路在不同时间分别传输地址和数据。

这能够减少线路数量和硬件成本，但地址与数据无法同时占用这组线路，因此**地址/数据复用本身不是提高总线数据传输率的方法**。

---

### 2. 按连接对象分类

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-002.svg" alt={"三类总线结构示意图"} />

#### 核内总线

用于 CPU 核内部各部件之间的信息交换，例如连接：

* 寄存器；
* ALU；
* 控制部件；
* 指令处理部件等。

#### 系统总线

连接计算机系统中的主要功能部件，例如：

* CPU；
* 主存；
* I/O 接口。

408 中讨论的“总线”通常主要指 **系统总线**。

#### 通信总线

用于不同计算机系统之间，或者计算机与其他外部系统之间通信，因此也常称为 **外部总线**。

---

### 3. 串行总线与并行总线

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-003.svg" alt={"b1 b0 b2 b4 b3 b5 b6 b7 b0 b1 b2 b3 b4 b5 b6 b7 并行总线 串行总线 集中传输多位 逐位传输数据"} />

#### 串行总线

串行传输是把一个数据字的各位 **按时间先后依次传输**。

特点：

* 所需数据线较少；
* 成本较低；
* 线路之间串扰较小；
* 更适合较长距离和高频传输；
* 现代高速互连大量采用串行技术。

常见串行标准：

| 标准                | 典型用途              |
| ----------------- | ----------------- |
| USB               | 键盘、鼠标、U 盘及其他外部设备  |
| PCI Express（PCIe） | GPU、网卡、NVMe SSD 等 |
| SATA              | SATA HDD、SATA SSD |
| Thunderbolt       | 高速外设、显示设备         |
| DisplayPort       | 显示设备              |
| HDMI              | 显示设备              |

#### 并行总线

并行传输使用多根数据线，在同一传输时刻同时传输多个数据位。

特点：

* 一次可以并行传输多个 bit；
* 适合距离较短的连接；
* 数据线越多，布线和同步越困难；
* 高频时会受到串扰、时钟偏斜等问题影响。

常见例子：

| 标准         | 说明          |
| ---------- | ----------- |
| PCI        | 传统并行扩展总线    |
| ISA        | 早期并行系统总线    |
| IDE / PATA | 早期并行磁盘接口    |
| DDR 内存通道   | 采用多根数据线并行传输 |

> **高频辨析**
>
> **PCI 是并行总线，PCIe 是高速串行互连。**
>
> **PATA 是并行 ATA，SATA 是串行 ATA。**

---

### 4. 同步总线与异步总线

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-004.svg" alt={"同步总线与异步总线时序对比"} />

#### 同步方式

通信双方按照统一的时钟节拍完成操作。

特点：

* 控制简单；
* 时序明确；
* 适合速度比较接近的部件；
* 慢速设备可能需要插入等待周期。

#### 异步方式

通信双方不依靠统一的固定节拍，而利用 **请求、回答等握手信号** 协调传输。

特点：

* 可以适应不同速度的设备；
* 不需要所有设备都在固定时刻完成操作；
* 控制逻辑通常比同步方式复杂。

后文的“同步定时”和“异步定时”就是这一思想在具体总线事务时序中的体现。

## 三、总线结构

### 1. 单总线结构

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-005.svg" alt={"外部设备1 外部设备2 外部设备n CPU 主存 I/O 接口 I/O 接口 I/O 接口 单总线结构"} />

单总线结构中，CPU、主存和多个 I/O 接口共享同一组主要系统总线。

优点：

* 结构简单；
* 成本低；
* 易于扩展设备。

缺点：

* 所有设备竞争同一总线；
* 总线容易成为系统瓶颈；
* 多个部件无法同时占用同一共享总线进行独立事务。

> **易错点**
>
> “单总线结构”并不等于“整个系统只有一根导线”。
>
> 系统总线本身仍然可以包含 **地址线、数据线和控制线**。
>
> 单总线强调的是主要部件**共享同一套系统互连资源**。

---

### 2. 多总线结构

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-006.svg" alt={"磁盘 打印机 I/O 接口 I/O 接口 通道/IO 处理器 CPU 主存 多总线结构 系统总线 存储总线 I/O 总线 键盘 I/O 接口 DMA 总线 高速外设 高速外设"} />

多总线结构设置多套具有不同功能的总线，例如：

* CPU—主存总线；
* I/O 总线；
* 高速扩展总线；
* DMA 相关数据通路。

优势是可以减少对同一总线的竞争，使不同类型的数据交换具有一定并行性，从而提高系统吞吐量。

---

### 3. 分层总线结构

现代计算机通常进一步采用 **分层互连结构**。

核心思想是：

> **不同速度、不同用途的设备连接到不同层次的互连，再由桥接器或控制器连接各层。**

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-007.svg" alt={"分层总线架构图"} />

典型现代系统中：

* CPU 通过集成内存控制器直接连接 DDR 主存；
* GPU 等高速设备通过 PCIe 与 CPU 或芯片组连接；
* NVMe SSD 使用 PCIe；
* USB、SATA、音频等设备通常由 PCH 等芯片组管理；
* CPU 与 PCH 之间通过 DMI 等高速互连通信。

这种设计使：

* 高速设备获得较低延迟和较高带宽；
* 低速设备可以集中管理；
* 不同设备不会全部竞争同一个低效的共享总线。

## 四、总线事务与总线周期

> **真题考查**
>
> * 选择题：2012 年第 19 题、2014 年第 20 题、2016 年第 21 题
> * 解答题：2013 年第 43 题

### 1. 总线事务

**总线事务（Bus Transaction）** 是主设备和从设备之间完成的一次完整信息交换过程。

一次事务通常完成：

* 一次读操作；
* 或一次写操作。

事务中主要存在两类角色。

#### 主设备

**主设备（Master）** 主动发起访问，并控制本次事务，例如：

* CPU；
* DMA 控制器。

主设备通常负责：

* 请求总线；
* 发出地址；
* 发出读写控制信号。

#### 从设备

**从设备（Slave）** 根据地址判断自己是否被访问，并对主设备的请求作出响应，例如：

* 主存；
* I/O 接口。

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-008.svg" alt={"总线事务（Bus Transaction） 主设备 Master 发起事务 · 发出地址/数据 控制读写信号 从设备 Slave 识别地址 · 响应读写 交换数据 · 发确认 地址总线 数据总线 总线事务的五个阶段 1 请求 Request 主设备发出 总线传输请求 2 仲裁 Arbitration 多设备竞争时 按优先级裁决 3 寻址 Addressing 放出目标地址 指定从设备 4 传输 Transfer 读/写数据 交换发生 5 终止 Termination 确认完成"} />

典型情况：

* CPU 访问主存时：CPU 是主设备；
* DMA 搬运数据时：DMA 控制器可以成为总线主设备；
* 主存或被访问的 I/O 接口通常作为从设备。

---

### 2. 总线周期

**总线周期（Bus Cycle）** 是完成一次总线事务所经历的时间。

> **事务强调“做了一次什么操作”，周期强调“完成它用了多长时间”。**

一个典型总线周期可以包含：

1. 总线请求；
2. 总线仲裁；
3. 寻址；
4. 数据传输；
5. 事务结束。

在具体同步总线中，这些过程可能被划分为若干时钟周期。

例如用四个节拍表示时，可记为：

$$
T_1,\quad T_2,\quad T_3,\quad T_4
$$

需要注意：

> **一个总线周期通常可以包含多个时钟周期。**
>
> 因此“时钟周期”和“总线周期”不能混为一谈。

---

## 五、突发传输与分离事务

### 1. 突发传输

**突发传输（Burst Transfer）** 的核心是：

> **一次寻址，连续传输多个数据。**

普通方式中，如果连续传送四个数据，每次都可能需要重新完成：

* 地址；
* 控制；
* 数据。

突发方式则只需要开始时给出起始地址，后续地址可以自动递增，从而连续传送多个数据单元。

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-009.svg" alt={"突发（Burst）总线传输事务 ❌ 普通传输方式（非突发） 每次传输都需要重新发送地址，浪费总线带宽 时钟周期: ADDR1 DATA1 ADDR2 DATA2 ADDR3 DATA3 ADDR4 DATA4 T1 T2 T3 T4 T5 T6 T7 T8 事务 ① 事务 ② 事务 ③ 事务 ④ 总耗时：8 个时钟周期 每传输 1 个数据 = 1 个地址周期 + 1 个数据周期，总线利用率仅 50% ✅ 突发传输方式（Burst） 仅发送一次起始地址，后续地址自动递增 时钟周"} />

优点：

* 减少地址阶段开销；
* 减少控制开销；
* 提高有效数据传输率；
* 非常适合连续块数据传送。

典型应用包括：

* Cache Line 填充；
* 内存块传输；
* DMA；
* 连续存储器访问。

---

### 2. 哪些方法能够提高数据传输率

常见措施：

| 方法       | 主要作用         |
| -------- | ------------ |
| 增大数据总线宽度 | 每次传更多数据      |
| 提高有效传输频率 | 单位时间传更多次     |
| 突发传输     | 降低寻址和控制开销    |
| 地址/数据复用  | 主要减少物理线路数量   |
| 分离事务     | 主要减少等待时的总线占用 |

因此：

* **增宽总线、提高频率、突发传输**可以直接提高有效数据传输能力；
* **地址/数据复用**主要为了节省引脚和线路；
* **分离式事务（Split Transaction）**主要提高总线利用率。

### 3. 分离式事务

普通事务中，主设备发出读请求后，如果从设备尚未准备好数据，总线可能长期被本次事务占据。

分离式事务将过程拆成：

1. **请求事务**；
2. **应答事务**。

主设备发出请求后即可释放总线，从设备准备好数据后再申请总线完成响应。

这样其他主设备可以在等待期间使用总线。

> **辨析**
>
> * **数据传输率**：单位时间真正传输了多少数据；
> * **总线利用率**：总线有多少时间真正被有效使用。
>
> 二者相关，但不是完全相同的指标。

## 六、总线定时

> **真题考查**
>
> * 选择题：2015 年第 19 题

不同设备的响应速度不同，因此必须规定：

* 地址什么时候有效；
* 控制信号什么时候有效；
* 数据什么时候可以读取；
* 一次事务什么时候结束。

这就是 **总线定时（Bus Timing）**。

主要有：

* 同步定时；
* 异步定时。

---

### 1. 同步定时

同步定时中，各设备使用统一的总线时钟。

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-010.svg" alt={"T1 T2 T3 T4 总线传输周期 时钟 地址 读命令 数据"} />

以一次典型读事务为例：

* `T1`：主设备给出地址；
* `T2`：主设备发出读控制信号；
* `T3`：从设备给出数据；
* `T4`：撤销有关信号，事务结束。

特点：

* 时序固定；
* 控制简单；
* 实现容易；
* 对设备速度差异的适应能力较弱。

如果慢速设备无法在规定时间内准备好数据，可以插入 **等待周期（Wait State）**。

> **核心记忆**
>
> **同步定时看“时钟”。**

---

### 2. 异步定时

异步定时不使用固定统一的节拍要求，而采用 **请求/回答握手**。

通常：

1. 主设备发出请求信号 `REQ`；
2. 从设备完成准备后发出回答信号 `ACK`；
3. 双方通过信号变化确认操作完成。

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-011.svg" alt={"总线定时的异步方式：请求/回答握手信号时序图"} />

优点：

* 能适应速度差异较大的设备；
* 无需按照最慢设备固定整个总线节拍。

缺点：

* 控制逻辑更复杂；
* 握手本身存在额外控制开销。

---

### 3. 异步通信的三种互锁方式

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-012.svg" alt={"不互锁 半互锁 全互锁 主设备 从设备"} />

#### 不互锁

双方的信号都按照预定时间自行撤销，不必等待对方确认。

特点：

* 控制简单；
* 对时序假设要求高；
* 可靠性最低。

#### 半互锁

主设备发出请求后：

* 必须等从设备回答，才撤销请求；

但从设备的回答信号：

* 可以经过固定时间自行撤销。

#### 全互锁

双方都要确认对方的状态变化：

1. 主设备发请求；
2. 从设备收到请求后发回答；
3. 主设备看到回答后撤销请求；
4. 从设备看到请求撤销后再撤销回答。

可靠性最高，但握手过程也最完整。

| 项目        | 同步定时 | 异步定时          |
| --------- | ---- | ------------- |
| 控制依据      | 统一时钟 | REQ/ACK 等握手信号 |
| 操作节拍      | 固定   | 由通信双方响应速度决定   |
| 控制复杂度     | 较低   | 较高            |
| 设备速度差异适应性 | 较弱   | 较强            |

> **同步看时钟，异步看握手。**

## 七、总线性能指标与计算

> **真题考查**
>
> * 选择题：2009 年第 20 题、2014 年第 19 题、2018 年第 21 题、2019 年第 19 题、2020 年第 19 题、2023 年第 20 题、2024 年第 20 题、2025 年第 20 题

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-013.svg" alt={"总线通信指标图解 ① 时钟频率（Clock Frequency） 时钟信号（100MHz → 周期 T = 10ns） T = 10 ns 每个脉冲上升 / 下降 = 1 个时钟周期 时钟频率 = 1 / T　（单位：Hz） ② 总线传输周期（Bus Transfer Cycle） 一次完整数据传输 = 多个时钟周期（示例：N = 4） 申请 寻址 传输数据 结束 T T T T 总线传输周期 = N × T（N = 4） 包含四个阶段： 🔹 申请 — 设备请求总线使用权 🔹"} />

### 1. 时钟周期与时钟频率

设时钟周期为 $T$，时钟频率为 $f$，则：

$$
f=\frac{1}{T}
$$

例如时钟频率为 100 MHz，则：

$$
T=\frac{1}{100\times10^6}
 =10\ \text{ns}
$$

---

### 2. 总线传输周期

如果一次数据传输需要 $N$ 个时钟周期，则：

$$
T_{\text{bus}}=N T
$$

如果每个总线周期只完成一次数据传输，则单位时间内能够完成的总线传输次数为：

$$
f_{\text{transfer}}
=\frac{1}{T_{\text{bus}}}
=\frac{f}{N}
$$

> **高频易错点**
>
> **时钟频率不一定等于数据传输频率。**
>
> 若一次总线传输需要多个时钟周期，则真正完成数据传输的频率会低于时钟频率。

---

### 3. 一个时钟周期传输多次数据

有些系统可以在一个时钟周期中完成多次数据传输。

例如：

* SDR：通常每周期传输一次；
* DDR：两个时钟边沿均可传输数据，因此每周期传输两次。

若每个时钟周期可以完成 $M$ 次有效数据传输，则有效数据传输频率为：

$$
f_{\text{transfer}}=M f
$$

这里的 $M$ 是 **每周期有效传输次数**。

---

### 4. 总线宽度

<InlineSvg src="/images/computer-organization/computer-organization-bus-bus-014.svg" alt={'总线宽度 & 总线带宽 图解 ① 总线宽度（Bus Width） 总线上能同时传输的数据位数 = 数据线的根数 8 位总线（8 根数据线） 1 0 1 1 0 0 1 0 8 根 → 每次传 1 字节 32 位总线（32 根数据线） 32 根 → 每次传 4 字节（位宽越宽，单次传输越多） 位宽决定"并行通道数" 8 位 → 1 字节 / 次 16 位 → 2 字节 / 次 32 位 → 4 字节 / 次 64 位 → 8 字节 / 次 ② 总线带宽（Bus Bandwidt'} />

总线宽度通常指 **数据总线宽度**。

例如：

|   总线宽度 | 每次最多传输数据 |
| -----: | -------: |
|  8 bit |   1 Byte |
| 16 bit |   2 Byte |
| 32 bit |   4 Byte |
| 64 bit |   8 Byte |

若总线宽度为 $W$ bit，则一次传输的数据量为：

$$
\frac{W}{8}\ \text{Byte}
$$

---

### 5. 总线带宽

**总线带宽**表示单位时间理论上能够传输的最大数据量。

若：

* 数据总线宽度为 $W$ bit；
* 有效传输频率为 $f_{\text{transfer}}$；

则：

$$
B
=
\frac{W}{8}
\times
f_{\text{transfer}}
$$

若每个时钟周期完成 $M$ 次传输，且时钟频率为 $f$，则：

$$
B
=
\frac{W}{8}
\times
f
\times
M
$$

如果存在 $C$ 个能够并行工作的数据通道，还可写成：

$$
B
=
\frac{W}{8}
\times
f
\times
M
\times
C
$$

其中带宽常用：

* MB/s；
* GB/s。

---

### 6. 总线计算题统一方法

遇到总线计算题，先判断题目究竟问：

* 最大带宽；
* 有效数据传输率；
* 总线周期；
* 传输整个数据块所需时间。

#### 情形一：直接求带宽

先确定：

1. 一次传多少 Byte；
2. 每秒传多少次。

即：

$$
\text{带宽}
=
\text{每次传输数据量}
\times
\text{每秒传输次数}
$$

#### 情形二：一次传输需要多个时钟周期

若一个传输周期需要 $N$ 个时钟周期，且每个总线周期完成一次数据传输：

$$
f_{\text{transfer}}=\frac{f}{N}
$$

再代入：

$$
B
=
\frac{W}{8}
\times
\frac{f}{N}
$$

#### 情形三：DDR 等每周期多次传输

若一个时钟周期传 $M$ 次：

$$
B
=
\frac{W}{8}
\times
f
\times
M
$$

#### 情形四：突发传输

不能简单地把每个数据单元都重新计算完整地址阶段。

一般应把时间拆成：

$$
T_{\text{total}}
=
T_{\text{启动/寻址}}
+
T_{\text{连续数据传输}}
$$

突发长度越大，地址和控制开销被摊薄得越充分。

#### 情形五：非突发传输

若每个数据单元都必须重新经历完整总线事务，则：

$$
T_{\text{total}}
=
N_{\text{data}}
\times
T_{\text{单次事务}}
$$

> **做题口诀**
>
> **先看一次传多少，再看一秒传几次；突发传输单独算首地址开销。**

## 八、常见总线和接口标准

需要认识的常见名称包括：

* ISA；
* EISA；
* PCI；
* PCIe；
* IDE / PATA；
* SATA；
* USB。

### 1. PCI

**PCI（Peripheral Component Interconnect）** 是早期常用的主板扩展总线，用于连接：

* 网卡；
* 声卡；
* 扩展控制卡等。

传统 PCI 是并行总线，后来逐步被 PCI Express 取代。

![PCI 扩展槽](/images/computer-organization/computer-organization-bus-bus-015.jpg)

---

### 2. SATA

**SATA（Serial ATA）** 是面向存储设备的串行连接标准，曾广泛用于：

* HDD；
* SATA SSD；
* 光驱。

![](/images/computer-organization/computer-organization-bus-bus-016.jpg)

其连接器通常呈明显的 L 形。

---

### 3. ISA 与 EISA

**ISA** 是早期扩展总线体系。

传统 ISA 主要为 16 位架构，EISA 是其扩展版本，现均已基本淘汰。

---

### 4. IDE / PATA

IDE/PATA 是早期硬盘和光驱常用的并行连接方式，后来主要被 SATA 替代。

---

### 5. USB

**USB（Universal Serial Bus）** 是广泛使用的外部设备连接标准。

典型设备：

* 键盘；
* 鼠标；
* U 盘；
* 打印机等。

![](/images/computer-organization/computer-organization-bus-bus-017.webp)

> **缩写辨析**
>
> 真题可能把总线标准和其他计算机名词混在一起。
>
> * ISA、EISA、PCI、PCIe：总线/互连标准；
> * CRT：显示器件；
> * CPI：性能指标；
> * RAM：存储器；
> * MIPS：性能指标。
>
> 不要看到英文缩写就默认是总线。

## 九、总线、接口和协议的区别

三者经常混淆。

* **接口/插槽**：设备在物理上如何连接；
* **总线/互连**：信息通过什么硬件通路传送；
* **协议**：通信双方按照什么规则组织和解释信息。

| 实际设备         | 物理接口            | 协议        | 底层互连 |
| ------------ | --------------- | --------- | ---- |
| SATA SSD     | SATA 接口         | AHCI 等    | SATA |
| M.2 SATA SSD | M.2             | AHCI      | SATA |
| M.2 NVMe SSD | M.2             | NVMe      | PCIe |
| PCIe 显卡      | PCIe 插槽         | PCIe 协议体系 | PCIe |
| USB U 盘      | USB-A / USB-C 等 | USB       | USB  |

其中：

* **M.2**主要描述物理接口/规格；
* **NVMe**主要是面向非易失性存储设备的协议；
* SATA、PCIe、USB 等术语在实际语境中可能同时涉及接口、协议和互连标准。
