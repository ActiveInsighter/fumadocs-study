## 6.5.1 为什么中断之后还需要 DMA

中断方式已经让 CPU 不必一直等待外设，但高速设备每产生一小批数据就中断一次，CPU 仍需要：

- 响应中断；
- 执行 ISR；
- 通过端口读写；
- 把数据在 I/O 与主存之间搬运。

**DMA（Direct Memory Access）**&#x2060;把大块数据搬运从 CPU 指令流中剥离出来：

> **CPU 负责配置和收尾，DMA 控制器负责数据块的直接搬运。**

典型数据路径：

```text
I/O 接口 ⇄ DMA 数据通路 ⇄ 主存
```

而不是：

```text
I/O 接口 ⇄ CPU 通用寄存器 ⇄ 主存
```

## 6.5.2 “DMA 不经过 CPU”应该怎样准确理解

408 里常说“DMA 数据不经过 CPU”，准确含义是：

> **数据不需要由 CPU 执行 load/store 或 I/O 指令，逐个数据单位经过 CPU 通用寄存器搬运。**

现代机器中物理传输仍可能经过：

- SoC 内部互连；
- 总线仲裁器；
- IOMMU；
- 内存控制器；
- Cache 一致性结构。

这些不改变 DMA 的考试本质：**CPU 核心不负责逐项搬运**。

## 6.5.3 DMA 控制器的典型寄存器

| 部件 | 作用 |
| --- | --- |
| MAR | 当前主存地址 |
| DC / Count | 剩余传输数量 |
| DR / Buffer | 暂存当前传输数据 |
| CR / Status | 方向、模式、状态、控制信息 |
| I/O 控制逻辑 | 与设备协调 |
| 总线控制逻辑 | 请求并控制系统总线/主存访问 |

### MAR

保存当前要访问的主存地址。连续传送时通常自动增加或按配置更新。

### DC

记录剩余数据量。每完成一个传输单位，计数器按规则递减；达到终止条件表示整个块完成。

### DR

作为 DMA 控制器内部的数据缓冲或暂存部件。具体实现可能不同，考试按题设理解。

### CR / 状态寄存器

常保存：

- 输入/输出方向；
- 传输模式；
- 设备/通道选择；
- 完成/错误状态。

## 6.5.4 DMA 的“块传输”不是“一次总线周期传完整块”

设 CPU 配置一个 $D$ Byte 的数据块，DMA 每次数据通路传 $w$ Byte。底层仍需要多次传送：

$$
K=\left\lceil\frac{D}{w}\right\rceil
$$

大致可理解为：

```text
CPU 配置一次
→ DMA 自动重复 K 次数据传送
→ 整块结束后通知 CPU
```

“以块为单位”的含义是：

> **CPU 以块为粒度下达任务，而不是每传一个字都重新参与控制。**

## 6.5.5 DMA 的完整工作过程

可以固定记成三阶段：

> **预处理 → 数据传送 → 后处理**

### 预处理：CPU 配置

CPU 设置：

- 设备或 I/O 地址；
- 主存起始地址；
- 传输长度；
- 传输方向；
- DMA 工作模式。

随后 CPU 可以继续执行其他程序。

### 设备准备并发 DMA 请求

外设准备好输入数据，或已经可以接收输出数据时，向 DMA 控制逻辑提出传送需求。

### DMA 申请互连/主存使用权

DMA 向 CPU 或总线仲裁器发出总线请求，竞争主存访问所需资源。

### 获得控制权并传送

DMA 成为本次事务的主设备，组织：

```text
I/O 接口 ⇄ 主存
```

每完成一个传输单位，通常：

- 更新 MAR；
- 更新 DC；
- 判断数据块是否结束。

### 释放资源

本轮或整个块完成后释放总线/主存访问权。

### 后处理：完成中断

整个 DMA 块完成后，控制器通常向 CPU 发出完成中断。CPU 再做：

- 检查状态；
- 错误处理；
- 更新 I/O 请求；
- 唤醒等待任务；
- 安排下一批传输。

> **关键对比**
>
> - 中断 I/O：设备请求 **CPU 来服务并搬数据**；
> - DMA：设备/DMA 控制器请求 **数据通路/总线资源，由 DMA 搬数据**；
> - DMA 块结束后又常用 **中断**通知 CPU。

## 6.5.6 CPU 与 DMA 为什么会争用主存

CPU 取指、读写操作数需要访问主存；DMA 也要直接访问主存，因此两者可能竞争：

- 系统总线；
- 内存控制器；
- 存储器周期。

传统教材常归纳三种协调方式。

### DMA 独占一段时间

DMA 获得使用权后连续传一批数据。

- DMA 效率高；
- CPU 一段时间内不能通过被占用资源访问主存。

### 周期挪用 Cycle Stealing

DMA 每次只“拿走”一个或少数几个主存/总线周期：

```text
CPU  CPU  DMA  CPU  CPU  DMA  CPU ...
```

此时 CPU 并非整个数据块期间都不能访问主存，只是在被 DMA 挪用的特定周期暂时失去该资源。

> **2020 类型高频陷阱**
>
> 周期挪用不等于 DMA 从开始到结束一直霸占总线。CPU 在未被挪用的周期仍可访问主存。

### 固定分时/透明方式

预先把可用时隙分给 CPU 和 DMA，或让 DMA 尽量使用 CPU 暂不访问主存的时间。教材名称可能不同，做题以题设规则为准。

## 6.5.7 为什么 DMA 往往比 CPU 具有更高总线优先级

高速 I/O 的缓冲区通常有限。数据到达后若不能及时转移：

- 输入数据可能覆盖、溢出；
- 输出设备可能断流。

CPU 通常可以短暂停顿，而实时到达的数据可能不能等。因此传统 408 模型中：

> **发生直接冲突时，DMA 常被赋予高于 CPU 的主存/总线访问优先级。**

这是“资源调度优先级”，不代表 DMA 的计算能力高于 CPU。

## 6.5.8 周期挪用的请求次数

若：

- 数据块大小为 $D$ Byte；
- I/O 接口/DMA 每次传送的数据缓冲单位为 $w$ bit；
- 每准备好一个缓冲单位就发起一次 DMA 总线请求；

则每次可传：

$$
q=\frac{w}{8}\ \text{Byte}
$$

总线请求/数据传送次数通常为：

$$
N=\left\lceil\frac{D}{q}\right\rceil
$$

例如一个扇区 512 Byte、缓冲寄存器 64 bit = 8 Byte，则：

$$
N=\frac{512}{8}=64
$$

次。

> **注意题设语言**
>
> “每个数据块一次 DMA”与“每个缓冲单位一次总线请求”不是同一层次。一个 DMA 块任务内部完全可能包含很多次总线请求。

## 6.5.9 DMA 的 CPU 开销模型

设：

- 外设数据率为 $R$ Byte/s；
- 每个 DMA 块大小为 $D$ Byte；
- CPU 每启动并完成处理一个 DMA 块共花 $C_{\text{dma}}$ 个时钟周期；
- CPU 主频为 $f_{\text{cpu}}$。

每秒 DMA 块数：

$$
r_{\text{dma}}=\frac{R}{D}
$$

CPU 用于 DMA 管理的时间占比近似为：

$$
\eta_{\text{dma}}
=\frac{r_{\text{dma}}C_{\text{dma}}}{f_{\text{cpu}}}
$$

这解释了为什么**增大 DMA 块粒度**通常可以显著减少 CPU 每秒被打扰的次数。
