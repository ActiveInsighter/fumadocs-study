## 6.6.1 通道：从“自动搬数据”进化到“自动执行 I/O 程序”

**通道（Channel）**&#x2060;是在 DMA 思想上进一步提高 I/O 自主能力的专用处理部件，传统上常见于大型机或 I/O 设备很多的系统。

DMA 的能力重点是：

> **按 CPU 给出的参数自动搬运一个数据块。**

通道进一步能够：

> **执行存放在主存中的通道程序，自主组织一系列 I/O 操作。**

因此通道可理解为一种**专用 I/O 处理机**。

## 6.6.2 通道程序与执行过程

典型流程：

1. CPU 在主存中准备通道程序；
2. CPU 将通道程序首地址等信息交给通道；
3. CPU 启动通道；
4. 通道独立执行通道程序；
5. 通道组织设备与主存的数据交换；
6. CPU 同时执行其他程序；
7. I/O 任务完成后，通道向 CPU 发出结束中断。

通道程序中可包含：

- 操作哪个设备；
- 执行何种 I/O 操作；
- 主存地址；
- 数据长度；
- 后续通道指令位置等。

> **高频易错点**
>
> 通道程序由**通道执行**，不是 CPU 逐条执行。CPU 负责启动和最终处理结果。

## 6.6.3 DMA 与通道的本质区别

| 对比项 | DMA | 通道 |
| --- | --- | --- |
| 主要能力 | 自动完成块数据传送 | 执行通道程序、组织复杂 I/O |
| 指令执行能力 | 通常没有通用意义上的 I/O 程序执行能力 | 有专用指令/通道程序能力 |
| CPU 参与 | 配置 + 完成中断 | 启动任务 + 完成中断 |
| 适合 | 高速、大块传输 | 多设备、复杂 I/O 管理 |
| 自主性 | 高 | 更高 |

## 6.6.4 四种 I/O 方式一张表

| 比较维度 | 程序查询 | 程序中断 | DMA | 通道 |
| --- | --- | --- | --- | --- |
| CPU 是否忙等待 | 是 | 否 | 否 | 否 |
| 如何发现/组织设备事件 | CPU 主动查询 | 设备中断 CPU | DMA 控制器协调 | 通道执行程序 |
| 实际数据搬运主体 | CPU | CPU | DMA 控制器/数据通路 | 通道控制的数据通路 |
| 数据是否经 CPU 通用寄存器逐项搬运 | 是 | 是 | 否 | 否 |
| CPU 介入粒度 | 几乎全程 | 每次服务事件 | 块首配置 + 块尾处理 | 任务首尾 |
| 硬件复杂度 | 最低 | 较低 | 较高 | 最高 |
| I/O 自主性 | 最弱 | 较弱 | 强 | 最强 |

演进主线：

> **程序查询 → 程序中断 → DMA → 通道：CPU 参与越来越少，I/O 子系统自主性越来越强。**

## 6.6.5 DMA 请求与中断请求不是一回事

### 中断请求

目标是：

> **要求 CPU 暂停当前正常控制流并处理某事件。**

它消耗的是 CPU 的处理时间和中断处理机制。

### DMA 请求

目标是：

> **要求获得直接数据传输所需的总线/主存访问资源。**

它主要涉及互连和存储器访问权。

DMA 任务完成后，控制器又常发一个**完成中断**，所以同一个 DMA 任务中可以同时出现：

- 多次 DMA 数据传送/总线请求；
- 最后一次 DMA 完成中断。

## 6.6.6 高频概念陷阱

### 陷阱 1：中断 I/O 的数据不经过 CPU

错误。

中断方式只是让 CPU 不再忙等待；ISR 中的数据搬运通常仍由 CPU 指令完成。

### 陷阱 2：DMA 完全不需要 CPU

错误。

CPU 至少通常需要：

- 初始化 DMA；
- 设置主存地址和数量；
- 设置方向/模式；
- 启动任务；
- 处理完成或异常中断。

### 陷阱 3：一个 DMA 数据块只产生一次总线访问

错误。

“块”是 CPU 的任务粒度；底层仍可包含很多次数据 beat 和总线请求。

### 陷阱 4：周期挪用时 CPU 整块期间都不能访存

错误。

DMA 只在被挪用的那些存储器/总线周期占用资源，其余周期 CPU 仍可访问。

### 陷阱 5：I/O 端口就是物理插口

错误。

408 中端口通常是 **I/O 接口内部可被 CPU 编址访问的寄存器**。

### 陷阱 6：地址总线宽度决定一次传多少数据

错误。

- 地址总线：决定可区分的地址数量；
- 数据总线：决定一次数据传输的位数。

### 陷阱 7：总线周期 = 时钟周期

通常错误。若一个总线传送需要 $N$ 个时钟周期：

$$
T_{\text{bus}}=N T_{\text{clk}}
$$

### 陷阱 8：地址/数据复用会直接提高带宽

通常错误。复用主要用于减少引脚；若地址和数据共用线路，还需要分时使用。

## 6.6.7 I/O 综合题统一解法

遇到查询/中断/DMA 综合计算，先画四层：

```text
① 外设产生/消费数据的速率
② 每次事件或每次 DMA 块处理多少数据
③ CPU 每次介入消耗多少周期
④ 总线/主存每次数据传输需要多少周期
```

然后分别算。

### 第一步：事件频率

若数据率为 $R$ Byte/s，每次事件处理 $q$ Byte：

$$
r=\frac{R}{q}
$$

### 第二步：CPU 开销

每次 CPU 介入花 $C$ 周期，则：

$$
C_{\text{per second}}=rC
$$

若 CPU 主频为 $f_{\text{cpu}}$：

$$
\eta_{\text{CPU}}=\frac{rC}{f_{\text{cpu}}}
$$

### 第三步：总线占用

若每次数据传输占 $c_b$ 个总线时钟周期，一秒要传 $r_b$ 次，则一秒消耗的总线周期数：

$$
C_{\text{bus/s}}=r_b c_b
$$

若题目要求总线利用率，再除以一秒内可用的总线时钟周期数。

### 第四步：看是否有重叠

外设准备、CPU 执行、DMA 传输有时可以并行。题目问“总历时”时必须判断这些阶段：

- 串行累加；
- 还是可重叠取最大值；
- 是否有启动/结束一次性开销。

**不能把所有时间无脑相加。**

## 6.6.8 总线性能综合题模板

若题目给：

- 总线宽度 $W$ bit；
- 时钟频率 $f$；
- 每个传送需 $N$ 周期；
- 每周期有效传输次数 $M$；

先判断题意对应哪一种模型。

若“每 $N$ 个时钟完成一次 $W$ bit 传送”：

$$
B=\frac{W}{8}\times\frac{f}{N}
$$

若“每时钟周期有 $M$ 个有效数据 beat”：

$$
B=\frac{W}{8}\times f\times M
$$

再根据仲裁、等待、协议开销求有效值。

## 6.6.9 整章知识链

```text
总线
├─ 传什么：数据 / 地址 / 控制
├─ 怎么连：单总线 / 多总线 / 分层互连
├─ 谁发起：主设备 / 从设备 / 仲裁
├─ 怎么定时：同步 / 异步握手
├─ 怎么提速：加宽 / 提频 / 多次传输 / 突发 / 分离事务
└─ 怎么算：一次传多少 × 每秒传几次

I/O
├─ I/O 接口：缓冲、转换、控制、状态
├─ I/O 端口：数据 / 状态 / 控制寄存器
├─ 编址：MMIO / PMIO
└─ 数据传送方式
   ├─ 查询：CPU 等 + 搬
   ├─ 中断：CPU 不等，但搬
   ├─ DMA：CPU 不等，也不逐项搬
   └─ 通道：还能执行通道程序
```

> **章末一句话**
>
> **总线解决“信息怎样在部件之间传”，I/O 控制方式解决“设备事件由谁发现、数据由谁搬、CPU 在何时介入”。**
