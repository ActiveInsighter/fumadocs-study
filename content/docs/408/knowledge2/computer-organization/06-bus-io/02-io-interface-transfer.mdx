## 十、输入/输出系统

**输入/输出系统（I/O System）**&#x2060;负责主机和外部设备之间的信息交换。

以主机为参照：

* 外部设备 → 主机：**输入**；
* 主机 → 外部设备：**输出**。

I/O 系统最重要的问题是：

> **CPU 很快，外设往往很慢，二者如何高效协同？**

---

### 十一、I/O 系统的基本结构

#### 1. 传统简单结构

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-001.svg" alt={"CPU 设备控制器 （I/O 接口） 外设 （如键盘/打印机） 控制 / 地址 / 数据 控制 / 地址 / 数据线"} />

一个典型的简化模型包括：

* CPU；
* 主存；
* I/O 接口或设备控制器；
* 外部设备。

#### CPU

CPU 负责：

* 发出 I/O 命令；
* 查询设备状态；
* 访问 I/O 接口；
* 必要时参与数据搬运；
* 处理中断。

#### 外设

外设负责与现实环境或外部存储介质交换信息，例如：

* 键盘；
* 鼠标；
* 打印机；
* 磁盘；
* 显示设备等。

#### I/O 接口

CPU 与外设之间通常不能直接简单连接，因为两者存在：

* 速度差异；
* 数据格式差异；
* 控制方式差异；
* 电气特性差异。

因此需要 **I/O 接口**在中间协调。

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-002.svg" alt={"CPU 发出指令 / 处理数据 内存 存放程序与数据 主机 (Host) I/O 总线 地址线 · 数据线 · 控制线 I/O 接口 设备控制器 控制逻辑 · 寄存器 接口插座 物理连接端口 接口电缆 USB · SATA · HDMI · VGA ... 外设 键盘 鼠标 显示器 磁盘 打印机 主机侧 系统总线 桥接层 外部线缆 外设侧"} />

> **I/O 接口与设备控制器**
>
> 两个概念的侧重点不同：
>
> * **设备控制器**强调设备控制逻辑；
> * **I/O 接口**强调主机与外设之间的信息交换接口。
>
> 在很多教材和具体硬件中，两者的功能高度重叠，考试语境下常结合理解。

---

#### 2. 现代 I/O 架构

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-003.svg" alt={"核心 / 缓存 IMC（内存控制器） PCIe 控制器 DMA 控制器等 PCH / 芯片组 （南桥） 高速互联（如 DMI） SATA 控制器 USB 控制器 硬盘 / SSD 鼠标 / 键盘 / U盘等 CPU (SoC) 主存（DDR4/DDR5） 内存总线 NVMe SSD 显卡 PCIe 总线 PCIe 总线"} />

现代 CPU 中已经集成大量传统上由芯片组负责的功能，例如：

* 内存控制器；
* PCIe 控制器；
* 高速互连接口。

常见结构是：

* DDR 内存直接连接 CPU 的内存控制器；
* GPU、NVMe SSD 等高速设备通过 PCIe；
* USB、SATA、音频、部分网卡等由 PCH 管理；
* PCH 与 CPU 通过 DMI 等高速互连通信。

这一部分主要帮助理解现代机器，与 408 的传统逻辑结构并不冲突。

---

#### 3. I/O 的软件层次

I/O 不仅包括硬件，也包括操作系统中的软件支持。

典型软件层次包括：

* 用户层 I/O 软件；
* 设备独立性软件；
* 设备驱动程序；
* 中断处理程序。

通过这种分层，应用程序无需直接了解具体硬件控制方法。

## 十二、I/O 接口

> **真题考查**
>
> * 选择题：2014 年第 21 题、2017 年第 21 题、2021 年第 20 题

### 1. I/O 接口的主要功能

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-004.svg" alt={"CPU 数据缓冲 寄存器 状态寄存器 控制寄存器 I/O 控制逻辑 地址译码器及 设备选择电路 外设 接口 控制 逻辑 地址线 控制线 数据线 地址信号 控制信号 设备 地址 交互 数据 设备状态 控制命令 外设1 控制 状态 数据 外设 接口 控制 逻辑 外设1 控制 状态 数据 外设 接口 控制 逻辑 外设1 控制 状态 数据 I/O 接口"} />

I/O 接口主要承担以下功能。

#### 数据缓冲

CPU 和主存的速度往往远高于外设。

因此接口中通常设置 **数据缓冲寄存器**，临时保存正在传输的数据，实现速度匹配。

#### 数据格式转换

例如：

* 串行 ↔ 并行；
* 数字信号与设备所需格式之间的转换。

#### 控制与定时

协调：

* 主机；
* I/O 接口；
* 外设

三者之间动作的先后次序。

#### 状态与错误检测

接口通过状态寄存器保存：

* 就绪；
* 忙；
* 错误；
* 传输完成等信息。

CPU 可读取这些状态。

#### 主机与设备通信

I/O 接口一侧连接主机总线，另一侧连接具体外设，因此同时承担两侧的通信组织工作。

## 十三、I/O 端口

**I/O 端口**是 **I/O 接口中能够被 CPU 直接访问的寄存器**。

注意：

> **I/O 端口不是单纯指电脑机箱上的 USB 插孔。**
>
> 408 中的“端口”主要指接口电路内部供 CPU 访问的寄存器。

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-005.svg" alt={"I/O 端口 I/O 端口 CPU I/O  总线 I/O 接口 I/O 控制器 I/O  设备"} />

---

### 1. I/O 端口的类型

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-006.svg" alt={"CPU 设备 I/O 接口 控制寄存器 状态寄存器 输入寄存器 输出寄存器"} />

#### 数据端口

保存 CPU 和设备之间交换的数据。

可能包含：

* 输入数据寄存器；
* 输出数据寄存器；
* 双向数据寄存器。

#### 状态端口

保存设备当前状态，例如：

* Ready；
* Busy；
* Error；
* Done。

通常主要由 CPU 读取。

#### 控制端口

接收 CPU 向设备发出的命令，例如：

* 启动；
* 停止；
* 复位；
* 设置工作模式。

通常主要由 CPU 写入。

---

## 十四、I/O 端口编址

I/O 端口必须具有能够被 CPU 识别的地址。

主要有两种方式：

1. **统一编址**；
2. **独立编址**。

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-007.svg" alt={"内存地址 （共960KB) 端口地址 （共64KB) 0 EFFFFH F0000H FFFFFH 内存地址 （共960KB) 端口地址 （共64KB) 0 FFFFH 0 FFFFFH 统一编址 独立编址"} />

---

### 1. 统一编址

统一编址又称：

**内存映射 I/O（Memory-Mapped I/O，MMIO）**。

核心思想：

> **把设备寄存器放进与主存相同的地址空间中。**

CPU 看来，一个设备寄存器就像某个特殊内存地址。

因此 CPU 可以使用普通访存指令访问设备。

例如：

```asm
MOV EAX, [0xF0001000]
MOV [0xF0001000], EBX
```

虽然形式上像访问内存，但地址译码最终可能选中的是设备寄存器，而不是 RAM。

#### 优点

* 不需要独立 I/O 指令；
* 可以使用丰富的普通访存指令；
* 地址译码和编程模型统一。

#### 缺点

* 设备寄存器会占用一部分统一地址空间。

现代 ARM、RISC-V 以及大量 PCIe 设备主要使用这种方法。

---

### 2. 独立编址

独立编址又称：

**端口映射 I/O（Port-Mapped I/O，PMIO）**。

它为 I/O 端口建立独立于主存的地址空间。

因此系统中同时存在：

* 主存地址空间；
* I/O 地址空间。

CPU 使用专门的 I/O 指令访问端口。

例如传统 x86：

```asm
IN  AL, 0x60
OUT 0x3F8, AL
```

一些经典端口号包括：

* 键盘控制器：`0x60`、`0x64`；
* COM1：`0x3F8`；
* LPT1：`0x378`。

---

### 3. 两种编址方法对比

| 项目            | 统一编址              | 独立编址       |
| ------------- | ----------------- | ---------- |
| 别名            | MMIO              | PMIO       |
| 主存与 I/O 地址空间  | 共用一套              | 两套独立地址空间   |
| 是否占用统一地址空间    | 是                 | 否          |
| 普通访存指令访问      | 可以                | 通常不可以      |
| 是否需要专用 I/O 指令 | 不需要               | 需要         |
| 典型访问          | `MOV`、`LDR`、`STR` | `IN`、`OUT` |

> **408 必记**
>
> **统一编址：同一个地址空间，普通访存指令。**
>
> **独立编址：两个地址空间，专用 I/O 指令。**

## 十五、I/O 数据传送方式

> **真题考查**
>
> * 选择题：2011 年第 22 题、2023 年第 22 题
> * 解答题：2018 年第 43 题

由于外设速度远低于 CPU，如果 CPU 全程等待设备，就会严重浪费处理器资源。

因此 I/O 控制方式不断发展，其总体趋势是：

> **CPU 参与得越来越少，I/O 系统的自主能力越来越强。**

主要有四种：

1. 程序查询；
2. 程序中断；
3. DMA；
4. 通道。

先用一张表建立整体框架。

| I/O 方式 | CPU 是否等待设备准备 | 数据是否经 CPU 寄存器搬运 | 专用硬件自主能力   |
| ------ | ------------ | --------------- | ---------- |
| 程序查询   | 是            | 是               | 很低         |
| 程序中断   | 否，可执行其他程序    | 是               | 较低         |
| DMA    | 否            | 否               | 较高         |
| 通道     | 否            | 否               | 很高，可执行通道程序 |

> **最重要的比较维度**
>
> 做题时优先问三个问题：
>
> 1. **谁等待？**
> 2. **谁搬数据？**
> 3. **CPU 什么时候介入？**

---

## 十六、程序查询方式

程序查询方式又称 **程序轮询方式**。

CPU 主动反复读取设备的状态寄存器，直到设备就绪。

数据路径通常为：

> **设备 → I/O 接口 → CPU → 主存**

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-008.svg" alt={"给 I/O 模块发出 读命令 读 I/O 模块的 状态 检查状态 从 I/O 模块中 读取字 往存储器中 写入字 完成？ CPU → I/O I/O → CPU 错误条件 I/O → CPU CPU → 存储器 下一条指令 未准备好 准备好 是 CPU 向控制器 发出命令 将 I/O 状态信息 读入 CPU 寄存器 设备可能出现错误 将数据寄存器的内容 读入 CPU 寄存器 将 CPU 寄存器中的内容 写到内存中"} />

典型过程：

1. CPU 向 I/O 接口发出命令；
2. CPU 读取状态寄存器；
3. 如果设备未就绪，继续查询；
4. 设备就绪后，CPU 读取数据端口；
5. CPU 将数据写入主存；
6. 重复上述过程。

#### 特点

优点：

* 硬件简单；
* 控制逻辑简单。

缺点：

* CPU 大量时间用于查询状态；
* 等待期间无法高效完成其他工作；
* CPU 利用率低。

> **关键**
>
> 程序查询方式中的主要浪费是 **CPU 忙等待（Busy Waiting）**。

---

## 十七、程序中断方式

程序中断方式不再要求 CPU 一直轮询设备。

CPU 启动设备后可以继续执行其他程序。

设备准备好数据后，向 CPU 发出 **中断请求**。

CPU：

1. 响应中断；
2. 保存必要现场；
3. 执行中断服务程序；
4. 在中断服务程序中完成数据搬运；
5. 返回原程序。

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-009.svg" alt={"给 I/O 模块发出 读命令 读 I/O 模块的 状态 检查状态 从 I/O 模块中 读取字 往存储器中 写入字 完成？ CPU → I/O I/O → CPU 错误条件 I/O → CPU CPU → 存储器 下一条指令 准备好 是 CPU 向控制器 发出命令 将 I/O 状态信息 读入 CPU 寄存器 设备可能出现错误 将数据寄存器的内容 读入 CPU 寄存器 将 CPU 寄存器中的内容 写到内存中 中断 做其他事情 否"} />

与查询方式相比：

* CPU 不再忙等待；
* CPU 与设备可以在设备准备数据阶段并行工作。

但是：

> **程序中断方式下，真正的数据搬运仍由 CPU 完成。**

例如输入时通常仍然需要：

> I/O 接口 → CPU 寄存器 → 主存

因此，如果高速设备不断产生数据，CPU 会频繁进入中断服务程序，开销仍然很大。

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-010.svg" alt={"中断驱动I/O方式"} />

## 十八、DMA 方式

> **真题考查**
>
> * 选择题：2013 年第 22 题、2017 年第 32 题、2019 年第 22 题、2020 年第 22 题、2024 年第 22 题、2025 年第 21 题
> * 解答题：2009 年第 43 题、2012 年第 43 题、2022 年第 44 题

**DMA（Direct Memory Access，直接存储器访问）**&#x2060;允许 I/O 设备和主存之间在专用控制逻辑的组织下直接传输数据，而 CPU 不再逐字、逐字节参与搬运。

核心思想：

> **CPU 负责“安排任务”，DMA 负责“搬数据”。**

---

### 1. 为什么需要 DMA

中断方式已经解决了“CPU 一直等待设备”的问题，但没有解决：

> **CPU 仍然要亲自搬运每批数据。**

高速设备如果频繁产生数据，则会导致：

* 大量中断；
* 大量现场保护与恢复；
* CPU 频繁执行数据搬运指令。

DMA 将大批量数据传输从 CPU 中剥离出来。

---

### 2. DMA 的基本原理

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-011.svg" alt={"CPU 运行主程序（与 DMA 并行） ① 预处理 ④ 后处理 仅参与 首尾两端 DMA 控制器 接管总线 · 自动搬运 MAR · DR · DC · CR ② 初始化参数 地址/长度/方向 ③ 完成中断 通知 CPU 校验/收尾 外设 如：磁盘 / 网卡 内存 主存 (RAM) 数据通路（不经过 CPU 寄存器/执行单元） 核心思想 ① 预处理： CPU 配置 DMA 参数（源地址、目标地址、长度、方向） ② 数据传输： DMA 控制器接管总线，在外设与内存之间 直接搬运"} />

DMA 工作时，CPU 主要参与：

#### 传输前

配置：

* I/O 设备；
* 主存起始地址；
* 数据数量；
* 传输方向；
* DMA 工作模式。

#### 传输过程中

数据在：

> **I/O 接口 ↔ 主存**

之间传输，不需要通过 CPU 的通用寄存器和 ALU 逐次搬运。

#### 传输完成后

DMA 控制器通常向 CPU 发送一次 **完成中断**。

CPU 再执行：

* 状态检查；
* 错误处理；
* 后续任务调度等。

因此 DMA 特别适合：

* 高速设备；
* 大批量连续数据传输；
* 块设备。

---

### 3. “DMA 不经过 CPU”到底是什么意思

408 中说：

> **DMA 数据不经过 CPU。**

准确含义是：

> **数据不需要经过 CPU 的通用寄存器和执行部件，由 CPU 指令逐个搬运。**

现代机器中具体的数据物理路径取决于硬件架构，DMA 请求可能仍经过：

* SoC 内部互连；
* 总线仲裁器；
* 内存控制器。

但这不改变 DMA 的本质：

> **CPU 核心不负责逐个数据单位的搬运。**
