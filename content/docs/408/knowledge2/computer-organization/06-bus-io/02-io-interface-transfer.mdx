## 10. I/O 系统的任务与基本结构

**I/O 系统（Input/Output System）**负责主机和外部设备之间的信息交换。

以主机为参照：

- 外设 $\rightarrow$ 主机：输入；
- 主机 $\rightarrow$ 外设：输出。

I/O 的根本矛盾是：

> **CPU/主存很快，而外设速度、数据格式和控制方式差异很大。**

典型传统结构可抽象为：

```text
CPU / 主存 ↔ 系统互连 ↔ I/O 接口（设备控制器）↔ 外设
```

CPU 负责发出命令、访问接口寄存器、处理中断以及在某些 I/O 方式下参与数据搬运；I/O 接口负责在主机与设备之间进行缓冲、控制和格式适配。

现代系统可能把内存控制器、PCIe Root Complex、DMA Engine 等集成在 CPU/SoC 内部，但不改变 408 的逻辑分析框架。

### 10.1 I/O 软件层次

从操作系统角度，I/O 还可以分层为：

- 用户层 I/O 软件；
- 设备独立性软件；
- 设备驱动程序；
- 中断处理程序。

硬件章节主要关心接口、端口与数据传送方式；软件层次主要在操作系统中进一步展开。

## 11. I/O 接口的功能与基本结构

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-004.svg" alt={"CPU 数据缓冲 寄存器 状态寄存器 控制寄存器 I/O 控制逻辑 地址译码器及 设备选择电路 外设 接口 控制 逻辑 地址线 控制线 数据线 地址信号 控制信号 设备 地址 交互 数据 设备状态 控制命令 外设1 控制 状态 数据 外设 接口 控制 逻辑 外设1 控制 状态 数据 外设 接口 控制 逻辑 外设1 控制 状态 数据 I/O 接口"} />
<InlineSvg src="/images/computer-organization/computer-organization-bus-io-005.svg" alt={"I/O 端口 I/O 端口 CPU I/O  总线 I/O 接口 I/O 控制器 I/O  设备"} />

> **真题考查**
>
> - 选择题：2014 年第 21 题、2017 年第 21 题、2021 年第 20 题

CPU 与外设通常不能直接简单相连，因为二者存在：

- 速度差异；
- 数据格式差异；
- 控制时序差异；
- 电气特性差异。

因此需要 **I/O 接口（I/O Interface）**在中间协调。

### 11.1 五类核心功能

| 功能 | 作用 |
| --- | --- |
| 数据缓冲 | 用寄存器/缓冲区协调主机与外设速度差异 |
| 格式转换 | 如串行/并行转换、字长或编码适配 |
| 控制与定时 | 组织命令、数据、状态的先后关系 |
| 状态与错误检测 | 保存 Ready、Busy、Error、Done 等状态 |
| 主机/设备通信 | 一侧连接主机互连，一侧连接具体设备 |

### 11.2 I/O 接口与设备控制器

两个术语侧重点不同：

- **I/O 接口**强调主机与设备之间的交换边界；
- **设备控制器**强调控制具体设备的硬件逻辑。

在很多教材或具体硬件中，两者功能高度重叠，考试时应依据题干结构判断，不必机械区分名字。

## 12. I/O 端口：CPU 实际访问的是寄存器

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-006.svg" alt={"CPU 设备 I/O 接口 控制寄存器 状态寄存器 输入寄存器 输出寄存器"} />

**I/O 端口**是 I/O 接口内部**能够被 CPU 直接访问的寄存器**，不是机箱上的 USB 插孔。

常见端口分三类。

| 端口 | 主要内容 | CPU 常见操作 |
| --- | --- | --- |
| 数据端口 | 输入/输出数据 | 读或写 |
| 状态端口 | Ready、Busy、Error、Done 等 | 以读为主 |
| 控制端口 | Start、Stop、Reset、Mode 等命令 | 以写为主 |

### 12.1 一个最小 I/O 接口模型

```text
CPU
 │ 地址/控制
 ▼
地址译码与控制逻辑
 ├── 数据寄存器  ↔ 外设数据
 ├── 状态寄存器  ← 外设状态
 └── 控制寄存器  → 外设命令
```

<Callout type="warning" title="端口的三个语境">

“端口”在不同课程中含义不同：

- 组成原理 I/O 端口：**接口内部寄存器**；
- 网络端口：TCP/UDP 的逻辑端口号；
- 日常硬件“USB 端口”：物理连接口。

做题必须先看语境。

</Callout>

## 13. I/O 端口编址：MMIO 与独立编址

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-007.svg" alt={"内存地址 （共960KB) 端口地址 （共64KB) 0 EFFFFH F0000H FFFFFH 内存地址 （共960KB) 端口地址 （共64KB) 0 FFFFH 0 FFFFFH 统一编址 独立编址"} />

设备寄存器必须有 CPU 可识别的地址。经典方法有两种。

### 13.1 统一编址（Memory-Mapped I/O，MMIO）

把设备寄存器映射进与主存相同的地址空间。

CPU 使用普通访存指令访问设备寄存器，例如：

```asm
MOV EAX, [0xF0001000]
MOV [0xF0001000], EBX
```

地址虽然形式上是“内存地址”，但地址译码后可能选中的是 I/O 设备寄存器，而不是 RAM。

优点：

- 不需要专用 I/O 指令；
- 可使用普通访存寻址方式和指令；
- 编程模型统一。

代价：

- 设备寄存器占用统一地址空间中的一部分地址范围。

<Callout type="warning" title="MMIO 地址不是普通内存">

MMIO 与 RAM 共用**地址空间**，不等于共用**存储介质**。设备寄存器通常还需要特殊的访问顺序、缓存属性和副作用语义；408 只要求理解“统一编址 + 普通访存指令”。

</Callout>

### 13.2 独立编址（Port-Mapped I/O，PMIO）

主存和 I/O 使用两套独立地址空间，CPU 用专用 I/O 指令访问端口。

传统 x86 例子：

```asm
IN  AL, 0x60
OUT 0x3F8, AL
```

### 13.3 两种方式对比

| 项目 | MMIO 统一编址 | PMIO 独立编址 |
| --- | --- | --- |
| 地址空间 | 主存与 I/O 共用 | 主存与 I/O 分离 |
| 是否占统一地址空间 | 是 | 否 |
| 指令 | 普通访存指令 | 专用 I/O 指令 |
| 典型示例 | `MOV/LDR/STR` | `IN/OUT` |

> **记忆：统一编址看起来像“访问内存”；独立编址使用专用 I/O 空间。**

## 14. 四种 I/O 数据传送方式的统一比较框架

> **真题考查**
>
> - 选择题：2011 年第 22 题、2023 年第 22 题
> - 解答题：2018 年第 43 题

经典 I/O 控制方式：

1. 程序查询；
2. 程序中断；
3. DMA；
4. 通道（传统大型机 I/O 扩展思想）。

做题不要只背定义，始终比较三个问题：

1. **设备准备期间 CPU 是否等待？**
2. **真正的数据由谁搬？**
3. **CPU 在什么时候介入？**

| 方式 | 设备准备阶段 CPU | 数据是否经 CPU 通用寄存器逐次搬运 | CPU 主要介入点 |
| --- | --- | --- | --- |
| 程序查询 | 忙等待 | 是 | 全程查询并搬运 |
| 程序中断 | 可执行其他程序 | 是 | 每次中断后搬运 |
| DMA | 可执行其他程序 | 否 | 初始化 + 完成处理 |
| 通道 | 可执行其他程序 | 否 | 启动通道程序 + 完成处理 |

可以把自主能力理解为：

> **查询 < 中断 < DMA < 通道。**

但这不是说每种后者都“完全取代”前者，实际系统会按设备特点组合使用。

## 15. 程序查询方式：CPU 既等又搬

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-008.svg" alt={"给 I/O 模块发出 读命令 读 I/O 模块的 状态 检查状态 从 I/O 模块中 读取字 往存储器中 写入字 完成？ CPU → I/O I/O → CPU 错误条件 I/O → CPU CPU → 存储器 下一条指令 未准备好 准备好 是 CPU 向控制器 发出命令 将 I/O 状态信息 读入 CPU 寄存器 设备可能出现错误 将数据寄存器的内容 读入 CPU 寄存器 将 CPU 寄存器中的内容 写到内存中"} />

程序查询（Polling）由 CPU 反复读取状态端口，直到设备就绪。

输入过程可抽象为：

```text
发出 I/O 命令
    ↓
反复读状态端口 ──未就绪──┐
    │就绪               │
    ▼                   │
读数据端口               │
    ↓                   │
写入主存                 │
    └───────────────────┘
```

数据路径通常是：

> **设备 → I/O 接口 → CPU 寄存器 → 主存。**

主要缺点是**忙等待（Busy Waiting）**：设备准备数据时 CPU 仍不断执行查询指令。

### 15.1 查询方式的 CPU 开销模型

若 CPU 每隔 $t_p$ 查询一次，每次查询消耗 $C_p$ 个 CPU 周期，在设备工作时间 $T_d$ 内大约需要：

$$
N_p\approx \frac{T_d}{t_p}
$$

次查询，则轮询开销约为：

$$
C_{\text{poll}}\approx N_p C_p
$$

具体题目若给出“每次轮询多少条指令、CPI、主频”，先换算成 CPU 周期或时间，再求占比。

## 16. 程序中断方式：CPU 不等，但仍然搬

中断 I/O 的核心改进是：

> **CPU 启动设备后不再反复查询；设备就绪时主动通知 CPU。**

典型过程：

1. CPU 启动外设；
2. CPU 执行其他程序；
3. 设备准备好一个传输单位并发出中断；
4. CPU 响应中断、保护必要现场；
5. 中断服务程序从 I/O 数据端口取数并写入主存（或反向输出）；
6. 中断返回。

因此：

- 中断方式解决了**等待**问题；
- 但通常没有解决**CPU 逐次搬数据**的问题。

输入数据路径仍常表示为：

> **设备 → I/O 接口 → CPU 寄存器 → 主存。**

### 16.1 中断方式 CPU 开销的统一模型

若设备传输率为 $R$ Byte/s，每次中断搬运 $D$ Byte，则每秒中断次数约为：

$$
N_{\text{int}}=\frac{R}{D}
$$

若一次中断从响应到服务完成需要 $C_{\text{int}}$ 个 CPU 周期，CPU 主频为 $f$，则每秒用于该设备的 CPU 时间为：

$$
T_{\text{CPU,I/O}}
=
\frac{N_{\text{int}}C_{\text{int}}}{f}
$$

CPU 时间占比：

$$
\eta
=
\frac{N_{\text{int}}C_{\text{int}}}{f}
$$

若中断服务程序给的是“指令条数 $I$、平均 CPI 为 $c$”，则：

$$
C_{\text{int}}=Ic+C_{\text{response/return}}
$$

<Callout type="warning" title="先找中断频率">

综合题最容易错在把“设备字节率”直接当“中断次数”。必须先看**每次中断搬多少 Byte**，再求每秒多少次中断。

</Callout>

## 17. DMA：CPU 负责首尾，DMA 负责批量搬运

> **真题考查**
>
> - 选择题：2013 年第 22 题、2017 年第 32 题、2019 年第 22 题、2020 年第 22 题、2024 年第 22 题、2025 年第 21 题
> - 解答题：2009 年第 43 题、2012 年第 43 题、2022 年第 44 题

**DMA（Direct Memory Access）**允许设备数据在 DMA 控制逻辑组织下直接与主存交换，而不再由 CPU 指令逐字、逐字节搬运。

核心分工：

> **CPU 安排任务，DMA 搬数据。**

### 17.1 为什么中断方式之后还需要 DMA

中断已经让 CPU 不必忙等待，但高速设备若每个很小的数据单位都中断一次，仍会产生：

- 大量中断响应与返回开销；
- 大量现场保护/恢复；
- CPU 频繁执行搬运指令。

DMA 把“大批量连续数据搬运”交给专用控制逻辑。

### 17.2 DMA 三阶段

**传输前：CPU 预处理**

配置：

- 设备/端口；
- 主存起始地址；
- 传输长度；
- 方向；
- DMA 工作模式。

**传输中：DMA 自动搬运**

```text
I/O 接口 ↔ DMA/互连 ↔ 主存
```

不需要 CPU 用通用寄存器逐个数据单位搬运。

**传输后：完成通知**

DMA 通常通过中断告诉 CPU：

- 数据块完成；
- 或发生错误。

CPU 再进行后处理。

### 17.3 “DMA 数据不经过 CPU”的准确含义

这句话的考试含义是：

> **数据不需要进入 CPU 通用寄存器，再由 CPU 指令逐个搬到主存。**

数据在物理上仍可能经过片上互连、内存控制器、IOMMU 等系统部件；这些并不改变 DMA 的定义。

## 18. 查询、中断、DMA 的定量题统一模型

三种方式的综合题，先把设备侧数据率转化为“CPU 每秒需要处理多少次事件”。

### 18.1 中断方式

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-009.svg" alt={"给 I/O 模块发出 读命令 读 I/O 模块的 状态 检查状态 从 I/O 模块中 读取字 往存储器中 写入字 完成？ CPU → I/O I/O → CPU 错误条件 I/O → CPU CPU → 存储器 下一条指令 准备好 是 CPU 向控制器 发出命令 将 I/O 状态信息 读入 CPU 寄存器 设备可能出现错误 将数据寄存器的内容 读入 CPU 寄存器 将 CPU 寄存器中的内容 写到内存中 中断 做其他事情 否"} />
<InlineSvg src="/images/computer-organization/computer-organization-bus-io-010.svg" alt={"中断驱动I/O方式"} />

设备速率 $R$ Byte/s，每次中断传 $D$ Byte：

$$
N_{\text{int}}=\frac{R}{D}
$$

若一次中断总开销 $C_{\text{int}}$ 个 CPU 周期：

$$
\eta_{\text{int}}
=
\frac{R}{D}\cdot\frac{C_{\text{int}}}{f}
$$

### 18.2 DMA 方式

<InlineSvg src="/images/computer-organization/computer-organization-bus-io-011.svg" alt={"CPU 运行主程序（与 DMA 并行） ① 预处理 ④ 后处理 仅参与 首尾两端 DMA 控制器 接管总线 · 自动搬运 MAR · DR · DC · CR ② 初始化参数 地址/长度/方向 ③ 完成中断 通知 CPU 校验/收尾 外设 如：磁盘 / 网卡 内存 主存 (RAM) 数据通路（不经过 CPU 寄存器/执行单元） 核心思想 ① 预处理： CPU 配置 DMA 参数（源地址、目标地址、长度、方向） ② 数据传输： DMA 控制器接管总线，在外设与内存之间 直接搬运"} />

若每个 DMA 块大小为 $B$ Byte，则每秒 DMA 块数：

$$
N_{\text{DMA}}=\frac{R}{B}
$$

若每块 DMA 的 CPU 预处理 + 后处理总开销为 $C_{\text{DMA}}$ 个 CPU 周期，则 CPU 时间占比：

$$
\eta_{\text{DMA}}
=
\frac{R}{B}\cdot\frac{C_{\text{DMA}}}{f}
$$

这就是 DMA 为什么适合大块数据：当 $B$ 增大时，CPU 的“每字节管理开销”被摊薄。

### 18.3 若题目加入 CPU 与 DMA 访存冲突

上述公式只计算 CPU 执行**控制开销**的时间。如果 DMA 会周期挪用主存/总线，还要额外计算 CPU 因总线被占用而产生的停顿。

<Callout type="info" title="综合题顺序">

**先算 CPU 软件/中断开销，再判断是否还有 DMA 窃取总线造成的硬件停顿。**

</Callout>
