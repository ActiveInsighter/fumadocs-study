## 36. 机械硬盘的物理结构

<InlineSvg src="/images/computer-organization/computer-organization-storage-storage-001.svg" alt="机械硬盘盘片、磁头、磁道与柱面" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-storage-002.svg" alt="磁道、扇区、柱面和磁头" />

机械硬盘由盘片、磁头、机械臂与驱动机构等组成。

关键概念：

- **盘片（Platter）**：旋转的磁性介质；
- **盘面（Surface）**：盘片可记录信息的一面；
- **磁头（Head）**：对应某个盘面读写；
- **磁道（Track）**：盘面上的同心圆记录区域；
- **柱面（Cylinder）**：不同盘面上半径相同的磁道集合；
- **扇区（Sector）**：磁道进一步划分出的数据单位。

可以用层次关系记忆：

```text
磁盘
├─ 多个盘面
│  └─ 多条磁道
│     └─ 多个扇区
└─ 各盘面上同半径磁道的集合 = 柱面
```

> **真题覆盖**
>
> - CHS：2013 Q25；2019 Q44、2022 Q44。
> - 磁盘性能：2013 Q21、2015 Q20；2019 Q44。
> - RAID：2013 Q20。

## 37. CHS 与磁盘容量

<InlineSvg src="/images/computer-organization/computer-organization-storage-storage-003.svg" alt="CHS 地址结构" />

传统 CHS 使用：

- C：Cylinder，柱面号；
- H：Head，磁头/盘面号；
- S：Sector，扇区号。

若共有 $C$ 个柱面、$H$ 个盘面、每磁道 $S$ 个扇区，每扇区 $B$ 字节，则理想容量为

$$
\text{Capacity}=C\times H\times S\times B
$$

编码所需位数分别为：

$$
\lceil\log_2C\rceil,\qquad
\lceil\log_2H\rceil,\qquad
\lceil\log_2S\rceil
$$

总编码位数为三者之和。

<Callout type="warning" title="“有多少个编号”与“最大编号是多少”要区分">
如果有 1000 个柱面，编号通常是 $0\sim999$，需要
$$
\lceil\log_21000\rceil=10
$$
位，而不是对 999 再机械做其他处理。
</Callout>

## 38. 磁盘访问时间

<InlineSvg src="/images/computer-organization/computer-organization-storage-storage-004.svg" alt="寻道、旋转等待与传输" />

机械硬盘访问一次数据主要经历：

1. **寻道时间** $T_{\text{seek}}$：磁头移动到目标磁道；
2. **旋转等待** $T_{\text{rotation}}$：等待目标扇区旋转到磁头下；
3. **传输时间** $T_{\text{transfer}}$：真正读/写数据。

因此：

$$
T_{\text{access}}
=
T_{\text{seek}}
+
T_{\text{rotation}}
+
T_{\text{transfer}}
$$

### 38.1 平均旋转等待

若转速为 $r$ 转/秒，则一圈时间为

$$
\frac{1}{r}
$$

平均等待半圈：

$$
T_{\text{rotation,avg}}
=
\frac{1}{2r}
$$

若给的是 rpm：

$$
r=\frac{\text{rpm}}{60}
$$

### 38.2 连续传输率

<InlineSvg src="/images/computer-organization/computer-organization-storage-storage-005.svg" alt="磁盘数据传输率" />

若每圈可传输 $N$ B，转速为 $r$ 转/秒，则理想连续传输率为

$$
D=rN
$$

若每磁道有 $S$ 个扇区，每扇区 $B$ B：

$$
N=SB
$$

因此

$$
D=rSB
$$

若一次连续传输的数据量为 $L$ B，则理想传输时间可直接写成

$$
T_{\text{transfer}}=\frac{L}{D}
$$

若题目要求读取一个扇区，也可以利用“一圈时间 / 每磁道扇区数”得到

$$
T_{\text{sector}}
=
\frac{1/r}{S}
=
\frac{1}{rS}
$$

两种算法本质一致。

<Callout type="warning" title="平均存取时间不是只算寻道">
408 磁盘题最常漏掉的是“半圈平均旋转等待”。若题目还给出数据长度，则传输时间也不能省略。
</Callout>

## 39. RAID：条带、镜像与校验

<InlineSvg src="/images/computer-organization/computer-organization-storage-storage-006.svg" alt="RAID 条带与校验示意" />

RAID（Redundant Array of Independent Disks）把多块物理盘组织成一个逻辑存储系统。

三类基本思想：

- **Striping（条带化）**：把数据分散到多盘，提升并行吞吐；
- **Mirroring（镜像）**：保存完整副本，提高可靠性；
- **Parity（校验）**：通过冗余校验信息恢复部分故障数据。

常见级别：

| RAID | 核心机制 | 可用容量（$N$ 块等容量磁盘，每块 $C$） | 典型容错能力 |
| --- | --- | --- | --- |
| RAID 0 | 条带化 | $NC$ | 0 块故障 |
| RAID 1 | 镜像 | 取决于镜像组织；最常见两盘镜像为 $C$ | 典型两盘镜像组可坏 1 块而不丢数据 |
| RAID 5 | 分布式单校验 | $(N-1)C$ | 任意 1 块故障 |
| RAID 6 | 分布式双校验 | $(N-2)C$ | 任意 2 块故障 |

其中 RAID 5/6 的校验信息是**分布式**放置的，不是固定由某一块磁盘永远承担校验盘角色。

对小随机写，带校验的 RAID 往往还需要读旧数据/旧校验并更新校验，因此写性能不能只看“磁盘数量更多就一定更快”。408 若未给具体 I/O 模型，通常只考机制、容量和容错关系。

<Callout type="warning" title="RAID 0 名字里有 RAID，但没有冗余">
RAID 0 只有条带化，不提供故障冗余。考试看到“提高可靠性”时，不能把 RAID 0 算进去。
</Callout>

## 40. SSD：Flash、FTL 与擦写特性

SSD 主要使用 NAND Flash，不依赖机械磁头和旋转盘片，因此：

- 没有机械寻道；
- 没有旋转等待；
- 随机访问延迟远低于 HDD；
- 抗震、无机械噪声；
- 擦写寿命有限。

Flash 的一个关键特性是：

> 读取和写入通常以 **Page** 为较小粒度，而擦除必须以更大的 **Erase Block** 为单位；写入前还受“先擦后写”等物理限制。

这也是 SSD 不能像 DRAM 那样随意原地覆盖任意字节的重要原因。更新一个逻辑页时，控制器经常把新数据写到其他空闲物理页，再把旧页标记为失效，之后由垃圾回收统一整理可擦除块。

因此 SSD 主控需要做很多“软件化管理”，典型包括：

- FTL（Flash Translation Layer）地址映射；
- Wear Leveling（磨损均衡）；
- Garbage Collection（垃圾回收）；
- ECC（纠错）；
- 坏块管理。

### 40.1 逻辑地址与物理 Flash 位置不是简单一一对应

操作系统看到的是逻辑块地址（LBA），FTL 再把 LBA 映射到具体 Flash 页。由于垃圾回收、磨损均衡和重写，某个 LBA 对应的物理位置可能不断变化。

这会带来一个常见概念：**写放大（Write Amplification）**。主机只写少量新数据时，SSD 内部可能因为搬移有效页、回收擦除块而产生更多实际 Flash 写入。写放大会影响性能与寿命，但 408 通常只要求理解产生原因，不要求掌握厂商级实现细节。

### 40.2 为什么 SSD 不适合传统磁盘式碎片整理

逻辑文件仍然可能不连续，但 SSD 没有机械寻道，因此“把逻辑文件整理成连续扇区”通常不会获得 HDD 上那种收益，反而可能增加不必要写入与擦写磨损。

## 41. HDD 与 SSD 对比

![](/images/computer-organization/computer-organization-storage-storage-007.jpg)
<InlineSvg src="/images/computer-organization/computer-organization-storage-storage-008.svg" alt="HDD 与 SSD 对比" />

| 项目 | HDD | SSD |
| --- | --- | --- |
| 介质 | 磁性盘片 | NAND Flash |
| 机械部件 | 有 | 无 |
| 寻道时间 | 有 | 无 |
| 旋转等待 | 有 | 无 |
| 随机访问延迟 | 高 | 低 |
| 抗震 | 较差 | 较好 |
| 典型寿命约束 | 机械与介质等 | Flash 擦写寿命 |
| 单位大容量成本 | 通常较低 | 通常较高 |

不要背某一代产品的固定“毫秒/微秒”参数；408 更重视结构与计算模型。

## 42. 存储层次综合：谁缓存谁

整章可压缩成一张关系表：

| 层次结构 | 上层保存什么 | 典型单位 | 典型管理 |
| --- | --- | --- | --- |
| Cache ↔ 主存 | 主存数据副本 | Cache Block | 硬件 |
| TLB ↔ 页表 | 地址翻译副本 | TLB Entry | MMU/硬件 |
| 主存 ↔ 辅存 | 当前驻留页面 | Page | OS + MMU |

三种典型命中/失效：

```text
TLB Miss   → 查页表
Page Fault → 去辅存调页
Cache Miss → 去主存取块
```

<Callout type="info" title="同一个虚拟地址可能连续经历三套机制">
一次访问可以先 TLB Miss、页表命中，再 Cache Miss，最后从主存调入 Cache；也可能 TLB Miss 后直接发现缺页。每一级都要独立判断。
</Callout>

## 43. 本章高频易错点

| 易错说法 | 正确理解 |
| --- | --- |
| SRAM 是“静态”，所以断电不丢 | 错，SRAM 仍是易失性 |
| DRAM 地址引脚数等于完整地址位数 | 错，行列地址可复用 |
| RAM 能随机访问，ROM 不能 | 错，ROM 通常也能随机读 |
| 多体交叉把单次访问延迟缩短为 $1/m$ | 错，主要提高连续吞吐 |
| 4 路组相联表示总共 4 组 | 错，表示每组 4 行 |
| Cache Miss 就是 Page Fault | 错，二者属于不同层次 |
| TLB Miss 就是 Page Fault | 错，先查页表 |
| 地址翻译会改变页内偏移 | 错，VPO=PPO |
| Write-Back 命中时立即写主存 | 错，通常淘汰时才写回 |
| Write-Through 必须依赖 Dirty | 通常不需要 |
| 缺页次数等于置换次数 | 错，有空闲页框时缺页可不置换 |
| SSD 不存在任何碎片 | 不准确，只是逻辑不连续没有 HDD 那种机械寻道惩罚 |
| RAID 5 有一块固定校验盘 | 错，RAID 5 的单校验信息通常分布在各盘 |
| SSD 可以像 DRAM 一样任意字节原地覆盖 | 错，Flash 存在页写、块擦除等粒度限制 |

## 44. 408 存储系统最终做题框架

### 44.1 主存芯片扩展

$$
N_{\text{chips}}
=
\frac{\text{目标字数}}{\text{单片字数}}
\times
\frac{\text{目标字长}}{\text{单片字长}}
$$

地址线按：

```text
高位片选 | 芯片内部地址 | 低位字内偏移
```

拆分。

### 44.2 Cache

先算：

$$
\text{Lines}
=
\frac{\text{Cache 数据容量}}{\text{块大小}}
$$

再算组数、偏移位、索引位，最后剩余高位为 Tag。

### 44.3 页式地址转换

$$
\text{Page Offset bits}=\log_2(\text{Page Size})
$$

$$
\text{VPN bits}=\text{VA bits}-\text{Offset bits}
$$

$$
\text{PPN bits}=\text{PA bits}-\text{Offset bits}
$$

并牢记：

$$
\text{PA}=\text{PPN}\Vert\text{VPO}
$$

### 44.4 综合访存

```text
VA
→ TLB
→ Page Table
→（若不驻留）Page Fault
→ PA
→ Cache
→（若 Miss）Main Memory
```

### 44.5 磁盘

$$
T_{\text{access}}
=
T_{\text{seek}}
+
T_{\text{rotation}}
+
T_{\text{transfer}}
$$

看到 rpm，先除以 60 换成转/秒；看到“平均旋转等待”，默认半圈模型，除非题目另有说明。

<Callout type="info" title="最后一分钟复习口令">

**主存看扩展，Cache 看地址，页表看翻译，TLB 看命中，磁盘看三段时间。**

</Callout>
