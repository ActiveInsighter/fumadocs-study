title: "3.8 TLB、页表、Cache 的完整访存链路"
description: "把虚拟地址翻译、TLB、页表、缺页、物理地址、Cache 命中与主存访问串成统一综合题流程。"
---

存储系统综合题最容易失分，不是因为某个公式不会，而是把**TLB Miss、Page Fault、Cache Miss**当成同一种“没命中”。正确做法是按层次逐级判断。

## 3.8.1 一次访存先分成两个阶段

### 阶段 A：地址翻译

$$
\text{VA}\rightarrow\text{PA}
$$

主要结构：

```text
TLB / Page Table / MMU
```

### 阶段 B：数据访问

$$
\text{PA}\rightarrow\text{Cache / Main Memory}
$$

主要结构：

```text
Cache / DRAM
```

在 408 典型模型中，先完成地址翻译，再用物理地址访问 Cache。

## 3.8.2 虚拟地址翻译固定流程

1. CPU 产生虚拟地址 VA；
2. 拆成 VPN 和 VPO；
3. 用 VPN 查 TLB；
4. TLB 命中：得到 PPN；
5. TLB 未命中：访问页表；
6. 页表项有效且页面驻留：取得 PPN，并可回填 TLB；
7. 页面合法但不驻留：触发缺页异常；
8. 操作系统调页或进行页面置换；
9. 更新页表以及必要的 TLB 状态；
10. 重新执行产生缺页的指令；
11. 拼接 PPN 与原 VPO 得到 PA。

$$
\text{PA}=\text{PPN}\Vert\text{VPO}
$$

## 3.8.3 得到物理地址后再访问 Cache

1. 按 Cache 块大小切出块内偏移；
2. 按映射方式切出行号或组号；
3. 剩余高位为 Tag；
4. 检查候选行的 Valid 与 Tag；
5. 命中则访问 Cache 数据；
6. 未命中则从主存调入目标块；
7. 若需要替换且牺牲块为脏块，先写回主存；
8. 更新新行的 Tag、Valid、Dirty 和替换状态；
9. 完成本次读/写。

## 3.8.4 一张必须背熟的流程图

```text
CPU 产生 VA
   ↓
VPN + VPO
   ↓
查 TLB
   ├─ Hit ───────────────→ PPN
   │
   └─ Miss → 查页表
              ├─ 页面驻留 → PPN → 更新 TLB
              │
              └─ 页面不驻留
                    ↓
                Page Fault
                    ↓
             调页 / 页面置换
                    ↓
              更新页表并重试

PPN + VPO
   ↓
得到 PA
   ↓
按 PA 查 Cache
   ├─ Hit → 访问 Cache 数据
   │
   └─ Miss → 访问主存
                ↓
         必要时替换 / 脏块回写
                ↓
             填充 Cache
```

## 3.8.5 三种“Miss”到底差在哪里

| 情况 | 哪一层没命中 | 下一步 | 是否需要操作系统介入 |
| --- | --- | --- | --- |
| TLB Miss | 地址翻译缓存 | 查页表 | 通常不需要 |
| Page Fault | 页面未驻留主存 | 从辅存调页 | 需要 |
| Cache Miss | 物理数据块不在 Cache | 访问主存并填充 | 通常不需要 |

> **关键结论**
>
> TLB Miss 不等于缺页；Cache Miss 也不等于缺页。三者可能在同一次指令访存中以不同组合出现。

## 3.8.6 Valid、Dirty 分别在哪些层次出现

### Cache

- Valid：Cache 行是否有效；
- Dirty：Write-Back 下 Cache 块是否需要写回主存。

### Page Table

- Present / Valid：映射是否有效、页面是否在内存，按题设解释；
- Dirty：物理页内容是否被修改，页面淘汰时可能需要写回辅存；
- Protection：读/写/执行权限。

这些位名字相似，但作用层次不同。

## 3.8.7 访问时间计算：先数“会访问哪些层次”

不要先找公式，应先画路径。

### 情况 1：TLB Hit + Cache Hit

可能只经历：

```text
TLB → Cache
```

### 情况 2：TLB Miss + 页表在主存 + Cache Hit

在最简串行模型中：

```text
TLB → 页表访存 → Cache
```

### 情况 3：TLB Hit + Cache Miss

```text
TLB → Cache → Main Memory
```

### 情况 4：Page Fault

会出现磁盘/SSD 调页，时间通常比普通主存访问大很多个数量级，因此哪怕缺页率很低，也可能显著拉高平均访存时间。

如果题目要求平均时间，先为每条路径写出概率和代价，再加权求和：

$$
E[T]=\sum_i P_iT_i
$$

## 3.8.8 Cache 的组索引是否落在页内偏移中

综合题常让你判断地址翻译前后哪些位保持不变。

页面大小为 $P$，则最低：

$$
\log_2P
$$

位页内偏移在 VA→PA 后不变。

如果 Cache 的“组索引 + 块内偏移”全部落在这部分位中，那么这些低位在地址翻译前后相同。

但标准 408 题仍应按题目画出的结构判断，不要自行推断现实处理器一定采用某种 VIPT/PIPT 设计。

## 3.8.9 综合题草稿模板

看到 “VA + TLB + 页表 + Cache” 时，建议按以下格式写：

```text
1. 页大小 = ? → VPO/PPO 位数 = ?
2. VA 位数 = ? → VPN 位数 = ?
3. PA 位数 = ? → PPN 位数 = ?
4. VPN 如何查 TLB？组号 / Tag 是什么？
5. 若 TLB Miss，页表如何索引？页面是否驻留？
6. PPN + VPO = PA
7. Cache 块大小 = ? → Offset 位数 = ?
8. Cache 组/行数 = ? → Index 位数 = ?
9. PA 的 Tag / Index / Offset 分别是什么？
10. Cache 是否命中？若 Miss，是否替换、是否写回？
```

## 3.8.10 全章最重要的层次关系

```text
寄存器
↓
Cache               ← 以块为单位，解决速度差
↓
主存 DRAM           ← 以页框承载进程页面
↓
SSD / HDD           ← 缺页时作为后备存储
```

地址翻译结构：

```text
TLB → 页表 → PPN
```

数据访问结构：

```text
Cache → 主存 → 辅存
```

> **考场原则**
>
> 先判断“当前问题属于地址翻译还是数据访问”，再判断是哪一级命中/未命中。只要层次不乱，综合题就不会乱。
