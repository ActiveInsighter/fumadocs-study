存储系统的本质，是用**层次化结构**同时追求“快、大、便宜”。408 在本章很少只考器件名词，更常把**主存组织、Cache、TLB、页表与地址位数**放进同一道题。

<Callout type="info" title="本章统一做题主线">

遇到存储系统综合题，按下面顺序拆解：

1. 先确认**编址单位**：按字节、按字还是按其他单位；
2. 再确认**容量与位宽**：地址位数、数据位数、块/页大小；
3. 判断当前层次解决的是**容量问题**还是**速度问题**；
4. 地址划分一律从**最低位偏移**开始，再算索引，最后剩余高位是 Tag；
5. TLB Miss、Page Fault、Cache Miss 分属不同层次，绝不能混为一谈。

</Callout>

> **真题覆盖**
>
> - SRAM/DRAM 与刷新：2010 Q16、2010 Q22、2011 Q14、2011 Q15、2015 Q17、2026 Q15。
> - 主存芯片扩展与多体存储：2009 Q15、2010 Q15、2014 Q15、2015 Q18、2016 Q16、2017 Q13、2018 Q17、2021 Q15、2022 Q17、2026 Q15；2012 Q43 为综合题。

## 1. 存储层次、局部性与命中

<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-001.svg" alt="存储系统层次结构" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-002.svg" alt="RAM 基本特性" />

典型存储层次可概括为：

```text
寄存器
  ↓
L1 / L2 / L3 Cache
  ↓
主存 DRAM
  ↓
SSD / HDD 等辅助存储
```

一般越靠近 CPU：

- 速度越快；
- 容量越小；
- 单位容量成本越高。

越远离 CPU，则趋势相反。

上一层通常保存下一层中**近期最可能被访问的一部分内容**。这一思想能成立，根本依据是程序的**局部性**：

- **时间局部性**：刚访问过的数据/指令，短期内可能再次访问；
- **空间局部性**：刚访问某地址后，其附近地址可能很快被访问。

<Callout type="warning" title="速度层次与容量层次不要混淆">

- Cache—主存主要缓解 **CPU 与 DRAM 的速度差距**，核心管理通常由硬件完成；
- 主存—辅存主要扩展**可见地址空间与有效容量**，虚拟存储需要 MMU 与操作系统协同。

</Callout>

## 2. SRAM：高速、无需刷新，但仍然易失

<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-003.svg" alt="SRAM 存储单元" />

SRAM（Static RAM）用双稳态电路保存状态，经典单元常用 6T 结构。

主要特征：

- 不需要周期性刷新；
- 访问速度快；
- 集成度较低；
- 单位容量成本高；
- 断电后数据仍会丢失。

因此 SRAM 常用于 Cache、片上高速缓冲等容量较小但性能要求高的场景。

| 对比项 | SRAM |
| --- | --- |
| 基本单元 | 双稳态电路，经典 6T |
| 是否刷新 | 不需要 |
| 易失性 | 易失 |
| 速度 | 快 |
| 集成度 | 较低 |
| 典型用途 | Cache |

<Callout type="warning" title="“Static” 不等于“Non-volatile”">
SRAM 的“静态”只表示**只要持续供电就不需要刷新**，并不表示断电后仍能保存数据。
</Callout>

## 3. DRAM：1T1C、行列组织与刷新

<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-004.svg" alt="DRAM 1T1C 存储单元" />

DRAM（Dynamic RAM）典型单元为“1 个晶体管 + 1 个电容”，用电容电荷表示 0/1。

主要特征：

- 集成度高；
- 单位容量成本低；
- 适合构成大容量主存；
- 电容会漏电，需要周期性刷新；
- 访问速度通常慢于 SRAM。

### 3.1 二维阵列与完整地址

<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-005.svg" alt="DRAM 行列地址结构" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-006.svg" alt="DRAM 位平面、Cell 与可寻址单元" />

若一个 DRAM 位平面有 $R$ 行、$C$ 列，则定位某个 Cell 所需的完整地址信息为

$$
\log_2R+\log_2C
$$

例如 64K 个位置：

$$
64K=2^{16}=2^8\times2^8
$$

可组织成 $256\times256$，完整定位需要 16 bit，其中行、列各 8 bit。

若芯片规格为 `64K × 4 bit`，可以理解为 4 个位平面同时在相同行列位置输出，共组成 4 bit 数据。

### 3.2 行列地址复用

<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-007.svg" alt="DRAM 行列地址复用" />

DRAM 为减少地址引脚，常让**同一组引脚分两次传输地址**：

1. 先送行地址并锁存；
2. 再送列地址并锁存。

若阵列为 $R\times C$，复用后地址引脚至少需要

$$
\max(\log_2R,\log_2C)
$$

例如内部为 $256\times256$，虽然完整地址有 16 bit，但复用后只需要 8 根地址引脚。

<Callout type="warning" title="地址信息量 ≠ 地址引脚数">
DRAM 仍然需要完整的行、列地址信息，只是通过**分时复用**减少外部引脚数量。不能因为只有 8 根地址引脚，就认为只能表示 $2^8$ 个存储位置。
</Callout>

### 3.3 DRAM 刷新

<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-008.svg" alt="DRAM 刷新原理" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-009.svg" alt="DRAM 三种刷新方式" />

刷新本质上是重新恢复逐渐衰减的电荷。教材模型通常按**行**刷新，而不是逐 Cell 刷新。

常见三种刷新方式：

| 方式 | 做法 | 特点 |
| --- | --- | --- |
| 集中刷新 | 在一段连续时间内刷新全部行 | 有明显“死区” |
| 分散刷新 | 每个存取周期都安排刷新 | 无长死区，但频繁占用周期 |
| 异步刷新 | 在刷新周期内均匀刷新各行 | 折中方案，408 最常计算 |

若刷新周期为 $T$，共有 $N$ 行，则异步刷新中相邻两次单行刷新间隔约为

$$
\frac{T}{N}
$$

刷新题还要区分三个时间概念：

- **存取时间**：发出一次读写请求到数据可用所需的时间；
- **存储周期**：连续两次独立存取请求之间允许的最小时间间隔，通常不小于存取时间；
- **刷新周期**：一行数据允许在不刷新情况下保持可靠信息的最长时间尺度，教材题常要求在这个周期内把所有行刷新一遍。

<Callout type="warning" title="刷新由存储器内部组织完成，不是 CPU 逐地址读一遍">
DRAM 刷新针对的是存储阵列中的行。刷新期间会占用 DRAM 的内部资源，但不等价于 CPU 执行普通读指令访问这些地址。
</Callout>

### 3.4 SDRAM：同步的是接口时序，不是“无需刷新”

SDRAM（Synchronous DRAM）仍属于 DRAM，仍需要刷新。它与传统异步 DRAM 的主要区别是：命令、地址和数据传输与系统时钟协调，可配合突发传输提高连续访问吞吐率。

因此常见判断如下：

| 说法 | 判断 |
| --- | --- |
| SDRAM 是 DRAM | 对 |
| SDRAM 不需要刷新 | 错 |
| SDRAM 的 S 表示 Static | 错，表示 Synchronous |
| SDRAM 可利用时钟和突发传输组织连续访问 | 对 |

## 4. SRAM 与 DRAM 高频对比

<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-010.svg" alt="SRAM 与 DRAM 对比" />

| 对比项 | SRAM | DRAM |
| --- | --- | --- |
| 经典基本单元 | 6T 双稳态电路 | 1T1C |
| 是否刷新 | 否 | 是 |
| 速度 | 快 | 较慢 |
| 集成度 | 较低 | 高 |
| 单位容量成本 | 高 | 低 |
| 地址接口 | 通常一次给出完整地址 | 常采用行列地址复用 |
| 典型用途 | Cache | 主存 |
| 断电保持 | 否 | 否 |

记忆关键词：

```text
SRAM：快、贵、无需刷新 → Cache
DRAM：密、便宜、要刷新 → 主存
```

## 5. ROM、EEPROM 与 Flash

<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-011.svg" alt="ROM 基本特性" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-012.svg" alt="MROM" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-013.svg" alt="PROM" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-014.svg" alt="EPROM" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-015.svg" alt="EEPROM" />

ROM 家族强调**非易失性**和“以读为主”，但不同类型的可改写能力差异很大。

| 类型 | 写入/擦除方式 | 是否可重复改写 |
| --- | --- | --- |
| MROM | 制造时固定 | 否 |
| PROM | 用户一次烧录 | 通常否 |
| EPROM | 紫外线擦除后重写 | 是 |
| EEPROM | 电擦除、电写入 | 是 |
| Flash | 电擦除，通常按块组织 | 是 |

### 5.1 RAM 与 ROM 的关键差异

RAM 与 ROM **都可以随机访问**。主要区别不在“能否按地址直接访问”，而在：

- 是否易失；
- 写入是否频繁、方便；
- 典型使用场景。

<Callout type="warning" title="RAM 的 R 是 Random，不是 Read">
“ROM 能不能随机访问”是经典陷阱。ROM 通常也支持按地址直接读取。
</Callout>

### 5.2 Flash

<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-016.svg" alt="Flash 存储器" />

Flash 是可电擦写的非易失性半导体存储器，通常具有：

- 高密度；
- 按块擦除；
- 写入/擦除慢于读取；
- 擦写次数有限。

常见应用：

- SSD；
- U 盘；
- SD 卡；
- 手机和嵌入式存储；
- BIOS / UEFI 固件存储。

Flash 在 408 教材中常被放入 ROM 家族讨论，但它并不是“一次写死”。

### 5.3 CD-ROM

<InlineSvg src="/images/computer-organization/computer-organization-storage-defs-017.svg" alt="CD-ROM" />

CD-ROM 是**光学只读辅助存储介质**，不是半导体 ROM。它应归入外存/辅存层次理解。

## 6. 单体多字存储器：一次取更宽的数据

<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-001.svg" alt="多模块存储器整体分类" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-002.svg" alt="单体多字存储器" />

若一个普通存储器一次读出一个 $m$ bit 存储字，单体多字存储器可以让一次地址访问得到 $n$ 个连续字，则一次数据通路宽度可达

$$
nm\text{ bit}
$$

它适合连续数据访问，但要注意：

> 单体多字是“一次取出更宽的一组连续数据”，并不意味着多个存储体能够独立接受多个随机请求。

因此它与多体交叉存储器的并行机制不同。

---

## 7. 多体交叉：高位交叉与低位交叉

设主存被划分为 $m$ 个可相对独立工作的 Bank。

### 7.1 高位交叉

<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-003.svg" alt="高位交叉编址" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-004.svg" alt="高位交叉存储器结构" />

高位地址选择 Bank，低位地址选择体内位置。

结果是：

- 一段连续地址往往先集中在同一个 Bank；
- 适合模块化扩容；
- 不利于连续地址并行访问。

以 4 个 Bank、每体 $n$ 个字为例：

```text
M0：0 ~ n-1
M1：n ~ 2n-1
M2：2n ~ 3n-1
M3：3n ~ 4n-1
```

### 7.2 低位交叉

<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-005.svg" alt="低位交叉编址" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-006.svg" alt="低位交叉存储器硬件结构" />

低位地址选择 Bank，高位地址作为体内地址。

若 Bank 数为 $m$，字地址为 $A$，则：

$$
\text{Bank}(A)=A\bmod m
$$

$$
\text{BankOffset}(A)=\left\lfloor\frac{A}{m}\right\rfloor
$$

4 体低位交叉时：

```text
M0：0, 4, 8, 12, ...
M1：1, 5, 9, 13, ...
M2：2, 6, 10, 14, ...
M3：3, 7, 11, 15, ...
```

因此连续地址会轮流落到不同 Bank，更利于流水并行。

---

## 8. 低位交叉的时间模型与带宽

<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-007.svg" alt="单个存储体的存储周期" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-008.svg" alt="低位交叉连续访问时序" />
<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-009.svg" alt="多体交叉流水时序示意" />

设单个 Bank 的存储周期为 $T$，共有 $m$ 个低位交叉 Bank。更通用的分析方法是再引入**相邻请求的启动间隔** $\tau$。

若题目假设：

- 连续访问；
- 各 Bank 可并行工作；
- 总线和控制器不构成瓶颈；

则要想让连续请求轮流落到不同 Bank 且回到同一 Bank 时上一请求已经结束，应满足

$$
m\tau\ge T
$$

也就是理想情况下至少需要

$$
m\ge\left\lceil\frac{T}{\tau}\right\rceil
$$

个 Bank。

教材若进一步取 $\tau=T/m$，则稳态可每隔

$$
\frac{T}{m}
$$

启动一次新的连续访问请求。连续读取 $n$ 个字时，常见模型为

$$
T_{\text{total}}
=
T+(n-1)\tau
$$

在 $\tau=T/m$ 时即化为

$$
T_{\text{total}}
=
T+(n-1)\frac{T}{m}
$$

首个结果仍要经历一次完整访问，之后才体现流水吞吐。

### 8.1 访存冲突的快速判断

低位交叉中，地址 $A$ 所在 Bank 为

$$
A\bmod m
$$

两个请求落到同一 Bank **并不自动意味着冲突**。还必须看它们的时间间隔：若第二次访问到达该 Bank 时，前一次访问尚未结束，才产生 Bank 冲突。

对“每隔 $\tau$ 发出一个请求”的题目，若两个同 Bank 请求相隔 $k$ 次启动，则其时间间隔为 $k\tau$。当

$$
k\tau<T
$$

时会冲突；当 $k\tau\ge T$ 时该 Bank 已可再次接受请求。

<Callout type="warning" title="多体交叉提高吞吐率，不等于单字延迟缩短">
多体交叉主要让**不同 Bank 的访问重叠**。单个 Bank 自身的存储周期 $T$ 并没有变成 $T/m$；另外，“同 Bank”只是冲突的必要条件之一，还要结合请求到达时间。
</Callout>

## 9. 存储芯片规格：先看“字数 × 字长”

芯片规格 `M × N bit` 的含义是：

- 共有 $M$ 个可寻址存储字；
- 每个存储字宽 $N$ bit。

因此芯片总容量为

$$
M\times N\text{ bit}
$$

做芯片扩展题时先问：

1. 目标需要多少**字**？
2. 每个字需要多少 **bit**？
3. 当前芯片的“字数”和“字长”分别差多少倍？

## 10. 位扩展、字扩展与字位扩展

### 10.1 位扩展：增加字长

若目标字数不变，只需把每个字变宽，则多个芯片在**同一地址**下并行工作。

例如用 `16K × 8 bit` 构成 `16K × 32 bit`：

$$
\frac{32}{8}=4
$$

需要 4 片并联。

连接规律：

- 地址线共用；
- 通常同时片选；
- 每片负责数据总线的一部分。

### 10.2 字扩展：增加字数

例如用 `16K × 8 bit` 构成 `64K × 8 bit`：

$$
\frac{64K}{16K}=4
$$

需要 4 片，数据位宽不变。

每片内部有 $16K=2^{14}$ 个位置，因此低 14 位接芯片地址端；额外的高位用于片选。

若总共 64K 个地址，需要 16 位地址：

```text
A15 A14 | A13 ... A0
 片选    | 片内地址
```

### 10.3 字位扩展

![存储芯片基本结构](/images/computer-organization/computer-organization-storage-memory-010.png)
![位扩展法](/images/computer-organization/computer-organization-storage-memory-011.png)
<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-014.svg" alt="16K×8 位扩展为 16K×32" />
![字扩展法](/images/computer-organization/computer-organization-storage-memory-012.png)
<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-015.svg" alt="16K×8 字扩展为 64K×8" />
![字位扩展法](/images/computer-organization/computer-organization-storage-memory-013.png)
<InlineSvg src="/images/computer-organization/computer-organization-storage-memory-016.svg" alt="16K×8 字位扩展为 32K×16" />

若字数和字长都要扩大，则分别计算两个倍数：

$$
N_{\text{chips}}
=
\frac{\text{目标字数}}{\text{单片字数}}
\times
\frac{\text{目标字长}}{\text{单片字长}}
$$

例如用 `16K × 8 bit` 构成 `32K × 16 bit`：

$$
\frac{32K}{16K}\times\frac{16}{8}=2\times2=4
$$

## 11. 主存扩展题的地址线分配模板

这是主存芯片题最稳定的解法。

### 第一步：确定编址单位

若按字节编址，一个 $W$ bit 存储字内部含

$$
\frac{W}{8}
$$

个字节，因此字内偏移位数为

$$
\log_2\frac{W}{8}
$$

例如 32 bit 字按字节编址：

$$
\log_2 4=2
$$

最低 2 位只选择一个字中的字节。

### 第二步：确定芯片内部地址位

若单片有 $M=2^k$ 个存储字，则需要 $k$ 位选择片内字。

### 第三步：剩余高位做片选

若纵向需要 $g$ 组，则至少需要

$$
\lceil\log_2g\rceil
$$

位参与片选译码。

### 第四步：若题目问“某芯片的地址范围”，先算一组覆盖多少 CPU 地址

这是扩展题最容易漏的一步。设一组芯片共同构成一个逻辑存储字，单组包含 $2^k$ 个这样的字：

- 若 CPU **按字编址**，一组直接覆盖 $2^k$ 个 CPU 地址；
- 若 CPU **按字节编址**，每个逻辑字为 $W$ B，则一组覆盖 $2^kW$ 个 CPU 字节地址。

若一组覆盖的地址数为 $L$，整个存储区域基址为 $A_0$，某地址为 $A$，且各组按连续地址分配，则所在组的起始地址可直接写成

$$
A_{\text{start}}
=
A_0+
\left\lfloor\frac{A-A_0}{L}\right\rfloor L
$$

当存储区域从地址 0 开始时，才可简化为 $\left\lfloor A/L\right\rfloor L$。

<Callout type="info" title="一套固定检查表">

```text
CPU 地址
= 高位片选
+ 芯片内部地址
+ 低位字内/字节偏移（若存在）
```

1. 先确定 CPU 的编址单位；
2. 再确定一个逻辑存储字包含几个编址单位；
3. 扣掉最低位偏移；
4. 分配芯片内部地址位；
5. 剩余高位参与片选。

注意：最低位偏移是否真正接到存储芯片地址端，取决于芯片的数据宽度和系统如何组织字节选通信号，不能机械认为所有 CPU 地址位都接到芯片地址脚。

</Callout>
