## 3.10.1 SSD 为什么没有机械寻道

SSD（Solid State Drive）主要使用 NAND Flash 保存数据，没有旋转盘片、磁头和机械臂。

因此：

- 无机械寻道；
- 无旋转等待；
- 随机访问延迟远低于 HDD；
- 抗震性和静音表现更好；
- 但 Flash 存在擦写寿命和擦除粒度问题。

## 3.10.2 NAND Flash 的页与块

理解 SSD 时要记住一个基本不对称：

```text
读：以页为基本粒度
写/编程：以页为基本粒度
擦除：以更大的块为基本粒度
```

Flash 通常不能像 DRAM 一样直接对已有内容任意覆盖写入，需要遵循“先擦除，再重新编程”的物理约束。

因此 SSD 控制器必须承担大量管理工作。

## 3.10.3 SSD 控制器的核心任务

### FTL

FTL（Flash Translation Layer）把主机看到的逻辑块地址映射到实际 Flash 物理位置。

### Wear Leveling

磨损均衡让写入尽量分散到不同擦除块，避免某些单元过早耗尽擦写寿命。

### Garbage Collection

垃圾回收整理仍有效的数据，把可回收块集中擦除后重新使用。

### ECC

错误检测与纠正机制用于提高数据可靠性。

## 3.10.4 SSD 的“碎片”怎么理解

文件系统层面仍可能出现逻辑碎片，但 SSD 没有机械磁头，因此不会像 HDD 那样因为文件被拆散到远距离磁道而产生额外寻道时间。

所以：

> **“SSD 不需要传统碎片整理”不等于“SSD 逻辑上绝对没有碎片”。**

## 3.10.5 HDD 与 SSD 对比

| 项目 | HDD | SSD |
| --- | --- | --- |
| 存储介质 | 磁性盘片 | NAND Flash |
| 机械部件 | 有 | 无 |
| 寻道/旋转延迟 | 有 | 无 |
| 随机访问延迟 | 高 | 低 |
| 抗震 | 较差 | 较好 |
| 噪声 | 有机械噪声 | 基本无 |
| 大容量单位成本 | 通常较低 | 通常较高 |
| 主要寿命约束 | 机械部件等 | Flash 擦写寿命等 |

不要背某个固定 MB/s 数值。接口、协议、NAND 类型和产品代际都会改变实际性能。

## 3.10.6 RAID 的三种核心思想

RAID（Redundant Array of Independent Disks）把多个物理磁盘组织成一个逻辑存储系统。

核心手段：

- **Striping**：条带化，把数据分散到多盘，提高并行吞吐；
- **Mirroring**：镜像，保存完整副本；
- **Parity**：校验，通过冗余信息支持故障恢复。

## 3.10.7 常见 RAID 级别

设有 $n$ 块同容量磁盘，每块容量为 $S$。

| RAID | 核心方式 | 典型可用容量 | 典型容错 |
| --- | --- | --- | --- |
| RAID 0 | 条带化 | $nS$ | 0 块 |
| RAID 1 | 镜像 | 典型成对镜像时约 $nS/2$ | 每个镜像组可坏 1 块 |
| RAID 5 | 分布式单校验 | $(n-1)S$ | 任意 1 块 |
| RAID 6 | 分布式双校验 | $(n-2)S$ | 任意 2 块 |

> **RAID 0 没有“R”**
>
> RAID 0 能提升并行性能，但没有冗余，任何一块盘故障都可能破坏整个阵列的数据可用性。

## 3.10.8 Cache 与 RAID 的“冗余”不是一回事

Cache 保存数据副本，主要目标是**性能**。

RAID 中的镜像或校验信息则用于**容错与可靠性**。

普通 Cache 不能因为“也有一份副本”就等价于可靠性冗余；尤其回写 Cache 中的新数据甚至可能尚未同步到下层。

## 3.10.9 本章高频易错点总表

| 易错说法 | 正确理解 |
| --- | --- |
| SRAM 的“静态”表示非易失 | 静态只表示不需刷新，SRAM 仍是易失性 |
| DRAM 完整地址位数等于地址引脚数 | 地址复用可让行、列分时使用同一组引脚 |
| ROM 不能随机访问 | ROM 通常也可随机读，关键差异在写入与掉电保持 |
| Flash 不能改写 | Flash 可电擦写，只是写入/擦除机制不同于 RAM |
| 高位交叉让连续地址轮流落到各 Bank | 低位交叉才有这种效果 |
| 多体交叉让单次访问延迟缩短 $m$ 倍 | 它主要提高连续访问吞吐率 |
| $n$ 路组相联表示有 $n$ 组 | 表示每组有 $n$ 行 |
| Cache Miss 就是 Page Fault | 前者是物理块不在 Cache，后者是页面不在主存 |
| TLB Miss 就是 Page Fault | TLB Miss 后先查页表 |
| VA→PA 时页内偏移变化 | 页与页框同大小，VPO=PPO |
| Write-Back 命中立即写主存 | 命中时只改 Cache 并置 Dirty，淘汰时再写回 |
| Write-Through 必须有 Dirty | 通常不需要 Dirty 判断是否写回 |
| SSD 完全不存在碎片 | 逻辑碎片可存在，只是没有机械寻道惩罚 |

## 3.10.10 主存芯片扩展速查

目标规格与单片规格：

$$
M_T\times N_T,
\qquad
M\times N
$$

所需芯片数：

$$
N_{chip}=\left\lceil\frac{M_T}{M}\right\rceil
\left\lceil\frac{N_T}{N}\right\rceil
$$

连接顺序：

```text
字节偏移 → 单片内部地址 → 高位片选
```

## 3.10.11 Cache 地址速查

按字节编址、块大小 $B$：

$$
\text{Offset}=\log_2B
$$

$n$ 路组相联：

$$
S=\frac{C}{n}
$$

$$
\text{Index}=\log_2S
$$

$$
\text{Tag}=\text{PA bits}-\text{Index}-\text{Offset}
$$

## 3.10.12 页式地址转换速查

页面大小 $P$：

$$
p=\log_2P
$$

$$
\text{VPN bits}=\text{VA bits}-p
$$

$$
\text{PPN bits}=\text{PA bits}-p
$$

$$
\text{PA}=\text{PPN}\Vert\text{VPO}
$$

## 3.10.13 综合访存终极框架

```text
VA
↓
TLB
├─ Hit → PPN
└─ Miss → Page Table
            ├─ Present → PPN + 回填 TLB
            └─ Not Present → Page Fault → 辅存调页 → 重试
↓
PA
↓
Cache
├─ Hit → 数据
└─ Miss → Main Memory → 必要时替换/写回 → 填充 Cache
```

## 3.10.14 考前优先级

建议按以下顺序复习：

1. **Cache 映射、地址划分、写策略**；
2. **页表、TLB、完整 VA→PA→Cache 流程**；
3. **主存芯片扩展与多体交叉**；
4. **SRAM/DRAM/Flash 与 DRAM 刷新**；
5. **磁盘性能计算**；
6. RAID、SSD 基本概念。

> **最终原则**
>
> 存储系统不是一堆独立器件名词，而是一条“程序地址 → 地址翻译 → 高速缓存 → 主存 → 辅存”的层次链路。综合题永远先定位当前访问处在哪一层，再判断命中、替换、写回或异常。
