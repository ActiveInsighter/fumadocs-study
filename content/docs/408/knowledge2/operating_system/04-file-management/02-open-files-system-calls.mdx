文件一旦被打开，后续访问就不再反复使用完整路径，而是通过文件描述符快速定位内核中的打开状态。

> **真题标签**
>
> 进程文件管理：2020 年第 23 题、2024 年第 29 题、2025 年第 29 题。

## 4.2.1 三层结构

最稳妥的理解方式是：

```text
进程
  ↓ fd
进程文件描述符表
  ↓
系统打开文件表（open file description）
  ↓
inode / vnode
  ↓
文件数据块
```

三层分别回答：

| 层次 | 作用 |
| --- | --- |
| 进程文件描述符表 | 本进程的整数 `fd` 映射到哪个打开实例 |
| 系统打开文件表 | 记录该打开实例的偏移量、打开标志、引用计数等 |
| inode 表 | 记录底层文件元数据和数据块定位信息 |

## 4.2.2 文件描述符 fd

`fd` 是进程范围内的小非负整数。UNIX 类系统通常约定：

- `0`：标准输入；
- `1`：标准输出；
- `2`：标准错误。

执行：

```c
int fd = open("a.txt", O_RDWR);
```

成功后，`fd` 只是**进程文件描述符表的索引**，它既不是 inode 号，也不是磁盘块号。

## 4.2.3 系统打开文件表保存什么

典型表项包含：

- 当前文件偏移量；
- 打开模式与状态标志；
- 引用计数；
- 指向 inode / vnode 的引用。

例如：

```c
write(fd, "Hello", 5);
```

若当前偏移量为 0，成功写入 5 字节后，偏移量通常变为 5。

## 4.2.4 独立 `open()` 与 `dup()`

### 两次独立 `open()`

同一文件被独立打开两次时，通常形成两个打开实例：

```text
fdA → 打开表项 X ─┐
                  ├→ 同一 inode
fdB → 打开表项 Y ─┘
```

因此：

- 底层文件相同；
- inode 相同；
- 两个打开实例的偏移量可以彼此独立。

### `dup()` / 描述符继承

若两个 fd 引用同一个打开表项：

```text
fd3 ─┐
     ├→ 打开表项 X → inode
fd4 ─┘
```

则通常共享：

- 文件偏移量；
- 该打开实例的状态标志。

<Callout type="warn" title="按题目模型作答">
部分 408 教材/题目会把“系统打开文件表”抽象成按文件集中管理的系统表，并另设用户打开文件表。若题干给出明确表结构，应以题干模型为准；本节采用现代 UNIX 中常见的“每个独立 open 形成独立打开实例”来解释偏移量共享关系。
</Callout>

## 4.2.5 `open()` 的逻辑过程

典型步骤：

1. 解析路径；
2. 查目录项并找到 inode；
3. 检查访问权限；
4. 建立系统打开文件表项；
5. 在进程文件描述符表中建立引用；
6. 返回 `fd`。

所以 `open()` 的主要目标是**建立后续访问所需的内核状态**，不是把整个文件一次读入内存。

## 4.2.6 `close()`

`close(fd)` 通常完成：

- 删除本进程相应 fd 表项；
- 减少打开表项引用计数；
- 必要时释放该打开实例；
- 当底层文件没有其他有效引用且链接计数满足回收条件时，相关资源才可能最终释放。

> **易错点**
>
> `close()` 是关闭一个打开描述符，不等于删除文件。

## 4.2.7 `read()` 与 `write()`

```c
read(fd, buf, count);
write(fd, buf, count);
```

### `read()`

从当前偏移量开始读取，成功后通常推进文件偏移量。若数据已在页缓存中，可直接从内核缓存复制到用户空间；否则需要先发起外存 I/O。

**预读（read-ahead）**：发现顺序读取后，提前把后续块读入缓存，以提高后续命中率。

### `write()`

通常先修改页缓存，再在合适时机回写外存。这种**延迟写/回写**能够合并 I/O，但“`write()` 已返回”不必然表示数据已经稳定落盘。

需要更强持久化语义时，可使用类似 `fsync()` 的机制。

## 4.2.8 `lseek()`

`lseek()` 修改打开实例的当前文件偏移量：

- 跳到文件开头；
- 跳过一段数据；
- 定位到指定记录；
- 配合 `read/write` 实现随机访问。

它本身通常不读取文件数据。

## 4.2.9 多进程共享文件的判断框架

遇到“两个进程/两个 fd/同一文件”时依次问：

1. 是否指向同一 inode？——决定是不是同一底层文件；
2. 是否指向同一打开表项？——决定是否共享偏移量；
3. 是否是不同进程的 fd 表？——fd 数值相同也不代表同一个对象；
4. 是否发生 `fork/dup`？——常导致打开表项共享。

## 4.2.10 本节速查

> **fd 属于进程；打开表项描述“打开实例”；inode 描述底层文件。**

> **独立 open 可独立偏移；共享同一打开表项时共享偏移。**
