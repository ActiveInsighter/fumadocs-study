文件系统把用户级文件抽象与底层存储设备连接起来，既要管理单个文件，也要维护整个卷/分区的全局结构。

> **真题标签**
>
> VFS：2025 年第 28 题。文件系统综合分析常与 inode、索引分配、目录和空闲空间管理组合考查。

## 4.7.1 扇区与文件系统块

### 扇区

更接近存储设备的底层传输单位，常见为 512 B 或 4 KiB。

### 文件系统块 / 盘块 / 簇

文件系统进行分配和管理的逻辑单位，通常由一个或多个扇区组成。

> **做题原则**
>
> 题目给“盘块大小”时，文件大小、索引块容量和位图通常都围绕盘块进行；不要把扇区号和文件系统块号混用。

## 4.7.2 一个文件系统的典型磁盘布局

可抽象为：

```text
文件系统
├── 引导相关区域
├── 超级块
├── inode 位图 / 管理信息
├── 数据块位图 / 空闲空间管理信息
├── inode 区
└── 数据区
```

### 超级块 Superblock

描述**整个文件系统**，典型信息：

- 文件系统总大小；
- 块大小；
- 块总数；
- inode 总数；
- 空闲空间状态；
- 文件系统状态和关键布局参数。

### inode 位图

记录哪些 inode 已被占用。

### 数据块位图

记录哪些数据块已被占用。

### inode 区

持久存放 inode。

### 数据区

可保存：

- 普通文件内容；
- 目录文件内容；
- 文件索引块；
- 其他文件系统数据结构。

## 4.7.3 分区与文件系统

磁盘可划分多个分区，每个分区可建立不同文件系统。MBR、GPT 负责描述分区布局；本章重点是**分区内部的文件系统结构**，不要把分区表与超级块混为一谈。

## 4.7.4 VFS：统一抽象层

操作系统可能同时支持 ext4、FAT、NTFS、ISO 9660、NFS 等不同文件系统。VFS（Virtual File System）的作用是为它们提供统一接口：

```text
应用程序
   ↓
open / read / write / close
   ↓
VFS
 ┌──────┬──────┬──────┐
 ↓      ↓      ↓
ext4    FAT    NFS
 ↓      ↓      ↓
本地盘  U盘    网络
```

VFS 不是一种具体磁盘格式，而是一层**统一文件对象和操作接口的抽象框架**。

## 4.7.5 VFS 的核心价值

1. **统一系统调用接口**：应用层无需为每种文件系统编写不同 API；
2. **屏蔽实现差异**：本地盘、网络文件系统等可采用统一访问方式；
3. **支持扩展**：具体文件系统实现 VFS 约定的操作后即可接入。

## 4.7.6 一次文件访问如何穿过 VFS

以：

```c
read(fd, buf, size);
```

为例，可抽象为：

```text
用户进程
  ↓ 系统调用
VFS
  ↓ 根据对象/挂载点确定具体文件系统
具体文件系统实现
  ↓
块设备层 / 驱动 / 网络
  ↓
数据返回
```

## 4.7.7 文件系统挂载

**挂载（mount）**&#x2060;是把一个独立文件系统接入当前目录树中的某个目录。

```text
原目录树
   /
   ├── home
   └── mnt  ← 挂载点
                 ↓
          外部文件系统根目录
```

挂载后，应用程序仍使用统一路径访问。

## 4.7.8 挂载点为什么不必为空

挂载点是目录树中的普通目录。若目录原来有内容，挂载新文件系统后，这些原内容通常暂时被遮蔽；卸载后又可重新看到。

所以：

> **“挂载点必须是空目录”不是一般性的必然条件。**

## 4.7.9 文件访问的全局链路

路径阶段：

```text
路径字符串
  ↓
VFS / 路径解析
  ↓
目录项
  ↓
inode
```

数据阶段：

```text
inode
  ↓
直接/间接索引
  ↓
文件系统块
  ↓
块设备 / 网络存储
```

打开后：

```text
fd → 打开文件表项 → inode → 数据块
```

这三条链路是文件系统综合题的核心骨架。
