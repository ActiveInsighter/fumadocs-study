目录的本质是建立：**名字 → 文件控制信息** 的映射。在 UNIX 类文件系统中，可进一步写成：

```text
文件名 → inode 号 → inode → 数据块
```

## 4.5.1 树形目录

现代文件系统通常使用层次化树形目录：

```text
/
├── home
│   └── alice
│       └── a.txt
├── etc
└── usr
```

其中 `/` 是根目录。

### 绝对路径

从根目录开始，例如：

```text
/home/alice/a.txt
```

### 相对路径

从当前工作目录开始。常见特殊目录：

- `.`：当前目录；
- `..`：父目录。

## 4.5.2 目录本身也是特殊文件

目录文件的数据块中保存一个个**目录项（directory entry）**：

```text
"."      → inode 100
".."     → inode 99
"a.txt"  → inode 123
"docs"   → inode 200
```

目录项最核心的两个成分：

- 文件名；
- 对应 inode 号。

目录项通常不需要重复保存完整 inode 元数据。

## 4.5.3 路径解析不是“一次查到”

解析：

```text
/home/alice/a.txt
```

大致过程：

```text
根目录 inode
   ↓ 读取根目录项
查找 "home"
   ↓ 得到 home inode
读取 home 目录
   ↓ 查找 "alice"
得到 alice inode
   ↓ 读取 alice 目录
查找 "a.txt"
   ↓
得到 a.txt inode
```

因此路径层级越深，若没有缓存，理论上可能产生更多目录相关 I/O。

## 4.5.4 目录缓存为什么有效

路径解析会重复访问：

- 常用目录 inode；
- 目录项；
- 路径前缀。

因此缓存目录项 / inode 后，可显著减少重复磁盘读取。

在题目中，如果明确“目录块、inode 已在内存”，路径解析所需磁盘 I/O 要相应减少。

## 4.5.5 文件与目录操作背后的本质

常见操作可以理解为对目录项、inode 和数据块的组合修改：

- 创建文件：分配 inode，增加目录项，必要时分配数据块；
- 删除文件名：删除目录项，减少链接计数；
- 重命名：主要修改目录项；
- 创建目录：分配目录 inode 和目录数据块，并建立 `.`、`..` 等关系；
- 移动文件：在目录树中改变目录项归属。

## 4.5.6 文件名相同不等于同一个文件

不同目录可以有相同文件名：

```text
/home/a.txt
/tmp/a.txt
```

是否是同一个底层文件，应看最终 inode，而不是只看最后一级名称。

## 4.5.7 绝对路径唯一性的边界

在普通树形目录模型下，从根到节点的路径唯一。但引入：

- 硬链接；
- 符号链接；
- 挂载；

后，同一个底层对象可能通过多个路径访问。因此考试中应区分“目录树中的路径”与“底层 inode 是否相同”。
