虚拟内存不仅要决定“缺页时淘汰谁”，还要先决定：

> **一个进程当前可以拥有多少个物理页框。**

这是页框分配与回收问题。

> **真题标签**
>
> 驻留集曾在 2012 年第 45 题、2016 年第 29 题等题目中考查；固定/可变分配与局部/全局置换在 2015 年第 30 题、2010 年第 46 题等题目中出现；抖动曾在 2011 年第 29 题考查。

## 3.6.1 驻留集与驻留集大小

**驻留集（Resident Set）**&#x2060;是某进程当前实际驻留在物理内存中的页面集合。

例如进程有虚拟页：

```text
0 1 2 3 4 5 6 7
```

当前在内存的是：

```text
{0,1,3,5}
```

则驻留集大小：

$$
RSS=4\text{ 页}
$$

驻留集太小会增加缺页；太大则会挤压其他进程。

## 3.6.2 工作集

**工作集（Working Set）**&#x2060;可理解为在某个最近时间窗口内，进程活跃使用的页面集合。

工作集反映的是“这一阶段真正需要哪些页面”，驻留集反映的是“现在内存里实际有哪些页面”。

理想状态是：

> 驻留集能够较好覆盖当前工作集。

## 3.6.3 固定分配与可变分配

这里的“固定/可变”指**页框数量**，不是连续分配中的固定/动态分区。

### 固定分配

进程运行期间拥有的页框数量基本保持不变。

若页框都满了，缺页时只能通过置换腾位置。

### 可变分配

操作系统可根据：

- 缺页率；
- 工作集；
- 系统负载；
- 空闲物理内存

动态增加或回收进程页框。

## 3.6.4 局部置换与全局置换

### 局部置换

牺牲页只能从当前进程自己的驻留集中选。

特点：

- 进程之间干扰较小；
- 该进程页框总量是否变化取决于分配策略。

### 全局置换

牺牲页可以从系统范围的可置换页中选。

因此进程 A 的缺页可能把进程 B 的页面淘汰。

## 3.6.5 三种有效组合

| 页框分配 | 置换范围 | 是否合理 |
| --- | --- | --- |
| 固定分配 | 局部置换 | 是 |
| 可变分配 | 局部置换 | 是 |
| 可变分配 | 全局置换 | 是 |
| 固定分配 | 全局置换 | **否** |

为什么“固定分配 + 全局置换”矛盾？

- 固定分配要求各进程拥有页框数固定；
- 全局置换允许一个进程抢占其他进程页框；
- 这会改变进程实际拥有的页框数量。

所以两者语义冲突。

## 3.6.6 页框回收的基本思想

当系统空闲页框不足时，需要回收可回收页面。一般应区分：

- **干净页**：若后备副本仍有效，可直接回收；
- **脏页**：回收前通常需要写回；
- **正在使用或不可换出页面**：不能任意回收。

可变分配系统中，页框回收还意味着某些进程的驻留集大小可能下降。

## 3.6.7 抖动 Thrashing

当分配给进程的页框不足以覆盖其活跃工作集时，会出现：

```text
页框不足
  ↓
刚换出的页很快又要访问
  ↓
缺页率剧增
  ↓
页面频繁换入/换出
  ↓
磁盘 I/O 激增
  ↓
CPU 大量等待
  ↓
吞吐量下降
```

这就是**抖动**。

<Callout type="warn" title="抖动的反直觉表现">
抖动严重时 CPU 利用率可能下降，而不是升高，因为 CPU 大量时间在等待慢速的页面调入 I/O。
</Callout>

## 3.6.8 虚拟内存性能的核心量：缺页率

若页面访问总次数为 $N$，缺页次数为 $F$：

$$
p=\frac{F}{N}
$$

其中 $p$ 为缺页率。

若普通内存访问时间约为 $t_m$，一次缺页服务的平均时间为 $t_f$，可用简化模型理解有效访问时间：

$$
EAT\approx (1-p)t_m+p t_f
$$

由于：

$$
t_f\gg t_m
$$

即使 $p$ 很小，也可能显著拖慢系统。

例如若 $t_m=100\text{ ns}$、$t_f=10\text{ ms}=10^7\text{ ns}$，缺页代价比普通内存访问高约五个数量级。

## 3.6.9 影响虚拟存储性能的主要因素

### 1. 页框数量

太少 → 缺页率高；太多 → 单进程性能可能好，但系统并发度下降。

### 2. 页面大小

页面过小：

- 页表更大；
- TLB 覆盖范围变小；
- 每次调页 I/O 数据量较少。

页面过大：

- 页表更小；
- 空间局部性利用更好；
- 可能调入大量无用数据；
- 内部碎片增大。

### 3. 页面置换算法

更准确地保留“将来更可能被使用”的页面，可降低缺页率。

### 4. 页面写回策略

脏页换出需要额外写 I/O，适当延迟/聚合写回可降低同步写的频率。

### 5. 程序局部性

局部性越好，工作集越稳定，虚拟内存越有效。

## 3.6.10 常见性能改进思路

- 根据工作集或缺页率动态调整驻留集；
- 抖动时减少多道程序度，让活跃进程获得足够页框；
- 使用 LRU/Clock 等更合理的置换策略；
- 对访问模式合适的场景进行预取；
- 合理选择页面大小；
- 尽量避免无意义的随机大跨度访问，提高空间/时间局部性；
- 对脏页采用合适的后台写回策略。

## 3.6.11 高频概念辨析

| 概念 | 讨论对象 |
| --- | --- |
| 固定/动态分区 | 连续内存分配方式 |
| 固定/可变分配 | 一个进程拥有多少页框 |
| 局部/全局置换 | 牺牲页允许从哪里选 |
| 驻留集 | 当前实际在内存的页 |
| 工作集 | 最近一段时间活跃使用的页 |
| 抖动 | 工作集无法稳定驻留导致频繁换页 |
