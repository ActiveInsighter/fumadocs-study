## 28. 内存映射文件

> **真题考查**
>
> 2025 年第 30 题、2026 年第 30 题。

**内存映射文件（Memory-Mapped File）** 允许进程把文件的一段内容映射到自己的虚拟地址空间，之后通过普通内存读写指令访问文件数据。

在类 Unix 系统中，典型接口是：

```c
mmap(...)
```

### 28.1 mmap 的基本过程

<InlineSvg src="/images/operating-system/operating-system-memory-management-019.svg" alt={"内存映射文件与进程地址空间"} />

调用 `mmap` 时，进程会指定：

- 文件对象；
- 文件偏移；
- 映射长度；
- 访问权限；
- 映射属性。

操作系统建立：

```text
进程虚拟地址区间  ↔  文件对应区间
```

但**建立映射不等于立刻把整个文件读入内存**。

通常仍采用按需调页：

1. 首次访问某个尚未驻留的映射页；
2. 发生缺页；
3. 内核根据映射关系定位文件中的对应页；
4. 把文件页调入物理内存；
5. 建立/更新页表映射；
6. 重新执行原访问指令。

因此 `mmap` 是文件系统与虚拟内存机制结合的典型应用。

### 28.2 普通 read 与 mmap 的区别

传统 `read` 的逻辑路径通常可理解为：

```text
文件/磁盘
   ↓
内核页缓存
   ↓ 复制
用户缓冲区
```

如果数据已经在页缓存中，就不必重新从磁盘读取，但一般仍需要把数据复制到用户提供的缓冲区。

而 `mmap` 可以让与文件页对应的物理页面直接映射到进程虚拟地址空间：

```text
文件页 / 页缓存中的物理页
             ↕
      进程虚拟地址
```

这样可以避免普通 `read` 路径中一次典型的“页缓存 → 用户缓冲区”复制。

<Callout type="warn" title="mmap 不是简单绕过页缓存">

文件映射页通常仍可由页缓存支撑。`mmap` 的关键是把这些页面直接纳入进程地址空间，而不是笼统地说“绕过内核缓存”。

</Callout>

### 28.3 mmap 的主要优点

**减少数据复制：**&#x2060;对大文件或频繁访问文件尤其有意义。

**按需加载：**&#x2060;只有真正访问的映射页才需要进入物理内存。

**访问方式自然：**&#x2060;程序可以像访问数组一样使用文件内容。

**便于共享：**&#x2060;多个进程可映射同一文件区域，从而共享底层物理页。

### 28.4 共享映射、私有映射与虚拟地址

> **真题考查**
>
> 2026 年第 30 题。

同一文件区域被多个进程做**共享映射**时，各进程中的虚拟地址可以不同：

```text
P1: 虚拟地址 W1 ─┐
                  ├→ 同一个驻留的文件物理页
P2: 虚拟地址 W2 ─┘
```

因此应牢记：

- 不同进程的虚拟地址 $W_1$、$W_2$ **不必相同**；
- 各进程页表项本身也不必逐位完全相同；
- 但若它们当前共享同一个文件页，页表映射可指向同一个物理页框；
- 共享映射下，一方对共享页的修改对另一方可见的具体时机仍受一致性与同步规则约束。

若采用**私有映射**，典型实现可结合写时复制（COW）：最初多个映射可共享物理页，某个进程第一次写入时再为它复制私有页，因此之后不再把该写入直接传播给原文件或其他私有映射。

<Callout type="warn" title="“映射同一文件”不自动等于“永远共享同一物理页”">
考试若明确说“共享文件/共享映射”，通常按共享物理页理解；若是私有映射或发生 COW，则写入后物理页可能分离。优先服从题目对映射语义的描述。
</Callout>

### 28.5 写映射

若进程对映射页面执行写操作，页面可能被标记为脏页。

之后根据映射类型和系统策略：

- 修改可能最终写回对应文件；
- 或采用私有写时复制等语义，不直接改动原文件。

具体行为取决于映射类型，但考试最重要的是理解：

> **文件映射页仍参与虚拟内存的缺页、页表映射和脏页管理。**

## 29. 内存管理方式总对比

| 管理方式 | 物理存放要求 | 是否必须一次全部装入 | 典型碎片 | 核心特点 |
| --- | --- | --- | --- | --- |
| 单一连续 | 整个用户程序连续 | 是 | 通常不是重点 | 一次一道用户程序 |
| 固定分区 | 每个进程占一个连续固定分区 | 是 | 内部碎片 | 分区预先划好 |
| 动态分区 | 每个进程占一块连续区域 | 是 | 外部碎片 | 按请求动态切割空闲区 |
| 基本分页 | 页可装入离散页框 | 是 | 内部碎片 | 固定页/页框，页表映射 |
| 基本分段 | 段间可离散，段内连续 | 是 | 外部碎片 | 按程序逻辑分段 |
| 基本段页式 | 页框可离散 | 是 | 页内内部碎片 | 先分段再分页 |
| 请求分页虚拟存储 | 页可离散 | 否 | 与分页相关 | 按需调页，可部分驻留 |

<Callout type="info" title="“基本”二字很重要">

“分页”本身并不自动等于“虚拟内存”。**基本分页**可以要求进程全部页面同时在内存；只有引入请求调页、缺页处理等机制后，才形成请求分页虚拟存储。

</Callout>

## 30. 虚拟存储器性能的影响因素与改进

> **真题考查**
>
> 2026 年第 29 题。

虚拟内存的性能不能只看“页面置换算法好不好”，而要把**地址翻译成本 + 缺页成本 + 页面写回成本**放在同一条链上理解。

### 30.1 TLB 命中率

TLB 命中时可以省去内存中的页表遍历，因此较高的 TLB 命中率能明显降低普通地址翻译开销。

但注意：

> **多级页表主要节省页表空间，本身并不保证更低的平均访存时间。**

在 TLB 未命中时，多级页表反而可能需要更多次页表访存。

### 30.2 缺页率是最关键的数量级因素

设：

- 正常访存平均耗时为 $t_m$；
- 缺页概率为 $p$；
- 一次缺页从陷入内核、可能置换、外存 I/O 到恢复执行的平均代价为 $t_{pf}$。

则可用简化模型表示：

$$
EAT=(1-p)t_m+p\,t_{pf}
$$

由于通常：

$$
t_{pf}\gg t_m
$$

即使 $p$ 很小，也可能显著拉高平均访存时间。因此减少缺页往往比在普通内存访问路径上节省几个纳秒更重要。

### 30.3 页面大小

页面过小：

- 页表项更多，页表更大；
- TLB 覆盖的虚拟地址范围更小；
- 页面 I/O 次数可能增多。

页面过大：

- 最后一页内部碎片可能增大；
- 一次缺页调入更多暂时用不到的数据；
- 页面传输单次数据量更大。

因此页面大小是“页表开销、TLB 覆盖、局部性、I/O 与内部碎片”之间的折中。

### 30.4 驻留集、工作集与页框回收

若给某进程的页框少于当前活跃工作集，需要的页面会互相挤出，缺页率升高，严重时形成抖动；若页框远多于工作集，则会降低系统能同时容纳的其他进程数量。

系统可以结合：

- 工作集估计；
- 缺页频率；
- 当前空闲页框；
- 进程优先级与系统负载

动态增减驻留集，并在内存紧张时回收冷页面。

### 30.5 脏页比例与写回代价

淘汰干净页通常不需要写回；淘汰脏页往往需要一次额外外存写操作。因此改进型 Clock 会把 $(R,M)=(0,0)$ 的页面放在更高淘汰优先级。

### 30.6 常见改进方向

| 性能问题 | 典型改进思路 |
| --- | --- |
| 页表遍历慢 | TLB、提高 TLB 命中率 |
| 页表太大 | 多级页表、稀疏地址空间按需建立下级页表 |
| 缺页过多 | 增加合适页框、工作集/PFF 调整、改进置换策略 |
| 抖动 | 降低多道程序度或给进程补足活跃工作集所需页框 |
| 脏页写回多 | 优先回收干净冷页、后台适时写回脏页 |
| 顺序局部性强 | 合理预取/预调页可减少后续同步缺页，但过度预取会浪费 I/O 与页框 |

<Callout type="warn" title="性能优化没有单一“越大越好”">
页框越多、页面越大、预取越激进都可能在某些场景产生副作用。408 题目通常要求根据给定访问模式、页框数和硬件参数定量判断，而不是套固定口号。
</Callout>

## 31. 高频易错点

### 31.1 分页不等于虚拟内存

基本分页可以让进程离散存放，但仍要求所有页面在运行前全部装入。

虚拟内存的关键是：

> **部分装入 + 按需调入 + 地址转换支持。**

### 31.2 页内偏移不变

虚拟地址：

```text
虚拟页号 | 页内偏移
```

物理地址：

```text
物理页框号 | 页内偏移
```

只替换页号对应关系，页内偏移保持不变。

### 31.3 页与页框必须等大

否则无法保持同一页内偏移直接落入对应页框的相同位置。

### 31.4 分页仍有内部碎片

若进程大小不是页面大小的整数倍，最后一页通常不能完全利用。

若假定进程大小在页面边界内均匀分布，则最后一页的**平均内部碎片**常近似为半页；但具体题目应按给定进程大小精确计算。

### 31.5 分段仍会产生外部碎片

段长可变，且每个段内部通常连续，因此物理内存可能被切成许多不连续的小空闲区。

### 31.6 页表项地址要乘页表项大小

若页表基址为 $B$，页号为 $p$，页表项大小为 $E$：

$$
PTEAddr=B+pE
$$

不能在数值题中直接写成 $B+p$，除非题目明确已经按页表项编号寻址。

### 31.7 缺页不一定发生置换

有空页框时：

> 缺页 → 直接装入。

无空页框时：

> 缺页 → 选择牺牲页 → 必要时写回 → 调入新页。

因此：

$$
\text{置换次数}\le\text{缺页次数}
$$

### 31.8 页面命中不会移动 Clock 指针

简单 Clock 命中已驻留页面时，通常只把该页面：

$$
R\leftarrow 1
$$

不会因为命中而主动移动指针。

### 31.9 FIFO 命中不改变进入顺序

FIFO 依据“装入先后”而非“最近访问”。命中不会把页面重新放到队尾。

### 31.10 OPT 看未来，LRU 看过去

- OPT：比较**下一次**访问距离现在有多远；
- LRU：比较**上一次**访问距离现在有多远。

### 31.11 固定/可变分配不是固定/动态分区

前者讨论请求分页中**页框数是否可变**；后者讨论连续内存中**分区大小是否预先固定**。两组概念完全不同。

### 31.12 工作集不是驻留集

- 驻留集：当前真正装在物理内存中的页面集合；
- 工作集：某一时间窗口内进程近期活跃访问的页面集合。

理想状态是让驻留资源能够较好覆盖活跃工作集，从而降低缺页率。

### 31.13 TLB 未命中不等于缺页

TLB Miss 只表示“快表里没有这个翻译结果”。接下来访问页表时，如果 PTE 表明页面已驻留，则只需得到页框号并更新 TLB，不需要访问磁盘。

### 31.14 多级页表不等于更快的地址翻译

多级页表的首要价值是**稀疏地址空间下节省页表内存**。如果没有 TLB，级数越多，完整页表遍历通常需要越多次内存访问。

### 31.15 TLB 命中不等于 Cache 命中

TLB 解决“虚拟地址怎么翻译成物理地址”，Cache 解决“物理地址对应的数据是否已经在高速缓存”。二者命中/未命中是两个维度。

### 31.16 虚拟地址相同不代表物理地址相同

两个进程都可能访问虚拟地址 `0x400000`，但各自页表可把它们映射到完全不同的物理页框。反过来，共享内存或共享文件映射也允许**不同虚拟地址映射到同一物理页**。

## 32. 页表、TLB 与 Cache 综合题统一模板

这类题常把操作系统内存管理和计算机组成原理 Cache 放在同一问中。最稳妥的方法是按真实路径逐层判断。

### 32.1 先从页面大小确定页内偏移

若页面大小为：

$$
P=2^b\text{ B}
$$

则页内偏移占 $b$ 位，剩余高位构成虚页号或多级页表索引。

### 32.2 再拆多级页表索引

若地址格式已给出，直接按各字段位数提取；若只给页面大小和 PTE 大小，则先求一张页表可放多少项，再反推每一级索引位数。

### 32.3 查询 TLB

若题目给出 TLB：

1. 用虚页号构造 TLB 的组号/标记；
2. 命中 → 直接得到物理页框号；
3. 未命中 → 再查内存页表。

### 32.4 查页表并判断是否缺页

- PTE 有效且页面在内存 → 得到页框号，可回填 TLB；
- PTE 表明页面不在内存 → 缺页异常，由 OS 调页；
- 地址/权限非法 → 不是普通缺页，而是访问异常。

### 32.5 形成物理地址

页内偏移不变：

$$
PA=\text{FrameNo}\times P+\text{Offset}
$$

### 32.6 若题目还有 Cache，再用物理地址查 Cache

典型物理地址拆分为：

```text
Tag | Cache 组/行索引 | 块内偏移
```

此时才判断 Cache 命中或缺失。

<Callout type="info" title="一条链记住四种结果">
```text
TLB Hit/Miss
    ↓
Page Table Hit / Page Fault
    ↓
形成物理地址
    ↓
Cache Hit/Miss
    ↓
必要时访问主存
```

- TLB Miss：通常只是多查页表；
- Page Fault：可能要访问外存，代价最大；
- Cache Miss：通常去主存取块；
- 四者不能用“命中/缺失”两个字混成同一层次。
</Callout>

## 33. 页面置换题统一解题模板

页面置换综合题最稳妥的方法不是心算，而是固定表格逐列推进。

### 33.1 第一步：写清访问串与页框数

例如：

```text
访问串：7 0 1 2 0 3 0 4 2 3 0 2
页框数：3
```

### 33.2 第二步：为每次访问先判断命中/缺页

每访问一个页面，第一问始终是：

> 该页面当前是否已经驻留？

若命中，再按算法更新状态：

- FIFO：顺序不变；
- LRU：更新最近访问次序；
- Clock：把 $R$ 置 1；
- OPT：一般不需要更新特殊队列状态。

### 33.3 第三步：缺页时先看有没有空页框

- 有空页框 → 直接装入；
- 无空页框 → 执行对应置换算法。

这是区分“缺页次数”和“置换次数”的关键。

### 33.4 第四步：按算法维护额外状态

**FIFO：**&#x2060;维护进入顺序。

**LRU：**&#x2060;维护最近访问顺序。

**OPT：**&#x2060;向右观察未来访问位置。

**Clock：**&#x2060;维护 $R$ 和时钟指针。

**改进型 Clock：**&#x2060;同时维护 $R$、$M$ 与扫描轮次。

### 33.5 第五步：分别统计结果

设：

- 缺页次数为 $F$；
- 访问总次数为 $N$；
- 实际淘汰旧页次数为 $R_p$。

则缺页率为：

$$
\text{Page Fault Rate}=\frac{F}{N}
$$

并单独记录 $R_p$，不要与 $F$ 混淆。

## 34. 动态分区题统一解题模板

动态分区题的核心是：

> **每次操作后都更新当前空闲表。**

建议始终画成：

```text
起始地址 | 大小
```

### 34.1 分配步骤

对每次申请：

1. 找出所有可容纳请求的空闲块；
2. 按 First/Next/Best/Worst Fit 选块；
3. 从选中空闲块中划出请求大小；
4. 更新剩余块的起始地址和大小；
5. 若恰好用完，则删除该空闲块表项。

### 34.2 回收步骤

释放分区时：

1. 确定释放区起始地址和大小；
2. 检查前方是否为空闲块；
3. 检查后方是否为空闲块；
4. 相邻则合并；
5. 更新空闲表顺序和大小。

### 34.3 Next Fit 额外注意

必须持续记录游标位置。后续分配不能擅自回到表头，除非游标扫描已经循环到表尾并按规则回绕。

## 35. 本章核心知识链

主线一：**从连续分配到虚拟存储**

```text
单一连续分配
        ↓
固定分区
        ↓
内部碎片明显
        ↓
动态分区
        ↓
外部碎片
        ↓
分页
        ↓
物理内存可离散分配
        ↓
虚拟存储
        ↓
进程不必全部驻留
        ↓
请求分页
        ↓
缺页
        ↓
页框不足
        ↓
页面置换
        ↓
FIFO / OPT / LRU / Clock
        ↓
页框与工作集不匹配
        ↓
抖动
```

主线二：**分页、分段、段页式**

```text
分页
→ 固定大小、机械划分、利于离散分配

分段
→ 可变大小、逻辑划分、利于保护与共享

段页式
→ 逻辑上按段组织，物理上按页离散分配
```

主线三：**地址转换**

```text
虚拟地址
→ 提取页号/多级索引/段号与偏移
→ 先查 TLB（若有）
→ TLB Miss 时查页表/段表
→ 合法性、存在位与权限检查
→ 不驻留则缺页调页
→ 得到物理页框号或段基址
→ 形成物理地址
→ 再进入 Cache/主存数据访问路径
```

<Callout type="info" title="本章最后应达到的理解">

- 连续分配主要解决“怎样找一整块内存”；
- 分页解决“物理内存不连续也能运行”；
- 分段解决“怎样按程序逻辑组织、保护和共享”；
- 虚拟存储解决“程序不必全部驻留内存”；
- 页面置换解决“页框不够时淘汰谁”；
- `mmap` 展示了虚拟内存机制如何与文件系统协同。

</Callout>
