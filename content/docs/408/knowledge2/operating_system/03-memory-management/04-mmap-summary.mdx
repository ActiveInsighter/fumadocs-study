## 28. 内存映射文件

> **真题考查**
>
> 2025 年第 30 题、2026 年第 30 题。

**内存映射文件（Memory-Mapped File）** 允许进程把文件的一段内容映射到自己的虚拟地址空间，之后通过普通内存读写指令访问文件数据。

在类 Unix 系统中，典型接口是：

```c
mmap(...)
```

### 28.1 mmap 的基本过程

<InlineSvg src="/images/operating-system/operating-system-memory-management-019.svg" alt={"内存映射文件与进程地址空间"} />

调用 `mmap` 时，进程会指定：

- 文件对象；
- 文件偏移；
- 映射长度；
- 访问权限；
- 映射属性。

操作系统建立：

```text
进程虚拟地址区间  ↔  文件对应区间
```

但**建立映射不等于立刻把整个文件读入内存**。

通常仍采用按需调页：

1. 首次访问某个尚未驻留的映射页；
2. 发生缺页；
3. 内核根据映射关系定位文件中的对应页；
4. 把文件页调入物理内存；
5. 建立/更新页表映射；
6. 重新执行原访问指令。

因此 `mmap` 是文件系统与虚拟内存机制结合的典型应用。

### 28.2 普通 read 与 mmap 的区别

传统 `read` 的逻辑路径通常可理解为：

```text
文件/磁盘
   ↓
内核页缓存
   ↓ 复制
用户缓冲区
```

如果数据已经在页缓存中，就不必重新从磁盘读取，但一般仍需要把数据复制到用户提供的缓冲区。

而 `mmap` 可以让与文件页对应的物理页面直接映射到进程虚拟地址空间：

```text
文件页 / 页缓存中的物理页
             ↕
      进程虚拟地址
```

这样可以避免普通 `read` 路径中一次典型的“页缓存 → 用户缓冲区”复制。

<Callout type="warn" title="mmap 不是简单绕过页缓存">

文件映射页通常仍可由页缓存支撑。`mmap` 的关键是把这些页面直接纳入进程地址空间，而不是笼统地说“绕过内核缓存”。

</Callout>

### 28.3 mmap 的主要优点

**减少数据复制：**&#x2060;对大文件或频繁访问文件尤其有意义。

**按需加载：**&#x2060;只有真正访问的映射页才需要进入物理内存。

**访问方式自然：**&#x2060;程序可以像访问数组一样使用文件内容。

**便于共享：**&#x2060;多个进程可映射同一文件区域，从而共享底层物理页。

### 28.4 写映射

若进程对映射页面执行写操作，页面可能被标记为脏页。

之后根据映射类型和系统策略：

- 修改可能最终写回对应文件；
- 或采用私有写时复制等语义，不直接改动原文件。

具体行为取决于映射类型，但考试最重要的是理解：

> **文件映射页仍参与虚拟内存的缺页、页表映射和脏页管理。**

## 29. 内存管理方式总对比

| 管理方式 | 物理存放要求 | 是否必须一次全部装入 | 典型碎片 | 核心特点 |
| --- | --- | --- | --- | --- |
| 单一连续 | 整个用户程序连续 | 是 | 通常不是重点 | 一次一道用户程序 |
| 固定分区 | 每个进程占一个连续固定分区 | 是 | 内部碎片 | 分区预先划好 |
| 动态分区 | 每个进程占一块连续区域 | 是 | 外部碎片 | 按请求动态切割空闲区 |
| 基本分页 | 页可装入离散页框 | 是 | 内部碎片 | 固定页/页框，页表映射 |
| 基本分段 | 段间可离散，段内连续 | 是 | 外部碎片 | 按程序逻辑分段 |
| 基本段页式 | 页框可离散 | 是 | 页内内部碎片 | 先分段再分页 |
| 请求分页虚拟存储 | 页可离散 | 否 | 与分页相关 | 按需调页，可部分驻留 |

<Callout type="info" title="“基本”二字很重要">

“分页”本身并不自动等于“虚拟内存”。**基本分页**可以要求进程全部页面同时在内存；只有引入请求调页、缺页处理等机制后，才形成请求分页虚拟存储。

</Callout>

## 30. 高频易错点

### 30.1 分页不等于虚拟内存

基本分页可以让进程离散存放，但仍要求所有页面在运行前全部装入。

虚拟内存的关键是：

> **部分装入 + 按需调入 + 地址转换支持。**

### 30.2 页内偏移不变

虚拟地址：

```text
虚拟页号 | 页内偏移
```

物理地址：

```text
物理页框号 | 页内偏移
```

只替换页号对应关系，页内偏移保持不变。

### 30.3 页与页框必须等大

否则无法保持同一页内偏移直接落入对应页框的相同位置。

### 30.4 分页仍有内部碎片

若进程大小不是页面大小的整数倍，最后一页通常不能完全利用。

若假定进程大小在页面边界内均匀分布，则最后一页的**平均内部碎片**常近似为半页；但具体题目应按给定进程大小精确计算。

### 30.5 分段仍会产生外部碎片

段长可变，且每个段内部通常连续，因此物理内存可能被切成许多不连续的小空闲区。

### 30.6 页表项地址要乘页表项大小

若页表基址为 $B$，页号为 $p$，页表项大小为 $E$：

$$
PTEAddr=B+pE
$$

不能在数值题中直接写成 $B+p$，除非题目明确已经按页表项编号寻址。

### 30.7 缺页不一定发生置换

有空页框时：

> 缺页 → 直接装入。

无空页框时：

> 缺页 → 选择牺牲页 → 必要时写回 → 调入新页。

因此：

$$
\text{置换次数}\le\text{缺页次数}
$$

### 30.8 页面命中不会移动 Clock 指针

简单 Clock 命中已驻留页面时，通常只把该页面：

$$
R\leftarrow 1
$$

不会因为命中而主动移动指针。

### 30.9 FIFO 命中不改变进入顺序

FIFO 依据“装入先后”而非“最近访问”。命中不会把页面重新放到队尾。

### 30.10 OPT 看未来，LRU 看过去

- OPT：比较**下一次**访问距离现在有多远；
- LRU：比较**上一次**访问距离现在有多远。

### 30.11 固定/可变分配不是固定/动态分区

前者讨论请求分页中**页框数是否可变**；后者讨论连续内存中**分区大小是否预先固定**。两组概念完全不同。

### 30.12 工作集不是驻留集

- 驻留集：当前真正装在物理内存中的页面集合；
- 工作集：某一时间窗口内进程近期活跃访问的页面集合。

理想状态是让驻留资源能够较好覆盖活跃工作集，从而降低缺页率。

## 31. 页面置换题统一解题模板

页面置换综合题最稳妥的方法不是心算，而是固定表格逐列推进。

### 31.1 第一步：写清访问串与页框数

例如：

```text
访问串：7 0 1 2 0 3 0 4 2 3 0 2
页框数：3
```

### 31.2 第二步：为每次访问先判断命中/缺页

每访问一个页面，第一问始终是：

> 该页面当前是否已经驻留？

若命中，再按算法更新状态：

- FIFO：顺序不变；
- LRU：更新最近访问次序；
- Clock：把 $R$ 置 1；
- OPT：一般不需要更新特殊队列状态。

### 31.3 第三步：缺页时先看有没有空页框

- 有空页框 → 直接装入；
- 无空页框 → 执行对应置换算法。

这是区分“缺页次数”和“置换次数”的关键。

### 31.4 第四步：按算法维护额外状态

**FIFO：**&#x2060;维护进入顺序。

**LRU：**&#x2060;维护最近访问顺序。

**OPT：**&#x2060;向右观察未来访问位置。

**Clock：**&#x2060;维护 $R$ 和时钟指针。

**改进型 Clock：**&#x2060;同时维护 $R$、$M$ 与扫描轮次。

### 31.5 第五步：分别统计结果

设：

- 缺页次数为 $F$；
- 访问总次数为 $N$；
- 实际淘汰旧页次数为 $R_p$。

则缺页率为：

$$
\text{Page Fault Rate}=\frac{F}{N}
$$

并单独记录 $R_p$，不要与 $F$ 混淆。

## 32. 动态分区题统一解题模板

动态分区题的核心是：

> **每次操作后都更新当前空闲表。**

建议始终画成：

```text
起始地址 | 大小
```

### 32.1 分配步骤

对每次申请：

1. 找出所有可容纳请求的空闲块；
2. 按 First/Next/Best/Worst Fit 选块；
3. 从选中空闲块中划出请求大小；
4. 更新剩余块的起始地址和大小；
5. 若恰好用完，则删除该空闲块表项。

### 32.2 回收步骤

释放分区时：

1. 确定释放区起始地址和大小；
2. 检查前方是否为空闲块；
3. 检查后方是否为空闲块；
4. 相邻则合并；
5. 更新空闲表顺序和大小。

### 32.3 Next Fit 额外注意

必须持续记录游标位置。后续分配不能擅自回到表头，除非游标扫描已经循环到表尾并按规则回绕。

## 33. 本章核心知识链

主线一：**从连续分配到虚拟存储**

```text
单一连续分配
        ↓
固定分区
        ↓
内部碎片明显
        ↓
动态分区
        ↓
外部碎片
        ↓
分页
        ↓
物理内存可离散分配
        ↓
虚拟存储
        ↓
进程不必全部驻留
        ↓
请求分页
        ↓
缺页
        ↓
页框不足
        ↓
页面置换
        ↓
FIFO / OPT / LRU / Clock
        ↓
页框与工作集不匹配
        ↓
抖动
```

主线二：**分页、分段、段页式**

```text
分页
→ 固定大小、机械划分、利于离散分配

分段
→ 可变大小、逻辑划分、利于保护与共享

段页式
→ 逻辑上按段组织，物理上按页离散分配
```

主线三：**地址转换**

```text
虚拟地址
→ 提取页号/段号与偏移
→ 查页表/段表
→ 合法性与权限检查
→ 得到物理页框号或段基址
→ 形成物理地址
```

<Callout type="info" title="本章最后应达到的理解">

- 连续分配主要解决“怎样找一整块内存”；
- 分页解决“物理内存不连续也能运行”；
- 分段解决“怎样按程序逻辑组织、保护和共享”；
- 虚拟存储解决“程序不必全部驻留内存”；
- 页面置换解决“页框不够时淘汰谁”；
- `mmap` 展示了虚拟内存机制如何与文件系统协同。

</Callout>
