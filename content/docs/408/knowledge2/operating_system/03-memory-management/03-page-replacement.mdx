## 18. 页面置换算法

当访问页面不在内存中：

> 发生缺页。

如果还有空闲页框：

> 直接将页面调入。

如果所有允许使用的页框都已经满：

> 必须选择一个页面淘汰。

决定淘汰哪个页面的方法，就是：

> **页面置换算法。**

重点掌握：

1. FIFO；
2. OPT；
3. LRU；
4. Clock；
5. 改进型 Clock。

LFU 作为补充理解。

---

## 19. FIFO 页面置换算法

**FIFO（First-In-First-Out）**：

> 淘汰最早进入内存的页面。

它只关心：

> 页面进入内存的先后顺序。

而不关心页面最近是否被访问。

通常可以用队列实现。

<InlineSvg src="/images/operating-system/operating-system-memory-management-007.svg" alt={"FIFO 页面置换算法"} />

---

### 19.1 FIFO 的特点

优点：

* 实现简单；
* 维护开销小。

缺点：

* “进入内存最早”并不等于“以后最不需要”；
* 可能淘汰一个频繁使用的页面；
* 可能出现 **Belady 异常**。

---

## 20. Belady 异常

> **真题考查**
>
> 2014 年第 30 题。

通常直觉认为：

> 页框越多，缺页越少。

但 FIFO 中可能发生：

> **增加页框数量，缺页次数反而增加。**

这称为：

> **Belady 异常。**

经典访问序列：

```text
1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
```

使用 FIFO：

* 3 个页框：可能产生 9 次缺页；
* 4 个页框：可能产生 10 次缺页。

因此：

> 页框从 3 增加到 4，缺页反而增加。

#### 哪些算法不会发生 Belady 异常？

具有**栈性质（Stack Property）**的算法不会出现。

典型包括：

* OPT；
* LRU。

---

## 21. OPT 最佳置换算法

**OPT（Optimal）** 的原则：

> 淘汰未来最长时间不会被访问的页面。

如果某个页面以后永远不会再访问：

> 优先淘汰。

<InlineSvg src="/images/operating-system/operating-system-memory-management-008.svg" alt={"OPT 页面置换算法"} />

OPT 的问题在于：

> 实际系统无法提前知道完整的未来页面访问序列。

因此 OPT：

* 实际不可实现；
* 主要用于理论分析；
* 用作其他算法的性能比较基准。

---

### 21.1 OPT 例题

假设有 3 个页框。

页面访问序列：

```text
7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 2
```

| 访问页 | 访问后内存   | 被淘汰页 |
| --- | ------- | ---- |
| 7   | 7       | —    |
| 0   | 7, 0    | —    |
| 1   | 7, 0, 1 | —    |
| 2   | 2, 0, 1 | 7    |
| 0   | 2, 0, 1 | —    |
| 3   | 2, 0, 3 | 1    |
| 0   | 2, 0, 3 | —    |
| 4   | 2, 4, 3 | 0    |
| 2   | 2, 4, 3 | —    |
| 3   | 2, 4, 3 | —    |
| 0   | 2, 0, 3 | 4    |
| 2   | 2, 0, 3 | —    |

共发生：

$$
7
$$

次缺页。

页面访问总次数：

$$
12
$$

因此缺页率：

$$
\frac{7}{12}
$$

前 3 次只是填充空页框，所以真正发生页面置换的次数为：

$$
7-3=4
$$

> **高频易错**
>
> **缺页次数不一定等于页面置换次数。**
>
> 初始空页框尚未装满时，缺页只需要装入页面，不必淘汰旧页面。

## 22. LRU 最近最久未使用算法

> **真题考查**
>
> 2015 年第 27 题、2019 年第 29 题、2025 年第 26 题。

**LRU（Least Recently Used）**：

> 淘汰过去最长时间没有被访问的页面。

其依据是时间局部性：

> 最近访问过的页面，短期内再次被访问的概率通常更高。

<InlineSvg src="/images/operating-system/operating-system-memory-management-009.svg" alt={"LRU 页面置换算法"} />

例如：

* A：1 分钟前访问；
* B：2 分钟前访问；
* C：3 分钟前访问；

那么优先淘汰：

```text
C
```

---

### 22.1 队列方式理解 LRU

可以把：

* 最近最久没使用的页面放队头；
* 刚刚访问过的页面放队尾。

访问页面 P 时：

#### P 已经在内存

将 P 移到队尾。

#### P 不在内存且还有空闲页框

把 P 加到队尾。

#### P 不在内存且页框已满

1. 淘汰队头；
2. 把 P 放入队尾。

<InlineSvg src="/images/operating-system/operating-system-memory-management-010.svg" alt={"LRU 队列变化"} />

<InlineSvg src="/images/operating-system/operating-system-memory-management-011.svg" alt={"LRU 算法流程"} />

---

### 22.2 LRU 例题

仍使用：

```text
7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 2
```

3 个页框。

| 访问页 | 访问后状态   | 淘汰 |
| --- | ------- | -- |
| 7   | 7       | —  |
| 0   | 7, 0    | —  |
| 1   | 7, 0, 1 | —  |
| 2   | 0, 1, 2 | 7  |
| 0   | 1, 2, 0 | —  |
| 3   | 2, 0, 3 | 1  |
| 0   | 2, 3, 0 | —  |
| 4   | 3, 0, 4 | 2  |
| 2   | 0, 4, 2 | 3  |
| 3   | 4, 2, 3 | 0  |
| 0   | 2, 3, 0 | 4  |
| 2   | 3, 0, 2 | —  |

缺页次数：

$$
9
$$

其中前 3 次填充空页框，因此置换次数：

$$
9-3=6
$$

缺页率：

$$
\frac{9}{12}
=
\frac34
=
75\%
$$

---

### 22.3 LRU 的实现问题

严格 LRU 需要精确知道：

> 所有页面最近一次访问的先后次序。

可以使用：

* 时间戳；
* 链表；
* 栈；
* 哈希表结合双向链表

实现。

但硬件精确维护完整 LRU 信息的成本较高。

因此实际系统常使用：

> **Clock 等近似 LRU 算法。**

## 23. Clock 页面置换算法

> **真题考查**
>
> 2016 年第 26 题、2021 年第 28 题、2018 年第 45 题。

Clock 又称：

> **Second-Chance，第二次机会算法。**

它使用硬件维护的：

> **访问位 / 引用位 R**

近似判断页面近期是否使用过。

<InlineSvg src="/images/operating-system/operating-system-memory-management-012.svg" alt={"Clock 页面访问位"} />

---

### 23.1 访问位 R

对每个驻留页维护访问位：

#### R = 1

页面自上一次检查以来：

> 被访问过。

因此暂时不给它淘汰。

#### R = 0

页面近期：

> 没有被访问。

因此可以作为候选淘汰页。

通常：

* 页面被访问 → R 置 1；
* 新页面装入 → R 置 1。

> **易错点**
>
> R 表示近期是否访问过，**不是页框是否被占用的标志**。

---

### 23.2 简单 Clock 的扫描规则

所有页框组织成一个环。

维护一个时钟指针。

发生页面置换时：

1. 查看指针当前页面；
2. 如果：

$$
R=0
$$

直接淘汰；

3. 如果：

$$
R=1
$$

将它修改为：

$$
R=0
$$

并把指针移动到下一个页框；

4. 重复扫描，直到找到：

$$
R=0
$$

的页面。

<InlineSvg src="/images/operating-system/operating-system-memory-management-013.svg" alt={"Clock 指针扫描"} />

<InlineSvg src="/images/operating-system/operating-system-memory-management-014.svg" alt={"Clock 算法流程"} />

---

### 23.3 为什么称为“第二次机会”

如果页面：

$$
R=1
$$

表示近期访问过。

指针第一次遇到它时不会立即淘汰，而是：

> 把 R 从 1 清成 0，然后跳过。

这相当于给它一次：

> **第二次机会。**

如果下一圈再次扫描到该页，而期间页面没有再被访问：

$$
R=0
$$

此时即可淘汰。

如果期间又访问了该页：

$$
R
$$

又会被硬件设置成 1。

因此频繁使用的页面不容易被淘汰。

<InlineSvg src="/images/operating-system/operating-system-memory-management-015.svg" alt={"简单 Clock 页面置换实例"} />

## 24. Clock 算法例题

假设：

* 3 个页框；
* 初始均为空；
* 页面访问序列：

```text
7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 2
```

用：

```text
页面号:R
```

表示页框。

其中 `*` 表示时钟指针所指位置。

| 访问页 | 访问后状态            | 淘汰 |
| --- | ---------------- | -- |
| 7   | `7:1  *空:0  空:0` | —  |
| 0   | `7:1  0:1  *空:0` | —  |
| 1   | `*7:1  0:1  1:1` | —  |
| 2   | `2:1  *0:0  1:0` | 7  |
| 0   | `*2:1  0:1  1:0` | —  |
| 3   | `*2:1  0:0  3:1` | 1  |
| 0   | `*2:1  0:1  3:1` | —  |
| 4   | `4:1  *0:0  3:0` | 2  |
| 2   | `4:1  2:1  *3:0` | 0  |
| 3   | `4:1  2:1  *3:1` | —  |
| 0   | `*4:0  2:0  0:1` | 3  |
| 2   | `*4:0  2:1  0:1` | —  |

共发生缺页：

$$
8
$$

其中前 3 次为填充空页框。

因此真正页面置换次数：

$$
8-3=5
$$

缺页率：

$$
\frac{8}{12}
=
\frac23
$$

## 25. 改进型 Clock

简单 Clock 只考虑：

> 页面近期是否访问过。

但实际页面置换还要考虑：

> 页面有没有被修改过。

如果页面被修改：

> 淘汰之前通常需要把内容写回磁盘。

如果页面没有修改：

> 可以直接丢弃，因为原始内容仍然可以从磁盘重新读取。

因此引入：

* 访问位 R；
* 修改位 M。

---

### 25.1 四类页面

| R | M | 含义        | 淘汰优先级 |
| - | - | --------- | ----- |
| 0 | 0 | 最近未访问、未修改 | 最高    |
| 0 | 1 | 最近未访问、已修改 | 次高    |
| 1 | 0 | 最近访问、未修改  | 较低    |
| 1 | 1 | 最近访问、已修改  | 最低    |

其中：

```text
R = Reference
M = Modified
```

修改位也常称：

> **脏位 Dirty Bit**

---

### 25.2 为什么优先淘汰 (0,0)

首先希望：

$$
R=0
$$

因为近期没有访问。

其次希望：

$$
M=0
$$

因为不需要写回磁盘。

因此最理想牺牲页为：

$$
(R,M)=(0,0)
$$

而：

$$
(1,1)
$$

既近期访问过，又已经被修改：

> 最不适合优先淘汰。

<InlineSvg src="/images/operating-system/operating-system-memory-management-016.svg" alt={"改进型 Clock 示例"} />

<InlineSvg src="/images/operating-system/operating-system-memory-management-017.svg" alt={"改进型 Clock 四类页面和扫描顺序"} />

---

### 25.3 改进型 Clock 的扫描

教材中常用“四轮扫描”理解：

#### 第一轮

寻找：

$$
(0,0)
$$

这一轮通常不修改访问位。

若找到：

> 立即淘汰。

#### 第二轮

寻找：

$$
(0,1)
$$

同时在扫描过程中把遇到页面的：

$$
R
$$

清 0。

#### 第三轮

再次寻找：

$$
(0,0)
$$

由于上一轮已经清除大量 R，此时更容易出现。

#### 第四轮

若仍不存在，则寻找：

$$
(0,1)
$$

通常一定可以得到候选页。

> 不同教材对扫描过程的表述可能略有差异，但核心思想始终是：
>
> **优先选择“近期没访问且没修改”的页面，同时利用扫描逐渐清除访问位。**

## 26. FIFO、OPT、LRU、Clock 对比

| 算法        | 淘汰依据    | 优点            | 缺点                |
| --------- | ------- | ------------- | ----------------- |
| FIFO      | 最早进入内存  | 简单            | 性能不稳定，有 Belady 异常 |
| OPT       | 未来最晚再访问 | 理论最优          | 实际无法实现            |
| LRU       | 过去最久未访问 | 利用时间局部性，效果好   | 精确实现成本较高          |
| Clock     | 访问位 R   | 开销低，近似 LRU    | 不记录精确访问次序         |
| 改进型 Clock | R + M   | 同时考虑访问历史和写回代价 | 比简单 Clock 更复杂     |

#### 记忆方法

```text
FIFO：看谁来得最早
OPT：看谁未来最晚再来
LRU：看谁过去最久没来
Clock：看最近有没有来过
改进 Clock：再看有没有被修改
```

## 27. LFU 最不经常使用算法

**LFU（Least Frequently Used）** 根据：

> 页面过去累计被访问的次数

选择淘汰页面。

基本方法：

1. 页面第一次装入时初始化访问计数；
2. 每次访问该页面时增加计数；
3. 需要置换时，选择计数最小的页面。

<InlineSvg src="/images/operating-system/operating-system-memory-management-018.svg" alt={"LFU 页面置换算法"} />

#### LFU 与 LRU 的区别

LRU 关注：

> **上一次是什么时候访问的。**

LFU 关注：

> **总共访问了多少次。**

例如：

* 页面 A 很久以前访问了 100 次，但最近完全没用；
* 页面 B 最近刚访问了几次。

LFU 可能仍然因为 A 历史计数很高而保留 A。

因此实际 LFU 往往需要：

* 老化机制；
* 周期性衰减计数；

避免早期访问历史永久影响淘汰决策。
