## 18. 页面置换算法

请求分页系统访问一个未驻留页面时会发生缺页。

- 若还有可用空闲页框：直接把目标页调入；
- 若允许使用的页框已满：必须先选择一个驻留页作为**牺牲页**淘汰。

决定“淘汰谁”的规则就是**页面置换算法（Page Replacement Algorithm）**。

408 重点掌握：

1. FIFO；
2. OPT；
3. LRU；
4. Clock；
5. 改进型 Clock。

LFU 可作为补充理解。

<Callout type="warn" title="先分清缺页与置换">

缺页时如果还有空闲页框，只需调入，不需要淘汰。因此：

$$
\text{页面置换次数}\le \text{缺页次数}
$$

二者只有在“每次缺页时都已无空闲页框”等特定条件下才可能相等。

</Callout>

## 19. FIFO 页面置换算法

<InlineSvg src="/images/operating-system/operating-system-memory-management-007.svg" alt={"FIFO 页面置换算法"} />

**FIFO（First-In-First-Out）** 的原则是：

> 淘汰**最早进入内存**的页面。

它只记录页面进入驻留集的先后顺序，不关心页面刚刚是否被再次访问。

可用队列理解：

```text
队头：最早进入
...
队尾：最近装入
```

### 19.1 FIFO 的处理规则

访问页面 $P$ 时：

- $P$ 已在内存：命中，FIFO 队列顺序通常**不变**；
- $P$ 不在内存且有空页框：把 $P$ 装入并加入队尾；
- $P$ 不在内存且页框已满：淘汰队头，再把 $P$ 加入队尾。

<Callout type="warn" title="命中不会让 FIFO 页面“重新排队”">

FIFO 记录的是“进入内存的先后”，不是“最近访问的先后”。页面命中后仍保留原来的进入次序，这是它和 LRU 的关键区别。

</Callout>

### 19.2 FIFO 的优缺点

**优点：**

- 实现简单；
- 维护成本低。

**缺点：**

- 最早进入并不代表未来最无用；
- 可能淘汰高频页面；
- 可能出现 **Belady 异常**。

## 20. Belady 异常

> **真题考查**
>
> 2014 年第 30 题。

直觉上，页框数增加通常应该让缺页次数减少，但 FIFO 存在反例：

> **增加页框数后，缺页次数反而增加。**

这称为 **Belady 异常**。

经典访问串：

```text
1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
```

使用 FIFO 时：

- 3 个页框：9 次缺页；
- 4 个页框：10 次缺页。

因此多一个页框反而多一次缺页。

### 20.1 栈性质

若某页面置换算法具有**栈性质（Stack Property）**：

> 对同一访问前缀，分配 $n$ 个页框时的驻留页面集合，总是包含在分配 $n+1$ 个页框时的驻留页面集合中。

则增加页框数不会使缺页次数增加，因此不会出现 Belady 异常。

典型具有栈性质的算法：

- OPT；
- LRU。

FIFO 不具有这种性质。

## 21. OPT 最佳置换算法

<InlineSvg src="/images/operating-system/operating-system-memory-management-008.svg" alt={"OPT 页面置换算法"} />

**OPT（Optimal Page Replacement）** 的原则是：

> 淘汰**从当前时刻往后看，最长时间不会再被访问**的页面。

若某页以后再也不会访问，则它是最优先的淘汰对象。

OPT 能得到给定页框数和访问串下的理论最少缺页次数，但真实系统无法提前知道完整未来访问序列，因此：

- 实际不可直接实现；
- 常作为理论最优基准；
- 常用于比较其他算法性能。

### 21.1 OPT 手算方法

发生缺页且页框已满时：

1. 对当前所有驻留页，从当前位置向右看；
2. 找各页“下一次出现”的位置；
3. 下一次出现最晚者被淘汰；
4. 若某页以后永不出现，优先淘汰它。

### 21.2 OPT 例题

3 个页框，访问串：

```text
7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 2
```

| 访问页 | 访问后驻留页 | 淘汰页 |
| --- | --- | --- |
| 7 | 7 | — |
| 0 | 7, 0 | — |
| 1 | 7, 0, 1 | — |
| 2 | 2, 0, 1 | 7 |
| 0 | 2, 0, 1 | — |
| 3 | 2, 0, 3 | 1 |
| 0 | 2, 0, 3 | — |
| 4 | 2, 4, 3 | 0 |
| 2 | 2, 4, 3 | — |
| 3 | 2, 4, 3 | — |
| 0 | 2, 0, 3 | 4 |
| 2 | 2, 0, 3 | — |

缺页次数为：

$$
F=7
$$

访问总次数为：

$$
N=12
$$

缺页率：

$$
\frac{F}{N}=\frac{7}{12}
$$

初始 3 次缺页只是填满空页框，因此实际淘汰旧页的次数为：

$$
7-3=4
$$

## 22. LRU 最近最久未使用算法

<InlineSvg src="/images/operating-system/operating-system-memory-management-009.svg" alt={"LRU 页面置换算法"} />
<InlineSvg src="/images/operating-system/operating-system-memory-management-010.svg" alt={"LRU 队列变化"} />
<InlineSvg src="/images/operating-system/operating-system-memory-management-011.svg" alt={"LRU 算法流程"} />

> **真题考查**
>
> 2015 年第 27 题、2019 年第 29 题、2025 年第 26 题。

**LRU（Least Recently Used）** 的原则是：

> 淘汰**从当前时刻往过去看，最长时间没有被访问**的页面。

它用“过去的访问历史”近似预测“未来是否还会使用”，依据是时间局部性。

### 22.1 LRU 的队列理解

可把驻留页按“最近访问时间”排序：

```text
队头：最久没访问
...
队尾：刚刚访问
```

访问页面 $P$ 时：

- $P$ 已驻留：把 $P$ 移到队尾；
- $P$ 缺页但有空页框：装入后放队尾；
- $P$ 缺页且页框已满：淘汰队头，再把 $P$ 放队尾。

<Callout type="info" title="OPT 与 LRU 的方向相反">

- OPT：**看未来**，下一次使用最晚者淘汰；
- LRU：**看过去**，上一次使用最早者淘汰。

</Callout>

### 22.2 LRU 例题

仍取访问串：

```text
7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 2
```

3 个页框，按“从最久未访问到最近访问”记录：

| 访问页 | 访问后次序 | 淘汰页 |
| --- | --- | --- |
| 7 | 7 | — |
| 0 | 7, 0 | — |
| 1 | 7, 0, 1 | — |
| 2 | 0, 1, 2 | 7 |
| 0 | 1, 2, 0 | — |
| 3 | 2, 0, 3 | 1 |
| 0 | 2, 3, 0 | — |
| 4 | 3, 0, 4 | 2 |
| 2 | 0, 4, 2 | 3 |
| 3 | 4, 2, 3 | 0 |
| 0 | 2, 3, 0 | 4 |
| 2 | 3, 0, 2 | — |

缺页次数：

$$
F=9
$$

页面置换次数：

$$
9-3=6
$$

缺页率：

$$
\frac{9}{12}=\frac{3}{4}=75\%
$$

### 22.3 LRU 的实现成本

精确 LRU 需要维护页面访问的精确时间顺序，可考虑：

- 时间戳；
- 栈/链表；
- 哈希表 + 双向链表。

但对操作系统页表而言，精确记录每次内存访问的全序开销很高，因此实际系统常用访问位等硬件信息实现近似 LRU，例如 Clock。

## 23. Clock 页面置换算法

<InlineSvg src="/images/operating-system/operating-system-memory-management-012.svg" alt={"Clock 页面访问位"} />

> **真题考查**
>
> 2016 年第 26 题、2021 年第 28 题、2018 年第 45 题。

**Clock（时钟）算法** 又称 **Second-Chance（第二次机会）算法**。

它用一个访问位/引用位 $R$ 表示页面近期是否被访问，并把页框组织成环形结构。

### 23.1 访问位 R

典型约定：

- 页面被访问 → 硬件把 $R$ 置 1；
- 新页面装入 → 通常令 $R=1$；
- Clock 扫描到 $R=1$ 的页面 → 清零并跳过；
- Clock 扫描到 $R=0$ 的页面 → 可淘汰。

<Callout type="warn" title="R 不是页框占用位">

$R=0$ 只说明“自上次相关检查以来没有观察到访问”，不代表该页框为空。

</Callout>

### 23.2 简单 Clock 的扫描规则

<InlineSvg src="/images/operating-system/operating-system-memory-management-013.svg" alt={"Clock 指针扫描"} />
<InlineSvg src="/images/operating-system/operating-system-memory-management-014.svg" alt={"Clock 算法流程"} />
<InlineSvg src="/images/operating-system/operating-system-memory-management-015.svg" alt={"简单 Clock 页面置换实例"} />

发生缺页且需要置换时，从当前时钟指针开始：

1. 若指向页面的 $R=0$，淘汰该页；
2. 若 $R=1$，先令 $R=0$，指针前移；
3. 重复扫描，直到找到 $R=0$ 的页面；
4. 新页装入被选页框；
5. 指针通常移动到被替换位置的下一个页框。

为什么叫“第二次机会”？

因为一个 $R=1$ 的页面第一次被扫描时不会立即淘汰，而是先被清零并获得一次保留机会；如果在下一轮扫描到它之前再次被访问，$R$ 又会变成 1。

### 23.3 Clock 命中时指针是否移动

页面命中时，通常只需要：

$$
R\leftarrow 1
$$

**不会因为一次普通命中就主动移动 Clock 指针。**

指针主要在寻找牺牲页、清访问位和完成置换过程中按规则移动。

## 24. Clock 算法例题

设 3 个页框，初始为空，访问串：

```text
7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 2
```

采用以下约定：

- 新页装入时 $R=1$；
- 置换后指针指向下一个页框；
- 命中只把对应 $R$ 置 1，不移动指针。

用 `页面号:R` 表示页框状态，`*` 表示指针位置：

| 访问页 | 访问后状态 | 淘汰页 |
| --- | --- | --- |
| 7 | `7:1  *空:0  空:0` | — |
| 0 | `7:1  0:1  *空:0` | — |
| 1 | `*7:1  0:1  1:1` | — |
| 2 | `2:1  *0:0  1:0` | 7 |
| 0 | `2:1  *0:1  1:0` | — |
| 3 | `*2:1  0:0  3:1` | 1 |
| 0 | `*2:1  0:1  3:1` | — |
| 4 | `4:1  *0:0  3:0` | 2 |
| 2 | `4:1  2:1  *3:0` | 0 |
| 3 | `4:1  2:1  *3:1` | — |
| 0 | `*4:0  2:0  0:1` | 3 |
| 2 | `*4:0  2:1  0:1` | — |

因此：

$$
\text{缺页次数}=8
$$

$$
\text{置换次数}=8-3=5
$$

$$
\text{缺页率}=\frac{8}{12}=\frac{2}{3}
$$

<Callout type="warn" title="Clock 手算必须先统一约定">

不同教材可能在“空页框如何填充”“置换后指针落在哪里”等细节上采用略不同表述。考试做题时优先服从题目给定规则；若题目未说明，采用教材标准约定并始终保持一致。

</Callout>

## 25. 改进型 Clock

<InlineSvg src="/images/operating-system/operating-system-memory-management-016.svg" alt={"改进型 Clock 示例"} />
<InlineSvg src="/images/operating-system/operating-system-memory-management-017.svg" alt={"改进型 Clock 四类页面和扫描顺序"} />

简单 Clock 只考虑近期是否访问，而实际换出页面还要考虑是否需要写回外存。

因此改进型 Clock 同时考虑：

- 访问位 $R$；
- 修改位 $M$（Modified/Dirty）。

### 25.1 四类页面

| $R$ | $M$ | 含义 | 一般淘汰优先级 |
| --- | --- | --- | --- |
| 0 | 0 | 近期未访问、未修改 | 最高 |
| 0 | 1 | 近期未访问、已修改 | 次高 |
| 1 | 0 | 近期访问、未修改 | 较低 |
| 1 | 1 | 近期访问、已修改 | 最低 |

为什么 $(0,0)$ 最理想？

- $R=0$：近期没有使用；
- $M=0$：淘汰时通常不需要把页面内容写回外存。

因此既“冷”又“干净”。

### 25.2 修改位 M

页面被写入后，内存中的内容可能与外存副本不一致，此时设置：

$$
M=1
$$

这种页面称为**脏页（Dirty Page）**。

若淘汰脏页，通常必须先写回；未修改页则往往可直接丢弃，因为外存已有可重新读取的有效副本。

### 25.3 改进型 Clock 的四轮扫描理解

常见教材可按四轮理解：

**第一轮：**&#x2060;寻找 $(0,0)$，通常不修改 $R$；找到即淘汰。

**第二轮：**&#x2060;寻找 $(0,1)$，扫描过程中把遇到的 $R=1$ 清为 0。

**第三轮：**&#x2060;再次寻找 $(0,0)$。

**第四轮：**&#x2060;若仍未找到，则寻找 $(0,1)$。

不同教材对扫描细节可能略有差异，但核心目标不变：

> **先偏向近期未访问的页面，再偏向无需写回的干净页面。**

## 26. FIFO、OPT、LRU、Clock 对比

| 算法 | 判断依据 | 是否可直接实现 | Belady 异常 | 主要特点 |
| --- | --- | --- | --- | --- |
| FIFO | 最早进入内存 | 是 | 可能 | 简单，但不利用局部性 |
| OPT | 未来最晚再访问 | 否 | 不会 | 理论最优基准 |
| LRU | 过去最久未访问 | 理论可实现但精确成本高 | 不会 | 利用时间局部性 |
| Clock | 访问位 $R$ | 是 | 不按栈算法保证 | 低成本近似 LRU |
| 改进型 Clock | $R+M$ | 是 | 不按栈算法保证 | 同时考虑近期访问和写回代价 |

记忆：

```text
FIFO：看谁来得最早
OPT：看谁未来最晚再来
LRU：看谁过去最久没来
Clock：看最近有没有来过
改进 Clock：再看是否被写脏
```

## 27. LFU 最不经常使用算法

<InlineSvg src="/images/operating-system/operating-system-memory-management-018.svg" alt={"LFU 页面置换算法"} />

**LFU（Least Frequently Used）** 根据页面累计访问频率选择牺牲页：

> 淘汰访问次数最少的页面。

### 27.1 LFU 与 LRU 的区别

LRU 看的是：

> **最近一次访问距离现在有多久。**

LFU 看的是：

> **过去累计访问了多少次。**

例如页面 A 很久以前被访问 100 次，最近已经不再使用；页面 B 最近刚开始频繁使用但累计只有 5 次。纯 LFU 可能仍然保留 A，这就是历史计数“污染”问题。

因此实际 LFU 往往配合：

- 计数老化；
- 周期性衰减；
- 时间窗口统计。

<Callout type="info" title="页面置换题统一决策顺序">

先问：**命中还是缺页？**

若缺页，再问：**有空页框吗？**

若没有，最后才问：**当前算法淘汰谁？**

按这个顺序做题，可以避免把“缺页”“装入”和“置换”混在一起。

</Callout>
