分页按固定大小机械切分；**分段（Segmentation）**&#x2060;则按程序的逻辑结构划分。

> **真题标签**
>
> 分段管理相关概念曾在 2009 年第 27 题、2016 年第 28 题、2019 年第 28 题等题目中出现。

## 3.4.1 为什么要分段

程序天然具有不同逻辑区域：

- 代码段；
- 全局数据段；
- 堆；
- 栈；
- 独立模块或过程；
- 共享库。

这些区域的：

- 长度不同；
- 权限不同；
- 生命周期不同；
- 共享需求不同。

因此分段的核心是：

> **让地址空间的划分与程序逻辑结构一致。**

## 3.4.2 段式逻辑地址

段式逻辑地址通常写成：

$$
(S,W)
$$

其中：

- $S$：段号；
- $W$：段内偏移。

每个进程维护自己的段表。

## 3.4.3 段表与 STBR

段表项通常包含：

- 段基址；
- 段长/界限；
- 访问权限；
- 其他状态信息。

**STBR（Segment Table Base Register）**&#x2060;保存当前进程段表的基地址。

地址转换过程：

1. 检查段号 $S$ 是否超出段表范围；
2. 由 $S$ 找到段表项；
3. 取出段长，检查：

$$
0\le W<\text{段长}
$$

4. 若合法，取段基址 $B$；
5. 计算：

$$
PA=B+W
$$

若段号或段内偏移越界，则产生异常。

## 3.4.4 为什么分段更适合保护与共享

因为段具有明确逻辑意义，可以自然设置：

| 段 | 典型权限 |
| --- | --- |
| 代码段 | 读、执行，通常不可写 |
| 普通数据段 | 读、写 |
| 栈段 | 读、写 |
| 共享代码段 | 多进程只读共享 |

多个进程还可以让各自段表项指向同一物理段，从而按逻辑模块共享。

## 3.4.5 分段为什么会产生外部碎片

段长是可变的，且一个段在纯段式管理中通常仍要求占据一块连续物理区域。

因此随着段反复创建、释放，会形成不同大小的空洞：

> **纯分段主要产生外部碎片。**

这与分页“固定页框 + 少量内部碎片”形成鲜明对比。

## 3.4.6 段页式：先分段，再分页

段页式把两种思想结合：

```text
进程
├── 代码段
│   ├── 第 0 页
│   ├── 第 1 页
│   └── ...
├── 数据段
│   ├── 第 0 页
│   └── ...
└── 栈段
    ├── 第 0 页
    └── ...
```

逻辑地址通常写成：

```text
段号 | 段内页号 | 页内偏移
```

即：

$$
(S,P,W)
$$

## 3.4.7 段页式地址转换

可以理解为两级查表：

### 第一级：查段表

由段号 $S$ 找到该段对应页表的位置、页表长度、权限等信息。

### 第二级：查该段页表

由段内页号 $P$ 找到物理页框号 $F$。

### 最后：拼接偏移

```text
物理页框号 | 页内偏移
```

页内偏移 $W$ 不变。

因此段页式同时具有：

- 分段的逻辑组织能力；
- 分页的离散物理分配能力。

## 3.4.8 页式、段式、段页式总对比

| 特征 | 页式 | 段式 | 段页式 |
| --- | --- | --- | --- |
| 划分依据 | 固定大小 | 程序逻辑 | 先逻辑分段，再固定分页 |
| 单位长度 | 固定 | 可变 | 段可变、页固定 |
| 物理布局 | 页框可离散 | 段间离散、段内连续 | 页框可离散 |
| 是否反映逻辑结构 | 否 | 是 | 是 |
| 主要碎片 | 内部碎片 | 外部碎片 | 页内内部碎片 |
| 共享/保护 | 可按页 | 按段最自然 | 按段组织、按页分配 |
| 转换结构 | 页表 | 段表 | 段表 + 页表 |

<Callout type="warn" title="一句话辨析">
页是**固定大小的地址转换/分配单位**；段是**按程序逻辑划分的可变长单位**。不要把“页是物理单位”机械理解成“页只存在于物理内存”——虚拟地址空间同样被划分为虚拟页。
</Callout>

## 3.4.9 三种方式的答题视角

遇到比较题，从四个维度回答最稳：

1. **划分依据**：固定大小还是逻辑结构；
2. **物理连续性**：整进程/整段/页框是否要求连续；
3. **碎片类型**：内部还是外部；
4. **保护共享**：按页还是按逻辑段更自然。
