本章先建立一条总主线：

> **应用程序不能随意控制关键硬件，因此操作系统一方面管理和复用资源，另一方面通过受保护的接口把硬件能力安全地提供给程序。**

操作系统概述的题目看似零散，实际可以统一到三个问题：

1. **谁有权做这件事？**——用户态还是内核态；
2. **控制权怎样进入内核？**——中断、异常或系统调用；
3. **程序如何获得可运行环境？**——链接、装入、地址空间与操作系统结构共同完成。

## 1.1.1 操作系统是什么

**操作系统（Operating System，OS）**&#x2060;是直接管理计算机硬件与软件资源、为应用程序提供运行环境和服务接口的系统软件。

从 408 角度，可以从三个身份理解：

| 视角 | 操作系统的角色 | 典型例子 |
| --- | --- | --- |
| 资源管理者 | 分配、回收、协调系统资源 | CPU 调度、内存分配、文件和设备管理 |
| 用户/程序与硬件之间的接口 | 屏蔽硬件细节并提供受控入口 | 系统调用、命令接口 |
| 扩充机器/抽象层 | 把复杂硬件抽象为更易使用的逻辑对象 | 进程、文件、虚拟地址空间 |

典型管理对象包括：

- 处理机；
- 主存与虚拟存储；
- 文件和外存；
- I/O 设备；
- 进程、线程及其通信资源；
- 各类系统级保护状态。

> **判断原则**
>
> 如果一个操作会直接控制硬件、修改全局系统状态、改变地址转换/保护机制，或可能影响其他进程，则通常必须由内核在受保护状态下完成。

## 1.1.2 操作系统的四个基本特征

408 教材通常概括为：

> **并发、共享、虚拟、异步。**

其中，**并发与共享是最基本的两个特征，并且互为存在条件**。

### 并发

**并发（Concurrency）**&#x2060;指多个事件在**同一时间间隔内**交替推进。

在单核处理机上，多进程通常依靠快速切换形成宏观上的“同时运行”；多核系统则可能让多个任务在同一时刻真正执行。

| 概念 | 时间含义 | 是否要求多个执行单元 |
| --- | --- | --- |
| 并发 | 同一时间段内都在推进 | 不要求 |
| 并行 | 同一时刻真正同时执行 | 通常要求 |

> **易错点**
>
> 单核可以并发，但不能在同一时刻执行两条属于不同任务的普通指令流；“多个程序同时运行”往往是宏观描述，不等于每个时刻都并行。

### 共享

**共享（Sharing）**&#x2060;指系统中的资源可供多个并发执行的进程共同使用。

常见两类共享方式：

- **互斥共享**：一个时间段内资源只允许一个进程占用，例如某些独占设备和临界资源；
- **同时共享**：允许多个进程在同一时间段共同使用，例如多个进程读取同一只读文件。

“同时共享”通常强调**宏观时间段内可共同使用**，不一定意味着底层物理资源每一瞬间都在并行服务多个进程。

### 并发与共享为什么互为条件

可以这样理解：

```text
多个程序并发执行
      ↓
会共同竞争/使用 CPU、内存、文件、设备
      ↓
必须建立资源共享与互斥规则

系统允许资源被合理共享
      ↓
多个程序才有条件同时驻留并交替推进
```

因此，并发带来共享需求，共享机制又支撑并发运行。

### 虚拟

**虚拟（Virtualization）**&#x2060;是把一个物理实体变换为若干逻辑上的对应物，使用户或进程获得“仿佛独占”的使用体验。

典型例子：

| 物理资源 | 逻辑抽象 |
| --- | --- |
| 一个/少量 CPU | 多个进程都像拥有自己的处理机 |
| 有限物理内存 | 每个进程拥有独立虚拟地址空间 |
| 一台物理主机 | 多台虚拟机 |

传统教材常从两种复用角度解释：

- **时分复用**：不同任务在不同时间片使用同一资源；
- **空分复用**：把资源空间划分给不同对象，例如不同内存区域。

### 异步

**异步（Asynchronism）**&#x2060;指在并发环境下，进程以不可预知的速度向前推进。

一个进程可能经历：

```text
运行 → 发起 I/O → 阻塞 → 被唤醒 → 等待调度 → 再运行
```

因此，“何时再次获得 CPU、何时完成”通常具有不确定性。

但异步不等于结果可以任意变化。操作系统必须依靠同步、互斥等机制，使**有正确同步约束的程序**得到确定、可接受的结果。

## 1.1.3 操作系统的发展：核心矛盾如何变化

发展主线可以概括为：

```text
手工操作
  ↓ 解决人工装入与机器速度不匹配
单道批处理
  ↓ 解决自动连续处理，但 CPU 仍会等 I/O
多道批处理
  ↓ 让 I/O 等待与其他作业计算重叠
分时系统
  ↓ 在高利用率基础上进一步追求交互和响应
实时系统
    把“按时完成”放在首要位置
```

### 手工操作阶段

没有操作系统，用户直接控制计算机：装入程序、启动、等待、记录结果、再交给下一用户。

主要矛盾是：

> **人机速度矛盾导致机器大量空闲。**

### 单道批处理系统

多个作业预先组成批次，由监督程序自动按顺序执行。

优点：减少人工干预；缺点是一个作业等待 I/O 时，CPU 往往仍然空闲。

### 多道批处理系统

核心技术是**多道程序设计**：让多个程序同时进入内存。

当作业 A 因 I/O 阻塞时，CPU 改去执行 B 或 C：

```text
A：计算 ── I/O 等待 ───────── 计算
B：      计算 ── I/O 等待 ── 计算
CPU： A → B → C → B → A ...
```

它提高效率的根本原因是：

> **让 CPU 计算与设备 I/O 尽量重叠，减少处理机空闲时间。**

主要目标：提高资源利用率和系统吞吐量。

局限：交互性较差，用户提交作业后通常不能频繁实时交互。

### 分时系统

把处理机时间划分为较短的**时间片**，多个用户/任务轮流运行。

主要特征：

- 多用户；
- 交互性强；
- 响应较快；
- 依靠快速切换形成“每人都像独占机器”的体验。

主要目标：

> **缩短响应时间、提升交互性。**

### 实时系统

关键要求是：

> **任务必须在规定的截止时间内得到响应或完成。**

- **硬实时**：错过截止时间可能造成严重后果，如飞控、工业安全控制；
- **软实时**：偶尔超时会降低质量，但通常不造成灾难，如部分多媒体业务。

| 系统类型 | 首要目标 | 高频关键词 |
| --- | --- | --- |
| 多道批处理 | 高利用率、高吞吐量 | I/O 等待时执行其他作业 |
| 分时 | 快速响应、交互 | 时间片、多用户 |
| 实时 | 满足时间约束 | 截止时间 |

## 1.1.4 复习时如何做概念判断

遇到概念题，先问“题目强调的到底是哪种能力”：

- **宏观上多个任务推进** → 并发；
- **同一时刻多个任务真实执行** → 并行；
- **资源能被多个进程共同使用** → 共享；
- **物理资源被抽象成多个逻辑资源** → 虚拟；
- **进程推进速度无法事先精确预测** → 异步；
- **I/O 等待时让 CPU 执行其他作业** → 多道程序；
- **强调交互与响应** → 分时；
- **强调截止时间** → 实时。
