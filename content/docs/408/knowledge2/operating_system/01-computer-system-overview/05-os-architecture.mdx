操作系统功能越来越复杂后，核心问题不再只是“实现哪些功能”，还包括：

> **这些功能应该放在哪里、怎样相互调用、故障能否隔离、性能开销有多大。**

408 重点考结构特点和优缺点，不要求把所有现实系统机械贴成某一种纯理论模型。

## 1.5.1 分层结构

分层结构把系统划分为若干层，通常上层只依赖下层提供的接口。

```text
用户与高级服务
────────────
文件等高级抽象
────────────
进程 / 内存管理
────────────
底层设备与硬件控制
────────────
硬件
```

优点：

- 结构清晰；
- 接口边界明确；
- 易于逐层设计、调试和验证。

局限：

- 层次很难做到绝对合理；
- 某些操作跨越多层可能增加路径和开销；
- 严格只向下调用会限制优化空间。

## 1.5.2 模块化结构

模块化按功能划分相对独立组件，例如：

- 调度；
- 内存管理；
- 文件系统；
- 网络；
- 设备驱动。

重点是：

> **模块通过明确接口协作，并可相对独立地开发、替换或扩展。**

分层与模块化并不互斥：

- 分层强调“上下层依赖关系”；
- 模块化强调“功能拆分和接口封装”。

现代内核常支持**可加载内核模块**，使某些功能可在运行期间装入/卸载，但模块一旦以内核模块身份运行，通常仍处于内核地址空间和高权限环境。

## 1.5.3 宏内核

**宏内核（Monolithic Kernel）**&#x2060;把较多核心服务放在内核空间运行，例如：

- 进程调度；
- 内存管理；
- 文件系统；
- 网络协议栈；
- 大量设备驱动；
- IPC 机制。

服务之间可在内核内部直接调用。

优点：

- 调用路径短；
- 内核服务之间通信效率高；
- 通常性能较好。

缺点：

- 内核规模大；
- 组件之间耦合可能较高；
- 一个严重的驱动或内核组件错误可能破坏整个系统。

Linux 通常视为宏内核体系，但采用模块化设计，因此“宏内核”和“模块化”并不冲突。

## 1.5.4 微内核

**微内核（Microkernel）**&#x2060;尽量只把最基础的机制保留在内核态，常见包括：

- 基本线程/调度机制；
- 地址空间的基础机制；
- IPC；
- 少量底层中断/硬件机制。

文件系统、网络服务、部分驱动等尽量移到用户态服务器进程。

```text
用户态：文件服务  驱动服务  网络服务  应用
             ↕ 消息/IPC
内核态：调度 + IPC + 最基本的地址空间/硬件机制
```

优点：

- 内核体积较小；
- 服务隔离好；
- 某个用户态服务失败不一定破坏整个内核；
- 边界清晰，可靠性和可维护性较好。

主要代价：

- 服务之间频繁 IPC；
- 更多用户态/内核态转换；
- 可能增加调度和数据复制开销。

> **408 高频结论**
>
> 微内核常以更强隔离和可维护性，换取潜在的 IPC 与状态切换性能开销。

## 1.5.5 宏内核与微内核对比

| 维度 | 宏内核 | 微内核 |
| --- | --- | --- |
| 内核中服务数量 | 多 | 尽量少 |
| 文件系统/部分驱动 | 通常内核态 | 可放用户态 |
| 服务通信 | 内核直接调用较多 | 消息/IPC 较多 |
| 性能 | 通常较高 | 可能有额外 IPC 开销 |
| 故障隔离 | 相对较弱 | 相对较强 |
| 内核规模 | 较大 | 较小 |

## 1.5.6 外核（Exokernel）

当前 408 大纲把**外核**也列入操作系统结构范围，需要知道基本思想。

外核追求：

> **内核只负责安全地复用和保护底层硬件资源，而把尽可能多的资源抽象策略交给用户级库操作系统。**

与传统内核“内核提供统一高级抽象”不同，外核希望减少内核替应用做策略决策。

可以概括为：

```text
传统 OS：内核既管保护/分配，又提供较多高级抽象
外核：   内核重点做保护与资源复用，抽象策略尽量上移
```

优点思想：

- 应用可按需求定制资源管理策略；
- 减少不必要的通用抽象层；
- 某些专用场景可能获得更高灵活性和性能。

代价：

- 系统设计复杂；
- 应用/库操作系统承担更多职责；
- 通用软件生态和兼容性实现更困难。

408 通常只要求识别其核心思想，不要求深入工程实现。

## 1.5.7 不要把现实系统强行二选一

现实内核经常混合多种思想：

- 宏内核 + 可加载模块；
- 微内核思想 + 大量性能优化；
- 混合内核；
- 分层与模块化同时采用。

例如 XNU 吸收 Mach 的微内核思想，同时包含 BSD 等组件，通常被描述为混合式设计，而非教材意义上的“纯微内核”。

因此考试更应关注：

> **某结构把哪些服务放在内核、服务之间怎么通信、这种边界会带来什么性能与可靠性后果。**
