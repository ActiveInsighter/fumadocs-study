I/O 管理的核心目标是：**屏蔽设备差异，为进程提供统一接口，并让 CPU、主存与慢速外设尽可能并行工作。**

从一道 408 题的视角，可以始终沿着下面这条链路定位知识点：

```text
用户程序提出 I/O 请求
        ↓
用户层 I/O 软件 / 系统调用
        ↓
设备独立性软件
        ↓
设备驱动程序
        ↓
设备控制器 + 具体硬件
        ↓
I/O 完成：中断 / DMA 完成通知
        ↓
内核处理完成事件并唤醒等待进程
```

<Callout type="info" title="本章复习主线">

- **控制方式**：程序查询、中断、DMA，比较 CPU 参与程度；
- **软件层次**：统一接口属于谁，具体寄存器操作属于谁；
- **缓冲与虚拟化**：Buffer、Cache、SPOOLing 分别解决什么问题；
- **磁盘管理**：格式化、分区、文件系统、引导的先后关系；
- **磁盘调度**：先确定当前位置、方向和边界，再计算访问顺序与移动距离。

</Callout>

## 1. I/O 设备及其分类

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-001.svg" alt={"I/O 设备类型分类 块设备 (Block) 固定大小数据块 支持随机访问 高数据传输速率 机械硬盘 HDD 固态硬盘 SSD USB 闪存盘 数据块 字符设备 (Character) 连续字符流 顺序访问 实时传输 键盘 鼠标 串口终端 A → B → C → D → E 字符流 网络设备 (Network) 数据包传输 高速实时传输 DMA 和中断机制 网络适配器 调制解调器 路由器 数据包"} />

操作系统面对的 I/O 设备差异很大：键盘按字符产生输入，磁盘按块存取数据，网卡按帧或数据包收发数据。I/O 子系统的价值就在于把这些差异封装起来。

### 1.1 块设备

**块设备（Block Device）**以固定大小的数据块为基本读写单位，一般能够定位到指定块，因此适合随机访问和大容量存储。

典型设备包括：

- [机械硬盘](/docs/408/knowledge2/computer-organization/03-storage-system/04-secondary-storage/)；
- [固态硬盘](/docs/408/knowledge2/computer-organization/03-storage-system/04-secondary-storage/)；
- USB 闪存盘。

块设备的典型特征是：

- 数据按块组织；
- 通常支持随机访问；
- 常配合缓存、调度和文件系统使用。

### 1.2 字符设备

**字符设备（Character Device）**通常以连续字符流的形式传输数据，不像块设备那样提供“第几个数据块”的随机定位抽象。

典型设备包括：

- 键盘；
- 鼠标；
- 串口终端；
- 打印机。

例如，键盘产生的是连续按键事件，操作系统没有必要先把若干按键凑成“磁盘块”再处理。

### 1.3 网络设备

网络设备通常使用**帧/数据包**抽象，而不是普通块设备的“块号”或字符设备的简单字节流抽象。典型硬件包括[网络适配器](/docs/408/knowledge2/computer_network/02-physical-layer/04-media-devices/)和调制解调器。

高性能网络 I/O 常配合：

- 中断；
- DMA；
- 环形描述符队列；
- 网络协议栈；
- 设备驱动程序。

<Callout type="warning" title="分类不是设备内部物理结构">
“块设备、字符设备、网络设备”描述的是**操作系统提供的访问抽象**。不能据此推断设备内部“物理上一次只能传一个块或一个字符”。
</Callout>

## 2. 设备控制器与 CPU 如何访问设备

CPU 通常不会直接操作设备机械部件，而是通过**设备控制器（Device Controller）**与设备交互。

控制器常向 CPU 暴露若干寄存器：

| 寄存器 | 典型作用 |
| --- | --- |
| 数据寄存器 | 暂存要发送或刚接收的数据 |
| 状态寄存器 | 反映忙、就绪、错误、完成等状态 |
| 控制寄存器 | 写入启动、复位、读/写方向等命令 |

CPU 访问这些寄存器时，常见两种编址方式：

- **独立编址 I/O**：I/O 端口具有独立地址空间，使用专门 I/O 指令；
- **统一编址 / 内存映射 I/O**：设备寄存器映射到内存地址空间，可使用普通访存指令访问。

这部分与组成原理中的 I/O 接口知识相互衔接。操作系统更关注的是：**谁发命令、谁等待、谁搬数据、完成后如何通知。**

## 3. I/O 控制方式：程序查询、中断与 DMA

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-002.svg" alt={"I/O 控制方式对比（CPU 参与度 / 数据流） 方式 数据流 CPU 参与度（时间轴） 程序查询 (Polling) 同步、忙等 CPU 设备 内存 轮询/读状态 数据→CPU 寄存器 CPU 再写入内存（每字节都经 CPU） CPU 全程忙：检查 → 传送 → 检查 → … 时间 → 几乎 100% CPU 占用，效率最低 程序中断 (Interrupt) 异步、需中断响应 CPU 设备 内存 启动 I/O 完成 → 中断 + 数据 中断服务程序搬运（仍经 CPU） 时"} />

I/O 控制方式回答的是：

> **CPU、主存和设备之间怎样协作，才能完成一次数据传送？**

408 最常比较三种方式：程序查询、程序中断和 DMA。

### 3.1 程序查询方式

[程序查询方式](/docs/408/knowledge2/computer-organization/06-bus-io/02-io-interface-transfer/)又称**轮询（Polling）**。

典型流程：

```text
CPU 启动设备
    ↓
反复读取状态寄存器
    ↓
未完成 ─────→ 继续查询
    ↓
已完成
    ↓
CPU 参与数据传送 / 后续处理
```

其核心问题是：**CPU 在等待设备期间不断执行查询，形成忙等。**

优点：

- 控制简单；
- 实现容易；
- 不要求复杂中断机制。

缺点：

- CPU 与低速设备同步等待；
- 大量处理器时间浪费在状态查询上；
- CPU 利用率通常最低。

### 3.2 程序中断方式

[程序中断方式](/docs/408/knowledge2/computer-organization/06-bus-io/02-io-interface-transfer/)允许 CPU 启动设备后先去执行其他任务，设备需要服务或完成 I/O 时再发出中断请求。

```text
CPU 启动 I/O
    ↓
CPU 执行其他程序
    ↓
设备完成 / 需要处理
    ↓
产生中断
    ↓
CPU 执行中断服务程序
    ↓
恢复原执行流
```

它相对查询方式的关键改进是：

> **等待设备期间 CPU 不再持续忙等。**

但中断方式并不等于“CPU 不参与 I/O”。CPU 仍需：

- 响应中断；
- 保存与恢复必要现场；
- 执行中断处理程序；
- 在需要时参与数据搬运或状态处理。

若每传送一个字节或少量数据就产生一次中断，中断频率过高时仍会造成明显开销。

### 3.3 DMA 方式

[DMA 方式](/docs/408/knowledge2/computer-organization/06-bus-io/02-io-interface-transfer/)即 **Direct Memory Access，直接存储器访问**。

DMA 的关键改进是：

> **一批数据可在 I/O 设备与主存之间直接传送，不再要求 CPU 逐字搬运。**

典型流程：

1. CPU 初始化 DMA 控制器；
2. 设置主存地址、传输方向、数据量等参数；
3. DMA 控制器负责设备与主存之间的数据传送；
4. 整批数据完成后，DMA 通过中断通知 CPU；
5. CPU 进行收尾处理。

CPU 并非完全退出：它仍要负责**初始化 DMA + 处理完成事件**，只是从“逐字搬运数据”中解放出来。

### 3.4 三种方式对比

| 控制方式 | 等待设备时 CPU 是否忙等 | 数据传送时 CPU 参与程度 | 常见传送粒度 | 主要特点 |
| --- | :---: | --- | --- | --- |
| 程序查询 | 是 | 很高 | 字 / 字节 | 实现简单，但浪费 CPU |
| 程序中断 | 否 | 较高 | 字 / 字节或少量数据 | 用中断代替持续轮询 |
| DMA | 否 | 很低 | 数据块 | 数据块在设备与主存间直接传送 |

可以用一句话记忆：

```text
查询：CPU 等设备
中断：设备需要时找 CPU
DMA：数据批量自己搬，搬完再找 CPU
```

<Callout type="warning" title="DMA 不是“完全不要 CPU”">
DMA 只是在**数据块传送阶段**显著减少 CPU 参与。CPU 仍负责初始化、授权和处理 DMA 完成中断。
</Callout>

## 5. 用户层 I/O 软件与系统调用

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-004.svg" alt={'用户层 I/O 软件 把"简单的库调用"翻译成"复杂的系统调用"，向下陷入内核 应用程序 printf("hello %d", n); fgets(buf, 128, stdin); fwrite(&s, sizeof s, 1, fp); // 想的是"输出一段话"，不关心设备 调用库函数 用户层 I/O 软件（库 / 运行时） 运行在用户态 ① 格式化 / 解析 printf scanf sprintf atoi / strtol ② 用户级缓冲 fopen / fclo'} />

用户层 I/O 软件直接面向应用程序，为程序员提供方便的接口和库函数。

例如：

```c
printf("hello %d", n);
fgets(buf, 128, stdin);
fwrite(&s, sizeof s, 1, fp);
```

应用程序通常只需要描述：

- 要读还是要写；
- 数据放在哪里；
- 操作哪个文件或逻辑设备。

它不需要知道：

- 某设备控制寄存器的地址；
- DMA 控制器如何配置；
- 中断向量是多少；
- 某块磁盘使用哪一种控制器协议。

用户态库函数在需要内核服务时，会进一步通过 `read`、`write` 等系统调用进入内核。

<Callout type="warning" title="库函数不等于系统调用">
`printf()` 可以先在用户态完成格式化、缓冲等工作，必要时再调用底层 `write()`。因此“库函数”和“系统调用”不能直接画等号。
</Callout>

## 6. 设备独立性软件

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-005.svg" alt={"设备独立性软件 位于用户层与设备驱动之间，屏蔽硬件差异，向上提供统一接口 用户层 I/O 软件（库函数 / 系统调用：read、write、printf…） 设备独立性软件（核心功能） ① 统一命名与接口 将不同设备抽象为文件 / 逻辑名 上层无需关心具体硬件类型 ② 缓冲管理 单缓冲 / 双缓冲 / 缓冲池 缓解 CPU 与设备速度差异 ③ 设备分配与回收 独占 / 共享 / 虚拟设备管理 避免多进程并发访问冲突 ④ 差错处理 校验、重试等通用错误处理 屏蔽底层硬件异常 ⑤"} />

**设备独立性软件（Device-independent I/O Software）**位于上层通用接口与具体驱动程序之间，其核心目标是：

> **屏蔽不同设备的硬件差异，为上层提供统一、稳定的 I/O 抽象。**

典型职责包括：

- 逻辑设备命名；
- 设备保护与权限检查；
- 设备分配与回收；
- 缓冲管理；
- 通用差错处理；
- 逻辑设备到物理设备的映射；
- 向上提供统一的读写接口。

例如，上层程序可以统一调用：

```text
read(...)
write(...)
```

底层换成另一厂商的同类硬件时，只要驱动和系统支持，上层程序通常不必修改。

**识别关键词：统一、通用、屏蔽差异、逻辑设备。**

## 7. 设备驱动程序

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-006.svg" alt={"设备驱动程序 承上启下：把设备独立性软件的通用命令 → 翻译为特定硬件能理解的指令 设备独立性软件（通用 I/O 命令：read / write / ioctl…） 设备驱动程序（内核态，针对具体硬件） ① 命令翻译 通用 I/O 请求 → 设备特定指令 写控制/命令寄存器 如：扇区读写、控制字符 ② 设备初始化与配置 复位、加载固件 分配 I/O 端口、DMA 通道 注册中断向量 ③ 数据传输 程序查询 / 中断 / DMA 在设备寄存器与内存间搬运 配合上层缓冲区 ④ 中"} />

**设备驱动程序（Device Driver）**直接面向某类具体硬件，它负责把上层通用 I/O 请求转换成设备能够理解的操作。

常见职责：

- 初始化设备；
- 设置控制寄存器；
- 读取状态寄存器；
- 启动 I/O；
- 配置 DMA；
- 处理设备特定错误；
- 把通用读写命令翻译为硬件命令。

例如：

- 磁盘驱动程序负责形成具体块读写请求；
- 打印机驱动程序负责生成打印机能够识别的控制操作。

驱动程序通常运行在**内核态**。

**识别关键词：具体型号、寄存器、控制器、硬件命令。**

## 8. 中断处理程序与 I/O 完成路径

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-007.svg" alt={"中断处理程序大致流程 硬件触发 → 保存现场 → 快速处理 → 恢复现场 → 回到原任务 设备 / 硬件 CPU / 中断处理程序（内核态，高优先级、代码精简） 用户/上层软件 ① 设备事件发生 数据到达 / 完成 / 出错 中断信号 ② 响应中断 暂停当前任务 切换到内核态 ③ 保存现场 PC、寄存器、状态字 压栈保存 ④ 识别中断源 / 分发 查中断向量表 跳转到对应处理例程 ⑤ 执行中断服务 读写设备寄存器 搬运数据、置状态 ⑥ 唤醒/通知上层 唤醒等待进程 通知驱动/"} />

设备完成 I/O 后，常通过硬件中断通知 CPU。[中断处理程序](/docs/408/knowledge2/computer-organization/06-bus-io/02-io-interface-transfer/)负责快速处理该完成事件。

典型过程：

1. 设备或 DMA 控制器产生中断；
2. CPU 暂停当前执行流并保存必要现场；
3. 根据中断源进入相应处理程序；
4. 读取设备状态，确认完成或错误；
5. 完成必要的应答、清除中断等动作；
6. 通知驱动程序或上层内核逻辑；
7. 唤醒等待 I/O 的进程；
8. 恢复被中断的执行流或触发调度。

网卡接收数据时，数据可能已经通过 DMA 放入主存。此时中断处理程序的主要工作是**确认完成并推动后续处理**，而不是再由 CPU 把整个数据包逐字搬一遍。

### 8.1 软件层次高频对应表

| 工作 | 最典型层次 |
| --- | --- |
| `printf`、格式化输入输出 | 用户层 I/O 软件 |
| 统一设备命名 | 设备独立性软件 |
| 缓冲管理 | 设备独立性软件 |
| 设备分配与回收 | 设备独立性软件 |
| 逻辑设备到物理设备映射 | 设备独立性软件 |
| 把通用 `read/write` 转成设备命令 | 设备驱动程序 |
| 设置设备控制寄存器 | 设备驱动程序 |
| 响应设备完成中断 | 中断处理程序 |
| 真正执行物理数据传送 | 硬件 / 控制器 |

<Callout type="info" title="三组关键词快速定位">

- **统一接口、屏蔽差异** → 设备独立性软件；
- **设备型号、寄存器、硬件命令** → 设备驱动程序；
- **设备完成后发信号** → 中断处理程序。

</Callout>
