I/O 管理的核心目标是：**屏蔽不同硬件设备之间的差异，向进程提供统一的 I/O 接口，并通过中断、DMA、缓冲、设备分配和调度等机制提高设备利用率与系统并行度。**

<InlineSvg src="/images/operating-system/operating-system-io-device-001.svg" alt={"I/O 管理与外存管理知识框架"} />

本章可以沿着一条主线理解：

**用户发出 I/O 请求 → 操作系统将通用请求转换为设备操作 → 设备执行 I/O → 完成后通知 CPU → 操作系统唤醒等待进程。**

| -------- | ---------------------------- |
| I/O 设备   | 块设备、字符设备、网络设备                |
| I/O 控制方式 | 程序查询、中断、DMA                  |
| I/O 软件层次 | 用户层软件、设备独立性软件、驱动程序、中断处理程序、硬件 |
| 缓冲       | 单缓冲、双缓冲、循环缓冲、缓冲池、磁盘高速缓存      |
| 设备管理     | 设备分配与回收、逻辑设备与物理设备映射          |
| SPOOLing | 用磁盘模拟脱机输入输出，把独占设备虚拟为共享设备     |
| 磁盘管理     | 物理格式化、分区、逻辑格式化、引导、坏块         |
| 磁盘调度     | FCFS、SSTF、SCAN、C-SCAN        |

## 一、I/O 设备基础

### 1. I/O 设备的分类

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-001.svg" alt={"I/O 设备类型分类 块设备 (Block) 固定大小数据块 支持随机访问 高数据传输速率 机械硬盘 HDD 固态硬盘 SSD USB 闪存盘 数据块 字符设备 (Character) 连续字符流 顺序访问 实时传输 键盘 鼠标 串口终端 A → B → C → D → E 字符流 网络设备 (Network) 数据包传输 高速实时传输 DMA 和中断机制 网络适配器 调制解调器 路由器 数据包"} />

按照设备传输数据的基本单位和访问方式，可以将常见 I/O 设备分为块设备、字符设备和网络设备。

| 类型   | 数据组织     | 随机访问        | 典型设备            | 主要特点      |
| ---- | -------- | ----------- | --------------- | --------- |
| 块设备  | 固定大小的数据块 | 支持          | HDD、SSD、USB 闪存盘 | 适合大量数据存储  |
| 字符设备 | 连续字符流    | 通常不支持       | 键盘、鼠标、串口、打印机    | 顺序传输      |
| 网络设备 | 数据包      | 不按普通块设备方式访问 | 网卡、调制解调器        | 强调高速和实时通信 |

#### 块设备

**块设备（Block Device）**以固定大小的数据块为基本读写单位，一般支持直接定位到指定的数据块，因此支持随机访问。

典型块设备包括：

* [机械硬盘](/docs/408/knowledge2/computer-organization/03-storage-system/04-secondary-storage/)；
* [固态硬盘](/docs/408/knowledge2/computer-organization/03-storage-system/04-secondary-storage/)；
* USB 闪存盘。

块设备通常具有较高的数据传输率，并通过专门的设备控制器和驱动程序管理。

#### 字符设备

**字符设备（Character Device）**以连续字符流的形式传输数据，一般只能按照数据到达顺序进行访问，不具有块设备那样的随机定位能力。

典型设备包括：

* 键盘；
* 鼠标；
* 串口终端；
* 打印机。

例如，键盘产生的是连续按键输入流，不需要首先形成一个完整磁盘块才能交给操作系统处理。

#### 网络设备

网络设备主要负责计算机和网络之间的**数据包传输**，例如[网络适配器](/docs/408/knowledge2/computer_network/02-physical-layer/04-media-devices/)和调制解调器。

网络设备通常需要配合：

* 中断机制；
* DMA；
* 网络协议栈；
* 设备驱动程序。

> **易错点**
>
> “块设备、字符设备”描述的是操作系统观察设备的方式，不应简单理解为设备“内部一次只能传一个块或字符”。

## 二、I/O 控制方式

I/O 控制方式解决的问题是：

**CPU、主存和外设之间究竟如何配合完成一次数据传送？**

本章主要掌握三种方式：

1. 程序查询方式；
2. 程序中断方式；
3. DMA 方式。

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-002.svg" alt={"I/O 控制方式对比（CPU 参与度 / 数据流） 方式 数据流 CPU 参与度（时间轴） 程序查询 (Polling) 同步、忙等 CPU 设备 内存 轮询/读状态 数据→CPU 寄存器 CPU 再写入内存（每字节都经 CPU） CPU 全程忙：检查 → 传送 → 检查 → … 时间 → 几乎 100% CPU 占用，效率最低 程序中断 (Interrupt) 异步、需中断响应 CPU 设备 内存 启动 I/O 完成 → 中断 + 数据 中断服务程序搬运（仍经 CPU） 时"} />

### 1. 程序查询方式

[程序查询方式](/docs/408/knowledge2/computer-organization/06-bus-io/02-io-interface-transfer/)又称**轮询方式**。

CPU 启动设备后不断读取设备状态寄存器：

```text
启动设备
  ↓
查询设备状态
  ↓
未完成 ─────→ 继续查询
  ↓
已完成
  ↓
传送数据
```

特点：

* 实现简单；
* CPU 与设备同步工作；
* CPU 在等待设备时处于**忙等**状态；
* 大量 CPU 时间浪费在状态查询上。

因此其 CPU 利用率最低。

---

### 2. 程序中断方式

[程序中断方式](/docs/408/knowledge2/computer-organization/06-bus-io/02-io-interface-transfer/)不要求 CPU 持续查询设备。

基本过程：

1. CPU 启动 I/O；
2. CPU 转去执行其他程序；
3. 外设完成或需要处理时向 CPU 发出中断请求；
4. CPU 响应中断；
5. 执行中断服务程序；
6. I/O 处理完成后恢复原程序。

相比程序查询方式，它消除了 CPU 的长时间忙等。

但应注意：

> **中断方式下，CPU 仍然需要参与数据传送和中断处理。**

如果大量数据每传送一个字或少量数据就产生一次中断，中断开销仍然很大。

---

### 3. DMA 方式

[DMA 方式](/docs/408/knowledge2/computer-organization/06-bus-io/02-io-interface-transfer/)即 **Direct Memory Access，直接存储器访问**。

DMA 的核心特点是：

**数据可以在 I/O 设备和主存之间直接成批传送，而不必让 CPU 逐字搬运。**

典型过程：

1. CPU 设置 DMA 控制器，包括主存地址、传输方向和数据量；
2. DMA 控制器接管数据传送；
3. DMA 在设备与主存之间传送一批数据；
4. 整批数据传送完成后，通过中断通知 CPU。

因此 CPU 通常只负责：

* 初始化 DMA；
* 在传输完成后进行后续处理。

### 4. 三种控制方式对比

| 控制方式 | 等待设备时 CPU 是否忙等 | 数据传送时 CPU 参与程度 | 通常的数据单位   | CPU 利用率 |
| ---- | -------------- | -------------- | --------- | ------- |
| 程序查询 | 是              | 很高             | 字/字节      | 最低      |
| 程序中断 | 否              | 较高             | 字/字节或少量数据 | 较高      |
| DMA  | 否              | 很低             | 数据块       | 最高      |

可以记成：

> **查询：CPU 等设备。**
> **中断：设备完成后找 CPU。**
> **DMA：数据自己搬，搬完再找 CPU。**

## 三、I/O 软件层次

> **真题考察**
>
> * 选择题：2011 年第 26 题、2012 年第 26 题、2013 年第 25 题、2022 年第 32 题、2026 年第 31 题、2026 年第 32 题
> * 解答题：2019 年第 44 题、2023 年第 46 题

I/O 软件通常采用层次化结构。

从上到下依次可以理解为：

```text
用户层 I/O 软件
       ↓
设备独立性软件
       ↓
设备驱动程序
       ↓
中断处理程序
       ↓
硬件
```

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-003.svg" alt={"用户层I/O软件 设备独立性软件 设备驱动程序 中断处理程序 硬件 I/O 请求 I/O 应答 执行 I/O 操作 设置设备寄存器；检查状态 命名；保护；分块；缓冲；分配 产生 I/O 请求；格式化 I/O；SPOOLing I/O 软件层次 I/O 完成时唤醒驱动程序"} />

408 最常考的不是“背五层名字”，而是：

**给出某项工作，判断它属于哪一层。**

---

### 1. 用户层 I/O 软件

用户层 I/O 软件直接面向应用程序，为程序员提供容易使用的 I/O 接口。

例如：

```c
printf("hello %d", n);
fgets(buf, 128, stdin);
fwrite(&s, sizeof s, 1, fp);
```

应用程序通常只关心：

* 我要读什么；
* 我要写什么；
* 我要操作哪个文件或逻辑设备。

而不需要知道：

* 磁盘控制器寄存器地址；
* DMA 如何工作；
* 硬盘使用 SATA 还是 NVMe；
* 中断向量是多少。

用户态库函数最终可以通过 `read`、`write` 等系统调用进入内核。

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-004.svg" alt={"用户层 I/O 软件 把"简单的库调用"翻译成"复杂的系统调用"，向下陷入内核 应用程序 printf("hello %d", n); fgets(buf, 128, stdin); fwrite(&s, sizeof s, 1, fp); // 想的是"输出一段话"，不关心设备 调用库函数 用户层 I/O 软件（库 / 运行时） 运行在用户态 ① 格式化 / 解析 printf scanf sprintf atoi / strtol ② 用户级缓冲 fopen / fclo"} />

> **易错点**
>
> `printf()` 等库函数和系统调用不是同一个概念。库函数可以在用户态完成部分工作，并在必要时进一步调用操作系统提供的系统调用。

---

### 2. 设备独立性软件

**设备独立性软件（Device-independent I/O Software）**位于用户层和设备驱动程序之间。

核心作用是：

> **屏蔽具体设备差异，为上层提供统一的逻辑 I/O 接口。**

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-005.svg" alt={"设备独立性软件 位于用户层与设备驱动之间，屏蔽硬件差异，向上提供统一接口 用户层 I/O 软件（库函数 / 系统调用：read、write、printf…） 设备独立性软件（核心功能） ① 统一命名与接口 将不同设备抽象为文件 / 逻辑名 上层无需关心具体硬件类型 ② 缓冲管理 单缓冲 / 双缓冲 / 缓冲池 缓解 CPU 与设备速度差异 ③ 设备分配与回收 独占 / 共享 / 虚拟设备管理 避免多进程并发访问冲突 ④ 差错处理 校验、重试等通用错误处理 屏蔽底层硬件异常 ⑤"} />

其典型工作包括：

* 设备命名；
* 设备保护；
* 设备分配与回收；
* 缓冲管理；
* 通用差错处理；
* 将逻辑设备映射到物理设备；
* 提供统一的读写接口。

例如，上层程序调用：

```text
read(...)
write(...)
```

而不需要因为底层换了一块不同厂商的磁盘就修改应用程序。

因此，**设备独立性是操作系统实现可移植性和统一设备管理的重要基础。**

---

### 3. 设备驱动程序

**设备驱动程序（Device Driver）**直接针对某一种具体硬件。

它的核心职责可以概括为：

> **把上层通用 I/O 命令翻译成具体设备能够执行的硬件操作。**

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-006.svg" alt={"设备驱动程序 承上启下：把设备独立性软件的通用命令 → 翻译为特定硬件能理解的指令 设备独立性软件（通用 I/O 命令：read / write / ioctl…） 设备驱动程序（内核态，针对具体硬件） ① 命令翻译 通用 I/O 请求 → 设备特定指令 写控制/命令寄存器 如：扇区读写、控制字符 ② 设备初始化与配置 复位、加载固件 分配 I/O 端口、DMA 通道 注册中断向量 ③ 数据传输 程序查询 / 中断 / DMA 在设备寄存器与内存间搬运 配合上层缓冲区 ④ 中"} />

常见工作包括：

* 初始化设备；
* 设置控制寄存器；
* 设置状态寄存器；
* 启动 I/O；
* 设置 DMA；
* 检查设备状态；
* 处理设备特定错误；
* 将通用读写操作转换成硬件命令。

例如：

* 硬盘驱动程序负责具体扇区读写；
* 打印机驱动程序负责产生打印机能够理解的控制命令。

驱动程序通常运行在**内核态**。

---

### 4. 中断处理程序

设备完成 I/O 后，通常通过硬件中断通知处理器。

[中断处理程序](/docs/408/knowledge2/computer-organization/06-bus-io/02-io-interface-transfer/)负责快速响应这些事件。

<InlineSvg src="/images/operating-system/operating-system-io-device-devices-007.svg" alt={"中断处理程序大致流程 硬件触发 → 保存现场 → 快速处理 → 恢复现场 → 回到原任务 设备 / 硬件 CPU / 中断处理程序（内核态，高优先级、代码精简） 用户/上层软件 ① 设备事件发生 数据到达 / 完成 / 出错 中断信号 ② 响应中断 暂停当前任务 切换到内核态 ③ 保存现场 PC、寄存器、状态字 压栈保存 ④ 识别中断源 / 分发 查中断向量表 跳转到对应处理例程 ⑤ 执行中断服务 读写设备寄存器 搬运数据、置状态 ⑥ 唤醒/通知上层 唤醒等待进程 通知驱动/"} />

大致过程：

1. 设备产生中断；
2. CPU 暂停当前执行流；
3. 保存必要现场；
4. 根据中断源找到相应中断处理程序；
5. 读取或修改设备状态；
6. 确认 I/O 完成或错误；
7. 通知驱动程序或唤醒等待 I/O 的进程；
8. 恢复现场。

中断处理程序通常要求：

* 执行速度快；
* 代码尽量短；
* 不执行没有必要的耗时工作。

例如网卡收到数据时，数据可能已经通过 DMA 放入主存，中断处理程序主要负责确认事件并通知后续网络处理逻辑，而不是一定由 CPU 逐字搬运整个数据包。

---

### 5. 硬件层

硬件是 I/O 软件体系的最底层，包括：

* 实际 I/O 设备；
* 设备控制器；
* 数据寄存器；
* 状态寄存器；
* 控制寄存器；
* I/O 端口；
* DMA 控制器；
* 数据传输通路。

最终所有软件请求都必须转化为硬件能够执行的操作。

---

### 6. 软件层次高频对应关系

| 工作                     | 最典型的所属层次   |
| ---------------------- | ---------- |
| `printf`、格式化输出         | 用户层 I/O 软件 |
| 统一设备命名                 | 设备独立性软件    |
| 缓冲管理                   | 设备独立性软件    |
| 设备分配和回收                | 设备独立性软件    |
| 逻辑设备到物理设备映射            | 设备独立性软件    |
| 把 `read/write` 转换为硬件命令 | 设备驱动程序     |
| 设置设备寄存器                | 设备驱动程序     |
| 响应设备完成中断               | 中断处理程序     |
| 实际完成物理传输               | 硬件         |

> **做题技巧**
>
> 看到“**与具体型号有关**”，优先想到**设备驱动程序**。
>
> 看到“**统一接口、屏蔽设备差异**”，优先想到**设备独立性软件**。
>
> 看到“**设备完成后发出中断**”，优先想到**中断处理程序**。
