现行 408 考纲把**固态硬盘的读写特性与磨损均衡**明确列入 I/O 管理。SSD 虽然和 HDD 都提供“块设备”接口，但底层物理约束完全不同。

> **真题标签**
>
> 2010 年第 45 题第（3）问已经考察 Flash/SSD 不存在机械寻道，因此不应继续用 C-SCAN 优化磁头移动。

## 5.7.1 NAND Flash 的基本读写粒度

SSD 内部通常基于 NAND Flash。

重点记住：

- **读（read）**：通常以页为基本粒度；
- **编程/写（program）**：通常以页为基本粒度；
- **擦除（erase）**：通常以更大的块（block）为基本粒度。

因此出现一个关键限制：

> **不能像 DRAM 那样随意原地覆盖已经写过的 Flash 页。**

## 5.7.2 异地更新（out-of-place update）

要修改一个已经存在的逻辑页时，SSD 常采用：

1. 找一个新的空闲物理页；
2. 把新版本写到新页；
3. 更新映射；
4. 旧页标记为无效；
5. 之后由垃圾回收统一处理旧页。

因此：

```text
逻辑块地址 LBA
      ↓
FTL 映射
      ↓
实际 Flash 物理页
```

## 5.7.3 FTL：闪存转换层

FTL（Flash Translation Layer）负责维护逻辑块地址与物理 Flash 位置之间的映射。

上层操作系统仍可像使用普通块设备一样读写 LBA，而 FTL 在内部完成：

- 地址映射；
- 异地更新；
- 垃圾回收；
- 坏块管理；
- 磨损均衡等。

所以“逻辑连续”并不保证底层 Flash 物理页真的连续。

## 5.7.4 垃圾回收与写放大

一个擦除块中可能同时包含：

- 有效页；
- 已失效旧页；
- 空闲页。

要回收这个块，控制器可能需要：

1. 把仍有效的页搬到别处；
2. 擦除整个块；
3. 再把该块变成可写空间。

这会产生额外内部写入。

若主机实际写入量为 $W_{host}$，SSD 内部实际写入量为 $W_{flash}$，写放大可表示为：

$$
WA=\frac{W_{flash}}{W_{host}}
$$

通常：

$$
WA\ge 1
$$

写放大越高，性能和寿命通常越不利。

## 5.7.5 TRIM 的作用

操作系统删除文件后，仅从文件系统元数据角度知道某些逻辑块“不再需要”。SSD 控制器若不知道这些块已失效，就可能在垃圾回收时错误地把无用旧数据也当有效页搬运。

TRIM 可以把“这些逻辑块已经不再需要”这一信息告诉 SSD，使其更高效地回收空间。

> **易错点**
>
> TRIM 不是“立刻把每个 Flash 单元全部擦成 0”，而是向设备传递逻辑块失效信息，具体擦除时机由控制器管理。

## 5.7.6 磨损均衡（wear leveling）

NAND Flash 的擦写次数有限。如果总在少数块上反复擦写，这些块会提前老化。

磨损均衡的目标：

> **让擦写尽可能均匀分布到不同物理块。**

### 动态磨损均衡

写入新数据时优先选择擦写次数较少的空闲块。

### 静态磨损均衡

不仅管理正在变化的数据，还可能把长期不变的“冷数据”迁移出去，释放擦写次数较少的块给后续写操作使用。

因此静态磨损均衡通常比动态方式更彻底，但迁移开销也更高。

## 5.7.7 HDD 与 SSD 的核心差异

| 对比项 | HDD | SSD |
| --- | --- | --- |
| 介质 | 磁介质盘片 | NAND Flash |
| 机械磁头 | 有 | 无 |
| 寻道时间 | 重要 | 无机械寻道 |
| 旋转延迟 | 有 | 无 |
| 原地覆盖 | 可按扇区磁写入 | 通常受擦除前写限制 |
| 擦除粒度 | 不强调 Flash 式块擦除 | 块级擦除 |
| 特有问题 | 磁头移动优化 | GC、写放大、磨损均衡 |

所以：

> 对 SSD，不能把 FCFS/SSTF/SCAN/C-SCAN 的主要价值解释成“减少磁头移动”。

实际 SSD 控制器仍可能重排请求以利用多通道并行、队列和内部资源，但这与机械寻道模型是两回事。

## 5.7.8 本章四组最容易混淆的概念

### 查询、中断、DMA

```text
查询：CPU 忙等 + CPU 搬
中断：CPU 不忙等，但 CPU 仍处理/搬少量数据
DMA：设备与主存成批直传，CPU 初始化 + 收尾
```

### 设备独立层与驱动

```text
设备独立层：统一、通用、屏蔽差异
驱动程序：型号相关、寄存器相关、具体硬件命令
```

### Buffer、Cache、SPOOLing

```text
Buffer：速度匹配
Cache：减少慢速重复访问
SPOOLing：独占设备排队与虚拟共享
```

### HDD 与 SSD

```text
HDD：寻道 + 旋转 + 传输
SSD：页读写 + 块擦除 + FTL + GC + 磨损均衡
```

## 5.7.10 本章完整知识链

```text
应用 read/write
   ↓
设备独立接口
   ↓
驱动程序
   ↓
查询 / 中断 / DMA / 通道
   ↓
缓冲与缓存优化数据流
   ↓
设备分配与 SPOOLing 管理共享
   ↓
块设备进入 HDD / SSD 外存管理
   ↓
HDD：格式化 + 调度
SSD：FTL + GC + 磨损均衡
```

把这条链串起来后，I/O 管理就不再是零散名词，而是一套“**从应用请求到真实设备完成**”的分层机制。
