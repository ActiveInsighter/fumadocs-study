I/O 管理的核心不是“让 CPU 会操作某一块具体硬件”，而是：**由操作系统屏蔽设备差异，向进程提供统一接口，再把通用请求逐层翻译成具体硬件操作。**

> **真题标签**
>
> I/O 软件层次与设备管理：2011 年第 26 题、2012 年第 26 题、2013 年第 25 题、2022 年第 32 题、2026 年第 31 题、2026 年第 32 题。
>

## 5.1.1 本章主线

一次典型输入可以沿下面的链路理解：

```text
用户进程 read(...)
      ↓
系统调用 / 通用 I/O 接口
      ↓
设备独立性软件
      ↓
设备驱动程序
      ↓
I/O 接口 / 控制器
      ↓
具体设备执行
      ↓
中断 / DMA 完成通知
      ↓
内核唤醒等待进程
```

做题时最重要的是判断：**某项工作究竟属于哪一层。**

## 5.1.2 I/O 设备的常见分类

按操作系统看到的数据组织方式，可重点区分：

| 类型 | 基本数据形式 | 是否通常支持随机定位 | 典型设备 |
| --- | --- | :---: | --- |
| 块设备 | 固定大小的数据块 | ✅ | HDD、SSD、U 盘 |
| 字符设备 | 连续字符/字节流 | ❌ | 键盘、鼠标、串口、打印机 |
| 网络设备 | 数据帧/数据包 | 不按普通块设备方式 | 网卡 |

### 块设备

块设备适合按块传输大量数据，并通常允许定位到指定逻辑块。

### 字符设备

字符设备通常按到达顺序处理数据，不具有“任意跳到某个数据块”这一普通块设备语义。

### 网络设备

网络设备强调数据包收发，常结合：

- 中断；
- DMA；
- 环形描述符队列；
- 网络协议栈。

<Callout type="warn" title="分类描述的是接口语义">
“块设备/字符设备”主要描述操作系统向上提供的访问模型，不应机械理解为硬件内部每次真的只移动一个块或一个字符。
</Callout>

## 5.1.3 I/O 接口与端口

CPU 通常不直接操作设备机械部件，而是访问**设备控制器 / I/O 接口**中的寄存器。

典型寄存器包括：

| 寄存器 | 作用 |
| --- | --- |
| 数据寄存器 | 暂存 CPU 与设备交换的数据 |
| 状态寄存器 | 记录就绪、忙、错误等状态 |
| 控制寄存器 | 接收启动、读写方向、复位等命令 |

这里的“端口（port）”可理解为 CPU 可访问的 I/O 寄存器地址。

### 独立编址 I/O

I/O 端口拥有独立地址空间，CPU 使用专门 I/O 指令访问。

```text
存储器地址空间 ≠ I/O 端口地址空间
```

### 统一编址 / 内存映射 I/O

把设备寄存器映射到普通物理地址空间的一部分：

```text
某段地址 → 内存
某段地址 → 设备寄存器
```

CPU 可使用普通访存指令访问设备寄存器。

> **易错点**
>
> “内存映射 I/O”只是让设备寄存器占用地址空间，并不意味着设备数据已经存放在普通 DRAM 中。

## 5.1.4 面向应用程序的 I/O 接口

应用程序通常使用统一系统调用，而不是直接读写硬件端口。

典型形式：

```c
read(fd, buf, n);
write(fd, buf, n);
ioctl(fd, cmd, arg);
```

可以按抽象类型理解：

- 字符流接口：键盘、终端、串口；
- 块接口：磁盘逻辑块；
- 网络接口：socket 等；
- 时钟、图形等特殊设备还可拥有专用接口。

### 阻塞与非阻塞

若同步 `read()` 所需数据尚未准备好，调用进程可能：

```text
运行态 → 阻塞态
```

设备完成后，中断处理和内核 I/O 路径使条件满足，进程再被唤醒进入就绪态。

非阻塞接口则通常在当前无法完成时立即返回，而不是睡眠等待。

## 5.1.5 I/O 软件层次

经典层次自上而下为：

```text
用户层 I/O 软件
      ↓
设备独立性软件
      ↓
设备驱动程序
      ↓
中断处理程序
      ↓
硬件
```

### 用户层 I/O 软件

负责提供容易使用的库接口，例如格式化输入输出、流缓冲等。

```c
printf("%d", x);
fread(buf, 1, n, fp);
```

<Callout type="warn" title="库函数不等于系统调用">
`printf()` 可以先在用户态进行格式化和用户级缓冲，只有在需要把数据交给内核时才进一步调用 `write()` 等系统调用。
</Callout>

### 设备独立性软件

核心目标：**把“具体设备”抽象成统一的逻辑设备。**

典型工作：

- 统一设备命名；
- 设备保护；
- 设备分配与回收；
- 缓冲管理；
- 通用差错处理；
- 逻辑设备到物理设备的映射；
- 为上层提供统一读写语义。

看到“**屏蔽设备差异 / 与具体型号无关**”，优先想到这一层。

### 设备驱动程序

驱动程序面向**某类具体控制器和硬件**，把通用请求翻译成设备命令。

典型工作：

- 初始化设备；
- 设置控制寄存器；
- 读取状态寄存器；
- 建立 DMA 描述信息；
- 启动 I/O；
- 处理设备特定错误。

驱动一般运行在内核态。

### 设备驱动接口

为了让上层内核不依赖某厂商设备，操作系统通常要求驱动实现一组约定好的入口，例如：

```text
open / close
read / write
control(ioctl)
interrupt-completion
```

因此：

> 上层依赖“驱动接口”，驱动内部再依赖具体硬件寄存器和协议。

### 中断处理程序

设备产生中断后，中断处理程序负责尽快：

1. 识别中断源；
2. 获取/确认设备状态；
3. 清除或应答中断；
4. 记录 I/O 完成结果；
5. 通知后续驱动逻辑或唤醒等待进程。

它通常应尽量短，耗时工作可留给后续内核路径处理。

### 硬件层

包括：

- 设备本体；
- 设备控制器；
- I/O 端口；
- DMA 控制器；
- 总线和物理数据通路。

## 5.1.6 高频归属判断

| 题目描述 | 最典型层次 |
| --- | --- |
| `printf` 格式化输出 | 用户层 I/O 软件 |
| 统一设备命名 | 设备独立性软件 |
| 设备分配和缓冲管理 | 设备独立性软件 |
| 逻辑设备映射到物理设备 | 设备独立性软件 |
| 把通用读写转换成控制器命令 | 设备驱动程序 |
| 设置设备寄存器 | 设备驱动程序 |
| 响应设备完成中断 | 中断处理程序 |
| 真正进行物理传输 | 硬件 |

> **速记**
>
> **通用功能看设备独立层；型号相关看驱动；完成通知看中断处理。**
