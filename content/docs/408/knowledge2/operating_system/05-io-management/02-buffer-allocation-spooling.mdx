## 四、缓冲技术

> **真题考察**
>
> * 选择题：2009 年第 1 题、2011 年第 31 题、2013 年第 27 题、2015 年第 28 题、2018 年第 31 题、2022 年第 30 题、2026 年第 32 题

**缓冲区（Buffer）**&#x2060;是在主存中开辟的一块临时区域，用于暂存 I/O 数据。

缓冲最重要的作用不是“永久保存数据”，而是：

* 缓和 CPU 与 I/O 设备之间的速度差异；
* 减少 CPU 等待；
* 减少设备等待；
* 允许 I/O 与计算在一定程度上并行；
* 减少中断频率；
* 解决数据处理粒度不匹配的问题。

<InlineSvg src="/images/operating-system/operating-system-io-device-management-001.svg" alt={"缓冲区：解耦快慢两端，平滑数据流 生产者 CPU / 进程 速度快 · 突发 缓冲区 (内存中) D1 D2 D3 空 空 先进先出 · 临时存储 写入端 → 读取端 消费者 I/O 设备 速度慢 · 平稳 写入 读取 CPU 无需等待慢设备 削峰填谷，匹配速度差 减少 I/O 中断频率 一块预留在内存中的临时存放区，让 I/O 与计算并行推进"} />

---

### 1. 磁盘高速缓存

**磁盘高速缓存（Disk Cache）**&#x2060;利用主存空间保存近期从磁盘读取的数据块。

因此：

* 从逻辑用途看，它缓存的是磁盘数据；
* 从物理位置看，它位于主存。

如果后续再次访问相同数据，系统可能直接访问缓存而不必重新访问磁盘。

> **缓冲与缓存不是同一个概念**
>
> * **缓冲 Buffer**：重点是解决数据生产方和消费方速度不匹配。
> * **缓存 Cache**：重点是保存数据副本，减少对慢速层次的重复访问。

---

### 2. 单缓冲

**单缓冲**只有一个缓冲区。

基本过程：

1. I/O 设备向缓冲区输入数据；
2. 数据到达后，进程使用缓冲区中的数据；
3. 缓冲区可重新使用后，设备才能继续向该缓冲区输入下一批数据。

<InlineSvg src="/images/operating-system/operating-system-io-device-management-002.svg" alt={"单缓冲 vs 双缓冲：并行才能省时 单缓冲 · 一块缓冲区，读与处理必须串行 I/O 设备 Buffer CPU 处理 时间轴 → I/O 读入1 等待 读入2 等待 读入3 CPU 等待 处理1 等待 处理2 等待 总耗时较长：读与处理相互等待 双缓冲 · 两块缓冲区交替使用，读与处理可并行 I/O 设备 Buf A Buf B CPU 处理 I/O 读→A 读→B 读→A 读→B 读→A CPU 空 处理 A 处理 B 处理 A 处理 B 读与处理并行 → 吞吐提升 → "} />

单缓冲比完全没有缓冲更有效，但由于只有一个缓冲区，I/O 和数据处理之间仍然存在较明显的相互制约。

---

### 3. 双缓冲

**双缓冲**设置两个缓冲区。

当 CPU 或进程处理缓冲区 A 中的数据时，I/O 设备可以同时向缓冲区 B 输入下一批数据。

随后交换两个缓冲区的角色：

```text
I/O → Buffer A → CPU
      Buffer B ← I/O

下一轮：

I/O → Buffer B → CPU
      Buffer A ← I/O
```

因此双缓冲能够实现更充分的：

**I/O 与计算并行。**

典型优点：

* 减少双方等待；
* 增大系统吞吐量；
* 适用于连续数据流。

---

### 4. 循环缓冲

**循环缓冲（Circular Buffer）**&#x2060;由多个连续缓冲单元构成，并在逻辑上形成一个环。

<InlineSvg src="/images/operating-system/operating-system-io-device-management-003.svg" alt={"循环缓冲 读写指针环形推进，尾部回绕到头部 D D D D 写指针 读指针 回绕 已写入 空闲槽 · 容量固定，可持续覆盖旧数据 缓冲池 一组共享缓冲区，按需借用与归还 共享缓冲池 B1 空 B3 空 B5 空 输入队列 · 输出队列 · 空闲队列 进程 P1 进程 P2 进程 P3 借用 归还 已分配 空闲 · 多进程共享 · 提高利用率"} />

通常设置：

* 读指针；
* 写指针。

指针到达数组末尾后会重新回到开始位置。

> **易错点**
>
> 循环缓冲区的**物理容量仍然有限**，并不是能够无限保存数据。
>
> 当生产速度长期高于消费速度时，系统必须选择：
>
> * 阻塞生产者；
> * 丢弃新数据；
> * 或覆盖尚未读取的旧数据。
>
> 具体策略取决于实现方式。

---

### 5. 缓冲池

**缓冲池（Buffer Pool）**&#x2060;是一组由系统统一维护和分配的缓冲区。

基本过程：

1. 进程需要缓冲区时向缓冲池申请；
2. 系统从空闲缓冲区中分配一个；
3. 使用完成后归还；
4. 其他进程可以继续复用。

如果没有可用缓冲区，申请进程可能阻塞等待。

缓冲池相比“为每个进程固定准备缓冲区”能够提高缓冲空间的整体利用率。

## 五、设备分配与回收

> **真题考察**
>
> * 选择题：2009 年第 32 题、2020 年第 30 题、2023 年第 32 题

设备分配的目标是：

> **在保证安全性的前提下，提高设备利用率并满足进程的 I/O 请求。**

从使用方式看，设备通常可以分为：

* 独占使用；
* 分时共享；
* 通过 SPOOLing 实现虚拟共享。

---

### 1. 设备控制表 DCT

操作系统需要维护设备相关状态。

常见数据结构之一是：

**DCT（Device Control Table，设备控制表）**。

<InlineSvg src="/images/operating-system/operating-system-io-device-management-004.svg" alt={"设备类型type DCT 1 DCT 2 DCT n 设备标识符deviceid 设备状态 指向控制器表的指针 重复执行次数或时间 设备队列的队首指针 设备控制表DCT"} />

DCT 通常保存：

* 设备类型；
* 设备标识符；
* 当前设备状态；
* 指向设备控制器信息的指针；
* 等待该设备的进程队列；
* 错误处理或重试信息。

在更完整的设备管理体系中，还可能存在系统设备表、控制器控制表、通道控制表等结构，它们共同描述：

```text
进程
 ↓
设备
 ↓
设备控制器
 ↓
I/O 通道
```

具体名称可能随教材模型不同而有所差异，408 做题时应以题目给定结构为准。

---

### 2. 静态分配与动态分配

#### 静态分配

设备在进程执行前一次性分配，进程结束后再释放。

优点：

* 管理简单；
* 可以避免执行过程中因为等待设备而产生某些资源竞争问题。

缺点：

* 设备占用时间长；
* 利用率较低。

#### 动态分配

进程真正需要设备时才申请，用完后立即释放。

优点：

* 设备利用率高；
* 多个进程能够交替使用设备。

缺点：

* 管理更复杂；
* 若多个资源的申请顺序不合理，可能产生死锁。

---

### 3. 安全分配与不安全分配

#### 安全分配

操作系统进行设备或资源分配时，保证系统仍能够处于一个可以继续完成所有进程的安全状态。

#### 不安全分配

进入**不安全状态**并不等价于已经发生死锁。

关系应记为：

```text
死锁状态 ⇒ 一定不安全

不安全状态 ⇏ 一定已经死锁
```

不安全状态意味着：

**系统已经存在进一步发展为死锁的可能性。**

这一思想与[死锁](/docs/408/knowledge2/operating_system/02-process-management/05-deadlock/)中的安全状态分析一致。

---

### 4. 逻辑设备与物理设备

设备独立性的一个重要基础，是将：

**逻辑设备名**

与

**物理设备**

分离。

#### 逻辑设备名

由用户程序使用，例如：

```text
/dev/sda
/dev/lp0
/dev/tty1
```

程序不需要知道设备实际挂在哪个总线、端口或控制器上。

#### 物理设备名

表示操作系统内部实际使用的具体硬件设备。

操作系统可以通过**逻辑设备表 LUT（Logical Unit Table）**&#x2060;维护两者之间的映射。

<InlineSvg src="/images/operating-system/operating-system-io-device-management-005.svg" alt={'逻辑设备 → 物理设备映射 应用只认友好名，内核通过 LUT 查到真实硬件 应用层 内核 · 逻辑设备表 (LUT) 硬件层 App A open("/dev/sda") App B open("/dev/lp0") App C open("/dev/tty1") 逻辑名 驱动 / 类型 物理地址 /dev/sda block · SATA PCI 0:1f:2 /dev/lp0 char · printer USB bus2 /dev/tty1 char · console'} />

例如，在类 Unix 系统中可以看到大量设备文件：

```text
> ls /dev

aes_0                ptyw9
afsc_type5           ptywa
apfs-raw-device.2.0  ptywb
auditpipe            ptywc
auditsessions        ptywd
autofs               ptywe
autofs_control       ptywf
autofs_homedirmounter random
autofs_notrigger     rdisk0
```

这些名称向程序提供逻辑接口，内核再将它们关联到相应驱动程序和具体硬件。

其意义是：

* 上层程序不依赖具体硬件；
* 更换设备时应用程序通常不需要修改；
* 便于统一进行设备管理和权限控制。

## 六、SPOOLing 技术

> **真题考察**
>
> * 选择题：2016 年第 31 题

**SPOOLing（Simultaneous Peripheral Operations On-Line）**&#x2060;称为**假脱机技术**或联机并发外设操作技术。

其核心思想是：

> **利用磁盘模拟脱机输入/输出，使多个进程能够以类似共享的方式使用原本的独占设备。**

<InlineSvg src="/images/operating-system/operating-system-io-device-management-006.svg" alt={'SPOOLing 技术 — 概念与典型应用 Simultaneous Peripheral Operations On-Line · 用磁盘做中间缓冲，把独占设备"改造"成共享设备 一、核心概念 多个用户 / 进程 P1 P2 P3 提交 I/O 请求后 立即返回，继续 执行自己的任务 感觉像独享设备 写入 SPOOLing 子系统（假脱机） 运行在主机 / CPU，用软件模拟"外围控制机" 输入井（磁盘） 模拟脱机时的输入带 job#1 data... job#2 data'} />

---

### 1. SPOOLing 的基本思想

假设多进程都需要打印：

```text
P1 ─┐
P2 ─┼→ 磁盘上的打印队列 → 打印后台程序 → 打印机
P3 ─┘
```

各进程并不是直接争抢打印机。

它们首先把需要打印的数据写入磁盘上的 SPOOLing 区域，然后就可以继续执行。

后台程序再按照一定顺序，把任务依次送往真正的打印机。

因此：

**多个进程感觉自己都可以使用打印机，而实际上某一时刻物理打印机仍然只能执行一个打印任务。**

---

### 2. 关键机制

#### 输入井和输出井

SPOOLing 通常在磁盘上开辟较大的存储区域，用来模拟脱机输入输出。

可以理解为：

* **输入井**：暂存输入数据；
* **输出井**：暂存输出数据。

#### 输入进程和输出进程

系统通过专门程序负责：

* 将外部输入设备数据送入输入井；
* 将输出井中的任务送给实际输出设备。

#### 请求队列

多个进程提交的 I/O 请求可以先排队，而不必立即获得物理设备。

---

### 3. SPOOLing 的作用

SPOOLing 可以：

* 提高独占设备利用率；
* 提高 CPU 与外设的并行程度；
* 减少进程直接等待慢速设备的时间；
* 将独占设备在逻辑上虚拟成共享设备。

打印机是最典型的应用。

> **高频结论**
>
> SPOOLing 并没有让多个进程在同一时刻真正同时操作一台物理打印机。
>
> 它只是通过**磁盘队列 + 后台进程**实现了逻辑共享。

---

### 4. Buffer、Cache 与 SPOOLing 对比

| 技术       | 主要位置   | 核心目标        | 典型应用    |
| -------- | ------ | ----------- | ------- |
| Buffer   | 主存     | 匹配速度、平滑数据流  | 单缓冲、双缓冲 |
| Cache    | 主存     | 保存副本，减少慢速访问 | 磁盘高速缓存  |
| SPOOLing | 主要利用磁盘 | 排队并虚拟化独占设备  | 打印队列    |

> **易混点**
>
> SPOOLing 中确实存在“暂存数据”的行为，但它不能简单等同于普通内存缓冲。SPOOLing 的关键是**模拟脱机 I/O 和虚拟设备**。
