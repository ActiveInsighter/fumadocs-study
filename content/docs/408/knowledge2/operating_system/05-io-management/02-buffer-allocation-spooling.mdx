## 9. 缓冲技术的目标

<InlineSvg src="/images/operating-system/operating-system-io-device-management-001.svg" alt={"缓冲区：解耦快慢两端，平滑数据流 生产者 CPU / 进程 速度快 · 突发 缓冲区 (内存中) D1 D2 D3 空 空 先进先出 · 临时存储 写入端 → 读取端 消费者 I/O 设备 速度慢 · 平稳 写入 读取 CPU 无需等待慢设备 削峰填谷，匹配速度差 减少 I/O 中断频率 一块预留在内存中的临时存放区，让 I/O 与计算并行推进"} />

> **真题考察**
>
> - 选择题：2009 年第 1 题、2011 年第 31 题、2013 年第 27 题、2015 年第 28 题、2018 年第 31 题、2022 年第 30 题、2026 年第 32 题

**缓冲区（Buffer）**是在主存中开辟的临时存储区域，用来暂存 I/O 数据。

缓冲的核心目标不是“永久保存”，而是**解耦速度不同的生产者与消费者**。

典型作用包括：

- 缓和 CPU 与 I/O 设备的速度差异；
- 减少 CPU 或设备直接等待对方的时间；
- 允许 I/O 与计算在一定程度上并行；
- 把零散传送合并成较大批次，降低控制开销；
- 解决双方一次处理数据量不同的问题。

<Callout type="warning" title="Buffer 与 Cache 不是同义词">

- **Buffer**：重点是匹配速度、平滑数据流；
- **Cache**：重点是保存已有数据的副本，利用局部性减少对慢速层次的重复访问。

二者都可能位于主存，但设计目的不同。

</Callout>

## 10. 单缓冲、双缓冲与循环缓冲

### 10.1 单缓冲

<InlineSvg src="/images/operating-system/operating-system-io-device-management-002.svg" alt={"单缓冲 vs 双缓冲：并行才能省时 单缓冲 · 一块缓冲区，读与处理必须串行 I/O 设备 Buffer CPU 处理 时间轴 → I/O 读入1 等待 读入2 等待 读入3 CPU 等待 处理1 等待 处理2 等待 总耗时较长：读与处理相互等待 双缓冲 · 两块缓冲区交替使用，读与处理可并行 I/O 设备 Buf A Buf B CPU 处理 I/O 读→A 读→B 读→A 读→B 读→A CPU 空 处理 A 处理 B 处理 A 处理 B 读与处理并行 → 吞吐提升 → "} />

单缓冲只设置一个缓冲区：

```text
设备 → Buffer → 用户工作区 / CPU 处理
```

一批数据到达缓冲区后，必须先把它取走，使缓冲区重新可用，设备才能继续把下一批数据写入同一缓冲区。

单缓冲相对“完全无缓冲”已有改进，但设备与处理程序仍会因为共享一个缓冲区而相互制约。

### 10.2 单缓冲时间模型

若题目约定：

- $T$：设备把一块数据输入缓冲区的时间；
- $M$：把一块数据从缓冲区复制到用户工作区的时间；
- $C$：CPU 处理一块数据的时间；

并且缓冲区释放后，设备输入下一块可以与 CPU 处理上一块并行，则处理 $n$ 块数据的典型总时间可写为：

$$
T_{\text{single}}
= T+nM+(n-1)\max(T,C)+C
$$

当 $n$ 很大时，每块的稳定阶段时间近似为：

$$
M+\max(T,C)
$$

<Callout type="info" title="公式必须服从题目时序">
408 缓冲计算题最重要的不是死背公式，而是先画出“输入、复制、处理”三个阶段能否重叠。若题目给出的缓冲区使用规则不同，应按题意重新画时间轴。
</Callout>

### 10.3 双缓冲

双缓冲设置两个缓冲区：当 CPU 处理缓冲区 A 对应的数据时，设备可以向缓冲区 B 输入下一批数据；随后两者交换角色。

```text
阶段 1：设备 → Buffer A
阶段 2：CPU 处理 A 对应数据，同时设备 → Buffer B
阶段 3：CPU 处理 B 对应数据，同时设备 → Buffer A
...
```

因此双缓冲比单缓冲更容易实现**设备输入与 CPU 处理的并行**。

在常见模型中，若一块数据从缓冲区复制并处理共需要 $M+C$，而设备输入一块需要 $T$，稳定阶段吞吐周期可近似看作：

$$
\max(T,M+C)
$$

### 10.4 循环缓冲

<InlineSvg src="/images/operating-system/operating-system-io-device-management-003.svg" alt={"循环缓冲 读写指针环形推进，尾部回绕到头部 D D D D 写指针 读指针 回绕 已写入 空闲槽 · 容量固定，可持续覆盖旧数据 缓冲池 一组共享缓冲区，按需借用与归还 共享缓冲池 B1 空 B3 空 B5 空 输入队列 · 输出队列 · 空闲队列 进程 P1 进程 P2 进程 P3 借用 归还 已分配 空闲 · 多进程共享 · 提高利用率"} />

**循环缓冲（Circular Buffer）**由多个缓冲单元组成，并在逻辑上首尾相接。

典型维护：

- 读指针；
- 写指针；
- 当前可读/可写状态。

```text
B0 → B1 → B2 → ... → Bk
↑                   ↓
└───────────────────┘
```

<Callout type="warning" title="循环 ≠ 无限">
循环缓冲只是重复利用一块**有限容量**空间。当生产速度长期大于消费速度时，最终仍会满。此时必须阻塞生产者、丢弃数据或按既定策略覆盖旧数据。
</Callout>

## 11. 缓冲池与磁盘高速缓存

### 11.1 缓冲池

**缓冲池（Buffer Pool）**是一组由系统统一管理、按需分配和回收的缓冲区。

典型过程：

1. 进程或内核模块申请一个缓冲区；
2. 系统从空闲缓冲中分配；
3. 使用完成后归还；
4. 其他请求继续复用。

相比分别为每个进程永久预留固定缓冲区，缓冲池能够提高整体空间利用率。若暂时没有可用缓冲区，请求者可能阻塞等待。

### 11.2 磁盘高速缓存

**磁盘高速缓存（Disk Cache）**利用主存保存近期访问过的磁盘数据块副本。

如果后续再次访问同一数据，命中缓存时可以直接从主存获得，无需再次访问慢速磁盘。

因此：

- 从物理位置看，它位于主存；
- 从逻辑用途看，它缓存的是外存数据；
- 核心收益来自**局部性**和**减少慢速访问**。

### 11.3 Buffer、Cache 的本质区别

| 对比项 | Buffer | Cache |
| --- | --- | --- |
| 核心目的 | 匹配速度、平滑数据流 | 保存副本、减少重复慢速访问 |
| 数据是否一定是其他位置的副本 | 不一定 | 通常是 |
| 典型场景 | 单缓冲、双缓冲、缓冲池 | 磁盘高速缓存、页缓存 |

## 12. 设备分配与回收

<InlineSvg src="/images/operating-system/operating-system-io-device-management-004.svg" alt={"设备类型type DCT 1 DCT 2 DCT n 设备标识符deviceid 设备状态 指向控制器表的指针 重复执行次数或时间 设备队列的队首指针 设备控制表DCT"} />

> **真题考察**
>
> - 选择题：2009 年第 32 题、2020 年第 30 题、2023 年第 32 题

设备分配的目标是：

> **满足进程 I/O 请求，同时避免冲突、提高设备利用率并保持系统可管理性。**

从使用方式看，设备可以表现为：

- **独占使用**：同一时刻只允许一个进程直接占用；
- **分时共享**：多个进程按时间交替使用；
- **虚拟共享**：借助 SPOOLing 等技术，把独占设备包装成逻辑上的共享设备。

### 12.1 常见设备管理表

不同教材命名细节可能略有差异，常见结构包括：

- **SDT（System Device Table，系统设备表）**：系统范围内记录设备；
- **DCT（Device Control Table，设备控制表）**：记录某个具体设备状态；
- **COCT（Controller Control Table，控制器控制表）**：记录设备控制器；
- **CHCT（Channel Control Table，通道控制表）**：记录 I/O 通道。

可把典型依赖关系理解为：

```text
系统设备表 SDT
      ↓
设备控制表 DCT
      ↓
控制器控制表 COCT
      ↓
通道控制表 CHCT
```

DCT 常记录：

- 设备类型和标识；
- 忙/闲等状态；
- 等待该设备的进程队列；
- 指向控制器信息的指针；
- 错误、重试等管理信息。

<Callout type="warning" title="以题目给定模型为准">
不同教材对设备、控制器、通道表的字段和连接关系可能有不同简化。综合题若明确给出数据结构，应优先按题目定义推导。
</Callout>

### 12.2 静态分配与动态分配

**静态分配**：进程执行前一次性申请所需设备，结束时统一释放。

- 优点：管理简单，某些情况下易于避免执行期资源等待；
- 缺点：设备占用时间长，利用率较低。

**动态分配**：真正需要时申请，用完即释放。

- 优点：设备利用率高；
- 缺点：资源申请顺序不当时可能参与形成死锁。

### 12.3 安全与不安全状态

设备分配若与其他不可剥夺资源共同参与死锁问题，也可借用安全状态思想分析。

必须记住：

```text
死锁状态 ⇒ 一定是不安全状态
不安全状态 ⇏ 已经发生死锁
```

不安全只表示：**系统已经失去“保证存在安全完成次序”的能力，后续可能发展为死锁。**

这一思想与[死锁](/docs/408/knowledge2/operating_system/02-process-management/05-deadlock/)中的安全状态分析一致。

## 13. 逻辑设备与物理设备映射

<InlineSvg src="/images/operating-system/operating-system-io-device-management-005.svg" alt={'逻辑设备 → 物理设备映射 应用只认友好名，内核通过 LUT 查到真实硬件 应用层 内核 · 逻辑设备表 (LUT) 硬件层 App A open("/dev/sda") App B open("/dev/lp0") App C open("/dev/tty1") 逻辑名 驱动 / 类型 物理地址 /dev/sda block · SATA PCI 0:1f:2 /dev/lp0 char · printer USB bus2 /dev/tty1 char · console'} />

设备独立性的重要基础，是把用户看到的**逻辑设备**与系统实际管理的**物理设备**分离。

### 13.1 逻辑设备名

用户程序使用稳定的逻辑名字，不需要了解硬件挂在哪个总线、端口或控制器上。

例如类 Unix 系统常见：

```text
/dev/sda
/dev/lp0
/dev/tty1
```

### 13.2 逻辑设备表 LUT

操作系统可以借助 **LUT（Logical Unit Table，逻辑设备表）**维护逻辑设备到物理设备的映射。

其价值包括：

- 应用程序不依赖具体硬件；
- 更换同类设备时，上层程序通常不需要修改；
- 便于统一执行设备分配、保护和权限控制。

类 Unix 系统中可以看到大量设备文件：

```text
> ls /dev

aes_0                ptyw9
afsc_type5           ptywa
apfs-raw-device.2.0  ptywb
auditpipe            ptywc
auditsessions        ptywd
autofs               ptywe
autofs_control       ptywf
autofs_homedirmounter random
autofs_notrigger     rdisk0
```

这些名字是上层访问入口，内核再把访问关联到相应驱动程序和具体设备。

## 14. SPOOLing：把独占设备虚拟成共享设备

<InlineSvg src="/images/operating-system/operating-system-io-device-management-006.svg" alt={'SPOOLing 技术 — 概念与典型应用 Simultaneous Peripheral Operations On-Line · 用磁盘做中间缓冲，把独占设备"改造"成共享设备 一、核心概念 多个用户 / 进程 P1 P2 P3 提交 I/O 请求后 立即返回，继续 执行自己的任务 感觉像独享设备 写入 SPOOLing 子系统（假脱机） 运行在主机 / CPU，用软件模拟"外围控制机" 输入井（磁盘） 模拟脱机时的输入带 job#1 data... job#2 data'} />

> **真题考察**
>
> - 选择题：2016 年第 31 题

**SPOOLing（Simultaneous Peripheral Operations On-Line）**又称**假脱机技术**。

核心思想是：

> **利用磁盘上的中间队列模拟脱机输入/输出，使多个进程能够以“像共享一样”的方式使用原本的独占设备。**

打印机是最典型的例子：

```text
P1 ─┐
P2 ─┼→ 磁盘输出井 / 打印队列 → 后台打印进程 → 物理打印机
P3 ─┘
```

应用进程把待打印数据提交到磁盘队列后就可以继续执行，不必一直占住真实打印机。

### 14.1 输入井、输出井与后台进程

SPOOLing 系统通常包含：

- **输入井**：在磁盘上暂存输入数据；
- **输出井**：在磁盘上暂存输出任务；
- **输入进程**：把外部输入送入输入井；
- **输出进程**：从输出井取任务并交给真实设备；
- **请求队列**：组织多个进程提交的 I/O 作业。

### 14.2 SPOOLing 的作用

SPOOLing 能够：

- 提高独占设备利用率；
- 提高 CPU 与外设并行程度；
- 减少用户进程直接等待慢速设备的时间；
- 将独占设备在**逻辑上**虚拟成共享设备。

<Callout type="warning" title="物理设备仍然没有变成并行设备">
多个进程可以同时提交打印任务，但一台物理打印机在同一时刻仍然只执行一个具体打印任务。SPOOLing 实现的是**排队 + 后台处理 + 逻辑共享**。
</Callout>

### 14.3 Buffer、Cache 与 SPOOLing 对比

| 技术 | 主要中间存储位置 | 核心目的 | 典型例子 |
| --- | --- | --- | --- |
| Buffer | 主存 | 匹配速度、平滑数据流 | 单缓冲、双缓冲 |
| Cache | 主存 | 保存副本，减少慢速层次重复访问 | 磁盘高速缓存 |
| SPOOLing | 主要使用磁盘 | 排队、模拟脱机 I/O、虚拟化独占设备 | 打印队列 |

一句话区分：

```text
Buffer：速度不同，先垫一下
Cache：以后可能再用，先留副本
SPOOLing：独占设备忙，先把作业排到磁盘队列
```
