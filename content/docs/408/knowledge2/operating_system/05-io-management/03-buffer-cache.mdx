**缓冲（buffering）**&#x2060;的核心任务是协调“生产数据”和“消费数据”双方的速度、粒度和时序差异。

> **真题标签**
>
> 缓冲区选择题：2009 年第 1 题、2011 年第 31 题、2013 年第 27 题、2015 年第 28 题、2018 年第 31 题、2022 年第 30 题、2026 年第 32 题。

## 5.3.1 为什么需要缓冲

主存中的缓冲区可以用于：

- 缓和高速 CPU 与低速设备之间的速度差；
- 让 I/O 与计算发生重叠；
- 把“少量多次”转成“较大批量”；
- 减少中断/系统调用等固定开销；
- 暂存突发数据，吸收短时流量波动。

缓冲不是永久存储，其内容通常只是数据流中的临时状态。

## 5.3.2 Buffer 与 Cache 的区别

| 技术 | 主要目的 | 数据是否通常是已有副本 | 典型例子 |
| --- | --- | :---: | --- |
| Buffer | 匹配生产/消费速度与时序 | 不一定 | 键盘输入缓冲、双缓冲 |
| Cache | 利用局部性减少慢速访问 | 通常是 | 页缓存、磁盘高速缓存 |

### 磁盘高速缓存

磁盘高速缓存把近期磁盘块的副本保留在主存中。

因此可以记：

> **逻辑上缓存磁盘数据，物理上驻留主存。**

若再次命中，系统可直接从内存得到数据，避免真实磁盘 I/O。

## 5.3.3 单缓冲

只有一个系统缓冲区：

```text
设备 → Buffer → 用户处理
```

一个典型周期：

1. 设备填充缓冲区；
2. 系统把数据交给用户工作区；
3. 用户处理；
4. 缓冲区重新可用后再接收后续数据。

如果设备填一块需 $T$，缓冲区复制到用户区需 $M$，CPU 处理一块需 $C$，在经典简化模型中，稳态每块常按：

$$
T_{single}\approx \max(T,C)+M
$$

理解重点不是死背公式，而是画出：**输入与处理能否重叠，复制阶段是否占用同一缓冲区。**

## 5.3.4 双缓冲

两个缓冲区交替工作：

```text
阶段 A：设备 → B1      CPU 处理 B2
阶段 B：设备 → B2      CPU 处理 B1
```

这样，设备填充一个缓冲区时，CPU 可以处理另一个缓冲区的数据。

在同一经典模型下，稳态每块常近似为：

$$
T_{double}\approx \max(T,M+C)
$$

<Callout type="warn" title="缓冲时间公式必须服从题设">
不同教材会对“复制是否可与设备输入并行、用户处理何时开始、最后一块是否计排空时间”作不同假设。综合题优先画时间线，再套公式。
</Callout>

## 5.3.5 循环缓冲

循环缓冲由多个缓冲单元构成，逻辑上首尾相接：

```text
B0 → B1 → B2 → ... → Bn-1
↑                   ↓
└───────────────────┘
```

常有：

- 读指针；
- 写指针；
- 空/满状态或计数器。

它适合连续数据流，例如音频、网络收包、设备驱动环形队列。

> **易错点**
>
> “循环”不等于“容量无限”。空间永远是有限的；生产速度长期高于消费速度时，最终必须阻塞、丢弃或覆盖数据，具体由策略决定。

## 5.3.6 缓冲池

缓冲池由系统统一维护一组可复用缓冲块：

```text
空闲队列 → 分配给 I/O → 装满/使用 → 回收到池
```

优点：

- 多进程共享，空间利用率更高；
- 不需要给每个进程永久固定大量缓冲；
- 可结合空闲队列、设备队列统一管理。

若没有可用缓冲，申请者可能阻塞。

## 5.3.7 提前读与延迟写

### 提前读（read-ahead）

根据空间局部性，在读当前块时预取后续可能使用的块。

若预测正确：

> 未来访问可能直接命中缓存，隐藏一部分磁盘延迟。

### 延迟写（write-behind / delayed write）

写操作先更新内存缓存并标记为脏，之后再批量刷新到外存。

优点：

- 可合并多次写；
- 减少真实设备访问次数；
- 让用户写调用更快返回。

代价：

- 掉电/崩溃前尚未持久化的数据可能丢失；
- 必须维护脏状态和刷写策略。

> **真题标签**
>
> 2018 年第 31 题把提前读、连续分配、延迟写和磁盘高速缓存放在一起考察文件访问性能优化。

## 5.3.8 缓冲解决的是“流水线”问题

可以把 I/O 看成生产者—消费者：

```text
设备生产数据
     ↓
缓冲区
     ↓
CPU / 进程消费数据
```

当生产和消费可以并行时，总吞吐率最终受较慢阶段限制，而不是所有阶段时间简单相加。

因此：

> 缓冲的价值常常不在“某一步更快”，而在于**把原本串行的两个阶段重叠起来**。
