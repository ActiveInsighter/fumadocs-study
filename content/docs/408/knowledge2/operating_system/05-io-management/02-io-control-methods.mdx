I/O 控制方式解决的是：**CPU、主存、I/O 接口和外设到底怎样协作，谁负责等待，谁负责搬数据，谁负责通知完成。**

## 5.2.1 程序查询方式

程序查询又称轮询（polling）。CPU 启动设备后反复读取状态：

```text
CPU 下发命令
   ↓
查询状态寄存器
   ↓
未就绪 ─────→ 继续查询
   ↓
已就绪
   ↓
CPU 参与数据传送
```

特点：

- 实现简单；
- CPU 与设备高度同步；
- 等待期间发生**忙等**；
- CPU 利用率低。

如果设备很慢，CPU 可能大量时间都浪费在“好了吗？”这一查询上。

## 5.2.2 程序中断方式

中断方式把“反复问设备”改成“设备好了主动通知”。

典型过程：

1. CPU 启动 I/O；
2. 当前进程若需要等待结果，可以阻塞；
3. CPU 转去运行其他任务；
4. 设备准备好数据或完成操作后发出中断；
5. CPU 响应中断并执行处理程序；
6. 完成必要的数据/状态处理；
7. 唤醒等待进程。

因此中断方式消除了长时间轮询，但：

> **CPU 仍要执行中断服务，并通常仍参与少量数据搬运。**

若每传一个字节就中断一次，中断开销仍可能很大。

## 5.2.3 DMA 方式

DMA（Direct Memory Access）允许设备与主存之间进行成批数据交换，而不要求 CPU 逐字搬运。

CPU 在开始前通常设置：

- 主存起始地址；
- 传输方向；
- 传输长度；
- 设备/通道信息。

之后：

```text
设备 ⇄ DMA 控制器 ⇄ 主存
          ↑
       总线仲裁
```

整批数据完成后，DMA 通常通过中断通知 CPU。

> **真题标签**
>
> 2023 年 I/O 方式选择题明确考察：DMA 的数据传送过程由 DMA 硬件完成，而不是 CPU 执行所谓“DMA 传送程序”逐字搬运。

### DMA 中 CPU 仍做什么

CPU 仍需要：

1. 初始化 DMA；
2. 设置地址、方向和长度；
3. 必要时处理一致性与保护；
4. 接收完成中断；
5. 执行后续逻辑。

所以：

> DMA 是“显著减少 CPU 参与”，不是“CPU 永远完全不参与”。

## 5.2.4 DMA 与总线竞争

DMA 访问主存时要占用系统总线/内存带宽，因此 CPU 与 DMA 可能竞争主存访问。

经典方式包括：

- 停止 CPU 访存后由 DMA 连续传送；
- **周期挪用（cycle stealing）**：DMA 临时占用一个或若干总线周期；
- 交替/透明方式：利用 CPU 不访存的时隙。

操作系统题若只问宏观控制方式，重点仍是：

> **DMA 直接在设备与主存之间成批传送。**

## 5.2.5 通道控制方式

I/O 通道可以看作功能更强的专用 I/O 处理部件。

与 DMA 相比，通道不仅能搬数据，还能执行一组**通道命令/通道程序**，独立完成更复杂的 I/O 控制序列。

典型逻辑：

```text
CPU 给出 I/O 任务
      ↓
通道执行通道程序
      ↓
控制一个或多个设备完成 I/O
      ↓
任务完成后中断 CPU
```

从“CPU 脱离 I/O 细节”的程度看，一般可粗略理解：

```text
程序查询 < 中断 < DMA < 通道
```

但这是宏观参与程度，不表示任何系统都必须按四档实现。

## 5.2.6 四种方式对比

| 方式 | 等待时 CPU 忙等 | 数据搬运主要责任者 | 典型粒度 | 完成通知 |
| --- | :---: | --- | --- | --- |
| 程序查询 | ✅ | CPU | 字/字节 | CPU 自己查询发现 |
| 程序中断 | ❌ | CPU + 接口 | 字/少量数据 | 设备中断 |
| DMA | ❌ | DMA 控制器 | 数据块 | DMA 完成中断 |
| 通道 | ❌ | I/O 通道 | 一组 I/O 操作 | 通道完成中断 |

## 5.2.7 一次输入请求的进程状态变化

假设进程执行阻塞式 `read()`，数据尚未就绪：

```text
运行态
  ↓ read()
阻塞态
  ↓ 设备完成、中断处理、条件满足
就绪态
  ↓ 被调度
运行态
```

注意：

- **中断处理程序运行**不等于“原进程立即运行”；
- 中断处理后只是可能把原进程从阻塞态移入就绪队列；
- 是否马上获得 CPU 仍由调度器决定。

## 5.2.8 I/O 定量题统一模型

分析一道查询/中断/DMA 综合题时，建议固定按四步：

1. 一次传输单位是多少；
2. 设备准备该单位需要多久；
3. CPU 每次查询/中断/DMA 初始化或收尾要多少时间；
4. 一共发生多少次这种开销。

若设备传输率为 $R$ B/s，一次传输 $B$ 字节，纯数据时间为：

$$
T_{data}=\frac{B}{R}
$$

若每个数据单位产生一次中断，共 $n$ 次，每次中断 CPU 开销为 $t_i$：

$$
T_{cpu,interrupt}=n t_i
$$

DMA 若每块只在开始/结束付固定 CPU 开销，则块越大，CPU 分摊开销通常越低。

<Callout type="warn" title="定量题不要擅自叠加">
题目若出现总线竞争、DMA 周期挪用、设备与 CPU 并行、多个设备同时工作，应严格按题设画时间线，不能把所有时间无条件相加。
</Callout>

## 5.2.9 三句速记

> **查询：CPU 等设备。**
>
> **中断：设备好了再找 CPU。**
>
> **DMA：数据成批自己搬，搬完再通知 CPU。**
