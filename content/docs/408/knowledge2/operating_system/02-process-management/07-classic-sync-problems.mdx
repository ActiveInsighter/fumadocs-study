经典同步问题的价值不在于代码本身，而在于它们分别代表三种高频并发约束：

1. **生产者—消费者**：资源数量 + 缓冲区互斥；
2. **读者—写者**：不同角色之间的兼容关系与公平性；
3. **哲学家就餐**：多资源申请与循环等待。

## 2.7.1 生产者—消费者：三个信号量各司其职

设有界缓冲区容量为 $N$：

```c
semaphore empty = N;
semaphore full  = 0;
semaphore mutex = 1;
```

含义：

- `empty`：当前空槽数量；
- `full`：当前已有产品数量；
- `mutex`：缓冲区数据结构的互斥访问许可。

### 生产者

```c
producer() {
    while (1) {
        item = produce();

        P(empty);
        P(mutex);
        put(item);
        V(mutex);
        V(full);
    }
}
```

### 消费者

```c
consumer() {
    while (1) {
        P(full);
        P(mutex);
        item = get();
        V(mutex);
        V(empty);

        consume(item);
    }
}
```

### 两条不变量

缓冲区任一时刻都有：

$$
empty+full=N
$$

并且进入真正共享缓冲区操作的执行流最多 1 个。

### 为什么先 P 资源再 P mutex

若生产者写成：

```text
P(mutex)
P(empty)
```

当缓冲区满时，它可能拿着 `mutex` 等 `empty`；消费者又必须获得 `mutex` 才能取走产品并产生 `empty`，导致死锁。

> **真题标签**
>
> 2009 年综合题就是生产者与两个分类消费者共享有限缓冲区的典型变式，核心仍是“空槽计数 + 分类产品计数 + 缓冲区互斥”。

## 2.7.2 生产者—消费者的变式怎么改

遇到“不同类型产品由不同消费者取走”，不要重新发明模板，只需把 `full` 细分：

```text
empty = N
odd   = 0
 even = 0
mutex = 1
```

生产者根据产品类型：

```text
put(x)
if x is odd:  V(odd)
else:         V(even)
```

奇数消费者只 `P(odd)`，偶数消费者只 `P(even)`。

核心不变量变为：

$$
empty+odd+even=N
$$

## 2.7.3 读者—写者：先列兼容矩阵

基本约束：

- 读者与读者可并发；
- 写者与写者互斥；
- 读者与写者互斥。

| 当前访问者 | 新读者 | 新写者 |
| --- | --- | --- |
| 无 | 可进入 | 可进入 |
| 读者 | 可并发 | 等待 |
| 写者 | 等待 | 等待 |

问题难点不是“会不会互斥”，而是：

> **等待的读者和写者谁先获得机会？**

这决定读者优先、写者优先或公平方案。

## 2.7.4 读者优先

设：

```c
int read_count = 0;
semaphore mutex = 1;  // 保护 read_count
semaphore wrt   = 1;  // 控制共享对象
```

读者：

```c
reader() {
    while (1) {
        P(mutex);
        read_count++;
        if (read_count == 1)
            P(wrt);
        V(mutex);

        read();

        P(mutex);
        read_count--;
        if (read_count == 0)
            V(wrt);
        V(mutex);
    }
}
```

写者：

```c
writer() {
    while (1) {
        P(wrt);
        write();
        V(wrt);
    }
}
```

一句话抓住结构：

> **第一个读者负责挡住写者，最后一个读者负责放行写者。**

风险：若读者持续到来，写者可能饥饿。

## 2.7.5 写者优先

目标：一旦已经有写者在等待，就不允许后来读者无限插队。

可增加：

- `write_count`：等待/活动写者数量；
- `write_mutex`：保护 `write_count`；
- `readTry`：第一个写者关闭“新读者入口”。

一个典型骨架是：

```c
int read_count = 0;
int write_count = 0;
semaphore wrt = 1;
semaphore mutex = 1;
semaphore write_mutex = 1;
semaphore readTry = 1;

writer() {
    while (1) {
        P(write_mutex);
        write_count++;
        if (write_count == 1)
            P(readTry);      // 第一个写者挡住后来读者
        V(write_mutex);

        P(wrt);
        write();
        V(wrt);

        P(write_mutex);
        write_count--;
        if (write_count == 0)
            V(readTry);      // 最后一个写者重新开放读入口
        V(write_mutex);
    }
}
```

读者进入读者计数区前先经过 `readTry`；这样已有读者仍可完成退出，但新读者不会在写者排队后源源不断插入。

核心逻辑：

```text
第一个写者到来 → P(readTry)
最后一个写者离开 → V(readTry)
```

代价：若写者持续到来，可能反过来让读者饥饿。

## 2.7.6 公平读写

可增加统一排队门闩：

```c
semaphore queue = 1;
```

读者在进入“读者计数/首读者申请 `wrt`”阶段前先经过 `queue`；写者也先经过 `queue`，再申请 `wrt`。一个简化骨架：

```c
reader() {
    P(queue);
    P(mutex);
    read_count++;
    if (read_count == 1)
        P(wrt);
    V(mutex);
    V(queue);

    read();

    P(mutex);
    read_count--;
    if (read_count == 0)
        V(wrt);
    V(mutex);
}

writer() {
    P(queue);
    P(wrt);
    V(queue);

    write();

    V(wrt);
}
```

核心不是死记变量名，而是：

> **后来者不能无限插到已经排队的另一类进程之前。**

公平策略通常牺牲一部分“读者批量并发的自由插入”，换取更好的无饥饿性质。

## 2.7.7 哲学家就餐：为什么会死锁

$N$ 位哲学家围成一圈，每人吃饭要同时获得左右两把叉子。

若所有人都执行：

```text
拿左叉
等待右叉
```

可能形成：

```text
P0 持有左叉，等 P1 的叉
P1 持有左叉，等 P2 的叉
...
Pn 持有左叉，等 P0 的叉
```

形成完整环路：

$$
P_0\rightarrow P_1\rightarrow\cdots\rightarrow P_{N-1}\rightarrow P_0
$$

这同时展示了死锁的“占有并等待 + 非抢占 + 循环等待”。

## 2.7.8 哲学家问题的常见破解方式

### 方法 1：破坏统一申请顺序

例如前 $N-1$ 人先左后右，最后一人先右后左：

```c
if (i != N - 1) {
    first = left;
    second = right;
} else {
    first = right;
    second = left;
}

P(fork[first]);
P(fork[second]);
eat();
V(fork[second]);
V(fork[first]);
```

它破坏原先完整的环形等待方向。

### 方法 2：最多允许 $N-1$ 人同时尝试取叉

增加：

```c
semaphore room = N - 1;
```

先获得进入许可，再尝试取两把叉。这样不可能让所有人同时各占一把形成完整环。

### 方法 3：按全局资源编号申请

给叉子统一编号，所有哲学家始终按编号从小到大申请，破坏循环等待条件。

### 方法 4：一次性检查并获得两把

通过更高层原子协议/管程，使“只拿到一把然后等待另一把”的状态不出现，本质上破坏“占有并等待”。

## 2.7.9 三类经典问题放在一起看

| 问题 | 核心资源模型 | 最关键技巧 | 最常见错误 |
| --- | --- | --- | --- |
| 生产者—消费者 | 有界槽位 + 共享缓冲区 | `empty/full/mutex` | P 顺序错误导致死锁 |
| 读者—写者 | 读读兼容、读写/写写冲突 | 首读者/末读者或公平门闩 | 忽略 `read_count` 自身互斥、饥饿 |
| 哲学家就餐 | 每人要多个互斥资源 | 破坏死锁必要条件 | 所有人同顺序拿资源形成环 |
