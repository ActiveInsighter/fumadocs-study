进程管理的核心不是背术语，而是同时回答四个问题：

1. **资源属于谁？**——进程；
2. **CPU 实际调度谁？**——可运行线程；
3. **当前执行到哪里？**——PC、寄存器、栈等执行现场；
4. **暂时不能运行时去了哪里？**——就绪队列或各种等待队列。

> **真题标签**
>
> 进程/线程、PCB 与状态转换长期为选择题高频；典型年份包括 2010、2011、2012、2014、2015、2018、2019、2021、2022、2023、2024。2024 年综合题还涉及进程控制信息。

## 2.1.1 进程：正在执行的程序实例

**程序（Program）**&#x2060;是静态的代码与数据集合；**进程（Process）**&#x2060;是程序的一次动态执行过程。

| 维度 | 程序 | 进程 |
| --- | --- | --- |
| 本质 | 静态指令/数据 | 动态执行实例 |
| 生命周期 | 作为文件长期存在 | 创建、运行、阻塞、终止 |
| 是否拥有运行现场 | 否 | 是 |
| 同一程序能否对应多个实例 | 不适用 | 可以 |

408 中最值得牢牢记住的是：

> **进程是资源分配和保护的基本单位；线程是处理机调度和执行的基本单位。**

更准确地说，进程建立了一个**资源容器与保护边界**：虚拟地址空间、打开文件、权限等通常按进程组织；线程则是容器内部真正向前执行的指令流。

<Callout type="warn" title="高频易错">
“进程 = 程序”错误；“进程就是正在 CPU 上运行的程序”也不严谨，因为处于就绪态或阻塞态的进程同样存在。
</Callout>

## 2.1.2 PCB：操作系统眼中的进程

操作系统使用 **PCB（Process Control Block，进程控制块）**&#x2060;记录进程管理信息。PCB 可以理解为进程在内核中的“管理档案”。

典型字段可按四类记忆：

| 类别 | 典型内容 | 用途 |
| --- | --- | --- |
| 标识信息 | PID、UID 等 | 区分进程与权限主体 |
| 调度/控制信息 | 状态、优先级、队列指针 | 调度与进程控制 |
| 处理机现场 | PC、通用寄存器、PSW 等 | 暂停后继续执行 |
| 资源信息 | 地址空间、页表、打开文件等 | 资源拥有与回收 |

传统单线程进程只有一个执行流，因此执行现场可直接与 PCB 联系起来。引入多线程以后，每个线程都要独立保存：

- 程序计数器；
- 寄存器；
- 栈；
- 线程状态；
- 调度信息。

这部分通常由 **TCB（Thread Control Block）**&#x2060;维护。

> **记忆口径**
>
> **PCB 管进程级资源与保护边界，TCB 管线程级执行现场。**

## 2.1.3 进程的创建、替换与回收

在 UNIX/Linux 语境下，最常见的三组操作是 `fork`、`exec`、`wait`。

### `fork()`：创建子进程

成功时：

- 父进程得到子进程 PID（大于 0）；
- 子进程得到返回值 0；
- 二者从 `fork()` 返回位置继续执行。

逻辑上，子进程得到父进程地址空间的一份副本；现代系统通常通过 **写时复制（Copy On Write，COW）**&#x2060;优化：

```text
fork 后：父、子暂时映射同一物理页（只读/COW 标记）
                ↓
某一方尝试写该页
                ↓
触发异常 → 分配新页 → 复制 → 修改映射 → 再写
```

因此：

> **父子进程的虚拟地址空间逻辑独立，但创建初期可暂时共享同一批物理页。**

### `exec()`：替换当前程序映像

`exec()` **不会创建新进程**。成功执行后：

- 当前进程身份（如 PID）通常继续存在；
- 原代码段、数据段、堆、栈等程序映像被新程序替换；
- 不会再从成功的 `exec()` 调用之后返回原程序继续运行。

### `wait()` / `waitpid()`：等待并回收子进程

父进程通过 `wait` 系列接口取得子进程退出信息并完成回收。

三者可以压缩为：

```text
fork：复制出一个新进程
exec：把“我”换成另一个程序
wait：父进程等待/回收已经结束的子进程
```

## 2.1.4 僵尸进程与孤儿进程

**僵尸进程（Zombie）**：子进程已经终止，但父进程尚未读取其退出状态。

- 不再占用 CPU；
- 大部分资源已释放；
- 内核仍保留 PID、退出状态等少量信息，供父进程回收。

**孤儿进程（Orphan）**：父进程先于仍在运行的子进程终止。

- 子进程通常仍可正常运行；
- 会被 `init`、`systemd` 或其他子进程收割者接管。

| 对比 | 僵尸进程 | 孤儿进程 |
| --- | --- | --- |
| 子进程是否已终止 | 是 | 通常否 |
| 原父进程 | 仍存在但未回收 | 已终止 |
| 是否继续执行 | 否 | 可能 |
| 关键问题 | 等待回收退出信息 | 父子关系重新托管 |

## 2.1.5 线程：进程内部的执行流

一个进程至少包含一个线程。多线程进程中的线程共享大部分进程级资源，但每个线程必须有独立执行现场。

### 同一进程线程共享什么

通常共享：

- 虚拟地址空间；
- 代码段；
- 全局变量、静态变量；
- 堆；
- 打开的文件；
- 其他进程级资源。

### 每个线程独有什么

通常独有：

- 线程标识；
- 程序计数器；
- 寄存器组；
- 栈；
- 线程状态；
- 调度信息。

> **高频陷阱**
>
> “每个线程有独立栈”指每个线程在同一进程虚拟地址空间中拥有自己的栈区域，并不意味着像进程那样存在硬件级地址隔离。

## 2.1.6 进程与线程对比

| 维度 | 进程 | 线程 |
| --- | --- | --- |
| 核心作用 | 资源拥有与保护 | 执行与调度 |
| 地址空间 | 不同进程通常独立 | 同进程线程共享 |
| PC/寄存器/栈 | 与执行线程相关 | 每个线程独立 |
| 通信 | 往往依赖 IPC | 可直接访问共享内存 |
| 创建/切换开销 | 通常较大 | 同进程线程通常较小 |
| 隔离性 | 较强 | 较弱 |
| 多核并行 | 取决于可运行线程 | 多线程可分布到不同核心 |

一句话压缩：

> **进程是资源容器，线程是执行实体。**

## 2.1.7 五种基本状态

典型五状态模型：

1. **创建态（New）**：正在建立 PCB、地址空间等；
2. **就绪态（Ready）**：除 CPU 外，继续执行所需条件基本具备；
3. **运行态（Running）**：正在处理机上执行；
4. **阻塞态（Blocked / Waiting）**：等待事件、I/O、锁、消息等；
5. **终止态（Terminated）**：已经结束，等待清理或回收。

最重要的区分：

> **就绪态只缺 CPU；阻塞态即使立刻给 CPU 也不能继续。**

## 2.1.8 状态转换：先找“为什么不能继续”

### 就绪 → 运行

调度器从就绪队列选中该执行实体并分配 CPU。

### 运行 → 就绪

进程仍具备运行条件，只是暂时失去 CPU。常见原因：

- 时间片耗尽；
- 被更高优先级任务抢占；
- 主动让出 CPU。

### 运行 → 阻塞

当前执行流必须等待某个事件：

- 发起阻塞 I/O；
- 等待锁、信号量或条件变量；
- 等待消息/信号；
- `sleep()`；
- `wait()`；
- 缺页后等待页面调入。

### 阻塞 → 就绪

等待事件发生后，执行流只是重新获得“可运行资格”：

- I/O 完成；
- 资源可用；
- 消息到达；
- 条件成立；
- 定时器到期。

> **真题标签**
>
> 状态转换题最常见陷阱是把“阻塞事件完成”写成“阻塞 → 运行”。正确的常规转换是 **阻塞 → 就绪**，之后还需要接受调度。

<Callout type="warn" title="状态题三问法">
遇到状态转换先问：①它现在还能不能继续？②只是没有 CPU，还是在等事件？③事件完成以后是否还要排队等 CPU？用这三问比死背箭头更稳。
</Callout>


## 2.1.9 进程虚拟地址空间：哪些区域属于谁

典型用户进程的虚拟地址空间可按用途理解为：

| 区域 | 典型内容 | 常见属性 |
| --- | --- | --- |
| 代码区 `.text` | 机器指令 | 常只读、可执行 |
| 已初始化数据区 `.data` | 已显式初始化的全局/静态变量 | 可读写 |
| BSS | 未显式初始化或零初始化的全局/静态变量 | 装入时按规则置零 |
| 堆 Heap | `malloc/new` 等动态对象 | 运行时扩展 |
| 内存映射区 mmap | 动态库、文件映射、匿名映射、共享内存 | 由映射属性决定 |
| 栈 Stack | 函数调用现场、局部变量等 | 每个线程有自己的栈区域 |
| 内核空间 | 内核代码/数据映射等 | 用户态不能直接访问 |

典型布局里堆常向高地址方向增长、栈常向低地址方向增长，但这只是常见实现布局，做题时应以题图/体系结构说明为准。

### 函数调用与线程栈

每个线程都需要独立栈，以保存自己的调用链。一个典型栈帧可能包含：

- 返回地址；
- 保存的寄存器；
- 局部变量；
- 参数或参数保存区；
- 上一栈帧相关信息。

因此同一进程的两个线程虽然共享代码、全局变量和堆，却不能共享“当前函数调用现场”。这也是“每个线程独立 PC、寄存器、栈”的原因。

> **交叉复习**
>
> 地址空间布局与第 1 章“链接、装入与进程地址空间”相连；函数栈帧与组成原理的 `call/ret`、寄存器保存约定相连。这里重点放在“哪些资源按进程共享、哪些现场按线程独立”。

## 2.1.10 进程控制与队列：状态变化不是改一个标签

操作系统进行进程/线程控制时，通常不仅修改 `state` 字段，还要把控制块在不同队列/结构之间移动。

典型动作：

- **创建**：分配标识与控制块，建立必要资源，最终进入就绪集合；
- **阻塞**：保存现场，把当前执行实体从运行状态放入某个事件/资源等待队列；
- **唤醒**：等待条件满足，从等待队列移入就绪队列；
- **抢占/时间片到**：保存现场，从运行状态回到就绪队列；
- **终止**：记录退出信息，释放/回收资源，最终销毁控制结构。

所以看到“阻塞/唤醒”时应联想到：

```text
阻塞：Running → 等待队列
唤醒：等待队列 → Ready Queue
```

而不是把状态转换理解成一个脱离队列管理的抽象箭头。
