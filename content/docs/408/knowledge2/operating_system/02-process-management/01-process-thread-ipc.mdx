## 一、进程与线程

> **复习优先级：高**
>
> **真题考察：**
> 选择题：2011 年第 25、32 题，2012 年第 31 题，2018 年第 25 题，2024 年第 28 题等。

### 1. 进程

在多道程序环境下，多个程序可以并发执行。为了描述、管理和控制这些并发执行的程序，操作系统引入了 **进程（Process）**。

最重要的两个结论是：

> **进程是系统资源分配和保护的基本单位。**

> **线程是处理机调度和执行的基本单位。**

进程解决的核心问题是：

> **资源归谁所有？**

线程解决的核心问题是：

> **究竟是哪一条执行流在使用 CPU？**

不同进程通常拥有相互独立的虚拟地址空间、文件描述符集合、权限和其他系统资源；同一个进程中的多个线程则共享大部分进程级资源。

---

### 2. 进程与程序

程序是**静态的**，进程是**动态的**。

* **程序**

  * 是一组指令和数据的静态集合。
  * 通常存储在磁盘等持久化介质中。
  * 程序本身不会主动执行。
  * 同一个程序可以被运行多次。

* **进程**

  * 是程序的一次执行过程。
  * 程序被装入并开始执行后，操作系统为它创建相应的进程。
  * 具有创建、就绪、运行、阻塞、终止等生命周期状态。
  * 同一个程序运行多次，通常会形成多个不同进程。

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-001.svg" alt={"Disk program CPU Memory process stack code static data heap Loading: 读取磁盘中的程序并将其加载到进程的地址空间中 code static data"} />

<Callout type="warn" title="易错点">
“进程 = 程序”是错误的。程序只是磁盘中的静态代码和数据，而进程还包括运行状态、资源、地址空间、CPU 现场等动态信息。
</Callout>

### 3. 进程控制块 PCB

> **真题考察：**
> 选择题：2010 年第 24 题、2020 年第 29 题、2021 年第 24 题、2024 年第 24 题。
> 解答题：2024 年第 46 题。

操作系统使用 **进程控制块（PCB，Process Control Block）** 管理进程。

可以把 PCB 理解成操作系统为每个进程保存的一份“管理档案”。

进程存在期间，对应的 PCB 一般始终存在于内核管理的数据结构中。

| 信息类别    | 典型内容                 |
| ------- | -------------------- |
| 进程标识信息  | PID、UID 等            |
| 进程控制信息  | 进程状态、优先级、调度信息        |
| 处理机状态信息 | PC、通用寄存器、PSW 等       |
| 资源信息    | 地址空间、页表、打开文件、内存管理信息等 |

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-002.svg" alt={"进程控制块 PCB PCB（进程控制块） 进程标识信息 PID（进程标识符）· UID（用户标识符） 进程控制信息 进程状态 · 进程优先级 处理机状态信息 PC · 通用寄存器 · PSW（程序状态字） 资源信息 打开的文件 · 内存指针 · 其他资源 常驻内存，随进程生命周期存在 ① 进程创建与终止 • 创建时，OS 为进程新建 PCB • PCB 常驻内存，可随时存取 • 进程结束时，PCB 被删除 PCB 是进程存在的唯一标志 ② 进程调度 • OS 读取 PCB 中"} />

各部分作用：

* **标识信息**：区分不同进程。
* **控制信息**：供调度器和操作系统进行进程管理。
* **处理机现场**：保存进程暂停执行时的 CPU 状态，使其之后可以从原位置继续运行。
* **资源信息**：记录进程拥有的虚拟地址空间、文件等系统资源。

在传统的单线程进程模型中，一个进程只有一个执行流，因此程序计数器、寄存器等现场可以直接与 PCB 关联。

引入多线程后，一个进程中可能存在多个执行流，每个线程都需要分别保存自己的：

* 程序计数器；
* 寄存器；
* 栈；
* 线程状态；
* 调度信息。

这些线程级信息通常由 **TCB（Thread Control Block，线程控制块）** 管理。

因此可以记为：

> **PCB 管资源，TCB 管执行。**

PCB 主要参与：

1. 进程创建；
2. 进程资源管理；
3. 进程或线程调度相关状态管理；
4. 上下文保存与恢复；
5. 进程终止和资源回收。

### 4. 父进程与子进程

在 UNIX/Linux 中，父进程可以通过 `fork()` 创建子进程。

```c
pid_t fork(void);
```

调用成功后：

* 父进程中返回 **子进程 PID**，返回值大于 `0`；
* 子进程中返回 `0`；
* 创建失败时，父进程中返回 `-1`，且不会产生子进程。

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-003.svg" alt={"图示"} />

`fork()` 成功后，父进程和子进程都会从 `fork()` 返回位置继续执行，但是二者得到的返回值不同。

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-004.svg" alt={"图示"} />

#### 4.1 fork 与写时复制

逻辑上，子进程拥有父进程地址空间的一份副本，包括：

* 代码；
* 数据；
* 堆；
* 栈。

但是现代操作系统通常通过 **写时复制（Copy On Write，COW）** 优化 `fork()`。

刚创建子进程时，父子进程可以暂时共享相同的物理页；只有其中一方试图修改某一页时，操作系统才真正复制该页。

因此：

> **父子进程的虚拟地址空间逻辑独立，但物理页可以暂时共享。**

子进程还会继承父进程的一些资源，例如打开的文件描述符。

---

#### 4.2 fork、exec 与 wait

三者要区分清楚：

| 操作                     | 作用               |
| ---------------------- | ---------------- |
| `fork()`               | 创建一个新的子进程        |
| `exec()`               | 用新程序替换当前进程的程序映像  |
| `wait()` / `waitpid()` | 父进程等待并回收已经结束的子进程 |

`exec()` **不会创建新进程**。

成功执行 `exec()` 后：

* 当前进程 PID 等身份通常保留；
* 原来的代码段、数据段、堆、栈等程序映像被新程序替换；
* 原程序不会从 `exec()` 后面继续运行。

---

#### 4.3 僵尸进程与孤儿进程

**僵尸进程（Zombie Process）**

子进程已经终止，但父进程还没有通过 `wait()` 或 `waitpid()` 获取其退出状态。

此时：

* 子进程不再执行；
* 用户地址空间和大部分资源已经释放；
* 内核仍需保存 PID、退出状态等少量信息。

**孤儿进程（Orphan Process）**

父进程在子进程结束之前先终止。

孤儿进程：

* 通常仍然正常运行；
* 会由 `init`、`systemd` 或其他子进程收割者接管；
* 以后由新的父进程负责回收。

| 项目       | 僵尸进程                         | 孤儿进程     |
| -------- | ---------------------------- | -------- |
| 是否已经终止   | 是                            | 通常否      |
| 原父进程     | 仍存在但未回收子进程                   | 已终止      |
| 是否占用 CPU | 否                            | 可能       |
| 保留资源     | PID、退出状态等少量内核信息              | 正常运行所需资源 |
| 处理方式     | 父进程调用 `wait()` / `waitpid()` | 由新的父进程接管 |

## 二、线程

### 1. 线程的基本概念

**线程是处理机调度和执行的基本单位。**

一个进程至少包含一个线程，即通常所说的主线程。

主线程还可以创建更多线程。

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-005.svg" alt={"Code Data Files Stack Registers Processes Code Data Files Stack Multi-Threaded Process Register Stack Register Stack Register T1 T2 T3 T1 T2 T3"} />

同一进程中的线程共享：

* 虚拟地址空间；
* 代码段；
* 全局变量；
* 静态变量；
* 堆；
* 打开的文件；
* 其他进程级资源。

每个线程独有：

* 线程标识符；
* 程序计数器；
* 寄存器；
* 栈；
* 线程状态；
* 调度信息。

<Callout type="warn" title="高频易错">
“每个线程拥有独立的栈”并不意味着线程之间存在进程级地址隔离。线程栈仍位于同一个进程的虚拟地址空间中，一个线程如果获得另一个线程栈内对象的地址，原则上仍可能访问它。
</Callout>

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-006.svg" alt={"Stack Heap Program + Data Stack Heap Program + Data Stack Stack 单线程的进程 包含多个线程的进程 进程的 内存空间"} />

---

### 2. 单线程进程

单线程进程只有一个执行流。

特点：

* 结构简单；
* 调试相对容易；
* 不存在进程内部多个线程之间的数据竞争；
* 唯一线程阻塞时，进程内部没有其他线程继续执行；
* 任一时刻最多利用一个逻辑核心执行该进程的线程。

---

### 3. 多线程进程

多线程进程拥有多个执行流。

优点：

* 线程之间通过共享地址空间通信，效率高；
* 多个线程可以被调度到不同逻辑核心上并行执行；
* 一个线程阻塞时，其他线程仍可继续运行；
* 可以提高 CPU 利用率和程序响应性。

代价：

* 共享数据可能产生竞态条件；
* 需要互斥锁、信号量等同步机制；
* 隔离性弱于不同进程；
* 一个线程发生严重错误可能影响整个进程。

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-007.svg" alt={"进程虚拟地址空间布局（32 位 Linux 典型视图） 内核空间 (Kernel) 所有进程共享，用户态不可访问 栈 (Stack) 函数调用帧、局部变量 向下增长 ↓ ，ESP/SP 指向栈顶 未分配空间 内存映射区 (mmap) 动态库 .so / 文件映射 匿名映射、共享内存 未分配空间 堆 (Heap) malloc / new 动态分配 向上增长 ↑ ，brk 移动边界 未初始化数据 (BSS) 未赋初值的全局/静态变量 已初始化数据 (Data) 带初值的全局/静"} />

---

### 4. PCB 与 TCB

多线程环境下：

* **PCB**：描述进程级资源和保护边界；
* **TCB**：描述某个线程的执行状态。

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-008.svg" alt={"PCB与TCB的关系"} />

一个进程只有一个主要的进程级资源环境，但可以拥有多个线程，因此通常表现为：

> 一个 PCB 对应一个进程，一个进程关联多个 TCB。

---

### 5. 进程与线程对比

| 对比项目   | 进程          | 线程            |
| ------ | ----------- | ------------- |
| 主要作用   | 建立资源拥有与保护边界 | 建立执行流         |
| 基本单位   | 资源分配基本单位    | CPU 调度和执行基本单位 |
| 地址空间   | 不同进程通常独立    | 同一进程中的线程共享    |
| 文件等资源  | 由进程拥有       | 共享所属进程资源      |
| PC、寄存器 | 与执行流相关      | 每个线程独立拥有      |
| 栈      | 至少包含线程栈     | 每个线程一个栈       |
| 通信     | 通常需要 IPC    | 可直接访问共享地址空间   |
| 切换开销   | 通常较大        | 同进程线程切换通常较小   |
| 隔离性    | 较强          | 较弱            |
| 多核并行   | 依赖可运行线程     | 多个线程可以同时运行    |

一句话记忆：

> **进程是资源容器，线程是执行实体。**

## 三、进程状态

> **真题考察：**
> 选择题：2012 年第 30 题、2014 年第 26 题、2015 年第 25 题、2018 年第 27 题、2019 年第 24 题、2021 年第 24、27 题、2022 年第 28 题、2023 年第 27 题等。

### 1. 五种基本状态

1. **创建态（New）**

   * 进程正在创建。
   * PCB、资源等尚在初始化。

2. **就绪态（Ready）**

   * 除 CPU 外，已经具备继续运行所需要的条件。
   * 正在等待调度。

3. **运行态（Running）**

   * 当前正在 CPU 上执行。

4. **阻塞态（Blocked / Waiting）**

   * 正在等待某个事件、I/O 或资源。
   * 即使立即把 CPU 给它也无法继续。

5. **终止态（Terminated）**

   * 进程已经结束，等待操作系统完成后续清理。

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-009.svg" alt={"新建 就绪 运行 终止 阻塞 创建 调度 时间到 事件等待 事件发生 退出"} />

---

### 2. 状态转换

#### 就绪态 → 运行态

原因：

* 被调度器选中；
* CPU 分配给该进程或其线程。

#### 运行态 → 就绪态

常见原因：

* 时间片耗尽；
* 被更高优先级任务抢占；
* 主动让出 CPU。

关键点：

> **运行 → 就绪通常说明进程仍然具备继续运行的条件，只是暂时没有 CPU。**

#### 运行态 → 阻塞态

常见原因：

* 发出 I/O 请求；
* 等待锁、信号量或资源；
* 等待消息、信号、条件；
* `sleep()`；
* `wait()` / `waitpid()`；
* 发生缺页，需要等待页面调入。

关键点：

> **运行 → 阻塞一定与“等待某件事情发生”有关。**

#### 阻塞态 → 就绪态

常见原因：

* I/O 完成；
* 锁或资源可用；
* 消息到达；
* 条件成立；
* 定时器到期；
* 等待事件发生。

<Callout type="warn" title="408 高频陷阱">
阻塞进程等待的事件完成以后，通常是 **阻塞态 → 就绪态**，而不是直接变成运行态。它仍需要经过 CPU 调度。
</Callout>

## 四、进程虚拟地址空间

> **真题考察：**
> 解答题：2025 年第 46 题。

一个典型用户进程的虚拟地址空间通常包括：

1. **代码区（Text Segment）**

   * 存放可执行指令；
   * 通常只读。

2. **已初始化数据区（Data Segment）**

   * 存放已经显式初始化的全局变量和静态变量。

3. **未初始化数据区（BSS）**

   * 存放没有显式初始化的全局变量和静态变量；
   * 程序装入时通常初始化为零。

4. **堆（Heap）**

   * 用于运行时动态分配内存；
   * 如 `malloc` / `new`；
   * 典型布局中向高地址增长。

5. **内存映射区（mmap）**

   * 动态链接库；
   * 文件映射；
   * 匿名映射；
   * 共享内存等。

6. **栈（Stack）**

   * 保存函数栈帧；
   * 参数；
   * 局部变量；
   * 返回地址等；
   * 典型布局中向低地址增长。

7. **内核空间**

   * 用户态程序不可直接访问；
   * 由操作系统内核使用。

### 1. 函数调用与栈帧

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-011.svg" alt={"上一个栈帧 上一个 栈帧 的 EBP 局部变量 callee 的参数列表 n ~ 1 caller 返回地址 caller 栈帧 的 EBP 局部变量 下一个函数的参数列表 n ~ 1 返回地址 下一个栈帧 调用函数（caller）的栈帧 被调用函数（callee）的栈帧 高地址，栈底 低地址，栈顶 caller 的 EBP callee 的 EBP"} />

以典型 32 位 x86 栈帧为例：

* `ESP` 指向当前栈顶；
* `EBP` 常用作当前栈帧基址；
* 栈通常从高地址向低地址增长。

一个函数栈帧中可能包含：

* 上一个栈帧的基址；
* 当前函数局部变量；
* 保存的寄存器；
* 返回地址；
* 参数等。

调用函数称为 **caller**，被调用函数称为 **callee**。

执行 `call` 时需要建立调用关系并记录返回位置；执行 `ret` 时根据保存的返回地址回到 caller。

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-012.svg" alt={"main main f1 main f1 f2 main f1 main 高地址 低地址 main(f1(f2())) 时间 函数的栈帧在内存中的结构变化"} />

<Callout type="info" title="交叉理解">
函数栈帧、`call`/`ret`、程序计数器和上下文保存可以与组成原理中的子程序调用、汇编函数调用一起理解。
</Callout>

## 五、进程间通信 IPC

> **复习优先级：低到中**
>
> **真题考察：**
> 选择题：2014 年第 31 题。

不同进程通常拥有相互独立的虚拟地址空间，因此一个进程不能像同进程线程那样直接访问另一个进程的普通数据。

因此需要 **进程间通信（IPC，Inter-Process Communication）**。

常见 IPC：

* 管道；
* 共享内存；
* 消息队列；
* 信号；
* 套接字；
* 信号量。

### 1. 管道

**管道（Pipe）** 本质上是由内核维护的一块缓冲区。

数据流向：

> 写进程 → 内核管道缓冲区 → 读进程

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-015.svg" alt={"管道（Pipe）机制示意图"} />

主要特点：

* 数据一般按 FIFO 顺序读取；
* 典型管道传递的是字节流；
* 管道容量有限；
* 数据位于内核缓冲区中；
* `read()` 和 `write()` 都可能阻塞；
* 经典匿名管道通常是单向的，要双向通信可建立两个管道。

当：

* 管道为空时，读进程可能阻塞；
* 管道已满时，写进程可能阻塞。

因此它与生产者—消费者问题具有明显相似性。

#### 匿名管道

* 没有文件系统中的普通名字；
* 常用于具有亲缘关系的进程，例如父子进程。

#### 有名管道 FIFO

* 文件系统中存在名字；
* 通信进程之间不需要具有亲缘关系。

---

### 2. 共享内存

共享内存把同一组物理页映射进多个进程的虚拟地址空间。

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-016.svg" alt={"栈 共享区 堆 未初始化数据 初始化数据 代码段 内核区 用户空间 页表 进程 A 虚拟地址空间 栈 共享区 堆 未初始化数据 初始化数据 代码段 内核区 用户空间 进程 B 虚拟地址空间 页表 物理地址空间 共享内存区域 进程 A 进程 B"} />

例如：

$$
VPN_A \rightarrow PPN_{200}
$$

$$
VPN_B \rightarrow PPN_{200}
$$

进程 A 和 B 可以使用不同虚拟地址，但最终访问同一个物理页。

核心思想：

> **不同进程中的不同虚拟地址，可以映射到同一物理内存区域。**

共享内存传递大量数据时效率很高，因为通信双方可以直接访问映射后的内存，而不需要像传统消息传递那样每次都经过完整的数据复制路径。

但共享内存本身并不能解决并发访问冲突，因此通常还要配合：

* 信号量；
* 互斥锁；
* 其他同步机制。

---

### 3. 消息队列

消息队列由内核维护，以“消息”为单位传输数据。

特点：

* 支持结构化消息；
* 可以在多个进程之间传递；
* 可实现同步或异步通信；
* 某些实现支持消息类型或优先级；
* 比共享内存通常多出内核操作和复制等开销。

---

## 六、用户级线程与内核级线程

> **真题考察：**
> 选择题：2019 年第 23 题、2026 年第 25 题。

### 1. 用户级线程 ULT

**用户级线程（User Level Thread）**

* 由用户空间中的线程库管理；
* 内核可能不知道这些用户线程的存在；
* 创建、切换开销通常较低。

如果多个用户线程只映射到一个内核调度实体，则：

* 一个用户线程进行阻塞系统调用，可能使整个进程对应的内核执行实体阻塞；
* 这些用户线程不能真正同时运行在多个 CPU 核心上。

---

### 2. 内核级线程 KLT

**内核级线程（Kernel Level Thread）**

* 由操作系统内核直接管理；
* 内核可以分别调度这些线程；
* 多个内核线程可以分配到不同 CPU 核心上并行执行。

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-017.svg" alt={"用户级线程 (ULT) 用户空间 内核空间 用户 / 内核边界 进程 线程库 创建 / 调度 / 切换 (用户态完成) 线程 T1 线程 T2 线程 T3 • 线程实体位于用户空间 • 切换不陷入内核，开销小、速度快 • 一个线程阻塞会导致整个进程阻塞 • 无法被内核调度到多核并行执行 • 可跨 OS 移植（依赖线程库） PCB（进程） 内核只看到 1 个执行实体 对线程完全无感知 内核调度以进程为单位 同一时刻只有 1 个线程能运行 内核级线程 (KLT) 用户空间 内核空"} />

---

### 3. 线程模型

常见实现方式：

* 纯用户级线程；
* 纯内核级线程；
* 用户线程与内核线程结合的混合模型。

<InlineSvg src="/images/operating-system/operating-system-process-process-thread-018.svg" alt={"Thread Library P User Space Kernel Space P User Space Kernel Space P User Space Kernel Space P Thread Library a) Pure user-level b) Pure kernel-level c) combined user-level thread kernel-level thread P Process"} />

映射关系：

| 模型  | 含义              |
| --- | --------------- |
| 多对一 | 多个用户线程映射到一个内核线程 |
| 一对一 | 每个用户线程对应一个内核线程  |
| 多对多 | 多个用户线程映射到多个内核线程 |
