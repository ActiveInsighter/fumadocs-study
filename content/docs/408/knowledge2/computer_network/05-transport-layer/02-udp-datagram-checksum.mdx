UDP（User Datagram Protocol）提供**无连接、面向报文**的传输服务。它的协议机制少、首部固定，408 的重点集中在**首部字段与校验和**。

> **真题标签**
>
> UDP：2014 年第 39 题、2018 年第 39 题、2021 年第 39 题、2024 年第 39 题。

## 5.2.1 UDP 首部

UDP 首部固定为 8 B，共 4 个 16 bit 字段：

| 字段 | 长度 | 含义 |
| --- | ---: | --- |
| 源端口 | 16 bit | 发送方端口，可用于返回 |
| 目的端口 | 16 bit | 接收方端口 |
| 长度 | 16 bit | UDP 首部 + UDP 数据 |
| 校验和 | 16 bit | 对伪首部、UDP 首部和数据进行检错 |

因此：

$$
L_{UDP}=8\text{ B}+L_{data}
$$

且 UDP Length 的最小值是：

$$
8\text{ B}
$$

如果目的端口没有对应进程，UDP 数据报会被丢弃，通常由 ICMP 返回**端口不可达**差错。

## 5.2.2 面向报文

应用层交给 UDP 一个报文，UDP 把它作为一个完整数据单位交给 IP 层；UDP 不像 TCP 那样把数据抽象为连续字节流。

因此使用 UDP 的应用通常必须自己处理：

- 报文边界；
- 丢包；
- 乱序；
- 重复；
- 需要时的重传。

## 5.2.3 UDP 校验和为什么有伪首部

UDP 校验范围包括：

```text
IP 伪首部 + UDP 首部 + UDP 数据
```

IPv4 UDP 伪首部主要含：

| 字段 | 长度 |
| --- | ---: |
| 源 IP 地址 | 32 bit |
| 目的 IP 地址 | 32 bit |
| 全 0 | 8 bit |
| 协议号 | 8 bit |
| UDP 长度 | 16 bit |

UDP 的 IP 协议号为：

$$
17
$$

<Callout type="warn" title="伪首部不会作为 UDP 首部发送">
伪首部只参与校验计算。它用于把关键 IP 层信息也纳入检错范围，并不真的出现在 UDP 用户数据报中。
</Callout>

## 5.2.4 发送端校验和计算

### 第 1 步：Checksum 字段暂置 0

计算时先把 UDP 首部中的校验和字段置 0。

### 第 2 步：拼接校验内容

按顺序考虑：

```text
伪首部 → UDP 首部 → UDP 数据
```

若参与计算的总字节数为奇数，在末尾补一个 `0x00`，只用于计算，不实际发送。

### 第 3 步：按 16 bit 做反码加法

所有 16 bit 字相加；若最高位产生进位，则把进位加回低 16 位，称为**回卷进位**。

### 第 4 步：逐位取反

最终和按位取反，得到 16 bit 校验和。若 IPv4 UDP 计算出的校验和值恰好为全 0，实际发送时用全 1 表示，以免与“未启用 UDP 校验和”的全 0 字段混淆。

可压缩为：

$$
Checksum=\sim\left(\sum_{1's\ complement} W_i\right)
$$

其中求和采用 16 bit 反码加法。

## 5.2.5 接收端验证

接收方重新构造伪首部，把收到的校验和连同其他 16 bit 字一起做反码加法。

若无差错，结果应为：

$$
\texttt{0xFFFF}
$$

即全 1。

UDP 只负责**检错**。检测到错误后通常丢弃数据报，并不会由 UDP 自己启动可靠重传。

## 5.2.6 IPv4 与 IPv6 下的 UDP 校验和

- IPv4 中 UDP 校验和可以不用；校验和字段为全 0 可表示未启用。
- IPv6 中通常要求 UDP 校验和使用，不能简单套 IPv4 的“全 0 表示不用校验”规则。


## 5.2.7 一个短计算例

假设 UDP 数据只有 3 B，则参与校验时总长度很可能为奇数字节。此时要在**计算副本**末尾补一个 `0x00`，例如：

```text
数据：48 65 6C
计算时：48 65 6C 00
16 bit 分组：0x4865, 0x6C00
```

补出的 `00` 不属于 UDP Length，也不会真的发到网络中。之后再把伪首部与 UDP 首部的 16 bit 字一起做反码加法。

## 5.2.8 校验和计算题模板

遇到手算题按以下清单逐项检查：

1. 是否加入伪首部；
2. UDP Length 是否包含 8 B 首部；
3. 奇数字节是否仅在计算时补 0；
4. 是否按 16 bit 分组；
5. 每次高位进位是否回卷；
6. 最后是否按位取反。

<Callout type="tip" title="一个很实用的自检">
发送端“求和后取反”，接收端“把收到的校验和也加进去”。若所有比特正确，最终反码和应为全 1。
</Callout>

## 5.2.9 UDP 为什么仍然重要

UDP 的优势不是“天然更快”，而是**机制少、首部小、应用自主性强**。常见用途包括：

- DNS；
- SNMP；
- 实时音视频；
- 在线游戏；
- QUIC 的承载基础。

应用若需要可靠性，可以在 UDP 上自行增加确认、重传、排序、FEC 或拥塞控制。

## 5.2.10 本节易错点

```text
UDP 首部 = 8 B
UDP Length = 首部 + 数据
伪首部只校验，不发送
UDP 校验和能检错，但不保证可靠传输
目的端口不存在 → 常见 ICMP Port Unreachable
UDP 面向报文，不是字节流
```
