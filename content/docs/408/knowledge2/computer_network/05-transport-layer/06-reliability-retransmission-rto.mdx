IP 提供尽最大努力交付，可能发生丢包、乱序、重复和比特错误。TCP 通过以下机制把它“包装”为可靠字节流：

```text
序号 + ACK + 校验和 + 重传 + 窗口 + 缓存/重排
```

## 5.6.1 累计确认的核心

若某段：

```text
seq = S
长度 = L B
```

且这些字节连续到达，则：

$$
ACK=S+L
$$

`ACK=N` 的意思不是“确认 N”，而是：

> `N` 以前的连续字节都已收到，下一步要 `N`。

## 5.6.2 丢包与乱序时 ACK 怎么变化

假设接收端期待 `seq=N`，但 `N` 对应的数据丢失，后续更大的序号先到达。

即使接收端缓存了这些乱序数据，累计 ACK 仍不能越过缺口，因此会重复：

```text
ACK = N
ACK = N
ACK = N
...
```

这正是发送方判断“前面某段可能丢了”的重要信号。

## 5.6.3 超时重传

发送方对尚未确认的数据维护重传计时。若在 RTO（Retransmission Timeout）内未获得足够确认，则重传相关数据。

超时可能源于：

- 数据段丢失；
- ACK 丢失；
- RTT 突然变大；
- 网络严重排队。

因此“超时”是一个比较强的异常/拥塞信号，但不意味着一定是数据段本身丢失。

## 5.6.4 快速重传

如果后续数据还能到达而前面有缺口，接收方会产生重复 ACK。

经典 TCP 规则：

> 收到 **3 个重复 ACK** 后，不等 RTO，立即重传推测丢失的报文段。

> **真题标签**
>
> 快速重传：2019 年第 38 题等多次考查。

### “3 个重复 ACK”怎么数

先出现一个正常的 `ACK=N`，之后又连续出现 3 个相同 `ACK=N`，这 3 个后续确认才是“三个重复 ACK”。

因此若把最初正常 ACK 也算在“看到的同值 ACK 数”里，触发时可能共看到 4 个相同 ACK。

<Callout type="warn" title="不要把“3 个相同 ACK”机械等同于“3 个重复 ACK”">
考试优先按题目措辞：若明确说“收到 3 个重复确认”，就触发快速重传。
</Callout>

## 5.6.5 接收端发现校验错误后会怎样

TCP 校验和错误的数据段会被丢弃。接收端不会发送一个特殊的“请重传命令”。发送方最终依靠：

- ACK 不前进；
- 重复 ACK；
- 或 RTO 超时；

触发重传。

## 5.6.6 RTO 为什么不能固定得太小或太大

- 太小：正常抖动也会造成误重传；
- 太大：真正丢包后恢复过慢。

因此 TCP 根据 RTT 动态估计重传超时。

常见教材模型：

$$
EstimatedRTT=(1-\alpha)EstimatedRTT+\alpha SampleRTT
$$

$$
DevRTT=(1-\beta)DevRTT+\beta|SampleRTT-EstimatedRTT|
$$

$$
RTO=EstimatedRTT+4DevRTT
$$

常见参数：

$$
\alpha=0.125,\qquad\beta=0.25
$$

理解为：

> **RTO = 平滑 RTT 估计 + 对 RTT 波动预留的安全余量。**

## 5.6.7 TCP 与 GBN/SR 的关系

TCP 的累计确认与 GBN 有相似之处，但真实 TCP 又可以：

- 缓存乱序数据；
- 快速重传；
- 使用 SACK 描述已收到的非连续区间。

因此：

```text
TCP ≠ GBN
TCP ≠ SR
```

只能说 TCP 吸收了某些相近思想。

## 5.6.8 TCP 校验和

TCP 校验和覆盖：

```text
IP 伪首部 + TCP 首部 + TCP 数据
```

它负责检错；真正的差错恢复依靠确认与重传机制。

## 5.6.9 可靠传输事件表

| 接收情况 | ACK 现象 | 发送方可能动作 |
| --- | --- | --- |
| 连续数据正常到达 | ACK 向前推进 | 正常继续发送 |
| 前面缺段、后续段到达 | 重复同一 ACK | 3 个重复 ACK 后快速重传 |
| 数据/ACK 丢失且无足够重复 ACK | ACK 长时间不推进 | RTO 到期重传 |
| 校验和错误 | 丢弃该段 | 最终通过重复 ACK/超时恢复 |

## 5.6.10 一道题的处理顺序

1. 先按 `seq + 长度` 标出每段覆盖的字节；
2. 找接收端“第一个缺失字节”；
3. 该字节序号就是累计 ACK；
4. 统计是否形成 3 个重复 ACK；
5. 若没有快速重传条件，再看是否会超时；
6. 若题目继续问拥塞窗口，再进入拥塞控制规则。
