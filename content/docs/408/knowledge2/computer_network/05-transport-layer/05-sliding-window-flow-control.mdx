如果发送一个 TCP 报文段后必须等待 ACK 才能发送下一个，链路会因 RTT 被大量闲置。TCP 通过**滑动窗口**允许多个字节/报文段处于“已发送但尚未确认”的状态，从而实现流水线传输。

> **真题标签**
>
> TCP 滑动窗口：2009 年第 38 题、2011 年第 40 题、2013 年第 39 题、2021 年第 40 题、2025 年第 38 题、2016 年第 41 题、2023 年第 47 题。

## 5.5.1 TCP 是字节级窗口

TCP 的序列号针对**字节**，不是给报文段编号。因此窗口大小本质上也是“允许多少字节处于某种状态”。

发送方字节流可以划成：

```text
已确认 | 已发送未确认 | 可发送未发送 | 暂不可发送
       <------ 发送窗口 ------>
```

当累计 ACK 前进，发送窗口左边界向右移动，新的字节进入可发送范围。

## 5.5.2 接收窗口

接收端可以抽象为：

```text
应用已读 | TCP 已收未读 | 当前允许接收 | 超出窗口
```

接收端根据：

- 接收缓存总大小；
- 已缓存未被应用读取的数据量；
- 应用程序读取速度；

计算接收窗口 `rwnd`。

## 5.5.3 `rwnd`、`cwnd`、`swnd`

### `rwnd`：接收窗口

- 由接收方决定；
- 反映接收缓存剩余空间；
- 通过 TCP Window 字段通告；
- 服务于**流量控制**。

### `cwnd`：拥塞窗口

- 由发送方维护；
- 反映网络当前可承受的未确认数据量；
- 不直接写入 TCP Window 字段；
- 服务于**拥塞控制**。

### `swnd`：实际可用发送窗口

408 常用模型：

$$
\boxed{swnd=\min(rwnd,cwnd)}
$$

因此：

```text
rwnd 小 → 接收方是瓶颈
cwnd 小 → 网络是瓶颈
```

## 5.5.4 ACK 如何推动窗口滑动

若收到：

```text
ACK = 5000
```

表示所有序号 `<5000` 的连续字节均已收到。

发送方可：

1. 删除/释放已确认数据；
2. 将窗口左边界推进到 5000；
3. 在 `swnd` 允许的情况下扩大右边界；
4. 继续发送新数据。

因此窗口移动的直接驱动力是**累计 ACK 前进**。

## 5.5.5 流量控制解决什么问题

流量控制保护的是**接收端**。

若发送方很快、接收应用很慢：

```text
数据不断到达
→ 接收缓存占用增大
→ 空闲空间减少
→ rwnd 变小
→ 发送方受限
```

当应用读取数据后，缓存腾出空间，接收方可在后续报文中通告更大的 `rwnd`。

## 5.5.6 零窗口

若接收缓存完全没有空闲空间，接收方可通告：

$$
rwnd=0
$$

发送方应停止发送普通新数据。

但如果接收方后来重新开放窗口，而“非零窗口通知”丢失，就可能出现双方互相等待。

TCP 因此使用**持续计时器（Persist Timer）**，发送零窗口探测，询问接收端窗口是否重新打开。

<Callout type="warn" title="零窗口不是连接断开">
`rwnd=0` 只是接收方暂时没有缓存空间，TCP 连接仍然存在。发送方需要等待/探测，而不是直接关闭连接。
</Callout>

## 5.5.7 窗口题的统一画法

先写三个量：

```text
当前累计 ACK = A
rwnd = R
cwnd = C
```

再算：

$$
swnd=\min(R,C)
$$

若题目要求“还能发送多少”，还要扣除已经发出但未确认的数据量 `FlightSize`：

$$
\text{还能新发}
=\max(0,swnd-FlightSize)
$$

这比直接把 `swnd` 当作“还能发送”更稳。

## 5.5.8 与数据链路层滑动窗口的关系

二者都利用流水线提高利用率，但不要简单等同：

- 数据链路层常以“帧”为单位讨论 GBN/SR；
- TCP 以“字节序列”为基础；
- TCP 有累计确认、乱序缓存、快速重传、SACK 等机制；
- TCP 窗口还同时受到接收方与网络拥塞影响。

## 5.5.9 高频辨析

| 问题 | 看哪个量 |
| --- | --- |
| 接收方还有多少缓存空间 | `rwnd` |
| 网络拥塞允许发多少 | `cwnd` |
| TCP 首部 Window 字段 | `rwnd` |
| 发送方实际窗口上限 | `min(rwnd,cwnd)` |
| 已发送未确认字节 | FlightSize |

一句话记忆：

> **`rwnd` 保护接收方，`cwnd` 保护网络，实际发送受二者较小值限制。**
