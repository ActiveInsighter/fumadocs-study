传输层位于应用层与网络层之间，只运行在**端系统**中。网络层负责把 IP 数据报从一台主机送往另一台主机，传输层则进一步回答：**数据到达目的主机后，应交给哪个应用进程？**

```text
应用进程
   ↓ 端口
UDP / TCP
   ↓
   IP
   ↓
网络
```

<Callout type="info" title="本章主线">
端口定位进程 → UDP/TCP 提供不同服务 → TCP 建立连接 → 序号与 ACK 保证可靠 → `rwnd` 做流量控制 → `cwnd` 做拥塞控制。
</Callout>

## 5.1.1 传输层提供的服务

传输层向应用层提供**进程到进程的逻辑通信**，主要功能包括：

- 进程寻址：用端口号标识通信端点；
- 复用与分用：多个应用共享网络层，又能在接收端正确分发；
- 差错检测：TCP、UDP 都有校验和；
- 可靠传输、流量控制、拥塞控制：由 TCP 提供；
- 无连接的轻量传输：由 UDP 提供。

网络中的路由器一般只处理到网络层，不会像端系统那样维护 TCP 连接状态。

## 5.1.2 端口号

TCP 和 UDP 端口号均为 16 bit，因此范围为：

$$
0\sim 2^{16}-1=65535
$$

端口是**逻辑标识**，不是物理接口，也不等同于进程本身。

常见分类可这样记：

| 范围 | 常见称呼 | 用途 |
| --- | --- | --- |
| `0~1023` | 熟知端口 | 常见标准服务 |
| `1024~49151` | 登记端口 | 已登记应用/服务 |
| `49152~65535` | 动态/私有端口 | 客户端临时端口等 |

408 更关心“端口用于进程寻址”，通常不要求死记完整端口分区。

## 5.1.3 IP、端口与套接字

一个通信端点常写为：

```text
(IP 地址, 端口号)
```

TCP 连接通常由四元组唯一标识：

```text
(源 IP, 源端口, 目的 IP, 目的端口)
```

因此同一台 Web 服务器可以使用同一个本地端口同时服务大量客户端，因为每条 TCP 连接的对端 IP/端口不同。

<Callout type="warn" title="不要把“端口号”当作 TCP 连接标识">
仅知道目的端口只能定位某类服务；一条具体 TCP 连接要结合双方 IP 与端口区分。
</Callout>

## 5.1.4 复用与分用

### 发送端：复用

多个应用进程的数据都可交给 UDP/TCP，再统一向 IP 层发送：

```text
进程 A ─┐
进程 B ─┼→ 传输层 → IP
进程 C ─┘
```

### 接收端：分用

IP 把报文交给传输层后，传输层根据首部中的端口等信息交给正确应用：

```text
IP → 传输层 ─┬→ 进程 A
              ├→ 进程 B
              └→ 进程 C
```

可记为：

```text
发送端：多 → 一，复用
接收端：一 → 多，分用
```

## 5.1.5 无连接服务与面向连接服务

### UDP：无连接

发送前不建立传输层连接，每个 UDP 用户数据报独立处理。UDP 本身不保证：

- 到达；
- 顺序；
- 不重复；
- 自动重传。

### TCP：面向连接

数据传输前建立连接，连接内提供：

- 可靠、有序、无重复的字节流；
- 全双工传输；
- 流量控制；
- 拥塞控制；
- 正常的连接释放过程。

## 5.1.6 UDP 与 TCP 的总体边界

| 对比项 | UDP | TCP |
| --- | --- | --- |
| 连接 | 无连接 | 面向连接 |
| 数据抽象 | 面向报文 | 面向字节流 |
| 可靠性 | 不保证 | 可靠 |
| 顺序 | 不保证 | 保证字节流有序 |
| 自动重传 | 无 | 有 |
| 流量控制 | 无 | 有 |
| 拥塞控制 | UDP 本身无 | 有 |
| 首部最小长度 | 8 B | 20 B |
| 广播/组播 | 可用 | TCP 不支持 |

<Callout type="warn" title="UDP 不等于“应用一定不可靠”">
应用完全可以在 UDP 之上自行实现确认、重传、排序与拥塞控制。QUIC 就建立在 UDP 之上，但提供了可靠传输等更复杂能力。
</Callout>

## 5.1.7 本节速记

```text
IP 地址：定位主机/接口
端口号：定位应用通信端点
四元组：定位一条 TCP 连接
复用：多个进程共用传输层
分用：把收到的数据交给正确进程
UDP：简单、无连接、面向报文
TCP：连接、可靠、字节流、全双工
```
