传输层综合题常把以下内容串在一起：

```text
三次握手
  ↓
seq / ACK
  ↓
发送窗口 min(rwnd,cwnd)
  ↓
若干 RTT 的数据传输
  ↓
丢包与重传
  ↓
四次挥手
```

本节给出统一的“账本法”。

## 5.8.1 序号账本：只记谁消耗序号

### 普通数据

若：

```text
seq = S
数据长度 = L
```

则下一个序号：

$$
S+L
$$

### SYN

$$
SYN\Rightarrow+1
$$

### FIN

$$
FIN\Rightarrow+1
$$

### 纯 ACK

不携带数据、SYN、FIN 的纯 ACK 通常：

$$
+0
$$

因此可以做一个简单流水账：

| 发送内容 | 起始 seq | 消耗 |
| --- | ---: | ---: |
| SYN | `x` | 1 |
| 500 B 数据 | `x+1` | 500 |
| 纯 ACK | `x+501` | 0 |
| FIN | `x+501` | 1 |

## 5.8.2 ACK 账本：找“第一个缺失字节”

只要记住：

$$
ACK=\text{下一个期望字节序号}
$$

例如已经连续收到：

$$
1000\sim1499
$$

则：

$$
ACK=1500
$$

如果 `1500~1999` 丢失，而 `2000~2499` 已到，累计 ACK 仍然是：

$$
1500
$$

## 5.8.3 发送窗口账本

先计算：

$$
swnd=\min(rwnd,cwnd)
$$

若已有 `FlightSize` 字节已发送但未确认，则当前还能新发：

$$
\max(0,swnd-FlightSize)
$$

如果题目用 MSS 为单位，要先统一单位。

例如：

```text
MSS = 500 B
cwnd = 3 MSS = 1500 B
rwnd = 1000 B
```

则：

$$
swnd=\min(1500,1000)=1000\text{ B}
$$

## 5.8.4 RTT 轮次题

如果忽略报文段发送时延，只按 RTT 计时，建议画“时刻—窗口—发送量”表：

| 时刻 | `cwnd` | `rwnd` | 本轮可发送 |
| --- | ---: | ---: | ---: |
| 第 0 轮 | ... | ... | ... |
| 第 1 个 RTT 后 | ... | ... | ... |
| 第 2 个 RTT 后 | ... | ... | ... |

每轮依次做：

1. 计算 `swnd`；
2. 受剩余文件大小限制确定本轮实际发送量；
3. 推进时间一个 RTT；
4. 根据 ACK 更新 `cwnd`、累计 ACK 和在途数据；
5. 判断文件是否已被“发送”还是已被“确认”。

<Callout type="warn" title="“发完”和“确认成功”不是同一时刻">
题目若问“发送方确定对端已成功收到全部数据”，通常要等最后一批数据的 ACK 返回，而不是最后一个数据段刚发出去的时刻。
</Callout>

## 5.8.5 慢开始的报文段累计数

若经典慢开始从 `1 MSS` 开始，并且连续若干轮窗口为：

$$
1,2,4,8,\ldots,2^{k-1}
$$

前 `k` 轮最多发送的 MSS 数为等比和：

$$
1+2+4+\cdots+2^{k-1}=2^k-1
$$

因此“第几个报文段在哪一轮发送”类题可以通过累计和快速定位。

## 5.8.6 拥塞事件题

### RTO 超时

经典教材模型：

$$
ssthresh\leftarrow\frac{cwnd}{2},\qquad cwnd\leftarrow1
$$

然后慢开始。

### 3 个重复 ACK

先快速重传；窗口如何变化按题设：

- 简化 408 模型：`cwnd ← ssthresh`；
- Reno 细节：可出现 `ssthresh+3 MSS` 的临时窗口。

## 5.8.7 UDP/TCP 终极对比

| 特征 | UDP | TCP |
| --- | --- | --- |
| 服务模型 | 无连接 | 面向连接 |
| 数据单位 | 报文 | 字节流 |
| 首部最小 | 8 B | 20 B |
| 可靠性 | 应用需要时自行实现 | 协议提供 |
| 流量控制 | 无 | `rwnd` |
| 拥塞控制 | UDP 本身无 | `cwnd` + `ssthresh` |
| 典型应用 | DNS、实时媒体、QUIC 基础 | Web 传统 TCP、FTP、邮件等 |

## 5.8.8 高频易错点清单

<Callout type="warn" title="考前逐条确认">

- 端口号不是物理接口；
- UDP Length 包含 8 B 首部；
- UDP/TCP 校验和都涉及伪首部；
- TCP `seq` 指向本段**第一个数据字节**；
- `ACK=N` 表示下一字节要 `N`；
- SYN、FIN 各消耗一个序号；
- 纯 ACK 通常不消耗序号；
- TCP Window 字段通告 `rwnd`，不是 `cwnd`；
- 实际发送上限是 `min(rwnd,cwnd)`；
- 慢开始按 RTT 观察约指数增长；
- 拥塞避免约每 RTT `+1 MSS`；
- 3 个重复 ACK 与 RTO 超时要分开处理；
- 快速重传与快速恢复不是同一件事；
- `TIME-WAIT` 在主动关闭方，并等待 `2MSL`。

</Callout>

## 5.8.9 本章知识树

```text
传输层
├─ 端口、复用与分用
├─ UDP
│  ├─ 8 B 首部
│  ├─ 面向报文
│  └─ 伪首部 + 反码校验和
└─ TCP
   ├─ 20~60 B 首部
   ├─ seq / ACK / 字节流
   ├─ 三次握手 / 四次挥手
   ├─ 滑动窗口
   │  └─ swnd = min(rwnd, cwnd)
   ├─ 可靠传输
   │  ├─ 累计确认
   │  ├─ RTO 超时重传
   │  └─ 3 个重复 ACK → 快速重传
   └─ 拥塞控制
      ├─ 慢开始
      ├─ 拥塞避免
      └─ 快速恢复
```
