## 21. IP 组播与 IGMP

<InlineSvg src="/images/computer-network/computer-network-network-ip-014.svg" alt={"IP 图 14"} />

IP 组播（IP Multicast）允许发送方只发送一份逻辑数据，由网络在需要的位置复制，送给一组感兴趣的接收者。

IPv4 传统 D 类地址范围：

```text
224.0.0.0 ~ 239.255.255.255
```

用于组播地址。

### 21.1 单播、广播、组播

| 方式 | 语义 |
| --- | --- |
| 单播 | 一对一 |
| 广播 | 一对当前广播域内所有节点 |
| 组播 | 一对一组加入该组的接收者 |

### 21.2 IGMP

IGMP（Internet Group Management Protocol）用于 IPv4 主机与本地组播路由器之间进行 **组成员管理**，使路由器知道某个本地网络是否存在某组播组成员。

需要区分：

- IGMP 解决“**本地链路上有没有这个组的成员**”；
- 组播路由协议解决“**组播流量怎样在路由器之间构造转发树**”。

## 22. IPv6：地址、基本首部与关键差异

> **真题考察**
>
> * 选择题：2023 年第 40 题
> * IPv6 地址相关：2023 年第 15 题

IPv6 地址长度为：

```text
128 bit
```

理论地址空间：

$$
2^{128}\approx3.4\times10^{38}
$$

### 22.1 IPv6 主要特征

- 128 bit 地址；
- 基本首部固定 40 Byte；
- 基本首部字段比 IPv4 更精简；
- 没有 IPv4 Header Checksum；
- 使用扩展首部承载可选功能；
- 支持单播、组播、任播；
- 没有传统 IPv4 广播；
- 路由器不执行 IPv4 式的中途分片，必要分片由源节点完成。

### 22.2 IPv6 基本首部

<InlineSvg src="/images/computer-network/computer-network-network-ip-015.svg" alt={"IP 图 15"} />

IPv6 基本首部固定为 40 Byte，包含 8 个基本字段：

| 字段 | 作用 |
| --- | --- |
| Version | IPv6 中为 6 |
| Traffic Class | 服务质量/优先级等 |
| Flow Label | 标识流 |
| Payload Length | 基本首部之后的负载长度 |
| Next Header | 指向扩展首部或 TCP/UDP/ICMPv6 等 |
| Hop Limit | 类似 IPv4 TTL |
| Source Address | 128 bit 源地址 |
| Destination Address | 128 bit 目的地址 |

<Callout type="warning" title="Payload Length 不含 40 Byte 基本首部">

IPv4 的 Total Length 包含首部；IPv6 的 Payload Length 表示**基本首部之后**的数据长度。做长度题时不要直接套 IPv4 口径。

</Callout>

### 22.3 IPv6 分片责任

IPv6 基本首部没有 IPv4 的 Identification、Flags、Fragment Offset。需要分片时，源节点使用 Fragment 扩展首部；中间路由器不进行传统 IPv4 式分片。

若路径 MTU 不够，路由器可返回 ICMPv6 Packet Too Big，源节点据此调整发送大小。

### 22.4 IPv6 地址书写

完整地址由 8 组、每组 16 bit 十六进制数组成：

```text
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

**规则 1：省略每组前导 0**

```text
2001:db8:85a3:0:0:8a2e:370:7334
```

**规则 2：连续若干个全 0 组可用 `::` 压缩**

一个地址中 `::` 最多只能出现一次，否则无法唯一恢复被省略的 0 组数量。

#### 22.4.1 压缩地址恢复四步法

例如：

```text
2001:db8::8a2e:370:7334
```

1. 先数显式写出的组数：左侧 2 组，右侧 3 组，共 5 组；
2. IPv6 总共必须有 8 组，因此 `::` 代表 $8-5=3$ 组 `0000`；
3. 每组补足 4 个十六进制数字；
4. 最终恢复为 128 bit。

<Callout type="warning" title=":: 不是‘任意多个 0’">

`::` 代表的是“恰好足够把整个地址补到 8 组”的连续全 0 组，因此一个地址中只能出现一次。

</Callout>

### 22.5 常见 IPv6 地址类型

IPv6 主要支持：

- Unicast（单播）；
- Multicast（多播）；
- Anycast（任播）。

任播允许多个节点共享同一地址，网络通常把数据送到路由意义上较近的一个实例。

常见特殊形式：

| 地址/前缀 | 含义 |
| --- | --- |
| `::` | 未指定地址 |
| `::1` | 环回地址 |
| `fe80::/10` | 链路本地单播地址范围 |
| `ff00::/8` | 多播地址范围 |

<Callout type="info" title="IPv6 没有广播">

IPv6 用多播、任播等机制替代许多 IPv4 广播场景，因此“没有广播地址”是高频判断点。

</Callout>

## 23. IPv4 向 IPv6 过渡

IPv4 与 IPv6 会长期共存，常见过渡思路包括双协议栈与隧道。

### 23.1 双协议栈

设备同时实现：

```text
IPv4 协议栈 + IPv6 协议栈
```

根据目标地址、DNS 返回结果与网络能力选择 IPv4 或 IPv6。

### 23.2 隧道

当 IPv6 数据报需要穿越仅支持 IPv4 的网络时，可以把完整 IPv6 数据报作为 IPv4 的负载：

```text
IPv6 数据报
   ↓ 封装进 IPv4
IPv4-only 网络
   ↓ 解封装
IPv6 数据报
```

隧道的本质是：**把一种协议的数据包作为另一种协议的载荷跨越不兼容区域。**

## 24. 移动 IP

移动 IP（Mobile IP）的目标是：移动节点改变接入网络后，仍能以相对稳定的归属身份被访问。

核心概念：

- **Home Address**：归属地址；
- **Home Network**：归属网络；
- **Home Agent**：归属代理；
- **Care-of Address**：转交地址。

典型过程：

1. 移动节点原本在归属网络使用 Home Address；
2. 移动到外地网络后获得 Care-of Address；
3. 向 Home Agent 登记当前位置；
4. 通信对端仍可把数据发往 Home Address；
5. Home Agent 截获相应数据并通过隧道送往 Care-of Address；
6. 移动节点在当前位置接收。

这可能形成经典的 **三角路由**：通信对端到移动节点的数据先经过归属代理，而返回流量可能直接发回对端。

## 25. 网络层拥塞控制：和流量控制分清楚

当大量主机同时向网络注入流量，使某些路由器/链路的**到达速率长期高于处理或发送能力**时，会出现：

```text
队列增长 → 排队时延上升 → 缓冲区耗尽 → 丢包 → 重传增多 → 可能进一步恶化拥塞
```

这就是拥塞（Congestion）。

### 25.1 拥塞控制与流量控制

| 对比 | 流量控制 | 拥塞控制 |
| --- | --- | --- |
| 主要矛盾 | 发送方 vs 接收方处理能力 | 全网/局部网络负载 vs 网络资源 |
| 典型观察量 | 接收窗口、接收缓存 | 队列长度、时延、丢包、ECN 等 |
| 典型层次 | 数据链路层/传输层常见 | 网络层与传输层都可参与 |

所以“接收方很强”并不意味着网络不会拥塞；即使终点能高速接收，中间瓶颈链路仍可能被压满。

### 25.2 两类基本思路

可以从考试角度把拥塞控制归纳为：

- **预防/开环思想**：在拥塞明显发生前，通过流量整形、合理路由、资源预留/准入等减少过载风险；
- **反馈/闭环思想**：观察队列、丢包、时延或显式拥塞信号，再让发送端降低负载或调整路径。

网络层设备还可以采用主动队列管理、丢弃策略、ECN 标记等方式反馈拥塞状态；传输层 TCP 再根据端到端信号调整发送速率。

<Callout type="warning" title="ICMP Source Quench 不要当现代标准答案">

经典教材可能提到 ICMP Source Quench，但它已经废弃。现代拥塞控制不应把“路由器发 Source Quench”当作核心机制。

</Callout>

## 26. SDN：控制平面与数据平面分离

<InlineSvg src="/images/computer-network/computer-network-network-sdn-001.svg" alt={"SDN 图 1"} />

> **真题考察**
>
> * 选择题：2022 年第 37 题

SDN（Software Defined Networking）的核心思想是：

> **把控制逻辑从具体转发设备中抽离，使控制平面与数据平面解耦。**

### 26.1 数据平面

数据平面强调高速执行，例如：

- 匹配流表；
- 从指定端口转发；
- 丢弃；
- 修改首部字段；
- 将特定分组送给控制器。

### 26.2 控制平面

控制平面负责：

- 计算策略与路径；
- 维护网络状态；
- 生成/下发流表；
- 响应拓扑变化。

SDN 控制器通常是**逻辑集中式**的；物理上可以用多个服务器组成集群，因此“逻辑集中”不等于“只能是一台物理服务器”。

### 26.3 南向、北向与东西向接口

| 接口 | 连接对象 | 典型用途 |
| --- | --- | --- |
| 南向 | Controller ↔ 转发设备 | 下发规则、读取状态；OpenFlow 是典型例子 |
| 北向 | 应用 ↔ Controller | 应用读取状态、提交策略 |
| 东西向 | Controller ↔ Controller | 多控制器协同 |

### 26.4 流表与 Match-Action

典型流表项包含：

- **Match**：源/目的地址、端口、VLAN、协议等匹配字段；
- **Priority**：多个规则同时命中时的优先级；
- **Counters**：分组数、字节数等统计；
- **Instructions/Actions**：转发、丢弃、修改、送控制器或继续查表。

可以把 SDN 数据平面理解为典型的：

```text
Match → Action
```

## 27. 网络层端到端转发全过程

假设主机 A：

```text
192.168.1.10/24
默认网关：192.168.1.1
```

要访问主机 B：

```text
10.0.0.20
```

### 27.1 判断是否同网段

A 用自己的掩码判断 B 不在本地子网，因此下一跳选择默认网关，而不是直接寻找 B 的 MAC。

### 27.2 ARP 默认网关

若缓存无记录：

```text
192.168.1.1 → ?
```

A 广播 ARP Request，获得网关接口 MAC。

### 27.3 首跳封装

IP 数据报：

```text
源 IP：192.168.1.10
目的 IP：10.0.0.20
```

第一跳以太网帧：

```text
源 MAC：A 的 MAC
目的 MAC：网关 MAC
```

### 27.4 每台路由器处理

普通路由器依次：

1. 去掉当前链路层封装；
2. 读取目的 IP；
3. TTL 减 1；
4. 最长前缀匹配；
5. 确定下一跳/接口；
6. 必要时 ARP 下一跳；
7. 必要时分片或 NAT；
8. 更新 IPv4 首部校验和；
9. 用新的链路层地址重新封装。

### 27.5 到达最终子网

最后一台路由器发现 B 所在前缀为直连网络，再 ARP 获得 B 的 MAC，把数据报封装成目的 MAC 为 B 的帧发送。

<Callout type="info" title="跨路由器时最常考的变化">

| 字段 | 普通逐跳转发 |
| --- | --- |
| 源 IP | 通常不变 |
| 目的 IP | 通常不变 |
| TTL | 每经过路由器减小 |
| IPv4 首部校验和 | 随首部变化重新计算 |
| 源/目的 MAC | 每条链路重新封装，通常变化 |
| IP/端口 | 经过 NAT 时可能变化 |

</Callout>

## 28. 网络层高频易错点总表

| 问题 | 正确判断 |
| --- | --- |
| ARP 查谁的 MAC？ | 当前链路下一跳；跨网段时通常是默认网关/下一台路由器 |
| 普通路由器会改源/目的 IP 吗？ | 通常不会；NAT 是例外 |
| MAC 会变吗？ | 跨链路重新封装，通常会变 |
| TTL 何时减？ | 每经过路由器减小 |
| TTL 失效？ | 丢弃，通常返回 ICMP Time Exceeded |
| IPv4 Header Checksum 校验什么？ | 只校验 IPv4 首部 |
| Fragment Offset 单位？ | 8 Byte |
| 同一原始数据报分片 ID？ | 相同 |
| 分片通常谁重组？ | 最终目的主机 |
| 最长前缀匹配比什么？ | 命中的前缀长度 |
| 默认路由？ | `0.0.0.0/0` |
| RIP 最大有效跳数？ | 15 |
| RIP 16 跳？ | 不可达 |
| RIP 算法思想？ | 距离向量 / Bellman-Ford |
| OSPF 算法思想？ | 链路状态 / Dijkstra SPF |
| BGP？ | 路径向量、策略驱动、跨 AS |
| RIP / OSPF / BGP 承载？ | UDP / 直接 IP / TCP |
| DHCP DORA？ | Discover、Offer、Request、ACK |
| ping？ | ICMP Echo |
| traceroute？ | TTL/Hop Limit + ICMP 超时 |
| IPv6 基本首部？ | 固定 40 Byte |
| IPv6 首部校验和？ | 没有 |
| IPv6 地址长度？ | 128 bit |
| IPv6 广播？ | 没有传统 IPv4 广播 |
| NAT = 防火墙？ | 不等于 |
| 流量控制 vs 拥塞控制？ | 前者偏发送方/接收方能力匹配；后者偏网络负载与网络资源匹配 |
| 拥塞的直接表现？ | 排队时延上升、缓冲溢出丢包等 |
| 私有 IPv4 块？ | `10/8`、`172.16/12`、`192.168/16` |

## 29. 本章做题框架与真题复习优先级

### 29.1 第一优先级：必须会算

- 网络地址、广播地址、主机范围；
- 掩码与 CIDR 前缀互换；
- FLSM/VLSM；
- 路由聚合；
- IPv4 分片；
- 路由表与最长前缀匹配；
- NAT 地址/端口变化。

### 29.2 第二优先级：必须能完整叙述流程

- 同网段/跨网段 ARP；
- DHCP DORA；
- 路由器逐跳转发；
- RIP 距离向量更新；
- OSPF LSA → LSDB → SPF；
- BGP 跨 AS 路由传播。

### 29.3 第三优先级：掌握关键区别

- ICMP 与 ping/traceroute；
- IP 组播与 IGMP；
- IPv4 vs IPv6；
- 双协议栈与隧道；
- 移动 IP；
- 流量控制 vs 拥塞控制；
- SDN 控制/数据平面。

### 29.4 网络层综合题推荐书写顺序

遇到“地址规划 + 路由表 + ARP/NAT + 分片”综合题时，建议严格按下面顺序：

```text
① 算网络前缀 / 子网范围
② 判断目的是否同网段
③ 查路由表并做最长前缀匹配
④ 确定当前链路下一跳
⑤ ARP 当前下一跳 MAC
⑥ 必要时 NAT / 分片
⑦ 写本跳 IP 与 MAC 的变化
⑧ 到下一台路由器重复
```

这种顺序可以避免最常见的“先写 MAC、后发现下一跳选错”或“把远端主机 MAC 当成本地 ARP 目标”的连锁错误。

<Callout type="info" title="本章一条主线串到底">

```text
IP/前缀判断目标网络
        ↓
路由协议帮助建立路由信息
        ↓
最长前缀匹配选下一跳
        ↓
ARP 得到当前链路下一跳 MAC
        ↓
链路层重新封装
        ↓
路由器逐跳重复
        ↓
最终到达目的主机
```

</Callout>
