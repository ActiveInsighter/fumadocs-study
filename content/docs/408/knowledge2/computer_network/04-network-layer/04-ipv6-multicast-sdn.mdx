## 21. IP 组播

IP 组播（IP Multicast）允许发送方发送一份数据，由网络根据组播转发结构复制给多个接收者。

<InlineSvg src="/images/computer-network/computer-network-network-ip-014.svg" alt={"IP 图 14"} />

IPv4 D 类地址：

```text
224.0.0.0 ~ 239.255.255.255
```

用于组播。

### 21.1 单播、广播与组播

| 模式 | 含义            |
| -- | ------------- |
| 单播 | 一对一           |
| 广播 | 一对当前广播域中的所有节点 |
| 组播 | 一对一组感兴趣的接收者   |

### 21.2 IGMP

IGMP（Internet Group Management Protocol）用于 IPv4 主机与本地组播路由器之间的 **组播成员管理**。

主机可以借助 IGMP 表示：

* 加入某个组播组。
* 维持组播成员关系。
* 离开组播组。

网络只需要把组播数据转发到存在成员的相关网络分支，而不是向所有节点复制。

## 22. IPv6

> **真题考察**
>
> * 选择题：2023 年第 40 题
> * IPv6 地址相关：2023 年第 15 题

IPv4 地址只有 32 bit。为了扩大地址空间，IPv6 将地址长度扩大为：

```text
128 bit
```

地址数量达到：

$$
2^{128}
\approx
3.4\times10^{38}
$$

### 22.1 IPv6 的主要特点

* 128 bit 地址空间。
* 基本首部固定为 40 Byte。
* 首部结构比 IPv4 更简洁。
* 不再包含 IPv4 首部校验和。
* 支持扩展首部。
* 支持单播、多播、任播。
* 支持无状态地址自动配置等机制。
* 路由器不对 IPv6 数据报进行传统 IPv4 式中途分片；需要时由源节点配合分片扩展首部处理。

> **易错点**
>
> IPv6 没有 IPv4 中的 **广播地址**，很多原来需要广播完成的功能会使用多播等机制实现。

### 22.2 IPv6 首部

<InlineSvg src="/images/computer-network/computer-network-network-ip-015.svg" alt={"IP 图 15"} />

IPv6 基本首部长度固定为：

```text
40 Byte
```

包含 8 个基本字段：

| 字段                  | 作用                    |
| ------------------- | --------------------- |
| Version             | IPv6 中值为 6            |
| Traffic Class       | 服务质量与优先级              |
| Flow Label          | 标识数据流                 |
| Payload Length      | 基本首部之后的有效载荷长度         |
| Next Header         | 指向扩展首部或 TCP、UDP 等上层协议 |
| Hop Limit           | 类似 IPv4 TTL           |
| Source Address      | 128 bit 源地址           |
| Destination Address | 128 bit 目的地址          |

IPv6 相比 IPv4：

* 没有 Header Checksum。
* 没有 IPv4 基本首部中的 Identification、Flags、Fragment Offset。
* 分片功能通过扩展首部实现。
* 路由器处理基本首部的工作得到简化。

### 22.3 IPv6 地址表示

IPv6 地址由 **8 个 16 bit 十六进制组**组成。

例如：

```text
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

#### 省略前导 0

每个组开头的 0 可以省略：

```text
2001:db8:85a3:0:0:8a2e:370:7334
```

#### 双冒号压缩

连续若干个全 0 组可以用：

```text
::
```

表示。

例如：

```text
4BF5:0000:0000:BA5F:039A:000A:2176:0001
```

可以缩写。

关键规则：

> 一个 IPv6 地址中 `::` 最多只能出现一次，否则无法判断被省略了多少组 0。

### 22.4 IPv6 地址类型

IPv6 主要包括：

* **单播（Unicast）**
* **多播（Multicast）**
* **任播（Anycast）**

任播表示：

> 同一个地址可以配置给多个节点，数据通常被路由到拓扑意义上较近的一个节点。

## 23. IPv4 向 IPv6 过渡

IPv4 和 IPv6 不能简单直接互换，因此长期过渡通常依赖兼容机制。

### 23.1 双协议栈

设备同时运行：

```text
IPv4 协议栈
+
IPv6 协议栈
```

并根据目标地址和网络能力选择对应协议。

### 23.2 隧道

当 IPv6 数据报需要经过只支持 IPv4 的网络时，可以把完整 IPv6 数据报封装到 IPv4 数据报中。

逻辑上相当于：

```text
IPv6
↓ 封装
IPv4 网络
↓ 解封装
IPv6
```

因此 IPv6 数据报像经过了一条 IPv4 “隧道”。

## 24. 移动 IP

移动 IP（Mobile IP）的目标是：

> 移动节点改变当前接入网络后，仍然能够使用相对稳定的身份地址继续通信。

理解时区分：

* **归属地址（Home Address）**
* **归属网络（Home Network）**
* **归属代理（Home Agent）**
* **转交地址（Care-of Address）**

典型逻辑：

1. 移动节点原本位于归属网络，使用固定的归属地址。
2. 移动到外地网络后获得转交地址。
3. 移动节点向归属代理登记当前位置。
4. 其他节点仍可以把数据发送到移动节点的归属地址。
5. 归属代理截获需要转给移动节点的数据。
6. 归属代理通过隧道把数据发送到移动节点当前的转交地址。
7. 移动节点在外地网络接收数据并继续通信。
8. 返回归属网络后恢复正常本地交付。

核心思想不是频繁改变对外身份，而是通过 **归属地址 + 转交地址 + 隧道** 支持移动性。

## 25. SDN

> **真题考察**
>
> * 选择题：2022 年第 37 题

SDN（Software Defined Networking，软件定义网络）的核心思想是：

> **把控制平面与数据平面分离。**

传统网络设备往往同时负责：

* 计算路由。
* 制定控制策略。
* 实际转发数据包。

SDN 则把网络控制逻辑集中到软件控制器中，使网络设备重点执行数据平面的转发操作。

<InlineSvg src="/images/computer-network/computer-network-network-sdn-001.svg" alt={"SDN 图 1"} />

### 25.1 数据平面

数据平面负责：

* 查询流表。
* 转发数据包。
* 丢弃数据包。
* 修改数据包字段。
* 将特定数据包发送给控制器。

要求高速执行。

### 25.2 控制平面

控制平面负责：

* 计算转发策略。
* 维护网络状态。
* 下发流表。
* 响应网络拓扑变化。

SDN 控制器通常表现为 **逻辑集中式控制器**，但物理实现可以由多个服务器组成分布式集群。

### 25.3 南向接口

南向接口连接：

```text
SDN Controller
↓
交换机 / 路由设备
```

用于：

* 控制器下发流表。
* 设备向控制器报告状态。

典型协议：

```text
OpenFlow
```

### 25.4 北向接口

北向接口连接：

```text
网络应用
↓
SDN Controller
```

网络应用可以借助接口：

* 获取网络状态。
* 提交网络策略。
* 请求控制器调整网络配置。

### 25.5 东西向接口

东西向接口主要用于：

```text
控制器 ↔ 控制器
```

特别适合存在多个 SDN 控制器的环境。

### 25.6 流表

一个典型 OpenFlow 流表项主要包含：

#### 匹配字段

可以根据：

* 源地址
* 目的地址
* 端口号
* VLAN 标签
* 协议类型

等字段匹配数据包。

#### 优先级

当多个流表项都匹配时，选择优先级更高的规则。

#### 计数器

统计：

* 匹配的数据包数量。
* 字节数。
* 使用时间等。

#### 指令与动作

匹配成功后可以：

* 从指定端口转发。
* 丢弃。
* 修改首部字段。
* 发送到控制器。
* 进入其他流表继续处理。

## 26. 网络层知识总串联

一次典型的跨网段通信可以把本章主要知识串起来。

假设：

```text
主机 A
192.168.1.10/24
默认网关 192.168.1.1
```

要访问：

```text
主机 B
10.0.0.20
```

### 第一步：判断是否同网段

A 根据：

```text
自己的 IP
子网掩码
目标 IP
```

判断 B 不在当前子网。

于是 A 不直接寻找 B 的 MAC，而要把数据交给：

```text
默认网关 192.168.1.1
```

### 第二步：ARP

A 查询：

```text
192.168.1.1 → ?
```

如果 ARP 缓存中没有记录，就广播 ARP Request，获得路由器接口 MAC。

### 第三步：封装

IP 数据报：

```text
源 IP：192.168.1.10
目的 IP：10.0.0.20
```

当前链路的以太网帧：

```text
源 MAC：A 的 MAC
目的 MAC：网关的 MAC
```

### 第四步：路由器转发

路由器：

1. 解开当前链路层帧。
2. 查看 IP 目的地址 `10.0.0.20`。
3. TTL 减 1。
4. 查询转发表。
5. 使用最长前缀匹配。
6. 确定下一跳。
7. 若需要，通过 ARP 获得下一跳 MAC。
8. 用新的 MAC 地址重新封装帧。
9. 转发。

### 第五步：沿路重复

每经过一个普通路由器：

* IP 源地址通常保持不变。
* IP 目的地址通常保持不变。
* TTL 不断减小。
* IPv4 首部校验和重新计算。
* MAC 地址逐链路改变。

若中途经过 NAT：

* IP 地址和端口号也可能被改写。

若 IP 数据报超过输出链路 MTU：

* IPv4 可能发生分片。

若 TTL 减到 0：

* 路由器丢弃数据报。
* 返回 ICMP Time Exceeded。

最终数据到达 B 所在网络后：

* 最后一台路由器通过 ARP 获得 B 的 MAC。
* 把 IP 数据报封装成目的 MAC 为 B 的链路层帧。
* B 收到数据。

## 27. 408 高频易错点

| 易错点                    | 正确理解                            |
| ---------------------- | ------------------------------- |
| ARP 查的是谁的 MAC？         | 当前链路的下一跳；跨网段时通常查默认网关 MAC        |
| IP 地址转发过程中会不会变？        | 普通路由器不改变源/目的 IP；NAT 是例外         |
| MAC 地址会不会变？            | 每跨一条链路通常重新封装，因此会改变              |
| TTL 什么时候减？             | 每经过一个路由器减 1                     |
| TTL 为 0 怎么办？           | 丢弃，并通常返回 ICMP Time Exceeded     |
| IPv4 checksum 校验什么？    | 只校验 IPv4 首部                     |
| 路由器修改 TTL 后怎么办？        | 重新计算 IPv4 首部校验和                 |
| Fragment Offset 单位是什么？ | 8 Byte                          |
| 分片的 ID 是否改变？           | 同一原始数据报的所有分片 ID 相同              |
| 哪个设备重组 IPv4 分片？        | 通常是最终目的主机                       |
| 最长前缀匹配看什么？             | 匹配的网络前缀长度                       |
| 默认路由是什么？               | `0.0.0.0/0`                     |
| RIP 最大有效跳数             | 15                              |
| RIP 的 16 跳             | 不可达                             |
| RIP 使用什么算法思想？          | Bellman-Ford / 距离向量             |
| OSPF 使用什么算法？           | Dijkstra / 链路状态                 |
| BGP 属于什么协议？            | 路径向量、跨 AS                       |
| RIP / OSPF / BGP 承载    | UDP / IP / TCP                  |
| DHCP 四步                | Discover、Offer、Request、ACK      |
| ping                   | ICMP Echo Request / Reply       |
| traceroute             | TTL + ICMP Time Exceeded        |
| IPv6 首部长度              | 固定 40 Byte                      |
| IPv6 有没有首部校验和？         | 没有                              |
| IPv6 地址长度              | 128 bit                         |
| IPv6 有没有广播地址？          | 没有传统 IPv4 广播                    |
| NAT 是否等于防火墙？           | 不等于                             |
| 私有 IPv4 地址             | `10/8`、`172.16/12`、`192.168/16` |

## 28. 真题复习优先级

### 第一优先级

必须能够独立完成计算：

* IPv4 网络地址与广播地址
* 子网掩码与前缀长度转换
* 主机数量计算
* FLSM / VLSM
* CIDR 路由聚合
* IPv4 分片
* 路由表填写
* 最长前缀匹配
* NAT 地址与端口变化

### 第二优先级

需要理解完整工作流程：

* ARP
* DHCP
* 路由器逐跳转发
* RIP 距离向量更新
* OSPF 链路状态
* RIP / OSPF / BGP 对比

### 第三优先级

掌握概念与关键区别：

* ICMP
* IP 组播与 IGMP
* IPv6
* IPv4/IPv6 过渡
* 移动 IP
* SDN

> **本章核心主线**
>
> ```text
> IP 地址确定“目标是谁”
>        ↓
> CIDR / 子网确定“目标在哪个网络”
>        ↓
> 路由协议帮助路由器建立路径信息
>        ↓
> 最长前缀匹配确定“下一跳往哪里走”
>        ↓
> ARP 确定“下一跳的 MAC 是什么”
>        ↓
> 数据链路层重新封装
>        ↓
> 路由器逐跳转发
>        ↓
> 最终到达目标主机
> ```
