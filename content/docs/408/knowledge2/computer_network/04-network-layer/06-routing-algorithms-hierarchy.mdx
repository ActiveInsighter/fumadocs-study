路由算法解决的是：

> **路由器应该依据什么信息，为各目的网络选择下一跳？**

## 4.6.1 静态路由与动态路由

| 项目 | 静态路由 | 动态路由 |
| --- | --- | --- |
| 建立方式 | 管理员手工配置 | 路由协议学习 |
| 拓扑变化 | 不自动适应 | 可自动收敛 |
| 控制开销 | 低 | 有协议通信和计算开销 |
| 适用环境 | 小型、稳定、缺省/固定路径 | 中大型或变化网络 |

静态与动态不是“谁绝对更优”，而是管理成本和自适应能力的取舍。

## 4.6.2 动态路由算法的两个核心家族

408 主线可分为：

```text
距离向量（Distance Vector）
链路状态（Link State）
```

前者典型协议是 RIP，后者典型协议是 OSPF。

## 4.6.3 距离向量算法

每个路由器主要维护：

```text
目的网络 → 当前距离 → 下一跳
```

它周期性或按协议规则从**邻居**得到对方的距离向量，再尝试更新自己的路由。

Bellman-Ford 思想可写为：

$$
D_x(y)=\min_v\left\{c(x,v)+D_v(y)\right\}
$$

其中：

- `x`：当前路由器；
- `y`：目的网络/结点；
- `v`：`x` 的邻居；
- `c(x,v)`：到邻居的代价；
- `D_v(y)`：邻居宣告的到目的地距离。

本质是：

> **“从哪个邻居走，邻居到目的地的代价 + 我到邻居的代价最小？”**

## 4.6.4 距离向量的计数到无穷

距离向量路由器没有完整拓扑图，可能出现“邻居告诉我还有路，但这条路其实又绕回我”的情况。

链路故障后，坏消息可能被相邻路由器来回传播：

```text
3 → 4 → 5 → 6 → ...
```

这就是**计数到无穷**，表现为“坏消息传得慢”。

常见缓解机制：

- 水平分割（Split Horizon）；
- 毒性逆转（Poison Reverse）；
- 触发更新（Triggered Update）。

这些机制能缓解部分环路，但不能改变距离向量算法缺少全局拓扑视角的根本特点。

## 4.6.5 链路状态算法

链路状态路由器的思路不同：

1. 发现自己的邻居；
2. 测量/确定本地链路代价；
3. 生成链路状态信息；
4. 把链路状态信息**泛洪**到区域内；
5. 各路由器构造较一致的链路状态数据库（LSDB）；
6. 在本地运行 Dijkstra，计算以自己为根的最短路径树；
7. 由最短路径树生成路由表/转发表。

## 4.6.6 距离向量 vs 链路状态

| 对比 | 距离向量 | 链路状态 |
| --- | --- | --- |
| 典型协议 | RIP | OSPF |
| 掌握的信息 | 到各目的地的距离 | 区域内链路拓扑 |
| 信息主要发给 | 邻居 | 区域内泛洪 |
| 交换内容 | 距离向量 | 链路状态 |
| 算法思想 | Bellman-Ford | Dijkstra |
| 全局拓扑视角 | 无 | 有 |
| 环路/慢收敛 | 更典型 | 相对较少 |

## 4.6.7 为什么需要层次路由

如果整个互联网所有路由器都维护全球完整拓扑：

- 路由表会极其庞大；
- 状态传播开销过高；
- 管理策略难以自治；
- 任一变化都可能波及全球控制平面。

因此互联网按自治系统（AS）分层：

```text
AS 内：IGP（如 RIP、OSPF）
AS 间：EGP（核心是 BGP）
```

这既控制规模，也允许不同组织拥有不同路由策略。

## 4.6.8 OSPF 内部还可进一步分区

在较大的 OSPF 自治系统内部，可以使用 Area 进一步层次化：

- 区域内详细维护拓扑；
- 区域间通过边界路由器交换汇总信息；
- 骨干区域用于连接其他区域。

408 若考“层次路由”，重点理解**减少状态规模、限制更新传播范围、便于自治管理**，不必把所有工程配置细节背下来。

## 4.6.9 路由算法题的判断关键词

```text
“只和邻居交换距离”      → 距离向量
“坏消息慢 / 计数到无穷” → 距离向量
“链路状态泛洪 / LSDB”   → 链路状态
“Dijkstra”              → 链路状态
“AS 内 / AS 间”          → 层次路由
```
