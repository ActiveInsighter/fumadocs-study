IPv4 分片题看似字段多，实际只有三个关键量：

```text
每片最多装多少数据？
这片从原始数据的哪个字节开始？
这片后面还有没有原始数据？
```

> **真题标签**
>
> IPv4 分片：2021 年第 36 题；2018 年第 47 题。

## 4.3.1 IPv4 首部的整体结构

IPv4 固定首部为 **20 Byte**；存在 Options 时可以更长。

| 字段 | 长度 | 408 重点 |
| --- | ---: | --- |
| Version | 4 bit | IPv4 中为 4 |
| IHL | 4 bit | 首部长度，以 4 Byte 为单位 |
| DS/服务字段 | 8 bit | 服务质量相关 |
| Total Length | 16 bit | 首部 + 数据的总长度 |
| Identification | 16 bit | 标识同一原始数据报的分片 |
| Flags | 3 bit | 重点是 DF、MF |
| Fragment Offset | 13 bit | 分片数据相对原始数据区起点的位置，单位 8 Byte |
| TTL | 8 bit | 每经一台路由器减 1 |
| Protocol | 8 bit | 标识上层协议 |
| Header Checksum | 16 bit | 只校验 IPv4 首部 |
| Source / Destination | 各 32 bit | 源/目的 IPv4 地址 |

## 4.3.2 IHL 与总长度

IHL 以 **4 Byte** 为单位：

```text
IHL = 5
→ 首部 = 5 × 4 = 20 Byte
```

总长度字段为 16 bit，因此 IPv4 数据报理论最大总长度为：

$$
2^{16}-1=65535\text{ Byte}
$$

注意 `Total Length` 包含：

```text
IPv4 首部 + IPv4 数据
```

## 4.3.3 TTL 与 Protocol

每经过一个路由器：

```text
TTL ← TTL - 1
```

若减为 0，路由器丢弃该数据报并通常返回 ICMP Time Exceeded。

常见 `Protocol` 值：

| 上层/控制协议 | 值 |
| --- | ---: |
| ICMP | 1 |
| TCP | 6 |
| UDP | 17 |

## 4.3.4 IPv4 首部校验和

IPv4 Header Checksum：

- **只覆盖 IPv4 首部**；
- 不校验数据字段；
- 路由器修改 TTL 后，首部内容发生变化，因此需要更新校验和。

<Callout type="warn" title="IPv4 与 TCP/UDP 校验范围不同">
不能看到“checksum”就认为一定覆盖整个报文。IPv4 首部校验和只校验 IP 首部；TCP/UDP 有自己的校验机制。
</Callout>

## 4.3.5 MTU 与为什么需要分片

MTU（Maximum Transmission Unit）表示某条链路一次能够承载的**最大网络层数据报长度**。

以太网常见 MTU：

```text
1500 Byte
```

若 IPv4 数据报超过下一跳链路 MTU：

- `DF=0`：允许分片；
- `DF=1`：禁止分片，路由器丢弃并可通过 ICMP 告知“需要分片”。

## 4.3.6 三个分片字段

### Identification

同一原始 IPv4 数据报产生的所有分片拥有相同的 Identification。

### MF：More Fragments

- `MF=1`：原始数据报在本片后面还有数据；
- `MF=0`：这是**整个原始数据报**的最后一片。

### Fragment Offset

Offset 相对于**原始 IPv4 数据区的起点**计算，单位是 8 Byte：

$$
\text{Offset}=\frac{\text{该片数据在原数据区中的字节偏移}}{8}
$$

<Callout type="warn" title="再次分片时 Offset 不重新从 0 计">
再次分片仍以最初原始数据报的数据区为参照，而不是以“当前父分片”为参照。
</Callout>

## 4.3.7 每个非最后分片最多装多少数据

设：

- MTU 为 `M`；
- 当前 IPv4 首部长度为 `H`。

由于后续分片的 Offset 以 8 Byte 为单位，非最后分片的数据长度取不超过 `M-H` 的最大 8 的倍数：

$$
L_{\max}=8\left\lfloor\frac{M-H}{8}\right\rfloor
$$

这是分片计算最重要的公式。

## 4.3.8 一次分片示例

设：

```text
首部 H = 20 Byte
原始数据 = 10000 Byte
MTU M = 4000 Byte
```

每个非最后分片最大数据量：

$$
L_{\max}=8\left\lfloor\frac{4000-20}{8}\right\rfloor=3976\text{ Byte}
$$

因此：

| 分片 | 数据长度 | 总长度 | 原数据字节偏移 | Offset | MF |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 3976 | 3996 | 0 | 0 | 1 |
| 2 | 3976 | 3996 | 3976 | 497 | 1 |
| 3 | 2048 | 2068 | 7952 | 994 | 0 |

因为：

$$
3976/8=497,\qquad 7952/8=994
$$

## 4.3.9 再次分片怎么做

若上表的“分片 1”继续经过 MTU 为 `2500 Byte` 的链路：

$$
8\left\lfloor\frac{2500-20}{8}\right\rfloor=2480\text{ Byte}
$$

分片 1 再拆为：

| 新分片 | 数据长度 | 总长度 | 相对原始数据偏移 | Offset | MF |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1.1 | 2480 | 2500 | 0 | 0 | 1 |
| 1.2 | 1496 | 1516 | 2480 | 310 | 1 |

`1.2` 虽然是“分片 1 的最后一片”，但原始数据报后面还有原来的分片 2、3，因此其 `MF` 仍为 1。

## 4.3.10 分片题固定检查表

每做完一片都检查：

1. `总长度 ≤ MTU`；
2. 非原始最后片的数据长度通常为 8 的倍数；
3. 所有分片 Identification 相同；
4. Offset 是“原数据字节偏移 ÷ 8”；
5. 只有原始数据最后一个分片 `MF=0`；
6. IPv4 分片通常在**最终目的主机**重组，中间路由器不负责重组。
