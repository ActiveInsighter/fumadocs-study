RIP、OSPF、BGP 不应作为三个孤立协议背诵，而应先定位它们所处的层次：

```text
一个 AS 内部：RIP / OSPF
不同 AS 之间：BGP
```

> **真题标签**
>
> 路由协议综合辨析：2010 年第 35 题、2017 年第 37 题、2026 年第 38 题；2013、2014、2024 年综合题。
>
> RIP 更新：2021 年第 37 题。

## 4.7.1 自治系统、IGP 与 EGP

自治系统（Autonomous System，AS）是由同一管理机构控制、具有统一对外路由策略的一组网络。

- **IGP**：在一个 AS 内使用，如 RIP、OSPF；
- **EGP**：不同 AS 间使用，现代互联网核心协议为 BGP。

## 4.7.2 三大协议总表

| 项目 | RIP | OSPF | BGP |
| --- | --- | --- | --- |
| 范围 | AS 内 | AS 内 | AS 间 |
| 类型 | 距离向量 | 链路状态 | 路径向量 |
| 核心算法 | Bellman-Ford 思想 | Dijkstra | 策略驱动的路径选择 |
| 主要交换信息 | 目的网络与距离 | 链路状态 | 前缀 + 路径属性 |
| 传播方式 | 与邻居交换 | 区域内 LSA 泛洪 | BGP 邻居会话 |
| 全局拓扑 | 不掌握 | 区域内有 LSDB | 不构造全球内部拓扑图 |
| 承载 | UDP | 直接封装在 IP | TCP |
| 适合规模 | 较小 | 中大型 AS | Internet 跨 AS |

## 4.7.3 RIP

RIP 使用**跳数**作为度量：

```text
15 跳：最大可达距离
16 跳：不可达
```

典型更新过程：

1. 先知道直连网络；
2. 从邻居接收距离向量；
3. 对邻居宣告距离加上到邻居的代价；
4. 与当前项比较并更新下一跳；
5. 多轮交换后逐渐收敛。

RIP 的典型弱点是：

- 度量过于简单；
- 网络规模受“16=无穷”限制；
- 发生故障时可能计数到无穷，收敛较慢。

## 4.7.4 OSPF

OSPF 是链路状态型 IGP。核心对象：

```text
LSA → 泛洪 → LSDB → Dijkstra → 最短路径树 → 路由表
```

每台路由器把自己的邻接和链路代价等状态生成 LSA，在区域内传播。各路由器根据 LSDB 独立运行 Dijkstra。

相比 RIP，OSPF：

- 拥有更完整的区域拓扑视图；
- 拓扑变化后通常收敛更快；
- 可使用层次化区域减小规模；
- 度量不局限于简单跳数。

<Callout type="warn" title="OSPF 不使用 TCP/UDP">
OSPF 直接封装在 IP 中。不要看到“路由协议”就默认它一定使用 UDP 或 TCP。
</Callout>

## 4.7.5 BGP

BGP 是**路径向量协议**，用于 AS 之间交换可达前缀及路径属性。

它关注的不只是“代价最小”，还要考虑运营策略。例如：

- 是否接受某条路由；
- 是否把某条路由继续通告给邻居；
- 更偏好哪个出口；
- 是否允许经过某个 AS。

因此：

> **BGP 的目标不是单纯寻找数学意义上的最短路径，而是在策略约束下选择可接受的跨 AS 路径。**

## 4.7.6 AS_PATH 为什么重要

BGP 路由可携带所经过的 AS 序列。它至少有两类直观作用：

1. 帮助进行跨 AS 的路径选择；
2. 如果自己的 AS 号已经出现在收到的 AS_PATH 中，可判断该通告会形成 AS 级环路并拒绝。

## 4.7.7 BGP 为什么用 TCP

BGP 邻居需要长期、可靠地交换路由更新，因此建立在 TCP 会话之上。

与 RIP 的周期性整表思想不同，BGP 更强调在路由变化时发送增量 UPDATE，如：

- 宣告新前缀；
- 修改路径属性；
- 撤销不可达前缀。

## 4.7.8 三协议最容易混淆的五组关系

```text
RIP  → 距离向量 → Bellman-Ford → UDP → 跳数
OSPF → 链路状态 → Dijkstra     → IP  → LSA/LSDB
BGP  → 路径向量 → 策略选择     → TCP → AS_PATH 等属性
```

再补两条：

```text
RIP / OSPF：IGP
BGP：EGP
```

## 4.7.9 综合题怎么把协议与转发联系起来

路由协议本身通常不逐包转发数据。正确关系是：

```text
RIP / OSPF / BGP
        ↓
学习或计算路由
        ↓
形成路由表/转发表
        ↓
数据报到来
        ↓
最长前缀匹配
        ↓
选择下一跳
```

所以“路由协议”解决的是控制平面信息来源，“最长前缀匹配”才是具体数据报转发时的查表规则。
