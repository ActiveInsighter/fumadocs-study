SDN 是网络层“控制平面与数据平面分离”的代表性思想；本节最后再把全章压缩成综合题可直接使用的固定动作。

> **真题标签**
>
> SDN：2022 年第 37 题。

## 4.10.1 SDN 的核心思想

传统网络设备中，单台路由器往往同时承担：

```text
控制：学习/计算路由、形成策略
数据：按表转发每个分组
```

SDN（Software Defined Networking）把控制逻辑从单个转发设备中抽离，使网络控制器逻辑集中地计算策略，设备重点执行高速转发。

核心关系：

```text
控制平面：决定“应该怎么转”
数据平面：执行“按规则转”
```

## 4.10.2 数据平面

SDN 转发设备可依据流表执行：

- 匹配报文字段；
- 从指定端口转发；
- 丢弃；
- 修改部分首部字段；
- 送往控制器；
- 跳转到后续流表。

数据平面要求每包高速处理。

## 4.10.3 控制平面

控制器可负责：

- 获取拓扑和设备状态；
- 运行网络控制逻辑；
- 计算转发策略；
- 向设备下发/修改流表；
- 响应链路和拓扑变化。

“逻辑集中”并不等于物理上必须只有一台服务器；工程上可以由控制器集群共同实现。

## 4.10.4 流表的 match-action 思想

一个典型流表项可理解成：

```text
匹配字段 + 优先级 + 计数器 + 动作/指令
```

匹配字段可以来自多个层次，例如：

- 源/目的 MAC；
- VLAN；
- 源/目的 IP；
- 传输层端口；
- 协议类型。

因此 SDN 的“流”可以比传统只按目的 IP 的转发表更灵活。

## 4.10.5 南向、北向与东西向

| 接口方向 | 连接关系 | 典型作用 |
| --- | --- | --- |
| 南向 | Controller ↔ 转发设备 | 下发规则、上报状态；OpenFlow 是典型例子 |
| 北向 | 网络应用 ↔ Controller | 应用提交策略、读取抽象网络状态 |
| 东西向 | Controller ↔ Controller | 多控制器之间协同 |

408 对 SDN 以基本概念为主，不需要把工程 API 细节当主线背诵。

## 4.10.6 一次跨网通信的完整链路

假设：

```text
A：192.168.1.10/24
默认网关：192.168.1.1
B：10.0.0.20
```

### ① A 判断目标是否同子网

```text
A_IP AND Mask
B_IP AND Mask
```

不相等，因此下一跳是默认网关。

### ② A 通过 ARP 获得网关 MAC

A 不查询 B 的 MAC，而查询：

```text
192.168.1.1 → 网关 MAC
```

### ③ A 封装第一跳

```text
IP：  Src=192.168.1.10, Dst=10.0.0.20
MAC： Src=A_MAC,         Dst=Gateway_MAC
```

### ④ 路由器逐跳处理

每台普通 IPv4 路由器：

1. 拆当前链路层帧；
2. TTL 减 1；
3. 按目的 IP 做最长前缀匹配；
4. 得到下一跳和输出接口；
5. 必要时 ARP；
6. 重新封装新的链路层帧。

若发生 NAT，则 IP/端口会按映射改变；若数据报大于 MTU 且允许分片，则 IPv4 还可能分片。

### ⑤ 最后一跳

最终路由器发现 B 所在网络是直连网络，于是 ARP B 的 MAC，并把数据报封装为目的 MAC=B 后交付。

## 4.10.7 网络大题的三套口径

### 地址口径

先写：

```text
IP/Mask → 网络地址 → 是否同网段 → 下一跳
```

地址题再分：

```text
切：VLSM/FLSM
聚：路由聚合
查：最长前缀匹配
```

### 封装口径

始终分开：

```text
IP 地址：描述端到端网络层通信
MAC 地址：描述当前一跳链路层通信
```

普通路由时：

```text
IP 源/目的通常不变
MAC 源/目的逐跳变化
TTL 逐跳减 1
```

### 路由口径

```text
路由协议 → 建表
目的 IP → 最长前缀匹配
路由表项 → 下一跳/接口
ARP → 下一跳 MAC
```

## 4.10.8 全章高频易错表

| 易错点 | 正确结论 |
| --- | --- |
| ARP 查谁的 MAC | 当前链路的下一跳；跨网时通常是网关 |
| 路由器是否改变源/目的 IP | 普通转发不改；NAT 是例外 |
| MAC 是否端到端不变 | 否，通常每跳重封装 |
| TTL | 每过一台路由器减 1 |
| IPv4 checksum | 只校验 IPv4 首部 |
| Fragment Offset | 单位 8 Byte，基于原始数据报数据区 |
| 分片 ID | 同一原始数据报的所有分片相同 |
| IPv4 分片重组 | 通常仅目的主机重组 |
| 最长前缀匹配 | 选匹配的 `/n` 最大者 |
| 默认路由 | `0.0.0.0/0` |
| RIP | 距离向量，16 跳表示不可达 |
| OSPF | 链路状态，Dijkstra |
| BGP | AS 间路径向量，策略驱动，TCP |
| DHCP | Discover → Offer → Request → ACK |
| ping | ICMP Echo Request/Reply |
| traceroute | TTL 递增 + ICMP Time Exceeded |
| IPv6 首部 | 基本首部固定 40 Byte，无首部校验和 |
| IPv6 分片 | 路由器不做传统中途分片 |
| IPv6 广播 | 无传统广播地址 |
| NAT | 地址转换，不等于防火墙 |
| SDN | 控制平面与数据平面分离 |

## 4.10.9 复习优先级

### 第一优先级：必须会算

- IPv4 网络地址、广播地址、主机范围；
- 前缀长度与掩码转换；
- VLSM/FLSM；
- 路由聚合；
- IPv4 分片；
- 最长前缀匹配；
- NAT 映射中的地址/端口变化。

### 第二优先级：必须能讲完整流程

- ARP 同网段/跨网段；
- DHCP DORA；
- 路由器逐跳转发；
- RIP/OSPF/BGP 区别；
- ping/traceroute。

### 第三优先级：掌握关键区别

- IPv6；
- IP 组播与 IGMP；
- 移动 IP；
- SDN。

<Callout type="info" title="本章一句话主线">
**IP 前缀回答“目标在哪个网络”，路由协议帮助设备“建表”，最长前缀匹配决定“下一跳”，ARP 决定“下一跳用哪个 MAC 发”，链路层再逐跳重新封装。**
</Callout>
