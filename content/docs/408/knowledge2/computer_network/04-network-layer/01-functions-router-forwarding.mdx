网络层解决的是：**当源主机和目的主机不在同一条链路、甚至不在同一种底层网络中时，如何把 IP 数据报跨越多个网络送到目的主机。**

本章主线可以压缩成：

```text
地址与子网 → 路由计算 → 转发表 → 最长前缀匹配
    ↓                         ↓
ARP / DHCP / ICMP / NAT    逐跳重新封装
    ↓                         ↓
IPv4 / IPv6              最终交付目的主机
```

<Callout type="info" title="网络层的核心对象">
网络层关注的是 **IP 数据报、IP 地址、网络前缀、下一跳和路由器**。MAC 地址只在当前链路上起作用，端口号主要属于传输层。
</Callout>

## 4.1.1 网络层提供什么服务

IP 提供的是**无连接、尽最大努力交付（Best Effort）**&#x2060;的数据报服务：

- 发送前不建立网络层连接；
- 每个数据报可独立路由；
- IP 本身不保证不丢失、不重复、不失序；
- 端到端可靠性若需要，通常由 TCP 等端系统协议实现。

因此不能把“IP 能把数据报送往目的网络”理解成“IP 保证可靠到达”。

## 4.1.2 异构网络互联

不同局域网可能采用不同的链路层技术、帧格式、MTU 和物理介质。网络层通过统一的 IP 数据报格式，把这些异构网络连接成逻辑上的互联网。

逐跳转发时，路由器会：

1. 从输入链路取出 IP 数据报；
2. 根据目的 IP 选择下一跳；
3. 在输出链路上重新封装新的链路层帧。

所以一条端到端通信中通常存在：

```text
IP 数据报：跨多跳持续存在
链路层帧：每一跳重新生成
```

## 4.1.3 路由与转发必须区分

| 概念 | 解决的问题 | 典型所在平面 |
| --- | --- | --- |
| **路由 Routing** | 到某个目的网络应该走哪条路径 | 控制平面 |
| **转发 Forwarding** | 当前这个数据报从哪个输出接口发出 | 数据平面 |

可记为：

```text
路由：算路、建表
转发：查表、发包
```

路由协议产生或维护路由信息；数据平面根据已经形成的转发表高速处理每个数据报。

> **真题标签**
>
> 路由器与分组转发：2012 年第 37 题、2015 年第 38 题；2009、2013、2014、2018、2019、2020 年均出现过相关综合题。

## 4.1.4 路由器的基本组成

典型路由器可抽象为四部分：

```text
输入端口 ─┐
输入端口 ─┼→ 交换结构 → 输出端口
输入端口 ─┘                输出端口
              ↑
          路由处理器
```

### 输入端口

负责接收物理信号、处理链路层帧，并把 IP 数据报送入交换结构；高速路由器往往会在输入端口附近完成转发表查询。

### 交换结构

把数据从正确的输入端口内部搬运到正确的输出端口。

### 输出端口

负责排队、链路层封装和物理发送。

### 路由处理器

运行路由协议、维护控制状态，并生成供数据平面使用的转发表。

## 4.1.5 数据平面与控制平面

传统路由器中，两者都存在于路由设备内部：

- **数据平面**：每包处理，要求快；
- **控制平面**：计算路径、维护网络状态，变化频率低得多。

SDN 则进一步把控制逻辑从单个设备中抽离出来，由逻辑集中式控制器负责，这将在本章末单独整理。

## 4.1.6 一次普通 IPv4 转发会做什么

路由器收到一个 IPv4 数据报后，典型逻辑是：

1. 接收并拆除当前链路层帧；
2. 检查 IPv4 首部；
3. TTL 减 1；
4. 若 TTL 为 0，则丢弃并通常返回 ICMP Time Exceeded；
5. 用目的 IP 查询转发表；
6. 按**最长前缀匹配**确定下一跳/输出接口；
7. 若下一跳 MAC 未知，则在当前链路上通过 ARP 解析；
8. 需要时执行 IPv4 分片或 NAT；
9. 因 TTL 等字段变化而重新计算 IPv4 首部校验和；
10. 用新的链路层源/目的地址封装并发出。

<Callout type="warn" title="逐跳转发时哪些字段会变">
普通路由器通常**不改源 IP 和目的 IP**；但 TTL 会变化，IPv4 首部校验和随之变化，源/目的 MAC 地址也会因重新封装而逐跳变化。NAT 是会改 IP/端口的特殊情况。
</Callout>

## 4.1.7 拥塞与流量控制不是一回事

网络层大纲要求理解**拥塞控制**的基本概念。

- **流量控制**：防止发送方压垮某个接收方；
- **拥塞控制**：防止过多流量压垮网络内部的链路、缓存和路由器。

拥塞典型表现为：

```text
到达速率过大
→ 路由器队列增长
→ 排队时延上升
→ 缓冲区耗尽
→ 丢包增加
```

网络层可通过路由调整、队列管理、显式拥塞通知等方式参与拥塞治理；TCP 还会在端系统侧执行端到端拥塞控制。

## 4.1.8 本节最小知识闭环

```text
路由协议/控制逻辑
        ↓
      路由信息
        ↓
      转发表
        ↓
目的 IP → 最长前缀匹配 → 下一跳/输出接口
        ↓
   新链路层帧逐跳转发
```

后续所有 IPv4 地址题、ARP、路由协议和综合题，都建立在这条链路上。
