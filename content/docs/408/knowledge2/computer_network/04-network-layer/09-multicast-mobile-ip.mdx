组播解决“一份数据发给一组接收者”，移动 IP 解决“主机移动后身份如何保持稳定”。两者都属于网络层较偏概念的内容。

## 4.9.1 单播、广播、组播

| 模式 | 通信关系 | 网络行为 |
| --- | --- | --- |
| 单播 | 一对一 | 按单个目的地址转发 |
| 广播 | 一对当前广播域所有节点 | 向广播域全部节点扩散 |
| 组播 | 一对一组成员 | 只沿存在组成员的方向复制 |

组播的目标是避免发送方为 `n` 个接收者重复发送 `n` 份完全相同的数据。

## 4.9.2 IPv4 组播地址

IPv4 组播使用原 D 类地址范围：

```text
224.0.0.0 ~ 239.255.255.255
= 224.0.0.0/4
```

组播地址表示的是**组**，不是一个普通单播主机地址。

## 4.9.3 IGMP 做什么

IGMP（Internet Group Management Protocol）用于 IPv4 主机与本地组播路由器之间进行**组播成员关系管理**。

主机可借助 IGMP：

- 表达加入某个组；
- 维持成员关系；
- 表达/触发离开相关组的状态变化。

要区分：

> **IGMP 管“本地网络里谁对某组感兴趣”，组播路由协议管“组播流量跨路由器怎样走”。**

408 通常更关注前者的基本概念。

## 4.9.4 组播为什么不是普通广播

广播会把数据交给当前广播域中的所有节点；组播只希望把数据送往含有目标组成员的网络分支。

因此理想的组播转发树会在必要的分叉点复制数据，而不是在源端复制很多份，也不是向整个互联网泛洪。

## 4.9.5 移动 IP 要解决的矛盾

传统 IP 地址同时带有两层含义：

```text
“你是谁” + “你现在接在哪个网络”
```

主机移动后，若直接换成新网络前缀，原有对外身份和通信连续性会受到影响。

移动 IP 的核心目标是：

> **移动节点换了接入网络，仍尽可能以稳定的归属地址被通信对端识别。**

## 4.9.6 移动 IP 的关键角色

- **归属地址 Home Address**：移动节点稳定的逻辑身份地址；
- **归属网络 Home Network**：归属地址所属网络；
- **归属代理 Home Agent**：在归属网络中帮助转交数据；
- **转交地址 Care-of Address**：节点在外地网络当前位置的可达地址。

## 4.9.7 典型通信过程

```text
① 移动节点离开归属网络
② 在外地网络获得转交地址
③ 向归属代理登记当前位置
④ 通信对端仍把数据发往归属地址
⑤ 归属代理截获相关数据
⑥ 归属代理建立隧道送往转交地址
⑦ 移动节点在外地网络收到数据
```

回到归属网络后，可恢复普通本地交付。

## 4.9.8 为什么会出现“三角路由”

经典移动 IP 中可能出现：

```text
通信对端 → 归属代理 → 移动节点
移动节点 → 通信对端（可能直接返回）
```

去程绕过归属网络形成三角形路径，可能不是最短路径。这是移动性与位置透明性之间的代价之一。

## 4.9.9 本节复习优先级

组播与移动 IP 通常以概念辨析为主，优先掌握：

```text
224/4 → IPv4 组播
IGMP → 本地成员管理
Home Address → 稳定身份
Care-of Address → 当前外地位置
Home Agent → 截获 + 隧道转交
```
