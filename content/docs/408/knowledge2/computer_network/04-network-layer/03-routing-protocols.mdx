## 16. 路由、直连路由与静态/动态路由

跨网段通信时，路由器需要知道：

```text
到某个目的前缀，下一跳是谁、从哪个接口走？
```

路由来源主要包括：

- **直连路由**：接口配置并启用后直接得到；
- **静态路由**：管理员手工配置；
- **动态路由**：通过路由协议学习。

### 16.1 静态路由与动态路由

<InlineSvg src="/images/computer-network/computer-network-network-route-012.svg" alt={"路由算法 图 12"} />
<InlineSvg src="/images/computer-network/computer-network-network-route-001.svg" alt={"路由算法 图 1"} />

| 项目 | 静态路由 | 动态路由 |
| --- | --- | --- |
| 生成方式 | 人工配置 | 协议自动学习 |
| 拓扑变化 | 一般需人工调整 | 可自动重新收敛 |
| 控制开销 | 低 | 需要协议消息与计算 |
| 适用场景 | 小型、稳定、默认/特定路径 | 中大型、拓扑变化较多 |

动态路由协议的任务是帮助路由器获得**可达前缀、代价、路径属性等信息**，最终形成可供转发使用的路由。

### 16.2 动态路由算法题先分两类

<Tabs items={["距离向量", "链路状态"]}>
<Tab value="距离向量">

路由器只从邻居得到“邻居到各目的有多远”，再做 Bellman-Ford 式更新：

$$
D_x(y)=\min_v\{c(x,v)+D_v(y)\}
$$

典型协议：RIP。

</Tab>
<Tab value="链路状态">

路由器先通过泛洪获得某范围内的拓扑/链路代价，再在本地运行 Dijkstra/SPF：

```text
收集链路状态 → 构图 → 以自己为源跑 SPF → 得到下一跳
```

典型协议：OSPF。

</Tab>
</Tabs>

<Callout type="warning" title="算法和协议是两个层次">

“距离向量、链路状态”是算法思想；RIP、OSPF 是具体路由协议。题目问“链路状态算法”时，不一定要求你背 OSPF 报文字段；题目问“OSPF”时，也不能只答一句 Dijkstra。

</Callout>

## 17. 自治系统、IGP 与 EGP

<InlineSvg src="/images/computer-network/computer-network-network-route-002.svg" alt={"路由算法 图 2"} />
<InlineSvg src="/images/computer-network/computer-network-network-route-003.svg" alt={"路由算法 图 3"} />
<InlineSvg src="/images/computer-network/computer-network-network-route-004.svg" alt={"路由算法 图 4"} />

> **真题考察**
>
> * 选择题：2010 年第 35 题、2017 年第 37 题、2026 年第 38 题
> * 解答题：2013 年第 47 题、2014 年第 42 题、2024 年第 47 题

### 17.1 自治系统 AS

自治系统（Autonomous System，AS）是一组受共同管理并采用统一对外路由策略的 IP 网络与路由器集合。

典型 AS 可以是：

- ISP；
- 大型企业网络；
- 大学校园网络；
- 云服务商网络。

### 17.2 IGP 与 EGP

按使用范围：

**IGP（Interior Gateway Protocol）**：一个 AS 内部使用，例如：

```text
RIP、OSPF
```

**EGP（Exterior Gateway Protocol）**：不同 AS 之间使用。现代 Internet 的核心协议是：

```text
BGP
```

### 17.3 层次路由为什么必要

Internet 规模巨大，若每台路由器都维护全球最细粒度拓扑并频繁交换全部信息，存储、计算和控制报文开销都难以承受。层次路由通过“**分域管理 + 聚合信息**”降低复杂度：

```text
Internet
  ↓ 按管理边界分为 AS
AS 内部：IGP
AS 之间：BGP
```

OSPF 还可在一个 AS 内继续划分 Area，把链路状态泛洪和 SPF 计算限制在合理范围内。

层次化的代价是：上层往往只看到聚合后的信息，因此得到的路径可能不如“全局完整信息下的理论最优路径”细致。

### 17.4 RIP、OSPF、BGP 总览

| 项目 | RIP | OSPF | BGP |
| --- | --- | --- | --- |
| 范围 | IGP | IGP | EGP |
| 基本思想 | 距离向量 | 链路状态 | 路径向量/策略 |
| 承载 | UDP | 直接封装在 IP 中 | TCP |
| 常考端口/协议号 | UDP 520 | IP Protocol 89 | TCP 179 |
| 核心算法 | Bellman-Ford 思想 | Dijkstra/SPF | 策略选路 |
| 传播内容 | 目的前缀与距离 | 链路状态 LSA | 前缀与路径属性 |
| 信息范围 | 邻居交换 | 区域内泛洪 | BGP 邻居会话 |

<Callout type="warning" title="不要把三者都理解成‘算最短路’">

RIP 关注跳数，OSPF 根据链路状态计算最短路径树；BGP 的目标是**策略驱动的跨 AS 可达性选择**，不等价于寻找数学意义上的最短路径。

</Callout>

## 18. RIP 与距离向量算法

RIP（Routing Information Protocol）是典型距离向量 IGP，使用**跳数**作为主要度量。

最重要的两个数字：

```text
15：最大有效跳数
16：不可达
```

### 18.1 距离向量的含义

<InlineSvg src="/images/computer-network/computer-network-network-route-006.svg" alt={"路由算法 图 6"} />

路由器维护“到各目的前缀的距离与下一跳”，并把自己的距离信息发送给相邻 RIP 路由器。

抽象地说，路由器 $x$ 到目的 $y$ 的最佳距离满足：

$$
D_x(y)=\min_v\{c(x,v)+D_v(y)\}
$$

其中：

- $v$：某个邻居；
- $c(x,v)$：到邻居的代价；
- $D_v(y)$：邻居声明的到目的距离。

对于 RIP，可把跨过一个相邻路由器理解为跳数增加 1。

### 18.2 RIP 更新流程

<InlineSvg src="/images/computer-network/computer-network-network-route-005.svg" alt={"路由算法 图 5"} />

> **真题考察**
>
> * 选择题：2021 年第 37 题

基本过程：

1. 先获得直连网络；
2. 周期性与邻居交换距离向量；
3. 收到邻居表后，对相应距离加上到邻居的代价；
4. 比较当前路由与候选路由；
5. 更新更优或协议规则要求替换的表项；
6. 多轮交换后逐渐收敛。

经典 RIP 周期更新约为 30 s。

#### 18.2.1 408 常见 RIP 表更新规则

假设从邻居 $N$ 收到“到目的 $D$ 的距离为 $d$”，经 $N$ 的候选距离通常先变为：

$$
d'=\min(d+1,16)
$$

然后分两种情况：

- **当前到 $D$ 的下一跳就是 $N$**：即使 $d'$ 变大，也应按来自同一下一跳的新信息更新；
- **当前下一跳不是 $N$**：只有候选路由更优时才替换；若等价是否替换取决于题目给定规则。

<Callout type="warning" title="RIP 更新最容易错的地方">

“只接受更小距离”并不总对。若原路由本来就是经邻居 $N$ 学来的，而 $N$ 告诉你该路径变差甚至不可达，你必须接受这个坏消息，否则会长期保留过期路由。

</Callout>

### 18.3 “坏消息传得慢”与计数到无穷

<InlineSvg src="/images/computer-network/computer-network-network-route-007.svg" alt={"路由算法 图 7"} />

距离向量路由器并不掌握完整拓扑，可能把邻居宣告的路径误认为独立路径，产生环路。

例如：

```text
A --- B --- C --- X
```

若 `C-X` 断开，A、B 可能暂时互相把对方当作“仍然能到 X 的下一跳”，距离不断增大：

```text
4 → 5 → 6 → ... → 16
```

这就是 **Count to Infinity**。

常见缓解机制：

- 水平分割（Split Horizon）；
- 毒性逆转（Poison Reverse）；
- 触发更新（Triggered Update）。

它们可以减轻问题，但不能把距离向量协议变成“拥有完整拓扑”的链路状态协议。

### 18.4 RIPv1 与 RIPv2 的理解

RIPv1 属于早期分类路由协议，不携带现代 CIDR 所需的完整掩码信息；RIPv2 支持无类别路由信息，更适合 VLSM/CIDR。

408 若题目只写 RIP 而未区分版本，通常考跳数、距离向量更新和 15/16 跳等共同核心。

## 19. OSPF 与链路状态路由

OSPF（Open Shortest Path First）是典型链路状态型 IGP。

与 RIP 最根本的思维差异：

```text
RIP：告诉邻居“我到各目的有多远”
OSPF：发布“我有哪些链路、它们的状态/代价是什么”
```

### 19.1 LSA 与泛洪

路由器把自己的邻接关系、链路代价等信息形成链路状态通告（LSA），并在 OSPF 的相应区域内可靠泛洪。

结果是：同一区域中稳定收敛后的 OSPF 路由器，通常拥有一致或高度一致的 **LSDB（Link State Database）**。

### 19.2 LSDB 与 SPF

<InlineSvg src="/images/computer-network/computer-network-network-route-008.svg" alt={"路由算法 图 8"} />

LSDB 描述的是网络拓扑，而不是简单的“别人已经算好的距离表”。路由器根据 LSDB 构建拓扑图，并以自己为根运行 Dijkstra/SPF，得到最短路径树，再形成路由。

Dijkstra 题可以用“已确定集合 $S$ + 暂定距离”来做：

1. 源点距离置 0，其余置 $\infty$；
2. 每轮选暂定距离最小且未确定的结点加入 $S$；
3. 用该结点松弛其邻接边；
4. 重复直到求出目标或全部结点。

若题目还要求路由表，除了最短距离，还要记录**从源路由器出发的第一跳/输出接口**。

> **真题范围**
>
> 2026 年第 37 题：链路断开后，链路状态数据库中的拓扑发生变化；应基于新拓扑重新跑最短路径，再把具有相同转发接口的连续目的前缀尝试聚合。

### 19.3 OSPF 的层次化

大型 OSPF 网络可以划分多个 Area，避免所有路由器都处理整个 AS 的全部链路状态。骨干区域通常为 Area 0。

> **真题范围**
>
> 2026 年第 38 题：在 RIP、OSPF、BGP 中，能够把一个自治系统进一步划分为多个区域的 IGP 是 **OSPF**。

因此“OSPF 每台路由器都拥有整个 AS 的完整拓扑”是一种过度简化；更准确地说，应结合**区域**理解链路状态数据库的范围。

### 19.4 RIP 与 OSPF 对比

<InlineSvg src="/images/computer-network/computer-network-network-route-009.svg" alt={"路由算法 图 9"} />

| 维度 | RIP | OSPF |
| --- | --- | --- |
| 掌握信息 | 到目的的距离 | 区域内链路状态 |
| 信息主要发给 | 邻居 | 区域内泛洪 |
| 计算思想 | Bellman-Ford | Dijkstra/SPF |
| 度量 | 跳数 | Cost |
| 拓扑视图 | 无完整图 | 可构造区域拓扑图 |
| 收敛 | 通常较慢 | 通常更快 |
| 环路问题 | 距离向量经典问题明显 | 收敛后依赖一致 LSDB 与 SPF |

## 20. BGP 与路径向量

<InlineSvg src="/images/computer-network/computer-network-network-route-010.svg" alt={"路由算法 图 10"} />
<InlineSvg src="/images/computer-network/computer-network-network-route-011.svg" alt={"路由算法 图 11"} />

BGP（Border Gateway Protocol）负责 **AS 之间的路由可达性传播与策略选路**。当前 Internet 广泛使用 BGP-4。

### 20.1 BGP 邻居与 TCP

BGP 路由器（BGP Speaker）与其他 BGP 邻居建立会话，底层使用：

```text
TCP 179
```

可靠字节流由 TCP 提供，BGP 在其上交换前缀与路径属性。

### 20.2 AS_PATH 与路径向量

BGP 的路由通告不仅表示“某前缀可达”，还带有路径属性，典型包括经过的 AS 序列 `AS_PATH`。

`AS_PATH` 的重要作用之一是：

- 表示跨 AS 路径；
- 辅助策略选择；
- 若路由器看到自己的 AS 已出现在路径中，可据此拒绝形成 AS 级环路的路由。

### 20.3 BGP 是策略驱动的

BGP 可以根据运营策略决定：

- 接受哪些前缀；
- 向哪些邻居发布；
- 多条可达路径选哪一条；
- 是否进行路由撤销。

因此：

> **BGP 的“最佳路径”不等同于跳数最少或链路代价最小。**

### 20.4 eBGP 与 iBGP

按邻居是否跨 AS，可区分：

- **eBGP**：不同 AS 之间交换路由；
- **iBGP**：同一 AS 内部传播外部 BGP 路由信息。

二者都属于 BGP 体系，不能把“iBGP”误认为 IGP。这里的 `i` 表示会话位于同一 AS 内，并不改变 BGP 的域间路由本质。

### 20.5 更新机制

BGP 建立会话后，不需要像 RIP 那样固定周期发送整张路由表；当路由发生变化时通过 UPDATE 等消息通告新增、属性变化或撤销的前缀。

<Callout type="info" title="三种协议一句话区分">

```text
RIP  ：邻居告诉我“距离”
OSPF ：区域内共享“链路状态”，我自己跑 SPF
BGP  ：邻居告诉我“前缀 + 路径属性”，我按策略选路
```

</Callout>
