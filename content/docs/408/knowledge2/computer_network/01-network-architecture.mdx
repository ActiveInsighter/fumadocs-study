本章负责建立整个计算机网络的**总框架**。后续物理层、数据链路层、网络层、传输层和应用层的知识，都应当挂到这个框架上。

复习时建议始终抓住三条主线：

1. **网络概述主线**：网络由什么组成、能做什么、如何分类、由谁制定标准；
2. **性能主线**：链路“理论上能多快”、实际“传了多快”，以及一个分组到底慢在哪里；
3. **分层主线**：每一层解决什么问题、处理什么 PDU、使用什么地址或标识、典型设备依据什么信息工作。

<Callout type="info" title="本章做题总框架">

遇到体系结构题，优先按下面顺序判断：

1. 题目说的是**网络概念、性能还是分层**？
2. 若涉及分层，问的是**协议、服务、接口还是实现**？
3. 当前功能属于**哪一层**？这一层的 **PDU** 是什么？
4. 这一层使用什么**地址或标识**？
5. 设备依据什么信息处理数据：**信号、MAC 地址、IP 地址还是端口号**？

</Callout>

## 1. 计算机网络的概念、组成与功能

### 1.1 什么是计算机网络

计算机网络可以理解为：

> **通过通信链路和交换设备，把地理上分散、具有独立功能的计算机系统互连起来，并按照网络协议实现数据通信和资源共享的系统。**

这个定义中有三个关键词：

- **互连**：主机之间通过链路、交换设备等形成可通信的网络；
- **自治**：联网主机仍是能够独立工作的计算机系统，而不是一个巨大计算机内部的部件；
- **协议**：通信双方必须遵守共同规则，否则“物理上连通”也不能正确交换信息。

### 1.2 网络的组成

从现代 Internet 的视角，网络中的对象可概括为三类：

| 组成 | 典型对象 | 作用 |
| --- | --- | --- |
| **端系统** | PC、服务器、手机、IoT 设备 | 运行应用程序，是数据通信的源或目的 |
| **通信链路** | 双绞线、光纤、无线链路等 | 承载比特传输 |
| **分组交换设备** | 交换机、路由器 | 在网络中转发帧或分组 |

从经典教材的功能划分看，还常把网络分为：

- **资源子网**：主要由主机、终端以及应用资源组成，负责信息处理与资源共享；
- **通信子网**：主要由通信链路和中间交换设备组成，负责数据传输。

<Callout type="warning" title="不要把“资源子网 / 通信子网”机械套到所有现代实现">

这是理解经典网络体系结构的抽象划分。实际设备可能同时承担多种功能，考试时应结合题目模型判断。

</Callout>

### 1.3 计算机网络的主要功能

常见功能包括：

1. **数据通信**：主机之间传输数据；
2. **资源共享**：共享软件、数据、存储、打印机等资源；
3. **分布式处理**：把任务拆分到不同计算机协同完成；
4. **提高可靠性**：通过冗余路径、备份节点等降低单点故障影响；
5. **负载均衡**：把请求或计算任务分散到多个节点。

其中“数据通信”是网络最基础的功能，其他功能通常建立在可通信的基础上。

## 2. 计算机网络的分类与拓扑

408 对“分类”通常考概念辨析，不需要把某个真实网络强行归入唯一类别；同一网络可以同时按多个维度分类。

### 2.1 按覆盖范围分类

| 类型 | 常见缩写 | 典型范围与特点 |
| --- | --- | --- |
| 个域网 | PAN | 个人设备附近的小范围互联 |
| 局域网 | LAN | 建筑、园区等较小范围，常见以太网 / WLAN |
| 城域网 | MAN | 城市范围 |
| 广域网 | WAN | 跨城市、跨地区甚至跨洲 |

Internet 不是“某一种局域网或广域网”，而是大量异构网络互连形成的**互联网（internet）**；全球公共 Internet 是其中最典型的实例。

### 2.2 按拓扑结构分类

常见拓扑包括：

- **总线型**：多个结点共享一条主干；
- **星型**：结点连接到中心设备；
- **环型**：结点形成闭合环；
- **树型**：按层次扩展；
- **网状型**：结点之间存在多条互连路径。

拓扑描述的是连接关系。判断优缺点时可从**成本、可靠性、扩展性、故障影响范围**四个角度分析。

### 2.3 其他常见分类口径

还可以按：

- 使用范围：**公用网 / 专用网**；
- 传输关系：**广播式 / 点到点式**；
- 接入介质：**有线 / 无线**。

<Callout type="info" title="分类题的做法">

先看题目给出的**分类维度**。不要因为“无线局域网”同时带有“无线”和“局域网”两个标签，就认为分类互相冲突。

</Callout>

## 3. 网络标准化工作与相关组织

不同厂商、不同网络若想互联，必须遵守共同标准。标准化的核心价值是：

> **让不同实现之间可以互操作。**

408 常见组织及其关键词如下：

| 组织 | 典型关键词 | 常见成果 |
| --- | --- | --- |
| **ISO** | 国际标准化组织 | OSI 参考模型 |
| **ITU-T** | 国际电信联盟电信标准化部门 | 电信与通信建议 |
| **IEEE** | 电气电子工程师学会 | IEEE 802 系列，如 802.3、802.11 |
| **IETF** | Internet 工程任务组 | Internet 协议标准与 RFC 文档 |

### 3.1 RFC 不等于“全部都是正式标准”

IETF 的大量技术文档以 **RFC（Request for Comments）** 形式发布，但 RFC 是一种文档系列，既可能包含标准轨协议，也可能包含信息性、实验性等文档。

因此更稳妥的判断是：

> **Internet 标准大量以 RFC 形式记录，但“RFC”本身不等价于“正式标准”。**

### 3.2 事实标准与法定标准

- **法定标准（de jure）**：由权威标准化组织按正式程序制定；
- **事实标准（de facto）**：因被广泛采用而形成事实上的统一规范。

考试中若只问“谁制定 OSI、IEEE 802、Internet RFC”，优先直接对应 ISO、IEEE、IETF。

## 4. 网络性能指标：速率、带宽与吞吐量

408 常把“链路理论能力”和“实际传输结果”放在一起考查，必须先区分概念。

### 4.1 速率

网络中的**速率（Data Rate / Bit Rate）**&#x2060;通常指单位时间传输的比特数，单位为 bit/s。

$$
1\text{ kb/s}=10^3\text{ bit/s}
$$

$$
1\text{ Mb/s}=10^6\text{ bit/s}
$$

$$
1\text{ Gb/s}=10^9\text{ bit/s}
$$

<Callout type="warning" title="bit/s 与 B/s 先统一单位">

网络速率通常以 bit/s 表示，而文件大小常以 B 表示。计算发送时延前要先用：

$$
1\text{ B}=8\text{ bit}
$$

再统一十进制或二进制前缀口径。

</Callout>

### 4.2 带宽

“带宽”有两种常见语境：

- 模拟信号语境：频带宽度，单位 Hz；
- 数字网络语境：链路的最高数据传输能力，常以 bit/s 表示。

408 若题目直接说“某链路带宽为 $R$ Mb/s”，通常是在第二种意义下使用。

### 4.3 吞吐量

**吞吐量（Throughput）**&#x2060;表示单位时间内实际通过某个网络、链路或端到端连接的数据量。

对经过若干串行链路的**固定路径**，忽略其他限制时：

$$
\text{Throughput}_{\max}\le \min(R_1,R_2,\ldots,R_n)
$$

其中最小容量链路称为**瓶颈链路**。

若网络存在多条并行路径，则整体最大吞吐量还可能涉及多条路径的共同承载能力，不能简单套“全网只看最小链路”。

> **带宽偏“理论能力”，吞吐量偏“实际结果”。**

### 4.4 好吞吐量 Goodput

若题目进一步区分协议首部、重传数据等开销，则真正交付给应用层的有效数据速率可称为 **Goodput**。

一般有：

$$
\text{Goodput}\le \text{Throughput}\le \text{Capacity}
$$

## 5. 时延、RTT、时延带宽积与利用率

一个分组从源主机到目的主机，典型会经历：

1. **发送时延（传输时延）**；
2. **传播时延**；
3. **处理时延**；
4. **排队时延**。

因此端到端总时延可以写成：

$$
D_{\text{total}}
=
D_{\text{trans}}
+
D_{\text{prop}}
+
D_{\text{proc}}
+
D_{\text{queue}}
$$

### 5.1 发送时延

若分组长度为 $L$ bit，链路发送速率为 $R$ bit/s，则：

$$
D_{\text{trans}}=\frac{L}{R}
$$

它描述的是：

> **把这 $L$ 个比特依次“推入链路”需要多久。**

### 5.2 传播时延

若链路长度为 $d$，信号传播速率为 $v$，则：

$$
D_{\text{prop}}=\frac{d}{v}
$$

它描述的是：

> **某个已经进入链路的比特，从链路一端传播到另一端需要多久。**

### 5.3 高频辨析

- 提高发送速率 $R$，会降低**发送时延**；
- 传播时延主要由距离 $d$ 和介质中的传播速率 $v$ 决定；
- “带宽更高”不意味着信号在介质中“传播得更快”；
- 分组还没到输出链路就可能先等待，因此排队时延随负载变化，通常最不稳定。

<Callout type="warning" title="发送时延和传播时延必须分开">

发送时延看 **数据量 / 发送速率**；传播时延看 **距离 / 传播速度**。

</Callout>

### 5.4 往返时延 RTT

**RTT（Round-Trip Time）**&#x2060;表示数据从发送方到接收方，再有响应返回发送方所经历的往返时间。

若只进行粗略估计且两个方向近似对称，可把单向传播相关时延近似看成 RTT 的一半；但真实 RTT 还可能包含处理、排队和响应生成等开销。

### 5.5 时延带宽积 BDP

若链路带宽为 $R$，单向传播时延为 $D_{\text{prop}}$，则链路中的“在途比特量”可近似表示为：

$$
\text{BDP}=R\cdot D_{\text{prop}}
$$

如果讨论发送窗口与往返确认关系，则常见估算是：

$$
W\approx R\cdot RTT
$$

含义是：若希望链路持续忙碌，发送方需要允许足够多的数据处于“已经发出但尚未确认”的状态。

### 5.6 利用率与排队

链路利用率提高意味着链路更加繁忙，但当到达速率逼近服务能力时，排队时延往往迅速增大。

因此：

> **高利用率不等于低时延，层次更多也不等于效率更高。**

## 6. 分组交换与存储转发：本章只建立直觉

Internet 的核心工作方式是**分组交换**：较大的数据被划分为若干分组，各分组经过交换设备逐跳转发，到达目的端后再交给上层处理。

分组交换的典型特点是：

- 链路可以被多个通信过程**统计复用**；
- 不必像电路交换那样为一对通信双方长期独占固定带宽；
- 分组可能经历排队、丢失、乱序等现象，需要更高层协议按需求处理。

详细的电路交换、报文交换、分组交换，以及数据报与虚电路将在物理层“通信基础”章节系统整理。本章只先掌握**存储转发**的时间直觉。

### 6.1 单个分组经过多条链路

若一个长度为 $L$ bit 的分组经过 $k$ 条发送速率均为 $R$ 的链路，采用存储转发，忽略传播、处理、排队时延，则：

$$
D=k\frac{L}{R}
$$

原因是每个中间结点必须先完整收到分组，才能向下一条链路发送。

### 6.2 多个等长分组的流水效果

若共有 $N$ 个等长分组，仍经过 $k$ 条等速链路，且各分组可以流水转发，则最后一个分组到达所需时间为：

$$
D=(N+k-1)\frac{L}{R}
$$

这个公式的本质是：

- 第一个分组要付出 $k$ 次发送时延；
- 后续每个分组在理想流水下只再增加一次 $L/R$。

> **真题考察**
>
> - 选择题：2010 年第 34 题

<Callout type="warning" title="分组交换不等于每个分组都走同一路径">

在无连接的数据报网络中，不同分组可以独立转发；在具体网络与具体时间段内，它们可能走相同路径，也可能因路由变化走不同路径。

</Callout>

## 7. 网络分层思想与“体系结构”到底描述什么

完整网络通信同时涉及：

- 物理信号传输；
- 帧组织与链路访问；
- IP 寻址与路由选择；
- 进程之间的数据传输；
- 应用程序之间的通信。

若所有功能都混在一个整体中，设计、实现和维护会非常困难，因此计算机网络采用**分层体系结构**。

每一层都可以概括为三件事：

1. **使用下层提供的服务**；
2. 完成本层规定的功能；
3. **向上层提供服务**。

### 7.1 分层的优点

- 各层功能边界清晰，降低系统设计复杂度；
- 便于标准化和模块化；
- 只要接口与服务保持稳定，各层技术可以相对独立演化；
- 便于故障定位、协议替换与扩展。

### 7.2 分层不是越多越好

层次过多也会带来：

- 首部 / 尾部等协议开销；
- 跨层调用与处理开销；
- 功能重复或信息难以跨层共享的问题。

因此“层次越多效率越高”是错误的。

> **真题考察**
>
> - 选择题：2026 年第 33 题

### 7.3 网络体系结构不等于具体实现

**网络体系结构（Network Architecture）**&#x2060;通常描述：

- 网络采用哪些层次；
- 每层应完成什么功能；
- 各层使用哪些协议及其逻辑关系。

它强调的是**抽象规范**，而不是某厂商如何写代码、寄存器如何设计、内部算法如何优化。

> **真题考察**
>
> - 选择题：2010 年第 33 题

<Callout type="warning" title="体系结构 ≠ 实现细节">

题目若问“某层协议的内部数据结构、代码组织、具体硬件实现”是否属于网络体系结构，通常应判断为**不属于**。

</Callout>

## 8. 协议、服务、接口与实体

这是本章最基础也最容易混淆的一组概念。

| 概念 | 含义 | 关系方向 |
| --- | --- | --- |
| **协议 Protocol** | 对等实体通信时遵守的规则集合 | 水平 |
| **服务 Service** | 下层通过接口向上层提供的功能 | 垂直 |
| **接口 Interface** | 相邻两层之间交换信息、访问服务的边界和规则 | 层间 |
| **实体 Entity** | 某一层中实现该层功能的软件或硬件对象 | 层内实现 |

可以快速记忆为：

> **同层靠协议，上下层靠服务，服务通过接口被使用。**

发送端与接收端的同层实体在逻辑上“横向通信”，但真实数据不会横向跳过中间层，而是：

```text
发送端：上层 → 下层 → 物理网络
接收端：物理网络 → 下层 → 上层
```

### 8.1 SAP：服务访问点

上层实体通过接口访问下层服务时，教材常用 **SAP（Service Access Point，服务访问点）** 描述逻辑访问位置。

理解即可：

> **协议规定对等层怎么说话；SAP / 接口规定相邻层从哪里、以什么方式使用服务。**

### 8.2 面向连接与无连接服务

从服务方式看，可粗略区分为：

| 服务类型 | 核心特点 | 直观类比 |
| --- | --- | --- |
| **面向连接** | 通信前先建立逻辑连接，通信结束后释放 | 先“建立关系”再持续传输 |
| **无连接** | 每个数据单元可独立处理，不要求预先建立连接 | 直接发送独立消息 |

“面向连接”与“可靠”不是同义词，“无连接”与“不可靠”也不是逻辑上必然绑定。判断时应看协议或服务的具体保证。

### 8.3 可靠服务与尽最大努力服务

- **可靠服务**：通过确认、重传、序号等机制，对交付正确性提供更强保证；
- **尽最大努力服务**：尽力传送，但不承诺一定到达、按序到达或不重复。

典型例子：TCP 提供可靠字节流；IP 提供尽最大努力的数据报服务。

协议主要包含三个要素：

| 要素 | 含义 | 典型问题 |
| --- | --- | --- |
| **语法 Syntax** | 数据和控制信息的格式、结构、编码 | 报文“长什么样” |
| **语义 Semantics** | 字段含义及收到信息后应执行的动作 | 字段“表示什么、收到后做什么” |
| **时序 Synchronization** | 事件先后、速度匹配和交互顺序 | “什么时候发、谁先谁后” |

速记：

> **语法看格式，语义看含义，时序看顺序。**

OSI 是**参考模型**，重点在于划分功能边界、说明各层职责，并不意味着现实 Internet 必须完整实现七个彼此独立的软件模块。

> **真题考察**
>
> - 选择题：2009 年第 33 题、2010 年第 33 题、2013 年第 33 题、2014 年第 33 题、2016 年第 33 题、2017 年第 33 题、2019 年第 33 题、2021 年第 33 题、2022 年第 33 题、2026 年第 33 题

OSI（Open Systems Interconnection）参考模型由 ISO 提出，共 7 层。

从低到高：

> **物理层 → 数据链路层 → 网络层 → 传输层 → 会话层 → 表示层 → 应用层**

速记：

> **物、链、网、输、会、示、用。**

传统教材还常把：

- 物理层、数据链路层、网络层称为**通信子网相关层次**；
- 会话层、表示层、应用层视为**资源子网相关层次**；
- 传输层位于中间，承担端到端传输并起承上启下作用。

这一划分主要用于理解经典 OSI 体系结构，不必把“通信子网/资源子网”机械套到所有现代网络实现中。

### 10.1 物理层

PDU 的基本单位：**Bit（比特）**。

核心任务：

> **在物理介质上传输原始比特流。**

主要关注：

- 机械、电气、功能和规程特性；
- 信号形式；
- 接口与引脚；
- 传输速率；
- 物理媒体上的比特传输。

### 10.2 数据链路层

PDU：**Frame（帧）**。

核心任务：

> **在相邻结点之间组织和传送帧。**

常见功能：

- 组帧；
- MAC 等链路层寻址；
- 差错检测；
- 流量控制；
- 介质访问控制；
- 某些链路协议中的确认和重传。

<Callout type="warning" title="不是所有链路层协议都必须可靠重传">

“差错控制”并不等于“每种数据链路层协议都一定负责可靠重传”。例如现代以太网通常进行差错检测，但不会像某些可靠链路协议那样在本层完成逐帧重传。

</Callout>

### 10.3 网络层

典型 PDU：**Packet / IP Datagram（分组 / IP 数据报）**。

核心任务：

> **把分组跨越多个网络和路由器，从源主机送往目的主机。**

主要功能：

- 逻辑寻址；
- 路由选择；
- 分组转发；
- 某些网络层控制与差错报告机制。

### 10.4 传输层

典型 PDU：

- TCP：**Segment（报文段）**；
- UDP：**User Datagram（用户数据报）**。

核心任务：

> **为不同主机中的应用进程提供端到端的逻辑通信。**

常见功能：

- 进程复用与分用；
- 可靠传输（TCP）；
- 流量控制（TCP）；
- 拥塞控制（TCP）；
- 端到端差错恢复等。

#### 点到点与端到端

典型路径：

```text
主机 A ── R1 ── R2 ── 主机 B
```

数据链路层关注的是每一跳：

```text
A → R1
R1 → R2
R2 → B
```

传输层关注的是：

```text
主机 A 中的进程 → 主机 B 中的进程
```

> **链路层看相邻结点，传输层看端到端进程。**

### 10.5 会话层

<InlineSvg src="/images/computer-network/computer-network-overall-iso-002.svg" alt={"分层结构 图 2"} />

主要负责建立、管理和终止会话，并可提供同步点、检查点等会话控制功能。

可理解为：

> **管理“会话何时建立、如何保持、从哪里恢复、何时结束”。**

### 10.6 表示层

主要解决数据表示问题，例如：

- 编码转换；
- 数据格式转换；
- 压缩与解压；
- 加密与解密。

可理解为：

> **解决“数据以什么形式表示”。**

### 10.7 应用层

为网络应用提供协议和网络服务接口，常见协议包括 HTTP、FTP、SMTP、DNS 等。

OSI 各层可以压缩为：

| 层次 | 核心问题 | 常见关键词 |
| --- | --- | --- |
| 应用层 | 应用要完成什么网络任务 | HTTP、DNS、FTP、邮件 |
| 表示层 | 数据怎么表示 | 编码、压缩、加密 |
| 会话层 | 会话怎么管理 | 建立、同步、恢复、终止 |
| 传输层 | 进程到进程怎么传 | TCP、UDP、端口 |
| 网络层 | 分组跨网络怎么走 | IP、路由 |
| 数据链路层 | 相邻结点怎么传帧 | MAC、Frame |
| 物理层 | 比特怎么过介质 | Bit、信号、接口 |

## 11. TCP/IP 四层模型

<InlineSvg src="/images/computer-network/computer-network-overall-iso-003.svg" alt={"分层结构 图 3"} />
<InlineSvg src="/images/computer-network/computer-network-overall-iso-004.svg" alt={"分层结构 图 4"} />

> **真题考察**
>
> - 选择题：2011 年第 33 题、2012 年第 33 题

TCP/IP 协议体系是 Internet 实际使用的核心体系结构。与 OSI 更偏“先有模型、再讨论协议”的教学视角不同，TCP/IP 更贴近现实 Internet 协议族的长期演化。

从低到高通常分为：

1. **网络接口层**；
2. **网际层**；
3. **传输层**；
4. **应用层**。

与 OSI 的常见对应关系：

| OSI 七层 | TCP/IP 四层 |
| --- | --- |
| 应用层 | 应用层 |
| 表示层 | 应用层 |
| 会话层 | 应用层 |
| 传输层 | 传输层 |
| 网络层 | 网际层 |
| 数据链路层 | 网络接口层 |
| 物理层 | 网络接口层 |

因此：

- TCP/IP **应用层**吸收了 OSI 会话层、表示层和应用层的功能；
- TCP/IP **网络接口层**覆盖 OSI 的数据链路层和物理层范围。

## 12. 五层协议体系结构

教学和 408 复习中常使用五层模型：

> **应用层 → 传输层 → 网络层 → 数据链路层 → 物理层**

三种模型可统一映射为：

| OSI 七层 | 五层模型 | TCP/IP 四层 |
| --- | --- | --- |
| 应用层 | 应用层 | 应用层 |
| 表示层 | 应用层 | 应用层 |
| 会话层 | 应用层 | 应用层 |
| 传输层 | 传输层 | 传输层 |
| 网络层 | 网络层 | 网际层 |
| 数据链路层 | 数据链路层 | 网络接口层 |
| 物理层 | 物理层 | 网络接口层 |

后续 408 网络知识最适合按五层模型整理：

```text
应用层       HTTP / DNS / FTP / SMTP ...
   ↓
传输层       TCP / UDP
   ↓
网络层       IP / 路由 / ICMP ...
   ↓
数据链路层   Ethernet / PPP / MAC ...
   ↓
物理层       信号 / 编码 / 介质 / 中继
```

## 13. PDU、SDU 与逐层封装

<InlineSvg src="/images/computer-network/computer-network-overall-iso-005.svg" alt={"分层结构 图 5"} />

> **真题考察**
>
> - 选择题：2009 年第 36 题
> - 解答题：2012 年第 47 题、2021 年第 47 题

**PDU（Protocol Data Unit）**&#x2060;是某层协议实际处理和逻辑交换的数据单元。对等实体之间逻辑上交换 PDU，实际数据仍会逐层向下传递并经过网络。

从服务关系角度还可区分：

- **SDU（Service Data Unit）**：上层交给本层的数据；
- **PCI（Protocol Control Information）**：本层协议加入的控制信息；
- **PDU**：本层最终形成并交给对等实体逻辑处理的数据单元。

可以抽象为：

$$
\text{PDU}=\text{PCI}+\text{SDU}
$$

其中 PCI 既可能表现为首部，也可能包含链路层尾部等控制信息。

发送端逐层加入控制信息，称为**封装（Encapsulation）**；接收端逐层去除对应控制信息，称为**解封装（Decapsulation）**。

典型封装过程：

```text
应用层数据
   ↓
TCP 首部 + 数据              → TCP Segment
   ↓
IP 首部 + TCP Segment       → IP Datagram
   ↓
帧首部 + IP Datagram + 帧尾  → Frame
   ↓
Bit Stream
```

### 13.1 各层常用 PDU 名称

<InlineSvg src="/images/computer-network/computer-network-overall-iso-006.svg" alt={"分层结构 图 6"} />

| 层次 | 常用名称 |
| --- | --- |
| 应用层 | Message / Data |
| 传输层 | TCP Segment / UDP User Datagram |
| 网络层 | Packet / IP Datagram |
| 数据链路层 | Frame |
| 物理层 | Bit |

<Callout type="warning" title="中文译名不统一时优先抓英文">

教材可能使用“报文、报文段、数据报、分组、数据包”等不同中文名称。最稳定的对应关系是：

- TCP → **Segment**；
- UDP → **User Datagram**；
- IP → **IP Datagram / Packet**；
- 链路层 → **Frame**；
- 物理层 → **Bit**。

</Callout>

## 14. 地址、标识与分用关系

网络中的不同层次使用不同标识解决不同问题。

| 层次 | 典型标识 | 解决的问题 |
| --- | --- | --- |
| 应用层 | 域名、URL 等 | 找到具体应用资源 |
| 传输层 | 端口号 | 找到主机中的进程/套接字端点 |
| 网络层 | IP 地址 | 找到网络中的主机或接口 |
| 数据链路层 | MAC 地址 | 在具体链路中识别接口 |

一条典型判断链可以写成：

```text
域名 → 解析出 IP
IP   → 跨网络路由
MAC  → 当前链路上一跳交付
端口 → 主机内交给正确应用进程
```

<Callout type="warning" title="IP 和 MAC 的作用范围不同">

IP 地址用于网络层的逻辑寻址；MAC 地址主要服务于当前数据链路上的帧交付。经过路由器后，链路层帧会重新封装，因此帧中的源/目的 MAC 地址通常随“每一跳”变化。若无 NAT 等地址转换，端到端通信中的源/目的 IP 地址通常保持不变。

</Callout>

## 15. 应用层常见协议与端口

应用层协议除了记“做什么”，还要同时掌握：

- 常见默认端口；
- 使用 TCP 还是 UDP；
- 是否存在多个连接或特殊承载规则。

| 协议 | 常见默认端口 | 常见传输层协议 | 主要作用 |
| --- | ---: | --- | --- |
| **HTTP** | 80 | TCP | Web 资源传输 |
| **HTTPS** | 443 | TCP | HTTP over TLS 的常见部署 |
| **FTP** | 21 / 20 | TCP | 文件传输 |
| **SMTP** | 25 | TCP | 邮件服务器间发送/转发 |
| **POP3** | 110 | TCP | 从服务器获取邮件 |
| **POP3S** | 995 | TCP | TLS 保护的 POP3 |
| **DNS** | 53 | UDP / TCP | 域名解析 |
| **DHCP** | 67 / 68 | UDP | 动态配置网络参数 |

### 15.1 FTP

FTP 的控制连接通常使用 TCP 21 端口。

经典主动模式下，服务器侧数据连接常使用 TCP 20 端口；其他工作模式的数据连接端口并不一定固定为 20。

需要掌握的核心特征是：

> **FTP 的控制信息与文件数据使用不同的 TCP 连接。**

### 15.2 DNS

DNS 端口为 53，既可使用 UDP，也可使用 TCP。

因此不能机械记成：

> “DNS 只用 UDP”。

### 15.3 DHCP

DHCP 常见端口：

- 服务器：UDP 67；
- 客户端：UDP 68。

用于自动获得：

- IP 地址；
- 子网掩码；
- 默认网关；
- DNS 服务器等配置。

## 16. TCP、UDP 与 IP 的层次定位

### 16.1 TCP

TCP 是传输层协议，典型特征：

- 面向连接；
- 可靠传输；
- 面向字节流；
- 全双工；
- 流量控制；
- 拥塞控制。

### 16.2 UDP

UDP 是传输层协议，典型特征：

- 无连接；
- 面向报文；
- 尽最大努力交付；
- 首部较小；
- 不在 UDP 协议内部提供 TCP 那样的可靠重传、流量控制和拥塞控制。

### 16.3 IP

IP 是网际层/网络层核心协议，提供：

> **无连接、尽最大努力交付的数据报服务。**

IP 本身不保证：

- 一定到达；
- 按序到达；
- 不重复；
- 不丢失。

## 17. ICMP、ARP、路由协议与 NAT 的层次口径

这组协议最容易因为“功能层次”和“实际承载方式”不同而混淆。

### 17.1 ICMP

ICMP 用于网络层控制、差错报告和诊断信息传递。

典型应用：

```text
ping
```

会使用 ICMP Echo Request / Echo Reply。

### 17.2 ARP

ARP 的核心作用是：

> **已知 IPv4 地址，解析得到当前链路上对应的 MAC 地址。**

ARP 位于网络层与链路层衔接位置，不同教材可能采用不同归类口径。408 做题时应优先抓住其**作用**，再结合题目给出的体系结构判断。

### 17.3 路由协议

常见路由协议：

- RIP；
- OSPF；
- BGP。

按路由范围：

- RIP、OSPF：自治系统内部常见；
- BGP：自治系统之间。

但“计算的是网络层路由”并不意味着它们的报文一定都以相同方式承载：

- RIP 典型使用 UDP；
- BGP 使用 TCP；
- OSPF 直接封装在 IP 中。

因此判断“某协议属于哪一层”时，要区分：

> **协议解决的问题、教材归类、报文实际承载方式。**

### 17.4 NAT

NAT（Network Address Translation）用于在不同地址空间之间转换 IP 地址信息，是 IPv4 网络常见机制。

在端口复用场景中还可能同时修改传输层端口号，因此具体实现会跨越网络层与传输层字段，但其核心目的仍是地址转换与连接映射。

## 18. 冲突域与广播域

> **真题考察**
>
> - 选择题：2010 年第 38 题、2016 年第 33 题、2016 年第 35 题、2020 年第 35 题

### 18.1 冲突域

**冲突域（Collision Domain）**&#x2060;是共享介质环境中，多个站点同时发送可能发生碰撞的范围。

在经典共享式以太网中：

- 集线器连接的所有端口仍共享同一冲突域；
- 网桥/交换机可把不同端口划分到不同冲突域。

现代全双工交换式以太网中，端口通常不再使用 CSMA/CD 处理碰撞，但考试仍常用“每个交换机端口是一个独立冲突域”来描述其隔离关系。

### 18.2 广播域

**广播域（Broadcast Domain）**&#x2060;是二层广播帧能够到达的范围。

普通二层交换机对广播帧进行泛洪，因此默认情况下：

> **交换机不隔离广播域。**

路由器不会把普通二层广播透明转发到另一个三层接口，因此：

> **路由器可以隔离广播域。**

### 18.3 VLAN 例外

配置 VLAN 后，二层交换机可以把一个物理交换网络划分成多个逻辑广播域。

因此更严谨的表述是：

> **普通二层交换转发本身不隔离同一 VLAN 内的广播；不同 VLAN 属于不同广播域。**

## 19. 中继器、集线器、网桥、交换机与路由器

判断设备工作层次时，最可靠的方法是看它**依据什么信息进行处理**。

### 19.1 中继器

[中继器](/docs/408/knowledge2/computer_network/02-physical-layer/04-media-devices/)工作在**物理层**。

主要作用：

- 再生或整形信号；
- 延长物理传输距离。

它不理解帧、MAC 地址或 IP 地址。

### 19.2 集线器

[集线器](/docs/408/knowledge2/computer_network/02-physical-layer/04-media-devices/)本质上是**多端口中继器**，工作在物理层。

特点：

- 收到信号后向其他端口转发；
- 不能按 MAC 地址进行智能过滤；
- 不能隔离冲突域；
- 不能隔离广播域。

### 19.3 网桥

[网桥](/docs/408/knowledge2/computer_network/03-data-link-layer/04-switch-bridge-summary/)工作在**数据链路层**，可依据 MAC 地址过滤和转发帧。

网桥：

- 可以隔离冲突域；
- 默认不隔离广播域。

### 19.4 交换机

<InlineSvg src="/images/computer-network/computer-network-overall-dev-001.svg" alt={"网络设备总结 图 1"} />

[交换机](/docs/408/knowledge2/computer_network/03-data-link-layer/04-switch-bridge-summary/)可视为多端口网桥，普通二层交换机依据 **MAC 地址表**转发帧。

典型结论：

- 每个端口形成独立冲突域；
- 同一 VLAN 内仍属于同一广播域。

### 19.5 路由器

<InlineSvg src="/images/computer-network/computer-network-overall-dev-002.svg" alt={"网络设备总结 图 2"} />

[路由器](/docs/408/knowledge2/computer_network/04-network-layer/02-router-arp-dhcp-icmp-nat/)工作在**网络层**，依据：

- 目的 IP 地址；
- 路由表；

决定下一跳。

路由器：

- 隔离冲突域；
- 隔离二层广播域。

## 20. 设备—层次—地址—域统一表

| 设备 | 主要工作层次 | 主要处理依据 | 隔离冲突域 | 隔离广播域 |
| --- | --- | --- | --- | --- |
| 中继器 | 物理层 | 信号 / Bit | ❌ | ❌ |
| 集线器 | 物理层 | 信号 / Bit | ❌ | ❌ |
| 网桥 | 数据链路层 | MAC 地址 | ✅ | ❌ |
| 二层交换机 | 数据链路层 | MAC 地址表 | ✅ | 默认 ❌ |
| 路由器 | 网络层 | IP 地址、路由表 | ✅ | ✅ |

可以进一步形成一条判断链：

```text
只看信号      → 物理层      → 中继器 / 集线器
看 MAC 地址   → 数据链路层  → 网桥 / 二层交换机
看 IP 地址    → 网络层      → 路由器
看端口号      → 传输层      → 进程分用
```

## 21. 数据在逐跳转发中的变化

这一部分是综合题的重要基础。

设主机 A 经路由器 R 到主机 B：

```text
A ── R ── B
```

### 21.1 经过交换机

普通二层交换机转发同一帧时，通常不会因为“经过交换机”就把 IP 数据报重新封装成新的网络层数据报。

交换机主要根据 MAC 地址表决定输出端口。

### 21.2 经过路由器

路由器收到帧后：

1. 去掉入站链路层封装；
2. 处理 IP 数据报并查询路由；
3. 为下一条链路重新封装新的链路层帧。

因此通常：

- **源/目的 IP 地址在端到端通信中基本保持不变**（NAT 等机制除外）；
- **源/目的 MAC 地址会随每一跳链路重新封装而变化**；
- IPv4 首部中的 TTL 等字段会在路由器转发时发生变化。

<Callout type="warning" title="交换机和路由器最核心的区别">

交换机主要决定“**这个帧从哪个二层端口出去**”；路由器主要决定“**这个 IP 分组下一跳去哪里**”。

</Callout>

## 22. 高频易错点

### 22.1 协议与服务

- 对等实体之间：**协议**；
- 相邻层之间：**服务**；
- 服务通过：**接口**被访问。

### 22.2 分层的收益与代价

- 分层有利于标准化、模块化和独立演化；
- 分层可降低系统设计与实现复杂度；
- **层次越多不代表效率越高**，过多层次会增加封装和处理开销。

> **真题考察**
>
> - 选择题：2026 年第 33 题

### 22.3 OSI 与 TCP/IP 层数

OSI：7 层。

TCP/IP：4 层。

教学五层模型：5 层。

不能把三个模型的层数和名称混在一起。

### 22.4 链路层与传输层

- 数据链路层：相邻结点的一跳传输；
- 传输层：端系统中进程之间的端到端逻辑通信。

### 22.5 发送时延与传播时延

$$
D_{\text{trans}}=\frac{L}{R}
$$

$$
D_{\text{prop}}=\frac{d}{v}
$$

提高发送速率不能直接缩短由距离和传播速度决定的传播时延。

### 22.6 交换机与广播域

普通二层交换机：

- 隔离冲突域；
- 同一 VLAN 内不隔离广播域。

路由器：

- 隔离冲突域；
- 隔离广播域。

### 22.7 DNS、ARP 和路由协议层次

不能只凭“功能看起来像某一层”就机械判断协议承载方式。

尤其需要记住：

- DNS 可用 UDP 或 TCP；
- ARP 位于 IP 与链路层衔接位置；
- RIP、BGP、OSPF 的承载方式不同。

```text
计算机网络体系结构
│
├─ 网络概述
│  ├─ 组成：端系统 / 链路 / 交换设备
│  ├─ 功能：通信 / 共享 / 分布式处理
│  ├─ 分类：PAN / LAN / MAN / WAN、拓扑等
│  └─ 标准：ISO / ITU-T / IEEE / IETF
│
├─ 性能
│  ├─ 速率 / 带宽 / 吞吐量 / Goodput
│  ├─ 发送时延 = L / R
│  ├─ 传播时延 = d / v
│  └─ BDP = 带宽 × 时延
│
├─ 分层
│  ├─ 协议：同层
│  ├─ 服务：上下层
│  ├─ 接口 / SAP：相邻层访问服务
│  └─ 协议三要素：语法 / 语义 / 时序
│
├─ 体系结构
│  ├─ OSI 七层
│  ├─ TCP/IP 四层
│  └─ 五层模型
│
├─ PDU
│  ├─ TCP Segment / UDP Datagram
│  ├─ IP Packet / Datagram
│  ├─ Frame
│  └─ Bit
│
├─ 地址
│  ├─ 端口号 → 传输层
│  ├─ IP → 网络层
│  └─ MAC → 数据链路层
│
└─ 设备
   ├─ 中继器 / 集线器 → 物理层
   ├─ 网桥 / 交换机   → 数据链路层
   └─ 路由器           → 网络层
```

最后重点记住：

> **同层讲协议，上下层讲服务。**

> **交换机主要看 MAC，路由器主要看 IP。**

> **发送时延看 $L/R$，传播时延看 $d/v$。**

> **网络体系结构描述层次、功能和协议关系，不描述具体内部实现。**

> **数据向下逐层封装，接收端向上逐层解封装。**
