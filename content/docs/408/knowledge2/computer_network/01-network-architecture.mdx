本章的核心任务是建立整个计算机网络的**分层框架**。

学习时不要只背“七层名称”，而要理解下面这条主线：

> **每一层使用下一层提供的服务，并向上一层提供服务；同层实体按照协议进行逻辑通信，而真实数据会在发送端逐层封装、经过网络传输后，在接收端逐层解封装。**

408 对本章的考查主要集中在：

* OSI、TCP/IP 与五层模型的层次对应关系；
* 各层的核心功能；
* 协议、服务及协议三要素；
* 各层协议数据单元 PDU 的名称；
* 常见网络协议所属层次；
* 中继器、集线器、交换机、路由器的工作层次；
* 冲突域与广播域的划分。

<Callout type="info" title="复习优先级">
本章整体优先级较高，其中 **OSI/TCP-IP 层次对应、各层功能、PDU、设备工作层次、冲突域与广播域** 是最需要掌握的内容。
</Callout>

## 1. 网络分层思想

一个完整的网络通信过程非常复杂，其中同时涉及：

* 物理信号传输；
* 帧的组织与链路访问；
* IP 寻址与路由选择；
* 进程之间的数据传输；
* 应用程序之间的通信。

因此，计算机网络采用**分层体系结构**，把复杂问题拆分为若干相对独立的层次。

每一层主要完成特定功能：

1. **使用下层提供的服务**；
2. 完成本层规定的功能；
3. **向上层提供服务**。

需要特别区分三个概念：

| 概念               | 含义                   | 关键词  |
| ---------------- | -------------------- | ---- |
| **协议 Protocol**  | 对等实体之间进行通信时必须遵守的规则集合 | 水平关系 |
| **服务 Service**   | 下层向上层提供的功能           | 垂直关系 |
| **接口 Interface** | 相邻两层之间交换信息的位置和规则     | 层间关系 |

因此：

> **协议是“同层之间”的规则，服务是“上下层之间”的关系。**

发送端的同层实体与接收端对应层在逻辑上进行通信，但数据并不会真正横向穿过网络，而是先沿发送方协议栈向下传递，再经过物理网络，最后沿接收方协议栈向上传递。

## 2. 网络协议的三要素

> **真题考察**
>
> * 选择题：2020 年第 33 题

网络协议规定通信双方进行信息交换时必须遵守的规则。

协议主要由三个要素组成：

| 要素                     | 含义                    | 典型问题           |
| ---------------------- | --------------------- | -------------- |
| **语法 Syntax**          | 数据和控制信息的格式、结构及编码方式    | “报文长什么样？”      |
| **语义 Semantics**       | 各字段或控制信息的含义，以及需要执行的操作 | “这个字段表示什么？”    |
| **时序 Synchronization** | 事件发生的先后顺序、速度匹配及双方协同关系 | “什么时候发送？谁先谁后？” |

可以快速记忆为：

> **语法看格式，语义看含义，时序看顺序。**

## 3. OSI 七层参考模型

> **真题考察**
>
> * 选择题：2009 年第 33 题、2010 年第 33 题、2013 年第 33 题、2014 年第 33 题、2016 年第 33 题、2017 年第 33 题、2019 年第 33 题、2021 年第 33 题、2022 年第 33 题、2026 年第 33 题

OSI（Open Systems Interconnection）参考模型由 ISO 提出，共分为 **7 层**。

从低到高依次为：

> **物理层 → 数据链路层 → 网络层 → 传输层 → 会话层 → 表示层 → 应用层**

常用记忆：

> **物、链、网、输、会、示、用**

<InlineSvg src="/images/computer-network/computer-network-overall-iso-001.svg" alt={"分层结构 图 1"} />

OSI 模型可以进一步理解为：

* **低三层：通信子网**

  * 物理层
  * 数据链路层
  * 网络层
* **高三层：资源子网**

  * 会话层
  * 表示层
  * 应用层
* **传输层：承上启下**

通信子网主要负责**数据传输**，资源子网主要负责**数据处理和网络应用**。

### 3.1 物理层

物理层的传输单位是：

> **比特 Bit**

物理层的主要任务是在物理媒体上传输原始比特流，使数据终端设备能够透明地传输二进制数据。

它主要规定各种物理接口和硬件标准，例如：

* 电缆类型；
* 接口类型；
* 电压标准；
* 信号形式；
* 传输速率；
* 接口引脚等。

物理层关心的是：

> **0 和 1 到底如何通过真实的物理介质传过去。**

物理层一般不参与网络层以上意义上的数据封装。

---

### 3.2 数据链路层

数据链路层的传输单位是：

> **帧 Frame**

数据在网络中往往需要经过一段一段的链路进行传输，因此需要数据链路层负责**相邻结点之间的数据传输**。

数据链路层接收网络层传下来的分组，将其封装成帧，然后在链路上传输。

主要功能包括：

* **组帧**；
* **物理寻址**；
* **差错控制**；
* **流量控制**；
* 必要的数据重传；
* 链路传输管理。

其核心目标可以理解为：

> 在物理层提供的原始比特传输能力之上，建立一条更加可靠、便于使用的数据链路。

---

### 3.3 网络层

网络层的主要传输单位通常称为：

> **分组 Packet / IP 数据报**

网络层关注的是通信子网内部的数据传输。

其核心任务是：

> **把分组从源主机传送到目的主机。**

其中最重要的问题是：

* **逻辑寻址**；
* **路由选择**；
* 分组转发；
* 网络层面的拥塞或流量控制等。

网络层必须解决：

> 数据跨越多个中间网络和路由器时，应该选择哪一条路径到达目的地。

---

### 3.4 传输层

传输层的传输单位取决于所使用的协议：

* TCP：**报文段 Segment**
* UDP：**用户数据报 Datagram**

传输层负责：

> **不同主机中的应用进程之间的通信。**

主要功能包括：

* 端到端的数据传输；
* 可靠传输；
* 流量控制；
* 差错控制；
* 服务质量；
* 数据传输管理。

#### 点到点与端到端

这是 408 中非常容易混淆的一组概念。

**数据链路层**关注：

> **相邻结点之间，即点到点（Point-to-Point）的传输。**

**传输层**关注：

> **源主机进程到目的主机进程，即端到端（End-to-End）的通信。**

例如：

```text
主机 A ── 路由器 R1 ── 路由器 R2 ── 主机 B
```

链路层处理的是：

```text
A → R1
R1 → R2
R2 → B
```

这些相邻结点之间的一跳通信。

而传输层看到的则是：

```text
主机 A 中的进程 → 主机 B 中的进程
```

中间经过多少个路由器对传输层而言通常是透明的。

<Callout type="warning" title="易错点">
不要把“点到点”简单理解成“源主机到目的主机”。数据链路层的点到点通常强调 **相邻结点之间的一跳传输**；传输层才负责真正意义上的 **进程到进程端到端通信**。
</Callout>

---

### 3.5 会话层

会话层负责不同主机中的进程之间建立、管理和终止会话。

<InlineSvg src="/images/computer-network/computer-network-overall-iso-002.svg" alt={"分层结构 图 2"} />

主要功能包括：

* 建立会话；
* 管理会话；
* 终止会话；
* 设置同步点或检查点。

检查点机制可以使通信在发生故障后从某个位置继续，而不是完全重新开始。

因此可以把会话层理解为：

> **管理双方“什么时候开始谈、如何保持谈话、从哪里继续谈、什么时候结束”。**

---

### 3.6 表示层

不同计算机系统可能采用不同的数据表示方式，例如：

* 不同字符编码；
* 不同数据格式；
* 不同数据结构。

表示层负责解决：

> **双方的数据应该以什么形式表示。**

主要功能包括：

* 数据格式转换；
* 字符编码转换；
* 数据压缩；
* 数据解压；
* 数据加密；
* 数据解密。

因此可以记为：

> **表示层负责“怎么表示数据”。**

---

### 3.7 应用层

应用层是 OSI 参考模型的最高层，也是用户应用程序访问网络服务的接口。

由于网络应用种类非常多，因此应用层包含大量不同的应用协议，例如：

* HTTP；
* FTP；
* SMTP；
* POP3；
* DNS；
* DHCP。

应用层的特点是：

> **协议种类最多，并且直接面向具体网络应用。**

## 4. OSI 各层功能总表

| 层次 | 名称    | 核心功能        | 典型关键词           |
| -- | ----- | ----------- | --------------- |
| 7  | 应用层   | 为网络应用提供服务   | HTTP、FTP、DNS、邮件 |
| 6  | 表示层   | 数据表示转换      | 编码、压缩、加密        |
| 5  | 会话层   | 建立、管理、终止会话  | 会话、同步点、检查点      |
| 4  | 传输层   | 进程到进程的端到端传输 | TCP、UDP、端口      |
| 3  | 网络层   | 跨网络传送分组     | IP、路由、逻辑地址      |
| 2  | 数据链路层 | 相邻结点间传输帧    | MAC、帧、差错检测      |
| 1  | 物理层   | 传输原始比特      | 信号、电缆、接口        |

## 5. TCP/IP 四层模型

> **真题考察**
>
> * 选择题：2011 年第 33 题、2012 年第 33 题

TCP/IP 模型是互联网实际采用的协议体系。

从低到高分为：

1. **网络接口层**
2. **网际层**
3. **传输层**
4. **应用层**

<InlineSvg src="/images/computer-network/computer-network-overall-iso-003.svg" alt={"分层结构 图 3"} />

TCP/IP 模型与 OSI 模型之间的基本对应关系如下：

| TCP/IP 模型 | OSI 模型 |
| --------- | ------ |
| 应用层       | 应用层    |
| 应用层       | 表示层    |
| 应用层       | 会话层    |
| 传输层       | 传输层    |
| 网际层       | 网络层    |
| 网络接口层     | 数据链路层  |
| 网络接口层     | 物理层    |

也就是说：

* TCP/IP 的**应用层**综合了 OSI 的应用层、表示层和会话层；
* TCP/IP 的**网络接口层**综合了 OSI 的数据链路层和物理层。

<InlineSvg src="/images/computer-network/computer-network-overall-iso-004.svg" alt={"分层结构 图 4"} />

TCP/IP 体系由于在 Internet 中被广泛采用，已经成为事实上的互联网标准。

## 6. 五层协议体系结构

实际学习计算机网络时，通常综合 OSI 和 TCP/IP 两种体系的特点，采用更便于教学和分析的**五层模型**：

> **应用层 → 传输层 → 网络层 → 数据链路层 → 物理层**

从低到高则为：

> **物理层 → 数据链路层 → 网络层 → 传输层 → 应用层**

三种模型的对应关系可以总结如下：

| OSI 七层 | 五层模型  | TCP/IP 四层 |
| ------ | ----- | --------- |
| 应用层    | 应用层   | 应用层       |
| 表示层    | ↑     | ↑         |
| 会话层    | ↑     | ↑         |
| 传输层    | 传输层   | 传输层       |
| 网络层    | 网络层   | 网际层       |
| 数据链路层  | 数据链路层 | 网络接口层     |
| 物理层    | 物理层   | ↑         |

408 的大部分网络知识都可以按照这套五层结构组织：

```text
应用层
  ↓
传输层
  ↓
网络层
  ↓
数据链路层
  ↓
物理层
```

## 7. 协议数据单元 PDU

> **真题考察**
>
> * 选择题：2009 年第 36 题
> * 解答题：2012 年第 47 题、2021 年第 47 题

PDU（Protocol Data Unit，协议数据单元）是：

> **某一协议层实际处理和交换的数据单元。**

发送端的数据沿协议栈向下传递时，各层会添加本层所需要的控制信息。

这个过程称为：

> **封装 Encapsulation**

接收方则进行相反过程：

> **解封装 Decapsulation**

<InlineSvg src="/images/computer-network/computer-network-overall-iso-005.svg" alt={"分层结构 图 5"} />

### 7.1 封装过程

可以把发送过程理解为：

```text
应用层数据
    ↓
TCP/UDP 首部 + 数据
    ↓
IP 首部 + 传输层数据
    ↓
帧首部 + 网络层数据 + 帧尾部
    ↓
比特流
```

接收方执行相反过程：

```text
比特流
    ↓
帧
    ↓
IP 分组
    ↓
TCP 报文段 / UDP 用户数据报
    ↓
应用层数据
```

---

### 7.2 各层 PDU 名称

| 层次    | PDU                        |
| ----- | -------------------------- |
| 应用层   | Data（数据）                   |
| 表示层   | Data（数据）                   |
| 会话层   | Data（数据）                   |
| 传输层   | TCP Segment / UDP Datagram |
| 网络层   | Packet / IP Datagram       |
| 数据链路层 | Frame（帧）                   |
| 物理层   | Bit（比特）                    |

对于中文名称，不同教材可能存在“数据包、分组、报文、报文段、数据段”等不同翻译。

因此复习时更建议掌握英文名称：

* **Segment**
* **Datagram**
* **Packet**
* **Frame**
* **Bit**

这样更不容易受到不同中文译法的影响。

<InlineSvg src="/images/computer-network/computer-network-overall-iso-006.svg" alt={"分层结构 图 6"} />

<Callout type="warning" title="高频易错">
最需要牢牢记住的是：

**传输层 → Segment / Datagram**
**网络层 → Packet / IP Datagram**
**数据链路层 → Frame**
**物理层 → Bit**
</Callout>

## 8. 常见网络协议总览

建立协议地图时，不应只记协议名字，还要同时记住：

* 协议完成什么功能；
* 工作在哪个层次；
* 应用层协议使用 TCP 还是 UDP；
* 高频应用层协议的默认端口号。

---

## 9. 应用层常见协议

应用层协议直接面向网络应用程序。

| 协议        |    默认端口 | 传输层协议     | 主要作用               |
| --------- | ------: | --------- | ------------------ |
| **HTTP**  |      80 | TCP       | Web 页面传输           |
| **HTTPS** |     443 | TCP       | 基于 TLS 等安全机制的 HTTP |
| **FTP**   | 20 / 21 | TCP       | 文件传输               |
| **SMTP**  |      25 | TCP       | 发送电子邮件             |
| **POP3**  |     110 | TCP       | 接收电子邮件             |
| **POP3S** |     995 | TCP       | 加密的 POP3           |
| **DNS**   |      53 | UDP / TCP | 域名解析               |
| **DHCP**  | 67 / 68 | UDP       | 动态配置 IP 地址等网络参数    |

### HTTP / HTTPS

HTTP（HyperText Transfer Protocol）主要用于 Web 资源传输。

默认端口：

* HTTP：`80`
* HTTPS：`443`

HTTPS 可以理解为在 HTTP 通信基础上增加 TLS 等安全机制。

---

### FTP

FTP（File Transfer Protocol）用于文件上传和下载。

FTP 使用两个典型端口：

* `21`：控制连接；
* `20`：传统主动模式下的数据连接。

需要记住 FTP 的一个重要特点：

> **控制信息和文件数据使用不同连接传输。**

---

### SMTP

SMTP（Simple Mail Transfer Protocol）主要负责：

> **发送邮件。**

默认端口：

```text
25
```

---

### POP3

POP3（Post Office Protocol Version 3）主要负责从邮件服务器获取邮件。

默认端口：

```text
110
```

加密 POP3S 常使用：

```text
995
```

---

### DNS

DNS（Domain Name System）负责：

> **将域名解析为 IP 地址。**

默认端口：

```text
53
```

通常使用 UDP。

部分场景会使用 TCP，例如：

* 较大的 DNS 响应；
* DNS 区域传送等。

因此：

> **不能简单记成“DNS 只使用 UDP”。**

---

### DHCP

DHCP（Dynamic Host Configuration Protocol）用于自动配置主机的网络参数，例如：

* IP 地址；
* 子网掩码；
* 默认网关；
* DNS 服务器等。

DHCP 使用 UDP：

| 角色          | 端口 |
| ----------- | -: |
| DHCP Server | 67 |
| DHCP Client | 68 |

---

## 10. 传输层常见协议

### TCP

TCP（Transmission Control Protocol）具有：

* 面向连接；
* 可靠传输；
* 面向字节流；
* 流量控制；
* 拥塞控制等特点。

适合对可靠性要求较高的应用，例如：

* HTTP；
* HTTPS；
* FTP；
* SMTP；
* POP3。

---

### UDP

UDP（User Datagram Protocol）具有：

* 无连接；
* 面向报文；
* 不保证可靠交付；
* 首部开销较小；
* 传输机制简单。

常见使用场景包括：

* DNS；
* DHCP；
* 对实时性要求较高的网络应用。

---

## 11. 网络层相关协议

### IP

IP（Internet Protocol）是 Internet 网络层的核心协议。

IP 提供：

> **无连接、尽最大努力交付的数据报服务。**

IP 本身并不能保证：

* 数据一定到达；
* 数据按序到达；
* 数据不重复；
* 数据不发生丢失。

---

### ICMP

ICMP（Internet Control Message Protocol）用于传递：

* 网络差错报告；
* 网络控制信息；
* 网络诊断信息。

例如常见的：

```text
ping
```

就会使用 ICMP 回显请求和回显应答。

---

### 路由选择协议

常见路由选择协议包括：

* RIP；
* OSPF；
* BGP。

从路由功能角度：

* RIP、OSPF 主要用于自治系统内部；
* BGP 主要用于自治系统之间。

<Callout type="warning" title="协议层次易错点">
“路由协议负责计算网络层路由”并不意味着所有路由协议报文都直接作为普通网络层协议存在。

例如在具体协议栈中，RIP、BGP、OSPF 的承载方式并不完全相同。做“协议属于哪一层”的题目时，应以题目采用的体系结构及教材定义为准，不要仅根据协议用途机械判断。
</Callout>

---

### NAT

NAT（Network Address Translation）即：

> **网络地址转换。**

它可以在私有网络地址和公网地址之间进行转换，是 IPv4 网络中非常常见的技术。

---

## 12. 数据链路层相关协议

### ARP

ARP（Address Resolution Protocol）的核心作用是：

> **根据 IPv4 地址获得对应的 MAC 地址。**

ARP 位于 IP 与具体链路技术的衔接位置，因此不同分层口径对其归类可能存在差异。

408 复习中最重要的是理解：

> **ARP 解决的是“已知 IP 地址，如何找到对应 MAC 地址”的问题。**

---

### PPP

PPP（Point-to-Point Protocol）即点对点协议。

主要用于：

> **点对点链路的数据传输。**

传统拨号网络中经常使用 PPP。

---

### HDLC

HDLC（High-Level Data Link Control）即高级数据链路控制协议。

其特点包括：

* 面向比特；
* 用于同步链路；
* 提供帧级数据传输与控制。

## 14. 冲突域

> **真题考察**
>
> * 选择题：2010 年第 38 题、2016 年第 33 题、2016 年第 35 题、2020 年第 35 题

**冲突域 Collision Domain** 是：

> 在共享介质以太网中，多个设备同时发送数据时可能发生碰撞的一组设备所处的范围。

早期共享式以太网通常使用 CSMA/CD。

其基本思想为：

1. 发送数据前监听信道；
2. 信道空闲时开始发送；
3. 如果多个设备几乎同时认为信道空闲并发送；
4. 则可能发生碰撞。

因此冲突产生的根本背景是：

> **多个设备共享同一传输介质。**

### 14.1 集线器与冲突域

集线器 Hub 工作在**物理层**。

它只是把收到的信号转发到其他端口，并不知道：

* MAC 地址；
* IP 地址；
* 帧的真正目的地。

因此：

> **连接在同一个集线器上的所有设备属于同一个冲突域。**

集线器：

> **不能隔离冲突域。**

---

### 14.2 交换机与冲突域

交换机 Switch 工作在**数据链路层**。

交换机可以依据：

> **MAC 地址**

进行帧转发。

现代交换式以太网中，交换机的每个端口可以形成一个独立的冲突域。

因此：

> **交换机能够隔离冲突域。**

## 15. 广播域

**广播域 Broadcast Domain** 是：

> 一个广播帧能够传播到的设备范围。

例如某设备发送二层广播帧时，同一广播域中的其他设备通常都能够收到。

在 IPv4 网络中，ARP 请求等操作也会产生广播。

### 15.1 交换机与广播域

普通二层交换机收到广播帧后，会将它转发到：

> **除接收端口以外的其他相关端口。**

因此普通交换机：

> **不能隔离广播域。**

---

### 15.2 路由器与广播域

路由器 Router 工作在**网络层**。

路由器根据：

> **IP 地址和路由表**

选择下一跳。

路由器通常不会将局域网二层广播继续转发到其他接口。

因此：

> **路由器可以隔离广播域。**

通常每一个路由器三层接口对应一个独立的广播域。

<InlineSvg src="/images/computer-network/computer-network-overall-dev-002.svg" alt={"网络设备总结 图 2"} />

## 16. 冲突域与广播域对比

| 对比    | 冲突域              | 广播域        |
| ----- | ---------------- | ---------- |
| 核心问题  | 多台设备是否可能发生介质访问碰撞 | 广播能传播到多大范围 |
| 集线器   | 不隔离              | 不隔离        |
| 网桥    | 隔离               | 不隔离        |
| 二层交换机 | 隔离               | 不隔离        |
| 路由器   | 隔离               | 隔离         |

快速记忆：

> **交换机隔冲突，不隔广播；路由器两者都隔。**

## 17. 常见网络设备

### 17.1 中继器

中继器 Repeater 工作在：

> **物理层**

主要功能：

* 再生信号；
* 放大或整形数字信号；
* 延长传输距离。

中继器不理解：

* 帧；
* MAC 地址；
* IP 地址。

因此：

> **既不能隔离冲突域，也不能隔离广播域。**

---

### 17.2 集线器

集线器 Hub 本质上可以看作：

> **多端口中继器。**

工作在：

> **物理层**

收到信号后，会向其他端口传播。

因此：

* 不隔离冲突域；
* 不隔离广播域。

---

### 17.3 网桥

网桥 Bridge 工作在：

> **数据链路层**

主要依据：

> **MAC 地址**

进行帧过滤和转发。

网桥可以：

* 分割冲突域；
* 不能分割普通广播域。

---

### 17.4 交换机

交换机 Switch 可以理解为：

> **多端口网桥。**

普通以太网交换机工作在：

> **数据链路层**

主要根据：

> **MAC 地址表**

进行帧转发。

因此普通二层交换机：

* 可以隔离冲突域；
* 不能隔离广播域。

---

### 17.5 路由器

路由器 Router 工作在：

> **网络层**

主要依据：

* 目的 IP 地址；
* 路由表；

进行分组转发。

因此：

* 可以隔离冲突域；
* 可以隔离广播域。

---

## 19. 层次、地址与设备对应关系

408 中经常把“层次—地址—设备”组合在一起考查。

| 层次    | 典型地址或标识  | 典型设备    |
| ----- | -------- | ------- |
| 应用层   | 域名、URL 等 | 应用服务器   |
| 传输层   | 端口号      | —       |
| 网络层   | IP 地址    | 路由器     |
| 数据链路层 | MAC 地址   | 网桥、交换机  |
| 物理层   | —        | 中继器、集线器 |

因此判断设备属于哪一层时，可以看它：

> **主要根据哪一层的控制信息进行处理。**

例如：

* 中继器只处理物理信号 → **物理层**；
* 交换机主要依据 MAC 地址转发 → **数据链路层**；
* 路由器主要依据 IP 地址转发 → **网络层**。

## 20. 高频易错点

### 20.1 协议与服务

错误：

> 同层之间提供服务。

正确：

> **同层实体之间遵守协议，相邻层之间提供和使用服务。**

---

### 20.2 TCP/IP 与 OSI 的层次

不要把 TCP/IP 也记成七层。

TCP/IP 是：

> **网络接口层、网际层、传输层、应用层。**

OSI 才是：

> **物理、链路、网络、传输、会话、表示、应用。**

---

### 20.3 点到点与端到端

* 数据链路层：**相邻结点之间**
* 传输层：**源进程到目的进程**

不能把二者混为一谈。

---

### 20.4 交换机与广播

错误：

> 交换机可以隔离广播。

正确：

> **普通二层交换机可以隔离冲突域，但不能隔离广播域。**

广播域主要由：

> **路由器等三层设备**

进行划分。

---

### 20.5 集线器与交换机

集线器：

```text
物理层
共享介质
一个冲突域
```

交换机：

```text
数据链路层
根据 MAC 地址转发
每个端口通常是独立冲突域
```

---

### 20.6 PDU 名称

高频对应关系：

```text
传输层     Segment / Datagram
网络层     Packet / IP Datagram
数据链路层 Frame
物理层     Bit
```
