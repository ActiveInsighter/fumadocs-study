网络通信同时涉及信号、链路、寻址、路由、可靠传输和应用语义。分层的目的，就是把一个巨大的系统问题拆成若干边界清晰、可独立演化的子问题。

> **真题标签**
>
> 网络体系结构：2010 年第 33 题、2026 年第 33 题。
>
> 协议三要素：2020 年第 33 题。

## 1.2.1 什么是网络体系结构

计算机网络体系结构可以概括为：

> **网络各层及其协议的集合，是对网络功能层次和层间关系的抽象描述。**

体系结构关注：

- 网络划分为哪些层；
- 每层完成哪些功能；
- 每层采用哪些协议；
- 相邻层之间如何提供服务。

体系结构通常**不规定具体协议的内部实现细节**。

<Callout type="warn" title="体系结构 ≠ 具体实现">
同一种体系结构可以由不同软件、不同操作系统、不同硬件厂商实现。考试看到“协议内部代码怎么写、具体芯片如何实现”时，不属于体系结构本身要描述的内容。
</Callout>

## 1.2.2 为什么要分层

分层的主要价值有：

1. **降低复杂度**：每层只解决有限问题；
2. **模块独立**：层内实现可变化，只要接口语义保持稳定；
3. **便于标准化**：不同厂商可按共同协议互通；
4. **便于故障定位**：可按层分析问题；
5. **便于复用**：上层可重复使用下层服务。

但分层也会带来：

- 首部等额外开销；
- 某些功能在多层重复；
- 层间边界过于严格时可能降低优化空间。

因此“分层”是一种工程折中，而不是越多层越好。

## 1.2.3 协议、服务与接口

| 概念 | 关系方向 | 含义 |
| --- | --- | --- |
| Protocol 协议 | 水平 | 对等实体通信时遵守的规则 |
| Service 服务 | 垂直 | 下层向上层提供的功能 |
| Interface 接口 | 相邻层 | 上下层交换信息和调用服务的边界 |

最重要的一句话：

> **协议描述“同层实体怎么通信”，服务描述“下层能为上层做什么”。**

### 对等实体

位于不同主机、同一协议层的通信实体称为对等实体。

例如：

```text
主机 A 的传输层  ⇄  主机 B 的传输层
```

这是一种**逻辑上的横向通信**。

真实数据不会直接横向穿过空气，而是：

```text
发送端：上层 → 下层 → 物理介质
接收端：物理介质 → 下层 → 上层
```

## 1.2.4 服务访问点与服务数据单元

为了理解封装，可以区分三个常见抽象：

- **SAP（Service Access Point）**：上层访问下层服务的位置或逻辑入口；
- **SDU（Service Data Unit）**：上层交给本层、希望本层传输的数据；
- **PCI（Protocol Control Information）**：本层为了完成协议功能加入的控制信息。

本层形成的协议数据单元可抽象为：

$$
PDU=PCI+SDU
$$

到了下一层，本层的整个 PDU 又会成为下一层看到的数据部分。

这就是逐层封装的本质。

## 1.2.5 网络协议三要素

协议由三个基本要素构成：

| 要素 | 回答的问题 | 典型内容 |
| --- | --- | --- |
| 语法 Syntax | “长什么样？” | 字段格式、编码、帧结构 |
| 语义 Semantics | “表示什么、要做什么？” | 字段含义、控制动作、响应 |
| 时序 Synchronization | “什么时候做、先后如何？” | 发送顺序、事件时机、速度配合 |

快速记忆：

> **语法看格式，语义看含义，时序看先后。**

## 1.2.6 面向连接与无连接服务

“连接”是服务模型中的重要维度。

### 面向连接

一般先建立逻辑关系，再传输数据，最后释放连接。

典型例子：TCP。

### 无连接

无需预先建立连接，每个数据单元相对独立地发送。

典型例子：IP、UDP。

注意：

> **“无连接”不等于“完全没有状态”，“面向连接”也不天然等于“绝对可靠”。**

可靠性取决于协议是否实现确认、重传、编号、校验、流量控制等具体机制。

## 1.2.7 可靠服务与不可靠服务

- **可靠服务**：尽量保证数据正确、完整、有序交付；
- **不可靠服务**：尽最大努力传输，但不承诺一定成功。

Internet 的经典分工是：

```text
IP：无连接、尽最大努力
TCP：在端系统中提供可靠字节流
UDP：简单的无连接报文服务
```

这也体现了网络设计中的重要思想：

> **某层不负责的能力，可以由更高层按需实现。**

## 1.2.8 分层题的判断顺序

遇到“某功能属于哪一层”时，不要只背词，按下面顺序判断：

1. 服务对象是谁？相邻结点、主机还是进程？
2. 使用什么地址？MAC、IP 还是端口号？
3. 处理的 PDU 是帧、分组还是报文段？
4. 设备依据哪类首部字段转发？

这样比孤立背诵层名更稳。
