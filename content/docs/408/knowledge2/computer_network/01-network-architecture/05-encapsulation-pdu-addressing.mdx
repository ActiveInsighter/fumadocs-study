如果说分层模型是“静态结构”，那么封装与解封装就是数据真正穿过协议栈时的“动态过程”。这是后续综合题最重要的总线索之一。

> **真题标签**
>
> PDU 与封装：2009 年第 36 题；2012 年第 47 题、2021 年第 47 题。

## 1.5.1 PDU 是什么

PDU（Protocol Data Unit）是某一层协议实体处理和交换的数据单元。

典型名称：

| 层次 | 常见 PDU 名称 |
| --- | --- |
| 应用层 | Data / Message |
| 传输层 | TCP Segment / UDP Datagram |
| 网络层 | Packet / IP Datagram |
| 数据链路层 | Frame |
| 物理层 | Bit |

中文教材可能出现“分组、包、数据报、报文、报文段”等译法差异。

因此优先建立英文对应：

```text
Segment / Datagram
Packet / IP Datagram
Frame
Bit
```

## 1.5.2 逐层封装

假设应用产生数据 $M$。

发送端大致经历：

```text
应用数据 M
   ↓
传输层首部 + M
   ↓
IP 首部 + 传输层 PDU
   ↓
链路层首部 + IP 数据报 + 链路层尾部
   ↓
比特流
```

形式上可以写成：

$$
PDU_n=H_n+PDU_{n+1}
$$

若该层还有尾部：

$$
PDU_n=H_n+PDU_{n+1}+T_n
$$

这里 $H_n$、$T_n$ 分别表示本层加入的首部与尾部控制信息。

## 1.5.3 接收端解封装

接收方执行相反过程：

```text
Bit
 ↓
Frame
 ↓
IP Datagram
 ↓
TCP Segment / UDP Datagram
 ↓
Application Data
```

每层主要读取本层关心的控制信息，再把载荷交给上层。

因此：

> **发送端向下逐层封装，接收端向上逐层解封装。**

## 1.5.4 三类关键地址

综合题中最常见的是：

| 层次 | 标识 | 作用 |
| --- | --- | --- |
| 传输层 | 端口号 | 标识主机中的应用进程 / 服务端点 |
| 网络层 | IP 地址 | 标识网络层接口并用于跨网络寻址 |
| 数据链路层 | MAC 地址 | 用于当前链路上的帧交付 |

把一条跨路由路径写出来：

```text
主机 A ── R1 ── R2 ── 主机 B
```

如果没有 NAT 等地址转换：

- **源/目的 IP 地址通常端到端保持不变**；
- **链路层源/目的 MAC 地址每经过一跳会重新封装**；
- TCP/UDP 端口用于端系统进程定位，中间普通路由器转发时不靠端口决定下一跳。

<Callout type="warn" title="MAC 地址不是端到端地址">
路由器每转发到一条新的二层链路，就需要重新构造适合该链路的帧。因此帧头中的 MAC 地址通常是“本跳”的源/目的，而不是整条路径固定不变。
</Callout>

## 1.5.5 一跳转发时发生什么

当路由器收到以太网帧时，可以抽象为：

1. 链路层检查帧并取出 IP 数据报；
2. 网络层查看目的 IP 地址；
3. 根据路由表选择下一跳 / 出接口；
4. IP 数据报按网络层规则更新必要字段；
5. 为下一条链路重新封装新的链路层帧；
6. 从出接口发送。

因此同一个 IP 数据报跨越不同链路时，会“换外层帧”。

这也是理解 ARP、交换机、路由器协同工作的关键。

## 1.5.6 点到点、主机到主机、进程到进程

一条完整通信链路可分成三种观察尺度：

### 链路层：相邻结点

```text
A → R1
R1 → R2
R2 → B
```

### 网络层：主机到主机

```text
Host A  ─────────→  Host B
```

网络层负责让分组跨多个网络到达目的主机。

### 传输层：进程到进程

```text
A:port_x  ───────→  B:port_y
```

传输层进一步把数据交给正确进程。

## 1.5.7 复用与分用

### 复用 Multiplexing

多个上层应用的数据可以通过同一套下层网络协议发送。

### 分用 Demultiplexing

接收方根据首部标识，把数据交给正确上层实体。

典型分用字段：

- 以太网 Type：指示上层协议；
- IP Protocol / IPv6 Next Header：指示 TCP、UDP、ICMP 等；
- TCP/UDP 目的端口：指示目标应用进程。

这说明“首部字段”的核心价值之一就是：

> **告诉本层如何处理，并告诉接收方下一步交给谁。**

## 1.5.8 封装题通用画法

遇到综合题，可以先画最小框架：

```text
应用数据
[ TCP/UDP H | Data ]
[ IP H | TCP/UDP H | Data ]
[ L2 H | IP H | TCP/UDP H | Data | L2 T ]
```

再逐项填写：

- 源/目的端口；
- 源/目的 IP；
- 本跳源/目的 MAC；
- 各层长度字段；
- 是否需要分片、校验、确认等。

这样比一开始直接套数字更不容易漏字段。
