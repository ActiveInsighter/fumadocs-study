OSI 更适合建立理论框架；TCP/IP 则是 Internet 实际协议体系的核心。408 复习通常再采用一个折中的**五层模型**来组织知识。

> **真题标签**
>
> TCP/IP 模型：2011 年第 33 题、2012 年第 33 题。

## 1.4.1 TCP/IP 四层模型

从低到高：

```text
应用层
传输层
网际层
网络接口层
```

其中：

- **应用层**：吸收 OSI 的应用层、表示层、会话层功能；
- **传输层**：对应 OSI 传输层；
- **网际层**：大体对应 OSI 网络层；
- **网络接口层**：覆盖链路接入与物理传输相关功能。

TCP/IP 的设计重点是：

> **不同底层网络都能承载 IP，应用则通过 TCP/UDP 等在端系统上实现端到端通信。**

## 1.4.2 五层教学模型

408 教材常用：

```text
应用层
传输层
网络层
数据链路层
物理层
```

它把：

- OSI 的高三层合并为应用层；
- TCP/IP 的网络接口层再拆成数据链路层和物理层。

三种模型可以对齐为：

| OSI 七层 | 五层模型 | TCP/IP 四层 |
| --- | --- | --- |
| 应用层 | 应用层 | 应用层 |
| 表示层 | ↑ | ↑ |
| 会话层 | ↑ | ↑ |
| 传输层 | 传输层 | 传输层 |
| 网络层 | 网络层 | 网际层 |
| 数据链路层 | 数据链路层 | 网络接口层 |
| 物理层 | 物理层 | ↑ |

<Callout type="warn" title="模型名称不要串">
OSI 是七层；TCP/IP 经典模型是四层；408 讲解常使用五层模型。题目问哪一种模型时，要按题目名称回答，不能把五层教学模型写成“TCP/IP 五层”。
</Callout>

## 1.4.3 常见协议的全局定位

这一表只用于“先放到正确层”，协议细节在后续章节展开。

| 层次 | 典型协议 / 技术 | 核心作用 |
| --- | --- | --- |
| 应用层 | HTTP、HTTPS、FTP、SMTP、POP3、DNS、DHCP | 面向具体网络应用 |
| 传输层 | TCP、UDP | 进程到进程传输 |
| 网络层及相关 | IP、ICMP、路由协议、NAT | 寻址、转发、控制 |
| 链路相关 | Ethernet、PPP、ARP | 本地链路交付与地址解析 |

### ARP 的层次归类

ARP 位于 IP 和具体链路技术的衔接位置，不同教材的“层次归类”口径可能不同。

408 更重要的是掌握它的功能：

> **已知同一链路上目标 IPv4 地址，解析得到对应 MAC 地址。**

遇到纯“属于哪一层”的争议题，应以题目给定体系和教材口径为准。

## 1.4.4 应用层协议与默认端口

| 协议 | 默认端口 | 常见传输协议 | 主要作用 |
| --- | ---: | --- | --- |
| HTTP | 80 | TCP | Web 传输 |
| HTTPS | 443 | TCP | 加密 Web 传输 |
| FTP | 21（控制）/ 20（传统主动数据） | TCP | 文件传输 |
| SMTP | 25 | TCP | 邮件发送 |
| POP3 | 110 | TCP | 邮件获取 |
| DNS | 53 | UDP / TCP | 域名解析 |
| DHCP Server | 67 | UDP | 地址配置服务端 |
| DHCP Client | 68 | UDP | 地址配置客户端 |

这些端口用于建立“协议地图”，不意味着现代互联网所有部署都只能使用这些端口。

### DNS 为什么既可能 UDP 又可能 TCP

普通 DNS 查询通常优先使用 UDP；某些场景会使用 TCP，例如：

- 区域传送；
- 响应需要改用 TCP 承载等情况。

因此不要记成“DNS 永远只使用 UDP”。

## 1.4.5 TCP 与 UDP 的定位

### TCP

典型特征：

- 面向连接；
- 可靠；
- 面向字节流；
- 有流量控制；
- 有拥塞控制。

### UDP

典型特征：

- 无连接；
- 面向报文；
- 不保证可靠交付；
- 首部简单、机制轻量。

“TCP 可靠、UDP 不可靠”是结果层面的概括，更深层原因在于 TCP 额外实现了序号、确认、重传、窗口等机制。

## 1.4.6 IP、ICMP 与路由协议

### IP

IP 提供：

> **无连接、尽最大努力的数据报服务。**

因此 IP 本身不承诺：

- 一定到达；
- 不重复；
- 按序到达；
- 永不丢失。

### ICMP

ICMP 用于网络控制、差错报告和诊断。常见 `ping` 使用 ICMP Echo Request / Reply。

### 路由协议

常见：

- RIP；
- OSPF；
- BGP。

它们都用于支撑路由信息形成，但**实际报文的承载方式并不完全相同**。不能仅凭“功能用于路由”就机械断定其报文封装方式。

## 1.4.7 协议地图的学习方式

对每一个协议至少记四件事：

```text
它解决什么问题？
它属于哪一层/靠近哪一层？
它被谁承载？
它使用什么关键地址或端口？
```

例如 HTTP：

```text
功能：Web 应用
层次：应用层
承载：通常 TCP
默认端口：80
```

这样后续综合题就能从“协议名”迅速还原整条协议栈。
