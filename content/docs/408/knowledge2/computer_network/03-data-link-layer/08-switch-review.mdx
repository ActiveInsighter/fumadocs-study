交换机题最核心的两步只有一句话：

> **先看源 MAC 学习，再看目的 MAC 转发。**

> **真题标签**
>
> 交换机选择题：2009-36、2014-34、2015-37、2024-35、2026-36。\
> 交换机综合题：2019-47、2021-47。

## 3.8.1 交换机是多端口网桥

二层交换机按 MAC 地址转发帧，维护类似：

```text
MAC 地址 → 端口
```

的转发表。实际表项还常包含 VLAN、老化时间、动态/静态属性等。

与 Hub 的根本区别：

- Hub：最高到物理层，不读 MAC，收到信号后向其他端口复制；
- Switch：最高到数据链路层，读取帧头，根据 MAC 表选择性转发。

## 3.8.2 自学习：永远先学源 MAC

交换机从端口 $P$ 收到一帧，首先观察**源 MAC**：

> 既然这个帧从 $P$ 端口进来，源主机就在 $P$ 方向。

因此更新：

```text
Source MAC → 入端口 P
```

随后才查询目的 MAC 决定如何处理。

如果同一源 MAC 后来从新端口出现，动态表项可被更新，这也是网络拓扑变化后交换机能够重新学习的基础。

## 3.8.3 四类转发结果

### 目的 MAC 已知，且在其他端口

```text
只向对应端口转发
```

### 目的 MAC 已知，且就在入端口

```text
过滤，不转发
```

因为目的主机与源主机位于同一端口方向，不需要再把帧送回去。

### 目的 MAC 未知

执行**未知单播泛洪（Unknown Unicast Flooding）**：

```text
向同 VLAN 内除入端口外的其他相关端口复制
```

### 目的 MAC 是广播

在当前 VLAN/广播域内，向除入端口外的相关端口泛洪。

<Callout type="warn" title="Flooding ≠ ARP">
Flooding 是交换机的转发动作；ARP 是主机/路由器为了把 IP 地址解析成下一跳 MAC 而发送的协议报文。交换机不知道目的 MAC 时泛洪，不代表交换机自己发起 ARP。
</Callout>

## 3.8.4 VLAN 交换机中的学习与转发

支持 VLAN 时，MAC 转发表通常要结合 VLAN 语境理解：

```text
(VLAN, MAC) → Port
```

帧只在所属 VLAN 内学习和转发。

因此判断某主机能否收到帧时，顺序应是：

1. 源端口属于哪个 VLAN；
2. 交换机学习源 MAC；
3. 目的 MAC 是单播还是广播；
4. 若单播，目的是否在该 VLAN 内有已知表项；
5. 若未知/广播，只在**本 VLAN**泛洪。

> **2026-36 典型模型**
>
> VLAN 交换机已经按端口分组，给出多帧 SA/DA，要求判断某主机能收到哪些帧。必须先限定 VLAN，再应用单播/广播规则。

## 3.8.5 碰撞域与广播域

| 设备/机制 | 碰撞域 | 广播域 |
| --- | --- | --- |
| Hub | 所有端口通常同一个 | 通常同一个 |
| 二层 Switch | 每端口独立 | 默认仍同一个 |
| VLAN | 不用于描述“分隔碰撞域” | 每个 VLAN 独立广播域 |
| Router | 每接口链路独立 | 分隔广播域 |

交换机“隔离碰撞域”并不自动意味着“隔离广播域”。

## 3.8.6 交换机的三种转发时机

这里的“交换方式”指交换机**收到一帧到什么时候开始从输出端口发出**，不要与电路/报文/分组交换混淆。

### 直通交换 Cut-Through

读到足够识别目的 MAC 的字段后即可开始转发。

- 优点：延迟低；
- 缺点：还没收到完整 FCS，可能转发坏帧。

### 存储转发 Store-and-Forward

先接收完整帧，再检查 FCS、查询转发表并转发。

- 优点：能过滤错误帧；
- 缺点：延迟更高。

### 碎片隔离 Fragment-Free

介于二者之间，传统实现常至少等待前 64 B，再开始转发，用于避开经典共享以太网中大量碰撞碎片。

## 3.8.7 网桥与交换机

网桥和交换机都可：

- 学习 MAC；
- 建立转发表；
- 过滤帧；
- 转发帧。

交换机可理解为高速、多端口网桥，现代 LAN 中已成为主流二层设备。

## 3.8.8 2021 类综合题：ARP 与交换机表同时为空

当主机要访问同一局域网或默认网关，但 ARP 表为空时：

1. 主机先发 ARP Request，目的 MAC 为广播；
2. 交换机收到广播帧，**先学习源 MAC → 入端口**；
3. 再在当前 VLAN 内泛洪 ARP Request；
4. ARP Reply 返回时，交换机再学习回复方源 MAC；
5. 之后单播数据帧即可按已学习表项定向转发。

这类题经常把“ARP 表”和“交换机 MAC 表”同时设为空，必须分别维护两个表，不能混为一个。

## 3.8.9 全章高频易错点

### CRC 能不能纠错

CRC 的主线能力是**检错**；错误恢复依赖重传或其他纠错机制。

### GBN 会不会缓存乱序帧

典型 GBN：

$$
W_r=1
$$

乱序帧直接丢弃。

### SR 会不会缓存乱序帧

只要帧位于接收窗口内，可以接收、ACK 并缓存。

### CSMA 为什么听到空闲仍会碰撞

因为存在**传播时延**：本地空闲不代表远端没有刚开始发送。

### CSMA/CD 最小帧长

核心条件：

$$
T_t\ge2T_p
$$

因此：

$$
L_{\min}\ge2T_pR
$$

### CSMA/CA 中 ACK 的作用

ACK 是**确认成功**，不是“避免碰撞”的唯一机制。真正减少碰撞依赖监听、随机退避、竞争窗口、SIFS/DIFS、可选 RTS/CTS 等。

### Ethernet 的 64 B 包不包含什么

不包含 7 B Preamble 和 1 B SFD。

### MTU 1500 B 是不是整帧

不是。它是普通 Ethernet Payload 的最大长度。

### Switch 到底看源还是目的 MAC

```text
源 MAC → 学习
目的 MAC → 转发
```

## 3.8.10 核心公式与结论速查

| 考点 | 结论 |
| --- | --- |
| 零比特填充 | 连续 5 个 `1` 后插 `0` |
| CRC | 模 2 除法，减法就是 XOR |
| 海明校验位 | $2^r\ge k+r+1$ |
| 检错能力 | $d_{\min}-1$ |
| 纠错能力 | $\lfloor(d_{\min}-1)/2\rfloor$ |
| Stop-and-Wait | $W_s=W_r=1$ |
| GBN | $W_r=1$ |
| GBN 最大窗口 | $2^n-1$ |
| SR 典型窗口 | $W_s=W_r$ |
| SR 最大窗口 | $2^{n-1}$ |
| CSMA/CD 条件 | $T_t\ge2T_p$ |
| CSMA/CD 最小帧 | $L_{\min}\ge2T_pR$ |
| Ethernet 最小帧 | 64 B |
| 普通 Ethernet 最大帧 | 1518 B |
| Ethernet MTU | 1500 B |
| MAC 地址 | 48 bit |
| 广播 MAC | `FF:FF:FF:FF:FF:FF` |
| VLAN Tag | 4 B |
| VLAN | 分隔广播域 |
| Switch 学习 | 源 MAC |

| PPP | FCS 检错，不负责可靠重传 |

## 3.8.11 全章三条主线

复习数据链路层时，把题目先归入三类：

### 主线 A：帧怎么被识别、怎么判断错没错

```text
组帧 → 透明传输 → 奇偶校验 / CRC / 海明码
```

### 主线 B：帧丢失、出错后怎么恢复

```text
Stop-and-Wait → GBN → SR → 窗口 → 利用率
```

### 主线 C：多个站都想发怎么办，帧最终往哪走

```text
MAC → CSMA/CD / CSMA/CA → Ethernet / WLAN / VLAN → Switch
```

只要先定位到正确模型，再按该模型的窗口、时序或转发表推进，数据链路层大多数 408 题都能稳定拆解。
