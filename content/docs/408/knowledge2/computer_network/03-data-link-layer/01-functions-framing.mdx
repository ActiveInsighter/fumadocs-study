数据链路层解决的是**相邻结点之间如何以帧为单位交付数据**。复习时先抓住一条主线：

```text
网络层分组 → 组帧 → 差错检测/纠错 → 流量与可靠传输 → 介质访问 → LAN/WAN → 二层转发
```

> **真题标签**
>
> 数据链路层功能、组帧与透明传输属于基础概念题；差错控制、ARQ、CSMA/CD、CSMA/CA 和交换机更常进入计算题与综合题。

## 3.1.1 数据链路层的核心功能

在 408 的典型模型中，数据链路层主要承担：

1. **组帧**：把网络层分组封装成帧，并标识帧边界；
2. **透明传输**：让任意比特/字节组合都能作为数据出现，而不与控制标记冲突；
3. **差错控制**：利用检错或纠错编码应对比特差错；
4. **流量控制**：约束发送方速度，避免接收方来不及处理；
5. **可靠传输**：必要时通过确认、超时和重传恢复丢帧/错帧；
6. **介质访问控制**：共享信道上决定“谁在什么时候发送”；
7. **链路层寻址与转发**：在 LAN 中通过 MAC 地址完成当前链路范围内的交付。

<Callout type="warn" title="逐跳可靠不等于端到端可靠">
链路层即使提供可靠传输，也只负责当前链路/相邻结点。端到端可靠性属于更高层协议的职责，不能把两者混为一谈。
</Callout>

## 3.1.2 为什么必须组帧

物理层只看到连续比特流。链路层必须让接收方知道：

> **一帧从哪里开始、在哪里结束。**

因此“加首部和尾部”只是形式，真正要解决的是**帧定界（Framing）**。

常见方法如下：

| 方法 | 定界依据 | 透明传输手段 | 主要风险/特点 |
| --- | --- | --- | --- |
| 字符计数法 | 首部长度字段 | 通常不需填充 | 长度字段错会破坏后续同步 |
| 字符定界法 | 特殊 FLAG 字节 | 字符填充 / ESC 转义 | 面向字节 |
| 零比特填充法 | 特殊比特串 | 连续 5 个 `1` 后插 `0` | 面向比特 |
| 违规编码法 | 未用于普通数据的物理编码 | 利用非法/保留信号状态 | 依赖物理编码 |

## 3.1.3 字符计数法

在帧首部设置**长度字段**，告诉接收方当前帧包含多少字节或字符。

接收方按如下过程处理：

1. 读取长度字段；
2. 按长度继续接收；
3. 读够长度后认为本帧结束；
4. 下一字节视为下一帧的开始。

优点是简单；缺点是长度字段本身一旦出错，可能导致**帧同步丢失**，并影响多个后续帧。

## 3.1.4 字符定界与字符填充

若协议使用特殊字节 `FLAG` 作为帧边界，就会遇到一个问题：**数据字段本身也可能出现 `FLAG`**。

解决方法是引入转义字节 `ESC`：

- 数据中出现 `FLAG`：发送 `ESC + FLAG`；
- 数据中出现 `ESC`：也需要对 `ESC` 本身转义；
- 接收端识别转义后删除额外的 `ESC`，恢复原数据。

这就是**字符填充（Byte Stuffing）**。

```text
原始数据： A FLAG B ESC C
线路数据： A ESC FLAG B ESC ESC C
```

透明传输的关键不是“不能出现 FLAG”，而是：

> **数据可以任意取值，但协议要保证接收端不会把数据误认成控制边界。**

## 3.1.5 零比特填充

典型面向比特协议使用：

```text
01111110
```

作为标志序列。为避免数据字段内部出现相同模式，发送端规定：

> 每遇到连续 **5 个 `1`**，就在后面自动插入一个 `0`。

例如：

```text
原始：   01111110
填充后： 011111010
```

接收端执行逆过程：若发现连续 5 个 `1` 后的 `0` 是填充位，就把它删除。

<Callout type="info" title="零比特填充速记">
看到 `01111110`，立即联想到“连续 5 个 1 后插 0”；接收端做相反操作。
</Callout>

## 3.1.6 违规编码法

某些物理编码并未使用全部可能的信号状态，因此可以把**正常数据永远不会出现的物理信号组合**用作帧边界。

例如某种编码要求每个码元中间必须跳变，那么不满足该正常编码规则的特殊状态就可被协议保留为定界符。

这种方法的本质是：

> **借用物理层“保留状态”做帧定界。**

## 3.1.7 四种组帧方法的判断顺序

遇到题目时可按以下关键词定位：

```text
长度字段            → 字符计数法
FLAG 字节 + ESC      → 字符填充
01111110             → 零比特填充
保留/非法物理编码状态 → 违规编码法
```

<Callout type="warn" title="字符填充与零比特填充不要混">
字符填充处理的是“特殊字节出现在数据中”；零比特填充处理的是“特殊比特模式出现在数据中”。两者都服务于透明传输，但操作单位不同。
</Callout>

## 3.1.8 本节最小知识闭环

数据链路层首先必须把连续比特流组织成帧：

```text
定界 → 防止数据冒充边界 → 形成透明传输
```

后续的 CRC、ARQ、MAC 和交换机都建立在“已经能正确识别帧”的基础上。
