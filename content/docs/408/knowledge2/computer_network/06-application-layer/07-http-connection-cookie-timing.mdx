HTTP 综合题的难点通常不在报文语法，而在“页面含多个对象时，需要多少次 TCP 建连、多少个 RTT”。做题前必须先区分两个独立维度：

```text
是否持久？
是否流水线？
```

## 6.7.1 非持久连接

非持久 HTTP 中，一条 TCP 连接通常只传输一个 HTTP 请求/响应对象。

若页面包含：

```text
1 个基础 HTML
+ n 个嵌入对象
```

且所有对象顺序获取，则每个对象通常都需要单独 TCP 连接。

在忽略数据发送时间、且 TCP 建连消耗 $1RTT$、HTTP 请求到收到响应首字节再消耗约 $1RTT$ 的简化模型中，每个对象约需：

$$
2RTT
$$

因此 $n+1$ 个对象顺序获取约为：

$$
T\approx 2(n+1)RTT
$$

DNS 时延应另算。

## 6.7.2 持久连接

持久连接允许多个 HTTP 请求/响应复用同一条 TCP 连接，减少重复握手。

### HTTP/1.0

默认通常按非持久连接理解；若显式使用 keep-alive，可保持连接。

### HTTP/1.1

默认采用持久连接。若请求/响应指定：

```text
Connection: close
```

则表示通信后关闭连接。

> **真题标签**
>
> 2015 年 HTTP 请求报文题曾直接用 `Connection: close` 判断是否采用持续连接。

## 6.7.3 持久但非流水线

建立 TCP 连接并取得基础 HTML 后，若后续对象仍必须：

```text
发请求 1 → 等响应 1
发请求 2 → 等响应 2
……
```

则称非流水线。

忽略传输时间时，若有 $n$ 个嵌入对象：

- 首个 HTML：约 $2RTT$；
- 后续每个对象：约再增加 $1RTT$。

因此：

$$
T\approx (n+2)RTT
$$

## 6.7.4 持久 + HTTP/1.1 流水线

HTTP Pipelining 允许客户端在前一个响应尚未返回时继续发送后续请求：

```text
请求 A ─→
请求 B ─→
请求 C ─→
       ←─ 响应 A
       ←─ 响应 B
       ←─ 响应 C
```

在经典 408 简化模型中，基础 HTML 获取后，多个嵌入对象的请求可以在一个额外 RTT 中批量完成请求—响应启动，因此：

$$
T\approx 3RTT
$$

这里同样忽略对象传输时间，并假设对象所在服务器与 TCP 连接条件符合题设。

<Callout type="warn" title="公式不是无条件成立">
若题目给出了对象大小、链路速率、并行 TCP 连接数、多个服务器、DNS RTT 或传输时延，就必须把这些因素显式加入事件链，不能机械套 $2RTT$、$3RTT$。
</Callout>

## 6.7.5 “持久”与“流水线”不是一回事

| 情况 | 是否复用 TCP | 是否可连续发多个请求而不等前一响应 |
| --- | --- | --- |
| 非持久 | 否 | 不适用 |
| 持久非流水线 | 是 | 否 |
| 持久流水线 | 是 | 是 |

因此：

```text
持久连接 ≠ 一定流水线
```

## 6.7.6 队头阻塞

HTTP/1.1 流水线中，响应通常按请求顺序返回。若最前面的响应迟迟不能完成，后面的响应即使准备好了，也可能被阻塞，这称为**队头阻塞**。

HTTP/2 通过多路复用改善 HTTP 层的顺序阻塞，但其经典实现仍建立在 TCP 上，因此底层 TCP 丢包仍可能影响同一连接中的数据交付。

HTTP/2 属于理解性补充，408 主线仍以 HTTP/1.0/1.1 为主。

## 6.7.7 Cookie：在无状态请求之间建立关联

服务器可在响应中发送：

```http
Set-Cookie: sessionId=abc123
```

浏览器保存后，在满足条件的后续请求中携带：

```http
Cookie: sessionId=abc123
```

服务器据此可关联：

- 登录会话；
- 用户偏好；
- 购物车；
- 其他应用状态。

这并未改变 HTTP 本身“请求相互独立、协议不自动维护应用状态”的定义。

## 6.7.8 Web 访问总时延拆分

综合题中可以把总时间写成：

$$
T_{total}=T_{DNS}+T_{TCP/HTTP}+T_{transmission}+T_{other}
$$

其中：

- $T_{DNS}$：域名解析各次 RTT；
- $T_{TCP/HTTP}$：TCP 握手与 HTTP 请求/响应等待；
- $T_{transmission}$：对象大小除以有效发送速率；
- $T_{other}$：题目明确给出的排队、处理等时延。

<Callout type="info" title="时延题最稳方法">
画时间线，逐个标出“DNS、TCP 建连、请求、响应、传输”，再看哪些事件能并行。**先画过程，再列公式。**
</Callout>

## 6.7.9 本节速记

```text
HTTP/1.0：默认非持久
HTTP/1.1：默认持久

持久 ≠ 流水线
Connection: close → 关闭连接

Cookie：
响应 Set-Cookie
后续请求 Cookie
用于应用状态关联
```
