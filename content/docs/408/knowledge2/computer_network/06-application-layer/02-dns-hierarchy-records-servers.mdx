DNS（Domain Name System）最基本的任务是把便于人类记忆的名字映射为网络通信所需的信息，408 最常考的是：

```text
域名 → IP 地址
```

> **真题标签**
>
> DNS：2010、2016、2020 第 40 题；也经常与 Web 访问流程、UDP/IP/ARP 一起出现在综合题中。

## 6.2.1 DNS 为什么采用层次结构

如果全球所有域名都交给一台服务器维护，会产生容量、性能、可靠性和管理边界问题。DNS 因此采用**分布式、层次化**设计。

以：

```text
www.example.com
```

为例，从右到左层级逐渐降低：

```text
. → com → example → www
```

- `.`：根域；
- `com`：顶级域名（TLD）；
- `example.com`：下一级域；
- `www`：该域下的主机名或子域标签。

完整限定域名常称 FQDN（Fully Qualified Domain Name）。

## 6.2.2 DNS 名称空间中的四类服务器

### 根域名服务器

根服务器位于 DNS 委派体系最顶端。它通常**不直接保存普通主机的最终 IP**，而是告诉查询者：

> 负责目标顶级域的 TLD 服务器在哪里。

根区存在 A～M 共 13 个**逻辑根服务器标识**；这不等于全球只有 13 台物理服务器，实际通过 Anycast 等技术部署了大量实例。

### 顶级域名服务器（TLD）

负责特定顶级域，如：

```text
.com  .org  .net  .cn
```

它通常返回目标域的权威 DNS 服务器信息。

### 权威域名服务器

权威服务器保存自己负责区域（zone）的权威资源记录，能够对相应名称给出权威答案。

例如：

```text
www.example.com → 93.184.216.34
```

最终记录通常来自 `example.com` 区域的权威服务器。

### 本地域名服务器 / 递归解析器

主机一般不亲自从根服务器一路查询，而是把请求交给配置好的本地递归解析器。它通常：

1. 接收主机查询；
2. 先查缓存；
3. 缓存未命中时代表主机向外查询；
4. 得到答案后返回给主机；
5. 按 TTL 缓存结果。

<Callout type="warn" title="本地 DNS 不是根/TLD/权威层次中的一层">
根、TLD、权威服务器体现的是 DNS 的**委派层次**；本地递归解析器站在用户一侧，负责替客户端完成解析。
</Callout>

## 6.2.3 常见 DNS 资源记录

DNS 数据以资源记录（Resource Record，RR）组织。408 核心仍是解析过程，但理解记录类型有助于判断服务器返回了什么。

| 类型 | 典型含义 |
| --- | --- |
| A | 域名对应 IPv4 地址 |
| AAAA | 域名对应 IPv6 地址 |
| NS | 某区域的权威名称服务器 |
| CNAME | 别名对应规范名称 |
| MX | 某域负责收邮件的邮件服务器 |

例如邮件服务器转发邮件时，可以先通过目标域的 `MX` 记录找到接收方邮件服务器。

## 6.2.4 DNS 为什么既使用 UDP 又使用 TCP

DNS 服务器端口为 **53**。

普通查询通常优先使用 UDP，因为：

- 无须建立连接；
- 请求/响应通常较短；
- 额外开销小。

DNS 也可以使用 TCP，例如：

- 响应过大，需要可靠传输；
- 区域传送等场景。

因此考题中最稳妥的表述是：

```text
DNS：UDP 为主，也可使用 TCP，服务器端口 53
```

## 6.2.5 “谁保存最终答案”怎么判断

查询 `www.example.com` 时，可按委派关系理解：

```text
根：我知道 .com 去哪问
 ↓
TLD：我知道 example.com 去哪问
 ↓
权威：我掌握 www.example.com 的权威记录
```

如果缓存已经有答案，则不一定需要访问上述全部服务器。

## 6.2.6 本节易错点

<Callout type="warn" title="DNS 高频错误">

- 根服务器通常返回**下一层委派信息**，不是所有域名的最终 IP；
- 本地 DNS 不是固定的“DNS 第四层”；
- DNS 不是每次都从根开始，首先可能命中浏览器、操作系统或递归解析器缓存；
- `53` 是 DNS 服务端口，不意味着只使用 UDP；
- “权威答案”与“缓存答案”来源不同。

</Callout>

## 6.2.7 本节速记

```text
DNS = 分布式 + 层次化

根      → TLD 在哪
TLD     → 权威 DNS 在哪
权威 DNS → 给权威资源记录
本地 DNS → 帮主机递归解析 + 缓存

端口：53
普通查询：UDP 为主
必要时：TCP
```
