应用层直接服务于网络应用进程。408 对本章的考查通常不要求复杂算法，而是要求把**协议用途、传输层、端口、连接建立方向和交互顺序**串成完整链路。

<Callout type="info" title="本章做题主线">
看到应用场景后，依次判断：**用什么应用层协议 → 下层是 TCP 还是 UDP → 服务器监听什么端口 → 谁主动建立连接 → 请求与响应按什么顺序发生**。
</Callout>

> **真题标签**
>
> 网络应用模型：2019 第 40 题、2025 第 39 题。应用层协议还经常与 DNS、TCP、ARP、交换机等知识组合成综合题。

## 6.1.1 C/S 模型

客户/服务器模型（Client/Server）中，客户端和服务器角色明确：

```text
客户端主动请求
      ↓
服务器监听并处理
      ↓
服务器返回响应
```

### 客户端

- 通常主动发起通信；
- 按需接入网络；
- 向服务器请求资源或服务；
- 客户端地址通常不要求固定。

### 服务器

- 通常长期运行；
- 在约定端口上监听；
- 地址相对稳定，便于客户端找到；
- 可能同时服务大量客户端。

典型 C/S 应用：

- Web 浏览器 ↔ Web 服务器；
- FTP 客户端 ↔ FTP 服务器；
- 邮件客户端 ↔ 邮件服务器。

<Callout type="warn" title="“客户端”是角色，不是设备类型">
同一台主机上的不同进程可以分别充当客户端和服务器。判断角色要看**谁主动请求、谁提供服务**。
</Callout>

## 6.1.2 P2P 模型

P2P（Peer-to-Peer）中，各节点逻辑地位更对等，一个节点既能请求资源，也能向其他节点提供资源。

典型特点：

- 资源分散在多个节点；
- 节点之间可直接交换数据；
- 新节点加入会增加需求，也可能增加系统服务能力；
- 管理与控制比集中式 C/S 更分散。

P2P 不意味着“完全没有服务器”。实际系统中仍可能存在用于**发现节点、认证、索引或协调**的辅助服务器，但核心数据交换可以直接发生在对等节点之间。

## 6.1.3 C/S 与 P2P 对比

| 对比项 | C/S | P2P |
| --- | --- | --- |
| 节点角色 | 客户端/服务器区分明显 | 节点可同时请求和提供资源 |
| 资源位置 | 较集中 | 较分散 |
| 管理 | 集中、方便 | 分散、复杂 |
| 扩展瓶颈 | 服务器可能成为瓶颈 | 新节点可同时带来资源 |
| 典型场景 | Web、FTP、邮件 | 对等文件共享等 |

## 6.1.4 应用层协议的定位方法

应用层题最有效的记忆方式不是孤立背端口，而是按“功能”识别协议：

```text
域名 → IP                  DNS
文件上传/下载              FTP
发送、转发电子邮件          SMTP
从邮箱服务器读取邮件        POP3 / IMAP
浏览网页                   HTTP / HTTPS
```

然后再确定下层传输协议和端口。

## 6.1.5 核心协议地图

| 协议 | 主要用途 | 传输层 | 408 常用服务器端口 | 核心特征 |
| --- | --- | --- | ---: | --- |
| DNS | 域名解析 | UDP 为主，也可 TCP | 53 | 层次服务器、递归/迭代、缓存 |
| FTP 控制连接 | 命令与响应 | TCP | 21 | 控制与数据分离 |
| FTP 主动模式数据连接 | 文件/目录数据 | TCP | 服务器传统源端口 20 | 服务器主动连客户端 |
| SMTP | 发送/转发邮件 | TCP | 25 | Push |
| POP3 | 下载邮件 | TCP | 110 | Pull |
| IMAP | 在线管理/同步邮箱 | TCP | 143 | 服务器端状态同步 |
| HTTP | Web 资源传输 | TCP | 80 | 请求/响应、无状态 |
| HTTPS | 加密 Web 访问 | TCP | 443 | HTTP + TLS |

<Callout type="warn" title="端口号的口径">
表中的端口通常指**服务器监听端口**。客户端一般使用操作系统临时分配的源端口，不应把“HTTP=80”理解为通信双方都使用 80 端口。
</Callout>

## 6.1.6 从 URL 到网页的宏观流程

用户输入一个域名形式的 URL 后，典型流程是：

```text
1. DNS：域名 → 服务器 IP
2. 必要时 ARP：下一跳 IP → MAC
3. TCP：与 Web 服务器建立连接
4. HTTP：发送请求
5. HTTP：接收响应对象
6. 浏览器解析页面，并继续请求嵌入对象
```

这里体现了 408 综合题常见的跨层关系：

```text
HTTP 数据
  ↓
TCP 段
  ↓
IP 数据报
  ↓
以太网帧
  ↓
比特流
```

## 6.1.7 本节速记

```text
C/S：客户端主动，服务器监听
P2P：节点可同时请求和提供资源

DNS：53，UDP 为主
FTP：TCP，控制 21，数据另建连接
SMTP：TCP 25，送信
POP3：TCP 110，取信
HTTP：TCP 80，无状态
HTTPS：TCP 443
```
