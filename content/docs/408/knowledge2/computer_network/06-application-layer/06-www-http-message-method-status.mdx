WWW（World Wide Web）是通过互联网访问相互关联资源的应用系统。408 需要把 **URL、HTTP、HTML** 三个概念分清。

> **真题标签**
>
> HTTP/WWW：2014、2015、2022、2024、2026 第 40 题；2011 第 47 题。HTTP 首部、连接方式和 Web 访问全过程都是高频考法。

## 6.6.1 URL、HTTP、HTML 的分工

### URL

URL（Uniform Resource Locator）描述资源的位置和访问方式，例如：

```text
https://www.example.com/docs/index.html
```

其中可包含：

- 协议方案；
- 主机名；
- 端口（若显式给出）；
- 路径；
- 查询参数等。

### HTTP / HTTPS

HTTP 用于浏览器与 Web 服务器之间传输资源。

```text
HTTP  → TCP 80
HTTPS → TCP 443（HTTP 语义 + TLS 安全保护）
```

### HTML

HTML 用于描述网页结构和内容。

```text
HTTP：负责传输
HTML：负责表示网页内容
```

## 6.6.2 HTTP 的请求—响应模型

最基本过程：

```text
客户端 → HTTP 请求 → 服务器
客户端 ← HTTP 响应 ← 服务器
```

HTTP/1.0、HTTP/1.1 与 HTTP/2 常见实现基于 TCP。408 主线主要讨论 HTTP/1.0 与 HTTP/1.1 的连接行为。

## 6.6.3 HTTP “无状态”的准确含义

HTTP 是无状态（stateless）协议：

> 协议本身不要求服务器自动记住同一客户端上一次请求的应用状态。

这并不等于 Web 应用无法维持登录状态。应用可借助：

- Cookie；
- Session；
- Token；

在多次 HTTP 请求之间建立逻辑关联。

<Callout type="warn" title="无状态 ≠ 没有 TCP 连接">
“无状态”描述的是**HTTP 应用状态**；“持久连接”描述的是底层 TCP 连接是否复用。HTTP/1.1 可以既无状态，又使用持久 TCP 连接。
</Callout>

## 6.6.4 HTTP 请求报文

典型结构：

```text
请求行
请求首部
空行
可选消息体
```

例如：

```http
GET /index.html HTTP/1.1
Host: www.example.com
Connection: close
Cookie: sid=123456

```

### 请求行

通常包含：

```text
方法  请求目标  HTTP 版本
```

## 6.6.5 HTTP 响应报文

典型结构：

```text
状态行
响应首部
空行
可选消息体
```

例如：

```http
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1234

<html>...</html>
```

## 6.6.6 常用请求方法

| 方法 | 典型作用 |
| --- | --- |
| GET | 获取资源 |
| POST | 提交数据 |
| PUT | 创建/更新指定资源 |
| DELETE | 删除资源 |
| HEAD | 获取与 GET 类似的响应首部，但不返回正常实体主体 |

408 最常见的是 `GET`。

## 6.6.7 状态码

按百位分类：

| 范围 | 含义 |
| --- | --- |
| 1xx | 信息性响应 |
| 2xx | 成功 |
| 3xx | 重定向 |
| 4xx | 客户端错误 |
| 5xx | 服务器错误 |

常见示例：

```text
200 OK
404 Not Found
500 Internal Server Error
```

## 6.6.8 高频首部字段

| 首部 | 作用 |
| --- | --- |
| `Host` | 指定目标主机/虚拟主机 |
| `Content-Type` | 消息体媒体类型 |
| `Content-Length` | 消息体长度 |
| `User-Agent` | 客户端软件信息 |
| `Connection` | 连接管理意图 |
| `Cookie` | 客户端向服务器发送 Cookie |
| `Set-Cookie` | 服务器要求客户端保存 Cookie |

<Callout type="info" title="从请求报文反推事实">
例如看到 `Connection: close`，可判断本次通信要求关闭连接；看到 `Cookie:`，可判断浏览器已持有该站点可发送的 Cookie，但不要把 Cookie 本身误认为 HTTP 变成了有状态协议。
</Callout>

## 6.6.9 本节速记

```text
URL：资源定位
HTTP：资源传输
HTML：网页描述

HTTP：请求/响应 + 无状态
请求：请求行 + 首部 + 空行 + 可选正文
响应：状态行 + 首部 + 空行 + 可选正文
```
