FTP（File Transfer Protocol）基于 TCP。它最有辨识度的特征是：

> **控制信息和实际数据不共用同一条 TCP 连接。**

这种方式常称为带外控制（out-of-band control）。

> **真题标签**
>
> FTP：2009、2017 第 40 题；2023 第 47 题。高频考点是控制/数据连接、主动/被动模式和连接发起方。

## 6.4.1 两类 TCP 连接

### 控制连接

控制连接用于传输：

- 登录信息；
- 文件操作命令；
- 目录操作命令；
- 状态码与响应。

服务器默认监听 TCP **21** 端口。

典型命令：

```text
USER  PASS  LIST  RETR  STOR  QUIT
```

控制连接通常在整个 FTP 会话期间保持，因此可视为**持久控制通道**。

### 数据连接

数据连接用于传输：

- 文件内容；
- 目录列表等数据。

它通常按需建立，一次数据传输结束后关闭。因此一个 FTP 会话可能是：

```text
1 条长期控制连接
+
多条先后建立的数据连接
```

## 6.4.2 典型 FTP 会话

```text
1. 客户端主动连接服务器 TCP 21
2. 登录认证
3. 通过控制连接发送命令/接收响应
4. 需要 LIST/RETR/STOR 时建立数据连接
5. 数据传输完成后关闭该数据连接
6. 控制连接继续存在
7. QUIT 后结束会话
```

## 6.4.3 主动模式（Active）

主动模式中：

1. 客户端已建立到服务器 21 端口的控制连接；
2. 客户端开放一个数据端口等待；
3. 客户端通过控制连接告诉服务器该端口；
4. **服务器主动向客户端建立数据 TCP 连接**。

传统主动模式下，服务器数据连接一侧通常使用 TCP **20** 端口。

记忆：

```text
“主动” = 服务器主动回连客户端数据端口
```

## 6.4.4 被动模式（Passive）

被动模式中：

1. 控制连接仍由客户端主动连接服务器 21；
2. 客户端发送 PASV 等请求；
3. 服务器开放一个动态数据端口；
4. 服务器把端口告诉客户端；
5. **客户端主动连接服务器的数据端口**。

记忆：

```text
“被动” = 服务器在数据连接上被动等待
```

## 6.4.5 主动与被动模式对比

| 对比项 | 主动模式 | 被动模式 |
| --- | --- | --- |
| 控制连接发起方 | 客户端 | 客户端 |
| 控制连接服务器端口 | 21 | 21 |
| 数据连接监听方 | 客户端 | 服务器 |
| 数据连接主动发起方 | 服务器 | 客户端 |
| 服务器数据端口 | 传统为 20 | 动态协商端口 |

<Callout type="warn" title="最常见陷阱">
“主动/被动”只是在描述**数据连接**。无论哪种模式，控制连接都仍是客户端主动连接服务器 21 端口。
</Callout>

## 6.4.6 ASCII 与二进制传输

FTP 传统上可按文件性质选择：

### ASCII 模式

适合文本，可能根据两端系统差异转换换行等文本表示。

### Binary 模式

按原始字节传输，适合：

- 图片；
- 音视频；
- 可执行程序；
- 压缩包；
- 其他二进制文件。

## 6.4.7 FTP 与 HTTP 文件下载不要混淆

两者都能“传文件”，但模型不同：

| 项目 | FTP | HTTP |
| --- | --- | --- |
| 传输层 | TCP | TCP |
| 控制/数据 | 两条逻辑连接体系 | 请求与响应在 HTTP 连接上完成 |
| 默认端口 | 控制 21 | 80 |
| 核心考点 | 双连接、主动/被动 | 持久连接、请求/响应、无状态 |

## 6.4.8 本节速记

```text
FTP = TCP

控制连接：
客户端 → 服务器 21
长期保持
传命令/响应

数据连接：
按需建立
传文件/目录

主动：服务器主动连客户端，传统源端口 20
被动：客户端主动连服务器动态端口
```
