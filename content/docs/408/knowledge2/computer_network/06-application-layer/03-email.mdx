## 11. 电子邮件系统组成与完整路径

<InlineSvg src="/images/computer-network/computer-network-application-mail-001.svg" alt={"电子邮件 图 1"} />

> **真题考察**
>
> - 2012、2013、2018、2025 年第 40 题
> - 2015 年第 33 题

电子邮件系统主要由三部分组成：

1. **用户代理（UA）**；
2. **邮件服务器**；
3. **邮件传输/访问协议**。

典型链路可以画成：

```text
发送方用户代理
      ↓ SMTP
发送方邮件服务器
      ↓ SMTP
接收方邮件服务器
      ↓ POP3 / IMAP
接收方用户代理
```

因此看到邮件题，先判断当前动作发生在哪一段：

- **发送、提交、服务器间转发**：主要看 SMTP；
- **用户从邮箱服务器读取/管理邮件**：看 POP3 或 IMAP；
- **正文、附件如何表示**：看 MIME；
- **通过浏览器访问 Webmail 页面**：浏览器与 Web 服务器之间使用 HTTP/HTTPS。

<Callout type="warning" title="“电子邮件场景”不等于一定只用邮件协议">

如果题目说“在网页浏览器中查看邮箱”，浏览器与 Webmail 服务器交互属于 HTTP/HTTPS；后台邮件服务器之间仍可能使用 SMTP。做题要按**当前通信的两端是谁**来判断协议。

</Callout>

---

## 12. 用户代理 UA

UA（User Agent）是用户直接操作的邮件应用或界面，例如桌面邮件客户端、手机邮件 App、Web 邮箱界面等。

典型功能包括：

- 编写、发送邮件；
- 阅读、回复、转发邮件；
- 管理收件箱、草稿、已发送等。

UA 属于用户侧应用软件，并不等同于邮件服务器。

---

## 13. 邮件服务器

邮件服务器负责接收、存储、转发邮件并维护用户邮箱。

常见协议分工：

```text
邮件发送/服务器间转发  → SMTP
用户访问服务器邮箱      → POP3 / IMAP
```

若发送方与接收方位于不同邮件服务器，典型过程包含：

```text
发送方服务器 ──SMTP──> 接收方服务器
```

邮件服务器收到邮件后将其放入收件人的邮箱，等待用户后续读取。

---

## 14. SMTP：发送与转发邮件

<InlineSvg src="/images/computer-network/computer-network-application-mail-002.svg" alt={"电子邮件 图 2"} />

SMTP（Simple Mail Transfer Protocol）用于**发送与转发电子邮件**。

典型位置：

```text
发送方 UA → 发送方邮件服务器
发送方邮件服务器 → 接收方邮件服务器
```

在 408 经典模型中 SMTP：

- 位于应用层；
- 使用 **TCP**；
- 传统服务器端口记为 **25**；
- 体现 **Push（推送）** 的应用行为。

也就是说，SMTP 客户端主动把邮件推给 SMTP 服务器或下一台邮件服务器。

<Callout type="warning" title="SMTP 不负责用户从邮箱服务器取信">

SMTP 的核心是“**送出去、转发过去**”。收件人从自己的邮箱服务器读取/同步邮件，应判断 POP3 或 IMAP，而不是 SMTP。

</Callout>

---

## 15. POP3：下载邮件

POP3（Post Office Protocol Version 3）用于用户从邮件服务器获取邮件。

典型特点：

- 使用 TCP；
- 默认端口 **110**；
- 用户代理主动连接服务器，属于 **Pull（拉取）**；
- 传统使用方式更偏向把邮件下载到本地管理，是否在服务器保留副本取决于配置。

```text
用户代理 ──请求/取信──> 邮件服务器
          <──邮件数据──
```

<Callout type="info" title="POP3 的“Pull”不是 TCP 单向传输">

TCP 建立后仍是全双工连接。“Pull”只描述应用层动作：由用户代理主动向服务器请求、下载邮件。

</Callout>

---

## 16. IMAP：服务器端同步管理

IMAP（Internet Message Access Protocol）也用于访问服务器上的邮件，默认使用 TCP **143** 端口。

与 POP3 相比，IMAP 更强调：

> 邮件主要保留在服务器端，客户端与服务器同步邮箱内容及状态。

可以同步的状态包括：

- 已读/未读；
- 文件夹；
- 邮件移动；
- 删除标记等。

因此多个设备访问同一邮箱时，IMAP 更适合保持一致状态。

| 对比项 | POP3 | IMAP |
| --- | --- | --- |
| 核心思路 | 下载邮件 | 在线访问、同步管理 |
| 管理重心 | 更偏本地客户端 | 更偏服务器端 |
| 多设备同步 | 较弱 | 较强 |
| 默认端口 | TCP 110 | TCP 143 |

## 17. SMTP、POP3、IMAP 与 Webmail 的协议分工

这是电子邮件最常见的协议辨析：

```text
SMTP：送信 / 转发
POP3：下载邮件
IMAP：在线访问并同步服务器邮箱
HTTP/HTTPS：浏览器访问 Webmail 页面
```

| 活动 | 典型协议 | 谁主动发起 |
| --- | --- | --- |
| 邮件客户端向邮件服务器发送邮件 | SMTP | 邮件客户端 |
| 邮件服务器之间转发邮件 | SMTP | 发送方邮件服务器 |
| 客户端从邮箱服务器下载邮件 | POP3 | 收件方客户端 |
| 客户端同步服务器邮箱状态 | IMAP | 收件方客户端 |
| 浏览器查看网页邮箱 | HTTP/HTTPS | 浏览器 |

<Callout type="warning" title="不要只看“邮件”两个字判断协议">

协议选择由**当前两个通信实体和动作**决定。例如浏览器查看网页邮箱时，浏览器到 Web 服务器用 HTTP/HTTPS；这不表示整个邮件系统不再使用 SMTP、POP3 或 IMAP。

</Callout>

## 18. 电子邮件格式：信封、首部与主体

<InlineSvg src="/images/computer-network/computer-network-application-mail-003.svg" alt={"电子邮件 图 3"} />

电子邮件可以从逻辑上理解为：

```text
电子邮件
├── 信封（SMTP 投递所需 envelope 信息）
└── 邮件内容
    ├── 首部
    └── 主体
```

### 18.1 信封

信封信息用于 SMTP 传输与投递，例如传输过程中的发件人、收件人地址。它与用户最终看到的邮件首部字段不是完全同一对象。

### 18.2 邮件首部

首部由若干“字段名: 值”组成，例如：

```text
From: sender@example.com
To: abc@example.net
Subject: Meeting Schedule
```

电子邮件地址常写作：

```text
用户名@域名
```

其中域名部分可以借助 DNS 的 MX 等记录找到负责该域邮件接收的服务器。

### 18.3 邮件主体

首部与主体之间用一个空行分隔：

```text
From: sender@example.com
To: abc@example.net
Subject: Meeting Schedule

Dear team,
Please find the meeting schedule attached.
```

<Callout type="warning" title="首部 To 与 SMTP 信封收件人不要机械等同">

实际 SMTP 投递依赖信封地址，邮件内容中的 `To:` 属于首部字段。408 基础题一般不会深入复杂邮件路由，但遇到“信封/邮件内容”辨析时应知道二者不是完全相同的对象。

</Callout>

## 19. MIME：扩展邮件内容表示

<InlineSvg src="/images/computer-network/computer-network-application-mail-004.svg" alt={"电子邮件 图 4"} />

MIME（Multipurpose Internet Mail Extensions）扩展了传统电子邮件内容表示方式，使邮件能够可靠表示多语言文本、图片、音频、视频和附件。

### 19.1 MIME 的主要作用

- 支持非 ASCII 字符和不同字符集；
- 描述消息体的媒体类型；
- 为二进制附件提供合适编码；
- 支持 Multipart，把一封邮件分成多个部分。

例如：

```text
multipart
├── 纯文本正文
├── HTML 正文
└── 附件
```

### 19.2 SMTP 与 MIME 的职责边界

```text
SMTP：邮件如何从一台主机/服务器送到另一台
MIME：邮件正文和附件如何表示与编码
```

<Callout type="warning" title="MIME 不是邮件传输协议">

MIME 不替代 SMTP，也不负责建立两台邮件服务器之间的网络连接。它主要扩展邮件内容的**类型描述与编码表示**。

</Callout>

### 19.3 电子邮件一页速记

```text
发送/转发：SMTP，TCP 25，Push
下载邮件：POP3，TCP 110，Pull
同步邮箱：IMAP，TCP 143
浏览器看 Webmail：HTTP/HTTPS
附件/多媒体表示：MIME
```
