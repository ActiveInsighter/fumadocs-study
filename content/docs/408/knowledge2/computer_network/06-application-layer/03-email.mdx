## 11. 电子邮件系统组成与完整路径

<InlineSvg src="/images/computer-network/computer-network-application-mail-001.svg" alt={"电子邮件 图 1"} />

> **真题考察**
>
> - 2012、2013、2018、2025 年第 40 题
> - 2015 年第 33 题

电子邮件系统主要由三部分组成：

1. **用户代理（UA）**；
2. **邮件服务器**；
3. **邮件传输与访问协议**。

典型通信链路为：

```text
发送方用户代理
      ↓ SMTP
发送方邮件服务器
      ↓ SMTP
接收方邮件服务器
      ↓ POP3 / IMAP
接收方用户代理
```

因此一道邮件协议题，首先要判断数据处在哪一段：

- **发送/转发**阶段：主要看 SMTP；
- **用户读取/管理邮箱**阶段：主要看 POP3 或 IMAP；
- **正文/附件如何表示**：看 MIME。

---

## 12. 用户代理 UA

UA（User Agent）是用户直接操作的邮件应用程序或界面，例如邮件客户端、Web 邮箱界面、Outlook 等。

典型功能包括：

- 编写、发送邮件；
- 阅读、回复、转发邮件；
- 管理收件箱、草稿、已发送邮件等。

UA 是用户侧软件，并不等同于邮件服务器。

---

## 13. 邮件服务器

邮件服务器负责接收、存储、转发邮件并维护用户邮箱。

常见协议分工：

```text
邮件服务器之间转发邮件 → SMTP
用户访问服务器邮箱       → POP3 / IMAP
```

如果发送方与接收方不在同一邮件服务器上，典型过程通常包含“发送方服务器 → 接收方服务器”的 SMTP 转发。

---

## 14. SMTP：发送与转发邮件

<InlineSvg src="/images/computer-network/computer-network-application-mail-002.svg" alt={"电子邮件 图 2"} />

SMTP（Simple Mail Transfer Protocol）用于**发送和转发电子邮件**。

典型位置：

```text
发送方 UA → 发送方邮件服务器
发送方邮件服务器 → 接收方邮件服务器
```

408 经典模型中 SMTP：

- 位于应用层；
- 使用 **TCP**；
- 服务器间传统默认端口为 **25**；
- 采用 **Push（推送）**思想。

也就是说，SMTP 客户端主动把邮件推送给 SMTP 服务器。

<Callout type="warning" title="SMTP 不负责用户收信">

SMTP 的核心职责是“**送出去、转发过去**”，不是让收件人从自己的邮箱服务器中读取邮件。用户收取或管理服务器中的邮件应看 POP3 / IMAP。

</Callout>

---

## 15. POP3：下载邮件

POP3（Post Office Protocol Version 3）用于用户从邮件服务器获取邮件。

典型特点：

- 使用 TCP；
- 默认端口为 **110**；
- 用户代理主动连接服务器，可理解为 **Pull（拉取）**；
- 传统使用方式偏向把邮件下载到本地管理，可根据配置决定服务器是否保留副本。

```text
用户代理 ──主动请求──> 邮件服务器
          <──邮件数据──
```

POP3 的核心不是“服务器主动推邮件给客户端”，而是客户端主动访问邮箱服务器。

---

## 16. IMAP：服务器端同步管理

IMAP（Internet Message Access Protocol）同样用于访问服务器上的邮件，默认使用 TCP **143 端口**。

与 POP3 相比，IMAP 更强调：

> 邮件保留在服务器端，由客户端与服务器同步邮箱状态。

可以同步：

- 已读/未读状态；
- 文件夹；
- 邮件移动；
- 删除状态等。

因此多设备访问同一邮箱时，IMAP 更适合保持一致状态。

| 对比项 | POP3 | IMAP |
| --- | --- | --- |
| 基本思路 | 下载邮件 | 在线访问、同步管理 |
| 主要管理位置 | 更偏本地客户端 | 更偏邮件服务器 |
| 多设备同步 | 较弱 | 较强 |
| 默认端口 | TCP 110 | TCP 143 |

---

## 17. SMTP、POP3 与 IMAP 的通信方向

这是应用层最容易混淆的一组协议：

```text
SMTP：送信 / Push
POP3：取信 / Pull
IMAP：访问并同步服务器邮箱
```

| 协议 | 谁主动 | 主要目的 |
| --- | --- | --- |
| SMTP | 发送方 SMTP 客户端 | 把邮件推送给服务器/下一邮件服务器 |
| POP3 | 收件方用户代理 | 从服务器下载邮件 |
| IMAP | 收件方用户代理 | 访问和同步服务器邮箱状态 |

<Callout type="info" title="Push / Pull 是应用行为，不是 TCP 方向">

TCP 连接建立后本身是全双工的。“SMTP 是 Push、POP3 是 Pull”描述的是**应用层谁主动发起邮件数据的发送/获取逻辑**，不要误解为 TCP 只能单向传输。

</Callout>

## 18. 电子邮件格式：信封、首部与主体

<InlineSvg src="/images/computer-network/computer-network-application-mail-003.svg" alt={"电子邮件 图 3"} />

电子邮件可以从逻辑上理解为：

```text
电子邮件
├── 信封（SMTP 传输使用的 envelope 信息）
└── 邮件内容
    ├── 首部
    └── 主体
```

### 18.1 信封

信封信息用于邮件传输和投递，例如 SMTP 传输过程中的发件人、收件人地址。它与用户看到的邮件首部字段不是完全同一概念。

### 18.2 邮件首部

首部由若干“字段名: 值”组成，常见字段：

```text
From: sender@example.com
To: abc@cskaoyan.com
Subject: Meeting Schedule
```

电子邮件地址通常写作：

```text
用户名@域名
```

### 18.3 邮件主体

首部和主体之间用一个空行分隔：

```text
From: sender@example.com
To: abc@cskaoyan.com
Subject: Meeting Schedule

Dear team,
Please find the meeting schedule attached.
```

<Callout type="warning" title="邮件首部 To 与 SMTP 信封收件人不要机械等同">

实际邮件投递由 SMTP 信封地址驱动，邮件内容中的 `To:` 等字段属于邮件首部。408 基础题一般不深入这一差异，但遇到“信封/内容”辨析时应知道二者不是完全相同的对象。

</Callout>

## 19. MIME：扩展邮件内容表示

<InlineSvg src="/images/computer-network/computer-network-application-mail-004.svg" alt={"电子邮件 图 4"} />

MIME（Multipurpose Internet Mail Extensions）是对传统电子邮件内容表示方式的扩展，解决早期纯 ASCII 邮件难以携带多语言文字、图片、音频、视频和附件的问题。

### 19.1 MIME 的主要作用

- 支持非 ASCII 字符和不同字符集；
- 描述消息体内容类型；
- 支持二进制附件的编码传输；
- 支持 Multipart，把一封邮件拆成多个部分。

例如：

```text
multipart
├── 纯文本正文
├── HTML 正文
└── 附件
```

常见 MIME 思想可以概括为：

```text
SMTP：负责“怎么把邮件送过去”
MIME：负责“邮件内容如何表示”
```

<Callout type="warning" title="MIME 不是邮件传输协议">

MIME 不替代 SMTP，也不负责在两台邮件服务器之间建立连接。它主要扩展邮件正文和附件的**内容类型与编码表示**。

</Callout>
