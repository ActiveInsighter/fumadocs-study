## 11. 电子邮件系统

电子邮件系统主要由三个部分组成：

1. **用户代理 UA**
2. **邮件服务器**
3. **电子邮件协议**

<InlineSvg src="/images/computer-network/computer-network-application-mail-001.svg" alt={"电子邮件 图 1"} />

整体过程可以概括为：

```text
发送方用户代理
      ↓ SMTP
发送方邮件服务器
      ↓ SMTP
接收方邮件服务器
      ↓ POP3 / IMAP
接收方用户代理
```

---

## 12. 用户代理 UA

UA（User Agent，用户代理）是用户直接使用的邮件应用程序或操作界面。

例如：

* 邮件客户端；
* Web 邮箱界面；
* Outlook 等软件。

用户代理负责：

* 编写邮件；
* 发送邮件；
* 查看邮件；
* 回复、转发邮件；
* 管理收件箱、发件箱、草稿等。

---

## 13. 邮件服务器

邮件服务器负责：

* 接收邮件；
* 存储邮件；
* 转发邮件；
* 保存用户邮箱；
* 向用户代理提供邮件访问服务。

邮件服务器之间发送邮件通常使用：

> **SMTP**

用户从服务器获取或管理邮件通常使用：

> **POP3 或 IMAP**

---

## 14. SMTP

SMTP（Simple Mail Transfer Protocol，简单邮件传输协议）用于：

> **发送和转发电子邮件。**

主要应用于：

```text
发送方 UA → 发送方邮件服务器
```

以及：

```text
发送方邮件服务器 → 接收方邮件服务器
```

SMTP：

* 位于应用层；
* 使用 **TCP**；
* 服务器之间传统默认端口为 **25**；
* 工作模式属于 **Push（推送）**。

也就是说：

> SMTP 客户端主动把邮件推送给 SMTP 服务器。

#### SMTP 的职责

SMTP 负责：

* 邮件的发送；
* 邮件服务器之间的转发。

SMTP **不负责**用户从邮箱服务器中读取邮件。

> **易错**
>
> SMTP 不等于“完整电子邮件协议”。
> SMTP 主要解决的是 **怎么把邮件送出去**。

---

## 15. POP3

POP3（Post Office Protocol Version 3）用于：

> 从邮件服务器获取邮件。

特点：

* 使用 TCP；
* 默认端口为 **110**；
* 属于 **Pull（拉取）**&#x2060;方式。

过程可以理解为：

```text
用户代理
   │
   │ 主动请求
   ↓
邮件服务器
   │
   ↓
下载邮件
```

传统 POP3 的典型使用方式是：

1. 用户登录邮箱服务器；
2. 将邮件下载到本地；
3. 根据配置决定服务器是否继续保留副本。

因此 POP3 更偏向：

> **把邮件从服务器下载到本地管理。**

---

## 16. IMAP

IMAP（Internet Message Access Protocol）同样用于访问服务器上的电子邮件。

与 POP3 相比，IMAP 更强调：

> 邮件保留在服务器上，由客户端与服务器同步邮件状态。

例如可以同步：

* 邮件是否已读；
* 文件夹；
* 邮件移动；
* 删除状态。

因此多设备使用邮箱时，IMAP 通常更适合保持一致状态。

默认 TCP 端口通常为：

```text
143
```

#### POP3 与 IMAP

| 项目       | POP3    | IMAP      |
| -------- | ------- | --------- |
| 主要思路     | 下载到本地   | 服务器端管理、同步 |
| 邮件主要管理位置 | 本地客户端   | 邮件服务器     |
| 多设备同步    | 较弱      | 较强        |
| 默认端口     | TCP 110 | TCP 143   |

---

## 17. SMTP 与 POP3 的 Push / Pull

<InlineSvg src="/images/computer-network/computer-network-application-mail-002.svg" alt={"电子邮件 图 2"} />

这是 408 中非常重要的一组区别。

#### SMTP

```text
Push
```

发送方主动把邮件：

> **推给服务器**

#### POP3 / IMAP

```text
Pull / Access
```

用户代理主动访问服务器：

> **获取或管理邮箱中的邮件**

因此可以记忆：

```text
SMTP：送信
POP3 / IMAP：取信
```

## 18. 电子邮件格式

电子邮件可以从逻辑上划分为：

```text
电子邮件
├── 信封
└── 内容
    ├── 首部
    └── 主体
```

<InlineSvg src="/images/computer-network/computer-network-application-mail-003.svg" alt={"电子邮件 图 3"} />

---

### 18.1 信封

信封包含邮件传输过程中需要的信息。

这些信息通常由邮件系统根据邮件首部自动提取，不需要普通用户手工填写完整的 SMTP 信封。

---

### 18.2 邮件首部

首部由若干首部行构成。

格式：

```text
关键字: 值
```

常见字段包括：

#### From

表示发件人邮箱地址。

例如：

```text
From: sender@example.com
```

#### To

表示一个或多个收件人地址。

例如：

```text
To: abc@cskaoyan.com
```

电子邮件地址通常写作：

```text
用户名@域名
```

#### Subject

表示邮件主题。

例如：

```text
Subject: Meeting Schedule
```

---

### 18.3 邮件主体

首部和主体之间：

> 使用一个空行分隔。

例如：

```text
From: sender@example.com
To: abc@cskaoyan.com
Subject: Meeting Schedule

Dear team,
Please find the meeting schedule attached.
```

## 19. MIME

MIME（Multipurpose Internet Mail Extensions，多用途互联网邮件扩展）是对传统电子邮件格式的扩展。

早期电子邮件主要面向 ASCII 文本，难以直接表示：

* 中文等非 ASCII 字符；
* 图片；
* 音频；
* 视频；
* 附件；
* 多种不同格式的正文。

MIME 用于解决这些问题。

<InlineSvg src="/images/computer-network/computer-network-application-mail-004.svg" alt={"电子邮件 图 4"} />

### 19.1 MIME 的主要作用

#### 支持非 ASCII 字符

可以传输：

* 中文；
* 其他语言文字；
* UTF-8 编码文本。

#### 支持多媒体

允许邮件携带：

* JPEG；
* PNG；
* 音频；
* 视频；
* 二进制附件。

#### 支持 Multipart

一封邮件可以同时包含多个部分，例如：

```text
multipart
├── 纯文本正文
├── HTML 正文
└── 附件
```

> **理解**
>
> SMTP 负责解决“怎么发送邮件”，MIME 主要解决“邮件内容怎么表示”。
