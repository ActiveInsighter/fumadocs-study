应用层是计算机网络最后一章，但综合题往往要求从应用层一路追踪到链路层。因此复习目标不是只记协议缩写，而是能回答：

> **某一步为什么发生、谁发给谁、用哪个协议封装、地址和连接状态如何变化。**

## 6.8.1 浏览器访问网页的完整链路

假设用户首次访问：

```text
http://www.example.com/index.html
```

一个典型过程是：

### 第 1 步：解析域名

```text
www.example.com
      ↓ DNS
目标服务器 IP
```

若 DNS 缓存未命中，主机通常向本地 DNS 发递归查询，本地 DNS 再向根/TLD/权威服务器迭代查询。

### 第 2 步：确定下一跳 MAC

如果 DNS 服务器或 Web 服务器 IP 不在本地链路，则主机实际发送以太网帧时，目的 MAC 往往是**默认网关**的 MAC。

若 ARP 缓存没有该映射，则先运行 ARP。

### 第 3 步：建立 TCP 连接

HTTP/1.x 的经典 408 模型中，浏览器与服务器建立 TCP 连接：

```text
客户端临时端口 → 服务器 80
```

### 第 4 步：发送 HTTP 请求

应用层数据向下封装：

```text
HTTP 请求
  ↓
TCP 段
  ↓
IP 数据报
  ↓
以太网帧
```

### 第 5 步：接收 HTML，并继续请求对象

浏览器解析基础 HTML 后，可能继续请求图片、CSS、脚本等对象。需要多少 TCP 连接、多少 RTT，要看题目给的是：

- 非持久；
- 持久非流水线；
- 持久流水线；
- 并行连接。

> **真题标签**
>
> 2021 年网络综合题就把 DNS、ARP、交换机学习、HTTP 和逐层封装放在同一场景中考查。

## 6.8.2 地址在不同层的变化

在没有 NAT 的普通跨网通信中：

```text
应用层：域名/URL 等应用标识
传输层：端口端到端使用
网络层：源/目的 IP 端到端基本不变
链路层：源/目的 MAC 每一跳重新封装
```

若经过 NAT，则 IP 地址/端口还可能按 NAT 表发生转换。

## 6.8.3 全章协议对比

| 协议 | 作用 | 传输层 | 默认端口 | 最关键考点 |
| --- | --- | --- | ---: | --- |
| DNS | 名称解析 | UDP/TCP | 53 | 递归/迭代、层次、缓存 |
| FTP 控制 | FTP 命令/响应 | TCP | 21 | 控制连接持续存在 |
| FTP 数据 | 文件/目录 | TCP | 主动模式服务器传统为 20 | 主动/被动模式 |
| SMTP | 发/转邮件 | TCP | 25 | Push |
| POP3 | 下载邮件 | TCP | 110 | Pull |
| IMAP | 邮箱同步管理 | TCP | 143 | 多设备状态同步 |
| HTTP | Web 资源 | TCP | 80 | 无状态、连接方式 |
| HTTPS | 安全 Web | TCP | 443 | HTTP + TLS |

## 6.8.4 高频“谁主动”

```text
C/S：客户端主动请求

FTP 控制连接：客户端 → 服务器 21
FTP 主动数据：服务器 → 客户端
FTP 被动数据：客户端 → 服务器

SMTP：发送端主动推送
POP3/IMAP：用户代理主动访问邮箱服务器

HTTP：浏览器/客户端主动发请求
```

## 6.8.5 高频“谁负责继续查”

```text
DNS 递归：被查询服务器继续查
DNS 迭代：查询者自己继续查
```

## 6.8.6 高频易错点总表

### DNS

- 缓存未命中才需要继续外部查询；
- 根服务器一般给 referral，不是最终 IP；
- 主机→本地 DNS 常见递归，本地 DNS→根/TLD/权威常见迭代；
- DNS 53 端口可使用 UDP，也可使用 TCP。

### FTP

- 不是只有一条 TCP 连接；
- 21 是控制端口；
- 主动/被动描述的是**数据连接的发起方向**。

### 邮件

- SMTP 是送信，不是取信；
- POP3/IMAP 是邮件访问；
- MIME 是内容表示扩展，不是邮件传输协议。

### HTTP

- 无状态不等于不能登录；
- 无状态与持久连接不矛盾；
- HTTP/1.1 默认持久；
- `Connection: close` 表示本次连接完成后关闭；
- 持久连接不等于流水线。

## 6.8.7 应用层选择题四步法

### ① 先识别场景

```text
域名 → DNS
文件 → FTP
发邮件 → SMTP
取邮件 → POP3/IMAP
网页 → HTTP
```

### ② 再识别下层

```text
FTP / SMTP / POP3 / IMAP / HTTP → TCP
DNS → UDP 为主，也可 TCP
```

### ③ 再看连接/方向

判断：

- 是否需要建立连接；
- 一条还是多条连接；
- 谁主动发起；
- 连接是否持久。

### ④ 最后串时间顺序

例如访问网页：

```text
DNS → TCP 建连 → HTTP 请求 → HTTP 响应
```

不要把 HTTP 请求放在 DNS 解析或 TCP 建立之前。

## 6.8.8 一页速记

```text
【应用模型】
C/S：客户端主动，服务器监听
P2P：节点既可请求也可服务

【DNS】
53，UDP 为主/TCP 可用
根 → TLD → 权威
主机→本地 DNS：常见递归
本地 DNS→外部 DNS：常见迭代
TTL 控制缓存寿命

【FTP】
TCP
控制：客户端→21，长期保持
数据：按需建立
主动：服务器回连客户端，传统源端口 20
被动：客户端连服务器动态端口

【邮件】
SMTP：TCP 25，Push，发送/转发
POP3：TCP 110，下载
IMAP：TCP 143，同步管理
MIME：扩展邮件内容格式

【HTTP】
HTTP：TCP 80
HTTPS：TCP 443
请求/响应，无状态
HTTP/1.0：默认非持久
HTTP/1.1：默认持久
持久 ≠ 流水线
Cookie：跨请求关联应用状态

【网页综合题】
DNS → 必要时 ARP → TCP → HTTP
应用数据 → TCP 段 → IP 数据报 → 帧
```
