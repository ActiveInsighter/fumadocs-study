电子邮件系统不是“一个协议”，而是由用户代理、邮件服务器和若干应用层协议共同完成发送、转发、存储与读取。

> **真题标签**
>
> 电子邮件：2012、2013、2018、2025 第 40 题；2015 第 33 题。高频判断是 SMTP/POP3/MIME 的职责边界。

## 6.5.1 电子邮件系统组成

主要包含：

1. **用户代理（UA）**：用户编写、查看和管理邮件；
2. **邮件服务器**：接收、存储、排队和转发邮件；
3. **邮件协议**：完成发送、服务器间转发和用户取信。

典型链路：

```text
发送方 UA
   │ SMTP
   ↓
发送方邮件服务器
   │ SMTP
   ↓
接收方邮件服务器
   │ POP3 / IMAP
   ↓
接收方 UA
```

若用户使用网页邮箱，则浏览器与 Web 邮箱站点之间还会使用 HTTP/HTTPS；服务器之间的邮件传递仍可使用 SMTP。

## 6.5.2 SMTP：负责“送信”

SMTP（Simple Mail Transfer Protocol）用于：

- 用户代理向发送方邮件服务器提交邮件；
- 邮件服务器之间转发邮件。

408 常用模型：

```text
SMTP → TCP → 服务器端口 25
```

SMTP 的方向可记为 **Push**：发送方 SMTP 客户端主动把邮件推送给 SMTP 服务器。

<Callout type="warn" title="SMTP 不负责用户读邮件">
SMTP 的核心职责是发送和转发。用户从邮箱服务器读取邮件通常使用 POP3、IMAP，或使用 Webmail 的 HTTP/HTTPS。
</Callout>

## 6.5.3 POP3：下载邮件

POP3（Post Office Protocol Version 3）：

```text
POP3 → TCP → 服务器端口 110
```

典型思想：

- 客户端主动登录邮件服务器；
- 把邮件下载到本地；
- 根据配置删除或保留服务器副本。

可记为：

```text
POP3 = Pull = “取信到本地”
```

## 6.5.4 IMAP：服务器端同步管理

IMAP（Internet Message Access Protocol）：

```text
IMAP → TCP → 服务器端口 143
```

与 POP3 相比，IMAP 更强调邮件保留在服务器上，并同步：

- 已读/未读状态；
- 文件夹；
- 删除与移动；
- 多设备访问状态。

| 对比项 | POP3 | IMAP |
| --- | --- | --- |
| 主要思路 | 下载到本地 | 服务器端管理和同步 |
| 多设备一致性 | 较弱 | 较强 |
| 默认端口 | TCP 110 | TCP 143 |

408 大纲主线要求 SMTP 与 POP3；IMAP 主要用于帮助区分现代邮件访问方式。

## 6.5.5 邮件内容：信封、首部、主体

逻辑上可写为：

```text
电子邮件
├─ 信封：SMTP 投递过程中使用的路由信息
└─ 内容
   ├─ 首部
   └─ 主体
```

邮件首部由若干：

```text
字段名: 值
```

组成，例如：

```text
From: sender@example.com
To: student@example.edu
Subject: Meeting Schedule

正文从这里开始……
```

首部与主体之间用**空行**分隔。

常见首部：

- `From`：发件人；
- `To`：收件人；
- `Subject`：主题。

## 6.5.6 MIME：解决“内容怎么表示”

MIME（Multipurpose Internet Mail Extensions）不是新的邮件传输协议，而是对邮件内容格式的扩展。

它解决传统邮件仅适合 ASCII 文本的问题，使邮件可表示：

- 中文等非 ASCII 文本；
- 图片、音频、视频；
- 二进制附件；
- 多部分内容（multipart）；
- 纯文本与 HTML 等不同内容类型。

因此要区分：

```text
SMTP：邮件怎么送
POP3/IMAP：用户怎么取/管邮件
MIME：邮件内容怎么表示
```

## 6.5.7 邮件服务器如何找到对方

发送方邮件服务器需要知道目标域的邮件服务器。DNS 中的 **MX 记录**可以提供该信息：

```text
收件人地址：user@example.com
          ↓
提取域：example.com
          ↓ DNS MX 查询
获得目标邮件服务器
          ↓ SMTP
服务器间转发邮件
```

这体现了应用层协议之间也可以协作。

## 6.5.8 高频判断

<Callout type="warn" title="四组边界">

- SMTP：**发送/转发**，不是读取；
- POP3：偏向**下载**；
- IMAP：偏向**服务器端同步管理**；
- MIME：**内容格式扩展**，不是传输协议。

</Callout>

## 6.5.9 本节速记

```text
SMTP：TCP 25，Push，送信
POP3：TCP 110，Pull，下载邮件
IMAP：TCP 143，服务器同步
MIME：中文/附件/多媒体/multipart

发送方服务器 → 接收方服务器：SMTP
用户取信：POP3 / IMAP
```
