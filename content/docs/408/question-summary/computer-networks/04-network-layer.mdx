### 高频边界与易错条件

<Callout type="warn" title="网络层最容易混淆的五件事">

- **路由器依据目的 IP 和路由表决定下一跳**，以太网帧的目的 MAC 是当前链路的下一跳 MAC，不一定是最终目的主机。
- **最长前缀匹配**选择最具体的匹配路由；汇总后可使用更具体的例外路由维持原转发行为。
- **IPv4 分片偏移以 8B 为单位**；非最后一片承载的 IP 数据长度应为 8B 整数倍（通常假定各片首部等长）。
- **TTL 每经路由器转发减 1**；路由器重算 IPv4 首部校验和，链路层 MAC 地址在逐跳封装时变化。
- **IPv6 路由器不会沿途进行分片**；不要把 IPv4 的 ARP、首部校验和、路由器分片照搬到 IPv6。

</Callout>

### 核心公式与概念对照

<Tabs items={["子网与主机数", "IPv4 分片", "RIP 距离向量", "最长前缀匹配"]} defaultIndex={0}>

<Tab value="子网与主机数">

CIDR 前缀为 $/p$ 时，地址块规模为 $2^{32-p}$ 个 IPv4 地址。**通常**的普通 LAN 子网在不考虑特殊地址和保留用途时可用主机数为：

$$
N_{\mathrm{host}}=2^{32-p}-2.
$$

这一课堂公式不适用于一概判断 $/31$ 点到点链路和 $/32$ 主机路由；具体应遵循相应标准与题目约定。

</Tab>

<Tab value="IPv4 分片">

原数据报总长 $L$、原 IP 首部长度 $H$、下一跳 MTU 为 $M$，若每个分片首部长度仍为 $H$ 且允许分片：

$$
D=L-H,\qquad D_{\max}=8\left\lfloor\frac{M-H}{8}\right\rfloor.
$$

第 $i$ 片的偏移字段为 **该片数据在原始负载中的起始字节位置除以 8**。分片前要先检查 DF 位、MTU 与首部长度；若 $M-H<8$，常规的非末片有效载荷推导不再适用。

</Tab>

<Tab value="RIP 距离向量">

经典距离向量更新：

$$
D_x(y)=\min_{v\in N(x)}\big[c(x,v)+D_v(y)\big].
$$

在 RIP 的跳数度量中，**16 代表不可达**，路由项更新还需考虑下一跳是否相同、计时器与毒性逆转等实际规则。

</Tab>

<Tab value="最长前缀匹配">

对所有包含目标 IP 的路由前缀，选取前缀长度最大的一个。若有多个相同前缀长度的有效路由，须根据实际路由优先级、度量或等价多路径配置决定，不能仅用前缀长度决定唯一下一跳。

</Tab>

</Tabs>

## 一、本章整体知识体系

网络层解决的核心问题是：

一个 IP 数据报如何从源主机出发，经过多个不同的网络和路由器，最终到达目的主机？

整个过程可以理解为：

```text
源主机产生 IP 数据报
        │
        ▼
根据 IP 地址和子网掩码
判断目标是否在同一子网
        │
        ├── 同一子网
        │     │
        │     ▼
        │   ARP 获取目标 MAC
        │     │
        │     ▼
        │   直接封装以太网帧发送
        │
        └── 不同子网
              │
              ▼
          查找默认网关
              │
              ▼
          ARP 获取网关 MAC
              │
              ▼
          发送给路由器
              │
              ▼
      路由器检查 IP 首部、TTL
              │
              ▼
       最长前缀匹配路由表
              │
              ▼
      选择下一跳、输出接口
              │
              ▼
      必要时执行 NAT / 分片
              │
              ▼
        重新封装链路层帧
              │
              ▼
          下一台路由器
              │
             ...
              │
              ▼
           目的主机
```

## 第一部分：网络层基本原理

## 二、网络层的功能与服务

### 2.1 网络层的四项核心功能

（1）异构网络互联

把以太网、无线网络等不同类型的网络连接起来，通过统一的 IP 寻址和分组转发实现通信。

不同网络的链路层帧格式可能不同，但它们可以共同承载 IP 数据报。

（2）路由选择 Routing

决定从源网络到目的网络应该经过哪些路由器。

例如：

```text
           R2 ───── R4
          /           \
A ──── R1              R5 ──── B
          \           /
           R3 ───────
```

从 A 到 B 存在两条路径。

路由算法需要决定应该选择哪条路径。

（3）分组转发 Forwarding

路由器收到具体 IP 数据报后，根据转发表决定输出端口。

路由与转发的区别：

| 路由选择        | 分组转发     |
| ----------- | -------- |
| 决定路径        | 执行逐跳发送   |
| 主要属于控制平面    | 属于数据平面   |
| 使用路由算法、路由协议 | 使用转发表    |
| 相对低频        | 需要高速逐包执行 |

记忆：

路由负责算路，转发负责送包。

（4）拥塞控制

当大量数据报进入网络，超过中间路由器或链路的处理能力时，就会出现排队、时延增大和丢包。

注意：

- 流量控制：解决发送方与接收方处理能力不匹配的问题。
- 拥塞控制：解决网络内部负载超过资源承载能力的问题。

网络层可以通过队列管理、主动丢弃、ECN 等机制参与拥塞控制，传输层 TCP 也具有端到端拥塞控制功能。

### 2.2 数据报服务与虚电路服务

这是理解网络层设计思想的基础。

| 对比          | 数据报服务      | 虚电路服务        |
| ----------- | ---------- | ------------ |
| 是否需要建立连接    | 不需要        | 需要           |
| 路由选择        | 分组可独立选路    | 通常建立虚电路时确定路径 |
| 分组首部        | 包含完整目的地址   | 可使用虚电路标识     |
| 路由器是否维护连接状态 | 不要求维护逐连接状态 | 需要维护相关状态     |
| 分组是否一定按序    | 不保证        | 同一虚电路通常按序    |
| 典型代表        | IP         | ATM 等虚电路网络   |

Internet 的 IP 层采用无连接、尽最大努力交付的数据报服务。

也就是说，IP 本身不保证：

- 一定送达；
- 按序到达；
- 不重复；
- 不发生错误或丢包。

IP 首部校验和也不能让 IP 变成可靠传输协议。

如果应用需要端到端可靠性，通常依靠 TCP 等更高层协议。

### 2.3 网络层、数据链路层、传输层的服务对象

| 层次    | 主要服务范围         | 核心信息   |
| ----- | -------------- | ------ |
| 数据链路层 | 相邻节点之间         | MAC 地址 |
| 网络层   | 源主机到目的主机的跨网络交付 | IP 地址  |
| 传输层   | 端到端进程通信        | 端口号    |

在普通 IP 路由过程中：

IP 地址主要负责端到端寻址，MAC 地址负责当前链路交付。

这是理解 ARP、路由器转发与 NAT 的关键。

## 第二部分：IPv4 地址、CIDR 与子网划分

## 三、IPv4 地址结构

IPv4 地址长度为 32 bit，即 4 Byte。

例如：

`192.168.1.100`

其二进制形式为：

```text
192       168       1         100

11000000  10101000  00000001  01100100
```

IPv4 地址可以划分为：

$$
\boxed{\text{IPv4 地址}=\text{网络前缀}+\text{主机部分}}
$$

网络前缀用于确定目的网络，主机部分用于区分该网络中的不同接口。

严格来说，IP 地址标识的是网络接口。一台路由器可以有多个接口 IP 地址。

## 四、分类 IPv4 地址

虽然现代互联网普遍采用 CIDR，但分类地址仍然是基础考点。

| 类别  | 最高位  | 首字节范围           | 默认掩码  |
| --- | ---- | --------------- | ----- |
| A 类 | 0    | 1～126（普通单播分配范围） | /8    |
| B 类 | 10   | 128～191         | /16   |
| C 类 | 110  | 192～223         | /24   |
| D 类 | 1110 | 224～239         | 组播    |
| E 类 | 1111 | 240～255         | 保留、实验 |

需要记住的特殊地址：

| 地址或地址块            | 含义          |
| ----------------- | ----------- |
| `0.0.0.0`         | 未指定地址       |
| `0.0.0.0/0`       | 默认路由        |
| `127.0.0.0/8`     | 环回地址块       |
| `127.0.0.1`       | 常见环回地址      |
| `255.255.255.255` | 受限广播        |
| `224.0.0.0/4`     | IPv4 组播     |
| `169.254.0.0/16`  | IPv4 链路本地地址 |

注意：

`0.0.0.0` 可以在主机尚未获得地址时作为源 IP，例如 DHCP Discover。

`255.255.255.255` 可以作为受限广播目的地址，路由器一般不转发这类广播。

## 五、CIDR 与子网掩码

CIDR 是无类别域间路由。

例如：

`192.168.1.100/26`

含义是：

- 前 26 位为网络前缀；
- 后 6 位为主机部分。

通用公式：

$$
h=32-n
$$

$$
\boxed{N_{\text{地址总数}}=2^{32-n}}
$$

在普通 IPv4 子网中：

$$
\boxed{N_{\text{可分配}}=2^{32-n}-2}
$$

减去的两个地址分别为网络地址和广播地址。

工程上 `/31` 可用于点对点链路，`/32` 可表示单主机路由，所以不要把“减 2”不加条件地应用于所有前缀。

### 5.1 高频掩码速查表

| CIDR | 子网掩码            | 地址总数 | 普通可分配数 | 末字节步长 |
| ---- | --------------- | ---- | ------ | ----- |
| /24  | 255.255.255.0   | 256  | 254    | 256   |
| /25  | 255.255.255.128 | 128  | 126    | 128   |
| /26  | 255.255.255.192 | 64   | 62     | 64    |
| /27  | 255.255.255.224 | 32   | 30     | 32    |
| /28  | 255.255.255.240 | 16   | 14     | 16    |
| /29  | 255.255.255.248 | 8    | 6      | 8     |
| /30  | 255.255.255.252 | 4    | 2      | 4     |

这里的“末字节步长”适用于 `/24` 到 `/30`。

特别注意 `/23`、`/22`、`/20`、`/18` 等前缀，块边界已经落在第三个字节，不能继续只看第四个字节。

**CIDR 一律用位掩码来判断**

  设 IPv4 地址为 $A$，前缀掩码为 $M$：网络地址 $A\land M$，该子网广播地址为 $(A\land M)\lor\neg M$（均在 32 位地址范围内）。/24、/25 等速算只是位运算的十进制表达。对于特殊用途的 /31、/32 网络，不要机械使用“减 2”主机数公式。

### 5.2 快速计算网络地址

核心方法：256 减去掩码中最后一个非 255、非 0 的字节。

例如：

IP：`192.168.1.151/27`

`/27` 掩码：

`255.255.255.224`

第四个字节的步长：

$$
256-224=32
$$

所以各子网起点：

```text
0
32
64
96
128
160
192
224
```

151 落在：

$$
128\le151\le159
$$

因此：

| 项目      | 结果              |
| ------- | --------------- |
| 网络地址    | `192.168.1.128` |
| 广播地址    | `192.168.1.159` |
| 最小可分配地址 | `192.168.1.129` |
| 最大可分配地址 | `192.168.1.158` |
| 可分配地址数  | 30              |

推广到任意前缀：

$$
\text{网络地址}=\text{IP}\ \operatorname{AND}\ \text{Mask}
$$

网络地址就是主机位全 0，广播地址就是主机位全 1。

### 5.3 真题：2012 年子网广播地址

题目：

某主机 IP 地址为 `180.80.77.55`，子网掩码为 `255.255.252.0`，求所在子网的广播地址。

第一步：确定掩码。

`255.255.252.0` 对应 `/22`。

第二步：计算块大小。

$$
256-252=4
$$

第三个字节的网络起点：

```text
0, 4, 8, ... , 72, 76, 80, ...
```

77 落在 76～79。

第三步：求网络地址和广播地址。

网络地址：

`180.80.76.0`

广播地址：

`180.80.79.255`

因此：

$$
\boxed{180.80.79.255}
$$

易错点：不能直接把 `180.80.77.55` 的最后一个字节改成 255。因为 `/22` 下，第三个字节的一部分也属于主机位。

### 5.4 真题：2023 年可分配地址范围

题目：

`168.16.84.24/20` 所在子网的最小和最大可分配地址分别是什么？

`/20` 对应：

`255.255.240.0`

第三字节步长：

$$
256-240=16
$$

84 落在：

$$
80\sim95
$$

网络地址：

`168.16.80.0`

广播地址：

`168.16.95.255`

所以：

$$
\boxed{168.16.80.1}
$$

$$
\boxed{168.16.95.254}
$$

这类题必须做到快速判断。

## 六、FLSM：定长子网划分

FLSM 要求所有子网采用相同长度的子网掩码。

假设：

`192.168.1.0/24`

需要划分成 8 个等长子网。

需要借用的主机位数：

$$
2^s=8
$$

$$
s=3
$$

新前缀为：

$$
24+3=27
$$

因此划分成 8 个 `/27`：

| 子网 | 网络地址             | 广播地址 | 可分配主机范围   |
| -- | ---------------- | ---- | --------- |
| 1  | 192.168.1.0/27   | .31  | .1～.30    |
| 2  | 192.168.1.32/27  | .63  | .33～.62   |
| 3  | 192.168.1.64/27  | .95  | .65～.94   |
| 4  | 192.168.1.96/27  | .127 | .97～.126  |
| 5  | 192.168.1.128/27 | .159 | .129～.158 |
| 6  | 192.168.1.160/27 | .191 | .161～.190 |
| 7  | 192.168.1.192/27 | .223 | .193～.222 |
| 8  | 192.168.1.224/27 | .255 | .225～.254 |

表中的 `.31` 等是 `192.168.1.31` 的缩写。

### 6.1 真题：2010 年子网数量

题目：

某网络为 `192.168.5.0/24`，采用定长子网划分，掩码为 `255.255.255.248`。

求：

1. 最大子网个数；
2. 每个子网最大可分配地址数。

新掩码为 `/29`。

借位：

$$
29-24=5
$$

子网数量：

$$
2^5=\boxed{32}
$$

剩余主机位：

$$
32-29=3
$$

每个子网可分配地址：

$$
2^3-2=\boxed{6}
$$

答案：32 个子网，每个子网 6 个可分配地址。

易错点：子网数量与每个子网的主机数量，使用的是两组不同的位数。

## 七、VLSM：变长子网划分

VLSM 允许不同子网采用不同前缀长度。

它比 FLSM 更节省地址。

### 7.1 通用解题方法

假设一个公司得到：

`192.168.10.0/24`

四个部门分别需要：

- A：100 台主机；
- B：50 台主机；
- C：20 台主机；
- D：10 台主机。

首先按需求从大到小排序。

然后对每个部门求：

$$
2^h-2\ge N
$$

选择满足要求的最小整数 $h$。

对 A：

$$
2^7-2=126\ge100
$$

所以采用 `/25`。

对 B：

$$
2^6-2=62\ge50
$$

采用 `/26`。

对 C：

$$
2^5-2=30\ge20
$$

采用 `/27`。

对 D：

$$
2^4-2=14\ge10
$$

采用 `/28`。

最终分配：

| 部门 | 需求  | 分配子网                | 可分配数 |
| -- | --- | ------------------- | ---- |
| A  | 100 | `192.168.10.0/25`   | 126  |
| B  | 50  | `192.168.10.128/26` | 62   |
| C  | 20  | `192.168.10.192/27` | 30   |
| D  | 10  | `192.168.10.224/28` | 14   |

剩余 `192.168.10.240/28` 尚可继续分配。

**VLSM 从大到小是有效的构造策略，不是唯一合法顺序**

  按需求从大到小选择满足容量的 $2^k$ 地址块并检查边界对齐，通常能减少碎片和回溯；最终合法性由**网络地址对齐、块大小及不重叠**共同决定。

### 7.2 为什么必须先大后小？

因为网络地址分配存在边界对齐约束。

例如 `/25` 必须从第四字节 0 或 128 等合法边界开始。

假如先随意分配多个较小子网，就可能打碎连续地址空间，使后面需要 `/25` 的部门找不到合法连续地址块。

所以 VLSM 的常规策略是：

$$
\boxed{\text{需求降序排列}\rightarrow\text{计算前缀}\rightarrow\text{按边界分配}}
$$

这不只是方便计算，而是为了避免地址碎片化。

### 7.3 真题：2019 年不等长子网划分

题目：

将 `101.200.16.0/20` 划分为 5 个子网，则可能的最小子网中，最多可分配多少个普通 IP 地址？

这道题有一个非常容易误判的地方：

题目只说划分为 5 个子网，没有要求 5 个子网等长。

假设每次将一个子网继续二分，则子网数量增加 1。

从 1 个子网变成 5 个子网，需要 4 次划分。

为了尽可能缩小其中一个子网，可以持续对同一分支进一步划分。

例如：

```text
原 /20
  ├── /21
  └── /21
       ├── /22
       └── /22
            ├── /23
            └── /23
                 ├── /24
                 └── /24
```

最终有：

```text
/21
/22
/23
/24
/24
```

共 5 个子网。

最小子网为 `/24`，可以分配：

$$
2^8-2=\boxed{254}
$$

关键结论：

划分为 $N$ 个子网，不等于必须平均划分为 $N$ 个子网。

一定先观察题目有没有明确要求“等长”“均分”“相同规模”。

## 八、CIDR 路由聚合

子网划分是把大网络拆成小网络。

路由聚合则相反：

把多个具有共同前缀的网络合并成一条路由。

作用是减少路由表项，降低路由信息规模。

### 8.1 基本聚合

例如：

```text
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```

四个连续 `/24`：

$$
4\times256=1024
$$

需要 10 位主机部分：

$$
2^{10}=1024
$$

因此前缀为：

$$
32-10=22
$$

可以聚合成：

$$
\boxed{192.168.0.0/22}
$$

但必须满足聚合地址块的合法边界。

### 8.2 真题：2018 年四条路由聚合

原路由表有：

```text
35.230.32.0/21
35.230.40.0/21
35.230.48.0/21
35.230.56.0/21
```

并且四条路由的输出接口相同。

`/21` 的第三个字节步长为 8。

它们覆盖：

```text
32～39
40～47
48～55
56～63
```

合起来为：

```text
32～63
```

第三字节共 32 个取值。

聚合为：

$$
\boxed{35.230.32.0/19}
$$

不是 `35.230.0.0/19`，因为聚合网络地址必须保持正确的高位前缀。

**路由聚合须保证覆盖范围与转发语义**

  两个相邻前缀合并成一个更短前缀，需要二进制地址前缀对齐；若聚合引入额外地址，可能产生错误路由或黑洞。不同下一跳的路由不是绝对不能聚合，但必须用更具体的路由等方式保持正确转发。

### 8.3 聚合的三个关键条件

考试中不能仅根据“两个网段连续”就直接合并。

应检查：

1. 地址块能否形成合法的较短前缀；
2. 地址块起点是否对齐；
3. 聚合是否会改变原有转发结果。

其中第三点尤其重要。

例如：

| 目的网络             | 下一跳 |
| ---------------- | --- |
| `192.168.0.0/24` | R1  |
| `192.168.1.0/24` | R2  |

虽然两个 `/24` 可以在地址数学上被 `192.168.0.0/23` 覆盖，但由于下一跳不同，不能简单地用一条指向 R1 或 R2 的 `/23` 路由替换它们。

如果使用汇总路由并保留更具体的例外路由，有时仍可以依靠最长前缀匹配实现正确转发。

这一点在 2013 年网络层综合真题中尤其重要。

## 第三部分：IP 数据报、分片与路由转发

## 九、IPv4 数据报首部

这是网络层计算题的另一大核心。

### 9.1 IPv4 首部格式

不含选项时，IPv4 首部固定部分为 20 Byte。

```text
  0                   15                  31
  ┌───────┬───────┬───────────┬────────────┐
  │版本(4)│IHL(4) │ DS/ECN(8) │ 总长度(16) │
  ├───────────────────┬───┬─────────────────┤
  │     标识(16)      │标志│ 片偏移(13)    │
  ├─────────┬─────────┬────────────────────┤
  │ TTL(8)  │协议(8)  │ 首部检验和(16)    │
  ├────────────────────────────────────────┤
  │             源 IP 地址(32)            │
  ├────────────────────────────────────────┤
  │             目的 IP 地址(32)          │
  ├────────────────────────────────────────┤
  │         选项与填充（如果存在）         │
  └────────────────────────────────────────┘
```

字段长度括号中的数字单位是 bit。

| 字段              | 长度     | 考试必须掌握的含义      |
| --------------- | ------ | -------------- |
| Version         | 4 bit  | IPv4 中为 4      |
| IHL             | 4 bit  | 首部长度，单位 4 Byte |
| DS/ECN          | 8 bit  | 区分服务和显式拥塞通知    |
| Total Length    | 16 bit | 整个 IP 数据报的字节数  |
| Identification  | 16 bit | 分片重组标识         |
| Flags           | 3 bit  | 包括 DF、MF       |
| Fragment Offset | 13 bit | 分片偏移，单位 8 Byte |
| TTL             | 8 bit  | 生存时间/跳数限制      |
| Protocol        | 8 bit  | 指示上层协议         |
| Header Checksum | 16 bit | 仅校验 IPv4 首部    |
| Source IP       | 32 bit | 源地址            |
| Destination IP  | 32 bit | 目的地址           |

### 9.2 首部长度 IHL

IHL 的单位是 4 Byte。

因此：

$$
H=4\times IHL
$$

最小合法 IHL 为 5：

$$
H_{\min}=5\times4=\boxed{20B}
$$

最大 IHL 为 15：

$$
H_{\max}=15\times4=\boxed{60B}
$$

注意：IHL 不等于整个数据报长度。

### 9.3 总长度 Total Length

总长度字段为 16 bit，单位 1 Byte。

因此理论最大 IPv4 数据报长度：

$$
L_{\max}=2^{16}-1=\boxed{65535B}
$$

总长度包含：

$$
\boxed{\text{IP 首部}+\text{IP 数据部分}}
$$

例如：

总长度为 1500B，IHL 为 5。

则：

$$
H=20B
$$

数据部分长度：

$$
D=1500-20=\boxed{1480B}
$$

这里的数据部分可能是完整的 TCP 报文段、UDP 数据报，或者其他上层协议报文。

### 9.4 Protocol 字段

必须记住：

| Protocol 值 | 对应协议 |
| ---------- | ---- |
| 1          | ICMP |
| 2          | IGMP |
| 6          | TCP  |
| 17         | UDP  |
| 89         | OSPF |

因此：

ICMP 和 OSPF 都可以直接使用 IP 承载，并不需要 TCP 或 UDP。

### 9.5 TTL 与首部校验和

TTL 用于防止 IP 数据报在网络中无限循环。

路由器每次转发时，TTL 至少减 1。

如果递减后 TTL 为 0，路由器丢弃数据报，通常返回 ICMP Time Exceeded。

假设：

初始 TTL 为 64。

数据报需要经过 5 台路由器。

则到达目的主机时：

$$
TTL=64-5=\boxed{59}
$$

在典型 408 题目中，如果必须经过 $k$ 台路由器才能到达目标，那么初始 TTL 至少为：

$$
\boxed{TTL_{\min}=k+1}
$$

为什么要加 1？

因为在最后一台路由器转发时，TTL 仍然必须大于 0。

IPv4 首部校验和只校验首部，不校验整个数据部分。

由于每经过路由器时 TTL 发生变化，首部校验和也需要更新。

易错点：IP 首部存在校验和，不代表 IP 保证可靠传输。

## 十、IPv4 分片：网络层最重要的计算题之一

建议把这一节练到能够不看答案直接列出所有分片字段。

### 10.1 为什么会产生 IP 分片？

不同链路允许承载的最大网络层数据报长度可能不同，这个限制称为 MTU。

例如：

```text
主机 A ── 以太网 MTU=1500 ── R1
                              │
                              │ MTU=800
                              ▼
                              R2 ── 主机 B
```

主机 A 发送一个总长度为 1500B 的 IP 数据报。

经过 R1 时，下一条链路 MTU 只有 800B。

如果 IPv4 数据报允许分片，R1 就需要将它分成多个较小的数据报片。

### 10.2 分片涉及的三个字段

① Identification：标识

同一个原始 IP 数据报产生的所有分片，标识字段相同。

但是应用重新发送相同数据时，通常会生成新的 IP 数据报，使用新的标识。

② MF：是否还有后续分片

- MF=1：原始数据报后面还有分片；
- MF=0：这是原始数据报的最后一个分片。

③ Fragment Offset：片偏移

表示当前分片的数据部分在原始 IP 数据报数据部分中的起始位置。

单位不是 Byte，而是：

$$
\boxed{8B}
$$

即：

$$
\boxed{\text{片偏移}=\frac{\text{数据起始字节偏移}}{8}}
$$

### 10.3 DF 与 MF 的区别

IPv4 标志字段共 3 bit：

```text
保留位 | DF | MF
```

DF：

- DF=1：不允许中间路由器分片；
- DF=0：允许分片。

MF：

- MF=1：后续还有分片；
- MF=0：原始数据报的最后一个分片。

当 DF=1 且数据报超过下一跳 MTU 时，路由器不能通过分片解决问题，只能丢弃，并可发送相应 ICMP 差错报文。

**分片前先读清“首部长度”和“第一次或二次分片”**

  如果原始分片再次被拆分，**新片偏移 = 父片原有偏移 + 新片内部数据起点字节数/8**。IP 首部的可复制选项可能造成各片首部长度不同；教材简化公式默认各分片首部均为 $H$ 字节。

### 10.4 分片的核心公式

设：

- 原数据报总长度为 $L$；
- IP 首部长度为 $H$；
- 下一跳 MTU 为 $M$。

原始数据部分长度：

$$
\boxed{D=L-H}
$$

每个非末片可携带的最大数据长度：

$$
\boxed{ D_{\max}=8\left\lfloor\frac{M-H}{8}\right\rfloor }
$$

分片总数在典型的等长首部题设下可计算为：

$$
\boxed{ N=\left\lceil\frac{D}{D_{\max}}\right\rceil }
$$

但每片的实际总长度和片偏移仍然需要分别计算。

注意：

最后一个分片的数据长度不要求为 8 的整数倍。

### 10.5 真题：2018 年第 47 题

原题给出：

- IPv4 数据报总长度：1500B；
- IP 首部长度：20B；
- 下一跳 MTU：800B。

要求求出最大分片的数据长度、分片数及片偏移。

第一步：求原始数据长度。

$$
D=1500-20=1480B
$$

第二步：求非末片最大数据长度。

$$
D_{\max} =8\left\lfloor\frac{800-20}{8}\right\rfloor
$$

$$
=8\times97=\boxed{776B}
$$

不能直接取 780B，因为 780 不是 8 的整数倍。

第三步：求每片的数据长度。

第一片携带：

$$
776B
$$

第二片携带：

$$
1480-776=704B
$$

因此只需要 2 片。

第四步：求片偏移与总长度。

| 字段             | 第 1 片 | 第 2 片 |
| -------------- | ----- | ----- |
| 数据长度           | 776B  | 704B  |
| IP 首部          | 20B   | 20B   |
| 总长度            | 796B  | 724B  |
| 片偏移            | 0     | 97    |
| MF             | 1     | 0     |
| Identification | 相同    | 相同    |

第二片的片偏移：

$$
\frac{776}{8}=\boxed{97}
$$

最终答案：最大数据长度 776B，分成 2 片，偏移分别为 0 和 97。

完整原题还结合 `/24` 均分为两个 `/25`、剩余可分配主机地址数量进行考查，是一道非常典型的子网划分与分片综合题。

### 10.6 真题：2021 年分片选择题

题目：

IP 数据报总长度为 1580B，首部长度 20B，经 MTU=800B 的链路分片，求第 2 片的总长度和 MF。

原始数据：

$$
D=1580-20=1560B
$$

最大非末片数据：

$$
D_{\max}=776B
$$

数据分配：

$$
1560=776+776+8
$$

因此分成三片：

| 分片 | 数据长度 | 总长度 | 偏移  | MF |
| -- | ---- | --- | --- | -- |
| 1  | 776  | 796 | 0   | 1  |
| 2  | 776  | 796 | 97  | 1  |
| 3  | 8    | 28  | 194 | 0  |

第二片：

$$
\boxed{\text{总长度}=796B,\quad MF=1}
$$

对应原题答案 B。

这道题最容易错在误以为第二片就是最后一片。

### 10.7 自编强化题：二次分片

原始 IPv4 数据报：

- 总长度：4020B；
- 首部：20B；
- 第一次经过 MTU=1500B 链路；
- 其中第一个分片又进入 MTU=620B 的链路。

假设首部长度在各片中相同，求两次分片的结果。

原始数据：

$$
4020-20=4000B
$$

第一次分片：

$$
D_{\max}=8\left\lfloor\frac{1500-20}{8}\right\rfloor=1480B
$$

所以：

$$
4000=1480+1480+1040
$$

第一次：

| 分片 | 数据长度 | 总长度  | 偏移  | MF |
| -- | ---- | ---- | --- | -- |
| A  | 1480 | 1500 | 0   | 1  |
| B  | 1480 | 1500 | 185 | 1  |
| C  | 1040 | 1060 | 370 | 0  |

现在只有 A 再进入 MTU=620B 的链路。

最大数据长度：

$$
8\left\lfloor\frac{620-20}{8}\right\rfloor=600B
$$

所以：

$$
1480=600+600+280
$$

A 被分为三片：

| 二次分片 | 数据长度 | 总长度 | 相对原数据偏移 | MF |
| ---- | ---- | --- | ------- | -- |
| A1   | 600  | 620 | 0       | 1  |
| A2   | 600  | 620 | 75      | 1  |
| A3   | 280  | 300 | 150     | 1  |

重点看 A3：

虽然它是原分片 A 的最后一个子片，但整个原始 IP 数据报后面还存在 B、C。

所以：

$$
\boxed{MF_{A3}=1}
$$

如果后续 B、C 都走能够容纳它们的链路，则最终可能存在 A1、A2、A3、B、C 五个分片。

二次分片的偏移始终相对于最初原始数据报的数据部分，不是重新从 0 开始计算。

### 10.8 分片重组的考点

IP 分片通常只在最终目的主机重组。

中间路由器不会每经过一跳就把所有分片重新拼接起来。

目的主机判断分片归属时，需要结合源 IP、目的 IP、协议号和 Identification 等信息。

你的模拟题库中有一道典型题：

某个 UDP 数据报第一次发送被分为 4 片，只有后两片到达；应用重新发送相同数据，第二次只有前两片到达。问能否把两次发送中收到的四片直接组合？

答案：通常不能。

原因是两次发送对应不同的原始 IP 数据报，标识字段通常不同。不能把两个原始数据报的分片混合重组。

## 十一、最长前缀匹配

### 11.1 基本原则

当目的 IP 同时匹配多条路由时，选择网络前缀最长的那条。

例如：

| 目的网络            | 下一跳 |
| --------------- | --- |
| `10.0.0.0/8`    | A   |
| `10.1.0.0/16`   | B   |
| `10.1.2.0/24`   | C   |
| `10.1.2.128/25` | D   |
| `0.0.0.0/0`     | E   |

假设目的地址是：

`10.1.2.130`

它能匹配：

```text
10.0.0.0/8
10.1.0.0/16
10.1.2.0/24
10.1.2.128/25
0.0.0.0/0
```

其中最长前缀为 `/25`。

因此选择：

$$
\boxed{D}
$$

不能简单按照路由表中的顺序选第一条匹配路由。

### 11.2 真题：2015 年最长前缀匹配

路由表：

| 目的网络             | 输出接口 |
| ---------------- | ---- |
| `169.96.40.0/23` | S1   |
| `169.96.40.0/25` | S2   |
| `169.96.40.0/27` | S3   |
| `0.0.0.0/0`      | S4   |

目标：

`169.96.40.5`

三条具体路由都能匹配。

选择最长前缀：

$$
\boxed{169.96.40.0/27}
$$

所以从：

$$
\boxed{S3}
$$

转发。

### 11.3 默认路由与主机路由

默认路由：

`0.0.0.0/0`

含义是匹配任意 IPv4 目的地址。

主机路由：

例如 `192.168.1.100/32`

只匹配一个具体 IP 地址。

在最长前缀匹配中：

$$
/32 > /24 > /16 > /0
$$

这里的大小表示匹配优先程度，不代表地址块包含的地址数量更大。

没有具体路由时，若存在默认路由就使用默认路由；如果连默认路由都没有，则通常丢弃数据报，并可能报告 ICMP 目的不可达。

**最长前缀只解决‘最具体’这一个维度**

  若两个路由前缀长度相同且都匹配，应结合管理距离、路由度量或等价多路径规则；若没有更具体前缀才考虑默认路由 $0.0.0.0/0$。

### 11.4 进阶：前缀长度相同怎么办？

最长前缀匹配只解决“哪个目的前缀最具体”。

如果有多条到同一前缀的候选路径，还可能需要根据：

- 路由来源的管理距离；
- 路由度量；
- 路由策略；
- 等价多路径 ECMP；

选择实际出口。

因此不能理解成“最长前缀匹配决定了一切”。

## 第四部分：ARP、DHCP、ICMP 与 NAT

## 十二、ARP 地址解析协议

ARP 是整个网络层最容易和数据链路层混在一起考的知识点。

### 12.1 ARP 的作用

ARP 用于：

$$
\boxed{\text{已知 IPv4 地址}\rightarrow\text{获得对应 MAC 地址}}
$$

但要加一个非常重要的限制：

ARP 通常只解析当前本地链路上下一跳的 MAC 地址。

ARP 请求直接封装在以太网帧中，不通过 TCP、UDP 或普通 IP 数据报传输。

### 12.2 ARP 请求与应答

当主机 A 需要给同网段主机 B 发数据，而本地 ARP 缓存中没有 B 的记录时：

```text
A                          B
│                          │
│──── ARP Request ────────>│
│    以太网广播            │
│                          │
│<──── ARP Reply ──────────│
│     通常单播             │
│                          │
│──── IP 数据帧 ──────────>│
```

ARP Request：

```text
目的 MAC：
FF:FF:FF:FF:FF:FF
```

ARP Reply：

```text
目的 MAC：
通常是请求主机 A 的 MAC
```

之后 A 会缓存：

```text
B 的 IP → B 的 MAC
```

### 12.3 同一子网通信

假设：

主机 A：

`192.168.1.10/24`

主机 B：

`192.168.1.20/24`

它们属于同一个 IP 子网。

A 发送给 B 时：

```text
IP 源地址：A
IP 目的地址：B

MAC 源地址：A
MAC 目的地址：B
```

如果 ARP 缓存没有记录，就先解析 B 的 MAC。

数据通信不需要经过默认网关。

### 12.4 不同子网通信

假设：

主机 A：

`192.168.1.10/24`

主机 B：

`192.168.2.20/24`

A 的默认网关为：

`192.168.1.1`

当 A 给 B 发送数据：

```text
IP 源地址：192.168.1.10
IP 目的地址：192.168.2.20

以太网帧源 MAC：A 的 MAC
以太网帧目的 MAC：默认网关的 MAC
```

A 应该先执行：

```text
ARP 查询：
192.168.1.1 → ?
```

而不是查询：

```text
192.168.2.20 → ?
```

因为 B 不在 A 的本地子网，ARP 广播不能跨越路由器直接找到远端 B。

### 12.5 真题：2018 年帧地址变化

2018 年真题给出：

```text
H1 ── S1 ── R ── S2 ── H2
```

H1 和 H2 位于不同 IP 子网。

题目要求：

1. H1 发出的以太网帧的目的 MAC；
2. H2 收到的以太网帧的源 MAC。

第一问：

H1 发出的帧要送给路由器 R。

因此目的 MAC：

$$
\boxed{\text{R 左侧接口 MAC}}
$$

第二问：

R 向 H2 所在网络转发时会重新封装帧。

因此 H2 收到的帧的源 MAC：

$$
\boxed{\text{R 右侧接口 MAC}}
$$

不是 H1 的 MAC。

原题对应地址分别是：

`00-1a-2b-3c-4d-51`

以及：

`00-a1-b2-c3-d4-61`

答案为 D。

### 12.6 ARP 缓存与交换机 MAC 地址表

| ARP 缓存       | 交换机 MAC 表        |
| ------------ | ---------------- |
| IP → MAC     | MAC → 端口         |
| 主机、路由器等设备维护  | 二层交换机维护          |
| 用于确定目标链路层地址  | 用于确定输出端口         |
| 依靠 ARP 等机制学习 | 通过收到的帧的源 MAC 自学习 |

这两个表不是同一个东西。

### 12.7 ARP 与 VLAN

ARP Request 是二层广播。

普通 VLAN 配置下，广播仅在所属 VLAN 内传播。

所以不同 VLAN 的主机不能通过普通 ARP 广播直接学习对方的 IP-MAC 映射。

跨 VLAN 通信通常需要三层转发。

2024 年真题专门利用 VLAN 隔离与 ARP 表项来考查这一点。

## 十三、DHCP 动态主机配置协议

### 13.1 DHCP 解决什么问题？

主机接入网络时，需要知道：

- 自己的 IP 地址；
- 子网掩码；
- 默认网关；
- DNS 服务器；
- 租约时间等。

DHCP 可以自动提供这些配置信息。

DHCP 属于应用层协议，使用 UDP。

| 通信端         | UDP 端口 |
| ----------- | ------ |
| DHCP Server | 67     |
| DHCP Client | 68     |

### 13.2 DHCP 四步：DORA

```text
客户端                    DHCP Server
   │                           │
   │── DHCP Discover ─────────>│
   │                           │
   │<──────── DHCP Offer ──────│
   │                           │
   │── DHCP Request ──────────>│
   │                           │
   │<──────── DHCP ACK ────────│
   │                           │
   ▼                           ▼
获得 IP、掩码、网关、DNS、租约等
```

DORA：

$$
\boxed{Discover\rightarrow Offer\rightarrow Request\rightarrow ACK}
$$

Discover：发现服务器

初始获取地址时，客户端可能没有合法 IP。

因此典型 IP 字段：

```text
源 IP：0.0.0.0
目的 IP：255.255.255.255
```

Offer：提供候选地址

DHCP Server 提供可用地址和配置参数。

Request：选择地址

客户端确认希望采用哪个服务器提供的地址。

ACK：确认租约

服务器确认配置生效。

需要注意，DHCP 不代表所有阶段都只能使用广播；后续续租等过程可能使用单播。

### 13.3 DHCP Relay

DHCP 初始发现通常使用广播。

但路由器不会默认跨子网转发普通广播。

如果 DHCP Server 与客户端不在同一个广播域，需要 DHCP 中继代理：

```text
客户端
   │
   │ 本地广播 Discover
   ▼
DHCP Relay
   │
   │ 跨三层转发
   ▼
远端 DHCP Server
```

这使大型校园网或企业网可以集中部署 DHCP 服务器。

### 13.4 真题：2015 年第 47 题

已知局域网：

`111.123.15.0/24`

已使用：

```text
111.123.15.1   路由器
111.123.15.2   DHCP Server
111.123.15.3   WWW Server
111.123.15.4   主机 1
```

其余主机通过 DHCP 获取地址。

问题一：最大动态地址分配范围？

`/24` 的普通可分配范围：

`.1～.254`

排除 `.1～.4` 后：

$$
\boxed{111.123.15.5\sim111.123.15.254}
$$

问题二：DHCP Discover 的源和目的 IP？

$$
\boxed{0.0.0.0\rightarrow255.255.255.255}
$$

问题三：某主机已经通过 DHCP 获得 IP，但 ARP 表为空，准备访问 Internet。其第一个 ARP 请求帧的目的 MAC？

$$
\boxed{\text{FF:FF:FF:FF:FF:FF}}
$$

真正承载 Internet 数据报的以太网帧，目的 MAC 则是默认网关接口的 MAC。

问题四：主机 1 错误地把 `111.123.15.2` 设置为默认网关，会怎样？

- 访问同网段 WWW 服务器 `111.123.15.3`：正常。
- 访问其他 IP 网络或 Internet：不能正常通过该错误网关转发。

原因：

同网段直接交付不依赖默认网关，而跨网段通信需要可正常转发分组的网关。

这道题是学习 DHCP、ARP、默认网关和同网/异网判断的最佳综合题之一。

## 十四、ICMP 网际控制报文协议

ICMP 是 IP 的辅助协议，用于差错报告、诊断和控制信息。

ICMP 报文直接封装在 IP 数据报中。

IPv4 Protocol：

$$
\boxed{1}
$$

ICMP 本身不能保证可靠传输。

### 14.1 常见 ICMP 报文

| 报文                      | 作用             |
| ----------------------- | -------------- |
| Destination Unreachable | 目的不可达          |
| Time Exceeded           | TTL 超时或分片重组超时等 |
| Redirect                | 重定向            |
| Parameter Problem       | 首部参数问题         |
| Echo Request            | 回送请求           |
| Echo Reply              | 回送回答           |

经典教材还包括 Source Quench（源点抑制）。

特别提醒：ICMP Source Quench 已被现代标准废弃。 2010 年的一道历史真题按当时教材的分类，在“拥塞丢包后可发送的 ICMP 报文”中选择源点抑制；应理解其历史考题背景，而不能把它当作当前网络的通用拥塞控制方案。

### 14.2 ICMP 差错报文的限制

为了避免差错报告引起新的差错报告风暴，ICMP 存在一些限制。

经典教材中的原则包括：

- 通常不对 ICMP 差错报告再产生 ICMP 差错报告；
- 通常不对 IP 广播或多播数据报产生 ICMP 差错报告；
- 通常不对非首片 IP 分片产生 ICMP 差错报告。

具体规则存在协议版本和报文类型差异，但对 408 来说，核心是理解：

不是每个出错的数据报都必须引发 ICMP 差错报告。

### 14.3 ping 工作原理

`ping` 主要使用：

- ICMP Echo Request；
- ICMP Echo Reply。

用于测试目标是否响应，并估计 RTT。

注意：

ping 失败并不一定表示目标主机完全不可达，可能只是 ICMP 被过滤。

### 14.4 traceroute 工作原理

核心是逐步增大 TTL。

```text
TTL=1
   │
   ▼
R1：TTL 递减到 0
   │
   └── ICMP Time Exceeded

TTL=2
   │
   ▼
R1 → R2
      │
      └── ICMP Time Exceeded

TTL=3
   │
   ▼
R1 → R2 → R3
           │
           └── ICMP Time Exceeded
```

由此发现经过的路由器。

不同平台可能使用 UDP、ICMP Echo 或其他探测方式，但逐步改变 TTL/Hop Limit 的原理相同。

## 十五、NAT 与 NAPT

NAT 是网络层综合题高频考点。

### 15.1 为什么需要 NAT？

IPv4 地址总数：

$$
2^{32}\approx42.95\text{ 亿}
$$

为了节省公网 IPv4 地址，很多局域网使用私有地址。

三个必须记住的私有地址块：

| 私有地址块            | 地址范围                        |
| ---------------- | --------------------------- |
| `10.0.0.0/8`     | 10.0.0.0～10.255.255.255     |
| `172.16.0.0/12`  | 172.16.0.0～172.31.255.255   |
| `192.168.0.0/16` | 192.168.0.0～192.168.255.255 |

不要误认为所有 `172.x.x.x` 都是私有地址。

只有：

$$
\boxed{172.16.0.0\sim172.31.255.255}
$$

属于该 RFC 1918 私有块。

### 15.2 NAT 的基本作用

例如：

```text
主机 A
192.168.1.10
   │
   ▼
NAT 路由器
公网：203.0.113.5
   │
   ▼
Internet
```

以上公网地址为文档示例地址。

内网主机访问外网时，NAT 路由器将源私有 IP 转换为公网 IP。

```text
转换前：

源 IP：192.168.1.10
目的 IP：198.51.100.20

转换后：

源 IP：203.0.113.5
目的 IP：198.51.100.20
```

这是出站源地址转换的典型形式。

**NAT 后哪些字段不变？**

  普通 SNAT/NAPT 修改源 IP 与可能的源端口，而目的 IP 通常仍是服务器地址；DNAT 则相反。若发生地址或端口改写，应重算对应的 IPv4 首部或传输层校验和（或使用增量校验更新）；链路层 MAC 仍由下一跳决定。

### 15.3 NAPT：地址与端口同时转换

如果内网很多主机共享同一个公网 IP，仅仅改写 IP 地址，往往不足以区分它们的不同连接。

NAPT/PAT 会同时改写地址和端口。

例如：

| 内部 IP:端口          | 外部 IP:端口          |
| ----------------- | ----------------- |
| 192.168.1.10:5000 | 203.0.113.5:40001 |
| 192.168.1.11:5000 | 203.0.113.5:40002 |
| 192.168.1.12:6000 | 203.0.113.5:40003 |

不同内部连接通过 NAT 分配的外部端口加以区分。

例如 A 发出：

```text
源：192.168.1.10:5000
目的：198.51.100.20:80
```

经过 NAPT：

```text
源：203.0.113.5:40001
目的：198.51.100.20:80
```

服务器返回：

```text
源：198.51.100.20:80
目的：203.0.113.5:40001
```

NAPT 查询映射表，恢复为：

```text
源：198.51.100.20:80
目的：192.168.1.10:5000
```

于是数据能够返回正确的内网主机。

### 15.4 NAT、SNAT、DNAT 的区别

| 类型       | 主要修改           |
| -------- | -------------- |
| SNAT     | 源 IP，可能包括源端口   |
| DNAT     | 目的 IP，可能包括目的端口 |
| NAPT/PAT | 使用地址和端口映射区分连接  |

通常：

- 内网访问 Internet：出站 SNAT/NAPT；
- 外部访问内部服务器：入站 DNAT/端口映射。

### 15.5 真题：2020 年第 47 题，双 NAT

这是一道非常典型的综合大题。

题目中，两个不同局域网都使用：

`192.168.1.0/24`

其中：

- H2 位于 R3 后方；
- Web 服务器位于 R2 后方；
- H2 与 Web 服务器恰好都使用 `192.168.1.2`；
- R3 外网地址为 `203.10.2.6`；
- R2 外网地址为 `203.10.2.2`；
- Web 服务器使用 HTTP 端口 80。

网络可以简化为：

```text
H2
192.168.1.2
    │
    ▼
   R3
203.10.2.6
    │
    ▼
   R2
203.10.2.2
    │
    ▼
Web Server
192.168.1.2:80
```

问题一：如何让 H2 访问 Web Server？

需要在 R2 配置端口映射：

```text
203.10.2.2:80
      ↓
192.168.1.2:80
```

问题二：H2 发出的 IP 数据报经过两台 NAT 设备时，源、目的 IP 如何变化？

第一阶段，H2 刚发出：

```text
源 IP：192.168.1.2
目的 IP：203.10.2.2
```

第二阶段，经过 R3 源 NAT：

```text
源 IP：203.10.2.6
目的 IP：203.10.2.2
```

第三阶段，经过 R2 目的 NAT：

```text
源 IP：203.10.2.6
目的 IP：192.168.1.2
```

整理为：

| 阶段     | 源 IP        | 目的 IP       |
| ------ | ----------- | ----------- |
| H2 发出  | 192.168.1.2 | 203.10.2.2  |
| R3 转发后 | 203.10.2.6  | 203.10.2.2  |
| R2 转发后 | 203.10.2.6  | 192.168.1.2 |

这里最重要的理解是：

两个互相隔离的私有网络可以使用相同的私有 IP 地址。

外部通信通过地址转换及相关状态映射来区分不同的网络端点。

### 15.6 NAT 综合题必须检查的字段

通常需要观察：

```text
源 IP
目的 IP
源端口
目的端口
下一跳
输出接口
```

并且区分：

普通路由转发一般不改源/目的 IP，而 NAT 可能改写源/目的 IP 和端口。

由于地址或端口变化可能影响校验值，NAT 设备还需要更新相关 IP、TCP/UDP 校验信息。

## 第五部分：路由算法与路由协议

这一部分一定要深入理解。

2024 年第 47 题把 RIP、OSPF、BGP、TTL、AS_PATH 和热土豆路由放进同一道 9 分大题，说明路由协议不仅要会背概念，还要能结合拓扑实际计算。

## 十六、路由的基本分类

路由来源通常有三类。

| 类型   | 含义            | 特点       |
| ---- | ------------- | -------- |
| 直连路由 | 路由器接口直接连接的网络  | 通常自动生成   |
| 静态路由 | 管理员手工配置       | 简单、控制开销低 |
| 动态路由 | 路由器通过协议交换信息获得 | 能适应拓扑变化  |

动态路由协议最重要的三种：

$$
\boxed{RIP,\quad OSPF,\quad BGP}
$$

不过它们不完全属于同一类别。

### 16.1 自治系统 AS

自治系统（Autonomous System）是一组在共同管理下采用统一对外路由策略的网络和路由器。

互联网中可以存在大量自治系统，例如大型 ISP、云服务商和大型企业网络。

根据是否跨自治系统，路由协议分为：

IGP：内部网关协议

负责一个 AS 内部的路由。

典型：

- RIP；
- OSPF。

EGP：外部网关协议

负责自治系统之间的路由。

典型：

\- BGP。

理解为：

```text
       AS1                      AS2

   R1 ─── R2                 R5 ─── R6
    │       │                 │       │
    └── R3 ─┘                 └── R7 ─┘
            │                 │
            └────── BGP ──────┘

    AS 内：RIP/OSPF        AS 内：RIP/OSPF

    AS 之间：BGP
```

需要特别注意：iBGP 虽然运行在同一个 AS 内，但它仍然属于 BGP 体系，而不是 RIP、OSPF 这样的 IGP。

## 十七、RIP：距离向量路由协议

### 17.1 RIP 的核心思想

RIP 使用距离向量算法。

每台路由器主要知道：

通过哪个邻居，可以用多少跳到达某个目的网络。

例如：

```text
R1 ── R2 ── R3 ── 网络 N
```

R3 向 R2 宣告自己能够到达 N。

R2 再把信息传播给 R1。

每经过一条相邻路由器间的链路，RIP 距离通常增加 1。

RIP 的两个重要数字：

$$
\boxed{15=\text{最大有效跳数}}
$$

$$
\boxed{16=\text{不可达}}
$$

RIP 经典周期更新间隔约为 30s，使用 UDP，端口 520。

### 17.2 Bellman-Ford 距离向量公式

核心公式：

$$
\boxed{ D_x(y)=\min_v\left[c(x,v)+D_v(y)\right] }
$$

其中：

- $D_x(y)$：路由器 $x$ 到目的 $y$ 的最短距离；
- $v$：路由器 $x$ 的某个邻居；
- $c(x,v)$：从 $x$ 到邻居 $v$ 的代价；
- $D_v(y)$：邻居 $v$ 到目的 $y$ 的距离。

这个公式的意思很简单：

枚举每一个邻居，把“到邻居的距离”和“邻居到目的的距离”相加，选择最小值。

### 17.3 真题：2021 年距离向量计算

站内真题给出路由器 E 与四个邻居的距离：

| 邻居 | E 到邻居的距离 |
| -- | -------- |
| A  | 8        |
| B  | 10       |
| C  | 12       |
| D  | 6        |

对某个目标网络 Net1，四个邻居分别报告距离：

$$
1,\ 23,\ 20,\ 22
$$

于是：

$$
D_E(Net1) =\min\{8+1,10+23,12+20,6+22\}
$$

$$
=\min\{9,33,32,28\}
$$

因此：

$$
\boxed{D_E(Net1)=9}
$$

下一跳应选择 A。

原题完整计算的四个目标距离为：

$$
\boxed{9,\ 20,\ 28,\ 20}
$$

注意，这里是一般距离向量计算，链路代价可以不是 1；而经典 RIP 使用跳数作为度量。

### 17.4 RIP 路由表更新规则

这是非常重要的选择题考点。

当 R1 收到邻居 R2 发来的 RIP 路由表时：

第一步：先给 R2 通告的距离加 1。

在标准 RIP 跳数模型中：

$$
d'=\min(d+1,16)
$$

第二步：判断原有路由的下一跳是不是 R2。

情况一：

当前路由原本就是通过 R2 到达目标。

那么应该根据 R2 的新信息更新，包括距离变大、变小或变成不可达。

情况二：

当前路由并不是通过 R2 到达目标。

此时通常只有经 R2 的新路线更优，才替换原路由；等价路线的处理依题目规则而定。

### 17.5 模拟题：RIP 路由表更新

R1 的原路由表：

| 目标网络     | 距离 | 下一跳 |
| -------- | -- | --- |
| 10.0.0.0 | 0  | 直连  |
| 20.0.0.0 | 7  | R2  |
| 30.0.0.0 | 4  | R2  |

R2 的通告：

| 目标网络     | 距离 |
| -------- | -- |
| 10.0.0.0 | 3  |
| 20.0.0.0 | 4  |
| 30.0.0.0 | 3  |

首先全部加 1：

$$
4,\ 5,\ 4
$$

然后更新：

对于 `10.0.0.0`：

R1 直接连接，原距离为 0，继续保留。

对于 `20.0.0.0`：

原下一跳为 R2，因此采用 R2 最新信息：

$$
7\rightarrow5
$$

对于 `30.0.0.0`：

原下一跳也是 R2，新距离：

$$
4
$$

不变。

最终：

$$
\boxed{0,\ 5,\ 4}
$$

对应站内模拟题答案 D。

高频陷阱：RIP 不是永远只接受更小的距离。

### 17.6 RIP 为什么会产生计数到无穷？

假设：

```text
R1 ── R2 ── R3 ── 网络 N
```

原本三台路由器都认为 N 可达。

突然 R3 与 N 断开。

R3 已经知道网络 N 不可达，但 R1、R2 可能还保留旧路由信息。

例如：

R1 仍向 R2 宣告：

```text
我距离 N 是 2
```

R2 可能错误地认为：

```text
经 R1 到 N：
2 + 1 = 3
```

于是 R2 的距离变为 3。

下一轮 R1 又可能根据 R2 的错误信息更新为 4。

这样不断增加：

```text
3 → 4 → 5 → ... → 16
```

直到认为不可达。

这就是：

$$
\boxed{\text{Count to Infinity}}
$$

即计数到无穷。

### 17.7 RIP 的改进机制

常见机制：

水平分割 Split Horizon

从某接口学到的路由，不再从同一个接口向外通告。

毒性逆转 Poison Reverse

从某邻居学到的路由，向该邻居通告时把距离设置为 16，表示不能通过自己回到该目的。

触发更新 Triggered Update

路由发生重要变化时，不必一直等到下一个周期，尽快发送更新。

这些方法可以缓解错误路由传播和环路，但不能彻底消除分布式路由收敛中的所有问题。

### 17.8 RIP 的定时题

假设：

```text
R1 ── R2 ── R3 ── R4 ── 网络 N
```

R4 在初始时刻就知道 N 是直连网络。

各路由器在 $t=0$ 立即交换初始距离向量，随后每隔 30s 交换一次。

那么：

| 时刻  | 新获知 N 的路由器 |
| --- | ---------- |
| 0s  | R3         |
| 30s | R2         |
| 60s | R1         |

因此 R1 最早在：

$$
\boxed{60s}
$$

获得正确路由。

注意这个结论依赖题目指定的同步交换模型，不意味着真实 RIP 必然需要这么长时间。

## 十八、OSPF：链路状态路由协议

OSPF 是另一种内部网关协议。

与 RIP 最大的区别是：

RIP 主要交换目的网络距离，OSPF 交换链路状态信息。

### 18.1 OSPF 的基本工作流程

```text
发现邻居、建立邻接关系
          │
          ▼
产生链路状态通告 LSA
          │
          ▼
在相应范围内泛洪 LSA
          │
          ▼
建立链路状态数据库 LSDB
          │
          ▼
运行 Dijkstra 最短路径算法
          │
          ▼
得到最短路径树 SPT
          │
          ▼
生成路由表与转发表
```

OSPF 不采用 RIP 的 15 跳限制，而是使用链路 Cost 衡量路径代价。

### 18.2 Dijkstra 算法

Dijkstra 的基本思想是：

每次确定一个当前距离源点最近的结点，再利用它更新其他结点的最短距离。

自编例题：

```text
       2             4
   A ───── B ─────────── D
    \       \            │
     \ 5     \ 1         │ 1
      \       \          │
       C ─────┘          E
        \                /
         └───── 2 ── D ─┘
```

为避免拓扑画法歧义，边权严格按下表计算：

| 边   | Cost |
| --- | ---- |
| A—B | 2    |
| A—C | 5    |
| B—C | 1    |
| B—D | 4    |
| C—D | 2    |
| D—E | 1    |
| C—E | 7    |

求 A 到各结点的最短路径。

初始：

$$
d(A)=0
$$

$$
d(B)=2,\quad d(C)=5
$$

$$
d(D)=\infty,\quad d(E)=\infty
$$

首先确定 B，因为：

$$
d(B)=2
$$

通过 B 更新 C：

$$
d(C)=\min(5,2+1)=3
$$

更新 D：

$$
d(D)=2+4=6
$$

接着确定 C：

$$
d(C)=3
$$

通过 C 更新 D：

$$
d(D)=\min(6,3+2)=5
$$

通过 C 更新 E：

$$
d(E)=3+7=10
$$

然后确定 D：

$$
d(D)=5
$$

通过 D 更新 E：

$$
d(E)=\min(10,5+1)=6
$$

最终：

| 目标 | 最短距离 | 最短路径      |
| -- | ---- | --------- |
| B  | 2    | A→B       |
| C  | 3    | A→B→C     |
| D  | 5    | A→B→C→D   |
| E  | 6    | A→B→C→D→E |

因此：

$$
\boxed{d(A,E)=6}
$$

更重要的是，如果 A 是路由器，则到 B、C、D、E 的这些最短路径，第一跳全部是 B。

所以路由表中这些目标都可以采用 B 作为下一跳。

Dijkstra 题不仅要算距离，还要记录第一跳。

### 18.3 RIP 与 OSPF 的系统比较

| 比较维度   | RIP          | OSPF           |
| ------ | ------------ | -------------- |
| 协议类型   | IGP          | IGP            |
| 算法思想   | 距离向量         | 链路状态           |
| 核心算法   | Bellman-Ford | Dijkstra       |
| 度量     | 跳数           | Cost           |
| 更新信息   | 距离向量         | LSA            |
| 主要传播方式 | 向邻居通告        | 相应区域内泛洪        |
| 最大有效距离 | 15 跳         | 无 RIP 式 15 跳限制 |
| 收敛速度   | 通常较慢         | 通常较快           |
| 拓扑认知   | 没有完整拓扑       | 拥有相应区域的链路状态数据库 |
| 封装     | UDP          | 直接使用 IP        |
| 端口或协议号 | UDP 520      | IP Protocol 89 |

### 18.4 OSPF 的区域划分

OSPF 可以将大型自治系统进一步划分为多个 Area。

骨干区域为：

$$
\boxed{\text{Area 0}}
$$

这样可以限制链路状态信息的泛洪范围，降低大规模网络的计算和管理开销。

因此：

“OSPF 所有路由器必然拥有整个 AS 的完整拓扑信息”

这种说法不准确。

更严谨的是：

同一区域中稳定收敛的相关路由器拥有该区域的链路状态信息；跨区域路由信息可以经过汇总和抽象。

### 18.5 真题：2014 年 OSPF 路由表

2014 年的综合真题给出了路由器的链路状态信息，要求：

1. 计算最短路径；
2. 构造 R1 的路由表；
3. 对可聚合的目的网络进行聚合；
4. 根据经过的路由器数量计算 TTL。

其中：

`192.1.6.0/24`

与：

`192.1.7.0/24`

从 R1 看输出接口和下一跳相同，因此可以聚合为：

$$
\boxed{192.1.6.0/23}
$$

题设中一个数据报初始 TTL 为 64，经过 R1、R2、R4 三台路由器后到达目的主机。

因此：

$$
TTL=64-3=\boxed{61}
$$

这道题体现了：

$$
\boxed{ \text{OSPF 建图} \rightarrow \text{最短路径} \rightarrow \text{路由表} \rightarrow \text{路由聚合} \rightarrow \text{逐跳转发} }
$$

## 十九、BGP：边界网关协议

BGP 是互联网中非常重要的跨自治系统路由协议。

最需要理解的区别是：

RIP 和 OSPF 主要根据距离、费用等衡量路径。

BGP 则更强调：

$$
\boxed{\text{路径属性}+\text{路由策略}}
$$

BGP 不保证选择跳数最少的路径，也不保证选择链路代价最小的路径。

### 19.1 BGP 的基本特点

BGP：

- 主要用于 AS 之间的可达性传播；
- 采用路径向量思想；
- 使用 TCP；
- 常用端口 179；
- 支持路由策略；
- 使用 AS_PATH 等路径属性；
- 使用 UPDATE 通告路由变化。

### 19.2 eBGP 与 iBGP

eBGP

用于不同 AS 之间的 BGP 邻居会话。

例如：

```text
AS1                 AS2

R1 ───── eBGP ───── R2
```

iBGP

用于同一 AS 内 BGP 路由器之间传播 BGP 可达性信息。

例如：

```text
AS1

R1 ───── iBGP ───── R2
```

记忆：

$$
\boxed{\text{不同 AS：eBGP}}
$$

$$
\boxed{\text{同一 AS：iBGP}}
$$

注意，会话是 eBGP 还是 iBGP，取决于两端 AS 编号，而不是物理距离。

### 19.3 BGP 报文类型

常见报文：

| 报文            | 作用             |
| ------------- | -------------- |
| OPEN          | 建立 BGP 会话并协商参数 |
| UPDATE        | 通告或撤销路由        |
| KEEPALIVE     | 维护会话           |
| NOTIFICATION  | 报告错误并终止会话      |
| ROUTE-REFRESH | 请求重新发送路由信息     |

其中：

$$
\boxed{\text{UPDATE}}
$$

是 408 非常重要的记忆点。

### 19.4 AS_PATH

例如两条路径：

路径 A：

```text
AS1 → AS2 → AS5
```

路径 B：

```text
AS1 → AS3 → AS4 → AS5
```

在其他优先级更高的路由属性及策略条件相同的情况下，较短的 AS_PATH 往往更受偏好。

路径 A 的 AS_PATH 较短。

但不能得出：

“BGP 永远选择 AS_PATH 最短的路线。”

因为 LOCAL_PREF 等属性和策略可能先于 AS_PATH 比较。

AS_PATH 还有一个非常重要的作用：

防止 AS 级路由环路。

若某 AS 收到的路由 AS_PATH 中已经包含自身 AS 编号，通常应拒绝该路径。

### 19.5 热土豆路由

热土豆路由（Hot Potato Routing）的直觉是：

在合适的外部路径之间，尽量选择距离自己更近的出口，把流量尽快交给其他 AS。

例如：

```text
             出口 R1 ─── AS2
            /
内部路由器 X
            \
             出口 R2 ─── AS3
```

假设两条候选 BGP 路由在优先级更高的属性上相同，且题目允许比较 IGP 出口代价。

如果：

$$
Cost(X,R1)=10
$$

$$
Cost(X,R2)=3
$$

那么会优先选择：

$$
\boxed{R2}
$$

即使两条 AS_PATH 长度相同，也可以因为内部出口距离不同而选择不同的出口。

### 19.6 传统 iBGP 的传播限制

站内模拟题还考查了 iBGP 的经典规则：

从一个 iBGP 邻居学习到的路由，通常不再直接通告给另一个 iBGP 邻居。

这是因为同一 AS 内传播时，AS_PATH 不会像跨 AS 传播那样不断增加本 AS 编号。

传统 iBGP 因此常需要逻辑全连接。

不过：

- 逻辑全连接不要求任意两台 BGP 路由器之间存在直接物理链路；
- 大规模网络可使用路由反射器等机制降低会话数量。

## 二十、真题：2024 年第 47 题——路由协议综合

这是本章特别值得完整训练的一道大题。

原题包含 4 个自治系统：

- AS1 使用 RIP；
- AS3 内两台主机通信最多经过 15 台路由器；
- AS4 规模较大，路径可能经过超过 20 台路由器。

#### 第 1 问：AS4 应采用 RIP 还是 OSPF？

RIP 最大有效跳数为 15。

AS4 内的路径可能超过 20 跳。

因此：

$$
\boxed{OSPF}
$$

#### 第 2 问：初始 TTL 至少为多少？

题目给出最多经过 15 台路由器。

必须保证通过最后一台路由器时 TTL 仍大于 0。

因此：

$$
TTL_{\min}=15+1
$$

$$
\boxed{16}
$$

#### 第 3 问：RIP 收敛时间

原题中，目标网络：

`210.2.4.0/24`

直接连接 R16。

从 R16 到最远路由器 R11，最短传播路径需要经过 3 条路由器间链路。

题目规定：

- 初始时刻立即交换一次距离向量；
- 此后每隔 30s 交换一次。

传播顺序：

```text
t=0s     第 1 次传播
t=30s    第 2 次传播
t=60s    第 3 次传播
```

因此：

$$
\boxed{60s}
$$

这里一定不要机械地计算 $3\times30=90s$，因为第一次交换发生在 0s。

#### 第 4 问：BGP 会话与报文

R44 属于 AS4，R13 属于 AS1。

它们之间使用：

$$
\boxed{eBGP}
$$

通告路由使用：

$$
\boxed{UPDATE}
$$

R13 再向同一个 AS1 内部的 R14 和 R15 通告 BGP 路由，则使用：

$$
\boxed{iBGP}
$$

#### 第 5 问：BGP 最优路径

原题给出：

| 路由来源 | AS_PATH           | 长度 |
| ---- | ----------------- | -- |
| R11  | AS2 AS8 AS19      | 3  |
| R12  | AS3 AS7 AS11 AS19 | 4  |
| R13  | AS4 AS10 AS19     | 3  |

在题设无策略约束且其他相关属性无差异的简化条件下：

R12 的路径较长，先排除。

R11 与 R13 的 AS_PATH 长度相同。

进一步比较内部到出口的代价。

根据原题拓扑：

- R14 更靠近 R11；
- R15 更靠近 R13。

因此：

$$
\boxed{R14\rightarrow R11}
$$

$$
\boxed{R15\rightarrow R13}
$$

#### 这道题的真正价值

它一次性覆盖：

| 考点        | 方法          |
| --------- | ----------- |
| RIP 适用范围  | 判断 15 跳限制   |
| OSPF      | 链路状态和较大规模网络 |
| TTL       | 路由器转发次数加 1  |
| RIP 传播    | 按题设定时轮次推算   |
| eBGP/iBGP | 根据 AS 归属区分  |
| UPDATE    | BGP 路由通告    |
| AS_PATH   | 比较路径属性      |
| 热土豆路由     | 比较内部出口代价    |

把它掌握之后，路由协议的综合题会清晰得多。

## 第六部分：IPv6、组播、移动 IP 与 SDN

## 二十一、IPv6

### 21.1 IPv6 为什么出现？

IPv4 地址只有 32 bit。

IPv6 使用：

$$
\boxed{128\text{ bit}}
$$

地址空间大小：

$$
2^{128}
$$

IPv4 地址空间大小：

$$
2^{32}
$$

因此 IPv6 地址空间是 IPv4 的：

$$
\boxed{2^{96}\text{ 倍}}
$$

不是 96 倍。

这个区别在 2023 年真题中出现过。

**IPv6 的三个不能机械套用**

  IPv6 基本首部不含首部校验和；邻居发现主要依赖 ICMPv6 的 NDP，不是 IPv4 ARP；沿途路由器不分片，源节点可按路径 MTU 调整报文大小或使用分片扩展首部。

### 21.2 IPv4 与 IPv6 的区别

| 项目      | IPv4          | IPv6        |
| ------- | ------------- | ----------- |
| 地址长度    | 32 bit        | 128 bit     |
| 基本首部    | 最小 20B，可变     | 固定 40B      |
| 首部校验和   | 有             | 无           |
| 中间路由器分片 | DF=0 时可以      | 不执行         |
| 源主机分片   | 可以            | 可以使用分片扩展首部  |
| 生存时间字段  | TTL           | Hop Limit   |
| 可选功能    | Options       | 扩展首部        |
| 广播      | 有             | 无传统 IPv4 广播 |
| 组播      | 支持            | 支持          |
| 任播      | 非 IPv4 基础寻址类别 | 原生支持        |

注意：

IPv6 取消了基本首部中的分片字段，不代表 IPv6 完全不能分片。

IPv6 中间路由器不能执行 IPv4 式分片，但源节点可以利用 Fragment 扩展首部进行分片。

### 21.3 IPv6 基本首部

IPv6 基本首部固定为 40 Byte。

主要字段：

| 字段                  | 作用          |
| ------------------- | ----------- |
| Version             | 版本号 6       |
| Traffic Class       | 流量类别        |
| Flow Label          | 流标签         |
| Payload Length      | 有效载荷长度      |
| Next Header         | 指向扩展首部或上层协议 |
| Hop Limit           | 跳数限制        |
| Source Address      | 128 bit     |
| Destination Address | 128 bit     |

注意 IPv4 与 IPv6 的长度字段含义不同：

IPv4 Total Length：

$$
\boxed{\text{IPv4 首部}+\text{数据}}
$$

IPv6 Payload Length 在普通情况下：

$$
\boxed{\text{扩展首部}+\text{上层数据}}
$$

不包括固定的 40B 基本首部。

### 21.4 IPv6 地址压缩规则

完整 IPv6 地址由 8 组组成，每组 16 bit。

例如：

`2001:0db8:0000:0000:0000:0000:0000:0001`

压缩规则有两个。

规则一：省略每组的前导 0。

例如：

`0db8` → `db8`

`0001` → `1`

但是：

`1200` 不能缩写成 `12`。

因为末尾的 0 不能删除。

规则二：连续全 0 组可以用 `::` 压缩。

上面的地址：

`2001:db8::1`

`::` 在一个 IPv6 地址中最多出现一次。

### 21.5 IPv6 地址恢复

例如：

`2001:db8::8a2e:370:7334`

显式写出了：

```text
2001
db8
8a2e
370
7334
```

共 5 组。

总共应有 8 组。

所以：

$$
8-5=3
$$

`::` 代表 3 组全 0。

恢复成：

`2001:0db8:0000:0000:0000:8a2e:0370:7334`

### 21.6 模拟题：IPv6 压缩判断

原地址：

`8000:0000:0000:0000:D000:1230:CDEF:89A0`

正确压缩：

$$
\boxed{\texttt{8000::D000:1230:CDEF:89A0}}
$$

不能写成：

`8::D0:123:CDEF:89A`

因为那样删除了非前导 0。

### 21.7 常见 IPv6 特殊地址

| IPv6 地址或前缀  | 含义           |
| ----------- | ------------ |
| `::`        | 未指定地址        |
| `::1`       | 环回地址         |
| `fe80::/10` | 链路本地单播范围     |
| `ff00::/8`  | IPv6 组播      |
| `2000::/3`  | 当前主要全球单播地址空间 |

IPv6 没有传统 IPv4 广播地址。

另外，IPv6 不使用 IPv4 ARP；IPv6 邻居发现等功能主要依靠 ICMPv6 的 NDP。

### 21.8 IPv4 与 IPv6 过渡

两种常见方式：

双协议栈

设备同时实现 IPv4 和 IPv6 协议栈。

隧道技术

例如让 IPv6 数据报穿越只支持 IPv4 的网络：

```text
IPv6 数据报
     │
     ▼
封装 IPv4 外层首部
     │
     ▼
IPv4 网络传输
     │
     ▼
隧道出口解封装
     │
     ▼
继续处理 IPv6 数据报
```

2023 年真题考查了双协议栈、隧道和 IPv6 首部等知识。

## 二十二、IP 组播与 IGMP

### 22.1 单播、广播、组播

| 类型 | 通信方式       |
| -- | ---------- |
| 单播 | 一对一        |
| 广播 | 一对广播域内所有节点 |
| 组播 | 一对特定接收组    |

组播的意义在于：

发送端可以发送一份逻辑数据，由网络在适当位置复制，交付给需要接收的组成员。

IPv4 组播地址：

$$
\boxed{224.0.0.0/4}
$$

即：

`224.0.0.0～239.255.255.255`

### 22.2 IPv4 组播地址映射 MAC

以太网 IPv4 组播 MAC 使用固定前缀：

`01:00:5E`

再使用 IPv4 组播地址的低 23 位。

规则可以理解成：

```text
IP 组播地址的低 23 位
            │
            ▼
01:00:5E:xx:xx:xx
```

其中第四个 MAC 字节的最高位为 0。

### 22.3 模拟题：组播 MAC 映射

IP 组播地址：

`238.212.24.5`

十六进制表示：

`EE:D4:18:05`

对应以太网组播 MAC：

`01:00:5E:54:18:05`

因为第二个 IP 字节 D4 的最高位不参与低 23 位映射：

$$
\texttt{D4}\ \operatorname{AND}\ \texttt{7F}=\texttt{54}
$$

所以：

$$
\boxed{\texttt{01:00:5E:54:18:05}}
$$

由于 IPv4 组播地址只有低 23 位用于这种 MAC 映射，因此不同 IPv4 组播地址可能对应同一个以太网 MAC。

### 22.4 IGMP

IGMP 全称：

Internet Group Management Protocol。

主要用于：

IPv4 主机与本地组播路由器之间的组成员关系管理。

它帮助本地路由器判断：

某个局域网内是否存在希望接收特定组播流量的主机。

IGMP 不负责整个 Internet 范围的组播最短路径计算。

必须区分：

$$
\boxed{\text{IGMP：管理本地组成员}}
$$

$$
\boxed{\text{组播路由协议：组织跨网络转发}}
$$

## 二十三、移动 IP

移动 IP 的目标是：

移动节点更换接入网络后，仍然能够使用稳定的归属身份进行通信。

重要概念：

| 名称              | 作用   |
| --------------- | ---- |
| Home Address    | 归属地址 |
| Home Network    | 归属网络 |
| Home Agent      | 归属代理 |
| Care-of Address | 转交地址 |

### 23.1 移动 IP 通信过程

```text
通信对端 B
    │
    │ 发送给 A 的归属地址
    ▼
Home Agent
    │
    │ 隧道封装
    │ 目的：转交地址
    ▼
外地网络
    │
    ▼
移动主机 A
```

移动主机向通信对端发送数据时，在基本移动 IP 模型中可以通过当前网络直接发送，不一定经过 Home Agent。

因此可能形成三角路由。

### 23.2 模拟题

移动主机 A：

归属地址：

`218.75.230.16`

转交地址：

`175.1.1.1`

主机 B 想与移动到外地网络的 A 通信。

B 最初发送的原始 IP 数据报目的地址：

$$
\boxed{218.75.230.16}
$$

归属代理隧道封装后的外层 IP 数据报目的地址：

$$
\boxed{175.1.1.1}
$$

注意这里是两层不同的 IP 首部，不能把原始数据报的目的 IP 和隧道外层目的 IP 混淆。

## 二十四、SDN：软件定义网络

SDN 核心思想：

$$
\boxed{\text{控制平面与数据平面分离}}
$$

### 24.1 控制平面

主要负责：

- 路由与策略计算；
- 网络状态维护；
- 生成并下发流表；
- 网络管理和控制。

### 24.2 数据平面

主要负责：

- 按流表匹配；
- 转发分组；
- 丢弃分组；
- 修改首部；
- 按规则统计流量。

其基本思想是：

```text
Match → Action
```

匹配字段可以涉及链路层、网络层和传输层。

### 24.3 SDN 三类接口

| 接口    | 连接对象     | 主要用途       |
| ----- | -------- | ---------- |
| 南向接口  | 控制器—转发设备 | 下发规则、读取状态  |
| 北向接口  | 应用—控制器   | 应用向控制器表达需求 |
| 东西向接口 | 控制器—控制器  | 协同管理       |

### 24.4 真题：2022 年 SDN

题目：

SDN 控制器向交换机下发流表时使用哪个接口？

答案：

$$
\boxed{\text{南向接口}}
$$

常见南向协议：

OpenFlow。

注意：SDN 的逻辑集中控制不要求只有一台物理控制服务器，实际部署可以分布式实现。

## 第七部分：路由器、冲突域与广播域

## 二十五、网络设备辨析

| 设备      | 主要层次  | 是否隔离冲突域 | 是否隔离广播域       |
| ------- | ----- | ------- | ------------- |
| 中继器     | 物理层   | 否       | 否             |
| 集线器 Hub | 物理层   | 否       | 否             |
| 网桥      | 数据链路层 | 是       | 通常否           |
| 二层交换机   | 数据链路层 | 是       | 普通无 VLAN 隔离时否 |
| 路由器     | 网络层   | 是       | 是             |

### 25.1 冲突域

冲突域是共享介质以太网中可能发生发送冲突的范围。

传统 Hub 不隔离冲突域。

交换机则为不同端口提供独立的冲突域；现代全双工交换链路实际上不再发生传统 CSMA/CD 冲突。

### 25.2 广播域

广播域是一个二层广播帧能够到达的范围。

普通二层交换机会传播广播帧。

路由器不会默认把接收到的二层广播帧转发到其他 IP 子网。

因此：

$$
\boxed{\text{路由器可以隔离广播域}}
$$

VLAN 也可以在二层交换网络中形成独立广播域。

### 25.3 真题：2010 年广播风暴

题目：

中继器、集线器、网桥、路由器中，哪个能有效抑制广播风暴跨网段传播？

答案：

$$
\boxed{\text{路由器}}
$$

## 二十六、真题：2009 年第 47 题——子网划分、路由表和聚合

这是很适合建立网络层综合题解题框架的一道题。

题目给出地址空间：

`202.118.1.0/24`

要求划分两个局域网，每个至少需要 120 个可分配 IP 地址。

R1 分别通过 E1、E2 连接两个局域网，通过 L0 连接 R2。

R1 的 L0：

`202.118.2.1`

R2 的 L0：

`202.118.2.2`

DNS 服务器地址：

`202.118.3.2`

#### 第 1 问：如何划分子网？

每个局域网至少 120 个地址。

需要：

$$
2^h-2\ge120
$$

当 $h=7$：

$$
2^7-2=126
$$

满足要求。

因此两个子网：

$$
\boxed{202.118.1.0/25}
$$

$$
\boxed{202.118.1.128/25}
$$

#### 第 2 问：写 R1 路由表

R1 连接：

- 局域网 1；
- 局域网 2；
- R2；
- 经 R2 访问 DNS 和 Internet。

因此：

| 目的前缀             | 下一跳         | 接口 |
| ---------------- | ----------- | -- |
| 202.118.1.0/25   | 直连          | E1 |
| 202.118.1.128/25 | 直连          | E2 |
| 202.118.3.2/32   | 202.118.2.2 | L0 |
| 0.0.0.0/0        | 202.118.2.2 | L0 |

为什么 DNS 使用 `/32`？

因为题目要求到特定 DNS 服务器的主机路由。

为什么需要默认路由？

因为不可能把整个 Internet 的所有网络前缀逐一写入这张简化路由表。

#### 第 3 问：R2 如何聚合到两个局域网的路由？

两个子网：

```text
202.118.1.0/25
202.118.1.128/25
```

恰好共同构成：

`202.118.1.0/24`

因此 R2 只需要：

| 目的前缀           | 下一跳         | 接口 |
| -------------- | ----------- | -- |
| 202.118.1.0/24 | 202.118.2.1 | L0 |

这道题的关键规律是：

$$
\boxed{ \text{主机需求} \rightarrow \text{子网划分} \rightarrow \text{直连/主机/默认路由} \rightarrow \text{CIDR 聚合} }
$$

## 二十七、真题：2013 年第 47 题——聚合与最长前缀覆盖

原题中有两个自治系统。

AS1 的两个子网：

```text
153.14.5.0/25
153.14.5.128/25
```

可以聚合为：

$$
\boxed{153.14.5.0/24}
$$

另一部分网络中，R3 后方存在两个目标子网，R2 还直连了一个位于相同较大地址块内的子网。

可以使用：

`194.17.20.0/23`

作为较大的汇总前缀。

同时保留：

`194.17.20.128/25`

作为更具体的直连路由。

这里特别重要的是：

汇总前缀允许与更具体的例外路由共同存在。

例如目的地址：

`194.17.20.200`

同时匹配：

`194.17.20.0/23`

以及：

`194.17.20.128/25`

因此选择：

$$
\boxed{194.17.20.128/25}
$$

原题从 R2 的 E0 接口直接交付。

这也解释了为什么路由聚合并不是机械地“看到下一跳不同就永远无法汇总”，而是要考虑汇总之后是否保留了正确的更具体路由。

原题还问：

R1 与 R2 分属不同 AS，应使用什么协议交换路由信息？

答案：

$$
\boxed{BGP}
$$

承载协议：

$$
\boxed{TCP}
$$

| N3 | 7  | R2  |

现在收到 R2 通告：

| 网络 | 距离 |
| -- | -- |
| N1 | 8  |
| N2 | 2  |
| N3 | 16 |

按照经典 RIP 更新规则，求新的路由。

<Accordions>

<Accordion title="练习 5 · 参考答案与推导" id="net04-answer-05">

解析

先加 1 并把不可达距离限制为 16：

| 网络 | 经 R2 的候选距离 |
| -- | ---------- |
| N1 | 9          |
| N2 | 3          |
| N3 | 16         |

N1：

原下一跳就是 R2，因此即使距离变大，也按 R2 新通告更新为 9。

N2：

原距离 5，经 R3。

现在经 R2 只需 3，因此改为经 R2，距离 3。

N3：

原下一跳就是 R2，现在 R2 宣告不可达，所以更新为 16。

最终：

| 网络 | 距离 | 下一跳 |
| -- | -- | --- |
| N1 | 9  | R2  |
| N2 | 3  | R2  |
| N3 | 16 | 不可达 |

</Accordion>

</Accordions>

### 练习 6：ARP 与 NAT 综合

假设主机 A：

`192.168.1.10/24`

默认网关：

`192.168.1.1`

默认网关 LAN MAC：

`AA:AA:AA:AA:AA:01`

A 的 MAC：

`AA:AA:AA:AA:AA:10`

路由器外网地址：

`203.0.113.9`

A 访问 Web 服务器：

`198.51.100.20:80`

且 NAT 把源端口 5000 映射为 40000。

问：

1. A 进行 ARP 时查询谁？
2. A 发出的 IP 数据报目的地址是谁？
3. A 发送的以太网帧目的 MAC 是谁？
4. NAT 后源 IP 和端口是什么？

<Accordions>

<Accordion title="练习 6 · 参考答案与推导" id="net04-answer-06">

答案

ARP 查询：

$$
\boxed{192.168.1.1}
$$

IP 目的：

$$
\boxed{198.51.100.20}
$$

帧目的 MAC：

`AA:AA:AA:AA:AA:01`

NAT 后源 IP、端口：

`203.0.113.9:40000`

其中最容易犯错的是：

数据报的目的 IP 是服务器，不是默认网关。默认网关的地址只用于决定当前链路的下一跳交付。

## 第十部分：全章易错点与考前速记

## 二十八、最容易混淆的 20 组概念

| 易错概念            | 正确认识                      |
| --------------- | ------------------------- |
| 路由与转发           | 路由计算路径，转发执行查表             |
| IP 与 MAC        | IP 用于跨网络寻址，MAC 用于当前链路交付   |
| 网络地址与广播地址       | 主机位全 0 与全 1               |
| 地址总数与可分配数       | 普通 IPv4 子网通常减 2           |
| FLSM 与 VLSM     | 等长子网与变长子网                 |
| CIDR 聚合         | 不仅要前缀对齐，还要保持转发正确性         |
| 默认路由            | `0.0.0.0/0`               |
| 主机路由            | IPv4 中典型为 `/32`           |
| IP Total Length | 包含 IPv4 首部                |
| Fragment Offset | 单位是 8 Byte                |
| MF 与 DF         | MF 表示后续是否还有分片，DF 表示是否允许分片 |
| 二次分片            | 偏移仍相对原始数据报                |
| IP 分片重组         | 通常由最终目的主机完成               |
| ARP 查询对象        | 当前链路下一跳，不一定是最终主机          |
| DHCP            | 自动提供地址、网关等网络配置            |
| ICMP            | 差错报告与控制，不保证可靠             |
| NAT 与普通路由       | NAT 可能改地址，普通路由一般不改        |
| RIP 与 OSPF      | 距离向量与链路状态                 |
| BGP 与 IGP       | BGP 重策略，IGP 解决 AS 内部路由    |
| IPv6 分片         | 中间路由器不分片，源节点可以分片          |

## 二十九、网络层最重要的公式汇总

| 题型               | 公式                                              |
| ---------------- | ----------------------------------------------- |
| 主机位数             | $h=32-n$                                    |
| 地址块总数            | $2^{32-n}$                                  |
| 普通可分配数           | $2^{32-n}-2$                                |
| 等长子网数            | $2^s$                                       |
| 新前缀              | $n_{\text{新}}=n_{\text{旧}}+s$             |
| 网络地址             | $\text{IP}\operatorname{AND}\text{Mask}$    |
| 最大非末片数据          | $8\left\lfloor\frac{MTU-H}{8}\right\rfloor$ |
| 片偏移              | $\frac{\text{分片起始字节位置}}{8}$                 |
| 原始 IP 数据部分长度     | $D=L-H$                                     |
| TTL 最小值          | $k+1$，其中 $k$ 为必须经过的路由器数                 |
| 距离向量更新           | $D_x(y)=\min_v[c(x,v)+D_v(y)]$              |
| IPv6 地址数         | $2^{128}$                                   |
| IPv6/IPv4 地址空间之比 | $2^{96}$                                    |

## 三十、网络层综合题统一解题模板

拿到复杂网络拓扑时，建议按这个顺序处理。

```text
第一步：识别 IP 网络
   │
   ├── 求每个接口的网络地址
   ├── 确定广播地址
   └── 判断哪些设备同网段
   │
   ▼
第二步：确定网络设备
   │
   ├── 哪些是交换机
   ├── 哪些是路由器
   └── 哪些设备负责 NAT
   │
   ▼
第三步：选择下一跳
   │
   ├── 同网段：直接交付
   └── 不同网段：查路由表
   │
   ▼
第四步：最长前缀匹配
   │
   ├── 选择目的前缀
   ├── 确定下一跳
   └── 确定输出接口
   │
   ▼
第五步：ARP
   │
   └── 解析当前链路下一跳 MAC
   │
   ▼
第六步：分析 IP 数据报
   │
   ├── 源 IP
   ├── 目的 IP
   ├── TTL
   └── 首部校验和
   │
   ▼
第七步：检查特殊处理
   │
   ├── NAT：修改地址/端口
   ├── MTU：是否需要分片
   └── TTL：是否超时
   │
   ▼
第八步：重新封装帧
   │
   ├── 当前链路源 MAC
   └── 当前链路目的 MAC
   │
   ▼
第九步：需要时重新计算路由
   │
   ├── RIP：距离向量
   ├── OSPF：Dijkstra
   └── BGP：路径属性/策略
   │
   ▼
第十步：路由表聚合
   │
   └── 验证聚合后转发语义不变
```

### 最后：怎样判断第 4 章已经真正掌握？

不是看自己能不能背出 RIP、OSPF、BGP 的定义，而是能不能独立完成下面几种事情：

第一，给出任意合法 IPv4 地址和前缀，能够快速算出网络地址、广播地址与可用范围。

第二，面对一张包含多个部门的拓扑，能够正确规划 VLSM 子网、分配网关并建立路由表。

第三，面对多个匹配前缀，能够准确应用最长前缀匹配，并解释为什么汇总路由可能需要更具体的例外项。

第四，给出 MTU 和 IP 数据报长度，能够完整算出所有分片的数据长度、总长度、片偏移和 MF，包括二次分片。

第五，能够从源主机一直跟踪到目的主机，明确每一跳的源/目的 IP、MAC、TTL，以及 NAT 对地址和端口的影响。

第六，能够根据距离向量更新 RIP，根据链路状态运行 Dijkstra，根据 AS 归属和路径属性分析 BGP。

第七，能够辨别 IPv6、组播、IGMP、移动 IP 和 SDN 的常见概念陷阱。

掌握这七项能力后，再结合具体题设与历年试卷练习，可系统覆盖网络层的主要 408 考查模式。
