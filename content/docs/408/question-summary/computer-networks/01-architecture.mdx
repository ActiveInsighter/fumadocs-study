<Tab value="四类时延">

$$
T_{\mathrm{send}}=\frac{L}{R},\qquad T_{\mathrm{prop}}=\frac{d}{v}.
$$

链路一跳总时延可以分解为发送、传播、处理、排队四部分，实际还需注意各阶段是否重叠。$L$ 的单位是 bit，$R$ 的单位是 bit/s，$d/v$ 的单位是 s。

</Tab>
<Tab value="等速分组流水线">

$N$ 个**等长分组**经过 $k$ 段**等速链路**，每段传输单个分组耗时 $t=L_p/R$，所有路由器对分组完整存储转发、无其他时间开销时：

$$
T=(N+k-1)t.
$$

若每跳传播时延为 $\tau_i$，且不阻止后续分组传输，则另加 $\sum_i\tau_i$。

</Tab>
<Tab value="异速流水线">

当 $k$ 段链路每个分组发送时延为 $t_i$、分组均等长、无竞争和额外排队时，理想完工时间为：

$$
T=\sum_{i=1}^{k}t_i+(N-1)\max_i t_i.
$$

这是同一条串行流水路径上的理想模型；不能据此忽略传播、处理时延或设备缓冲约束。

</Tab>
<Tab value="封装效率">

单一封装层的有效负载为 $D$ bit，首部和尾部合计 $H$ bit 时：

$$
\eta=\frac{D}{D+H}.
$$

多层封装需要检查首部是否逐层叠加，数据是否分片，以及链路层是否还有填充、前导码等实际开销。

</Tab>
</Tabs>

## 二、计算机网络的基本概念

### 2.1 什么是计算机网络？

计算机网络是将地理位置不同、具有独立功能的计算机系统，通过通信设备和通信链路互连起来，在网络协议控制下实现数据通信和资源共享的系统。

这里要抓住三个关键词。

① 独立自治

网络中的计算机通常可以独立运行。

例如，两台电脑通过交换机连接后，仍然是两台独立计算机，并不是一台计算机的两个内部部件。

② 互连

计算机之间通过有线或无线通信链路进行连接。

仅仅有物理连接还不够，双方还需要采用能够互操作的通信协议。

③ 协议

协议规定双方如何交换信息，包括数据格式、含义以及交互顺序。

例如，浏览器和 Web 服务器必须按照双方支持的应用层协议通信。

### 2.2 计算机网络的主要功能

| 功能    | 解释              | 例子          |
| ----- | --------------- | ----------- |
| 数据通信  | 不同计算机交换数据       | 发送消息        |
| 资源共享  | 共享软硬件与数据        | 网络打印机、文件服务器 |
| 分布式处理 | 多个计算机协同完成任务     | 分布式计算       |
| 提高可靠性 | 利用冗余结点和链路减小故障影响 | 多服务器、多路径    |
| 负载均衡  | 将任务分散到多个结点      | Web 服务集群    |

数据通信是最基础的功能，其他功能通常建立在通信能力之上。

### 2.3 网络的组成

#### 从功能划分

经典教材常将网络分为资源子网和通信子网。

| 类型   | 主要组成          | 作用        |
| ---- | ------------- | --------- |
| 资源子网 | 主机、终端、软件及数据资源 | 信息处理、资源共享 |
| 通信子网 | 通信链路、交换设备等    | 数据传输、交换   |

注意：这是经典的功能划分，而非要求现代每台设备只能属于其中一类。

#### 从 Internet 的角度划分

Internet 可以理解为两大部分。

边缘部分主要由端系统构成，例如用户电脑、手机和服务器。网络应用通常运行在这里。

核心部分主要由大量路由器及其互连链路构成，为端系统之间的数据通信提供转发服务。

例如：

```text
主机A
  │
接入网络
  │
路由器R1
  │
路由器R2
  │
路由器R3
  │
接入网络
  │
服务器B
```

主机 A 和服务器 B 属于端系统；中间路由器及其互连链路承担核心转发功能。

### 2.4 客户端—服务器与 P2P

这是网络边缘部分常见的两种通信模式。

客户端—服务器（C/S）

服务器通常持续提供服务，客户端主动发起请求。

例如浏览器访问网站。

P2P（Peer-to-Peer）

参与通信的结点可以同时作为服务请求方和服务提供方。

例如部分文件共享应用。

需要注意：C/S 与 P2P 描述的是应用组织方式，不是判断某网络是否属于局域网的标准。

### 2.5 网络分类

按覆盖范围划分：

| 类型  | 英文  | 常见覆盖范围   |
| --- | --- | -------- |
| 个域网 | PAN | 个人设备周围   |
| 局域网 | LAN | 房间、建筑、园区 |
| 城域网 | MAN | 城市       |
| 广域网 | WAN | 跨城市、跨地区  |

按传输技术还可以划分为广播式网络、点对点网络。

按使用范围可以划分为公用网、专用网。

按介质可以划分为有线网、无线网。

考试陷阱：不同分类标准不能混淆。

例如无线局域网同时具有“无线”和“局域网”两个属性，并不矛盾。

### 2.6 网络拓扑

| 拓扑  | 特点         | 常见问题       |
| --- | ---------- | ---------- |
| 总线型 | 多个结点共享主干   | 主干故障影响较大   |
| 星型  | 所有结点连接中心设备 | 中心设备是关键故障点 |
| 环型  | 结点构成闭合环    | 需要处理环路传输   |
| 树型  | 分层扩展       | 上层故障可能影响子树 |
| 网状型 | 存在多条连接路径   | 成本较高，冗余性较好 |

需要区分物理拓扑和逻辑拓扑。

例如，使用集线器连接的以太网在物理连接上是星型，但所有设备仍共享同一个碰撞域。

因此，物理上呈星型，不代表设备之间具有独立的传输信道。

### 2.7 网络标准化组织

| 组织    | 全称或名称          | 重要成果          |
| ----- | -------------- | ------------- |
| ISO   | 国际标准化组织        | OSI 参考模型      |
| IEEE  | 电气电子工程师学会      | IEEE 802 标准   |
| ITU-T | 国际电信联盟电信标准化部门  | 电信技术建议        |
| IETF  | Internet 工程任务组 | Internet 协议标准 |

重点记忆：

- IEEE 802.3：以太网相关标准。
- IEEE 802.11：无线局域网相关标准。
- ISO：OSI 七层参考模型。
- IETF：Internet 协议标准化工作的重要组织。

RFC 不等于正式 Internet 标准。

RFC 是技术文档系列，其中既有标准轨文档，也有信息性、实验性等文档。

## 三、计算机网络性能指标

这一部分是本章最重要的计算基础。

### 3.1 速率、带宽、吞吐量的区别

#### 速率（Rate）

通常指单位时间传输的比特数。

单位为 bit/s、kb/s、Mb/s、Gb/s。

换算：

$$
1\ \mathrm{kb/s}=10^3\ \mathrm{bit/s}
$$

$$
1\ \mathrm{Mb/s}=10^6\ \mathrm{bit/s}
$$

$$
1\ \mathrm{Gb/s}=10^9\ \mathrm{bit/s}
$$

特别注意：

$$
1\ \mathrm{B}=8\ \mathrm{bit}
$$

网络传输速率通常用 bit/s，而文件大小通常用 B。

#### 带宽（Bandwidth）

有两种不同的语境：

1. 模拟信道的频带宽度，单位 Hz。
2. 数字网络中链路的数据传输能力，单位 bit/s。

例如：

> 一条链路的带宽是 100 Mb/s。

表示该链路的标称数据传输能力，而不表示一个文件一定能够以 100 Mb/s 的应用有效速率传输。

#### 吞吐量（Throughput）

表示单位时间内实际通过网络或链路的数据量。

假设：

```text
主机A
  │ 100Mb/s
  ▼
 R1
  │ 10Mb/s
  ▼
 R2
  │ 50Mb/s
  ▼
主机B
```

在单一路径、无其他限制时，端到端持续吞吐量的上限受到最慢链路限制：

$$
T_{\max}\leq\min(100,10,50)
$$

所以：

$$
\boxed{T_{\max}\leq10\ \mathrm{Mb/s}}
$$

中间 10 Mb/s 的链路就是瓶颈链路。

这里说的是持续吞吐能力，而不是某个很短分组传输一次所需的总时间。

#### 好吞吐量（Goodput）

好吞吐量只统计实际交付给上层的有效数据。

例如：

- 数据帧有首部。
- IP 数据报有首部。
- TCP 报文段有首部。
- 某些数据还可能因为丢包而重新发送。

这些开销会使真正交付的有效数据速率进一步下降。

在相同统计口径下：

$$
\mathrm{Goodput}\leq\mathrm{Throughput}
$$

#### 典型辨析题

某链路带宽 100 Mb/s，但实际吞吐量只有 60 Mb/s，是否说明链路带宽变成了 60 Mb/s？

答案：不是。

100 Mb/s 是链路能力，60 Mb/s 是当前实际传输表现。

### 3.2 四种时延

网络中的分组从源主机到目的主机，通常经历：

$$
\boxed{ D=D_{\mathrm{trans}}+D_{\mathrm{prop}} +D_{\mathrm{proc}}+D_{\mathrm{queue}} }
$$

分别是：

1. 发送时延。
2. 传播时延。
3. 处理时延。
4. 排队时延。

#### ① 发送时延（Transmission Delay）

指把数据的所有比特依次送入链路所需的时间。

$$
\boxed{T_t=\frac{L}{R}}
$$

其中：

- $L$：数据长度，单位 bit。
- $R$：发送速率，单位 bit/s。

例如：

发送一个长度为 12000 bit 的分组，速率是 12 Mb/s。

$$
T_t=\frac{12000}{12\times10^6}
$$

$$
\boxed{T_t=1\ \mathrm{ms}}
$$

发送时延的直观含义：

假设一列汽车通过收费站，收费站每秒能够放行一定数量的汽车。

整列车依次通过收费站需要时间。

这个时间就类似发送时延。

它与链路长度没有直接关系。

#### ② 传播时延（Propagation Delay）

表示信号在介质中从一端传播到另一端需要的时间。

$$
\boxed{T_p=\frac{d}{v}}
$$

其中：

- $d$：传播距离。
- $v$：信号在介质中的传播速度。

例如，链路长 2000 km，传播速度为：

$$
v=2\times10^8\ \mathrm{m/s}
$$

那么：

$$
T_p=\frac{2000\times1000}{2\times10^8}
$$

$$
\boxed{T_p=10\ \mathrm{ms}}
$$

还是用汽车举例：

汽车离开收费站后，还需要沿公路行驶到终点。

行驶时间类似传播时延。

#### ③ 处理时延

交换设备对收到的数据进行处理所需要的时间。

例如：

- 检查帧。
- 解析首部。
- 查询转发表。
- 决定输出端口。

#### ④ 排队时延

当分组到达路由器时，如果输出端口正在发送其他分组，就需要等待。

排队时间与网络负载有关，通常最不稳定。

当流量接近链路处理能力时，排队时延可能迅速增大。

<Callout type="idea" title="判断时延的两个独立变量">一份 $L$ bit 数据发到链路上要花 $L/R$ 秒；首比特在长度 $d$ 的链路上传播要花 $d/v$ 秒。增加线路长度不改变同速链路的发送时延；提高带宽不改变同一介质上的传播速度。</Callout>

### 3.3 发送时延与传播时延：最重要的辨析

| 比较     | 发送时延      | 传播时延      |
| ------ | --------- | --------- |
| 决定因素   | 分组长度、发送速率 | 距离、传播速度   |
| 公式     | $L/R$ | $d/v$ |
| 提高带宽   | 通常减小      | 不直接改变     |
| 增大数据长度 | 增大        | 不直接改变     |
| 增大链路距离 | 不直接改变     | 增大        |

经典陷阱：带宽越大，信号传播越快？

错误。

提高带宽通常让发送设备能更快地把比特送入链路，但不会直接让电磁波在介质中的传播速度变快。

### 3.4 一个分组完整到达需要多久？

设：

- 分组长度 $L$。
- 发送速率 $R$。
- 链路长度 $d$。
- 传播速度 $v$。

忽略处理、排队时延。

第一个比特从发送方出发后，经过：

$$
\frac{d}{v}
$$

即可到达接收方。

但是最后一个比特必须先被发送出来。

其发送完成时间是：

$$
\frac{L}{R}
$$

然后还需要传播：

$$
\frac{d}{v}
$$

所以整个分组完整到达的时间为：

$$
\boxed{ T=\frac{L}{R}+\frac{d}{v} }
$$

例如前面的例子：

$$
T=1+10=11\ \mathrm{ms}
$$

这同时说明：

第一个比特到达时间与最后一个比特到达时间不同。

题目如果说“开始接收到数据”，与“完整收到整个数据帧”，往往是不同的时间点。

### 3.5 往返时延 RTT

RTT（Round-Trip Time）表示一次请求从发送方出发，到相应响应返回发送方的往返时间。

假设：

```text
A ──────────────→ B
     请求

A ←────────────── B
     响应
```

如果请求和响应都非常短，发送时间忽略，双方也没有处理与排队时间，则：

$$
RTT\approx2T_p
$$

但实际 RTT 还可能包含：

- 请求发送时间。
- 响应发送时间。
- 处理时间。
- 排队时间。

因此不能无条件认定：

$$
RTT=2T_p
$$

### 模拟题：王道卷三 Q33

题意：

A 发送很短的分组，B 收到后立即回复，双方发送时延可以忽略。

测量得到的 RTT 与传输介质往返传播时延是什么关系？

正确答案：

$$
\boxed{RTT\geq T_{\text{往返传播}}}
$$

原因：

处理时延、排队时延不可能使信号在介质中的传播时间变短。

但它们可以为零，因此不能说 RTT 一定严格大于往返传播时延。

这是典型的等号边界陷阱。

### 3.6 时延带宽积 BDP

时延带宽积（Bandwidth-Delay Product）表示一条链路中能够同时存在多少正在传播的比特。

$$
\boxed{BDP=R\times T_p}
$$

其中这里使用的是单向传播时延。

#### 例题

带宽：

$$
R=100\ \mathrm{Mb/s}
$$

单向传播时延：

$$
T_p=20\ \mathrm{ms}
$$

那么：

$$
BDP=100\times10^6\times0.02
$$

$$
\boxed{BDP=2\times10^6\ \mathrm{bit}}
$$

即约 2 Mbit。

它表示：

当发送方持续以 100 Mb/s 发送，并且链路足够长时，链路中最多可以有约 2 Mbit 正在传播。

形象理解：

链路像一根水管。

- 带宽相当于水流速率。
- 传播时延反映水从入口到出口需要多久。
- 时延带宽积相当于水管中能够容纳的在途数据量。

#### 延伸：发送窗口与 RTT

在基于确认的可靠传输中，如果发送方受到窗口限制，通常还需要考虑 RTT。

若希望长期维持速率 $R$，理想情况下所需的在途未确认数据量约为：

$$
\boxed{W\gtrsim R\times RTT}
$$

这里的 RTT 不应直接与单向传播时延混淆。

后面 TCP 滑动窗口计算题会反复使用这个思想。

### 3.7 利用率

链路利用率表示链路处于传输状态的时间所占比例。

在简化模型中：

$$
U=\frac{\text{有效发送时间}}{\text{总观察时间}}
$$

但利用率越高，不一定意味着网络性能越好。

在排队系统中，当到达速率越来越接近链路服务能力时，平均等待时间通常迅速增大。

因此，链路高利用率与低时延不是一回事。

## 四、三种数据交换方式

这是本章第二个重要计算模块。

### 4.1 为什么需要数据交换？

设主机 A 要向主机 B 发送数据。

如果所有主机两两直接连接，成本会非常高。

因此需要中间设备帮助转发。

```text
A ─── R1 ─── R2 ─── B
```

不同交换方式的核心区别在于：

传输过程中是否预留资源，以及中间设备以多大的数据单元进行转发。

### 4.2 电路交换

电路交换通常分为三个阶段：

```text
建立电路
    ↓
数据传输
    ↓
释放电路
```

经典例子是传统电话交换网络。

特点：

- 通信前需要建立连接。
- 为通信预留相关传输资源。
- 建立后可以连续传输数据。
- 通信过程中一般无须对每个数据单元重新选择路径。

优点是传输性能相对可预测，适合持续、稳定的通信流。

缺点是空闲期间仍可能占用已分配的资源。

#### 电路交换总时延

设：

- 电路建立时间 $T_c$。
- 数据长度 $L$。
- 传输速率 $R$。
- 共经过 $k$ 段链路。
- 每段传播时延 $T_p$。

则理想情况下：

$$
\boxed{ T_{\mathrm{circuit}} =T_c+\frac{L}{R}+kT_p }
$$

为什么不是：

$$
T_c+k\frac{L}{R}+kT_p
$$

因为建立电路后，数据流可以沿整个电路连续传输，不需要在每一个中间设备都等待整个报文完整接收后才继续转发。

### 4.3 报文交换

报文交换将整个报文作为存储转发单位。

例如：

```text
A ─── R ─── B
```

A 发送一个报文。

R 必须先完整接收这个报文，才能继续向 B 发送。

因此：

```text
0～2s：A → R
2～4s：R → B
```

报文交换的特点：

- 通常不需要提前建立专用电路。
- 中间设备需要缓存完整报文。
- 报文越长，存储转发等待可能越明显。

对于 $k$ 条等速链路，忽略其他时延：

$$
\boxed{ T_{\mathrm{message}}=k\frac{L}{R} }
$$

若每段传播时延都是 $T_p$，则：

$$
T_{\mathrm{message}} =k\frac{L}{R}+kT_p
$$

### 4.4 分组交换

分组交换将较长报文拆分为多个较短分组。

例如，一个 20 kb 的报文：

```text
原始报文
████████████████████

拆分为：

分组1：██████████
分组2：██████████
```

中间设备不必等待整个原始报文接收完成。

只要完整收到第一个分组，就可以开始转发它。

同时源主机还可以继续发送第二个分组。

这就是流水线传输。

#### 分组交换的主要特点

优点：

- 不必长期占用专用链路。
- 可以统计复用网络资源。
- 多个分组能够在不同链路上同时传输。
- 通常适合突发性数据通信。

代价：

- 每个分组可能增加首部。
- 分组可能排队、丢失或乱序。
- 需要中间设备进行分组处理和转发。

分组交换不是无条件比电路交换快。

需要结合电路建立时间、分组首部、流量负载、传播时延等综合判断。

<Callout type="warn" title="理想分组流水线的前提">经典 $(N+k-1)L_p/R$ 要求分组长度相同、每段链路等速、全分组存储转发、无额外开销。不同链路速率的理想模型可用 $\sum t_i+(N-1)\max t_i$；存在队列、链路竞争、尾包不足一整包时必须另行处理。</Callout>

### 4.5 分组交换中的流水线公式

这是 408 必须掌握的公式。

假设：

- 总共有 $N$ 个分组。
- 每个分组长度为 $P$ bit。
- 经过 $k$ 条链路。
- 每条链路的发送速率都是 $R$。
- 各结点采用完整分组存储转发。
- 不考虑传播、处理、排队时延。

那么：

$$
\boxed{ T=(N+k-1)\frac{P}{R} }
$$

#### 公式怎么推导？

设一个分组在一条链路上的发送时间为：

$$
t=\frac{P}{R}
$$

第一个分组需要经过 $k$ 条链路，所以：

$$
T_1=kt
$$

后续分组能够与前面分组流水传输。

每多发送一个分组，最后完成时间增加一个 $t$。

因此：

$$
T=kt+(N-1)t
$$

整理得到：

$$
\boxed{T=(N+k-1)t}
$$

代入：

$$
t=\frac{P}{R}
$$

就得到最终公式。

#### 重要前提

这个公式并非任意网络都可以直接使用。

它要求：

- 分组等长。
- 各条链路速率相同。
- 能够形成稳定流水线。
- 不存在额外等待。
- 未计入分组头部、传播及处理时延。

如果题目不满足这些条件，要重新分析时间线。

### 4.6 模拟题：竟成模拟六 Q35

题意：

甲和乙之间有一个路由器，共两段链路。

已知：

- 传输速率均为 10 kb/s。
- 报文大小 20 kb。
- 每个分组大小 10 kb。
- 忽略传播时延及其他开销。

先求分组交换所需时间。

#### 第一步：计算分组数量

$$
N=\frac{20}{10}=2
$$

#### 第二步：计算每个分组发送时间

$$
t=\frac{10}{10}=1\ \mathrm{s}
$$

#### 第三步：确定链路数量

甲到路由器、路由器到乙：

$$
k=2
$$

#### 第四步：使用流水线公式

$$
T=(N+k-1)t
$$

$$
T=(2+2-1)\times1
$$

$$
\boxed{T=3\ \mathrm{s}}
$$

时间过程：

| 时间    | 甲 → 路由器 | 路由器 → 乙 |
| ----- | ------- | ------- |
| 0～1 s | 发送分组 1  | —       |
| 1～2 s | 发送分组 2  | 转发分组 1  |
| 2～3 s | —       | 转发分组 2  |

注意 1～2 s 期间，两条链路同时工作。

#### 第五步：改成报文交换

题目进一步问：

如果仍然使用 3 s，报文交换能发送多大的报文？

设报文大小为 $X$ kb。

中间路由器必须完整接收后再发送，所以：

$$
2\frac{X}{10}=3
$$

解得：

$$
\boxed{X=15\ \mathrm{kb}}
$$

答案：15 kb。

这道模拟题的重点不是公式记忆，而是理解报文交换和分组交换的时间线为什么不同。

### 4.7 电路交换与分组交换的时延比较

### 模拟题：王道卷一 Q33

设：

- 报文长度 $x$ bit。
- 共经过 $k$ 段链路。
- 每段传播时延为 $d$。
- 数据传输率为 $b$ bit/s。
- 电路建立时间为 $c$。
- 分组长度为 $p$ bit。
- 分组等长，首部开销忽略。

求分组交换比电路交换更快的条件。

#### 电路交换

$$
T_c=c+\frac{x}{b}+kd
$$

#### 分组交换

源主机发送全部数据：

$$
\frac{x}{b}
$$

最后一个分组还需要经过剩余 $k-1$ 条链路：

$$
(k-1)\frac{p}{b}
$$

再加传播时延：

$$
kd
$$

所以：

$$
T_p=\frac{x}{b}+(k-1)\frac{p}{b}+kd
$$

要求：

$$
T_p<T_c
$$

即：

$$
\frac{x}{b}+(k-1)\frac{p}{b}+kd < c+\frac{x}{b}+kd
$$

两边消去公共项：

$$
\boxed{ (k-1)\frac{p}{b}<c }
$$

答案是王道卷一 Q33 的 A 选项。

#### 这道题真正考什么？

第一，电路交换需要建立时间。

第二，分组交换存在最后一个分组逐跳转发的额外发送时间。

第三，两种交换方式的传播时延相同，所以在这个简化模型下比较时可以抵消。

如果把分组交换错误地写成：

$$
k\frac{x}{b}
$$

就相当于把它当成了整报文存储转发，忽略了流水线。

### 4.8 数据报与虚电路

分组交换还可以进一步分成两种常见服务方式。

| 比较     | 数据报        | 虚电路         |
| ------ | ---------- | ----------- |
| 建立连接   | 通常不需要      | 需要先建立逻辑连接   |
| 转发依据   | 目的地址       | 虚电路标识       |
| 不同分组路径 | 可能不同       | 通常沿预先确定的路径  |
| 到达顺序   | 可能乱序       | 正常情况下通常保持顺序 |
| 中间结点故障 | 后续分组可能重新选路 | 原虚电路可能失效    |
| 典型例子   | IP 网络      | ATM 等虚电路网络  |

其中最容易误解的是：

虚电路不是电路交换。

虚电路只是提前建立逻辑转发关系，并不意味着必须像传统电路交换一样独占一条物理线路。

### 模拟题：竟成模拟四 Q34

题目问：

数据报和虚电路交换方式中，哪项描述错误？

关键错误说法是：

> 两种交换方式在中间结点故障时，都能直接重新选择路由继续传输。

虚电路的既定路径发生故障，原虚电路通常需要重新建立，因此这个说法错误。

正确选项：C。

## 五、计算机网络的分层体系结构

这是本章真题考查最密集的部分之一。

在原稿的分类真题中，2009、2010、2011、2013、2014、2016、2017、2019、2020、2021、2022 年的题目，均与网络体系结构及相关概念密切相关。

### 5.1 为什么计算机网络要分层？

考虑这样一个问题：

主机 A 通过 Internet 向服务器 B 发送一个 HTTP 请求。

这个过程需要解决：

- 数据应该采用什么格式？
- 发送给服务器的哪个进程？
- 服务器的 IP 地址是什么？
- 应该经过哪些路由器？
- 数据如何组织成帧？
- 如何将比特转换成物理信号？

如果所有功能由一个整体完成，设计会非常复杂。

因此使用分层思想。

每一层完成相对独立的功能，通过规定好的接口进行协作。

#### 分层的优点

1. 降低系统设计复杂度。
2. 各层具有相对独立性。
3. 便于实现、调试和维护。
4. 有利于标准化。
5. 可以独立替换某一层的具体实现。

但分层不意味着越多越好。

因为层数过多可能导致：

- 协议首部开销增加。
- 数据处理步骤增多。
- 不同层重复实现某些功能。
- 跨层信息共享困难。

分层的核心是合理划分功能，而不是无限增加层数。

### 5.2 OSI 七层参考模型

OSI 七层从低到高为：

$$
\boxed{ \text{物理}\rightarrow \text{链路}\rightarrow \text{网络}\rightarrow \text{传输}\rightarrow \text{会话}\rightarrow \text{表示}\rightarrow \text{应用} }
$$

口诀：

物、链、网、传、会、表、应。

#### 七层功能总表

| 层次 | 名称    | 核心功能       | 关键词          |
| -- | ----- | ---------- | ------------ |
| 7  | 应用层   | 为网络应用提供服务  | HTTP、DNS、FTP |
| 6  | 表示层   | 数据表示与转换    | 编码、加密、压缩     |
| 5  | 会话层   | 建立与管理会话    | 同步、对话管理      |
| 4  | 传输层   | 进程之间的端到端通信 | TCP、UDP、端口   |
| 3  | 网络层   | 跨网络分组转发    | IP、路由        |
| 2  | 数据链路层 | 相邻结点之间传帧   | MAC、帧、差错检测   |
| 1  | 物理层   | 传输原始比特     | 信号、接口、介质     |

下面逐层讲解，重点是每一层究竟解决什么问题。

#### 第一层：物理层

物理层负责在物理介质上传送比特。

例如：

```text
10110100
    ↓
电信号、光信号或无线信号
    ↓
物理介质
```

主要功能包括：

- 规定接口的机械特性。
- 规定电气特性。
- 规定功能特性。
- 规定规程特性。
- 实现原始比特的传输。

常见设备：

- 中继器。
- 集线器。

注意，物理层不负责理解 IP 地址、MAC 地址或应用内容。

#### 第二层：数据链路层

关键词是：

相邻结点、帧、MAC 地址。

例如：

```text
主机A ─── 路由器R1
```

链路层解决的是 A 到 R1 这一跳如何传送数据。

主要功能：

1. 封装成帧。
2. 帧定界。
3. 差错检测。
4. 介质访问控制。
5. 在需要时提供逐跳流量控制与可靠传输机制。

其中必须注意：

数据链路层并不意味着所有协议都保证可靠交付。

例如以太网有帧校验机制，但通常不会在以太网链路层自动对所有错误帧进行可靠重传。

#### 第三层：网络层

关键词是：

IP 地址、路由选择、分组转发。

例如：

```text
A ── R1 ── R2 ── R3 ── B
```

网络层要解决：

> 如何使一个 IP 分组跨越多个网络到达目的主机？

主要功能包括：

- 逻辑寻址。
- 路由选择。
- 分组转发。
- 网际互连。
- 网络层控制与差错报告。

网络层不直接负责决定目的主机中哪个应用进程接收数据。

#### 第四层：传输层

关键词是：

端到端、进程到进程、端口号。

假设服务器运行：

```text
Web服务器
邮件服务器
数据库服务
```

当 IP 分组到达服务器后，数据应该交给哪个应用？

这需要传输层提供复用与分用机制。

传输层主要功能包括：

- 端到端逻辑通信。
- 进程复用与分用。
- 差错检测。
- 可靠数据传输（如 TCP）。
- 流量控制（如 TCP）。
- 拥塞控制（如 TCP）。

#### 网络层和传输层到底有什么区别？

这是本章最重要的概念之一。

| 比较     | 网络层        | 传输层         |
| ------ | ---------- | ----------- |
| 典型通信对象 | 主机或网络接口    | 应用进程        |
| 主要解决   | 分组如何到达目的主机 | 数据如何交付给目标进程 |
| 主要标识   | IP 地址      | 端口号         |
| 典型协议   | IP         | TCP、UDP     |
| 核心功能   | 路由、转发      | 复用分用、端到端传输  |

需要进一步强调：网络层同样承担跨网络的主机到主机交付任务，但在 OSI 模型的经典考研表述中，传输层是自下而上第一个提供端到端传输服务的层次。

#### 第五层：会话层

关键词：

会话建立、管理、同步、恢复。

例如两台主机之间持续交换数据：

```text
建立会话
   ↓
开始数据交换
   ↓
设置同步点
   ↓
继续交换
   ↓
结束会话
```

会话层主要负责管理通信双方的对话关系。

#### 第六层：表示层

关键词：

格式转换、编码、加密、压缩。

例如：

发送端使用某种字符编码，接收端需要按照约定的格式解释数据。

表示层处理的是数据应该如何表示。

表示层不等于应用层。

表示层侧重数据的表示形式，应用层侧重具体应用通信服务。

#### 第七层：应用层

负责为网络应用提供协议及服务。

例如：

- HTTP：Web 通信。
- FTP：文件传输。
- SMTP：邮件发送。
- DNS：域名解析。

应用层不等于具体应用程序本身。HTTP 是应用层协议，浏览器是使用相关协议的应用程序。

### 5.3 TCP/IP 四层参考模型

TCP/IP 体系结构通常分为四层：

```text
应用层
  ↓
传输层
  ↓
网际层
  ↓
网络接口层
```

注意：

TCP/IP 四层模型并不是 OSI 七层模型的简单改名。

它们在层次划分、协议组织和设计思想上都有差别。

### 5.4 五层教学模型

为了方便学习，408 教材经常采用五层模型：

```text
应用层
  ↓
传输层
  ↓
网络层
  ↓
数据链路层
  ↓
物理层
```

三种模型的对应关系：

| OSI 七层 | TCP/IP 四层 | 五层教学模型 |
| ------ | --------- | ------ |
| 应用层    | 应用层       | 应用层    |
| 表示层    | 应用层       | 应用层    |
| 会话层    | 应用层       | 应用层    |
| 传输层    | 传输层       | 传输层    |
| 网络层    | 网际层       | 网络层    |
| 数据链路层  | 网络接口层     | 数据链路层  |
| 物理层    | 网络接口层     | 物理层    |

最容易考错的一点是：

> 物理、数据链路、网络、传输、应用五层，是教学五层模型的划分，不是经典 TCP/IP 四层参考模型的严格层次划分。

### 5.5 OSI 与 TCP/IP 的区别

| 比较    | OSI           | TCP/IP           |
| ----- | ------------- | ---------------- |
| 层数    | 7 层           | 经典模型 4 层         |
| 定位    | 通用参考模型        | 实际 Internet 协议体系 |
| 设计特点  | 强调服务、接口、协议的区分 | 更注重具体协议体系        |
| 网络层服务 | 可支持面向连接与无连接   | IP 提供无连接数据报服务    |
| 传输层   | 经典模型强调端到端传输服务 | TCP 和 UDP 等协议并存  |

### 模拟题：竟成模拟六 Q33

题目要求判断以下说法：

I. TCP/IP 参考模型自下而上是物理层、链路层、网络层、传输层、应用层。

II. OSI 参考模型共有七层。

III. TCP/IP 将会话层与表示层相关功能并入应用层范围。

分析：

- I 错：这是五层教学模型。
- II 对：OSI 为七层。
- III 对：TCP/IP 没有独立的会话层和表示层。

因此：

$$
\boxed{\text{答案：C，II、III}}
$$

## 六、协议、服务、接口：高频概念辨析

### 6.1 三者之间的关系

这是一个非常抽象但常考的知识点。

首先看下面的逻辑结构：

```text
主机A                       主机B

应用层实体 ←─应用层协议─→ 应用层实体
    ↑                         ↑
   服务                       服务
    ↑                         ↑
传输层实体 ←─传输层协议─→ 传输层实体
    ↑                         ↑
   服务                       服务
    ↑                         ↑
网络层实体 ←─网络层协议─→ 网络层实体
```

必须记住：

协议是水平的，服务是垂直的。

#### 协议（Protocol）

协议是对等实体之间通信时遵守的规则。

例如：

A 主机的 TCP 实体与 B 主机的 TCP 实体，在逻辑上按照 TCP 协议进行通信。

#### 服务（Service）

服务是下层向相邻上层提供的功能。

例如：

传输层向应用层提供数据传输服务。

#### 接口（Interface）

接口是上下相邻层之间交换信息、访问服务的边界及规则。

SAP 是服务访问点（Service Access Point）。

#### 三者关系表

| 概念 | 作用对象      | 核心     |
| -- | --------- | ------ |
| 协议 | 不同主机的同层实体 | 如何通信   |
| 服务 | 同一主机的相邻层  | 提供什么功能 |
| 接口 | 上下相邻层     | 如何访问服务 |

理解这个关系之后，再看下面的问题。

第 $n$ 层：

- 使用第 $n-1$ 层提供的服务。
- 向第 $n+1$ 层提供服务。

所以第 $n$ 层是：

- 第 $n-1$ 层的用户。
- 第 $n+1$ 层的服务提供者。

### 6.2 协议三要素

$$
\boxed{ \text{协议}=\text{语法}+\text{语义}+\text{时序} }
$$

#### 语法（Syntax）

规定数据的格式、结构及编码方式。

例如：

TCP 首部的源端口字段占 16 bit。

这描述的是数据格式，因此属于语法。

#### 语义（Semantics）

规定信息的含义，以及收到相关信息后应该执行什么操作。

例如：

TCP 报文中 SYN 标志置 1 表示连接建立相关的控制含义。

这是语义。

再例如：

HTTP 服务器收到 GET 请求后，应根据请求语义执行相应操作。

这也是语义。

#### 时序（Timing）

规定事件的发生顺序、通信双方如何交互以及时间关系。

例如：

```text
A → SYN → B

A ← SYN+ACK ← B

A → ACK → B
```

如果题目重点描述的是报文交互顺序，就属于时序。

#### 经典辨析

| 描述                | 协议要素 |
| ----------------- | ---- |
| TCP 源端口字段占 16 bit | 语法   |
| SYN=1 的含义         | 语义   |
| 收到某请求后执行相应操作      | 语义   |
| 先发送请求，再返回确认       | 时序   |
| 字段如何排列            | 语法   |
| 发送与等待的先后顺序        | 时序   |

<Callout type="warn" title="‘面向连接’不等于‘保证可靠’">连接表示通信关系或通信状态，不自动提供可靠交付；可靠性需要额外的确认、重传、序号等机制。网络层 IP 通常按尽最大努力方式转发，TCP 的可靠性是传输层端到端的机制。</Callout>

### 6.3 面向连接与可靠性不是一回事

这也是模拟题反复考查的陷阱。

#### 面向连接

表示通信前需要建立某种逻辑连接关系。

#### 无连接

表示发送数据前不需要建立该类型的连接关系。

#### 可靠传输

表示协议对数据交付提供特定保证，通常需要确认、重传、序号等机制。

因此：

$$
\boxed{ \text{面向连接}\not\Rightarrow\text{可靠} }
$$

同样：

$$
\boxed{ \text{无连接}\not\Rightarrow\text{必然不可靠} }
$$

#### TCP 与 UDP 的典型区别

| 比较      | TCP  | UDP          |
| ------- | ---- | ------------ |
| 连接      | 面向连接 | 无连接          |
| 数据组织    | 字节流  | 报文           |
| 协议内可靠传输 | 提供   | 不提供 TCP 式可靠性 |
| 流量控制    | 有    | 无            |
| 拥塞控制    | 有    | UDP 本身无      |
| 首部开销    | 较大   | 较小           |

IP 网际层则提供：

无连接、尽最大努力交付的数据报服务。

这意味着 IP 自身不保证：

- 一定到达。
- 按序到达。
- 不发生重复。
- 丢失后自动重传。

### 模拟题：竟成模拟四 Q33

其中有一个说法：

“面向连接的服务一定可靠。”

答案：错误。

原因不是连接没有意义，而是连接机制与可靠性保证属于两个不同维度。

## 七、PDU、SDU、PCI 与逐层封装

### 7.1 三个概念

#### SDU：服务数据单元

上层交给本层处理的数据。

#### PCI：协议控制信息

本层协议为实现通信功能而附加的控制信息。

例如首部、某些尾部控制字段。

#### PDU：协议数据单元

本层处理并在对等实体之间逻辑交换的数据单元。

三者的关系为：

$$
\boxed{ PDU_n=SDU_n+PCI_n }
$$

这是逻辑上的封装关系，真实系统中可能还涉及分段、聚合等处理。

### 7.2 五层模型中各层的数据单位

| 层次      | 常见 PDU 名称            |
| ------- | -------------------- |
| 应用层     | Message / Data       |
| 传输层 TCP | Segment，报文段          |
| 传输层 UDP | User Datagram，用户数据报  |
| 网络层     | Packet / IP Datagram |
| 数据链路层   | Frame，帧              |
| 物理层     | Bit，比特               |

重点记忆：

报文段 → IP 数据报 → 帧 → 比特。

### 7.3 数据封装过程

假设浏览器发送 HTTP 请求。

在典型的 TCP/IP 通信中：

```text
应用层
┌─────────────────┐
│    HTTP数据      │
└─────────────────┘
          ↓
传输层
┌────────┬────────┐
│ TCP首部│ HTTP数据│
└────────┴────────┘
          ↓
网络层
┌────────┬────────┬────────┐
│ IP首部 │ TCP首部│ HTTP数据│
└────────┴────────┴────────┘
          ↓
链路层
┌────────┬────────┬────────┬────────┬────────┐
│ 帧首部 │ IP首部 │ TCP首部│ HTTP数据│ 帧尾部 │
└────────┴────────┴────────┴────────┴────────┘
          ↓
物理层
       比特流
```

接收端反过来逐层解封装。

这里最重要的理解：

同层实体在逻辑上使用本层协议通信，但真实数据是在发送端逐层向下、经过物理网络、再在接收端逐层向上传递。

### 7.4 真题：2017 年封装效率

这是第 1 章非常经典的计算题。

题目：

OSI 参考模型中，应用层发送 400 B 数据，不进行拆分。

除物理层和应用层外，其余各层封装时都增加 20 B 的额外开销。

求应用层数据传输效率。

#### 第一步：判断增加首部的层数

OSI 七层：

```text
应用层    不增加
表示层    +20B
会话层    +20B
传输层    +20B
网络层    +20B
链路层    +20B
物理层    不增加
```

因此共有五层增加开销。

#### 第二步：计算额外开销

$$
H=5\times20=100\ \mathrm{B}
$$

#### 第三步：计算实际传输数据长度

$$
L=400+100=500\ \mathrm{B}
$$

#### 第四步：计算效率

$$
\eta=\frac{400}{500}\times100\%
$$

$$
\boxed{\eta=80\%}
$$

正确答案：A。

#### 通用公式

如果有效数据长度为 $D$，各层增加的控制信息长度为 $h_1,h_2,\ldots,h_n$，且没有拆分、重传等额外开销：

$$
\boxed{ \eta=\frac{D}{D+\sum_{i=1}^{n}h_i} }
$$

这一公式可以直接迁移到：

- IP 分组有效载荷比例。
- 以太网帧封装效率。
- TCP 首部开销计算。
- 分组长度优化问题。

### 7.5 模拟题：竟成模拟七 Q33

题目：

OSI 模型自下而上前三层的 SDU 分别是什么？

资料答案：

数据帧、数据分组、报文段。

为什么？

因为 SDU 是本层从上层接收的数据，而不是本层自身的 PDU 名称。

例如：

- 网络层从传输层接收报文段。
- 数据链路层从网络层接收 IP 分组。
- 物理层从数据链路层接收帧所表示的数据。

但要注意：这是题目采用的抽象层间数据单位口径。实际物理层处理的是帧对应的比特序列，并不会像数据链路层一样解析帧结构。

考研做题时必须根据题干判断问的是 PDU 还是 SDU。

## 八、地址、设备和完整通信过程

### 8.1 MAC、IP、端口号、域名分别解决什么问题？

| 标识     | 所属层次  | 主要作用         |
| ------ | ----- | ------------ |
| 域名     | 应用层使用 | 标识域名资源       |
| IP 地址  | 网络层   | 逻辑寻址、跨网络路由   |
| MAC 地址 | 数据链路层 | 当前链路上的帧交付    |
| 端口号    | 传输层   | 区分传输层端点和应用服务 |

可以这样理解：

- 域名：我要访问哪个网站？
- IP：我要把数据发送到哪个网络接口？
- MAC：这一跳的帧要交给谁？
- 端口：数据应交付给哪个应用服务？

#### 一个具体例子

主机 A 访问另一网络中的服务器 B。

```text
主机A ── R1 ── R2 ── 服务器B
```

忽略 NAT 等地址转换：

- IP 数据报中的源 IP、目的 IP 通常保持不变。
- 每经过路由器重新封装链路层帧，源 MAC、目的 MAC 通常会改变。
- TCP 源端口、目的端口通常保持不变。

路由器转发时还会修改 IP 层的部分信息，例如 IPv4 的 TTL。

### 8.2 集线器、交换机和路由器

2016 年真题直接考过这三个设备的最高工作层次。

| 设备           | 主要层次  | 转发依据 | 特点         |
| ------------ | ----- | ---- | ---------- |
| 中继器          | 物理层   | 信号   | 再生、整形信号    |
| 集线器 Hub      | 物理层   | 信号   | 多端口中继器     |
| 网桥           | 数据链路层 | MAC  | 过滤、转发帧     |
| 二层交换机 Switch | 数据链路层 | MAC  | 根据 MAC 表转发 |
| 路由器 Router   | 网络层   | IP   | 路由选择与分组转发  |

最重要的记忆：

$$
\boxed{ Router=3,\quad Switch=2,\quad Hub=1 }
$$

注意这里的 Switch 指普通二层交换机，现实中也存在三层交换机。

### 8.3 冲突域与广播域

#### 冲突域

经典共享介质以太网中，多个站点同时发送可能导致碰撞的范围。

#### 广播域

二层广播帧能够传播到的逻辑范围。

| 设备    | 隔离冲突域 | 隔离广播域        |
| ----- | ----- | ------------ |
| 集线器   | 否     | 否            |
| 网桥    | 是     | 默认否          |
| 二层交换机 | 是     | 同一 VLAN 内不隔离 |
| 路由器   | 是     | 是            |

#### 易错点

普通二层交换机可以隔离冲突域，但不会自动将每个端口划分成独立广播域。

配置 VLAN 后，不同 VLAN 可以分别形成广播域。

现代全双工交换式以太网实际上不再存在传统共享介质碰撞问题，但在考研教材的逻辑划分中，仍经常使用“交换机每个端口隔离冲突域”这样的说法。

### 8.4 第一章需要提前认识的典型协议

| 协议       | 典型层次      | 重要作用              |
| -------- | --------- | ----------------- |
| HTTP     | 应用层       | Web 数据交换          |
| DNS      | 应用层       | 域名解析              |
| FTP      | 应用层       | 文件传输              |
| SMTP     | 应用层       | 邮件发送              |
| TCP      | 传输层       | 可靠字节流             |
| UDP      | 传输层       | 无连接报文传输           |
| IP       | 网络层       | 网际寻址与转发           |
| ICMP     | 网络层       | 控制、差错报告与诊断        |
| ARP      | 网络层与链路层衔接 | IPv4 地址到 MAC 地址解析 |
| Ethernet | 数据链路层     | 以太网帧交换            |

常见默认端口也应初步掌握：

| 协议       | 端口     |
| -------- | ------ |
| HTTP     | 80     |
| HTTPS    | 443    |
| FTP 控制连接 | 21     |
| SMTP     | 25     |
| DNS      | 53     |
| DHCP 服务器 | UDP 67 |
| DHCP 客户端 | UDP 68 |

这些是典型端口，不代表所有实现都只采用一种传输协议。

例如 DNS 可以使用 UDP 或 TCP；现代 HTTP/3 通过 QUIC 使用 UDP，不能机械地认为 HTTPS 一定基于 TCP。

## 十、模拟题中的高阶计算：必须重点掌握

这一部分是从“会背概念”提升到“能够处理新题”的关键。

### 10.1 题型一：停止—等待协议的实际传输速率

### 模拟题：王道卷七 Q35

题目条件：

- 链路速率：2 Mb/s。
- 链路长度：1 km。
- 信号传播速度：20 m/ms。
- 数据帧大小：100 B。
- 确认帧大小忽略。
- 使用停止—等待协议。

求实际数据率。

#### 第一步：帧长度换算

$$
L=100\times8=800\ \mathrm{bit}
$$

#### 第二步：计算发送时延

$$
T_t=\frac{800}{2\times10^6}
$$

$$
T_t=0.4\ \mathrm{ms}
$$

#### 第三步：计算单向传播时延

$$
T_p=\frac{1000}{20}=50\ \mathrm{ms}
$$

注意题目给出的传播速度单位是 m/ms，需要保持单位一致。

#### 第四步：计算停止—等待周期

发送方发送一帧后，需要等待确认返回。

确认帧发送时延忽略，因此：

$$
T=T_t+2T_p
$$

$$
T=0.4+100=100.4\ \mathrm{ms}
$$

#### 第五步：实际数据率

$$
R_{\mathrm{actual}}=\frac{800}{0.1004}
$$

$$
R_{\mathrm{actual}}\approx7968\ \mathrm{bit/s}
$$

即：

$$
\boxed{R_{\mathrm{actual}}\approx8\ \mathrm{kb/s}}
$$

答案：C。

#### 深层理解

为什么明明有 2 Mb/s 的链路，实际只有约 8 kb/s？

因为发送一个 100 B 数据帧只需要 0.4 ms，但往返传播就需要 100 ms。

绝大部分时间都在等待。

#### 通用公式

确认帧发送时间忽略，处理与排队时延忽略：

$$
\boxed{ U=\frac{T_t}{T_t+RTT} }
$$

其中 RTT 在此简化模型中等于双向传播时延。

再乘链路速率可以得到实际数据率。

这是后面数据链路层滑动窗口计算的直接基础。

### 10.2 题型二：时延带宽积与信道容量综合

### 模拟题：王道卷一 Q34

已知：

- 信道长度 1 km。
- 信道带宽 160 MHz。
- 信号功率 0.6 W。
- 噪声功率 0.0193 W。
- 信号传播速度 200000 km/s。
- 连续发送 6000 bit 数据。

求链路上同时存在的最大比特数。

这道题结合了香农公式与时延带宽积。

#### 第一步：计算信噪比

$$
\frac SN=\frac{0.6}{0.0193}\approx31.09
$$

#### 第二步：计算信道容量

香农公式：

$$
C=W\log_2\left(1+\frac SN\right)
$$

代入：

$$
C=160\times10^6\log_2(32.09)
$$

近似：

$$
C\approx800\times10^6\ \mathrm{bit/s}
$$

#### 第三步：计算传播时延

$$
T_p=\frac{1}{200000}
$$

$$
T_p=5\times10^{-6}\ \mathrm{s}
$$

#### 第四步：计算时延带宽积

$$
BDP=C T_p
$$

$$
BDP=800\times10^6\times5\times10^{-6}
$$

$$
\boxed{BDP\approx4000\ \mathrm{bit}}
$$

因为要发送 6000 bit，数据量足以填满链路，所以最大在途比特数约为 4000 bit。

答案：D。

#### 本题的关键方法

此类题目要分清：

- 香农公式计算容量。
- 传播公式计算单向传播时间。
- 容量乘传播时间，得到最大在途比特数。

奈奎斯特公式和香农公式属于物理层的重点，建议在第二章继续专项练习。

### 10.3 题型三：最佳分组长度

### 模拟题：王道卷二 Q33

条件：

- 原始报文长度 0.2 MB。
- 分组首部长度 20 B。
- 经过两段等速链路。
- 采用存储转发。
- 忽略传播、处理、排队时延。
- 各分组的数据载荷长度相同。

求使总传输时间最小的数据载荷长度。

#### 第一步：设未知数

设每个分组的数据载荷长度为 $x$ B。

首部长度：

$$
h=20\ \mathrm{B}
$$

原始数据总长度：

$$
M=0.2\ \mathrm{MB}
$$

分组数为：

$$
N=\frac{M}{x}
$$

每个分组实际长度：

$$
P=x+h
$$

#### 第二步：建立时间函数

共有两段链路：

$$
k=2
$$

所以：

$$
T=(N+1)\frac{x+h}{R}
$$

代入：

$$
T=\left(\frac Mx+1\right)\frac{x+h}{R}
$$

展开：

$$
T=\frac{M+\frac{Mh}{x}+x+h}{R}
$$

其中 $M$、$h$、$R$ 都是常数。

所以只需要让：

$$
f(x)=\frac{Mh}{x}+x
$$

最小。

#### 第三步：求极小值

求导：

$$
f'(x)=-\frac{Mh}{x^2}+1
$$

令：

$$
f'(x)=0
$$

得：

$$
x^2=Mh
$$

因此：

$$
\boxed{x=\sqrt{Mh}}
$$

#### 第四步：代入数据

按照该题解析的单位约定：

$$
M=0.2\times1024\times1024\ \mathrm{B}
$$

所以：

$$
x=\sqrt{0.2\times1024\times1024\times20}
$$

$$
\boxed{x=2048\ \mathrm{B}}
$$

答案：B。

#### 为什么不是分组越小越好？

分组太小：

- 分组数量增多。
- 每个分组都需要附加首部。
- 总首部开销增加。

分组太大：

- 每个分组发送时间增长。
- 多跳网络中的流水线优势减弱。

因此存在最优值。

#### 推广到 $k$ 条等速链路

在相同理想条件下：

$$
T=\left(\frac Mx+k-1\right)\frac{x+h}{R}
$$

展开后与 $x$ 有关的项为：

$$
f(x)=\frac{Mh}{x}+(k-1)x
$$

令：

$$
f'(x)=0
$$

得到：

$$
\boxed{ x_{\mathrm{opt}}=\sqrt{\frac{Mh}{k-1}} }
$$

其中 $k\geq2$。

这只是连续变量下的理想最优解。

实际题目中还需要考虑：

- 分组数为整数。
- 分组长度约束。
- MTU 限制。
- 尾部分组可能不足一个完整分组。
- 是否包含其他控制开销。

这是一个非常值得掌握的综合解题模型。

### 10.4 题型四：多跳网络存在不同速率怎么办？

前面的流水线公式假设链路速率相同。

现在考虑：

```text
A ──10Mb/s── R1 ──5Mb/s── R2 ──20Mb/s── B
```

每个分组长度：

$$
L=10000\ \mathrm{bit}
$$

三条链路的发送时延分别为：

$$
t_1=\frac{10000}{10\times10^6}=1\ \mathrm{ms}
$$

$$
t_2=\frac{10000}{5\times10^6}=2\ \mathrm{ms}
$$

$$
t_3=\frac{10000}{20\times10^6}=0.5\ \mathrm{ms}
$$

第一个分组的总发送相关时延：

$$
T_1=1+2+0.5=3.5\ \mathrm{ms}
$$

如果发送很多个等长分组，采用理想流水传输，那么持续传输阶段的完成间隔由瓶颈链路决定：

$$
t_{\max}=2\ \mathrm{ms}
$$

设总共有 $N$ 个分组，在所有链路可流水工作且无其他额外等待时：

$$
\boxed{ T=\sum_{i=1}^{k}t_i+(N-1)\max_i t_i }
$$

这是等长分组、固定路径、各链路独立工作且不考虑传播等开销时的常用推广公式。

例如发送 4 个分组：

$$
T=3.5+(4-1)\times2
$$

$$
\boxed{T=9.5\ \mathrm{ms}}
$$

这种题不能直接套：

$$
(N+k-1)\frac LR
$$

因为各段链路没有统一的 $R$。

### 10.5 题型五：IP 分片与 TCP 排序

### 模拟题：王道卷一 Q38

题目考查：

IP 分组乱序到达后，谁负责重新排序？

IP 分片后，谁负责重组？

答案是：

- TCP 字节流的有序交付由传输层 TCP 完成。
- IPv4 分片的重组由目的主机的网络层完成。

因此：

排序由传输层完成，分片重组由网络层完成。

答案 D。

#### 为什么？

IP 是无连接数据报协议，不承诺按序交付。

TCP 如果接收到乱序报文段，可根据序号进行处理，向应用提供有序字节流。

另一方面，IPv4 分片属于 IP 数据报内部处理，所以由目的主机 IP 层完成重组。

需要注意：

这里讨论的是 IPv4 分片机制；IPv6 的分片规则有所不同。

## 十一、自编综合大题：多跳分组交换完整计算

虽然你的本章历年大题页尚未收录题目，但这个知识模块能够与后续章节结合形成综合计算题。

下面设计一道覆盖本章多个重点的强化题。

### 题目

主机 A 向主机 B 发送一个 12000 bit 的应用数据块。

A 与 B 之间有两个存储转发路由器：

```text
A ─── R1 ─── R2 ─── B
```

已知：

- 三条链路的数据发送速率均为 2 Mb/s。
- 每条链路的传播时延为 2 ms。
- 每个分组的数据载荷大小为 4000 bit。
- 每个分组增加 160 bit 首部。
- 忽略排队、处理及确认时延。

求：

1. 分组数量。
2. 每个分组的总长度。
3. 第一个分组完整到达 B 的时间。
4. 全部数据完整到达 B 的时间。
5. 有效数据传输效率。

### 第一问：分组数量

$$
N=\frac{12000}{4000}
$$

$$
\boxed{N=3}
$$

### 第二问：每个分组长度

数据载荷为：

$$
4000\ \mathrm{bit}
$$

首部为：

$$
160\ \mathrm{bit}
$$

所以：

$$
P=4000+160
$$

$$
\boxed{P=4160\ \mathrm{bit}}
$$

### 第三问：第一个分组到达时间

每条链路上的发送时延：

$$
T_t=\frac{4160}{2\times10^6}
$$

$$
T_t=2.08\ \mathrm{ms}
$$

每条链路传播时延：

$$
T_p=2\ \mathrm{ms}
$$

共三条链路。

第一个分组完整到达 B：

$$
T_1=3T_t+3T_p
$$

$$
T_1=3\times2.08+3\times2
$$

$$
\boxed{T_1=12.24\ \mathrm{ms}}
$$

### 第四问：全部数据到达时间

第一个分组经过三条链路。

后面两个分组形成流水线。

发送时间部分：

$$
T_{\mathrm{send}}=(N+k-1)T_t
$$

$$
T_{\mathrm{send}}=(3+3-1)\times2.08
$$

$$
T_{\mathrm{send}}=10.4\ \mathrm{ms}
$$

传播时延部分：

$$
T_{\mathrm{prop}}=3\times2=6\ \mathrm{ms}
$$

因此：

$$
T=10.4+6
$$

$$
\boxed{T=16.4\ \mathrm{ms}}
$$

### 第五问：有效数据传输效率

应用数据：

$$
D=12000\ \mathrm{bit}
$$

三个分组的总首部：

$$
H=3\times160=480\ \mathrm{bit}
$$

所以：

$$
\eta=\frac{12000}{12000+480}
$$

$$
\boxed{\eta\approx96.15\%}
$$

#### 这道题考查的能力

同一道题中，需要同时判断：

- 原始数据如何分组。
- 分组首部如何计入。
- 多跳链路如何存储转发。
- 多个分组如何形成流水线。
- 发送时延与传播时延如何分别累加。
- 应用有效数据与实际封装量的比例。

它比单纯记忆七层模型更能体现真正的计算能力。

## 十二、资料中值得注意的题目问题

阅读模拟题时，还发现两处值得特别提醒的地方。

### 12.1 王道卷七 Q33 存在多选项正确的问题

题目询问分层概念的正确描述，其中：

A. 分层机制使网络灵活且易于修改。

C. 把相关网络功能组合在一层中。

从概念上看，两者都正确。

你的站内解析也指出，这道题按照当前表述存在多个正确选项，不适合作为具有唯一答案的单选题。

学习时应该记住两个正确知识点，而不是强行记成一个单选答案。

### 12.2 王道卷四 Q35 的边界条件

题目涉及停止—等待协议，要求达到“50% 以上”的利用率。

资料按照“不低于 50%”进行计算，答案是 200 B。

此时：

$$
U=50\%
$$

如果题目的“50% 以上”被严格理解为“大于 50%”，200 B 就不符合严格不等式，需要更长的帧。

因此这类题一定要注意：

$$
U\geq50\%
$$

与：

$$
U>50\%
$$

是不同的数学条件。

这也说明做模拟题不能只核对最终选项，还要检查题目的边界条件。

| 1. 带宽就是吞吐量               | 带宽偏能力，吞吐量是实际表现           |

| 7. 电路交换必须逐跳存储整个报文        | 电路建立后可以连续传输              |

| 9. 虚电路就是物理专用电路           | 虚电路是逻辑连接                 |
| 10. 网络体系结构规定具体代码实现       | 只规定层次、功能、协议等抽象规范         |
| 11. 协议发生在相邻层之间           | 协议约束对等层实体                |
| 12. 服务发生在对等层之间           | 服务由下层向上层提供               |
| 13. 面向连接一定可靠             | 连接与可靠性是不同维度              |
| 14. TCP/IP 就是五层          | 经典 TCP/IP 参考模型是四层        |
| 15. 网络层是 OSI 第一个端到端传输服务层 | 经典考研答案是传输层               |
| 16. PDU 和 SDU 完全相同       | PDU 包含本层控制信息             |
| 17. IP 地址在路由时总会改变        | 无 NAT 等机制时源/目的 IP 通常保持不变 |
| 18. 普通交换机隔离每个端口的广播域      | 同 VLAN 内仍可传播广播           |
| 19. UDP 提供 TCP 式可靠重传     | UDP 本身不提供这种机制            |
| 20. 物理层负责解析 MAC 地址       | MAC 地址由链路层相关机制处理         |

## 十五、本章核心公式总结

建议把下面这张表作为考前复习的公式卡片。

| 公式                                                                   | 用途              |
| -------------------------------------------------------------------- | --------------- |
| $\displaystyle T_t=\frac LR$                                     | 发送时延            |
| $\displaystyle T_p=\frac dv$                                     | 传播时延            |
| $\displaystyle D=T_t+T_p+T_{\mathrm{proc}}+T_{\mathrm{queue}}$ | 单段链路时延分解        |
| $\displaystyle BDP=RT_p$                                         | 时延带宽积           |
| $\displaystyle U=\frac{T_t}{T_t+RTT}$                            | 简化停止—等待利用率      |
| $\displaystyle T=k\frac LR$                                      | 等速链路整报文存储转发     |
| $\displaystyle T=(N+k-1)\frac PR$                                | 等长分组、等速链路流水传输   |
| $\displaystyle T=\sum t_i+(N-1)\max t_i$                         | 等长分组、异速链路理想流水传输 |
| $\displaystyle T_c=c+\frac LR+kT_p$                              | 简化电路交换总时延       |
| $\displaystyle \eta=\frac{D}{D+H}$                               | 有效数据封装效率        |
| $\displaystyle x_{\mathrm{opt}}=\sqrt{\frac{Mh}{k-1}}$          | 理想最优分组载荷长度      |

需要特别强调：这些公式中的变量、假设和适用条件不同，不能只背公式而忽略使用前提。

对于复杂的时延题，最可靠的方法永远是先画出各链路的传输时间线。

它能够将第一章、数据链路层和传输层的多类计算题串起来。

## 十七、最终复习框架

本章全部知识可以压缩为六句话。

第一，网络通过链路和交换设备互连独立端系统，并通过协议完成通信。

第二，发送时延看数据长度与速率，传播时延看距离与传播速度。

第三，分组交换能够形成流水线，但必须考虑存储转发及首部开销。

第四，OSI 七层、TCP/IP 四层和五层教学模型必须明确区分。

第五，同层实体依靠协议通信，上下层通过接口使用服务。

第六，交换机主要看 MAC，路由器主要看 IP，传输层通过端口实现进程间通信。

从考研 408 的实际解题要求看，第一章学到位应该达到三个标准：

- 概念题：不依赖死记硬背，能根据功能、对象和作用范围确定层次。
- 计算题：能够独立推导发送时延、传播时延、多跳分组传输时间和封装效率。
- 综合题：面对主机、交换机、路由器组成的网络，能够解释数据逐层封装、逐跳转发及目的端解封装的全过程。

做到这些，第一章就不只是会做本章的选择题，而是为后面整门计算机网络课程的综合题建立了完整基础。
