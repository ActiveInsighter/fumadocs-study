<Callout type="warn" title="地址转换的三个‘未命中’不是一回事">

- **TLB 未命中**：快表没有页表映射的缓存，可能继续查页表，并不必然缺页。
- **Cache 未命中**：目标缓存块未命中，通常访问下一级存储结构，不等于页不在内存。
- **缺页异常**：页表检查发现所需页面不驻留等异常情况，通常由操作系统处理。

在经典的有效映射与一致性模型下，TLB 命中意味着映射有效，但它**不保证 Cache 一定命中**。计算访存时间之前必须先画出题设允许的路径。

</Callout>

</Tab>
<Tab value="多体交叉">

低位交叉的存储体号一般为 $A\bmod m$（这里 $A$ 为字地址、$m$ 为存储体数）。单体存储周期为 $T$、连续发起请求的时间间隔为 $\tau$ 时，实现无冲突顺序访问至少需 $m\tau\ge T$；初次延迟与稳态吞吐率不要混同。

</Tab>

## 408 计算机组成原理第 3 章：存储系统——知识点、考点与真题精讲

本章是计算机组成原理中最重要的章节之一，也是 408 综合计算题的重点。

原始资料中的知识讲义采用第 3 章《存储系统》，真题库采用第 3 章《存储器层次结构》；二者涵盖的主要考点相互对应。

原稿所引优化版讲义将本章分为四个部分：

1. 存储层次与主存组织：SRAM、DRAM、存储芯片扩展、多体交叉存储器。
2. Cache 高速缓存：地址映射、组相联、命中率、替换算法、写策略。
3. 虚拟存储器、页表与 TLB：虚拟地址转换、多级页表、快表、缺页异常、联合访存。
4. 外存、RAID 与 SSD：磁盘性能、磁盘结构、RAID、Flash 与 SSD。

本章重点不只是记忆概念，而是弄清楚每种结构为什么存在、地址如何变化、数据如何流动，以及如何把这些原理用于解决真题。

### 一、本章总框架：先建立存储系统的整体理解

#### 1. 为什么需要存储层次？

计算机存在一个难以同时满足的三角关系：

- 速度快：希望 CPU 能迅速读取数据。
- 容量大：希望保存大量程序和数据。
- 成本低：希望单位容量价格便宜。

一般来说，速度越快的存储器，单位容量成本越高。因此计算机不采用单一存储器，而采用层次化结构。

```text
                  CPU
                   │
              寄存器组
                   │
              L1 Cache
                   │
              L2 Cache
                   │
              L3 Cache
                   │
               主存 DRAM
                   │
              SSD / HDD
                   │
             其他辅助存储
```

从上到下，通常表现为：

| 指标         | 上层     | 下层         |
| ---------- | ------ | ---------- |
| 访问速度       | 快      | 慢          |
| 单位容量成本     | 高      | 低          |
| 容量         | 小      | 大          |
| CPU 直接访问能力 | 强      | 通常需要通过其他机制 |
| 主要作用       | 提高访问速度 | 扩大存储容量     |

这里最重要的是两组关系。

第一组：Cache—主存

解决 CPU 与主存之间的速度差距。CPU 不必每次都访问相对较慢的 DRAM。

第二组：主存—辅存

通过虚拟存储器，使程序可以使用比实际物理内存更大的虚拟地址空间，并按需将页面调入主存。

注意，虚拟地址空间大小与实际可用存储容量不是完全相同的概念。

#### 2. 理解本章的三个核心机制

| 机制    | 本质          | 基本工作单位 | 未命中时       |
| ----- | ----------- | ------ | ---------- |
| Cache | 缓存实际数据      | 主存块    | 到下一层取数据块   |
| TLB   | 缓存地址转换结果    | 页表翻译项  | 查询页表       |
| 虚拟存储器 | 管理虚拟页面与物理页框 | 页面     | 缺页时由操作系统调页 |

需要特别理解：

Cache 保存的是数据，TLB 保存的是地址映射，页表记录的是虚拟页与物理页框之间的映射和状态。

三者不是同一种东西。

#### 3. 一次访存究竟如何完成？

在 408 常见的物理地址 Cache 模型中：

```text
CPU 发出虚拟地址 VA
        │
        ▼
提取虚拟页号 VPN 和页内偏移
        │
        ▼
查询 TLB
        │
        ├── 命中 ────────────┐
        │                    │
        └── 未命中           │
              │              │
              ▼              │
           查询页表          │
              │              │
              ├─ 页面不在内存
              │      │
              │      ▼
              │   缺页异常
              │   调入页面
              │
              └─ 页面在内存
                     │
                     ▼
               得到物理页框号
                     │
                     ▼
              生成物理地址 PA
                     │
                     ▼
                 查询 Cache
                     │
              ┌──────┴──────┐
              │             │
            命中          未命中
              │             │
              │          访问主存
              │             │
              └──────┬──────┘
                     ▼
                  获得数据
```

这张流程图贯穿本章大量综合题。

以后看到涉及 TLB、页表、Cache 的题目，必须先确定当前操作属于哪一个层次，不能把三种未命中混为一谈。

### 二、主存储器：从存储单元到存储芯片扩展

这一部分的核心问题是：

数据怎样存储？地址怎样定位数据？多个芯片怎样组合成更大的存储器？

#### 2.1 主存的基本组成

主存储器可以抽象为：

```text
                  CPU
                   │
               地址信息
                   │
                   ▼
            MAR（地址寄存器）
                   │
                   ▼
               地址译码器
                   │
          ┌────────┼────────┐
          ▼        ▼        ▼
        单元0    单元1    单元...
          │        │        │
          └────────┼────────┘
                   │
                   ▼
            MDR（数据寄存器）
                   │
                   ▼
                  CPU
```

其中有两个很重要的寄存器：

| 寄存器 | 含义                      | 主要决定        |
| --- | ----------------------- | ----------- |
| MAR | Memory Address Register | 可以表示多少个存储地址 |
| MDR | Memory Data Register    | 一次能够传送多少位数据 |

##### 考点 1：地址线与容量

假设按字节编址，地址宽度为 $n$ 位：

$$
\boxed{C=2^n\text{ B}}
$$

例如，主存地址空间为 $64\text{ MB}$：

$$
64\text{ MB}=2^{26}\text{ B}
$$

所以需要：

$$
\boxed{26\text{ 位地址}}
$$

如果按 4 字节一个字进行字编址，则同样容量所需的字地址位数变成：

$$
\log_2\frac{2^{26}}4=24
$$

必须先判断按字节编址还是按字编址。

##### 2011 年 408 真题：MAR 位数

题目给出：

- 主存地址空间：64 MB；
- 实际安装主存：32 MB；
- RAM 芯片：$4M\times8$ bit；
- 按字节编址。

问 MAR 至少多少位？

正确答案：

$$
\boxed{26\text{ 位}}
$$

因为 MAR 的位数由可寻址地址空间决定，而不是由已经安装多少 RAM 芯片决定。

这类题故意同时给出“地址空间”和“实际容量”，目的就是考查概念区别。

#### 2.2 存取时间、存取周期、带宽

这三个量经常一起考。

存取时间 $T_a$：从发起一次访问到完成数据访问所需的时间。

存取周期 $T_c$：连续发起两次独立访问之间允许的最短时间间隔。

一般：

$$
T_c\ge T_a
$$

因为一次访问完成后，存储器可能还需要恢复、再生等操作。

存储器带宽：单位时间传送的数据量。

理想情况下，如果一次传输 $W$ 字节，连续传输启动间隔为 $\tau$，则：

$$
\boxed{BW=\frac{W}{\tau}}
$$

注意，带宽衡量的是吞吐能力，而存取时间衡量的是单次访问延迟。

一个存储系统可以具有很高的带宽，但单次访问延迟仍然较大。

#### 2.3 SRAM 与 DRAM：为什么 Cache 和主存采用不同器件？

这是基础概念题的重点。

##### SRAM：静态随机存储器

SRAM 通常用双稳态电路保存一个二进制位，经典结构采用 6 个晶体管。

其特点是：

- 只要持续供电，就能保持存储状态；
- 不需要周期性刷新；
- 读取通常不破坏原信息；
- 速度快；
- 集成度相对较低，成本高。

因此 SRAM 通常适合 Cache。

注意：

$$
\boxed{\text{SRAM 静态}\ne\text{断电不丢失}}
$$

SRAM 仍然属于易失性存储器。

##### DRAM：动态随机存储器

DRAM 典型存储单元为 1T1C，即一个晶体管和一个电容。

其本质是：

```text
电容存有一定电荷 → 表示某个逻辑状态

电容没有足够电荷 → 表示另一个逻辑状态
```

由于电容会漏电，电荷状态无法无限期保持。

因此 DRAM 需要定期刷新。

此外，典型 DRAM 读出会影响存储电荷，因此读取后还需要恢复数据。

| 比较项目   | SRAM  | DRAM     |
| ------ | ----- | -------- |
| 存储原理   | 双稳态电路 | 电容电荷     |
| 经典单元   | 6T    | 1T1C     |
| 刷新     | 不需要   | 需要       |
| 典型读取   | 非破坏性  | 破坏性，需要恢复 |
| 速度     | 较快    | 较慢       |
| 集成度    | 较低    | 较高       |
| 单位容量价格 | 高     | 低        |
| 断电数据   | 丢失    | 丢失       |
| 主要用途   | Cache | 主存       |

##### 真题：2015 年

下列存储器中，工作期间需要周期性刷新的有：

A. SRAM\
B. SDRAM\
C. ROM\
D. Flash

答案：B

SDRAM 全称为同步动态随机存储器。

其中：

- S = Synchronous，同步；
- D = Dynamic，动态。

SDRAM 仍然属于 DRAM，因此仍需要刷新。

<Callout type="info" title="DRAM 地址位数：区分地址数量与物理引脚">

若芯片有 $2^a$ 个可独立编址的字单元，地址总信息量为 $a$ 位；行列地址复用后，在**行列位数均衡、无额外地址编码约束的简化模型**中，地址引脚约需 $\lceil a/2\rceil$ 个。数据引脚还应按单元字宽另外计算。真实 DRAM 芯片还需考虑 Bank、片选、控制信号等，不能直接把这一简化公式推广到全部封装引脚。

</Callout>

#### 2.4 DRAM 行列地址复用：经典计算题

这是存储芯片知识中非常容易考计算的一节。

假设一个 DRAM 芯片规格为：

$$
4M\times8\text{ bit}
$$

先理解其含义。

$$
4M=2^{22}
$$

表示该芯片有 $2^{22}$ 个可寻址位置，每个位置保存 8 位。

因此，完整地址信息需要：

$$
\log_2 2^{22}=22\text{ bit}
$$

如果采用普通地址接口，就需要传输 22 位地址。

但 DRAM 常采用行列地址复用。

把二维阵列组织成：

$$
2^{11}\times2^{11}
$$

即：

$$
2048\times2048
$$

可以把地址拆成：

```text
完整地址：22 bit

┌──────────────┬──────────────┐
│  行地址 11位  │  列地址 11位  │
└──────────────┴──────────────┘

第一次传输：11位行地址
第二次传输：11位列地址

复用同一组地址引脚
```

于是只需要 11 根地址引脚。

为什么不是 22 根？

因为同一组引脚被分时使用。

但是完整的地址信息仍然是 22 位。

##### 2014 年 408 真题

一个存储器由若干 $4M\times8$ bit 的 DRAM 芯片构成。

问单片 DRAM 的地址引脚和数据引脚总数。

地址引脚：

$$
\frac{22}{2}=11
$$

数据引脚：

$$
8
$$

所以：

$$
\boxed{11+8=19}
$$

答案为 19 根。

##### 进阶：为什么 DRAM 阵列通常接近正方形？

假设总存储位置数为：

$$
2^{11}=2048
$$

要求行列地址复用后的引脚数最少，同时尽量降低刷新开销。

考虑两种组织：

$$
64\times32
$$

与：

$$
32\times64
$$

第一种需要：

$$
\max(6,5)=6
$$

根地址引脚。

第二种也需要 6 根。

但 DRAM 按行刷新：

- 第一种需要刷新 64 行；
- 第二种只需要刷新 32 行。

因此在这两个候选组织中：

$$
\boxed{32\times64}
$$

更合适。

这就是 2018 年 408 DRAM 阵列题的核心。

总结：

在教材采用的二维阵列与行刷新模型中，通常希望行列规模尽量接近，并在地址引脚数量相同的条件下减少行数。

#### 2.5 DRAM 刷新机制

DRAM 的刷新不是 CPU 将所有数据逐字节读取一遍。

一般按行刷新。

如果一共有 $R$ 行，要求在 $T$ 时间内完成所有行的刷新，那么采用均匀安排的异步刷新时，相邻两次刷新操作的间隔为：

$$
\boxed{\Delta t=\frac{T}{R}}
$$

##### 例题

DRAM 有 8192 行，刷新周期为 64 ms。

问异步刷新时，相邻两次单行刷新的平均间隔。

$$
\Delta t=\frac{64\text{ ms}}{8192}
$$

得到：

$$
\boxed{\Delta t=7.8125\ \mu s}
$$

这不代表每次刷新操作持续 $7.8125\ \mu s$，而是相邻两次刷新操作的安排间隔。

##### 三种刷新方式

| 刷新方式 | 工作原理            | 特点       |
| ---- | --------------- | -------- |
| 集中刷新 | 连续刷新所有行         | 存在明显刷新死区 |
| 分散刷新 | 将刷新安排到各存取周期中    | 刷新占用较多周期 |
| 异步刷新 | 将刷新操作均匀分布在刷新周期内 | 综合效果较好   |

##### 刷新计算的另一个陷阱

假设有 $2048\times2048$ 的存储阵列。

总存储位置数：

$$
2048^2
$$

但在按行刷新的模型下，刷新一轮需要执行的单行刷新操作数是：

$$
\boxed{2048}
$$

而不是：

$$
2048^2
$$

因为每次刷新的是整行。

#### 2.6 DRAM 行缓冲、突发传输与 DDR

为什么连续读取内存通常比随机访问更高效？

这是因为现代 DRAM 存在行缓冲和突发传输机制。

当存储器选中某一行时，内部会将该行的数据读入感应放大器和行缓冲结构。

后续访问同一已打开行中的不同列，可以避免重复开行的部分开销。

常见时序涉及：

- 行激活；
- 列读取或写入；
- 预充电；
- 刷新。

因此，内存访问延迟不仅与频率有关，还与行是否已经打开、Bank 状态、访问模式等因素有关。

##### DDR 为什么能提高带宽？

DDR 的全称是 Double Data Rate。

核心思想是在时钟上升沿和下降沿都传输数据。

因此理想情况下：

$$
\text{数据传输率}=2f_{\text{总线时钟}}
$$

##### 模拟题：DDR3 带宽

已知：

- DRAM 内部核心频率为 133.25 MHz；
- 采用 8n 预取；
- 数据传输率是核心频率的 8 倍；
- 总线每次传输 8 B。

则数据传输率：

$$
133.25\times8=1066\text{ MT/s}
$$

DDR 总线时钟频率：

$$
\frac{1066}{2}=533\text{ MHz}
$$

峰值带宽：

$$
1066\times10^6\times8 =8.528\times10^9\text{ B/s}
$$

因此：

$$
\boxed{BW\approx8.53\text{ GB/s}}
$$

注意区别：

- 533 MHz：总线时钟频率；
- 1066 MT/s：数据传输率。

不能把两者混为一谈。

#### 2.7 主存芯片扩展：位扩展、字扩展、字位扩展

这是本章必须独立完成的计算题。

先明确一个存储芯片的规格：

$$
M\times W
$$

其中：

- $M$：可寻址存储字数量；
- $W$：每个存储字的位数。

假设目标存储器为：

$$
M_t\times W_t
$$

单个芯片为：

$$
M_c\times W_c
$$

在整倍数扩展条件下，芯片数量为：

$$
\boxed{ N= \frac{M_t}{M_c} \times \frac{W_t}{W_c} }
$$

前一个比值是字扩展倍数，后一个比值是位扩展倍数。

##### 情况一：位扩展

例如用：

$$
8K\times1
$$

构成：

$$
8K\times8
$$

字数不变，位宽增加 8 倍。

所以需要 8 片，并行工作。

```text
                 地址线
                   │
     ┌──────┬──────┼──────┬──────┐
     ▼      ▼      ▼      ▼
   芯片0  芯片1   ...   芯片7
     │      │             │
     ▼      ▼             ▼
     D0     D1            D7
```

同一个地址选中所有芯片，各芯片分别输出一个数据位。

##### 情况二：字扩展

例如：

$$
16K\times8
$$

构成：

$$
64K\times8
$$

需要：

$$
\frac{64K}{16K}=4
$$

片。

每片内部：

$$
16K=2^{14}
$$

需要 14 位片内地址。

目标存储器：

$$
64K=2^{16}
$$

需要 16 位地址。

所以：

```text
A15 A14 │ A13 A12 ... A0
────────┼──────────────
 片选   │  片内字地址
```

地址空间划分为：

| 片选 | 地址范围        |
| -- | ----------- |
| 00 | 0000H～3FFFH |
| 01 | 4000H～7FFFH |
| 10 | 8000H～BFFFH |
| 11 | C000H～FFFFH |

##### 情况三：字位扩展

目标：

$$
64K\times16
$$

芯片：

$$
16K\times8
$$

位扩展：

$$
\frac{16}{8}=2
$$

字扩展：

$$
\frac{64K}{16K}=4
$$

总芯片：

$$
\boxed{N=2\times4=8}
$$

结构为：

```text
第0组：2片并联 → 16K×16
第1组：2片并联 → 16K×16
第2组：2片并联 → 16K×16
第3组：2片并联 → 16K×16

总计：64K×16
```

##### 2009 年 408 真题：ROM 与 RAM 芯片数

主存总容量 64 KB。

其中：

- ROM 区：4 KB；
- RAM 区：60 KB；
- ROM 芯片：$2K\times8$ bit；
- RAM 芯片：$4K\times4$ bit。

ROM 芯片数：

$$
\frac{4K}{2K}=2
$$

RAM 首先要把位宽从 4 bit 扩展到 8 bit：

$$
\frac84=2
$$

每组两片提供 4 KB。

需要的组数：

$$
\frac{60K}{4K}=15
$$

因此 RAM 芯片数量：

$$
15\times2=30
$$

最终：

$$
\boxed{\text{ROM：2片，RAM：30片}}
$$

##### 2010 年 408 真题：芯片地址范围

用若干：

$$
2K\times4
$$

芯片构成：

$$
8K\times8
$$

问地址 `0B1FH` 所在芯片组的起始地址。

先做位扩展：

$$
8/4=2
$$

即每组 2 片。

字扩展：

$$
8K/2K=4
$$

每组对应的地址长度：

$$
2K=2048=0800H
$$

所以各组范围是：

| 组号 | 起始地址  | 结束地址  |
| -- | ----- | ----- |
| 0  | 0000H | 07FFH |
| 1  | 0800H | 0FFFH |
| 2  | 1000H | 17FFH |
| 3  | 1800H | 1FFFH |

地址 `0B1FH` 位于第 1 组。

因此答案：

$$
\boxed{0800H}
$$

芯片地址题的万能顺序：先确定编址单位，再算单组覆盖多少地址，最后确定地址区间。

常见 $T+(n-1)\tau$ 模型假定：第一次读取延迟为 $T$，此后能够每隔 $\tau$ 启动并完成下一个顺序访问，且无存储体冲突。若 $m\tau<T$，就不能无条件使用该公式；应排队计算体冲突，并考虑总线约束。

#### 2.8 多体交叉存储器：提高的是吞吐率

为什么需要多体交叉存储？

假设一个存储体完成一次访问需要 80 ns。

如果每次都等它完成，再访问下一个地址，连续访问效率很低。

于是将主存划分为多个可以相对独立工作的存储体。

##### 高位交叉编址

例如 4 个存储体：

```text
体0：地址  0～255
体1：地址256～511
体2：地址512～767
体3：地址768～1023
```

连续访问地址 0、1、2、3，全部落在同一个体中。

因此难以充分发挥多体并行能力。

##### 低位交叉编址

把连续地址分配到不同存储体：

```text
地址：  0   1   2   3   4   5   6   7
体号：  0   1   2   3   0   1   2   3
```

核心公式：

$$
\boxed{\text{体号}=A\bmod m}
$$

其中：

- $A$：存储字地址；
- $m$：存储体数量。

体内地址：

$$
\boxed{ \text{体内地址}= \left\lfloor\frac{A}{m}\right\rfloor }
$$

这些公式默认 $A$ 表示交叉编址使用的存储字序号；如果题目给的是字节地址，必须先按存储字大小进行换算。

##### 流水式访问

假设有 4 个存储体：

- 单体存储周期 $T=80\text{ ns}$；
- 相邻请求启动间隔 $\tau=20\text{ ns}$。

访问时刻：

```text
时间(ns)   0    20    40    60    80
           │     │     │     │     │
体0       启动 ───────────────── 完成
体1             启动 ─────────────────
体2                   启动 ───────────
体3                         启动 ─────
体0                               可再次启动
```

虽然每个体依然需要 80 ns，但不同体的访问可以重叠。

所以稳态时每隔 20 ns 就能启动一次访问。

关键关系：

$$
\boxed{m\tau\ge T}
$$

如果要让连续请求无冲突，所需存储体数至少为：

$$
\boxed{ m\ge\left\lceil\frac T\tau\right\rceil }
$$

##### 连续读取 $n$ 个字的时间

在首字延迟为 $T$，后续每隔 $\tau$ 输出一个字的理想模型下：

$$
\boxed{ T_{\text{total}}=T+(n-1)\tau }
$$

例如 4 体低位交叉：

$$
T=80\text{ ns},\quad\tau=20\text{ ns}
$$

连续读取 8 个字：

$$
T_{\text{total}} =80+7\times20
$$

得到：

$$
\boxed{220\text{ ns}}
$$

而没有交叉并行时，如果每个字都要等待完整存储周期：

$$
8\times80=640\text{ ns}
$$

所以多体交叉的核心收益是提升连续访问吞吐率。

##### 模拟题：八体低位交叉带宽

某存储器：

- 8 个存储体；
- 每个体周期 80 ns；
- 每次输出 64 bit；
- 理想轮流启动。

相邻启动间隔：

$$
\tau=\frac{80}{8}=10\text{ ns}
$$

每次数据：

$$
64\text{ bit}=8\text{ B}
$$

因此：

$$
BW=\frac{8\text{ B}}{10\text{ ns}}
$$

得到：

$$
\boxed{800\text{ MB/s}}
$$

这个结果与原稿引用的模拟题库一致。

##### 体冲突：不能只看体号

假设两次请求都访问体 1。

是否一定冲突？

不一定。

还要判断第二次访问到达时，第一次访问是否已经完成。

例如存储周期为 80 ns：

- 第一次在 20 ns 启动；
- 第二次在 120 ns 启动。

两次启动间隔：

$$
120-20=100\text{ ns}
$$

已经超过 80 ns，所以不会冲突。

如果第二次在 60 ns 启动：

$$
60-20=40<80
$$

此时就会冲突。

做体冲突题一定画出：

| 请求 | 地址 | 体号 | 最早允许启动时刻 | 实际启动时刻 |
| -- | -- | -- | -------- | ------ |

每访问一次，都更新对应存储体的下一次可用时刻。

### 三、Cache 高速缓存：本章第一大核心

Cache 是第 3 章最重要的内容之一。

408 主要考查五件事：

1. Cache 为什么有效；
2. 主存块如何映射到 Cache；
3. Cache 地址如何划分；
4. 替换算法和写策略如何执行；
5. 数组访问会发生多少次 Cache Miss。

其中最重要的是 组相联映射、地址拆分与数组命中率计算。

#### 3.1 为什么 Cache 必须以块为单位？

假设 CPU 需要读取主存地址 1000 中的一个字节。

如果 Cache 块大小是 64 B，那么该地址所在主存块的起始地址为：

$$
\left\lfloor\frac{1000}{64}\right\rfloor\times64 =960
$$

所以整个主存块范围是：

```text
960 ────────────────────────── 1023
 │                               │
 └────────────64 Bytes───────────┘
                          ▲
                        地址1000
```

CPU 只需要一个字节，为什么却搬来 64 B？

因为程序通常具有空间局部性。

访问完地址 1000 后，接下来可能访问 1001、1002 等相邻地址。

提前将它们装入 Cache，就可以减少后续对主存的访问。

##### 两种局部性

时间局部性：同一位置可能短时间内反复访问。

例如：

```c
for (int i = 0; i < 1000; i++) {
    sum += a[0];
}
```

数组元素 `a[0]` 被重复访问。

空间局部性：访问一个位置后，可能访问相邻位置。

```c
for (int i = 0; i < 1000; i++) {
    sum += a[i];
}
```

数组按照地址顺序访问，具有空间局部性。

注意：时间局部性并不等于空间局部性。顺序扫描一个数组且每个元素只访问一次，仍然可以具有良好的空间局部性。

#### 3.2 主存块号、块内偏移、Cache 行号

这是 Cache 所有计算的基础。

假设：

- 主存按字节编址；
- 块大小为 $B$ 字节；
- CPU 访问的物理地址为 $A$。

那么：

$$
\boxed{ \text{主存块号}= \left\lfloor\frac AB\right\rfloor }
$$

$$
\boxed{ \text{块内偏移}=A\bmod B }
$$

例如：

$$
A=1000,\qquad B=64
$$

则：

$$
\text{主存块号} =\left\lfloor\frac{1000}{64}\right\rfloor =15
$$

块内偏移：

$$
1000\bmod64=40
$$

因此地址 1000 是：

主存第 15 块中的第 40 个字节（从 0 编号）。

先把这个关系搞清楚，后面的直接映射与组相联就是在此基础上继续计算。

#### 3.3 三种 Cache 映射方式

##### 方式一：直接映射

一个主存块只能放到唯一的 Cache 行。

假设 Cache 有 $C$ 行，主存块号为 $j$。

映射规则：

$$
\boxed{i=j\bmod C}
$$

例如 Cache 有 8 行。

| 主存块号 | Cache 行号 |
| ---- | -------- |
| 0    | 0        |
| 1    | 1        |
| 7    | 7        |
| 8    | 0        |
| 9    | 1        |
| 15   | 7        |
| 16   | 0        |

主存块 0、8、16 都映射到 Cache 第 0 行。

假设访问序列是：

$$
0,8,0,8,0,8
$$

Cache 初始为空。

第一次访问块 0：

- Miss；
- 将块 0 放入第 0 行。

访问块 8：

- 仍然只能进入第 0 行；
- 将块 0 替换出去。

再次访问块 0：

- 块 0 已经被替换；
- 再次 Miss。

最终六次访问全部 Miss。

$$
\boxed{H=0}
$$

即使 Cache 其他 7 行都是空的，也无法避免这种冲突。

所以直接映射的缺点是冲突失效较严重。

但优点也明显：硬件结构简单，定位速度快。

##### 方式二：全相联映射

一个主存块可以放入任意 Cache 行。

例如 Cache 有 8 行：

```text
主存块100
     │
     ▼
Cache 任意有效位置或空行

行0  行1  行2  行3  行4  行5  行6  行7
```

查找时需要比较相关标记，确定对应数据是否存在。

全相联的优点是基本消除了映射约束导致的冲突失效。

缺点是需要更复杂的相联比较硬件。

##### 方式三：组相联映射

这是 408 最常考的形式。

把 Cache 分为若干组，每组有若干行。

例如 8 行、2 路组相联：

```text
Cache

组0
 ├── Way0
 └── Way1

组1
 ├── Way0
 └── Way1

组2
 ├── Way0
 └── Way1

组3
 ├── Way0
 └── Way1
```

共有：

$$
8/2=4
$$

组。

一个主存块只能进入指定组，但可以放在该组中的任意一路。

映射公式：

$$
\boxed{ \text{组号}=\text{主存块号}\bmod\text{组数} }
$$

例如主存块 10：

$$
10\bmod4=2
$$

只能进入 Cache 第 2 组。

但是它既可以进入该组 Way0，也可以进入 Way1。

组号由地址决定，组内具体使用哪一路由当前状态和替换策略决定。

##### 三种映射的本质区别

| 对比        | 直接映射 | 组相联      | 全相联  |
| --------- | ---- | -------- | ---- |
| 可放置位置     | 唯一行  | 指定组内任意一路 | 任意行  |
| 比较范围      | 1 行  | 组内各路     | 全部行  |
| 冲突失效      | 较多   | 较少       | 最少   |
| 硬件复杂度     | 低    | 中        | 高    |
| 是否需要选择牺牲行 | 不需要  | 组满时需要    | 满时需要 |

#### 3.4 Cache 地址划分：整章最重要的计算公式

先明确：

一个物理地址需要告诉 Cache 三件事：

- 要找哪个主存块；
- 这个主存块应该在哪一组；
- 要读取块内哪个字节。

因此对于常见的组相联 Cache：

```text
物理地址
┌────────────────┬─────────────┬─────────────┐
│      Tag       │ Set Index   │ BlockOffset │
└────────────────┴─────────────┴─────────────┘
      高位             中间            低位
```

假设：

- 物理地址为 $p$ 位；
- Cache 数据容量为 $C$ 字节；
- 块大小为 $B$ 字节；
- 相联度为 $n$ 路。

第一步，求 Cache 总行数：

$$
\boxed{L=\frac CB}
$$

第二步，求组数：

$$
\boxed{S=\frac Ln}
$$

第三步，求块内偏移位数：

$$
\boxed{b=\log_2B}
$$

第四步，求组索引位数：

$$
\boxed{s=\log_2S}
$$

第五步，求标记位数：

$$
\boxed{t=p-s-b}
$$

以上为块大小和组数均为 2 的整数次幂的常见教材模型。

##### 完整计算示例

某计算机：

- 物理地址：32 bit；
- Cache 数据区：32 KB；
- 块大小：64 B；
- 8 路组相联。

求 Tag、组号、块内偏移的位数。

第一步：块内偏移

$$
64=2^6
$$

所以：

$$
b=6
$$

第二步：总行数

$$
L=\frac{32\times1024}{64}=512
$$

第三步：组数

$$
S=\frac{512}{8}=64
$$

第四步：组号位数

$$
s=\log_264=6
$$

第五步：Tag

$$
t=32-6-6=20
$$

最终：

```text
32位物理地址

31                     12 11       6 5       0
┌────────────────────────┬──────────┬─────────┐
│       Tag 20位         │ 组号6位  │ 偏移6位 │
└────────────────────────┴──────────┴─────────┘
```

即：

$$
\boxed{20+6+6=32}
$$

这类 Tag、Set、Offset 位数划分也是相关 Cache 综合题的基础。

#### 3.5 Cache 实际总容量：数据位不等于全部存储位

这是另一种高频计算。

一个 Cache 行不仅需要存放数据，还需要保存管理信息。

典型 Cache 行：

```text
┌───────┬─────────────┬──────────┬──────────┐
│ Valid │     Tag     │  Dirty   │   Data   │
└───────┴─────────────┴──────────┴──────────┘
```

有些实现还需要替换状态位。

因此：

$$
\boxed{ \text{总容量} = \text{数据位} +\text{标记位} +\text{有效位} +\text{其他控制位} }
$$

注意 LRU 等替换状态可能按组保存，不能一律当作每行一个固定数量。

##### 2010 年 408 第 44 题：Cache 总容量

题目给出：

- 主存地址空间 256 MB；
- 按字节编址；
- Cache 共 8 行；
- 每行数据 64 B；
- 直接映射；
- 计算数据位、Tag 和有效位，不计其他控制位。

主存地址位数：

$$
256\text{ MB}=2^{28}\text{ B}
$$

所以：

$$
p=28
$$

Cache 块大小 64 B：

$$
b=6
$$

Cache 行数 8：

$$
s=3
$$

Tag：

$$
t=28-6-3=19
$$

每行数据位：

$$
64\times8=512
$$

每行总位数：

$$
512+19+1=532\text{ bit}
$$

8 行总位数：

$$
8\times532=4256\text{ bit}
$$

换成字节：

$$
\frac{4256}{8}=532\text{ B}
$$

所以：

$$
\boxed{\text{Cache 总容量}=532\text{ B}}
$$

但 Cache 的数据区容量只有：

$$
8\times64=512\text{ B}
$$

请注意区分这两个结果。

#### 3.6 Cache 替换算法：LRU 与 FIFO

当指定组内所有行都被占用，而新块需要进入时，就必须选择牺牲块。

最常考的是 LRU。

##### LRU：最近最少使用

LRU 根据最近访问情况进行替换。

淘汰的是距离当前时刻最久没有被访问的块。

假设某组有 2 路，初始为空。

访问序列：

$$
A,B,A,C,B,A
$$

逐次模拟：

| 访问 | 组内内容 | Hit/Miss | 原因        |
| -- | ---- | -------- | --------- |
| A  | A    | Miss     | 第一次访问     |
| B  | A、B  | Miss     | 使用空行      |
| A  | A、B  | Hit      | A 最近被访问   |
| C  | A、C  | Miss     | 淘汰较久未用的 B |
| B  | C、B  | Miss     | 淘汰 A      |
| A  | B、A  | Miss     | 淘汰 C      |

总共：

$$
6\text{ 次访问}
$$

其中：

$$
1\text{ 次 Hit}
$$

所以：

$$
\boxed{H=\frac16}
$$

##### FIFO：先进先出

FIFO 只考虑数据进入 Cache 的先后顺序。

例如：

$$
A,B,A,C
$$

2 路组中，FIFO 会淘汰 A，因为 A 最早进入。

虽然 A 刚被访问过，但 FIFO 不考虑这个事实。

而 LRU 会淘汰 B。

这就是两种算法最关键的区别。

##### 三类 Cache Miss

| 类型   | 产生原因         | 主要改善方法     |
| ---- | ------------ | ---------- |
| 强制失效 | 第一次访问某块      | 预取、利用空间局部性 |
| 容量失效 | Cache 装不下工作集 | 增大有效容量     |
| 冲突失效 | 不同块竞争同一组     | 提高相联度、调整布局 |

提高相联度主要缓解冲突失效，但不保证所有访问序列的命中率一定提高。

#### 3.7 Cache 写策略：必须区分两个维度

写策略可以分成两组问题。

第一个问题：写命中后怎样处理？

| 策略               | 操作                 | 特点            |
| ---------------- | ------------------ | ------------- |
| Write Through 直写 | 同时更新 Cache 和下一级存储器 | 一致性较易维护，写流量较大 |
| Write Back 回写    | 先更新 Cache，修改脏位     | 减少下一级写次数      |

回写法最重要的是 Dirty 位。

```text
Write Back：

CPU 写入
   │
   ▼
更新 Cache 数据
   │
   ▼
Dirty = 1
   │
   ▼
以后被替换
   │
   ▼
若 Dirty = 1，则写回主存
```

第二个问题：写未命中怎样处理？

| 策略                     | 操作              |
| ---------------------- | --------------- |
| Write Allocate 写分配     | 将主存块调入 Cache，再写 |
| No Write Allocate 非写分配 | 不调入，直接向下一级写     |

常见组合：

$$
\text{Write Back}+\text{Write Allocate}
$$

以及：

$$
\text{Write Through}+\text{No Write Allocate}
$$

但是它们不是唯一合法组合，必须按题目条件判断。

##### 为什么虚拟存储器通常采用回写？

因为将页面写回 SSD 或磁盘的开销比写入主存大得多。

如果每次写页面中的一个数据，都立即执行后备存储写入，性能将受到严重影响。

因此修改驻留页面通常先设置脏位，之后根据换出、同步或其他管理机制决定是否写回。

这正是 2016 年 408 第 45 题涉及的原理。

<Callout type="warn" title="AMAT：额外缺失损失与未命中总时间必须二选一">

先看题目是否将命中检测时间计入未命中分支。如果 $P_{miss}$ 指未命中后的**额外损失**，用 $T_{hit}+mP_{miss}$；如果给定的是未命中分支的**全部用时** $T_{miss,total}$，用 $(1-m)T_{hit}+mT_{miss,total}$。不能将两种定义混合，否则时间重复计算。

</Callout>

#### 3.8 Cache 平均访问时间 AMAT

AMAT 是 Average Memory Access Time。

最通用的基础公式：

$$
\boxed{ AMAT= T_{\text{hit}} + r_{\text{miss}}\times P_{\text{miss}} }
$$

其中：

- $T_{\text{hit}}$：Cache 命中时间；
- $r_{\text{miss}}$：缺失率；
- $P_{\text{miss}}$：未命中后额外产生的时间损失。

例如：

- Cache 命中时间 2 ns；
- 命中率 95%；
- Miss 额外损失 100 ns。

则：

$$
r_{\text{miss}}=0.05
$$

$$
AMAT=2+0.05\times100
$$

得到：

$$
\boxed{7\text{ ns}}
$$

但考试存在两种不同表述。

如果题目给的是 Miss 额外损失，则用：

$$
T_{\text{hit}}+r_{\text{miss}}P_{\text{miss}}
$$

如果题目给的是 Miss 整个分支的总耗时，则应写：

$$
\boxed{ AMAT=hT_{\text{hit}}+(1-h)T_{\text{miss,total}} }
$$

二者不能混用，否则可能重复计算命中检查时间。

多级 Cache 也类似。例如两级串行访问的简化模型：

$$
\boxed{ AMAT=T_1+m_1(T_2+m_2P_m) }
$$

其中 $m_1$ 为 L1 缺失率，$m_2$ 是 L1 未命中条件下的 L2 局部缺失率。

### 四、虚拟存储器、页表与 TLB：本章第二大核心

这部分最重要的是建立一个思想：

虚拟地址不等于物理地址。

程序通常使用虚拟地址，而实际访问 DRAM 需要物理地址。

#### 4.1 为什么需要虚拟存储器？

假设一台计算机：

- 进程使用 32 位虚拟地址；
- 物理内存只有 1 GB。

32 位虚拟地址理论上可表示：

$$
2^{32}\text{ B}=4\text{ GB}
$$

一个进程仍然可以拥有 4 GB 的虚拟地址空间。

原因是：

虚拟地址空间中的页面不要求全部同时存放在主存中。

只有当前需要访问的页面才必须映射到适当的物理页框或被调入主存。

虚拟存储器还能够提供：

- 进程间的地址空间隔离；
- 页面保护；
- 页面共享；
- 灵活的内存分配；
- 按需调页。

#### 4.2 页式地址划分

假设：

- 虚拟地址 32 bit；
- 物理地址 24 bit；
- 页面大小 4 KB。

页面大小：

$$
4\text{ KB}=2^{12}\text{ B}
$$

所以页内偏移占：

$$
\boxed{12\text{ 位}}
$$

虚拟地址：

```text
VA：32bit

┌──────────────────────┬──────────────┐
│     VPN 20位         │ Offset 12位  │
└──────────────────────┴──────────────┘
```

物理地址：

```text
PA：24bit

┌────────────────┬──────────────┐
│   PPN 12位     │ Offset 12位  │
└────────────────┴──────────────┘
```

其中：

- VPN：Virtual Page Number，虚拟页号；
- PPN：Physical Page Number，物理页框号。

地址转换的核心：

$$
\boxed{ VPN\xrightarrow{\text{页表}}PPN }
$$

页内偏移不改变。

因此：

$$
\boxed{ PA=PPN\times\text{页大小}+\text{页内偏移} }
$$

或者表示为：

$$
\boxed{PA=PPN\Vert Offset}
$$

这里 $\Vert$ 表示二进制位拼接。

#### 4.3 虚拟地址转换例题

假设：

- 页面大小 4 KB；
- 虚拟地址为 `0x12345ABC`；
- 页表中虚页 `0x12345` 映射到物理页框 `0x02D`。

第一步：

因为页大小是 $2^{12}$ B，最低 12 位是页内偏移。

一个十六进制数位对应 4 bit，因此最低 3 位十六进制数字表示页内偏移。

所以：

$$
VPN=\texttt{0x12345}
$$

$$
Offset=\texttt{0xABC}
$$

第二步：

查询页表得到：

$$
PPN=\texttt{0x02D}
$$

第三步：

拼接页框号和页内偏移：

$$
PA=\texttt{0x02DABC}
$$

最终：

$$
\boxed{PA=\texttt{0x02DABC}}
$$

这就是最基本的分页地址转换。

#### 4.4 页表项 PTE：到底保存什么？

PTE = Page Table Entry。

页表项不是只有物理页框号。

典型页表项包含：

| 字段              | 作用          |
| --------------- | ----------- |
| PPN             | 记录物理页框号     |
| Present / Valid | 表示页面驻留或映射状态 |
| R/W/X           | 访问权限        |
| Dirty           | 页面是否被修改     |
| Accessed        | 页面是否被访问     |
| 其他属性            | 缓存控制、特权级等   |

具体字段取决于体系结构。

##### 页表项的物理地址

如果：

- 页表基址为 $PTBR$；
- 每项大小为 $E$ B；
- 需要查找第 $VPN$ 项；

则：

$$
\boxed{ PTEAddr=PTBR+VPN\times E }
$$

例如：

$$
PTBR=\texttt{0x1000}
$$

$$
VPN=5,\quad E=4
$$

则：

$$
PTEAddr=\texttt{0x1000}+5\times4
$$

得到：

$$
\boxed{\texttt{0x1014}}
$$

这里最常见的错误是直接计算：

$$
PTBR+VPN
$$

忘记一个页表项可能占多个字节。

#### 4.5 为什么需要多级页表？

还是假设：

- 虚拟地址 32 位；
- 页面大小 4 KB；
- 每个页表项 4 B。

虚页号有：

$$
32-12=20
$$

位。

所以整个虚拟地址空间共有：

$$
2^{20}
$$

个虚拟页。

如果使用完整单级页表，那么页表大小：

$$
2^{20}\times4\text{ B}
$$

即：

$$
\boxed{4\text{ MB}}
$$

如果有大量进程，每个进程都为完整虚拟地址空间分配一张单级页表，就会产生较大空间开销。

多级页表的思想是：

把一张完整的大表拆成多张较小的表，只给实际需要的部分分配下级页表。

##### 二级页表地址结构

一个 4 KB 页面能够容纳：

$$
\frac{4096}{4}=1024
$$

个页表项。

$$
1024=2^{10}
$$

所以二级页表索引可以使用 10 位。

虚页号共 20 位，刚好再分成两个 10 位字段。

```text
32位虚拟地址

┌────────────┬────────────┬──────────────┐
│ 一级索引10 │ 二级索引10 │ 页内偏移12位 │
└────────────┴────────────┴──────────────┘
```

地址转换：

```text
虚拟地址
   │
   ▼
一级页表索引
   │
   ▼
一级页表项
   │
   ▼
找到二级页表
   │
   ▼
二级页表项
   │
   ▼
物理页框号
   │
   ▼
拼接页内偏移
   │
   ▼
物理地址
```

如果没有 TLB 命中，并且页表项访问都需要实际访问主存，那么一次数据访存需要：

- 一级页表访问 1 次；
- 二级页表访问 1 次；
- 目标数据访问 1 次。

总共：

$$
\boxed{3\text{ 次主存访问}}
$$

这是不考虑 Cache、并行访问及硬件页表遍历优化的简单模型。

##### 多级页表级数公式

如果一页页表最多容纳 $2^k$ 个表项，而虚页号长度为 $v$ 位，则在每级页表至多占一页的条件下，至少需要：

$$
\boxed{ L=\left\lceil\frac vk\right\rceil }
$$

级页表。

多级页表主要减少稀疏地址空间所需的页表存储开销，但 TLB 未命中时，可能增加页表遍历次数。

#### 4.6 TLB：为什么页表还需要高速缓存？

如果每次访问数据都必须先访问主存中的页表，再访问目标数据，效率会很低。

所以 CPU 使用 TLB。

TLB 本质上是：

近期地址翻译结果的高速缓存。

它保存的核心关系：

$$
VPN\rightarrow PPN
$$

例如：

```text
VPN       PPN
────────────────
0x0012    0x00A4
0x0020    0x00B8
0x0031    0x00C2
```

当 CPU 再次访问 VPN `0x0020` 时，可以直接从 TLB 中取得对应页框号，而不必重新遍历页表。

##### TLB 与 Cache 对比

| 对比   | TLB       | Cache      |
| ---- | --------- | ---------- |
| 保存内容 | 地址翻译      | 指令或数据      |
| 主要输入 | 虚拟页号      | 地址中的标记和索引  |
| 输出   | 物理页框号及权限等 | 实际数据       |
| 目的   | 加快地址转换    | 加快数据访问     |
| 常见实现 | 高速相联结构    | SRAM 等高速结构 |

##### TLB 的组相联映射

TLB 也可以直接映射、组相联或全相联。

例如：

- 8 组；
- 每组 2 路。

那么组号：

$$
\boxed{s=VPN\bmod8}
$$

组号占：

$$
\log_28=3
$$

位。

注意：

TLB 的组号来自虚页号，而不是直接使用虚拟地址最低 3 位。

因为虚拟地址最低若干位是页内偏移。

#### 4.7 2021 年 408 第 44 题：TLB 与 LRU 综合

这是一道极有代表性的真题。

题目条件：

- 虚拟地址 30 位；
- 物理地址 24 位；
- 页面大小 4 KB；
- TLB 2 路组相联；
- TLB 共 8 组；
- 使用 LRU；
- 初始为空。

访问的虚页号序列：

$$
10,12,16,7,26,4,12,20
$$

求发生了哪一次替换、哪个表项被替换。

##### 第一步：求 VPN 和偏移位数

4 KB 页面：

$$
Offset=12
$$

VPN：

$$
30-12=18
$$

位。

因此：

$$
VPN=A_{29}\sim A_{12}
$$

##### 第二步：TLB 组号和标记

8 组：

$$
s=3
$$

组号：

$$
A_{14}\sim A_{12}
$$

TLB 标记：

$$
18-3=15
$$

位。

因此：

$$
Tag=A_{29}\sim A_{15}
$$

##### 第三步：模拟访问序列

每个虚页对应组号：

$$
s=VPN\bmod8
$$

| 访问 VPN | 组号 | 结果   | 本组状态变化          |
| ------ | -- | ---- | --------------- |
| 10     | 2  | Miss | 装入 10           |
| 12     | 4  | Miss | 装入 12           |
| 16     | 0  | Miss | 装入 16           |
| 7      | 7  | Miss | 装入 7            |
| 26     | 2  | Miss | 组 2 装入 26       |
| 4      | 4  | Miss | 组 4 装入 4        |
| 12     | 4  | Hit  | 12 更新为最近使用      |
| 20     | 4  | Miss | 淘汰组 4 中较久未使用的 4 |

重点看组 4。

访问完 VPN 12 和 VPN 4 后：

```text
组4：
 ├─ VPN12
 └─ VPN4
```

随后再次访问 VPN 12，发生命中。

于是：

```text
最近使用：VPN12

最久未用：VPN4
```

现在 VPN 20 也映射到组 4：

$$
20\bmod8=4
$$

必须选择一个表项淘汰。

根据 LRU：

$$
\boxed{\text{被替换的 VPN 是 4}}
$$

这题进一步询问，如果虚拟地址从 30 位增加到 32 位，TLB 表项增加多少位。

因为页面大小、组数、物理页框号位数都不变，增加的虚拟地址位只扩大 VPN 的高位标记。

所以：

$$
\boxed{\text{增加 2 位}}
$$

这道题的全部考点就是：

页内偏移、VPN、TLB 组号、TLB Tag、LRU。

<Callout type="info" title="TLB、Cache 与缺页：采用题设的统一地址翻译模型">

在典型物理标记 Cache 的分析中，先通过 TLB/页表获得物理地址，再判断 Cache 是否命中；实际硬件可能使用虚拟索引、并行访问等优化。原稿中讨论“不可能组合”的结论建立在**TLB 表项与页表有效性一致、页面驻留状态已同步**的教学模型上，不可脱离假设推广。

</Callout>

#### 4.8 TLB Miss、Cache Miss 与 Page Fault

这三个概念必须彻底区分。

TLB Miss

说明地址翻译没有命中 TLB。

下一步通常是查询页表。

并不代表目标页面没有装入主存。

Cache Miss

说明目标数据块没有命中当前 Cache。

如果页面已经驻留，通常从下一级存储器读取数据块。

Page Fault

说明当前页面不在主存，或者触发了体系结构定义的其他页故障条件。

在 408 最常见的请求分页模型中，缺页意味着需要由操作系统处理页面未驻留问题。

##### 2010 年 408 真题：哪些组合不可能？

| TLB  | Cache | Page | 是否可能 |
| ---- | ----- | ---- | ---- |
| Miss | Miss  | Miss | 可能   |
| Miss | Hit   | Hit  | 可能   |
| Hit  | Miss  | Hit  | 可能   |
| Hit  | Hit   | Miss | 不可能  |

为什么最后一种不可能？

正常一致的地址转换系统中，TLB 命中说明存在有效的地址转换，且相应页面当前可用。

因此：

$$
\boxed{TLB\ Hit\Rightarrow Page\ Hit}
$$

但是：

$$
TLB\ Miss\not\Rightarrow Page\ Fault
$$

因为 TLB 只是页表翻译缓存。

查询页表后，完全可能发现目标页面已经在主存中。

同样：

$$
TLB\ Miss\not\Rightarrow Cache\ Miss
$$

因为二者缓存的是不同对象。

这是一道非常基础但非常重要的判断题。

#### 4.9 缺页异常的完整处理过程

当页面未驻留时，通常执行：

```text
CPU 访问虚拟地址
        │
        ▼
查询 TLB / 页表
        │
        ▼
发现页面不在主存
        │
        ▼
触发缺页异常
        │
        ▼
操作系统介入
        │
        ▼
检查有无空闲页框
        │
   ┌────┴────┐
   │         │
   有        无
   │         │
   │       选择牺牲页
   │         │
   │       必要时写回
   │         │
   └────┬────┘
        │
        ▼
从后备存储调入页面
        │
        ▼
更新页表和必要的 TLB 状态
        │
        ▼
重新执行发生缺页的指令
```

注意三个数量：

- 缺页次数；
- 页面置换次数；
- 页面写回次数。

它们不相同。

例如有 3 个空闲页框，依次访问 3 个原本不在主存的不同页面。

可以发生：

$$
3\text{ 次缺页}
$$

但：

$$
0\text{ 次页面置换}
$$

因为存在空闲页框，不需要淘汰旧页面。

#### 4.10 TLB 有效访存时间

考虑简单单级页表模型。

假设：

- TLB 查询时间为 $T_t$；
- 主存访问时间为 $T_m$；
- TLB 命中率为 $h$；
- TLB 与主存访问串行；
- 不考虑 Cache 与缺页。

TLB 命中：

$$
T_{\text{hit}}=T_t+T_m
$$

TLB 未命中：

先查 TLB，再访问页表，最后访问目标数据。

因此：

$$
T_{\text{miss}}=T_t+2T_m
$$

平均访问时间：

$$
\boxed{ EAT=h(T_t+T_m)+(1-h)(T_t+2T_m) }
$$

##### 例题

已知：

$$
T_t=10\text{ ns}
$$

$$
T_m=100\text{ ns}
$$

$$
h=0.9
$$

则：

$$
EAT=0.9(10+100)+0.1(10+200)
$$

得到：

$$
\boxed{EAT=120\text{ ns}}
$$

这类题千万不要无条件套固定公式。若题目改变了页表级数、Cache 命中情况、并行查询方式或缺页代价，就要重新分析每条分支的时间。

#### 4.11 2016 年 408 第 45 题：TLB、页表、Cache 一起考

题目给出：

- 虚拟地址 32 bit；
- 物理地址 24 bit；
- 页面大小 8 KB；
- TLB 全相联；
- Cache 数据区 64 KB；
- 2 路组相联；
- Cache 块 64 B。

先求页式地址结构。

页面大小：

$$
8\text{ KB}=2^{13}\text{ B}
$$

所以页内偏移：

$$
13\text{ 位}
$$

虚页号：

$$
32-13=19
$$

物理页框号：

$$
24-13=11
$$

全相联 TLB 使用虚页号及必要的地址空间标识进行匹配；在本题简化模型中，虚页号标记占 19 位。

现在计算 Cache。

行数：

$$
L=\frac{64\times1024}{64}=1024
$$

组数：

$$
S=\frac{1024}{2}=512
$$

组号位数：

$$
\log_2512=9
$$

块内偏移：

$$
\log_264=6
$$

Cache Tag：

$$
24-9-6=9
$$

所以物理地址可划分为：

```text
24 bit 物理地址

┌─────────────┬─────────────┬──────────────┐
│  Tag 9位    │  组号 9位   │ 块内偏移 6位 │
└─────────────┴─────────────┴──────────────┘
```

若给出主存块号：

$$
j=4099
$$

则映射组号：

$$
4099\bmod512=3
$$

所以：

$$
\boxed{\text{Cache 第 3 组}}
$$

其 Tag 对应高位块号：

$$
\left\lfloor\frac{4099}{512}\right\rfloor=8
$$

也就是说，题目并不复杂，只是连续进行了两次不同的地址拆分。

### 五、外存储器：机械磁盘、RAID、SSD

#### 5.1 磁盘的物理结构

机械硬盘由盘片、盘面、磁道、扇区、磁头等组成。

```text
磁盘
 │
 ├── 盘片
 │    ├── 上盘面
 │    └── 下盘面
 │
 ├── 每个盘面
 │    └── 多条磁道
 │          └── 多个扇区
 │
 └── 不同盘面上半径相同的磁道
          └── 柱面
```

传统磁盘物理地址常用：

$$
\boxed{CHS}
$$

表示：

- Cylinder：柱面；
- Head：磁头或盘面；
- Sector：扇区。

##### 磁盘容量

如果：

- 柱面数为 $C$；
- 每柱面可用盘面数为 $H$；
- 每道扇区数为 $S$；
- 每扇区数据大小为 $B$；

则：

$$
\boxed{ Capacity=CHSB }
$$

注意实际格式化容量还受到扇区管理信息等因素影响。

#### 5.2 磁盘平均访问时间

一次机械磁盘随机访问通常包括：

1. 寻道；
2. 等待盘片旋转；
3. 传输数据。

因此：

$$
\boxed{ T_{\text{access}} = T_{\text{seek}} + T_{\text{rotation}} + T_{\text{transfer}} }
$$

如果题目还给出控制器开销、排队时间，就需要按要求加上。

##### 平均旋转等待

转速为 $r$ rpm：

$$
T_{\text{rev}}=\frac{60}{r}\text{ s}
$$

平均等待半圈：

$$
\boxed{ T_{\text{rotation}}=\frac{30}{r}\text{ s} }
$$

例如 7200 rpm：

$$
T_{\text{rev}}=\frac{60}{7200} \approx8.333\text{ ms}
$$

平均旋转等待：

$$
\boxed{4.167\text{ ms}}
$$

##### 2022 年 408 第 44 题

题目：

- 4 个双面盘片；
- 每盘面 20000 条磁道；
- 每磁道 500 个扇区；
- 每扇区 512 B；
- 转速 7200 rpm；
- 平均寻道时间 5 ms。

第一问，CHS 各字段需要多少位？

柱面数为 20000：

$$
\lceil\log_220000\rceil=15
$$

盘面数：

$$
4\times2=8
$$

需要：

$$
\log_28=3
$$

位。

每道扇区数为 500：

$$
\lceil\log_2500\rceil=9
$$

因此：

$$
\boxed{15,\ 3,\ 9}
$$

第二问，平均访问一个扇区需要多长时间？

平均寻道：

$$
5\text{ ms}
$$

平均旋转等待：

$$
4.167\text{ ms}
$$

单扇区传输：

$$
\frac{8.333}{500}\approx0.0167\text{ ms}
$$

所以：

$$
T\approx5+4.167+0.0167
$$

得到：

$$
\boxed{9.18\text{ ms}}
$$

第三问，若 DMA 数据缓冲区为 64 bit，一个扇区需要多少次 DMA 总线请求？

一个扇区：

$$
512\text{ B}
$$

每次传输：

$$
64\text{ bit}=8\text{ B}
$$

所以：

$$
\boxed{\frac{512}{8}=64\text{ 次}}
$$

此处考的是 64 bit 数据宽度对应的传输次数，与 CHS 地址字段长度无关。

#### 5.3 RAID：条带、镜像与校验

RAID 把多块物理磁盘组织成逻辑磁盘系统。

常见机制：

| RAID    | 核心思想   | 可用容量（同容量盘）     | 容错             |
| ------- | ------ | -------------- | -------------- |
| RAID 0  | 条带化    | $NC$       | 无              |
| RAID 1  | 镜像     | 两盘镜像为 $C$  | 可坏其中一盘         |
| RAID 5  | 分布式单校验 | $(N-1)C$   | 任意一盘           |
| RAID 6  | 分布式双校验 | $(N-2)C$   | 任意两盘           |
| RAID 10 | 镜像后条带化 | 典型为 $NC/2$ | 取决于故障是否落在同一镜像对 |

注意 RAID 0 不具备冗余机制。

因此：

$$
\boxed{\text{RAID 0 不提高数据容错能力}}
$$

2013 年 408 真题考查哪些措施可以提高 RAID 可靠性。

正确的是：

- 磁盘镜像；
- 奇偶校验。

条带化主要提高并行 I/O 性能，本身不提供冗余。

另外，RAID 不是备份的替代品。误删除、勒索软件和逻辑损坏等问题，RAID 并不能普遍解决。

#### 5.4 SSD 与 Flash

SSD 主要使用 NAND Flash。

与 HDD 相比：

| 项目     | HDD     | SSD    |
| ------ | ------- | ------ |
| 存储介质   | 磁盘      | Flash  |
| 机械寻道   | 有       | 无      |
| 旋转等待   | 有       | 无      |
| 随机访问延迟 | 较大      | 较小     |
| 抗震性    | 较差      | 较好     |
| 主要寿命约束 | 机械和磁介质等 | 闪存擦写寿命 |

理解 SSD，重点是三个粒度：

- 读取粒度；
- 编程写入粒度；
- 擦除粒度。

NAND Flash 通常以页为读写的基本组织单位之一，而擦除通常需要针对更大的擦除块。

所以 SSD 不适合像普通 DRAM 那样直接覆盖任意字节。

##### FTL

FTL = Flash Translation Layer。

作用是建立逻辑地址与物理 Flash 位置之间的映射。

因为 SSD 更新数据时可能把新数据写入其他物理页，旧物理页则标记为失效。

##### 磨损均衡

Wear Leveling 的主要目的：

让擦写尽量分散，避免少数 Flash 块过早达到寿命限制。

不是单纯为了提高读写速度。

##### 垃圾回收

Garbage Collection 负责整理失效页、迁移仍有效的数据，并回收可供重新写入的空间。

这也可能导致写放大：

$$
\boxed{ WA= \frac{\text{实际写入 Flash 的数据量}} {\text{主机请求写入的数据量}} }
$$

例如主机写入 1 MB，但 SSD 内部实际发生 2 MB Flash 写入：

$$
WA=2
$$

理解产生原因即可，不必把复杂的 SSD 固件实现当作 408 核心。

### 六、重点大题精讲：把本章知识综合起来

这一部分最接近真正的 408 大题考查方式。

#### 大题一：2010 年 408 第 44 题——二维数组与 Cache 命中率

题目中：

```text
int a[256][256];
```

两个程序访问相同数组。

程序 A：

```text
for (i = 0; i < 256; i++)
    for (j = 0; j < 256; j++)
        sum += a[i][j];
```

程序 B：

```text
for (j = 0; j < 256; j++)
    for (i = 0; i < 256; i++)
        sum += a[i][j];
```

Cache 条件：

- 8 行；
- 每行 64 B；
- 直接映射；
- `int` 为 4 B；
- 数组首地址为十进制 320；
- C 语言按行优先存储。

##### 第一步：求每个块可保存多少元素

$$
\frac{64}{4}=16
$$

即：

$$
\boxed{16\text{ 个 int}}
$$

##### 第二步：程序 A

按行优先访问，物理地址连续增长。

对于一个 Cache 块：

- 第一次读取：Miss；
- 后续 15 个整数：Hit。

所以：

$$
H_A=\frac{15}{16}
$$

得到：

$$
\boxed{H_A=93.75\%}
$$

##### 第三步：程序 B

按列访问。

数组每行有：

$$
256\times4=1024\text{ B}
$$

因此相邻两次内层循环访问的地址相差：

$$
1024\text{ B}
$$

换算成主存块距离：

$$
\frac{1024}{64}=16
$$

Cache 只有 8 行：

$$
16\bmod8=0
$$

所以这些访问反复映射到同一个 Cache 行。

在程序 B 的内层循环中，各行相应数据块不断互相替换。

当下一列再次访问原来的行时，原块早已被替换。

因此：

$$
\boxed{H_B=0}
$$

这道题最终答案：

| 程序   | 命中率    |
| ---- | ------ |
| 程序 A | 93.75% |
| 程序 B | 0%     |

程序 A 在题设条件下更快。

但要注意：按列访问并不必然意味着命中率为零。

这道题的 0% 与数组行跨度、Cache 行数以及直接映射结构共同有关。

#### 大题二：2020 年 408 第 44 题——Cache 地址与数组

题目：

- 32 位物理地址；
- Cache 数据区 32 KB；
- 8 路组相联；
- 块大小 64 B；
- 直写；
- LRU；
- 初始为空。

程序：

```text
for (k = 0; k < 1024; k++)
    s[k] = 2 * s[k];
```

其中：

- `int` 为 4 B；
- 数组首地址为 `008000C0H`；
- `k` 在寄存器中。

问数组访问的 Cache Miss 次数。

数组长度：

$$
1024\times4=4096\text{ B}
$$

每块：

$$
64\text{ B}
$$

所以数组占用：

$$
\frac{4096}{64}=64
$$

个主存块。

数组起始地址是 64 B 对齐的。

由于顺序扫描，且题目中的 Cache 足够大，没有额外冲突导致重复调块，因此每个块只在首次访问时缺失。

最终：

$$
\boxed{64\text{ 次 Cache Miss}}
$$

注意程序有读取与写入，但并不意味着每个数组元素都会产生两次 Miss。

第一次读取对应块后，该块已经装入 Cache；随后的写入访问通常会命中。

#### 大题三：2012 年 408 第 43 题——CPU、Cache、主存、DMA

这是存储系统与 CPU 性能、总线、DMA 结合的典型题。

已知：

- 主频 80 MHz；
- CPI = 4；
- 平均每条指令访存 1.5 次；
- Cache 命中率 99%；
- Cache 块大小 16 B；
- 存储器总线宽度 32 bit。

求 MIPS、每秒 Cache Miss 次数和最低主存带宽。

##### 第一步：每秒执行指令数

$$
IPS=\frac{f}{CPI}
$$

$$
=\frac{80\times10^6}{4}
$$

得到：

$$
\boxed{20\text{ MIPS}}
$$

##### 第二步：每秒访存次数

$$
20\times10^6\times1.5 =30\times10^6
$$

##### 第三步：每秒 Cache Miss 次数

缺失率：

$$
1-0.99=0.01
$$

所以：

$$
30\times10^6\times0.01 =300000
$$

即：

$$
\boxed{3\times10^5\text{ 次/s}}
$$

##### 第四步：最低主存带宽

假设每次 Miss 需要调入 16 B，忽略脏块写回等额外流量。

$$
BW=300000\times16
$$

得到：

$$
\boxed{4.8\text{ MB/s}}
$$

如果 Cache Miss 后还有 $0.0005\%$ 的缺页率：

$$
0.0005\%=0.000005
$$

每秒缺页：

$$
300000\times0.000005=1.5
$$

所以平均每秒：

$$
\boxed{1.5\text{ 次缺页}}
$$

若每个页面 4 KB，DMA 每次传输 32 bit：

$$
32\text{ bit}=4\text{ B}
$$

每页需要：

$$
\frac{4096}{4}=1024
$$

次 DMA 数据传输。

平均每秒：

$$
1.5\times1024=1536
$$

因此：

$$
\boxed{1536\text{ 次/s}}
$$

这道题需要养成一个重要习惯：

先把每秒指令数转化成每秒访存次数，再转化成每秒 Miss 次数，最后转化成数据流量或 I/O 次数。

不能跳步骤。

#### 大题四：2023 年 408 第 43 题——数组、分页、Cache 综合

这道题覆盖本章多个核心考点。

题目：

```text
for (i = 0; i < 24; i++)
    for (j = 0; j < 64; j++)
        a[i][j] = 10;
```

已知：

- `int` 为 4 B；
- 数组按行优先；
- 虚拟首地址 `00422000H`；
- 页面大小 4 KB；
- Cache 数据区 8 KB；
- 4 路组相联；
- Cache 块大小 32 B；
- 初始时数组不在主存；
- 执行中不发生页面置换。

##### 第一问：数组占几个页面？

数组有：

$$
24\times64=1536
$$

个元素。

总容量：

$$
1536\times4=6144\text{ B}
$$

即：

$$
6\text{ KB}
$$

页面大小 4 KB。

起始地址恰好页对齐，所以：

$$
\boxed{2\text{ 页}}
$$

若两页最初均不在主存，且执行过程中不会被换出，则发生：

$$
\boxed{2\text{ 次缺页}}
$$

对应首次访问的虚拟地址为：

```text
00422000H
00423000H
```

##### 第二问：是否具有时间局部性？

题目只考虑数组访问。

每个元素仅被写入一次，不会重复访问。

因此：

$$
\boxed{\text{没有针对数组元素的时间局部性}}
$$

但按行连续访问，具有空间局部性。

##### 第三问：Cache 地址结构

Cache 数据容量：

$$
8\text{ KB}=8192\text{ B}
$$

块大小 32 B。

总行数：

$$
8192/32=256
$$

4 路组相联：

$$
S=256/4=64
$$

组号位数：

$$
\log_264=6
$$

块内偏移：

$$
\log_232=5
$$

所以地址中的：

$$
\boxed{A_4\sim A_0}
$$

表示块内偏移。

$$
\boxed{A_{10}\sim A_5}
$$

表示组号。

##### 第四问：`a[1][0]` 的地址

行优先数组地址公式：

$$
\boxed{ Addr(a[i][j]) = Base+(iN+j)\times w }
$$

其中：

- $N=64$；
- $w=4$ B。

所以：

$$
Addr(a[1][0]) = \texttt{00422000H}+64\times4
$$

$$
=\texttt{00422000H}+\texttt{100H}
$$

得到：

$$
\boxed{\texttt{00422100H}}
$$

组号：

$$
\left\lfloor\frac{\texttt{0x100}}{32}\right\rfloor\bmod64 =8
$$

这里计算的是页面内相对偏移对应的组号；由于 Cache 组索引位 $A_{10}\sim A_5$ 完全落在 12 位页内偏移中，地址翻译不改变这些位。

所以：

$$
\boxed{\text{Cache 第 8 组}}
$$

##### 第五问：数组占多少 Cache 块？

数组容量：

$$
6144\text{ B}
$$

每块 32 B：

$$
\frac{6144}{32}=192
$$

所以：

$$
\boxed{192\text{ 块}}
$$

##### 第六问：命中率

每个 Cache 块：

$$
32/4=8
$$

个整数。

在写缺失分配并调入数据块的假设下，且不发生导致重复调块的冲突：

- 第一次访问块内元素：Miss；
- 后续 7 次访问：Hit。

因此：

$$
H=\frac78
$$

得到：

$$
\boxed{87.5\%}
$$

##### 第七问：交换循环顺序会怎样？

交换后：

```text
for (j = 0; j < 64; j++)
    for (i = 0; i < 24; i++)
        a[i][j] = 10;
```

一般来说，按列访问可能降低 Cache 性能。

但是这道题比较特殊。

相邻两行对应元素地址相差：

$$
64\times4=256\text{ B}
$$

即相隔：

$$
256/32=8
$$

个 Cache 块。

因此，对同一列访问 24 行时，块组号以 8 为步长循环。

因为总共 64 组，所以每 8 行返回同一组。

24 行对应到每个相关组中最多 3 个不同的块，而每组有 4 路。

这意味着当前涉及的块可以共存，不需要因为组内路数不足而相互淘汰。

随着列下标增长，同一块中的 8 个整数仍然能够复用。

最终仍是 192 次强制缺失。

因此：

$$
\boxed{H=87.5\%}
$$

这道题最值得学到的不是答案，而是不要仅凭行优先、列优先就直接判断命中率。

真正的判断依据是：

$$
\boxed{ \text{地址序列} \rightarrow \text{主存块号} \rightarrow \text{Cache 组号} \rightarrow \text{替换过程} }
$$

#### 大题五：2025 年 408 第 43 题——Cache、数组、页面与平均时间

这是一道很好的较新综合训练题。

题目：

```text
int x, d[2048], i;

for (i = 0; i < 2048; i++)
    d[i] = d[i] / x;
```

已知：

- `int` 为 4 B；
- Cache 数据容量 32 KB；
- 8 路组相联；
- 主存块大小 64 B；
- Cache 命中时间 2 个时钟周期；
- Miss 额外损失 200 个时钟周期；
- 页面大小 4 KB；
- 数组起始地址 `01800020H`；
- `i` 和 `x` 已在寄存器中；
- 数组最初在主存中，但不在 Cache。

##### 第一问：Cache 组号多少位？

行数：

$$
L=\frac{32\times1024}{64}=512
$$

组数：

$$
S=\frac{512}{8}=64
$$

组索引：

$$
\boxed{6\text{ 位}}
$$

块内偏移：

$$
\boxed{6\text{ 位}}
$$

因为：

$$
6+6=12
$$

而页面偏移也是 12 位，所以组索引可以直接使用虚拟地址中的：

$$
\boxed{VA_{11}\sim VA_6}
$$

这些位在虚拟地址与物理地址之间保持相同。

这也是为什么某些 VIPT Cache 可以并行进行部分 Cache 索引和 TLB 查询。

##### 第二问：`d[100]` 的虚拟地址

数组首地址：

$$
\texttt{01800020H}
$$

元素偏移：

$$
100\times4=400=\texttt{190H}
$$

所以：

$$
VA(d[100]) =\texttt{01800020H}+\texttt{190H}
$$

得到：

$$
\boxed{\texttt{018001B0H}}
$$

对应组号：

$$
\left\lfloor\frac{\texttt{0x1B0}}{64}\right\rfloor\bmod64 =6
$$

所以：

$$
\boxed{\text{第 6 组}}
$$

##### 第三问：为什么数组涉及 129 个块，而不是 128 个？

数组数据量：

$$
2048\times4=8192\text{ B}
$$

如果从块边界开始：

$$
8192/64=128
$$

块。

但本题起始地址最低 6 位不为零。

其块内偏移：

$$
\boxed{\texttt{20H}=32\text{ B}}
$$

所以实际覆盖字节范围相对于第一个块边界是：

$$
32+8192=8224\text{ B}
$$

块数：

$$
N= \left\lceil\frac{8224}{64}\right\rceil
$$

得到：

$$
\boxed{129\text{ 块}}
$$

这里最重要的易错点：

求一个连续数据区占多少 Cache 块，不能在未确认地址对齐时直接用数据量除以块大小。

通用公式：

$$
\boxed{ N_{\text{blocks}} = \left\lceil \frac{(Base\bmod B)+Size}{B} \right\rceil }
$$

##### 第四问：Cache 缺失率

程序中每次循环对数组元素执行：

```text
d[i] = d[i] / x;
```

典型情况下需要：

- 读取 `d[i]`；
- 写入 `d[i]`。

因此总数组访问次数：

$$
2048\times2=4096
$$

Cache 初始为空，访问遍历的 129 个块每块第一次读取时缺失。

数组工作集能够保留在本题 Cache 中，不需要重复调入已访问的块。

因此：

$$
N_{\text{miss}}=129
$$

缺失率：

$$
r=\frac{129}{4096}
$$

得到：

$$
\boxed{r\approx3.15\%}
$$

##### 第五问：平均访问时间

$$
AMAT=T_{\text{hit}}+rP
$$

代入：

$$
AMAT=2+\frac{129}{4096}\times200
$$

得到：

$$
\boxed{AMAT\approx8.30\text{ 个时钟周期}}
$$

##### 第六问：数组占几个页面？

页面大小 4 KB：

$$
P=4096\text{ B}
$$

数组起始页内偏移：

$$
\texttt{20H}=32
$$

因此：

$$
N_{\text{pages}} = \left\lceil\frac{32+8192}{4096}\right\rceil
$$

得到：

$$
\boxed{3\text{ 页}}
$$

注意：

- Cache 占 129 个块；
- 虚拟存储器占 3 个页面。

二者属于不同层次，不能混淆。

如果这些页面最初都不在主存，且执行中不发生重复换出，则：

$$
\boxed{3\text{ 次缺页}}
$$

这道题非常值得反复练习，因为它把本章最重要的计算关系集中到了同一道题中。

| --------------------- | ------------------- |
| SRAM 静态，所以断电不丢数据      | SRAM 仍然易失           |
| SDRAM 不需要刷新           | SDRAM 仍属于 DRAM      |

| 两次访问同一存储体一定冲突         | 还要判断时间间隔            |
| 4 路组相联就是 4 组          | 每组有 4 行             |
| 组号与路号都由地址直接决定         | 地址确定组，具体路由状态决定      |
| Cache 容量一定等于数据区容量     | 总容量还可能包括 Tag 和控制位   |
| Write Back 立即修改主存     | 通常先修改 Cache，之后再写回   |
| Cache 块越大一定越好         | 可能增加 Miss 代价或冲突     |
| TLB Miss 一定缺页         | TLB Miss 后仍可查页表成功   |
| Cache Miss 一定缺页       | 两者处于不同层次            |
| Page Fault 等于页面置换     | 有空闲页框时可缺页而不置换       |
| 虚拟地址转换会改变页内偏移         | 页内偏移保持不变            |
| 多级页表必然提高单次地址转换速度      | 主要节省页表空间，未命中时可能增加访存 |
| 按列访问数组必然没有 Cache 命中   | 必须结合组号、相联度和替换分析     |
| RAID 0 提高容错能力         | RAID 0 没有故障冗余       |
| SSD 可以任意字节直接覆盖        | Flash 存在编程和擦除粒度约束   |

#### 1. 必须记住的公式

| 类型           | 核心公式                                                             |
| ------------ | ---------------------------------------------------------------- |
| 存储容量         | $2^n\times\text{编址单位大小}$                                     |
| 芯片数量         | $\dfrac{M_t}{M_c}\dfrac{W_t}{W_c}$                           |
| 低位交叉体号       | $A\bmod m$                                                   |
| 无冲突条件        | $m\tau\ge T$                                                 |
| 连续访问时间       | $T+(n-1)\tau$                                                |
| 主存块号         | $\lfloor A/B\rfloor$                                         |
| 块内偏移         | $A\bmod B$                                                   |
| Cache 行数     | $C/B$                                                        |
| Cache 组数     | $L/n$                                                        |
| Cache Tag 位数 | $p-s-b$                                                      |
| Cache 命中率    | $1-\dfrac{Miss}{Access}$                                     |
| 平均访问时间       | $T_{\text{hit}}+r_{\text{miss}}P$                          |
| 页内偏移位数       | $\log_2P$                                                    |
| 虚页号位数        | $V-\log_2P$                                                  |
| 物理页框号位数      | $M-\log_2P$                                                  |
| 物理地址         | $PPN\times P+Offset$                                         |
| 页表项地址        | $PTBR+VPN\times E$                                           |
| 磁盘平均时间       | $T_{\text{seek}}+T_{\text{rotation}}+T_{\text{transfer}}$ |

#### 2. 存储系统综合题的固定方法

遇到一道很长的综合题，不要从头到尾反复读。

应该先提取所有已知条件。

例如：

```text
虚拟地址位数：
物理地址位数：
页面大小：
页表项大小：
TLB 组数：
TLB 相联度：
Cache 数据容量：
Cache 块大小：
Cache 相联度：
Cache 写策略：
替换算法：
数组元素大小：
数组起始地址：
数组访问顺序：
```

然后按照以下顺序：

第一步：分析地址空间

先拆出：

$$
VA=VPN\Vert Offset
$$

第二步：分析地址翻译

$$
VPN\rightarrow TLB/PageTable\rightarrow PPN
$$

第三步：得到物理地址

$$
PA=PPN\Vert Offset
$$

第四步：分析 Cache

$$
PA=Tag\Vert Set\Vert BlockOffset
$$

第五步：分析访问序列

把每次访问转换成主存块号和组号，判断命中、替换和写回。

第六步：统计数量和时间

计算：

- Cache Miss 数；
- TLB Miss 数；
- 缺页次数；
- 页面置换次数；
- 数据传输量；
- AMAT 或总执行时间。

如果题目给出了特殊的 VIPT 或其他并行访存结构，再根据结构修正上述顺序。
