## 第一部分：计算机系统的基本结构

### 二、计算机系统到底由什么组成？

#### 2.1 计算机系统 = 硬件 + 软件

完整的计算机系统由两部分组成：

$$
\boxed{\text{计算机系统}=\text{硬件系统}+\text{软件系统}}
$$

硬件是实际执行计算的物理设备；软件则规定这些设备要完成什么任务。

硬件主要包括 CPU、主存储器、输入设备、输出设备和连接它们的通信结构。

软件分为系统软件与应用软件。

| 系统软件    | 应用软件  |
| ------- | ----- |
| 操作系统    | 浏览器   |
| 编译程序    | 文本编辑器 |
| 汇编程序    | 游戏    |
| 链接程序    | 视频播放器 |
| 数据库管理系统 | 办公软件  |

判断方法：

系统软件主要为计算机系统运行和应用程序提供公共服务；应用软件主要用于完成用户的具体工作。

例如，数据库管理系统通常归入系统软件，而一个使用数据库开发的学生成绩管理程序属于应用软件。

### 三、计算机系统的层次结构

计算机可以从不同抽象层次理解。

从高级语言程序员到实际硬件，可以形成：

```text
高级语言程序
       ↓
编译器、运行时等
       ↓
操作系统与系统服务
       ↓
指令集体系结构 ISA
       ↓
CPU 微体系结构
       ↓
逻辑电路
       ↓
电子器件
```

这里是一张帮助理解的抽象层次图。实际系统中，操作系统、编译器与 ISA 之间并不是简单的单向调用关系。

#### 3.1 ISA 是什么？

ISA 是 Instruction Set Architecture，称为指令集体系结构。

它定义了软件能够使用的机器级接口。

典型内容包括：

| ISA 通常规定     | 不属于 ISA 的典型实现细节 |
| ------------ | --------------- |
| 机器指令及其编码     | CPU 流水线级数       |
| 程序员可见寄存器     | Cache 容量        |
| 数据类型与相关指令语义  | Cache 组相联度      |
| 寻址方式         | 乱序执行机制          |
| 软件可见的异常和状态规则 | 硬布线或微程序控制方式     |

重点理解：

ISA 规定一条机器指令是什么意思，而不是规定硬件必须通过哪种电路完成它。

例如，假设两台计算机都支持同一种 ISA：

机器 A 使用五级流水线。

机器 B 使用更复杂的多发射、乱序执行结构。

只要两者满足相同的 ISA 语义，同一份适用的机器代码原则上可以在两台机器上正确运行。

但两台机器的 CPI、主频和运行速度可能差别很大。

#### 3.2 计算机体系结构与计算机组成的区别

这是经典概念题。

| 计算机体系结构        | 计算机组成        |
| -------------- | ------------ |
| 关注计算机对软件呈现什么功能 | 关注这些功能如何实现   |
| 指令系统           | 数据通路         |
| 程序员可见寄存器       | 运算器具体结构      |
| 寻址方式           | 控制器实现        |
| 软件可见的数据类型及操作   | Cache、流水线等实现 |

记忆：

$$
\boxed{\text{体系结构：做什么}}
$$

$$
\boxed{\text{计算机组成：怎么做}}
$$

例如：

“CPU 支持整数加法指令”属于 ISA 层面的描述。

“整数加法由哪种加法器实现”属于计算机组成层面的描述。

### 高频陷阱

同一 ISA 并不意味着：

- 两台机器的 CPI 相同；
- 两台机器主频相同；
- 两台机器 Cache 大小相同；
- 两台机器采用相同的流水线；
- 两台机器一定具有相同的执行时间。

此外，同一 ISA 也不自动保证不同编译结果具有完全相同的动态指令条数。

这点在性能计算题中非常关键。

## 第二部分：冯·诺依曼计算机

### 四、存储程序思想

本章第一个核心考点是存储程序。

冯·诺依曼计算机最重要的思想就是：

> 把程序和数据都存放在存储器中，计算机按照程序规定的顺序自动取出指令并执行。

为什么这个思想重要？

因为计算机无需为每项任务重新连接硬件电路，只要改变存储器中的程序，就可以完成不同任务。

#### 4.1 五大组成部件

经典冯·诺依曼计算机由五个基本部件组成。

| 部件   | 核心作用      |
| ---- | --------- |
| 运算器  | 算术运算与逻辑运算 |
| 控制器  | 控制指令执行过程  |
| 存储器  | 保存程序和数据   |
| 输入设备 | 接收外部信息    |
| 输出设备 | 向外部输出信息   |

可以简单理解为：

```text
             输入设备
                │
                ▼
             存储器
                ▲
                │
        ┌───────┴───────┐
        │      CPU      │
        │  ┌─────────┐  │
        │  │ 控制器  │  │
        │  └─────────┘  │
        │  ┌─────────┐  │
        │  │ 运算器  │  │
        │  └─────────┘  │
        │   寄存器组    │
        └───────┬───────┘
                │
                ▼
             输出设备
```

这张图只表示功能组成，不能理解为所有数据都必须经过图中的每条连接。

#### 4.2 经典冯·诺依曼机的六个特点

这是需要记住的知识。

第一，采用存储程序方式。

程序被存放在存储器中，由计算机自动执行。

第二，指令和数据以二进制形式存储。

同一个二进制位串可以按照不同语义被解释为指令、整数、地址或其他信息。

第三，指令和数据在经典模型中处于统一的存储体系。

这与典型哈佛结构的分离式指令、数据存储方式不同。

第四，机器指令通常包含操作码和地址相关字段。

操作码说明进行什么操作。

其他字段说明操作数的位置、寻址信息或立即数等。

第五，程序通常顺序执行。

在没有改变控制流的情况下，CPU 顺序取指。

遇到跳转、调用或异常等情况，下一条指令地址可能改变。

第六，经典模型以运算器为中心。

现代计算机通常强调以存储器为中心组织数据交换。

注意题目问的是“经典模型”还是“现代计算机”。

### 五、为什么计算机采用二进制？

主要原因不是节省存储空间。

核心原因包括物理实现和逻辑运算两个方面。

#### 5.1 二进制容易由电路实现

电子电路可以通过两个稳定的逻辑状态表示：

$$
0,\quad 1
$$

例如使用低电平与高电平代表不同逻辑值。

实际数字电路允许一定电压范围，因此具有抗噪声能力。

#### 5.2 运算规则简单

二进制的基本加法规则：

$$
0+0=0
$$

$$
0+1=1
$$

$$
1+1=10_2
$$

可以通过简单的组合逻辑电路实现。

#### 5.3 与布尔代数天然对应

布尔代数包含与、或、非等运算。

计算机中的逻辑门直接支持这些运算。

因此二进制便于实现算术、逻辑、比较和控制功能。

记住三个理由：

两稳态器件容易实现、运算规则简单、适合逻辑电路。

### 六、指令和数据究竟怎样区分？

这是本章非常容易出错的考点。

#### 真题 1：2009 年

题目：

冯·诺依曼计算机中，指令和数据均以二进制形式存放在存储器中，CPU 区分它们的依据是：

A. 指令操作码的译码结果\
B. 指令和数据的寻址方式\
C. 指令周期的不同阶段\
D. 指令和数据所在的存储单元

答案：C。

#### 6.1 为什么选择 C？

因为指令和数据在存储器中的物理表示形式没有本质区别。

假设主存中存放：

```text
10110000 00000101
```

这串二进制数据可以被解释为机器指令，也可能作为普通数据使用。

真正决定其用途的是 CPU 当前的控制流程。

在取指阶段，CPU 把从指令地址取出的位串当作机器指令。

在取操作数阶段，CPU 按照当前指令要求获取数据。

所以：

$$
\boxed{\text{区分依据：当前指令周期阶段}}
$$

#### 6.2 为什么不选 A？

操作码译码确实可以确定一条指令的操作类型。

但在译码前，CPU 必须首先根据取指控制流程，把相应内容当作指令取入。

所以操作码译码结果不是题目所问的根本区分依据。

#### 6.3 另一道模拟题为什么选控制器？

模拟题：

“冯·诺依曼机可以区分指令和数据的部件是？”

A. 总线\
B. 控制器\
C. 控制存储器\
D. 运算器

答案：B，控制器。

这与 2009 年真题不矛盾。

两道题的提问角度不同：

| 问题                | 答案        |
| ----------------- | --------- |
| 区分指令和数据的依据是什么？    | 指令周期的不同阶段 |
| 哪个部件负责组织取指、译码和控制？ | 控制器       |

这是非常典型的 408 出题方式。

同一个知识点，改变提问对象，就可能改变答案。

## 第三部分：CPU 怎样执行程序

### 七、CPU、主存与 I/O 如何协同工作？

CPU 的典型执行流程可以简化为：

```text
主存中保存程序
       ↓
CPU 取出指令
       ↓
控制器译码
       ↓
产生控制信号
       ↓
获取操作数
       ↓
运算器执行
       ↓
结果写回
       ↓
执行下一条指令
```

这就是存储程序自动执行的基础。

### 八、四个重要寄存器

本章需要先认识 PC、IR、MAR、MDR。

| 寄存器 | 英文名称                    | 作用           |
| --- | ----------------------- | ------------ |
| PC  | Program Counter         | 保存下一条待取指令的地址 |
| IR  | Instruction Register    | 保存当前指令       |
| MAR | Memory Address Register | 保存本次访存地址     |
| MDR | Memory Data Register    | 暂存访存的数据      |

#### 8.1 PC：程序计数器

PC 负责指出下一条要取的指令在哪里。

例如：

$$
PC=1000
$$

假设指令长度为 4 字节，按照字节编址，并且下一条指令顺序存放在后面，则取指过程中 PC 可以更新为：

$$
PC\leftarrow1004
$$

注意，这只是一个假设指令长度固定的例子。

在变长指令系统中，PC 的顺序更新量不一定为固定值。

#### 8.2 MAR：存储器地址寄存器

MAR 保存本次访问主存的地址。

取指时，PC 给出的地址可以送入 MAR。

但 MAR 不只负责访问指令。

读取数据时，也需要向存储器提供数据地址。

#### 8.3 MDR：存储器数据寄存器

MDR 暂存从主存读取的数据，或者准备写入主存的数据。

在经典教学模型中，MAR 负责地址，MDR 负责数据。

#### 8.4 IR：指令寄存器

IR 保存当前正在译码或执行的机器指令。

控制器根据 IR 中的指令信息产生相应控制信号。

#### 8.5 一次典型取指过程

以经典非流水数据通路为例：

$$
MAR\leftarrow PC
$$

$$
MDR\leftarrow M[MAR]
$$

$$
IR\leftarrow MDR
$$

然后控制器对 IR 中的指令译码。

PC 还会按照指令长度及控制流规则更新。

其中：

$$
M[MAR]
$$

表示 MAR 指向的存储位置中的内容。

必须区分：

PC 保存下一条待取指令的地址。

MAR 保存当前访存地址。

IR 保存当前机器指令。

MDR 保存访存数据。

这四个寄存器不会因为某次取指过程中传送了相同内容，就具有相同作用。

### 九、机器语言、汇编语言和高级语言

| 语言   | 形式        | CPU 能否直接执行    |
| ---- | --------- | ------------- |
| 机器语言 | 二进制机器指令   | 能             |
| 汇编语言 | 指令助记符     | 不能，需要汇编       |
| 高级语言 | C、C++ 等程序 | 不能，需要相应语言处理过程 |

#### 真题 2：2015 年

计算机硬件能够直接执行的是：

I. 机器语言程序\
II. 汇编语言程序\
III. 硬件描述语言程序

答案：仅 I。

原因：

汇编语言是机器指令的符号化表示，需要汇编器进行转换。

硬件描述语言用于描述电路或数字系统，不能直接作为普通 CPU 的机器程序执行。

#### 真题 3：2024 年

题目问 CPU 能理解并直接执行：

I. 伪指令\
II. 微指令\
III. 机器指令\
IV. 汇编指令

答案：B，仅 II、III。

这里特别需要区分四个概念。

| 类型   | 含义              |
| ---- | --------------- |
| 机器指令 | ISA 规定的机器级指令    |
| 汇编指令 | 机器指令的助记符表示      |
| 伪指令  | 由汇编器处理、展开的汇编层构造 |
| 微指令  | 微程序控制器内部使用的控制信息 |

机器指令由 CPU 按 ISA 语义执行。

采用微程序控制的 CPU，还会由内部微程序控制器执行微指令。

汇编指令和伪指令不能直接作为 CPU 的机器指令使用。

易错点：微指令和机器指令不处于同一个抽象层次。

## 第四部分：高级语言到机器执行的完整过程

### 十、预处理、编译、汇编、链接、装载

这是明确的考试重点。

典型 C 语言程序的处理流程：

```text
hello.c
  │
  │ 预处理
  ▼
hello.i
  │
  │ 编译
  ▼
hello.s
  │
  │ 汇编
  ▼
hello.o
  │
  │ 链接
  ▼
可执行文件
  │
  │ 装载
  ▼
进程地址空间
  │
  ▼
CPU 执行机器指令
```

<Steps>

<Step>

    ### 10.1 预处理

主要完成宏展开、头文件包含、条件编译。

例如：

```c
#define N 100

```

预处理器会对宏进行展开。

</Step>

<Step>

    ### 10.2 编译

编译器主要将高级语言转换为较低层表示，并完成语法、语义分析以及优化、代码生成等工作。

在典型 GCC 教学流程中，可以生成汇编代码。

</Step>

<Step>

    ### 10.3 汇编

汇编器将汇编语言转换为机器级目标代码，生成目标文件。

目标文件中通常还包含符号表和重定位信息。

</Step>

<Step>

    ### 10.4 链接

链接器主要完成：

符号解析与重定位。

例如，一个源文件调用了另一个源文件中的函数。

链接器需要确定这个函数的具体位置，建立相应引用关系。

</Step>

<Step>

    ### 10.5 装载

装载阶段将程序建立为能够运行的进程映像。

操作系统为其准备运行所需的地址空间、相关映射和执行环境。

</Step>

</Steps>

#### 真题 4：2022 年

将高级语言源程序转换为可执行目标文件的主要过程是：

A. 预处理 → 编译 → 汇编 → 链接\
B. 预处理 → 汇编 → 编译 → 链接\
C. 预处理 → 编译 → 链接 → 汇编\
D. 预处理 → 汇编 → 链接 → 编译

答案：A。

需要记住：

$$
\boxed{\text{预处理}\rightarrow\text{编译}\rightarrow\text{汇编}\rightarrow\text{链接}}
$$

这是典型 C 工具链的流程。

不能将它机械推广为所有编程语言都必须经历完全相同的阶段。

#### 10.6 编译与解释的区别

模拟题问：

“翻译一句，执行一句”的程序是什么？

答案：解释程序。

传统教学中的区别如下：

| 编译方式           | 解释方式        |
| -------------- | ----------- |
| 通常先生成目标程序或低层表示 | 在运行时逐步解释执行  |
| 翻译和执行通常相对分离    | 翻译与执行紧密结合   |
| 编译结果可形成独立可执行文件 | 通常依赖解释器或运行时 |

但现代语言实现可能结合字节码和 JIT 编译，因此不能认为解释器一定严格逐行解释源代码。

## 第五部分：计算机性能指标——本章最重要的计算部分

### 十一、为什么主频高不代表计算机一定快？

先理解一个根本问题：

程序执行时间究竟取决于什么？

答案是：

1. 程序执行多少条机器指令；
2. 每条指令平均消耗多少时钟周期；
3. 一个时钟周期有多长。

这三个量构成本章最重要的公式。

### 十二、时钟周期与主频

#### 12.1 时钟周期

时钟周期是同步数字电路的基本时间单位。

记为：

$$
T_{\mathrm{clk}}
$$

#### 12.2 主频

主频是单位时间内的时钟周期数。

记为：

$$
f
$$

两者满足：

$$
\boxed{f=\frac{1}{T_{\mathrm{clk}}}}
$$

或者：

$$
\boxed{T_{\mathrm{clk}}=\frac{1}{f}}
$$

例如，CPU 主频为：

$$
f=2\,\mathrm{GHz}
$$

意味着：

$$
f=2\times10^9\,\mathrm{Hz}
$$

因此：

$$
T_{\mathrm{clk}} =\frac{1}{2\times10^9} =0.5\,\mathrm{ns}
$$

注意：

2 GHz 表示每秒有 20 亿个时钟周期，不意味着每秒一定执行 20 亿条指令。

一条指令可能需要多个周期。

超标量 CPU 也可能平均每周期完成多条指令。

#### 12.3 必须熟悉的单位

| 单位    | 数值                          |
| ----- | --------------------------- |
| 1 kHz | $10^3\,\mathrm{Hz}$    |
| 1 MHz | $10^6\,\mathrm{Hz}$    |
| 1 GHz | $10^9\,\mathrm{Hz}$    |
| 1 ms  | $10^{-3}\,\mathrm{s}$  |
| 1 μs  | $10^{-6}\,\mathrm{s}$  |
| 1 ns  | $10^{-9}\,\mathrm{s}$  |
| 1 ps  | $10^{-12}\,\mathrm{s}$ |

常见结果：

$$
1\,\mathrm{GHz}\rightarrow1\,\mathrm{ns}
$$

$$
2\,\mathrm{GHz}\rightarrow0.5\,\mathrm{ns}
$$

$$
4\,\mathrm{GHz}\rightarrow0.25\,\mathrm{ns}
$$

这些换算最好能够直接心算。

### 十三、时钟周期、机器周期与指令周期

三个概念容易混淆。

#### 13.1 时钟周期

同步电路的基本时序单位。

#### 13.2 机器周期

传统 CPU 教学模型中，完成某个基本操作所需要的时间。

例如取指机器周期、执行机器周期等。

#### 13.3 指令周期

从一条机器指令开始执行，到该指令完成所经历的过程。

传统模型中可以画成：

```text
       指令周期
           │
     ┌─────┴─────┐
     │           │
 取指阶段     执行阶段
     │           │
 若干时钟     若干时钟
   周期         周期
```

更复杂的指令还可能有间址、间接访存等过程。

#### 13.4 与流水线的关系

不能认为一条指令必须完全执行结束，下一条指令才能开始。

现代流水线 CPU 可以让多条指令的执行阶段重叠。

因此：

指令周期是描述单条指令执行过程的概念，CPI 是统计平均每条指令消耗的时钟周期数。

二者不能直接画等号。

### 十四、CPI：平均每条指令消耗的周期数

CPI 是 Cycles Per Instruction。

定义：

$$
\boxed{ \mathrm{CPI} = \frac{\text{总时钟周期数}}{\text{执行指令总条数}} }
$$

例如，一个程序执行 1000 条指令，消耗 3000 个时钟周期：

$$
\mathrm{CPI} =\frac{3000}{1000} =3
$$

说明平均每条指令消耗 3 个周期。

#### 14.1 为什么 CPI 是平均值？

因为程序中不同指令的执行成本可能不同。

例如：

| 指令类型 | 条数   | CPI |
| ---- | ---- | --- |
| 加法指令 | 1000 | 1   |
| 乘法指令 | 500  | 3   |
| 访存指令 | 500  | 5   |

总指令数：

$$
N=1000+500+500=2000
$$

总时钟周期数：

$$
C=1000\times1+500\times3+500\times5
$$

$$
C=5000
$$

平均 CPI：

$$
\boxed{\mathrm{CPI}_{\mathrm{avg}}=2.5}
$$

#### 14.2 加权平均 CPI

如果给的是各类指令所占比例：

$$
\boxed{ \mathrm{CPI}_{\mathrm{avg}} =\sum_{i=1}^{k}p_i\mathrm{CPI}_i }
$$

其中 $p_i$ 是第 $i$ 类指令占总指令数的比例。

注意：

$$
\sum_{i=1}^{k}p_i=1
$$

不能直接将各类 CPI 求普通算术平均。

#### 真题 5：2013 年

CPU 主频为：

$$
1.2\,\mathrm{GHz}
$$

指令比例和 CPI 如下：

| 类型 | 比例  | CPI |
| -- | --- | --- |
| A  | 50% | 2   |
| B  | 20% | 3   |
| C  | 10% | 4   |
| D  | 20% | 5   |

求 MIPS。

第一步：计算平均 CPI。

$$
\begin{aligned} \mathrm{CPI}_{\mathrm{avg}} &=0.5\times2+0.2\times3\\ &\quad+0.1\times4+0.2\times5\\ &=3 \end{aligned}
$$

第二步：计算 MIPS。

主频：

$$
f=1200\,\mathrm{MHz}
$$

因此：

$$
\mathrm{MIPS} =\frac{1200}{3}
$$

$$
\boxed{\mathrm{MIPS}=400}
$$

答案：C。

这类题最重要的是先求加权平均 CPI，再计算 MIPS。

### 十五、IPC：平均每个周期执行多少条指令

IPC 是 Instructions Per Cycle。

$$
\boxed{ \mathrm{IPC} = \frac{\text{执行指令数}}{\text{总时钟周期数}} }
$$

所以，在相同统计范围下：

$$
\boxed{\mathrm{IPC}=\frac{1}{\mathrm{CPI}}}
$$

例如：

$$
\mathrm{CPI}=2
$$

则：

$$
\mathrm{IPC}=0.5
$$

平均两个时钟周期完成一条指令。

如果：

$$
\mathrm{IPC}=2
$$

则：

$$
\mathrm{CPI}=0.5
$$

说明平均每周期完成两条指令。

这通常需要多发射或其他能够实现相应吞吐能力的硬件结构。

因此：

CPI 不一定大于或等于 1。

不要把超标量 CPU 的平均 CPI 与单条指令本身的执行延迟混淆。

### 十六、CPU 执行时间公式

这是本章最核心、必须熟练掌握的公式。

设：

$$
N=\text{动态执行的指令总条数}
$$

$$
\mathrm{CPI}=\text{平均每条指令消耗的周期数}
$$

$$
f=\text{CPU 主频}
$$

总时钟周期数为：

$$
C=N\times\mathrm{CPI}
$$

又因为：

$$
T_{\mathrm{clk}}=\frac{1}{f}
$$

所以：

$$
T_{\mathrm{CPU}}=C\times T_{\mathrm{clk}}
$$

最终得到：

$$
\boxed{ T_{\mathrm{CPU}} = N\times\mathrm{CPI}\times T_{\mathrm{clk}} }
$$

即：

$$
\boxed{ T_{\mathrm{CPU}} = \frac{N\times\mathrm{CPI}}{f} }
$$

需要理解：

$$
\text{执行时间} = \frac{\text{总周期数}}{\text{每秒周期数}}
$$

而不是只机械记忆公式。

#### 16.1 例题：直接计算

某程序执行：

$$
N=2\times10^9
$$

条指令，平均 CPI 为 1.5，CPU 主频为：

$$
3\,\mathrm{GHz}
$$

求 CPU 执行时间。

代入：

$$
T_{\mathrm{CPU}} = \frac{2\times10^9\times1.5} {3\times10^9}
$$

得到：

$$
\boxed{T_{\mathrm{CPU}}=1\,\mathrm{s}}
$$

#### 真题 6：2022 年

主频：

$$
1\,\mathrm{GHz}
$$

程序执行 10000 条指令。

其中：

80% 指令的 CPI 为 1；

20% 指令的 CPI 为 10。

求平均 CPI 和 CPU 时间。

第一步：

$$
\mathrm{CPI}_{\mathrm{avg}} =0.8\times1+0.2\times10 =2.8
$$

第二步：

$$
C=10000\times2.8=28000
$$

第三步：

$$
T=\frac{28000}{10^9} =2.8\times10^{-5}\,\mathrm{s}
$$

所以：

$$
\boxed{T=28\,\mu\mathrm{s}}
$$

答案：A，2.8 和 28 μs。

这道题主要考查加权平均和单位换算。

## 第六部分：指令执行速度与其他性能指标

### 十七、IPS、MIPS、FLOPS

#### 17.1 IPS

IPS 是 Instructions Per Second。

表示每秒执行多少条指令。

$$
\mathrm{IPS} = \frac{N}{T_{\mathrm{CPU}}}
$$

因为：

$$
T_{\mathrm{CPU}} =\frac{N\times\mathrm{CPI}}{f}
$$

所以：

$$
\boxed{\mathrm{IPS}=\frac{f}{\mathrm{CPI}}}
$$

#### 17.2 MIPS

MIPS 是 Million Instructions Per Second。

表示每秒执行多少百万条指令。

$$
\boxed{ \mathrm{MIPS} =\frac{f}{\mathrm{CPI}\times10^6} }
$$

如果主频单位直接使用 MHz：

$$
\boxed{ \mathrm{MIPS} =\frac{f_{\mathrm{MHz}}}{\mathrm{CPI}} }
$$

#### 真题 7：2023 年

主频：

$$
f=1.5\,\mathrm{GHz}
$$

指令条数：

$$
N=5\times10^5
$$

平均 CPI：

$$
1.2
$$

求指令执行速度和用户 CPU 时间。

第一步：计算 IPS。

$$
\mathrm{IPS} =\frac{1.5\times10^9}{1.2}
$$

$$
=1.25\times10^9
$$

所以：

$$
\boxed{\mathrm{IPS}=1.25\,\mathrm{GIPS}}
$$

第二步：计算 CPU 时间。

$$
T =\frac{5\times10^5\times1.2} {1.5\times10^9}
$$

$$
=4\times10^{-4}\,\mathrm{s}
$$

因此：

$$
\boxed{T=0.4\,\mathrm{ms}}
$$

答案：C。

#### 17.3 为什么 MIPS 高不一定代表性能好？

因为不同 ISA 的一条机器指令，可能完成完全不同的工作。

例如：

机器 A 执行一个任务需要 1000 万条指令。

机器 B 执行同一个任务只需要 300 万条指令。

即使 A 的 MIPS 更高，也不能直接证明它完成该任务更快。

比较同一任务的真实性能，优先看执行时间。

### 十八、FLOPS：浮点运算速度

FLOPS 是 Floating-point Operations Per Second。

表示每秒完成多少次浮点运算。

与 MIPS 不同，它统计的是浮点操作数，而不是机器指令数。

#### 18.1 常见单位

| 单位     | 对应浮点运算次数/秒    |
| ------ | ------------- |
| MFLOPS | $10^6$    |
| GFLOPS | $10^9$    |
| TFLOPS | $10^{12}$ |
| PFLOPS | $10^{15}$ |
| EFLOPS | $10^{18}$ |

#### 真题 8：2011 年

哪一个指标描述浮点数操作速度？

A. MIPS\
B. CPI\
C. IPC\
D. MFLOPS

答案：D。

#### 真题 9：2021 年

某超级计算机浮点运算速度为：

$$
93.0146\,\mathrm{PFLOPS}
$$

问每秒约完成多少次浮点操作。

因为：

$$
1\,\mathrm{PFLOPS} =10^{15}\,\mathrm{FLOPS}
$$

所以：

$$
93.0146\times10^{15} =9.30146\times10^{16}
$$

又因为：

$$
1\text{ 亿亿}=10^{16}
$$

所以约为：

$$
\boxed{9.3\text{ 亿亿次/秒}}
$$

这道题的核心是数量级换算。

### 十九、响应时间与吞吐量

#### 19.1 响应时间

响应时间关注：

完成一个任务需要多久。

例如，某程序从启动到结束耗时 5 秒。

#### 19.2 吞吐量

吞吐量关注：

单位时间完成多少个任务。

例如，一台服务器每秒完成 1000 个请求。

#### 19.3 二者的区别

假设一个处理器需要 10 秒完成某个任务。

增加处理器数量后，系统可以并行处理多个相互独立的任务。

系统总吞吐量可能提高。

但如果原来的单个任务不能并行执行，那么该任务的响应时间可能几乎不变。

因此：

$$
\boxed{\text{吞吐量提高}\not\Rightarrow\text{单任务响应时间必然缩短}}
$$

这是多处理器性能题的重要思想。

### 二十、CPU 时间与墙钟时间

这里尤其容易混淆。

<Tabs items={['CPU 时间', '墙钟时间']} defaultIndex={0}>

<Tab value="CPU 时间">

CPU 执行时间是处理器实际为程序执行工作消耗的处理时间。

它可以进一步区分为：

用户 CPU 时间和系统 CPU 时间。

</Tab>

<Tab value="墙钟时间">

墙钟时间是程序开始到结束的实际经历时间。

其中可能包含：

程序执行、I/O 等待、调度等待等。

</Tab>

</Tabs>

#### 模拟题 2：CPU 时间占比

CPU 主频：

$$
f=2\,\mathrm{GHz}
$$

平均 CPI：

$$
1.2
$$

程序执行：

$$
4\times10^9
$$

条指令。

程序从启动到结束共经历 4 秒。

求 CPU 执行时间占总经历时间的比例。

第一步：计算 CPU 时间。

$$
T_{\mathrm{CPU}} = \frac{4\times10^9\times1.2}{2\times10^9} =2.4\,\mathrm{s}
$$

第二步：计算比例。

$$
\frac{2.4}{4}\times100\%=60\%
$$

因此：

$$
\boxed{60\%}
$$

答案：B。

剩余 1.6 秒可能包含等待等时间。

本题的表述需要按照“CPU 执行时间 / 程序总经历时间”理解，不能直接解释为 CPU 对所有进程的总体利用率。

## 第七部分：性能比较与优化计算

### 二十一、性能与执行时间的关系

对完成同一个任务的两台机器：

$$
\boxed{\text{性能}\propto\frac{1}{\text{执行时间}}}
$$

假设：

机器 A 执行时间为 4 秒。

机器 B 执行时间为 8 秒。

则：

$$
\frac{P_A}{P_B} =\frac{T_B}{T_A} =\frac{8}{4}=2
$$

说明 A 的性能是 B 的 2 倍。

注意：性能比与执行时间比互为倒数。

#### 21.1 加速比

定义：

$$
\boxed{ S=\frac{T_{\mathrm{old}}}{T_{\mathrm{new}}} }
$$

如果：

$$
T_{\mathrm{old}}=20\,\mathrm{s}
$$

$$
T_{\mathrm{new}}=10\,\mathrm{s}
$$

则：

$$
S=2
$$

表示性能加速 2 倍。

执行时间减少的比例则是：

$$
\frac{20-10}{20}\times100\%=50\%
$$

不要把“速度提高 100%”与“执行时间减少 100%”混淆。

### 二十二、性能优化题：三个参数必须一起考虑

核心公式：

$$
T=\frac{N\times\mathrm{CPI}}{f}
$$

优化之后：

$$
T' =\frac{N'\times\mathrm{CPI}'}{f'}
$$

因此：

$$
\boxed{ \frac{T'}{T} = \frac{N'}{N} \times \frac{\mathrm{CPI}'}{\mathrm{CPI}} \times \frac{f}{f'} }
$$

这条式子非常重要。

无论题目说：

指令数减少、主频提高、CPI 上升、时钟周期增加，都可以使用。

#### 真题 10：2014 年

程序原来执行时间为 20 秒。

编译优化后：

指令条数减少到原来的 70%。

CPI 增加到原来的 1.2 倍。

主频不变。

求新执行时间。

由公式：

$$
\frac{T'}{T} =0.7\times1.2=0.84
$$

所以：

$$
T'=20\times0.84
$$

得到：

$$
\boxed{T'=16.8\,\mathrm{s}}
$$

答案：D。

### 为什么不是 14 秒？

14 秒只考虑指令数减少：

$$
20\times0.7=14
$$

但忽略了 CPI 增加。

这正是题目设置的陷阱。

优化代码可能减少了指令条数，却让剩余指令更复杂、平均 CPI 上升。

所以不能只考虑一个参数。

### 二十三、两台机器性能比较

#### 真题 11：2017 年

两台机器具有相同 ISA。

机器 M1：

$$
f_1=1.5\,\mathrm{GHz}
$$

$$
\mathrm{CPI}_1=2
$$

机器 M2：

$$
f_2=1.2\,\mathrm{GHz}
$$

$$
\mathrm{CPI}_2=1
$$

求执行时间比：

$$
\frac{T_1}{T_2}
$$

按题目通常假设，两台机器执行该程序的指令数相同。

于是：

$$
\frac{T_1}{T_2} = \frac{N\times2/(1.5\times10^9)} {N\times1/(1.2\times10^9)}
$$

约去 $N$：

$$
=\frac{2}{1.5}\times1.2
$$

得到：

$$
\boxed{\frac{T_1}{T_2}=1.6}
$$

答案：C。

说明 M1 虽然主频更高，但因为 CPI 更大，最终执行时间反而更长。

注意此题关于指令条数相同的假设。

严格而言，仅有“相同 ISA”并不必然保证动态指令数一致；如果使用不同代码或编译器，仍需考虑实际指令数。

### 二十四、王道模拟题：编译器与机器共同影响性能

这是本章非常有代表性的综合计算题。

M1 的主频：

$$
800\,\mathrm{MHz}
$$

M2 的主频：

$$
400\,\mathrm{MHz}
$$

两台机器的 CPI 和编译器生成的指令比例：

| 指令 | M1 CPI | M2 CPI | 编译器 C1 比例 | 编译器 C2 比例 |
| -- | ------ | ------ | --------- | --------- |
| A  | 2      | 1      | 30%       | 30%       |
| B  | 3      | 2      | 50%       | 20%       |
| C  | 4      | 1.5    | 20%       | 50%       |

已知指令总条数相同。

求：

使用 C1 时，M1 的执行速度是 M2 的多少倍？

使用 C2 时，M2 的执行速度是 M1 的多少倍？

#### 24.1 使用 C1

M1 平均 CPI：

$$
\mathrm{CPI}_{M1,C1} =0.3\times2+0.5\times3+0.2\times4
$$

$$
=2.9
$$

M2 平均 CPI：

$$
\mathrm{CPI}_{M2,C1} =0.3\times1+0.5\times2+0.2\times1.5
$$

$$
=1.6
$$

两机指令数相同，因此：

$$
\frac{V_{M1}}{V_{M2}} = \frac{T_{M2}}{T_{M1}}
$$

$$
= \frac{1.6/400}{2.9/800}
$$

$$
\approx1.103
$$

因此：

$$
\boxed{V_{M1}\approx1.1V_{M2}}
$$

#### 24.2 使用 C2

M1 的平均 CPI：

$$
0.3\times2+0.2\times3+0.5\times4=3.2
$$

M2 的平均 CPI：

$$
0.3\times1+0.2\times2+0.5\times1.5=1.45
$$

注意题目问的是 M2 相对于 M1。

所以：

$$
\frac{V_{M2}}{V_{M1}} = \frac{T_{M1}}{T_{M2}}
$$

$$
= \frac{3.2/800}{1.45/400}
$$

$$
\approx1.103
$$

因此：

$$
\boxed{V_{M2}\approx1.1V_{M1}}
$$

最终答案：

$$
\boxed{1.1,\quad1.1}
$$

### 这道题考查什么？

它同时考查三个能力：

加权计算平均 CPI。

根据 CPI 和主频计算执行时间。

正确判断性能比的方向。

做这类题的万能方法：先分别求每台机器的总执行时间，再求速度比。

## 第八部分：局部优化与阿姆达尔定律

### 二十五、为什么局部性能提高很多，总体可能只提高一点？

因为一个程序往往包含不同部分。

例如：

CPU 计算部分耗时 90 秒。

I/O 部分耗时 10 秒。

即使 CPU 速度提高，I/O 时间不会自动消失。

#### 真题 12：2012 年

程序总执行时间：

$$
100\,\mathrm{s}
$$

其中 CPU 时间：

$$
90\,\mathrm{s}
$$

I/O 时间：

$$
10\,\mathrm{s}
$$

CPU 速度提高 50%，I/O 速度不变。

求新的总时间。

#### 25.1 注意“速度提高 50%”的含义

速度变为原来的：

$$
1.5
$$

倍。

因此 CPU 时间变为：

$$
T'_{\mathrm{CPU}} =\frac{90}{1.5}=60\,\mathrm{s}
$$

I/O 时间保持：

$$
10\,\mathrm{s}
$$

所以：

$$
T'=60+10
$$

得到：

$$
\boxed{T'=70\,\mathrm{s}}
$$

答案：D。

不能直接计算：

$$
100\times0.5=50\,\mathrm{s}
$$

因为 CPU 速度提高 50%，不等于程序总时间减少 50%。

### 二十六、阿姆达尔定律

阿姆达尔定律用于衡量：

仅优化程序的一部分，对整体性能有多大影响。

设：

$p$：原执行时间中可优化部分所占比例；

$k$：这部分加速的倍数。

则整体加速比：

$$
\boxed{ S= \frac{1}{(1-p)+\frac{p}{k}} }
$$

#### 26.1 用上一道真题验证

$$
p=0.9
$$

$$
k=1.5
$$

所以：

$$
S = \frac{1}{0.1+\frac{0.9}{1.5}}
$$

$$
=\frac{1}{0.7}
$$

$$
\boxed{S\approx1.429}
$$

新执行时间：

$$
T'=\frac{100}{1.429}\approx70\,\mathrm{s}
$$

与直接计算一致。

#### 26.2 极限情况

如果优化部分可以获得无限大加速：

$$
k\rightarrow\infty
$$

那么：

$$
\boxed{ S_{\max}=\frac{1}{1-p} }
$$

例如，程序 80% 的时间都在某个可优化模块中：

$$
p=0.8
$$

即使让这个模块无限快，整体最大加速比也只有：

$$
S_{\max} =\frac{1}{0.2} =5
$$

这说明性能优化受未优化部分限制。

#### 26.3 多核处理器的应用

如果程序有比例 $p$ 可以在 $n$ 个处理器上理想并行：

$$
\boxed{ S(n)=\frac{1}{(1-p)+p/n} }
$$

这里忽略了同步、通信、调度等额外开销。

因此增加处理器并不保证获得线性加速。

### 一个资料中的辨析点

我核对到两道措辞接近、但答案口径不同的模拟题。

某章节模拟题将“增加处理器数量”视为可能改善程序完成时间的措施，因此其答案为包含全部措施的 D。实际分析应结合程序是否并行化。

2027 王道第二套卷中的相关题则强调“不同处理器同时执行不同程序”主要提高系统吞吐量，不能据此认定某一个程序的 CPU 时间缩短，因此选择 C。

两者应当按照题目条件理解：

如果单个程序能够并行化，增加处理器可能缩短它的完成时间；如果只是不同处理器分别执行不同程序，通常主要提高吞吐量，而非单程序执行速度。

不能机械背答案。

## 第九部分：机器字长、存储字长与寻址容量

### 二十七、机器字长是什么？

机器字长通常指 CPU 一次能够处理的基本二进制数据宽度。

例如：

32 位计算机。

64 位计算机。

在传统 408 模型中，机器字长通常与 ALU 和通用寄存器的基本数据宽度密切相关。

但不能直接推断所有寄存器、所有总线都是这个宽度。

#### 27.1 四种容易混淆的宽度

| 名称     | 含义               |
| ------ | ---------------- |
| 机器字长   | CPU 处理的基本数据宽度    |
| 存储字长   | 一个存储字包含的二进制位数    |
| 指令字长   | 一条机器指令编码的位数      |
| 数据通路宽度 | 某条数据通路一次可并行传输多少位 |

这四个概念没有必然相等关系。

例如，一台 64 位 CPU 可以具有：

32 位长的固定长度指令；

128 位宽的向量寄存器；

64 位通用寄存器。

#### 真题 13：2020 年

题目问通常与机器字长相同的部件宽度。

I. ALU\
II. 指令寄存器\
III. 通用寄存器\
IV. 浮点寄存器

参考答案：

B，仅 I、III。

在常见教材模型中：

ALU 的基本运算位数和通用寄存器位数对应机器字长。

指令寄存器位数受指令编码长度影响。

浮点寄存器则可能有不同宽度。

需要注意，“一定”在现代复杂处理器中并不适合不加条件地推广；应按题目的传统机器字长定义作答。

### 二十八、MAR 与 MDR 的位数

#### 28.1 MAR

MAR 保存访存地址。

如果 MAR 为 $n$ 位，在经典简化模型中，可以表示：

$$
\boxed{2^n}
$$

个不同的地址。

#### 28.2 MDR

MDR 保存访存数据。

它的宽度与数据传送或存储器接口的组织有关。

在传统单字存取模型中，MDR 位数通常与存储字长对应。

但在更复杂的系统中，不能仅凭 MAR 位数或机器字长断定 MDR 位数。

### 二十九、按字节编址与按字编址

这是容量计算题最重要的基础。

#### 29.1 按字节编址

一个地址对应一个字节。

$$
1\,\mathrm{B}=8\,\mathrm{bit}
$$

如果有：

$$
2^{20}
$$

个地址，则理论可寻址容量是：

$$
2^{20}\,\mathrm{B}
$$

即：

$$
\boxed{1\,\mathrm{MiB}}
$$

#### 29.2 按字编址

一个地址对应一个存储字。

假设字长：

$$
16\,\mathrm{bit}=2\,\mathrm B
$$

地址位数仍然为 20。

可寻址字数为：

$$
2^{20}
$$

所以可寻址容量：

$$
2^{20}\times2\,\mathrm B
$$

即：

$$
\boxed{2\,\mathrm{MiB}}
$$

为什么两个结果不同？

因为一个地址对应的空间大小不同。

#### 29.3 通用计算公式

假设地址位数为 $n$，每个可寻址单元大小为 $W$ bit。

则：

$$
\boxed{C=2^n\times W\ \mathrm{bit}}
$$

如果每个可寻址单元大小为 $b$ 字节：

$$
\boxed{C=2^n\times b\ \mathrm B}
$$

反过来，如果已知容量与编址单位：

$$
N_{\mathrm{addr}} = \frac{\text{总容量}}{\text{编址单位大小}}
$$

需要的最少地址位数：

$$
\boxed{ n=\left\lceil\log_2N_{\mathrm{addr}}\right\rceil }
$$

注意，如果地址数刚好是 2 的整数次幂，可以直接取对数。

### 三十、综合例题：MAR 位数计算

这是根据学习讲义编写的训练题。

某计算机主存容量为：

$$
128\,\mathrm{KiB}
$$

存储字长为：

$$
16\,\mathrm{bit}
$$

求按字节编址与按字编址时所需的 MAR 位数。

#### 30.1 按字节编址

$$
128\,\mathrm{KiB}=2^{17}\,\mathrm B
$$

一个地址对应一个字节。

所以需要：

$$
2^{17}
$$

个地址。

得到：

$$
\boxed{\mathrm{MAR}=17\text{ 位}}
$$

#### 30.2 按字编址

每个存储字：

$$
16\,\mathrm{bit}=2\,\mathrm B
$$

存储字数量：

$$
\frac{2^{17}}{2} =2^{16}
$$

因此：

$$
\boxed{\mathrm{MAR}=16\text{ 位}}
$$

### 结论

MAR 位数由可寻址单元数量决定，而不是单纯由容量的 bit 数决定。

### 三十一、地址空间与实际主存容量

这也是经常被忽略的陷阱。

假设 CPU 可产生 32 位地址，按字节编址。

则理论地址空间：

$$
2^{32}\,\mathrm B
$$

即：

$$
\boxed{4\,\mathrm{GiB}}
$$

但这不意味着计算机一定安装了 4 GiB 的物理内存。

它可能只安装 1 GiB。

另外，真实机器的地址空间中还可能包含设备映射等区域。

因此：

最大可寻址范围不一定等于实际配置的主存容量。

也不要混淆虚拟地址位数、物理地址位数与实际主存容量。

## 第十部分：重点模拟题与综合题型

### 三十二、模拟题：指令占比与时间占比

这是 2027 王道模拟卷中的重点计算题。

某类指令 $I$：

CPI 为 20。

占程序指令总数的 10%。

其他指令平均 CPI 为 5。

问这类指令占总 CPU 执行时间的比例。

#### 32.1 计算程序平均 CPI

$$
\mathrm{CPI}_{\mathrm{avg}} =0.1\times20+0.9\times5
$$

$$
=6.5
$$

#### 32.2 计算目标指令占用的周期比例

目标指令贡献的平均周期数：

$$
0.1\times20=2
$$

所以时间占比：

$$
p=\frac{2}{6.5}
$$

$$
\boxed{p\approx30.77\%}
$$

注意：指令数量占 10%，不代表 CPU 时间只占 10%。

因为不同指令的执行成本不同。

#### 32.3 进一步优化

假设将该类指令的 CPI 从 20 降低到 10。

但 CPU 时钟周期延长 10%。

问是否值得优化？

新平均 CPI：

$$
0.1\times10+0.9\times5=5.5
$$

设原时钟周期为 $\tau$。

原执行时间：

$$
T_{\mathrm{old}}=6.5N\tau
$$

新时钟周期：

$$
\tau'=1.1\tau
$$

所以：

$$
T_{\mathrm{new}} =5.5N\times1.1\tau
$$

$$
=6.05N\tau
$$

计算：

$$
\frac{T_{\mathrm{new}}}{T_{\mathrm{old}}} =\frac{6.05}{6.5} \approx0.93077
$$

新执行时间约为原来的 93.08%。

因此：

$$
\boxed{\text{值得优化}}
$$

执行时间减少约：

$$
6.92\%
$$

对应加速比：

$$
S=\frac{6.5}{6.05}\approx1.0744
$$

这一题同时考查：

平均 CPI、时间占比、时钟周期变化、性能比较。

### 三十三、模拟题：由总时间反推替换指令数

考虑一道进阶题。

程序原执行时间为 12 秒。

替换部分指令后，执行时间为 10 秒。

新指令：

每次 Cache 未命中额外增加 100 个时钟周期。

求替换的指令数量。

#### 33.1 原指令平均 CPI

未命中率：

1-0.9=0.1

$$
94+0.1\times100

$$
\boxed{104}

#### 33.2 新指令平均 CPI

1-0.99=0.01

\boxed{4}

#### 33.3 每替换一条指令节省多少周期？

104-4=100

个时钟周期。

CPU 主频：

#### 34.1 总指令数

$$
N=4500+200+500+800

$$
\boxed{N=6000}

\boxed{C=7200}

## 第十一部分：跨章节知识点与易错题

### 三十五、冯·诺依曼结构与哈佛结构

| 对比    | 冯·诺依曼结构      | 哈佛结构         |
| ----- | ------------ | ------------ |
| 指令与数据 | 经典模型采用统一存储体系 | 典型结构分离       |
| 指令访问  | 按指令地址取指      | 从指令存储路径取指    |
| 数据访问  | 按操作数地址访存     | 从数据存储路径访存    |
| 特点    | 存储程序模型经典     | 有利于并行取指与数据访问 |

注意：

现代 CPU 即使采用分离的 L1 指令 Cache 和数据 Cache，也不能直接断言整个系统就是完全分离的哈佛结构。

需要区分缓存组织与软件可见的存储模型。

### 三十六、操作数与操作数地址如何区分？

#### 真题 14：2023 年

某通用寄存器中存放的是操作数或操作数地址。

CPU 根据什么判断？

答案：操作数的寻址方式。

举例：

寄存器 R1 中存放：

$$
1000
$$

如果采用寄存器寻址：

操作数就是 R1 中的 1000。

如果采用寄存器间接寻址：

R1 中的 1000 被当作地址。

CPU 需要访问该地址指向的存储单元，获取真正操作数。

所以：

同一个二进制值究竟是数据还是地址，由当前指令的语义和寻址方式决定。

这与前面“指令和数据的区分”具有相同的基本思想：二进制位串没有脱离解释上下文的固定意义。

### 三十七、编址单位与存取单位不同

假设：

主存按字节编址。

一次主存存取可以读写 32 bit。

这意味着：

一个地址对应：

$$
1\,\mathrm B
$$

一次存取的数据宽度：

$$
32\,\mathrm{bit}=4\,\mathrm B
$$

两者完全可以同时成立。

因此：

$$
\boxed{\text{编址单位}\neq\text{存取单位}}
$$

不能因为一次读 4 字节，就认为地址每增加 1 必须跨越 4 字节。

### 三十八、机器字长与地址宽度不同

假设一台机器：

机器字长是 64 位。

地址宽度是 32 位。

不考虑其他限制，按字节编址时，其 32 位地址形成的理论地址空间仍为：

$$
2^{32}\,\mathrm B
$$

不能因为机器字长为 64 位，就直接计算：

$$
2^{64}\,\mathrm B
$$

机器字长描述的是基本数据处理宽度。

地址位数决定的是能够编码多少个地址。

这两个概念必须分开。

| 冯·诺依曼机的核心思想是存储程序                  | 对  | 最重要的基本思想        |
| 汇编语言能被 CPU 直接执行                   | 错  | 需要汇编处理          |
| 机器指令能被 CPU 直接执行                   | 对  | CPU 执行机器级指令     |
| 编译和链接是一回事                         | 错  | 作用不同            |
| CPI 一定大于或等于 1                     | 错  | 超标量平均 CPI 可小于 1 |
| IPC 与 CPI 在相同口径下互为倒数              | 对  | 定义直接决定          |
| 指令数量占比等于 CPU 时间占比                 | 错  | 不同指令的 CPI 不同    |
| MIPS 越高，不同 ISA 的计算机一定越快           | 错  | 单条指令工作量可能不同     |
| 多核数量翻倍，单程序性能一定翻倍                  | 错  | 受可并行比例和开销影响     |
| 机器字长一定等于指令字长                      | 错  | 指令长度可以不同        |
| 地址位数为 $n$，最多可编码 $2^n$ 个地址 | 对  | 二进制编码规律         |
| 按字节编址意味着每次只能读 1 字节                | 错  | 存取单位与编址单位不同     |
| 实际物理内存一定等于最大可寻址容量                 | 错  | 两者不同            |

尤其要警惕题目中的：

“必然”“一定”“全部”“任何情况下”“总是”。

很多概念题的错误选项不是完全没有道理，而是把有条件成立的结论说成无条件成立。

## 第十四部分：综合训练（建议先自己做）

下面六道题是根据本章考点设计的补充训练，并非冒充历年真题。

### 训练 1：主频与周期

某 CPU 主频为：

$$
2.5\,\mathrm{GHz}
$$

求时钟周期。

解析：

$$
T_{\mathrm{clk}} =\frac{1}{2.5\times10^9}
$$

$$
\boxed{T_{\mathrm{clk}}=0.4\,\mathrm{ns}}
$$

### 训练 2：加权 CPI

某程序有三类指令：

| 类型 | 比例  | CPI |
| -- | --- | --- |
| A  | 40% | 1   |
| B  | 40% | 2   |
| C  | 20% | 5   |

求平均 CPI。

解析：

$$
\mathrm{CPI}_{\mathrm{avg}} =0.4\times1+0.4\times2+0.2\times5
$$

$$
\boxed{\mathrm{CPI}_{\mathrm{avg}}=2.2}
$$

### 训练 3：CPU 执行时间

CPU 主频 2 GHz。

程序执行：

$$
10^8
$$

条指令。

平均 CPI 为 4。

求执行时间。

$$
T=\frac{10^8\times4}{2\times10^9}
$$

$$
\boxed{T=0.2\,\mathrm{s}}
$$

### 训练 4：指令优化

程序原执行时间为 10 秒。

优化后：

动态指令条数减少 20%。

CPI 增加 10%。

主频提高 25%。

求新的执行时间。

$$
\frac{T'}{T} = \frac{0.8\times1.1}{1.25}
$$

$$
=0.704
$$

所以：

$$
T'=10\times0.704
$$

$$
\boxed{T'=7.04\,\mathrm{s}}
$$

加速比：

$$
S=\frac{10}{7.04}
$$

$$
\boxed{S\approx1.420}
$$

### 训练 5：地址空间

某主存地址为 24 位，按字节编址。

求理论最大可寻址空间。

$$
C=2^{24}\,\mathrm B
$$

$$
\boxed{C=16\,\mathrm{MiB}}
$$

如果改为按 32 位字编址，而地址仍然为 24 位，则：

$$
32\,\mathrm{bit}=4\,\mathrm B
$$

所以：

$$
C=2^{24}\times4
$$

$$
\boxed{C=64\,\mathrm{MiB}}
$$

### 训练 6：阿姆达尔定律

某程序中：

70% 的执行时间可以优化。

优化后该部分速度提高为原来的 4 倍。

剩余部分不变。

求整体加速比。

$$
S= \frac{1}{0.3+0.7/4}
$$

$$
=\frac{1}{0.475}
$$

$$
\boxed{S\approx2.105}
$$

虽然局部速度提高到 4 倍，但整体只提高约 2.11 倍。

如果把可优化部分进一步提升到无限快：

$$
S_{\max} =\frac{1}{0.3}
$$

$$
\boxed{S_{\max}\approx3.333}
$$

这说明局部加速存在整体性能上限。

## 第十五部分：考场解题方法总结

### 三十九、性能计算题的统一思路

遇到计算机性能题，不要先找可以直接套用的数字。

要先判断题目究竟要求：

CPU 执行时间、平均 CPI、主频、MIPS、性能比，还是加速比。

### 第一步：确定指令数

如果给出了各类指令数量：

$$
N=\sum_iN_i
$$

如果给出了指令比例，就先计算平均 CPI。

### 第二步：计算总周期数

$$
\boxed{C=\sum_iN_i\mathrm{CPI}_i}
$$

或者：

$$
\boxed{C=N\times\mathrm{CPI}_{\mathrm{avg}}}
$$

### 第三步：计算执行时间

$$
\boxed{T=\frac{C}{f}}
$$

### 第四步：若涉及性能比较

$$
\boxed{ \frac{P_A}{P_B}=\frac{T_B}{T_A} }
$$

### 第五步：若涉及优化

$$
\boxed{ \frac{T'}{T} = \frac{N'}{N} \times \frac{\mathrm{CPI}'}{\mathrm{CPI}} \times \frac{f}{f'} }
$$

这五步可以解决本章绝大多数性能计算题。

### 四十、容量计算题的统一思路

容量题最重要的是分清三个量：

地址位数、编址单位大小、总容量。

设：

地址位数为 $n$。

每个可寻址单元大小为 $W$ bit。

则：

$$
\boxed{ C=2^nW\ \mathrm{bit} }
$$

反过来求 MAR：

$$
\boxed{ n= \left\lceil \log_2 \left( \frac{\text{容量}}{\text{寻址单位大小}} \right) \right\rceil }
$$

解题顺序：

先看按字节还是按字编址，再求地址数量，最后处理容量单位。

不要将机器字长直接代入存储容量公式，除非题目已经说明一个可寻址单元就是一个机器字。

### 2. 核心公式

| 考点     | 公式                                                           |
| ------ | ------------------------------------------------------------ |

### 3. 本章需要真正掌握的三个能力

第一，能解释一条高级语言程序如何经过语言处理、装载，最终被 CPU 执行。

包括 ISA、存储程序、PC、MAR、MDR、IR、控制器的作用。

第二，看到任何性能题，都能从指令数、CPI、主频三个因素展开计算。

不仅会计算执行时间，还应会比较两台机器、判断优化是否值得、求平均 CPI、MIPS 和整体加速比。

第三，能够把所有容易混淆的“位数”和“容量”分开。

机器字长、指令字长、存储字长、MAR 位数、地址空间、数据通路宽度、实际主存容量分别具有不同含义。

本章可以按照下列顺序复习：

| ③  | PC、IR、MAR、MDR | 能独立描述一次典型取指     |
| ④  | CPI、主频、CPU 时间 | 不看公式表也能完成计算     |
| ⑤  | 加权 CPI 与性能比较  | 能独立解出两机比较题      |

| ⑦  | 机器字长与寻址容量     | 能处理按字节、按字编址问题   |
| ⑧  | 历年真题与王道模拟题    | 能解释正确答案及错误选项原因  |

本章最重要的最终结论：

$$
\boxed{ T_{\mathrm{CPU}} = \frac{\text{指令总条数}\times\text{平均 CPI}}{\text{主频}} }
$$

整个计算机组成原理后续的性能分析，几乎都能回到这条公式。

Cache 未命中可能导致 CPI 增大；流水线与超标量技术可能提高指令吞吐率；编译优化可能改变指令数；更快的数据通路可能缩短时钟周期。

所以，不要把第一章看作单纯的概念性绪论。

第一章实际上建立了计算机组成原理最重要的性能分析框架。把它彻底掌握，后面学习指令系统、CPU、Cache 和流水线时，就能清楚地理解每一种硬件设计究竟在优化什么。
