### 核心模型对照

<Tabs items={['三大性能量', '加速与瓶颈', '容量与编址']} defaultIndex={0}>
<Tab value="三大性能量">

$IC$ 是动态执行指令数，$CPI$ 是平均每条指令所需周期数，$f$ 是时钟频率；于是总周期数 $C=IC\times CPI$，CPU 时间 $T=C/f$。在相同统计口径下，$IPC=1/CPI$。

</Tab>
<Tab value="加速与瓶颈">

若**原执行时间**中占比 $p$ 的部分加速 $s$ 倍，则整体加速比为：

$$
S=\frac{1}{(1-p)+p/s}
$$

$p$ 是时间比例，而不是指令数量比例。

</Tab>
<Tab value="容量与编址">

$n$ 位 MAR 最多表示 $2^n$ 个地址。若每个地址对应 $W$ 字节，可寻址容量为 $2^nW$ 字节。**按字节编址**时 $W=1$；数据总线宽度不能直接替代 $W$。

</Tab>
</Tabs>

<Step>

把 GHz、MHz 换算为 Hz，毫秒与微秒换算为秒。

</Step>
<Step>

### 建立周期数

使用 $C=\sum_i IC_iCPI_i$；若题目给指令比例，则 $CPI=\sum_i p_iCPI_i$。

</Step>

</Step>

## 第一部分：计算机系统的基本原理

### 二、计算机发展历程

这一节通常作为低频识记内容。

##### 1. 四代计算机

| 代次  | 主要逻辑元件       | 典型特征           |
| --- | ------------ | -------------- |
| 第一代 | 电子管          | 体积大、功耗高、机器语言为主 |
| 第二代 | 晶体管          | 可靠性提高、高级语言发展   |
| 第三代 | 中小规模集成电路     | 集成度提高、操作系统发展   |
| 第四代 | 大规模及超大规模集成电路 | 微处理器广泛应用       |

注意：这是传统教材按照主要逻辑元件进行的分类。

##### 2. 为什么计算机使用二进制？

并非因为二进制的数字更少，或者天然比十进制计算速度快。

主要原因是：

- 电子电路容易形成两个可区分的稳定状态。
- 二进制运算规则简单。
- 二进制与布尔逻辑直接对应。
- 在一定噪声条件下，两个稳定电平更容易可靠区分。

考点：二进制既方便逻辑设计，也适合数字电路的物理实现。

### 三、计算机系统的层次结构

#### 3.1 计算机系统由什么组成？

$$
\boxed{\text{计算机系统}=\text{硬件系统}+\text{软件系统}}
$$

硬件包括 CPU、主存、外存、总线和 I/O 设备。

软件包括系统软件与应用软件。

| 系统软件    | 应用软件      |
| ------- | --------- |
| 操作系统    | 浏览器       |
| 编译程序    | 文字处理程序    |
| 汇编程序    | 图像编辑软件    |
| 链接程序    | 游戏        |
| 数据库管理系统 | 面向用户的业务软件 |

【竟成·模拟二】

下列软件不属于系统软件的是：

A. 编译程序

B. 操作系统

C. 文本处理程序

D. 数据库管理系统

答案：C。

判断方法不是看软件是否复杂，而是看它主要负责提供基础运行环境，还是完成具体应用任务。

#### 3.2 计算机体系结构与计算机组成

这是后面全部章节的基础。

二者最重要的区别：

计算机体系结构规定机器对程序员呈现什么功能，计算机组成研究这些功能在硬件中怎样实现。

举个例子。

假设两颗 CPU 都支持：

```asm
ADD R1, R2, R3
```

表示将两个寄存器的数据相加。

它们可以采用不同的内部实现：

| CPU A     | CPU B     |
| --------- | --------- |
| 简单流水线     | 超标量流水线    |
| 顺序执行      | 乱序执行      |
| 较小的 Cache | 较大的 Cache |
| 较低主频      | 较高主频      |

两者可能都正确执行同一段机器代码。

也就是说：

ISA 可以相同，微体系结构和性能却完全不同。

##### ISA 到底是什么？

ISA（Instruction Set Architecture，指令集体系结构）是软硬件之间的重要接口。

通常包含：

- 机器指令的语义与编码。
- 程序员可见的寄存器。
- 数据类型与寻址方式。
- 软件必须遵守的相关体系结构规则。

通常不直接规定：

- Cache 具体容量。
- 流水线级数。
- 具体运算电路。
- 控制器是硬布线还是微程序实现。

##### 一道自编判断题

以下哪些通常属于 ISA 的规定？

Ⅰ. 机器指令编码

Ⅱ. Cache 组相联度

Ⅲ. 通用寄存器的体系结构编号

Ⅳ. 流水线级数

答案：Ⅰ、Ⅲ。

记住这个判断方法：

> 软件为了正确使用机器，必须知道的规则，通常偏向 ISA；硬件内部如何实现这些规则，通常属于计算机组成。

#### 3.3 软硬件逻辑功能等价性

同一个功能可能由软件实现，也可能由硬件实现。

例如浮点乘法：

- 有专门浮点运算单元时，可以直接通过硬件完成。
- 没有相应硬件时，也可以使用软件例程模拟。

在保证相同语义的前提下，两种实现能够得到相应的计算结果。

但它们在速度、成本、能耗和灵活性方面通常不同。

因此：

逻辑功能相同，不代表实现方式相同，更不代表性能相同。

#### 3.4 什么叫“透明”？

计算机组成原理中经常出现：

“某部分对程序员透明。”

意思是程序员通常不需要了解该部分的内部细节，就能正确使用相关功能。

例如：

同一条加法指令由串行进位加法器实现，还是超前进位加法器实现，通常对普通应用程序员透明。

但机器指令的含义不应对汇编程序员透明。

### 四、冯·诺依曼计算机

这是本章最重要的概念部分之一。

#### 4.1 什么是存储程序思想？

早期计算设备的一种工作方式是通过线路连接、开关设置等方式规定计算过程。

存储程序思想则将：

程序指令和程序处理的数据事先保存在存储器中，计算机能够自动取出指令并执行。

由此产生了现代通用计算机的重要基础。

#### 4.2 冯·诺依曼计算机的主要特点

传统教材通常总结为：

1. 由运算器、控制器、存储器、输入设备和输出设备五大部件组成。
2. 指令和数据以二进制形式表示。
3. 指令和数据可存放在同一存储器中。
4. 指令通常由操作码和地址码等字段组成。
5. 指令通常按地址顺序取出和执行，转移指令能够改变执行流程。
6. 经典模型常描述为以运算器为中心。

现代计算机常强调以存储器为中心的数据交换组织。

注意：现代 CPU 还可能采用分离的一级指令 Cache 和数据 Cache。这并不意味着所有现代计算机都不再采用存储程序思想。

#### 4.3 五大部件究竟做什么？

| 部件   | 核心功能           |
| ---- | -------------- |
| 运算器  | 算术、逻辑、移位、比较等运算 |
| 控制器  | 取指、译码、产生控制信号   |
| 存储器  | 保存指令、数据和运算结果   |
| 输入设备 | 将信息送入计算机       |
| 输出设备 | 输出处理结果         |

CPU 的核心部分通常包括控制单元、运算单元以及寄存器等。

运算器中的典型部件是：

ALU（算术逻辑单元）。

控制器负责组织各部件工作。

#### 4.4 为什么指令和数据能够放在同一个存储器？

因为二者在存储形式上都是二进制位串。

例如：

```text
00000000 00000000 00000000 00000101
```

这段位串可能表示：

- 整数 5。
- 某种机器指令的部分编码。
- 一个地址或偏移量。
- 其他编码数据。

它到底是什么，取决于处理器如何解释和使用。

这是极其重要的基础认识：

数据的意义不由二进制位串本身单独决定。

#### 4.5 【2009 年真题】指令和数据的区分

题目：

冯·诺依曼计算机中指令和数据均以二进制形式存放在存储器中，CPU 区分它们的依据是：

A. 指令操作码的译码结果

B. 指令和数据的寻址方式

C. 指令周期的不同阶段

D. 指令和数据所在的存储单元

正确答案：C。

为什么？

因为存储器返回的只是二进制内容。

CPU 在取指阶段按照 PC 给出的地址读取内容，将其作为指令处理。

执行指令时，CPU 又可能按照指令规定的地址读取操作数。

因此在这道题的传统计算机模型中，区分依据是当前执行过程所处的阶段及访存目的。

注意一个细节：

不能简单说“读取到 IR 的是指令，读取到 MDR 的就是数据”。

在经典取指过程中，刚从主存读出的指令也可以先经过 MDR，再进入 IR。

MDR 本身不能单独决定内容的语义。

#### 4.6 【2019 年真题】冯·诺依曼思想

题目问错误叙述。

其中错误选项是：

“指令按地址访问，数据都在指令中直接给出。”

为什么错误？

因为操作数可能来自：

- 指令立即数字段。
- CPU 寄存器。
- 主存。
- 其他由指令规定的数据来源。

例如：

```asm
MOV R1, #5
```

这里的操作数 5 是立即数。

而：

```text
LOAD R1, [R2]
```

这里的操作数来自 R2 指定的存储位置。

所以不能认为所有数据都直接写在指令里。

#### 4.7 冯·诺依曼结构与哈佛结构

| 对比      | 冯·诺依曼结构     | 哈佛结构       |
| ------- | ----------- | ---------- |
| 指令与数据存储 | 统一存储空间是典型特点 | 指令与数据空间分离  |
| 访问通路    | 经典模型共用通路    | 可有独立通路     |
| 并行访问    | 容易受到共享通路限制  | 可独立访问指令与数据 |

经典冯·诺依曼瓶颈指 CPU 与存储器之间的信息传送能力可能限制系统性能。

现代处理器通常通过 Cache、流水线、预取和多级存储等技术缓解相关问题。

### 五、计算机怎样自动执行程序？

不要只背“取指、译码、执行”，要理解实际数据流向。

#### 5.1 四个重要寄存器

| 寄存器 | 英文全称                    | 保存内容       |
| --- | ----------------------- | ---------- |
| PC  | Program Counter         | 下一条待取指令的地址 |
| IR  | Instruction Register    | 当前指令       |
| MAR | Memory Address Register | 本次访存地址     |
| MDR | Memory Data Register    | 本次访存读写的数据  |

特别容易混淆的是 PC 和 MAR。

PC 关注下一条指令在哪里；MAR 关注本次访存访问哪里。

取指时，通常可以把 PC 的内容送到 MAR。

但执行指令时，MAR 也可能保存操作数的地址。

因此二者不能等同。

#### 5.2 一条指令的执行过程

在经典简化数据通路中：

```text
              PC
              │
       提供指令地址
              ↓
             MAR
              │
              ↓
             主存
              │
       返回机器指令
              ↓
             MDR
              │
              ↓
              IR
              │
           指令译码
              ↓
       读取所需操作数
              ↓
          ALU 等执行
              ↓
       写入结果、更新状态
              ↓
       继续执行下一条指令
```

这是教学抽象。

现代 CPU 可能使用多级流水线、指令 Cache、取指队列和乱序执行，但逻辑上仍然必须完成指令规定的功能。

#### 5.3 PC 如何变化？

假设某机器按字节编址，机器指令固定长度为 4B。

初始：

$$
PC=100
$$

顺序执行时：

$$
100\rightarrow104\rightarrow108\rightarrow112
$$

因此在这一简化模型中：

$$
PC_{\mathrm{next}}=PC_{\mathrm{current}}+4
$$

如果执行的是转移指令，例如跳转到地址 200，那么 PC 可以改为：

$$
PC_{\mathrm{next}}=200
$$

这就是程序能够实现 `if`、`while`、`for` 和函数调用等控制流程的基础。

#### 5.4 时钟周期、机器周期与指令周期

这三个概念容易出选择题。

| 概念   | 含义                         |
| ---- | -------------------------- |
| 时钟周期 | 时钟信号的一个基本周期                |
| 机器周期 | 完成一个相对完整基本操作所需时间，属于传统模型的概念 |
| 指令周期 | 从开始取出一条指令到该指令完成的过程         |

传统非流水模型中，一条指令可能经历：

取指周期、间址周期、执行周期，以及与中断有关的处理阶段。

这里存在一个重要区别：

指令周期不等于 CPI。

指令周期描述的是执行过程，CPI 描述的是平均每条指令消耗多少时钟周期。

现代流水线中不同指令的执行过程可以重叠，因此更不能直接把二者混为一谈。

### 六、计算机语言与程序翻译

#### 6.1 三种程序设计语言

| 语言   | 示例           | CPU 能否直接执行     |
| ---- | ------------ | -------------- |
| 机器语言 | 二进制机器指令      | 能              |
| 汇编语言 | `ADD R1, R2` | 不能，需汇编         |
| 高级语言 | `c = a + b`  | 不能，需编译或相应运行时处理 |

重点是：

CPU 最终执行的是机器指令。

高级语言解释执行，也需要通过运行在机器上的解释器或虚拟机完成。

#### 6.2 【2015 年真题】硬件直接执行什么？

Ⅰ. 机器语言程序

Ⅱ. 汇编语言程序

Ⅲ. 硬件描述语言程序

答案：仅Ⅰ。

汇编语言首先需要经过汇编器翻译。

硬件描述语言通常用于描述数字电路，不是普通 CPU 直接执行的机器程序。

#### 6.3 编译、汇编、链接和装载

以典型 C 程序为例：

```text
hello.c
  │
  │ 预处理
  ↓
hello.i
  │
  │ 编译
  ↓
hello.s
  │
  │ 汇编
  ↓
hello.o
  │

  ↓
```

必须区分各阶段：

| 阶段  | 核心作用              |
| --- | ----------------- |
| 预处理 | 宏展开、头文件包含、条件编译    |
| 编译  | 将高级语言转换为汇编等较低层表示  |
| 汇编  | 将汇编指令转换为机器级目标代码   |
| 链接  | 解析符号、处理重定位、组合目标模块 |
| 装载  | 建立运行所需映像并准备执行     |

##### 【2022 年真题】

高级语言源程序转换为可执行目标文件的主要过程：

预处理 → 编译 → 汇编 → 链接。

但要注意，实际编译工具链也可能直接生成机器级目标代码，因此这是考试中典型 C 编译流程的表达。

#### 6.4 编译程序与解释程序

编译程序：

通常对源程序进行整体翻译，生成目标代码或其他中间表示。

解释程序：

通常边解释程序内容边组织执行，不要求事先生成独立的原生可执行文件。

考试中的传统表述是：

编译：先翻译，再运行。

解释：边翻译，边执行。

但真实语言实现可能同时使用解释、即时编译和提前编译，不能仅根据语言名称绝对判断执行方式。

#### 6.5 【2024 年真题】四种“指令”

题目区分：

Ⅰ. 伪指令

Ⅱ. 微指令

Ⅲ. 机器指令

Ⅳ. 汇编指令

按照题库中的经典微程序控制器语境，CPU 内部能够直接执行的是：

Ⅱ、Ⅲ。

需要理解两种不同层次的“执行”。

机器指令由处理器按照 ISA 定义的语义执行。

微指令则在采用微程序控制的处理器内部，由微程序控制部件读取和执行，用于产生相应控制信号。

汇编指令是机器指令的人类可读表示。

伪指令一般需要由汇编器处理或展开。

所以：

微指令不等于机器指令，伪指令也不等于机器指令。

## 第二部分：计算机性能指标

这是第一章计算题的核心。

### 七、衡量性能究竟看什么？

先分清两类指标。

时间类指标：越小通常越好。

例如：

- 响应时间。
- CPU 执行时间。
- 完成任务的总耗时。

速率类指标：越大通常越好。

例如：

- 吞吐量。
- IPS。
- MIPS。
- FLOPS。

#### 7.1 响应时间与吞吐量

响应时间表示完成一项任务所花的时间。

吞吐量表示单位时间内完成的任务数量。

例如：

服务器 A 每秒能完成 1000 个请求，但单个请求平均等待 100ms。

服务器 B 每秒只能完成 100 个请求，但单个请求平均等待 20ms。

A 的吞吐量更高，但单个请求的响应时间不一定更低。

所以不能把二者当作同一个指标。

#### 7.2 CPU 时间与总运行时间

CPU 执行时间反映处理器为程序执行工作消耗的时间。

程序的墙钟运行时间还可能受到：

- I/O 等待。
- 调度等待。
- 其他程序竞争。
- 系统活动。

等因素影响。

对于没有执行重叠的简化模型，常用：

$$
T_{\mathrm{total}}=T_{\mathrm{CPU}}+T_{\mathrm{wait}}
$$

但是在多线程或异步 I/O 场景中，CPU 工作与等待可能重叠，不能无条件这样相加。

做题原则：先判断题目给的是 CPU 时间还是总经过时间。

### 八、主频与时钟周期

#### 8.1 主频是什么？

主频表示单位时间内的时钟周期数。

记作：

$$
f
$$

单位为 Hz。

时钟周期记为：

$$
T_c
$$

两者满足：

$$
\boxed{T_c=\frac{1}{f}}
$$

例如主频为：

$$
f=2\,\mathrm{GHz}=2\times10^9\,\mathrm{Hz}
$$

则：

$$
T_c=\frac{1}{2\times10^9} =0.5\,\mathrm{ns}
$$

常见换算：

| 主频      | 时钟周期    |
| ------- | ------- |
| 100 MHz | 10 ns   |
| 200 MHz | 5 ns    |
| 500 MHz | 2 ns    |
| 1 GHz   | 1 ns    |
| 2 GHz   | 0.5 ns  |
| 4 GHz   | 0.25 ns |

记住：

$$
1\,\mathrm{GHz}\leftrightarrow1\,\mathrm{ns}
$$

这里的对应关系表示频率 1GHz 时周期为 1ns，而不是二者是相同物理量。

#### 8.2 主频越高，CPU 一定越快吗？

不一定。

因为一条指令可能需要多个周期。

不同机器执行同一程序时，可能还有不同的指令条数和平均 CPI。

真正需要比较的是执行时间，而不是单独比较主频。

### 九、CPI 与 IPC

#### 9.1 CPI 是什么？

CPI：

Cycles Per Instruction。

表示平均每条机器指令需要多少个时钟周期。

定义为：

$$
\boxed{ CPI=\frac{\text{总时钟周期数}}{\text{执行的指令条数}} }
$$

假设程序执行 1000 条指令，一共消耗 2500 个周期，则：

$$
CPI=\frac{2500}{1000}=2.5
$$

这表示平均每条指令消耗 2.5 个周期。

注意“平均”二字。

CPI 为 2.5 并不意味着存在某条指令实际执行了半个时钟周期。

#### 9.2 IPC 是什么？

IPC：

Instructions Per Cycle。

表示平均每个周期完成多少条指令。

$$
IPC=\frac{\text{指令数}}{\text{总周期数}}
$$

因此在相同统计口径下：

$$
\boxed{IPC=\frac{1}{CPI}}
$$

例如：

$$
CPI=2
$$

则：

$$
IPC=0.5
$$

平均两个周期完成一条指令。

#### 9.3 CPI 一定大于等于 1 吗？

不一定。

现代超标量处理器可能在一个周期内完成多条指令。

例如平均每周期完成两条：

$$
IPC=2
$$

则：

$$
CPI=0.5
$$

这里讨论的是整个程序执行过程中的平均吞吐表现。

即使平均 CPI 小于 1，也不代表一条指令从开始到完成的延迟一定小于一个时钟周期。

### 十、多种指令的平均 CPI

这是大量真题的共同起点。

假设程序有三类指令：

| 指令类型 | 指令数量 | CPI |
| ---- | ---- | --- |
| A    | 100  | 1   |
| B    | 200  | 2   |
| C    | 700  | 4   |

总指令数：

$$
IC=100+200+700=1000
$$

总周期数：

$$
C=100\times1+200\times2+700\times4
$$

$$
C=3300
$$

平均 CPI：

$$
\boxed{CPI_{\mathrm{avg}}=\frac{3300}{1000}=3.3}
$$

也可以使用加权平均公式：

$$
\boxed{CPI_{\mathrm{avg}}=\sum_i p_iCPI_i}
$$

其中：

$$
p_i=\frac{IC_i}{IC}
$$

因此：

$$
CPI_{\mathrm{avg}} =0.1\times1+0.2\times2+0.7\times4=3.3
$$

#### 必须掌握的易错点

不能直接算：

$$
\frac{1+2+4}{3}
$$

因为各类指令的比例不同。

CPI 必须按指令出现频率加权。

**CPU 时间的适用前提**

$T_{\mathrm{CPU}}=IC\times CPI/f$ 假设统计窗口内所用的频率和 CPI 可用相应的平均值表征。动态调频、多个处理器或流水线性能测量题，应按题目给出的时间窗口和口径求和，不能把不同区间的数据直接平均。

## 十一、CPU 执行时间公式

推导过程非常简单。

设程序执行：

$$
IC
$$

条指令。

平均 CPI 为：

$$
CPI
$$

那么总周期数为：

$$
C=IC\times CPI
$$

每个周期的长度为：

$$
T_c=\frac1f
$$

所以：

$$
T_{\mathrm{CPU}}=C\times T_c
$$

得到：

$$
\boxed{ T_{\mathrm{CPU}} =IC\times CPI\times T_c =\frac{IC\times CPI}{f} }
$$

这是本章最重要的计算公式。

##### 公式中的三个变量

| 变量      | 含义         | 主要影响因素          |
| ------- | ---------- | --------------- |
| IC      | 执行的机器指令条数  | 算法、编译器、ISA      |
| CPI     | 平均每条指令的周期数 | 处理器实现、指令组合、存储系统 |
| $f$ | 主频         | 时钟系统、电路设计       |

三者必须综合考虑。

#### 11.1 一道基础例题

某机器主频为 2GHz，执行程序需要 $10^9$ 条指令，平均 CPI 为 2。

求 CPU 执行时间。

直接代入：

$$
T_{\mathrm{CPU}} =\frac{10^9\times2}{2\times10^9}
$$

$$
\boxed{T_{\mathrm{CPU}}=1\,\mathrm{s}}
$$

#### 11.2 公式的另一种常见形式

如果给出了各类指令数及 CPI：

$$
\boxed{ T_{\mathrm{CPU}} =\frac{\sum_i IC_iCPI_i}{f} }
$$

这种形式不用先计算平均 CPI。

实际解题时，两个公式哪个更方便就用哪个。

MIPS 表示每秒执行多少百万条指令。

### 十五、【2017 年真题】高主频反而更慢

题目给出两台机器：

| 参数     | M1     | M2     |
| ------ | ------ | ------ |
| 主频     | 1.5GHz | 1.2GHz |
| 平均 CPI | 2      | 1      |

两台机器采用相同 ISA，在题目默认的相同指令数条件下执行同一个基准程序。

求：

$$
\frac{T_1}{T_2}
$$

#### 解题过程

执行时间：

$$
T=\frac{IC\times CPI}{f}
$$

两边取比值：

$$
\frac{T_1}{T_2} = \frac{IC\times2/1.5}{IC\times1/1.2}
$$

约去相同的 IC：

$$
\frac{T_1}{T_2} =\frac{2\times1.2}{1.5\times1}
$$

$$
\boxed{\frac{T_1}{T_2}=1.6}
$$

因此：

M1 的主频虽然更高，但执行程序反而需要 M2 的 1.6 倍时间。

#### 为什么？

从一个周期来看，M1 的周期更短。

但从完成同样的指令工作量来看：

- M1 平均每条指令需要 2 个周期。
- M2 平均每条指令只需要 1 个周期。

M2 在周期利用效率上的优势，超过了 M1 的频率优势。

##### 延伸陷阱

严格来说，相同 ISA 不必然保证两次执行的动态指令数相同。

如果编译器、机器代码或实际执行路径不同，IC 仍可能改变。

这道题采用了相同基准程序对应相同指令数的假设。

综合比较题若明确 IC 不同，就不能约去 IC。

### 十六、【2014 年真题】编译优化一定能让程序快吗？

题目：

某程序原执行时间：

$$
T=20\,\mathrm{s}
$$

编译优化后：

- 指令数变为原来的 70%。
- 平均 CPI 变为原来的 1.2 倍。
- 主频不变。

求优化后的执行时间。

#### 解法一：比例法

$$
T=\frac{IC\times CPI}{f}
$$

因此：

$$
\frac{T'}T = \frac{IC'}{IC} \times \frac{CPI'}{CPI}
$$

代入：

$$
\frac{T'}T=0.7\times1.2=0.84
$$

所以：

$$
T'=20\times0.84
$$

$$
\boxed{T'=16.8\,\mathrm{s}}
$$

原题答案 D。

#### 为什么减少 30% 指令，时间却没有减少 30%？

因为优化后平均 CPI 增加了。

减少的指令可能恰好是比较简单的指令，也可能使用更复杂的指令替代原来的指令序列。

所以：

指令条数减少，不代表总时钟周期数一定同比减少。

#### 解法二：统一变化公式

无论 IC、CPI、主频怎样变化，都可以使用：

$$
\boxed{ \frac{T'}{T} = \frac{IC'}{IC} \cdot \frac{CPI'}{CPI} \cdot \frac{f}{f'} }
$$

这是所有性能变化题的核心比例公式。

### 十七、【2012 年真题】CPU 加速与程序整体加速

题目：

基准程序总运行时间：

$$
100\,\mathrm{s}
$$

其中：

$$
90\,\mathrm{s}
$$

为 CPU 时间。

其余 10s 为 I/O 时间。

现在 CPU 速度提高 50%，I/O 速度不变。

问新的总运行时间。

#### 关键：速度提高 50% 是什么意思？

速度提高 50%，表示新速度为原来的：

$$
1.5
$$

倍。

对相同工作量而言，CPU 时间变为：

$$
T'_{\mathrm{CPU}} =\frac{90}{1.5}
$$

$$
=60\,\mathrm{s}
$$

I/O 不变：

$$
T'_{\mathrm{I/O}}=10\,\mathrm{s}
$$

所以：

$$
T'=60+10
$$

$$
\boxed{70\,\mathrm{s}}
$$

原题答案 D。

#### 为什么不是 55s？

因为不能直接认为 CPU 时间减少了 50%。

速度和完成相同工作所需的时间互为倒数关系：

$$
T\propto\frac1V
$$

若速度提高 50%：

$$
T'=\frac{T}{1.5}
$$

也就是：

$$
\frac{T'}T=\frac23
$$

时间实际上减少：

$$
1-\frac23=\frac13
$$

约 33.33%。

速度提高 50%，不等于时间减少 50%。

## 第四部分：性能加速与综合优化

**局部加速三步法**

1. 从**优化前时间**求受益部分占比 $p$。
2. 计算可优化部分时间缩短为原来的 $1/s$，不可优化部分保持原时长。
3. 求新时间，再计算 $S=T/T'$；若 $s\to\infty$，上限是 $1/(1-p)$。

## 十八、Amdahl 定律

2012 年真题实际上已经体现了 Amdahl 定律的思想。

#### 18.1 为什么局部优化不能带来同比例的整体加速？

假设程序原来需要：

$$
T
$$

其中比例 $p$ 的时间用于可优化部分。

则：

$$
T_{\mathrm{可优化}}=pT
$$

$$
T_{\mathrm{不可优化}}=(1-p)T
$$

假设可优化部分速度提升为原来的 $s$ 倍。

优化后的时间：

$$
T'=(1-p)T+\frac{pT}{s}
$$

两边除以原时间：

$$
\frac{T'}T=(1-p)+\frac{p}{s}
$$

整体加速比：

$$
S=\frac{T}{T'}
$$

得到：

$$
\boxed{ S=\frac1{(1-p)+\frac{p}{s}} }
$$

这就是 Amdahl 定律。

注意：这里的 $p$ 是原运行时间的占比，不是指令条数比例。

#### 18.2 用 2012 真题验证

原程序 90% 时间用于 CPU：

$$
p=0.9
$$

CPU 速度提高 50%：

$$
s=1.5
$$

因此：

$$
S= \frac1{0.1+\frac{0.9}{1.5}}
$$

$$
=\frac1{0.7}
$$

$$
S\approx1.4286
$$

新的程序总时间：

$$
T'=\frac{100}{1.4286}
$$

$$
\boxed{70\,\mathrm{s}}
$$

与直接计算完全一致。

#### 18.3 极限问题：CPU 无限快，程序能加速多少？

令：

$$
s\rightarrow\infty
$$

则：

$$
\frac{p}{s}\rightarrow0
$$

得到：

$$
\boxed{S_{\max}=\frac1{1-p}}
$$

如果程序有 90% 的运行时间可加速，那么即使这一部分无限快：

$$
S_{\max}=\frac1{0.1}=10
$$

整体最多也只能加速 10 倍。

因为剩下 10% 的时间没有消失。

#### 18.4 自编预测题：反推加速倍数

某程序原运行时间的 80% 可以优化，希望整体加速 4 倍。

问可优化部分至少要加速多少倍？

设：

$$
s=x
$$

则：

$$
4=\frac1{0.2+\frac{0.8}{x}}
$$

所以：

$$
0.2+\frac{0.8}{x}=0.25
$$

$$
\frac{0.8}{x}=0.05
$$

$$
\boxed{x=16}
$$

这类题先判断理论极限，再反推所需局部加速倍数。

### 十九、【王道·卷一】慢指令优化是否值得？

这道模拟题比基础真题更综合。

题目条件：

某类指令 I：

- 占全部指令的 10%。
- 原 CPI 为 20。
- 其他指令平均 CPI 为 5。

现在通过硬件优化：

- I 的 CPI 降至 10。
- CPU 时钟周期却延长 10%。

问题：

1. 原来 I 占全部 CPU 时间的比例是多少？
2. 这种优化值得吗？

<Steps>
<Step>

### 第一步：计算原总周期数

设程序总指令数为：

$$
N
$$

I 类指令有：

$$
0.1N
$$

其他指令：

$$
0.9N
$$

总周期：

$$
C=0.1N\times20+0.9N\times5
$$

$$
C=2N+4.5N
$$

$$
\boxed{C=6.5N}
$$

</Step>
<Step>

### 第二步：求 I 的时间占比

I 消耗的周期数：

$$
C_I=2N
$$

所以：

$$
p=\frac{2N}{6.5N}
$$

$$
\boxed{p\approx30.77\%}
$$

这里是一个重要陷阱：

指令数只占 10%，并不代表执行时间也只占 10%。

因为不同类型指令的 CPI 不同。

</Step>
<Step>

### 第三步：计算优化后周期数

$$
C'=0.1N\times10+0.9N\times5
$$

$$
\boxed{C'=5.5N}
$$

如果只看周期数：

优化似乎明显有效。

但题目还告诉我们：

时钟周期延长 10%。

设原周期长度为：

$$
T_c
$$

新周期长度：

$$
T'_c=1.1T_c
$$

因此原执行时间：

$$
T=6.5NT_c
$$

新执行时间：

$$
T'=5.5N\times1.1T_c
$$

$$
T'=6.05NT_c
$$

比较：

$$
\frac{T'}T=\frac{6.05}{6.5}
$$

$$
\approx0.9308
$$

所以执行时间减少约：

$$
1-0.9308=6.92\%
$$

结论：值得优化。

本题的关键不是记住答案，而是：

$$
\boxed{\text{CPU 时间}=\text{总周期数}\times\text{时钟周期长度}}
$$

优化可能同时改变总周期数与周期长度。

必须综合比较。

</Step>
</Steps>
### 二十、【王道·卷三】不同机器与不同编译器

模拟题给出两台机器：

| ---- | ------ | ------ | --------- | --------- |

| B    | 3      | 2      | 50%       | 20%       |
| C    | 4      | 1.5    | 20%       | 50%       |

假设不同编译器生成的总指令数相同。

M1：

$$
CPI_{M1} =0.3\times2+0.5\times3+0.2\times4
$$

$$
=2.9

M2：

$$
CPI_{M2} =0.3\times1+0.5\times2+0.2\times1.5
$$

$$
=1.6
$$

速度比较：

$$
\frac{V_{M1}}{V_{M2}} = \frac{T_{M2}}{T_{M1}}
$$

$$
= \frac{1.6/400}{2.9/800}
$$

$$
\boxed{\frac{V_{M1}}{V_{M2}}\approx1.10}
$$

因此 M1 约快 1.1 倍。

#### 使用 C2 编译器

M1：

$$

=3.2

\frac{V_{M2}}{V_{M1}} = \frac{T_{M1}}{T_{M2}}

### 二十一、【竟成·模拟一】Cache + CPI 综合

这道题把第一章的执行时间公式与第三章的 Cache 知识结合起来。

某机器：

$$
f=100\,\mathrm{MHz}
$$

程序原来使用乘 4 指令，优化后改为左移 2 位。

原程序：

- 执行时间 12s。
- 原指令命中 Cache 时 CPI 为 94。
- Cache 命中率 90%。

优化后：

- 执行时间 10s。
- 左移指令命中时 CPI 为 3。
- Cache 命中率 99%。

未命中时均额外增加 100 个周期。

问替换了多少条指令。

<Steps>
<Step>

### 第一步：求原有效 CPI

未命中率：

$$
1-0.9=0.1
$$

因此：

$$
CPI_{\mathrm{old}} =94+0.1\times100
$$

$$
\boxed{104}
$$

</Step>
<Step>

### 第二步：求优化后有效 CPI

$$
CPI_{\mathrm{new}} =3+0.01\times100
$$

$$
\boxed{4}
$$

</Step>
<Step>

### 第三步：求每条指令节省周期数

$$
104-4=100
$$

每替换一条，平均节省 100 个周期。

</Step>
<Step>

### 第四步：求总共节省多少周期

程序时间从 12s 减少到 10s。

$$
\Delta T=2\,\mathrm{s}
$$

在主频不变的条件下：

$$
\Delta C=\Delta T\times f
$$

$$
=2\times100\times10^6
$$

$$
=2\times10^8
$$

</Step>
<Step>

### 第五步：反推替换数量

$$
N=\frac{2\times10^8}{100}
$$

$$
\boxed{N=2\times10^6}
$$

即替换了 200 万条动态执行的指令。

这题要掌握的通用思路是：

$$
\boxed{ \text{替换次数} = \frac{\text{总节省周期数}} {\text{每次平均节省周期数}} }
$$

适用前提是：其他执行开销保持不变，相关优化的周期差能够直接累加。

</Step>

## 第五部分：性能指标的其他考法

### 二十二、MIPS、IPS、FLOPS 的区别

| 指标     | 含义         | 公式或特点               |
| ------ | ---------- | ------------------- |
| IPS    | 每秒执行指令数    | $IPS=f/CPI$     |
| MIPS   | 每秒百万条指令    | $MIPS=IPS/10^6$ |
| GIPS   | 每秒十亿条指令    | $GIPS=IPS/10^9$ |
| FLOPS  | 每秒浮点运算次数   | 按浮点操作数统计            |
| MFLOPS | 每秒百万次浮点运算  | $10^6$ FLOPS    |
| GFLOPS | 每秒十亿次浮点运算  | $10^9$ FLOPS    |
| TFLOPS | 每秒万亿次浮点运算  | $10^{12}$ FLOPS |
| PFLOPS | 每秒千万亿次浮点运算 | $10^{15}$ FLOPS |

#### 22.1 【2011 年真题】

描述浮点数操作速度的指标是：

MFLOPS。

为什么不是 MIPS？

因为：

MIPS 统计机器指令数量。

FLOPS 统计浮点操作数量。

一条机器指令可能执行一个或多个浮点操作，某些向量指令甚至可以在一次指令执行中完成许多浮点操作。

所以二者不能直接等同。

#### 22.2 【2021 年真题】PFLOPS 数量级

题目给出：

$$
93.0146\,PFLOPS
$$

求每秒浮点操作次数。

因为：

$$
1\,PFLOPS=10^{15}\,FLOPS
$$

所以：

$$
93.0146\times10^{15}
$$

$$
=9.30146\times10^{16}
$$

又因为：

$$
1\text{亿亿}=10^{16}
$$

所以约为：

$$
\boxed{9.3\text{亿亿次/秒}}
$$

#### 22.3 为什么 MIPS 高不一定快？

假设机器 A：

$$
500\,MIPS
$$

机器 B：

$$
400\,MIPS
$$

能否判断 A 更快？

不能。

假设完成同样任务：

A 需要：

$$
10^9
$$

条指令。

B 只需要：

$$
5\times10^8
$$

条指令。

则 A 的时间：

$$
T_A=\frac{10^9}{500\times10^6}=2\,\mathrm{s}
$$

B 的时间：

$$
T_B=\frac{5\times10^8}{400\times10^6} =1.25\,\mathrm{s}
$$

所以 B 反而更快。

结论：

跨机器、跨 ISA 比较完成相同任务的性能，应该优先比较实际执行时间。

## 第六部分：字长、寄存器与寻址能力

### 二十三、机器字长是什么？

机器字长通常指 CPU 一次能处理的基本二进制数据宽度。

例如：

32 位计算机的典型基本数据处理宽度为 32 bit。

64 位计算机的典型基本数据处理宽度为 64 bit。

但一定要区分几个概念。

| 名称     | 具体含义          |
| ------ | ------------- |
| 机器字长   | CPU 基本数据处理宽度  |
| 指令字长   | 一条机器指令的编码长度   |
| 存储字长   | 一个存储字包含的二进制位数 |
| 数据通路宽度 | 一次并行传送的数据位数   |
| 地址宽度   | 能够表示的地址位数     |

这些宽度可能相同，也可能不同。

#### 23.1 【2020 年真题】机器字长

题目：

哪些部件的位数一定与机器字长相同？

Ⅰ. ALU

Ⅱ. 指令寄存器

Ⅲ. 通用寄存器

Ⅳ. 浮点寄存器

按照 408 传统教材的机器字长定义：

正确答案：Ⅰ、Ⅲ。

即 ALU 和通用寄存器。

为什么不选 IR？

因为机器指令可能采用不同长度。

为什么不选浮点寄存器？

因为浮点数据格式可能有不同宽度，甚至存在宽于通用寄存器的数据寄存器。

这里的“一定”应按照题目所采用的经典机器模型理解，不代表所有实际微处理器内部的 ALU 通路和寄存器实现都必须严格同宽。

### 二十四、MAR 位数与主存容量

这是第一章很有价值的综合考点。

#### 24.1 最核心的原理

假设 MAR 为 $n$ 位。

最多能够表示：

$$
2^n
$$

个不同地址。

但每个地址对应的数据量取决于：

按什么单位编址。

#### 24.2 按字节编址

如果一个地址对应 1B，则：

$$
C=2^n\,\mathrm{B}
$$

例如地址位数为 20 位：

$$
C=2^{20}\,\mathrm{B}
$$

$$
\boxed{C=1\,\mathrm{MiB}}
$$

#### 24.3 按字编址

如果一个字为 32bit：

$$
32\,\mathrm{bit}=4\,\mathrm{B}
$$

且采用按字编址。

地址位数仍是 20 位。

则可寻址：

$$
2^{20}
$$

个字。

容量：

$$
C=2^{20}\times4\,\mathrm{B}
$$

$$
\boxed{C=4\,\mathrm{MiB}}
$$

#### 24.4 为什么两道题容量不同？

因为一个地址对应的存储量不同。

同样是 20 位地址：

| 编址方式      | 一个地址对应 | 理论容量 |
| --------- | ------ | ---- |
| 按字节编址     | 1B     | 1MiB |
| 按 16 位字编址 | 2B     | 2MiB |
| 按 32 位字编址 | 4B     | 4MiB |
| 按 64 位字编址 | 8B     | 8MiB |

通用公式：

$$
\boxed{ C=2^n\times W }
$$

其中 $W$ 为每个可寻址单元的容量。

#### 24.5 反推 MAR 位数

某主存容量 128KiB，按字节编址。

因为：

$$
128\,\mathrm{KiB}=2^{17}\,\mathrm{B}
$$

所以：

$$
\boxed{MAR=17\text{位}}
$$

如果仍是 128KiB，但一个字为 16bit，采用按字编址：

$$
128\,\mathrm{KiB}=2^{17}\,\mathrm{B}
$$

每字 2B。

可寻址字数：

$$
\frac{2^{17}}{2}=2^{16}
$$

所以：

$$
\boxed{MAR=16\text{位}}
$$

#### 24.6 容易混淆的三个量

地址空间： 地址编码理论上覆盖的范围。

实际主存容量： 机器真正安装的主存容量。

一次存取宽度： 一次读写操作传送多少位。

例如：

某机器有 32 位地址，按字节编址，但实际只安装 1GiB 内存。

理论地址空间：

$$
2^{32}\,\mathrm{B}=4\,\mathrm{GiB}
$$

实际物理内存：

$$
1\,\mathrm{GiB}
$$

二者并不矛盾。

此外，20 位地址线、32 位数据总线的机器，也不能直接推断有 $2^{20}\times4$ 字节的按字节编址空间。

地址线决定可编码地址数量；数据总线主要决定一次并行传输的数据宽度。

## 第九部分：本章所有核心题型的统一解题法

### 二十八、六类性能计算题

| 题型            | 首选方法      | 核心公式                        |
| ------------- | --------- | --------------------------- |
| 多类指令求平均 CPI   | 加权平均      | $CPI=\sum p_iCPI_i$     |
| 指令数、主频求时间     | 基本公式      | $T=IC\times CPI/f$      |
| 两机器比较性能       | 时间取比      | $T_1/T_2$               |
| IC、CPI、主频同时变化 | 比例法       | $T'/T$                  |
| 只优化部分运行时间     | Amdahl 定律 | $S=1/[(1-p)+p/s]$       |
| 反推优化的指令次数     | 周期差法      | $N=\Delta C/\Delta CPI$ |

#### 28.1 题型一：直接计算 CPU 时间

$$
\boxed{T=\frac{IC\times CPI}{f}}
$$

若给出了各类指令数：

$$
\boxed{T=\frac{\sum IC_iCPI_i}{f}}
$$

#### 28.2 题型二：比较两台机器

最一般的公式：

$$
\boxed{ \frac{T_1}{T_2} = \frac{IC_1}{IC_2} \cdot \frac{CPI_1}{CPI_2} \cdot \frac{f_2}{f_1} }
$$

如果 IC 相同：

$$
\boxed{ \frac{T_1}{T_2} = \frac{CPI_1}{CPI_2} \cdot \frac{f_2}{f_1} }
$$

注意时间比和速度比互为倒数。

#### 28.3 题型三：优化前后比较

$$
\boxed{ \frac{T'}{T} = \frac{IC'}{IC} \cdot \frac{CPI'}{CPI} \cdot \frac{f}{f'} }
$$

最适合题目给百分比变化的情况。

#### 28.4 题型四：整体加速比

$$
\boxed{ S=\frac{T_{\mathrm{old}}}{T_{\mathrm{new}}} }
$$

例如：

原运行时间 10s，新运行时间 5s。

$$
S=2
$$

说明性能达到原来的 2 倍，执行时间减少 50%。

若新速度提高 25%：

$$
S=1.25
$$

则新时间：

$$
T'=\frac{T}{1.25}=0.8T
$$

执行时间减少 20%，不是 25%。

#### 28.5 题型五：局部加速

$$
\boxed{ S=\frac1{(1-p)+p/s} }
$$

牢记：

$p$ 是原时间占比，$s$ 是可优化部分的速度倍数。

#### 28.6 题型六：反推主频

由：

$$
T=\frac{IC\times CPI}{f}
$$

得：

$$
\boxed{ f=\frac{IC\times CPI}{T} }
$$

如果是两台机器比较，可以优先用比例法消去未知的 IC。

### 二十九、基础概念题

#### 练习 1

冯·诺依曼计算机能够自动执行程序的关键思想是：

A. 采用 Cache

B. 存储程序

C. 采用流水线

答案：B。

Cache 和流水线属于性能改进技术，不是存储程序的前提。

#### 练习 2

关于计算机组成和体系结构，正确的是：

A. Cache 容量必然由 ISA 规定

B. 相同 ISA 的两颗 CPU 必须采用相同流水线

C. 体系结构主要定义程序员可见的机器接口

D. 主频属于机器指令编码的一部分

答案：C。

#### 练习 3

程序取指过程中保存当前访存地址的寄存器是：

A. PC

B. IR

C. MAR

D. ALU

答案：C。

PC 保存下一条待取指令的地址；取指时可以将其送入 MAR。

### 三十、计算题

#### 练习 4：综合 CPI

某机器主频 2GHz。

程序包含：

| 类型 | 指令条数              | CPI |
| -- | ----------------- | --- |
| A  | $2\times10^8$ | 1   |
| B  | $3\times10^8$ | 2   |
| C  | $5\times10^8$ | 4   |

求平均 CPI 和执行时间。

解：

总指令数：

$$
IC=10^9
$$

总周期：

$$
C=2\times10^8+6\times10^8+20\times10^8
$$

$$
=2.8\times10^9
$$

所以：

$$
CPI=\frac{2.8\times10^9}{10^9}=2.8
$$

执行时间：

$$
T=\frac{2.8\times10^9}{2\times10^9}
$$

$$
\boxed{T=1.4\,\mathrm{s}}
$$

#### 练习 5：主频提高但 CPI 增大

某程序原执行时间 12s。

优化后：

$$
IC'=0.9IC
$$

$$
CPI'=1.25CPI
$$

$$
f'=1.5f
$$

求新时间。

$$
\frac{T'}T =\frac{0.9\times1.25}{1.5}
$$

$$
=0.75
$$

所以：

$$
T'=12\times0.75
$$

$$
\boxed{T'=9\,\mathrm{s}}
$$

加速比：

$$
S=\frac{12}{9}
$$

$$
\boxed{S=\frac43}
$$

#### 练习 6：Amdahl 极限

某程序有 60% 的执行时间可以加速，其余无法优化。

问整体最多加速多少倍？

$$
S_{\max}=\frac1{1-0.6}
$$

$$
\boxed{S_{\max}=2.5}
$$

如果有人声称通过只优化这 60% 的部分，使整个程序加速 3 倍，那么在题设条件下不可能。

#### 练习 7：地址容量

某机器：

- 24 位地址。
- 按字节编址。
- 数据总线宽度 64bit。

问理论可寻址容量。

$$
C=2^{24}\,\mathrm{B}
$$

$$
\boxed{C=16\,\mathrm{MiB}}
$$

数据总线是 64bit，不代表每个地址对应 8B。

## 第十一部分：高频易错点集中辨析

### 三十一、必须避免的错误认识

| 错误说法                             | 正确理解                     |
| -------------------------------- | ------------------------ |
| 主频越高，程序一定越快                      | 必须同时考虑 IC 与 CPI          |
| CPI 越小，执行时间一定越短                  | 还要考虑主频和指令数               |
| 每条指令都需要一个周期                      | 不同指令及架构的周期数可能不同          |
| 平均 CPI 必须大于等于 1                  | 超标量机器可能小于 1              |
| 机器字长就是指令字长                       | 二者没有必然相等关系               |
| 64 位 CPU 必然能访问 $2^{64}$ B 主存 | 实际地址宽度可能不同               |
| MIPS 高意味着程序一定更快                  | 还取决于完成任务需要多少指令           |
| 所有操作数都直接存在指令里                    | 操作数也可能来自寄存器或主存           |
| 指令与数据在存储器中形式不同                   | 二者都是二进制编码                |
| 编译器减少指令数一定提高性能                   | CPI 与执行路径可能同时改变          |
| CPU 速度提高 50%，时间减少 50%            | 同工作量下时间变为原来的 $1/1.5$ |
| 一类指令占 10%，也占 10% CPU 时间          | 时间占比还取决于 CPI             |
| MAR 位数决定实际安装内存容量                 | 它决定相关模型中的可编码地址范围         |
| 地址空间与一次存取宽度是同一个概念                | 编址单位和传输宽度必须分开            |
| 相同 ISA 意味着性能相同                   | ISA 相同仍可采用不同实现           |

### 最后总结：用三个原理理解整章

第一个原理：存储程序。

计算机之所以能够自动工作，是因为指令和数据可以事先保存，CPU 按照程序规定的流程不断取指、译码和执行。

第二个原理：执行时间由工作量与执行代价共同决定。

$$
\boxed{ T_{\mathrm{CPU}} =\frac{IC\times CPI}{f} }
$$

主频不是全部，CPI 不是全部，指令条数也不是全部。任何性能优化都必须回到实际执行时间来判断。

第三个原理：优化整个系统，需要考虑瓶颈与不能加速的部分。

$$
\boxed{ S=\frac1{(1-p)+\frac{p}{s}} }
$$

CPU 再快，如果大量时间用于无法加速的 I/O 等待，程序整体性能也会受到限制。

这三个原理分别对应：

计算机如何工作 → 如何衡量它的工作速度 → 如何改进它的性能。

掌握这条逻辑链，再进入第二章的数据表示、第三章的存储系统、第四章的指令系统与第五章的 CPU，就能够把很多原本分散的知识点联系起来，而不是孤立地背概念和公式。
