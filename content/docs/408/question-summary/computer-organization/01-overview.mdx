### 计算机系统的基本概念

**计算机系统由什么组成？** 计算机系统包含硬件与软件。 $\boxed{ \text{计算机系统} = \text{硬件系统} + \text{软件系统} }$

注意：计算机系统不等于计算机硬件。 硬件是实际执行计算的物理基础，软件决定硬件如何按照用户需求完成任务。

**硬件系统** 主要包括：

| 部件 | 主要功能 |
|---|---|
| CPU | 执行机器指令、进行运算和控制 |
| 主存储器 | 保存正在使用的程序与数据 |
| 外存储器 | 长期保存程序与数据 |
| 总线或互连 | 实现部件之间的信息传输 |
| 输入设备 | 输入数据 |
| 输出设备 | 输出结果 |

注意 CPU 与主存储器的区别：CPU 负责处理信息，主存负责保存信息。 CPU 内部虽然存在寄存器和 Cache，但不能因此认为 CPU 就等于主存储器。

**软件系统** 分为系统软件和应用软件。 系统软件：操作系统；编译程序；汇编程序；链接程序；数据库管理系统。 应用软件：

- 浏览器
- 文本处理程序
- 图像编辑软件
- 游戏
- 面向用户的业务程序

**判断方法：** 系统软件主要提供基础运行环境、资源管理或公共支撑功能。 应用软件主要解决用户的具体任务。

**例题 1【模拟题：软件分类】** 下列软件中，不属于系统软件的是：A. 编译程序 B. 操作系统 C. 文本处理程序 D. 数据库管理系统

**答案：C** **解析：** 编译程序负责程序翻译，操作系统负责系统资源管理，数据库管理系统通常归为系统软件。 文本处理程序主要用于用户编写和编辑文档，因此属于应用软件。

**拓展：** 不能因为一个软件功能复杂、规模大，就认为它是系统软件。 判断依据是软件的主要用途。

**计算机的发展历程** 传统教材通常根据主要逻辑元件，将电子计算机分为四代。

| 代次 | 主要元件 | 特点 |
|---|---|---|
| 第一代 | 电子管 | 体积大、功耗高、可靠性较低 |
| 第二代 | 晶体管 | 体积减小，可靠性提高 |
| 第三代 | 中小规模集成电路 | 集成度提高，操作系统发展 |
| 第四代 | 大规模和超大规模集成电路 | 微处理器广泛应用 |

容易出现的概念题：第一代计算机的主要逻辑元件是电子管，而不是晶体管。 现代计算机的发展涉及多核、并行计算、GPU 和专用加速器，但不应简单把这些技术直接当作传统分类中的新一代逻辑元件。

**为什么计算机使用二进制？** 主要原因有四个。

**第一：物理实现容易。** 电子器件比较容易表示两个不同的稳定状态，例如高电平与低电平。

**第二：运算规则简单。** 二进制只有 0 和 1，基本运算规则较少。

**第三：适合逻辑运算。** 布尔代数使用真和假两种逻辑值，可以直接与数字逻辑电路对应。

**第四：可靠性较好。** 在合理设计的数字电路中，两个逻辑电平之间可以保留一定的噪声容限。 所以，使用二进制并不只是为了节省表示符号。

### 计算机体系结构与计算机组成

**计算机体系结构与计算机组成的区别** 这是典型的概念辨析考点。

**计算机体系结构** 主要研究：

**计算机向机器语言程序员提供什么功能。** 例如：指令系统；程序员可见寄存器；数据类型；指令编码；寻址方式；体系结构规定的异常行为。 这些内容主要属于 ISA。 ISA 是 Instruction Set Architecture 的缩写，即指令集体系结构。

**计算机组成** 主要研究：

**计算机通过什么硬件结构和实现方法完成上述功能。** 例如：数据通路；ALU 实现方式；控制器实现方式；Cache 组织；流水线结构；总线连接方式；微体系结构。 可以记忆为：体系结构规定做什么，计算机组成研究怎么做。

**举例理解** 假设两颗 CPU 都支持机器指令：`ADD R1, R2, R3` 表示：`R1 = R2 + R3` CPU A：使用简单流水线；顺序执行；较小 Cache；较低主频。 CPU B：使用超标量流水线；乱序执行；较大 Cache；较高主频。 两者可以采用相同的 ISA。 因此相同的机器代码能够在两者上正确执行。 但由于内部实现不同，两者的性能可能不同。

结论：**相同 ISA 不代表相同硬件实现，更不代表相同性能。**

**什么叫对程序员透明？** 透明意味着：程序员使用某项功能时，通常不需要知道其内部具体实现。 例如：CPU 使用串行进位加法器还是超前进位加法器，通常对普通程序员透明。 但机器指令的功能、编码规则、寄存器使用方式等不能对汇编程序员完全透明。

**软硬件逻辑功能等价性** 同一种功能可能通过软件或硬件实现。 例如：某种机器没有专用的浮点乘法硬件，可以通过软件例程实现相应计算。 专用硬件也可以实现同样的功能。 只要实现满足相同的功能语义，二者就可以在逻辑功能上等价。 但是：执行速度可能不同；硬件成本可能不同；能耗可能不同；实现复杂程度可能不同。 所以：

**逻辑功能等价不意味着性能等价。** **例题 2【自编训练：ISA 判断】** 以下哪些通常属于 ISA 的规定？ Ⅰ. 机器指令编码 Ⅱ. Cache 组相联度 Ⅲ. 程序员可见寄存器编号 Ⅳ. 流水线级数

答案：**Ⅰ、Ⅲ**

解析：机器指令编码与程序员可见寄存器属于 ISA 规定。 Cache 的组相联度和流水线级数属于具体实现。

**一种通用判断方法** 遇到类似选择题时，问自己：如果更换一颗采用相同 ISA、不同内部实现的 CPU，原机器代码是否仍然可以正确执行？ 如果可以，那么被更换的内部实现特性通常不属于 ISA 必须规定的内容。

## 冯·诺依曼结构与程序执行

### 冯·诺依曼计算机

**存储程序思想** 冯·诺依曼计算机最核心的思想是：

**存储程序。** 也就是：把程序指令和程序使用的数据保存在存储器中，然后由 CPU 自动取出指令并执行。 这里最重要的是两个词：

1. 存储程序
2. 自动执行

**为什么存储程序很重要？** 在早期某些计算设备中，改变计算任务可能需要改变线路连接、开关设置等。 而采用存储程序后，可以直接通过改变存储器中的程序来改变计算机的任务。 因此同一台硬件设备可以执行不同程序。 这也是通用计算机能够实现多种功能的重要基础。

**冯·诺依曼计算机的基本特点** 传统教材常见总结如下：

1. 由运算器、控制器、存储器、输入设备和输出设备五大部件组成。
2. 指令与数据都以二进制表示。
3. 指令与数据可以存放在同一存储器中。
4. 指令通常包含操作码和地址码等字段。
5. 指令通常按地址顺序执行，转移指令可以改变执行顺序。
6. 经典冯·诺依曼模型通常描述为以运算器为中心。

现代计算机通常强调以存储器为中心的数据交换组织。

注意：这里的“顺序执行”是一般工作方式，并不是说程序不能跳转。 分支、循环、函数调用、中断等都会影响控制流程。

**五大部件的作用**

| 部件 | 功能 |
|---|---|
| 运算器 | 算术运算、逻辑运算、比较等 |
| 控制器 | 取指、译码、控制执行 |
| 存储器 | 保存程序和数据 |
| 输入设备 | 接收外部信息 |
| 输出设备 | 输出处理结果 |

其中：$\boxed{ \text{CPU 核心结构} \approx \text{运算器} + \text{控制器} + \text{寄存器组} }$ 这是功能上的简化表达。 现代 CPU 还包含 Cache、流水线控制等复杂结构。

**运算器** 核心部件是 ALU。 ALU：Arithmetic Logic Unit，算术逻辑单元。 主要完成：

- 加法
- 减法
- 与运算
- 或运算
- 异或运算
- 比较运算

乘除法等功能可能由专门的运算电路完成。 **控制器** 控制器负责：获取机器指令；解释指令含义；产生控制信号；控制数据传送；协调各部件工作。

注意：**控制器负责组织指令执行，运算器负责执行相应运算。**

**CPU 如何区分指令与数据？** 这是非常重要的真题考点。 在经典冯·诺依曼模型中：指令和数据都是二进制位串。 例如：`00000000 00000000 00000000 00000101` 它可以表示：

- 整数 5
- 某段机器代码
- 地址
- 字符编码的一部分

到底表示什么，取决于处理器如何使用与解释这些二进制位。 因此：

**不能仅凭存储器中的二进制内容区分指令与数据。** **【2009 年真题】** 冯·诺依曼计算机中指令和数据均以二进制形式存放在存储器中，CPU 区分它们的依据是：A. 指令操作码的译码结果 B. 指令和数据的寻址方式 C. 指令周期的不同阶段 D. 指令和数据所在的存储单元

**答案：C** **解析** CPU 在取指阶段：根据 PC 给出的指令地址访问存储器。 取出的内容作为指令进行处理。 CPU 在执行阶段：根据指令要求访问操作数。 此时取得的内容作为数据进行处理。 因此，在这道题的传统模型中，区分依据是当前指令周期的不同阶段。

**为什么其他选项错误？** A：操作码译码发生在取得指令之后，不能直接作为访存时区分指令与数据的依据。 B：寻址方式规定如何寻找操作数，不是本题所问的指令与数据的根本区分依据。 D：指令与数据可以存放在相同的存储器中。 不存在必须使用两种物理存储单元的要求。

**易错点** 不能简单认为：进入 MDR 的一定是数据。 因为经典取指过程也可以让指令先经过 MDR，再进入 IR。

**【2019 年真题】** 下列关于冯·诺依曼计算机基本思想的叙述中，错误的是：A. 程序的功能都通过中央处理器执行指令实现 B. 指令和数据都用二进制数表示，形式上无差别 C. 指令按地址访问，数据都在指令中直接给出 D. 程序执行前，指令和数据需预先存放在存储器中

**答案：C** **解析** 错误的地方是：“数据都在指令中直接给出”。 操作数可能存在多个位置。 例如：第一种：立即数。 `ADD R1, R1, #5` 操作数 5 直接在指令中给出。 第二种：寄存器。 `ADD R1, R2, R3` 操作数来自寄存器。 第三种：主存。 `LOAD R1, [R2]` 操作数来自 R2 指定的存储单元。 因此：

**指令中的操作数不一定是立即数。** 这一结论还会在第四章“指令寻址方式”中反复使用。

**冯·诺依曼结构与哈佛结构**

| 特点 | 冯·诺依曼结构 | 哈佛结构 |
|---|---|---|
| 指令与数据 | 经典模型使用统一存储空间 | 指令与数据空间分离 |
| 访问通路 | 经典模型可以共用 | 可以使用独立通路 |
| 并行取指与访数 | 容易受到共享通路限制 | 便于独立访问 |
| 典型问题 | 存储访问可能成为性能瓶颈 | 结构和控制相对复杂 |

**冯·诺依曼瓶颈** CPU 需要不断从存储器获得指令和数据。 如果 CPU 的处理能力远远高于存储器传输能力，就可能出现：

```text
CPU 等待数据
    ↓
运算单元无法充分工作
    ↓
处理器性能受到存储访问限制
```

这就是经典冯·诺依曼瓶颈的主要思想。 **如何缓解？** 现代计算机使用：

- Cache
- 指令预取
- 流水线
- 多级存储结构
- 更高效的数据传输机制

来缓解相关问题。

注意：现代 CPU 即使具有分离的 L1 指令 Cache 和数据 Cache，也不意味着其软件可见的内存模型必然变成传统的纯哈佛结构。

### 计算机如何自动执行程序

**CPU 中几个重要寄存器** 本章至少要掌握四个寄存器。

| 寄存器 | 全称 | 作用 |
|---|---|---|
| PC | Program Counter | 保存下一条待取指令的地址 |
| IR | Instruction Register | 保存当前指令 |
| MAR | Memory Address Register | 保存本次访存地址 |
| MDR | Memory Data Register | 暂存本次访存读写的数据 |

**PC** PC 保存程序的取指位置。 假设程序指令固定为 4B，主存按字节编址：初始：$PC=100$ 依次顺序取指时：`100 → 104 → 108 → 112` 如果执行跳转指令：`JUMP 200` 那么下一次取指地址可能变成：$PC=200$

注意：PC 的变化方式由 ISA 和具体执行流程决定。 不能一律认为 PC 每次加 1。

**MAR** MAR 保存本次访存地址。 取指时，MAR 可以得到 PC 提供的地址。 读取操作数时，MAR 可以保存操作数地址。 所以：

**PC 和 MAR 不是同一个寄存器。** **MDR** MDR 保存访存过程中传送的数据。 它既可能暂存从主存读出的内容，也可能暂存准备写入主存的内容。

**IR** IR 保存当前指令，供控制器译码和执行控制使用。

**一条机器指令的执行过程** 以经典的非流水简化数据通路为例。

```text
PC
 |
 | 提供下一条指令地址
 ↓
MAR
 |
 | 发出访存地址
 ↓
主存
 |
 | 返回指令
 ↓
MDR
 |
 | 传送指令
 ↓
IR
 |
 | 指令译码
 ↓
控制器
 |
 +-- 读取操作数
 |
 +-- 控制 ALU 运算
 |
 +-- 控制访存
 |
 +-- 控制结果写回
 |
 ↓
更新 PC，继续执行
```

整个过程可以概括为：`取指 → 译码 → 执行` 实际指令执行还可能包含：操作数读取；地址计算；数据访存；结果写回。

**为什么 CPU 能够自动执行下一条指令？** 关键就在 PC。 CPU 完成当前指令的相关操作后，会按照控制流规则继续取得下一条指令。 所以：存储程序思想解决“程序在哪里”。 PC 和指令执行控制解决“程序怎样连续运行”。

**指令、微指令和伪指令的区别**

| 名称 | 本质 |
|---|---|
| 机器指令 | ISA 定义的机器操作 |
| 汇编指令 | 机器指令的人类可读助记符表示 |
| 微指令 | 微程序控制器内部使用的控制信息 |
| 伪指令 | 汇编器处理或展开的特殊表示 |

**【2024 年真题】** 通常将汇编语言程序中实现特定功能的指令序列定义成一条伪指令。 下列选项中，CPU 能理解并直接执行的是：Ⅰ. 伪指令 Ⅱ. 微指令 Ⅲ. 机器指令 Ⅳ. 汇编指令 A. 仅Ⅰ、Ⅳ B. 仅Ⅱ、Ⅲ C. 仅Ⅲ、Ⅳ D. 仅Ⅰ、Ⅲ、Ⅳ

**答案：B** **解析** 机器指令：由 CPU 按 ISA 规定执行。 微指令：在采用微程序控制的 CPU 中，由内部微程序控制机制读取和执行。 汇编指令：需要经过汇编转换。 伪指令：需要由汇编器按其规则展开或处理。 所以选择Ⅱ、Ⅲ。

注意：微指令并不属于普通机器语言程序员直接使用的 ISA 指令。 它处于 CPU 内部控制层次。

### 程序语言与程序转换

**三种程序设计语言**

| 语言 | 特点 | CPU 能否直接执行 |
|---|---|---|
| 机器语言 | 机器指令的二进制编码 | 能 |
| 汇编语言 | 使用助记符表示机器操作 | 不能直接执行文本 |
| 高级语言 | 更接近人的表达方式 | 不能直接执行源代码 |

**机器语言** 机器语言是 CPU 最终执行的形式。 不同 ISA 的机器指令编码通常不同。 所以某种架构的机器代码通常不能直接在另一种不兼容的 ISA 上运行。

**汇编语言** 例如：`ADD R1, R2, R3` 使用助记符描述机器操作。 必须经过汇编器转换。

**高级语言** 例如：`int c = a + b;` 高级语言需要通过编译器、解释器或相应运行时机制执行。 解释型语言也不是 CPU 直接执行高级语言文本。 CPU 实际执行的是解释器、虚拟机或编译后代码对应的机器指令。

**从源程序到可执行程序** 以 C 程序为例：

```text
hello.c
   |
   | 预处理
   ↓
hello.i
   |
   | 编译
   ↓
hello.s
   |
   | 汇编
   ↓
hello.o
   |
   | 链接
   ↓
可执行文件
   |
   | 装载
   ↓
运行中的程序
   |
   ↓
CPU 执行机器指令
```

**预处理** 主要完成：

- 宏展开
- 头文件包含
- 条件编译

例如：`#define N 100` 预处理器会按照宏定义规则处理相关文本。

**编译** 将高级语言转换为较低层的程序表示。 典型编译过程包含：

- 词法分析
- 语法分析
- 语义分析
- 中间代码处理
- 优化
- 代码生成

在典型 GCC 教学流程中，可以把编译阶段理解为生成汇编代码。 但实际编译器也可以采用不同的内部流程或直接生成机器级目标代码。

**汇编** 把汇编程序转换为机器级目标文件。 目标文件可能包含：

- 机器代码
- 符号表
- 重定位信息
- 数据段等

**链接** 把多个目标文件以及需要的库组织成可执行文件。 主要工作：

1. 符号解析
2. 重定位

例如：程序调用其他文件定义的函数。 链接器需要解决相应的符号引用。

**装载** 操作系统为程序建立运行所需的进程映像和地址空间，并安排进入程序执行过程。

注意：**链接完成不代表程序已经进入 CPU 执行。**

**相关真题** **【2015 年真题】** 计算机硬件能够直接执行的是：Ⅰ. 机器语言程序 Ⅱ. 汇编语言程序 Ⅲ. 硬件描述语言程序

**答案：仅Ⅰ** 汇编语言需要经过汇编。 硬件描述语言通常用于描述电路，不是普通 CPU 直接执行的机器语言程序。

**【2016 年真题】** 将高级语言源程序转换为机器级目标代码文件的程序是：A. 汇编程序 B. 链接程序 C. 编译程序 D. 解释程序

**答案：C** 这道题考查编译程序的主要作用。 注意区分：“高级语言到机器级目标代码”是整体翻译任务；“汇编语言到机器码”是汇编器的任务。 在具体工具链中，编译驱动程序可能组织多个阶段协作完成目标文件。

**【2022 年真题】** 将高级语言源程序转换为可执行目标文件的主要过程是：A. 预处理→编译→汇编→链接 B. 预处理→汇编→编译→链接 C. 预处理→编译→链接→汇编 D. 预处理→汇编→链接→编译

**答案：A** 这是典型的顺序识记题。 必须区分：

- 编译
- 汇编
- 链接
- 装载

尤其注意：装载通常发生在运行可执行文件时，不是生成可执行文件的必要构建步骤。

## 性能指标、主频与平均 CPI

### 计算机性能指标

这是本章最重要的计算部分。 **性能评价的两个基本维度** 计算机性能可以从两个角度观察。

**响应时间** 响应时间关注：完成一个任务需要多长时间。 例如：一个程序从开始到结束需要 10 秒。 响应时间越短，通常意味着用户等待越少。

**吞吐量** 吞吐量关注：单位时间内系统完成多少任务。 例如：服务器每秒完成 1000 个请求。

**区别** 假设：单核系统一次处理一个任务。 双核系统可以同时处理两个独立任务。 如果任务无法利用多个核心加速：增加处理器数量可能显著增加总吞吐量。 但单个任务的响应时间不一定缩短。 因此：

**响应时间描述单任务完成速度。** **吞吐量描述整体任务处理能力。**

**CPU 时间与总运行时间** 这是极容易混淆的概念。

**总运行时间** 也称经过时间、墙钟时间。 可能包含：CPU 执行时间；I/O 等待；调度等待；排队等待；其他系统开销。

**CPU 时间** 通常指 CPU 实际为相应程序执行工作所消耗的时间。 进一步可以分为：用户 CPU 时间和系统 CPU 时间。 用户 CPU 时间：执行用户态代码消耗的 CPU 时间。 系统 CPU 时间：操作系统在内核态为该程序处理相关工作消耗的 CPU 时间。

**最重要的区别** CPU 时间计算公式：$T_{\mathrm{CPU}} = \frac{IC\times CPI}{f}$ 这里：$IC$：执行的机器指令数；$CPI$：平均每条指令的时钟周期数；$f$：CPU 时钟频率。 它计算的是相应统计口径下的 CPU 执行时间。 不能随意把总墙钟时间代入。

### 时钟周期、主频与 CPI

**主频和时钟周期** **主频** 主频表示每秒有多少个时钟周期。 单位：Hz。 例如：$f=2\,\mathrm{GHz} =2\times10^9\,\mathrm{Hz}$ 表示每秒有：$2\times10^9$ 个时钟周期。

**时钟周期** 时钟周期是相邻同类有效时钟边沿之间的时间。 公式：$\boxed{ T_{\mathrm{clk}}=\frac1f }$ 例如：主频 2GHz。 $T_{\mathrm{clk}} = \frac1{2\times10^9} = 0.5\,\mathrm{ns}$

**常见换算**

| 主频 | 时钟周期 |
|---|---|
| 100MHz | 10ns |
| 200MHz | 5ns |
| 500MHz | 2ns |
| 1GHz | 1ns |
| 2GHz | 0.5ns |
| 4GHz | 0.25ns |

必须记住：$1\,\mathrm{ms}=10^{-3}\,\mathrm{s}$ $1\,\mu\mathrm{s}=10^{-6}\,\mathrm{s}$ $1\,\mathrm{ns}=10^{-9}\,\mathrm{s}$

**三个周期的区别** **时钟周期** 同步数字电路的基本时钟节拍。

**机器周期** 传统 CPU 模型中，完成一个相对完整的基本操作所需的时间。 例如取指机器周期。

**指令周期** 从开始执行一条指令，到完成这条指令的整个过程。 传统非流水 CPU 中，一条指令可能经历若干机器周期。 每个机器周期又可能包含多个时钟周期。 但现代流水线可以让不同指令的执行过程重叠。 因此不能认为现代 CPU 必须完整执行一条指令之后才开始下一条指令。

**CPI** CPI：Cycles Per Instruction。 含义：

**平均每条机器指令需要多少个时钟周期。** 公式：$\boxed{ CPI = \frac{N_{\mathrm{cycle}}}{IC} }$ 其中：$N_{\mathrm{cycle}}$ 为总时钟周期数。 $IC$ 为执行的机器指令条数。 例如：程序执行了 1000 条指令。 总共消耗 3000 个时钟周期。 则：$CPI=\frac{3000}{1000}=3$

**CPI 一定大于等于 1 吗？** 不一定。 对于理想化单发射流水线处理器，稳定执行时平均 CPI 可以接近 1。 对于超标量处理器：每个周期可能完成多条指令。 例如平均每周期完成 2 条指令：$IPC=2$ 那么：$CPI=0.5$ 所以：

**平均 CPI 可以小于 1。** 但这不意味着单条指令的执行延迟只有半个时钟周期。 这里必须区分：

- 单条指令的执行延迟
- 一段程序的平均指令吞吐率

**IPC** IPC：Instructions Per Cycle。 含义：平均每个时钟周期完成多少条指令。 公式：$\boxed{ IPC = \frac{IC}{N_{\mathrm{cycle}}} }$ 在相同的统计区间和相同指令计数口径下：$\boxed{ IPC=\frac1{CPI} }$ 例如：$CPI=2$ 则：$IPC=0.5$ 表示平均两个周期完成一条指令。

**多种指令的平均 CPI** 这是历年真题反复出现的考点。 假设程序有三类指令。

| 指令类型 | 指令条数 | CPI |
|---|---:|---:|
| A | 100 | 1 |
| B | 200 | 2 |
| C | 700 | 4 |

总指令数：$IC=100+200+700=1000$ 总时钟周期数：$N_{\mathrm{cycle}} = 100\times1+200\times2+700\times4$ $N_{\mathrm{cycle}}=3300$ 因此：$\boxed{ CPI_{\mathrm{avg}} = \frac{3300}{1000} = 3.3 }$

**加权平均公式** 如果给出各类指令所占比例：$\boxed{ CPI_{\mathrm{avg}} = \sum_i p_i CPI_i }$ 其中：$p_i=\frac{IC_i}{IC}$ 所以：$CPI_{\mathrm{avg}} = 0.1\times1 + 0.2\times2 + 0.7\times4$ $=3.3$

**最常见的错误** 直接计算：$\frac{1+2+4}{3}$ 这是错误的。 因为三类指令数量不同。

**平均 CPI 必须按照各类指令在总指令数中的占比加权。**

## CPU 执行时间与性能计算

### CPU 执行时间核心公式

**公式推导** 假设程序执行：$IC$ 条指令。 每条指令平均需要：$CPI$ 个周期。 那么：$N_{\mathrm{cycle}}=IC\times CPI$ 每个周期的长度为：$T_{\mathrm{clk}}=\frac1f$ 因此：$T_{\mathrm{CPU}} = N_{\mathrm{cycle}}T_{\mathrm{clk}}$ 得到：

$\boxed{ T_{\mathrm{CPU}} = IC\times CPI\times T_{\mathrm{clk}} }$ 等价于：$\boxed{ T_{\mathrm{CPU}} = \frac{IC\times CPI}{f} }$ 这是本章最重要的公式。

**三个决定因素** CPU 执行时间取决于：

1. 动态执行的指令数 IC
2. 平均 CPI
3. 主频 f

任何一个因素发生变化，都可能影响程序运行时间。 **三个因素分别受什么影响？**

| 参数 | 主要影响因素 |
|---|---|
| IC | 算法、编译器、ISA |
| CPI | 指令组合、流水线、Cache、数据通路 |
| 主频 | 电路设计、时钟系统、微体系结构 |

所以：主频提高不意味着执行时间一定缩短。 指令条数减少也不意味着执行时间一定缩短。 必须看三个因素的综合变化。

**基础计算题** 某处理器：$f=2\,\mathrm{GHz}$ 执行指令数：$IC=10^9$ 平均：$CPI=2$ 求 CPU 时间。 解：$T = \frac{10^9\times2}{2\times10^9}$ $\boxed{ T=1\,\mathrm{s} }$ 这种题的核心就是：统一单位，代入公式。

**程序性能优化的通用公式** 优化前：$T_{\mathrm{old}} = \frac{IC_{\mathrm{old}}CPI_{\mathrm{old}}} {f_{\mathrm{old}}}$ 优化后：$T_{\mathrm{new}} = \frac{IC_{\mathrm{new}}CPI_{\mathrm{new}}} {f_{\mathrm{new}}}$ 两式相除：

$$
\boxed{
\frac{T_{\mathrm{new}}}{T_{\mathrm{old}}}
=
\frac{IC_{\mathrm{new}}}{IC_{\mathrm{old}}}
\cdot
\frac{CPI_{\mathrm{new}}}{CPI_{\mathrm{old}}}
\cdot
\frac{f_{\mathrm{old}}}{f_{\mathrm{new}}}
}
$$

这是处理优化前后比较题最有用的公式。 **通用方法** 如果题目说：指令数减少 20%。 那么：$IC'=0.8IC$ 如果 CPI 增加 25%：$CPI'=1.25CPI$ 如果主频增加 50%：$f'=1.5f$ 则：$\frac{T'}T = \frac{0.8\times1.25}{1.5} = \frac23$ 所以新的执行时间为原来的：$\frac23$ 整体加速比为：$S=\frac{T}{T'}=1.5$

**为什么比例法很重要？** 因为很多真题并没有给出实际指令条数。 只给出：指令数变化百分比；CPI 变化百分比；主频变化百分比。 此时不需要假设具体执行多少条指令。 直接比较比例即可。

### 历年性能计算真题

**【2013 年真题】平均 CPI 与 MIPS**

题目：某计算机主频为 1.2GHz。 指令分类如下。

| 指令类型 | 比例 | CPI |
|---|---:|---:|
| A | 50% | 2 |
| B | 20% | 3 |
| C | 10% | 4 |
| D | 20% | 5 |

求机器的 MIPS。 **第一步：计算平均 CPI** $CPI = 0.5\times2 + 0.2\times3 + 0.1\times4 + 0.2\times5$ $=1+0.6+0.4+1$ $\boxed{CPI=3}$

**第二步：计算指令执行速率** $IPS=\frac{f}{CPI}$ 因此：$IPS = \frac{1.2\times10^9}{3}$ $=4\times10^8$

**第三步：换算 MIPS** MIPS 表示每秒百万条指令。 $MIPS=\frac{IPS}{10^6}$ 所以：$\boxed{MIPS=400}$

答案：**400 MIPS。**

**题型总结** 出现：

```text
各类指令比例
       +
     CPI
       +
     主频
```

优先计算加权平均 CPI。 然后根据问题计算：

- CPU 执行时间
- MIPS
- IPS
- 总时钟周期数

**【2022 年真题】平均 CPI 与 CPU 时间**

题目：计算机主频为 1GHz。 程序执行 10000 条指令。 其中：80% 的指令需要 1 个时钟周期。 20% 的指令需要 10 个时钟周期。 求平均 CPI 和执行时间。

**第一步：计算 CPI** $CPI = 0.8\times1+0.2\times10$ $\boxed{CPI=2.8}$

**第二步：计算总周期数** $N_{\mathrm{cycle}} = 10000\times2.8$ $\boxed{ N_{\mathrm{cycle}}=28000 }$

**第三步：计算执行时间** 主频：$f=10^9\,\mathrm{Hz}$ 因此：$T = \frac{28000}{10^9}$ $=2.8\times10^{-5}\,\mathrm{s}$ $\boxed{ T=28\,\mu\mathrm{s} }$

**易错点** 很多人会误认为：$28000\,\mathrm{ns}=28\,\mathrm{ms}$ 实际上：$28000\,\mathrm{ns}=28\,\mu\mathrm{s}$ 单位换算错误会直接导致选错。

**【2023 年真题】GIPS 与 CPU 时间** 已知：$f=1.5\,\mathrm{GHz}$ $IC=5\times10^5$ $CPI=1.2$ 求：

1. 指令执行速率
2. CPU 执行时间

**第一步：计算 IPS** $IPS = \frac{1.5\times10^9}{1.2}$ $=1.25\times10^9$ 因此：$\boxed{ IPS=1.25\,\mathrm{GIPS} }$

**第二步：计算时间** $T = \frac{5\times10^5\times1.2} {1.5\times10^9}$ $=4\times10^{-4}\,\mathrm{s}$ 所以：$\boxed{ T=0.4\,\mathrm{ms} }$ 这道题要理解：IPS 体现单位时间执行多少条指令。 CPU 时间体现执行完指定程序需要多长时间。

**【2014 年真题】编译优化是否一定有效？**

题目：程序原执行时间为：$T=20\,\mathrm{s}$ 优化后：指令数变为原来的 70%；CPI 变为原来的 1.2 倍；主频不变。 求新的执行时间。

**解法一：比例法** $\frac{T'}T = 0.7\times1.2$ $=0.84$ 因此：$T' = 20\times0.84$ $\boxed{ T'=16.8\,\mathrm{s} }$

**解法二：总周期数思想** 优化前：$N_{\mathrm{cycle}}=IC\times CPI$ 优化后：$N'_{\mathrm{cycle}} = 0.7IC\times1.2CPI$ $=0.84IC\times CPI$ 说明优化后只需要原来的 84% 的时钟周期数。 由于主频不变：CPU 时间同样变为原来的 84%。

**为什么减少 30% 的指令，时间没有减少 30%？** 因为平均 CPI 反而增加了。 例如：编译器用一条复杂指令替代多条简单指令。 虽然总指令数变少，但每条指令平均消耗的周期数可能增加。 这就是该题最重要的思想。

**【2017 年真题】主频高反而更慢** 题目给出两台机器。

| 参数 | M1 | M2 |
|---|---:|---:|
| 主频 | 1.5GHz | 1.2GHz |
| 平均 CPI | 2 | 1 |

两台机器使用相同 ISA，题目按相同动态指令数比较同一个基准程序。 求：$\frac{T_1}{T_2}$

**解题** $T=\frac{IC\times CPI}{f}$ 所以：$\frac{T_1}{T_2} = \frac{IC\times2/1.5} {IC\times1/1.2}$ 约去 IC：$= \frac{2\times1.2}{1.5}$ $\boxed{ \frac{T_1}{T_2}=1.6 }$

**结论** M1 主频更高，但执行时间更长。 其原因是：M1 的平均 CPI 更大。

**特别注意** “相同 ISA”并不必然意味着不同编译器生成的程序具有相同动态指令数。 这类比较题约去 IC，必须满足指令数相同的题设条件或默认假设。 如果两台机器的动态指令数不同，就必须保留 IC 项。

## Amdahl 定律、IPS 与模拟题

### 局部优化与 Amdahl 定律

**为什么局部加速不等于整体加速？** 假设：某程序执行 100 秒。 其中：90 秒属于 CPU 计算。 10 秒属于 I/O 等待。 如果 CPU 速度提高 2 倍：CPU 计算部分变成：$\frac{90}{2}=45\,\mathrm{s}$ 但 I/O 部分仍然需要：$10\,\mathrm{s}$ 所以：$T'=45+10=55\,\mathrm{s}$ 整体加速比为：$S=\frac{100}{55}\approx1.818$ 而不是 2。 原因：

**没有得到优化的部分仍然消耗时间。** **Amdahl 定律推导** 假设：原程序执行时间为：$T$ 其中比例：$p$ 的时间可以优化。 其他部分占：$1-p$ 现在把可优化部分的执行速度提高到原来的：$s$ 倍。 优化后的时间为：$T' = (1-p)T+\frac{pT}{s}$ 两边除以：$T$ 得到：$\frac{T'}T = (1-p)+\frac ps$ 整体加速比：$S=\frac{T}{T'}$ 最终得到：

$\boxed{ S= \frac1{(1-p)+p/s} }$ 这就是 Amdahl 定律。

**最重要的理解** 这里的：$p$ 表示原来运行时间中，可优化部分所占的比例。 不是指令条数比例。 两者不能混淆。

**【2012 年真题】CPU 速度提高 50%**

<Callout type="warn" title="速度与时间变化不是同一比例">

题目：某基准程序原运行时间为 100 秒。 其中：CPU 时间为 90 秒。 I/O 时间为 10 秒。 现在 CPU 速度提高 50%。 I/O 速度不变。 求新运行时间。

</Callout>

**第一步：理解速度提高 50%** 速度提高 50%：$s=1.5$ 不是执行时间直接减少 50%。

**第二步：计算新的 CPU 时间** $T'_{\mathrm{CPU}} = \frac{90}{1.5}$ $=60\,\mathrm{s}$

**第三步：加上没有优化的部分** $T'=60+10$ $\boxed{ T'=70\,\mathrm{s} }$

**使用 Amdahl 定律验证** $p=0.9$ $s=1.5$ 所以：$S = \frac1{0.1+0.9/1.5}$ $=\frac1{0.7}$ $\approx1.4286$ 新运行时间：$T'=\frac{100}{1.4286}$ $\boxed{T'=70\,\mathrm{s}}$ 两种方法一致。

**本题最容易错在哪里？** “速度提高 50%”不等于“时间减少 50%”。 速度为原来的 1.5 倍时：$T'=\frac{T}{1.5}$ 也就是原来的：$\frac23$

**Amdahl 定律的极限** 如果可优化部分无限快：$s\rightarrow\infty$ 那么：$\frac ps\rightarrow0$ 因此：$\boxed{ S_{\max} = \frac1{1-p} }$ 例如：90% 的时间可以优化。 则：$p=0.9$ 即使这 90% 的部分无限快：$S_{\max} = \frac1{0.1}$ $\boxed{S_{\max}=10}$ 因此程序整体最多加速 10 倍。 这是因为剩余 10% 的时间无法被消除。

**【自编综合题】反推局部加速倍数** 某程序原执行时间的 80% 可以加速。 现在希望程序整体加速 4 倍。 问可优化部分至少需要加速多少倍？

**第一步：建立公式** $4 = \frac1{0.2+0.8/s}$

**第二步：两边取倒数** $0.25 = 0.2+\frac{0.8}{s}$ 因此：$\frac{0.8}{s}=0.05$

**第三步：求 s** $s=\frac{0.8}{0.05}$ $\boxed{s=16}$

**检查合理性** 理论最大加速比：$S_{\max} = \frac1{1-0.8} = 5$ 目标加速比为 4，小于理论最大值 5。 因此存在有限的局部加速倍数能够实现目标。 如果题目要求整体加速 6 倍，则在这些条件下不可能实现。

### IPS、MIPS、FLOPS

**IPS 与 MIPS** IPS：Instructions Per Second。 每秒执行的机器指令条数。 $\boxed{ IPS=\frac f{CPI} }$ MIPS：Million Instructions Per Second。 每秒百万条机器指令。 $\boxed{ MIPS=\frac{f}{CPI\times10^6} }$ 如果 f 使用 MHz 为单位：$\boxed{ MIPS=\frac{f_{\mathrm{MHz}}}{CPI} }$

**MIPS 越高，CPU 一定越快吗？** 不一定。 不同 ISA 的一条指令可能完成不同的工作量。 例如：CPU A：每秒执行 10 亿条指令。 完成某个任务需要 100 亿条指令。 那么：$T_A=10\,\mathrm{s}$ CPU B：每秒执行 5 亿条指令。 但完成同样任务只需要 10 亿条指令。 那么：$T_B=2\,\mathrm{s}$ 虽然 B 的 MIPS 更低，但完成这个任务反而更快。 因此：

**跨 ISA 比较实际程序性能，应该优先使用同一工作负载的执行时间。** **FLOPS** FLOPS：Floating-point Operations Per Second。 表示每秒完成多少次浮点运算。

| 指标 | 数量级 |
|---|---:|
| MFLOPS | $10^6$ |
| GFLOPS | $10^9$ |
| TFLOPS | $10^{12}$ |
| PFLOPS | $10^{15}$ |
| EFLOPS | $10^{18}$ |

注意：FLOPS 统计浮点操作数量。 MIPS 统计机器指令数量。 一条向量指令可以完成多个浮点运算。 所以：

**一条机器指令不一定对应一次浮点操作。** **【2011 年真题】** 下列选项中，描述浮点数操作速度指标的是：A. MIPS B. CPI C. IPC D. MFLOPS

**答案：D**

解析：MFLOPS 专门表示每秒百万次浮点运算。 其余指标并不专门统计浮点操作。

**【2021 年真题】PFLOPS 数量级** 题目给出：某超级计算机浮点运算速度为：$93.0146\,\mathrm{PFLOPS}$ 求每秒浮点操作次数。 因为：$1\,\mathrm{PFLOPS} = 10^{15}\,\mathrm{FLOPS}$ 所以：$93.0146\times10^{15}$ $= 9.30146\times10^{16}$ 因此：$\boxed{ 9.30146\times10^{16} }$ 次每秒。 约为 9.3 亿亿次每秒。

### 模拟题综合精讲

**【王道模拟题】慢指令优化是否值得？**

题目：某类指令 I：占全部指令的 10%。 原 CPI 为 20。 其他指令平均 CPI 为 5。 现在进行硬件优化：I 的 CPI 降至 10。 但 CPU 时钟周期延长 10%。 问：

1. 原来 I 占 CPU 总执行时间的比例是多少？
2. 是否值得进行优化？

**第一步：计算原平均 CPI** $CPI_{\mathrm{old}} = 0.1\times20+0.9\times5$ $=2+4.5$ $\boxed{ CPI_{\mathrm{old}}=6.5 }$

**第二步：计算 I 的时间占比** 设总指令数为 N。 I 的总周期数：$C_I=0.1N\times20=2N$ 程序总周期数：$C=6.5N$ 因此 I 的时间占比：$p = \frac{2N}{6.5N}$ $\boxed{ p\approx30.77\% }$

注意：I 只占总指令数的 10%。 但消耗的 CPU 时间约为 30.77%。 这是因为 I 的 CPI 远高于其他指令。

**第三步：计算优化后的 CPI** $CPI_{\mathrm{new}} = 0.1\times10+0.9\times5$ $=1+4.5$ $\boxed{ CPI_{\mathrm{new}}=5.5 }$

**第四步：考虑时钟周期变化** 设原时钟周期为：$\tau$ 则新时钟周期：$\tau'=1.1\tau$ 优化前时间：$T_{\mathrm{old}} = 6.5N\tau$ 优化后时间：$T_{\mathrm{new}} = 5.5N\times1.1\tau$ $=6.05N\tau$ 所以：$\frac{T_{\mathrm{new}}}{T_{\mathrm{old}}} = \frac{6.05}{6.5}$ $\approx0.93077$

执行时间减少：$1-0.93077$ $\boxed{ 6.92\% }$

**最终答案**

1. I 原来占 CPU 时间约 30.77%。
2. 优化后执行时间减少约 6.92%，值得优化。

**这道题真正考什么？** 同时考查：指令数比例；时间比例；加权平均 CPI；时钟周期；优化前后执行时间。 最关键的结论是：$\boxed{ T_{\mathrm{CPU}} = IC\times CPI\times T_{\mathrm{clk}} }$ 即使 CPI 降低，也必须检查时钟周期是否发生变化。

**【王道模拟题】不同机器与编译器**

题目：两台机器 M1 和 M2：$f_1=800\,\mathrm{MHz}$ $f_2=400\,\mathrm{MHz}$ 各类指令 CPI 如下。

| 类型 | M1 CPI | M2 CPI | C1 比例 | C2 比例 |
|---|---:|---:|---:|---:|
| A | 2 | 1 | 30% | 30% |
| B | 3 | 2 | 50% | 20% |
| C | 4 | 1.5 | 20% | 50% |

已知不同编译器生成的总指令条数相同。 求：

1. 使用 C1 时，M1 比 M2 快多少？
2. 使用 C2 时，M2 比 M1 快多少？

**第一问：使用 C1** M1 的 CPI：$CPI_{1,C1} = 0.3\times2+0.5\times3+0.2\times4$ $=2.9$ M2 的 CPI：$CPI_{2,C1} = 0.3\times1+0.5\times2+0.2\times1.5$ $=1.6$ 由于指令数相同：$\frac{V_1}{V_2} = \frac{T_2}{T_1}$ 因此：$\frac{V_1}{V_2} = \frac{1.6/400}{2.9/800}$

$=\frac{3.2}{2.9}$ $\boxed{ \frac{V_1}{V_2}\approx1.10 }$ M1 约为 M2 的 1.10 倍速度。

**第二问：使用 C2** M1：$CPI_{1,C2} = 0.3\times2+0.2\times3+0.5\times4$ $=3.2$ M2：$CPI_{2,C2} = 0.3\times1+0.2\times2+0.5\times1.5$ $=1.45$ 求 M2 相对 M1 的性能比：$\frac{V_2}{V_1} = \frac{T_1}{T_2}$ $= \frac{3.2/800}{1.45/400}$ $=\frac{1.6}{1.45}$

$\boxed{ \frac{V_2}{V_1}\approx1.10 }$ **这道题的核心认识** 同样的机器，使用不同编译器生成不同指令组合，性能表现也可能变化。 高主频的机器不一定总是更快。 甚至同一对机器面对不同指令组合时，性能优势可以反转。 因此：

**性能是机器、程序和编译结果共同作用的结果。** **【模拟题】Cache 与 CPI 的综合计算** 这道题虽然涉及第三章 Cache，但核心仍然是第一章 CPU 时间公式。 题目条件：机器主频为：$100\,\mathrm{MHz}$ 原程序使用乘 4 指令。 优化后将其替换为左移 2 位指令。 原程序：执行时间 12 秒；乘 4 指令命中 Cache 时 CPI 为 94；Cache 命中率 90%。 优化后：

执行时间 10 秒；左移指令命中 Cache 时 CPI 为 3；Cache 命中率 99%。 未命中时均额外增加 100 个周期。 求替换的指令数量。

**第一步：计算原指令的平均 CPI** 未命中率：$1-0.9=0.1$ 原指令平均 CPI：$CPI_{\mathrm{old}} = 94+0.1\times100$ $\boxed{104}$

**第二步：计算优化后指令的平均 CPI** 未命中率：$1-0.99=0.01$ 因此：$CPI_{\mathrm{new}} = 3+0.01\times100$ $\boxed{4}$

**第三步：计算替换一条节省多少周期** $\Delta C_{\mathrm{one}} = 104-4$ $\boxed{ \Delta C_{\mathrm{one}}=100 }$

**第四步：计算整个程序节省多少周期** 程序时间减少：$\Delta T=12-10=2\,\mathrm{s}$ 主频：$f=100\times10^6$ 所以：$\Delta C = \Delta T\times f$ $=2\times100\times10^6$ $\boxed{ \Delta C=2\times10^8 }$

**第五步：反推替换数量** $N = \frac{2\times10^8}{100}$ $\boxed{ N=2\times10^6 }$ 即：

**替换了 200 万条动态执行的指令。** **通用方法** 这类问题可以归纳为：$\boxed{ \text{替换次数} = \frac{\text{总节省周期数}} {\text{每次平均节省周期数}} }$ 但前提是：其他指令的执行开销、运行环境等保持不变，题目中的时间差可以归因于所讨论的替换。

**【模拟题勘误】原题选项全部不正确** 有一道模拟题值得特别注意。 某计算机：$f=200\,\mathrm{MHz}$ 指令构成如下。

| 类型 | CPI | 指令条数 |
|---|---:|---:|
| A | 1 | 4500 |
| B | 3 | 200 |
| C | 1 | 500 |
| D | 2 | 800 |

求执行时间和 MIPS。 **第一步：总指令数** $IC=4500+200+500+800$ $\boxed{IC=6000}$

**第二步：总周期数** $C = 4500\times1 + 200\times3 + 500\times1 + 800\times2$ $=4500+600+500+1600$ $\boxed{C=7200}$

**第三步：执行时间** $T=\frac{7200}{200\times10^6}$ $=3.6\times10^{-5}\,\mathrm{s}$ $\boxed{ T=36\,\mu\mathrm{s} }$

**第四步：MIPS** $MIPS = \frac{IC}{T\times10^6}$ $= \frac{6000}{36\times10^{-6}\times10^6}$ $\boxed{ MIPS\approx166.7 }$

**正确结果** $\boxed{ 36\,\mu\mathrm{s},\quad166.7\,\mathrm{MIPS} }$ 此题原选项存在错误，需要依据计算结果进行勘误。 这里真正需要掌握的不是选项，而是：

**不能为了匹配选项而改变正确的计算结果。** 遇到题目数据与选项不一致时，先核对：指令数是否求对；CPI 是否加权；主频单位是否统一；ns 与微秒是否转换正确。 如果计算过程无误，而原选项全部不匹配，就应考虑题目存在问题。

## 机器字长、主存与编址

### 机器字长、寄存器与寻址能力

**机器字长** 机器字长通常指 CPU 一次能够处理的基本二进制数据宽度。 例如：32 位 CPU。 64 位 CPU。 机器字长通常与：

- ALU 的基本运算宽度
- 通用寄存器的体系结构宽度

密切相关。 但不能据此推断所有寄存器和总线都具有同样的位宽。

**几个容易混淆的长度**

| 概念 | 含义 |
|---|---|
| 机器字长 | CPU 基本处理数据的宽度 |
| 存储字长 | 存储器一个存储字的宽度 |
| 指令字长 | 一条机器指令的编码长度 |
| 数据总线宽度 | 一次并行传输的数据宽度 |
| MAR 位数 | 能表示的存储地址位数 |
| MDR 位数 | 经典模型中与一次存储数据传送宽度相关 |

**机器字长不等于指令字长** 例如：64 位 CPU 可能采用 32 位定长指令。 也可能采用变长指令格式。 因此：64 位 CPU 不意味着每条机器指令都是 64 位。

**机器字长不等于数据总线宽度** 例如：某机器 CPU 基本数据宽度为 32 位。 但外部数据总线可能是 64 位。 所以不能仅凭机器字长判断总线宽度。

**MAR 与 MDR 的区别** MAR：用于保存地址。 MDR：用于暂存访存数据。 所以：MAR 位数主要与地址编码能力相关。 MDR 位数主要与存储器数据传送组织相关。

**【2020 年真题】机器字长**

题目：通常情况下，下列部件中，其位数与机器字长相同的是：Ⅰ. ALU Ⅱ. 指令寄存器 Ⅲ. 通用寄存器 Ⅳ. 浮点寄存器

**答案：Ⅰ、Ⅲ** **解析** 按 408 教材的典型机器字长模型：ALU 与通用寄存器通常采用机器字长对应的基本运算宽度。 但指令寄存器由指令编码长度决定。 浮点寄存器则可能采用不同的数据格式和宽度。 所以：不能认为 IR 和浮点寄存器都必须等于机器字长。

注意：这是传统教材中的基本模型和对应题目的判断口径。 真实 CPU 可以支持多个不同位宽的数据通路和寄存器。

### 主存容量与寻址计算

**什么是编址单位？** 这是解决所有寻址容量题的第一步。 所谓编址单位，就是：

**一个存储地址对应多少存储空间。** 常见有：

- 按字节编址
- 按字编址

**按字节编址** 一个地址对应：$1\,\mathrm{B}=8\,\mathrm{bit}$ 如果地址共有：$2^{20}$ 个。 那么最大可寻址容量为：$2^{20}\,\mathrm{B}$ 即：$\boxed{1\,\mathrm{MiB}}$

<Callout type="warn" title="容量计算先看编址单位">

**按字编址** 假设机器一个字为：$32\,\mathrm{bit}=4\,\mathrm{B}$ 如果可以表示：$2^{20}$ 个字地址。 则理论可寻址容量为：$2^{20}\times4\,\mathrm{B}$ $\boxed{4\,\mathrm{MiB}}$

</Callout>

注意：同样是 20 位地址。 按字节编址和按字编址得到的最大容量可以不同。

**MAR 位数** 假设 MAR 有 n 位。 最多可以表示：$\boxed{2^n}$ 个不同地址。 如果每个地址对应：$W\,\mathrm{bit}$ 那么理论可寻址容量：$\boxed{ C=2^n\times W\,\mathrm{bit} }$ 如果编址单位为 B 字节：$\boxed{ C=2^n\times B\,\mathrm{B} }$

**重要区别** MAR 位数决定的是相应简化模型中可表示的地址范围。 不一定等于实际安装的内存容量。 例如：32 位字节地址：$2^{32}\,\mathrm{B}=4\,\mathrm{GiB}$ 但机器可能只安装 1GiB 的主存。 因此：

**理论地址空间不等于实际物理内存容量。** **容量计算题型一：已知 MAR 求容量** 【自编训练】 某计算机 MAR 为 24 位。 按字节编址。 数据总线宽度为 64 位。 问最大可寻址容量。

**解题** MAR 位数：$n=24$ 可寻址单元数：$2^{24}$ 每个编址单位：$1\,\mathrm{B}$ 因此：$C=2^{24}\times1\,\mathrm{B}$ $\boxed{C=16\,\mathrm{MiB}}$

**为什么不用乘 64？** 因为 64 位是数据总线宽度。 不是一个地址对应的字节数。 题目已经明确：按字节编址。 所以一个地址对应 1B。

**容量计算题型二：已知容量求 MAR** 【自编训练】 某主存容量为：$128\,\mathrm{KiB}$ 按字节编址。 求至少需要多少位地址。

**解题** $128\,\mathrm{KiB} = 128\times2^{10}\,\mathrm{B}$ $=2^{17}\,\mathrm{B}$ 按字节编址：共有：$2^{17}$ 个可寻址单元。 因此：$\boxed{n=17}$

**容量计算题型三：按字编址** 【自编训练】 某主存容量：$128\,\mathrm{KiB}$ 字长：$16\,\mathrm{bit}$ 按字编址。 求地址位数。

**第一步：计算一个字有多少字节** $16\,\mathrm{bit}=2\,\mathrm{B}$

**第二步：计算字数** $N = \frac{128\times2^{10}}{2}$ $=2^{16}$

**第三步：求地址位数** $\boxed{n=16}$

**对比** 相同的 128KiB：按字节编址需要 17 位地址。 按 16 位字编址需要 16 位地址。 核心原因：每个地址对应的存储空间不同。

**寻址题的统一方法** 遇到寻址容量问题，固定按照四步求解。

**第一步：判断编址单位。** 一个地址对应多少位或多少字节？

**第二步：计算地址个数。** 若地址有 n 位：$N=2^n$

**第三步：计算容量。** $C=N\times\text{每个编址单位大小}$

**第四步：区分其他宽度。** 不要把：机器字长；数据总线宽度；MDR 位数；一次存取宽度。 直接当成编址单位。 这是寻址题最主要的陷阱。

## 综合解题方法与考前训练

### 综合题的统一解题框架

**六类高频性能题** **类型一：求 CPU 时间** 已知：

- 指令数
- CPI
- 主频

使用：$\boxed{ T=\frac{IC\times CPI}{f} }$

**类型二：求平均 CPI** 已知各类指令数：$\boxed{ CPI= \frac{\sum_i IC_iCPI_i} {\sum_i IC_i} }$ 已知各类指令比例：$\boxed{ CPI=\sum_i p_iCPI_i }$

**类型三：比较两台机器** 使用：

$$
\boxed{
\frac{T_1}{T_2}
=
\frac{IC_1}{IC_2}
\cdot
\frac{CPI_1}{CPI_2}
\cdot
\frac{f_2}{f_1}
}
$$

如果指令数相同，可约去指令数比值。 **类型四：比较优化前后** $\boxed{ \frac{T'}T = \frac{IC'}{IC} \cdot \frac{CPI'}{CPI} \cdot \frac f{f'} }$

**类型五：局部优化** $\boxed{ S= \frac1{(1-p)+p/s} }$

**类型六：求 MIPS** $\boxed{ MIPS=\frac{f}{CPI\times10^6} }$ 其中 f 使用 Hz。 如果主频直接以 MHz 表示：$\boxed{ MIPS=\frac{f_{\mathrm{MHz}}}{CPI} }$

**遇到陌生综合题怎么办？** 不要先寻找所谓的特殊公式。 应该从基本关系推导。 例如：某题要求反推主频。 已知：$T=\frac{IC\times CPI}{f}$ 直接移项：$\boxed{ f=\frac{IC\times CPI}{T} }$ 如果要求指令条数：$\boxed{ IC=\frac{Tf}{CPI} }$ 如果要求 CPI：$\boxed{ CPI=\frac{Tf}{IC} }$ 同一组基本关系可以解决许多不同题型。

### 高价值综合训练

**训练 1：直接计算** 【自编训练】 某计算机主频为 2GHz。 程序执行指令：

| 类别 | 指令条数 | CPI |
|---|---:|---:|
| A | $2\times10^8$ | 1 |
| B | $3\times10^8$ | 2 |
| C | $5\times10^8$ | 4 |

求：

1. 总指令数
2. 平均 CPI
3. CPU 时间

**答案与解析** 总指令数：$IC=10^9$ 总周期数：$C = 2\times10^8 + 3\times10^8\times2 + 5\times10^8\times4$ $=2.8\times10^9$ 平均 CPI：$CPI = \frac{2.8\times10^9}{10^9}$ $\boxed{CPI=2.8}$ 执行时间：$T = \frac{2.8\times10^9}{2\times10^9}$

$\boxed{T=1.4\,\mathrm{s}}$ **训练 2：三个参数同时变化** 【自编训练】 程序原执行时间为 12 秒。 优化后：指令数变为原来的 90%。 平均 CPI 变为原来的 125%。 主频变为原来的 150%。 求新执行时间。

**解题** $\frac{T'}T = \frac{0.9\times1.25}{1.5}$ $=0.75$ 因此：$T'=12\times0.75$ $\boxed{T'=9\,\mathrm{s}}$ 加速比：$S=\frac{12}{9}$ $\boxed{S=\frac43}$

**训练 3：Amdahl 极限** 【自编训练】 某程序 60% 的执行时间可以优化。 其他部分完全无法优化。 问整体最大加速比。

**解题** $p=0.6$ 所以：$S_{\max} = \frac1{1-0.6}$ $\boxed{ S_{\max}=2.5 }$ 因此：如果题目声称仅通过优化这 60% 的部分，使整体加速 3 倍，则在题设条件下不可能。

**训练 4：反推主频** 【自编训练】 两台计算机执行同一机器代码，动态指令数相同。 M1：$f_1=800\,\mathrm{MHz}$ $T_1=12\,\mathrm{s}$ M2：$T_2=8\,\mathrm{s}$ 并且：$CPI_2=1.5CPI_1$ 求 M2 主频。

**解题** 由：$T=\frac{IC\times CPI}{f}$ 得到：$\frac{T_2}{T_1} = \frac{CPI_2}{CPI_1} \cdot \frac{f_1}{f_2}$ 代入：$\frac8{12} = 1.5\times\frac{800}{f_2}$ 解得：$f_2 = 1.5\times800\times\frac{12}{8}$ $\boxed{ f_2=1800\,\mathrm{MHz} }$ 即：

$\boxed{ f_2=1.8\,\mathrm{GHz} }$ 这道题的核心是：即使 CPI 更大，只要主频提升足够多，程序仍然可能执行得更快。

**训练 5：CPU 使用时间占比** 【模拟题】 某机器主频为：$2\,\mathrm{GHz}$ CPI 为：$1.2$ 程序执行：$4\times10^9$ 条指令。 从程序启动到结束总共经过 4 秒。 求：程序 CPU 执行时间占总经过时间的比例。

**第一步：求 CPU 执行时间** $T_{\mathrm{CPU}} = \frac{4\times10^9\times1.2} {2\times10^9}$ $=2.4\,\mathrm{s}$

**第二步：求时间占比** $p = \frac{2.4}{4}$ $\boxed{ p=60\% }$

**解析** 这里计算的是：程序 CPU 执行时间占程序总经过时间的比例。 不能把 4 秒都认为是 CPU 在执行该程序。 其余时间可能包含等待。 注意该模拟题的原始“占整个 CPU 时间”表述不够严谨，实际按题意应理解为占总经过时间的比例。

### 易错点与特殊判断

**必须纠正的常见错误**

| 错误认识 | 正确理解 |
|---|---|
| 主频越高计算机一定越快 | 还要考虑 IC 和 CPI |
| CPI 越小程序一定越快 | 还要考虑 IC 和主频 |
| 每条指令只需要一个周期 | 不同指令执行时间不同 |
| 平均 CPI 一定大于等于 1 | 超标量处理器可以小于 1 |
| 一条指令只完成一次浮点运算 | 向量指令可以完成多个浮点操作 |
| MIPS 越高任务一定完成越快 | 指令数和单条指令工作量也不同 |
| 指令与数据的存储形式不同 | 二者都是二进制位串 |
| 操作数都直接存放在指令中 | 也可能来自寄存器或主存 |
| PC 与 MAR 完全相同 | 二者保存的信息与作用不同 |
| 机器字长等于指令字长 | 二者没有必然关系 |
| 64 位 CPU 必然使用 64 位指令 | 指令长度由 ISA 规定 |
| MAR 位数等于实际内存容量 | MAR 主要反映地址表示能力 |
| 数据总线宽度等于编址单位 | 数据传输宽度与编址单位不同 |
| 速度提高 50% 就是时间减少 50% | 同工作量时间变为原来的 $1/1.5$ |
| 局部加速 10 倍整体一定加速 10 倍 | 受未优化部分限制 |
| 一类指令占 10%，时间也占 10% | 时间比例还取决于 CPI |
| 编译优化减少指令一定加速 | CPI 也可能增大 |
| 相同 ISA 的 CPU 性能相同 | 内部实现和主频可以不同 |

### 与后续章节的联系

**为什么第 1 章必须真正理解？** 第 1 章不仅是概念介绍。 后续章节大量计算都可以回到本章公式。

**第二章：数据的表示和运算** 机器字长会影响：

- 定点整数表示范围
- 补码运算
- 加减法
- 溢出判断
- 数据类型转换

**第三章：存储系统** Cache 未命中可能增加 CPU 等待周期。 假设：基础 CPI 为：$CPI_{\mathrm{base}}$ 平均每条指令由于访存未命中而额外增加：$CPI_{\mathrm{stall}}$ 则：$CPI_{\mathrm{eff}} = CPI_{\mathrm{base}} + CPI_{\mathrm{stall}}$ 于是：

$T_{\mathrm{CPU}} = \frac{IC\times CPI_{\mathrm{eff}}}{f}$ 这就是为什么 Cache 命中率会影响程序执行时间。

**第四章：指令系统** ISA 会影响：指令编码；寻址方式；操作数表示；编译得到的指令序列。 从而影响：$IC$ 以及指令组合对应的 CPI。

**第五章：中央处理器** 流水线设计可能影响：时钟周期；有效 CPI；指令吞吐率。 例如：流水线加深可能缩短单级逻辑延迟。 但也可能增加分支错误预测等情况下的性能损失。 所以不能简单认为：流水线级数越多越快。 最终仍然需要比较：$T_{\mathrm{CPU}} = \frac{IC\times CPI}{f}$

**第六章：总线与 I/O** 总线和 I/O 会影响：数据传输时间；存储器访问性能；CPU 等待；整体响应时间。 因此：CPU 性能与系统整体性能并不完全相同。

### 本章公式总表

**必须熟练掌握的公式**

| 知识点 | 公式 |
|---|---|
| 时钟周期 | $T_{\mathrm{clk}}=1/f$ |
| 主频 | $f=1/T_{\mathrm{clk}}$ |
| CPI | $CPI=N_{\mathrm{cycle}}/IC$ |
| 平均 CPI | $CPI_{\mathrm{avg}}=\sum_i p_iCPI_i$ |
| 总周期数 | $N_{\mathrm{cycle}}=IC\times CPI$ |
| CPU 时间 | $T=IC\times CPI/f$ |
| IPC | $IPC=1/CPI$ |
| IPS | $IPS=f/CPI$ |
| MIPS | $MIPS=f/(CPI\times10^6)$ |
| 性能加速比 | $S=T_{\mathrm{old}}/T_{\mathrm{new}}$ |
| Amdahl 定律 | $S=1/[(1-p)+p/s]$ |
| 最大加速比 | $S_{\max}=1/(1-p)$ |
| 可寻址单元数 | $N=2^n$ |
| 最大寻址容量 | $C=2^n\times W$ |

其中：$IC$：动态执行指令数；$CPI$：平均每条指令消耗的周期数；$f$：主频；$p$：原执行时间中可加速部分的比例；$s$：可加速部分的局部加速倍数；$n$：地址位数；$W$：每个可寻址单元的容量。

### 考场解题策略

**性能题的五步法** 第一步：明确题目要求。 到底要求：

- CPU 时间
- 总运行时间
- 平均 CPI
- 指令执行速率
- 性能比
- 加速比

第二步：统一单位。 特别注意：GHz、MHz、ns、微秒、毫秒。 第三步：计算总周期数。 如果有多类指令：$N_{\mathrm{cycle}} = \sum_i IC_iCPI_i$ 第四步：建立 CPU 时间关系。 $T=\frac{N_{\mathrm{cycle}}}{f}$ 第五步：根据题意进行比较或移项。 对于优化前后比较：

$\frac{T'}T = \frac{IC'}{IC} \cdot \frac{CPI'}{CPI} \cdot \frac f{f'}$ 对于局部加速：$S=\frac1{(1-p)+p/s}$

**概念题的判断策略** **问 ISA** 判断是否为软件可见的机器规则。

**问冯·诺依曼结构** 优先想到：存储程序、二进制、五大部件、按地址取指。

**问指令和数据的区分** 优先考虑：当前执行阶段以及 CPU 对访存内容的解释方式。

**问程序转换** 记住：预处理 → 编译 → 汇编 → 链接 → 装载。

**问机器字长** 优先考虑：CPU 基本运算数据宽度及通用寄存器。

**问 MAR** 优先考虑：地址表示能力。

**问容量** 先确定：一个地址对应多大的存储空间。

### 最终复习总结

**必须形成的三个核心模型** **模型一：计算机如何运行程序**

```text
高级语言
   ↓
编译和汇编
   ↓
机器指令
   ↓
链接生成可执行文件
   ↓
装载
   ↓
PC 提供指令地址
   ↓
CPU 取指、译码、执行
   ↓
运算器、存储器协同工作
   ↓
继续执行下一条指令
```

<Callout type="warn" title="性能比较的前提">

**模型二：程序为什么快或慢** $\boxed{ T_{\mathrm{CPU}} = \frac{IC\times CPI}{f} }$ 执行时间由：指令数、平均 CPI、主频共同决定。 不能只看主频。

</Callout>

**模型三：为什么局部优化有上限** $\boxed{ S= \frac1{(1-p)+p/s} }$ 如果存在无法优化的部分：那么整体加速比会受到限制。

**真正掌握本章的标准** 学完后，应当能够独立完成下面这些任务：

1. 解释存储程序思想及冯·诺依曼结构。
2. 区分计算机体系结构与计算机组成。
3. 判断 ISA 与硬件实现的关系。
4. 解释 CPU 如何区分指令和数据。
5. 说明 PC、MAR、MDR、IR 的功能。
6. 理解机器指令的基本执行流程。
7. 区分预处理、编译、汇编、链接和装载。
8. 区分时钟周期、机器周期、指令周期。
9. 根据指令比例求平均 CPI。
10. 根据主频、CPI、指令数计算 CPU 时间。
11. 比较不同机器执行同一程序的性能。
12. 分析编译优化前后的实际性能变化。
13. 使用 Amdahl 定律求局部优化后的整体加速。
14. 根据加速比反推局部加速倍数。
15. 计算 IPS、MIPS、FLOPS 等指标。
16. 区分机器字长、指令字长和数据通路宽度。
17. 根据 MAR 和编址方式计算理论可寻址容量。
18. 综合考虑 Cache 额外开销对 CPI 的影响。
19. 检查模拟题中的数据、单位与选项错误。
20. 面对新题能够从基本公式推导，而不是只记住已有题目的答案。

**本章结语** 本章最重要的不是单独背诵主频、CPI 或指令数，而是建立一个完整的性能分析体系：

$$
\boxed{
T_{\mathrm{CPU}}
=
IC\times CPI\times T_{\mathrm{clk}}
=
\frac{IC\times CPI}{f}
}
$$

掌握这个公式后，再理解：$\boxed{ CPI_{\mathrm{avg}}=\sum_i p_iCPI_i }$ 以及：$\boxed{ S=\frac1{(1-p)+p/s} }$ 就能够解决第 1 章绝大多数性能计算题。 对于综合题，最重要的是做到：

**先判断考查对象，再建立基本关系，最后根据已知条件推导。** 不要仅记忆具体真题的数字和答案，而要掌握能够适用于新题的计算方法与判断逻辑。
