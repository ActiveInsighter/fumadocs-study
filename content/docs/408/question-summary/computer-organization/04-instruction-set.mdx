## 一、本章整体知识体系与考情分析

### 1.1 指令系统到底研究什么？

一台计算机要执行程序，首先必须能够理解机器指令。

例如：

```asm
add r1, r2, r3
```

这条指令表示执行加法操作。

但要让 CPU 真正执行它，还必须解决以下问题：

1. CPU 怎么知道这是一条加法指令？
2. CPU 怎么知道应该读取哪些寄存器？
3. 操作数是在寄存器、主存还是指令本身？
4. 如果操作数在主存中，如何计算它的地址？
5. 如果是跳转指令，下一条指令地址如何确定？
6. 如果调用函数，如何保存返回地址？
7. 高级语言中的数组、循环、函数怎样转换成机器指令？

这些问题共同构成了指令系统的主要内容。

可以把指令执行理解为：

```text
高级语言程序
     │
     ▼
编译器、汇编器
     │
     ▼
机器指令
     │
     ├── 操作码：做什么？
     │
     └── 操作数字段：对什么数据操作？
                │
                ▼
           确定寻址方式
                │
                ▼
           获得操作数
                │
                ▼
           CPU执行操作
                │
                ├── 运算结果
                ├── 修改寄存器
                ├── 修改主存
                ├── 修改标志位
                └── 修改PC
```

**本章最核心的主线是：指令编码 → 操作数寻址 → 指令语义 → 机器状态变化。**

遇到任何综合题，都可以沿着这条主线分析。

## 二、指令集体系结构 ISA

### 2.1 ISA的定义

ISA，全称 Instruction Set Architecture，即指令集体系结构。

它规定了程序员、编译器和操作系统能够观察到的机器行为。

可以理解为：

**ISA是软件与处理器硬件之间的接口规范。**

例如：

```asm
add r1, r2, r3
```

ISA必须规定：

- `add` 是什么操作；
- 三个寄存器分别承担什么角色；
- 寄存器宽度是多少；
- 发生溢出时如何处理；
- 执行后哪些状态会改变。

但ISA通常不需要规定CPU内部使用几个加法器。

### 2.2 ISA规定的主要内容

| 内容 | 是否属于ISA | 原因 |
|---|---|---|
| 指令格式 | 是 | 影响机器码编码 |
| 操作码 | 是 | 决定指令语义 |
| 寻址方式 | 是 | 决定操作数定位 |
| 通用寄存器数量 | 是 | 软件直接使用 |
| 通用寄存器位数 | 是 | 影响机器指令 |
| 数据类型 | 是 | 规定数据操作语义 |
| 指令执行结果 | 是 | 软件可观察 |
| 异常及特权机制 | 通常是 | 系统软件依赖 |
| CPU时钟周期 | 否 | 属于实现细节 |
| 流水线级数 | 否 | 属于微架构 |
| Cache容量 | 通常否 | 属于实现细节 |
| 分支预测方式 | 否 | 属于微架构 |
| ALU数量 | 否 | 属于微架构 |
| 加法器进位实现 | 否 | 属于电路实现 |

注意：虚拟存储相关的体系结构支持、页表控制寄存器等可能属于ISA，但具体TLB容量、替换策略通常不属于ISA。

### 2.3 ISA与微架构的区别

最重要的判断标准：

> ISA规定机器要完成什么操作，微架构规定这些操作在硬件内部如何实现。

假设两款CPU都执行：

```asm
ADD R1, R2, R3
```

它们可以分别采用：

```text
CPU A：
单周期执行
一个ALU
无乱序执行

CPU B：
五级流水线
多个执行单元
乱序执行
```

只要两者对这条指令提供相同的体系结构语义，就可以属于同一个ISA。

因此：

**相同ISA不意味着相同性能。**

#### 真题：2022年408

判断以下内容是否属于ISA规定：

I. 指令字格式和指令类型

II. CPU时钟周期

III. 通用寄存器个数和位数

IV. 加法器进位方式

分析：

- I：决定机器码形式，属于ISA。
- II：具体硬件性能参数，不属于ISA。
- III：软件需要知道寄存器编号和宽度，属于ISA。
- IV：加法器内部电路实现，不属于ISA。

答案：

**I、III。**

#### 迁移判断方法

遇到新选项时，问自己：

**改变这一设计后，原来的机器程序还能不能保持相同的语义执行？**

如果可能改变机器指令的编码或软件可见行为，通常涉及ISA。

如果只改变内部性能和实现方式，通常涉及微架构。


## 三、机器指令的基本格式

### 3.1 指令的组成

一般机器指令由两部分组成：

```text
┌─────────────┬────────────────────┐
│   操作码OP  │     操作数字段     │
└─────────────┴────────────────────┘
```

#### 操作码

说明执行什么操作。

例如：

- ADD：加法
- SUB：减法
- MOV：数据传送
- LOAD：读取主存
- STORE：写主存
- JMP：跳转

#### 操作数字段

说明操作对象。

它可能表示：

- 寄存器编号；
- 主存地址；
- 立即数；
- 地址偏移；
- 寻址方式。

**地址字段并不一定存放主存地址。**

例如：

```asm
ADD R1, R2, 5
```

其中：

- R1：目标寄存器；
- R2：源寄存器；
- 5：立即数。

这里没有显式的主存数据地址。


### 3.2 零地址、一地址、二地址和三地址指令

#### ① 零地址指令

没有显式地址字段。

例如栈式计算机：

```asm
ADD
```

假设栈顶两个元素是：

```text
栈顶 → 8
       5
```

执行ADD：

1. 弹出8；
2. 弹出5；
3. 相加得到13；
4. 将13压回栈。

零地址不代表没有操作数。

**操作数可以隐含在栈顶或特定寄存器中。**

#### ② 一地址指令

典型累加器结构：

```asm
ADD A
```

可能表示：

$$
ACC\leftarrow ACC+M[A]
$$

其中：

- ACC：隐含累加器；
- A：显式地址字段。

优点：

节省指令中的地址字段。

缺点：

频繁依赖累加器，数据操作灵活性较低。

#### ③ 二地址指令

例如：

```asm
ADD R1, R2
```

假设采用目的在前的语义：

$$
R1\leftarrow R1+R2
$$

特点：

- 两个显式操作数字段；
- 结果通常覆盖其中一个操作数。

#### ④ 三地址指令

例如：

```asm
ADD R3, R1, R2
```

表示：

$$
R3\leftarrow R1+R2
$$

优点：

不必覆盖原操作数。

缺点：

需要更多寄存器编号或地址字段。

#### 对比

| 类型 | 显式地址数 | 典型特点 |
|---|---:|---|
| 零地址 | 0 | 操作数隐含 |
| 一地址 | 1 | 常依赖累加器 |
| 二地址 | 2 | 常覆盖一个操作数 |
| 三地址 | 3 | 源、目的分离 |

**地址字段数越多，通常留给操作码的编码空间越小。**

这正是扩展操作码的基础。


### 3.3 指令字长、机器字长与存储字长

这三个概念必须区分。

#### 机器字长

CPU一次基本整数运算能够处理的数据宽度。

例如：

16位计算机通常拥有16位基本整数运算数据通路。

#### 指令字长

一条机器指令占用多少位。

例如：

```text
机器字长：32位
指令字长：32位
```

但两者不一定相同。

#### 存储字长

存储系统一次基本存取所涉及的存储字宽度。

其具体定义和宽度由题设中的存储组织决定。

#### 高频易错

不能直接认为：

$$
\text{机器字长}=\text{指令字长}=\text{MDR位数}
$$

例如2021年408综合题：

- 机器字长16位；
- 指令字长16位；
- 地址线20位；
- 数据线8位。

于是：

$$
ALU=16\text{位}
$$

$$
IR=16\text{位}
$$

$$
MAR=20\text{位}
$$

$$
MDR=8\text{位}
$$

这里MDR按照题目中一次主存数据传送的宽度确定。

不能看到机器字长16位，就机械认为MDR也是16位。


### 3.4 定长指令与变长指令

#### 定长指令

每条指令长度固定。

例如：

```text
指令1：4B
指令2：4B
指令3：4B
```

优点：

- 取指简单；
- 指令边界容易判断；
- 译码规则；
- 有利于流水线设计。

缺点：

- 部分指令可能浪费编码空间；
- 代码密度未必最优。

#### 变长指令

不同指令长度可以不同。

例如x86：

```asm
push ebp
cmp dword ptr [ebp-0Ch], ecx
shl edx, 1
```

对应机器码可能分别占：

```text
1B
3B
2B
```

优点：

- 编码灵活；
- 能够提供丰富的寻址形式；
- 某些情况下代码更紧凑。

缺点：

- 指令边界判断复杂；
- 取指与译码相对复杂。

#### 必须区分

**定长指令字不等于定长操作码。**

例如一台机器可以：

- 所有指令都是16位；
- 二地址指令使用4位操作码；
- 一地址指令使用10位操作码；
- 零地址指令使用16位操作码。

这就是扩展操作码。


## 四、扩展操作码：本章重点计算题

### 4.1 为什么需要扩展操作码？

假设指令字长16位，每个地址字段4位。

三地址指令：

```text
┌────┬────┬────┬────┐
│ OP │ A1 │ A2 │ A3 │
│ 4位│ 4位│ 4位│ 4位│
└────┴────┴────┴────┘
```

操作码只有：

$$
16-3\times4=4\text{位}
$$

最多表示：

$$
2^4=16
$$

种操作。

但如果采用一地址指令：

```text
┌────────────┬────┐
│     OP     │ A1 │
│    12位    │ 4位│
└────────────┴────┘
```

便拥有更多操作码位数。

因此可以利用减少的地址字段扩展操作码。

### 4.2 扩展操作码的本质

**用上一级未分配的操作码前缀，继续向下扩展。**

例如：

```text
4位操作码
│
├── 0000：三地址指令
├── 0001：三地址指令
├── ...
├── 1110：三地址指令
│
└── 1111：保留，用于扩展
       │
       ├── 1111 0000：二地址指令
       ├── 1111 0001：二地址指令
       ├── ...
       └── 1111 1111：继续扩展
```

最重要的规则：

**已经作为完整操作码使用的短码，不能再作为其他长操作码的前缀。**

否则CPU无法唯一判断应该执行哪种指令。

这属于前缀编码约束。


### 4.3 扩展操作码的通用算法

设：

- 指令字长为 $L$；
- 每个地址字段占 $a$ 位；
- 二地址指令数量为 $N_2$；
- 一地址指令数量为 $N_1$。

二地址指令操作码位数：

$$
m=L-2a
$$

基础操作码数量：

$$
C_2=2^m
$$

分配二地址指令后，剩余前缀：

$$
r_2=C_2-N_2
$$

一地址候选容量：

$$
C_1=r_2\times2^a
$$

分配一地址指令后：

$$
r_1=C_1-N_1
$$

零地址指令最多：

$$
\boxed{N_{0,\max}=r_1\times2^a}
$$

合并：

$$
\boxed{
N_{0,\max}
=
\left[
(2^{L-2a}-N_2)2^a-N_1
\right]2^a
}
$$

这是二地址、一地址、零地址逐级扩展，并且各地址字段等宽时的公式。

其他指令格式应按照实际字段划分逐级推导。


### 4.4 真题：2022年408扩展操作码

#### 题目

某计算机采用：

- 16位定长指令字；
- 地址字段6位；
- 二地址指令12条；
- 一地址指令254条。

求最多还能定义多少条零地址指令。

#### 第一步：求基础操作码宽度

二地址指令有两个6位地址字段。

$$
m=16-2\times6=4
$$

基础操作码有：

$$
2^4=16
$$

种。

#### 第二步：扣除二地址指令

已经使用12种：

$$
16-12=4
$$

还剩4个可扩展前缀。

#### 第三步：扩展成一地址指令

每个前缀再扩展6位：

$$
4\times2^6=256
$$

所以最多定义256条一地址指令。

实际只有254条。

剩余：

$$
256-254=2
$$

个前缀。

#### 第四步：继续扩展零地址指令

最后一个地址字段宽6位：

$$
2\times2^6=128
$$

答案：

$$
\boxed{128\text{条}}
$$

#### 易错分析

错误一：

直接用：

$$
2^{16}-12-254
$$

这是错误的，因为不是所有16位组合都能作为独立操作码。

错误二：

二地址剩余4种前缀，就直接认为只有4条一地址指令。

实际上每个前缀还可以再扩展6位。

错误三：

只记住结果128，不理解逐级扩展过程。

**考试必须从编码树理解，而不是死记公式。**


### 4.5 真题：2017年408最短指令字长

#### 题目

某计算机：

- 按字节编址；
- 指令字长固定；
- 三地址指令29条；
- 二地址指令107条；
- 每个地址字段6位。

问最短指令字长。

选项：

A. 24位

B. 26位

C. 28位

D. 32位

#### 第一步：三地址操作码至少多少位？

29条指令至少需要：

$$
\lceil\log_2 29\rceil=5
$$

位。

三个地址字段：

$$
3\times6=18
$$

位。

理论下界：

$$
L=5+18=23\text{位}
$$

#### 第二步：检查二地址指令容量

5位操作码共有：

$$
2^5=32
$$

种。

三地址指令使用29种。

剩余：

$$
32-29=3
$$

种前缀。

利用一个6位地址字段扩展：

$$
3\times2^6=192
$$

因为：

$$
192\ge107
$$

所以23位已经满足纯编码容量要求。

#### 第三步：结合选项

选项中最小可行指令字长为24位。

因此：

$$
\boxed{24\text{位}}
$$

答案A。

#### 特别重要的严谨性问题

不能简单认为：

> 按字节编址，所以所有指令字长必定是8的整数倍。

按字节编址规定的是存储地址对应的单位，并不单独规定机器指令编码长度。

本题：

- 按纯编码容量分析，下界是23位；
- 给定选项中最短可行值是24位；
- 采用通常的整字节指令存放约定时，也得到24位。

如果某题明确允许特殊位级打包，就不能擅自加入整字节对齐条件。

#### 对应模拟题

模拟选择题还会考查：

- 单地址指令260条；
- 二地址指令12条；
- 每个地址字段6位。

假设基础操作码4位：

$$
(2^4-12)2^6=256<260
$$

不够。

改为5位：

$$
(2^5-12)2^6=1280\ge260
$$

所以按纯编码位数得到：

$$
L=5+12=17\text{位}
$$

这个例子提醒我们：

**首先求编码容量下界，再看题目是否另外要求整字节存储、指令对齐或其他格式约束。**


### 4.6 扩展操作码题的万能解法

以后遇到任何类似题目，按照以下流程：

```text
① 找地址字段宽度
        ↓
② 找地址数最多的指令格式
        ↓
③ 计算最短基础操作码
        ↓
④ 扣除已经分配的指令
        ↓
⑤ 剩余前缀向下一层扩展
        ↓
⑥ 再扣除下一类指令
        ↓
⑦ 重复直到目标格式
        ↓
⑧ 检查指令长度与额外约束
```

最容易失分的是第五步。

**一个剩余前缀并不只产生一条新指令，而是可以展开成 $2^a$ 个新编码。**


## 五、指令寻址与数据寻址

这是整章最核心的内容之一。

### 5.1 两种寻址的区别

#### 指令寻址

解决：

**下一条执行的指令在哪里？**

主要由PC完成。

#### 数据寻址

解决：

**当前指令要使用的操作数在哪里？**

涉及：

- 立即寻址；
- 寄存器寻址；
- 直接寻址；
- 间接寻址；
- 基址寻址；
- 变址寻址；
- 相对寻址等。

例如：

```asm
LOAD R1, [1000]
```

CPU首先需要通过PC找到这条LOAD指令。

随后根据指令中的地址信息找到数据。

所以：

```text
PC找到指令
     ↓
解析指令
     ↓
计算数据有效地址
     ↓
读取操作数
```


### 5.2 三个核心概念

#### 形式地址 A

指令中给出的地址信息。

#### 有效地址 EA

最终用于访问操作数所在内存位置的地址。

#### 操作数 Operand

真正参与运算的数据。

约定：

$$
M[x]=\text{地址 }x\text{ 中保存的数据}
$$

例如：

$$
A=1000
$$

$$
M[1000]=250
$$

若采用直接寻址：

$$
EA=1000
$$

操作数：

$$
Operand=M[1000]=250
$$

**1000是地址，250才是数据。**

这是所有寻址题的基础。


## 六、所有常见寻址方式彻底讲解

### 6.1 立即寻址

操作数直接写在指令中。

例如：

```asm
MOV R1, 100
```

表示：

$$
R1\leftarrow100
$$

这里100就是数据本身。

不需要根据100去访问主存。

特点：

- 取数据不需要额外访存；
- 速度快；
- 立即数范围受到字段位数限制。

注意：

立即数需要随指令一起取出，但没有额外的操作数主存读取。


### 6.2 寄存器直接寻址

操作数就在寄存器中。

```asm
MOV R1, R2
```

假设：

$$
(R2)=500
$$

那么：

$$
R1\leftarrow500
$$

不需要额外读取主存。

与立即寻址的区别：

- 立即寻址：操作数存放在指令中；
- 寄存器寻址：操作数存放在寄存器中。


### 6.3 直接寻址

指令直接给出主存地址。

$$
\boxed{EA=A}
$$

操作数：

$$
Operand=M[A]
$$

假设：

$$
A=1000
$$

$$
M[1000]=500
$$

那么：

$$
EA=1000
$$

$$
Operand=500
$$

通常需要1次额外的数据访存。


### 6.4 存储器间接寻址

指令给出的形式地址中保存的是操作数的真正地址。

公式：

$$
\boxed{EA=M[A]}
$$

真正操作数：

$$
Operand=M[EA]
$$

例如：

$$
A=1000
$$

$$
M[1000]=2000
$$

$$
M[2000]=500
$$

执行过程：

```text
指令中 A=1000
      ↓
访问 M[1000]
      ↓
得到地址 2000
      ↓
访问 M[2000]
      ↓
得到数据 500
```

因此：

$$
EA=2000
$$

$$
Operand=500
$$

通常需要2次额外的数据访存。

#### 易错点

不能把第一次读出的2000直接当作操作数。

它只是有效地址。


### 6.5 寄存器间接寻址

有效地址保存在寄存器中。

公式：

$$
\boxed{EA=(R)}
$$

操作数：

$$
Operand=M[(R)]
$$

假设：

$$
(R)=2000
$$

$$
M[2000]=500
$$

那么：

$$
EA=2000
$$

$$
Operand=500
$$

通常需要1次额外的数据访存。

#### 与寄存器直接寻址比较

| 寻址方式 | 寄存器内容代表什么 | 操作数 |
|---|---|---|
| 寄存器直接 | 数据本身 | $(R)$ |
| 寄存器间接 | 数据所在地址 | $M[(R)]$ |

例如：

```asm
MOV R1, R2
```

和：

```asm
MOV R1, [R2]
```

不是一回事。

前者取R2的内容。

后者取R2指向的内存内容。


### 6.6 基址寻址

公式：

$$
\boxed{EA=(BR)+A}
$$

其中：

- BR：基址寄存器；
- A：指令中的位移量。

例如：

$$
(BR)=3000
$$

$$
A=100
$$

则：

$$
EA=3100
$$

#### 典型用途

1. 程序重定位；
2. 函数栈帧；
3. 结构体成员访问；
4. 访问某个连续存储区域。

例如：

```asm
MOV EAX, [EBP+8]
```

表示：

$$
EA=(EBP)+8
$$

然后读取对应内存。

#### 基址寄存器是否一定不变？

不一定。

传统教材强调：

- 基址寄存器通常由系统软件建立；
- 在某段程序执行期间相对稳定；
- 变址寄存器通常由程序动态修改。

但实际ISA中，通用寄存器既可以充当基址，也可以充当变址。

不能把教材典型用途当成所有处理器的硬性规则。


### 6.7 变址寻址

公式：

$$
\boxed{EA=A+(IX)}
$$

其中：

- A：基准地址；
- IX：变址寄存器。

典型用途：

**数组访问。**

例如：

```c
int a[100];
```

假设：

$$
Base=1000
$$

每个int占4B。

访问：

```c
a[5]
```

元素地址：

$$
EA=1000+5\times4
$$

所以：

$$
\boxed{EA=1020}
$$

这里地址单位是字节。

#### 为什么不能直接加5？

因为下标表示第几个元素。

主存地址通常表示字节位置。

必须将元素下标转换为字节偏移。

通用公式：

$$
\boxed{EA=Base+i\times sizeof(T)}
$$


### 6.8 基址变址与比例变址寻址

x86常见形式：

$$
\boxed{
EA=Base+Index\times Scale+Displacement
}
$$

例如：

```asm
mov eax, [ebx+ecx*4+8]
```

假设：

$$
EBX=1000
$$

$$
ECX=5
$$

则：

$$
EA=1000+5\times4+8
$$

$$
\boxed{EA=1028}
$$

然后：

$$
EAX\leftarrow M[1028]
$$

注意：

1028只是地址。

如果题目要求EAX最后的内容，还需要读取：

$$
M[1028]
$$

#### LEA与MOV的区别

```asm
mov eax, [ebx+ecx*4]
```

真正访问内存：

$$
EAX\leftarrow M[EBX+4ECX]
$$

而：

```asm
lea eax, [ebx+ecx*4]
```

只计算地址：

$$
EAX\leftarrow EBX+4ECX
$$

**LEA一般不读取该有效地址中的数据。**

这是反汇编题的重要易错点。


### 6.9 先变址后间址

2016年408选择题考查过。

假设：

- 形式地址D；
- 变址寄存器I；
- 先变址；
- 再间址。

#### 第一步：先变址

$$
T=(I)+D
$$

#### 第二步：再间址

$$
EA=M[T]
$$

所以：

$$
\boxed{EA=M[(I)+D]}
$$

#### 举例

假设：

$$
(I)=1000
$$

$$
D=2000
$$

$$
M[3000]=5000
$$

则：

$$
T=1000+2000=3000
$$

$$
EA=M[3000]=5000
$$

如果还需要读取操作数：

$$
Operand=M[5000]
$$

注意：

$$
M[(I)+D]
$$

与：

$$
M[D]+(I)
$$

一般不相等。

**地址加法与访问主存的先后顺序不能交换。**


### 6.10 寄存器间接自增寻址

典型形式：

```asm
(Rn)+
```

通常表示：

1. 使用Rn原来的内容作为地址；
2. 访问该地址；
3. Rn再自增。

公式：

$$
EA=(R_n)_{\text{old}}
$$

随后：

$$
R_n\leftarrow R_n+\Delta
$$

其中增量由编址单位、操作数宽度和指令语义共同决定。

#### 按字编址

如果每次访问一个字：

$$
\Delta=1
$$

#### 按字节编址

如果每次访问一个4B的数据：

$$
\Delta=4
$$

但具体应以ISA或题目规定为准。


### 6.11 前自减寻址

典型形式：

```asm
-(Rn)
```

通常表示：

1. 先减少寄存器；
2. 再按新地址访问操作数。

例如按字节编址、访问4B数据：

$$
R_n\leftarrow R_n-4
$$

$$
EA=(R_n)_{\text{new}}
$$

#### 后自增与前自减区别

| 类型 | 修改寄存器时机 | 本次使用地址 |
|---|---|---|
| 后自增 | 访问后 | 原地址 |
| 前自减 | 访问前 | 新地址 |

这是2010年综合题的重要基础。


## 七、寻址方式总表

| 寻址方式 | EA或操作数 | 典型用途 | 额外数据访存 |
|---|---|---|---:|
| 立即寻址 | $Operand=A$ | 常量 | 0 |
| 寄存器直接 | $Operand=(R)$ | 运算 | 0 |
| 直接寻址 | $EA=A$ | 固定地址 | 1 |
| 存储器间接 | $EA=M[A]$ | 指针间接 | 2 |
| 寄存器间接 | $EA=(R)$ | 指针 | 1 |
| 基址寻址 | $EA=(BR)+A$ | 重定位、栈帧 | 1 |
| 变址寻址 | $EA=A+(IX)$ | 数组 | 1 |
| 基址变址 | $EA=(BR)+(IX)+A$ | 数组、结构体 | 1 |
| PC相对 | $Target=PC_b+offset$ | 分支转移 | 依用途而定 |
| 堆栈寻址 | SP隐含决定 | PUSH、POP | 依指令而定 |

#### 访存次数要特别注意

表中只统计为了获取一个内存数据操作数而产生的额外主存访问。

不包括：

- 取指令；
- TLB查找；
- 页表遍历；
- Cache访问；
- 写回数据；
- 其他隐含操作。

例如：

```asm
STORE R1, [R2]
```

需要一次数据内存写入。

不能因为寄存器间接寻址的表格写着1次数据访存，就认定这里一定是1次内存读取。

**读操作数与写操作数必须区分。**


## 八、寻址方式典型真题

### 8.1 2013年408：变址寻址

已知：

$$
(R)=1000H
$$

形式地址：

$$
A=2000H
$$

内存：

$$
M[1000H]=2000H
$$

$$
M[2000H]=3000H
$$

$$
M[3000H]=4000H
$$

求变址寻址取得的操作数。

#### 解答

变址寻址：

$$
EA=(R)+A
$$

所以：

$$
EA=1000H+2000H=3000H
$$

取得：

$$
Operand=M[3000H]
$$

因此：

$$
\boxed{4000H}
$$

#### 为什么容易错？

题目故意提供了：

$$
M[1000H]
$$

和：

$$
M[2000H]
$$

诱导考生不断访问内存。

但变址寻址只是将寄存器内容与形式地址相加。

不需要先读取：

$$
M[1000H]
$$

所以不能把变址寻址做成间接寻址。


### 8.2 2014年408：位移字段范围

题目条件：

- 指令字长32位；
- 操作码及寻址方式字段8位；
- 16个通用寄存器；
- Store指令使用一个源寄存器和一个基址寄存器；
- 偏移量使用补码。

求偏移量范围。

#### 第一步：寄存器编号位数

16个寄存器需要：

$$
\log_2 16=4
$$

位。

两个寄存器字段：

$$
4+4=8
$$

位。

#### 第二步：计算位移字段

$$
32-8-8=16
$$

位。

#### 第三步：补码范围

16位补码范围：

$$
-2^{15}\le x\le2^{15}-1
$$

因此：

$$
\boxed{-32768\sim32767}
$$

#### 迁移能力

以后遇到指令字段计算题：

**先分配操作码和寄存器字段，再确定立即数或位移字段。**


### 8.3 2018年408：数组下标计算

已知：

- 数组首地址2000H；
- double占8B；
- 当前访问元素地址2100H；
- 变址寄存器保存元素下标。

求进入该次循环时的下标。

字节偏移：

$$
2100H-2000H=100H=256
$$

每个元素8B：

$$
i=\frac{256}{8}
$$

因此：

$$
\boxed{i=32}
$$

#### 易错点

不能把：

$$
100H
$$

直接当成100。

十六进制：

$$
100H=256
$$

也不能忘记除以元素大小。


## 九、PC相对寻址与分支跳转

<Callout type="warn" title="PC 相对位移以题目定义为准">

确认基准地址是当前 PC 还是下一条指令地址，位移是有符号还是无符号，单位是字节、字或指令字；必要时还要乘以指令宽度。

</Callout>


这是本章另一个高频核心。

### 9.1 PC的作用

PC保存下一条需要取出的指令地址。

顺序执行时：

$$
PC_{\text{next}}=PC_{\text{current}}+L
$$

这里 $L$ 是指令占用的地址单位数。

例如：

- 按字节编址；
- 每条指令4B。

那么：

```text
1000H
1004H
1008H
100CH
```

如果是变长指令，则每条指令的PC增量可能不同。


### 9.2 PC相对寻址公式

常见形式：

$$
\boxed{
Target=PC_{\text{base}}+\operatorname{SExt}(offset)\times s
}
$$

其中：

- $PC_{\text{base}}$：题目定义的基准地址；
- $offset$：指令编码的相对位移；
- $s$：位移单位对应的字节数或其他比例。

在很多x86和408题目中：

$$
PC_{\text{base}}=PC_{\text{next}}
$$

所以：

$$
\boxed{
Target=PC_{\text{next}}+offset\times s
}
$$

注意：

**不能把这个公式无条件推广到所有ISA。**

例如MIPS风格分支通常以PC+4为基准，并将16位有符号偏移乘4。


### 9.3 正位移

假设：

- 指令地址1000H；
- 指令长度4B；
- 位移量20H；
- 位移单位1B。

那么：

$$
PC_{\text{next}}=1004H
$$

$$
Target=1004H+20H
$$

得到：

$$
\boxed{1024H}
$$


### 9.4 负位移

假设：

- 指令地址1000H；
- 长度4B；
- 位移字段FFF8H；
- 16位补码；
- 单位1B。

首先解释FFF8H：

$$
FFF8H=-8
$$

然后：

$$
PC_{\text{next}}=1004H
$$

$$
Target=1004H-8
$$

得到：

$$
\boxed{0FFCH}
$$

#### 最重要的步骤

**先按照字段宽度进行符号解释，再计算地址。**

不要把FFF8H当作一个很大的正数直接相加。


### 9.5 有符号位移范围

如果位移字段有 $n$ 位，采用补码：

$$
\boxed{
-2^{n-1}\le offset\le2^{n-1}-1
}
$$

如果位移单位为 $s$ Byte：

$$
\boxed{
Target_{\min}=PC_b-2^{n-1}s
}
$$

$$
\boxed{
Target_{\max}=PC_b+(2^{n-1}-1)s
}
$$

这里给的是编码所对应的理论目标区间；最终还可能受到地址空间、对齐和具体ISA语义限制。

#### 高频考点

位移字段16位时：

$$
-32768\le offset\le32767
$$

若单位1B：

相对基准的位移范围为：

$$
[-32768,32767]\text{B}
$$

若单位4B：

实际字节位移范围为：

$$
[-131072,131068]\text{B}
$$

**位移字段位数相同，不代表字节寻址范围相同。**


### 9.6 2009年408真题

题目：

- 指令位于2000H；
- 长度2B；
- 相对位移06H；
- 每读取一个字节PC自动加1。

求成功跳转后的目标地址。

#### 解答

取完指令：

$$
PC_{\text{next}}=2000H+2
$$

$$
=2002H
$$

再加位移：

$$
Target=2002H+06H
$$

最终：

$$
\boxed{2008H}
$$

#### 错误答案

$$
2000H+06H=2006H
$$

错误原因：

没有考虑取指结束后PC已经变化。


### 9.7 模拟题：反求负位移机器码

题目：

- 当前转移指令地址200CH；
- 指令长度2B；
- 跳转目标1FB0H；
- 位移字段8位补码；
- 位移单位1B。

求位移字段内容。

#### 第一步：计算下一条地址

$$
PC_{\text{next}}=200CH+2
$$

$$
=200EH
$$

#### 第二步：反求位移

$$
offset=1FB0H-200EH
$$

$$
=-5EH
$$

十进制：

$$
-94
$$

#### 第三步：转换成8位补码

$$
2^8-94=162
$$

即：

$$
\boxed{A2H}
$$

#### 检查

A2H作为8位补码：

$$
162-256=-94
$$

代入：

$$
200EH-94=1FB0H
$$

正确。

#### 通用模板

求跳转地址：

$$
Target=PC_{\text{next}}+offset\times s
$$

求位移：

$$
\boxed{
offset=\frac{Target-PC_{\text{next}}}{s}
}
$$

最后还必须判断：

1. 是否为整数；
2. 能否放入给定补码位宽；
3. 是否满足目标地址对齐限制。


## 十、2013年408综合题：条件转移与PC

### 10.1 题目核心条件

一台机器采用：

- 16位定长指令；
- 8位补码OFFSET；
- CF、ZF、NF三个标志；
- C、Z、N三个检测位。

指令格式：

```text
┌────────┬───┬───┬───┬────────┐
│ 00000  │ C │ Z │ N │ OFFSET │
│  5位   │1位│1位│1位│   8位  │
└────────┴───┴───┴───┴────────┘
```

跳转公式：

$$
\boxed{
PC'=PC+2+2\times OFFSET
}
$$

条件：

**只要被选中检测的标志中有一个为1，就发生转移。**

### 10.2 判断条件

数学形式：

$$
J=(C\land CF)\lor(Z\land ZF)\lor(N\land NF)
$$

其中：

- C、Z、N：检测开关；
- CF、ZF、NF：实际状态标志。

这两组值不能混淆。

例如：

```text
C=0
Z=1
N=1
```

表示：

- 不检查CF；
- 检查ZF；
- 检查NF。

因此：

$$
J=ZF\lor NF
$$

即使CF=1，也不一定发生跳转。


### 10.3 求最大反向跳转范围

OFFSET为8位补码：

$$
-128\le OFFSET\le127
$$

最大负位移：

$$
OFFSET=-128
$$

代入：

$$
PC'=PC+2+2(-128)
$$

$$
PC'=PC-254
$$

每条指令2B：

$$
\frac{254}{2}=127
$$

因此最远能够跳到当前指令之前第127条指令的位置。

注意：

如果以**下一条顺序指令**作为计数基准，则反向偏移128个指令长度。

这两个数字并不矛盾，区别是计数起点不同。


### 10.4 计算实际跳转地址

给定：

```text
PC=200CH

C=0
Z=1
N=1

OFFSET=11100011B
```

首先：

$$
11100011_2=E3H
$$

作为8位补码：

$$
227-256=-29
$$

若：

```text
CF=0
ZF=0
NF=1
```

由于NF被检测且为1，所以跳转。

$$
PC'=200CH+2+2(-29)
$$

$$
=200EH-3AH
$$

得到：

$$
\boxed{PC'=1FD4H}
$$

如果：

```text
CF=1
ZF=0
NF=0
```

虽然CF=1，但C=0，不检查CF。

因此不跳转：

$$
\boxed{PC'=200EH}
$$


### 10.5 无符号小于等于时跳转

执行无符号比较：

$$
a-b
$$

无符号小于意味着借位：

$$
CF=1
$$

相等意味着：

$$
ZF=1
$$

所以：

$$
a\le b
\iff CF\lor ZF
$$

因此检测位：

```text
C=1
Z=1
N=0
```

答案：

$$
\boxed{C=1,\ Z=1,\ N=0}
$$

这里使用的是题目给出的CF借位语义。


### 10.6 这道综合题的完整做题框架

任何条件转移题都拆成两个问题：

#### 问题一：是否发生跳转？

根据：

- 标志寄存器；
- 条件码；
- 比较的signed/unsigned语义。

#### 问题二：跳转到哪里？

根据：

- PC基准；
- 指令长度；
- 位移位宽；
- 正负位移；
- 位移单位。

最终：

```text
比较或运算产生标志
       ↓
判断跳转条件
       ↓
     是否跳转？
      /     \
    否       是
    │        │
PC顺序执行  PC相对地址计算
```

不能只算出目标地址，就默认CPU一定跳转。


## 十一、数据对齐

### 11.1 为什么要对齐？

假设一个int占4B。

若要求4B对齐，起始地址必须满足：

$$
\boxed{Address\bmod4=0}
$$

合法：

```text
1000H
1004H
1008H
100CH
```

不符合4B对齐：

```text
1001H
1002H
1003H
```

对齐的作用：

- 减少跨边界读取；
- 简化某些硬件实现；
- 提高访存效率；
- 满足某些ISA的访问限制。

但必须注意：

**未对齐不意味着所有CPU都无法访问。**

具体行为取决于ISA和实现。


### 11.2 常见数据类型的对齐

在题目采用典型32位C ABI规则时：

| 类型 | 典型大小 | 常见对齐 |
|---|---:|---:|
| char | 1B | 1B |
| short | 2B | 2B |
| int | 4B | 4B |
| float | 4B | 4B |
| double | 8B | 依ABI |
| 指针 | 4B或8B | 依ABI |

不要认为：

- 所有double一定8B对齐；
- 所有long一定8B；
- 所有指针一定8B。

考试优先使用题目明确给出的规则。


### 11.3 结构体对齐

例如：

```c
struct S {
    char c;
    int x;
    short y;
};
```

假设：

- char占1B，对齐1B；
- int占4B，对齐4B；
- short占2B，对齐2B；
- 整个结构体按4B对齐。

#### 第一步：char

```text
偏移0：c
```

#### 第二步：int

int必须4B对齐。

偏移1不满足。

所以填充：

```text
偏移1
偏移2
偏移3
```

int放在：

```text
偏移4～7
```

#### 第三步：short

接下来的偏移8满足2B对齐。

所以：

```text
偏移8～9：y
```

#### 第四步：尾部填充

目前使用10B。

但结构体整体按4B对齐。

所以补齐到12B。

最终：

```text
偏移0       c
偏移1～3    padding
偏移4～7    x
偏移8～9    y
偏移10～11  padding
```

因此：

$$
\boxed{sizeof(S)=12B}
$$

而不是：

$$
1+4+2=7B
$$


### 11.4 通用对齐公式

若当前偏移为 $p$，下一成员要求 $K$ 字节对齐。

需要填充：

$$
\boxed{
Padding=(K-(p\bmod K))\bmod K
}
$$

成员起始位置：

$$
p'=p+Padding
$$

如果整体对齐要求为 $A$，结构体结束偏移为 $p_{end}$，则：

$$
\boxed{
Size=
\left\lceil
\frac{p_{end}}{A}
\right\rceil A
}
$$


### 11.5 2012年408真题

```c
struct {
    int a;
    char b;
    short c;
} record;

record.a = 273;
```

已知：

- int为4B；
- short为2B；
- 小端存储；
- 按边界对齐；
- record首地址为0xC008。

求：

1. 地址0xC008中的内容；
2. record.c的地址。

#### 第一问

273转换为十六进制：

$$
273=111H
$$

32位表示：

```text
00000111H
```

按字节切分：

```text
00 00 01 11
```

小端存储：

```text
地址       内容

C008       11
C009       01
C00A       00
C00B       00
```

所以：

$$
\boxed{M[C008H]=11H}
$$

#### 第二问

a占：

```text
C008～C00B
```

b占：

```text
C00C
```

short要求2B对齐。

C00D不是2B对齐位置。

需要填充1B。

因此：

$$
\boxed{\&record.c=C00EH}
$$


## 十二、大端与小端

### 12.1 字节序的定义

字节序决定：

**一个多字节数据的各字节如何排列在连续内存地址中。**

例如32位数据：

```text
12345678H
```

划分成：

```text
12 | 34 | 56 | 78
```

其中：

- 12：最高有效字节；
- 78：最低有效字节。


### 12.2 大端存储

高位字节放低地址。

```text
地址      内容

1000H     12
1001H     34
1002H     56
1003H     78
```

口诀：

**大端：高位字节放低地址。**


### 12.3 小端存储

低位字节放低地址。

```text
地址      内容

1000H     78
1001H     56
1002H     34
1003H     12
```

口诀：

**小端：低位字节放低地址。**

#### 特别注意

字节序只影响字节之间的排列。

不会把每个字节内部的bit顺序颠倒。

例如：

```text
12H = 00010010B
```

即使采用小端，12H这个字节内部也不会变成：

```text
01001000B
```


### 12.4 2016年408真题

给定：

```text
1122334455667788H
```

采用小端存储。

起始地址：

```text
00008040H
```

求：

```text
00008046H
```

中的内容。

#### 第一步：划分字节

```text
11 22 33 44 55 66 77 88
```

#### 第二步：小端排列

```text
8040H → 88
8041H → 77
8042H → 66
8043H → 55
8044H → 44
8045H → 33
8046H → 22
8047H → 11
```

因此：

$$
\boxed{22H}
$$


### 12.5 2018年408真题：负数与小端

已知：

```text
int i=0
```

对应机器码：

```text
C745FC00000000
```

求：

```c
int i=-64;
```

的机器码。

#### 第一步：计算补码

64的十六进制为：

$$
40H
$$

32位负数补码：

$$
2^{32}-64
$$

得到：

$$
FFFFFFC0H
$$

#### 第二步：小端排列立即数

```text
C0 FF FF FF
```

#### 第三步：保持其他指令字段不变

原机器码：

```text
C7 45 FC 00 00 00 00
```

替换立即数：

```text
C7 45 FC C0 FF FF FF
```

最终：

$$
\boxed{\texttt{C745FCC0FFFFFF}}
$$

#### 易错点

机器码中的立即数是多字节字段。

小端存储需要按照字节顺序排列，而不是把整个十六进制数字逐字符倒过来。


### 12.6 2019年408：基址寻址与大端联合

题目给出：

- 大端存储；
- 操作数为1234FF00H；
- 基址寄存器为F0000000H；
- 形式地址FF12H；
- 形式地址为16位补码。

求最低有效字节LSB所在地址。

#### 第一步：符号扩展

FF12H是负数：

$$
FF12H=-238
$$

扩展到32位：

$$
FFFFFF12H
$$

#### 第二步：计算EA

$$
EA=F0000000H+FFFFFF12H
$$

在32位地址运算中：

$$
\boxed{EA=EFFFFF12H}
$$

#### 第三步：处理大端

数据：

```text
12 34 FF 00
```

大端存储：

```text
EFFFFF12H → 12
EFFFFF13H → 34
EFFFFF14H → FF
EFFFFF15H → 00
```

最低有效字节：

```text
00
```

位于：

$$
\boxed{EFFFFF15H}
$$

#### 题型总结

这道题同时考查三个独立步骤：

```text
补码符号扩展
      ↓
基址寻址计算EA
      ↓
根据大小端定位字节
```

**以后遇到这种题，不能先处理大小端而忽略EA计算。**

```asm
add rd, rs, rt
```

R[rd]\leftarrow R[rs]+R[rt]

```asm
addi rt, rs, imm
```

### 13.4 MIPS分支位移

例如：

```asm
beq rs, rt, label
```

经典MIPS风格中：

$$
\boxed{
Target=PC+4+\operatorname{SExt}(imm16)\times4
}
$$

为什么乘4？

因为：

- 指令固定4B；
- 分支位移以指令字为单位；
- 指令地址按字节表示。

#### 例题

假设：

```text
分支指令地址：3000H
位移字段：FFFC H
```

16位补码：

$$
FFFC H=-4
$$

下一条地址：

$$
PC+4=3004H
$$

实际位移：

$$
-4\times4=-16B
$$

所以：

$$
Target=3004H-10H
$$

得到：

$$
\boxed{2FF4H}
$$

#### 易错点

- 不是从3000H直接加；
- 不是把FFFC当正数；
- 不能忘记乘4。


### 13.5 立即数符号扩展与零扩展

典型MIPS中：

| 指令 | 立即数处理 |
|---|---|
| addi | 符号扩展 |
| lw | 符号扩展 |
| sw | 符号扩展 |
| beq | 符号扩展后按分支单位换算 |
| ori | 零扩展 |
| andi | 零扩展 |
| xori | 零扩展 |
| lui | 立即数放入高16位，低16位补0 |

例如：

```text
imm16=FF00H
```

符号扩展：

```text
FFFFFF00H
```

零扩展：

```text
0000FF00H
```

二者完全不同。

#### 重要提醒

不能认为：

**所有I型指令都采用符号扩展。**

立即数扩展规则是每条指令语义的一部分。


## 十四、2027王道模拟综合题：构造32位地址

### 14.1 题目

假设要将任意32位地址A装入寄存器t0。

地址分成：

$$
A=A_{\text{upper}}\times2^{16}+A_{\text{lower}}
$$

其中：

- $A_{\text{upper}}$：高16位；
- $A_{\text{lower}}$：低16位。

方式一：

```asm
lui t0, A_upper
ori t0, t0, A_lower
```

方式二：

```asm
lui t0, A_upper_adjusted
lw s0, A_lower(t0)
```

第二种方式的低16位偏移采用有符号数。

求高16位是否需要调整。


### 14.2 方式一：LUI + ORI

`lui`：

$$
R[t0]=A_{\text{upper}}\ll16
$$

低16位补0。

`ori`：

立即数零扩展，再与寄存器按位或。

因此：

$$
R[t0]=(A_{\text{upper}}\ll16)\lor A_{\text{lower}}
$$

最终：

$$
\boxed{R[t0]=A}
$$

高低16位直接组合即可。


### 14.3 方式二：LUI + LW

关键问题：

`lw`的偏移量采用16位有符号数。

假设：

$$
A=1234F234H
$$

高16位：

$$
A_{\text{upper}}=1234H
$$

低16位：

$$
A_{\text{lower}}=F234H
$$

但是：

$$
F234H
$$

作为16位补码表示负数。

它的值为：

$$
F234H-10000H=-DCC H
$$

如果直接使用：

```asm
lui t0, 1234H
lw s0, F234H(t0)
```

实际地址：

$$
12340000H-DCC H
$$

这不是原来的1234F234H。

因此必须把高16位加1。

```asm
lui t0, 1235H
lw s0, F234H(t0)
```

有效地址：

$$
12350000H-DCC H
$$

得到：

$$
\boxed{1234F234H}
$$


### 14.4 通用结论

$$
\boxed{
A_{\text{upper,adjusted}}=
\begin{cases}
A_{\text{upper}},&A_{\text{lower}}<8000H\\
A_{\text{upper}}+1,&A_{\text{lower}}\ge8000H
\end{cases}
}
$$

高16位按相应位宽处理进位。

#### 为什么8000H是分界线？

16位补码：

$$
8000H=-32768
$$

最高位为1时，符号扩展结果为负。

所以：

- 低16位最高位为0：不调整；
- 低16位最高位为1：高16位加1。

这类题的本质：

**立即数采用哪种扩展方式，会影响最终有效地址。**


## 十五、2021年408综合题：R/I/J型指令与补码

### 15.1 题目条件

某计算机：

- 字长16位；
- 按字节编址；
- 地址线20位；
- 数据线8位；
- 定长指令16位；
- R/I/J三种格式。

R型使用：

```text
000000 | rs | rt | rd | op1
 6位     2位  2位  2位   4位
```

I/J型共享其余6位主操作码空间。


### 15.2 各类硬件位宽

#### ALU

机器字长16位：

$$
\boxed{ALU=16\text{位}}
$$

#### 主存可寻址空间

20位地址线：

$$
2^{20}
$$

按字节编址：

$$
\boxed{2^{20}B=1MiB}
$$

#### IR

指令16位：

$$
\boxed{IR=16\text{位}}
$$

#### MAR

地址线20位：

$$
\boxed{MAR=20\text{位}}
$$

#### MDR

数据线8位：

$$
\boxed{MDR=8\text{位}}
$$


### 15.3 指令数量

R型具体操作码op1为4位。

所以：

$$
\boxed{2^4=16}
$$

种操作。

I/J型使用6位主操作码。

总共有：

$$
2^6=64
$$

种前缀。

但是：

```text
000000
```

已经分配给R型。

因此：

$$
64-1=63
$$

所以：

$$
\boxed{\text{I型与J型合计最多63种}}
$$

注意是**合计**，不是各63种。

#### 寄存器数量

编号字段2位：

$$
2^2=4
$$

所以：

$$
\boxed{4\text{个通用寄存器}}
$$


### 15.4 解码01B2H

机器码：

```text
01B2H
```

展开：

```text
0000 0001 1011 0010
```

按照题设划分：

```text
000000 | 01 | 10 | 11 | 0010
 前缀    rs   rt   rd    op1
```

因此：

```text
rs=R1
rt=R2
rd=R3
op1=0010
```

题目规定：

```text
0010：带符号减法
```

所以：

$$
\boxed{R3\leftarrow R1-R2}
$$


### 15.5 补码减法

给定：

$$
R1=B052H
$$

$$
R2=0008H
$$

B052H作为16位补码：

$$
B052H=-20398
$$

因此：

$$
-20398-8=-20406
$$

仍在16位补码范围内。

机器数：

$$
\boxed{B04AH}
$$

无溢出。


### 15.6 补码乘法

如果：

```text
op1=0011
```

表示乘法。

机器码：

```text
01B3H
```

功能：

$$
R3\leftarrow R1\times R2
$$

数学结果：

$$
-20398\times8=-163184
$$

16位补码范围：

$$
[-32768,32767]
$$

因此发生有符号溢出。

低16位机器结果：

$$
\boxed{8290H}
$$

#### 为什么不能只看结果最高位？

8290H最高位为1，表示负数。

但：

**结果是负数不等于发生溢出。**

真正的判断依据是完整数学结果是否能由16位补码表示。

本题：

$$
-163184<-32768
$$

因此溢出。


## 十六、2026年408综合题：自定义R/I/M型指令

这道题非常有价值，因为它说明：

**不能套用固定的MIPS或RISC-V位段定义，必须按照题目中的机器M重新解码。**

### 16.1 指令格式

题目给定16位指令。

#### R型

```text
0000 | rt | rs/num | op1
 4位   4位    4位     4位
```

#### I型

```text
op2 | rt | imm8
 4位  4位   8位
```

#### M型

```text
op3 | offset12
 4位     12位
```

其中M型使用题设规定的隐含寄存器R0、R15。


### 16.2 操作码是否可以相同？

题目问：

- op1和op2能否相同？
- op2和op3能否相同？

#### op1与op2

可以相同。

原因：

R型：

```text
最高4位固定0000
```

具体操作码在最低4位。

I型：

```text
操作码在最高4位
```

由于字段位置和类型区分不同，不一定造成译码冲突。

#### op2与op3

不能相同。

因为I型和M型的操作码都处于最高4位。

如果没有其他类型区分信息，相同编码就会造成歧义。

#### 通用判断方法

不能只看操作码的二进制数字是否相同。

必须同时看：

1. 操作码位于哪些位；
2. 是否有固定格式前缀；
3. 其他字段能否唯一地区分类型。


### 16.3 指令执行题

给定：

$$
R2=ABCDH
$$

$$
R9=F001H
$$

执行：

```text
0000 0010 1001 0001
```

解码：

```text
0000 | 0010 | 1001 | 0001
R型    rt=2   rs=9   ADD
```

功能：

$$
R2\leftarrow R2+R9
$$

所以：

$$
ABCDH+F001H=19BCEH
$$

16位寄存器只保留低16位：

$$
\boxed{R2=9BCEH}
$$

R9作为源寄存器，没有被修改：

$$
\boxed{R9=F001H}
$$

#### 标志位进一步分析

如果按16位无符号加法判断：

产生了最高位进位：

$$
CF=1
$$

如果按16位带符号补码判断：

两个负数相加，数学结果仍在16位有符号范围内：

$$
OF=0
$$

因此：

**CF和OF可以不同。**


### 16.4 用指令实现 $y=16x-5$

题目规定：

- x、y都是16位整数；
- 按字节编址；
- x和y连续存放；
- R15保存x的地址；
- R0作为数据寄存器。

目标：

$$
y=16x-5
$$

可以分成四步。

#### 第一步：加载x

```asm
LOAD R0, [R15+0]
```

#### 第二步：乘16

因为：

$$
16=2^4
$$

所以：

```asm
SHL R0, 4
```

#### 第三步：减5

相当于加-5：

```asm
ADDI R0, -5
```

8位补码：

$$
-5=FBH
$$

#### 第四步：存储y

x占2B。

y紧跟x后面。

所以：

$$
\&y=\&x+2
$$

执行：

```asm
STORE [R15+2], R0
```

对应题设完整机器码：

```text
1110 0000 0000 0000

0000 0000 0100 0010

0100 0000 1111 1011

1111 0000 0000 0010
```

#### 核心考查

这道题同时涉及：

- 指令编码；
- 寄存器编号；
- 立即数补码；
- 左移运算；
- 按字节编址；
- 连续变量地址；
- LOAD/STORE。

以后遇到要求“用若干条指令实现C表达式”的题目，可以将目标表达式拆成：

```text
LOAD
  ↓
计算
  ↓
修改
  ↓
STORE
```

如果数学结果超出目标类型表示范围，则机器仍可能写入低位比特，但不能认为其有符号数学结果仍然正确。


## 十七、x86汇编指令体系

### 17.1 常用寄存器

| 16位 | 32位 | 64位 | 典型用途 |
|---|---|---|---|
| AX | EAX | RAX | 运算、返回值 |
| BX | EBX | RBX | 通用数据、基址 |
| CX | ECX | RCX | 计数 |
| DX | EDX | RDX | 数据、乘除法 |
| SP | ESP | RSP | 栈指针 |
| BP | EBP | RBP | 栈帧基址 |
| SI | ESI | RSI | 源索引 |
| DI | EDI | RDI | 目的索引 |
| IP | EIP | RIP | 指令指针 |

需要重点认识：

```text
EAX：32位运算结果、返回值
ESP：32位栈顶指针
EBP：32位经典栈帧基址
EIP：32位指令指针
```


### 17.2 Intel与AT&T语法

#### Intel

```asm
mov eax, ebx
```

操作数顺序：

```text
目的, 源
```

表示：

$$
EAX\leftarrow EBX
$$

#### AT&T

```asm
movl %ebx, %eax
```

操作数顺序：

```text
源, 目的
```

同样表示：

$$
EAX\leftarrow EBX
$$

#### 对比

| 特征 | Intel | AT&T |
|---|---|---|
| 操作数顺序 | 目的、源 | 源、目的 |
| 寄存器 | eax | %eax |
| 立即数 | 5 | $5 |
| 内存访问 | [eax] | (%eax) |
| 32位传送 | mov | movl |

AT&T常见后缀：

```text
b：8位
w：16位
l：32位
q：64位
```


### 17.3 MOV

```asm
mov eax, ebx
```

表示：

$$
EAX\leftarrow EBX
$$

```asm
mov eax, [ebx]
```

表示：

$$
EAX\leftarrow M[EBX]
$$

```asm
mov [ebx], eax
```

表示：

$$
M[EBX]\leftarrow EAX
$$

注意：

普通x86 MOV一般不能让源和目的同时都是普通内存操作数。


### 17.4 ADD与SUB

```asm
add eax, ebx
```

$$
EAX\leftarrow EAX+EBX
$$

```asm
sub eax, ebx
```

$$
EAX\leftarrow EAX-EBX
$$

这些运算一般还会修改条件标志。


### 17.5 INC与DEC

```asm
inc eax
```

$$
EAX\leftarrow EAX+1
$$

```asm
dec eax
```

$$
EAX\leftarrow EAX-1
$$

但要注意：

x86中的INC和DEC不修改CF。

所以不能认为：

```asm
inc eax
```

和：

```asm
add eax, 1
```

在所有标志位效果上都完全一致。


### 17.6 CMP

```asm
cmp eax, ebx
```

本质：

$$
EAX-EBX
$$

用于设置条件标志。

但不把减法结果写回EAX。

例如：

```asm
cmp eax, ebx
je equal
```

第一条指令：

设置标志位。

第二条指令：

根据标志位决定跳转。


### 17.7 TEST

```asm
test eax, eax
```

相当于进行按位与：

$$
EAX\land EAX
$$

用于设置标志。

但不保存运算结果。

常用于：

- 判断是否为0；
- 检测某些位；
- 根据结果设置ZF、SF等标志。


### 17.8 SHL与SHR

#### 逻辑左移

```asm
shl eax, 1
```

高位移出，低位补0。

例如8位数：

```text
00101101
```

左移1位：

```text
01011010
```

如果没有有效位丢失，对应数值乘2。

#### 逻辑右移

```asm
shr eax, 1
```

高位补0。

例如：

```text
10010000
```

结果：

```text
01001000
```

#### 算术右移SAR

```asm
sar eax, 1
```

高位补原符号位。

例如：

```text
11110000
```

结果：

```text
11111000
```

#### 重要易错

算术右移对于负奇数的舍入方式，不一定与高级语言中的有符号整数除法相同。

例如：

$$
-3/2
$$

C整数除法通常向0截断，得到-1。

而典型补码算术右移1位相当于向负无穷取整，得到-2。

不能无条件认为SAR就是C语言的整数除法。


## 十八、标志寄存器与条件转移

### 18.1 四个重要标志

| 标志 | 名称 | 主要含义 |
|---|---|---|
| ZF | Zero Flag | 结果是否为0 |
| SF | Sign Flag | 结果符号位 |
| CF | Carry Flag | 无符号进位或借位 |
| OF | Overflow Flag | 有符号溢出 |

#### ZF

$$
ZF=1
$$

表示结果为0。

#### SF

通常反映结果的最高符号位。

#### CF

在无符号加减运算中用于判断进位或借位。

#### OF

判断有符号结果是否超出对应补码范围。


### 18.2 CF与OF的区别

假设8位数相加：

```text
7FH + 01H = 80H
```

无符号解释：

$$
127+1=128
$$

8位无符号范围：

$$
0\sim255
$$

没有无符号溢出。

所以：

$$
CF=0
$$

有符号解释：

$$
127+1=128
$$

但8位补码范围：

$$
-128\sim127
$$

发生有符号溢出。

因此：

$$
OF=1
$$

所以：

$$
\boxed{CF=0,\ OF=1}
$$

再看：

```text
FFH + 01H = 00H
```

无符号解释：

$$
255+1=256
$$

超出8位无符号范围：

$$
CF=1
$$

有符号解释：

$$
-1+1=0
$$

没有有符号溢出：

$$
OF=0
$$

所以：

$$
\boxed{CF=1,\ OF=0}
$$

**这两个例子必须掌握。**


### 18.3 有符号条件跳转

| 指令 | 含义 | 条件 |
|---|---|---|
| JE/JZ | 等于 | $ZF=1$ |
| JNE/JNZ | 不等于 | $ZF=0$ |
| JG | 有符号大于 | $ZF=0\land SF=OF$ |
| JGE | 有符号大于等于 | $SF=OF$ |
| JL | 有符号小于 | $SF\ne OF$ |
| JLE | 有符号小于等于 | $ZF=1\lor SF\ne OF$ |

最重要：

$$
\boxed{JL:\ SF\oplus OF=1}
$$

$$
\boxed{JGE:\ SF=OF}
$$

$$
\boxed{JLE:\ ZF=1\lor(SF\ne OF)}
$$

#### 为什么不能只看SF？

因为减法可能发生有符号溢出。

此时结果符号位可能与数学比较关系不一致。

因此需要结合OF修正。


### 18.4 无符号条件跳转

| 指令 | 含义 | 条件 |
|---|---|---|
| JA | 无符号大于 | $CF=0\land ZF=0$ |
| JAE | 无符号大于等于 | $CF=0$ |
| JB | 无符号小于 | $CF=1$ |
| JBE | 无符号小于等于 | $CF=1\lor ZF=1$ |

最重要：

**有符号比较主要结合SF、OF、ZF。**

**无符号比较主要结合CF、ZF。**


### 18.5 模拟选择题：JL判断

题目问：

```asm
jl label
```

的条件是什么？

答案：

$$
\boxed{SF\oplus OF=1}
$$

不能简单选：

$$
SF=1
$$

因为有符号减法发生溢出时，SF可能失真。


## 十九、CALL、RET与堆栈

### 19.1 JMP与CALL的区别

#### JMP

```asm
jmp label
```

主要作用：

改变PC。

#### CALL

```asm
call func
```

主要作用：

1. 保存返回地址；
2. 跳转到函数入口。

#### RET

```asm
ret
```

主要作用：

从保存的位置恢复返回地址，并让PC返回调用点。

因此：

**CALL不仅仅是JMP。**


### 19.2 返回地址是什么？

假设：

```text
CALL首地址：1000H
CALL长度：5B
```

那么：

$$
ReturnAddress=1000H+5
$$

所以：

$$
\boxed{1005H}
$$

这个地址是CALL后面顺序执行的下一条指令地址。

不是被调用函数入口地址。


### 19.3 栈向低地址增长

经典32位x86栈通常向低地址增长。

#### PUSH

```asm
push eax
```

在典型32位栈模型中：

```text
ESP ← ESP-4

M[ESP] ← EAX
```

#### POP

```asm
pop eax
```

通常：

```text
EAX ← M[ESP]

ESP ← ESP+4
```

因此：

**PUSH先减SP，POP后加SP。**

但某些考题给出的机器按字编址，SP变化单位可能是1个字地址。

必须按题设判断。


### 19.4 模拟题：CALL改变SP

题目：

- 双字长CALL指令；
- 按字编址；
- CALL地址1000H；
- 目标地址5000H；
- SP初值0100H；
- 入栈规则是先SP减1，再存数据。

求CALL后的SP和新栈顶。

#### 第一步：返回地址

双字长意味着占两个字地址。

$$
ReturnAddress=1000H+2
$$

$$
=1002H
$$

#### 第二步：修改SP

$$
SP=0100H-1
$$

$$
\boxed{SP=00FFH}
$$

#### 第三步：保存返回地址

$$
M[00FFH]\leftarrow1002H
$$

所以：

$$
\boxed{\text{新栈顶内容}=1002H}
$$

#### 第四步：进入函数

$$
PC\leftarrow5000H
$$

注意：

5000H是调用目标地址。

1002H才是返回地址。


## 二十、经典32位x86函数栈帧

### 20.1 函数调用示例

```c
int add(int x, int y) {
    return x + y;
}
```

一种经典cdecl风格的实现：

```asm
add:
    push ebp
    mov ebp, esp

    mov eax, [ebp+8]
    add eax, [ebp+12]

    mov esp, ebp
    pop ebp
    ret
```

### 20.2 栈帧布局

```text
高地址

┌────────────────────┐
│ 第二个参数 y       │ ← EBP+12
├────────────────────┤
│ 第一个参数 x       │ ← EBP+8
├────────────────────┤
│ 返回地址           │ ← EBP+4
├────────────────────┤
│ 旧EBP              │ ← EBP
├────────────────────┤
│ 局部变量1          │ ← EBP-4
├────────────────────┤
│ 局部变量2          │ ← EBP-8
└────────────────────┘

低地址
```

前提：

- 32位x86；
- 使用该典型栈传参约定；
- 每个栈槽按4B计算；
- 使用EBP作为固定帧指针。

#### 典型访问

```asm
mov eax, [ebp+8]
```

读取第一个参数。

```asm
mov eax, [ebp+12]
```

读取第二个参数。

```asm
mov eax, [ebp-4]
```

读取局部变量。


### 20.3 为什么参数是正偏移？

因为：

1. 调用前参数已经放在栈上；
2. CALL保存返回地址；
3. 被调用函数保存旧EBP；
4. EBP成为当前栈帧基准；
5. 局部变量向更低地址分配。

所以：

- 参数常位于EBP上方；
- 局部变量常位于EBP下方。

#### 重要提醒

这是经典栈帧模型。

现代编译器可能：

- 优先用寄存器传参；
- 省略帧指针；
- 内联函数；
- 优化栈布局。

不能认为每个函数都必须有同样的栈帧。


### 20.4 Caller与Callee

#### Caller

调用者。

#### Callee

被调用者。

例如：

```c
int main() {
    return add(3, 5);
}
```

其中：

- main：caller；
- add：callee。

调用约定还决定：

- 参数放在哪；
- 返回值放在哪；
- 哪些寄存器由调用者保存；
- 哪些寄存器由被调用者保存；
- 谁负责清理参数栈。

#### Caller-saved

如果调用者希望函数调用后某寄存器的旧值仍然有效，需要自行保存。

#### Callee-saved

如果被调用者修改某些受保护寄存器，则返回前需要恢复。


## 二十一、2019年408综合题：递归、CALL与机器码

### 21.1 题目背景

递归计算阶乘：

```c
int f1(int n) {
    if (n > 1)
        return n * f1(n-1);
    else
        return 1;
}
```

给出的关键机器码：

```text
00401018  83 7D 08 01       cmp
0040101C  7E 17             jle
0040101E  8B 45 08          mov
00401021  83 E8 01          sub
00401024  50                push
00401025  E8 D6 FF FF FF    call f1
...
00401030  0F AF C1          imul
00401033  EB 05             jmp
...
0040104A  C3                ret
```


### 21.2 递归调用次数

计算：

$$
f(10)
$$

递归链：

```text
f(10)
 ↓
f(9)
 ↓
f(8)
 ↓
...
 ↓
f(2)
 ↓
f(1)
```

一共进入函数10次。

因此：

$$
\boxed{10\text{次函数调用层次}}
$$

但递归CALL指令实际执行：

$$
\boxed{9\text{次}}
$$

为什么？

因为：

```text
f(1)
```

已经到达递归基例，不再执行递归CALL。

**函数进入次数与递归CALL执行次数可能相差1。**


### 21.3 识别条件转移

```asm
jle
```

是条件转移。

```asm
call
```

是函数调用控制转移。

```asm
jmp
```

是无条件转移。

```asm
ret
```

是函数返回控制转移。

所以：

- 条件转移：jle；
- 执行时必改变控制流：call、jmp、ret。

CMP本身不改变PC。


### 21.4 求CALL下一条地址

CALL地址：

```text
00401025H
```

机器码：

```text
E8 D6 FF FF FF
```

长度5B。

所以：

$$
PC_{\text{next}}=00401025H+5
$$

得到：

$$
\boxed{0040102AH}
$$


### 21.5 求CALL位移

函数目标：

```text
00401000H
```

位移：

$$
offset=Target-PC_{\text{next}}
$$

$$
=00401000H-0040102AH
$$

$$
=-2AH
$$

十进制：

$$
-42
$$

32位补码：

$$
\boxed{FFFFFFD6H}
$$

小端编码：

```text
D6 FF FF FF
```

与题目机器码一致。

因此计算机采用小端存储。

#### 这道题的考查链条

```text
识别CALL
    ↓
计算指令长度
    ↓
求下一条PC
    ↓
反求相对位移
    ↓
转换成补码
    ↓
检查小端机器码
```


### 21.6 阶乘溢出

数学上：

$$
13!=6227020800
$$

32位有符号整数最大值：

$$
2^{31}-1=2147483647
$$

显然：

$$
6227020800>2147483647
$$

发生有符号溢出。

如果题设机器只保留低32位：

$$
6227020800\bmod2^{32}
$$

得到：

$$
\boxed{1932053504}
$$

但严格来说，标准C中的有符号整数溢出属于未定义行为。

题目中的返回值对应的是特定机器实现下的截断结果。

#### 如何修复？

应该使用更宽的类型：

```c
long long f1(int n) {
    if (n <= 1)
        return 1LL;

    return (long long)n * f1(n - 1);
}
```

不仅外部变量要变宽。

递归函数的返回类型和乘法中间结果都需要具有足够宽度。


### 21.7 IMUL有符号乘法溢出

假设两个32位整数相乘，得到完整64位乘积：

```text
高32位 H | 低32位 L
```

如果低32位能够无损表示整个有符号乘积，那么：

```text
低32位最高位为0：
H必须全0
```

或者：

```text
低32位最高位为1：
H必须全1
```

否则：

$$
\boxed{OF=1}
$$

等价条件：

$$
\boxed{
OF=1
\iff
P\ne\operatorname{SExt}_{64}(P_L)
}
$$

其中：

- $P$：完整64位积；
- $P_L$：低32位结果。

在支持相应指令的32位x86环境中，可以通过INTO根据OF触发溢出异常。

也可以用：

```asm
jo overflow_handler
```

跳转到软件溢出处理路径。

### 22.2 if-else的汇编结构

C：

```c
if (a > b) {
    max = a;
} else {
    max = b;
}
```

一种典型汇编：

```asm
cmp eax, ebx
jle else_label

mov ecx, eax
jmp end_label

else_label:
mov ecx, ebx

end_label:
```

其中：

- CMP：设置比较标志；
- JLE：条件不成立时跳转；
- JMP：跳过另一分支；
- 标签：控制流汇合点。

#### 判断方法

找到：

1. CMP或TEST；
2. 条件跳转；
3. 两条分支；
4. 汇合点。

就能够大致恢复if-else结构。


### 22.3 while循环

C：

```c
while (i < 10) {
    i++;
}
```

典型汇编：

```asm
loop:
    cmp ecx, 10
    jge end

    inc ecx
    jmp loop

end:
```

特征：

**先判断，再执行。**

所以循环可能执行0次。


### 22.4 do-while循环

```c
do {
    i++;
} while (i < 10);
```

典型汇编：

```asm
loop:
    inc ecx
    cmp ecx, 10
    jl loop
```

特征：

**先执行，再判断。**

所以至少执行一次。


### 22.5 for循环

```c
for (int i=0; i<10; i++) {
    sum += i;
}
```

可以分解为：

```text
初始化
  ↓
条件判断
  ↓
循环体
  ↓
更新变量
  ↓
跳回条件判断
```

一种典型汇编：

```asm
mov ecx, 0
mov eax, 0

loop:
    cmp ecx, 10
    jge end

    add eax, ecx
    inc ecx
    jmp loop

end:
```

#### 反汇编的核心技巧

看到向后跳转，不一定就能直接断定原代码是while。

必须结合：

- 初始化位置；
- 判断位置；
- 循环体；
- 更新表达式；
- 跳转目标。

编译器优化还可能改写源程序的控制结构。


## 二十三、2023年408综合题：机器码、二维数组与分页

### 23.1 题目背景

C程序：

```c
for (i=0; i<24; i++)
    for (j=0; j<64; j++)
        a[i][j] = 10;
```

其中：

```c
int a[24][64];
```

每个int占4B。

数组首地址：

```text
00422000H
```

关键机器指令：

```text
004010AE
C7 84 82 00 20 42 00 0A 00 00 00
```

对应：

```asm
mov [ecx+edx*4+00422000h], 0Ah
```


### 23.2 求下一条指令地址

机器码共有11字节。

因此：

$$
PC_{\text{next}}=004010AEH+0BH
$$

得到：

$$
\boxed{004010B9H}
$$

#### 易错点

不能因为是32位计算机，就认为每条指令都是4B。

这里采用x86风格变长指令。


### 23.3 求数组元素地址

二维数组按行优先存放：

$$
\boxed{
EA=Base+(i\times列数+j)\times元素大小
}
$$

本题：

$$
EA=00422000H+(64i+j)\times4
$$

展开：

$$
EA=00422000H+256i+4j
$$

机器指令：

```asm
[ecx+edx*4+00422000h]
```

已知：

$$
edx=j
$$

那么：

$$
\boxed{ecx=256i}
$$

#### 为什么不是64i？

因为64i表示前面有多少个数组元素。

而内存地址需要的是字节偏移。

每个元素占4B：

$$
64i\times4=256i
$$


### 23.4 判断源操作数寻址方式

指令：

```asm
mov [ecx+edx*4+00422000h], 0Ah
```

源操作数：

```text
0AH
```

直接写在指令中。

所以：

**源操作数采用立即寻址。**

目的操作数：

```text
[ecx+edx*4+00422000h]
```

采用基址、比例变址、位移组合寻址。

#### 易错点

一条指令可以有多个操作数。

不同操作数的寻址方式可以不同。

不能只因为指令访问了内存，就说所有操作数都是内存寻址。


### 23.5 判断大小端

机器码中：

```text
00 20 42 00
```

代表：

```text
00422000H
```

多字节字段按照低有效字节在前排列。

立即数：

```text
0A 00 00 00
```

代表：

```text
0000000AH
```

所以机器采用：

**小端存储。**


### 23.6 取指是否缺页？

页面大小4KB。

第一条指令地址：

```text
00401072H
```

第19条指令地址：

```text
004010AEH
```

两者位于同一个4KB代码页：

```text
00401000H～00401FFFH
```

如果前面的代码已经成功执行，且该代码页没有被换出，那么第19条取指时，不会因为该代码页尚未调入而首次缺页。

但必须区分：

- 取指访问代码页；
- STORE/MOV写数据访问数组页。

即使取指不缺页，写数组数据仍可能引发数据页缺页。

**这是一道典型的指令系统与虚拟存储器综合题。**


## 二十四、2024年408综合题：数组地址、小端与分页

### 24.1 题目

C语句：

```c
sum += a[i];
```

对应机器指令：

```asm
slli r4, r2, 2
add  r4, r3, r4
lw   r5, 0(r4)
add  r1, r1, r5
```


### 24.2 识别寄存器用途

第一条：

```asm
slli r4, r2, 2
```

表示：

$$
r4=r2\times4
$$

由于int占4B，所以r2保存数组下标i。

第二条：

```asm
add r4, r3, r4
```

表示：

$$
r4=r3+4i
$$

所以r3保存数组首地址。

第三条：

```asm
lw r5, 0(r4)
```

表示读取：

$$
a[i]
$$

第四条：

```asm
add r1, r1, r5
```

表示：

$$
sum\leftarrow sum+a[i]
$$

因此：

| 寄存器 | 含义 |
|---|---|
| r1 | sum |
| r2 | i |
| r3 | 数组首地址 |
| r4 | 元素地址 |
| r5 | 元素值 |


### 24.3 求a[5]地址

已知：

$$
i=5
$$

数组首地址：

$$
0013DFF0H
$$

每个int占4B。

所以：

$$
EA=0013DFF0H+5\times4
$$

$$
=0013DFF0H+14H
$$

得到：

$$
\boxed{0013E004H}
$$


### 24.4 求a[5]的值

题目给出从该地址开始的4个字节：

```text
DC EC FF FF
```

由于采用小端：

```text
低地址 → 低有效字节
```

所以32位机器数：

$$
\boxed{FFFFECDCH}
$$

按32位补码解释：

$$
\boxed{a[5]=-4900}
$$


### 24.5 求sum的新值

原来：

$$
sum=1332H
$$

十进制：

$$
4914
$$

因此：

$$
sum_{\text{new}}=4914-4900
$$

$$
=14
$$

对应：

$$
\boxed{0000000EH}
$$


### 24.6 求页号

页面大小4KB：

$$
4KB=2^{12}B
$$

所以页内偏移12位。

页号：

$$
VPN=EA\gg12
$$

代入：

$$
0013E004H\gg12
$$

得到：

$$
\boxed{0013EH}
$$

数组首地址：


位于：


因为题目没有给出数组的完整大小。

### 24.7 指令编码

这道题的`slli`采用题设计算机M自定义的字段编码。

对应：

```text

```

拼接：

```text

```

得到：

\boxed{00212213H}
$$

注意：

这里的funct3取010，是题目专门定义的。

不能用标准RISC-V RV32I中`slli`的funct3=001直接替换。

#### 如果int改为short？


因为int占4B：

改成short占2B：

所以：

但实际读取short时，还应使用合适的半字加载指令及符号扩展或零扩展规则。


## 二十五、RISC与CISC

### 25.1 CISC

复杂指令集计算机。

典型特点：

- 指令种类丰富；
- 寻址方式较多；
- 指令格式灵活；
- 可以支持较复杂的操作；
- 部分运算指令可直接访问内存操作数；
- 经典教材常与微程序控制联系。

典型代表：

x86、x86-64。


### 25.2 RISC

精简指令集计算机。

典型特点：

- 指令形式规则；
- 寻址方式相对较少；
- 通用寄存器较多；
- 强调Load/Store结构；
- 有利于规则流水线；
- 经典教材常与硬布线控制联系。

典型代表：

MIPS、RISC-V等。


### 25.3 Load/Store思想

例如：

```c
a[i]++;
```

在典型RISC中可能拆成：

```asm
计算a[i]地址

LOAD 读取a[i]

ADD 结果加1

STORE 写回a[i]
```

运算通常在寄存器之间完成。

而某些CISC指令可以在一条机器指令语义中组合内存操作和运算。


### 25.4 对比表

| 项目 | CISC典型特点 | RISC典型特点 |
|---|---|---|
| 指令种类 | 较丰富 | 相对精简 |
| 指令格式 | 较灵活 | 较规则 |
| 指令长度 | 常变长 | 常较固定 |
| 寻址方式 | 较多 | 较少 |
| 通用寄存器 | 传统上相对较少 | 通常较多 |
| 访存 | 部分运算可带内存操作数 | 强调Load/Store |
| 控制方式 | 经典教材常联系微程序 | 经典教材常联系硬布线 |
| 译码 | 相对复杂 | 相对简单 |
| 流水线 | 规则性相对弱 | 更易规则化 |

#### 注意

这些是经典设计思想的典型特征。

现代CPU经常融合不同设计方法。

不能认为：

- 所有RISC指令必定等长；
- CISC一定使用微程序控制器；
- RISC一定比CISC快；
- CISC一定没有流水线。


### 25.5 2009年408真题

问：

下列关于RISC的叙述中，错误的是哪一项？

A. RISC普遍采用微程序控制器

B. RISC大多数简单指令执行时间较短

C. RISC通用寄存器通常较多

D. RISC指令、寻址方式相对精简

经典RISC设计通常强调硬布线控制、规则化指令和较短控制路径。

## 二十六、2017年408：无符号下溢与浮点移位

### 26.1 无符号整数下溢

C代码：

```c
unsigned n;
```

假设：

```c
n = 0;
```

计算：

```c
n - 1
```

若unsigned为32位：

$$
0-1\equiv2^{32}-1\pmod{2^{32}}
$$

所以：

$$
\boxed{FFFFFFFFH}
$$

不是数学整数-1的有符号解释。


### 26.2 CMP与CF

假设：

```text
i=0
n-1=FFFFFFFFH
```

比较：

$$
i-(n-1)
$$

即：

$$
0-FFFFFFFFH
$$

按32位无符号运算发生借位。

所以：

$$
\boxed{CF=1}
$$

即使低32位结果是：

```text
00000001H
```

也不能因此认为没有借位。


### 26.3 为什么float不能直接SHL乘2？

例如：

```c
float x = 1.5f;
```

IEEE 754单精度机器数：

```text
3FC00000H
```

如果把整个32位机器码当整数左移：

```text
7F800000H
```

对应：

$$
+\infty
$$

但数学上：

$$
1.5\times2=3.0
$$

3.0的单精度机器数：

```text
40400000H
```

二者不同。

因此：

**整数位移与IEEE 754浮点乘法不是相同操作。**

这道题的价值在于：

同样的高级语言表达式：

```c
power *= 2;
```

对于int和float，底层指令实现可能不同。

## 二十八、王道模拟题：Load-Use冒险

考虑：

```asm
sll t1, s3, 2
add t1, t1, s6
lw  t0, 0(t1)
bne t0, s5, exit
addi s3, s3, 1
j loop
```

### 28.1 RAW相关

RAW表示Read After Write。

后一条指令需要读取前一条尚未写回的数据。

#### 相关一

```asm
sll t1, s3, 2
add t1, t1, s6
```

第二条需要读取第一条产生的t1。

#### 相关二

```asm
add t1, t1, s6
lw t0, 0(t1)
```

lw需要读取上一条计算的地址。

#### 相关三

```asm
lw t0, 0(t1)
bne t0, s5, exit
```

bne需要读取lw得到的t0。


### 28.2 为什么ALU结果可以转发？

经典五级流水线：

```text
IF → ID → EX → MEM → WB
```

ALU运算通常在EX阶段结束时产生结果。

下一条指令在EX阶段使用操作数。

因此可以通过：

```text
EX/MEM → EX
```

进行转发。


### 28.3 为什么Load-Use仍可能停顿？

LOAD：

```text
IF ID EX MEM WB
```

数据通常到MEM阶段结束才获得。

下一条指令：

```text
IF ID EX MEM WB
```

如果紧跟LOAD，下一条到EX时，LOAD的数据还未及时产生。

所以典型情况下需要插入一个气泡：

```text
lw
bne
```

在分支比较发生于EX、支持对应转发的经典五级流水线模型中：

$$
\boxed{\text{需要1周期停顿}}
$$

但如果分支在ID阶段完成比较，或者题目给出其他数据通路，停顿周期可能不同。

不能把“load-use必定停1周期”理解为所有CPU的普遍规律。


## 二十九、综合题统一解题方法

<Callout type="idea" title="指令题七步法">

先拆机器码，再确定寻址与数据类型，最后逐条更新寄存器、主存、标志位和 PC，并检查地址与位移范围。

</Callout>


以后遇到任何陌生的指令系统综合题，建议使用以下七步法。

<Steps>
<Step>
#### 第一步：明确机器基本信息

列出：

```text
机器字长
指令字长
按字节还是按字编址
地址线宽度
数据线宽度
寄存器编号位数
数据大小端
```

必要时计算：

$$
N_{\text{reg}}=2^{r}
$$

$$
Capacity=2^{MAR位数}\times编址单位
$$


</Step>
<Step>
#### 第二步：按位段切分机器码

例如：

```text
16位机器码：
0000 0010 1001 0001
```

按照题目字段：

```text
0000 | 0010 | 1001 | 0001
```

逐段解释。

千万不要在没有拆分位段前猜测指令功能。


</Step>
<Step>
#### 第三步：确定每个操作数的寻址方式

分别写出：

- 源操作数；
- 目的操作数；
- 立即数；
- 有效地址。

例如：

```asm
ADD (R4), (R5)+
```

必须分别计算：

$$
Operand_s=M[(R4)]
$$

$$
Operand_d=M[(R5)]
$$

而不是直接把R4、R5内容相加。


</Step>
<Step>
#### 第四步：确定立即数和位移的解释方式

必须检查：

- 有符号还是无符号；
- 补码位数；
- 符号扩展还是零扩展；
- 是否需要乘2或乘4；
- 是否存在地址对齐要求。


</Step>
<Step>
#### 第五步：计算指令执行结果

注意：

- 完整数学结果；
- 寄存器实际保留的低位；
- CF；
- OF；
- ZF；
- SF。

这些不是同一个概念。


</Step>
<Step>
#### 第六步：跟踪状态变化

建议制作表格：

| 指令 | 源操作数 | 目的操作数 | EA | 写回 | 标志位 |
|---|---|---|---|---|---|
| LOAD | 内存 | 寄存器 | 已计算 | 寄存器 | 依ISA |
| ADD | 寄存器 | 寄存器 | 无 | 寄存器 | 依ISA |
| STORE | 寄存器 | 内存 | 已计算 | 主存 | 依ISA |
| BRANCH | 标志或寄存器 | PC | 目标地址 | PC | 依ISA |

对于栈操作，还要记录：

```text
SP
BP
栈顶内容
返回地址
```


</Step>
<Step>
#### 第七步：验证结果

可以检查：

1. 机器码位数是否正确；
2. 十六进制与二进制转换是否正确；
3. 有效地址是否在允许范围；
4. 位移能否由对应字段表示；
5. 数据是否满足对齐；
6. 写回位置是否正确；
7. 计算结果是否发生溢出；
8. PC是否指向正确地址；
9. 函数能否正确返回。


</Step>
</Steps>

## 三十二、考前必须掌握的核心公式

### 32.1 寄存器编号

若编号字段为 $r$ 位：

$$
\boxed{N_{\text{reg}}=2^r}
$$

反过来：

$$
\boxed{
r=\lceil\log_2 N_{\text{reg}}\rceil
}
$$


### 32.2 操作码位数

定长指令：

$$
\boxed{
OP位数=L-\sum\text{其他字段位数}
}
$$


### 32.3 扩展操作码

下一层候选容量：

$$
\boxed{
C_{\text{next}}=r_{\text{current}}\times2^a
}
$$

其中：

- $r_{\text{current}}$：剩余前缀数；
- $a$：释放出的字段位数。


### 32.4 有符号位移范围

$$
\boxed{
-2^{n-1}\le offset\le2^{n-1}-1
}
$$


### 32.5 直接寻址

$$
\boxed{EA=A}
$$


### 32.6 存储器间接寻址

$$
\boxed{EA=M[A]}
$$


### 32.7 寄存器间接寻址

$$
\boxed{EA=(R)}
$$


### 32.8 基址寻址

$$
\boxed{EA=(BR)+A}
$$


### 32.9 变址寻址

$$
\boxed{EA=A+(IX)}
$$


### 32.10 基址比例变址

$$
\boxed{
EA=Base+Index\times Scale+Displacement
}
$$


### 32.11 PC相对寻址

$$
\boxed{
Target=PC_{\text{base}}+\operatorname{SExt}(offset)\times s
}
$$


### 32.12 反求位移

$$
\boxed{
offset=\frac{Target-PC_{\text{base}}}{s}
}
$$


### 32.13 一维数组地址

$$
\boxed{
EA=Base+i\times Size
}
$$


### 32.14 二维数组行优先地址

$$
\boxed{
EA=Base+(i\times N+j)\times Size
}
$$

其中 $N$ 为列数。


### 32.15 对齐填充

$$
\boxed{
Padding=(K-(p\bmod K))\bmod K
}
$$


### 32.16 结构体大小

$$
\boxed{
Size=\left\lceil\frac{p_{end}}{A}\right\rceil A
}
$$


### 32.17 页号

页面大小为 $2^k$ Byte：

$$
\boxed{
VPN=\left\lfloor\frac{VA}{2^k}\right\rfloor
}
$$

页内偏移：

$$
\boxed{
Offset=VA\bmod2^k
}
$$


### 32.18 平均CPI

$$
\boxed{
CPI=\frac{\text{总时钟周期数}}{\text{总指令数}}
}
$$


### 32.19 MIPS

$$
\boxed{
MIPS=\frac{f}{CPI\times10^6}
}
$$


### 32.20 执行时间

$$
\boxed{
T=\frac{IC\times CPI}{f}
}
$$

其中：

- $IC$：动态执行的指令数；
- $f$：时钟频率。

## 三十五、考前最后记忆：20个核心结论

1. **ISA规定软件可见的机器行为，微架构规定内部实现。**

2. **指令字段中的数字不一定是主存地址，也可能是寄存器编号、立即数或位移。**

3. **扩展操作码必须满足唯一译码约束，已经使用的短操作码不能继续作为长码前缀。**

4. **扩展操作码计算要逐级扣除、逐级扩展，不允许直接把所有编码数量相加。**

5. **立即寻址取的是指令中的数据，直接寻址取的是某地址中的内存内容。**

6. **寄存器直接寻址取寄存器的值，寄存器间接寻址取该寄存器指向的内存内容。**

7. **有效地址EA与操作数Operand是两个不同概念。**

8. **基址寻址与变址寻址计算公式类似，但经典用途不同。**

9. **数组寻址必须把元素下标转换为字节偏移。**

10. **先变址后间址是先相加再访存，运算顺序不能交换。**

11. **PC相对寻址必须明确PC基准、位移符号、位移单位与指令长度。**

12. **MIPS风格分支常采用PC+4与有符号字偏移，不能直接套用x86位移公式。**

13. **指令逻辑编码与内存中字节排列是两个问题。**

14. **大端高位字节放低地址，小端低位字节放低地址。**

15. **数据对齐决定存放起点，大小端决定多字节数据内部的排列。**

16. **CF主要用于无符号进位/借位，OF用于有符号溢出。**

17. **CMP设置标志但不保存减法结果；signed比较要结合SF和OF。**

18. **CALL保存返回地址并转入函数，RET恢复返回控制流，不能把函数入口当成返回地址。**

19. **机器寄存器保留低位结果，不代表数学结果一定没有溢出。**

20. **面对陌生综合题，始终按照“位段解码→寻址→取数→运算→写回→状态变化”的顺序分析。**
