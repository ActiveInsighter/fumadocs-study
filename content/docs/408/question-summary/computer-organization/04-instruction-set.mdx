### 易错前提

<Callout type="warn" title="指令系统题先确认‘以哪一种机器为准’">

同名指令在不同 ISA 中的操作数格式、位移单位、标志位语义和栈行为可能不同。`PC + offset` 里的 PC 可能是**下一条指令的地址**，也可能遵循另一定义；偏移还可能按字节或按指令字计数。题设未明确时不要机械套用 x86 或 RISC-V 规则。

</Callout>

### 关键概念对照

<Tabs items={["寻址与访存", "PC 相对", "扩展操作码", "对齐与大小端"]} defaultIndex={0}>

<Tab value="寻址与访存">

**直接**寻址通常 $EA=A$、操作数为 $M[EA]$；**存储器间接**寻址先查 $M[A]$ 得到 $EA$，再取 $M[EA]$；**寄存器间接**寻址以寄存器内容作为有效地址。数访存次数时，按题设区分**取指**与**取操作数**，也要区分 Cache/主存。

</Tab>

<Tab value="PC 相对">

一般形式：

$$
Target=PC_{\mathrm{base}}+\operatorname{SExt}(offset)\times u.
$$

其中 $PC_{\mathrm{base}}$ 由 ISA 指定，$u$ 为位移单位（例如字节或半字），并非总是 1。

</Tab>

<Tab value="扩展操作码">

扩展操作码分配应保证编码**无前缀冲突**；较短格式使用的操作码前缀不能又被分配给较长格式。先扣除已占用的前缀，再计算可扩展的编码个数，而不是把所有字段组合直接相加。

</Tab>

<Tab value="对齐与大小端">

对齐决定一个对象的起始地址和填充，大小端决定**同一多字节对象**在各地址上的字节顺序。大端：最高有效字节放低地址；小端：最低有效字节放低地址。结构体总大小还可能有末尾填充。

</Tab>

</Tabs>

## 二、指令系统与 ISA：理解 CPU 怎样执行程序

### 2.1 机器指令到底是什么？

CPU 本身不能直接执行 C 语言语句。

例如：

```text
c = a + b;
```

假设变量已经分别存放在寄存器中，一种可能的机器级操作为：

```asm
add r3, r1, r2
```

含义是：

$$
R[3]\leftarrow R[1]+R[2]
$$

其中：

- `add`：操作类型。
- `r1`：第一个源操作数所在寄存器。
- `r2`：第二个源操作数所在寄存器。
- `r3`：计算结果写入的寄存器。

机器码实际上由一串二进制字段组成，这些字段规定 CPU 应执行什么操作，以及如何找到操作数。

因此，一条机器指令本质上就是对 CPU 发出的、经过编码的操作命令。

#### CPU 执行指令的基本过程

```text
PC 给出指令地址
       ↓
从指令存储器取出指令
       ↓
IR 保存当前指令
       ↓
译码器分析操作码
       ↓
确定源操作数的位置
       ↓
从寄存器或存储器取数
       ↓
ALU 或其他功能部件执行
       ↓
写回结果、更新相关状态
       ↓
确定下一条指令的 PC
```

这只是逻辑上的执行过程。实际 CPU 可能采用流水线、乱序执行等技术，不一定严格串行完成这些操作。

理解这条过程很重要，因为本章的各种寻址方式、指令格式和控制转移，实际上都在回答这个过程中的某一个问题。

### 2.2 ISA 是什么？

ISA（Instruction Set Architecture）称为指令集体系结构。

它是软件与处理器硬件之间的约定。

ISA 主要规定：

1. 支持哪些机器指令，以及每条指令的功能。
2. 指令格式、操作码和编码规则。
3. 程序员可见寄存器的数量、编号和宽度。
4. 支持的数据类型及运算语义。
5. 寻址方式和存储器访问规则。
6. 控制转移、异常和特权机制等体系结构行为。

例如，一个 ISA 规定：

```asm
共有 32 个通用寄存器
每个寄存器宽 32 位
ADD 指令执行整数加法
LW 指令从内存中读取数据
SW 指令把数据写入内存
```

那么实现该 ISA 的处理器必须遵循这些对软件可见的规则。

但是，ISA 通常不规定该 CPU 必须采用几级流水线、几个 ALU 或多大的 Cache。

#### ISA 与微架构的区别

| ISA（做什么）     | 微架构（怎样实现）     |
| ------------ | ------------- |
| 指令的操作语义      | ALU 的具体内部电路   |
| 指令格式和编码      | 指令译码器的内部实现    |
| 通用寄存器数量及宽度   | 物理寄存器数量和重命名机制 |
| 软件可见的地址与异常规则 | Cache 容量和组织方式 |
| 条件转移指令语义     | 分支预测算法        |
| 软件可见的状态变化    | 流水线深度、乱序调度    |

判断诀窍：改变这个设计后，原有机器语言程序是否还能按照同样的体系结构规则执行？

如果会改变程序看到的机器接口，通常属于 ISA；如果只是改变内部实现和性能，通常属于微架构。

#### 2022 年 408 真题

下列属于 ISA 规定的内容的是：

Ⅰ. 指令字格式和指令类型

Ⅱ. CPU 时钟周期

Ⅲ. 通用寄存器的个数和位数

Ⅳ. 加法器的进位方式

答案：Ⅰ、Ⅲ。

分析：

- Ⅰ 正确。机器指令必须按照 ISA 规定的格式译码。
- Ⅱ 错误。时钟周期属于具体处理器实现。
- Ⅲ 正确。寄存器属于程序员可见资源。
- Ⅳ 错误。串行进位、超前进位等通常是算术电路的实现细节。

由此可知：

$$
\boxed{\text{ISA 相同}\not\Rightarrow\text{CPU 性能相同}}
$$

## 三、指令的基本格式

### 3.1 一条指令有哪些字段？

最简单的抽象格式：

```text
┌───────────┬─────────────────┐
│  操作码 OP │  操作数/地址字段  │
└───────────┴─────────────────┘
```

操作码告诉 CPU 干什么。

操作数或地址字段告诉 CPU 对谁进行操作。

但必须注意：

> 地址字段中的二进制数不一定表示内存地址，也可能是寄存器编号、立即数或相对位移。

例如：

```asm
mov r1, 5
```

`5` 是操作数本身。

```asm
mov r1, [1000]
```

`1000` 是内存地址。

```asm
mov r1, [r2]
```

`r2` 是寄存器编号，寄存器内容才是内存地址。

这三种情况必须严格区分。

### 3.2 零地址、一地址、二地址、三地址指令

假设执行：

$$
C=A+B
$$

不同类型的机器可以采用不同指令格式。

| 类型  | 例子          | 结果保存位置    |
| --- | ----------- | --------- |
| 三地址 | `ADD C,A,B` | 单独指定 C    |
| 二地址 | `ADD A,B`   | 通常覆盖 A    |
| 一地址 | `ADD A`     | 使用隐含累加器   |
| 零地址 | `ADD`       | 使用隐含栈顶操作数 |

这里的地址数量指显式操作数字段的数量，不代表必然要进行相同次数的主存访问。

#### 三地址指令

```asm
ADD R3, R1, R2
```

$$
R[3]\leftarrow R[1]+R[2]
$$

两个源操作数和结果位置可以独立指定。

优点：灵活，不必覆盖源操作数。

缺点：需要较多寄存器编号字段。

#### 二地址指令

假设约定：

```asm
ADD R1, R2
```

则：

$$
R[1]\leftarrow R[1]+R[2]
$$

结果覆盖第一个操作数所在寄存器。

不同汇编语法的源、目的顺序可能不同，考试必须服从题设。

#### 一地址指令

假设机器有累加器 ACC：

```asm
LOAD A
ADD B
STORE C
```

则：

$$
ACC\leftarrow A
$$

$$
ACC\leftarrow ACC+B
$$

$$
C\leftarrow ACC
$$

这里 `ADD B` 虽然只有一个显式地址，但实际上参与运算的是两个操作数，其中一个隐含为 ACC。

#### 零地址指令

经典栈式机器可能使用：

```asm
PUSH A
PUSH B
ADD
POP C
```

执行 `ADD` 时，从栈顶取出两个操作数，计算后将结果重新压栈。

因此 `ADD` 不需要显式指定操作数地址。

#### 考试关键结论

地址字段越多，在指令总长度固定时，留给操作码的空间通常越少。

若：

- 指令字长为 $L$ 位；
- 每个地址字段占 $a$ 位；
- 共使用 $k$ 个同宽地址字段；

则操作码位数为：

$$
\boxed{OP=L-ka}
$$

在没有其他固定控制字段、也不考虑扩展编码限制的情况下，这一级格式的操作码组合数为：

$$
N=2^{L-ka}
$$

### 3.3 定长指令字与变长指令字

定长指令字：每条指令长度相同。

例如都是 32 位：

```text
指令 1：32 bit
指令 2：32 bit
指令 3：32 bit
```

其优点是取指、识别指令边界和译码比较容易。

变长指令字：不同指令长度可以不同。

例如：

```asm
PUSH EBP        1 Byte
CMP ...         3 Byte
CALL ...        5 Byte
```

其优点是编码灵活，某些操作可以用更短的指令表示；但确定指令边界、取指和译码通常更复杂。

必须区分两个概念：

- 指令字长：整条指令占多少位。
- 操作码长度：用于表示操作类型的字段占多少位。

因此，定长指令字完全可以使用变长操作码。

典型技术就是下一节的扩展操作码。

## 四、扩展操作码：必须彻底掌握的计算题

### 4.1 为什么需要扩展操作码？

假设机器指令长 16 位，每个地址字段占 4 位。

三地址指令：

```text
┌────┬────┬────┬────┐
│ OP │ A1 │ A2 │ A3 │
│4位 │4位 │4位 │4位 │
└────┴────┴────┴────┘
```

操作码只有：

$$
16-3\times4=4\text{ 位}
$$

最多区分：

$$
2^4=16
$$

种三地址指令。

但是，如果某些指令只需要两个地址，那么空出来的 4 位为什么不能用来表示更多操作呢？

这正是扩展操作码的设计思想。

让地址字段较少的指令使用较长的操作码。

例如：

```text
三地址：
[ OP(4) ][ A1(4) ][ A2(4) ][ A3(4) ]

二地址：
[   OP(8)   ][ A1(4) ][ A2(4) ]

一地址：
[       OP(12)       ][ A1(4) ]

零地址：
[            OP(16)            ]
```

这里整条指令始终为 16 位，只是操作码所占比例不同。

### 4.2 扩展操作码为什么不能随便编码？

假设：

```text
0000
```

已经是一条完整的三地址指令操作码。

那么就不能再使用：

```text
0000 0001
0000 0010
```

表示二地址指令。

因为处理器看到前面的 `0000` 时，无法按照原有编码规则唯一判断它属于哪种格式。

所以扩展操作码必须遵守前缀无冲突原则：

> 已经分配给某条完整指令的操作码，不能同时充当另一条更长操作码的前缀。

它本质上类似一棵前缀编码树：上层保留了某条指令，就不能再把它下方的编码空间分配给其他格式。

**扩展操作码的先占用、再延长原则**

把一个长度为 $m$ 位的操作码视为前缀。若它已分配给某一格式，任何以该前缀开头的更长编码都不能另作他用；若该前缀保留用于扩展，再乘以新释放字段的全部编码数。最短指令字长问题要**从较短字长尝试并证明不足**，不要只给一个可行字长。

### 4.3 通用计算方法

设基本操作码有 $m$ 位，每个地址字段有 $a$ 位。

已使用 $N_3$ 个三地址操作码，则剩余前缀数为：

$$
r_3=2^m-N_3
$$

每个剩余前缀向下扩展 $a$ 位，可以产生 $2^a$ 种二地址操作码。

因此二地址候选容量：

$$
C_2=r_3 2^a
$$

若已使用 $N_2$ 条二地址指令，则剩余：

$$
r_2=C_2-N_2
$$

继续扩展得到一地址候选容量：

$$
C_1=r_2 2^a
$$

如果使用 $N_1$ 条一地址指令，最多可定义的零地址指令条数为：

$$
\boxed{N_{0,\max}=(C_1-N_1)2^a}
$$

以上以三、二、一、零地址逐级扩展且每级释放同宽字段为前提。遇到其他格式，应按照实际字段宽度逐级计算。

### 4.4 2022 年 408 真题：最多有多少条零地址指令？

题目

某计算机采用 16 位定长指令字，采用扩展操作码，地址字段为 6 位。

已知：

- 二地址指令 12 条；
- 一地址指令 254 条；

<Steps>
<Step>

### 第一步：计算基本操作码位数

二地址指令有两个 6 位地址字段。

$$
m=16-2\times6=4
$$

所以基本操作码最多有：

$$
2^4=16
$$

种组合。

</Step>
<Step>

### 第二步：扣掉二地址操作码

已经使用 12 种：

$$

$$

还剩 4 种前缀。

</Step>
<Step>

### 第三步：扩展为一地址操作码

最多定义 256 条一地址指令。

实际需要 254 条，所以剩余：

$$

$$

个可继续扩展的前缀。

<Step>

### 第四步：计算零地址指令数量

继续借用最后一个 6 位字段：

$$

最终：

$$
\boxed{128\text{ 条}}
$$

这道题真正考查的是编码空间的逐级分配，而不是单纯背公式。

</Step>
</Steps>

位。

## 五、数据寻址方式：本章最核心的内容

这是理解指令系统的关键部分，也是整章最需要反复做题训练的知识点。

### 5.1 先理解三个概念：形式地址、有效地址、操作数

假设一条指令写作：

```asm
LOAD R1, [1000]
```

我们需要区分：

形式地址 $A$：指令地址字段给出的数。

有效地址 $EA$：经过寻址计算后，真正用于访问内存的地址。

操作数 $Operand$：实际参与运算的数据。

用三个符号表示：

$$
A=\text{指令中的地址字段}
$$

$$
EA=\text{有效地址}
$$

$$
M[EA]=\text{有效地址对应的内存内容}
$$

如果是普通的内存操作数：

$$
\boxed{Operand=M[EA]}
$$

但在立即寻址和寄存器直接寻址时，操作数并不是通过内存有效地址取得的。

这就是为什么做题时必须先判断寻址方式。

### 5.2 用同一个例子理解所有常见寻址方式

假设：

$$
A=1000
$$

$$
(R)=2000
$$

内存中：

$$
M[1000]=3000
$$

$$
M[2000]=4000
$$

$$
M[3000]=5000
$$

$$
M[4000]=6000
$$

这里数字均为十进制。

#### ① 立即寻址

操作数直接位于指令中。

例如：

```asm
MOV R1, 1000
```

操作数就是：

$$
\boxed{Operand=1000}
$$

不需要根据这个数再次访问主存。

立即寻址适合常量：

```asm
ADD R1, R1, 1
```

例如循环变量加 1。

易错点：不能把 1000 当成地址，再去读取 $M[1000]$。

#### ② 寄存器直接寻址

操作数就在寄存器中。

```asm
MOV R1, R
```

于是：

$$
Operand=(R)
$$

所以：

$$
\boxed{Operand=2000}
$$

寄存器内容就是数据本身。

不需要额外的数据主存访问。

#### ③ 直接寻址

指令地址字段直接给出内存地址：

$$
EA=A
$$

本例：

$$
EA=1000
$$

操作数：

$$
Operand=M[1000]
$$

所以：

$$
\boxed{Operand=3000}
$$

只需要一次数据访存即可取得操作数。

#### ④ 存储器间接寻址

指令给出的地址并不直接存放真正操作数，而是存放真正操作数的地址。

因此：

$$
EA=M[A]
$$

本例：

$$
EA=M[1000]=3000
$$

然后：

$$
Operand=M[3000]=5000
$$

于是：

$$
\boxed{EA=3000,\quad Operand=5000}
$$

它需要两次数据访存：

```text
形式地址 A=1000
       ↓
访问 M[1000]
       ↓
得到真正地址 3000
       ↓
访问 M[3000]
       ↓
得到操作数 5000
```

这就是所谓的“间接”。

它相当于先找一张纸，纸上写着真正要找的数据存在哪里。

#### ⑤ 寄存器间接寻址

真正的内存地址放在寄存器中。

$$
EA=(R)
$$

本例：

$$
EA=2000
$$

真正操作数：

$$
Operand=M[2000]=4000
$$

所以：

$$
\boxed{Operand=4000}
$$

与寄存器直接寻址不同：

- 寄存器直接寻址：寄存器中保存数据。
- 寄存器间接寻址：寄存器中保存数据的地址。

寄存器间接通常只需一次数据访存，因为读取寄存器本身不属于访问主存。

#### ⑥ 基址寻址

通过基址寄存器与形式地址相加：

$$
\boxed{EA=(BR)+A}
$$

假设：

$$
(BR)=2000,\quad A=1000
$$

则：

$$
EA=3000
$$

操作数：

$$
Operand=M[3000]=5000
$$

基址寻址特别适合访问某个区域中具有固定偏移的数据，例如结构体成员或栈帧中的变量。

#### ⑦ 变址寻址

通过变址寄存器与形式地址相加：

$$
\boxed{EA=(IX)+A}
$$

如果：

$$
(IX)=2000,\quad A=1000
$$

则：

$$
EA=3000
$$

$$
Operand=M[3000]=5000
$$

可以发现，基址寻址和变址寻址的数学形式完全一样。

区别主要在于设计用途与寄存器的角色。

| 比较       | 基址寻址         | 变址寻址    |
| -------- | ------------ | ------- |
| 主要用途     | 重定位、访问某一数据区域 | 数组与循环   |
| 寄存器的典型含义 | 区域起始地址       | 动态下标或偏移 |
| 执行过程中    | 基址常较稳定       | 变址经常变化  |
| 现代处理器    | 可以组合         | 可以组合    |

不能机械地认为“基址寄存器永远不变”或“变址寄存器永远不保存基址”。

### 5.3 寻址方式总表

这里的访存次数只统计获取一个数据操作数时的额外主存访问，不计取指、Cache、地址转换和页表查询等开销。

| 寻址方式  | EA 或操作数              | 典型数据访存次数 |
| ----- | -------------------- | -------- |
| 立即寻址  | $Operand=A$      | 0        |
| 寄存器直接 | $Operand=(R)$    | 0        |
| 直接寻址  | $EA=A$           | 1        |
| 存储器间接 | $EA=M[A]$        | 2        |
| 寄存器间接 | $EA=(R)$         | 1        |
| 基址寻址  | $EA=(BR)+A$      | 1        |
| 变址寻址  | $EA=(IX)+A$      | 1        |
| 基址变址  | $EA=(BR)+(IX)+A$ | 1        |
| 相对寻址  | $EA=(PC)+A$      | 依用途而定    |
| 堆栈寻址  | 由 SP 隐含定位            | 依指令而定    |

特别要注意：

计算有效地址不一定需要读取主存。

例如：

$$
EA=(BR)+A
$$

只需要读取寄存器并进行加法。

只有在需要获取内存操作数时，才会再访问：

$$
M[EA]
$$

另外，若题目问的是 `STORE` 指令，应该区分“读操作数”和“写内存”，不能直接把读取次数表套到所有指令上。

### 5.4 2013 年 408 真题：变址寻址与操作数

已知：

$$
(R)=1000H
$$

指令形式地址：

$$
A=2000H
$$

内存内容为：

$$
M[1000H]=2000H
$$

$$
M[2000H]=3000H
$$

$$
M[3000H]=4000H
$$

问变址寻址访问到的操作数。

第一步：识别变址寻址。

$$
EA=(R)+A
$$

第二步：计算 EA。

$$
EA=1000H+2000H=3000H
$$

第三步：取内存内容。

$$
Operand=M[3000H]=4000H
$$

因此：

$$
\boxed{4000H}
$$

这里 $M[1000H]$ 与 $M[2000H]$ 的内容都不参与本次变址地址计算。

很多同学会沿着内存内容反复查找，最终错把变址寻址做成间接寻址。

### 5.5 2016 年 408 真题：先变址后间址

这种题专门考查寻址操作的顺序。

设：

- 形式地址为 $D$；
- 变址寄存器为 $I$；
- $M[x]$ 表示内存地址 $x$ 中保存的数据。

题目规定先变址、后间址。

#### 第一步：先变址

$$
T=(I)+D
$$

此时 $T$ 只是一个中间地址。

#### 第二步：再间址

$$
EA=M[T]
$$

合并：

$$
\boxed{EA=M[(I)+D]}
$$

如果题目反过来说先间址后变址，可能得到：

$$
EA=M[D]+(I)
$$

具体仍应以指令集定义为准。

关键在于两个操作的先后顺序。

地址运算和内存取值不是可以随意交换顺序的操作。

### 5.6 自增、自减寻址

这个知识点在综合大题中特别容易丢分。

典型形式：

```text
(Rn)+
```

它通常表示先使用寄存器间接寻址，再增加寄存器内容。

若按字编址，每次访问一个字：

$$
EA=(R_n)_{\text{old}}
$$

随后：

$$
(R_n)_{\text{new}}=(R_n)_{\text{old}}+1
$$

而：

```text
-(Rn)
```

通常表示先减小寄存器，再访问新的地址。

如果机器按字节编址且操作数长 4 字节，自增量常为 4，而不是 1。

#### 2010 年 408 综合题

这道题给了一台 16 位计算机，采用单字长指令：

| 位段 | 15～12 | 11～9 | 8～6 | 5～3 | 2～0 |
| -- | ----- | ---- | --- | --- | --- |
| 字段 | OP    | Ms   | Rs  | Md  | Rd  |

其中：

- OP：操作码；
- Ms：源寻址方式；
- Rs：源寄存器号；
- Md：目的寻址方式；
- Rd：目的寄存器号。

题目规定：

```text
OP = 0010：ADD
001：寄存器间接
010：寄存器间接、自增
```

执行：

```asm
add (R4), (R5)+
```

逗号前为源，逗号后为目的。

已知：

$$
(R4)=1234H
$$

$$
(R5)=5678H
$$

$$
M[1234H]=5678H
$$

$$
M[5678H]=1234H
$$

#### 问题一：机器码是什么？

逐字段编码：

```text
OP = 0010
Ms = 001
Rs = 100
Md = 010
Rd = 101
```

拼接：

```text
0010 001 100 010 101
```

整理成 16 位：

```text
0010 0011 0001 0101
```

对应：

$$
\boxed{2315H}
$$

#### 问题二：执行后哪些数据改变？

源操作数：

$$
M[(R4)]=M[1234H]=5678H
$$

目的操作数原值：

$$
M[(R5)]=M[5678H]=1234H
$$

执行加法：

$$
5678H+1234H=68ACH
$$

结果写回原目的地址：

$$
\boxed{M[5678H]=68ACH}
$$

由于目的采用自增寻址：

$$
(R5)\leftarrow(R5)+1
$$

因此：

$$
\boxed{R5=5679H}
$$

R4 不变。

这道题要记住两个原则：

第一，源操作数和目的操作数必须分别计算。

第二，自增寻址修改的是地址寄存器，不能误认为计算结果写到自增后的新地址。

## 六、指令寻址与 PC 相对寻址

### 6.1 指令寻址和数据寻址有什么区别？

数据寻址解决：

> 本条指令需要的数据在哪里？

指令寻址解决：

> CPU 下一步应从哪里取指令？

通常由程序计数器 PC 保存下一条需要取出的指令地址。

在不改变控制流时，指令按顺序执行。

例如：

```text
1000H：第一条指令，占 4B
1004H：第二条指令，占 4B
1008H：第三条指令，占 4B
```

如果从 1000H 取出长度为 4B 的指令，顺序下一条地址是：

$$
PC_{\text{next}}=1000H+4=1004H
$$

但是遇到 `JMP`、条件转移、`CALL`、`RET` 等指令，下一条执行地址就可能发生变化。

**PC 相对寻址的基准和位移单位都由 ISA 定义**

以常见的“下一条顺序指令地址”为基准时：$Target=PC_{next}+\operatorname{SExt}(offset)\times u$；其中 $u$ 不一定是 1 字节，分支偏移也可能有隐含低位零。负位移应按字段位宽先作符号扩展，再计算目标地址。

### 6.2 PC 相对寻址的本质

相对寻址不在指令中保存完整目标地址，而是保存相对于某个基准地址的位移量。

常见形式：

$$
\boxed{Target=PC_{\text{base}}+Offset}
$$

其中基准地址取什么，必须由 ISA 或题目定义。

在很多考试题和 x86 相对转移中：

$$
PC_{\text{base}}=PC_{\text{next}}
$$

于是：

$$
\boxed{Target=PC_{\text{next}}+Offset}
$$

如果位移量以字、半字或指令长度为单位：

$$
\boxed{Target=PC_{\text{base}}+Offset\times s}
$$

其中 $s$ 是比例因子。

例如，位移字段数值为 5，但规定单位为 2 字节，实际向前位移就是：

$$
5\times2=10B
$$

#### 为什么要使用相对寻址？

假设程序原本装入内存地址 `1000H`，某个跳转目标位于 `1100H`。

两者距离：

$$
1100H-1000H=100H
$$

如果整个程序移动到其他内存区域，但两条指令间的相对距离不变，那么原来的位移编码可能继续有效。

因此 PC 相对寻址有利于程序重定位和位置无关代码，也经常能节省地址字段位数。

### 6.3 2009 年 408 真题：最基础的相对寻址

题目给出：

- 指令位于 `2000H`；
- 指令长度为 2 字节；
- 相对位移为 `06H`；
- 取指时 PC 每读取一个字节自动加 1。

问成功转移后的地址。

取指完毕：

$$
PC_{\text{next}}=2000H+2=2002H
$$

再加偏移：

$$
Target=2002H+06H
$$

得到：

$$
\boxed{2008H}
$$

这个题看起来非常简单，但它对应了最常见的陷阱：

错误地直接计算：

$$
2000H+06H=2006H
$$

问题在于忽略了取指过程中 PC 已经变化。

### 6.4 负位移：补码必须先转换

假设：

```text
指令首地址：1000H
指令长度：4B
位移字段：FFF8H
位移宽度：16 位补码
位移单位：1B
```

问跳转地址。

首先：

$$
FFF8H
$$

是 16 位负数补码。

其真值：

$$
-8
$$

下一条顺序地址：

$$
PC_{\text{next}}=1000H+4=1004H
$$

因此：

$$
Target=1004H-8
$$

得到：

$$
\boxed{0FFCH}
$$

注意，如果位移宽度只有 8 位，`F8H` 同样表示 $-8$；但若题目将它定义为无符号数，则其数值是 248。

所以不能只根据十六进制外观判断正负。

### 6.5 2013 年 408 大题：PC 相对转移与条件标志

这道题非常有代表性，因为它同时考查：

- PC；
- 指令长度；
- 补码位移；
- 条件转移逻辑；
- 指令地址范围。

题目给定一条 16 位条件转移指令：

```text
┌────────┬───┬───┬───┬────────┐
│ 00000  │ C │ Z │ N │ OFFSET │
│  5位   │1位│1位│1位│   8位  │
└────────┴───┴───┴───┴────────┘
```

其中：

- C：是否检查 CF；
- Z：是否检查 ZF；
- N：是否检查 NF；
- OFFSET：8 位有符号补码偏移。

规定只要被选中检查的某个标志位为 1，就发生转移。

目标地址公式：

$$
PC'=PC+2+2\times OFFSET
$$

#### 问题一：为什么能够判断按字节编址？

指令长 16 位，即 2 字节。

顺序执行时 PC 增加 2。

说明连续两条指令的地址相差两个地址单位，对应 2 字节。

因此属于按字节编址。

#### 问题二：最多能向后跳多远？

OFFSET 为 8 位补码：

$$
-128\le OFFSET\le127
$$

最大负位移：

$$
OFFSET=-128
$$

代入：

$$
PC'=PC+2+2(-128)
$$

得到：

$$
PC'=PC-254
$$

每条指令 2 字节，所以目标位于当前指令之前第：

$$
\frac{254}{2}=127
$$

条指令的位置。

因此：

$$
\boxed{\text{最多跳到当前指令之前第127条指令}}
$$

这里之所以不是 128，是因为偏移从下一条顺序指令地址开始计算。

#### 问题三：给定标志位，计算转移目标

假设：

```text
指令地址：200CH

C = 0
Z = 1
N = 1

OFFSET = 11100011B
```

8 位补码：

$$
11100011_2=E3H
$$

其真值为：

$$
227-256=-29
$$

若：

```text
CF = 0
ZF = 0
NF = 1
```

由于 N 检测位为 1，且 NF=1，满足跳转条件。

于是：

$$
PC'=200CH+2+2(-29)
$$

$$
PC'=200EH-3AH
$$

最终：

$$
\boxed{PC'=1FD4H}
$$

但若：

```text
CF = 1
ZF = 0
NF = 0
```

虽然 CF=1，但 C 检测位为 0，因此 CF 不参与判断。

被检测的 ZF、NF 都等于 0。

所以不转移：

$$
\boxed{PC'=200EH}
$$

#### 最值得记住的思维方式

转移指令一定分成两个独立问题：

1. 是否转移？ 由条件码和标志位决定。
2. 转移到哪里？ 由基准 PC、位移及单位决定。

不能把这两个问题混在一起。

## 七、边界对齐与大小端

这一部分看似属于数据存储问题，但实际经常与指令寻址、数组和汇编代码共同出题。

### 7.1 数据为什么需要对齐？

假设一个 `int` 占 4 字节。

如果要求按 4 字节边界对齐，则它的起始地址应满足：

$$
\boxed{Address\bmod4=0}
$$

例如：

```text
0x1000  可以
0x1004  可以
0x1008  可以

0x1001  不满足4B对齐
0x1002  不满足4B对齐
```

对齐有利于 CPU 高效读取数据。

某些处理器访问未对齐数据可能需要多次访存，甚至直接触发异常。

但是：

没有对齐不等于所有 CPU 都无法访问。

实际行为由 ISA 和具体内存系统决定。

### 7.2 结构体为什么会出现填充字节？

看下面的 C 语言结构体：

```c
struct S {
    char c;
    int x;
    short y;
};
```

假设：

- `char` 大小及对齐均为 1B；
- `int` 大小及对齐均为 4B；
- `short` 大小及对齐均为 2B；
- 结构体整体按 4B 对齐。

我们逐个放置成员。

<Steps>
<Step>

### 第一步：放 char

从偏移 0 开始，占 1 字节。

```text
offset 0：c
```

</Step>
<Step>

### 第二步：放 int

此时下一个空闲位置为偏移 1。

但 `int` 要求 4B 对齐，所以必须从偏移 4 开始。

因此偏移 1～3 都是填充字节。

```text
offset 0：c
offset 1：padding
offset 2：padding
offset 3：padding
offset 4~7：x
```

</Step>
<Step>

### 第三步：放 short

`int` 到偏移 7 结束，接下来是偏移 8。

8 能被 2 整除，满足 `short` 对齐要求。

因此：

```text
offset 8~9：y
```

</Step>
<Step>

### 第四步：计算整个结构体长度

虽然实际成员结束于偏移 9，但结构体整体按 4 字节对齐。

因此尾部需要补两个字节：

```text
offset 10~11：padding
```

最终布局：

| 偏移    | 内容   |
| ----- | ---- |
| 0     | c    |
| 1～3   | 填充   |
| 4～7   | x    |
| 8～9   | y    |
| 10～11 | 尾部填充 |

总长度：

$$
\boxed{sizeof(S)=12B}
$$

而不是：

$$
1+4+2=7B
$$

</Step>
</Steps>
#### 通用填充公式

若当前位置是 $p$，下一成员要求 $K$ 字节对齐，则需要的填充字节数为：

$$
\boxed{Padding=(K-(p\bmod K))\bmod K}
$$

它保证对齐时填充 0 字节，不会多加一个完整对齐单位。

### 7.3 大端和小端到底是什么意思？

假设某 32 位整数为：

```text
0x12345678
```

按字节分割：

```text
12 34 56 78
```

这里：

- `12` 是最高有效字节；
- `78` 是最低有效字节。

#### 大端 Big Endian

高位字节放低地址。

| 地址    | 内容 |
| ----- | -- |
| 1000H | 12 |
| 1001H | 34 |
| 1002H | 56 |
| 1003H | 78 |

#### 小端 Little Endian

低位字节放低地址。

| 地址    | 内容 |
| ----- | -- |
| 1000H | 78 |
| 1001H | 56 |
| 1002H | 34 |
| 1003H | 12 |

记忆：

$$
\boxed{\text{大端：高位字节放低地址}}
$$

$$
\boxed{\text{小端：低位字节放低地址}}
$$

注意是字节顺序，不是把一个字节内部的 8 个二进制位也倒过来。

另外，大小端并不会颠倒数组元素的逻辑排列顺序，而是决定每个多字节元素内部如何存放。

### 7.4 2012 年 408 真题：结构体 + 小端

题目：

```c
struct {
    int a;
    char b;
    short c;
} record;

record.a = 273;
```

条件：

- `record` 首地址 `0xC008`；
- `int` 4B，`short` 2B；
- 小端存储；
- 按自然边界对齐。

求：

1. 地址 `0xC008` 中的内容；
2. 成员 `record.c` 的起始地址。

#### 第一步：转换整数

$$
273=0x111
$$

32 位表示：

```text
00 00 01 11
```

小端存储：

```text
11 01 00 00
```

因此：

$$
\boxed{M[0xC008]=0x11}
$$

#### 第二步：计算结构体布局

`a` 占 4 字节：

```text
C008 ~ C00B：a
```

`b` 占 1 字节：

```text
C00C：b
```

`short c` 要求 2 字节对齐。

`C00D` 不满足对齐要求，需要填充。

因此：

```text
C00D：Padding
C00E ~ C00F：c
```

最终：

$$
\boxed{\operatorname{addr}(record.c)=0xC00E}
$$

答案：0x11，0xC00E。

这道题应该形成固定解题顺序：

> 先计算布局，再找到成员地址，最后按照大小端读取字节。

不要反过来。

### 7.5 2019 年真题：负位移 + 大端 + LSB 地址

已知：

- 基址寄存器为 `F0000000H`；
- 形式地址为 `FF12H`；
- 形式地址采用 16 位补码；
- 操作数为 32 位；
- 大端存储。

求操作数最低有效字节 LSB 的地址。

<Steps>
<Step>

### 第一步：把形式地址转换为有符号位移

16 位补码：

$$
FF12H=-238
$$

扩展到 32 位：

$$
FFFFFF12H
$$

</Step>
<Step>

### 第二步：计算 EA

$$
EA=F0000000H+FFFFFF12H
$$

按 32 位地址运算：

$$
\boxed{EA=EFFFFF12H}
$$

</Step>
<Step>

### 第三步：处理大端

32 位操作数占 4 字节。

大端存放时：

```text
EA+0：最高有效字节
EA+1：次高字节
EA+2：次低字节
EA+3：最低有效字节
```

因此：

$$
LSBAddress=EA+3
$$

最终：

$$
\boxed{EFFFFF15H}
$$

这题考的不是一个知识点，而是三个：补码符号扩展、基址寻址、字节序。

</Step>
</Steps>
## 八、数组地址计算：机器级代码题的基础

### 8.1 一维数组

假设：

```text
int a[100];
```

每个 `int` 占 4 字节。

数组首地址：

$$
Base=1000H
$$

那么：

$$
\operatorname{addr}(a[i])=Base+4i
$$

例如：

$$
\operatorname{addr}(a[5])=1000H+20
$$

因为：

$$
20_{10}=14H
$$

所以：

$$
\boxed{\operatorname{addr}(a[5])=1014H}
$$

这就是为什么汇编经常使用：

```text
[base + index*4]
```

这里乘 4 是把数组下标换算成字节偏移量。

#### 常见元素大小与移位

若元素大小为 $2^k$ 字节：

$$
i\times2^k=i\ll k
$$

因此：

| 元素大小 | 字节偏移量       |
| ---- | ----------- |
| 1B   | $i$     |
| 2B   | $i\ll1$ |
| 4B   | $i\ll2$ |
| 8B   | $i\ll3$ |

例如：

```text
slli r4, r2, 2
```

表示：

$$
R[4]\leftarrow R[2]\ll2
$$

若 `r2` 保存数组下标，这通常是在计算 4B 元素的字节偏移。

### 8.2 二维数组

C 语言二维数组采用行优先顺序存放。

假设：

```text
int a[24][64];
```

每一行有 64 个元素。

元素 `a[i][j]` 前面共有：

$$
64i+j
$$

个元素。

每个元素占 4 字节，因此：

$$
\boxed{ \operatorname{addr}(a[i][j]) =Base+(64i+j)\times4 }
$$

整理：

$$
\boxed{ \operatorname{addr}(a[i][j]) =Base+256i+4j }
$$

这里：

- $256i$：前面 $i$ 行的总字节数；
- $4j$：本行中前面 $j$ 个元素的总字节数。

于是：

```text
[base + ecx + edx*4]
```

如果已知 `edx=j`，那么 `ecx` 很可能保存：

$$
\boxed{ecx=256i}
$$

而不是直接保存 $i$。

这个区别正是 2023 年综合题的核心。

## 九、常用汇编指令：从机器角度理解程序执行

这一部分是近年 408 综合题的重要基础。

尤其需要掌握：

- 数据传送与运算；
- CMP 与条件跳转；
- CALL 与 RET；
- 数组和指针；
- 寄存器值的变化；
- C 语言与汇编指令的对应。

### 9.1 首先弄清不同汇编语法

x86 常见两种汇编语法。

| 特征     | Intel 语法  | AT&T 语法   |
| ------ | --------- | --------- |
| 操作数顺序  | 目的、源      | 源、目的      |
| 寄存器    | `eax`     | `%eax`    |
| 立即数    | `5`       | `$5`      |
| 内存操作数  | `[ebx+4]` | `4(%ebx)` |
| 32 位操作 | `mov`     | `movl`    |

例如：

```asm
mov eax, ebx
```

在 Intel 语法中：

$$
EAX\leftarrow EBX
$$

而：

```text
movl %eax, %ebx
```

在 AT&T 语法中：

$$
EBX\leftarrow EAX
$$

不能把两种语法的操作数顺序混为一谈。

RISC-V、MIPS 等又有自己的操作数约定，应先看题目给出的指令格式及语义。

### 9.2 MOV 与 LEA 的区别

这两个指令非常值得放在一起理解。

假设：

$$
EBX=1000H
$$

$$
ECX=3
$$

执行：

```asm
mov eax, [ebx + ecx*4]
```

计算有效地址：

$$
EA=1000H+3\times4=100CH
$$

接下来真正读取内存：

$$
EAX\leftarrow M[100CH]
$$

但是：

```asm
lea eax, [ebx + ecx*4]
```

只计算地址：

$$
\boxed{EAX\leftarrow100CH}
$$

不会因为这条 `LEA` 去读取 `M[100CH]`。

因此：

| 指令          | 功能          |
| ----------- | ----------- |
| `MOV` 从内存读取 | 取得 EA 对应的数据 |
| `MOV` 写内存   | 将数据存到 EA    |
| `LEA`       | 计算 EA 本身    |

这与前面讲的“有效地址不等于操作数”完全对应。

### 9.3 ADD、SUB、MUL、IMUL

常见运算：

```asm
add eax, ebx
```

$$
EAX\leftarrow EAX+EBX
$$

```asm
sub eax, ebx
```

$$
EAX\leftarrow EAX-EBX
$$

```text
imul eax, ecx
```

对于常见的 x86 双操作数 `IMUL` 形式，结果写回 EAX，若完整带符号乘积超出目标宽度，则发生有符号溢出。

必须记住：

> 寄存器中的结果通常具有固定宽度，而数学运算结果不一定能在这个宽度内表示。

例如 16 位有符号整数：

$$
32767+1=32768
$$

但 16 位补码最大正数只能表示 32767。

机器的低 16 位结果是：

$$
7FFFH+0001H=8000H
$$

将 `8000H` 作为 16 位补码解释，得到：

$$
-32768
$$

因此有符号溢出。

实际判断不能只看最高位，必须结合运算规则和标志位。

## 十、标志寄存器：CF、OF、ZF、SF

这部分与第 2 章的补码运算紧密相连。

**CF 与 OF 不能混用，不同 ISA 的减法 CF 定义可能相反**

OF 反映有符号算术溢出；加法 CF 常反映最高位进位。对于减法，某些 ISA 的 CF 表示**借位发生**，另一些表示**未借位**（例如某些带进位减法约定），因此解释 `CMP` 或无符号条件转移时必须服从指定架构。标准 C 的有符号整数溢出是未定义行为，不应直接代入硬件补码回绕规则。

### 10.1 四个核心标志位

| 标志 | 名称            | 主要含义       |
| -- | ------------- | ---------- |
| CF | Carry Flag    | 无符号进位或减法借位 |
| OF | Overflow Flag | 有符号运算溢出    |
| ZF | Zero Flag     | 运算结果是否为零   |
| SF | Sign Flag     | 运算结果最高符号位  |

特别注意：

$$
\boxed{CF\ne OF}
$$

它们关注的是两种不同的数值解释。

同一串二进制可以作为无符号数，也可以作为有符号补码。

所以同一次运算可能：

- CF=1，OF=0；
- CF=0，OF=1；
- 两者都为 0；
- 两者都为 1。

#### 例题一：无符号进位但无有符号溢出

8 位运算：

$$
FFH+01H=100H
$$

低 8 位结果：

$$
00H
$$

存在第 9 位进位，因此：

$$
CF=1
$$

如果按 8 位补码解释：

$$
-1+1=0
$$

没有超出表示范围：

$$
OF=0
$$

由于结果为 0：

$$
ZF=1
$$

最终：

$$
\boxed{CF=1,\quad OF=0,\quad ZF=1}
$$

#### 例题二：没有无符号进位，却发生有符号溢出

8 位运算：

$$
7FH+01H=80H
$$

作为无符号数：

$$
127+1=128
$$

没有超出 8 位无符号表示范围，所以：

$$
CF=0
$$

但作为有符号补码：

$$
127+1=128
$$

超过最大正数 127。

因此：

$$
OF=1
$$

结果 `80H` 最高位为 1：

$$
SF=1
$$

最终：

$$
\boxed{CF=0,\quad OF=1,\quad SF=1}
$$

### 10.2 CMP 到底做了什么？

在 x86 Intel 语法中：

```asm
cmp eax, ebx
```

相当于计算：

$$
EAX-EBX
$$

但不将差值写回 EAX。

它只根据减法结果设置条件标志。

随后，条件转移指令根据这些标志决定是否跳转。

例如：

```asm
cmp eax, ebx
jl less
```

其含义是：

> 若 EAX 在有符号比较下小于 EBX，就跳转到 less。

为什么不能只判断 SF？

因为有符号减法可能溢出，此时结果最高位不能正确反映数学差值的符号。

所以有符号严格小于的判断需要：

$$
\boxed{SF\oplus OF=1}
$$

即 SF 与 OF 不同。

### 10.3 条件转移指令总表

以下针对 x86 的 `CMP a,b`（计算 $a-b$）语义。

| 指令      | 条件      | 标志位判定                   |
| ------- | ------- | ----------------------- |
| JE/JZ   | 相等      | $ZF=1$              |
| JNE/JNZ | 不相等     | $ZF=0$              |
| JL      | 有符号小于   | $SF\ne OF$          |
| JLE     | 有符号小于等于 | $ZF=1\lor SF\ne OF$ |
| JG      | 有符号大于   | $ZF=0\land SF=OF$   |
| JGE     | 有符号大于等于 | $SF=OF$             |
| JB      | 无符号小于   | $CF=1$              |
| JBE     | 无符号小于等于 | $CF=1\lor ZF=1$     |
| JA      | 无符号大于   | $CF=0\land ZF=0$    |
| JAE     | 无符号大于等于 | $CF=0$              |

这里最容易混淆的是：

有符号比较主要结合 SF、OF、ZF，无符号比较主要结合 CF、ZF。

#### 模拟例题：相同位模式，不同比较结果

8 位寄存器：

```text
AL = 7FH
BL = FFH
```

执行：

```asm
cmp al, bl
```

按无符号解释：

$$
127<255
$$

所以无符号 `JB` 条件成立。

按有符号解释：

$$
127>-1
$$

所以有符号 `JL` 条件不成立。

为什么？

减法结果：

$$
7FH-FFH=80H
$$

此时：

$$
CF=1,\quad SF=1,\quad OF=1
$$

对于无符号小于：

$$
CF=1
$$

成立。

对于有符号小于：

$$
SF\oplus OF=1\oplus1=0
$$

不成立。

这就是为什么同一条 `CMP` 后可以根据变量类型选择不同的条件跳转。

## 十一、函数调用、堆栈与 CALL/RET

### 11.1 CALL 为什么不等于 JMP？

`JMP` 的主要作用是修改程序执行位置。

而 `CALL` 除了转移到函数入口，还必须让程序能够在函数执行完后返回调用处。

因此典型 `CALL` 至少涉及两个动作：

1. 保存返回地址。
2. 修改 PC，跳转到被调用函数。

返回地址通常是：

$$
\boxed{\text{CALL 指令结束后的下一条指令地址}}
$$

而不是被调用函数的入口地址。

`RET` 则根据保存的返回地址恢复程序执行位置。

### 11.2 通过栈理解函数调用

以经典 32 位 x86 栈帧为例，假设栈向低地址增长。

某函数：

```c
int add(int a, int b) {
    int c = a + b;
    return c;
}
```

一种可能的调用布局为：

```text
高地址
┌─────────────────────┐
│ 第二个参数 b         │  EBP+12
├─────────────────────┤
│ 第一个参数 a         │  EBP+8
├─────────────────────┤
│ 返回地址             │  EBP+4
├─────────────────────┤
│ 调用者保存的 EBP     │  EBP
├─────────────────────┤
│ 局部变量 c           │  EBP-4
└─────────────────────┘
低地址
```

因此经常会看到：

```asm
mov eax, [ebp+8]
```

读取第一个参数。

```asm
add eax, [ebp+12]
```

加上第二个参数。

```asm
mov [ebp-4], eax
```

保存局部变量。

```asm
ret
```

返回调用处。

这里采用的是一种传统 32 位 x86 调用约定。不同 ABI、优化方式和 64 位调用约定，参数与局部变量的位置可能不同。

### 11.3 SP 和 EBP 有什么区别？

SP/ESP/RSP：栈指针，通常指向当前栈顶。

BP/EBP/RBP：传统栈帧指针，为函数参数、局部变量提供相对稳定的地址基准。

因此：

- SP 通常会随着 `PUSH`、`POP` 等操作变化；
- BP 可以在一个函数执行过程中保持相对稳定。

但经过编译器优化后，函数也可能不使用专门的帧指针。

### 11.4 CALL 计算题

模拟题条件：

- PC 当前值为 `1000H`；
- CALL 指令为双字长；
- 按字编址；
- SP 为 `0100H`；
- 栈向低地址增长；
- 入栈时先修改 SP，再存入数据。

问执行后 SP 及新栈顶内容。

<Steps>
<Step>

### 第一步：求返回地址

指令占两个字，每个地址对应一个字。

因此：

$$
PC_{\text{next}}=1000H+2=1002H
$$

返回地址是：

$$
\boxed{1002H}
$$

</Step>
<Step>

### 第二步：更新 SP

按题设：

$$
SP=0100H-1
$$

所以：

$$
\boxed{SP=00FFH}
$$

</Step>
<Step>

### 第三步：保存返回地址

新栈顶存放：

$$
M[00FFH]=1002H
$$

最终：

$$
\boxed{SP=00FFH,\quad \text{栈顶内容}=1002H}
$$

注意这台机器按字编址。

如果是 32 位 x86、按字节编址，压入一个 4 字节返回地址，ESP 通常需要减少 4。

栈指针变化量取决于题设的编址单位、栈元素大小和进出栈约定。

## 十二、C 语言如何变成机器级代码？

### 12.1 从源码到可执行程序

典型过程：

```text
C 源程序
   ↓
预处理
   ↓
编译
   ↓
汇编代码
   ↓
汇编
   ↓
目标文件
   ↓
链接
   ↓
可执行程序
   ↓

```

各阶段作用：

| 阶段  | 主要工作              |
| --- | ----------------- |
| 预处理 | 宏展开、头文件处理、条件编译    |
| 编译  | 将高级语言转换为汇编或相应低级表示 |

特别注意：

### 12.2 if/else 如何实现？

假设：

```text
if (a > b) {
    x = a;
} else {
    x = b;
}
```

一种 Intel 风格的示意代码：

```asm
cmp eax, ebx
jle else_label

mov ecx, eax
jmp end_label

else_label:
mov ecx, ebx

end_label:
```

注意：

```text
jle else_label
```

判断的是：

$$
a\le b
$$

也就是说，编译器常把高级语言中的判断条件取反，从而跳过 `if` 分支。

这就是反汇编题中的常见陷阱。

不能看到 `jle` 就认为源代码一定写了：

```text
if (a <= b)
```

还要看跳转目标对应哪一段代码。

### 12.3 while、for、do-while 的本质

这三种循环最终都可以由：

- 条件判断；
- 条件跳转；
- 无条件跳转；

实现。

例如：

```text
while (i < 10) {
    i++;
}
```

一种可能的汇编结构：

```asm
loop:
    cmp ecx, 10
    jge end

    inc ecx
    jmp loop

end:
```

控制流：

```text
检查循环条件
      ↓
是否满足？
 ┌────┴────┐
 │         │
是         否
 │         │
执行循环体  退出

```

考试经常通过跳转方向帮助判断循环结构。

- 跳向更高地址：常见于退出循环、跳过分支。
- 跳向更低地址：常见于返回循环开始位置。

但这只是线索，编译器优化后不一定严格符合简单模式。

## 十三、RISC 与 CISC

### 13.1 两种指令系统设计思想

CISC（Complex Instruction Set Computer）：

复杂指令集计算机。

RISC（Reduced Instruction Set Computer）：

精简指令集计算机。

它们的差异主要体现在指令系统的设计取舍。

| 比较项目  | 传统 CISC       | 典型 RISC        |
| ----- | ------------- | -------------- |
| 指令种类  | 较丰富           | 相对较少           |
| 指令功能  | 可能较复杂         | 通常较简单          |
| 寻址方式  | 较多            | 较少             |
| 指令格式  | 可能复杂、变长       | 通常较规则          |
| 寄存器使用 | 依 ISA 而定      | 通常强调较多通用寄存器    |
| 控制器   | 传统实现较常使用微程序   | 典型设计倾向硬布线      |
| 内存操作  | 可能支持内存操作数参与运算 | 常强调 Load/Store |
| 流水线   | 可以实现          | 通常更容易规则化       |
| 编译器优化 | 需要适配复杂指令语义    | 通常强调编译优化       |

注意这是典型特征比较，并非每条性质都具有绝对性。

### 13.2 为什么 RISC 强调 Load/Store？

考虑：

```text
c = a + b;
```

如果变量存在内存中，典型 Load/Store 架构可能采用：

```asm
lw r1, 0(r2)
lw r3, 0(r4)
add r5, r1, r3
sw r5, 0(r6)
```

主要步骤：

1. 从内存加载 a。
2. 从内存加载 b。
3. 在寄存器之间进行加法。
4. 把结果保存到内存。

关键思想：

> 普通算术指令主要操作寄存器，访问数据存储器通常使用专门的 Load/Store 指令。

这样通常更有利于简化译码、组织流水线和处理数据相关。

### 13.3 2009 年 408 真题

关于 RISC 的叙述，错误的是：

A. RISC 普遍采用微程序控制器。

B. RISC 大多数指令执行时间较短。

C. RISC 通常具有较多通用寄存器。

D. RISC 通常具有较少的指令类型和寻址方式。

答案：

$$
\boxed{A}
$$

经典 RISC 设计更倾向于使用硬布线控制器。

但不能因此推出 CISC 无法使用硬布线，也不能认为所有 RISC 指令必然一个周期完成。

还要避免另一种错误：

RISC 不等于性能一定比 CISC 好。

实际性能还取决于程序、编译器、流水线、Cache、执行单元、主频等因素。

### 14.1 2017 年：机器代码长度与无符号整数

题目给出了某 C 程序及其对应的 x86 机器代码。

其中：

```text
00401020  55         push ebp
...
0040105E  39 4D F4   cmp ...
...
00401066  D1 E2      shl edx,1
...
0040107F  C3         ret
```

#### 问题一：机器是 RISC 还是 CISC？

观察指令长度：

- `push ebp` 占 1B；
- `cmp ...` 占 3B；
- `shl edx,1` 占 2B。

机器指令长度不统一，并具有典型 x86 内存操作数形式。

所以是：

$$
\boxed{CISC}
$$

#### 问题二：函数机器代码总长多少？

函数第一条指令位于：

```text
00401020H
```

最后一条 `ret` 从：

```text
0040107FH
```

开始，长度为 1B。

因此代码总长：

$$
L=(0040107FH+1)-00401020H
$$

$$
=60H
$$

$$
\boxed{L=96B}
$$

通用公式：

$$
\boxed{ L=Addr_{\text{last}}-Addr_{\text{first}}+Len_{\text{last}} }
$$

仅把最后一条指令的起始地址减去第一条指令地址，会少算最后一条指令的长度。

#### 问题三：unsigned 的陷阱

源代码存在类似：

```c
for (unsigned i = 0; i <= n - 1; i++)
```

当：

$$
n=0
$$

在题目所设 32 位无符号整数下：

$$
n-1=FFFFFFFFH
$$

而不是把它作为有符号数理解成 $-1$。

如果此时：

$$
i=0
$$

`CMP` 计算：

$$
0-FFFFFFFFH
$$

在无符号减法中，需要借位。

因此：

$$
\boxed{CF=1}
$$

这说明：

> 即使运算结果低 32 位看起来是正数，也不能据此判断 CF=0。

CF 要根据完整的无符号运算过程判断。

#### 问题四：为什么 float 不能直接左移实现乘 2？

对于整数：

```text
shl edx, 1
```

相当于将位模式左移一位。

如果不发生需要特别处理的溢出，数值效果可以相当于乘 2。

但 IEEE 754 浮点数由符号位、阶码、尾数字段构成。

例如：

$$
1.5_f=3FC00000H
$$

直接将它的位模式左移一位：

$$
3FC00000H\ll1=7F800000H
$$

得到的是单精度正无穷的位模式。

而：

$$
1.5\times2=3.0
$$

正确位模式为：

$$
40400000H
$$

因此：

浮点数的机器编码不能直接当普通整数位模式，通过整体左移完成一般意义上的浮点乘法。

### 14.2 2019 年：递归、CALL、相对位移与整数溢出

这一题非常典型，值得完整掌握。

题目给出阶乘函数：

```c
int f1(int n) {
    if (n > 1)
        return n * f1(n - 1);
    else
        return 1;
}
```

部分机器代码：

```text
00401025 E8 D6 FF FF FF  call f1
```

函数入口：

```text
00401000H
```

#### 问题一：计算 10!，调用函数多少次？

调用关系：

```text
f1(10)
  ↓
f1(9)
  ↓
f1(8)
  ↓
...
  ↓
f1(2)
  ↓
f1(1)
```

包含最初调用，共：

$$
\boxed{10\text{ 次}}
$$

其中执行递归调用的 `CALL` 指令共 9 次。

这是两个不同的计数。

#### 问题二：求 CALL 的相对位移

CALL 指令从：

```text
00401025H
```

开始，占 5B。

所以返回地址：

$$
PC_{\text{next}}=00401025H+5
$$

$$
\boxed{PC_{\text{next}}=0040102AH}
$$

函数入口：

$$
Target=00401000H
$$

所以位移：

$$
Offset=Target-PC_{\text{next}}
$$

$$
=00401000H-0040102AH
$$

$$
=-2AH
$$

32 位补码：

$$
\boxed{FFFFFFD6H}
$$

机器码中的相对位移字节为：

```text
D6 FF FF FF
```

低字节位于低地址，所以采用小端方式。

#### 问题三：为什么 13! 发生溢出？

数学结果：

$$
13!=6227020800
$$

32 位有符号整数最大值：

$$
2^{31}-1=2147483647
$$

显然：

$$
6227020800>2147483647
$$

因此不能用 32 位有符号 `int` 正确保存这个结果。

其低 32 位对应：

$$
6227020800\bmod2^{32}=1932053504
$$

所以题目中函数返回的机器计算结果和真实数学阶乘不同。

解决方法是采用足够宽的整数类型，并保证中间乘法也使用相应宽度。

例如：

```c
long long f1(int n) {
    if (n > 1)
        return n * f1(n - 1);
    return 1;
}
```

对于 13!，64 位有符号整数已经足够。

但如果继续计算更大的阶乘，64 位同样会溢出。

#### 问题四：乘法溢出的高低位判据

假设两个 32 位补码整数相乘，得到完整 64 位乘积：

```text
高32位 H | 低32位 L
```

若结果能够用 32 位补码准确表示，则高 32 位必须与低 32 位符号位扩展后的内容一致。

即：

$$
H= \begin{cases} 00000000H,& L_{31}=0\\ FFFFFFFFH,& L_{31}=1 \end{cases}
$$

否则发生有符号溢出：

$$
\boxed{OF=1}
$$

在题目涉及的传统 32 位 x86 环境中，可通过检查 OF 的溢出自陷机制（如 `INTO`）或相应条件分支进入异常处理逻辑。

### 14.3 2021 年：指令格式与体系结构综合题

本题给出：

- 16 位机器字长；
- 20 位地址总线；
- 8 位数据总线；
- 按字节编址；
- 16 位定长指令；
- R 型、I 型、J 型三种格式。

#### 问题一：ALU、IR、MAR、MDR 各为多少位？

机器字长为 16 位，题目所设基本运算宽度：

$$
\boxed{ALU=16\text{ 位}}
$$

指令长 16 位：

$$
\boxed{IR=16\text{ 位}}
$$

地址线有 20 位：

$$
\boxed{MAR=20\text{ 位}}
$$

数据总线有 8 位，该题按一次 8 位数据传送设计主存数据通路：

$$
\boxed{MDR=8\text{ 位}}
$$

20 位地址，按字节编址：

$$
2^{20}B=1MiB
$$

因此：

$$
\boxed{\text{可寻址空间}=1MiB}
$$

#### 最容易错的地方

很多人会看到“16 位机器”，就把：

```text
ALU
IR
MAR
MDR
```

全部写成 16 位。

这是错误的。

它们分别对应：

- ALU：题设中的基本运算数据宽度；
- IR：指令长度；
- MAR：地址宽度；
- MDR：主存数据通路宽度。

这几个参数可能完全不同。

#### 问题二：指令格式容量

R 型格式：

```text
前6位固定为 000000
后面有4位 op1
```

所以 R 型可定义：

$$
2^4=16
$$

种操作。

I 型和 J 型使用另外的 6 位主操作码。

6 位主操作码一共有：

$$
2^6=64
$$

种。

其中 `000000` 已经分配给 R 型。

所以：

$$
64-1=63
$$

因此：

$$
\boxed{\text{I型与J型合计最多63种操作}}
$$

不是各 63 种。

#### 问题三：机器码分段解码

题目中的 R 型：

```text
000000 | rs(2) | rt(2) | rd(2) | op1(4)
```

机器码：

```text
01B2H
```

转换为：

```text
000000 | 01 | 10 | 11 | 0010
```

得到：

```text
rs = 1
rt = 2
rd = 3
op1 = 0010
```

题目规定 `0010` 表示带符号减法。

所以：

$$
\boxed{R[3]\leftarrow R[1]-R[2]}
$$

已知：

```text
R1 = B052H
R2 = 0008H
```

结果：

$$
B052H-0008H=B04AH
$$

因此：

$$
\boxed{R3=B04AH}
$$

且按 16 位有符号数解释，没有发生溢出。

若最后的操作码改为乘法 `0011`，就需要计算完整乘积、截取结果低 16 位，并独立判断是否发生有符号溢出。

这类题的通用步骤就是：

> 先按字段解码，再根据题设操作语义计算，最后判断结果位宽与溢出。

### 14.5 2024 年：数组 + RISC 风格指令 + 小端 + 虚拟页

这道题综合程度更高。

C 语言：


对应机器指令：


#### 第一问：识别寄存器用途

第一条：

```text
slli r4, r2, 2
```

$$
R[4]=R[2]\times4
$$

由于 `int` 占 4B，因此：

$$
\boxed{r2=i}
$$

第二条：

```asm
add r4, r3, r4
```

用基址加数组字节偏移，因此：

$$
\boxed{r3=\operatorname{base}(a)}
$$

第三条：

```asm
lw r5, 0(r4)
```

从计算出的地址取得数组元素。

第四条：

```asm
add r1, r1, r5
```

把加载的数据累加到 r1。

因此：

$$
\boxed{r1=sum}
$$

#### 第二问：计算数组元素地址

已知：

```text
i  = 5
r3 = 0013DFF0H
```

数组元素宽 4B。

字节偏移：

$$
5\times4=20=14H
$$

所以：

$$
EA=0013DFF0H+14H
$$

得到：

$$
\boxed{EA=0013E004H}
$$

#### 第三问：小端恢复数据

从该地址开始的 4 个字节是：

```text
DC EC FF FF
```

小端恢复 32 位机器数：

```text
FF FF EC DC
```

因此：

$$
\boxed{a[5]=FFFFECDCH}
$$

作为 32 位补码：

$$
a[5]=-4900
$$

原：

```text
sum = 00001332H
```

对应十进制：

$$
4914
$$

执行累加：

$$
4914-4900=14
$$

最终：

$$
\boxed{sum=0000000EH}
$$

#### 第四问：虚拟页号

页大小：

$$
4KB=2^{12}B
$$

页内偏移为低 12 位。

因此：

$$
VPN=VA\gg12
$$

其中：

$$
VA=0013E004H
$$

所以：

$$
\boxed{VPN=0013EH}
$$

数组起点：

```text
0013DFF0H
```

位于 `0013DH` 页。

而 `a[5]` 位于 `0013EH` 页。

因此可确定数组：

$$
\boxed{\text{至少跨越2个虚拟页}}
$$

注意：

数组跨页，不代表本次 `lw` 一定跨页。

本次访问从 `0013E004H` 开始，读取 4 字节，不跨页面边界。

#### 第五问：数组类型改变

如果把数组由：

```text
int a[];
```

改为：

```text
short a[];
```

每个元素从 4B 变为 2B。

因此计算字节偏移量时：

原来：

```text
slli r4, r2, 2
```

变为：

```text
slli r4, r2, 1
```

也就是：

$$
\boxed{i\times4\longrightarrow i\times2}
$$

#### 这道题还考查机器码编码

资料中的 2024 年题目，给出了特定机器 M 的指令编码规则。

按照该题设，`slli r4,r2,2` 的机器码为：

```text
00212213H
```

注意这需要使用题目规定的功能码字段，不能擅自代入标准 RV32I 对同名指令的编码。

本题的考点不是死记某个机器码，而是能够根据给定 ISA 的各字段正确拼接机器指令。

### 14.6 2026 年：R/I/M 型指令编码综合题

这道题能够检验是否真正理解“指令格式与译码”。

题目给出一台 16 位计算机：

- 按字节编址；
- 16 位地址；
- R0～R15，共 16 个通用寄存器；
- 指令有 R、I、M 三种格式。

其中：

R 型：

```text
0000 | rt(4) | rs/num(4) | op1(4)
```

I 型：

```text
op2(4) | rt(4) | imm(8)
```

M 型：

```text
op3(4) | offset(12)
```

#### 第一问：主存单元与寄存器宽度

按字节编址：

$$
\boxed{\text{每个编址单元}=8\text{ 位}}
$$

16 位机器，题目所设通用寄存器宽度：

$$
\boxed{16\text{ 位}}
$$

这两者不能混为一谈。

#### 第二问：不同格式操作码能不能重复？

R 型的 `op1` 位于指令末尾。

I 型的 `op2` 位于指令最高 4 位。

并且 R 型最高 4 位固定为 `0000`，可以由此前缀先识别格式。

因此，在满足唯一译码的前提下：

$$
\boxed{op1\text{ 与 }op2\text{ 可以数值相同}}
$$

但 I 型和 M 型的 `op2`、`op3` 都占据最高 4 位。

在该题没有其他区分字段的条件下：

$$
\boxed{op2\text{ 与 }op3\text{ 不可以相同}}
$$

关键原则：

> 判断操作码是否冲突，要看完整指令是否能够唯一译码，而不是只看两个局部字段的数值是否一样。

#### 第三问：解析机器码

给定：

```text
0000 0010 1001 0001
```

按 R 型切分：

```text
0000 | 0010 | 1001 | 0001
```

因此：

```text
rt  = R2
rs  = R9
op1 = 加法
```

指令执行：

$$
R[2]\leftarrow R[2]+R[9]
$$

已知：

```text
R2 = ABCDH
R9 = F001H
```

相加：

```text
  ABCD
+ F001
------
 19BCE
```

寄存器只有 16 位，因此保留低 16 位：

$$
\boxed{R2=9BCEH}
$$

R9 不变：

$$
\boxed{R9=F001H}
$$

这一运算产生了无符号进位。

但两个操作数按 16 位补码解释均为负数，结果仍为可表示的负数，没有发生有符号溢出。

#### 第四问：将高级语言表达式翻译为机器指令

题目要求实现：

$$
y=16x-5
$$

其中 x、y 均为 16 位整数，并在内存中连续存放。

已知 R15 保存 x 的地址。

因为每个整数占 2B：

$$
\operatorname{addr}(y)=(R15)+2
$$

整个程序可以拆成四步：

```text
读取 x
   ↓
左移 4 位，相当于乘 16
   ↓
加立即数 -5
   ↓
保存到 y
```

对应机器指令编码：

| 步骤   | 16 位机器码               | 功能        |
| ---- | --------------------- | --------- |
| 取数   | `1110 0000 0000 0000` | R0 读取 x   |
| 左移   | `0000 0000 0100 0010` | R0 左移 4 位 |
| 加立即数 | `0100 0000 1111 1011` | R0 加上 -5  |
| 存数   | `1111 0000 0000 0010` | 将 R0 存到 y |

其中：

$$
-5
$$

的 8 位补码：

$$
\boxed{FBH}
$$

左移 4 位：

$$
x\ll4
$$

对应乘：

$$
2^4=16
$$

最终计算结果写回 16 位寄存器。

因此必须注意：

$$
16x-5
$$

的数学值如果超出 16 位补码表示范围，机器中只能得到相应的截断位模式，不能保证其带符号数值仍与数学结果相同。

1. 能依据字段位置正确解码。
2. 能追踪寄存器和内存的读写关系。
3. 能把高级语言算式拆解为具体机器指令。

只背指令格式定义是不够的。

## 十五、跨章节综合：指令系统怎样连接存储器与操作系统？

本章与第 3 章存储系统、第 5 章 CPU 的联系特别紧密。

### 15.1 一条 LOAD 指令真正需要经历什么？

例如：

```asm
lw r5, 12(r4)
```

首先根据指令语义计算：

$$
EA=(R4)+12
$$

如果系统采用虚拟存储器，EA 通常是一个有效虚拟地址。

接下来可能经历：

```text
计算有效虚拟地址 EA
          ↓
拆分 VPN 和页内偏移
          ↓
查询 TLB
          ↓
必要时查询页表
          ↓
得到物理页框号
          ↓
形成物理地址
          ↓
访问 Cache / 主存
          ↓
读取数据并写入 r5
```

注意：这是便于理解的逻辑流程。不同处理器的地址转换、Cache 查询等步骤可能重叠执行。

### 15.2 地址之间的关系

假设页大小为：

$$
4KB=2^{12}B
$$

虚拟地址：

```text
0013E004H
```

则：

$$
VPN=\left\lfloor\frac{VA}{4096}\right\rfloor
$$

$$
Offset=VA\bmod4096
$$

得到：

$$
\boxed{VPN=13EH}
$$

$$
\boxed{Offset=004H}
$$

这里若省略前导零，VPN 为 `13EH`；按原虚拟地址字段写，也可以记为 `0013EH`。

再假设页表将该虚拟页映射到物理页框：

```text
PFN = 1A3H
```

那么物理地址：

$$
PA=(PFN\ll12)+Offset
$$

因此：

$$
PA=1A3000H+004H
$$

得到：

$$
\boxed{PA=1A3004H}
$$

这里的 PFN 是本例额外假设的值，不是原 2024 真题已经给出的条件。

#### 如果继续考 Cache

假设：

- Cache 容量 16KB；
- 4 路组相联；
- 块大小 64B。

组数：

$$
S=\frac{16KB}{4\times64B}=64
$$

块内偏移位数：

$$
b=\log_2 64=6
$$

组索引位数：

$$
s=\log_2 64=6
$$

对于物理地址 $PA$，采用普通物理地址索引时：

$$
\boxed{SetIndex=(PA\gg6)\bmod64}
$$

因此，一道题完全可以要求：

- 根据机器指令计算 EA；
- 通过页表求 PA；
- 根据 PA 计算 Cache 组号；
- 判断 Cache 命中；
- 最后恢复加载数据的机器数。

这就是第 3 章和第 4 章知识点真正的交汇处。

## 十七、全章高频易错点

把这些错误彻底纠正，比单独记住很多零散定义更有价值。

#### 易错一：EA 和操作数混淆

$$
EA=\text{地址}
$$

$$
M[EA]=\text{内存中的数据}
$$

题目问哪个，就回答哪个。

#### 易错二：PC 相对寻址直接使用当前指令首地址

必须先确认 PC 基准。

题目可能规定：

$$
Target=PC_{\text{next}}+Offset
$$

也可能使用其他规则。

不要无条件套一个公式。

#### 易错三：补码位移未符号扩展

例如：

$$
FF12H
$$

如果是 16 位补码：

$$
FF12H=-238
$$

扩为 32 位：

$$
FFFFFF12H
$$

不能错误地使用零扩展：

```text
0000FF12H
```

#### 易错四：忘记数组元素宽度

$$
\operatorname{addr}(a[i]) =Base+i\times sizeof(a[0])
$$

二维数组：

$$
\operatorname{addr}(a[i][j]) =Base+(iN+j)\times sizeof(T)
$$

重点是把下标换算为字节数。

#### 易错五：大小端与数据数值混淆

大小端改变内存中的字节排列，不改变一个数本身的数学含义。

也不会颠倒每个字节内部的位顺序。

#### 易错六：忽略结构体末尾填充

不仅成员之间可能填充，结构体尾部也可能填充，以满足数组中下一个结构体元素的对齐要求。

#### 易错七：把返回地址当成函数入口地址

CALL 保存的是返回位置，而不是函数入口。

#### 易错八：把 CF 当成有符号溢出

无符号进位、借位主要由 CF 反映。

有符号溢出由 OF 反映。

#### 易错九：看到负数位模式就判断溢出

例如：

$$
7FFFH+0001H=8000H
$$

发生有符号溢出。

但：

$$
FFFFH+0001H=0000H
$$

作为 16 位有符号运算：

$$
-1+1=0
$$

并没有有符号溢出。

#### 易错十：不同 ISA 的机器码混用

相同助记符不一定代表相同编码。

考试给出了自定义机器 M 的指令格式，就必须遵循该机器的字段定义。

| 变址寻址    | $EA=(IX)+A$                                                   |
| 基址变址    | $EA=(BR)+(IX)+A$                                              |
| PC 相对跳转 | $Target=PC_{\text{base}}+Offset\times s$                     |
| 一维数组    | $EA=Base+i\times sizeof(T)$                                   |
| 二维数组    | $EA=Base+(iN+j)\times sizeof(T)$                              |
| 对齐要求    | $Address\bmod K=0$                                            |
| 页号      | $VPN=\lfloor VA/PageSize\rfloor$                              |
| 页内偏移    | $Offset=VA\bmod PageSize$                                     |
| 有符号小于   | $SF\oplus OF=1$                                               |
| 无符号小于   | $CF=1$（针对 x86 CMP）                                            |
| 指令代码跨度  | $Addr_{\text{last}}-Addr_{\text{first}}+Len_{\text{last}}$ |

### 18.2 遇到综合题的统一解题顺序

建议固定使用这套方法：

第一层：先建立机器模型。

看清：

- 字长；
- 按字节还是按字编址；
- 指令长度；
- 寄存器宽度；
- 大小端；
- 补码与无符号数约定。

第二层：确定指令格式。

划分操作码、寄存器编号、立即数、位移字段。

第三层：计算 EA。

如果是内存操作数，写出有效地址公式；如果是立即数或寄存器操作数，不要额外引入无关的内存访问。

第四层：执行实际运算。

追踪寄存器、内存和标志位变化。

第五层：分析控制流。

遇到 JMP、CALL、条件跳转，先求下一条顺序指令地址，再根据题设计算转移目标。

第六层：检查跨章节信息。

如果存在虚拟存储、Cache、字节序或数据对齐条件，继续分析页号、物理地址、块号、访存数据及异常情况。

### 二十、最后总结：这一章到底要学会什么？

计算机组成原理第 4 章的核心并不是记住几十条汇编指令，而是建立一套完整的机器执行模型。

可以把它浓缩成一条主线：

$$
\boxed{ \text{指令编码} \rightarrow \text{译码} \rightarrow \text{寻找操作数} \rightarrow \text{执行运算} \rightarrow \text{写回结果} \rightarrow \text{确定下一条指令} }
$$

对应到实际做题时：

- 看到机器码，应想到如何切分字段、解释操作码。
- 看到立即数，应想到补码表示与符号扩展。
- 看到 `[base+index*4]`，应想到数组地址与字节偏移。
- 看到 `PC+offset`，应想到位移单位、取指后的 PC 和补码范围。
- 看到内存字节，应想到大小端和数据宽度。
- 看到 `CMP/JL/JBE`，应想到有符号与无符号的条件标志。
- 看到 `CALL/RET`，应想到函数返回地址和堆栈变化。
- 看到 `LW/SW`，应想到有效地址、虚拟存储器和 Cache。
- 看到不同的 R/I/M 型格式，应想到软件可见 ISA、指令编码和唯一译码。

对于 408，真正掌握这一章的标准是：给你一段 C 程序、一组机器码、若干寄存器和内存初值，你能够不依赖选项，一步步算出地址、数据、寄存器变化、跳转结果和最终执行效果。

达到这个程度，第 4 章的选择题和综合大题就能用同一套原理解决，也为后续第 5 章 CPU 的指令执行流程、数据通路、控制器和流水线打好了基础。
