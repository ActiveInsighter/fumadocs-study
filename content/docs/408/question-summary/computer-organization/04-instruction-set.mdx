## 一、全章知识体系与考情

### 1.1 本章究竟研究什么？

计算机的硬件能够执行二进制机器指令，但程序员写的是高级语言。

两者之间需要一套明确的规则：

```text

    ▼
编译、汇编、链接

    ▼

    │
    ▼

    ├── 操作码代表什么？

    ├── 如何计算内存地址？
    ├── 如何执行运算？

    ▼

    ▼
```

第4章的核心，就是理解一条机器指令如何被编码、解释和执行。

## 二、指令集体系结构 ISA

### 2.1 ISA是什么？

ISA 全称 Instruction Set Architecture，即指令集体系结构。

它规定软件可以看到和使用的机器接口。

一般包括：

| ISA规定的内容 | 具体例子               |
| -------- | ------------------ |
| 指令集合     | ADD、SUB、LOAD、STORE |
| 指令格式     | 32位指令如何划分字段        |
| 寄存器组织    | 可见寄存器数量及编号         |
| 寻址方式     | 立即数、直接、间接、变址       |
| 数据类型     | 整数、浮点数等            |
| 存储器相关规则  | 地址空间、字节序等          |
| 控制转移     | 分支、跳转、调用           |
| 异常与特权机制  | 特权级、异常、系统寄存器       |

可以这样理解：

ISA 是软件与硬件之间的约定。

### 2.2 ISA与微架构的区别

这是近年来很重要的选择题考点。

ISA规定机器指令做什么；微架构决定处理器内部怎样完成。

例如：

ISA规定：

$$
R_1\leftarrow R_2+R_3
$$

但具体怎样实现？

可以有很多方案：

- 使用单周期数据通路。
- 使用多周期CPU。
- 使用五级流水线。
- 使用乱序执行。
- 使用多个ALU。

这些实现方式可以不同，但最终必须符合相应ISA规定的行为。

| 设计内容     | 属于ISA吗？ |
| -------- | ------- |
| 指令操作码    | 是       |
| 指令语义     | 是       |
| 软件可见寄存器  | 是       |
| 寻址方式     | 是       |
| 软件可见异常机制 | 是       |
| 流水线级数    | 否       |
| ALU数量    | 否       |
| Cache容量  | 通常否     |
| 分支预测算法   | 否       |
| 乱序执行技术   | 否       |

### 2.3 典型真题：ISA判断

知识讲义 列出了2026年408相关考点。

题目会让你判断哪些内容属于ISA。

例如：

① 处理器是否采用超级流水线。

② 是否定义专门的I/O指令。

③ 异常与中断的体系结构接口。

④ 虚拟存储的体系结构支持。

分析：

① 不属于ISA。超级流水线属于内部实现。

② 如果ISA明确规定I/O指令，则属于ISA。

③ 软件可见的异常和中断规则属于ISA。

④ ISA规定的地址转换机制及系统寄存器等属于ISA。

注意一个细节：不是所有与虚拟存储有关的硬件参数都属于ISA。 例如TLB具体采用多少路组相联，通常属于微架构。

### 2.4 ISA相同是否意味着性能相同？

不意味着。

两台CPU可以执行同一种机器语言，但采用不同的主频、流水线、Cache和执行单元。

执行时间仍然满足：

$$
T=\frac{IC\times CPI}{f}
$$

其中：

$IC$：动态执行指令数。

$CPI$：平均每条指令所需时钟周期数。

$f$：时钟频率。

即使ISA相同，CPI和主频也可能不同。

考场结论：ISA兼容不等于性能相同。

## 三、机器指令的基本格式

### 3.1 一条指令由什么组成？

典型机器指令可以抽象为：

```text
┌────────────┬────────────────┐
│   操作码   │ 操作数/地址字段 │
└────────────┴────────────────┘
      │               │
      ▼               ▼
    做什么？       对谁操作？
```

操作码 Opcode 指明操作类型。

例如：

```text
ADD R1, R2
SUB R1, R2
MOV R1, R2
```

操作数字段用于确定数据或数据的位置。

但要特别注意：

地址字段不一定保存主存地址。

它还可能保存寄存器编号、立即数、位移量等。

例如：

```text
MOV R1, 100
```

可以表示把立即数100写入R1。

```text
MOV R1, [100]
```

则表示读取地址100中的数据。

### 3.2 四种常见地址格式

| 指令类型 | 示例        | 典型特点          |
| ---- | --------- | ------------- |
| 零地址  | ADD       | 操作数隐含，例如栈式机器  |
| 一地址  | ADD A     | 常隐含累加器        |
| 二地址  | ADD A,B   | 常把结果写回一个操作数位置 |
| 三地址  | ADD C,A,B | 可以单独指定目的操作数   |

以加法为例：

零地址指令：

```text
栈顶两个元素出栈
       ↓
      相加
       ↓
     结果入栈
```

一地址指令：

$$
ACC\leftarrow ACC+M[A]
$$

二地址指令，假设目的在前：

$$
R_1\leftarrow R_1+R_2
$$

三地址指令：

$$
R_3\leftarrow R_1+R_2
$$

这些只是典型语义，具体操作数顺序必须服从题目或ISA约定。

### 3.3 地址字段越多，会怎样？

假设：

- 指令字长16位；
- 每个地址字段4位。

三地址指令：

```text
┌────┬────┬────┬────┐
│ OP │ A1 │ A2 │ A3 │
│ 4位│ 4位│ 4位│ 4位│
└────┴────┴────┴────┘
```

操作码只有：

$$
16-3\times4=4\text{位}
$$

因此，最多表示：

$$
2^4=16
$$

种基本操作。

如果是二地址指令：

$$
16-2\times4=8\text{位}
$$

其操作码位数可以更多。

这就引出了本章第一个重点计算考点——扩展操作码。

### 3.4 指令字长、机器字长、操作码长度

这三个量不能混淆。

| 概念    | 含义             |
| ----- | -------------- |
| 机器字长  | CPU基本整数运算的数据位宽 |
| 指令字长  | 一条指令的编码长度      |
| 操作码长度 | 用于表示操作类型的位数    |

例如：

一台机器可以具有：

- 机器字长32位；
- 指令字长16位；
- 操作码4位。

它们不要求相等。

同样，定长指令字不意味着操作码必须定长。

### 3.5 定长与变长指令

定长指令：

```text
指令1：32 bit
指令2：32 bit
指令3：32 bit
```

优点是取指、译码比较规则。

变长指令：

```text
指令1：2 Byte
指令2：5 Byte
指令3：3 Byte
```

优点是编码灵活，部分情况下可以提高代码密度。

缺点是识别指令边界更复杂。

真实x86就是变长指令的典型代表。

考试中，只要给出了机器码序列和指令首地址，就要根据机器码的实际长度确定下一条PC，不能默认所有指令加4。

## 四、扩展操作码——必会计算题

这是本章最适合通过典型题掌握的内容之一。

### 4.1 为什么需要扩展操作码？

假设16位指令每个地址字段占4位。

三地址指令只有4位操作码。

如果16个操作码全部分配完，就没有可供扩展的前缀了。

但如果只使用15个呢？

```text
4位基础操作码
│
├── 0000：三地址指令
├── 0001：三地址指令
├── ...
├── 1110：三地址指令
│
└── 1111：保留作扩展
         │
         ├── 1111 0000：二地址指令
         ├── 1111 0001：二地址指令
         ├── ...
         └── 1111 1111：继续扩展
```

原来保留的一个4位前缀，可以利用减少的一个地址字段继续形成：

$$
2^4=16
$$

种扩展编码。

这就是扩展操作码的基本思想。

### 4.2 扩展操作码的核心约束

已经分配给完整指令的短操作码，不得再作为另一条长操作码的前缀。

否则CPU无法唯一译码。

例如：

```text
0000：已经是一条完整指令
```

就不能再定义：

```text
0000 0011：另一条操作指令
```

因为前面的 `0000` 已经被占用。

### 4.3 通用计算模型

假设：

- 指令总长度为 $L$ 位；
- 每个地址字段宽度为 $a$ 位；
- 二地址指令 $N_2$ 条；
- 一地址指令 $N_1$ 条。

二地址指令基础操作码宽度：

$$
m=L-2a
$$

基础操作码容量：

$$
C_2=2^m
$$

分配二地址指令后，剩余：

$$
r_2=2^m-N_2
$$

扩展为一地址指令：

$$
C_1=r_2\times2^a
$$

分配一地址指令后，剩余：

$$
r_1=C_1-N_1
$$

因此，在没有其他保留编码限制的情况下，最多还能定义：

$$
\boxed{ N_{0,\max}= \left[(2^{L-2a}-N_2)2^a-N_1\right]2^a }
$$

条零地址指令。

但必须检查每一级剩余容量非负，否则原有要求就无法实现。

### 4.4 典型题：2022年408扩展操作码

题目条件：

- 16位定长指令；
- 每个地址字段6位；
- 二地址指令12条；
- 一地址指令254条。

问：最多还能定义多少条零地址指令？

第一步：二地址操作码位数。

$$
16-2\times6=4
$$

共有：

$$
2^4=16
$$

种基础操作码。

第二步：分配二地址指令。

$$
16-12=4
$$

还剩4个可扩展前缀。

第三步：扩展一地址操作码。

释放一个6位地址字段：

$$
4\times2^6=256
$$

分配254条后：

$$
256-254=2
$$

剩余2个前缀。

第四步：继续扩展零地址指令。

$$
2\times2^6=128
$$

因此：

$$
\boxed{128\text{条}}
$$

关键不是记住128，而是理解：

剩余前缀数每进入下一层，都要乘以释放字段所产生的编码分支数。

### 4.5 模拟题：最短指令字长

典型模拟题：

某计算机：

- 指令字长固定；
- 只有一地址和二地址指令；
- 一地址指令260条；
- 二地址指令12条；
- 每个地址字段6位。

求按编码容量计算的最短指令字长。

假设二地址基础操作码为 $m$ 位。

那么：

$$
L=m+12
$$

先试 $m=4$。

基础编码有：

$$
2^4=16
$$

分配12种后剩4种：

$$
(16-12)\times2^6=256
$$

但需要260条。

$$
256<260
$$

不够。

改为 $m=5$：

$$
(32-12)\times64=1280
$$

足够。

因此：

$$
L=5+12
$$

$$
\boxed{17\text{位}}
$$

为什么不是16位？

因为16位对应的编码容量少了4条。

为什么可以得到17位？

因为本题按纯指令编码容量求最小位宽，并未额外规定必须使用整字节长度存放指令。

如果题目另行规定指令字长必须为8位的整数倍，就必须再次考虑该约束。

### 4.6 2017年408：三地址和二地址混合编码

题型条件：

- 三地址指令29条；
- 二地址指令107条；
- 每个地址字段6位；
- 备选指令字长为24、26、28、32位。

求最短可行长度。

先求三地址指令所需基础操作码：

$$
m\ge\lceil\log_2 29\rceil=5
$$

因此：

$$
L\ge5+3\times6=23
$$

检查23位下的二地址扩展容量：

$$
(2^5-29)\times2^6 =3\times64 =192
$$

足以容纳107条二地址指令。

说明23位已经满足纯编码容量要求。

但备选项最小为24位，所以选：

$$
\boxed{24\text{位}}
$$

这题最重要的不是24，而是明确区分：

- 纯编码可行下界：23位；
- 题目选项中的最小可行长度：24位。

不能仅凭“按字节编址”就推断所有指令必然是8位的整数倍。

<Callout type="idea" title="扩展操作码按前缀树分配">

先确定各地址字段占用位数，再从短操作码的剩余前缀递推；不能直接把不同地址数指令的操作码容量相加。

</Callout>

### 4.7 扩展操作码的常见陷阱

| 错误做法                                | 正确方法         |
| ----------------------------------- | ------------ |
| 把各类指令数量直接相加                         | 按前缀树逐级分配     |
| 每个剩余前缀只算1条指令                        | 下一层还要乘扩展分支数  |
| 不检查容量够不够                            | 每一级检查剩余数量    |
| 只用 $\lceil\log_2 N\rceil$ 求最短字长 | 还要检验其他地址格式   |
| 定长指令意味着定长操作码                        | 操作码可以逐级扩展    |
| 按字节编址就一定8位对齐                        | 还需要额外格式或存放约束 |

做到这里，应该能够独立解决扩展操作码数量、最大操作种类和最短指令字长三类题。

## 五、寻址方式——全章最重要的基础

寻址方式在选择题和综合大题中都会出现。

理解它的关键，是始终区分三个概念：

形式地址、有效地址、操作数。

### 5.1 三个概念

假设指令为：

```text
MOV R1, [1000H]
```

并且：

```text
M[1000H] = 5678H
```

那么：

- 形式地址：`1000H`
- 有效地址 EA：`1000H`
- 操作数：`5678H`

这里有两个不同的量：

$$
EA=1000H
$$

$$
Operand=M[EA]=5678H
$$

EA是数据所在的位置，Operand才是数据本身。

后面所有寻址方式都可以按照这个思路理解。

### 5.2 寻址方式总表

设：

$A$：指令给出的形式地址。

$(R)$：寄存器R的内容。

$M[x]$：内存地址x中的内容。

| 寻址方式    | 有效地址或操作数                          | 典型数据访存次数 |
| ------- | --------------------------------- | -------- |
| 立即寻址    | $Operand=A$                   | 0        |
| 寄存器寻址   | $Operand=(R)$                 | 0        |
| 直接寻址    | $EA=A$                        | 1        |
| 存储器间接寻址 | $EA=M[A]$                     | 2        |
| 寄存器间接寻址 | $EA=(R)$                      | 1        |
| 基址寻址    | $EA=(BR)+A$                   | 1        |
| 变址寻址    | $EA=(IX)+A$                   | 1        |
| 基址比例变址  | $EA=Base+Index\times Scale+D$ | 1        |
| PC相对寻址  | $Target=PC_b+offset$          | 视指令语义而定  |
| 堆栈寻址    | 由SP隐含决定                           | 视具体操作而定  |

这里统计的是取得一个数据操作数通常需要的主存访问次数，不包括取指，也不考虑Cache、TLB等机制。

<Tabs items={['立即寻址', '直接寻址', '存储器间接', '寄存器间接']} defaultIndex={0}>

<Tab value="立即寻址">

操作数直接包含在指令里面。

```text
MOV R1, 100
```

执行：

$$
R_1\leftarrow100
$$

不需要为取得这个操作数再次访问主存。

优点是速度快，缺点是立即数字段宽度有限。

如果立即数字段是8位：

无符号范围：

$$
0\sim255
$$

补码有符号范围：

$$
-128\sim127
$$

考题经常进一步问立即数的符号扩展。

例如：

```text
8位立即数：FCH
```

如果把它作为8位补码：

$$
FCH=-4
$$

扩展为16位时：

```text
符号扩展：FFFCH
零扩展：  00FCH
```

这两个结果完全不同。

</Tab>

<Tab value="直接寻址">

指令中直接给出内存地址。

```text
MOV R1, [1000H]
```

其语义为：

$$
EA=1000H
$$

$$
R_1=M[1000H]
$$

为了读取数据，需要一次数据访存。

</Tab>

<Tab value="存储器间接">

这种寻址方式最容易和直接寻址混淆。

假设：

```text
指令形式地址 A = 1000H

M[1000H] = 2000H
M[2000H] = 5678H
```

执行存储器间接寻址：

```text
A = 1000H
     │
     ▼
访问 M[1000H]
     │
     ▼
得到地址 2000H
     │
     ▼
访问 M[2000H]
     │
     ▼
获得操作数 5678H
```

所以：

$$
EA=M[1000H]=2000H
$$

$$
Operand=M[2000H]=5678H
$$

取得数据需要两次访存。

</Tab>

<Tab value="寄存器间接">

假设：

```text
R2 = 2000H
M[2000H] = 5678H
```

指令：

```text
MOV R1, [R2]
```

那么：

$$
EA=(R_2)=2000H
$$

$$
Operand=M[2000H]=5678H
$$

虽然也有“间接”两个字，但这里只需要一次数据访存。

因为寄存器中的地址已经能够直接读到，无需先访问主存寻找指针。

</Tab>

</Tabs>

### 5.7 选择题：四种寻址方式的区别

这是一道典型的寻址方式辨析题。

已知：

```text
R = 600

M[600] = 700
M[700] = 800
```

问下面哪些寻址方式得到的操作数是600？

| 方式       | 计算过程                | 操作数 |
| -------- | ------------------- | --- |
| 直接寻址600  | $M[600]$        | 700 |
| 寄存器间接寻址R | $M[(R)]=M[600]$ | 700 |
| 立即寻址600  | 直接使用600             | 600 |
| 寄存器寻址R   | 读取寄存器内容             | 600 |

所以：

$$
\boxed{\text{立即寻址和寄存器寻址}}
$$

这里根本不需要复杂计算，关键是是否理解“地址”和“值”的区别。

### 5.8 基址寻址与变址寻址

这两者计算公式类似：

$$
EA=(R)+A
$$

区别主要在典型用途。

基址寻址：

$$
EA=(BR)+A
$$

基址寄存器通常表示某个数据区域的起始位置。

例如：

```text
BR = 2000H
A  = 30H
```

则：

$$
EA=2030H
$$

常见用途是程序重定位、结构体访问、函数栈帧等。

变址寻址：

$$
EA=(IX)+A
$$

变址寄存器通常随着数组下标或循环过程变化。

例如：

```text
数组首地址 A = 2000H
IX = 20H
```

则：

$$
EA=2020H
$$

| 对比    | 基址寻址   | 变址寻址   |
| ----- | ------ | ------ |
| 主要作用  | 提供基准地址 | 提供动态偏移 |
| 典型应用  | 重定位、栈帧 | 数组、循环  |
| 寄存器变化 | 通常相对稳定 | 常随循环改变 |
| 地址公式  | 基址+位移  | 基准+变址  |

特别提醒：现代ISA中两种角色经常结合使用，不能认为基址寄存器绝对不会变化。

### 5.9 基址比例变址寻址

这是数组类综合题的基础。

例如：

```text
MOV EAX, [EBX+ECX*4+8]
```

有效地址为：

$$
EA=EBX+ECX\times4+8
$$

如果：

```text
EBX = 1000H
ECX = 3
```

则：

$$
EA=1000H+3\times4+8
$$

$$
\boxed{EA=1014H}
$$

注意这里的乘4是因为数组元素可能占4字节。

### 5.10 二维数组地址计算

C语言的普通二维数组按行优先连续存放。

假设：

```c
int a[20][30];
```

每个int占4B，首地址为1000H。

求：

```text
a[3][5]
```

地址。

对于有 $N$ 列的二维数组：

$$
EA(a[i][j])=Base+(iN+j)\times Size
$$

代入：

$$
EA=1000H+(3\times30+5)\times4
$$

$$
=1000H+380
$$

十进制380转换为十六进制：

$$
380=17CH
$$

所以：

$$
\boxed{EA=117CH}
$$

常见错误是忘记乘元素大小，或者把十进制380直接当成 `380H`。

### 5.11 自增与自减寻址

这是真题常考的细节。

例如：

```text
(R4)+
```

表示寄存器间接后自增。

执行顺序是：

```text
先用R4原来的内容形成地址
          ↓
读取操作数
          ↓
R4再自增
```

而：

```text
-(R4)
```

通常表示先自减，再访问新地址。

更重要的是：

自增多少取决于编址单位和操作数大小。

如果按字编址，每次前进一个字：

$$
R\leftarrow R+1
$$

如果按字节编址，每个操作数占4B，并且规定每次前进一个操作数：

$$
R\leftarrow R+4
$$

这正是2010年408大题的重要考点。

## 六、PC相对寻址与控制转移

这是整个指令系统中最容易出现计算错误的部分之一。

### 6.1 顺序寻址与跳跃寻址

CPU使用程序计数器PC记录下一步需要取的指令地址。

顺序执行时，PC按照指令长度更新。

例如：

当前指令地址：

```text
1000H
```

指令长度4B。

那么下一条顺序指令地址是：

$$
PC_{next}=1004H
$$

如果执行跳转指令，PC可能被设置为其他地址。

<Callout type="warn" title="相对寻址必须确认 PC 基准点">

题目中的位移可能以字节、字或指令字长为单位；PC 可能指向当前指令或下一条指令。计算之前先明确基准地址和缩放因子。

</Callout>

### 6.2 PC相对寻址公式

常见公式：

$$
\boxed{Target=PC_{next}+offset}
$$

但这是以“下一条指令地址”为基准的情况。

更一般地：

$$
\boxed{ Target=PC_{base}+ \operatorname{SExt}(offset)\times s }
$$

其中：

$PC_{base}$：题目规定的基准PC。

$offset$：有符号位移。

$s$：位移单位换算成字节的比例。

必须回答四个问题：

1. 位移字段多少位？
2. 位移是不是补码？
3. 位移单位是什么？
4. 基准PC是当前指令还是下一条指令？

### 6.3 例题：负位移

已知：

```text
跳转指令首地址：200CH
指令长度：2B
目标地址：1FB0H
位移字段：8位补码
位移单位：1B
```

求位移字段。

先求下一条指令地址：

$$
PC_{next}=200CH+2=200EH
$$

再计算：

$$
offset=1FB0H-200EH
$$

$$
=-5EH=-94
$$

8位补码为：

$$
256-94=162=A2H
$$

所以：

$$
\boxed{offset=A2H}
$$

检验：

$$
200EH+(-94)=1FB0H
$$

正确。

### 6.4 位移可达范围

如果位移字段为 $n$ 位补码：

$$
-2^{n-1}\le offset\le2^{n-1}-1
$$

如果是8位：

$$
-128\le offset\le127
$$

若位移单位为4B：

$$
-512\le offset\times4\le508
$$

因此相对于基准PC，能够到达的字节地址区间为：

$$
\boxed{[PC_{base}-512,\ PC_{base}+508]}
$$

还要考虑地址合法性、对齐以及可能的地址回绕规则。

### 6.5 2013年408综合题：条件转移

这是一道非常值得反复练习的真题。

题设规定：

- 16位定长指令；
- 按字节编址；
- 8位补码OFFSET；
- 每条指令2B。

目标地址公式：

$$
PC'=PC+2+2\times OFFSET
$$

某条件转移指令位于：

```text
PC = 200CH
OFFSET = E3H
```

先解释OFFSET：

$$
E3H=227
$$

8位补码真值：

$$
227-256=-29
$$

代入：

$$
PC'=200CH+2+2(-29)
$$

$$
=200EH-3AH
$$

得到：

$$
\boxed{PC'=1FD4H}
$$

注意这里的 `E3H` 不能当成正数227。

##### 条件转移怎样判断？

题目设置了三个检测位：

```text
C、Z、N
```

分别决定是否检测：

```text
CF、ZF、NF
```

如果指令检测位为：

```text
C=0
Z=1
N=1
```

则跳转逻辑为：

$$
Jump=ZF\lor NF
$$

如果：

```text
CF=0
ZF=0
NF=1
```

则：

$$
Jump=1
$$

发生跳转，PC为 `1FD4H`。

如果：

```text
CF=1
ZF=0
NF=0
```

虽然CF为1，但是C检测位为0。

因此不会跳转，PC为：

$$
\boxed{200EH}
$$

这一题最重要的教训是：

先判断跳转条件，再计算实际更新后的PC。

不能看到某个标志位为1就直接断定跳转。

### 6.6 MIPS分支目标地址

典型32位MIPS分支：

$$
\boxed{ Target=PC+4+\operatorname{SExt}(imm16)\times4 }
$$

为什么乘4？

因为一条指令占4B，而分支位移以指令字为单位。

例如：

```text
PC = 3000H
imm16 = FFFCH
```

补码：

$$
FFFCH=-4
$$

因此：

$$
Target=3004H-4\times4
$$

$$
=3004H-10H
$$

$$
\boxed{Target=2FF4H}
$$

MIPS风格分支与x86短跳转通常不能直接套用完全相同的位移单位。

## 七、大小端与数据对齐

### 7.1 大端与小端

假设一个32位整数：

```text
0x12345678
```

它由四个字节组成：

```text
12 | 34 | 56 | 78
```

其中：

- `12` 是最高有效字节；
- `78` 是最低有效字节。

大端：高位字节放低地址。

小端：低位字节放低地址。

| 地址    | 大端 | 小端 |
| ----- | -- | -- |
| 1000H | 12 | 78 |
| 1001H | 34 | 56 |
| 1002H | 56 | 34 |
| 1003H | 78 | 12 |

考试中只需要牢牢记住：

> 小端是字节顺序变化，不是字节内部二进制位顺序颠倒。

### 7.2 小端典型题

32位数据：

```text
A1B2C3D4H
```

从地址1000H开始按小端存储。

那么：

```text
1000H → D4
1001H → C3
1002H → B2
1003H → A1
```

问1002H中的内容。

答案：

$$
\boxed{B2H}
$$

### 7.3 数据对齐

数据对齐要求对象起始地址满足指定的倍数关系。

如果要求按 $K$ 字节对齐：

$$
Address\bmod K=0
$$

例如：

一个4B整数要求4B对齐。

合法起始地址可以是：

```text
1000H
1004H
1008H
100CH
```

但 `1001H` 不满足4B对齐。

非对齐访问可能需要额外内存访问，有些ISA还会触发异常。

### 7.4 结构体对齐计算

考虑：

```c
struct S {
    char c;
    int x;
    short y;
};
```

假设：

```text
char  1B，对齐1B
int   4B，对齐4B
short 2B，对齐2B
结构体整体对齐4B
```

内存布局：

```text
偏移 0       c
偏移 1~3     padding
偏移 4~7     x
偏移 8~9     y
偏移 10~11   尾部padding
```

因此：

$$
\boxed{sizeof(S)=12B}
$$

不是：

$$
1+4+2=7B
$$

### 7.5 对齐通用公式

当前偏移为 $p$，下一个成员要求按 $K$ 字节对齐。

需要填充：

$$
\boxed{ Padding=(K-(p\bmod K))\bmod K }
$$

成员起始偏移：

$$
p'=p+Padding
$$

若结构体整体对齐为 $A$，最后总大小：

$$
\boxed{ Size=\left\lceil\frac{p_{end}}{A}\right\rceil A }
$$

这些是通常ABI下的计算模型；如果题目指定特殊打包规则，必须按题设计算。

### 7.6 大小端与对齐的关系

它们解决的是两个不同问题：

对齐：数据从哪里开始存放。

大小端：数据内部的字节怎样排列。

同一个数据可以同时满足4B对齐，并且采用小端方式。

不要把两个概念混为一谈。

## 八、RISC与CISC

<Tabs items={['CISC', 'RISC']} defaultIndex={0}>

<Tab value="CISC">

CISC是复杂指令集计算机。

典型特点：

- 指令功能丰富；
- 寻址方式较多；
- 指令长度可能变化；
- 某些指令可以直接使用内存操作数；
- 译码较复杂。

典型代表是x86。

</Tab>

<Tab value="RISC">

RISC是精简指令集计算机。

典型特点：

- 指令格式比较规则；
- 寻址方式相对简单；
- 强调寄存器操作；
- 常采用Load/Store结构；
- 比较容易形成规则流水线。

典型代表包括MIPS和RISC-V。

</Tab>

</Tabs>

### 8.3 Load/Store思想

假设C语言：

```text
a[i] = a[i] + 1;
```

典型RISC会拆成：

```text
计算a[i]地址
       ↓
LOAD到寄存器
       ↓
寄存器加1
       ↓
STORE写回内存
```

而一些CISC指令可以直接把内存操作数参与运算的语义写进单条机器指令。

### 8.4 对比总结

| 特点    | RISC         | CISC        |
| ----- | ------------ | ----------- |
| 指令语义  | 相对简单         | 可以较复杂       |
| 指令格式  | 较规则          | 较灵活         |
| 寻址方式  | 较少           | 较多          |
| 内存操作  | 强调Load/Store | 某些运算可直接涉及内存 |
| 传统控制器 | 常用硬布线        | 常见微程序       |
| 流水线   | 通常更容易规则化     | 译码相对复杂      |
| 典型代表  | MIPS、RISC-V  | x86         |

注意：

RISC并不意味着每条指令实际都只需要一个周期完成。

流水线理想情况下可以达到平均每周期完成一条指令，但数据冒险、Cache未命中等仍可能增加CPI。

同样，CISC也完全可以使用流水线。

### 8.5 2017年408真题

题目给出一段x86机器级代码，包含不同长度的指令。

例如：

```text
push ebp
cmp dword ptr [ebp-0Ch], ecx
shl edx, 1
```

这些指令长度不同，而且 `cmp` 可以使用内存操作数。

因此可判断为典型CISC。

另外，题目给出：

```text
首条指令：00401020H
最后RET： 0040107FH
RET长度： 1B
```

求机器代码总长度：

$$
L=(0040107FH+1)-00401020H
$$

$$
=60H
$$

即：

$$
\boxed{96B}
$$

注意不能遗漏最后一条RET所占的字节。

## 九、机器级指令与汇编

这部分是连接综合大题的重要基础。

### 9.1 x86常见寄存器

| 作用   | 32位寄存器 | 64位寄存器 |
| ---- | ------ | ------ |
| 累加器  | EAX    | RAX    |
| 基址   | EBX    | RBX    |
| 计数   | ECX    | RCX    |
| 数据   | EDX    | RDX    |
| 栈指针  | ESP    | RSP    |
| 栈帧基址 | EBP    | RBP    |
| 指令指针 | EIP    | RIP    |

考研尤其需要熟悉：

`EAX`：常用于运算结果、返回值。

`ESP`：栈顶指针。

`EBP`：经典函数栈帧基址。

`EIP`：指令指针。

### 9.2 Intel与AT&T语法

Intel：

```text
mov eax, ebx
```

表示：

```text
目的 ← 源
```

AT&T：

```text
movl %ebx, %eax
```

表示：

```text
源 → 目的
```

| 特征    | Intel | AT&T   |
| ----- | ----- | ------ |
| 操作数顺序 | 目的、源  | 源、目的   |
| 寄存器写法 | eax   | %eax   |
| 立即数写法 | 10    | $10    |
| 内存访问  | [eax] | (%eax) |

AT&T还常用：

```text
b：8位
w：16位
l：32位
q：64位
```

考试中首先要识别题目采用哪种语法，避免弄反源操作数和目的操作数。

### 9.3 MOV与LEA

这是一组高频易混指令。

```text
mov eax, [ebx+ecx*4]
```

表示读取内存：

$$
EAX\leftarrow M[EBX+ECX\times4]
$$

而：

```text
lea eax, [ebx+ecx*4]
```

表示计算有效地址：

$$
EAX\leftarrow EBX+ECX\times4
$$

MOV可能读取内存内容；LEA只计算有效地址。

### 9.4 CMP与TEST

`CMP`：

```text
cmp eax, ebx
```

在Intel语法中，类似计算：

$$
EAX-EBX
$$

但不保存减法结果，只修改相关条件标志。

`TEST`：

```text
test eax, eax
```

类似执行按位与以设置标志，但不写回结果。

常用于判断寄存器是否为0。

### 9.5 条件标志位

| 标志 | 含义       |
| -- | -------- |
| CF | 无符号进位/借位 |
| ZF | 结果是否为0   |
| SF | 结果符号位    |
| OF | 有符号溢出    |

CF与OF必须分开理解。

例如8位加法：

```text
7FH + 01H = 80H
```

无符号解释：

$$
127+1=128
$$

仍在8位无符号范围内：

$$
\boxed{CF=0}
$$

有符号解释：

$$
127+1=128
$$

超出8位补码最大值127：

$$
\boxed{OF=1}
$$

机器结果是 `80H`，但在补码中被解释为 $-128$。

### 9.6 有符号与无符号条件跳转

假设执行：

```text
cmp eax, ebx
```

然后根据标志位跳转。

| 指令  | 判断含义    | 跳转条件                    |
| --- | ------- | ----------------------- |
| JE  | 相等      | $ZF=1$              |
| JNE | 不等      | $ZF=0$              |
| JG  | 有符号大于   | $ZF=0\land SF=OF$   |
| JGE | 有符号大于等于 | $SF=OF$             |
| JL  | 有符号小于   | $SF\ne OF$          |
| JLE | 有符号小于等于 | $ZF=1\lor SF\ne OF$ |
| JA  | 无符号大于   | $CF=0\land ZF=0$    |
| JAE | 无符号大于等于 | $CF=0$              |
| JB  | 无符号小于   | $CF=1$              |
| JBE | 无符号小于等于 | $CF=1\lor ZF=1$     |

记住：

有符号大小比较重点看SF与OF；无符号大小比较重点看CF。

其中 `CMP` 本身只是计算差值并设置标志，最终采用有符号还是无符号关系，由后续跳转指令决定。

### 9.7 移位指令

| 指令  | 功能   |
| --- | ---- |
| SHL | 逻辑左移 |
| SAL | 算术左移 |
| SHR | 逻辑右移 |
| SAR | 算术右移 |
| ROL | 循环左移 |
| ROR | 循环右移 |

例如：

```text
11110000
```

逻辑右移：

```text
01111000
```

算术右移：

```text
11111000
```

算术右移保留符号位。

但要注意：

- 左移并不总能表示数学乘2，因为可能溢出；
- 算术右移负数时可能存在舍入问题；
- 对浮点数的机器编码做整数移位，不等于浮点数乘2。

这也是2017年408综合题考查的知识。

### 9.8 CALL、RET与栈

经典32位x86采用向低地址增长的栈。

`PUSH EAX`：

```text
sub esp, 4
mov [esp], eax
```

`POP EAX`：

```text
mov eax, [esp]
add esp, 4
```

`CALL`：

保存返回地址，然后转到被调用函数。

`RET`：

恢复返回地址，然后继续执行调用者后面的指令。

因此：

CALL与JMP都能改变PC，但CALL还需要建立返回路径。

### 9.9 CALL计算例题

题目：

```text
CALL首地址：1000H
CALL长度：5B
栈向低地址增长
SP初值：8000H
返回地址占4B
先减SP再压栈
```

求执行CALL后的SP以及保存的返回地址。

下一条指令地址：

$$
ReturnAddress=1000H+5
$$

$$
\boxed{1005H}
$$

SP变化：

$$
SP=8000H-4
$$

$$
\boxed{SP=7FFCH}
$$

所以压入栈的是：

```text
1005H
```

而不是被调用函数的入口地址。

### 10.2 if/else对应的汇编

C语言：

```c
if (a > b)
    max = a;
else
    max = b;
```

假设采用Intel语法，并且两个变量均为有符号整数：

```text
cmp eax, ebx
jle else_label

mov ecx, eax
jmp end_label

else_label:
mov ecx, ebx

end_label:
```

它的控制结构是：

```text
       比较a与b
           │
     ┌─────┴─────┐
     │           │
    a>b         a<=b
     │           │
   max=a       max=b
     │           │
     └─────┬─────┘
           │
          结束
```

反汇编题的核心是找到比较指令、条件跳转和合流位置。

### 10.3 while循环

C语言：

```c
while (i < 10) {
    i++;
}
```

典型汇编：

```text
loop:
cmp ecx, 10
jge end

inc ecx
jmp loop

end:
```

特点是先判断、后执行。

### 10.4 do-while循环

```c
do {
    i++;
} while (i < 10);
```

典型汇编：

```text
loop:
inc ecx

cmp ecx, 10
jl loop
```

特点是至少执行一次循环体。

### 10.5 函数调用与经典栈帧

考虑：

```c
int add(int x, int y) {
    return x + y;
}
```

典型32位x86 cdecl模型：

```text
add:
    push ebp
    mov ebp, esp

    mov eax, [ebp+8]
    add eax, [ebp+12]

    mov esp, ebp
    pop ebp
    ret
```

栈帧：

```text
高地址

┌──────────────────────┐
│ 第二个参数 y         │ EBP+12
├──────────────────────┤
│ 第一个参数 x         │ EBP+8
├──────────────────────┤
│ 返回地址             │ EBP+4
├──────────────────────┤
│ 旧EBP                │ EBP
├──────────────────────┤
│ 局部变量             │ EBP-4
└──────────────────────┘

低地址
```

因此：

```text
mov eax, [ebp+8]
```

读取第一个参数。

```text
add eax, [ebp+12]
```

加上第二个参数。

但这是经典32位x86栈传参模型。

现代ABI可能使用寄存器传参，编译器也可能省略帧指针，因此必须以题设为准。

### 真题1：2010年第43题——机器码与自增寻址

#### 题目条件

某计算机：

- 字长16位；
- 主存128KB；
- 按字编址；
- 采用16位单字长指令。

格式：

```text
┌────┬────┬────┬────┬────┐
│ OP │ Ms │ Rs │ Md │ Rd │
│ 4位│ 3位│ 3位│ 3位│ 3位│
└────┴────┴────┴────┴────┘
```

寻址方式：

```text
000：寄存器直接
001：寄存器间接
010：寄存器间接自增
```

已知：

```text
OP(add) = 0010

R4 = 1234H
R5 = 5678H

M[1234H] = 5678H
M[5678H] = 1234H
```

执行：

```text
add (R4), (R5)+
```

约定将源操作数加到目的操作数，结果写回目的位置。

#### 第一问：有多少操作码、寄存器？

操作码4位：

$$
2^4=16
$$

所以最多16种操作码。

寄存器编号3位：

$$
2^3=8
$$

最多8个通用寄存器。

#### 第二问：MAR和MDR宽度

主存128KB：

$$
128KB=2^{17}B
$$

字长16位，一个字占2B。

按字编址：

$$
N=\frac{2^{17}}{2}=2^{16}
$$

需要16位字地址，因此：

$$
\boxed{MAR=16\text{位}}
$$

MDR至少能保存一个16位主存字：

$$
\boxed{MDR=16\text{位}}
$$

这是本题抽象主存模型下的结果。

#### 第三问：机器码

`add (R4), (R5)+`

源操作数：

```text
(R4)
```

采用寄存器间接寻址：

```text
Ms = 001
Rs = 100
```

目的操作数：

```text
(R5)+
```

采用后自增：

```text
Md = 010
Rd = 101
```

拼接：

```text
OP   Ms  Rs  Md  Rd
0010 001 100 010 101
```

整理为：

```text
0010 0011 0001 0101
```

得到：

$$
\boxed{2315H}
$$

#### 第四问：执行结果

源操作数：

$$
M[(R4)]=M[1234H]=5678H
$$

目的操作数：

$$
M[(R5)]=M[5678H]=1234H
$$

相加：

$$
5678H+1234H=68ACH
$$

因此：

$$
\boxed{M[5678H]=68ACH}
$$

目的寄存器R5采用后自增，且按字编址：

$$
R5=5678H+1
$$

$$
\boxed{R5=5679H}
$$

R4不变。

本题最容易错的地方：结果写回的是旧有效地址 `5678H`，不是自增后的 `5679H`。

### 真题2：2019年第45题——递归、CALL、字节序和溢出

这道题综合程度非常高。

#### 第一问：递归调用次数

C语言：

```c
int f1(int n) {
    if (n > 1)
        return n * f1(n - 1);
    else
        return 1;
}
```

计算：

```text
f1(10)
```

递归过程：

```text
f1(10)
  ↓
f1(9)
  ↓
f1(8)
  ↓
 ...
  ↓
f1(2)
  ↓
f1(1)
```

共有10层函数执行。

因此：

$$
\boxed{\text{函数进入次数}=10}
$$

但最后的 `f1(1)` 不再递归。

因此：

$$
\boxed{\text{递归CALL执行次数}=9}
$$

两种计数口径必须分开。

#### 第二问：CALL相对位移

机器代码：

```text
地址：00401025H

E8 D6 FF FF FF
```

这是5B长的相对CALL。

目标地址：

```text
00401000H
```

下一条指令地址：

$$
PC_{next}=00401025H+5
$$

$$
\boxed{0040102AH}
$$

相对位移：

$$
offset=00401000H-0040102AH
$$

$$
=-42
$$

32位补码：

$$
\boxed{FFFFFFD6H}
$$

而机器码中的字节是：

```text
D6 FF FF FF
```

低字节先存，说明采用：

$$
\boxed{\text{小端}}
$$

CALL保存的返回地址为：

```text
0040102AH
```

#### 第三问：为什么13!结果错误？

数学上：

$$
13!=6227020800
$$

但32位有符号整数最大值为：

$$
2^{31}-1=2147483647
$$

显然：

$$
6227020800>2147483647
$$

因此不能被32位有符号int表示。

在题设的机器低32位截断模型下：

$$
6227020800\bmod2^{32}
$$

$$
=\boxed{1932053504}
$$

这解释了题目给出的返回值。

注意标准C语言中，有符号整数溢出属于未定义行为，不能把上述回绕当作所有C程序都保证发生的结果。

#### 第四问：怎样修正？

需要使递归函数本身使用足够宽的返回类型。

```c
long long f1(int n) {
    if (n <= 1)
        return 1LL;

    return (long long)n * f1(n - 1);
}
```

只把：

```c
int result;
```

改成：

```c
long long result;
```

却保留内部 `int f1(...)`，不能修复内部已经发生的溢出。

#### 第五问：有符号乘法OF判断

假设64位完整乘积为 $P$，但目的寄存器只保存低32位 $P_L$。

当：

$$
P\ne\operatorname{SExt}_{64}(P_L)
$$

说明低32位无法正确表示完整有符号乘积。

因此：

$$
\boxed{OF=1}
$$

对应x86可以使用：

```text
jo overflow_handler
```

在OF为1时转入溢出处理逻辑。

### 真题3：2021年第43题——R/I/J型指令与补码

#### 题目条件

计算机M：

```text
机器字长：16位
指令字长：16位
按字节编址

地址总线：20位
数据总线：8位
```

#### 第一问：各部件位宽

ALU基本运算宽度：

$$
\boxed{16\text{位}}
$$

可寻址存储空间：

$$
2^{20}B=1MiB
$$

IR保存完整指令：

$$
\boxed{IR=16\text{位}}
$$

MAR保存主存地址：

$$
\boxed{MAR=20\text{位}}
$$

MDR对应题设8位数据总线：

$$
\boxed{MDR=8\text{位}}
$$

一条16位指令通过8位数据总线取得，在该简化模型中至少需要两次8位传输。

#### 第二问：操作码容量

题图规定：

R型使用6位固定前缀：

```text
000000
```

再使用4位功能码。

因此R型最多：

$$
2^4=16
$$

种操作。

I型和J型共享剩余6位主操作码空间。

因为：

```text
000000
```

已经留给R型，因此剩：

$$
2^6-1
$$

$$
\boxed{63\text{种}}
$$

这里是I型与J型合计63种，不是各63种。

#### 第三问：机器码解码

给出：

```text
01B2H
```

展开：

```text
0000 0001 1011 0010
```

按题设字段拆分：

```text
000000 | 01 | 10 | 11 | 0010
```

解释：

```text
R型
rs = R1
rt = R2
rd = R3
op1 = 减法
```

因此：

$$
R3\leftarrow R1-R2
$$

已知：

```text
R1 = B052H
R2 = 0008H
```

减法：

$$
B052H-0008H
$$

得到：

$$
\boxed{B04AH}
$$

将R型功能码换为乘法：

```text
01B3H
```

真实有符号乘积为：

$$
-20398\times8=-163184
$$

超出16位补码范围：

$$
[-32768,32767]
$$

因此发生溢出。

低16位结果：

$$
\boxed{8290H}
$$

即：

寄存器可以保存 `8290H`，但数学乘积不能由16位补码正确表示。

### 真题4：2023年第44题——变长指令、二维数组和分页

已知：

```c
int a[24][64];
```

数组首地址：

```text
00422000H
```

每个int为4B。

其中一条机器指令：

```text
004010AEH:
C7 84 82 00 20 42 00 0A 00 00 00
```

共11B。

#### 第一问：下一条指令地址

$$
PC_{next}=004010AEH+0BH
$$

$$
\boxed{004010B9H}

注意变长指令必须数机器码字节。

#### 第二问：二维数组地址

对应汇编的内存地址形式：

```text
[ecx+edx*4+00422000h]
```

题目告诉我们：

```text
edx = j
```

$$
EA=Base+(64i+j)\times4
$$

整理：

$$
EA=Base+256i+4j
$$

$$
EA=00422000H+ECX+EDX\times4
$$

因此：

$$
\boxed{ECX=256i}
$$

这里ECX保存的是字节偏移，而不是单纯的行号。

#### 第三问：大小端

机器代码中的4字节立即数：

```text
0A 00 00 00
```

表示：

```text
0000000AH
```

所以低有效字节先存：

$$
\boxed{\text{小端}}
$$

#### 第四问：是否缺页？

第19条代码和前面已经执行的代码位于同一个代码虚拟页。

在该页未换出的前提下，不会因为执行到第19条而首次发生代码页缺页。

### 真题5：2024年第44题——数组、端序和机器码

这道题是近年来跨章节综合考查的典型。

C语言：

```text
sum += a[i];
```

对应指令：

```text
slli r4, r2, 2
add  r4, r3, r4
lw   r5, 0(r4)
add  r1, r1, r5
```

#### 第一问：寄存器角色

第一条：

$$
r4=r2\times4
$$

因此r2保存数组下标i。

第二条：

$$
r4=r3+r4
$$

因此r3保存数组首地址。

第三条：

$$
r5=M[r4]
$$

因此r5保存数组元素。

第四条：

$$
r1=r1+r5
$$

因此r1保存sum。

得到：

| 寄存器 | 作用      |
| --- | ------- |
| r1  | sum     |
| r2  | i       |
| r3  | 数组首地址   |
| r4  | 元素有效地址  |
| r5  | 读取的数组元素 |

#### 第二问：计算a[5]地址

题设：

```text
i = 5
数组首地址 = 0013DFF0H
```

每个int占4B。

$$
EA=0013DFF0H+5\times4
$$

$$
=0013DFF0H+14H
$$

$$
\boxed{EA=0013E004H}
$$

#### 第三问：大小端读取

题图给出的四个字节：

```text
地址        内容
...E004     DC
...E005     EC
...E006     FF
...E007     FF
```

小端组合：

```text
FFFFECDCH
```

作为32位补码：

$$
\boxed{a[5]=-4900}
$$

题目给出原sum为：

```text
00001332H
```

换算：

$$
1332H=4914
$$

因此：

$$
sum=4914-4900
$$

$$
\boxed{sum=14}
$$

机器数：

$$
\boxed{0000000EH}
$$

#### 第四问：虚拟页号

页面大小：

$$
4KB=2^{12}B
$$

因此页内偏移占12位。

虚拟页号：

$$
VPN=\left\lfloor\frac{VA}{2^{12}}\right\rfloor
$$

地址为：

```text
0013E004H
```

所以：

$$
\boxed{VPN=0013EH}
$$

数组首地址在 `0013DH` 页，a[5]在 `0013EH` 页。

因此整个数组至少涉及两个页面。

但本次a[5]占用的4B均位于同一页。

数组跨页不等于本次元素访问跨页。

#### 第五问：编码slli

题目采用自定义机器M的字段约定。

其机器码为：

```text
00212213H
```

注意不能机械套用标准RISC-V的功能码，因为题目规定的字段编码与标准RISC-V存在差异。

如果把数组改为2B的short数组，地址偏移由：

$$
4i
$$

变成：

$$
2i
$$

因此：

```text
slli r4, r2, 1
```

同时，真正读取short时还需要采用符合题设的半字加载指令。

### 真题6：2026年第43题——自定义指令系统

这是理解“陌生指令系统如何分析”的绝佳题型。

题设是一台：

```text
16位计算机
按字节编址
16位主存地址
16个通用寄存器
```

定义三种指令格式。

| 格式 | 字段组成                 |
| -- | -------------------- |
| R型 | 固定前缀、寄存器、寄存器/移位量、op1 |
| I型 | op2、寄存器、8位立即数        |
| M型 | op3、12位位移            |

#### 第一问：为什么操作码可以重复？

R型最低4位保存 `op1`。

其最高4位有固定前缀：

```text
0000
```

I型最高4位保存 `op2`。

因此R型的 `op1` 和I型的 `op2` 即使数值相同，也不会必然造成译码冲突。

但I型和M型的操作码都处于最高4位，而且题设没有其他区分条件。

如果 `op2` 和 `op3` 相同，就可能无法确定应该按哪种格式译码。

结论：

$$
\boxed{op1\text{与}op2\text{可以同码}}
$$

$$
\boxed{op2\text{与}op3\text{不能同码}}
$$

核心原则是看完整机器码是否具有唯一解释，不是机械比较操作码数字。

#### 第二问：机器码执行

题目：

```text
0000 0010 1001 0001
```

解码：

```text
R型
rt = 2
rs = 9
op1 = 加法
```

执行：

$$
R2\leftarrow R2+R9
$$

已知：

```text
R2 = ABCDH
R9 = F001H
```

相加：

$$
ABCDH+F001H=19BCEH
$$

只保存低16位：

$$
\boxed{R2=9BCEH}
$$

R9不被写回：

$$
\boxed{R9=F001H}
$$

#### 第三问：实现y=16x-5

题目要求使用4条机器指令完成：

```text
y = 16*x - 5;
```

假设x、y均为16位数据，连续存储，R15保存x的地址。

执行思路：

```text
读取x
  ↓
左移4位
  ↓
加(-5)
  ↓
存入y
```

对应完整机器码：

```text
1110 0000 0000 0000
0000 0000 0100 0010
0100 0000 1111 1011
1111 0000 0000 0010
```

解释：

第一条：

```text
LOAD R0 ← M[R15+0]
```

第二条：

```text
R0 ← R0 << 4
```

因为：

$$
16=2^4
$$

第三条：

```text
R0 ← R0 + (-5)
```

8位补码：

$$
-5=FBH
$$

第四条：

```text
STORE M[R15+2] ← R0
```

因为x占2B，y紧随其后，所以：

$$
\&y=\&x+2
$$

这一题的核心在于：

先理解指令功能，再根据字段逐位编码。

题设的16位运算在发生有符号溢出时只能保证相应的低16位机器结果，不能保证得到数学意义上正确的 $16x-5$。

## 十二、王道模拟题中的重要综合模型

### 模拟题1：使用MIPS指令构造32位地址

来源：2027王道408冲刺模拟第2套第44题。

给定32位地址：

$$
A=A_{upper}\times2^{16}+A_{lower}
$$

MIPS立即数字段只有16位。

如何构造任意32位地址？

#### 方式一：LUI + ORI

```text
lui t0, A_upper
ori t0, t0, A_lower
lw  s0, 0(t0)
```

`lui` 将16位立即数放到高16位，低16位补0。

$$
t0=A_{upper}\ll16
$$

`ori` 将16位立即数零扩展后按位或：

$$
t0=(A_{upper}\ll16)\lor A_{lower}
$$

因此构造完整地址A。

#### 方式二：LUI + LW

```text
lui t0, A_upper_adjusted
lw  s0, A_lower(t0)
```

这里的陷阱是：

LW的16位位移采用符号扩展。

例如：

```text
A = 1234F234H
```

低16位：

```text
F234H
```

最高位为1，作为16位补码是负数。

$$
F234H=-3532
$$

因此需要先把高16位加1：

```text
lui t0, 1235H
lw  s0, F234H(t0)
```

地址计算：

$$
12350000H-0DCCH
$$

$$
\boxed{1234F234H}
$$

所以高位修正公式：

$$
\boxed{ A_{upper,adj}= \begin{cases} A_{upper},&A_{lower}<8000H\\ (A_{upper}+1)\bmod2^{16},&A_{lower}\ge8000H \end{cases} }
$$

这是非常值得掌握的立即数符号扩展综合模型。

### 模拟题2：循环指令数、CPI和MIPS

来源：2027王道408冲刺模拟第7套第44题。

C语言：

```c
for (i = 0; i < 5; i++)
    j = j + B[i];
```

给出的MIPS风格机器代码包含：

```text
add
sll
add
lw
add
addi
slti
bne
```

第一条初始化执行1次。

后面7条每轮执行一次，共5轮。

因此动态执行指令数：

$$
IC=1+5\times7
$$

$$
\boxed{IC=36}
$$

注意最后一次bne虽然不跳转，但仍然执行。

题目规定：

```text
运算指令：4周期
访存指令：5周期
分支指令：3周期
```

统计：

| 类型 | 执行次数 | 总周期 |
| -- | ---- | --- |
| 运算 | 26   | 104 |
| 访存 | 5    | 25  |
| 分支 | 5    | 15  |
| 合计 | 36   | 144 |

平均CPI：

$$
CPI=\frac{144}{36}
$$

$$
\boxed{CPI=4}
$$

主频100MHz。

MIPS：

$$
MIPS=\frac{100}{4}
$$

$$
\boxed{25MIPS}
$$

执行时间：

$$
T=\frac{144}{100\times10^6}
$$

$$
\boxed{T=1.44\mu s}
$$

此处采用题目规定的非流水周期统计。

不能直接把这个结果与流水线启动、停顿和排空周期混算。

### 模拟题3：Load-Use冒险

来源：2027王道408冲刺模拟第8套第44题。

典型指令：

```text
sll t1, s3, 2
add t1, t1, s6
lw  t0, 0(t1)
bne t0, s5, exit
```

五级流水线：

```text
IF → ID → EX → MEM → WB
```

第一组相关：

```text
sll t1, s3, 2
add t1, t1, s6
```

第二条读取第一条生成的t1。

属于RAW数据相关。

如果支持EX阶段转发，通常可以消除相应的数据等待。

第二组：

```text
lw t0, 0(t1)
bne t0, s5, exit
```

`lw` 的数据通常要到MEM阶段结束才能获得。

紧邻的 `bne` 如果在EX阶段需要该值，即使支持常规转发，也可能赶不上。

在题设的经典五级流水模型中，需要：

$$
\boxed{1\text{周期停顿}}
$$

不过，分支比较发生在ID还是EX阶段、转发路径如何设置，都会影响实际停顿周期。

这部分属于第5章流水线知识，但常与指令系统综合考查。

## 十三、本章统一解题模板

面对陌生的指令系统综合题，可以按照以下顺序分析。

<Steps>

<Step>

    ### 第一步：列出机器基本参数

| 参数    | 需要确认的问题       |
| ----- | ------------- |
| 机器字长  | ALU、寄存器基本运算宽度 |
| 指令字长  | 一条指令多少位       |
| 编址单位  | 按字节还是按字       |
| 地址线宽度 | 可寻址多少单元       |
| 数据线宽度 | 一次外部传输多少位     |
| 寄存器数量 | 编号字段需要多少位     |
| 字节序   | 大端还是小端        |

这里尤其要防止把机器字长、指令字长、数据线宽度和地址线宽度写成同一个数。

</Step>

<Step>

    ### 第二步：拆分指令字段

例如：

```text
0000 0010 1001 0001
```

如果题设规定：

```text
前4位：格式标识
中间4位：目的寄存器
后4位：源寄存器
最后4位：操作码
```

就必须严格按照这些位置解码。

不能根据十六进制外形猜指令功能。

</Step>

<Step>

    ### 第三步：明确每个操作数

为每个操作数单独建立关系：

```text
指令字段
    ↓
寻址规则
    ↓
有效地址EA
    ↓
实际操作数
```

对于寄存器直接寻址，不必强行构造内存EA。

</Step>

<Step>

    ### 第四步：处理立即数和位移

检查：

- 是补码还是无符号；
- 需要符号扩展还是零扩展；
- 位移以字节、字还是指令为单位；
- 是否需要左移2位；
- PC使用什么基准。

</Step>

<Step>

    ### 第五步：执行运算

分别判断：

$$
\text{完整数学结果}
$$

$$
\text{机器保存的低位结果}
$$

$$
CF,\ OF,\ ZF,\ SF
$$

不要因为机器保存了结果，就认为没有溢出。

</Step>

<Step>

    ### 第六步：跟踪状态变化

可以建立这样的表：

| 指令     | 输入      | 操作   | 写回位置  | 其他变化     |
| ------ | ------- | ---- | ----- | -------- |
| LOAD   | 有效地址    | 读取内存 | 寄存器   | 可能更新指针   |
| ADD    | 两个操作数   | 加法   | 目的位置  | 按ISA更新标志 |
| STORE  | 地址与数据   | 写内存  | 主存    | 可能更新指针   |
| BRANCH | 条件与位移   | 计算目标 | PC    | 控制流变化    |
| CALL   | 目标与返回地址 | 调用   | PC、栈等 | 建立返回状态   |

对于CALL、PUSH、POP、RET，最好额外记录SP和栈顶内容。

</Step>

<Step>

    ### 第七步：检查结果

主要检查机器码位数、补码转换、地址单位、读写位置、指令长度、跳转目标、溢出及数据对齐是否正确。

</Step>

</Steps>

### 本章最核心的一句话

遇到任何指令系统综合题，都按照“机器参数 → 字段解码 → 寻址 → 取操作数 → 运算 → 写回 → 更新PC及其他状态”的顺序推导。

只要能够熟练掌握这条主线，再遇到改变操作码位置、指令字长、寄存器数量、立即数位宽或寻址规则的新题，就不必依赖死记答案，而可以根据题目定义重新推导。这才是408计算机组成原理第4章最重要的学习目标。
