## 总线结构、信号与仲裁

### 总线的基本概念

**一、什么是总线？** 总线（Bus）是一组用于多个功能部件之间传输信息的公共通信线路或互连资源。传统计算机可以抽象为：

```text
CPU ───────────┐
               │
主存 ──────────┤
               ├── 系统总线
I/O接口A ──────┤
               │
I/O接口B ──────┘
```

总线有两个重要特征。

**1. 共享性** 多个设备可以共享同一套互连资源。这样可以避免所有设备都建立独立连接。但共享也意味着：

**多个设备可能竞争同一条总线。**

**2. 分时性** 在经典单通路共享总线中，同一时刻通常只能有一个主设备控制总线事务。例如：

```text
时间 →

CPU访问主存 | DMA访问主存 | CPU访问主存
```

多个设备轮流获得使用权。注意：

**单总线不是只有一根物理导线。** 一套总线通常包含大量信号线。另外，PCIe 等现代互连采用点到点链路和交换结构，不一定符合传统物理共享总线模型。考研分析时，必须明确题目讨论的是经典共享总线，还是多通道、交换式互连。

**二、三类系统总线** 按照传送信息的功能，分为：

1. 数据总线；
2. 地址总线；
3. 控制总线。

**1. 数据总线** 负责传输实际的数据内容。包括：机器指令；操作数；运算结果；I/O 命令字；I/O 状态字；中断类型号等。数据总线通常支持双向传送。例如：

```text
CPU读取主存：

主存 ───数据───→ CPU

CPU写入主存：

CPU ───数据───→ 主存
```

**高频陷阱：数据总线能不能传指令？** 能。因为指令本质上也是二进制数据。例如 CPU 取指令时，指令通过数据通路从存储器送往 CPU。

**真题：2011 年** 在系统总线的数据线上，不可能传输的是： A. 指令 B. 操作数 C. 握手应答信号 D. 中断类型号

**答案：C。**

解析：指令、操作数、中断类型号都可以作为编码信息通过数据线传输。握手应答属于直接协调传输时序的控制信号。因此应走控制信号通路。注意区分：

- 命令字：编码后的数据，可以经数据总线传输。
- 控制信号：读使能、写使能、请求、应答等具体控制信号。

**2. 地址总线** 负责指出访问的位置。若具有 $n$ 根独立地址线，则最多可以编码： $N=2^n$ 个不同地址。如果采用按字节编址： $S=2^n\ \mathrm{B}$ 例如 32 位地址总线： $S=2^{32}\ \mathrm{B}=4\ \mathrm{GiB}$ 需要特别注意：

**地址总线宽度决定可表示的地址数量，不决定一次传输多少数据。**

**例题** 某计算机：地址总线 32 位；数据总线 64 位；按字节编址。求理论最大寻址空间和每次并行传输的数据量。解：寻址空间： $2^{32}\ \mathrm{B}=4\ \mathrm{GiB}$ 每次数据量： $\frac{64}{8}=8\ \mathrm{B}$

**答案：4 GiB，8 B。** 这里还有一个细节：如果按字编址，地址线能够表示的字地址数量仍为 $2^n$，但换算成字节容量时还需要乘每个编址字的字节数。因此不能脱离编址单位使用寻址空间公式。

**地址总线的方向** 经典 CPU 访问主存的模型中： `CPU ───地址───→ 主存` 地址通常由 CPU 发出。但在 DMA 系统中： `DMA ───地址───→ 主存` DMA 可能获得总线主控权。所以更准确的表述是：

**地址由当前主设备发往目标设备。** 不能认为地址一定由 CPU 发出。

**3. 控制总线** 负责协调总线操作。典型信号：

- 读请求；
- 写请求；
- 总线申请；
- 总线允许；
- 中断请求；
- 中断响应；
- Ready；
- ACK；
- 时钟；
- 复位。

控制总线中不同信号方向可能不同。例如：

```text
CPU ───Read───→ 主存

CPU ←──Ready─── 主存
```

所以：

**控制总线整体不能简单理解为全部单向。** 应区分：主设备发出的命令；从设备返回的状态；仲裁器发出的允许信号；设备发出的请求信号。

**模拟题：信息传输方向** 某传统主从总线模型中： I. 地址信息 II. 数据 III. 控制命令 IV. 状态响应 哪些信息类别按其典型发送方和接收方具有固定方向？

答案：I、III、IV。解释：

- 地址：主设备到从设备；
- 控制命令：主设备到从设备；
- 状态响应：从设备到主设备；
- 数据：读写方向不同。

但这并不意味着整个控制总线只能单向传输。这是两种不同的分类口径。

**三、总线的其他分类**

**1. 按连接对象分类**

| 类型 | 连接对象 |
|---|---|
| 核内总线 | CPU 内部部件 |
| 系统总线 | CPU、主存、I/O 接口 |
| 通信总线 | 计算机与外部系统 |

**2. 按数据传输组织分类**

| 类型 | 特征 |
|---|---|
| 串行总线 | 数据位沿少量线路依次传送 |
| 并行总线 | 多根数据线同时传送不同位 |

**3. 按定时方式分类**

| 类型 | 特征 |
|---|---|
| 同步总线 | 统一时钟 |
| 异步总线 | 请求、应答等握手 |
| 半同步总线 | 统一时钟配合等待或握手 |

这些分类相互独立。一条总线可以同时是：系统总线；并行总线；同步总线。

### 串行、并行与总线标准

**一、串行与并行的真正区别**

**1. 并行传输** 例如 8 位并行数据通路：

```text
D7 ─────────────→
D6 ─────────────→
D5 ─────────────→
D4 ─────────────→
D3 ─────────────→
D2 ─────────────→
D1 ─────────────→
D0 ─────────────→
```

一个传输时刻可以同时发送 8 位。优点：

- 一次传输的数据位数多；
- 低频短距离场景实现直观。

缺点：

- 信号线多；
- 布线复杂；
- 时钟偏斜；
- 串扰；
- 高频下难以保证各位同时到达。

**2. 串行传输** 数据位沿较少的线路依次传送。 `1 → 0 → 1 → 1 → 0 → 0 → ...` 优点：线路数量少；易于实现高速差分传输；适合高速互连；时钟偏斜问题更易控制。

**高频易错**

**并行不一定比串行快。** 原因是实际带宽不仅取决于一次传送多少位，还取决于每秒传送多少次。例如：并行总线： 32 bit；33 MHz；每周期一次。带宽：

$$
B=\frac{32}{8}\times33\times10^6
=132\ \mathrm{MB/s}
$$

另一串行互连若单条链路有效数据率达到： $2\times10^9\ \mathrm{bit/s}$ 则对应： $B=250\ \mathrm{MB/s}$ 即使只用一条串行数据通道，也可能超过上述并行总线。实际标准还要考虑编码、协议和链路开销。

**二、PCI、PCIe、USB 等标准**

| 标准 | 类型 | 主要特征 |
|---|---|---|
| ISA | 传统并行总线 | 早期扩展卡 |
| EISA | 传统并行总线 | ISA 的扩展 |
| PCI | 并行扩展总线 | 传统扩展设备 |
| PCIe | 高速串行互连 | 点到点、可多 Lane |
| USB | 串行外部互连 | 热插拔、即插即用 |
| PATA | 并行 ATA | 早期硬盘接口 |
| SATA | 串行 ATA | 硬盘和 SSD |

特别注意：

**PCI 与 PCIe 不是同一种物理传输结构。** PCI 是传统并行总线。 PCIe 使用串行 Lane。

**真题：2017 年** PCIe ×16 是否表示 16 位并行总线？ 不是。 ×16 表示具有 16 条 Lane。每条 Lane 内部采用高速串行传输。不能将 PCIe ×16 直接理解为 16 bit 宽的传统并行数据总线。

**三、单工、半双工与全双工**

**1. 单工** 信息只能沿一个方向传送。 `A ─────→ B`

**2. 半双工** 双方都能发送，但不能同时发送。

```text
A ─────→ B

或

A ←───── B
```

**3. 全双工** 双方可以同时发送。 `A ─────→ B` `A ←───── B` 全双工是总线带宽题的重要考点。设：单方向有效带宽为 $B$；双方向完全对称；两个方向可以同时满速传输。则双向合计吞吐量： $B_{\mathrm{total}}=2B$ 但如果只问：

**单方向发送带宽是多少？** 不能乘 2。

### 总线结构与仲裁

**一、单总线结构**

```text
CPU ──┐
      │
主存 ─┼── 共享系统总线
      │
I/O ──┘
```

优点：结构简单；成本低；易于扩展。缺点：总线竞争严重；容易成为性能瓶颈；共享通路无法同时独立完成多个事务。

**一个重要区别** “单总线结构”有时还出现在 CPU 内部数据通路设计中。 CPU 内部单总线和计算机系统单总线不是完全相同的讨论对象。考试时必须看图中连接的是：

- CPU 内部寄存器与 ALU；
- 还是 CPU、主存与 I/O 设备。

**二、双总线与多总线结构** 为降低竞争，可以将不同设备划分到不同互连层次。例如：

```text
CPU
 │
 ├──── 高速存储器通路 ─── 主存
 │
 └──── I/O互连 ───────── 外设控制器
```

更复杂的系统还可能设置：存储器总线；高速 I/O 总线；低速 I/O 总线；桥接器或交换结构。优点：分流不同设备的数据；降低资源竞争；便于不同设备采用不同速率。缺点：结构复杂；成本提高；跨互连通信可能引入转换与排队开销。

**靠近 CPU 的互连通常要求更高带宽和更低延迟。**

**三、总线仲裁** 多个主设备同时申请共享总线时，需要决定：

**谁先获得使用权？** 这称为总线仲裁。例如：

```text
CPU ─────请求─────┐
                  │
DMA ─────请求─────┼── 仲裁器
                  │
其他主设备 ─请求──┘
                  │
             分配总线控制权
```

经典集中式仲裁包括三种方式。

**1. 链式查询（菊花链）** 总线允许信号按设备连接顺序逐级传递。 `仲裁器 → A → B → C → D` 如果 A 提出请求，它可能直接截获允许信号。优点：

- 控制线路少；
- 实现简单。

缺点：优先级通常固定；靠近仲裁器的设备优先级高；低优先级设备可能饥饿；链路故障可能影响后续设备。

**2. 计数器定时查询** 由计数器依次查询各设备是否申请总线。例如： `设备0 → 设备1 → 设备2 → 设备3` 可以改变计数起点，改善公平性。优点：

- 控制线较少；
- 优先级可调整。

缺点：

- 逐个查询有时间开销；
- 最坏情况下需要查询多个设备。

**3. 独立请求方式** 每个主设备分别拥有请求和允许信号。

```text
设备A ─请求A──→
设备B ─请求B──→ 仲裁器
设备C ─请求C──→
```

优点：仲裁速度快；优先级灵活；适合较高性能的共享互连。缺点：

- 控制线路多；
- 仲裁逻辑复杂。

**对比总结**

| 方式 | 速度 | 线路数量 | 优先级 |
|---|---|---|---|
| 链式查询 | 受链长影响 | 少 | 通常固定 |
| 计数器查询 | 受扫描过程影响 | 较少 | 可调整 |
| 独立请求 | 较快 | 多 | 灵活 |

### 总线事务与总线定时

**一、主设备与从设备** 主设备负责发起事务。从设备负责响应事务。例如 CPU 读取主存：

```text
CPU                     主存
 │                       │
 │────地址与读命令───────→│
 │                       │
 │      准备数据         │
 │                       │
 │←────返回数据──────────│
 │                       │
```

在这次事务中：

- CPU 是主设备；
- 主存是从设备。

如果 DMA 发起主存写入：

- DMA 控制器可以是主设备；
- 主存是目标设备。

**主设备的身份取决于谁发起当前事务，而不是哪个部件永远更重要。**

**二、时钟周期、总线周期、总线事务** 这三个概念必须分别理解。

**1. 时钟周期** 一个时钟信号周期的时间： $T_c=\frac{1}{f}$ 例如： $f=100\ \mathrm{MHz}$ 则： $T_c=10\ \mathrm{ns}$

**2. 总线周期** 完成一次规定的总线操作所需要的时间。假设一次总线周期占 4 个时钟周期： $T_{\mathrm{bus}}=4T_c$ 所以： $T_{\mathrm{bus}}=40\ \mathrm{ns}$

**3. 总线事务** 主从设备之间的一次完整逻辑交互。可能包括：

1. 申请总线；
2. 发送地址；
3. 发出控制命令；
4. 等待设备；
5. 传输一个或多个数据；
6. 结束事务。

要注意：

**一次总线事务不一定只传一次数据。** 突发传输就是典型例子。

**三、同步总线定时** 同步定时使用统一时钟组织通信。例如：

```text
时钟： T1 | T2 | T3 | T4

T1：传地址
T2：传读命令
T3：返回数据
T4：结束
```

各设备按照统一时序工作。优点：控制简单；时序明确；易于实现高速连续传输。缺点：

- 对设备速度差异适应性较弱；
- 需要处理慢速设备造成的等待。

**等待周期** 如果主存尚未准备好数据，可以插入等待周期。例如：

```text
T1 地址
T2 等待
T3 等待
T4 数据
```

注意：

**同步总线并不是绝对不能等待。** 其核心是通过统一时钟协调传输。

**四、异步总线定时** 异步通信不要求设备依靠同一个固定时钟完成全部动作。通常使用：

- 请求 REQ；
- 应答 ACK。

基本过程：

```text
主设备发出请求
       ↓
从设备检测请求
       ↓
从设备准备数据
       ↓
从设备发出应答
       ↓
主设备确认完成
```

适合：设备速度差异大；响应时间变化大；外设不能保证固定时钟内完成任务。

**模拟题** CPU、主存、打印机接口之间，哪种情况最适合异步定时？ A. I/O 接口与打印机交换信息 B. CPU 与高速主存交换信息 C. CPU 与传统同步 PCI 总线通信 D. 已由统一时钟严格控制的设备

**答案：A。** 原因：打印机可能等待机械动作、缓存、纸张处理等，响应时间不固定。异步握手能够适应这种差异。

**五、异步通信的三种互锁方式**

**1. 不互锁** 请求和应答信号可以依据预先约定的时序自行撤销。优点：

- 简单；
- 控制开销小。

缺点：

- 对设备响应时间要求严格；
- 可靠性较差。

**2. 半互锁** 通常请求方等待应答信号出现后才撤销请求。但应答方可能不等待请求撤销便自行撤销应答。可靠性和控制开销介于两者之间。

**3. 全互锁** 经典四相握手：

```text
REQ ↑
   ↓
ACK ↑
   ↓
REQ ↓
   ↓
ACK ↓
```

即：

1. 请求升高；
2. 应答升高；
3. 请求撤销；
4. 应答撤销。

**记忆：请求升、应答升、请求降、应答降。** 全互锁控制完整、可靠性高，但存在更多握手依赖。不能脱离具体实现就断言某种协议的实际吞吐率一定最低。

**六、半同步通信** 半同步方式结合：

- 同步时钟；
- 等待或就绪信号。

既通过时钟保持统一节拍，又允许慢设备请求更多等待周期。例如：

```text
T1：地址
T2：等待
T3：等待
T4：设备就绪
T5：数据
```

**真题：2015 年** 同步总线中，各设备能否各自独立提供互不协调的时钟？ 不能。同步通信需要统一或经过协调的时钟关系。否则不能保证正确的数据采样时刻。

**七、突发传输 Burst** 这是本章最重要的考点之一。

**1. 普通非突发传输** 假设读取连续 4 个数据。

```text
地址1 → 数据1
地址2 → 数据2
地址3 → 数据3
地址4 → 数据4
```

每次需要重新发送地址。

**2. 突发传输** 只发送一次首地址。 `首地址 → 数据1 → 数据2 → 数据3 → 数据4` 后续地址通常自动递增。它能够减少：地址重复传输；部分事务启动开销；重复命令开销。因此提高完整数据块的平均传输效率。

**3. 突发传输不等于改变总线宽度** 例如：数据总线仍然是 64 bit。一次传输仍然最多传： $8\ \mathrm{B}$ Burst 并不会让一条 64 bit 数据总线突然变成 512 bit。它的优势在于：

**通过连续传输摊薄事务开销。**

**八、分离事务 Split Transaction** 一次读取需要经历：

```text
主设备提出读请求
        ↓
从设备准备数据
        ↓
从设备返回结果
```

如果从设备准备数据需要很久，而总线一直被占用，就会浪费共享资源。分离事务把请求和响应拆开。

```text
主设备发送请求
        ↓
   释放互连资源
        ↓
从设备独立准备数据
        ↓
稍后返回响应
```

好处：减少等待期间的总线占用；提高总线利用率；支持其他事务在等待期间推进。但是：

**分离事务不保证单次读取延迟一定缩短。** 主要提升的是共享互连利用效率和并发能力。

**九、地址/数据复用** 某些总线使用同一组线路分别发送：

- 地址；
- 数据。

例如：

```text
周期1：发送地址

周期2：发送数据
```

优点：减少信号线；减少芯片引脚；降低成本。缺点：

- 地址与数据不能同时使用同一组复用线路；
- 可能增加事务时间。

**高频选择题** 下列方式哪些能够提高总线的数据传输率？ I. 增加数据总线宽度 II. 提高总线工作频率 III. 使用突发传输 IV. 地址/数据线复用

**答案：I、II、III。** 原因：

- I：一次能够传更多；
- II：每秒能够传更多次；
- III：减少事务开销，提高有效传输率；
- IV：主要减少线路，不能直接提高带宽。

要注意： III 通常提升的是有效事务吞吐率，而不一定提高数据线的物理峰值带宽。

## 总线定时与性能计算

### 总线性能指标与全部计算模型

这是整章计算题的核心。

**一、总线宽度** 设数据总线宽度为 $W$ bit。一次并行传输的数据量： $D=\frac{W}{8}\ \mathrm{B}$ 例如：

| 总线宽度 | 每次传输量 |
|---|---|
| 8 bit | 1 B |
| 16 bit | 2 B |
| 32 bit | 4 B |
| 64 bit | 8 B |
| 128 bit | 16 B |

注意：

**机器字长和数据总线宽度不一定相等。** 例如某 CPU 的机器字长为 32 bit，但外部存储器数据总线可以是 64 bit。

**二、总线时钟频率** 若时钟频率为 $f$： $T_c=\frac{1}{f}$ 常用换算：

| 频率 | 时钟周期 |
|---|---|
| 10 MHz | 100 ns |
| 50 MHz | 20 ns |
| 100 MHz | 10 ns |
| 200 MHz | 5 ns |
| 500 MHz | 2 ns |
| 1 GHz | 1 ns |

这一组应当熟练掌握。

**三、数据传输频率** 特别注意：

**时钟频率不一定等于数据传输频率。**

**情况一：每周期传一次** $f_t=f$

**情况二：每周期传两次** $f_t=2f$ 典型代表：DDR 双沿传输。

**情况三：每次传输需要 $N$ 个周期** $f_t=\frac{f}{N}$ 所以做题时，必须看：

- 一个时钟周期传几次？
- 还是传一次需要几个时钟周期？

这两个条件不能混淆。

**四、理论最大带宽** 最基本公式：

$$
\boxed{
B_{\max}=
\frac{W}{8}\times f_t
}
$$

其中：

- $W$：一次有效传输的数据位数；
- $f_t$：每秒能够完成的数据传输次数。

若每时钟周期传 $r$ 次：

$$
\boxed{
B_{\max}=
\frac{W}{8}\times f\times r
}
$$

如果有 $C$ 个真正独立、能够并行工作的通道：

$$
\boxed{
B_{\mathrm{total}}=
\frac{W}{8}\times f\times r\times C
}
$$

注意：不能仅仅因为系统存在多个设备就乘通道数量。必须满足通道实际独立且可并行传输。

**五、全双工带宽** 如果单方向带宽为 $B$： $B_{\rightarrow}=B$ $B_{\leftarrow}=B$ 那么双向同时传输的合计带宽： $B_{\mathrm{total}}=2B$ 但如果题目只问： “每个方向的数据传输率” 答案仍是 $B$。此外，如果物理传输位中包含校验位、编码开销，则还需要区分：

- 线路原始比特率；
- 有效数据率。

**六、有效带宽** 理论峰值只反映理想的数据传送能力。完整事务还可能包含：

- 地址阶段；
- 控制命令；
- 等待主存；
- 仲裁；
- 总线空闲；
- 数据阶段。

所以有效数据率为：

$$
\boxed{
B_{\mathrm{eff}}=
\frac{\text{有效传输的数据字节数}}
{\text{完整耗费时间}}
}
$$

总线利用率：

$$
\boxed{
\eta=
\frac{B_{\mathrm{eff}}}{B_{\max}}
}
$$

必须保证分子和分母使用相同方向、相同有效数据口径。

**七、非突发传输计算模型** 设：总共需要 $K$ 次数据传输；每次地址阶段用 $a$ 个周期；每次准备数据用 $m$ 个周期；每次数据阶段用 $d$ 个周期。若所有事务串行执行、互不重叠：

$$
\boxed{
N_{\mathrm{nonburst}}=
K(a+m+d)
}
$$

总时间：

$$
T_{\mathrm{nonburst}}=
\frac{K(a+m+d)}{f}
$$

**例题** 读取 4 个数据。每个数据需要：地址 1 周期；主存准备 6 周期；数据传送 1 周期。则： $N=4(1+6+1)=32$ 如果时钟周期为 1 ns： $T=32\ \mathrm{ns}$

**八、突发传输计算模型** 如果只需要一次地址和准备阶段，之后能够连续传输 $K$ 个数据单位：

$$
\boxed{
N_{\mathrm{burst}}=a+m+Kd
}
$$

总时间：

$$
T_{\mathrm{burst}}=
\frac{a+m+Kd}{f}
$$

例如：地址 1 周期；初始等待 6 周期；连续发送 4 个数据；每个数据 1 周期。则： $N=1+6+4=11$ 如果时钟周期为 1 ns： $T=11\ \mathrm{ns}$ 对比非突发： $32\ \mathrm{ns}\rightarrow11\ \mathrm{ns}$ 但是，这只有在题目明确允许后续数据连续传输时才成立。不能认为所有 Burst 都一定具有零等待的连续数据阶段。

**九、首数据延迟模型** 某些题目不是分别给地址与等待周期，而是直接说： “首个数据在第 $L$ 个周期完成，此后每隔 $d$ 个周期完成一次数据传输。” 此时：

$$
\boxed{
N=L+(K-1)d
}
$$

例如：第一个数据需要 5 周期；后续每 1 周期一个；共 8 个数据。则： $N=5+7=12$ 不要写成： $5+8=13$ 因为第一个数据已经包含在首延迟中。

**本章最重要的计算辨析** 一定要问：

**题目给出的首延迟，是否已经包含第一个数据的传输？** 如果已经包含，后面只有 $K-1$ 次。如果没有包含，数据阶段通常还有 $K$ 次。

**十、DDR 有效频率** DDR 可以在时钟上升沿和下降沿传送数据。若基础时钟为 $f$，每周期两次传送： $f_t=2f$ 但是如果题目直接给出的是： “有效传输率为 3200 MT/s” 就不能再乘 2。例如 DDR4-3200 的 3200 通常表示每秒 3200 百万次传输，而不是基础时钟 3200 MHz。

**一个记忆方法** 看到 MHz：先判断是物理时钟，还是题目沿用的有效工作频率表述。看到 MT/s：通常已经是传输次数，不再额外乘 DDR 系数。

### 总线历年真题精讲

**真题一：2009 年——总线周期与带宽**

**题目** 某系统总线：每个总线周期传输 4 B；一个总线周期占 2 个时钟周期；总线时钟频率为 10 MHz。求总线带宽。

**解答** 每秒时钟周期： $10\times10^6$ 每两个时钟周期完成一次传输：

$$
f_t=\frac{10\times10^6}{2}
=5\times10^6
$$

每次传 4 B： $B=4\times5\times10^6$ $\boxed{B=20\ \mathrm{MB/s}}$

**答案：20 MB/s。**

**核心考点** 不能直接写： $4\times10=40\ \mathrm{MB/s}$ 因为一次总线传输需要两个时钟周期。

**真题二：2012 年——地址/数据复用与突发传输**

**题目** 某同步总线：时钟频率 100 MHz；宽度 32 bit；地址与数据线复用；每传一个地址或数据需要一个时钟周期；支持突发传输。一次主存写事务传送 128 bit 数据，至少需要多少时间？

**第一步：求时钟周期**

$$
T_c=\frac{1}{100\times10^6}
=10\ \mathrm{ns}
$$

**第二步：计算数据传输次数** $K=\frac{128}{32}=4$

**第三步：加入地址阶段** 突发传输只发送一次首地址： $N=1+4=5$

**第四步：计算时间** $T=5\times10=50\ \mathrm{ns}$ $\boxed{50\ \mathrm{ns}}$

**易错分析** 错误一：只计算 4 次数据传输。这样得到 40 ns，遗漏地址阶段。错误二：每个数据重新发送地址。这样得到 80 ns，误把突发传输当成普通独立事务。

**真题三：2014 年——双沿传输带宽**

**题目** 某同步总线：地址/数据线共 32 根；时钟频率 66 MHz；每个时钟周期传输 2 次数据。求最大带宽。

**解答** 每次传输： $D=\frac{32}{8}=4\ \mathrm{B}$ 每秒传输次数： $f_t=66\times10^6\times2$ 所以： $B=4\times66\times10^6\times2$ $\boxed{B=528\ \mathrm{MB/s}}$

**核心考点** 地址/数据复用不改变数据阶段的 32 bit 宽度。题目问的是最大传输率，不是完整读写事务的平均效率。

**真题四：2019 年——三通道 DDR 存储器**

**题目** 某计算机采用三通道存储器。每通道：宽度 64 bit；DDR3-1333；按题设 1333 的有效数据传输频率计算。求总带宽。

**第一步：每次传输数据量** $D=\frac{64}{8}=8\ \mathrm{B}$

**第二步：单通道带宽** $B_1=1333\times10^6\times8$ $B_1=10.664\ \mathrm{GB/s}$

**第三步：三个通道** $B=3\times10.664$ $\boxed{B\approx32\ \mathrm{GB/s}}$

**特别注意** DDR3-1333 的 1333 在规范语境中对应约 1333 MT/s 的有效传输率。不能再乘以 2。本题最容易出现的错误就是重复计算 DDR 的双沿系数。

**真题五：2020 年——QPI 全双工与校验位**

**题目** 某 QPI 总线：全双工；每方向一次传输 20 bit；其中 16 bit 是有效数据；4 bit 是校验信息；时钟频率 2.4 GHz；每周期可传输两次。求双方向合计有效带宽。

**第一步：计算单方向每次有效数据** $D=\frac{16}{8}=2\ \mathrm{B}$ 不能使用 20 bit。因为题目求有效数据带宽，校验位不是有效负载。

**第二步：单方向带宽** $B_1=2.4\times10^9\times2\times2$ $B_1=9.6\ \mathrm{GB/s}$

**第三步：全双工** $B_{\mathrm{total}}=2\times9.6$ $\boxed{19.2\ \mathrm{GB/s}}$

**这道题同时考查四件事**

1. 总线时钟频率；
2. 每周期传输次数；
3. 有效数据与校验位；
4. 全双工两个方向。

**做这种题必须逐层分析，不能只看见几个数字就直接相乘。**

**真题六：2023 年——非突发主存块传输**

**题目** 某存储器总线：

- 宽度 64 bit；
- 频率 1 GHz；
- 地址传输占 1 个周期；
- 数据传输占 1 个周期；
- 主存准备一个 64 bit 数据需要 6 ns；
- 不支持突发传送；
- 主存块大小 32 B。

求读取一个主存块需要多少时间。

**第一步：每次传输数据量** $D=\frac{64}{8}=8\ \mathrm{B}$

**第二步：传输次数** $K=\frac{32}{8}=4$

**第三步：求一个时钟周期** $T_c=\frac{1}{1\times10^9}=1\ \mathrm{ns}$

**第四步：一次事务时间** 一次读取包括：地址 1 ns；准备数据 6 ns；传输数据 1 ns。所以： $T_1=1+6+1=8\ \mathrm{ns}$

**第五步：因为不支持 Burst** 每次都需要重新支付完整开销： $T=4\times8$ $\boxed{32\ \mathrm{ns}}$

**为什么不是 11 ns？** 如果错误地认为支持突发，会得到： $1+6+4=11\ \mathrm{ns}$ 但题目明确说明不支持突发传输。

**考试迁移** 今后遇到 Cache 块读取问题：

1. 看 Cache 块大小；
2. 看数据总线宽度；
3. 求传输次数；
4. 判断是否支持 Burst；
5. 判断各次事务是否可以重叠；
6. 再计算时间。

**真题七：2024 年——理论峰值与完整事务带宽**

**题目** 某存储器总线：时钟频率 420 MHz；宽度 64 bit；每个时钟周期传送 2 次数据；支持最多 8 次数据传输的突发事务；第 1 周期发送地址和命令；第 4 至第 7 周期连续传输 8 次数据。问总线带宽，即最大数据传输率。

**第一步：每次传输量** $D=\frac{64}{8}=8\ \mathrm{B}$

**第二步：每秒数据传输次数** $f_t=420\times10^6\times2$

**第三步：理论最大带宽** $B_{\max}=8\times420\times10^6\times2$ $\boxed{B_{\max}=6.72\ \mathrm{GB/s}}$

**为什么不能把 7 个周期直接算进最大带宽？** 因为题目问的是：

**数据传输通路的最大数据传输率。** 但可以进一步拓展：如果题目问这种完整 8 数据突发事务的平均有效带宽呢？ 一次事务数据量： $L=8\times8=64\ \mathrm{B}$ 完整事务持续 7 个周期： $T=\frac{7}{420\times10^6}$ 于是：

$$
B_{\mathrm{eff}}
=\frac{64}{7/(420\times10^6)}
$$

$\boxed{B_{\mathrm{eff}}=3.84\ \mathrm{GB/s}}$ 所以： $B_{\max}=6.72\ \mathrm{GB/s}$ $B_{\mathrm{eff}}=3.84\ \mathrm{GB/s}$ 二者不相等。利用率： $\eta=\frac{3.84}{6.72}$ $\boxed{\eta\approx57.14\%}$ 这里的有效带宽计算建立在完整事务串行重复、无事务间重叠的假设下。

**本题最重要的结论**

**最大带宽与完整事务平均有效带宽是两种不同问题。** 不能把计算完整事务的周期数直接套进理论峰值公式。

### I/O 系统与 I/O 接口

**一、为什么需要 I/O 接口？** CPU、主存与外设之间存在很多差异：速度差异；数据格式差异；控制时序差异；电气特性差异。例如： CPU 很快。键盘或鼠标的输入频率相对很低。磁盘和网卡则可能连续产生大量数据。因此需要 I/O 接口协调。典型结构：

```text
CPU / 主存
    │
    │ 系统互连
    │
I/O接口
    │
    │ 设备侧接口
    │
   外设
```

I/O 接口的核心作用：

**对主机提供标准访问入口，对外设适配具体的数据和控制方式。**

**二、I/O 接口的功能** 常见功能包括：

**1. 数据缓冲** 协调 CPU 与外设的速度差异。例如：设备先将数据写入接口缓冲寄存器。 CPU 稍后读取。

**2. 数据格式转换** 例如：串行转并行；并行转串行；数据编码转换。

**3. 设备控制** 向外设发送：

- 启动；
- 停止；
- 复位；
- 模式设置。

**4. 状态检测** 读取： Ready；Busy；Done；Error。

**5. 地址译码** CPU 给出端口地址。接口识别是否访问自身，以及访问哪个寄存器。

**三、I/O 端口** 这里的端口不是 USB 插孔。

**I/O 端口是 I/O 接口中能够被 CPU 直接访问的寄存器。** 通常包括三类。

**1. 数据端口** 用于交换数据。 `CPU ↔ 数据寄存器 ↔ 外设`

**2. 状态端口** 用于读取设备状态。例如：是否准备好；是否发生错误；是否完成操作。

**3. 控制端口** CPU 写入控制命令。例如：

- 开始；
- 停止；
- 复位。

**真题：2017 年** I/O 指令实现的数据传送通常发生在： A. I/O 设备与 I/O 端口之间 B. CPU 通用寄存器与 I/O 设备之间 C. 两个 I/O 端口之间 D. CPU 通用寄存器与 I/O 端口之间

**答案：D。** 因为独立编址的 I/O 指令通常访问的是接口内部端口。设备本体与端口之间的数据交换，由设备控制器负责协调。

**四、统一编址 MMIO** Memory-Mapped I/O。将设备寄存器映射进统一地址空间。例如：

```text
0x00000000 ───── RAM
   ...
0xF0000000 ───── I/O设备寄存器
```

CPU 使用普通访存指令访问设备寄存器。例如伪代码： `LOAD R1, [DEVICE_STATUS]` 从指令形式看，它与普通内存访问相似。但地址译码后，目标可能是设备寄存器。

**优点** 使用普通访存指令；不需要单独设计 I/O 指令；可使用普通访存寻址方式。

**缺点**

- 设备寄存器占用统一地址空间中的地址范围；
- 需要适当控制设备寄存器的缓存属性和访问顺序。

**重要辨析** MMIO 和主存共用地址空间，不代表设备寄存器就是 RAM。

**五、独立编址 PMIO** 主存和 I/O 端口分别使用不同的地址空间。 CPU 通常使用专门 I/O 指令。例如传统 x86： `IN AL, 0x60` `OUT 0x3F8, AL`

**特点** I/O 地址空间与主存分离；可以使用专门 I/O 指令；两个地址空间中可以存在相同的数值地址。例如：内存地址 0x60。 I/O 端口地址 0x60。两者可以同时存在，因为属于不同地址空间。

**六、统一编址与独立编址对比**

| 比较 | MMIO | PMIO |
|---|---|---|
| 地址空间 | 统一 | 分离 |
| 访问指令 | 普通访存指令 | 专用 I/O 指令 |
| 是否占统一地址空间 | 是 | 否 |
| 地址数值能否与内存重复 | 不作为两个独立空间理解 | 可以 |
| 编程方式 | 类似内存访问 | 显式端口访问 |

**真题：2014 年** 采用统一编址时，CPU 不能用访存指令访问 I/O 端口。判断：错误。正确结论：

**统一编址就是通过普通访存指令访问映射到地址空间中的 I/O 端口。**

### 四种 I/O 控制方式

**一、为什么需要不同的 I/O 方式？** 外设速度差异很大。例如：

- 键盘：数据量小，事件不频繁；
- 鼠标：小量事件输入；
- 磁盘：可能批量传输大量数据；
- 网卡：可能持续高速收发数据。

如果所有外设都由 CPU 一字一字地搬运，就会浪费大量 CPU 时间。所以存在四种经典 I/O 方式：

1. 程序查询；
2. 程序中断；
3. DMA；
4. 通道。

最关键的三个判断问题：

**问题一：设备准备数据时，CPU 是否必须等待？**

**问题二：数据由谁搬运？**

**问题三：CPU 在什么时候介入？**

**二、程序查询方式**

**1. 工作过程**

```text
CPU启动设备
    ↓
查询状态寄存器
    ↓
  就绪？
   /  \
 否    是
 │      │
继续   读取数据
查询     │
         ↓
     CPU搬运数据
```

**2. 数据传输路径**

```text
外设
 ↓
I/O接口
 ↓
CPU通用寄存器
 ↓
主存
```

CPU 既要检查状态，也要搬运数据。

**3. 主要缺点** 忙等待。设备尚未准备好时，CPU 仍反复执行查询程序。

**三、查询方式的时间计算** 假设：

- 设备数据率 $R\ \mathrm{B/s}$；
- 接口缓冲容量 $D\ \mathrm{B}$。

如果缓冲区只有一个，必须在新数据覆盖旧数据之前读取，则理想最大查询间隔为：

$$
\boxed{
T_{\max}=\frac{D}{R}
}
$$

例如： $D=4\ \mathrm{B}$ $R=2\times10^6\ \mathrm{B/s}$ 那么：

$$
T_{\max}
=\frac{4}{2\times10^6}
$$

$\boxed{T_{\max}=2\ \mu\mathrm{s}}$ 注意：这是假设数据持续均匀到达、单缓冲且查询处理足够及时的理想上限。实际系统要考虑调度延迟和抖动，通常需要留出时间余量。

**四、查询方式的 CPU 占用率** 若：每秒查询 $N$ 次；每次查询执行 $I$ 条指令；CPI 为 $c$；CPU 主频为 $f$。那么：

$$
\boxed{
\eta_{\mathrm{poll}}=
\frac{NIc}{f}
}
$$

其中 $f$ 单位为周期/s。例如：每秒查询： $N=5\times10^5$ 每次执行 10 条指令： $I=10$ CPI： $c=4$ 主频： $f=500\times10^6$ 因此：

$$
\eta=
\frac{5\times10^5\times10\times4}
{500\times10^6}
$$

$\boxed{\eta=4\%}$ 需要特别注意：

**每次查询的指令数必须乘 CPI。** 如果题目直接给出“每次查询消耗 40 个时钟周期”，就不能再乘 CPI。

### 程序中断方式

**一、中断解决了什么问题？** 查询方式最大的问题： CPU 必须主动反复检查设备。中断方式允许：

```text
CPU启动设备
    ↓
CPU执行其他程序
    ↓
设备准备好数据
    ↓
设备发出中断请求
    ↓
CPU响应中断
    ↓
执行中断服务程序
```

因此：

**中断让 CPU 不必忙等待设备。** 但是：

**中断方式下，数据通常仍然由 CPU 指令搬运。** 这两句话必须同时掌握。

**二、中断 I/O 的数据路径**

```text
外设
 ↓
I/O接口数据寄存器
 ↓
CPU通用寄存器
 ↓
主存
```

中断服务程序通过 CPU 指令完成数据交换。因此，中断方式主要节省的是等待开销，而不是逐次数据搬运开销。

**三、中断响应流程** 典型外部可屏蔽中断的处理过程：

1. 设备发出中断请求；
2. CPU 在允许的时刻检测请求；
3. 检查中断允许及屏蔽条件；
4. 接受中断；
5. 保存断点与必要处理器状态；
6. 确定中断服务程序入口；
7. 执行 ISR；
8. 恢复必要现场；
9. 中断返回。

**中断响应时机** 在经典 408 模型中：

**外部中断通常在当前指令执行结束后响应。** 不能认为设备发出请求后 CPU 立即中止当前指令。

**四、中断隐指令** 中断隐指令不是程序员编写的一条普通机器指令。它代表 CPU 硬件在中断响应阶段自动完成的一系列操作。典型包括：保存断点；保存必要处理器状态；根据体系结构进行中断屏蔽或状态更新；获取并转入 ISR 入口。

**高频陷阱** 保存所有通用寄存器是否一定由硬件完成？ 不一定。通常区分：

| 工作 | 典型完成者 |
|---|---|
| 检测中断请求 | 硬件 |
| 保存返回断点 | 硬件机制 |
| 保存必要状态 | 硬件机制 |
| 确定中断服务入口 | 硬件机制参与 |
| 保存通用寄存器 | 通常由软件完成 |
| 设备具体服务 | ISR 软件 |
| 恢复并返回 | 软件与硬件配合 |

不同 ISA 的自动保存范围不同，不能将某一种处理器的细节当作全部计算机的统一规则。

**五、单重中断与多重中断**

**1. 单重中断** CPU 执行当前 ISR 时，不允许其他可屏蔽中断嵌套打断。典型处理过程：

```text
响应中断A
    ↓
处理A
    ↓
返回原程序
```

**2. 多重中断** 执行低优先级 ISR 期间，允许满足条件的高优先级中断进入。

```text
主程序
   ↓
中断A
   ↓
更高优先级中断B
   ↓
处理B
   ↓
返回A
   ↓
返回主程序
```

因此：

**多重中断不能在整个 ISR 期间始终关中断。** 需要在保护现场、设置屏蔽条件等操作后，适当重新开放中断。

**六、中断响应优先级与处理优先级** 这是非常容易混淆的两个概念。

**1. 中断响应优先级** 当多个中断请求同时存在时，硬件首先响应谁。通常由：硬件排队器；中断控制器；中断线路优先级。等决定。

**2. 中断处理优先级** CPU 正在处理一个中断时，哪些其他中断允许嵌套进入。可以通过中断屏蔽字等机制改变。

**核心区别**

**中断屏蔽字主要影响允许哪些中断进入当前处理过程，不等于直接改变硬件固有的响应优先级。**

**七、真题：2011 年中断屏蔽字** 已知：中断响应优先级： `L0 > L1 > L2 > L3 > L4` 要求中断处理优先级： `L4 > L0 > L2 > L1 > L3` 屏蔽位： $M_i=1$ 表示屏蔽 $L_i$。求 L1 的 ISR 中应设置的屏蔽字。

**第一步：找到比 L1 高的处理优先级** 高于 L1 的：

- L4；
- L0；
- L2。

这些中断应该允许进入： $M_4=0,\quad M_0=0,\quad M_2=0$

**第二步：屏蔽自身和更低优先级** L1 自身： $M_1=1$ L3： $M_3=1$

**第三步：按位序排列** 题目要求： $M_4M_3M_2M_1M_0$ 代入： $0\ 1\ 0\ 1\ 0$ $\boxed{01010}$

**解题技巧** 不要按照题干给出的响应优先级顺序直接填写屏蔽字。应该先按处理优先级找出允许嵌套的中断，再按照屏蔽字规定的位序排列。

**八、中断与异常** 两者都可能改变 CPU 正常执行流程。但来源和检测时机不同。

| 比较 | 异常 | 外部中断 |
|---|---|---|
| 产生原因 | 当前指令执行相关事件 | 处理器外部事件 |
| 检测时机 | 通常在指令执行过程中 | 通常在指令边界 |
| 典型例子 | 缺页、除零、保护错 | 键盘、DMA完成 |
| 返回位置 | 取决于异常类型 | 通常继续后续指令 |

**高频真题** 下列哪项属于异常？ A. DMA 传输结束 B. 打印机缺纸 C. 缺页 D. 网卡接收完成

**答案：C。** 缺页通常是当前指令访存时发现页面不在主存。 OS 调入缺失页面后，需要重新执行尚未完成的访存指令。 DMA 完成则通常属于外部中断。

## I/O 接口与数据传送方式

### 中断方式的计算模型

**一、每秒中断次数** 设：

- 设备传输率为 $R\ \mathrm{B/s}$；
- 每次中断传输 $D\ \mathrm{B}$。

则：

$$
\boxed{
N_{\mathrm{int}}=\frac{R}{D}
}
$$

例如： $R=1\times10^6\ \mathrm{B/s}$ 每次传： $D=4\ \mathrm{B}$ 每秒需要： $N_{\mathrm{int}}=250000$ 次中断。

**二、每次中断开销** 假设： ISR 有 $I$ 条指令；CPI 为 $c$；其他响应开销为 $C_0$ 个 CPU 周期。则：

$$
\boxed{
C_{\mathrm{int}}=Ic+C_0
}
$$

注意：如果其他开销给的是“等效指令条数”，要先合并指令数再乘 CPI。如果给的是“时钟周期数”，不能重复乘 CPI。

**三、CPU 时间占比**

$$
\boxed{
\eta_{\mathrm{int}}=
\frac{R}{D}\times
\frac{C_{\mathrm{int}}}{f}
}
$$

也就是：

$$
\boxed{
\eta_{\mathrm{int}}=
\frac{\text{每秒中断次数}\times\text{每次CPU周期数}}
{\text{CPU每秒总周期数}}
}
$$

这个公式是中断 I/O 大题的核心。

**四、中断方式是否可行？** 如果每次中断耗费： $C_{\mathrm{int}}$ 个 CPU 周期，CPU 主频为： $f$ 那么 CPU 在全部时间用于处理该类中断的理想情况下，最多能处理：

$$
\boxed{
N_{\max}=\frac{f}{C_{\mathrm{int}}}
}
$$

次中断每秒。若每次处理 $D$ 字节：

$$
\boxed{
R_{\max}=
\frac{Df}{C_{\mathrm{int}}}
}
$$

如果设备实际速率： $R>R_{\max}$ 则不能持续用这种逐次中断方式完成传送。还需要注意：即使平均 CPU 占用率低于 100%，单缓冲系统也可能因服务延迟和中断抖动而丢失数据。因此 CPU 周期预算是必要检查，还要考虑缓冲和实时性。

### DMA 直接存储器访问

**一、为什么需要 DMA？** 中断方式虽然不要求 CPU 忙等待，但每次数据搬运仍由 CPU 完成。如果高速设备每秒需要传输几千万字节，就可能产生极其频繁的中断。例如：设备每秒传： $40\ \mathrm{MB}$ 每次中断只搬： $4\ \mathrm{B}$ 则每秒需要：

$$
\frac{40\times10^6}{4}
=10^7
$$

即：

**1000 万次中断。** 这会产生大量：中断响应；现场保存；中断服务；中断返回；CPU 数据搬运。 DMA 用专门的硬件控制逻辑完成批量数据传输。

**二、DMA 的核心思想** DMA： Direct Memory Access。直接存储器访问。基本结构：

```text
外设
 │
 ▼
I/O接口
 │
 ▼
DMA控制逻辑
 │
 ▼
系统互连
 │
 ▼
主存
```

在经典教材模型中：

**设备接口与主存之间的数据交换由 DMA 控制逻辑组织，不需要 CPU 通用寄存器逐次参与搬运。** CPU 的主要工作：设置参数；启动 DMA；处理传送完成或错误事件。

**三、DMA 工作的三个阶段**

**1. 预处理** CPU 配置 DMA 控制器。主要设置：主存起始地址；数据长度；数据传输方向；外设信息；工作模式。

**2. 数据传输** DMA 控制逻辑：申请总线；获得传输机会；控制设备与主存交换数据；更新主存地址；更新剩余数据计数。 CPU 可以执行其他不受资源冲突阻塞的操作。

**3. 后处理** 整块传送完成后： DMA 设置完成状态；通常发出完成中断；CPU 执行收尾处理。

**四、DMA 控制器的主要寄存器**

| 部件 | 作用 |
|---|---|
| MAR | 保存当前主存地址 |
| DC | 数据量或传输计数 |
| DR | 暂存数据 |
| CR | 控制命令、模式及状态 |
| I/O 控制逻辑 | 与外设协调 |
| 总线控制逻辑 | 请求和控制总线 |

**一个特别重要的细节** DMA 每次传送之后： MAR 增加多少？ 取决于：

- 主存编址单位；
- 每次传输的数据量。

例如：主存按字节编址；每次传送 32 bit；即每次传送 4 B。那么连续地址通常按：

```text
0x1000
0x1004
0x1008
0x100C
```

递增。不是必然每次加 1。同样，DC 是按字节、按字还是按传输次数计数，都要依据题目定义。

**五、DMA 请求与中断请求** 这是 408 高频概念辨析。

**DMA 请求** 主要目的是：

**申请数据传输资源或主存访问权。** 例如： `DMA → 总线仲裁器：` `请求使用共享总线`

**中断请求** 主要目的是：

**请求 CPU 执行中断处理程序。** 例如： `DMA → CPU：` `数据块已完成`

**关键对比**

| 项目 | DMA 请求 | 中断请求 |
|---|---|---|
| 目的 | 申请总线/主存访问 | 请求 CPU 处理事件 |
| 主要对象 | 总线仲裁或存储系统 | CPU |
| CPU 是否执行 ISR | 不必 | 接受中断后需要 |
| 可能出现次数 | 一块中可多次 | 一块完成后通常一次 |
| 典型时机 | 数据需要传输时 | 数据块完成或出错时 |

**经典 408 判断** 中断请求：通常在一条指令执行结束后的允许时刻响应。 DMA 请求：经典共享总线模型下，通常在当前总线周期或事务结束后协调交接使用权。这是两个不同的控制层次。

### DMA 与 CPU 争用主存

**一、为什么会发生争用？** CPU 要访问主存。 DMA 也要访问主存。如果两者共享同一不可同时服务的总线或存储资源，就需要仲裁。

```text
CPU ──────┐
          ├── 共享主存通路 ── 主存
DMA ──────┘
```

经典 DMA 主存访问方式可以分为三类。

**二、停止 CPU 访存：成组传送** DMA 获得总线后连续传送一批数据。

```text
时间 →

CPU | DMA DMA DMA DMA | CPU
```

优点：

- DMA 传输效率高；
- 多次数据传输可以摊薄仲裁开销。

缺点：

- CPU 在资源被 DMA 占用期间可能无法访问主存。

**三、周期挪用 Cycle Stealing** DMA 每次只占用一个或少量主存/总线周期。

```text
时间 →

CPU CPU DMA CPU CPU DMA CPU CPU DMA
```

特点： DMA 不长期独占总线；CPU 可以在其他周期访问主存；CPU 某些访存请求可能延迟。

**真题：2020 年** 某 DMA 方式：每次传送一个 512 B 数据块；I/O 接口缓冲寄存器为 32 bit；使用周期挪用。判断： “整个 512 B 传送期间，CPU 都不能访问主存。”

**错误。** 周期挪用只是在需要搬运数据时占用一个或少数总线周期。两次 DMA 访存之间，CPU 仍可能访问主存。如果一次传送 4 B： $N=\frac{512}{4}=128$ 在题设每 4 B 对应一次总线请求的模型下，需要 128 次这样的 DMA 传输机会。但这不表示 CPU 从第 1 次到第 128 次之间始终无法访存。

**四、透明传送** DMA 只使用 CPU 不需要主存或共享总线的空闲时间。优点：

- 对 CPU 主存访问影响较小。

缺点：

- DMA 传输速度依赖可用空闲时隙；
- 无法保证总有足够带宽。

**五、三种方式对比**

| 方式 | 主要原理 | 对 CPU 影响 |
|---|---|---|
| 成组传送 | DMA 连续占用一段时间 | 可能较长时间阻塞访存 |
| 周期挪用 | DMA 拿走少量周期 | 部分 CPU 访存延迟 |
| 透明传送 | 使用 CPU 空闲时隙 | 对 CPU 影响较小 |

**特别注意** CPU 因 DMA 周期挪用而等待，不等于 CPU 正在执行中断服务程序。这是不同机制。所以 DMA 题必须区分：

1. CPU 管理 DMA 的开销；
2. DMA 实际占用总线的时间；
3. CPU 因总线冲突产生的停顿。

三者不能简单认为相等。

### DMA CPU 占用率计算

设：设备数据率 $R\ \mathrm{B/s}$；DMA 每块大小 $B\ \mathrm{B}$；CPU 每块管理成本 $C$ 个时钟周期；CPU 主频 $f$。

**第一步：每秒块数**

$$
\boxed{
N_{\mathrm{DMA}}=\frac{R}{B}
}
$$

**第二步：每秒 CPU 管理周期数**

$$
C_{\mathrm{total}}
=
N_{\mathrm{DMA}}C
$$

**第三步：CPU 占用率**

$$
\boxed{
\eta_{\mathrm{DMA}}=
\frac{R}{B}\times\frac{C}{f}
}
$$

这是 DMA 计算题最重要的公式。

**和中断方式比较** 中断：

$$
\eta_{\mathrm{int}}
=
\frac{R}{D}\times
\frac{C_{\mathrm{int}}}{f}
$$

DMA：

$$
\eta_{\mathrm{DMA}}
=
\frac{R}{B}\times
\frac{C_{\mathrm{DMA}}}{f}
$$

DMA 之所以通常能够显著降低 CPU 管理开销，是因为： $B\gg D$ CPU 按块管理，而不是逐字节或逐数据字管理。但较大的 DMA 块也会带来缓冲容量、启动延迟等方面的取舍。

## 历年综合真题与计算

### 通道方式

**一、什么是通道？** 通道是一种能够执行专门 I/O 指令、组织复杂 I/O 操作的控制部件。可以理解为具有一定程序执行能力的专用 I/O 处理机构。通道不等于普通 CPU。其指令体系和任务范围主要针对 I/O 操作。

**二、通道的工作过程**

```text
CPU准备通道程序
      ↓
CPU启动通道
      ↓
通道执行通道程序
      ↓
通道控制外设传输
      ↓
数据在外设与主存之间交换
      ↓
任务完成后中断CPU
```

通道程序可以描述：访问哪个设备；执行什么 I/O 操作；数据存放地址；传输长度；后续操作。

**核心区别** DMA 控制器通常负责按配置自动完成一个数据块传输。通道能够执行通道程序，组织更复杂的 I/O 操作序列。因此通道自主能力更强。

**三、四种 I/O 方式总对比**

| 方式 | CPU 等待？ | 谁搬数据？ | CPU 介入粒度 |
|---|---|---|---|
| 程序查询 | 忙等待 | CPU | 每次查询和传送 |
| 程序中断 | 不必忙等待 | CPU | 每次中断 |
| DMA | 不必忙等待 | DMA 逻辑 | 数据块首尾 |
| 通道 | 不必忙等待 | 通道控制的数据通路 | 整个 I/O 任务 |

最重要的记忆方法：

**查询：CPU 等，CPU 搬。**

**中断：CPU 不等，CPU 搬。**

**DMA：CPU 不等，DMA 搬。**

**通道：CPU 启动任务，通道组织执行。** 注意这里讨论的是经典教材中的数据搬运模型。现代操作系统中的中断、DMA、缓冲和设备驱动可能组合使用，并不是四种方式完全互斥。

### 历年综合大题精讲

**大题一：2009 年第 43 题——中断与 DMA 的 CPU 占用率**

**题目条件** CPU：

- 主频 500 MHz；
- CPI = 5。

设备：传输速率 0.5 MB/s；每次中断处理 32 bit 数据；中断服务程序 18 条指令；其他开销相当于 2 条指令。问中断方式 CPU 占用率。之后设备速率提高到： $5\ \mathrm{MB/s}$ 改用 DMA：每块 5000 B；每块 CPU 管理开销为 500 个时钟周期；忽略 DMA 与 CPU 访存冲突。求 DMA 的 CPU 占用率。

**第（1）问：中断方式** 每次传输： $D=\frac{32}{8}=4\ \mathrm{B}$ 每秒中断次数： $N=\frac{0.5\times10^6}{4}$ $N=125000$ 每次中断等效指令条数： $I=18+2=20$ CPI = 5： $C=20\times5=100$ 个时钟周期。每秒 CPU 总周期： $f=500\times10^6$ 因此：

$$
\eta=
\frac{125000\times100}
{500\times10^6}
$$

$\boxed{\eta=2.5\%}$

**第（2）问：DMA** 设备速率： $R=5\times10^6\ \mathrm{B/s}$ 每块： $B=5000\ \mathrm{B}$ 每秒块数： $N=\frac{5\times10^6}{5000}=1000$ 每块 CPU 开销： $C=500$ 总周期： $1000\times500=500000$ 所以：

$$
\eta=
\frac{500000}{500\times10^6}
$$

$\boxed{\eta=0.1\%}$

**最终答案**

| 方式 | CPU 占用率 |
|---|---|
| 中断 | 2.5% |
| DMA | 0.1% |

**这道题真正考查什么？** 不是简单背 DMA 快。而是理解：

**中断按小数据单位支付 CPU 开销，DMA 按数据块支付 CPU 开销。** 还有一个易错点：第一问的额外开销是“等效 2 条指令”，需要乘 CPI。第二问的 500 已经是“时钟周期”，不能再乘 CPI。

**大题二：2016 年第 44 题——串行通信与时间重叠** 这是一道非常值得反复研究的综合题。

**题目条件** CPU： $f=50\ \mathrm{MHz}$ $CPI=4$ 设备 D：传送 7 bit ASCII 字符；1 bit 奇校验；1 bit 停止位；每字符准备时间 0.5 ms。中断方式：每字符产生一次中断；中断响应 10 周期；ISR 有 20 条指令；第 15 条指令启动设备下一次工作。求：

1. 每个字符在通信线上传多少位？
2. 每秒最多向接口送入多少字符？
3. 接收 1000 字符任务的总历时？
4. CPU 实际用于此任务多少周期？

**第（1）问：串行帧位数** 异步串行通信通常包括：起始位；数据位；可选校验位；停止位。题目中： $L=1+7+1+1$ $\boxed{L=10\ \mathrm{bit}}$ 其中：

- 7 位是 ASCII 数据；
- 另外 3 位属于传输开销。

**第（2）问：每秒字符数** 设备准备一个字符： $0.5\ \mathrm{ms}$ 因此： $N=\frac{1}{0.5\times10^{-3}}$ $\boxed{N=2000\ \mathrm{字符/s}}$ 注意：这个结果是设备工作速率给出的上限。若另有线路 bit/s 限制，还需要检查串行链路能否承载。

**第（3）问：总任务历时** 先将设备工作时间换算为 CPU 时钟周期。

$$
C_D=
0.5\times10^{-3}\times50\times10^6
$$

$\boxed{C_D=25000}$ 即设备处理一个字符需要 25000 个 CPU 时钟周期的实际时间。 CPU 中断响应： $10$ 周期。 ISR 第 15 条指令启动下一次设备工作。所以重新启动前需要：

$$
C_{\mathrm{restart}}
=10+15\times4
$$

$\boxed{C_{\mathrm{restart}}=70}$ 周期。

**关键理解** ISR 有 20 条指令。但设备在第 15 条指令完成时就重新开始工作。后面 5 条指令的执行可以与设备下一轮工作重叠。因此不能把整个 ISR 的 20 条指令全部算成设备下一次工作之前必须等待的开销。

**画出时间关系**

```text
首次启动设备
     │
     ├────设备工作25000周期────┐
     │                         │
     │                    字符到达
     │                         │
     │                    中断响应10
     │                         │
     │                    ISR前15条60
     │                         │
     │                    启动下一字符
     │                         │
     │                    ├────设备工作25000
     │                    │
     │                    ISR后5条20
     │                    │
     │                    CPU可继续执行其他程序
```

设备工作与 ISR 后半部分存在时间重叠。如果总共接收 1000 个字符，计时从第一次启动开始，到最后一个字符对应 ISR 完成结束：

$$
C_{\mathrm{total}}
=
1000\times25000
+999\times70
+(10+20\times4)
$$

计算：

$$
C_{\mathrm{total}}
=
25000000+69930+90
$$

$$
\boxed{
C_{\mathrm{total}}=25070020
}
$$

即约： $2.507\times10^7$ 个时钟周期。因为题目问“大约”，通常也可以写成约 2507 万周期。

**第（4）问：CPU 实际忙碌周期** 每个字符 CPU 必须完成：

- 中断响应 10 周期；
- 20 条 ISR 指令，每条平均 4 周期。

所以：

$$
C_{\mathrm{CPU,one}}
=10+20\times4
$$

$C_{\mathrm{CPU,one}}=90$ 1000 个字符：

$$
C_{\mathrm{CPU}}
=1000\times90
$$

$$
\boxed{
C_{\mathrm{CPU}}=90000
}
$$

**最终对比**

| 指标 | 周期数 |
|---|---:|
| 任务总历时 | 约 25,070,020 |
| CPU 实际处理开销 | 90,000 |

二者相差巨大。原因：设备工作期间，CPU 可以执行其他程序。

**这道题最重要的思想**

**任务从开始到结束的总时间，不等于 CPU 实际为任务执行指令的时间。** CPU 的实际占用与设备等待可以发生重叠。这也是操作系统、流水线与 I/O 综合题中非常重要的思想。

**大题三：2018 年第 43 题——查询、中断、DMA 三合一**

**题目条件** CPU： $f=500\ \mathrm{MHz}$ $CPI=4$ 设备 A： $R_A=2\ \mathrm{MB/s}$ 设备 B： $R_B=40\ \mathrm{MB/s}$ 两设备接口各有 32 bit 缓冲寄存器。

**第（1）问：设备 A 程序查询** 每次缓冲： $D=4\ \mathrm{B}$ 设备速率： $R_A=2\times10^6$ 最长查询间隔： $T_{\max}=\frac{4}{2\times10^6}$ $\boxed{T_{\max}=2\ \mu\mathrm{s}}$ 每秒至少处理：

$$
N=\frac{2\times10^6}{4}
=5\times10^5
$$

次。每次查询需要至少 10 条指令。 CPI = 4： $C=10\times4=40$ CPU 占用率：

$$
\eta_A=
\frac{5\times10^5\times40}
{500\times10^6}
$$

$\boxed{\eta_A=4\%}$

**第（2）问：设备 B 使用中断** 设备速率： $R_B=40\times10^6\ \mathrm{B/s}$ 每次处理： $D=4\ \mathrm{B}$ 每秒中断次数： $N=\frac{40\times10^6}{4}$ $N=10^7$ 每次响应和处理至少消耗 400 个时钟周期。因此每秒需要：

$$
C_{\mathrm{required}}
=10^7\times400
$$

$$
C_{\mathrm{required}}
=4\times10^9
$$

CPU 每秒只有： $500\times10^6$ 个周期。理论资源需求比例：

$$
\eta=
\frac{4\times10^9}
{500\times10^6}
$$

$\boxed{\eta=800\%}$ 这意味着所需处理能力达到 CPU 总预算的 8 倍。因此：

**无法以逐 4 B 中断方式持续完成设备 B 的传输。** 800% 不是 CPU 真的能够被占用 800%。它表示需求严重超出 CPU 能力。

**第（3）问：B 改用 DMA** 每块： $B=1000\ \mathrm{B}$ 每秒块数： $N=\frac{40\times10^6}{1000}$ $N=40000$ 每块 CPU 管理开销： $C=500$ 所以：

$$
\eta=
\frac{40000\times500}
{500\times10^6}
$$

$\boxed{\eta=4\%}$

**最终结果**

| 问题 | 结论 |
|---|---|
| A 最大查询间隔 | 2 μs |
| A 查询方式 CPU 占用率 | 至少 4% |
| B 逐缓冲中断方式 | 不可持续 |
| B 中断理论 CPU 需求 | 800% |
| B DMA 管理开销占比 | 满载时 4% |

**这道题的核心思路** 第一步：统一传输单位。第二步：用设备速率除以每次数据量，得到事件频率。第三步：计算每次事件的 CPU 开销。第四步：除以 CPU 总周期预算。第五步：判断可行性。这套方法可以推广到大量新的 I/O 计算题。

## 拓展综合题与跨章节联系

### 2027 王道模拟综合题——两种存储器总线比较

2027 王道冲刺模拟八套卷第 4 套第 44 题，是一道很有代表性的综合题。

**一、题目条件** CPU：

- 字长 32 bit；
- 时钟频率 100 MHz。

总线 A：地址与数据复用；数据通路 64 bit；一次最多传 8 个 32 bit 字；地址 1 周期；等待 2 周期；后续每周期传 2 字。总线 B： 32 bit 地址总线；32 bit 数据总线；地址与数据线分离。读：地址 1 周期；等待 2 周期；每周期传 1 字。写：首周期同时发送地址与第一个字；再等待 2 周期完成第一个字写入；后续每周期再传 1 字。假设：不同事务串行执行，不发生跨事务重叠。

**二、理论峰值带宽** 总线 A：每周期传： $64\ \mathrm{bit}=8\ \mathrm{B}$ 所以： $B_A=8\times100\times10^6$ $\boxed{B_A=800\ \mathrm{MB/s}}$ 总线 B：每周期传： $32\ \mathrm{bit}=4\ \mathrm{B}$ 因此： $B_B=4\times100\times10^6$ $\boxed{B_B=400\ \mathrm{MB/s}}$

**三、单字读事务** 一个字： $32\ \mathrm{bit}=4\ \mathrm{B}$ 总线 A：地址 1 周期；等待 2 周期；数据 1 周期。共： $N_A=4$ 总线 B 相同： $N_B=4$ 时钟周期： $T_c=10\ \mathrm{ns}$ 有效数据率： $R=\frac{4}{4\times10\times10^{-9}}$ $\boxed{R=100\ \mathrm{MB/s}}$ 两条总线单字读有效速率相同。

**为什么 A 更宽却没有更快？** 因为只传一个 32 bit 字。 A 的 64 bit 数据通路没有被充分利用。这说明：

**总线宽度越大，不代表所有事务的延迟都一定更低。**

**四、单字写事务** 总线 A： $N_A=1+2+1=4$ 所以： $R_A=100\ \mathrm{MB/s}$ 总线 B：首周期同时发送地址与第一个字。随后等待 2 周期。共： $N_B=3$ 因此：

$$
R_B=
\frac{4}{3\times10\times10^{-9}}
$$

$$
\boxed{
R_B\approx133.33\ \mathrm{MB/s}
}
$$

**重要结论** 虽然 B 的数据总线只有 32 bit，但其单字写事务的有效速率可以高于 A。原因是：

**B 的首周期地址与数据能够重叠。** 比较实际效率必须看完整时序，不能只看总线宽度。

**五、完整 8 字数据块** 总数据量： $L=8\times4=32\ \mathrm{B}$ 总线 A：每周期传 2 字。数据阶段： $\frac{8}{2}=4$ 周期。完整事务： $N_A=1+2+4=7$ 有效速率： $R_A=\frac{32}{7\times10^{-8}}$

$$
\boxed{
R_A\approx457.14\ \mathrm{MB/s}
}
$$

总线 B：读： $N_{\mathrm{read}}=1+2+8=11$ 写： $N_{\mathrm{write}}=1+2+7=10$ 如果 60% 为读事务、40% 为写事务：

$$
\overline N
=0.6\times11+0.4\times10
$$

$\overline N=10.6$ 所以长期平均有效速率： $R_B=\frac{32}{10.6\times10^{-8}}$

$$
\boxed{
R_B\approx301.89\ \mathrm{MB/s}
}
$$

**最终结果**

| 指标 | 总线 A | 总线 B |
|---|---:|---:|
| 理论峰值带宽 | 800 MB/s | 400 MB/s |
| 单字读 | 100 MB/s | 100 MB/s |
| 单字写 | 100 MB/s | 133.33 MB/s |
| 8 字块混合读写 | 457.14 MB/s | 301.89 MB/s |

**本题最值得记住的解题技巧** 长期混合负载的平均速率应该使用：

$$
\boxed{
R_{\mathrm{avg}}=
\frac{\text{总有效数据量}}
{\text{总耗时}}
}
$$

如果每个事务的数据量相同，可以先对事务耗时进行加权平均。不能简单把读速率和写速率做算术加权平均。原因是：

**速率的分母是时间，不是事务次数。**

### 跨章节综合——Cache、主存与 DMA

**一、Cache 缺失为什么与总线有关？** CPU 访问 Cache 时：

- 命中：直接获得数据；
- 缺失：需要从下一层存储器读取数据块。

例如： Cache 块： $64\ \mathrm{B}$ 数据总线： $64\ \mathrm{bit}$ 每次传： $8\ \mathrm{B}$ 所以： $K=\frac{64}{8}=8$ 次数据传输。但总缺失代价还取决于：地址阶段；主存首次访问延迟；后续数据传输间隔；是否允许突发；主存是否存在并行与流水能力。因此：

$$
\boxed{
\text{Cache缺失代价}
\neq
\frac{\text{块大小}}{\text{理论峰值带宽}}
}
$$

在只估算理想纯数据传输时间时，可以使用数据量除以带宽。但完整访存延迟通常还要加首字等待和协议开销。

**二、CPU 与 DMA 的总线竞争** 假设： CPU 每秒需要 1 亿次主存访问；DMA 每秒需要 2000 万次；每次访问占一个总线周期；总线每秒提供 1.5 亿个周期；访问互不重叠，忽略其他开销。总需求： $N=100\times10^6+20\times10^6$ $N=120\times10^6$ 利用率：

$$
\eta=
\frac{120\times10^6}{150\times10^6}
$$

$\boxed{\eta=80\%}$ 从平均资源容量看，总线能够承载这两类请求。但是：

**平均总线利用率为 80%，不代表任何时刻都没有排队。** 如果多个请求在同一时刻到达，仍然可能产生仲裁等待。

**三、CPU 占用率与总线利用率不能混为一谈** 例如： DMA 每秒传： $30\ \mathrm{MB/s}$ 总线一次传： $8\ \mathrm{B}$ 每秒总线数据传输次数：

$$
N=\frac{30\times10^6}{8}
=3.75\times10^6
$$

总线频率： $60\ \mathrm{MHz}$ 每周期最多一个数据传输。那么理想数据周期占比：

$$
\eta_{\mathrm{bus}}
=
\frac{3.75\times10^6}{60\times10^6}
$$

$\boxed{\eta_{\mathrm{bus}}=6.25\%}$ 但不能直接说： “DMA 让 CPU 损失了 6.25% 的性能。” 因为： CPU 可能正在执行寄存器运算；CPU 可能命中 Cache；CPU 可能没有访问共享主存；DMA 使用总线时可能恰好不与 CPU 冲突。只有给出 CPU 访存行为、仲裁方式、停顿周期等条件，才能推导 CPU 因 DMA 造成的额外停顿。

### 串行帧与有效数据率

**一、串行帧格式** 经典异步串行通信可以抽象为： `起始位 | 数据位 | 校验位 | 停止位` 设：数据位数为 $d$；起始位数为 $s$；校验位数为 $p$；停止位数为 $t$。每帧总位数：

$$
\boxed{
L=s+d+p+t
}
$$

如果采用：起始位 1；数据位 8；校验位 1；停止位 1。则： $L=11\ \mathrm{bit}$ 其中有效数据只有： $8\ \mathrm{bit}$

**二、字符传输率** 若线路二进制比特率： $R_b$ 则线路每秒能够发送的完整字符数约为：

$$
\boxed{
N_{\mathrm{char}}=
\frac{R_b}{L}
}
$$

例如： $R_b=9600\ \mathrm{bit/s}$ 每帧： $L=11$ 那么：

$$
N_{\mathrm{char}}
=\frac{9600}{11}
$$

$$
\boxed{
N_{\mathrm{char}}\approx872.73\ \mathrm{字符/s}
}
$$

这是连续传输的平均上限；在固定整数秒内计数完整字符，还要考虑帧边界。

**三、有效数据率** 若每帧只有 $d$ 个有效数据位：

$$
\boxed{
R_{\mathrm{payload}}=
R_b\times\frac{d}{L}
}
$$

例如：

$$
R_{\mathrm{payload}}
=9600\times\frac{8}{11}
$$

$$
\boxed{
R_{\mathrm{payload}}\approx6981.82\ \mathrm{bit/s}
}
$$

**高频易错** 波特率严格来说是每秒符号数。只有在每个符号携带 1 bit 的二进制传输条件下，才可以直接将波特率等同于 bit/s。题目如果给的是复杂调制方式，还要考虑每个符号携带的比特数。

### 补充高价值综合题

**题目一：总线理论带宽与实际带宽** 某总线：

- 宽度 128 bit；
- 频率 200 MHz；
- 每周期传送两次数据；
- 每次突发传送 8 个数据单位；
- 地址阶段 1 周期；
- 等待阶段 3 周期；
- 数据阶段每周期传送 2 个数据单位；
- 事务之间不重叠。

求：

1. 理论最大带宽；
2. 一次突发传送的数据量；
3. 事务周期数；
4. 事务有效带宽。

<Callout type="warn" title="峰值带宽与有效吞吐量">

**解答** 每次传输： $D=\frac{128}{8}=16\ \mathrm{B}$ 理论带宽：

</Callout>

$$
B_{\max}
=16\times200\times10^6\times2
$$

$\boxed{B_{\max}=6.4\ \mathrm{GB/s}}$ 一次突发数据： $L=16\times8=128\ \mathrm{B}$ 地址： $1$ 等待： $3$ 数据： $\frac{8}{2}=4$ 总周期： $N=1+3+4=8$ 时钟周期： $T_c=5\ \mathrm{ns}$ 总时间： $T=8\times5=40\ \mathrm{ns}$ 有效带宽：

$$
B_{\mathrm{eff}}
=
\frac{128}{40\times10^{-9}}
$$

$$
\boxed{
B_{\mathrm{eff}}=3.2\ \mathrm{GB/s}
}
$$

利用率： $\boxed{\eta=50\%}$

**迁移技巧** 如果只改变总线宽度，还要明确题目要求保持：

- 数据单位数量不变；
- 还是总数据字节数不变。

两种条件下需要的数据传输次数可能不同。

**题目二：DMA 至少需要多大的块？** 设： CPU 主频 600 MHz；设备速率 1.6 MB/s；中断每次处理 8 B；中断总 CPU 成本 90 周期；DMA 每块 CPU 管理成本 700 周期。问： DMA 管理开销低于中断方式时，DMA 块至少需要多大？

**解题思路** 中断方式每字节 CPU 成本： $\frac{90}{8}$ DMA 方式每字节 CPU 成本： $\frac{700}{B}$ 希望 DMA 更省 CPU： $\frac{700}{B}<\frac{90}{8}$ 交叉相乘： $700\times8<90B$ $B>\frac{5600}{90}$ $B>62.22$ 如果 DMA 块必须是 8 B 的整数倍： $\boxed{B_{\min}=64\ \mathrm{B}}$

**这道题的本质** 比较两种方式的 CPU 管理成本，不一定要先算完整 CPU 占用率。如果设备数据率和 CPU 主频相同，可以直接比较：

$$
\boxed{
\text{每字节CPU周期成本}
}
$$

这样更快。

**题目三：CPU 中断能力不足时怎么办？** 某设备： $R=40\ \mathrm{MB/s}$ 每次中断处理 4 B。 CPU： $f=500\ \mathrm{MHz}$ 每次中断消耗： $C=160$ 周期。 CPU 最多允许将 80% 时间用于中断处理。问：如果采用中断合并，每次中断处理 $k$ 个 4 B 数据单位，求最小 $k$。

**解答** 原始每秒中断次数：

$$
N=\frac{40\times10^6}{4}
=10^7
$$

合并 $k$ 个单位： $N_k=\frac{10^7}{k}$ CPU 占用率：

$$
\eta=
\frac{(10^7/k)\times160}
{500\times10^6}
$$

整理： $\eta=\frac{3.2}{k}$ 要求： $\frac{3.2}{k}\le0.8$ 因此： $k\ge4$ $\boxed{k_{\min}=4}$ 一次中断至少处理： $4\times4=16\ \mathrm{B}$

**注意** 中断合并要求足够的设备缓冲能力。如果接口仍然只有一个 4 B 寄存器，没有 FIFO 或等价缓冲机制，不能仅靠软件“等四次再中断”，否则早期数据可能被覆盖。

**题目四：总线吞吐率与 CPU 停顿** 某系统：总线 100 MHz；每周期最多传 8 B；DMA 持续传输 50 MB/s。求：

1. 理想总线数据传输利用率；
2. 能否据此算 CPU 停顿比例？

**解答** 理论总线数据带宽： $B_{\max}=100\times10^6\times8$ $B_{\max}=800\ \mathrm{MB/s}$ DMA 利用率：

$$
\eta=
\frac{50}{800}
$$

$\boxed{\eta=6.25\%}$ 但这只能说明在忽略地址和仲裁开销时，DMA 至少需要占用约 6.25% 的数据传输能力。不能据此直接得到 CPU 的停顿率。因为缺少 CPU 访存分布和仲裁信息。

| 控制总线所有信号都单向 | 不同控制信号可以有不同方向 |
| CPU 永远是主设备 | DMA 也可能成为主设备 |
| 一个总线周期等于一个时钟周期 | 总线周期可能包含多个时钟周期 |
| 同步总线不能插入等待 | 可以插入等待周期 |
| 异步总线一次握手只能传一位 | 可以传一个数据单位 |

| 全双工任何问题都乘2 | 只有双向合计才相加 |
| 校验位都属于有效数据 | 有效负载需排除校验开销 |

### 全章公式总表

**一、总线基础** 时钟周期： $\boxed{T_c=\frac{1}{f}}$ 每次数据量： $\boxed{D=\frac{W}{8}}$ 按字节编址寻址空间： $\boxed{S=2^n\ \mathrm{B}}$ 其中 $n$ 为地址线数量。

**二、总线带宽** 每周期传 $r$ 次：

$$
\boxed{
B_{\max}=\frac{W}{8}fr
}
$$

多个独立通道：

$$
\boxed{
B_{\mathrm{total}}=
C\frac{W}{8}fr
}
$$

双向全双工合计：

$$
\boxed{
B_{\mathrm{total}}=
B_{\rightarrow}+B_{\leftarrow}
}
$$

有效带宽：

$$
\boxed{
B_{\mathrm{eff}}=
\frac{L}{T_{\mathrm{total}}}
}
$$

利用率：

$$
\boxed{
\eta=
\frac{B_{\mathrm{eff}}}{B_{\max}}
}
$$

**三、突发与非突发** 非突发：

$$
\boxed{
T_{\mathrm{nonburst}}
=
\frac{K(a+m+d)}{f}
}
$$

突发：

$$
\boxed{
T_{\mathrm{burst}}
=
\frac{a+m+Kd}{f}
}
$$

首数据延迟已经包括首次传输时：

$$
\boxed{
T=\frac{L+(K-1)d}{f}
}
$$

注意这里的 $L$ 表示首数据所需周期数，和其他公式中表示数据长度的 $L$ 不同。

**四、串行通信** 帧长：

$$
\boxed{
L=s+d+p+t
}
$$

字符率：

$$
\boxed{
N_{\mathrm{char}}=\frac{R_b}{L}
}
$$

有效数据率：

$$
\boxed{
R_{\mathrm{payload}}
=
R_b\frac{d}{L}
}
$$

**五、程序查询** 最大理想查询间隔：

$$
\boxed{
T_{\max}=\frac{D}{R}
}
$$

CPU 占用率：

$$
\boxed{
\eta_{\mathrm{poll}}
=
\frac{NIc}{f}
}
$$

**六、中断** 中断次数：

$$
\boxed{
N_{\mathrm{int}}=\frac{R}{D}
}
$$

每次 CPU 开销：

$$
\boxed{
C_{\mathrm{int}}=Ic+C_0
}
$$

CPU 占用率：

$$
\boxed{
\eta_{\mathrm{int}}
=
\frac{RC_{\mathrm{int}}}{Df}
}
$$

理想最大中断频率：

$$
\boxed{
N_{\max}=\frac{f}{C_{\mathrm{int}}}
}
$$

**七、DMA** 每秒块数：

$$
\boxed{
N_{\mathrm{DMA}}=\frac{R}{B}
}
$$

CPU 管理占用率：

$$
\boxed{
\eta_{\mathrm{DMA}}
=
\frac{RC_{\mathrm{DMA}}}{Bf}
}
$$

理想数据周期需求：

$$
\boxed{
N_{\mathrm{bus}}=
\frac{R}{D_{\mathrm{bus}}}
}
$$

最后一式的使用前提是每次总线传输均满载，且忽略协议等额外开销。

### 考研做题方法总结

**一、看到总线计算题** 按照以下顺序处理：

**第一步：识别题目要求** 到底问：

- 理论最大带宽；
- 有效数据率；
- 一次事务时间；
- 读取整个主存块时间；
- 总线利用率？

不要混为一谈。

**第二步：计算每次数据量** 由位宽换算： $D=\frac{W}{8}$

**第三步：确定每秒传输次数** 判断：每周期一次；每周期两次；一次需要多个周期；给出的是否已经是有效传输频率。

**第四步：确定事务开销** 判断：

- 地址；
- 命令；
- 等待；
- 数据；
- 仲裁；
- 是否可重叠。

**第五步：判断 Burst** 重点看是否只给一次首地址。

**第六步：检查单位** 尤其注意： bit 与 Byte；MHz 与 MT/s；MB 与 MiB；GB 与 GiB；ns 与 μs。

**二、看到 I/O 计算题** 按照以下顺序：

**第一步：设备数据率** 统一为： $R\ \mathrm{B/s}$

**第二步：每次处理多少数据** 程序查询：看缓冲容量。中断：看每次中断处理多少字节。 DMA：看每块传送多少字节。

**第三步：计算每秒事件数量** $N=\frac{R}{D}$

**第四步：计算每次 CPU 周期数** 可能需要： $C=I\times CPI$

**第五步：计算 CPU 占用率** $\eta=\frac{NC}{f}$

**第六步：判断是否存在额外限制** 例如： CPU 处理能力是否足够；缓冲区是否足够；设备数据是否会覆盖；DMA 是否争用主存；总线带宽是否足够；工作过程是否发生时间重叠。

### 最后的知识体系总结

整章真正需要建立的是下面这套逻辑。

**一、总线解决三个问题**

**谁来传？** CPU；DMA；其他主设备。通过总线仲裁决定资源使用权。

**怎么传？** 同步还是异步；串行还是并行；一次传一个还是 Burst；是否支持分离事务；是否能重叠多个操作阶段。

**传多快？** 由：数据宽度；数据传输频率；有效负载比例；事务开销。共同决定。

**二、I/O 解决三个问题**

**CPU 是否等待设备？** 查询方式：通常忙等待。中断、DMA、通道： CPU 通常可以执行其他工作。

**数据是谁搬的？** 查询： CPU。中断： CPU。 DMA： DMA 控制逻辑。通道：通道组织控制的数据通路。

**CPU 什么时候介入？** 查询：反复查询和搬运。中断：响应中断并执行 ISR。 DMA：配置、启动、传送完成或出错后处理。通道：启动通道程序并处理任务完成事件。

**三、最重要的三个数学模型**

**模型一：带宽**

$$
\boxed{
\text{带宽}
=
\text{每次数据量}
\times
\text{每秒传输次数}
}
$$

**模型二：完整事务时间**

$$
\boxed{
\text{总时间}
=
\text{不可重叠阶段时间之和}
}
$$

如果有并行重叠，必须根据关键路径和具体时序重新计算，而不能直接相加。

**模型三：CPU I/O 管理占用率**

$$
\boxed{
\text{CPU占用率}
=
\frac{
\text{每秒事件次数}\times
\text{每次CPU开销}
}{
\text{CPU每秒周期预算}
}
}
$$

**最终结论** 这一章最重要的不是记住大量孤立定义，而是理解整个计算机的数据交换过程。 CPU 发起访问，地址和控制信息指定目标，存储器或 I/O 接口完成响应，总线负责传输数据，仲裁机制协调共享资源，时序机制规定传送顺序，突发和分离事务则用于改善利用效率。面对 I/O 任务，还需要进一步判断： CPU 是否必须等待；数据由谁搬运；每次处理多少字节；CPU 为每次事件付出多少周期；设备与 CPU 能否并行工作；总线和主存是否构成瓶颈。只要能够把这些条件正确拆解，就可以独立分析新的总线与 I/O 综合题，而不必依赖背诵某一道真题的解题过程。
