### 易错前提

<Callout type="warn" title="流水线时间轴比背停顿数更可靠">

经典五级流水线中，ALU 结果通常在 **EX 结束**产生，LOAD 数据通常在 **MEM 结束**产生，而寄存器通常在 **WB** 写回。若题目同时允许 EX/MEM、MEM/WB 前递和同周期先写后读，停顿数可能不同于没有前递的模型；必须根据**生产时间与使用时间**逐周期画表。经典按序流水线中的 WAR、WAW 是逻辑相关，但通常不会形成实际冒险。

</Callout>

### 关键概念对照

<Tabs items={["周期与吞吐", "相关与冒险", "微指令字段", "中断与异常"]} defaultIndex={0}>

<Tab value="周期与吞吐">

理想 $k$ 段标量流水线执行 $n$ 条指令、时钟周期 $T_c$：

$$
T=(k+n-1)T_c.
$$

如有额外 $s$ 个停顿周期，固定阶段模型下 $T=(k+n-1+s)T_c$。实际流水线周期通常取最长段组合逻辑延迟再加流水段寄存器开销。

</Tab>

<Tab value="相关与冒险">

RAW 为**真相关**（先写后读），WAR 为**反相关**（先读后写），WAW 为**输出相关**（先写后写）。具有相关不代表必定插入停顿；实际冒险由发射、执行、读取和写回的时序决定。

</Tab>

<Tab value="微指令字段">

对于互斥的 $m$ 条微命令，如还需要一个“本组不发命令”状态，则最少编码位数为：

$$
b=\left\lceil\log_2(m+1)\right\rceil.
$$

若题目明确无需空操作状态，才按 $\lceil\log_2m\rceil$。多字段拼接须累加每字段位数。

</Tab>

<Tab value="中断与异常">

同步异常通常与当前指令执行有关，外部中断通常来自异步设备或时钟事件；**普通 Cache Miss 不等于缺页**。Fault 一般支持修复后重试故障指令，Trap 常从后继位置继续，但具体返回地址以架构规定为准。

</Tab>

</Tabs>

#### 1.2 用一条主线理解 CPU

假设执行一条机器指令：

```asm
ADD R3, R1, R2
```

其含义是：

$$
R3\leftarrow R1+R2
$$

CPU 内部需要解决的问题是：

| 问题                | 对应知识        |
| ----------------- | ----------- |
| 怎么知道下一条指令在哪里？     | PC          |
| 从哪里读取指令？          | 存储器、MAR、MDR |
| 怎么知道指令要做加法？       | IR、指令译码器    |
| R1、R2 的数据在哪里？     | 通用寄存器组      |
| 怎么把操作数交给 ALU？     | 数据通路        |
| 谁控制寄存器读写和 ALU 运算？ | 控制器         |
| 哪个时刻执行哪个操作？       | 时序控制        |
| 怎么让多条指令同时进行？      | 指令流水线       |
| 数据还没有算出来怎么办？      | 数据冒险、转发、阻塞  |
| 出现异常或中断怎么办？       | 异常与中断机制     |

理解本章的关键，就是分清数据如何流动、控制信号如何产生，以及这些操作如何安排到不同的时钟周期中。

## 二、5.1 CPU 的功能和基本结构

### 2.1 CPU 到底由什么组成？

传统教材将 CPU 分成：

$$
\boxed{\text{CPU}=\text{运算器}+\text{控制器}}
$$

从执行过程理解，还可以划分为数据通路与控制逻辑。

#### 运算器

负责执行数据加工，包括算术、逻辑和移位等运算。

典型部件如下。

| 部件           | 功能           |
| ------------ | ------------ |
| ALU          | 加、减、与、或、非等运算 |
| 通用寄存器组 GPRs  | 存放操作数和运算结果   |
| 暂存寄存器        | 暂时保存运算操作数    |
| 移位器          | 左移、右移        |
| 状态寄存器 PSW/FR | 保存运算产生的条件标志  |

#### 控制器

负责控制整个 CPU 的动作。

其核心功能包括指令控制、操作控制、时间控制，以及异常与中断处理相关的控制。

例如：

```asm
ADD R3, R1, R2
```

控制器需要产生相应信号，使 CPU 读取 R1、R2，令 ALU 执行加法，并将结果写入 R3。

注意：

控制器并不亲自完成加法，而是控制数据通路中的 ALU 完成加法。

### 2.2 CPU 中最重要的寄存器

这部分需要特别熟悉。

| 寄存器       | 全称                       | 作用         | 通常是否程序员可见 |
| --------- | ------------------------ | ---------- | --------- |
| PC        | Program Counter          | 提供取指地址     | 是         |
| IR        | Instruction Register     | 保存当前指令     | 否         |
| MAR       | Memory Address Register  | 保存访存地址     | 否         |
| MDR       | Memory Data Register     | 保存访存数据     | 否         |
| GPR       | General Purpose Register | 保存操作数和结果   | 是         |
| PSW/FLAGS | 状态寄存器                    | 保存标志位和控制状态 | 通常部分可见    |
| SP        | Stack Pointer            | 保存栈顶位置     | 通常是       |
| T/Y/Z     | 内部暂存寄存器                  | 暂存操作数或结果   | 通常否       |

程序员可见性最终取决于 ISA，表中反映的是 408 常见的抽象机器。

#### PC：程序计数器

PC 用于确定取指位置。

顺序执行时：

$$
PC\leftarrow PC+L
$$

其中 $L$ 是以编址单位表示的指令长度。

这句话特别重要。

假设一台计算机：

- 按字节编址；
- 指令定长 32 位。

则一条指令占 4B：

$$
\boxed{PC\leftarrow PC+4}
$$

若定长 16 位，同样按字节编址：

$$
\boxed{PC\leftarrow PC+2}
$$

如果按机器字编址，而且每条指令恰好一个机器字，则可以是：

$$
\boxed{PC\leftarrow PC+1}
$$

所以 PC 不一定加 1，也不一定加 4。

遇到跳转、异常、中断、函数返回时，PC 可能由目标地址取代顺序地址。

#### IR：指令寄存器

IR 保存当前指令。

比如：

```asm
ADD R3,R1,R2
```

取指完成后，IR 保存该指令的机器码。

控制器从中分析操作码、寄存器编号、寻址方式、立即数等字段。

#### MAR：存储器地址寄存器

保存本次存储器访问的地址。

例如：

$$
MAR\leftarrow PC
$$

表示将 PC 中的取指地址送给 MAR。

#### MDR：存储器数据寄存器

保存 CPU 与存储器之间交换的数据。

读操作：

$$
MDR\leftarrow M[MAR]
$$

写操作：

$$
M[MAR]\leftarrow MDR
$$

注意：

$$
\boxed{MAR=\text{地址},\qquad MDR=\text{数据}}
$$

不要因为读存储器时两者同时出现，就混淆作用。

**寄存器可见性的判断应以 ISA 而非物理芯片布局为准**

PC/程序状态、通用寄存器等通常属于体系结构状态或可观察的程序执行状态；但 **IR、MAR、MDR** 多属微体系结构实现细节，通常不是用户程序可直接读写的架构寄存器。不要把“控制器内部存在某寄存器”与“ISA 公开这个寄存器”混同。

### 2.3 真题：哪些寄存器程序员可见？

2010 年 408 真题

下列寄存器中，汇编语言程序员可见的是：

A. MAR\
B. PC\
C. MDR\
D. IR

答案：B

解析：

PC 虽然未必能通过普通算术指令直接修改，但程序可以通过跳转、调用、返回等机器指令改变控制流。

而 MAR、MDR、IR 主要服务于 CPU 内部执行过程。

因此：

$$
\boxed{PC\text{ 可见，MAR/MDR/IR 通常不可见}}
$$

2021 年的相关真题进一步考查了基址寄存器、状态寄存器、指令寄存器和微指令寄存器的区别。

关键方法不是背名字，而是看它是否属于 ISA 暴露的体系结构状态。

### 2.4 真题：PC 和 IR 的位数

2016 年 408 真题

某计算机：

- 主存容量 4GB；
- 按字节编址；
- 指令长度 32 位；
- 所有指令按字边界对齐。

问 PC、IR 至少需要多少位？

<Steps>
<Step>

### 第一步：求主存地址空间

$$
4GB=2^{32}B
$$

主存有 $2^{32}$ 个字节地址。

</Step>
<Step>

### 第二步：分析 PC

每条指令占：

$$
32/8=4B
$$

按字边界对齐时，合法指令起始地址共有：

$$
\frac{2^{32}}{4}=2^{30}
$$

种。

若 PC 只需要编码这些对齐的指令位置，则至少：

$$
\boxed{30\text{ 位}}
$$

</Step>
<Step>

### 第三步：分析 IR

IR 必须保存完整指令：

$$
\boxed{32\text{ 位}}
$$

答案：

$$
\boxed{PC=30,\qquad IR=32}
$$

这道题有一个容易忽视的前提：这里求的是区分合法对齐取指位置所需的最少信息位数。

实际 CPU 完全可以采用 32 位字节地址 PC，低两位在正常对齐取指时为零。不能据此认为所有 32 位地址处理器的 PC 物理上只有 30 位。

</Step>
</Steps>
### 2.5 组合逻辑与时序逻辑

2023 年真题考查过这一区分。

| 组合逻辑元件  | 时序逻辑元件 |
| ------- | ------ |
| ALU     | PC     |
| MUX     | IR     |
| 译码器     | MAR    |
| 三态门     | MDR    |
| 普通组合门电路 | 寄存器组   |

核心区别：

组合逻辑没有独立保存历史状态的能力，时序逻辑可以保存状态。

例如：

$$
F=A+B
$$

ALU 可以产生 $F$，但如果需要下一周期继续使用这个结果，必须把它锁存到寄存器。

这就是数据通路中出现大量暂存寄存器的原因。

## 三、5.2 指令执行过程

### 3.1 指令是如何执行的？

经典指令执行过程可以概括为：

```text
          PC
           │
           ▼
          MAR
           │
           ▼
        指令存储器
           │
           ▼
          MDR
           │
           ▼
          IR
           │
           ▼
       译码与控制
           │
           ▼
       读取操作数
           │
           ▼
          ALU
           │
           ▼
       写回执行结果
```

这是教材中的抽象模型，不表示所有现代 CPU 物理上都必须经过独立的 MAR、MDR。

#### 取指阶段

抽象微操作：

$$
MAR\leftarrow PC
$$

$$
MDR\leftarrow M[MAR]
$$

$$
IR\leftarrow MDR
$$

$$
PC\leftarrow PC+L
$$

其中 PC 增量操作能否与访存同时进行，取决于数据通路。

#### 译码阶段

控制器从 IR 中分析指令。

例如：

```asm
LOAD R1, 8(R2)
```

需要确定操作类型为 LOAD，基址寄存器为 R2，目的寄存器为 R1，偏移为 8。

#### 执行阶段

形成有效地址：

$$
EA=R[R2]+8
$$

#### 访存阶段

$$
MDR\leftarrow M[EA]
$$

#### 写回阶段

$$
R[R1]\leftarrow MDR
$$

这便完成了整条 LOAD 指令。

注意：并非所有指令都需要数据访存或写回通用寄存器。

### 3.2 三种周期必须区分

| 周期   | 定义            |
| ---- | ------------- |
| 时钟周期 | CPU 基本时序节拍    |
| 机器周期 | 完成某项基本操作的时间单位 |
| 指令周期 | 完成一条机器指令需要的时间 |

在传统多周期模型中：

$$
\text{指令周期}\geq\text{一个机器周期}
$$

一个机器周期通常包含一个或多个时钟周期。

但需要注意，现代单周期、多周期和流水线处理器的具体时序划分不同，不能把某种教材模型中的周期关系当作所有 CPU 的固定物理结构。

### 3.3 单周期、多周期、流水线有什么区别？

这是后面流水线题的基础。

| 处理器     | 工作方式          | 典型特点         |
| ------- | ------------- | ------------ |
| 单周期 CPU | 一条指令在一个时钟周期完成 | CPI=1，时钟周期较长 |
| 多周期 CPU | 一条指令拆分为多个时钟周期 | 不同指令可用不同周期数  |
| 流水线 CPU | 多条指令的不同阶段重叠执行 | 提高吞吐率        |

例如一条 LOAD 需要：

取指、译码、地址计算、访存、写回。

单周期实现中，所有动作必须在一个周期内完成，时钟周期受到最长指令路径限制。

传统多周期实现则分拍完成。

流水线允许：

```text
周期       1     2     3     4     5     6
I1        IF    ID    EX    MEM   WB
I2              IF    ID    EX    MEM   WB
I3                    IF    ID    EX    MEM
```

多条指令可以重叠。

最容易混淆的点：

流水线不是让一条指令直接变成一个时钟周期就执行完毕，而是让多条指令的不同阶段同时占用不同的硬件资源。

### 3.4 单周期 CPU 的时钟周期计算

来自本站模拟题的典型条件：

| 功能部件  | 延迟  |
| ----- | --- |
| 指令存储器 | 3ns |
| 数据存储器 | 3ns |
| 寄存器读  | 1ns |
| 寄存器写  | 1ns |
| ALU   | 2ns |

忽略题目指定的其他延迟。

设最长路径是 LOAD：

```text
取指
 ↓
读寄存器
 ↓
计算地址
 ↓
读数据存储器
 ↓
写寄存器
```

总延迟：

$$
T=3+1+2+3+1
$$

$$
\boxed{T=10ns}
$$

因此，该抽象模型的单周期时钟周期至少为 10ns。

注意，这个结果依赖题目对寄存器读写延迟及其他部件延迟的建模约定。

方法：沿真正的最长组合路径相加，而不是把所有部件延迟全部相加。

## 四、5.3 数据通路——本章第一大难点

数据通路是这章最应该认真练习的大题专题。

从 2009、2015、2022 到 2024、2026 年，本站整理的综合题都涉及数据通路的不同形式。

### 4.1 什么是数据通路？

数据通路是 CPU 内部传送和处理数据的一套硬件路径。

典型结构：

```text
        ┌───────────────┐
        │  通用寄存器组  │
        └──────┬────────┘
               │
               ▼
          多路选择器
               │
               ▼
             ALU
               │
               ▼
           结果寄存器
               │
               ▼
         写回寄存器组
```

数据通路包含寄存器、ALU、MUX、总线、暂存器等。

控制器则通过控制信号决定每一步走哪条路径。

**单总线数据通路：每拍先看谁在驱动总线**

若一条内部总线只能由一个输出源驱动，便不能在同一拍令两个寄存器同时向总线送数。二元 ALU 操作通常要先把一个操作数暂存在 $Y$ 等寄存器，再将另一个操作数送入 ALU；结果写入 $Z$ 或目标寄存器，具体信号顺序应按题图决定。

### 4.2 单总线数据通路为什么需要暂存器？

这是 2015、2022 年综合题的核心问题。

假设：

$$
R3\leftarrow R1+R2
$$

CPU 内部只有一条共享总线。

这条总线同一时刻只能由一个数据源驱动。

但 ALU 做加法需要两个操作数。

怎么办？

#### 第一拍：保存 R1

$$
Y\leftarrow R1
$$

控制信号：

```text
R1out
Yin
```

此时 R1 驱动总线，Y 锁存数据。

#### 第二拍：取 R2 并执行加法

Y 已经保存 R1。

让 R2 驱动总线：

$$
Z\leftarrow Y+R2
$$

控制信号可抽象为：

```text
R2out
ALUop=ADD
Zin
```

#### 第三拍：写回结果

$$
R3\leftarrow Z
$$

控制信号：

```text
Zout
R3in
```

因此，这种单总线模型需要至少三个相继的关键节拍。

| 节拍 | 微操作                    | 控制信号                  |
| -- | ---------------------- | --------------------- |
| 1  | $Y\leftarrow R1$   | R1out, Yin            |
| 2  | $Z\leftarrow Y+R2$ | R2out, ALUop=ADD, Zin |
| 3  | $R3\leftarrow Z$   | Zout, R3in            |

这里假设 ALU 输入和结果寄存器之间具有相应连接，且单拍可完成组合运算并锁存结果。

记住：

Y 保存操作数，Z 保存运算结果。

它们可以是不同机器中名称不同但作用相近的暂存寄存器。

### 4.3 为什么不能让两个寄存器同时输出到一条总线？

如果同一条普通三态共享总线同时执行：

```text
R1out=1
R2out=1
```

那么 R1、R2 都试图驱动总线。

两者数据不同，就可能发生电气争用。

因此，经典单总线结构一次通常只能选一个输出源。

三态门的意义就是允许某个寄存器暂时与总线断开。

其三种输出状态为：

$$
0,\qquad1,\qquad Z
$$

其中 $Z$ 是高阻态。

这是总线式数据通路能够复用连线的重要基础。

### 4.4 MUX 与译码器的区别

这也是典型考点。

#### MUX

多路选择器：

$$
n\text{ 路输入}\longrightarrow1\text{ 路输出}
$$

根据选择信号确定哪一路数据通过。

例如一个二选一 MUX：

```text
A ──┐
    ├── MUX ── OUT
B ──┘
       ↑
     Select
```

当选择信号为 0 时输出 A，为 1 时输出 B，具体对应关系由图中标号决定。

#### 译码器

译码器将二进制编码转换为相应的选择信号。

例如 4 位输入可以区分：

$$
2^4=16
$$

种编码。

在寄存器组中通常有如下区别：

| 操作              | 常见实现          |
| --------------- | ------------- |
| 从 16 个寄存器中读取一个  | 16 选 1 MUX    |
| 向 16 个寄存器中的一个写入 | 4-16 译码器产生写使能 |

注意：

MUX 负责选数据，译码器负责产生选择/使能信号。

### 4.5 真题：2009 年数据通路综合大题

原题是一台 16 位计算机，要求执行：

```asm
ADD (R1), R0
```

题目明确其语义为：

$$
M[R1]\leftarrow M[R1]+R0
$$

这里最重要的是理解括号。

若：

$$
R1=1000H
$$

则：

$$
M[R1]=M[1000H]
$$

表示地址 1000H 中存放的数据。

并不是 R1 本身。

### 第一步：拆解指令

指令要做的事可以表示为：

$$
EA\leftarrow R1

S\leftarrow R0
$$

$$
M[EA]\leftarrow D+S

### 第二步：转换成具体微操作

| 节拍 | 微操作                                             | 有效控制信号                   |
| -- | ----------------------------------------------- | ------------------------ |
| C5 | $MAR\leftarrow R1$                          | R1out, MARin             |

### 第三步：理解最关键的细节

为什么 C6 可以同时做两件事？

因为读主存使用外部数据通路，而 R0 送 A 使用内部总线，题设两条路径不冲突。

为什么需要区分 MDRin 和 MDRinE？

在该题的具体结构中：

- MDRin：来自 CPU 内部总线。
- MDRinE：来自外部数据总线。

这不是所有 CPU 都统一采用的信号命名。

为什么不修改 R1？

R1 保存目标地址，最终结果应该写到这个地址指向的主存单元。

假设：

$$
R1=0200H
$$

$$
R0=0003H
$$

$$
M[0200H]=FFFEH
$$

则：

$$
FFFEH+0003H=10001H
$$

只保留 16 位：

$$
\boxed{M[0200H]=0001H}
$$

R0 和 R1 均不改变。

这道题训练的不是死背 C5～C9，而是将指令语义翻译成真正的数据流，再推导控制信号和时序。

### 4.6 真题：2015 年单总线数据通路

2015 年第 43 题是一道非常经典的结构分析题。

题设：

ALU 支持七种操作：

```asm
mova
add
sub
and
or
not
inc
```

移位寄存器 SR 支持：

```asm
mov
left
right
```

问 ALUop、SRop 最少需要多少位？

#### ALUop

七种互斥操作需要：

$$
2^n\ge7
$$

$$
n=\lceil\log_2 7\rceil
$$

$$
\boxed{n=3}
$$

#### SRop

三种互斥操作：

$$
2^n\ge3
$$

$$
\boxed{n=2}
$$

因此：

$$
\boxed{ALUop=3\text{ 位},\quad SRop=2\text{ 位}}
$$

题目还问为什么 MUX 存在常数 2。

原因是该计算机：

- 指令长 16 位；
- 按字节编址。

所以顺序取指需要：

$$
\boxed{PC\leftarrow PC+2}
$$

2015 年第 44 题又进一步结合相同数据通路考查指令编码、控制信号和执行时钟周期。

原题指令格式的操作码为 7 位：

$$
2^7=128
$$

因此最多可区分 128 种操作码。

原题解析中的典型执行节拍为：

| 指令               | 执行阶段最少节拍 |
| ---------------- | -------- |
| `inc R1`         | 2        |
| `sub R1,R3,(R2)` | 4        |

这里的周期数仅适用于原题所给数据通路、存储器时序和控制信号安排，不能推广为所有 CPU 的统一结果。

### 4.7 真题：2022 年 CPU 数据通路与控制信号

2022 年第 43 题中，给出了：

- 通用寄存器组 GPRs；
- ALU；
- Y、Z 暂存寄存器；
- 标志寄存器 FR；
- 控制器和主存读写路径。

其中几个结论特别重要。

#### 寄存器数量

题图中的寄存器地址字段为 4 位。

因此最多：

$$
\boxed{2^4=16}
$$

个可编码的通用寄存器。

读寄存器编号进入 MUX，写寄存器编号进入译码器。

#### 为什么要设置 Y 和 Z？

Y 保存 ALU 的一个操作数。

Z 保存 ALU 输出结果。

本质上是解决单总线不能同时传输多个独立数据源的问题。

#### 取指周期计算

原题规定从发出主存读命令到数据进入 MDR 共需 5 个时钟周期。

忽略 PC 增量：

$$
MAR\leftarrow PC
$$

需要 1 周期。

主存读取到 MDR 需要 5 周期。

$$
IR\leftarrow MDR
$$

再需要 1 周期。

所以：

$$
\boxed{T=1+5+1=7\text{ 个时钟周期}}
$$

这里千万不能再给 MDR 接收数据额外加一个周期，因为题目已经把这一步包含在 5 周期的主存读取过程中。

### 4.8 ALU 状态标志：CF、OF、SF、ZF

2013、2017、2019、2022、2024 年相关题型都涉及条件标志。

#### SF：符号标志

对于 $n$ 位结果 $F$：

$$
SF=F_{n-1}
$$

即取结果最高位。

#### ZF：零标志

当运算结果为零时：

$$
ZF=1
$$

否则：

$$
ZF=0
$$

#### CF：进位标志

主要用于判断无符号运算中的最高位进位或减法借位相关状态。

其中减法时 CF 的具体含义可能因 ISA 而异。

#### OF：有符号溢出标志

这是最容易考错的。

##### 加法溢出

两个同号数相加，却得到异号结果。

例如 8 位补码：

$$
127+1=128
$$

数学结果 128 已超出表示范围：

$$
[-128,127]
$$

硬件得到：

```text
01111111
00000001
--------
10000000
```

因此：

$$
OF=1
$$

但并没有向第 9 位产生进位：

$$
CF=0
$$

说明：

$$
\boxed{OF\ne CF}
$$

##### 减法溢出

被减数与减数异号，结果符号却与被减数异号。

例如 8 位：

$$
-128-1=-129
$$

结果超出范围，发生有符号溢出。

#### 2022 年真题中的逻辑表达式

设 $A_{15},B_{15},F_{15}$ 分别为两个操作数和运算结果的符号位。

加法溢出：

$$
\boxed{ OF_{+} = \overline{A_{15}\oplus B_{15}} \left(A_{15}\oplus F_{15}\right) }
$$

减法溢出：

$$
\boxed{ OF_{-} = \left(A_{15}\oplus B_{15}\right) \left(A_{15}\oplus F_{15}\right) }
$$

符号标志：

$$
\boxed{SF=F_{15}}
$$

这是综合大题中应该会推导，而不是只会记忆的公式。

### 4.9 真题：2024 年指令编码与数据通路

2024 年第 43 题把三类知识结合到一起：

$$
\boxed{\text{指令编码}+\text{数据表示}+\text{数据通路}}
$$

题目给出 `add`、`slli`、`lw` 等 32 位指令。

#### 问题一：最多多少个寄存器？

寄存器字段宽度为 5 位。

$$
\boxed{2^5=32}
$$

#### 问题二：为什么 shamt 为 5 位？

32 位数据逻辑左移的常规移位次数为：

$$
0,1,\ldots,31
$$

一共 32 种：

$$
\boxed{\lceil\log_2 32\rceil=5}
$$

#### 问题三：ALU 标志计算

给定：

$$
A=\texttt{87654321H}
$$

$$
B=\texttt{98765432H}
$$

做加法：

$$
A+B=\texttt{11FDB9753H}
$$

32 位 ALU 只保留低 32 位：

$$
\boxed{F=\texttt{1FDB9753H}}
$$

最高位有进位：

$$
\boxed{CF=1}
$$

两个操作数按 32 位补码均为负数，结果却为正数：

$$
\boxed{OF=1}
$$

#### 问题四：LOAD 有效地址计算

原题机器码：

```text
A040A103H
```

对应题设中的 `lw` 指令。

其 12 位立即数为：

```text

```

作为 12 位补码：

$$

$$

假设基址寄存器：

$$
R1=\texttt{FFFFA2D0H}
$$

则有效地址：

$$

得到：

特别注意：这是内存地址，并不是读取出来的数据。

## 五、5.4 控制器的功能和工作原理

这一节的重点是理解控制信号从哪里来，以及微指令编码的计算方法。

### 5.1 硬布线控制器与微程序控制器

CPU 的控制器需要根据指令、时间和状态决定哪些控制信号有效。

例如执行：

$$
R3\leftarrow R1+R2
$$

控制器需要依次控制寄存器读取、ALU 加法、结果写回。

控制器通常有两种经典实现方式。

| 比较   | 硬布线控制器   | 微程序控制器       |
| ---- | -------- | ------------ |
| 实现方式 | 固定逻辑电路   | 控制存储器中的微指令   |
| 控制信号 | 由逻辑直接产生  | 从微指令译码产生     |
| 速度   | 通常较快     | 通常相对较慢       |
| 修改   | 较困难      | 相对容易         |
| 复杂指令 | 控制逻辑可能复杂 | 更容易组织复杂控制序列  |
| 典型联系 | RISC 常采用 | 传统复杂指令处理器常采用 |

这里是典型实现倾向，不代表所有 RISC 都必须使用硬布线，或者 CISC 必须完全依靠微程序。

#### 硬布线控制器

其控制信号可以抽象为：

$$
C_i=f(OP,T,FLAGS,STATE)
$$

其中：

$OP$ 表示操作码，$T$ 表示当前时序，$FLAGS$ 表示条件标志，$STATE$ 表示控制状态。

理解方法：

硬布线控制器相当于用逻辑电路直接算出下一步需要什么控制信号。

#### 微程序控制器

微程序控制器把控制过程组织为微指令。

```text
机器指令操作码
      ↓
形成微程序入口地址
      ↓
    微地址寄存器
      ↓
    控制存储器
      ↓
    微指令寄存器
      ↓
   发出微命令
      ↓
   执行微操作
      ↓
   形成下一微地址
```

微程序控制器本身仍是硬件。

微程序不是操作系统中的普通程序。

### 5.2 微操作、微命令、微指令、微程序

这四个概念必须区别清楚。

| 概念  | 含义             | 示例                     |
| --- | -------------- | ---------------------- |
| 微操作 | CPU 内部执行的基本动作  | $MAR\leftarrow PC$ |
| 微命令 | 控制微操作的信号       | PCout、MARin            |
| 微指令 | 一组微命令及微地址控制信息  | 同一控制节拍的控制字             |
| 微程序 | 实现某条机器指令的一组微指令 | ADD 指令对应的微程序           |

它们之间的关系：

$$
\boxed{ \text{机器指令} \rightarrow \text{微程序} \rightarrow \text{微指令} \rightarrow \text{微命令} \rightarrow \text{微操作} }
$$

例如：

$$
MAR\leftarrow PC
$$

这个动作是微操作。

使其发生的：

```text
PCout=1
MARin=1
```

是相应微命令。

一条微指令可以包含多个互不冲突的微命令。

这是选择题的重要陷阱。

### 5.3 微程序控制器中的重要部件

| 部件         | 作用            |
| ---------- | ------------- |
| CM         | 控制存储器，保存微指令   |
| CMAR / µPC | 保存当前或下一条微指令地址 |
| CMDR / µIR | 保存读出的微指令      |
| 微地址形成部件    | 决定下一微地址       |
| 微命令译码器     | 根据微指令产生控制信号   |

#### 控制存储器与主存有什么区别？

主存主要保存普通机器指令和数据。

控制存储器保存用于实现机器指令的微指令。

例如程序中有一条：

```asm
ADD R3,R1,R2
```

普通机器指令来自主存或指令 Cache。

若采用微程序控制，其具体控制步骤则由控制存储器中的微指令决定。

所以：

$$
\boxed{\text{机器指令}\ne\text{微指令}}
$$

**微命令字段编码：把互斥与并行分开**

同一个字段只能选出一个互斥操作；不同字段可以并行发命令。每个字段若包含 $m$ 条互斥命令且要求空操作码，则需 $\lceil\log_2(m+1)\rceil$ 位。微指令总长度还可能包含微地址、转移方式、测试条件和其他控制位，不可把**操作控制字段长度**当作全部长度。

### 5.4 微指令的编码方式

这是非常适合命制计算题的地方。

#### 直接编码

假设 CPU 有 20 个控制信号。

如果每个控制信号对应一个独立控制位，那么至少需要：

$$
\boxed{20\text{ bit}}
$$

优点是控制信号可直接输出，并行能力强。

缺点是微指令可能很长。

#### 字段直接编码

把互斥的微命令放在同一个字段。

例如某字段包含：

```text
000：不执行操作
001：R1out
010：R2out
011：R3out
100：R4out
```

该字段有 4 条互斥微命令，再加一种空操作。

因此需要表示 5 种状态：

$$
n=\lceil\log_2 5\rceil=3
$$

所以至少 3 位。

#### 最重要的公式

若一个互斥组中有 $m$ 条微命令，并需要保留“不执行任何微命令”的编码：

$$
\boxed{ n=\lceil\log_2(m+1)\rceil }
$$

注意多出来的 $1$。

如果题目明确不需要空操作编码，则可按：

$$
n=\lceil\log_2m\rceil
$$

计算。

### 5.5 真题：2012 年微指令编码

题设：

微程序控制器共有 33 个微命令，分成 5 个互斥类：

$$
7,\quad3,\quad12,\quad5,\quad6
$$

问操作控制字段至少多少位？

#### 第一组

7 条微命令，加上空操作：

$$
n_1=\lceil\log_2(7+1)\rceil=3
$$

#### 第二组

$$
n_2=\lceil\log_2(3+1)\rceil=2
$$

#### 第三组

$$
n_3=\lceil\log_2(12+1)\rceil=4
$$

#### 第四组

$$
n_4=\lceil\log_2(5+1)\rceil=3
$$

#### 第五组

$$
n_5=\lceil\log_2(6+1)\rceil=3
$$

最后相加：

$$
n=3+2+4+3+3
$$

$$
\boxed{n=15\text{ bit}}
$$

答案：15 位。

这道题最容易犯的错误，是直接计算：

$$
\lceil\log_2(33+1)\rceil
$$

这是错误的。

因为题目允许不同字段的控制信号并行发出，必须先分别编码，再把字段位数相加。

### 5.6 微地址字段的位数计算

若控制存储器共有 $N$ 个可寻址的微指令字，那么微地址至少需要：

$$
\boxed{ n=\lceil\log_2N\rceil }
$$

#### 真题：2014 年微地址计算

已知：

- 共有 32 条机器指令；
- 公共取指微程序需要 2 条微指令；
- 每条机器指令对应的执行微程序平均需要 4 条微指令；
- 采用下地址字段法。

求下地址字段最少位数。

首先计算微指令总数：

$$
N=2+32\times4
$$

$$
N=130
$$

由于：

$$
2^7=128<130
$$

而：

$$
2^8=256
$$

因此：

$$
\boxed{n=8\text{ 位}}
$$

这里不能漏掉公共取指微程序。

如果漏掉 2 条：

$$
32\times4=128
$$

就会错误得到 7 位。

#### 微指令总字长

若微指令格式包含：

- 操作控制字段 $a$ 位；
- 判别字段 $b$ 位；
- 下地址字段 $c$ 位。

那么：

$$
\boxed{W=a+b+c}
$$

如果控制存储器包含 $N$ 条微指令：

$$
\boxed{C=N\times W\text{ bit}}
$$

完整解题顺序应当是：

$$
\boxed{ \text{微命令分组} \rightarrow \text{字段编码} \rightarrow \text{下地址位数} \rightarrow \text{总字长} \rightarrow \text{控制存储器容量} }
$$

### 5.7 水平型与垂直型微指令

| 比较      | 水平型         | 垂直型       |
| ------- | ----------- | --------- |
| 微指令字长   | 通常较长        | 通常较短      |
| 并行控制能力  | 较强          | 相对较弱      |
| 译码复杂程度  | 通常较低        | 通常较高      |
| 控制存储器需求 | 通常较大        | 通常较小      |
| 特点      | 一条微指令控制多个操作 | 控制信息编码较集中 |

直接编码是水平型微指令的典型形式。

字段编码则不能仅根据“出现字段”就认定一定是垂直型，具体还要看格式和并行控制能力。

## 六、5.5 异常与中断机制

这部分与操作系统紧密联系，是高频选择题专题。

### 6.1 异常与中断的根本区别

| 比较      | 异常 Exception   | 外部中断 Interrupt |
| ------- | -------------- | -------------- |
| 来源      | 当前指令或处理器内部执行事件 | CPU 外部事件       |
| 同步性     | 通常同步           | 通常异步           |
| 与当前指令关系 | 通常直接相关         | 通常没有直接因果关系     |
| 典型情况    | 缺页、除零、非法指令     | 时钟、键盘、I/O 完成   |

例如：

```text
DIV R1,R2
```

若 R2 为零，执行除法时产生除零异常。

这是由当前指令直接导致的同步事件。

而键盘按下某个键，通常与 CPU 当前执行的机器指令无关。

它属于外部中断。

#### 高频判断

| 事件            | 分类          |
| ------------- | ----------- |
| 除零            | 异常          |
| 非法指令          | 异常          |
| 访问越权          | 异常          |
| 缺页            | 异常          |
| 系统调用          | 同步陷阱/自陷     |
| 定时器中断         | 外部中断        |
| 键盘输入请求        | 外部中断        |
| 磁盘 I/O 完成     | 外部中断        |
| 普通 Cache Miss | 通常不属于体系结构异常 |

最后一个尤其重要。

普通 Cache Miss 通常由缓存层次结构处理，必要时从下一级存储器取数据。

而缺页意味着操作系统需要介入处理虚拟内存中的页不在内存等情况。

因此：

$$
\boxed{\text{Cache Miss}\ne\text{缺页异常}}
$$

当然，Cache Miss 对应的访存最终仍可能触发缺页等异常。

### 6.2 三种内部异常：Fault、Trap、Abort

| 类型    | 含义    | 典型例子      | 处理后          |
| ----- | ----- | --------- | ------------ |
| Fault | 故障    | 缺页        | 修复后可能重新执行原指令 |
| Trap  | 陷阱/自陷 | 系统调用、调试陷阱 | 通常从后续位置继续    |
| Abort | 终止    | 严重机器错误    | 通常难以恢复       |

#### Fault：故障

例如 CPU 执行：

```asm
LOAD R1,0(R2)
```

发现目标虚拟页面当前不在主存。

处理过程：

```text
执行 LOAD
    ↓
发现缺页
    ↓
进入异常处理程序
    ↓
操作系统调入所需页面
    ↓
更新页表等状态
    ↓
重新执行原 LOAD
```

因此 Fault 的一个重要特点是：

故障可以被修复，随后重新执行引发故障的指令。

#### Trap：自陷

例如程序主动执行系统调用指令。

```text
用户程序
    ↓
系统调用指令
    ↓
进入内核态
    ↓
执行内核服务
    ↓
返回用户程序
```

如果是已完成的自陷指令，返回地址通常指向后继指令。

所以：

$$
\boxed{ \text{Fault 常重做原指令} }
$$

$$
\boxed{ \text{Trap 通常执行后继指令} }
$$

这是判断异常返回地址时非常实用的方法。

### 6.3 外部中断什么时候响应？

经典 408 模型中：

CPU 通常在当前指令执行结束后，检查并响应可接受的外部中断。

但异常可能在当前指令执行过程中被检测出来。

因此以下说法是错误的：

> 只要外部设备发出中断请求，CPU 就立即停止当前指令。

一个外部中断要被响应，通常需要同时考虑中断请求、中断允许状态、中断屏蔽情况、优先级以及是否到达合法响应时点。

### 6.4 完整中断处理过程

```text
外设发出中断请求
        ↓
CPU 检测并决定响应
        ↓
硬件保存必要断点状态
        ↓
取得中断服务程序入口
        ↓
转入中断服务程序 ISR
        ↓
软件保护必要现场
        ↓
执行具体中断服务
        ↓
软件恢复现场
        ↓
中断返回
        ↓
恢复原程序运行
```

其中有两类特别容易混淆的操作。

#### 保存断点

断点用于保证中断返回后可以继续执行原程序。

典型保存内容有 PC、必要的状态寄存器信息等。

#### 保存现场

现场通常包括中断处理程序可能修改、而原程序还需要继续使用的寄存器状态。

典型包括通用寄存器等。

408 常见抽象：

$$
\boxed{\text{硬件保断点，软件保现场}}
$$

但这只是常见教学模型。具体处理器可能自动保存更多状态。

### 6.5 中断隐指令

2012 年 408 真题考查过。

所谓中断隐指令，不是程序员写在程序中的一条普通机器指令。

它是 CPU 响应中断时自动完成的一系列硬件动作。

典型包括：

$$
\boxed{ \text{关中断} + \text{保存断点} + \text{取得中断服务入口} }
$$

要区分：

| 中断隐指令    | 中断服务程序      |
| -------- | ----------- |
| 硬件自动执行   | 由程序指令完成具体服务 |
| 负责进入中断处理 | 负责处理实际事件    |
| 保存必要断点   | 保存和恢复必要工作现场 |
| 形成服务入口   | 执行设备处理等任务   |

因此，不能说“中断隐指令就是中断服务程序的第一条指令”。

### 6.6 中断向量与中断向量表

中断向量可以表示中断服务程序入口地址，或者用于定位该入口的信息。

中断向量表负责建立中断编号与处理程序入口之间的对应关系。

例如：

| 中断号 | ISR 入口 |
| --- | ------ |
| 0   | 1000H  |
| 1   | 2000H  |
| 2   | 3000H  |

当发生中断号 1 对应的事件时，CPU 可以根据中断向量信息找到相应 ISR。

中断向量不是中断服务程序本身。

### 6.7 中断优先级、屏蔽与嵌套

假设有四个中断源：

$$
A>B>C>D
$$

其中 A 优先级最高。

#### 响应优先级

当多个中断同时提出请求时，决定优先响应谁。

#### 处理优先级

决定某个中断服务程序正在执行时，哪些新的中断可以打断它。

两者可能受到中断屏蔽字的影响。

#### 单重中断

执行 ISR 期间不再响应其他可屏蔽中断：

```text
主程序
  ↓
ISR B
  ↓
返回主程序
```

#### 多重中断

允许高优先级中断抢占低优先级 ISR：

```text
主程序
  ↓
ISR C
  ↓
ISR B
  ↓
ISR A
  ↓
返回 ISR B
  ↓
返回 ISR C
  ↓
返回主程序
```

#### 屏蔽字计算

假设：

$$
A>B>C>D
$$

并规定：

- 1 表示屏蔽；
- 0 表示允许。

正在执行 B 的 ISR，并且只允许 A 抢占。

那么屏蔽字可以设置为：

| 中断源 | A | B | C | D |
| --- | - | - | - | - |
| 屏蔽位 | 0 | 1 | 1 | 1 |

所以：

$$
\boxed{0111}
$$

但如果题目规定 1 表示允许、0 表示屏蔽，则答案会改变。

做题必须先确认屏蔽位的定义。

#### NMI 与可屏蔽中断

NMI 是不可屏蔽中断。

它不受普通的可屏蔽中断允许标志控制。

因此：

$$
IF=0
$$

不代表所有可能的中断和异常都会被禁止。

## 七、5.6 指令流水线——本章最重要的计算专题

流水线内容需要真正理解时间轴。

它不仅考公式，更重要的是分析多条指令之间的数据依赖和控制流变化。

### 7.1 为什么需要流水线？

设完成一条指令需要经过 5 个阶段，每个阶段耗时 1ns。

如果完全串行执行：

$$
T_{\text{单条}}=5ns
$$

100 条指令需要：

$$
100\times5=500ns
$$

如果采用理想五级流水线，允许不同指令在不同阶段重叠：

第一条指令仍然需要约 5ns，但之后理想情况下每 1ns 可以完成一条。

因此：

$$
T=(5+100-1)\times1
$$

$$
\boxed{T=104ns}
$$

流水线的关键收益是：

$$
\boxed{\text{提高吞吐率}}
$$

而不是必然缩短单条指令的执行延迟。

### 7.2 五级流水线

经典结构：

$$
\boxed{IF\rightarrow ID\rightarrow EX\rightarrow MEM\rightarrow WB}
$$

| 阶段  | 功能          | 关键考点        |
| --- | ----------- | ----------- |
| IF  | 取指          | 指令存储器、PC    |
| ID  | 译码与读取寄存器    | RAW 相关、寄存器读 |
| EX  | ALU 运算、地址计算 | ALU 结果产生    |
| MEM | 数据访存        | LOAD 数据产生   |
| WB  | 写回寄存器       | RAW 等待结束时刻  |

最重要的三个时间点：

普通 ALU 指令的运算结果通常在 EX 结束时产生。

LOAD 指令的数据通常在 MEM 结束时产生。

寄存器文件通常在 WB 阶段写回。

后面所有数据冒险题，都可以通过比较这些时间点求解。

### 7.3 流水线时钟周期计算

设流水线各段的组合逻辑延迟为：

$$
t_1,t_2,\ldots,t_k
$$

流水段寄存器开销为 $t_r$。

则：

$$
\boxed{ T_c=\max(t_1,t_2,\ldots,t_k)+t_r }
$$

注意取最大值，而不是求和。

#### 2009 年真题

4 段流水线延迟分别为：

$$
90ns,\quad80ns,\quad70ns,\quad60ns
$$

忽略寄存器开销：

$$
T_c=\max(90,80,70,60)
$$

$$
\boxed{T_c=90ns}
$$

#### 2018 年真题

五个功能段的延迟分别为：

$$
80ps,\quad50ps,\quad50ps,\quad70ps,\quad50ps
$$

流水段寄存器延迟：

$$
t_r=20ps
$$

则：

$$
T_c=80+20
$$

$$
\boxed{T_c=100ps}
$$

这两道题放在一起，就能记住完整公式。

**流水线 $k+n-1$ 公式的前提**

只适用于各阶段延迟以**同一流水线周期**度量、每周期发射一条、固定 $k$ 段、没有停顿和错误预测冲刷的理想标量流水线。若题目给出独立访存延迟、多发射、变长阶段或停顿，应先逐周期列时间轴，再计算总耗时。

### 7.4 流水线完成时间

理想 $k$ 段流水线执行 $n$ 条指令：

$$
\boxed{ T=(k+n-1)T_c }
$$

若额外出现 $s$ 个停顿周期：

$$
\boxed{ T=(k+n-1+s)T_c }
$$

公式成立需要满足题目采用的固定阶段、固定时钟周期模型。

#### 2013 年真题

已知：

- CPU 主频 1.03GHz；
- 4 级流水线；
- 执行 100 条指令；
- 无流水线阻塞。

需要时钟周期数：

$$
N=4+100-1=103
$$

时钟周期：

$$
T_c=\frac{1}{1.03\times10^9}
$$

执行总时间：

$$
T=\frac{103}{1.03\times10^9}
$$

$$
T=10^{-7}s
$$

吞吐率：

$$
TP=\frac{100}{10^{-7}}
$$

$$
\boxed{TP=10^9\text{ 条指令/秒}}
$$

容易错的地方是直接选 1.03G 条指令/秒。

后者是理想稳态极限吞吐率，而本题总共只有 100 条指令，还需要填充流水线。

### 7.5 吞吐率、加速比、效率

#### 吞吐率

$$
\boxed{ TP=\frac{n}{T} }
$$

理想稳态：

$$
\boxed{ TP_{\max}=\frac{1}{T_c} }
$$

对于每拍最多完成一条指令的标量流水线，这就是理想极限。

#### 加速比

$$
S=\frac{T_{\text{非流水}}}{T_{\text{流水}}}
$$

若非流水执行每个任务需要 $kT_c$：

$$
S=\frac{nkT_c}{(k+n-1)T_c}
$$

$$
\boxed{ S=\frac{nk}{k+n-1} }
$$

当：

$$
n\rightarrow\infty
$$

有：

$$
\boxed{S\rightarrow k}
$$

但只有在理想均衡、忽略流水寄存器开销、无停顿等条件下，这个结论才成立。

#### 流水线效率

在上述理想模型下：

$$
\boxed{E=\frac{S}{k}}
$$

所以：

$$
E=\frac{n}{k+n-1}
$$

### 7.6 CPI 到底是什么？

CPI 是平均每条指令消耗的时钟周期数。

$$
\boxed{ CPI=\frac{\text{总时钟周期数}}{\text{完成指令数}} }
$$

要区分单周期、多周期和流水线。

| CPU 类型  | 典型 CPI       |
| ------- | ------------ |
| 单周期     | 1            |
| 传统多周期   | 通常大于 1       |
| 基本标量流水线 | 理想稳态趋近 1     |
| 双发射超标量  | 理想情况下可达 0.5  |
| 四发射超标量  | 理想情况下可达 0.25 |

CPI=1 不意味着一条指令只经过一个流水阶段。

例如五级流水线中，一条指令仍要经过五个阶段，但进入稳态后可以每拍完成一条。

CPU 执行时间的统一公式：

$$
\boxed{ T_{\text{CPU}} = IC\times CPI\times T_c }
$$

也可写为：

$$
\boxed{ T_{\text{CPU}} = \frac{IC\times CPI}{f} }
$$

其中 $IC$ 是指令数，$f$ 是时钟频率。

## 八、流水线三大冒险

这部分必须做到看到指令序列就会判断。

### 8.1 结构冒险

原因是不同指令同时争用同一硬件资源。

例如：

```text
I1 正在 MEM 阶段访问数据存储器
I4 正在 IF 阶段读取指令
```

如果取指和数据访存必须使用同一个单端口存储器，就可能发生资源冲突。

解决方法包括增加硬件资源、分离指令和数据存储器或 Cache、增加端口、插入停顿等。

### 8.2 数据冒险

数据冒险来自指令之间的数据依赖与流水时序冲突。

重点是 RAW、WAR、WAW。

#### RAW：写后读

```text
I1: ADD R1,R2,R3
I2: SUB R4,R1,R5
```

I1 写 R1。

I2 读 R1。

因此：

$$
\boxed{I1\rightarrow I2:\ RAW}
$$

RAW 是真正的数据相关。

#### WAR：读后写

```text
I1: ADD R3,R1,R2
I2: SUB R1,R4,R5
```

I1 需要读取 R1。

I2 后面才写 R1。

属于 WAR。

#### WAW：写后写

```text
I1: ADD R1,R2,R3
I2: SUB R1,R4,R5
```

两个指令均写 R1。

如果写回顺序错误，可能改变最终结果。

属于 WAW。

#### 三种相关总结

| 类型  | 前指令 | 后指令 | 本质    |
| --- | --- | --- | ----- |
| RAW | 写 X | 读 X | 真数据相关 |
| WAR | 读 X | 写 X | 反相关   |
| WAW | 写 X | 写 X | 输出相关  |

经典按序五级流水线主要关注 RAW 冒险。

由于其读寄存器和写寄存器阶段的顺序固定，WAR、WAW 通常不会成为实际执行冲突。

但在乱序执行和复杂多发射流水线中，这两类相关需要额外处理。

### 8.3 什么是 Forwarding？

Forwarding 称为数据前递或旁路。

目的：

不必等到生产者把结果写回寄存器后，消费者才能使用结果。

例如：

```text
I1: ADD R1,R2,R3
I2: SUB R4,R1,R5
```

I1 在 EX 结束时产生 R1 的新值。

I2 下一周期进入 EX 时需要 R1。

如果存在合适的旁路：

```text
I1 的 EX 结果
       ↓
     Forwarding
       ↓
I2 的 EX 输入
```

就可以直接使用。

因此：

$$
\boxed{\text{ALU}\rightarrow\text{ALU 通常可实现零停顿}}
$$

这里的零停顿指经典五级流水线具备相应 EX 前递通路的情况。

**Load-Use 停顿不是‘永远 1 拍’**

在经典五级、单周期访存、数据在 MEM 末端产生、消费者在下一 EX 使用并配备常规前递的模型中，相邻 LOAD-Use **通常需要 1 个停顿**。若无前递、主存延迟更长、采用不同的读写时序或存在其他优化，停顿数需重新推导。

### 8.4 Load-Use 冒险——必会

这是最重要的数据冒险特例。

```text
I1: LW  R1,0(R2)
I2: ADD R3,R1,R4
```

I1 读取主存数据，写入 R1。

I2 需要 R1 参与运算。

#### 为什么普通 Forwarding 仍然不够？

因为：

I1 的数据直到 MEM 阶段结束时才可用。

但紧跟着的 I2，在原定时序的 EX 阶段开始时就需要 R1。

具体时序：

| 周期 | I1：LW | I2：ADD |
| -- | ----- | ------ |
| 1  | IF    |        |
| 2  | ID    | IF     |
| 3  | EX    | ID     |
| 4  | MEM   | ID 停顿  |
| 5  | WB    | EX     |
| 6  |       | MEM    |
| 7  |       | WB     |

在第 4 周期结束时，LW 才取得数据。

因此 I2 需要晚一个周期进入 EX。

最终：

$$
\boxed{\text{典型 Load-Use 需要 1 个停顿周期}}
$$

#### 2024 年真题

题目问错误的说法。

其中有一项大意是：

> 所有数据冒险都可以通过转发电路解决。

答案就是这项错误。

因为典型 Load-Use 冒险无法仅靠普通前递完全消除。

做流水线题不要只问有没有数据相关，还要问数据何时产生、消费者何时需要，以及是否存在对应旁路。

### 8.5 无 Forwarding 时如何计算停顿？

假设：

```text
I1: LW  R1,0(R2)
I2: ADD R3,R1,R4
```

五级流水线：

$$
IF\rightarrow ID\rightarrow EX\rightarrow MEM\rightarrow WB
$$

没有任何 Forwarding。

I1 的正常时间：

| IF | ID | EX | MEM | WB |
| -- | -- | -- | --- | -- |
| 1  | 2  | 3  | 4   | 5  |

I2 最初计划在周期 3 进入 ID。

但是 R1 要到 I1 的周期 5 才写回。

#### 情况一：支持同周期先写后读

如果寄存器文件可以在周期 5 前半周期写，在后半周期读：

I2 可以在周期 5 完成读取。

于是原计划周期 3 的 ID，推迟至周期 5：

$$
\boxed{\text{额外等待 2 周期}}
$$

#### 情况二：同周期不能读写同一寄存器

则 I2 的 ID 最早在周期 6 完成。

需要：

$$
\boxed{\text{额外等待 3 周期}}
$$

两个结果不同，不是哪个公式错了，而是寄存器文件的时序假设不同。

这是流水线大题非常关键的审题条件。

## 九、2012 年 408 流水线综合大题

这道题值得反复做。

原题采用：

- 五级流水线；
- 按序发射、按序完成；
- 无转发；
- 同周期不能读写同一寄存器。

### 9.1 为什么后面的指令也会阻塞？

假设：

```text
I1: LOAD R1,[a]
I2: LOAD R2,[b]
I3: ADD  R1,R2
I4: STORE R2,[x]
```

在题设指令语义中，I3 要读取前面两条 LOAD 得到的数据。

I1 的 WB 在第 5 周期。

I2 的 WB 在第 6 周期。

所以 I3 必须等到第 7 周期才能完成 ID 中的寄存器读取。

由于流水线按序发射，I3 卡在 ID，会使它前面的 IF/ID 流水接口停止推进。

因此 I4 不能绕过 I3 继续正常前进。

这叫流水线的反压或阻塞传播。

### 9.2 为什么不能直接用 $k+n-1$？

因为该公式只适用于没有额外停顿的理想情形。

若有停顿：

$$
T=(k+n-1+s)T_c
$$

但要先通过时序分析算出 $s$。

不能看到 5 条指令就直接计算：

$$
5+5-1=9
$$

因为相关指令可能等待很多周期。

### 9.3 2012 真题中的变式

题目要求实现：

```text
x = x * 2 + a;
```

可以使用：

```asm
LOAD  R1,[x]
LOAD  R2,[a]
SHL   R1
ADD   R1,R2
STORE R2,[x]
```

这里采用原题给定的 ADD 操作数和目的寄存器语义。

其中：

```text
SHL R1
```

表示左移一位：

$$
R1\leftarrow2R1
$$

如果按照原题给定的流水线条件安排，本站解析给出的最短执行时间为：

$$
\boxed{17\text{ 个时钟周期}}
$$

为什么这么长？

因为没有 Forwarding，多个紧密相邻的数据依赖必须等待前面的寄存器写回。

因此流水线有不少气泡。

这说明：

有流水线不代表执行程序一定能达到 CPI=1。

## 十、控制冒险

### 10.1 什么是控制冒险？

假设：

```asm
BEQ R1,R2,L1
```

CPU 执行到这条指令时，下一条指令地址可能是顺序地址，也可能是 L1。

即：

$$
PC_{\text{next}}= \begin{cases} PC_{\text{branch}}+L,&\text{不跳转}\\ PC_{\text{target}},&\text{跳转} \end{cases}
$$

在分支条件尚未确定时，CPU 不知道应该从哪个地址取指。

这就是控制冒险。

#### 常见解决方法

| 方法                | 思想               |
| ----------------- | ---------------- |
| Stall             | 等分支结果确定          |
| Branch Prediction | 预测是否跳转           |
| Flush             | 清除错误路径指令         |
| 提前分支判断            | 尽早确定下一 PC        |
| 延迟分支              | 特定 ISA 通过延迟槽安排指令 |

### 10.2 分支预测失败为什么需要冲刷？

假设 CPU 预测不跳转：

```asm
BEQ R1,R2,L1
ADD R3,R4,R5
SUB R6,R7,R8
```

但分支实际需要跳转 L1。

那么已经进入流水线的 ADD、SUB 可能都属于错误路径。

CPU 必须防止这些指令产生错误的体系结构可见结果。

一种处理方式就是 Flush。

若某经典五级流水线在 EX 阶段结束时才确定分支，且正确 PC 下一周期即可开始取指，则一次错误预测可能清除两条较年轻的错误路径指令，产生约 2 周期的分支惩罚。

实际惩罚必须按题目给出的判断阶段和硬件约定计算。

### 10.3 2023 年真题：转发与控制冒险

指令序列：

```text
I1: add  s2,s1,s0
I2: load s3,0(s2)
I3: beq  t2,s1,L1
I4: addi t2,t2,20
```

条件：

- 数据冒险使用转发；
- 控制冒险使用硬件阻塞。

#### 分析 I1 与 I2

I1 写 s2。

I2 用 s2 计算 LOAD 的有效地址。

I1 的结果在 EX 结束时可用。

I2 下一周期在 EX 需要它。

因此可以转发，不需要额外数据停顿。

#### 分析 I3

I3 是条件分支。

由于使用硬件阻塞处理控制冒险，I3 的控制结果尚未确定时，后继 I4 的推进受到限制。

根据原题的问法，阻塞涉及的指令为：

$$
\boxed{I3,\ I4}
$$

原题答案 C。

这道题说明：

不能看到 I1 与 I2 存在 RAW，就立即认为 I2 必然阻塞。

## 十一、2014 年 408 流水线与指令系统综合题

这是一道非常有代表性的跨章节题。

题目给出 C 语言：

```c
for (int i = 0; i < N; i++)
    sum += A[i];
```

以及对应的汇编：

```text
I1: sll  R4,R2,2
I2: add  R4,R4,R3
I3: load R5,0(R4)
I4: add  R1,R1,R5
I5: addi R2,R2,1
I6: bne  R2,R6,loop
```

### 11.1 为什么数组元素大小是 4B？

第一条指令：

```text
sll R4,R2,2
```

说明：

$$
R4=R2\times2^2
$$

即：

$$
R4=4i
$$

下一条指令：

```asm
add R4,R4,R3
```

表示：

$$
R4=4i+\text{Base}(A)
$$

所以：

$$
\boxed{\operatorname{Addr}(A[i])=\operatorname{Base}(A)+4i}
$$

说明每个数组元素相隔 4 个字节。

因此：

$$
\boxed{A[i]\text{ 占 }4B=32bit}
$$

这是指令系统和数组地址计算的典型联合考法。

### 11.2 PC 相对寻址

原题分支指令：

```text
bne R2,R6,loop
```

指令地址：

```text
08048114H
```

下一条顺序地址：

```text
08048118H
```

目标地址：

```text
08048100H
```

机器码中的偏移字段：

```text
FFFAH
```

按 16 位补码解释：

$$
FFFAH=65530-65536=-6
$$

相差：

$$
-6\times4=-24B
$$

因此：

$$
PC_{\text{target}} = PC_{\text{branch}}+4+4\times(-6)
$$

代入：

$$
PC_{\text{target}} = 08048114H+4-24
$$

$$
\boxed{PC_{\text{target}}=08048100H}
$$

必须记住：

分支位移是以字节、指令字还是其他单位表示，要根据 ISA 或题目规定判断。

### 11.3 哪些指令存在 RAW？

| 生产者 | 消费者 | 相关寄存器 |
| --- | --- | ----- |
| I1  | I2  | R4    |
| I2  | I3  | R4    |
| I3  | I4  | R5    |
| I5  | I6  | R2    |

在原题无转发的流水线条件下，I2、I3、I4、I6 会受到相应数据相关引起的等待影响。

I6 本身是分支，因此还存在控制冒险。

此外：

本轮 I5 更新 R2，下一轮 I1 读取 R2，也存在跨迭代 RAW。

但原题规定每条分支带来 3 个阻塞周期，使 I5 有时间完成写回，因此下一轮 I1 不再产生额外的数据等待。

这里体现一个非常重要的区别：

$$
\boxed{\text{有数据相关}\ne\text{一定需要额外停顿}}
$$

## 十二、实际 CPI 与综合性能计算

这部分适合出模拟计算题。

### 12.1 有停顿时的 CPI

基础公式：

$$
CPI_{\text{actual}} = CPI_{\text{ideal}} + CPI_{\text{stall}}
$$

对于理想标量流水线：

$$
CPI_{\text{ideal}}\approx1
$$

若各种额外停顿互不重复计算：

$$
CPI = 1+ CPI_{\text{data}} + CPI_{\text{control}} + CPI_{\text{structure}}
$$

### 12.2 典型综合模拟题

假设一台五级流水线处理器：

- LOAD 指令占全部指令的 20%；
- LOAD 中有 30% 会发生需要停顿 1 周期的 Load-Use；
- 分支指令占 15%；
- 分支预测失败率为 10%；
- 每次预测失败损失 3 周期；
- 其他冒险忽略。

求 CPI。

#### 数据冒险贡献

$$
CPI_{\text{data}} = 0.2\times0.3\times1
$$

$$
\boxed{CPI_{\text{data}}=0.06}
$$

#### 控制冒险贡献

$$
CPI_{\text{control}} = 0.15\times0.1\times3
$$

$$
\boxed{CPI_{\text{control}}=0.045}
$$

#### 总 CPI

$$
CPI=1+0.06+0.045
$$

$$
\boxed{CPI=1.105}
$$

若 CPU 主频是 2GHz，执行 $10^9$ 条指令：

$$
T=\frac{10^9\times1.105}{2\times10^9}
$$

$$
\boxed{T=0.5525s}
$$

注意，这种概率加权计算默认题目中的停顿事件频率已定义清楚、且没有重复计入同一批停顿周期。

## 十三、5.7 多处理器的基本概念

这一节计算难度相对低，但容易考概念。

### 13.1 Flynn 分类

按指令流与数据流数量划分。

| 分类   | 指令流 | 数据流 | 典型情况         |
| ---- | --- | --- | ------------ |
| SISD | 单   | 单   | 传统串行处理       |
| SIMD | 单   | 多   | 向量处理、SIMD 运算 |
| MISD | 多   | 单   | 较少见的特殊结构     |
| MIMD | 多   | 多   | 多核、多处理器      |

#### SIMD

单指令多数据。

例如一条向量加法：

```text
A = [1,2,3,4]
B = [5,6,7,8]
```

运算：

$$
A+B=[6,8,10,12]
$$

同一种操作作用于多个数据元素。

#### MIMD

多个处理单元执行不同指令流。

现代通用多核 CPU 是典型例子。

所以：

$$
\boxed{\text{向量处理}\rightarrow SIMD}
$$

$$
\boxed{\text{典型多核}\rightarrow MIMD}
$$

### 13.2 什么是超标量处理器？

超标量 Superscalar 的核心是：

一个时钟周期可以发射多条指令。

例如双发射：

$$
IPC_{\max}=2
$$

则理想：

$$
CPI_{\min}=\frac12=0.5
$$

IPC 是每周期执行完成的平均指令数，在相同统计范围下：

$$
\boxed{IPC=\frac1{CPI}}
$$

#### 超流水线

超流水线是把原有流水阶段划分得更细。

目的主要是缩短时钟周期。

它不等于一个周期自动发射多条指令。

#### VLIW

VLIW 是超长指令字技术。

多个可以并行执行的操作由编译器安排在一条超长指令中。

| 类型   | 核心特点          |
| ---- | ------------- |
| 超标量  | 硬件动态寻找并行执行机会  |
| 超流水线 | 增加流水深度，提高时钟频率 |
| VLIW | 编译器静态安排多个并行操作 |

### 13.3 动态流水线与乱序执行

假设：

```text
I1: LW  R1,0(R2)
I2: ADD R3,R1,R4
I3: SUB R5,R6,R7
```

I2 依赖 I1。

但是 I3 与前两条指令可能不存在数据依赖。

如果 I1 因访存等待而迟迟无法提供 R1，某些乱序 CPU 可以让 I3 先执行。

这就是动态调度的重要思想。

#### 寄存器重命名

主要用于消除 WAR、WAW 这样的名称相关。

例如：

```text
I1: ADD R1,R2,R3
I2: SUB R1,R4,R5
```

逻辑上都写 R1。

硬件可以为不同结果分配不同的物理寄存器，避免名称冲突。

但：

真正的 RAW 数据依赖不能仅靠寄存器重命名消除。

#### 按序提交

尽管内部可以乱序执行，处理器仍需要保证体系结构可见行为符合程序的规定。

因此典型乱序 CPU 使用按序提交等机制维护精确异常和正确程序语义。

### 13.4 硬件多线程、SMT

硬件多线程允许一个物理核心维护多个硬件线程的执行状态。

| 类型     | 特征              |
| ------ | --------------- |
| 粗粒度多线程 | 遇到较长停顿再切换线程     |
| 细粒度多线程 | 以较细时间粒度轮换线程     |
| SMT    | 同一周期可以发射多个线程的指令 |

SMT 的典型目的是提高执行单元利用率。

假设：

$$
4\text{ 个物理核心}\times2\text{ 路 SMT}
$$

则操作系统可能看到：

$$
\boxed{8\text{ 个逻辑处理器}}
$$

但：

$$
\boxed{8\text{ 个逻辑处理器}\ne8\text{ 个完整物理核心}}
$$

因为同一个物理核心中的多个硬件线程共享大量执行资源。

### 13.5 UMA 与 NUMA

| 类型   | 特点                  |
| ---- | ------------------- |
| UMA  | 不同处理器访问共享内存的基础延迟较均匀 |
| NUMA | 访问本地内存和远程内存的代价不同    |

NUMA 中通常：

$$
T_{\text{local}}<T_{\text{remote}}
$$

这会影响多核程序的内存访问性能。

### 13.6 Amdahl 定律

这是理解多核加速的重要公式。

假设程序中可以并行的比例是 $p$，处理器数量为 $N$。

理想加速比：

$$
\boxed{ S(N)=\frac1{(1-p)+\frac pN} }
$$

例如程序有 90% 可以并行：

$$
p=0.9
$$

使用 4 个处理器：

$$
S(4)=\frac1{0.1+\frac{0.9}{4}}
$$

$$
S(4)=\frac1{0.325}
$$

$$
\boxed{S(4)\approx3.08}
$$

如果处理器数量无限增加：

$$
S_{\max}=\frac1{1-p}
$$

$$
\boxed{S_{\max}=10}
$$

所以：

增加处理器数量不能无限提高性能，串行部分会成为瓶颈。

### 题 5：Load-Use 与转发

```text
I1: LW  R1,0(R2)
I2: ADD R3,R1,R4
I3: SUB R5,R3,R6
```

条件：

- 经典五级流水线；
- 有 EX/MEM、MEM/WB 等常规前递；
- LOAD 数据在 MEM 结束时产生。

<Accordions>

LOAD-Use，通常停 1 周期。

I2 到 I3：

普通 ALU-ALU RAW，能够使用前递。

因此：

\boxed{1\text{ 个停顿周期}}

### 题 7：流水线 CPI

某处理器理想 CPI 为 1。

已知：

- 30% 的指令为 LOAD；
- 其中 20% 需要停顿 1 周期；
- 10% 为分支；
- 其中 25% 预测失败；
- 每次失败损失 2 周期。

忽略其他因素。

求实际 CPI。

<Accordions>
<Accordion title="展开：第 7 题参考答案与解析" id="co05-practice-7">

数据停顿：

$$
0.3\times0.2\times1=0.06
$$

分支停顿：

$$
0.1\times0.25\times2=0.05
$$

所以：

$$
CPI=1+0.06+0.05
$$

$$
\boxed{CPI=1.11}
$$

</Accordion>

### 题 8：2026 年综合题考法——扩展控制信号

## 十六、本章公式总表

| 考点             | 核心公式                                             |
| -------------- | ------------------------------------------------ |
| 编码 $N$ 种操作 | $\lceil\log_2N\rceil$                        |

| 微地址位数          | $\lceil\log_2M\rceil$                        |
| 控制存储器容量        | $N\times W$ bit                              |

| 理想流水总周期数       | $k+n-1$                                      |
| 含停顿总周期数        | $k+n-1+s$                                    |
| 流水线吞吐率         | $TP=n/T$                                     |
| 理想稳态最大吞吐率      | $1/T_c$                                      |

| 理想流水效率         | $E=S/k$                                      |
| 平均 CPI         | $\text{Cycles}/IC$                           |
| CPU 执行时间       | $IC\times CPI\times T_c$                     |
| CPI 停顿贡献       | $\text{事件频率}\times\text{每次损失周期}$             |
| SIMD           | 单指令流、多数据流                                        |

另外还要记住两个溢出表达式。

加法：

$$
\boxed{ OF_+ = \overline{A_s\oplus B_s} (A_s\oplus F_s) }
$$

减法：

$$
\boxed{ OF_- = (A_s\oplus B_s) (A_s\oplus F_s) }
$$

其中 $A_s,B_s,F_s$ 为对应的符号位。

## 十七、真正应掌握的三套解题方法

### 方法一：数据通路综合大题

拿到指令与 CPU 结构图后：

1. 翻译指令语义。 先写清楚操作数从哪里来、计算结果到哪里去。
2. 寻找真实数据路径。 标出寄存器、总线、MUX、ALU 和存储器。
3. 拆成 RTL 微操作。 例如 $MAR\leftarrow R1$。
4. 判断硬件资源约束。 尤其检查单总线冲突、暂存器和主存访问延迟。
5. 安排时钟节拍。 资源互不冲突时才考虑并行。
6. 写出控制信号。 包括 Rout、Rin、ALUop、MUX 选择、MemR/MemW。
7. 核对最终结果。 确认地址、操作数方向、写回位置都正确。

这是 2009、2015、2022、2024 等数据通路题的核心方法。

### 方法二：微程序控制计算题

面对微指令字段题：

先根据互斥关系把微命令分组。

再分别判断每组是否需要空操作编码。

计算各控制字段的位数。

然后计算判别字段和下一微地址字段。

最后得到微指令字长和控制存储器容量。

特别警惕：

$$
\boxed{\lceil\log_2(N+1)\rceil}
$$

中的 $+1$ 是否需要，以及各字段能否并行发出命令。

### 方法三：流水线综合大题

首先确定流水线阶段和时序假设。

再给每条指令列出：

$$
R(I_i),\qquad W(I_i)
$$

寻找 RAW、WAR、WAW。

重点检查 RAW 生产者的数据何时可用。

再检查消费者在哪个阶段需要它、是否有 Forwarding、寄存器同周期能否先写后读。

处理数据冒险后，再分析分支、结构冒险与流水线反压。

最后才画时空图，并统计总周期数。

不要一上来就套：

$$
k+n-1
$$

因为一旦存在冒险，实际周期数就可能明显增加。
