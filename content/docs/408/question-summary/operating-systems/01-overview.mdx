### 关键前提与易错点

<Callout type="warn" title="三个概念一定分开">

- **模式切换**：处理器执行权限改变，不代表更换了运行进程。
- **进程上下文切换**：保存一个进程的执行上下文，恢复另一个进程的上下文，需要内核参与。
- **系统调用**：用户程序受控请求内核服务，通常经历用户态到内核态再返回，但不一定阻塞或切换进程。

</Callout>

### 核心概念分项对照

<Tabs items={["中断与异常", "系统调用", "模式与进程切换", "引导链"]} defaultIndex={0}>

<Tab value="中断与异常">

外部中断通常**异步**，异常通常因当前指令而**同步**触发。Fault 常在纠正问题后重新执行故障指令；Trap 可能从后继指令继续；具体的 PC、PSW 保存方式由 ISA 决定。

</Tab>

<Tab value="系统调用">

`read()` 等接口最终可陷入内核，但普通数学库函数 `sin()` 通常在用户态完成。**用户态可执行用于请求系统调用的 Trap/SVC 类指令**；不代表它有权执行任意特权指令。

</Tab>

<Tab value="模式与进程切换">

CPU 响应中断、异常或系统调用时可能仍在同一进程中执行；只有调度器决定切换且满足切换条件时，才需要保存/恢复两个进程的上下文。

</Tab>

<Tab value="引导链">

传统 BIOS/MBR 与 UEFI 的启动路径不同。UEFI 常结合 GPT 和 EFI 系统分区（ESP），但 GPT 并非所有 UEFI 情形的绝对必要条件。启动阶段先加载引导组件，再初始化内核并接管硬件。

</Tab>

</Tabs>

## 一、操作系统的本质：为什么计算机必须有操作系统？

### 1.1 操作系统到底是什么？

操作系统（Operating System，OS）是一种系统软件，负责控制和管理计算机系统的硬件、软件资源，合理组织计算机工作，并为用户和应用程序提供方便的接口和运行环境。

它可以理解为硬件与应用程序之间的资源管理层。

```text
              用户
               │
        应用程序 / Shell
               │
        库函数与系统调用
               │
┌───────────────────────────┐
│          操作系统          │
│                           │
│  处理机管理   内存管理      │
│  文件管理     设备管理      │
│  资源保护     进程通信      │
└───────────────────────────┘
               │
        CPU / RAM / 磁盘
        网络设备 / 外设
```

思考一个问题：

假如没有操作系统，三个程序同时希望访问硬盘，两个程序同时希望占用 CPU，会怎样？

程序必须自己决定：

- 谁先使用 CPU？
- 如何避免同时修改同一片内存？
- 磁盘空间分配给谁？
- 谁能读取哪个文件？
- 一个程序崩溃后，如何避免破坏其他程序？

如果让每个程序自己管理，不仅开发困难，而且无法可靠地实现资源保护。

所以操作系统的存在，首先解决的是资源的统一管理、分配与保护问题。

### 1.2 操作系统的三个核心身份

| 身份    | 含义              | 具体例子                        |
| ----- | --------------- | --------------------------- |
| 资源管理者 | 统一分配、回收、协调硬件资源  | CPU 调度、内存分配                 |
| 硬件抽象层 | 将复杂物理资源封装为易用对象  | 文件、进程、虚拟地址空间                |
| 服务提供者 | 提供应用程序访问系统资源的接口 | `read()`、`write()`、`fork()` |

这三个身份之间存在联系。

例如，程序需要读取硬盘上的一个文件：

1. 程序指定文件名。
2. 操作系统根据文件系统找到数据的位置。
3. 操作系统协调设备完成数据读取。
4. 操作系统将结果返回给程序。

程序不需要知道具体磁盘的控制指令，也不需要自己调度磁盘。

这就是硬件抽象与资源管理。

### 1.3 操作系统的四大管理功能

处理机管理： 负责进程和线程管理、CPU 分配、调度与进程同步等。

存储器管理： 负责内存空间的分配回收、地址转换、内存保护和虚拟内存管理。

文件管理： 负责文件的创建、删除、读写、目录管理和外存空间管理。

设备管理： 负责设备分配、驱动、I/O 控制、缓冲及设备共享。

这些功能分别会在后续章节深入学习。本章主要理解操作系统为什么要提供这些功能。

### 1.4 操作系统提供哪些接口？

这里有一道非常典型的 408 真题。

【2010 年真题】

下列选项中，操作系统提供给应用程序的接口是（ ）。

A. 系统调用\
B. 中断\
C. 库函数\
D. 原语

答案：A

逐项分析：

- A 正确。系统调用是操作系统向应用程序提供内核服务的接口。
- B 错误。中断是一种事件处理机制，不是应用程序使用操作系统服务的一般程序接口。
- C 错误。库函数是程序库提供的函数，并不等于操作系统的系统调用。
- D 错误。原语是完成特定原子操作的程序段，不是面向应用程序的通用服务接口。

这里要特别记住：

库函数 ≠ 系统调用。

例如：

```text
double y = sin(1.0);
```

调用 `sin()` 通常只在用户态完成。

而：

```text
read(fd, buf, 100);
```

`read()` 通常是 C 运行库提供的包装函数，内部通过相应机制请求内核的读文件服务。

所以：

- 库函数调用不一定引起用户态与内核态切换。
- 系统调用需要进入内核提供服务。
- 一个库函数内部可以调用一个或多个系统调用。

这一区别在历年真题中反复出现。

## 二、操作系统的四个基本特征

必须掌握：

并发、共享、虚拟、异步。

其中，并发和共享是两个最基本的特征。

### 2.1 并发与并行

这是整个 408 中最容易混淆的概念之一。

并发（Concurrency）：多个事件在同一时间间隔内发生或推进。

并行（Parallelism）：多个事件在同一时刻真正同时进行。

例如，单核 CPU 运行程序 A、B、C。

```text
时间 ─────────────────────────────►

CPU     A A A │ B B │ C C │ A A │ B B
        └──────── 时间片轮换 ───────┘

宏观看：A、B、C 同时推进
微观看：某一时刻 CPU 只执行一个程序
```

这就是并发。

如果有两个 CPU 核心：

```text
时间 ───────────────────────►

CPU 0   A A A A A A A
CPU 1   B B B B B B B
```

此时 A、B 才可能真正并行执行。

注意：多核不代表所有程序都必须并行。程序仍可能因为资源限制或调度策略而交替执行。

### 真题：哪些对象可以并行？

【2009 年真题】

单处理机系统中，可并行的是（ ）。

Ⅰ. 进程与进程\
Ⅱ. 处理机与设备\
Ⅲ. 处理机与通道\
Ⅳ. 设备与设备

A. 仅Ⅰ、Ⅱ、Ⅲ\
B. 仅Ⅰ、Ⅱ、Ⅳ\
C. 仅Ⅰ、Ⅲ、Ⅳ\
D. Ⅱ、Ⅲ、Ⅳ

答案：D

分析：

Ⅰ. 单处理机同一时刻只能执行一个进程的指令流，因此两个进程通常只能并发，不能真正并行。

Ⅱ. CPU 正在运算时，磁盘控制器可以独立进行数据传输，因此 CPU 与设备能够并行。

Ⅲ. 通道是一种专门管理 I/O 的处理机构，可以与 CPU 并行工作。

Ⅳ. 不同 I/O 设备具有相对独立的控制部件，可以并行工作。

所以选择 D。

这里的真正考点是：单处理机不等于整个计算机系统只能执行一项活动。

CPU 和设备能够并行工作，是多道程序技术提高资源利用率的重要硬件基础。

### 2.2 共享：多个程序如何使用同一个资源？

共享是指系统中的资源可供多个并发执行的进程共同使用。

分为两类。

| 共享方式 | 特点               | 典型例子    |
| ---- | ---------------- | ------- |
| 互斥共享 | 同一时刻只允许一个进程使用    | 独占打印机   |
| 同时共享 | 多个进程可以在同一时间段共同使用 | 多进程读取文件 |

例如，两个进程都要使用一台传统独占式打印机。

如果没有协调：

```text
进程 A：打印第 1 页
进程 B：打印第 1 页
进程 A：打印第 2 页
进程 B：打印第 2 页
```

结果可能相互混杂。

操作系统必须协调对打印机的使用，保证互斥访问，或者借助 SPOOLing 将多个打印任务排队处理。

#### 高频陷阱

同时共享不一定意味着两个进程在每一个物理时刻都同时访问资源。

共享强调资源的使用关系，而并行强调活动发生的时间关系。

并发与共享之间具有非常密切的联系：

- 并发执行产生了资源共享的需求。
- 资源共享又要求操作系统提供互斥与同步机制。
- 共享资源的竞争进一步造成进程执行顺序的不确定性。

### 2.3 虚拟：让一个物理资源表现为多个逻辑资源

虚拟并不是凭空创造硬件资源，而是通过管理和映射技术，使用户感受到更方便、更独立的逻辑资源。

主要有时分复用和空分复用两种思想。

时分复用：

```text
一颗 CPU
   │
   ├── 时间片 1 → 进程 A
   ├── 时间片 2 → 进程 B
   ├── 时间片 3 → 进程 C
   └── 时间片 4 → 进程 A
```

多个进程仿佛各自拥有 CPU。

空分复用：

```text
物理内存
┌─────────────┐
│ 进程 A 区域  │
├─────────────┤
│ 进程 B 区域  │
├─────────────┤
│ 进程 C 区域  │
└─────────────┘
```

不同程序共享物理内存的不同部分。

但是，需要理解一个细节：

普通内存分区体现的是空间复用和隔离，而现代虚拟内存的核心还涉及虚拟地址到物理地址的映射。

因此，内存分区与虚拟内存不是完全相同的概念。

其他典型技术包括：

- 虚拟处理器：通过调度实现 CPU 时分复用。
- 虚拟内存：通过地址转换和存储管理提供独立地址空间。
- SPOOLing：把独占式设备包装成可供多个用户使用的逻辑设备。
- 虚拟机：将物理计算资源抽象为多个虚拟计算环境。

### 2.4 异步：为什么程序的执行顺序不能完全预测？

异步是指多道程序环境中，各程序按照不可预知的速度向前推进。

例如：

```text
进程 A：运行 → 等待磁盘 → 就绪 → 运行
进程 B：就绪 → 运行 → 等待网络 → 就绪
进程 C：就绪 → 运行 → 时间片耗尽
```

由于调度、资源竞争和 I/O 完成时间不确定，每个进程何时得到 CPU、何时结束等待可能不同。

但这里有一个重要区别：

异步不等于程序结果必然不确定。

如果进程之间有正确的同步和互斥机制，即使执行次序不同，最终结果也可以保持一致。

如果没有正确的同步机制，多个进程修改共享数据，就可能出现竞态条件，导致结果不一致。

### 2.5 本节综合判断题

判断下列说法：

| 说法                   | 判断 | 原因           |
| -------------------- | -- | ------------ |
| 单核 CPU 可以实现并发        | 正确 | 通过时间片切换      |
| 单核 CPU 无法让 CPU 与磁盘并行 | 错误 | CPU 与设备可独立工作 |
| 并发与并行完全相同            | 错误 | 是否同一时刻执行不同   |
| 共享资源一定可以同时访问         | 错误 | 存在互斥共享       |
| 虚拟化能够增加物理 CPU 数量     | 错误 | 增加的是逻辑资源     |
| 异步性意味着执行结果必然随机       | 错误 | 同步机制可保证结果    |
| 多任务操作系统必须具有多个 CPU    | 错误 | 单核可以并发执行     |

这一部分的知识量不大，但经常作为综合选择题的判断依据。

## 三、操作系统的发展历程

理解发展史，不应该只是记住不同系统的名字，而应该抓住一个问题：

上一代系统存在什么问题？下一代系统通过什么机制解决？

### 3.1 从手工操作到现代操作系统

```text
手工操作
   │ 人工操作太慢，CPU 经常空闲
   ▼
单道批处理
   │ 可以自动执行作业，但等待 I/O 时 CPU 空闲
   ▼
多道批处理
   │ CPU 利用率提高，但缺乏良好交互
   ├──────────────┐
   ▼              ▼
分时系统          实时系统
追求响应快        追求满足截止时间
```

### 3.2 手工操作阶段

早期计算机没有成熟的操作系统。

程序员需要手动装入程序、启动执行、等待结果。

主要问题是人机速度矛盾：人类操作速度远低于 CPU 的处理速度。

为了减少人工干预，产生了批处理思想。

### 3.3 脱机输入/输出

这里需要补充一个容易在选择题中出现的概念。

早期计算机可以使用外围机，预先将作业输入到磁带，再由主机批量处理。

```text
输入设备
   ↓
外围机
   ↓
磁带
   ↓
主机处理
   ↓
磁带
   ↓
外围机
   ↓
输出设备
```

这样减少了主机等待慢速输入/输出设备的时间。

所谓脱机 I/O，强调输入输出工作可以脱离主计算机，由外围设备完成。

后来的 SPOOLing 技术借鉴了脱机输入/输出的思想，但能够利用磁盘和操作系统软件模拟脱机工作过程。

### 3.4 单道批处理系统

单道批处理允许作业自动依次执行。

一个作业结束后，再执行下一个作业。

例如：

```text
作业 A
CPU 计算：3 ms
I/O 等待：7 ms
CPU 计算：2 ms
```

执行过程：

```text
CPU：计算 A ─── 空闲 7ms ─── 计算 A
```

总历时为：

$$
T=3+7+2=12\text{ ms}
$$

其中 CPU 真正工作的时间：

$$
T_{\mathrm{CPU}}=5\text{ ms}
$$

因此：

$$
U_{\mathrm{CPU}} =\frac{5}{12}\times100\% \approx41.67\%
$$

这里的 CPU 利用率很低，因为等待 I/O 时，没有其他作业可以占用 CPU。

### 3.5 多道批处理系统：为什么能提高 CPU 利用率？

**多道程序设计（Multiprogramming）**&#x2060;允许多个作业同时驻留内存。

当一个作业等待 I/O 时，CPU 可以运行其他已就绪作业。

例如：

```text
时间 ─────────────────────────►

进程 A    CPU计算 │ I/O等待 ────│ CPU
进程 B            │ CPU计算 ───│ I/O等待
进程 C                         │ CPU计算
```

其核心思想是：

用其他程序的计算时间，填补当前程序的 I/O 等待时间。

注意：

不是让单核 CPU 同一时刻执行多个进程，而是重叠不同资源的工作时间。

多道程序设计的主要优点包括：

1. CPU 利用率提高。
2. I/O 设备利用率提高。
3. 系统吞吐量提高。
4. 减少资源闲置。

但代价也很明显：

- 调度和进程切换需要额外时间。
- 内存与资源管理复杂。
- 需要更完善的同步与互斥机制。
- 用户交互能力通常较差。

### 真题一：多道程序的优势

【2017 年真题】

与单道程序系统相比，多道程序系统的优点是（ ）。

Ⅰ. CPU 利用率高\
Ⅱ. 系统开销小\
Ⅲ. 系统吞吐量大\
Ⅳ. I/O 设备利用率高

A. 仅Ⅰ、Ⅲ\
B. 仅Ⅰ、Ⅳ\
C. 仅Ⅱ、Ⅲ\
D. Ⅰ、Ⅲ、Ⅳ

答案：D

原因：

Ⅰ、Ⅲ、Ⅳ均是多道程序设计的典型优势。

Ⅱ错误。为了支持多道程序，操作系统必须管理更多状态、维护更多数据结构并进行调度切换，系统开销通常不会更小。

### 真题二：程序越多越好吗？

【2022 年真题】

下列关于多道程序系统的叙述中，不正确的是（ ）。

A. 支持进程的并发执行\
B. 不必支持虚拟存储管理\
C. 需要实现对共享资源的管理\
D. 进程数越多 CPU 利用率越高

答案：D

这里的陷阱是：

> 提高多道程序度通常有利于隐藏 I/O 等待，但并不意味着进程越多，CPU 利用率就能无限提高。

当进程数量过多时，可能出现：

- 内存不足。
- 频繁缺页。
- 大量进程切换。
- 资源竞争。
- 系统抖动（Thrashing）。

最终反而可能导致 CPU 利用率下降。

拓展计算：多道程序系统的 CPU 利用率

假设每个作业独立地有 $p$ 的时间概率处于 I/O 等待，系统中同时有 $n$ 个作业，而且只要存在可运行作业，CPU 就能有效工作。

在忽略调度开销等理想条件下：

$$
P(\text{所有作业均在等待})=p^n
$$

所以：

$$
\boxed{U_{\mathrm{CPU}}=1-p^n}
$$

例如：

$$
p=0.8,\quad n=3
$$

则：

$$
U_{\mathrm{CPU}}=1-0.8^3=0.488
$$

即：

$$
\boxed{48.8\%}
$$

如果增加到 5 个作业：

$$
U_{\mathrm{CPU}}=1-0.8^5=67.232\%
$$

说明多道程序度增加可以提高 CPU 利用率。

但是，该公式只是理想概率模型，不适用于存在明显内存竞争、相关等待和调度开销的所有真实系统。

### 3.6 分时操作系统

分时系统的核心是：将 CPU 时间分成较短的时间片，使多个用户能够交互式使用计算机。

典型特点：

| 特征  | 解释              |
| --- | --------------- |
| 多路性 | 多个用户可以同时使用系统    |
| 独立性 | 用户感觉自己拥有独立的工作环境 |
| 及时性 | 系统能够较快响应用户      |
| 交互性 | 用户与系统能够持续交互     |

假设三个用户同时使用一台计算机。

```text
CPU 时间片：

用户 A → 用户 B → 用户 C → 用户 A → …
```

只要时间片足够短，各个用户便会觉得系统响应及时。

但需要理解：

分时系统追求的是响应速度，不是严格保证任务在某个截止时间前完成。

### 3.7 实时操作系统

实时系统（Real-Time Operating System）强调任务执行的时间约束。

其关键不只是“速度快”，而是响应时间具有可预测性，能够满足规定的截止时间。

分为两类：

硬实时系统：

任务必须满足关键截止时间。

例如飞行控制、工业安全控制等。

软实时系统：

偶尔错过截止时间通常不会导致整个系统失效，但会降低服务质量。

例如部分音视频处理任务。

#### 核心对比

| 比较项目   | 多道批处理   | 分时系统    | 实时系统      |
| ------ | ------- | ------- | --------- |
| 首要目标   | 吞吐量、利用率 | 交互、响应速度 | 时间约束      |
| 用户交互   | 通常较弱    | 强       | 按应用需求     |
| 时间片    | 不一定     | 典型机制    | 可采用多种调度方式 |
| 截止时间保证 | 通常没有    | 通常没有    | 核心要求      |
| 典型场景   | 批量任务    | 多用户交互   | 工业控制      |

### 3.8 真题：批处理系统

【2016 年真题】

下列关于批处理系统的叙述中，正确的是（ ）。

Ⅰ. 批处理系统允许多个用户与计算机直接交互。\
Ⅱ. 批处理系统分为单道批处理系统和多道批处理系统。\
Ⅲ. 中断技术使得多道批处理系统的 I/O 设备可与 CPU 并行工作。

A. 仅Ⅱ、Ⅲ\
B. 仅Ⅱ\
C. 仅Ⅰ、Ⅱ\
D. Ⅰ、Ⅲ

答案：A

解析：

- Ⅰ错误。批处理系统通常缺乏运行时的直接交互。
- Ⅱ正确。批处理系统包括单道和多道批处理。
- Ⅲ正确。中断机制使设备完成 I/O 后再通知 CPU，而 CPU 在设备工作期间可以执行其他任务。

这里还要区分两个概念：

CPU 与 I/O 设备并行依赖设备具有相对独立的工作能力。

中断技术的关键贡献是让 CPU 不必一直忙等设备完成，可以先处理其他任务。

## 四、CPU 的运行模式：用户态与内核态

这是本章最重要的内容之一。

历年题目经常直接考查用户态、内核态与特权指令之间的关系。

### 4.1 为什么需要两种运行模式？

假设一个普通程序能够任意执行以下操作：

```text
关闭所有中断
修改其他进程的页表
修改中断向量表
直接控制硬盘
读取受保护的内核数据
```

那么这个程序就可能破坏系统的正常运行。

为了防止这种情况，CPU 硬件提供不同的特权级。

常见的两种运行模式是：

- 用户态（User Mode）
- 内核态（Kernel Mode）

CPU 处于哪种模式，由硬件体系结构规定的处理器状态信息决定，例如程序状态字 PSW 或相应控制寄存器。

### 4.2 用户态与内核态的区别

| 比较项目        | 用户态        | 内核态         |
| ----------- | ---------- | ----------- |
| 权限          | 受限制        | 高权限         |
| 普通算术指令      | 可以         | 可以          |
| 合法普通访存      | 可以         | 可以          |
| 特权指令        | 不可合法执行     | 可以          |
| 修改页表        | 不可以        | 可以          |
| 控制关键 I/O 设备 | 不可以直接进行    | 可以          |
| 执行系统调用服务程序  | 不可以        | 可以          |
| 典型执行程序      | 应用程序、Shell | 内核服务、中断处理程序 |

#### 高频陷阱一：内核态能不能执行非特权指令？

当然可以。

内核态具有更高的权限，并不是只能执行特权指令。

即：

$$
\text{用户态允许指令}\subseteq\text{内核态允许指令}
$$

这里的包含关系是按照典型二态权限模型理解的。

### 真题

【2022 年真题】

下列关于 CPU 模式的叙述中，正确的是（ ）。

A. CPU 处于用户态时只能执行特权指令\
B. CPU 处于内核态时只能执行特权指令\
C. CPU 处于用户态时只能执行非特权指令\
D. CPU 处于内核态时只能执行非特权指令

答案：C

因为：

用户态不能合法执行特权指令，而内核态可以执行特权和非特权指令。

### 4.3 什么是特权指令？

特权指令是只允许具有足够特权的程序执行的机器指令。

典型包括：

| 操作            | 是否通常属于特权操作 | 原因        |
| ------------- | ---------- | --------- |
| 关闭中断          | 是          | 影响系统控制权   |
| 设置硬件定时器       | 是          | 影响计时和调度   |
| 修改页表基址寄存器     | 是          | 影响地址空间保护  |
| 修改内存保护寄存器     | 是          | 影响访问权限    |
| 修改中断向量表关键状态   | 是          | 可能劫持中断入口  |
| 执行直接设备 I/O 指令 | 通常是        | 控制设备资源    |
| 普通加减乘除        | 否          | 普通计算      |
| 普通跳转          | 否          | 正常程序控制    |
| 合法内存访问        | 否          | 应用程序必需    |
| 普通函数调用        | 否          | 不直接改变系统权限 |

注意：现代某些体系结构采用内存映射 I/O，因此不一定存在统一的专用 I/O 指令。设备访问权限也可以通过页表和其他保护机制控制。

408 通常使用“直接 I/O 指令属于特权指令”的经典模型出题。

**用户态可以发起 Trap/SVC，但不能在用户态任意执行内核操作**

硬件通常允许用户程序执行受控陷入指令以进入系统调用入口；陷入发生后切换特权级并按约定验证参数。区分**可在用户态发出该指令**与**可不经检查直接执行任意特权功能**。

### 4.4 Trap 指令为什么不是普通意义上的特权指令？

这是整章必考陷阱。

Trap（陷入/访管）指令必须允许用户程序执行。

原因很简单：

如果普通用户程序不能执行系统调用入口指令，就无法主动请求操作系统服务。

例如：

```text
用户程序
   │
   │ 执行 Trap / syscall / svc
   ▼
CPU 硬件受控地切换权限
   │
   ▼
内核态
   │
   │ 执行内核服务
   ▼
返回用户态
```

必须把两个动作分开：

1. 用户程序执行 Trap 指令。
2. 硬件根据 Trap 指令切换到内核态。

第一个动作允许在用户态发起。

第二个动作由处理器的受控机制完成。

所以：

> 可以导致 CPU 进入内核态的指令，不一定是特权指令。

### 真题

【2014 年真题】

下列指令中，不能在用户态执行的是（ ）。

A. trap 指令\
B. 跳转指令\
C. 压栈指令\
D. 关中断指令

答案：D

Trap 可以由用户程序执行。

跳转和压栈属于普通程序运行所需操作。

关中断会改变系统中断状态，需要较高权限。

### 4.5 修改 PC 是否属于特权操作？

不一定。

普通程序执行：

```text
JMP label
```

就是修改 PC 的一种方式。

函数调用、条件跳转、函数返回都会改变程序计数器。

因此，修改 PC 的值本身不等于执行特权指令。

但是，不能由此推断：

> 用户程序可以任意跳转到内核代码，并获得内核权限。

因为 CPU 的执行权限与当前处理器模式有关，普通跳转不会自动提升特权级。

### 4.6 命令解释程序是不是运行在内核态？

通常不是。

命令解释程序，例如 Shell，是用户与操作系统交互的程序。

它可以：

- 读取用户输入；
- 解析命令；
- 执行普通计算；
- 调用库函数；
- 发起系统调用。

但它不必始终运行在内核态。

### 真题

【2011 年真题】

下列选项中，在用户态执行的是（ ）。

A. 命令解释程序\
B. 缺页处理程序\
C. 进程调度程序\
D. 时钟中断处理程序

答案：A

解析：

命令解释程序通常运行在用户态。

缺页处理、调度和时钟中断处理都属于内核职责。

### 4.7 进入内核态和返回用户态

最重要的是理解状态转换方向。

```text
┌─────────────────────┐
│       用户态         │
│                     │
│ 普通程序正在执行     │
└──────────┬──────────┘
           │
           │ 系统调用
           │ 外部中断
           │ 异常
           ▼
┌─────────────────────┐
│       内核态         │
│                     │
│ 处理中断/异常        │
│ 执行内核服务         │
│ 必要时进行调度       │
└──────────┬──────────┘
           │
           │ 恢复相应程序现场
           │ 特权返回
           ▼
        用户态
```

用户态进入内核态： 通常由系统调用、中断、异常等受控事件触发。

内核态返回用户态： 通过受控的特权返回机制完成，可能继续原进程，也可能运行另一个用户进程。

需要注意：

内核态处理程序也可能因中断或异常而进入其他内核处理路径，不是所有中断都会表现为用户态到内核态的转换。

## 五、中断与异常：彻底理解操作系统如何获得控制权

这一部分是整章中最需要理解原理的内容。

### 5.1 先思考一个问题

假设只有一个 CPU，当前用户程序进入死循环：

```text
while (1) {
    // 永远循环
}
```

如果它始终不主动请求操作系统服务，操作系统如何重新获得 CPU 控制权？

答案是：依靠硬件中断机制，典型方式是时钟中断。

CPU 可以在运行用户程序时响应中断，进入预先设置的中断处理程序。

这为抢占式调度提供了重要条件。

### 5.2 中断的本质

中断机制使 CPU 能够在正常执行程序的过程中，响应需要及时处理的事件，暂停当前执行流，进入相应的处理程序。

处理完成后，CPU 可以恢复原来的执行流，也可以在调度器决定后运行其他任务。

```text
CPU 正常执行程序
       │
       ▼
  外部事件到达
       │
       ▼
硬件响应中断并保存必要信息
       │
       ▼
进入中断处理程序
       │
       ▼
处理设备事件或时钟事件
       │
       ▼
恢复原程序 / 执行其他进程
```

中断的重要意义：

- 使 CPU 不必反复查询设备状态。
- 支持 CPU 与设备并行工作。
- 支持 I/O 完成通知。
- 支持抢占式进程调度。
- 为系统处理异步事件提供机制。

### 5.3 中断与异常的分类

教材通常区分：

外中断（Interrupt）：由 CPU 当前指令执行之外的事件引起。

内中断/异常（Exception）：由当前执行指令或其执行条件引起。

| 事件        | 类型   | 是否通常同步 |
| --------- | ---- | ------ |
| 时钟中断      | 外中断  | 异步     |
| 键盘输入完成    | 外中断  | 异步     |
| 磁盘 I/O 完成 | 外中断  | 异步     |
| 网络数据到达    | 外中断  | 异步     |
| 整数除零      | 异常   | 同步     |
| 非法指令      | 异常   | 同步     |
| 缺页        | 异常   | 同步     |
| 越权访存      | 异常   | 同步     |
| 系统调用陷入    | 主动陷入 | 同步     |

这里必须掌握：

外中断通常与当前指令没有直接因果关系；异常通常由当前执行的指令引起。

### 5.4 同步和异步是什么意思？

同步异常强调：

当程序执行到某一特定指令，并满足特定机器状态时，就会触发相应异常。

例如：

```c
int a = 10;
int b = 0;
int c = a / b;
```

在将整数除零报告为异常的体系结构中，异常直接与除法指令有关。

而键盘中断：

用户什么时候按下键盘，与 CPU 当前执行哪一条普通指令没有必然关系。

因此是异步事件。

### 5.5 外部中断：可屏蔽与不可屏蔽

可屏蔽中断（Maskable Interrupt）

能够由硬件中断屏蔽机制暂时屏蔽。

例如许多普通设备中断。

不可屏蔽中断（Non-Maskable Interrupt，NMI）

不能通过普通可屏蔽中断控制位屏蔽。

通常用于某些严重硬件事件。

注意：

不可屏蔽不代表在所有处理器状态下都绝对立即响应，也不代表它完全不受硬件优先级和其他机制影响。

### 5.6 异常的三种典型类型

| 类型    | 英文    | 主要特点           | 例子        |
| ----- | ----- | -------------- | --------- |
| 故障    | Fault | 可能修复后重新执行当前指令  | 缺页        |
| 陷阱/自陷 | Trap  | 程序主动请求或指令执行后报告 | 系统调用、调试陷阱 |
| 终止    | Abort | 严重错误，通常无法正常恢复  | 严重机器状态错误  |

不同 CPU 体系结构可能采用不同分类，这里使用 408 常见的概念模型。

#### 重点：为什么缺页属于异常，而不是外中断？

假设 CPU 执行：

```text
x = a[100];
```

执行该访存指令时，MMU 发现对应虚拟页当前没有驻留主存。

CPU 触发缺页异常。

```text
执行访存指令
     │
     ▼
检查地址转换和页表项
     │
     ▼
页面不在主存
     │
     ▼
产生缺页异常
     │
     ▼
内核缺页处理程序
     │
     ▼
必要时把页面调入内存
     │
     ▼
更新页表
     │
     ▼
重新执行原访存指令
```

这里的缺页异常来自访存指令。

所以它是同步异常。

另外：

缺页异常本身与调页所需的磁盘 I/O 完成中断属于两个不同事件。

前者由当前访存引起；后者可能由设备在数据传输完成后产生。

**中断现场：硬件/软件职责有体系结构差异**

教材典型模型中，硬件机制负责进入异常入口、保存或提供必要的 PC/状态信息，内核入口代码再按调用约定保存需要的软件可见寄存器。不能把“PC 一定硬件自动压栈”或“PSW 一定由固定寄存器保存”作为所有 ISA 的通用结论。

### 5.7 中断响应全过程：硬件与操作系统分别干什么？

这是典型的 408 高频考点。

假设用户程序执行时，磁盘设备发出了中断请求。

典型处理过程：

阶段一：中断到达

磁盘控制器向中断控制器或 CPU 发出中断请求。

阶段二：CPU 判断是否响应

CPU 根据当前中断状态、优先级等机制判断能否响应。

对于典型指令边界响应模型，CPU 在完成当前指令后进入中断响应过程。

阶段三：硬件完成必要状态保护

包括：

- 保存返回地址或断点信息。
- 保存必要的处理器状态。
- 必要时切换特权级和执行栈。
- 根据中断向量进入预设处理入口。

阶段四：操作系统保护软件现场

中断入口代码根据需要保存通用寄存器等现场信息。

阶段五：执行中断服务程序

例如：

- 确认中断源。
- 读取设备状态。
- 处理或记录设备输入数据。
- 向设备控制器应答。
- 唤醒等待 I/O 的进程。

阶段六：恢复执行

可能：

- 恢复原程序；
- 触发调度；
- 切换到其他进程。

### 5.8 重点表：谁负责保存什么？

| 操作              | 典型执行主体        |
| --------------- | ------------- |
| 响应中断并进入可信入口     | 硬件            |
| 保存必要断点/返回地址     | 硬件机制          |
| 保存必要处理器状态，如 PSW | 硬件机制          |
| 切换到中断处理所需的权限模式  | 硬件机制          |
| 保存通用寄存器         | 通常由 OS 入口代码完成 |
| 处理中断事件          | OS / 驱动       |
| 唤醒进程            | OS            |
| 进程调度            | OS            |
| 恢复软件保存的通用寄存器    | OS            |
| 完成受控中断返回        | 软件配合硬件返回指令    |

这里的具体保存位置和保存寄存器集合因处理器体系结构而不同。

考试主要考查硬件与软件的基本职责划分。

### 真题：中断现场保护

【2015 年真题】

处理外部中断时，应该由操作系统保存的是（ ）。

A. 程序计数器 PC 的内容\
B. 通用寄存器的内容\
C. 快表 TLB 中的内容\
D. Cache 中的内容

答案：B

原因：

CPU 响应中断时，必要的断点和处理器状态首先由硬件机制保存。

而通用寄存器通常由操作系统的中断入口代码进一步保存。

TLB 和 Cache 不需要在每次中断发生时完整保存。

### 5.9 PSW 为什么特别重要？

PSW（程序状态字）或等价的处理器状态信息，可能包含：

- 条件标志；
- 中断控制信息；
- 处理器运行模式；
- 其他关键状态位。

而 PC 保存下一条待执行指令或相应返回位置。

普通函数调用一般也需要保存返回地址，但未必需要保存完整处理器状态。

所以普通函数调用与中断处理的现场保护要求不同。

### 真题

【2012 年真题】

中断处理和子程序调用都需要压栈以保护现场，中断处理一定会保存而子程序调用不需要保存其内容的是（ ）。

A. 程序计数器\
B. 程序状态字寄存器\
C. 通用数据寄存器\
D. 通用地址寄存器

答案：B

因为两者都需要能够返回原控制流，通常都要处理返回地址。

但中断处理涉及 CPU 状态恢复，需要保护程序状态字或等价状态。

### 5.10 中断返回后执行哪条指令？

这个问题经常考。

对于典型外部中断：

CPU 在完成当前指令后响应中断，因此返回后通常执行原程序下一条尚未执行的指令。

对于缺页故障：

触发缺页的指令尚未成功执行完成，因此处理完成后通常需要重新执行引发缺页的指令。

对于系统调用陷入：

成功处理并返回后，通常继续执行系统调用入口指令之后的用户指令。

对比：

| 事件      | 正常处理后典型返回位置 |
| ------- | ----------- |
| 外部中断    | 下一条待执行指令    |
| 可恢复缺页故障 | 重新执行故障指令    |
| 系统调用陷入  | 系统调用入口之后    |
| 严重异常    | 可能无法正常返回    |

不要把所有中断和异常都套用同一种返回位置。

### 5.11 中断向量表为什么适合用数组？

【2023 年真题】

在操作系统内核中，中断向量表适合采用的数据结构是（ ）。

A. 数组\
B. 队列\
C. 单向链表\
D. 双向链表

答案：A

原因：

中断类型号可以用于索引中断向量表，从而快速找到处理入口。

数组支持高效随机访问。

考试标准模型中的查找时间：

$$
T(n)=O(1)
$$

所以数组更适合中断向量表。

### 5.12 非常重要：中断发生时 CPU 一定处于内核态吗？

不一定。

必须区分：

- 中断发生的时刻。
- CPU 响应中断并切换权限的过程。
- 中断处理程序开始执行的时刻。

例如：

```text
CPU 正在用户态执行
        │
        ▼
设备发出中断请求
        │
        ▼
CPU 响应中断
保存状态并进入内核入口
        │
        ▼
中断处理程序在内核态执行
```

外部中断可以在 CPU 处于用户态时发生。

因此：

> 中断或异常发生时，CPU 不一定已经处于内核态；但典型操作系统的中断或异常处理程序在内核态执行。

### 真题

【2024 年真题】

下面关于中断、异常和系统调用的叙述中，错误的是（ ）。

A. 中断或异常发生时，CPU 处于内核态\
B. 每个系统调用都有对应的内核服务例程\
C. 中断处理程序开始执行时，CPU 处于内核态\
D. 系统添加新类型设备时，需注册相应的中断服务例程

答案：A

A 把“事件发生”与“处理程序执行”混为一谈。

这也是本章常见的文字陷阱。

## 六、系统调用：应用程序如何请求操作系统服务？

这是本章最重要的考点之一。

系统调用不是单纯的函数调用，而是连接用户程序与操作系统内核的受控入口。

### 6.1 为什么需要系统调用？

普通应用程序不能随意执行特权操作。

但程序又必须能够：

- 创建新进程；
- 读取文件；
- 向磁盘写入数据；
- 请求网络通信；
- 使用操作系统管理的设备；
- 申请某些系统资源。

所以操作系统提供系统调用（System Call）。

例如：

```c
int fd = open("test.txt", O_RDONLY);
read(fd, buffer, 100);
close(fd);
```

这些 C 库接口通常会请求内核提供相应服务。

注意：系统调用由内核实现，而用户程序通常通过系统调用包装函数发起请求。

### 6.2 系统调用的完整过程

假设用户程序需要读取一个文件。

```text
用户态
┌──────────────────────────────┐
│ ① 准备系统调用号与参数       │
│              ↓               │
│ ② 执行系统调用入口指令       │
└──────────────┬───────────────┘
               │
               ▼
       CPU 硬件受控陷入
       保存必要返回信息
       切换到内核态
               │
               ▼
内核态
┌──────────────────────────────┐
│ ③ 保存必要的软件现场         │
│              ↓               │
│ ④ 检查系统调用号与参数       │
│              ↓               │
│ ⑤ 执行系统调用服务程序       │
│              ↓               │
│ ⑥ 设置返回值，恢复软件现场   │
└──────────────┬───────────────┘
               │
               ▼
       特权返回机制
               │
               ▼
用户态
┌──────────────────────────────┐
│ ⑦ 用户程序继续执行           │
└──────────────────────────────┘
```

必须记住执行顺序：

$$
\boxed{ \text{准备参数} \rightarrow \text{执行陷入} \rightarrow \text{内核服务} \rightarrow \text{返回用户态} }
$$

### 6.3 真题：系统调用顺序

【2017 年真题】

执行系统调用的过程包括如下主要操作：

Ⅰ. 返回用户态\
Ⅱ. 执行陷入（trap）指令\
Ⅲ. 传递系统调用参数\
Ⅳ. 执行相应的服务程序

正确的执行顺序是（ ）。

A. Ⅱ → Ⅲ → Ⅰ → Ⅳ\
B. Ⅱ → Ⅳ → Ⅲ → Ⅰ\
C. Ⅲ → Ⅱ → Ⅳ → Ⅰ\
D. Ⅲ → Ⅳ → Ⅱ → Ⅰ

答案：C

逐步推导：

第一步，用户程序必须先准备参数，否则内核不知道要执行什么操作。

第二步，执行 Trap 指令进入内核。

第三步，内核执行对应的系统调用服务程序。

第四步，恢复状态并返回用户态。

因此：

$$
\boxed{\mathrm{III\rightarrow II\rightarrow IV\rightarrow I}}
$$

### 6.4 真题：硬件和软件如何分工？

【2022 年真题】

执行系统调用的过程涉及下列操作，其中由操作系统完成的是（ ）。

Ⅰ. 保存断点和程序状态字\
Ⅱ. 保存通用寄存器的内容\
Ⅲ. 执行系统调用服务例程\
Ⅳ. 将 CPU 模式改为内核态

A. 仅Ⅰ、Ⅲ\
B. 仅Ⅱ、Ⅲ\
C. 仅Ⅱ、Ⅳ\
D. 仅Ⅱ、Ⅲ、Ⅳ

答案：B

解释：

Ⅰ属于硬件陷入机制需要完成的工作。

Ⅱ通常由内核软件保存。

Ⅲ由操作系统执行。

Ⅳ依赖硬件提供的特权级切换机制。

因此选择 B。

### 6.5 系统调用与库函数有什么区别？

| 比较维度       | 普通库函数              | 系统调用            |
| ---------- | ------------------ | --------------- |
| 提供者        | 程序库                | 操作系统内核          |
| 是否必然进入内核   | 否                  | 是               |
| 是否必然涉及特权转换 | 否                  | 从用户态调用时是        |
| 是否使用陷入机制   | 不一定                | 是               |
| 典型例子       | `sin()`、`strlen()` | `read`、`fork` 等 |
| 开销         | 通常较低               | 通常较高            |

例如：

```c
int x = abs(-10);
```

这类计算可以在用户态完成。

但：

```text
read(fd, buf, 100);
```

通常需要内核提供文件读取服务。

另外，像 `printf()` 这样的库函数可能先在用户态完成格式化和缓冲，在适当时机调用 `write` 等系统调用。

因此不能认为：

> 只要调用库函数就会进入内核态。

### 6.6 哪些操作属于系统调用？

这是一个经常出现的概念判断。

【2021 年真题】

下列选项中，通过系统调用完成的操作是（ ）。

A. 页置换\
B. 进程调度\
C. 创建新进程\
D. 生成随机整数

答案：C

原因：

创建新进程需要向操作系统申请资源，属于用户程序请求内核服务的典型场景。

页置换是内核在存储管理过程中执行的内部操作。

进程调度由操作系统自行完成。

生成伪随机整数通常可以由用户态算法直接实现。

这里有一个非常重要的判断标准：

需要内核完成的操作，不一定就是系统调用。

系统调用强调的是：

> 用户程序主动通过接口请求内核服务。

而操作系统内部运行的调度程序、缺页处理程序，不是用户程序直接发起系统调用的同义词。

### 6.7 系统调用接口是否由所有操作系统统一提供？

不是。

不同操作系统可能有不同的：

- 系统调用号；
- 系统调用种类；
- 参数格式；
- 调用约定；
- ABI。

即使高级语言源代码相似，也不意味着底层的系统调用接口完全一致。

【2019 年真题】

下列关于系统调用的叙述中，正确的是（ ）。

Ⅰ. 执行系统调用服务程序时，CPU 处于内核态。\
Ⅱ. 操作系统通过系统调用避免用户程序直接访问外设。\
Ⅲ. 不同操作系统为应用程序提供统一的系统调用接口。\
Ⅳ. 系统调用是操作系统内核为应用程序提供服务的接口。

A. 仅Ⅰ、Ⅳ\
B. 仅Ⅱ、Ⅲ\
C. 仅Ⅰ、Ⅱ、Ⅳ\
D. Ⅰ、Ⅲ、Ⅳ

答案：C

Ⅰ正确，Ⅱ正确，Ⅳ正确。

Ⅲ错误。不同操作系统的系统调用接口并不统一。

## 七、用户态/内核态切换与进程上下文切换

这是理解中断、系统调用和进程调度之间关系的关键。

### 7.1 两者到底有什么区别？

用户态与内核态切换：

改变 CPU 的权限级别。

进程上下文切换：

改变当前占用 CPU 执行的进程。

例如：

```text
进程 A 用户态
      │
      │ 执行系统调用
      ▼
进程 A 内核态
      │
      │ 完成系统调用
      ▼
进程 A 用户态
```

这里发生了特权级转换。

但是，从开始到结束，仍然是进程 A 在执行。

因此不一定发生进程切换。

**一步判定进程是否切换**

问自己：服务执行期间是否**必须等待**，或内核是否**选择调度另一个就绪进程**？如果没有，即便发生内核态切换也可能恢复原进程；如果系统调用阻塞，内核才需要调度其他可运行进程或等待事件。

### 7.2 系统调用什么时候会导致进程切换？

假设进程 A 调用 `read()`。

如果目标数据已经在内核缓存中：

```text
进程 A 用户态
      ↓
进入内核
      ↓
复制缓存数据
      ↓
返回进程 A
```

可能完全不需要切换进程。

如果数据需要等待磁盘读取：

```text
进程 A 用户态
      ↓
read 系统调用
      ↓
进程 A 进入内核
      ↓
发现需要等待磁盘 I/O
      ↓
进程 A 阻塞
      ↓
调度器选择进程 B
      ↓
进程 B 开始运行
```

此时发生了进程切换。

之后磁盘 I/O 完成：

```text
磁盘发出中断
      ↓
中断服务程序处理
      ↓
唤醒进程 A
      ↓
A 进入就绪态
      ↓
调度器在适当时机重新运行 A
      ↓
read 返回
```

这一过程还说明：

被唤醒不等于立即运行。

唤醒操作通常只是让阻塞进程转为就绪状态。

真正运行还需要由调度器分配 CPU。

### 7.3 真题：什么不可能在用户态发生？

【2012 年真题】

下列选项中，不可能在用户态发生的事件是（ ）。

A. 系统调用\
B. 外部中断\
C. 进程切换\
D. 缺页

答案：C

解释：

系统调用可以由用户程序发起。

外部中断可以在用户态执行过程中到来。

缺页可以由用户程序的访存指令触发。

但进程上下文切换必须由内核中的调度和切换机制完成。

因此选择 C。

### 7.4 进程切换一定伴随用户态到内核态的转换吗？

不能简单这么说。

如果原进程本来就在内核态运行，随后内核调度另一个进程，那么进程切换并不一定包含“原进程从用户态进入内核态”的过程。

但在常见的用户程序抢占场景中，CPU 通常会先因为时钟中断等原因进入内核，再执行调度与切换。

因此做题时需要分别判断：

1. 原来处于什么特权级？
2. 是否发生中断、异常或系统调用？
3. 是否执行了调度程序？
4. 是否换成另一个进程？

### 7.5 真题：一条普通指令能否导致内核态切换？

【2015 年真题】

假定下列指令已装入指令寄存器，则执行时不可能导致 CPU 从用户态变为内核态的是（ ）。

A. `DIV R0, R1`\
B. `INT n`\
C. `NOT R0`\
D. `MOV R0, addr`

答案：C

逐项分析：

A：除法可能出现除零异常。

B：`INT n` 可以主动触发软件中断或陷入。

C：对寄存器取反，属于普通运算，不会因该运算自身触发缺页、除零等异常。

D：访存可能产生缺页或访问保护异常。

因此选择 C。

注意题目中的“不可能”，是按照指令自身可能引发的同步异常或陷入来判断的。

如果考虑任何时刻都可能到达的外部中断，那么连普通 `NOT` 执行附近也可能发生模式切换。这不是该题的考查口径。

## 八、程序链接、装入与内存映像

这一部分在优化版讲义中有专门章节，是完整理解程序运行环境的重要内容。

### 8.1 一个程序如何变成正在执行的进程？

总体流程：

```text
源程序
  ↓
编译 / 汇编
  ↓
目标文件
  ↓
链接
  ↓
可执行文件
  ↓
装入 / 建立运行环境
  ↓
进程内存映像
  ↓
CPU 执行程序
```

这里要特别区分三个阶段：

链接： 解决多个目标模块之间的符号引用和组合问题。

装入： 将程序映射或加载到运行所需的地址空间。

执行： CPU 开始取指，操作系统维护进程的执行环境。

### 8.2 静态链接与动态链接

假设有两个程序都需要一个数学库。

采用静态链接时：

```text
程序 A + 数学库 → 可执行文件 A
程序 B + 数学库 → 可执行文件 B
```

两个可执行文件通常都包含各自需要的库代码。

特点：

- 可执行文件可能较大；
- 对对应共享库的运行时依赖较少；
- 更新库时，常需要重新链接。

采用动态链接时：

```text
程序 A ─┐
        ├── 共享数学库
程序 B ─┘
```

程序在装入或运行时解析共享库符号，并可共享某些只读库代码页。

特点：

- 可执行文件通常更小；
- 更容易共享库代码；
- 运行时需要对应的动态库和兼容接口。

注意：

动态链接和动态装入是两个不同维度。

动态链接讨论库和符号如何解析。

动态装入讨论程序模块何时被装入运行环境。

### 8.3 地址重定位是什么？

假设某程序使用逻辑地址 200。

程序真正被装入物理内存时，起始地址是 10000。

如果采用简单的基址重定位模型：

$$
\text{物理地址}=\text{基址}+\text{逻辑地址}
$$

那么：

$$
PA=10000+200=10200
$$

因此该逻辑地址对应的物理地址为：

$$
\boxed{10200}
$$

这便是地址重定位思想的一个简单例子。

### 8.4 三种典型装入方式

| 方式    | 地址绑定时机 | 特点             |
| ----- | ------ | -------------- |
| 绝对装入  | 编译或链接时 | 地址事先确定         |
| 静态重定位 | 装入时    | 装入时修改地址，之后通常固定 |
| 动态重定位 | 运行时    | 依赖运行时地址转换机制    |

#### 典型题

某程序被装入基址为 5000 的连续内存区域，逻辑地址为 320。若采用简单基址重定位机制，访问的物理地址是多少？

解：

$$
PA=5000+320
$$

因此：

$$
\boxed{PA=5320}
$$

这道题计算非常简单，真正重要的是理解地址转换发生在什么阶段。

如果在装入时完成地址修正，属于静态重定位。

如果执行访存时才进行转换，属于动态重定位。

### 8.5 程序的典型内存映像

进程运行时通常包含：

```text
高虚拟地址
┌─────────────────┐
│      Stack      │
│       ↓         │
│                 │
│       ↑         │
│      Heap       │
├─────────────────┤
│ mmap / 共享库等 │
├─────────────────┤
│      BSS        │
├─────────────────┤
│      Data       │
├─────────────────┤
│      Text       │
└─────────────────┘
低虚拟地址
```

这是教学中的示意布局，不代表所有操作系统上的实际排列完全相同。

各区域的典型作用：

- Text：机器指令。
- Data：已初始化的全局或静态变量。
- BSS：未显式初始化或零初始化的全局或静态变量。
- Heap：动态分配对象。
- Stack：函数调用栈。
- mmap/共享库：文件映射、共享库映射等。

### 8.6 模拟题：变量属于哪个区域？

观察下面的程序：

```c lineNumbers
#include <stdlib.h>

int a = 10;
int b;

int main() {
    static int c = 20;
    int d = 30;

    int *p = malloc(sizeof(int));
    *p = 40;

    free(p);
    return 0;
}
```

判断：

| 对象             | 典型存储位置 |
| -------------- | ------ |
| `a`            | Data   |
| `b`            | BSS    |
| `c`            | Data   |
| `d`            | Stack  |
| `p` 指针变量本身     | Stack  |
| `malloc` 分配的对象 | Heap   |
| `main` 的机器代码   | Text   |

为什么 `p` 不属于堆？

因为 `p` 是一个定义在函数中的普通局部指针变量。

它的指针变量本身通常位于栈中。

而它指向的 `malloc` 分配对象位于堆中。

这两个位置不能混淆。

## 九、操作系统的结构：宏内核、微内核和外核

### 9.1 先理解内核结构究竟要解决什么问题

操作系统内核承担很多任务：

- 进程管理；
- 内存管理；
- 设备驱动；
- 文件系统；
- 网络协议栈；
- 中断处理。

这些功能之间存在复杂关系。

关键设计问题是：

> 哪些功能应该放在内核态？哪些功能可以放在用户态？

不同的回答，就产生了不同的内核结构。

### 9.2 分层结构

分层设计强调上层通过下层接口获取服务。

优势是逻辑清晰、易于调试和维护。

局限是层次划分不一定容易，严格的层间调用可能增加开销。

### 9.3 模块化结构

模块化强调把系统划分为相对独立的功能模块。

例如：

```text
操作系统
├── 进程管理
├── 内存管理
├── 文件管理
├── 设备管理
└── 网络管理
```

各模块有明确接口。

模块化不代表模块必须在用户态运行。

例如，Linux 支持可装卸内核模块，但依旧属于宏内核体系。

### 9.4 宏内核

宏内核把大量操作系统服务放在内核空间中。

```text
用户态
┌─────────────────────────────┐
│          用户程序            │
└─────────────────────────────┘
              │
         系统调用
              ▼
内核态
┌─────────────────────────────┐
│  调度器 / 内存 / 文件系统     │
│  设备驱动 / 网络协议栈       │
│  其他内核服务                │
└─────────────────────────────┘
              │
             硬件
```

优点是：

内核组件之间可以直接调用，通常具有较好的执行效率。

缺点是：

运行在内核中的服务更多，某个组件发生严重错误时，可能导致整个系统崩溃。

### 9.5 微内核

微内核把更多服务放在用户态。

```text
用户态
┌──────────┐ ┌────────────┐
│ 用户程序 │ │ 文件服务器 │
└──────────┘ └────────────┘
         │       │
         └───┬───┘
             │ IPC
             ▼
内核态
┌─────────────────────────────┐
│ 基本调度 / 地址空间机制      │
│ IPC / 中断等基础机制        │
└─────────────────────────────┘
             │
            硬件
```

微内核强调：

尽量把非必要的内核服务移出内核，保留最基础的机制。

这样做有三个明显好处：

- 减少内核中的代码规模；
- 增强服务隔离；
- 提高可维护性与扩展性。

但代价是：

用户程序和文件服务器等服务之间，可能需要通过更多 IPC 完成通信。

### 9.6 微内核为什么可能性能较低？

假设一个用户程序读取文件。

在典型宏内核设计中：

```text
用户程序
   ↓ 系统调用
内核文件系统
   ↓
内核设备驱动
   ↓
返回
```

在典型微内核设计中：

```text
用户程序
   ↓ IPC
文件服务器
   ↓ IPC
设备相关服务
   ↓
返回
```

后一种设计可能包含更多：

- 消息传递；
- 权限级切换；
- 调度；
- 数据复制。

因此可能增加额外开销。

但不能简单断言所有微内核在任何工作负载下都一定比宏内核慢。

### 9.7 外核

外核（Exokernel）强调更少地在内核中规定高层资源抽象。

内核主要负责安全地分配和保护底层硬件资源。

用户态的库操作系统则实现更高层的文件、内存等管理策略。

简化比较：

| 结构  | 核心思想                      |
| --- | ------------------------- |
| 宏内核 | 大量服务放在内核内部                |
| 微内核 | 保留基础机制，其他服务尽量移到用户态        |
| 外核  | 内核重点负责资源保护与安全复用，高层抽象交给用户态 |

### 9.8 真题：宏内核和微内核对比

【2023 年真题】

与宏内核操作系统相比，下列特征中，微内核操作系统具有的是（ ）。

Ⅰ. 较好的性能\
Ⅱ. 较高的可靠性\
Ⅲ. 较高的安全性\
Ⅳ. 较强的可扩展性

A. Ⅱ、Ⅳ\
B. Ⅰ、Ⅱ、Ⅲ\
C. Ⅰ、Ⅲ、Ⅳ\
D. Ⅱ、Ⅲ、Ⅳ

答案：D

分析：

Ⅰ：不属于微内核的一般优势。更多 IPC 可能带来性能开销。

Ⅱ：正确。服务隔离有利于提高可靠性。

Ⅲ：正确。减少内核中的代码与权限范围有利于安全性。

Ⅳ：正确。独立的服务更容易维护和扩展。

因此：

$$
\boxed{\mathrm{II、III、IV}}
$$

### 9.9 机制与策略的区别

这是进一步理解微内核设计的重要思想。

**机制（Mechanism）**&#x2060;回答：

> 系统能够提供什么基本能力？

**策略（Policy）**&#x2060;回答：

> 在多种可能的做法中，应该选择哪一种？

例如 CPU 调度：

机制是实现线程切换。

策略是选择优先级调度、时间片轮转等算法。

又如内存管理：

机制是实现地址转换和内存保护。

策略是决定给哪个进程分配多少内存。

理想的设计通常希望适当分离机制与策略，以便提高灵活性。

## 十、操作系统的引导过程

### 10.1 为什么必须存在引导程序？

操作系统的主体通常存放在磁盘或其他非易失性存储设备中。

但是，计算机刚开机时，内核尚未运行。

这时需要先由固件和引导程序把内核装入内存，并交出控制权。

这就是操作系统引导（Boot）。

### 10.2 传统 BIOS + MBR 引导流程

```text
计算机上电
    ↓
CPU 执行固件代码
    ↓
BIOS 初始化、自检
    ↓
选择启动设备
    ↓
读取 MBR
    ↓
执行引导代码
    ↓
加载后续引导程序
    ↓
加载 OS 内核
    ↓
内核初始化
    ↓
启动系统服务
```

这里需要认识几个术语。

BIOS： 固件系统，负责上电后的基本初始化及启动工作。

MBR： 主引导记录，传统 BIOS 启动方案的重要组成部分。

Bootloader： 引导加载程序，负责加载内核并转交控制权。

### 10.3 MBR 中包含什么？

传统 MBR 位于磁盘第一个逻辑扇区。

在经典 512 字节 MBR 布局中：

| 区域      | 大小    |
| ------- | ----- |
| 引导代码等区域 | 446 B |
| 分区表     | 64 B  |
| 结束标志    | 2 B   |
| 总计      | 512 B |

其中结束标志通常为：

`0x55AA`

但要注意：

这属于传统 MBR 模型。

现代 UEFI + GPT 启动方式不能简单照搬这套步骤。

**引导模式、磁盘分区表和文件系统不要一概而论**

常见 UEFI/GPT 安装使用 ESP（EFI 系统分区）存放启动加载器；BIOS/MBR 则依赖传统引导扇区代码。但固件模式、分区表类型与具体兼容策略是不同维度，答题时以给定硬件、固件和系统支持情况为准。

### 10.4 UEFI 引导

现代系统常使用 UEFI。

简化流程：

```text
计算机上电
    ↓
UEFI 固件
    ↓
硬件初始化
    ↓
选择启动项
    ↓
从 EFI 系统分区加载 EFI 程序
    ↓
启动管理器 / 内核加载器
    ↓
操作系统内核
```

要注意：

GPT 是分区表格式，不是引导程序。

UEFI 与 GPT 经常一起出现，但不是同一个概念。

### 10.5 真题：操作系统最终加载到哪里？

【2013 年真题】

计算机开机后，操作系统最终被加载到（ ）。

A. BIOS\
B. ROM\
C. EPROM\
D. RAM

答案：D

解释：

操作系统内核需要装入能够供 CPU 正常执行的主存区域。

BIOS 是固件系统。

ROM、EPROM 是非易失性存储器类型。

在经典题目模型中，操作系统最终被加载到 RAM 中。

### 10.6 模拟题：开机首先执行什么？

【竟成·模拟五-23】

计算机开机后，需要进行 BIOS 引导，该过程的第一步是（ ）。

A. 硬件自检\
B. 将主引导记录加载到内存\
C. 将分区引导记录加载到内存\
D. 将 OS 内核加载到内存

答案：A

在传统 BIOS 启动模型下，BIOS 首先进行基本硬件初始化和通电自检。

然后才选择启动设备并加载后续引导程序。

## 十一、虚拟机：一台计算机如何运行多个操作系统？

### 11.1 虚拟机的本质

虚拟机（Virtual Machine）是利用软件和硬件支持，在物理计算机上创建出来的逻辑计算环境。

例如：

```text
物理服务器
      │
      ▼
   Hypervisor
    /      \
   /        \
虚拟机 A    虚拟机 B
Linux       Windows
```

每个虚拟机都可以具有自己的：

- 虚拟 CPU；
- 虚拟内存；
- 虚拟磁盘；
- 虚拟网络设备；
- Guest OS。

### 11.2 Hypervisor 是什么？

Hypervisor 是虚拟机监控程序，也称 VMM。

它负责虚拟资源的提供、调度、隔离和管理。

### 11.3 Type 1 与 Type 2

Type 1：裸机型虚拟化

Hypervisor 直接运行在硬件之上。

```text
虚拟机 A      虚拟机 B
    │            │
    └─────┬──────┘
          ▼
     Hypervisor
          │
         硬件
```

Type 2：宿主型虚拟化

Hypervisor 运行在宿主操作系统之上。

```text
       虚拟机
         │
    虚拟机软件
         │
      Host OS
         │
        硬件
```

最核心区别是：

> Hypervisor 是否直接作为底层虚拟化平台运行在硬件之上。

### 11.4 Guest OS 能否自由执行特权指令？

不能简单认为它拥有对真实物理机器的最高控制权。

Guest OS 虽然在虚拟机内部执行内核功能，但其对真实硬件的访问仍受到 Hypervisor 和硬件虚拟化机制的约束。

例如 Guest OS 修改虚拟 CPU 的关键状态，不能因此任意修改宿主机真实 CPU 的全部受保护状态。

这一点是虚拟机安全隔离的基础。

### 11.5 虚拟机与容器有什么区别？

| 对比             | 虚拟机     | 容器     |
| -------------- | ------- | ------ |
| 是否通常拥有独立 OS 内核 | 是       | 否      |
| 虚拟化层次          | 硬件/机器层次 | 操作系统层次 |
| 资源开销           | 通常较大    | 通常较小   |
| 启动速度           | 通常较慢    | 通常较快   |

容器通常共享宿主机内核。

而完整系统虚拟机可以运行独立的 Guest OS。

### 题目 4：中断、异常和系统调用的组合判断

某单核计算机正在用户态执行进程 A。

A 依次经历：

1. 执行 `sin()`。
2. 执行 `read()`。
3. 执行普通访存指令，但发生缺页。
4. 执行加法指令期间，外部设备发出中断请求。

判断哪些步骤一定需要内核参与。

<Accordions>

<Accordion title="展开：参考答案与详细解析" id="os01-solution-04">

解答：

步骤 1：

`sin()` 通常是用户态库函数，不必进入内核。

步骤 2：

`read()` 需要内核提供系统调用服务。

步骤 3：

缺页需要进入内核缺页处理程序。

步骤 4：

CPU 响应外部中断后需要进入相应中断处理程序。

因此：

| 步骤        | 是否需要内核参与 |
| --------- | -------- |
| `sin()`   | 通常不需要    |
| `read()`  | 需要       |
| 缺页处理      | 需要       |
| 响应并处理外部中断 | 需要       |

特别注意：

步骤 4 中，中断请求到达与 CPU 实际响应中断不是完全相同的时刻。

如果中断暂时被屏蔽，或 CPU 尚未到达可响应的位置，就可能延迟处理。

</Accordion>

</Accordions>

### 题目 5：多道程序的资源竞争

某多道程序系统中，同时存在 10 个进程。

某同学认为：

> 只要继续增加进程数量，CPU 利用率一定提高，因此将进程数量增加到 1000 个最好。

该说法是否正确？

<Accordions>

<Accordion title="展开：参考答案与详细解析" id="os01-solution-05">

答案：错误。

需要综合考虑：

- CPU 调度开销；
- 内存容量；
- 工作集大小；
- 缺页频率；
- I/O 竞争；
- 进程切换开销。

当进程数量过多时，可能由于频繁换页造成抖动。

因此，多道程序度存在资源约束，不是越高越好。

</Accordion>

</Accordions>

### 题目 6：系统调用是否必然引起进程切换？

某进程 A 使用系统调用从已经缓存的数据中读取 100 字节。

假设内核立即完成请求，且没有其他调度原因。

问：

1. 是否发生用户态到内核态切换？
2. 是否一定发生进程切换？
3. 是否需要执行系统调用服务程序？

<Accordions>

<Accordion title="展开：参考答案与详细解析" id="os01-solution-06">

解析：

第一问：是。

从用户态发起系统调用，需要受控进入内核。

第二问：不一定。

由于请求可以立即完成，可能仍由 A 继续执行。

第三问：是。

内核需要执行相应服务来完成读取。

本题核心结论：

$$
\boxed{\text{系统调用}\not\Rightarrow\text{进程切换}}
$$

但从用户态执行系统调用，需要通过受控机制进入内核态。

</Accordion>

</Accordions>

### 题目 7：缺页后返回哪里？

某程序执行第 100 条机器指令时发生可恢复的缺页异常。

操作系统成功调入所需页面后，一般应该如何恢复执行？

A. 直接执行第 101 条指令\
B. 重新执行第 100 条指令\
C. 重新执行第 99 条指令\
D. 从程序入口重新执行

<Accordions>

<Accordion title="展开：参考答案与详细解析" id="os01-solution-07">

答案：B

缺页导致第 100 条指令尚未成功完成。

因此需要重新执行该指令。

注意区别于普通外部中断返回后继续下一条尚未执行的指令。

</Accordion>

</Accordions>

最后，用六句话概括本章最重要的内容：

1. 操作系统的本质是管理、抽象和保护资源。 并发、共享、虚拟、异步是它的四个基本特征。
