### 1.2 本章必须掌握的计算公式

先把最重要的公式放在一起，后面逐个推导。

单缓冲（常见流水模型）：

$$
T_{\text{single}} =T+nM+(n-1)\max(T,C)+C
$$

双缓冲（常见流水模型）：

$$
T_{\text{double}} =T+(n-1)\max(T,M+C)+M+C
$$

其中：

- $T$：设备输入一块数据的时间。
- $M$：缓冲区复制到用户工作区的时间。
- $C$：CPU 分析一块数据的时间。
- $n$：数据块数量。

磁盘访问时间：

$$
T_{\text{access}} =T_{\text{seek}}+T_{\text{rotation}}+T_{\text{transfer}}
$$

磁头总移动距离：

$$
D=\sum_{i=1}^{n}|x_i-x_{i-1}|
$$

磁盘容量：

$$
C_{\text{disk}} =N_{\text{柱面}}\times N_{\text{每柱面磁道}} \times N_{\text{每磁道扇区}}\times B_{\text{扇区}}
$$

位示图最少字节数：

$$
B_{\text{bitmap}}= \left\lceil\frac{N_{\text{blocks}}}{8}\right\rceil
$$

这些是本章最值得熟练掌握的计算模型，但尤其要记住：缓冲公式依赖时序假设，磁盘调度公式依赖实际运动路径。

## 二、I/O 设备与 I/O 控制方式

### 2.1 操作系统为什么需要 I/O 管理？

CPU 和外设存在很大的速度差异。

例如：

- CPU 可以在极短时间内执行大量指令。
- 键盘需要等待人按键。
- 机械硬盘需要磁头寻道和盘片旋转。
- 打印机需要花较长时间完成物理打印。

如果 CPU 每次都必须等待外设完成工作，处理器资源就会被大量浪费。

操作系统的 I/O 管理主要解决四件事：

1. 设备独立性：让应用程序不必了解具体硬件。
2. 高效传输：减少 CPU 对慢速设备的等待。
3. 资源管理：合理分配、回收和共享设备。
4. 性能优化：通过缓冲、缓存和调度提高效率。

可以把一次 I/O 的完整过程理解为：

```text
应用程序提出 I/O 请求
          ↓
系统调用，进入内核
          ↓
设备独立性软件
          ↓
设备驱动程序
          ↓
设备控制器
          ↓
物理 I/O 设备
          ↓
I/O 完成或出现错误
          ↓
中断处理 / 完成通知
          ↓
内核更新状态，唤醒等待进程
          ↓
应用程序继续执行
```

需要注意：这是常见的请求与完成流程，不代表所有 I/O 都一定以阻塞和中断结束。

### 2.2 I/O 设备的分类

#### 按信息交换单位分类

| 类型   | 典型设备        | 特征            |
| ---- | ----------- | ------------- |
| 块设备  | HDD、SSD、U 盘 | 按块读写，通常支持随机访问 |
| 字符设备 | 键盘、鼠标、串口    | 按字符流或事件流处理    |
| 网络设备 | 网卡          | 按帧或数据包收发      |

容易混淆的是：

块设备支持随机访问，不代表每次访问都很快。

机械硬盘能随机读取某个逻辑块，但跨磁道访问仍需要寻道。

SSD 同样是块设备，只是没有机械寻道和旋转延迟。

#### 按使用方式分类

| 设备类型 | 特征                | 示例            |
| ---- | ----------------- | ------------- |
| 独占设备 | 同一时间通常只能由一个作业直接占用 | 传统打印机         |
| 共享设备 | 可以交替服务多个进程        | 磁盘            |
| 虚拟设备 | 通过软件把独占设备表现为可共享   | SPOOLing 打印设备 |

这里的“共享”不意味着同一设备所有物理动作都能同时执行。

### 2.3 设备控制器与设备驱动程序

这两个概念必须区分。

设备控制器是硬件，设备驱动程序是软件。

设备控制器通常包含：

| 寄存器   | 作用               |
| ----- | ---------------- |
| 数据寄存器 | 存放输入或输出的数据       |
| 状态寄存器 | 表示设备是否忙碌、就绪、出错   |
| 控制寄存器 | 接受启动、停止、复位、读写等命令 |

假设 CPU 要从磁盘读取数据。

设备驱动程序向控制器发出读命令，控制器负责协调磁盘硬件完成读操作。

因此：

- 驱动程序负责下达具体操作命令。
- 控制器负责执行硬件控制工作。
- 中断处理程序负责处理设备完成事件。

#### I/O 端口的两种编址方式

独立编址（I/O 映射编址）：I/O 端口拥有独立地址空间，CPU 通常通过专门的 I/O 指令访问。

统一编址（存储器映射 I/O）：设备寄存器占用存储地址空间的一部分，可以通过相应的访存指令访问。

不要把“内存映射 I/O”误解为设备内部数据全部存放在主存中。它指的是设备寄存器的地址映射方式。

### 2.4 I/O 控制方式——本章重点

408 主要考查程序查询、中断驱动和 DMA。

<Tabs items={['程序查询', '中断驱动', 'DMA']} defaultIndex={0}>

<Tab value="程序查询">

也叫程序直接控制方式或轮询方式。

工作流程：

```text
CPU 发出 I/O 命令
       ↓
查询设备状态
       ↓
设备完成了吗？
  ├─ 否 → 继续查询
  └─ 是 → CPU 参与传输数据
```

最关键的特点：

CPU 在等待设备期间不断查询状态，形成忙等。

例如：

```c
while (!device_ready()) {
    // 不断查询设备是否准备好
}
read_device_data();
```

这样做的优点是简单，硬件要求相对较低。

缺点是等待期间占用 CPU 执行时间，尤其不适合长时间等待的慢速设备。

不过，轮询并不一定在所有实际场景下都低效。对于极短的设备操作或高频低延迟场景，适当轮询也可能避免中断开销。

考试按经典模型比较即可。

</Tab>

<Tab value="中断驱动">

中断方式的改进在于：

CPU 不必持续等待设备，可以先执行其他任务。

流程：

```text
CPU 启动设备
       ↓
CPU 执行其他工作
       ↓
设备需要服务或完成操作
       ↓
设备发出中断请求
       ↓
CPU 进入中断服务程序
       ↓
处理数据、设备状态或完成通知
       ↓
恢复执行
```

假设键盘输入一个字符：

1. 用户按下按键。
2. 键盘控制器产生输入事件。
3. 控制器向 CPU 请求中断。
4. CPU 响应中断。
5. 键盘中断处理程序读取并处理输入。
6. 输入信息被送到内核输入缓冲区。
7. 等待输入的进程可以被唤醒。

注意：中断方式只减少忙等，不意味着 CPU 不参与数据传送。

在经典中断驱动模型中，CPU 仍需要通过指令完成相应的数据搬运。

</Tab>

<Tab value="DMA">

DMA：Direct Memory Access，直接存储器访问。

核心思想：

设备与主存之间的一批数据，可以由 DMA 硬件直接传输，不要求 CPU 逐字搬运。

```text
CPU 配置 DMA 控制器
          ↓
设置地址、方向、数据长度
          ↓
启动设备传输
          ↓
DMA 控制器负责数据传输
          ↓
传输完成
          ↓
DMA 发出完成中断
          ↓
CPU 执行结束处理
```

典型的数据路径是：

```text
普通程序中断方式：

设备 → 控制器 → CPU 寄存器 → 主存

DMA 方式：

设备 → DMA/设备控制器 → 主存
                   ↑
              CPU 负责配置
```

DMA 减少的是 CPU 对数据搬运的直接参与。

CPU 仍需要初始化 DMA 控制器、管理传输资源、处理完成事件等。

</Tab>

</Tabs>

#### 三种方式的重要对比

| 比较维度       | 程序查询     | 中断驱动   | DMA              |
| ---------- | -------- | ------ | ---------------- |
| CPU 是否持续忙等 | 是        | 否      | 否                |
| 数据主要由谁搬运   | CPU      | CPU    | DMA 硬件           |
| 完成通知       | CPU 主动查询 | 中断     | 通常为完成中断          |
| 典型传输单位     | 字节或字     | 字节或字   | 数据块              |
| 主要优势       | 简单       | 减少忙等   | 降低大量数据传送的 CPU 开销 |
| 主要问题       | CPU 时间浪费 | 频繁中断开销 | 需要 DMA 硬件支持      |

这里的传输单位是 408 经典模型的典型情况，不代表所有真实设备都严格遵循该粒度。

#### 真题 1：2017 年 DMA 执行顺序

题目给出：

① DMA 控制器发出中断请求。

② 初始化 DMA 控制器并启动磁盘。

③ 从磁盘传输一块数据到内存缓冲区。

④ 执行 DMA 结束中断服务程序。

求正确执行顺序。

解题：

首先，CPU 必须配置 DMA 才能传输，所以②最先。

接着设备与内存之间进行数据传输，即③。

传输完成后发出中断，即①。

最后 CPU 执行中断处理，即④。

因此：

$$
\boxed{②\rightarrow③\rightarrow①\rightarrow④}
$$

这是一个可以直接迁移到类似流程题的结论。

#### 模拟题 2：中断处理时间预算

模拟题：

条件：

- CPU 主频为 500 MHz；
- CPI 为 3；
- 鼠标回报率为 200 Hz；
- 鼠标中断处理占用 CPU 的时间必须低于 0.1%。

问每次中断处理最多允许执行多少条指令。

第一步：计算每秒 CPU 周期数

$$
f=500\times10^6
$$

第二步：计算每秒允许的周期预算

$$
N_{\text{budget}} =500\times10^6\times0.001 =500000
$$

第三步：计算一次中断可以消耗多少周期

$$
\frac{500000}{200}=2500
$$

第四步：根据 CPI 转换为指令数

$$
N=\frac{2500}{3}\approx833.33
$$

由于指令条数必须是整数，且要求严格低于规定比例：

$$
\boxed{N_{\max}=833}
$$

答案为 C。

这一类题目的通式是：

$$
\boxed{ N_{\max} \approx \frac{f\alpha}{r\cdot CPI} }
$$

其中：

- $f$：CPU 每秒时钟周期数；
- $\alpha$：允许的 CPU 时间占比；
- $r$：每秒发生的中断次数。

最终取满足题目不等式的最大整数。

## 三、I/O 软件层次——选择题高频考点

这一部分最容易出现两类题目：

- 给出 I/O 处理流程，要求判断正确顺序。
- 给出某项具体工作，要求判断由哪个软件层完成。

### 3.1 四层 I/O 软件结构

从上到下：

```text
┌──────────────────────────┐
│  ① 用户层 I/O 软件       │
│  printf、scanf、库函数   │
├──────────────────────────┤
│  ② 设备独立性软件        │
│  统一接口、设备分配      │
│  缓冲管理、逻辑设备映射  │
├──────────────────────────┤
│  ③ 设备驱动程序          │
│  控制寄存器、硬件命令    │
│  初始化设备、启动 DMA   │
├──────────────────────────┤
│  ④ 中断处理程序          │
│  中断响应、完成处理      │
├──────────────────────────┤
│        物理硬件          │
└──────────────────────────┘
```

这张图表示教材中的逻辑分层，而不是所有 I/O 请求都要依次调用四层函数。

尤其要注意，中断处理程序通常在设备产生中断后被调用，并不是驱动程序每次启动 I/O 时都必须先调用中断处理程序。

### 3.2 第一层：用户层 I/O 软件

用户层 I/O 软件向应用程序提供方便的输入输出接口。

例如：

```text
printf("Hello");
scanf("%d", &x);
fread(buf, 1, 100, fp);
```

这些函数通常属于用户态的标准库。

它们可以完成格式化、缓冲等操作，必要时通过系统调用请求内核服务。

例如：

```text
printf()
   ↓
用户态格式化
   ↓
用户态缓冲
   ↓
write() 系统调用
   ↓
内核处理
```

易错：库函数不等于系统调用。

`printf()` 是库函数，底层可能通过 `write()` 系统调用输出。

调用库函数并不一定立即进入内核态。

### 3.3 第二层：设备独立性软件

设备独立性也叫设备无关性。

核心思想：

用户程序应当独立于具体使用的物理设备。

举例：

某程序向打印设备输出文件。

原来使用打印机 A。

后来更换为兼容的打印机 B。

正常情况下，用户程序不需要重新编写。

因为它只面向逻辑设备接口，具体物理设备的变化由操作系统和驱动程序处理。

设备独立性软件主要承担：

1. 提供统一的设备访问接口。
2. 逻辑设备与物理设备的映射。
3. 设备分配与回收。
4. 缓冲管理。
5. 设备保护与权限检查。
6. 通用差错处理。
7. SPOOLing 等通用设备管理机制。

#### 什么是逻辑设备名？

例如，某程序想使用打印机，并不需要把打印机的控制器地址写死在代码里。

程序可以使用逻辑名称：

```text
逻辑设备名：printer
        ↓
逻辑设备映射表 LUT
        ↓
物理打印机 A
```

如果打印机 A 故障，可以将映射改为打印机 B。

```text
逻辑设备名：printer
        ↓
逻辑设备映射表 LUT
        ↓
物理打印机 B
```

应用程序仍然使用 `printer`。

这就是设备独立性的重要价值。

#### 真题 3：2009 年设备标识

题目：程序员通过系统调用打开 I/O 设备时，通常使用哪一种设备标识？

A. 逻辑设备名

B. 物理设备名

C. 主设备号

D. 从设备号

答案：A。

原因是用户程序应当独立于具体物理设备。

主设备号、次设备号等可以参与操作系统内部设备识别，但不应成为应用程序必须依赖的具体硬件标识。

#### 真题 4：2020 年设备独立性

题目问：具备设备独立性的系统中，哪项说法错误？

其中一个选项是：

> 更换物理设备后，必须修改访问该设备的应用程序。

该说法错误。

因为设备独立性的目的恰恰是：

$$
\boxed{\text{物理设备变化}\not\Rightarrow\text{应用程序必须修改}}
$$

只要接口兼容且系统具有相应驱动支持，更换设备通常不需要修改应用程序。

### 3.4 第三层：设备驱动程序

设备驱动程序直接面向具体硬件。

主要工作：

- 接收上层 I/O 请求。
- 将通用请求翻译为设备命令。
- 初始化设备。
- 检查设备状态。
- 设置控制寄存器。
- 配置 DMA。
- 启动读写操作。
- 处理设备特有的错误。

例如：

```text
上层请求：
读取磁盘上的某个数据块
        ↓
设备驱动程序：
形成具体设备命令
配置控制器和数据缓冲区
        ↓
设备控制器执行
```

最重要的区别：

设备独立性软件负责统一，驱动程序负责具体。

#### 真题 5：2013 年磁盘地址计算

题目给出：

```text
用户程序
   ↓
系统调用处理程序
   ↓
设备驱动程序
   ↓
中断处理程序
```

问：负责计算磁盘数据所在柱面号、磁头号、扇区号的程序是哪个？

答案：设备驱动程序。

原因：

CHS（柱面、磁头、扇区）转换涉及具体设备的地址组织，是设备相关工作。

这里要补充一个重要细节：

在现代磁盘中，操作系统通常使用 LBA 逻辑块地址，真实物理位置的转换可能由控制器固件完成。

但按照该真题的经典设备模型，应选择设备驱动程序。

#### 真题 6：2022 年设备驱动程序

题目问，关于设备驱动程序，哪一项不正确？

A. 驱动程序与 I/O 控制方式无关。

B. 驱动程序负责设备初始化。

C. 进程执行驱动相关操作时可能阻塞。

D. 设备读写操作由驱动程序控制。

答案：A。

驱动程序当然与 I/O 控制方式有关。

因为：

- 程序查询方式需要驱动检查状态。
- 中断方式需要驱动与中断机制配合。
- DMA 方式需要驱动配置 DMA。

因此：

$$
\boxed{\text{驱动程序与具体硬件及 I/O 控制方式密切相关}}
$$

### 3.5 第四层：中断处理程序

设备完成操作后，可以发出中断请求。

中断处理程序需要：

1. 确认中断来源。
2. 保存必要的软件现场。
3. 读取设备状态。
4. 进行必要的数据或错误处理。
5. 清除、应答中断。
6. 更新 I/O 完成状态。
7. 唤醒等待进程或触发后续处理。

#### 特别重要：中断点与现场保存

需要区分两个概念。

中断点的保存：

典型 408 模型中，由硬件保证保存中断返回所需的程序计数器等关键信息。

其他现场信息的保存：

通用寄存器等上下文通常由中断入口软件保存。

因此，不能简单说“所有现场都是硬件保存”，也不能说“保存断点完全由操作系统软件负责”。

#### 真题 7：2020 年中断操作

题目给出：

I. 保存被中断程序的中断点。

II. 提供中断服务。

III. 初始化中断向量表。

IV. 保存中断屏蔽字。

问哪些操作由操作系统完成。

答案：

$$
\boxed{\text{II、III、IV}}
$$

原因：

- I：中断点由硬件在中断响应过程中保存。
- II：中断服务由操作系统提供。
- III：中断向量表需要由系统初始化。
- IV：中断屏蔽字的相关软件现场需要保存。

这道题考查的是中断响应阶段的硬件职责与操作系统职责的边界。

### 3.6 软件层次总结表

| 具体工作         | 负责的软件层次    |
| ------------ | ---------- |
| 格式化输出        | 用户层 I/O 软件 |
| 提供统一设备接口     | 设备独立性软件    |
| 逻辑设备名映射      | 设备独立性软件    |
| 设备分配与回收      | 设备独立性软件    |
| 通用缓冲管理       | 设备独立性软件    |
| 将读写请求翻译成硬件命令 | 设备驱动程序     |
| 配置设备控制寄存器    | 设备驱动程序     |
| 配置 DMA 控制器   | 设备驱动程序     |
| 处理设备完成中断     | 中断处理程序     |
| 完成实际物理传输     | 设备控制器及相关硬件 |

#### 真题 8：2011 年 I/O 请求处理顺序

题目：用户程序发出磁盘 I/O 请求后，系统的正确处理流程是什么？

答案：

$$
\boxed{ \text{用户程序} \rightarrow \text{系统调用处理程序} \rightarrow \text{设备驱动程序} \rightarrow \text{中断处理程序} }
$$

为什么系统调用处理程序在前？

因为用户程序无法直接随意控制硬件，必须先进入内核。

为什么驱动程序在中断处理程序之前？

因为设备必须先被启动，完成操作后才会发生相应的完成中断。

#### 2012 年真题：软件层次排序

正确的从上到下顺序：

$$
\boxed{ \text{用户级 I/O 软件} \rightarrow \text{设备独立性软件} \rightarrow \text{设备驱动程序} \rightarrow \text{中断处理程序} }
$$

两道题看似相似，但一定要区分：

- 2011 年问的是一次 I/O 请求的处理流程。
- 2012 年问的是I/O 软件的静态层次结构。

## 四、缓冲管理——本章最重要的计算专题之一

### 4.1 为什么要设置缓冲区？

假设磁盘每读取一块数据需要 100 微秒，CPU 处理这一块只需要 20 微秒。

如果每读取一块都必须等 CPU 完成处理后才能继续读取，就会形成大量空闲时间。

缓冲区可以把设备生产数据与进程消费数据分开。

主要作用包括：

- 缓和速度不匹配。
- 降低进程等待时间。
- 允许设备输入与 CPU 处理重叠。
- 减少频繁的小规模传输。
- 平滑突发数据流。

但缓冲区并不会自动加快设备本身的物理传输速度。

### 4.2 必须区分 Buffer、Cache、SPOOLing

| 技术       | 主要解决的问题     | 典型位置      |
| -------- | ----------- | --------- |
| Buffer   | 生产与消费速度不匹配  | 主存        |
| Cache    | 重复访问慢速数据    | 主存        |
| SPOOLing | 独占设备共享与任务排队 | 磁盘输出井、输入井 |

例如：

Buffer： 磁盘读出来的数据先放到内存，等待 CPU 处理。

Cache： 某数据块刚从磁盘读过，下次访问时直接从内存获取。

SPOOLing： 多个程序把打印任务提交到磁盘队列，由后台进程逐个打印。

这三个技术都可能使用临时存储，但核心目的不同。

### 4.3 单缓冲技术

单缓冲只有一个系统缓冲区。

```text
磁盘
  │
  │ T：读取数据
  ▼
系统缓冲区
  │
  │ M：复制数据
  ▼
用户工作区
  │
  │ C：CPU 分析
  ▼
处理结果
```

关键条件：

如果系统只有一个缓冲区，那么磁盘输入和缓冲区复制不能同时占用这个缓冲区。

但是，当数据已经复制到用户工作区后，CPU 分析当前数据时，磁盘可以使用空闲的系统缓冲区读取下一块。

这意味着：

- 设备输入与缓冲区复制不能重叠。
- 设备输入下一块与 CPU 处理上一块可以重叠。

#### 单缓冲时间推导

设：

$$
T=\text{输入一块的时间}
$$

$$
M=\text{复制一块的时间}
$$

$$
C=\text{分析一块的时间}
$$

第一块必须经历：

$$
T+M+C
$$

从第二块开始：

- CPU 处理上一块，需要 $C$。
- 磁盘输入下一块，需要 $T$。
- 这两个操作可以重叠。

因此中间阶段需要：

$$
\max(T,C)
$$

随后，还必须进行下一次复制，耗时 $M$。

所以稳定阶段每块的节拍是：

$$
\boxed{\Delta_{\text{single}}=\max(T,C)+M}
$$

对于 $n$ 块数据，常见模型的总时间为：

$$
\boxed{ T_{\text{single}} =T+nM+(n-1)\max(T,C)+C }
$$

也可以写成：

$$
\boxed{ T_{\text{single}} =T+M+(n-1)[\max(T,C)+M]+C }
$$

两种写法等价。

要注意这些公式假设每块使用一个用户工作区，复制与对该工作区的处理串行，且设备输入与 CPU 处理能够重叠。

### 4.4 双缓冲技术

双缓冲使用两个系统缓冲区。

```text
              ┌── Buffer A ──┐
磁盘输入 ──────┤              ├── 用户工作区
              └── Buffer B ──┘
```

工作过程：

第一块输入 Buffer A。

然后 CPU 处理 Buffer A 对应的数据，同时磁盘向 Buffer B 输入第二块。

随后两个缓冲区交换角色。

这样减少了“缓冲区被上一块占用，下一块无法进入”的问题。

#### 双缓冲时间推导

在典型模型中：

- 输入一块耗时 $T$。
- 复制并处理一块耗时 $M+C$。
- 两部分可以流水重叠。

因此稳定节拍为：

$$
\boxed{\Delta_{\text{double}}=\max(T,M+C)}
$$

处理 $n$ 块：

$$
\boxed{ T_{\text{double}} =T+(n-1)\max(T,M+C)+M+C }
$$

当复制时间可以忽略时：

$$
\boxed{ T_{\text{double}} =T+(n-1)\max(T,C)+C }
$$

注意，双缓冲不是简单地把单缓冲时间除以 2。

它的收益取决于设备输入和 CPU 处理能否真正并行，以及哪一阶段是瓶颈。

### 4.5 2011 年真题：单缓冲与双缓冲综合计算

这是一道必须独立掌握的经典题。

某文件占 10 个磁盘块，需要逐块读取并分析。

已知：

| 操作         | 时间                |
| ---------- | ----------------- |
| 从磁盘读入缓冲区   | $100\,\mu s$ |
| 从缓冲区复制到用户区 | $50\,\mu s$  |
| CPU 分析一块   | $50\,\mu s$  |
| 数据块数量      | 10                |

求单缓冲、双缓冲下的总时间。

#### 第一问：单缓冲

设：

$$
T=100,\quad M=50,\quad C=50,\quad n=10
$$

代入公式：

$$
\begin{aligned} T_{\text{single}} &=T+nM+(n-1)\max(T,C)+C\\ &=100+10\times50+9\times100+50\\ &=1550\,\mu s \end{aligned}
$$

因此：

$$
\boxed{T_{\text{single}}=1550\,\mu s}
$$

为什么不是 $2000\,\mu s$？

因为 $2000$ 相当于把每块的三个阶段完全串行执行：

$$
10(100+50+50)=2000
$$

忽略了 CPU 处理上一块时，磁盘可以读取下一块。

#### 第二问：双缓冲

首先计算进程侧复制加分析时间：

$$
M+C=50+50=100
$$

设备输入同样需要：

$$
T=100
$$

所以流水节拍：

$$
\max(T,M+C)=100
$$

总时间：

$$
\begin{aligned} T_{\text{double}} &=100+9\times100+100\\ &=1100\,\mu s \end{aligned}
$$

因此：

$$
\boxed{T_{\text{double}}=1100\,\mu s}
$$

最终答案：

$$
\boxed{(1550\,\mu s,\ 1100\,\mu s)}
$$

对应原题 B。

#### 这道题的本质

单缓冲时，复制操作会阻止设备继续使用唯一的缓冲区。

双缓冲时，设备可以交替使用两个缓冲区，输入和处理形成更充分的流水。

因此双缓冲提高的是并行程度，而不是让磁盘本身运行速度翻倍。

### 4.6 2013 年真题：两个数据块的最短处理时间

条件：

$$
T=100,\quad M=5,\quad C=90
$$

需要处理两块数据。

系统缓冲区和用户工作区均采用单缓冲。

题目问：最短需要多少时间？

#### 先画时间轴

第一块输入：

$$
0\sim100
$$

复制第一块：

$$
100\sim105
$$

此时第一块进入用户工作区。

接下来：

- CPU 从 105 开始分析第一块，需要 90。
- 磁盘从 105 开始读取第二块，需要 100。

时间轴为：

```text
时间：

0       100 105       195 205 210       300
|--------|---|----------|---|---|----------|

磁盘：
[第一块输入]   [第二块输入]

复制：
          [M1]              [M2]

CPU：
              [分析第一块]      [分析第二块]
```

具体事件：

- $t=105$：第一块复制完毕。
- $t=195$：第一块分析完毕。
- $t=205$：第二块输入完毕。
- $t=210$：第二块复制完毕。
- $t=300$：第二块分析完毕。

因此：

$$
\boxed{T_{\text{total}}=300}
$$

也可以使用公式：

$$
\begin{aligned} T_{\text{single}} &=100+2\times5+(2-1)\max(100,90)+90\\ &=100+10+100+90\\ &=\boxed{300} \end{aligned}
$$

答案 C。

#### 为什么这道题容易错？

因为许多同学看到“两块”，直接算：

$$
2(100+5+90)=390
$$

这样忽略了输入第二块与 CPU 分析第一块之间的重叠。

另一种错误是将两块直接视为双缓冲流水，也会算错。

解这种题最可靠的办法是画时间轴，而不是盲目套公式。

### 4.7 模拟题：稳态平均时间

假设：

$$
T=80\,\mu s,\quad M=40\,\mu s,\quad C=30\,\mu s
$$

采用单缓冲连续处理大量数据。

问每块平均需要多少时间。

这里没有给出具体 $n$，而且强调“连续处理多块”。

因此考查稳态节拍：

$$
\Delta_{\text{single}}=\max(T,C)+M
$$

代入：

$$
=\max(80,30)+40
$$

$$
\boxed{120\,\mu s}
$$

不要把“处理一块的平均稳态耗时”与“第一块完成的延迟”混淆。

第一块完成需要：

$$
80+40+30=150\,\mu s
$$

而稳定流水阶段的平均节拍是：

$$
120\,\mu s
$$

#### 缓冲计算题通用判断表

| 题目条件             | 主要方法                         |
| ---------------- | ---------------------------- |
| 单缓冲，处理大量块        | $\max(T,C)+M$            |
| 单缓冲，处理 $n$ 块 | 单缓冲总时间公式                     |
| 双缓冲，复制时间可忽略      | $T+(n-1)\max(T,C)+C$     |
| 双缓冲，复制不可忽略       | $T+(n-1)\max(T,M+C)+M+C$ |
| 题目给出特殊并行限制       | 重新画时间轴                       |
| 只问第一块完成时间        | $T+M+C$                  |

### 4.8 循环缓冲

循环缓冲使用多个缓冲单元。

```text
B0 → B1 → B2 → B3
↑              ↓
└──────────────┘
```

一般设置读指针和写指针。

生产者把数据写入写指针指向的位置。

消费者从读指针指向的位置读取。

读取或写入后，指针按照环形规则更新。

例如有 4 个槽位：

$$
\text{next}=(\text{current}+1)\bmod4
$$

注意：

循环缓冲不等于无限缓冲。

如果生产速度长期大于消费速度，缓冲区最终会满。

这与第二章生产者—消费者问题直接关联。

### 4.9 缓冲池

缓冲池是一组由系统统一管理的缓冲区。

典型组成：

1. 空缓冲队列。
2. 输入队列。
3. 输出队列。
4. 用于执行当前 I/O 操作的工作缓冲区。

当设备输入数据时，可以申请空缓冲区。

输入完成后，将相应缓冲区放入输入队列。

进程处理完毕后，再归还空缓冲区。

#### 模拟题

问：下面哪个不属于缓冲池的典型组成？

A. 空白缓冲队列

B. 输入队列

C. 输出队列

D. 循环缓冲

答案：D。

因为循环缓冲是另一种缓冲组织方式，不是缓冲池的典型队列类别。

### 4.10 磁盘高速缓存、预读与延迟写

#### 磁盘高速缓存

在主存保存磁盘块的副本。

当应用程序再次读取某个磁盘块时：

```text
应用请求读取
      ↓
查询内存缓存
  ├─ 命中 → 直接返回数据
  └─ 未命中 → 访问磁盘
```

它的主要目的：

减少真实的磁盘 I/O 次数。

#### 预读

如果程序正在顺序访问磁盘块：

```text
100 → 101 → 102 → 103
```

操作系统可以提前读取后续可能需要的数据。

这种技术称为预读（Read-ahead）。

预读通常能够改善顺序读性能。

对于完全不规则的随机访问，顺序预读的收益往往较低，但不能说所有随机访问都绝对不能进行预取。

#### 延迟写

程序修改数据后，操作系统可以先修改内存中的缓存块，并将其标记为脏块。

之后再选择合适的时机写回磁盘。

```text
应用修改数据
      ↓
修改内存缓存
      ↓
标记为脏块
      ↓
以后批量写回
```

这样可以合并多次写入。

但是，如果数据尚未持久化就发生断电，可能出现数据丢失。

因此延迟写通常需要与同步写、日志、刷盘等机制配合。

#### 2015 年真题

题目问：在系统内存中设置磁盘缓冲区的主要目的是什么？

A. 减少磁盘 I/O 次数。

B. 减少平均寻道时间。

C. 提高磁盘数据可靠性。

D. 实现设备无关性。

答案：A。

这道题强调磁盘缓存能够减少实际磁盘访问。

要注意：缓存减少某些访问，并不代表磁头执行一次寻道所需的机械时间变短。

## 五、设备分配与回收

### 5.1 设备分配要考虑什么？

给进程分配设备时，至少要考虑：

- 设备类型。
- 使用权限。
- 当前占用情况。
- 逻辑设备与物理设备的映射。
- 控制器、通道等相关资源是否可用。
- 分配策略是否可能引起死锁。

#### 2023 年真题

题目给出：

I. 设备类型。

II. 设备访问权限。

III. 设备占用状态。

IV. 逻辑设备和物理设备的映射关系。

问设备分配需要考虑哪些因素。

答案：四项全部需要，选 D。

因为设备分配既要满足资源可用性，也要保证访问合法性和映射关系正确。

### 5.2 四张设备管理表

这是典型的直接记忆型考点。

| 缩写   | 英文名称                     | 中文名称   | 核心职责        |
| ---- | ------------------------ | ------ | ----------- |
| SDT  | System Device Table      | 系统设备表  | 全局登记设备      |
| DCT  | Device Control Table     | 设备控制表  | 记录具体设备状态    |
| COCT | Controller Control Table | 控制器控制表 | 记录控制器状态     |
| CHCT | Channel Control Table    | 通道控制表  | 记录 I/O 通道状态 |

典型分配顺序：

```text
进程提出设备请求
         ↓
SDT：寻找合适设备
         ↓
DCT：检查设备能否分配
         ↓
COCT：检查控制器能否分配
         ↓
CHCT：检查通道能否分配
         ↓
建立占用关系
         ↓
启动 I/O
```

因此：

$$
\boxed{SDT\rightarrow DCT\rightarrow COCT\rightarrow CHCT}
$$

#### 模拟题

题目直接要求判断设备分配访问四张表的先后顺序。

答案：

$$
\boxed{SDT\rightarrow DCT\rightarrow COCT\rightarrow CHCT}
$$

对应 B。

记忆方法：

系统找设备，设备找控制器，控制器找通道。

要注意，现代设备系统不一定真的按这一套传统结构逐级分配。408 题目如果采用该模型，就按给定结构作答。

### 5.3 静态分配和动态分配

| 分配方式 | 特征                | 优点    | 缺点          |
| ---- | ----------------- | ----- | ----------- |
| 静态分配 | 进程执行前申请所需设备，结束后释放 | 管理简单  | 占用时间长       |
| 动态分配 | 运行期间按需申请，用完释放     | 利用率较高 | 可能引起资源竞争或死锁 |

#### 设备分配与死锁

若进程在持有某些设备资源时，又去申请其他不可剥夺资源，就可能形成资源等待关系。

例如：

```text
P1 占有设备 A，等待设备 B
P2 占有设备 B，等待设备 A
```

如果两者无法被强制剥夺，又没有其他解除机制，可能发生死锁。

这与第二章死锁的四个必要条件相对应：

互斥、请求和保持、不可剥夺、循环等待。

还要记住：

$$
\boxed{\text{死锁状态}\Rightarrow\text{不安全状态}}
$$

但：

$$
\boxed{\text{不安全状态}\not\Rightarrow\text{已经发生死锁}}
$$

不安全状态只是无法保证所有进程都有安全完成序列。

### 5.4 设备独立性与设备分配的关系

设备独立性解决的是：

程序不知道实际使用哪台物理设备。

设备分配解决的是：

系统决定现在把哪台设备交给哪个请求使用。

二者依靠逻辑设备映射关联起来。

例如：

```text
应用请求逻辑设备 printer
            ↓
LUT 查询
            ↓
系统设备表 SDT
            ↓
选择可用物理打印机
            ↓
设备驱动程序启动操作
```

因此，逻辑设备表 LUT 与系统设备表 SDT 不应混为一谈：

- LUT 主要处理逻辑名与实际设备的对应关系。
- SDT 主要登记系统设备资源。

## 六、SPOOLing——假脱机技术

### 6.1 什么是 SPOOLing？

SPOOLing 全称为：

Simultaneous Peripheral Operations On-Line

中文通常称为假脱机技术。

其思想是：

利用外存和后台 I/O 进程，让原本独占的设备在逻辑上表现为共享设备。

经典场景：打印机。

假设有三个进程：

```text
P1 ─┐
    │
P2 ─┼──→ 磁盘输出井
    │           ↓
P3 ─┘      后台输出进程
                ↓
             打印机
```

三个进程不需要同时直接占用打印机。

它们可以把打印任务放入磁盘输出井。

后台输出进程逐个取出任务并发送给打印机。

### 6.2 SPOOLing 系统的组成

主要有四种结构：

| 组成   | 作用                |
| ---- | ----------------- |
| 输入井  | 在磁盘上保存等待处理的输入数据   |
| 输出井  | 在磁盘上保存等待输出的数据     |
| 输入进程 | 管理外设输入与输入井之间的传送   |
| 输出进程 | 管理输出井与实际输出设备之间的传送 |

另外还需要内存中的输入、输出缓冲区，以及相应的任务队列和控制信息。

非常重要：用户进程不负责直接控制设备与输入井、输出井之间的实际传送。

这一工作由操作系统的后台输入输出进程负责。

### 6.3 SPOOLing 为什么能够提高效率？

假设打印一个任务需要 30 秒。

没有假脱机机制时，如果作业必须同步等待打印完成，进程可能长时间受打印操作制约。

使用 SPOOLing 后：

1. 程序把打印数据提交到输出井。
2. 输出请求进入队列。
3. 程序通常可以继续执行。
4. 后台输出进程负责实际打印。

注意：

SPOOLing 不会让一台不能同时打印两份文档的物理打印机突然实现同时打印。

它改善的是任务提交、排队与设备使用的组织方式。

### 6.4 SPOOLing 的必要支持

经典模型中主要需要：

外存支持：

因为输入井和输出井通常位于磁盘上。

多道程序设计支持：

因为用户进程和后台输入输出进程需要能够并发推进。

所以：

$$
\boxed{\text{SPOOLing}=\text{外存队列}+\text{后台 I/O 进程}+\text{逻辑设备虚拟化}}
$$

### 6.5 2016 年真题：SPOOLing

问：下列关于 SPOOLing 的说法，错误的是哪一项？

A. 需要外存支持。

B. 需要多道程序设计支持。

C. 可以使多个作业共享一台独占设备。

D. 由用户作业控制设备与输入输出井之间的数据传送。

答案：D。

前三项正确。

D 错误，因为设备与输入输出井之间的实际传送由操作系统的后台 I/O 进程控制。

#### 模拟题：SPOOLing 属于哪一层？

A. 用户层 I/O 软件。

B. 设备独立性软件。

C. 设备驱动程序。

D. 中断处理程序。

答案：B。

因为 SPOOLing 是操作系统提供的通用设备管理与虚拟化机制。

当然，具体输出数据仍然需要设备驱动程序与硬件配合。

### 6.6 SPOOLing、缓冲和虚拟存储器的区别

这是容易跨章节混淆的地方。

| 技术       | 虚拟化或优化对象       |
| -------- | -------------- |
| 单缓冲、双缓冲  | 数据传送的速度匹配和流水并行 |
| 磁盘高速缓存   | 对慢速数据的重复访问     |
| SPOOLing | 独占 I/O 设备      |
| 虚拟存储器    | 进程的逻辑地址空间      |

特别注意：

虚拟设备不等于虚拟存储器。

SPOOLing 把一台物理打印机表现为多个可并发提交请求的逻辑打印服务。

虚拟存储器则通过地址映射与按需调页，为进程提供与实际驻留主存不同的地址空间抽象。

## 七、磁盘基础与磁盘管理

这一部分开始进入本章另一大计算专题。

学习磁盘管理时，必须建立两个不同的概念：

磁盘的物理组织决定数据如何存储。

磁盘调度算法决定请求按照什么顺序被处理。

先弄懂物理组织，后面才能正确计算磁盘地址、访问时间和磁头移动距离。

### 7.1 机械磁盘的基本结构

传统机械硬盘主要包含：

- 盘片。
- 磁头。
- 磁道。
- 扇区。
- 柱面。

#### 磁道

盘面上的同心圆形记录区域叫磁道。

#### 扇区

每条磁道进一步划分为若干扇区。

扇区是传统磁盘的基本物理记录单位。

#### 柱面

多个盘面上，具有相同半径的磁道共同构成一个柱面。

例如：

```text
柱面 0：
  盘面 0 的磁道 0
  盘面 1 的磁道 0
  盘面 2 的磁道 0

柱面 1：
  盘面 0 的磁道 1
  盘面 1 的磁道 1
  盘面 2 的磁道 1
```

同一柱面内更换磁头通常不需要磁臂跨柱面移动。

跨柱面访问才涉及主要的寻道动作。

#### 簇

簇是文件系统进行空间分配时使用的逻辑单位。

一个簇可以包含多个扇区。

例如：

$$
1\text{ 簇}=4\text{ 扇区}
$$

每扇区 512B，则：

$$
1\text{ 簇}=4\times512=2048\text{ B}
$$

必须区分：

磁道、柱面、扇区属于磁盘组织概念；簇属于文件系统的分配概念。

### 7.2 磁盘容量计算

假设磁盘共有：

- 300 个柱面。
- 每柱面 10 条磁道。
- 每磁道 200 个扇区。
- 每扇区 512B。

容量：

$$
\begin{aligned} C &=300\times10\times200\times512\\ &=\boxed{307200000\text{ B}} \end{aligned}
$$

按十进制单位：

$$
\boxed{307.2\text{ MB}}
$$

按二进制单位：

$$
\frac{307200000}{1024^2}\approx292.97\text{ MiB}
$$

这里有一个细节：

如果题目采用 $1\text{ KB}=1024\text{ B}$，就应按照题目的单位约定换算。

不要把 MB 和 MiB 的换算约定随意混用。

### 7.3 磁盘地址转换——重点计算

传统磁盘地址可以表示为：

$$
(\text{柱面号},\text{磁头号},\text{扇区号})
$$

简称 CHS。

此类题目的核心方法是：

逐层整除、逐层取余。

假设：

- 每柱面有 $H$ 条磁道。
- 每磁道有 $S$ 个扇区。
- 所有编号从 0 开始。
- 连续编号遵循先扇区、再磁道、最后柱面的顺序。

对于逻辑扇区号 $k$：

柱面号：

$$
\boxed{ c=\left\lfloor\frac{k}{HS}\right\rfloor }
$$

柱面内剩余偏移：

$$
r=k\bmod(HS)
$$

磁头号：

$$
\boxed{ h=\left\lfloor\frac{r}{S}\right\rfloor }
$$

扇区号：

$$
\boxed{s=r\bmod S}
$$

#### 模拟题：5687 号逻辑记录的位置

某磁盘：

- 80 个柱面。
- 每柱面 12 条磁道。
- 每磁道 16 个扇区。
- 每条逻辑记录占一个扇区。
- 所有编号从 0 开始。

求 5687 号逻辑记录的 CHS。

第一步：每柱面记录数

$$
12\times16=192
$$

第二步：求柱面号

$$
5687=29\times192+119
$$

因此：

$$
c=29
$$

第三步：求磁头号

$$
119=7\times16+7
$$

因此：

$$
h=7,\qquad s=7
$$

最终：

$$
\boxed{(29,7,7)}
$$

答案 C。

这类题目最常见的错误是忘记编号从 0 开始，或者把磁头数和扇区数的除法顺序颠倒。

$$
C=300\times10\times200\times512

$$

#### 第三问：100530 号簇的物理地址

先求柱面号：

$$
c=\left\lfloor\frac{100530}{1000}\right\rfloor=100
$$

柱面内簇号：

$$
100530\bmod1000=530
$$

每磁道有 100 簇，所以磁头号：

$$
h=\left\lfloor\frac{530}{100}\right\rfloor=5
$$

磁道内簇号：

$$

$$

每簇有 2 个扇区，所以起始扇区号：

### 7.5 位示图管理磁盘空闲空间

这部分与操作系统第 4 章文件管理有交叉，但在 2010 年 I/O 综合大题中也出现过。

位示图的基本思想是：

每个磁盘块使用一个二进制位表示其分配状态。

例如：

```text
磁盘块号：0 1 2 3 4 5 6 7

位示图：  1 0 0 1 1 0 1 0
```

可以约定：

- 0：空闲。
- 1：已分配。

也可以反过来，但必须保持一致。

#### 位示图空间计算

假设有 16384 个磁盘块。

每块占 1 bit。

需要：

$$
16384\text{ bit}
$$

转换为字节：

$$
\frac{16384}{8}=2048\text{ B}
$$

也就是：

$$
\boxed{2\text{ KiB}}
$$

因此 2 KiB 恰好可以表示 16384 个磁盘块的状态。

#### 边界问题

假设有 16385 个磁盘块。

需要：

$$
\left\lceil\frac{16385}{8}\right\rceil =\boxed{2049\text{ B}}
$$

不能仍然使用 2048B。

另外，位示图最后一个字节中可能存在不对应实际磁盘块的填充位。

这些填充位必须标记为不可分配，否则扫描位示图时可能分配不存在的磁盘块。

## 八、磁盘初始化与系统引导

### 8.1 磁盘初始化的三个重要阶段

经典顺序：

$$
\boxed{ \text{物理格式化} \rightarrow \text{磁盘分区} \rightarrow \text{逻辑格式化} }
$$

#### 第一阶段：物理格式化

也叫低级格式化。

主要负责建立底层物理记录结构，例如：

- 磁道。
- 扇区。
- 底层控制信息。
- 校验信息。

现代 HDD 的低级格式化通常在工厂完成。

#### 第二阶段：磁盘分区

在磁盘上建立不同的逻辑区域。

例如：

```text
整个磁盘
   ├── 分区 A
   ├── 分区 B
   └── 分区 C
```

建立分区表，记录各分区的范围和属性。

#### 第三阶段：逻辑格式化

也叫高级格式化。

其主要作用是建立文件系统。

包括：

- 初始化文件系统元数据。
- 初始化空闲空间管理结构。
- 建立根目录。
- 建立文件分配或索引结构。

#### 三者对比

| 操作    | 主要工作       | 是否创建文件系统根目录 |
| ----- | ---------- | ----------- |
| 物理格式化 | 建立底层物理记录结构 | 否           |
| 分区    | 划分逻辑区域     | 否           |
| 逻辑格式化 | 建立文件系统     | 是           |

### 8.2 2017 年真题：逻辑格式化

题目问：逻辑格式化完成哪些工作？

I. 对磁盘进行分区。

II. 建立文件系统根目录。

III. 确定磁盘扇区校验码所占位数。

IV. 初始化保存空闲磁盘块信息的数据结构。

判断：

- I：属于分区。
- II：属于逻辑格式化。
- III：属于物理格式化。
- IV：属于逻辑格式化。

所以：

$$
\boxed{\text{II、IV}}
$$

答案 B。

### 8.4 2021 年第 46 题：系统引导综合大题

原题明确采用传统 MBR 引导模型。

要求回答：

1. 四种引导程序的执行顺序。
2. 制作启动盘的操作顺序。
3. 扇区划分和根目录建立分别属于哪个阶段。

#### 第一问：引导程序执行顺序

正确顺序：

$$
\boxed{ \text{ROM 引导程序} \rightarrow \text{磁盘引导程序} \rightarrow \text{分区引导程序} \rightarrow \text{操作系统初始化程序} }
$$

为什么 ROM 最先？

因为开机时内存中的操作系统尚未运行，需要固件代码首先获取控制权。

为什么磁盘引导程序在分区引导程序之前？

因为磁盘引导程序首先确定后续启动目标，才会转交给相应分区的引导程序。

#### 第二问：制作启动盘的顺序

$$
\boxed{ \text{物理格式化} \rightarrow \text{磁盘分区} \rightarrow \text{逻辑格式化} \rightarrow \text{安装操作系统} }
$$

这是原题所采用的经典抽象过程。

现实计算机通常已经完成低级格式化，不要求每次安装操作系统都重新物理格式化。

#### 第三问：扇区与根目录

扇区的底层物理记录结构由：

$$
\boxed{\text{物理格式化}}
$$

建立。

\boxed{\text{逻辑格式化}}

## 九、磁盘访问时间——必须掌握的公式

机械硬盘一次访问主要包含：

$$
\boxed{ T_{\text{access}} =T_s+T_r+T_t }
$$

其中：

- $T_s$：寻道时间。
- $T_r$：旋转延迟。
- $T_t$：数据传输时间。

### 9.1 寻道时间

磁头移动到目标磁道所花费的时间。

若题目规定每跨越一个磁道耗时 $t$，则：

$$
T_s=D\times t
$$

其中 $D$ 是累计跨越的磁道数。

真实机械硬盘的寻道时间不一定与移动距离严格成正比，但 408 计算题经常采用这一简化模型。

### 9.2 旋转延迟

磁头到达目标磁道后，还需要等待目标扇区旋转到磁头下方。

假设转速为：

$$
r\text{ 转/分钟}
$$

那么一圈时间：

$$
\boxed{T_{\text{rev}}=\frac{60}{r}\text{ s}}
$$

如果随机访问的目标扇区均匀分布，平均旋转延迟约为半圈：

$$
\boxed{ T_r=\frac{30}{r}\text{ s} }
$$

例如：

$$
r=6000\text{ r/min}
$$

则每秒：

$$
100\text{ 转}
$$

一圈时间：

$$
T_{\text{rev}}=\frac{1}{100}=0.01\text{ s}
$$

即：

$$
10\text{ ms}
$$

平均旋转延迟：

$$
\boxed{5\text{ ms}}
$$

注意：

平均旋转延迟是 5ms，并不意味着每次旋转等待都固定为 5ms。

### 9.3 传输时间

假设每磁道有 100 个扇区。

一圈需要 10ms。

则读取一个扇区的理想传输时间：

$$
T_t=\frac{10}{100}
$$

$$
\boxed{0.1\text{ ms}}
$$

如果连续读取 $k$ 个扇区，且忽略额外开销：

$$
T_t=\frac{kT_{\text{rev}}}{S}
$$

其中 $S$ 表示每磁道扇区数。

#### 典型计算

假设：

- 寻道时间 8ms。
- 转速 6000r/min。
- 每磁道 100 个扇区。
- 读取一个随机扇区。

则平均访问时间：

$$
T=8+5+0.1
$$

$$
\boxed{13.1\text{ ms}}
$$

要注意，磁盘调度通常主要改变寻道时间，不能仅根据寻道距离推断旋转等待一定如何变化。

## 十、磁盘调度算法——本章最重要的计算考点

### 10.1 六种算法的总体比较

| 算法     | 中文名称      | 调度依据            |
| ------ | --------- | --------------- |
| FCFS   | 先来先服务     | 请求到达顺序          |
| SSTF   | 最短寻道时间优先  | 距离当前磁头最近        |
| SCAN   | 扫描算法、电梯算法 | 沿固定方向到边界再折返     |
| LOOK   | 改进扫描算法    | 沿固定方向到最远请求再折返   |
| C-SCAN | 循环扫描算法    | 单方向服务，到物理边界后回绕  |
| C-LOOK | 改进循环扫描    | 单方向服务，在请求端点之间回绕 |

所有算法都必须先确定：

- 初始磁头位置。
- 请求队列。
- 初始移动方向。
- 磁盘边界。
- 回绕是否计入移动距离。

这里重点强调：

严格 SCAN 和 LOOK 不完全相同，严格 C-SCAN 和 C-LOOK 也不完全相同。

很多题目只要求访问顺序，此时二者可能给出相同序列。

但一旦要求实际磁头移动距离，区别就很重要。

### 10.2 FCFS：先来先服务

直接按照请求到达顺序访问。

假设：

$$
Q=(55,58,39,18,90,160,150,38,184)
$$

初始磁头位于：

$$
100
$$

则访问顺序：

$$
100\rightarrow55\rightarrow58\rightarrow39 \rightarrow18\rightarrow90\rightarrow160 \rightarrow150\rightarrow38\rightarrow184
$$

累计移动距离：

$$
\begin{aligned} D={}&45+3+19+21+72\\ &+70+10+112+146\\ ={}&\boxed{498} \end{aligned}
$$

FCFS 的优势：

- 简单。
- 按到达顺序处理。
- 不会因为请求距离较远而永久推迟已经进入队列的请求。

缺点：

- 不考虑磁头当前位置。
- 可能频繁跨磁道往返。

### 10.3 SSTF：最短寻道时间优先

核心规则：

每次选距离当前磁头最近的请求。

特别注意，SSTF 每完成一个请求都需要重新比较剩余请求。

#### 2021 年真题

当前磁头位于：

$$
184
$$

请求序列：

$$
184,\ 187,\ 176,\ 182,\ 199
$$

第一步：请求 184 与当前磁头位置相同。

移动距离：

$$
0
$$

第二步：从 184 找最近的请求。

到 182：

$$
2
$$

到 187：

$$
3
$$

到 176：

$$
8
$$

到 199：

$$
15
$$

所以选择 182。

接下来依次选择：

$$
187\rightarrow176\rightarrow199
$$

完整顺序：

$$
184\rightarrow184\rightarrow182\rightarrow187 \rightarrow176\rightarrow199
$$

累计移动距离：

$$
D=0+2+5+11+23
$$

$$
\boxed{D=41}
$$

答案 C。

#### SSTF 的缺点：可能饥饿

假设磁头总是在 50 附近。

系统不断产生：

$$
49,\ 50,\ 51
$$

附近的新请求可能持续被优先处理。

而远处 190 号磁道的请求可能长期得不到服务。

因此：

$$
\boxed{\text{SSTF 可能发生饥饿}}
$$

另外，如果两个请求距离相同，SSTF 本身没有规定唯一的选择顺序，需要根据题目给定的额外规则处理。

<Tabs items={['SCAN', 'LOOK']} defaultIndex={0}>

<Tab value="SCAN">

也叫电梯算法。

假设磁头位于 100，正在向磁道号增大的方向移动。

请求：

$$
18,38,39,55,58,90,150,160,184
$$

先访问当前方向上的请求：

$$
150\rightarrow160\rightarrow184
$$

然后折返访问较低磁道：

$$
90\rightarrow58\rightarrow55\rightarrow39\rightarrow38\rightarrow18
$$

因此服务顺序：

$$
\boxed{ 150,160,184,90,58,55,39,38,18 }
$$

这是典型的 SCAN 访问序列。

<Callout type="warn" title="严格 SCAN 的边界条件">

注意：如果采用严格 SCAN，磁头还需要到达该方向的物理边界才折返。

</Callout>

因为这道题只问服务顺序，所以是否经过物理边界不改变答案。

但如果要求实际移动距离，就必须确定边界。

</Tab>

<Tab value="LOOK">

LOOK 与 SCAN 的区别：

LOOK 只移动到当前方向上最后一个待处理请求，就可以折返。

例如：

- 当前磁头为 100。
- 向大号移动。
- 请求为 20、90、120、180。
- 磁盘范围为 0～299。

LOOK：

```text
100 → 120 → 180 → 90 → 20
```

移动距离：

$$
D=20+60+90+70
$$

$$
\boxed{240}
$$

严格 SCAN：

```text
100 → 120 → 180 → 299 → 90 → 20
```

移动距离：

$$
D=20+60+119+209+70
$$

$$
\boxed{478}
$$

虽然两者服务请求的先后顺序完全相同，但实际磁头移动距离不同。

这就是 SCAN 与 LOOK 的关键区别。

</Tab>

</Tabs>

### 10.6 C-SCAN：循环扫描

C-SCAN 只在一个方向上服务请求。

到达磁盘边界后，磁头回到另一端，并继续沿原来的方向服务。

例如：

```text
方向：磁道号增大

0 → → → → → 199
↑             │
└─────────────┘
```

从最高端返回最低端时，不沿途服务请求。

#### 2024 年真题：C-SCAN

磁盘共有 400 个磁道：

$$
0\sim399
$$

当前磁头在 200 号磁道。

方向为磁道号减小。

待处理请求：

$$
300,120,110,0,160,210,399
$$

第一步：沿减小方向服务

$$
200\rightarrow160\rightarrow120\rightarrow110\rightarrow0
$$

从 200 到 0：

$$
D_1=200
$$

第二步：回绕到另一端

从 0 返回 399：

$$
D_2=399
$$

回绕途中不服务请求。

第三步：继续沿减小方向服务

到达 399 后，依次处理：

$$
399\rightarrow300\rightarrow210
$$

移动距离：

$$
D_3=399-210=189
$$

所以总距离：

$$
D=200+399+189
$$

$$
\boxed{D=788}
$$

答案 C。

这是严格 C-SCAN 典型题。

特别注意：

从 0 到 399 的回绕段，虽然不服务中间的请求，但磁头发生了物理移动，因此计算实际移动距离时应当计入。

### 10.7 C-LOOK：改进循环扫描

C-LOOK 不必到达磁盘物理边界。

它只在实际请求的最远端之间循环。

例如：

- 初始磁头：100。
- 方向：增大。
- 请求：30、50、90、120。

C-LOOK：

```text
100 → 120 → 30 → 50 → 90
```

实际移动距离：

$$
D=20+90+20+40
$$

$$
\boxed{170}
$$

如果磁盘范围是 0～199，严格 C-SCAN：

```text
100 → 120 → 199 → 0 → 30 → 50 → 90
```

移动距离：

$$
\begin{aligned} D={}&20+79+199+30+20+40\\ ={}&\boxed{388} \end{aligned}
$$

两者都服务：

$$
120\rightarrow30\rightarrow50\rightarrow90
$$

但移动距离不同。

## 十一、2010 年第 45 题：磁盘综合大题完整解析

这道题非常重要，因为它把三个知识点结合在一起：

1. 位示图。
2. 循环扫描与磁盘访问时间。
3. HDD 和 SSD 的区别。

并且，这道题存在一个值得特别注意的算法定义与参考答案口径差异。

### 11.1 原题条件

系统用 2KB 内存记录 16384 个磁盘块的空闲状态。

磁盘条件：

| 参数         | 数值           |
| ---------- | ------------ |
| 转速         | 6000 r/min   |
| 每磁道扇区数     | 100          |
| 每跨一个磁道平均耗时 | 1ms          |
| 当前磁头位置     | 100          |
| 初始方向       | 增大           |
| 请求队列       | 50、90、30、120 |

每个请求读取一个随机分布的扇区。

### 11.2 第一问：空闲空间管理方法

每个磁盘块需要一个状态位。

$$
16384\text{ bit}=2048\text{ B}
$$

而：

$$
2\text{ KiB}=2048\text{ B}
$$

所以使用：

$$
\boxed{\text{位示图法}}
$$

空间恰好足够。

### 11.3 第二问：磁盘访问时间

首先计算与访问次序无关的部分。

#### 旋转时间

$$
6000\text{ r/min}=100\text{ r/s}
$$

因此每转：

$$
T_{\text{rev}}=10\text{ ms}
$$

平均旋转延迟：

$$
T_r=5\text{ ms}
$$

每扇区传输时间：

$$
T_t=\frac{10}{100}=0.1\text{ ms}
$$

读取 4 个随机扇区：

$$
4(5+0.1)=20.4\text{ ms}
$$

#### 按一种常见参考口径计算

一种常见参考计算口径采用以下移动路径：

```text
100 → 120 → 30 → 50 → 90
```

累计移动距离：

$$
D=20+90+20+40
$$

$$
D=170
$$

每跨一个磁道需要 1ms，所以：

$$
T_s=170\text{ ms}
$$

总时间：

$$
T=170+20.4
$$

$$
\boxed{190.4\text{ ms}}
$$

这是该题常见的参考结果。

#### 必须注意的严格定义问题

上述路径实际上符合C-LOOK 的请求端点回绕方式。

如果严格按照 C-SCAN 定义，磁头必须到达磁盘物理边界，再回绕到另一端。

若最大磁道编号为 $H$，严格 C-SCAN 的路径应为：

$$
100\rightarrow120\rightarrow H\rightarrow0 \rightarrow30\rightarrow50\rightarrow90
$$

移动距离：

$$
D=(H-100)+H+90
$$

即：

$$
\boxed{D=2H-10}
$$

总平均时间：

$$
\boxed{T=2H+10.4\text{ ms}}
$$

由于原题没有明确给出最高磁道编号，若采用严格 C-SCAN 且把回绕的实际移动计入时间，就不能唯一确定数值。

例如，补充规定磁道范围为 $0\sim199$，则：

$$
D=2\times199-10=388
$$

总时间：

$$
\boxed{408.4\text{ ms}}
$$

因此考试复习时应同时记住：

- 原题参考计算口径：190.4ms。
- 严格 C-SCAN：必须考虑物理磁道边界。
- C-LOOK：只在请求端点之间回绕。

做题时优先遵循题目给出的完整运行规则。如果题目存在类似定义不一致的情况，应明确写出所采用的模型。

### 11.4 第三问：替换为 SSD 后如何调度？

机械硬盘的性能受寻道和旋转延迟影响。

但 SSD 没有传统机械磁头和旋转盘片。

因此：

- 不存在机械寻道距离。
- 不存在盘片旋转延迟。
- 按磁道号远近重排请求不再具有相同的意义。

按照该真题的简化模型，可以使用：

$$
\boxed{FCFS}
$$

原因是 FCFS 实现简单、公平，不需要为了减少机械寻道而重排请求。

但现实 SSD 仍然可能通过请求合并、队列管理、通道并行等方式优化 I/O。

所以不能简单推出“SSD 完全不需要 I/O 调度”。

## 十二、磁盘调度高频易错点与算法比较

### 12.1 一个例子比较六种算法

假设：

- 磁盘范围为 0～199。
- 当前磁头位置为 100。
- 当前方向为增大。
- 所有请求已经到达。
- 请求队列：

$$
55,58,39,18,90,160,150,38,184
$$

按严格边界规则计算实际磁头移动距离，回绕段也计入。

| 算法     | 服务请求顺序                        | 移动距离 |
| ------ | ----------------------------- | ---- |
| FCFS   | 55,58,39,18,90,160,150,38,184 | 498  |
| SSTF   | 90,58,55,39,38,18,150,160,184 | 248  |
| SCAN   | 150,160,184,90,58,55,39,38,18 | 280  |
| LOOK   | 150,160,184,90,58,55,39,38,18 | 250  |
| C-SCAN | 150,160,184,18,38,39,55,58,90 | 388  |
| C-LOOK | 150,160,184,18,38,39,55,58,90 | 250  |

这里特别注意，表中 SCAN、C-SCAN 的数值采用到物理边界的严格定义。

例如：

SCAN：

$$
100\rightarrow199\rightarrow18
$$

所以：

$$
D=(199-100)+(199-18)=280
$$

C-SCAN：

$$
100\rightarrow199\rightarrow0\rightarrow90
$$

所以：

$$
D=(199-100)+199+90=388
$$

SSTF 则需要逐个比较最近请求，不能从其他算法的排序结果直接推断。

这个例子说明：

不同算法的总寻道距离并没有对所有请求集合都成立的固定大小顺序。

不要死记“SSTF 一定比 LOOK 短”或“SCAN 一定比 FCFS 好”。

具体结果要根据请求集合计算。

### 12.2 2015 年真题：SCAN 的方向判断

某硬盘有 200 个磁道。

最外侧磁道号为 0。

请求：

$$
130,42,180,15,199
$$

当前磁头在 58 号磁道，并从外侧向内侧移动。

由于最外侧编号为 0，向内侧移动就是向磁道号增大的方向移动。

SCAN 先访问：

$$
130\rightarrow180\rightarrow199
$$

再反向：

$$
42\rightarrow15
$$

总距离：

$$
D=(199-58)+(199-15)
$$

$$
D=141+184
$$

$$
\boxed{325}
$$

答案 C。

这道题的核心陷阱是：

不要凭直觉把“向内侧”理解为磁道编号减小。

必须先根据题目给出的编号方式确定方向。

### 12.3 2018 年真题：磁臂黏着

磁臂黏着是指磁头长期停留在某个磁道或附近区域，不能及时响应其他区域的访问请求。

真题问：哪种调度算法不会导致磁臂黏着？

A. FCFS。

B. SSTF。

C. SCAN。

D. C-SCAN。

答案：A。

原因是 FCFS 按请求到达顺序处理，不会因为后续请求持续出现在某个磁道附近，就一直把更早到达的远端请求向后推。

其他基于位置或方向的调度，在某些动态请求条件下可能出现磁臂黏着。

注意：

“某请求发生饥饿”与“磁臂黏着”不是完全相同的定义。

二者可能相关，但不能直接当作同义词。

## 十三、SSD 固态硬盘——容易考概念辨析

### 13.1 SSD 与 HDD 的主要区别

| 特征     | HDD      | SSD             |
| ------ | -------- | --------------- |
| 存储介质   | 磁性盘片     | Flash 闪存        |
| 机械磁头   | 有        | 无               |
| 寻道时间   | 有        | 无传统机械寻道         |
| 旋转延迟   | 有        | 无               |
| 随机访问   | 受机械运动影响  | 通常更快            |
| 核心管理机制 | 磁头与扇区访问  | FTL、垃圾回收、磨损均衡   |
| 典型性能瓶颈 | 寻道、旋转、传输 | 闪存操作、并行度、控制器管理等 |

### 13.2 SSD 的读写单位

NAND Flash 的典型特点：

按页读取和编程，按擦除块擦除。

例如：

一个擦除块包含多个页。

当需要修改某个页时，不能把 NAND Flash 当成普通 RAM 一样随意原地覆盖。

实际控制器通常会把更新数据写入新的物理页，再调整映射关系。

旧数据所在页随后被标记为无效。

这引出了三个重要概念。

#### FTL：闪存翻译层

Flash Translation Layer。

负责把逻辑块地址映射到闪存内部的物理存储位置。

```text
主机逻辑块地址 LBA
          ↓
         FTL
          ↓
闪存内部物理页
```

FTL 是 SSD 的重要核心机制。

#### 垃圾回收

随着数据不断更新，Flash 中会出现失效页。

垃圾回收负责整理有效数据，并回收包含无效页的擦除块空间。

#### 磨损均衡

Flash 擦除次数有限。

如果一直使用某些物理块，会使它们过早磨损。

磨损均衡的目标是尽量合理分散擦写次数，延长设备寿命。

### 13.3 SSD 模拟题

题目问：哪一项关于 SSD 的描述正确？

A. SSD 属于磁表面存储器。

B. FTL 可以完成地址转换。

C. SSD 的随机写性能与普通 HDD 基本相同。

D. SSD 的所有页都可以不受限制地任意顺序写入。

答案：B。

A 错，因为 SSD 使用半导体闪存。

C 错，因为 SSD 没有机械寻道，随机读写通常都显著快于 HDD。

D 的描述过于绝对，不符合典型 NAND Flash 的编程限制。

因此：

$$
\boxed{\text{FTL 的核心作用之一是逻辑地址到物理闪存位置的映射}}
$$

### 综合题 1：DMA 与中断

某设备使用 DMA，每秒传送 1000 个数据块，每块 4KiB。

假设每块传输完成产生一次中断，CPU 每次中断处理需要 2000 个时钟周期，CPU 主频为 1GHz。

问：仅完成中断处理占 CPU 时间的百分比是多少？

解答：

每秒中断次数：

$$
1000
$$

总中断周期：

$$
1000\times2000=2000000
$$

CPU 每秒周期：

$$
10^9
$$

因此：

$$
\alpha=\frac{2\times10^6}{10^9}
$$

$$
\boxed{\alpha=0.2\%}
$$

注意：题目只给出中断处理周期，因此不能把 DMA 初始化等其他开销也算进去。

### 综合题 2：单缓冲与双缓冲

某系统处理 8 个数据块：

$$
T=120,\quad M=20,\quad C=80
$$

求单缓冲与双缓冲下的总时间。

单缓冲：

$$
\begin{aligned} T_{\text{single}} &=120+8\times20\\ &\quad+7\times\max(120,80)+80\\ &=120+160+840+80\\ &=\boxed{1200} \end{aligned}
$$

双缓冲：

$$
M+C=100
$$

$$
\begin{aligned} T_{\text{double}} &=120+7\times\max(120,100)+100\\ &=120+840+100\\ &=\boxed{1060} \end{aligned}
$$

双缓冲节省：

$$
1200-1060=\boxed{140}
$$

### 综合题 4：位示图

某磁盘共有 10000 个块，采用位示图管理。

问至少需要多少字节？

$$
B=\left\lceil\frac{10000}{8}\right\rceil
$$

$$
\boxed{1250\text{ B}}
$$

如果编号从 0 开始，问块号 9999 位于哪个字节？

$$
\left\lfloor\frac{9999}{8}\right\rfloor=1249
$$

位序号：

$$
9999\bmod8=7
$$

所以：

- 字节下标 1249。
- 位序号 7。

前提是每个字节按 bit0～bit7 对应连续块号。

### 综合题 5：SPOOLing

某系统有一台独占打印机。

三个进程 P1、P2、P3 同时提交打印任务。

问：

1. 这三个进程是否能同时提交任务？
2. 打印机是否能同时实际打印三份任务？
3. 谁负责输出井与打印机之间的传送？
4. 该技术主要属于哪一层 I/O 软件？

答案：

1. 可以通过 SPOOLing 并发提交任务。
2. 一台传统独占打印机通常仍然逐个执行实际打印任务。
3. 操作系统后台输出进程。
4. 设备独立性软件。

### 综合题 6：格式化与系统引导

一台采用传统 BIOS/MBR 模式的计算机已经完成磁盘分区，但尚未逻辑格式化。

问：

1. 是否已经建立文件系统根目录？
2. 能否直接通过正常文件系统路径保存文件？
3. 根目录由什么操作创建？
4. 安装系统后，是否只要内核文件存在就必然能够引导？

答案：

1. 没有。
2. 尚不能通过未建立的文件系统正常按路径保存文件。
3. 逻辑格式化。
4. 不一定，还必须具备有效的引导代码、引导配置和加载过程。

## 十六、408 考场最容易犯的 15 个错误

| 错误理解              | 正确结论                     |
| ----------------- | ------------------------ |
| DMA 完全不需要 CPU     | CPU 仍需初始化和完成处理           |
| 中断方式 CPU 完全不搬数据   | 经典中断驱动方式仍由 CPU 参与搬运      |
| 程序查询不需要设备驱动       | 查询也需要设备控制软件              |
| 设备控制器就是驱动程序       | 控制器是硬件，驱动是软件             |
| 库函数等于系统调用         | 用户态库函数不一定立即陷入内核          |
| 驱动程序提供统一设备接口      | 统一抽象主要属于设备独立性软件          |
| Buffer 与 Cache 相同 | Buffer 重速度匹配，Cache 重数据复用 |
| 双缓冲一定使效率翻倍        | 效率取决于流水阶段瓶颈              |
| 循环缓冲容量无限          | 容量仍然有限                   |
| SPOOLing 增加物理设备数量 | 增加的是逻辑共享能力               |
| 逻辑格式化负责磁盘分区       | 分区与逻辑格式化是不同操作            |
| SSTF 只要排序一次       | 每完成一个请求都要重新选最近者          |
| SCAN 一定等于 LOOK    | 严格 SCAN 要走到物理边界          |
| C-SCAN 回绕不算距离     | 实际移动距离通常需要计入             |
| SSD 不需要任何 I/O 调度  | 只是不需要优化机械磁头寻道            |

## 十七、最后建立一套统一解题方法

<Steps>

<Step>

    ### 识别考点和设备模型

    判断属于 I/O 控制、软件层次、缓冲区、磁盘地址、调度还是访问时间；区分 HDD 与 SSD。

</Step>

<Step>

    ### 固定题目约束

    写清缓冲数、复制/处理能否重叠、磁头初始方向、磁道上下界、请求序列及缓存假设。

</Step>

<Step>

    ### 画流程或时间轴并计算

    控制方式画数据传送路径，缓冲题画流水时间轴，磁盘调度题画服务路径；最后检查单位与边界。

</Step>

</Steps>

遇到本章题目，可以按以下思路迅速判断。

第一类：软件层次题

先找关键词。

```text
格式化输入输出 → 用户层 I/O 软件

统一接口、逻辑设备 → 设备独立性软件

寄存器、具体硬件命令 → 设备驱动程序

完成通知、中断响应 → 中断处理程序
```

第二类：控制方式题

问三个问题：

```text
CPU 是否持续忙等？
数据是否经过 CPU 逐字搬运？
完成后由谁通知？
```

对应：

```text
查询：CPU 主动等

中断：设备找 CPU

DMA：硬件搬数据，CPU 管首尾
```

第三类：缓冲计算题

先判断：

```text
有几个缓冲区？
输入能否与处理重叠？
复制是否占用缓冲区？
需要处理多少块？
```

然后画时间轴，再套公式。

第四类：磁盘地址计算题

先算：

$$
\text{每柱面扇区数}
$$

再逐级：

$$
\boxed{\text{整除确定上层编号，取余确定下层偏移}}
$$

第五类：磁盘调度题

先写明：

```text
当前磁头位置
请求队列
移动方向
磁道范围
算法定义
```

然后画完整路径：

$$
x_0\rightarrow x_1\rightarrow\cdots\rightarrow x_n
$$

最后求：

$$
\boxed{D=\sum|x_i-x_{i-1}|}
$$

第六类：磁盘访问时间题

分开算：

$$
\boxed{ T=T_{\text{seek}}+T_{\text{rotation}}+T_{\text{transfer}} }
$$

不要把磁头移动距离与旋转等待混成一个量。
