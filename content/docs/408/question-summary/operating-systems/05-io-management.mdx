<Tab value="缓冲流水">

在教材经典三阶段模型中，设设备输入用时 $T$、缓冲区到工作区复制用时 $M$、CPU 处理用时 $C$，处理 $n\ge1$ 块：

$$
\begin{aligned}
T_{\text{single}}&=T+M+(n-1)[\max(T,C)+M]+C,\\
T_{\text{double}}&=T+(n-1)\max(T,M+C)+M+C.
\end{aligned}
$$

**两式仅适用于对应缓冲可并行关系的经典模型**，不能把稳态周期直接乘以块数而漏算首末阶段。

</Tab>
<Tab value="磁盘容量">

经典等密度简化 CHS 模型：柱面数 $C_y$、每柱面磁道数 $H$、每磁道扇区数 $S$、每扇区 $B$ 字节，则

$$
V=C_yHSB.
$$

现代硬盘往往采用 LBA 和区带记录，物理扇区数并非所有磁道都相同；做题按指定模型计算。

</Tab>
<Tab value="访问时间">

经典平均磁盘访问时间：

$$
T_a=T_s+T_r+T_t,\qquad T_r=\frac{1}{2r},\quad T_t=\frac{b}{rN}.
$$

其中 $r$ 为转/秒，$N$ 为每磁道的字节数，$b$ 为连续读写字节数；随机扇区、无缓存、忽略控制器开销为常见默认简化前提。

</Tab>
<Tab value="调度路线">

FCFS 按到达顺序，SSTF 选当前最近；SCAN 到物理端点折返，LOOK 到该方向最后请求折返；C-SCAN 到端点后回绕，C-LOOK 在两端请求间回绕。求**服务顺序**和求**总移动距离**是两道不同的运算，尤其不能漏加回绕。

</Tab>

## 第一部分：5.1 I/O 管理概述

## 二、先理解：操作系统为什么需要 I/O 管理？

CPU 可以直接执行指令、访问内存，但计算机必须和外部世界交换数据。

例如：

- 键盘输入字符。
- 鼠标产生事件。
- 磁盘读取文件。
- 打印机输出文档。
- 网卡接收网络数据。

这些设备有一个共同特点：它们的速度、数据格式、控制方法差异非常大。

假如没有操作系统，每个应用程序都必须知道：

- 外设控制寄存器的地址。
- 设备支持哪些命令。
- 如何读取设备状态。
- 如何处理中断。
- 如何检查设备是否被占用。

这会导致应用程序严重依赖具体硬件。

因此，操作系统 I/O 管理主要解决四个问题：

第一，设备抽象。

把各种不同设备包装成统一的访问接口。

第二，设备控制。

负责启动设备、传输数据、处理中断。

第三，资源分配。

多个进程需要同一设备时，决定谁先使用。

第四，性能优化。

通过 DMA、缓冲、缓存和磁盘调度减少等待时间。

#### 一次 I/O 请求的完整过程

假设程序执行：

```text
read(fd, buf, 4096);
```

完整过程可以简化为：

```text
用户程序
   │
   │ read()
   ▼
系统调用入口
   │
   ▼
设备独立性软件
   │
   │ 检查参数
   │ 查找目标设备
   │ 管理缓冲区
   ▼
设备驱动程序
   │
   │ 构造具体设备命令
   │ 配置DMA
   ▼
设备控制器
   │
   ▼
物理设备执行I/O
   │
   │ 数据传输完成
   ▼
产生中断
   │
   ▼
中断处理程序
   │
   │ 确认完成
   │ 唤醒等待进程
   ▼
进程继续执行
```

这里有一个贯穿本章的重要思想：

用户程序不直接控制硬件，而是由操作系统通过软件层次管理硬件。

## 三、I/O 设备分类

### 3.1 按数据交换单位分类

| 比较项目   | 块设备     | 字符设备         |
| ------ | ------- | ------------ |
| 基本交换单位 | 数据块     | 字符或字节        |
| 随机访问   | 通常支持    | 通常不支持        |
| 典型设备   | HDD、SSD | 键盘、鼠标、串口、打印机 |
| 常用方式   | DMA     | 中断           |
| 接口特点   | 按块寻址    | 顺序数据流        |

为什么磁盘是块设备？

假设磁盘包含：

```text
Block 0
Block 1
Block 2
...
Block 9999
```

程序可以直接请求：

```text
读取 Block 500
```

不需要从 Block 0 一直读到 Block 500。

而键盘输入是：

```text
A → B → C → D
```

用户不能任意寻址过去某一次按键。

所以键盘属于字符设备。

注意，块设备支持随机访问，并不代表随机访问成本一定很低。机械磁盘的随机访问仍存在寻道和旋转等待。

### 3.2 按资源共享属性分类

| 类型   | 特点              | 例子             |
| ---- | --------------- | -------------- |
| 独占设备 | 同一时刻只能由一个进程独占使用 | 传统打印机          |
| 共享设备 | 多个进程可通过调度共享     | 磁盘             |
| 虚拟设备 | 通过软件模拟多台逻辑设备    | SPOOLing 虚拟打印机 |

特别容易出题的是：

> SPOOLing 技术可以将独占设备改造成逻辑上可共享的虚拟设备。

它并没有凭空制造多台物理打印机。

## 四、设备控制器与 I/O 端口

### 4.1 为什么需要设备控制器？

CPU 和外设之间不能直接使用同一种控制方式。

设备控制器负责：

- 接收 CPU 命令。
- 控制设备动作。
- 报告设备状态。
- 交换数据。
- 缓冲数据。
- 进行错误检测。

结构如下：

```text
             CPU
              │
        系统总线
              │
              ▼
        设备控制器
     ┌────────────────┐
     │ CPU接口        │
     │                │
     │ 控制逻辑       │
     │                │
     │ 数据寄存器     │
     │ 状态寄存器     │
     │ 控制寄存器     │
     └────────────────┘
              │
              ▼
           I/O设备
```

必须区分：

设备控制器是硬件，设备驱动程序是软件。

设备驱动程序通过操作设备控制器来控制物理设备。

### 4.2 三种重要寄存器

| 寄存器   | 作用              |
| ----- | --------------- |
| 数据寄存器 | 保存正在交换的数据       |
| 状态寄存器 | 保存忙、就绪、完成、错误等状态 |
| 控制寄存器 | 接收 CPU 下达的操作命令  |

例如程序查询方式：

```text
while ((STATUS & READY) == 0) {
    // 等待
}

data = DATA_REGISTER;
```

CPU 反复检查的就是设备控制器的状态寄存器。

### 4.3 I/O 端口编址

这是操作系统与计算机组成原理的交叉考点。

| 对比   | 独立编址           | 统一编址         |
| ---- | -------------- | ------------ |
| 又称   | I/O 映射 I/O     | 存储器映射 I/O    |
| 地址空间 | I/O 与内存分离      | I/O 占用统一地址空间 |
| 指令   | 通常需要专门的 I/O 指令 | 可使用普通访存指令    |
| 典型指令 | IN、OUT         | LOAD、STORE   |
| 特点   | 地址空间分离         | 编程方式相对统一     |

例如独立编址：

```text
IN AL, 60H
```

统一编址：

```text
LOAD R1, [DEVICE_ADDR]
```

考试看到“I/O 端口可以使用普通访存指令访问”，通常对应统一编址。

但统一编址并不意味着设备寄存器可以当作普通可缓存内存任意访问；实际硬件仍需要特殊的访问属性和顺序约束。

## 五、★★★★★ 四种 I/O 控制方式

这是全章核心中的核心。

四种方式的发展目标是：

> 减少 CPU 在 I/O 操作中的干预，提高 CPU 和外设的并行工作能力。

### 5.1 程序直接控制方式（轮询）

又称程序查询方式。

执行过程：

```text
CPU发出I/O命令
      │
      ▼
查询设备状态
      │
      ▼
设备准备好了吗？
   ┌──┴──┐
   │     │
   否    是
   │     │
继续查询 读取数据
         │
         ▼
     CPU搬运数据
         │
         ▼
       完成
```

最大缺点是忙等待。

例如键盘 100ms 后才有数据，CPU 可能在这 100ms 内反复检查设备状态。

轮询不一定在所有场景下都低效。极短等待或某些嵌入式场景可能适合轮询，但传统考研模型强调它会浪费 CPU 时间。

关键特征：CPU 等设备，CPU 搬数据。

### 5.2 中断驱动方式

为了避免忙等待，操作系统允许 CPU 在设备工作期间运行其他任务。

```text
CPU启动I/O
     │
     ▼
当前进程等待I/O
     │
     ▼
CPU运行其他进程
     │
     │
设备完成操作
     │
     ▼
设备产生中断
     │
     ▼
CPU执行中断处理
     │
     ▼
唤醒等待进程
```

中断驱动的优势：

- CPU 不需要持续查询设备。
- 可以与设备并行工作。
- 适合中低速设备及异步事件。

但是在经典的中断驱动 I/O 模型中，CPU 仍需参与数据搬运。

例如：

```text
设备控制器
     ↓
CPU寄存器
     ↓
主存
```

如果每传输一个字都需要 CPU 参与，那么大量数据传输仍有较大开销。

#### 高频考点：中断后进程状态如何变化？

假设进程 P 请求磁盘数据：

```text
P：运行
   ↓
发出阻塞式I/O
   ↓
P：阻塞
   ↓
设备完成并触发中断
   ↓
中断处理程序确认完成
   ↓
P：就绪
   ↓
等待CPU调度
   ↓
P：运行
```

最重要的是：

$$
\boxed{\text{阻塞态}\longrightarrow\text{就绪态}}
$$

而不是直接进入运行态。

因为设备完成只是使进程具备继续执行的条件，能否立刻运行还取决于 CPU 调度。

### 5.3 DMA：直接存储器存取

DMA 的全称是 Direct Memory Access。

它进一步解决的问题是：

> 既然 CPU 不需要一直等待设备，能不能连数据搬运工作也交给专门硬件？

答案就是 DMA 控制器。

传统中断驱动：

```text
设备 → CPU寄存器 → 内存
```

DMA：

```text
设备 ←→ DMA控制器 ←→ 主存
                │
                │ 完成后发中断
                ▼
               CPU
```

CPU 主要负责启动传输、配置参数和完成处理，而不再逐字搬运整块数据。

#### DMA 控制器的主要寄存器

| 寄存器 | 含义       |
| --- | -------- |
| CR  | 命令或状态寄存器 |
| MAR | 主存地址寄存器  |
| DR  | 数据寄存器    |
| DC  | 数据计数器    |

例如要把 4096B 数据写入内存地址 `0x100000`。

CPU 设置：

```text
MAR = 0x100000
DC  = 4096
CR  = READ
```

然后启动设备。

DMA 控制器执行数据传输，完成后通知 CPU。

#### DMA 的完整执行顺序

这是 2017 年 408 真题考过的内容。

1. CPU 初始化 DMA 控制器，并启动 I/O 设备。
2. DMA 控制器直接在设备和主存之间传输数据。
3. 传输结束，DMA 控制器发出中断请求。
4. CPU 执行 DMA 完成中断服务程序。

因此：

$$
\boxed{②\rightarrow③\rightarrow①\rightarrow④}
$$

对应原真题答案 B。

最容易错的是：DMA 并非完全不需要 CPU，也不是完全没有中断。

它只是让 CPU 不必承担整个数据块的逐字搬运工作。

另外，DMA 会访问主存，可能与 CPU 竞争内存总线带宽。实际系统还需要处理 DMA 缓冲区地址映射及缓存一致性等问题。

### 5.4 通道控制方式

通道可以理解为专门执行 I/O 程序的处理机。

相比 DMA，通道的独立性更强。

DMA 通常由 CPU 配置一次或一组数据传输参数，而通道可以执行通道程序，完成多个 I/O 操作。

```text
CPU
 │
 │ 提交通道程序
 ▼
通道处理机
 │
 ├─ 控制设备A
 ├─ 控制设备B
 └─ 控制设备C
 │
 ▼
I/O完成
 │
 ▼
中断通知CPU
```

通道同样不是通用 CPU，而是专门负责 I/O 工作的控制部件。

#### 四种方式完整对比

| 项目           | 程序查询 | 中断驱动   | DMA     | 通道        |
| ------------ | ---- | ------ | ------- | --------- |
| CPU 是否忙等     | 通常是  | 否      | 否       | 否         |
| CPU 是否逐字搬运数据 | 是    | 经典模型中是 | 否       | 否         |
| 典型传输单位       | 字/字节 | 字/字节   | 数据块     | 一组 I/O 操作 |
| CPU 干预频率     | 高    | 较高     | 较低      | 更低        |
| 额外硬件         | 较少   | 中断机构   | DMA 控制器 | 通道处理机     |
| 典型场景         | 简单设备 | 中低速设备  | 大块高速传输  | 复杂 I/O 系统 |

记忆方法：

程序查询：CPU 等、CPU 搬。

中断驱动：CPU 不等、CPU 还要搬。

DMA：CPU 不等、数据块也不用 CPU 搬。

通道：CPU 把一系列 I/O 控制任务交出去。

#### 相关真题

2017 年：DMA 执行顺序

答案是初始化 DMA → 传输数据 → 发出完成中断 → 执行中断处理。

2022 年：设备驱动程序是否与 I/O 控制方式无关？

答案：错误。

设备驱动程序必须依据具体设备采用的轮询、中断、DMA 等方式执行操作。

模拟题：DMA 是否完全由硬件执行，不需要操作系统？

答案：错误。

操作系统仍然需要进行设备管理、缓冲区准备、初始化和完成处理。

## 六、★★★★★ I/O 软件层次结构

408 常用的四层结构为：

```text
┌───────────────────────┐
│ 用户层 I/O 软件       │
├───────────────────────┤
│ 设备独立性软件        │
├───────────────────────┤
│ 设备驱动程序          │
├───────────────────────┤
│ 中断处理程序          │
├───────────────────────┤
│ I/O硬件               │
└───────────────────────┘
```

注意，这是教材用于说明职责分工的经典层次模型。实际系统中，驱动程序与中断处理程序并非只能严格上下级调用，二者通常配合工作。

### 6.1 用户层 I/O 软件

最接近应用程序。

例如：

```text
printf();
scanf();
fread();
fwrite();
```

这些属于用户层常见的 I/O 库函数。

它们根据需要调用：

```text
read();
write();
```

等系统调用进入内核。

### 6.2 设备独立性软件

也叫设备无关软件。

负责所有设备都需要的公共管理功能。

例如：

- 设备统一命名。
- 设备访问权限检查。
- 设备分配和回收。
- 逻辑设备与物理设备映射。
- 缓冲管理。
- 通用差错处理。

其核心是屏蔽硬件差异。

### 6.3 设备驱动程序

设备驱动程序负责把抽象请求转换成具体设备操作。

例如：

```text
上层请求：
读取逻辑块100
```

磁盘驱动程序需要：

```text
构造设备命令
配置控制器
提交读取请求
处理设备状态
```

因此驱动程序与具体设备硬件密切相关。

### 6.4 中断处理程序

主要负责响应中断事件。

例如：

```text
磁盘读取完成
    ↓
设备产生中断
    ↓
执行中断处理程序
    ↓
读取或确认设备状态
    ↓
完成必要的结束处理
    ↓
通知驱动程序或唤醒等待进程
```

#### 谁负责什么？高频对比

| 功能            | 主要负责者   |
| ------------- | ------- |
| 调用 `printf()` | 用户层软件   |
| 统一命名和设备权限     | 设备独立性软件 |
| 逻辑设备与物理设备映射   | 设备独立性软件 |
| 设置设备控制器参数     | 设备驱动程序  |
| 构造具体磁盘 I/O 命令 | 设备驱动程序  |
| 处理设备完成中断      | 中断处理程序  |
| 执行实际设备命令      | 硬件控制器   |

### 6.5 结合历年真题理解

2010 年真题：用户通过键盘登录时，谁首先获得键盘输入信息？

答案：中断处理程序。

原因是键盘按键首先引发硬件事件，CPU 响应键盘中断后，由相关中断处理代码取得并处理输入信息。

2011 年真题：用户程序发出磁盘 I/O 请求后的处理流程是什么？

正确流程：

$$
\boxed{ \text{用户程序} \rightarrow \text{系统调用处理程序} \rightarrow \text{设备驱动程序} \rightarrow \text{中断处理程序} }
$$

答案 B。

注意：中断处理程序通常在设备完成或产生相关事件后运行，不能把它安排在设备驱动程序启动操作之前。

2012 年真题：四层 I/O 软件的合理排列顺序是什么？

$$
\boxed{ \text{用户层} \rightarrow \text{设备独立层} \rightarrow \text{驱动层} \rightarrow \text{中断处理层} }
$$

答案 A。

2013 年真题：谁计算数据所在磁盘的柱面号、磁头号和扇区号？

按照真题使用的经典磁盘抽象模型，答案是：

设备驱动程序。

因为这类转换需要知道设备结构和控制方式。

现实磁盘广泛使用 LBA，部分物理映射由控制器固件完成；考试应按题目给定的设备模型作答。

## 七、中断处理中的硬件工作与软件工作

这是一个容易被忽视的细节。

中断发生后，并不是所有操作都由操作系统完成。

| 工作           | 典型执行主体       |
| ------------ | ------------ |
| 保存中断点等必要现场信息 | 硬件自动完成       |
| 转入中断入口       | 硬件配合系统完成     |
| 保存其余通用寄存器现场  | 中断入口代码       |
| 执行中断服务       | 操作系统         |
| 初始化中断向量表     | 操作系统初始化代码    |
| 保存或恢复中断屏蔽状态  | 硬件与系统软件按架构分工 |
| 唤醒等待 I/O 的进程 | 操作系统         |

2020 年 408 真题

题目询问：

I. 保存被中断程序的中断点

II. 提供中断服务

III. 初始化中断向量表

IV. 保存中断屏蔽字

按该题的经典教学模型：

- I：硬件完成。
- II：操作系统完成。
- III：操作系统完成。
- IV：操作系统完成。

因此答案为 D，仅 II、III、IV。

这类题应注意区分“硬件自动压栈”和“系统软件保存完整现场”，不要笼统认为所有现场保存都由硬件完成。

## 八、★★★★★ 缓冲技术

### 8.1 为什么需要缓冲？

假设磁盘每 100ms 产生一个数据块，而 CPU 处理一个数据块只需要 20ms。

如果完全串行：

```text
磁盘读块1：100ms
CPU处理1： 20ms

磁盘读块2：100ms
CPU处理2： 20ms
```

两个块一共：

$$
2(100+20)=240\text{ms}
$$

这种处理方式浪费了大量可以并行的时间。

如果使用缓冲：

```text
时间 →
磁盘：读取块1 ─── 读取块2 ───
CPU：           处理块1 ─── 处理块2
```

CPU 处理块 1 时，磁盘就可以读取块 2。

这就是缓冲技术的基本思想。

缓冲的主要作用有：

1. 缓和 CPU 与 I/O 设备之间的速度差异。
2. 减少 CPU 中断或设备启动的频率。
3. 解决数据传输单位不匹配的问题。
4. 提高 CPU 与 I/O 设备的并行程度。

缓冲区一般设置在主存中。

### 8.2 先统一三个时间符号

后面所有计算题都用：

| 符号      | 含义                       |
| ------- | ------------------------ |
| $T$ | 设备将一个数据块读入系统缓冲区的时间       |
| $M$ | 系统缓冲区向用户工作区传送一个数据块的时间    |
| $C$ | CPU 对用户工作区中的一个数据块进行处理的时间 |

基本路径：

```text
磁盘
 │
 │ T
 ▼
系统缓冲区
 │
 │ M
 ▼
用户工作区
 │
 │ C
 ▼
CPU处理完成
```

一定注意：

$T$、$M$、$C$ 是三个不同阶段，不能不加分析就直接相加。

核心是判断哪些阶段可以并行。

### 8.3 单缓冲

只有一个系统缓冲区。

```text
             T            M          C
磁盘 ────────→ Buffer ─────→ 用户区 ─────→ CPU
```

对于连续数据块：

- 设备读取下一块，可以和 CPU 处理上一块并行。
- 但系统缓冲区向用户工作区复制数据时，缓冲区不能同时接收新的一整块数据。

例如：

$$
T=100,\quad M=10,\quad C=60
$$

进入稳定流水后，一块数据对应的周期是：

$$
\boxed{P_1=\max(T,C)+M}
$$

代入：

$$
P_1=\max(100,60)+10=110
$$

为什么不是：

$$
100+10+60=170
$$

因为设备读入下一块与 CPU 处理上一块可以重叠。

#### 单缓冲的时间关系

```text
读取块1：   [======= T =======]
复制块1：                    [M]
处理块1：                      [==== C ====]

读取块2：                      [======= T =======]
复制块2：                                       [M]
处理块2：                                         [==== C ====]
```

图中只是表示重叠关系，不代表所有阶段严格按比例绘制。

需要记住：

$$
\boxed{\text{单缓冲稳定周期}=\max(T,C)+M}
$$

#### 单缓冲处理 $n$ 块的总时间

在经典单设备、单用户工作区、复制过程独占系统缓冲区的模型下：

$$
\boxed{ T_{\text{single}} = T+M+(n-1)[\max(T,C)+M]+C }
$$

整理得到：

$$
\boxed{ T_{\text{single}} = T+C+nM+(n-1)\max(T,C) }
$$

这个公式同时考虑了：

- 第一块的读入。
- 中间流水阶段。
- 最后一块的 CPU 处理。

因此做有限块数计算题时，不能直接用稳定周期乘以 $n$。

## 九、★★★★★ 双缓冲

双缓冲设置两个系统缓冲区。

```text
              ┌──── Buffer A ────┐
磁盘 ──────────┤                  ├──── 用户区 → CPU
              └──── Buffer B ────┘
```

当 CPU 正在处理 Buffer A 对应的数据时，设备可以向 Buffer B 输入下一块数据。

两个缓冲区交替使用。

在经典模型中：

$$
T
$$

可以与：

$$
M+C
$$

整体重叠。

因此双缓冲稳定周期为：

$$
\boxed{ P_2=\max(T,M+C) }
$$

这和单缓冲的区别非常重要。

单缓冲：

$$
\boxed{P_1=\max(T,C)+M}
$$

双缓冲：

$$
\boxed{P_2=\max(T,M+C)}
$$

<Callout type="warn" title="缓冲计算：先画时序，再选模型">

单/双缓冲公式依赖复制阶段 $M$ 是否阻止设备向同一缓冲继续写入、CPU 处理 $C$ 是否在独立工作区进行，以及两个缓冲是否能交替使用。若条件不符，不能照套教材公式；任何 $n=1$ 的模型都应退化为 $T+M+C$。

</Callout>

### 双缓冲处理 $n$ 块

总时间：

$$
\boxed{ T_{\text{double}} = T+(n-1)\max(T,M+C)+M+C }
$$

这也是经典流水模型下的结果。

对于 $n=1$，两种缓冲的总时间都为：

$$
T+M+C
$$

因为只有一块数据，没有后续数据可用于形成流水。

双缓冲并不是让每个阶段本身变快，而是让多个阶段尽可能重叠。

## 十、2011 年 408 真题：单缓冲与双缓冲

这是整个章节最经典的缓冲计算题之一。

### 题目

一个文件有 10 个磁盘块，逐块读入并分析。

已知：

$$
T=100\mu s
$$

$$
M=50\mu s
$$

$$
C=50\mu s
$$

求单缓冲和双缓冲分别需要多少时间。

#### 第一步：计算单缓冲

稳定周期：

$$
P_1=\max(100,50)+50=150\mu s
$$

处理 10 块：

$$
T_{\text{single}} = 100+50+9\times150+50
$$

$$
\boxed{T_{\text{single}}=1550\mu s}
$$

#### 第二步：计算双缓冲

稳定周期：

$$
P_2=\max(100,50+50)=100\mu s
$$

总时间：

$$
T_{\text{double}} = 100+9\times100+50+50
$$

$$
\boxed{T_{\text{double}}=1100\mu s}
$$

因此原题答案为 B。

#### 第三步：理解为什么少了 450μs

单缓冲每块的稳定周期是：

$$
150\mu s
$$

双缓冲每块的稳定周期是：

$$
100\mu s
$$

对于 10 块，双缓冲节省：

$$
1550-1100=450\mu s
$$

节省比例：

$$
\frac{450}{1550}\times100\% \approx29.03\%
$$

这说明双缓冲能够通过并行显著缩短总完成时间。

但双缓冲并不能无限提高性能。

如果设备读取远远慢于处理速度：

$$
T\gg M+C
$$

双缓冲最终也要受限于设备输入速度。

## 十一、2013 年 408 真题：两个数据块的最短时间

题设：

$$
T=100,\quad M=5,\quad C=90
$$

只有 2 个数据块。

使用单缓冲。

#### 第一步：读取第一个数据块

$$
100
$$

#### 第二步：复制到用户工作区

$$
5
$$

此时累计：

$$
105
$$

#### 第三步：同时处理块 1、读取块 2

CPU 处理块 1：

$$
90
$$

设备读入块 2：

$$
100
$$

这两个阶段重叠。

所以经过：

$$
\max(100,90)=100
$$

#### 第四步：复制和处理第二块

$$
5+90=95
$$

最终：

$$
T_{\text{total}} = 100+5+100+5+90
$$

$$
\boxed{T_{\text{total}}=300}
$$

答案 C。

#### 从这道题学到什么？

必须考虑流水线的启动和结束时间。

直接使用：

$$
2[\max(T,C)+M]
$$

会得到：

$$
210
$$

这是错误的。

因为该式是两个稳定周期的长度，不是从第一块开始读入到第二块处理完成的总时间。

## 十二、模拟题：双缓冲 10 块数据

原稿所列模拟题给出：

$$
T=100ns
$$

$$
M=5ns
$$

$$
C=90ns
$$

需要处理 10 块。

双缓冲周期：

$$
P_2=\max(100,5+90)
$$

$$
P_2=100ns
$$

总时间：

$$
T_{\text{double}} = 100+9\times100+5+90
$$

$$
\boxed{T_{\text{double}}=1095ns}
$$

答案 C。

#### 缓冲计算万能模板

对于经典单缓冲、双缓冲模型：

| 类型  | 稳定周期              | $n$ 块总时间                   |
| --- | ----------------- | ------------------------------ |
| 单缓冲 | $\max(T,C)+M$ | $T+M+(n-1)[\max(T,C)+M]+C$ |
| 双缓冲 | $\max(T,M+C)$ | $T+(n-1)\max(T,M+C)+M+C$   |

考试步骤：

1. 写清楚 $T,M,C$。
2. 判断单缓冲还是双缓冲。
3. 找出能够并行的阶段。
4. 计算稳定周期。
5. 加上首块启动与末块处理的开销。

若题目允许复制与其他操作并行，或者工作区、DMA 资源的使用规则不同，则应重新画时序图，不能机械套公式。

## 十三、循环缓冲与缓冲池

### 13.1 循环缓冲

设置多个缓冲区并循环使用：

```text
Buffer1 → Buffer2 → Buffer3 → Buffer4
   ↑                            │
   └────────────────────────────┘
```

通过输入指针和输出指针管理。

特别适合生产者和消费者速度不完全相同的场景。

例如：

- 网络数据接收。
- 音频流处理。
- 连续传感器数据。
- 数据采集系统。

### 13.2 缓冲池

缓冲池是操作系统统一管理的一组缓冲区。

经典模型通常有三个队列：

```text
┌─────────────────┐
│ 空缓冲队列      │
├─────────────────┤
│ 输入队列        │
├─────────────────┤
│ 输出队列        │
└─────────────────┘
```

四种典型工作缓冲区：

| 类型     | 含义   |
| ------ | ---- |
| `hin`  | 收容输入 |
| `sin`  | 提取输入 |
| `hout` | 收容输出 |
| `sout` | 提取输出 |

比如输入过程：

```text
空缓冲队列
    ↓
取出空缓冲区
    ↓
设备写入数据
    ↓
放入输入队列
    ↓
进程获取数据
    ↓
缓冲区重新变为空闲
```

模拟题曾直接问：

> 哪个不属于缓冲池的组成队列？

选项：

A. 空缓冲队列

B. 输入队列

C. 输出队列

D. 循环缓冲

答案 D。

因为循环缓冲是一种独立的缓冲组织方式，不是缓冲池的三个基本队列之一。

## 十四、★★★★★ Buffer 与 Cache 的区别

这是高频概念辨析题。

| 对比    | Buffer（缓冲）     | Cache（缓存）    |
| ----- | -------------- | ------------ |
| 核心目的  | 缓和速度差异、解耦生产和消费 | 减少重复访问慢设备    |
| 主要依据  | 流水处理和速率匹配      | 时间局部性、空间局部性  |
| 保存的数据 | 正在交换的中间数据      | 可能再次使用的数据副本  |
| 核心收益  | 提高并行性          | 提高命中率，减少慢速访问 |

举例：

#### Buffer

磁盘每次产生大量数据，而应用每次只处理一部分。

先把数据存入缓冲区：

```text
磁盘 → Buffer → 应用程序
```

设备和应用程序不需要始终保持相同速度。

#### Cache

程序反复读取文件同一部分。

第一次：

```text
磁盘 → 内存中的磁盘缓存 → 应用
```

第二次：

```text
磁盘缓存 → 应用
```

第二次可能根本不需要访问磁盘。

所以：

缓冲重点解决速度匹配，缓存重点解决重复访问。

不过现实系统中，同一块内存区域可能同时承担缓冲和缓存功能，因此二者并非物理上完全隔离。

### 14.1 磁盘高速缓存放在哪里？

考试通常回答：

主存。

不是 CPU 与内存之间的 L1/L2/L3 Cache，也不是必须在磁盘内部。

磁盘内部也可能有硬件缓存，但操作系统章节所说的磁盘高速缓存通常指利用主存缓存磁盘块。

### 14.2 预读与延迟写

#### 预读（Read-ahead）

操作系统预测未来需要的数据，提前读取。

例如顺序读取：

```text
Block 100
Block 101
Block 102
Block 103
```

当读取 Block 100 时，可以提前把 101、102 读入缓存。

适合顺序访问、规律访问。

但随机访问并不意味着绝对不可能预读，只是预测更困难。

#### 延迟写（Write-behind）

进程修改数据后，先保存在缓存中。

```text
用户写数据
    ↓
修改缓存
    ↓
标记为脏
    ↓
稍后写入磁盘
```

优点：

- 合并多次写操作。
- 降低写入次数。
- 减少应用程序同步等待。

缺点：

如果数据尚未持久化时系统突然断电，可能丢失最近的修改。

因此不能把“写入缓存成功”直接等同于“已经持久化到磁盘”。

## 十五、★★★★★ 设备分配与回收

多个进程可能同时申请设备。

例如：

```text
P1申请打印机
P2申请打印机
P3申请磁盘
P4申请打印机
```

操作系统必须管理设备的分配、等待和释放。

### 15.1 设备分配需要考虑什么？

2023 年 408 真题直接考过。

四个因素：

I. 设备类型

II. 访问权限

III. 占用状态

IV. 逻辑设备与物理设备的映射关系

答案：

$$
\boxed{\text{I、II、III、IV}}
$$

即 D。

原因：

设备分配不能只看设备是否空闲，还必须检查设备类型、权限和映射关系。

### 15.2 四种管理表

| 缩写   | 英文                       | 中文     | 主要记录         |
| ---- | ------------------------ | ------ | ------------ |
| SDT  | System Device Table      | 系统设备表  | 全系统设备信息      |
| DCT  | Device Control Table     | 设备控制表  | 某台设备的状态和等待队列 |
| COCT | Controller Control Table | 控制器控制表 | 控制器状态        |
| CHCT | Channel Control Table    | 通道控制表  | 通道状态         |

经典设备分配顺序：

$$
\boxed{ SDT\rightarrow DCT\rightarrow COCT\rightarrow CHCT }
$$

即：

```text
查询系统设备表
       ↓
找到目标设备
       ↓
检查设备控制表
       ↓
检查控制器控制表
       ↓
检查通道控制表
       ↓
完成资源分配
```

为什么要检查控制器和通道？

因为设备本身即使空闲，其所属控制器或通道也可能正在被其他设备占用。

设备和设备控制器不是完全独立的资源。

#### 设备分配策略

常见策略包括：

- FCFS：先申请先分配。
- 优先级优先：优先处理高优先级请求。

设备分配也可能涉及死锁。

例如：

```text
P1占用设备A，等待设备B
P2占用设备B，等待设备A
```

形成循环等待。

教材通常区分：

安全分配：进程发出 I/O 请求后阻塞等待，限制继续申请其他设备的机会，从而降低死锁风险。

不安全分配：允许进程占有部分设备时继续申请其他设备，有更好的并行性，但可能发生死锁。

注意，这里“安全分配”是 I/O 设备分配章节的一种教学术语，不应与银行家算法中的“安全状态”完全混为一谈。

## 十六、★★★★★ 设备独立性与逻辑设备表 LUT

### 16.1 设备独立性是什么？

假设用户程序直接访问：

```text
PhysicalPrinter-3
```

打印机损坏后，程序可能无法正常使用。

更合理的方法是：

```text
应用程序
    ↓
逻辑打印机
    ↓
操作系统
    ↓
某台实际打印机
```

应用程序只关心“我要使用打印机”。

至于物理打印机是哪一台，由操作系统决定。

这就是设备独立性。

设备独立性描述的是用户程序不依赖特定物理设备，而不是设备可以完全脱离 CPU 独立工作。

### 16.2 逻辑设备表 LUT

LUT（Logical Unit Table）负责记录逻辑设备与物理设备的对应关系。

例如：

| 逻辑设备名     | 物理设备       |
| --------- | ---------- |
| Printer_A | Printer_03 |
| Printer_B | Printer_07 |
| Disk_A    | SSD_01     |

程序使用：

```text
Printer_A
```

操作系统查询 LUT 后找到：

```text
Printer_03
```

用户程序不需要知道这个映射过程。

#### 2009 年真题

程序员利用系统调用打开 I/O 设备时，通常使用什么设备标识？

A. 逻辑设备名

B. 物理设备名

C. 主设备号

D. 从设备号

答案 A。

#### 2020 年真题

更换物理设备后，是否必须修改访问该设备的应用程序？

答案：不必。

设备独立性就是为了避免用户程序依赖具体物理设备。

但如果替换成完全不兼容的设备类别，也不意味着所有应用都能无条件继续工作。

## 十七、★★★★★ SPOOLing 假脱机技术

这是全章最重要的概念考点之一。

### 17.1 为什么需要 SPOOLing？

打印机通常是典型的独占设备。

假设 P1 要打印 100 页，P2 也要打印。

传统方式：

```text
P1 ─────→ 打印机
             │
             │ 正在打印
             │
P2 ─────→ 等待
```

如果 P1 需要 10 分钟才能打印完成，P2 就得等待。

SPOOLing 的思想是：

让用户进程先把输出数据提交到磁盘，真正打印由后台进程完成。

```text
P1 ──┐
P2 ──┼──→ 输出井（磁盘）
P3 ──┘          │
                ▼
           后台输出进程
                │
                ▼
           输出缓冲区
                │
                ▼
              打印机
```

于是 P1、P2、P3 可以快速提交打印任务。

真正的物理打印机仍然一次处理一个任务，但各进程在逻辑上可以并发使用打印服务。

这就是：

$$
\boxed{ \text{独占设备} \xrightarrow{\text{SPOOLing}} \text{逻辑共享设备} }
$$

### 17.2 SPOOLing 的组成

必须记住三个部分。

| 组成          | 所在位置 | 作用           |
| ----------- | ---- | ------------ |
| 输入井、输出井     | 外存   | 暂存输入输出任务的数据  |
| 输入缓冲区、输出缓冲区 | 主存   | 缓和外设与外存之间的传输 |
| 输入进程、输出进程   | 软件   | 完成后台输入输出管理   |

#### 输入过程

```text
输入设备
    ↓
输入缓冲区（主存）
    ↓
输入井（外存）
    ↓
用户作业
```

#### 输出过程

```text
用户作业
    ↓
输出井（外存）
    ↓
输出缓冲区（主存）
    ↓
输出设备
```

#### 输入井和输入缓冲区千万别混

输入井在外存。

输入缓冲区在主存。

输出井同理。

这属于选择题很常见的陷阱。

### 17.3 SPOOLing 的核心特点

- 需要外存支持。
- 依赖多道程序并发处理。
- 通过后台输入输出程序管理实际设备。
- 可以将独占设备逻辑上虚拟为共享设备。
- 用户进程不需要长期占用真正的独占设备。

注意：

提交打印任务成功，不意味着打印机已经完成打印。

#### 2016 年 408 真题

下列有关 SPOOLing 的说法，错误的是：

A. 需要外存支持

B. 需要多道程序设计技术支持

C. 可以让多个作业共享独占设备

D. 由用户作业控制设备和输入/输出井之间的数据传送

答案 D。

因为输入/输出井与实际设备之间的数据传送主要由操作系统管理的后台输入输出程序控制。

### 17.4 SPOOLing 与设备独立性有什么区别？

| 比较        | 设备独立性        | SPOOLing    |
| --------- | ------------ | ----------- |
| 主要目标      | 屏蔽物理设备差异     | 虚拟化独占设备     |
| 核心技术      | 逻辑设备映射       | 外存井、缓冲、后台进程 |
| 是否必须使用外存井 | 不需要          | 经典实现需要      |
| 典型作用      | 更换物理设备无需修改应用 | 多个进程共享打印服务  |

一句话：

设备独立性解决“用户程序不关心具体是哪台设备”，SPOOLing 解决“多个用户如何共享一台原本独占的设备”。

## 十八、磁盘的基本结构

### 18.1 磁道、扇区、柱面

机械硬盘主要由盘片、磁头、磁臂等组成。

```text
            一个盘面

        ┌───────────────┐
        │   同心磁道    │
        │  ┌─────────┐  │
        │  │  ┌───┐  │  │
        │  │  └───┘  │  │
        │  └─────────┘  │
        └───────────────┘
```

需要掌握四个概念：

| 概念 | 含义             |
| -- | -------------- |
| 盘面 | 盘片上可用于存储数据的表面  |
| 磁道 | 盘面上的同心圆形存储区域   |
| 扇区 | 磁道划分出的数据存储单位   |
| 柱面 | 不同盘面上半径相同的一组磁道 |

最容易错的是柱面。

柱面不是单独一条磁道，而是不同盘面上相同半径的磁道集合。

例如一个硬盘有 4 个有效盘面、200 个柱面，那么一共有：

$$
4\times200=800
$$

条磁道。

### 18.2 为什么优先访问同一柱面？

假设文件有连续的两个块。

可以选择：

方案 A：

```text
柱面10、盘面0
柱面10、盘面1
```

方案 B：

```text
柱面10、盘面0
柱面11、盘面0
```

方案 A 不需要磁臂移动到另一个柱面，只需要切换磁头。

方案 B 需要寻道。

因此，在传统机械磁盘模型中：

同一柱面不同磁道之间的访问，通常比跨柱面访问更快。

实际硬盘使用 LBA、缓存和内部调度，物理布局未必对操作系统完全可见，但这一原理仍是考试中的基本模型。

## 十九、★★★★★ 磁盘容量计算

假设：

- $C$：柱面数。
- $H$：每个柱面的磁道数。
- $S$：每条磁道的扇区数。
- $B$：每个扇区的字节数。

磁盘容量：

$$
\boxed{ V=C\times H\times S\times B }
$$

#### 例题

某磁盘有：

- 200 个柱面。
- 每柱面 8 条磁道。
- 每磁道 100 个扇区。
- 每扇区 512B。

求总容量。

$$
V=200\times8\times100\times512
$$

$$
\boxed{V=81920000\text{B}}
$$

按十进制换算：

$$
81.92\text{MB}
$$

按二进制换算：

$$
78.125\text{MiB}
$$

注意 MB 与 MiB 的区别：

$$
1\text{MB}=10^6\text{B}
$$

$$
1\text{MiB}=2^{20}\text{B}
$$

在考研题中，要按题目给定的换算口径计算。

另外，该公式假设每条磁道的扇区数量相同。实际 HDD 可能采用分区位记录 ZBR，不同区域磁道容量不一定相同。

## 二十、★★★★★ 逻辑地址到物理地址的转换

这是 2019 年综合真题的重要考点。

磁盘的经典物理地址表示为：

$$
(\text{柱面号},\text{磁头号},\text{扇区号})
$$

也称 CHS 地址。

### 20.1 通用换算公式

假设：

- 每个柱面有 $H$ 条磁道。
- 每条磁道有 $S$ 个扇区。
- 扇区从 0 开始编号。
- 逻辑扇区号为 $L$。

则：

#### 柱面号

$$
\boxed{ c=\left\lfloor\frac{L}{HS}\right\rfloor }
$$

#### 磁头号

$$
\boxed{ h=\left\lfloor \frac{L\bmod(HS)}{S} \right\rfloor }
$$

#### 扇区号

$$
\boxed{s=L\bmod S}
$$

需要注意，最后的 $s$ 是从 0 开始编号的扇区号。

如果题目采用从 1 开始的扇区编号，则结果需要相应调整。

### 20.2 模拟题：5687 号逻辑记录在哪里？

原稿所列模拟题给出：

- 每柱面 12 条磁道。
- 每磁道 16 个扇区。
- 每条逻辑记录恰好占一个扇区。
- 编号全部从 0 开始。
- 从磁盘 0 号位置顺序存储。

求第 5687 号逻辑记录的物理位置。

#### 第一步：每柱面容纳多少记录？

$$
12\times16=192
$$

#### 第二步：计算柱面号

$$
5687=29\times192+119
$$

所以：

$$
c=29
$$

#### 第三步：计算磁头号

$$
119=7\times16+7
$$

所以：

$$
h=7
$$

#### 第四步：计算扇区号

$$
s=7
$$

最终：

$$
\boxed{(29,7,7)}
$$

原模拟题答案 C。

核心技巧：

先除出柱面，再对余数除出磁头，最后得到扇区。

## 二十一、2019 年 408 综合真题：磁盘容量、SSTF、地址转换

这道题非常值得完整掌握，因为它把多个知识点结合在一起。

### 21.1 已知条件

某磁盘：

- 300 个柱面。
- 每柱面 10 条磁道。
- 每磁道 200 个扇区。
- 每扇区 512B。
- 每个簇包含 2 个扇区。

要求：

1. 计算磁盘容量。
2. 使用 SSTF 调度四个簇的访问。
3. 将簇号 100530 转换为物理地址。

### 21.2 第一问：容量

直接计算：

$$
V=300\times10\times200\times512
$$

$$
\boxed{V=307200000\text{B}}
$$

也可以表示为：

$$
300000\text{KiB}
$$

### 21.3 第二问：簇号转换成柱面号

每个簇包含 2 个扇区。

每磁道簇数：

$$
\frac{200}{2}=100
$$

每柱面簇数：

$$
10\times100=1000
$$

因此：

$$
\boxed{ \text{柱面号} = \left\lfloor \frac{\text{簇号}}{1000} \right\rfloor }
$$

四个请求：

| 簇号     | 柱面号 |
| ------ | --- |
| 100260 | 100 |
| 60005  | 60  |
| 101660 | 101 |
| 110560 | 110 |

磁头当前位于 85 号柱面。

采用 SSTF。

#### 第一次选择

从 85 出发：

| 目标  | 距离 |
| --- | -- |
| 100 | 15 |
| 60  | 25 |
| 101 | 16 |
| 110 | 25 |

最近的是：

$$
100
$$

#### 第二次选择

磁头位于 100。

剩余：

$$
60,\ 101,\ 110
$$

对应距离：

$$
40,\ 1,\ 10
$$

选择：

$$
101
$$

#### 第三次选择

磁头位于 101。

剩余：

$$
60,\ 110
$$

距离：

$$
41,\ 9
$$

选择：

$$
110
$$

#### 第四次选择

最后访问：

$$
60
$$

因此柱面顺序为：

$$
85\rightarrow100\rightarrow101\rightarrow110\rightarrow60
$$

对应簇号：

$$
\boxed{ 100260\rightarrow101660\rightarrow110560\rightarrow60005 }
$$

总磁头移动距离：

$$
D=15+1+9+50
$$

$$
\boxed{D=75}
$$

#### 这里最容易犯的错误

SSTF 不是简单地把柱面号排序。

它是：

> 每完成一次访问，就以当前磁头位置为起点，重新计算所有未处理请求的距离。

因此这是一个逐步贪心选择过程。

### 21.4 第三问：100530 簇的位置

每柱面 1000 簇。

$$
100530=100\times1000+530
$$

因此柱面号：

$$
c=100
$$

柱面内剩余 530 簇。

每磁道 100 簇。

$$
530=5\times100+30
$$

因此磁头号：

$$
h=5
$$

磁道内第 30 个簇。

每簇包含 2 个扇区。

因此起始扇区：

$$
s=30\times2=60
$$

这个簇占用：

$$
60,\ 61
$$

两个扇区。

最终：

$$
\boxed{(100,5,60)}
$$

在题设模型中，执行这种具体设备地址换算的是设备驱动程序。

#### 这道题的核心能力

要能把以下知识连起来：

```text
逻辑簇号
   ↓
柱面号
   ↓
磁头号
   ↓
扇区号
   ↓
设备驱动程序
   ↓
磁盘访问调度
```

考试可能改变簇大小，也可能要求计算文件块偏移或访问多个簇，但基本思路相同。

## 二十二、★★★★★ 磁盘访问时间

磁盘访问时间通常由三部分组成：

$$
\boxed{T_a=T_s+T_r+T_t}
$$

其中：

- $T_s$：寻道时间。
- $T_r$：旋转延迟。
- $T_t$：数据传输时间。

### 22.1 寻道时间

寻道就是移动磁头到目标磁道。

如果跨越一个磁道平均需要 $m$ 秒，移动了 $n$ 个磁道：

$$
T_s\approx mn
$$

如果题目给出磁臂启动时间 $s$，可能采用：

$$
T_s=mn+s
$$

注意固定启动开销是否对每次寻道都计入，应以题目说明为准。

### 22.2 平均旋转延迟

磁头到达正确磁道后，还需要等待目标扇区旋转到磁头下面。

假设磁盘每秒转 $r$ 圈。

一圈时间：

$$
T_{\text{rev}}=\frac{1}{r}
$$

若目标扇区在圆周上均匀随机分布，平均等待半圈：

$$
\boxed{ T_r=\frac{1}{2r} }
$$

#### 例题：7200r/min

先换算：

$$
r=\frac{7200}{60}=120\text{r/s}
$$

一圈时间：

$$
T_{\text{rev}}=\frac{1}{120}\text{s}
$$

$$
T_{\text{rev}}\approx8.33\text{ms}
$$

平均旋转延迟：

$$
T_r\approx4.17\text{ms}
$$

### 22.3 传输时间

如果每条磁道有 $N$ 字节，需要连续传输 $b$ 字节：

$$
\boxed{ T_t=\frac{b}{rN} }
$$

这里假设理想连续传输，并且 $r$ 的单位是圈/秒。

如果一条磁道有 100 个扇区，那么读取一个扇区的理想传输时间就是一圈时间的 $1/100$。

### 22.4 综合例题

某磁盘：

- 转速 6000r/min。
- 每磁道 100 个扇区。
- 每扇区 512B。
- 寻道时间 8ms。

读取一个随机扇区的平均访问时间是多少？

第一步：

$$
r=\frac{6000}{60}=100\text{r/s}
$$

第二步：

$$
T_s=8\text{ms}
$$

第三步：

$$
T_r=\frac{1}{2\times100}\text{s}=5\text{ms}
$$

第四步：

$$
T_t=\frac{10}{100}=0.1\text{ms}
$$

所以：

$$
T_a=8+5+0.1
$$

$$
\boxed{T_a=13.1\text{ms}}
$$

特别注意：

计算读取多个随机扇区的总时间时，不能忘记每次访问可能产生的旋转等待。

若题目给出连续扇区访问、交错编号或确定的物理位置，则需要根据实际扇区分布分析，而不是对所有数据块一律加半圈等待。

## 二十三、★★★★★ 六种磁盘调度算法

这一部分一定要会画磁道数轴。

### 23.1 FCFS：先来先服务

按照请求到达的先后顺序访问。

例如：

```text
初始位置：100

请求顺序：
20，90，120，180
```

访问路径：

```text
100 → 20 → 90 → 120 → 180
```

总移动距离：

$$
D=80+70+30+60
$$

$$
\boxed{D=240}
$$

优点：

- 实现简单。
- 按先后次序服务。
- 不会因新来的近距离请求而饿死旧请求。

缺点：

\- 寻道距离可能较长。

### 23.2 SSTF：最短寻道时间优先

每次选择距离当前磁头最近的请求。

还是这个例子：

```text
当前：100

请求：
20，90，120，180
```

首先选择：

$$
90
$$

然后从 90 重新计算。

选择：

$$
120
$$

接着：

$$
180
$$

最后：

$$
20
$$

完整访问顺序：

```text
100 → 90 → 120 → 180 → 20
```

总距离：

$$
D=10+30+60+160
$$

$$
\boxed{D=260}
$$

虽然 SSTF 经常减少平均寻道距离，但不保证对每一组请求都比 FCFS 更好。

这个例子中 SSTF 就比 FCFS 多移动了 20 个磁道。

#### SSTF 最大问题：饥饿

如果磁头一直在 50 附近，而不断出现：

```text
48
49
51
52
50
```

那么远处的 190 号请求可能长期得不到服务。

<Callout type="warn" title="SCAN、C-SCAN 与 LOOK、C-LOOK 的关键差别">

在严格 SCAN/C-SCAN 教材模型中需要考虑磁道端点，循环返回的距离通常需要计入实际磁头移动距离；LOOK/C-LOOK 则只到该方向最后一个请求。未给出物理端点且只列请求的题目，应检验其采用的是哪种简化定义，不要在计算中途更换规则。

</Callout>

### 23.3 SCAN：扫描算法

又称电梯算法。

例如：

```text
磁头：100
方向：增大
请求：20，90，120，180
磁道：0～199
```

按照严格 SCAN：

先向增大方向访问：

```text
120 → 180
```

继续移动到物理端点：

```text
199
```

然后反向访问：

```text
90 → 20
```

完整路径：

```text
100 → 120 → 180 → 199 → 90 → 20
```

总距离：

$$
D=(199-100)+(199-20)
$$

$$
\boxed{D=278}
$$

注意：

199 虽然不是请求位置，但磁头经过它，移动距离仍要计算。

有些教材或习题将“SCAN”简化为到最远请求就折返，此时计算口径实际上接近 LOOK。

做题时要看清算法定义。

### 23.4 C-SCAN：循环扫描算法

SCAN 是双向提供服务。

C-SCAN 只沿一个方向提供服务。

例如仍然向磁道号增大方向移动：

```text
100 → 120 → 180 → 199
                  │
                  ▼
                  0 → 20 → 90
```

磁头从 199 返回 0 时不处理请求。

总距离：

$$
D=(199-100)+(199-0)+(90-0)
$$

$$
\boxed{D=388}
$$

特点：

- 服务方向固定。
- 等待时间通常更加均匀。
- 可能产生额外回程开销。

一定注意：

如果题目要求实际磁头移动距离，从末端回到起点的移动也应计入，除非题目明确规定不计。

### 23.5 LOOK：改进的 SCAN

LOOK 不必移动到磁盘物理端点。

只要该方向没有等待请求，就折返。

例如：

```text
100 → 120 → 180 → 90 → 20
```

总移动：

$$
D=20+60+90+70
$$

$$
\boxed{D=240}
$$

与严格 SCAN 对比：

$$
278-240=38
$$

LOOK 减少了没有实际请求的磁道移动。

### 23.6 C-LOOK：改进的 C-SCAN

C-LOOK 不移动到物理端点，而是在当前方向最远的请求与另一端的请求之间回绕。

```text
100 → 120 → 180
             │
             ▼
             20 → 90
```

总距离：

$$
D=20+60+160+70
$$

$$
\boxed{D=310}
$$

### 23.7 六种算法完整对比

以上统一使用：

- 磁道号 0～199。
- 磁头初始位置 100。
- 初始移动方向增大。
- 请求按到达顺序为 20、90、120、180。
- 所有请求开始时已经到达。
- 回绕距离计入实际磁头移动量。

| 算法     | 服务顺序          | 总移动距离 |
| ------ | ------------- | ----- |
| FCFS   | 20→90→120→180 | 240   |
| SSTF   | 90→120→180→20 | 260   |
| SCAN   | 120→180→90→20 | 278   |
| C-SCAN | 120→180→20→90 | 388   |
| LOOK   | 120→180→90→20 | 240   |
| C-LOOK | 120→180→20→90 | 310   |

这是理解算法差异的完整对照。

不要根据这一组特定数据得出“FCFS 总是比 C-SCAN 快”之类的结论。不同请求分布下，各算法的表现会变化。

#### 算法特点总结

| 算法     | 优点          | 缺点        |
| ------ | ----------- | --------- |
| FCFS   | 简单、公平       | 可能频繁大幅寻道  |
| SSTF   | 通常能降低寻道距离   | 可能饥饿      |
| SCAN   | 减少无序移动      | 等待时间可能不均匀 |
| C-SCAN | 服务方向统一      | 回绕开销      |
| LOOK   | 减少无效端点移动    | 仍有方向性等待   |
| C-LOOK | 减少循环扫描的无效移动 | 仍有回绕开销    |

## 二十六、★★★★★ 2010 年综合真题：位示图、磁盘调度、SSD

这是你的大题资料中最重要的一道综合题。

### 26.1 第一问：位示图管理空闲磁盘块

已知：

- 16384 个磁盘块。
- 使用 2KB 内存记录其空闲状态。

问采用什么管理方法。

#### 解答

一个磁盘块用一个 bit 表示状态。

所以需要：

$$
16384\text{bit}
$$

转换成字节：

$$
\frac{16384}{8}=2048\text{B}
$$

按题目采用的二进制口径：

$$
2048\text{B}=2\text{KiB}
$$

因此：

$$
\boxed{\text{使用位示图管理空闲磁盘块}}
$$

每一位对应一个磁盘块。

例如约定：

```text
0：空闲
1：已分配
```

则：

```text
块号：  0 1 2 3 4 5 6 7
状态：  1 0 0 1 1 0 1 0
```

表示 1、2、5、7 号块空闲。

#### 位示图通用公式

如果共有 $N$ 个磁盘块，每块对应一位：

$$
\boxed{ B_{\text{bitmap}}= \left\lceil\frac{N}{8}\right\rceil }
$$

单位为字节。

例如 16385 个块：

$$
\left\lceil\frac{16385}{8}\right\rceil=2049\text{B}
$$

因此 2KiB 就不够了。

不要忘记向上取整。

### 26.2 第二问：磁盘访问时间

题设：

- 磁头初始位于 100。
- 初始移动方向增大。
- 请求磁道为 50、90、30、120。
- 转速 6000r/min。
- 每磁道 100 个扇区。
- 每移动一个磁道平均 1ms。
- 每个请求读取一个随机分布的扇区。
- 使用 C-SCAN。

#### 第一步：确定服务顺序

磁头从 100 向增大方向移动。

先访问：

$$
120
$$

然后循环回来：

$$
30\rightarrow50\rightarrow90
$$

服务顺序：

$$
\boxed{120\rightarrow30\rightarrow50\rightarrow90}
$$

#### 第二步：求旋转延迟

转速：

$$
6000\text{r/min}=100\text{r/s}
$$

一圈时间：

$$
10\text{ms}
$$

平均等待半圈：

$$
5\text{ms}
$$

四个随机扇区：

$$
T_r=4\times5=20\text{ms}
$$

#### 第三步：求传输时间

每条磁道 100 个扇区。

一个扇区传输时间：

$$
\frac{10}{100}=0.1\text{ms}
$$

四个扇区：

$$
T_t=0.4\text{ms}
$$

#### 第四步：求寻道时间——这道题存在一个重要的口径问题

你 Fumadocs 的选择真题整理给出的路径是：

$$
100\rightarrow120\rightarrow30\rightarrow50\rightarrow90
$$

总移动距离：

$$
D=20+90+20+40=170
$$

所以答案为：

$$
T=170+20+0.4
$$

$$
\boxed{T=190.4\text{ms}}
$$

这就是原稿参考资料采用的答案；其省略物理端点移动的条件与严格 C-SCAN 不同，宜作为 C-LOOK 类简化模型理解。

不过，这个解法没有将严格 C-SCAN 的物理端点移动计入，按照通常算法定义，更接近 C-LOOK。

你的大题详解中也专门指出了这一差异。

#### 如果题目明确磁道为 0～199，且采用严格 C-SCAN

正确移动路径应为：

$$
100\rightarrow120\rightarrow199\rightarrow0 \rightarrow30\rightarrow50\rightarrow90
$$

总移动距离：

$$
D=(199-100)+(199-0)+(90-0)
$$

$$
D=99+199+90
$$

$$
\boxed{D=388}
$$

总时间：

$$
T=388+20+0.4
$$

$$
\boxed{T=408.4\text{ms}}
$$

所以应当区分：

| 模型                    | 总移动距离 | 总时间     |
| --------------------- | ----- | ------- |
| 原资料简化回绕，接近 C-LOOK     | 170   | 190.4ms |
| 明确磁道 0～199 的严格 C-SCAN | 388   | 408.4ms |

考试原则：先遵循题目的算法定义和边界约束。

如果题目只给出 C-SCAN，而没有给出物理端点位置，则不能在严格端点模型下凭空算出唯一的总移动距离。

### 26.3 第三问：换成 SSD 后如何调度？

原题问：如果把机械磁盘换成 Flash 存储器，有没有更合适的调度算法？

答案：

在该题采用的简化随机访问模型下，可以采用 FCFS。

理由：

机械磁盘需要减少磁头寻道距离，而 SSD 没有机械磁头和旋转盘片。

因此无需按磁道号重新排列请求。

不过，实际 SSD 仍然存在：

- 多通道并行。
- 垃圾回收。
- 写放大。
- I/O 请求合并。
- 延迟与吞吐量权衡。

所以真实 SSD 系统也可以采用复杂的 I/O 调度策略，只是不再以机械寻道距离作为主要优化目标。

## 二十七、磁盘空闲空间管理

这一知识点与第 4 章文件管理交叉。

除了位示图，还需要掌握常见管理方法。

| 方法    | 核心思想             | 特点            |
| ----- | ---------------- | ------------- |
| 空闲表法  | 记录空闲连续区域的起始位置和长度 | 适合连续空闲空间      |
| 空闲链表法 | 将空闲空间组织成链表       | 管理简单，但逐项遍历可能慢 |
| 位示图法  | 每块对应一个 bit       | 容易判断空闲状态      |
| 成组链接法 | 将多个空闲块号组织成组并相互链接 | 适合批量管理空闲块     |

### 模拟题：成组链接法

某系统使用成组链接法管理空闲块。

问其主要优点。

正确理解是：

将若干空闲块号集中管理，通过组间链接实现批量分配与回收。

不能认为它的主要作用是加快目录查找。

因为空闲块管理与目录查找属于不同层次的功能。

## 二十八、★★★★★ 磁盘格式化

非常容易考概念判断。

要区分三个操作：

### 28.1 物理格式化

又称低级格式化。

经典机械磁盘模型中负责：

- 划分磁道和扇区。
- 设置必要的扇区控制信息。
- 初始化物理存储组织。

现代硬盘的低级格式化通常由厂商完成。

### 28.2 磁盘分区

将磁盘划分为多个逻辑区域。

例如：

```text
Disk
 ├─ Partition 1
 ├─ Partition 2
 └─ Partition 3
```

分区操作主要建立分区边界和分区表等信息。

分区本身不等于建立文件系统。

### 28.3 逻辑格式化

又称高级格式化。

主要负责建立文件系统。

例如：

- 文件系统管理信息。
- 空闲空间管理结构。
- 根目录。
- 必要的文件元数据结构。

完整关系：

```text
物理格式化
     ↓
磁盘分区
     ↓
逻辑格式化
     ↓
安装操作系统
```

这是教材中的概念性流程，实际现代磁盘的物理格式化往往早已完成。

#### 2017 年 408 真题

磁盘逻辑格式化需要执行哪些工作？

I. 磁盘分区

II. 建立文件系统根目录

III. 确定扇区校验码所占位数

IV. 初始化空闲磁盘块管理结构

正确：

$$
\boxed{\text{II、IV}}
$$

答案 B。

原因：

- I 属于分区操作。
- II 属于逻辑格式化。
- III 属于物理格式化层面的工作。
- IV 属于逻辑格式化。

## 二十九、2021 年 408 综合真题：系统引导与格式化

### 29.1 第一问：引导顺序

题目采用传统 BIOS/MBR 模型。

```text
ROM引导程序
      ↓
磁盘引导程序
      ↓
分区引导程序
      ↓
```

- 逻辑格式化。
- 磁盘分区。

按照题目中的经典模型：

$$
\boxed{ \text{物理格式化} \rightarrow \text{磁盘分区} \rightarrow \text{逻辑格式化} \rightarrow \text{安装操作系统} }
$$

### 29.3 第三问：物理扇区与根目录分别何时建立？

物理扇区的划分：

物理格式化。

根目录的建立：

逻辑格式化。

#### 补充：现代 UEFI/GPT 引导

现代计算机不一定经过传统 MBR 分区引导链。

典型 UEFI 启动可以是：

```text
UEFI固件
    ↓
从ESP加载EFI启动程序
    ↓
操作系统加载器
    ↓
操作系统内核
    ↓
初始化
```

ESP 是 EFI System Partition。

GPT 则负责描述分区的边界、类型、标识等信息。

考试如果明确限定 BIOS/MBR，就不要擅自替换为 UEFI 模型。

## 三十、坏块管理

机械磁盘可能出现无法正常读写的坏扇区。

常见处理方式：

#### 方式一：操作系统管理

操作系统或文件系统记录坏块，避免继续将其分配给正常文件。

#### 方式二：设备控制器重映射

设备控制器发现坏扇区后，将对应逻辑地址映射到备用物理扇区。

```text
原逻辑扇区
    ↓
发现物理坏块
    ↓
控制器重新映射
    ↓
备用物理扇区
```

这样上层软件可以继续使用相同逻辑地址。

需要区分：

逻辑地址不变，不代表数据仍然位于原来的物理位置。

## 三十一、减少旋转延迟的技术

### 31.1 交替编号

假设磁盘连续扇区编号为：

```text
0 1 2 3 4 5 6 7
```

CPU 读完扇区 0 后，需要一定时间处理。

等准备读取扇区 1 时，扇区 1 可能已经旋转过去。

于是又要等待一圈。

解决办法：

让逻辑连续扇区在物理上适当间隔排列。

例如：

```text
物理位置：
0 4 1 5 2 6 3 7
```

使下一次目标扇区恰好在处理结束时旋转到磁头下面。

这种技术本质上是利用物理布局补偿处理延迟。

### 31.2 错位命名

不同盘面之间切换磁头也需要时间。

如果两个盘面的扇区位置完全对齐，切换磁头完成时，目标扇区可能已经转过磁头。

因此可以让不同盘面的扇区编号适当错开。

核心目的都是：

$$
\boxed{\text{减少不必要的旋转等待}}
$$

现代硬盘通常将这些复杂性封装在控制器和固件中。

## 三十二、★★★★★ 固态硬盘 SSD

### 32.1 SSD 与 HDD 的区别

| 项目     | HDD       | SSD          |
| ------ | --------- | ------------ |
| 存储介质   | 磁盘盘片      | Flash 闪存     |
| 机械磁头   | 有         | 无            |
| 寻道时间   | 有         | 无机械寻道        |
| 旋转延迟   | 有         | 无            |
| 随机访问   | 相对较慢      | 通常更快         |
| 典型优化   | 减少寻道和旋转等待 | 并行、写入管理、垃圾回收 |
| 主要寿命因素 | 机械与介质可靠性  | 擦写寿命等        |

不能简单说 SSD 的所有访问时间完全相同。

SSD 的读、写、擦除操作开销不同，不同逻辑地址还可能映射到不同内部状态的闪存区域。

### 32.2 SSD 的页与块

SSD 的 Flash 存储空间可以划分为：

```text
Block 0
 ├─ Page 0
 ├─ Page 1
 ├─ Page 2
 └─ Page 3

Block 1
 ├─ Page 0
 ├─ Page 1
 ├─ Page 2
 └─ Page 3
```

核心结论：

$$
\boxed{\text{读写以页为基本单位，擦除以块为单位}}
$$

对典型 NAND Flash 而言：

- 可以读取页。
- 可以向符合编程条件的页写入。
- 擦除通常要对整个擦除块进行。
- 已写入的页不能像普通 RAM 那样随意原地覆盖。

这是 SSD 随机写管理比随机读复杂的重要原因。

### 32.3 为什么 SSD 写入可能需要垃圾回收？

假设某块有四个页：

```text
Page0：有效
Page1：有效
Page2：旧数据
Page3：有效
```

现在 Page2 对应的逻辑数据更新了。

SSD 不一定能够直接覆盖原物理页。

通常会：

1. 将新数据写入另一个可编程页。
2. 修改逻辑地址到物理地址的映射。
3. 把原 Page2 标记为无效。
4. 在适当时机把有效页搬迁。
5. 擦除包含较多无效页的旧块。

这个回收可重用空间的过程属于垃圾回收。

<Callout type="info" title="SSD 不再进行机械寻道，但仍存在设备内部调度">

SSD 没有旋转盘片、机械磁臂与寻道延迟，因而不能直接沿用 HDD 的电梯调度收益。但闪存仍需进行地址映射、队列处理、磨损均衡和垃圾回收；实际系统并非完全没有调度或内部延迟。

</Callout>

### 32.4 FTL：闪存翻译层

FTL = Flash Translation Layer。

主要负责：

$$
\boxed{\text{逻辑块地址}\rightarrow\text{物理闪存地址}}
$$

它需要维护映射信息。

例如：

```text
逻辑地址100
     ↓
物理页A
```

当逻辑地址 100 的数据被更新后，可能变成：

```text
逻辑地址100
     ↓
物理页B
```

应用程序仍然访问逻辑地址 100。

但数据真正所在的物理位置已经改变。

FTL 还与以下功能密切相关：

- 垃圾回收。
- 磨损均衡。
- 坏块管理。
- 写入优化。

### 32.5 SSD 磨损均衡

Flash 擦除块的擦写次数有限。

假设：

```text
Block A：1000次
Block B：100次
Block C：10次
```

如果不断写入 Block A，它可能提前达到寿命极限。

磨损均衡就是尽量避免部分物理块承受过多擦写操作。

#### 动态磨损均衡

新写入的数据尽量分配到磨损较轻的可用块。

例如：

```text
A：1000次
B：100次
C：10次
```

在其他条件相当时，可以优先使用 C。

#### 静态磨损均衡

不仅管理新写入数据，还会考虑长期不变的静态数据。

例如：

```text
Block A：静态系统文件，很少修改
Block B：经常写入的数据
```

如果 A 长期占用低磨损块，而 B 不断被擦写，磨损将越来越不均匀。

静态磨损均衡可以主动迁移静态数据，使原本低磨损的块参与后续写入。

#### 两者区别

| 项目           | 动态磨损均衡       | 静态磨损均衡     |
| ------------ | ------------ | ---------- |
| 管理对象         | 主要是新写入数据与可用块 | 也考虑长期不变的数据 |
| 是否可能主动搬迁静态数据 | 通常不需要        | 可以         |
| 目标           | 避免持续写入高磨损块   | 让整体磨损更加均匀  |

## 三十四、模拟题 1：中断开销计算

原稿所列模拟题给出：

- CPU 主频 500MHz。
- CPI = 3。
- 鼠标每秒产生 200 次中断。
- 用于鼠标中断的 CPU 时间必须低于总时间的 0.1%。

求每次中断最多允许执行多少条指令。

#### 第一步：计算 CPU 每秒可执行指令数

$$
IPS=\frac{f}{CPI}
$$

代入：

$$
IPS=\frac{500\times10^6}{3}
$$

$$
IPS\approx1.6667\times10^8
$$

#### 第二步：计算允许的指令预算

CPU 时间占比：

$$
0.1\%=0.001
$$

因此每秒最多可使用：

$$
1.6667\times10^8\times0.001
$$

约：

$$
166666.7
$$

条指令。

#### 第三步：除以中断次数

每秒 200 次。

$$
N=\frac{166666.7}{200}
$$

$$
N\approx833.33
$$

指令数必须是整数。

因此：

$$
\boxed{N_{\max}=833}
$$

原模拟题答案 C。

#### 这类题的万能公式

设：

- CPU 主频 $f$。
- 平均 CPI 为 $c$。
- 每秒中断次数为 $r$。
- 允许占用 CPU 时间的比例为 $p$。

则：

$$
\boxed{ N_{\max} = \left\lfloor \frac{fp}{cr} \right\rfloor }
$$

如果题目要求严格小于上限，则结果需要满足严格不等式。

## 三十六、模拟题 3：SSTF 与 LOOK 对比

磁盘：

$$
0\sim199
$$

当前磁头：

$$
100
$$

向增大方向移动。

请求：

$$
142,82,197,90,108
$$

#### SSTF

从 100 开始，每次选择最近的请求：

$$
100\rightarrow108\rightarrow90\rightarrow82 \rightarrow142\rightarrow197
$$

总移动距离：

$$
D=8+18+8+60+55
$$

$$
\boxed{D=149}
$$

#### LOOK

按照初始方向，先访问所有大于 100 的请求：

$$
108,142,197
$$

再反向：

$$
90,82
$$

完整路径：

$$
100\rightarrow108\rightarrow142\rightarrow197 \rightarrow90\rightarrow82
$$

距离：

$$
D=8+34+55+107+8
$$

$$
\boxed{D=212}
$$

因此：

$$
\boxed{149,\ 212}
$$

原模拟题答案 A。

#### 易错点

LOOK 要遵守初始方向。

SSTF 不需要遵守初始方向，而是每次重新比较距离。

## 三十七、模拟题 4：SSD 原理判断

以下哪个说法正确？

A. SSD 属于磁表面存储器。

B. SSD 的 FTL 具有逻辑地址到物理地址映射功能。

C. SSD 随机写一定比 HDD 随机写慢。

D. SSD 可以任意覆盖已经写入的 Flash 页。

正确答案：

$$
\boxed{B}
$$

解析：

A 错，SSD 使用 Flash 半导体存储器。

B 对，FTL 负责地址映射。

C 错，SSD 随机写通常也显著快于机械硬盘，但可能受到垃圾回收等因素影响。

D 错，NAND Flash 不能像 RAM 一样任意覆盖已经编程的物理页。

## 三十八、综合预测题一：DMA + 中断 + 进程状态

### 题目

某进程 P 使用阻塞式 I/O 请求从磁盘读取一个 8KiB 数据块。

系统使用 DMA 方式，P 发出请求后进入阻塞态。

请回答：

1. 数据是否必须经过 CPU 通用寄存器？
2. DMA 传输期间 CPU 能否运行其他进程？
3. DMA 完成后是否一定需要相关完成处理？
4. P 最先从阻塞态转变成什么状态？
5. 哪个部件负责执行具体设备操作的初始化？

<Accordions>
<Accordion title="展开：综合预测题 1 分步计算与解析" id="os5-predict-01">

#### 解析

第一问：

数据块由 DMA 控制器负责在设备和主存之间搬运。

$$
\boxed{\text{不需要逐字经过 CPU 通用寄存器}}

第三问：

通常需要完成通知和结束处理，可通过中断完成。

DMA 并不代表没有中断。

第四问：

$$
\boxed{\text{阻塞态}\rightarrow\text{就绪态}}
$$

并不直接转成运行态。

第五问：

操作系统通过设备驱动程序配置 DMA 和设备控制器，实际控制命令由相关硬件执行。

#### 这道题的价值

## 第七部分：最容易混淆的 15 组概念

| 易混概念            | 正确区别                                            |
| --------------- | ----------------------------------------------- |
| 程序查询 vs 中断驱动    | 查询通常忙等待；中断驱动通过通知避免持续查询                          |
| 中断驱动 vs DMA     | 中断驱动的经典模型需要 CPU 搬运数据；DMA 可直接搬运数据块               |
| DMA vs 通道       | DMA 侧重数据块传输；通道可执行一组 I/O 控制命令                    |
| 设备控制器 vs 设备驱动   | 控制器是硬件；驱动是软件                                    |
| 设备独立层 vs 驱动层    | 前者负责公共抽象；后者负责具体设备控制                             |
| 阻塞态 vs 就绪态      | I/O 完成后通常先就绪，等待调度                               |
| Buffer vs Cache | Buffer 侧重速度匹配；Cache 侧重重复访问命中                    |
| 单缓冲 vs 双缓冲      | 单缓冲周期 $\max(T,C)+M$；双缓冲周期 $\max(T,M+C)$ |
| 输入井 vs 输入缓冲区    | 输入井在外存；缓冲区在主存                                   |
| 逻辑设备 vs 物理设备    | 逻辑设备是上层抽象；物理设备是真实硬件                             |
| 独占设备 vs 虚拟设备    | SPOOLing 可把独占设备在逻辑上虚拟为共享设备                      |
| SCAN vs C-SCAN  | SCAN 双向服务；C-SCAN 单方向服务                          |
| SCAN vs LOOK    | 严格 SCAN 到物理端点；LOOK 到最远待处理请求                     |
| 物理格式化 vs 逻辑格式化  | 前者组织物理扇区；后者建立文件系统                               |
| HDD vs SSD      | HDD 有机械寻道与旋转；SSD 通过 Flash 和 FTL 管理数据            |

## 第八部分：考前必背公式与做题方法

## 四十一、计算公式总表

| 类型               | 必背公式                                                      |
| ---------------- | --------------------------------------------------------- |
| 单缓冲稳定周期          | $\max(T,C)+M$                                         |
| 双缓冲稳定周期          | $\max(T,M+C)$                                         |
| 单缓冲 $n$ 块总时间 | $T+M+(n-1)[\max(T,C)+M]+C$                            |
| 双缓冲 $n$ 块总时间 | $T+(n-1)\max(T,M+C)+M+C$                              |
| 磁盘容量             | $CHSB$                                                |
| 寻道距离             | $\sum_{i=1}^{n}\|x_i-x_{i-1}\|$                     |
| 磁盘平均访问时间         | $T_s+T_r+T_t$                                         |
| 平均旋转延迟           | $\frac{1}{2r}$                                        |
| 数据传输时间           | $\frac{b}{rN}$                                        |
| 位示图字节数           | $\left\lceil\frac{N_{\text{blocks}}}{8}\right\rceil$ |
| 中断指令预算           | $\left\lfloor\frac{fp}{CPI\cdot r}\right\rfloor$      |

表中不同公式可能使用相同的字母表示不同物理量，具体使用时应以各自定义为准。

## 四十二、拿到题目后如何快速判断考什么？

看到“设备完成以后、哪个程序首先处理”：

优先考虑中断处理程序。

看到“设置设备控制器、转换具体设备命令”：

优先考虑设备驱动程序。

看到“逻辑设备名、设备更换”：

优先考虑设备独立性与 LUT。

看到“多个进程共享一台打印机”：

优先考虑 SPOOLing。

看到“$T,M,C$ 三个时间”：

立即判断单缓冲或双缓冲，画出并行阶段。

看到“当前磁头位置、初始方向、请求序列”：

立即想到 FCFS、SSTF、SCAN、C-SCAN、LOOK、C-LOOK。

看到“柱面数、磁道数、扇区数、簇号”：

先计算每柱面的簇数，再逐层整除和取余。

看到“物理格式化、逻辑格式化、根目录”：

区分物理扇区组织和文件系统建立。

看到“FTL、页、块、擦写寿命”：

立即想到 SSD 的地址映射、垃圾回收和磨损均衡。

### 最后：真正学懂第 5 章的标准

如果已经能够不看答案独立完成下面这些任务，说明这一章的核心内容基本掌握：

- 能画出一次 `read()` 请求从用户程序到驱动、DMA、中断的完整过程。
- 能解释为什么 DMA 仍可能产生中断，以及为什么设备完成后进程不是直接变成运行态。
- 能独立推导单缓冲和双缓冲的公式，并计算 2 块、10 块和任意 $n$ 块的总时间。
- 能解释 SPOOLing 如何用磁盘输出井实现打印机的逻辑共享。
- 能完成磁盘容量、簇号到 CHS 地址的转换。
- 能计算 FCFS、SSTF、SCAN、C-SCAN、LOOK、C-LOOK 的服务顺序和磁头移动距离，并且不会混淆物理端点。
- 能把寻道、旋转延迟和数据传输时间结合起来完成综合计算。
- 能区分物理格式化、分区、逻辑格式化和操作系统引导。
- 能解释 SSD 为什么需要 FTL、垃圾回收与磨损均衡。

这一章最重要的贯穿逻辑是：操作系统通过统一的软件接口屏蔽设备差异，通过中断和 DMA 减少 CPU 干预，通过缓冲、设备分配和 SPOOLing 实现并行与共享，再通过磁盘调度和 SSD 管理提高外存访问效率。

从 408 解题角度来说，尤其要把缓冲流水时间、磁盘调度距离、磁盘地址转换这三种计算练熟；把I/O 软件层次、DMA、中断、SPOOLing 和 SSD这些概念辨析练准。它们构成了本章最有价值的复习核心。
