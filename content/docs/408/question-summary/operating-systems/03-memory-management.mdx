## 二、内存管理的基本概念

### 1. 为什么需要内存管理？

假设有两个进程：

- 进程 A 需要 200 KB 内存。
- 进程 B 需要 300 KB 内存。

如果没有操作系统管理，它们可能出现几个问题：

- 都想使用相同的物理地址；
- A 意外修改 B 的数据；
- A 结束后，内存不知道怎样回收；
- 内存剩下很多零散区域，无法装入新进程；
- 程序很大，无法全部放进内存。

所以操作系统需要完成：

分配、回收、地址转换、保护、共享、虚拟扩充。

这六个词分别对应本章后续所有知识点。

### 2. 逻辑地址与物理地址

#### 逻辑地址

程序运行时使用的地址，也叫虚拟地址。

例如程序访问：

```c
int x = 10;
printf("%d", x);
```

程序所使用的 `x` 的地址，通常是其进程虚拟地址空间中的地址。

#### 物理地址

数据实际位于物理内存中的地址。

例如：

```text
进程 A：
逻辑地址 1000
        ↓
地址转换
        ↓
物理地址 81000

进程 B：
逻辑地址 1000
        ↓
地址转换
        ↓
物理地址 121000
```

两个进程完全可以使用相同的逻辑地址，因为它们拥有各自的地址映射。

408 高频结论：逻辑地址相同，物理地址不一定相同；逻辑地址不同，也可能通过共享映射指向相同物理内存。

#### 地址形成的阶段

2011 年选择题考查：

题目问：统一的逻辑地址在程序处理的哪个阶段形成？

按照该题的教材模型：

```text
源程序
  ↓ 编译
目标模块及模块内相对地址
  ↓ 链接
统一的逻辑地址空间
  ↓ 装入、运行
建立逻辑地址与物理地址的对应关系
```

答案是：链接阶段。

注意，编译器可以形成模块内相对地址，但题目说的是整个程序统一的逻辑地址空间。

### 3. 静态重定位与动态重定位

| 对比      | 静态重定位    | 动态重定位      |
| ------- | -------- | ---------- |
| 转换时间    | 装入时      | 运行时        |
| 地址确定    | 装入时修正    | 每次访问由硬件转换  |
| 程序运行时搬迁 | 不方便      | 比较方便       |
| 主要支持    | 装入程序     | MMU、地址映射硬件 |
| 与紧凑的关系  | 不利于运行时紧凑 | 支持紧凑       |

#### 动态重定位的基本计算

假设：

- 基址寄存器的值为 5000；
- 进程的逻辑地址空间长度为 3000；
- CPU 发出逻辑地址 1500。

必须先检查：

$$
0\leq LA<L
$$

即：

$$
0\leq1500<3000
$$

成立。

随后计算：

$$
PA=B+LA
$$

$$
PA=5000+1500=\boxed{6500}
$$

如果 CPU 发出逻辑地址 3500，则：

$$
3500\geq3000
$$

发生越界异常。

不能计算出 8500 就认为访问成功。

<Callout type="warn" title="地址转换先判断越界">

考场顺序：先检查地址是否合法，再做地址转换。

</Callout>

这也是 2009 年内存保护选择真题的核心：连续分区管理通常利用基址、界限等机制实现地址保护。

## 三、连续分配管理

### 1. 三种连续分配方式

#### 单一连续分配

物理内存主要划分为：

```text
┌─────────────────┐
│    操作系统      │
├─────────────────┤
│                 │
│   一个用户进程   │
│                 │
└─────────────────┘
```

同一时刻用户内存中只有一道用户程序。

特点：

- 实现简单；
- 内存利用率较低；
- 不利于多道程序并发。

#### 固定分区分配

将内存提前划成固定分区：

```text
┌─────────────────┐
│ 系统区           │
├─────────────────┤
│ 分区1：100KB      │
├─────────────────┤
│ 分区2：100KB      │
├─────────────────┤
│ 分区3：100KB      │
└─────────────────┘
```

例如一个进程需要 70 KB，分配给它 100 KB 分区。

实际浪费：

$$
100-70=30\text{ KB}
$$

这 30 KB 已经属于该进程的分区，但未被有效使用。

称为内部碎片。

#### 动态分区分配

不提前划分固定大小的分区，而是根据进程的实际请求动态分配。

例如：

```text
初始：500KB 空闲

进程A申请100KB
进程B申请150KB
进程C申请100KB
```

分配后：

```text
┌─────────────────┐
│ A：100KB         │
├─────────────────┤
│ B：150KB         │
├─────────────────┤
│ C：100KB         │
├─────────────────┤
│ 空闲：150KB       │
└─────────────────┘
```

如果 B 退出：

```text
A：100KB
空闲：150KB
C：100KB
空闲：150KB
```

总空闲空间为 300 KB。

但是现在来了一个需要 200 KB 连续空间的进程。

它能成功分配吗？

不能。

因为没有任何单个空闲块达到 200 KB。

这就是外部碎片。

### 2. 内部碎片与外部碎片

这是 408 最基础、最容易混淆的考点。

| 比较   | 内部碎片        | 外部碎片         |
| ---- | ----------- | ------------ |
| 空间状态 | 已分配出去       | 尚未分配         |
| 浪费原因 | 已分配区域内部没有用完 | 空闲区域被分割      |
| 固定分区 | 有           | 非主要问题        |
| 动态分区 | 理论模型中通常无    | 有            |
| 基本分页 | 有           | 无            |
| 基本分段 | 理论模型中通常无    | 有            |
| 段页式  | 有           | 无            |
| 伙伴系统 | 有           | 仍可能受块大小和合并限制 |

口诀：

分出去没用完，是内部碎片；没分出去却拼不起来，是外部碎片。

这里按照 408 教材的理想模型分类。实际内存分配器还会受到对齐、管理元数据和分配粒度等因素影响。

#### 怎样解决外部碎片？

一种方法是紧凑（Compaction）：

```text
紧凑前：

[A][空闲][B][空闲][C][空闲]

紧凑后：

[A][B][C][     大块空闲     ]
```

但移动进程后，其实际物理位置变化。

所以一般需要动态重定位机制支持。

### 3. 四种动态分区分配算法

这部分要掌握得非常熟练。

| 算法              | 规则             | 关键特点        |
| --------------- | -------------- | ----------- |
| First Fit（首次适应） | 从起点找第一块足够大的空闲区 | 简单、通常较快     |
| Next Fit（临近适应）  | 从上次查找位置继续循环寻找  | 必须记录游标      |
| Best Fit（最佳适应）  | 选足够大的块中最小的一块   | 容易产生很小的空闲碎片 |
| Worst Fit（最坏适应） | 选最大的空闲块        | 容易消耗大块连续空间  |

#### 基础教学例题

现有空闲分区：

$$
10,\ 30,\ 20,\ 50,\ 40\text{ KB}
$$

申请：

$$
18\text{ KB}
$$

四种算法的结果：

| 算法        | 选中空闲块 | 剩余大小  |
| --------- | ----- | ----- |
| First Fit | 30    | 12    |
| Next Fit  | 取决于游标 | 取决于游标 |
| Best Fit  | 20    | 2     |
| Worst Fit | 50    | 32    |

为什么 Best Fit 不一定最好？

因为它可能不断制造出 1 KB、2 KB、3 KB 这样的小空闲区域。

这些区域往往难以再利用。

最佳适应的“最佳”只表示当前选择最接近请求大小，不表示长期内存利用率一定最佳。

### 5. 2017 年真题：分区回收与链表排序

这是比上一题更复杂的类型。

当前空闲分区：

| 起始地址  | 大小     |
| ----- | ------ |
| 20K   | 40 KB  |
| 500K  | 80 KB  |
| 1000K | 100 KB |
| 200K  | 200 KB |

现在释放：

- 起始地址：60K；
- 长度：140 KB。

采用最佳适应算法，每次操作后重新按空闲分区大小排序。

#### 第一步：写成地址区间

已有空闲块：

$$
[20,60)
$$

$$
[500,580)
$$

$$
[1000,1100)
$$

$$
[200,400)
$$

释放的区域：

$$
[60,200)
$$

注意到：

$$
[20,60),\ [60,200),\ [200,400)
$$

三个区间恰好相邻。

#### 第二步：合并

合并成：

$$
[20,400)
$$

长度：

$$
40+140+200=\boxed{380\text{ KB}}
$$

合并后的空闲块为：

$$
380,\ 80,\ 100
$$

所以空闲块一共 3 个。

#### 第三步：重新排序

Best Fit 的空闲链按大小递增组织：

$$
80,\ 100,\ 380
$$

第一个分区为：

- 起始地址：500K；
- 大小：80 KB。

因此答案是：

$$
\boxed{3,\ 500K,\ 80\text{ KB}}
$$

正确选项：B。

这类题的陷阱是：物理地址顺序和空闲链表顺序不一定相同。

### 6. 动态分区回收的四种情况

| 左边是否空闲 | 右边是否空闲 | 回收后空闲块数变化 |
| ------ | ------ | --------- |
| 否      | 否      | $+1$  |
| 是      | 否      | $0$   |
| 否      | 是      | $0$   |
| 是      | 是      | $-1$  |

当左右两边都空闲时：

```text
[空闲A][待释放B][空闲C]
```

释放 B 后：

```text
[      空闲A+B+C      ]
```

原本有两个空闲块，合并后只剩一个。

所以空闲块数量减少 1。

这个结论经常用于快速解答选择题。

## 四、伙伴系统 Buddy System

### 1. 伙伴系统是什么？

它是一种按照 2 的整数次幂组织内存块的分配方法。

典型块大小：

$$
1,\ 2,\ 4,\ 8,\ 16,\ 32,\ 64,\ldots
$$

假设申请 13 KB。

最小能够满足的 2 的整数次幂块是：

$$
2^4=16
$$

所以分配 16 KB。

内部浪费：

$$
16-13=3\text{ KB}
$$

一般公式：

$$
B=2^{\lceil\log_2S\rceil}
$$

其中 $S$ 为申请大小；如果系统规定了最小块大小，还必须同时满足该限制。

### 2. 伙伴系统怎样分裂？

假设有一个 64 KB 空闲块，现在申请 10 KB：

```text
64 KB
├── 32 KB
│   ├── 16 KB ← 分配给申请者
│   └── 16 KB ← 空闲
└── 32 KB     ← 空闲
```

请求 10 KB，分得 16 KB。

后续如果释放 16 KB，就可以尝试与其伙伴合并。

### 3. 什么时候能够合并？

必须满足：

- 两块大小相同；
- 两块都空闲；
- 两块是同一个父块分裂得到的伙伴。

相邻、等大，不一定就是伙伴。

例如：

```text
[0,8)     与 [8,16)      是伙伴
[8,16)    与 [16,24)     不是伙伴
[16,24)   与 [24,32)     是伙伴
```

虽然第二组相邻且都为 8 KB，但不是同一个 16 KB 父块分裂出来的。

#### 伙伴地址公式

当内存起始地址以相应块边界对齐，块大小为 $2^k$ 时：

$$
Buddy(A)=A\oplus2^k
$$

这里的 $\oplus$ 表示按位异或。

#### 对应真题

2024 年选择题考查：

哪种分配算法回收内存时，只能按相同大小的伙伴关系合并？

答案：伙伴算法。

## 五、基本分页存储管理——全章第一个核心

从这里开始，是 408 内存管理综合大题最重要的内容之一。

### 1. 为什么需要分页？

连续分配要求：

> 一个进程必须占据一整块连续的物理内存。

假设内存中有三个空闲区：

$$
4\text{ KB},\ 4\text{ KB},\ 4\text{ KB}
$$

一个进程需要 12 KB。

动态分区无法满足，因为三个空闲区不连续。

但如果把进程划分为三个 4 KB 页面：

```text
进程虚拟地址空间：

┌────────┐
│  页0   │
├────────┤
│  页1   │
├────────┤
│  页2   │
└────────┘
```

三个页面可以分别放入三个不连续的物理页框：

```text
虚页0 → 物理页框8
虚页1 → 物理页框3
虚页2 → 物理页框12
```

此时整个进程不需要占据连续物理空间。

这就是分页的根本价值。

### 2. 页、页框、页表

必须区分三个概念。

| 概念            | 含义           |
| ------------- | ------------ |
| 页 Page        | 虚拟地址空间的固定大小块 |
| 页框 Frame      | 物理内存的固定大小块   |
| 页表 Page Table | 保存虚页到物理页框的映射 |

分页系统中：

$$
\boxed{\text{页面大小}=\text{页框大小}}
$$

页表中保存的映射可以表示为：

$$
VPN\longrightarrow PFN
$$

其中：

- VPN：Virtual Page Number，虚页号；
- PFN：Page Frame Number，物理页框号。

### 3. 分页地址转换公式

设：

- 虚拟地址为 $A$；
- 页面大小为 $P$；
- 页号为 $p$；
- 页内偏移为 $d$；
- 页框号为 $f$。

那么：

$$
\boxed{p=\left\lfloor\frac{A}{P}\right\rfloor}
$$

$$
\boxed{d=A\bmod P}
$$

根据页表查出 $f$，得到：

$$
\boxed{PA=fP+d}
$$

记住最重要的一点：

地址转换改变页号对应关系，但页内偏移不变。

### 4. 典型教学例题：分页地址转换

假设：

- 页面大小为 4 KB；
- 虚拟地址为 `0x12345`；
- 页表显示虚页 `0x12` 对应物理页框 `0xAB`。

求物理地址。

#### 第一步：确定页面大小

$$
4\text{ KB}=2^{12}\text{ B}=0x1000
$$

因此低 12 位为页内偏移。

#### 第二步：拆分虚拟地址

```text
虚拟地址：0x12345

虚页号：0x12
页内偏移：0x345
```

#### 第三步：查页表

已知：

$$
VPN=0x12\longrightarrow PFN=0xAB
$$

#### 第四步：拼接物理地址

$$
PA=0xAB\times0x1000+0x345
$$

$$
\boxed{PA=0xAB345}
$$

注意：

如果页面大小不是 4 KB，而是 1 KB，那么偏移占 10 位，不可以简单地拿最低三个十六进制数字作为偏移。

必须严格按照页面大小计算。

### 5. 页表项保存什么信息？

普通分页页表项的核心是物理页框号。

请求分页系统还会包含或关联更多信息：

| 字段        | 作用         |
| --------- | ---------- |
| 页框号       | 指向物理页框     |
| 存在位/有效位   | 表示页面是否驻留   |
| 访问位       | 是否近期访问     |
| 修改位       | 是否被写入      |
| 保护位       | 控制读、写、执行权限 |
| 外存位置等管理信息 | 帮助定位被换出的页面 |

其中后四类是请求分页和页面置换的重要基础。

需要注意：有的处理器把“无效映射”“不在内存”和“权限错误”编码、处理得更复杂，不能把所有异常都理解成必须从磁盘调页。

## 六、页表大小、页表项地址与页表空间

### 1. 单级页表大小

假设：

- 虚拟地址宽度为 $n$ 位；
- 页面大小为 $2^k$ B；
- 每个页表项大小为 $E$ B。

页内偏移占：

$$
k\text{ 位}
$$

虚拟页号占：

$$
n-k\text{ 位}
$$

完整虚拟地址空间拥有：

$$
2^{n-k}
$$

个虚拟页面。

如果每页都需要对应一个页表项，则完整单级页表大小为：

$$
\boxed{S=2^{n-k}E}
$$

### 2. 2013 年第 46 题：单级页表

历年综合大题

条件：

- 32 位虚拟地址；
- 页面大小 4 KB；
- 页表项大小 4 B。

求完整一级页表的最大大小。

#### 第一步：页内偏移位数

$$
4\text{ KB}=2^{12}\text{ B}
$$

所以偏移占 12 位。

#### 第二步：虚拟页号位数

$$
32-12=20
$$

#### 第三步：页表项数量

$$
2^{20}
$$

#### 第四步：页表大小

$$
2^{20}\times4=2^{22}\text{ B}
$$

所以：

$$
\boxed{4\text{ MiB}}
$$

这里的 4 MiB 指的是页表本身的最大存储开销，不是数据页面大小。

### 3. 页表项地址怎么求？

假设：

- 页表起始物理地址为 $B$；
- 查找虚页号 $p$；
- 每个页表项占 $E$ 字节。

则：

$$
\boxed{PTEAddr=B+pE}
$$

例如：

- 页表起始物理地址 `0x200000`；
- 虚页号 8；
- 页表项 4 B。

那么：

$$
PTEAddr=0x200000+8\times4
$$

$$
\boxed{PTEAddr=0x200020}
$$

这是页表项本身的物理地址。

不是该虚页中数据的物理地址。

#### 四个概念必须分清

| 名称            | 含义          |
| ------------- | ----------- |
| 虚拟页号 VPN      | 需要查询哪个虚页    |
| 页表项地址 PTEAddr | 映射信息存放在哪里   |
| 物理页框号 PFN     | 数据页映射到哪个物理框 |
| 数据物理地址 PA     | 最终访问哪个物理字节  |

很多 408 大题的难点并不是公式复杂，而是题目同时询问这些不同层次的地址。

## 七、多级页表——408 综合大题重点

### 1. 为什么需要多级页表？

仍以刚才的系统为例：

- 32 位虚拟地址；
- 页面大小 4 KB；
- 完整单级页表需要 4 MiB。

假设一个进程实际只用几页内存。

如果还为它预留完整的大页表，就很浪费。

因此把页表本身分级管理。

#### 单级页表

```text
一个大页表

[页0][页1][页2] ... [页1048575]
```

#### 二级页表

```text
          页目录
             │
      ┌──────┼──────┐
      ↓      ↓      ↓
    页表A   页表B   页表C
      │      │      │
      ↓      ↓      ↓
    物理页框 物理页框 物理页框
```

多级页表的主要目的：

减少稀疏地址空间中的页表空间浪费，降低连续存储大页表的要求。

但不意味着转换地址一定更快。

### 2. 经典 32 位二级页表

这是必须熟记的模型。

已知：

- 32 位虚拟地址；
- 4 KB 页面；
- 4 B 页表项；
- 每张二级页表占一页。

#### 第一步：确定偏移位数

$$
4\text{ KB}=2^{12}\text{ B}
$$

偏移占 12 位。

#### 第二步：每张页表容纳多少表项？

$$
\frac{4096}{4}=1024=2^{10}
$$

所以二级页表索引占 10 位。

#### 第三步：剩下的位数

$$
32-12-10=10
$$

因此地址结构为：

```text
┌──────────┬──────────┬────────────┐
│ 页目录号 │ 页表索引 │ 页内偏移    │
│  10位    │  10位    │   12位     │
└──────────┴──────────┴────────────┘
```

即：

$$
\boxed{10+10+12=32}
$$

#### 第四步：每张二级页表覆盖多少虚拟地址？

每张表有 1024 项。

每项映射一个 4 KB 页面。

所以：

$$
1024\times4\text{ KB} =\boxed{4\text{ MiB}}
$$

因此每一个页目录项对应的二级页表，可以管理 4 MiB 虚拟地址范围。

### 3. 2015 年第 46 题：完整二级页表占多少页？

题目给定：

```text
页目录号10位 | 页表索引10位 | 偏移12位
```

每个页目录项、页表项均占 4 B。

#### 第一步：页目录大小

目录项共有：

$$
2^{10}=1024
$$

个。

页目录总大小：

$$
1024\times4=4096\text{ B}
$$

所以页目录占 1 页。

#### 第二步：二级页表数量

最多：

$$
2^{10}=1024
$$

张。

每张二级页表恰好占一页。

#### 第三步：总大小

$$
1+1024=\boxed{1025\text{ 页}}
$$

这是完整覆盖整个虚拟地址空间时的上界。

如果实际只使用很少一部分虚拟地址，就不必建立所有二级页表。

#### 原题的另一重要考点

虚拟地址：

```text
01000000H
01112048H
```

问：它们涉及几张不同的二级页表？

页目录号计算：

$$
PD=VA\gg22
$$

两个地址的目录号都是 4。

因此：

$$
\boxed{\text{只涉及一张二级页表}}
$$

注意：

“涉及一张二级页表”不等于“只进行一次查表访存”。

它们是两个不同概念。

### 4. 多级页表的访存次数

假设不使用 TLB、Cache，并且页表和数据都已经在主存中。

#### 单级页表

```text
访问页表
    ↓
访问目标数据
```

共：

$$
\boxed{2\text{ 次主存访问}}
$$

#### 二级页表

```text
访问页目录项
      ↓
访问二级页表项
      ↓
访问目标数据
```

共：

$$
\boxed{3\text{ 次主存访问}}
$$

#### 三级页表

```text
一级页表
    ↓
二级页表
    ↓
三级页表
    ↓
目标数据
```

共：

$$
\boxed{4\text{ 次主存访问}}
$$

一般：

$$
\boxed{k\text{ 级页表}\Rightarrow k+1\text{ 次主存访问}}
$$

上述结论基于没有 TLB、无 Cache 优化、数据页驻留且各次访问串行的典型教学模型。

## 八、2020 年第 46 题：二维数组 + 二级页表综合

这是一道非常值得反复做的真题。

它把数据结构、C 语言数组、组成原理和操作系统地址转换结合到了一起。

### 1. 题目条件

某 32 位系统采用二级页表：

```text
10位目录号 | 10位页表索引 | 12位页内偏移
```

页目录项和页表项均为 4 B。

程序中：

```c
int a[1024][1024];
```

数组起始虚拟地址为：

```text
10800000H
```

每个元素 4 B。

页目录起始物理地址为：

```text
00201000H
```

求 `a[1][2]`：

1. 虚拟地址。
2. 页目录号和页表索引。
3. 页目录项物理地址。
4. 若二级页表所在页框号为 `00301H`，求对应 PTE 的物理地址。

### 2. 求数组元素虚拟地址

C 语言二维数组按行优先存储。

对于：

```c
int a[M][N];
```

元素 `a[i][j]` 相对于首地址的字节偏移为：

$$
\Delta=(iN+j)\times sizeof(int)
$$

这里：

$$
\Delta=(1\times1024+2)\times4
$$

$$
=1026\times4=4104
$$

转换为十六进制：

$$
4104=0x1008
$$

所以：

$$
VA=0x10800000+0x1008
$$

$$
\boxed{VA=0x10801008}
$$

### 3. 求页目录号

高 10 位是页目录号：

$$
PD=VA\gg22
$$

得到：

$$
\boxed{PD=0x42}
$$

### 4. 求二级页表索引

$$
PT=(VA\gg12)\bmod2^{10}
$$

得到：

$$
\boxed{PT=1}
$$

页内偏移：

$$
\boxed{d=0x008}
$$

### 5. 求页目录项物理地址

公式：

$$
PDEAddr=PDBR+PD\times E
$$

因此：

$$
PDEAddr=0x00201000+0x42\times4
$$

$$
=0x00201000+0x108
$$

$$
\boxed{PDEAddr=0x00201108}
$$

### 6. 求二级页表项物理地址

已知二级页表所在物理页框号：

$$
PFN=0x00301
$$

页大小是：

$$
0x1000
$$

所以二级页表物理基址：

$$
PTBase=0x00301\times0x1000
$$

$$
=0x00301000
$$

二级页表索引为 1，每项 4 B：

$$
PTEAddr=0x00301000+1\times4
$$

$$
\boxed{PTEAddr=0x00301004}
$$

#### 本题最终结果

| 所求量       | 结果          |
| --------- | ----------- |
| 数组元素虚拟地址  | `10801008H` |
| 页目录号      | `042H`      |
| 二级页表索引    | `001H`      |
| 页目录项物理地址  | `00201108H` |
| 二级页表项物理地址 | `00301004H` |

注意，本题没有提供最终数据页 PTE 中保存的物理页框号。

所以不能进一步算出 `a[1][2]` 数据本身的物理地址。

很多同学把最后求出的 PTE 地址直接当成数组元素的物理地址，这是严重的概念错误。

### 7. 数组为什么适合按行遍历？

一行有：

$$
1024\times4=4096\text{ B}
$$

恰好是一页。

按行遍历：

```c
for (int i = 0; i < 1024; i++)
    for (int j = 0; j < 1024; j++)
        use(a[i][j]);
```

相邻访问通常只相差 4 B。

因此一页调入后，可以连续访问其中的 1024 个元素。

而按列遍历：

```c
for (int j = 0; j < 1024; j++)
    for (int i = 0; i < 1024; i++)
        use(a[i][j]);
```

相邻访问相差：

$$
1024\times4=4096\text{ B}
$$

也就是一页。

如果可用页框较少，按列遍历可能频繁在不同页面之间跳跃，造成大量缺页。

因此：

按行遍历空间局部性更好。

不过，是否一定发生更多缺页，还取决于实际页框数、置换算法和初始驻留情况。

## 九、TLB 快表与有效访存时间

### 1. 为什么需要 TLB？

分页地址转换要访问页表。

如果每次访存都先查页表，就会增加内存访问次数。

TLB（Translation Lookaside Buffer）用于缓存近期使用的地址转换结果。

可以把它理解为：

页表在地址转换路径上的高速缓存。

典型逻辑过程：

```text
CPU产生虚拟地址
        ↓
     查询TLB
     ┌──┴──┐
   命中   未命中
    ↓       ↓
  得到PFN  查询页表
    │       ↓
    │    得到PFN
    └──┬────┘
       ↓
   拼接物理地址
       ↓
     访问数据
```

### 2. TLB 与页表、Cache 的区别

| 结构    | 缓存内容         | 主要作用    |
| ----- | ------------ | ------- |
| 页表    | 页到物理页框的映射及状态 | 地址转换、保护 |
| TLB   | 近期使用的地址转换信息  | 加速地址转换  |
| Cache | 指令或数据块       | 加速数据访问  |

特别重要：

$$
\boxed{\text{TLB Miss}\neq\text{Page Fault}}
$$

<Callout type="warn" title="TLB 未命中不等于缺页">

TLB 未命中，只说明缓存中没有所需映射。

</Callout>

但页面仍然可能位于主存。

只有进一步检查发现页面不在内存，才需要进行相应的缺页处理。

### 3. TLB 有效访存时间公式

设：

- TLB 查询时间为 $\varepsilon$；
- 主存访问时间为 $t$；
- TLB 命中率为 $\alpha$。

假设：

- 单级页表；
- 不考虑缺页；
- 不考虑 Cache；
- TLB 与主存访问串行。

#### 情况一：TLB 命中

```text
查TLB
  ↓
访问数据
```

时间：

$$
T_1=\varepsilon+t
$$

#### 情况二：TLB 未命中

```text
查TLB
  ↓
查页表
  ↓
访问数据
```

时间：

$$
T_2=\varepsilon+2t
$$

#### 平均有效访存时间

根据加权平均：

$$
EAT=\alpha T_1+(1-\alpha)T_2
$$

代入：

$$
EAT=\alpha(\varepsilon+t)+(1-\alpha)(\varepsilon+2t)
$$

化简：

$$
\boxed{EAT=\varepsilon+(2-\alpha)t}
$$

这是本章需要掌握的经典公式之一。

### 4. 教学例题：计算 TLB 平均访存时间

已知：

$$
t=100\text{ ns}
$$

$$
\varepsilon=10\text{ ns}
$$

$$
\alpha=0.9
$$

求平均有效访存时间。

代入：

$$
EAT=10+(2-0.9)\times100
$$

$$
=10+110
$$

$$
\boxed{120\text{ ns}}
$$

如果没有 TLB，单级页表需要两次主存访问：

$$
T=2\times100=200\text{ ns}
$$

所以快表显著降低了平均地址转换开销。

### 5. 多级页表 + TLB

如果采用 $k$ 级页表，且未命中 TLB 时需要完整访问全部 $k$ 级页表：

TLB 命中：

$$
T_1=\varepsilon+t
$$

TLB 未命中：

$$
T_2=\varepsilon+(k+1)t
$$

因此：

$$
\boxed{ EAT=\alpha(\varepsilon+t) +(1-\alpha)[\varepsilon+(k+1)t] }
$$

注意，这些公式必须根据题设调整。

如果题目指出 TLB 查询与 Cache 查询并行、页表项可能缓存命中，或者缺页处理包含部分额外访问，就必须重新分析时间路径。

不要把经典 EAT 公式当成所有计算机都通用的固定公式。

## 十、分段管理与段页式管理

前面讲过，分页是按固定大小把地址空间机械划分。

但程序本身是有逻辑结构的，例如：

```text
一个程序
├── 主函数代码
├── 其他函数代码
├── 全局变量
├── 动态分配区域
└── 栈
```

如果希望按照这些逻辑结构分别管理，就可以使用分段思想。

### 1. 分段管理

分段把程序的逻辑地址空间划分成长度可以不同的段。

例如：

```text
段0：代码段，20KB
段1：数据段，12KB
段2：栈段，8KB
```

一个段内部通常在物理内存中连续存放，但不同段可以分散到不同物理区域。

#### 分段逻辑地址

一般写成：

$$
\boxed{(S,W)}
$$

其中：

- $S$：段号；
- $W$：段内偏移。

#### 段表的内容

| 段号 | 段基址   | 段长   |
| -- | ----- | ---- |
| 0  | 4000  | 1000 |
| 1  | 9000  | 2000 |
| 2  | 15000 | 3000 |

假设 CPU 访问：

$$
(1,500)
$$

先检查段号 1 是否有效。

然后检查偏移：

$$
0\le500<2000
$$

成立。

所以：

$$
PA=9000+500
$$

$$
\boxed{PA=9500}
$$

#### 分段地址转换公式

$$
\boxed{PA=Base[S]+W}
$$

前提是：

$$
\boxed{0\le W<Length[S]}
$$

必须先检查偏移是否合法。

### 2. 2016 年真题：段越界

题目给出段表：

| 段号 | 段长  | 内存起始地址 | 状态   |
| -- | --- | ------ | ---- |
| 0  | 100 | 6000   | 在内存  |
| 1  | 200 | —      | 不在内存 |
| 2  | 300 | 4000   | 在内存  |

现在访问：

$$
(2,400)
$$

很多人直接计算：

$$
4000+400=4400
$$

然后认为结果为 4400。

这是错误的。

因为段 2 的段长为：

$$
300
$$

合法偏移范围是：

$$
0\le W<300
$$

而题目给出：

$$
W=400
$$

越界。

因此答案是：

$$
\boxed{\text{段越界异常}}
$$

一旦地址非法，就不能正常完成地址转换。

### 3. 分页与分段的区别

| 对比       | 分页        | 分段        |
| -------- | --------- | --------- |
| 划分依据     | 固定大小      | 程序逻辑      |
| 大小       | 页面等大      | 段长可以不同    |
| 是否体现逻辑结构 | 一般不直接体现   | 体现        |
| 物理存储     | 页可离散      | 段内通常连续    |
| 典型碎片     | 内部碎片      | 外部碎片      |
| 地址结构     | 页号 + 页内偏移 | 段号 + 段内偏移 |
| 共享与保护    | 可以按页实现    | 按逻辑段实现较自然 |

#### 2019 年真题：共享段

两个进程共享同一个物理段。

问：它们必须使用相同的段号吗？

答案：不必须。

例如：

```text
进程A：
段号2 ──┐
         ├── 共享物理段
进程B：  │
段号5 ──┘
```

共享的是物理内存内容，不是逻辑段号。

这与分页系统中“不同虚页可以映射同一物理页框”的思想完全一致。

### 4. 段页式管理

段页式就是：

先分段，再对每段分页。

例如：

```text
程序
├── 代码段
│   ├── 页0
│   ├── 页1
│   └── 页2
│
├── 数据段
│   ├── 页0
│   └── 页1
│
└── 栈段
    ├── 页0
    └── 页1
```

段页式逻辑地址由三部分组成：

$$
\boxed{(S,P,W)}
$$

- $S$：段号；
- $P$：段内页号；
- $W$：页内偏移。

#### 地址转换过程

```text
段号S
  ↓
查段表
  ↓
得到该段页表的位置
  ↓
用页号P查询页表
  ↓
得到物理页框号F
  ↓
与页内偏移W组合
  ↓
物理地址
```

计算：

$$
\boxed{PA=F\times PageSize+W}
$$

在没有 TLB、Cache 且相关表和数据均驻留的典型模型中，访问段表、页表、目标数据共需要 3 次主存访问。

#### 段页式的碎片

段内再次分页，因此：

- 不再要求整个段连续占据物理内存；
- 通常没有分页意义上的外部碎片；
- 段的最后一页可能装不满，存在内部碎片。

## 十一、虚拟存储器——理解整个第三章的关键

### 1. 虚拟存储为什么出现？

此前讲的基本分页管理，可以把一个进程分散存放在内存中。

但在基本分页模型下，程序运行前仍可能要求全部页面装入内存。

假设：

- 一个程序需要 8 GB 地址空间；
- 系统能够分配给它的物理内存只有 2 GB；
- 程序当前实际上只使用其中 500 MB。

有没有必要把全部 8 GB 的内容都装入内存？

没有。

虚拟存储的基本思想是：

> 只把当前需要的部分放进物理内存，其他部分按需调入。

这就是请求分页等机制的基础。

### 2. 虚拟存储的三个基本特征

408 教材通常概括为：

| 特征  | 含义                   |
| --- | -------------------- |
| 多次性 | 程序可以分多次装入内存          |
| 对换性 | 运行过程中可以换入、换出页面       |
| 虚拟性 | 进程可见地址空间可以大于实际可用物理内存 |

#### 虚拟存储器的容量

假设 CPU 使用 32 位虚拟地址，按字节编址。

理论地址范围最多为：

$$
2^{32}\text{ B}=4\text{ GiB}
$$

所以，虚拟存储器并不是无限大。

还需要考虑：

- 虚拟地址位数；
- 操作系统的地址空间布局；
- 实际存储资源；
- 页面后备存储机制。

特别注意：

不能简单认为虚拟存储器容量等于物理内存容量加硬盘容量。

虚拟地址空间上限首先受可表示的虚拟地址范围约束。

### 3. 局部性原理

这是虚拟存储能够有效运行的根本依据。

<Tabs items={['时间局部性', '空间局部性']} defaultIndex={0}>

<Tab value="时间局部性">

近期访问过的数据，未来可能再次访问。

例如：

```c
for (int i = 0; i < 100000; i++) {
    sum += x;
}
```

变量 `x` 和循环指令会反复被使用。

</Tab>

<Tab value="空间局部性">

访问一个地址后，附近地址可能很快被访问。

例如：

```c
for (int i = 0; i < 1000; i++) {
    sum += a[i];
}
```

数组元素通常连续存储，顺序访问表现出良好的空间局部性。

</Tab>

</Tabs>

#### 模拟选择题：二分查找与局部性

模拟题：哪种程序技术的典型访问模式不利于请求分页发挥空间局部性优势？

选项包括：

- 堆栈；
- 线性搜索；
- 向量运算；
- 二分搜索。

答案是：二分搜索。

原因是二分搜索在大型有序数组中不断跳转到不同位置，早期访问可能跨越较远的页面。

但要特别注意：

这不意味着二分搜索的总体运行速度一定比线性搜索慢。

这里比较的是访问模式的空间局部性，而不是算法总体时间复杂度。

## 十二、请求分页与缺页异常

### 1. 请求分页是什么？

请求分页允许一个进程只装入部分页面。

访问已驻留页面时：

```text
CPU发出虚拟地址
      ↓
查询地址映射
      ↓
目标页在主存
      ↓
正常访问
```

访问尚未驻留的合法页面时：

```text
CPU发出虚拟地址
      ↓
检查页表
      ↓
页面不在内存
      ↓
产生缺页异常
      ↓
操作系统调入页面
      ↓
更新映射
      ↓
重新执行故障指令
```

### 2. 缺页异常处理全过程

必须掌握以下步骤：

<Steps>

<Step>

    ### 发现缺页并进入异常处理

    CPU 访问虚拟地址，页表状态表明页面未就绪，触发缺页异常，内核检查地址合法性和访问权限。

</Step>

<Step>

    ### 确定页面来源与目标页框

    定位后备存储或页面初始化来源；寻找空闲页框，必要时选择牺牲页，并按需写回脏页。

</Step>

<Step>

    ### 装入页面并更新映射

    把目标页调入内存或完成建立，更新页表及 TLB 相关状态。

</Step>

<Step>

    ### 恢复现场并重新执行

    恢复进程执行环境，通常重新执行引起缺页的指令。

</Step>

</Steps>

#### 三个必须分清的概念

缺页异常

当前指令访问尚未驻留的合法页面，通常是同步异常。

外部中断

如磁盘 I/O 完成产生的中断，通常是异步事件。

非法地址访问

访问越界或权限不允许，不能简单通过调页解决。

### 3. 2022 年真题：缺页不一定置换

题目问：

某进程访问的页不在内存，发生缺页异常。缺页处理过程中，不一定包含哪个操作？

选项包括：

A. 淘汰已有页面\
B. 建立页号与页框的关系\
C. 将目标页面从外存读入\
D. 修改页表状态

答案：A。

为什么？

假设：

```text
当前有3个页框

页框1：页面A
页框2：页面B
页框3：空闲
```

现在要访问页面 C。

虽然 C 不在内存，会发生缺页，但可以直接使用页框 3。

所以：

$$
\boxed{\text{缺页次数}\neq\text{置换次数}}
$$

这是极高频考点。

## 十三、驻留集、页框分配与置换范围

### 1. 驻留集

驻留集指的是当前真正位于主存中的页面集合。

假设一个进程共有 8 页：

$$
\{0,1,2,3,4,5,6,7\}
$$

当前实际驻留：

$$
\{0,1,3,5\}
$$

那么驻留集大小为：

$$
\boxed{4}
$$

### 2. 固定分配与可变分配

#### 固定分配

为进程分配的页框数量在其运行期间保持不变。

例如始终为进程分配 3 个页框。

如果三个页框都已占满，再次缺页时，需要在允许的范围内淘汰页面。

#### 可变分配

进程获得的页框数量可以根据运行状态动态变化。

例如：

```text
开始：3个页框
   ↓
缺页率高
   ↓
增加到5个页框
   ↓
活跃页面减少
   ↓
回收部分页框
```

### 3. 局部置换与全局置换

#### 局部置换

进程发生缺页时，只能从该进程自身的可置换页面中选择牺牲页。

#### 全局置换

允许在系统范围内选择符合条件的牺牲页面。

因此进程 A 缺页时，可能导致进程 B 的某个页面被淘汰。

### 4. 2015 年真题：分配策略组合

| 分配策略 | 置换策略 | 408 教材中的典型结论 |
| ---- | ---- | ------------ |
| 固定分配 | 局部置换 | 可以           |
| 固定分配 | 全局置换 | 通常不采用        |
| 可变分配 | 局部置换 | 可以           |
| 可变分配 | 全局置换 | 可以           |

为什么固定分配和全局置换不能作为经典组合？

固定分配要求每个进程持有的页框数量保持固定。

全局置换可能把其他进程的页框重新分配给当前进程，导致每个进程持有的页框数变化。

因此与经典固定分配策略矛盾。

这就是 2015 年对应选择题的考点。

## 十四、页面置换算法——全章第二个核心

这是第三章最需要动手训练的部分。

要掌握：

- FIFO；
- OPT；
- LRU；
- CLOCK；
- 改进型 CLOCK；
- Belady 异常；
- 缺页次数、置换次数与写回次数。

### 1. FIFO：先进先出

FIFO 的规则是：

淘汰最早装入内存的页面。

注意：不是最早访问的页面。

例如三个页框中：

```text
装入顺序：

A → B → C
```

现在访问新页面 D，三个页框已满。

FIFO 淘汰 A：

```text
B → C → D
```

即使 A 刚刚被访问过，FIFO 仍可能淘汰 A。

FIFO 命中时，不改变装入先后顺序。

### 2. OPT：最佳页面置换

OPT 的规则：

淘汰未来最长时间不再访问的页面。

假设当前驻留：

$$
\{1,2,3\}
$$

未来访问：

```text
2, 3, 2, 4, 3, 1
```

现在发生缺页，需要淘汰一个页面。

向未来看：

- 页面 2：下一次访问很近；
- 页面 3：稍后访问；
- 页面 1：很久之后才会访问。

因此淘汰页面 1。

OPT 的特点：

- 在已知完整未来访问序列的模型下，缺页次数最少；
- 实际运行时通常无法准确预知未来；
- 主要作为算法比较的理论基准。

### 3. LRU：最近最久未使用

LRU 的规则：

淘汰过去最长时间没有被访问的页面。

注意与 OPT 的区别。

| 算法   | 比较方向  |
| ---- | ----- |
| OPT  | 看未来   |
| LRU  | 看过去   |
| FIFO | 看装入时间 |

#### LRU 教学例题

当前驻留：

```text
A B C
```

最近访问顺序：

```text
A → B → C → A
```

现在访问 D，发生缺页。

过去最近的访问顺序：

- A：刚访问；
- C：比 A 早；
- B：最久未访问。

所以淘汰：

$$
\boxed{B}
$$

LRU 中，即使页面命中，也必须更新最近使用顺序。

### 4. FIFO 与 LRU 的完整模拟

以 2027 王道模拟第 6 套第 45 题为例。

题目给出：

页面大小 100 B。

虚拟地址依次为：

```text
10, 11, 104, 170, 73, 309,
185, 245, 246, 434, 458, 364
```

为进程分配 2 个页框，初始为空。

#### 第一步：把地址转换为页号

公式：

$$
VPN=\left\lfloor\frac{VA}{100}\right\rfloor
$$

因此页面访问串为：

```text
0, 0, 1, 1, 0, 3, 1, 2, 2, 4, 4, 3
```

这一步非常重要。

页面置换算法处理的是页面访问串，不是原始字节地址串。

#### 第二步：分别模拟

表中的两个页框状态均按“旧 → 新”排列，但“旧”的含义不同：FIFO 指最早装入，LRU 指最久未访问。

| 次序 | 访问页 | FIFO 状态 | FIFO 缺页 | LRU 状态 | LRU 缺页 |
| -- | --- | ------- | ------- | ------ | ------ |
| 1  | 0   | 0       | 是       | 0      | 是      |
| 2  | 0   | 0       | 否       | 0      | 否      |
| 3  | 1   | 0,1     | 是       | 0,1    | 是      |
| 4  | 1   | 0,1     | 否       | 0,1    | 否      |
| 5  | 0   | 0,1     | 否       | 1,0    | 否      |
| 6  | 3   | 1,3     | 是       | 0,3    | 是      |
| 7  | 1   | 1,3     | 否       | 3,1    | 是      |
| 8  | 2   | 3,2     | 是       | 1,2    | 是      |
| 9  | 2   | 3,2     | 否       | 1,2    | 否      |
| 10 | 4   | 2,4     | 是       | 2,4    | 是      |
| 11 | 4   | 2,4     | 否       | 2,4    | 否      |
| 12 | 3   | 4,3     | 是       | 4,3    | 是      |

结果：

$$
\boxed{FIFO=6\text{ 次缺页}}
$$

$$
\boxed{LRU=7\text{ 次缺页}}
$$

#### 这里有一个特别重要的结论

LRU 并不保证对任意访问串、任意相同页框数，都比 FIFO 缺页更少。

在这道题中：

$$
6<7
$$

FIFO 反而更少。

所以不能把“LRU 通常更好”误解成“LRU 必然不劣于 FIFO”。

OPT 才是在给定完整访问序列和相同资源条件下的理论最优算法。

### 5. 缺页次数与置换次数

假设：

- 初始有 3 个空闲页框；
- 页框数量固定；
- 访问过程中一共发生 10 次缺页。

前三次导致不同页面装入时，可以使用空闲页框。

从第 4 次缺页开始，才需要置换。

因此：

$$
10-3=\boxed{7\text{ 次置换}}
$$

一般情况下，如果初始 $m$ 个页框全空，页面访问过程中共发生 $F$ 次缺页，且装满后不再增减页框：

$$
\boxed{R=\max(0,F-m)}
$$

其中 $R$ 是实际发生的页面置换次数。

这不是所有内存管理策略都通用的公式，而是固定页框、初始全空的经典模型。

## 十五、Belady 异常

### 1. 什么是 Belady 异常？

直觉上，给进程更多页框，应该减少缺页。

但是 FIFO 等某些页面置换算法可能出现：

页框数增加，缺页次数反而增加。

这就是 Belady 异常。

### 2. 经典教学访问串

```text
1 2 3 4 1 2 5 1 2 3 4 5
```

采用 FIFO：

- 3 个页框时：9 次缺页；
- 4 个页框时：10 次缺页。

因此：

$$
\boxed{9<10}
$$

页框数增加了，但缺页次数也增加了。

#### 哪些算法会出现？

| 算法    | 是否可能发生 Belady 异常 |
| ----- | ---------------- |
| FIFO  | 可能               |
| OPT   | 不会               |
| LRU   | 不会               |
| CLOCK | 不具有 LRU 的栈性质保证   |

为什么 OPT、LRU 不会？

因为它们具有栈性质。

在经典相同访问序列的模型中，较少页框所形成的页面集合会包含在较多页框对应的集合内，因此增加页框不会导致缺页数上升。

#### 2014 年真题

选项：

I. LRU\
II. FIFO\
III. OPT

问哪些算法可能出现 Belady 异常？

答案：

$$
\boxed{\text{仅 II}}
$$

## 十六、CLOCK 时钟页面置换算法

CLOCK 是对 LRU 的一种近似实现。

精确维护每个页面的完整使用时间可能比较昂贵。

因此 CLOCK 利用访问位和循环扫描指针进行近似判断。

### 1. 基本规则

每个页面设置访问位 $R$。

- 页面被访问后，设置 $R=1$；
- 需要置换时，扫描指针循环寻找；
- 遇到 $R=1$，清零并继续；
- 遇到 $R=0$，选择该页淘汰。

例如：

```text
             页A(R=1)
           /           \
    页D(R=0)           页B(R=1)
           \           /
             页C(R=1)
```

假设指针从 A 开始：

1. A 的 $R=1$，改为 0，指针移动。
2. B 的 $R=1$，改为 0，指针移动。
3. C 的 $R=1$，改为 0，指针移动。
4. D 的 $R=0$，淘汰 D。

#### 必须注意

普通页面命中时，通常只是更新访问位：

$$
R\leftarrow1
$$

不会因为一次普通页面命中就自动移动 CLOCK 置换指针。

### 2. 2010 年第 46 题：FIFO 与 CLOCK

这是操作系统非常经典的综合题。

#### 题目条件

- 逻辑地址空间：64 KB；
- 物理地址空间：64 KB；
- 页面大小：1 KB；
- 为进程固定分配 4 个页框。

驻留状态：

| 虚页号 | 物理页框号 | 装入时刻 | 访问位 |
| --- | ----- | ---- | --- |
| 0   | 7     | 130  | 1   |
| 1   | 4     | 230  | 1   |
| 2   | 2     | 200  | 1   |
| 3   | 9     | 160  | 1   |

现在访问逻辑地址：

```text
17CAH
```

CLOCK 指针指向物理页框 2，具体循环顺序按照题图。

#### 第一问：求虚页号与偏移

页面大小：

$$
1\text{ KB}=1024\text{ B}=0x400
$$

计算：

$$
0x17CA=5\times0x400+0x3CA
$$

所以：

$$
\boxed{VPN=5}
$$

$$
\boxed{d=0x3CA}
$$

页 5 不在驻留集中。

因此发生缺页。

#### 第二问：FIFO

各页面装入时刻：

```text
页0：130
页1：230
页2：200
页3：160
```

最早装入的是页 0。

页 0 使用物理页框 7。

所以页 5 换入页框 7。

物理地址：

$$
PA=7\times0x400+0x3CA
$$

$$
=0x1C00+0x3CA
$$

$$
\boxed{PA=0x1FCA}
$$

#### 第三问：CLOCK

题目给定指针从页框 2 开始。

所有页面的访问位最初均为 1。

因此第一圈扫描中，全部访问位都会被清为 0。

扫描再次回到页框 2 时：

$$
R=0
$$

于是淘汰页框 2 中的页面。

页 5 被装入页框 2。

计算：

$$
PA=2\times0x400+0x3CA
$$

$$
=0x800+0x3CA
$$

$$
\boxed{PA=0x0BCA}
$$

#### 最终答案

| 问题         | 结果      |
| ---------- | ------- |
| 虚页号        | 5       |
| FIFO 物理地址  | `1FCAH` |
| CLOCK 物理地址 | `0BCAH` |

这道题说明：

相同的虚拟地址，在不同页面置换算法下，最终可能对应不同物理地址。

原因是目标页面使用了不同的物理页框。

## 十七、改进型 CLOCK

普通 CLOCK 主要考虑页面近期有没有被访问。

但还有一个因素很重要：

页面有没有被修改过。

如果页面没有修改，通常可以直接淘汰，因为后备存储中的副本仍然有效。

如果页面已经修改，淘汰前可能需要写回磁盘。

所以改进型 CLOCK 使用两个状态位：

- $R$：访问位；
- $M$：修改位。

### 1. 四类页面

| $R$ | $M$ | 含义        | 淘汰优先级 |
| ------- | ------- | --------- | ----- |
| 0       | 0       | 未近期访问、未修改 | 最高    |
| 0       | 1       | 未近期访问、已修改 | 次高    |
| 1       | 0       | 近期访问、未修改  | 较低    |
| 1       | 1       | 近期访问、已修改  | 最低    |

典型优先级：

$$
\boxed{ (0,0)\rightarrow(0,1)\rightarrow(1,0)\rightarrow(1,1) }
$$

为什么优先选择：

$$
(0,0)
$$

因为它既不活跃，又不需要额外写回。

### 2. 改进型 CLOCK 的扫描

408 中常见的教材实现可分为四轮理解：

第一轮：寻找 $(0,0)$，不修改访问位。

第二轮：寻找 $(0,1)$，扫描时将经过的访问位 1 清零。

第三轮：重新寻找 $(0,0)$。

第四轮：必要时寻找 $(0,1)$。

具体扫描位置和状态更新要服从题目给定的实现规则，不能只按四类的静态优先级猜答案。

#### 2016 年真题

问四种页面类型的淘汰次序。

答案：

$$
\boxed{(0,0),(0,1),(1,0),(1,1)}
$$

## 十八、2009 年第 46 题：TLB + LRU + 缺页时间综合

这一题非常值得重点掌握。

它同时考查：

- 虚拟地址拆分；
- TLB 查询；
- 页表；
- 缺页异常；
- LRU；
- 指令重新执行；
- 物理地址计算。

### 1. 题目条件

页表如下：

| 虚页号 | 物理页框号  | 有效位 |
| --- | ------ | --- |
| 0   | `101H` | 1   |
| 1   | —      | 0   |
| 2   | `254H` | 1   |

其他条件：

- 页面大小：4 KB；
- 主存访问一次：100 ns；
- TLB 查询一次：10 ns；
- 缺页处理耗时：$10^8$ ns；
- 固定分配 2 个页框；
- 局部 LRU 置换；
- TLB 初始为空；
- 缺页处理时间包含更新页表和 TLB；
- 处理完后重新执行故障指令。

访问顺序：

```text
2362H
1565H
25A5H
```

### 2. 第一次访问 `2362H`

页面大小：

$$
4\text{ KB}=0x1000
$$

拆分：

$$
0x2362=2\times0x1000+0x362
$$

所以访问虚页 2。

虚页 2 已经在内存中，但 TLB 初始为空。

过程：

```text
查TLB：10ns
    ↓
TLB未命中
    ↓
查主存页表：100ns
    ↓
页面已驻留
    ↓
读取目标数据：100ns
```

总时间：

$$
T_1=10+100+100
$$

$$
\boxed{T_1=210\text{ ns}}
$$

访问完成后，页 2 成为最近使用的页面。

### 3. 第二次访问 `1565H`

拆分：

$$
0x1565=1\times0x1000+0x565
$$

访问虚页 1。

页 1 有效位为 0，发生缺页。

首先：

$$
10+100=110\text{ ns}
$$

然后处理缺页：

$$
10^8\text{ ns}
$$

因为驻留集已满，需要 LRU 页面置换。

此前页 2 刚访问。

因此最近最久未访问的是页 0。

淘汰页 0，让页 1 使用原来的物理页框：

```text
101H
```

缺页处理结束后，故障指令重新执行。

根据题设，此时 TLB 已更新，所以重新执行时：

$$
10+100=110\text{ ns}
$$

因此总时间：

$$
T_2=10+100+10^8+10+100
$$

$$
\boxed{T_2=100000220\text{ ns}}
$$

#### 求物理地址

页 1 现在位于页框：

$$
0x101
$$

页内偏移：

$$
0x565
$$

因此：

$$
PA=0x101\times0x1000+0x565
$$

$$
\boxed{PA=0x101565}
$$

### 4. 第三次访问 `25A5H`

访问虚页 2。

页 2 没有被淘汰，仍然位于主存。

而且此前已经把页 2 的映射加入 TLB。

因此 TLB 命中。

耗时：

$$
T_3=10+100
$$

$$
\boxed{T_3=110\text{ ns}}
$$

#### 最终结果

| 虚地址     | 事件            | 耗时           |
| ------- | ------------- | ------------ |
| `2362H` | TLB 未命中，页面已驻留 | 210 ns       |
| `1565H` | 缺页，LRU 淘汰页 0  | 100000220 ns |
| `25A5H` | TLB 命中        | 110 ns       |

另外：

$$
\boxed{PA(1565H)=101565H}
$$

#### 这道题最重要的启示

一旦发生缺页，必须看题目怎样规定缺页处理费用与故障指令重新执行的费用。

有的题把全部相关费用包含在“缺页处理时间”内。

有的题只给出额外调页开销。

有的题明确要求重新执行一次地址转换和数据访问。

不能统一机械地套某一个公式。

## 十九、缺页率与有效访存时间

### 1. 缺页率

设：

- 共发生 $F$ 次缺页；
- 总页面访问次数为 $N$。

则：

$$
\boxed{p=\frac{F}{N}}
$$

例如：

12 次页面访问中，发生 6 次缺页。

$$
p=\frac6{12}=50\%
$$

### 2. 缺页对性能的影响

正常访存可能只需要几十或几百纳秒。

但是发生需要外存 I/O 的缺页，处理开销可能大得多。

因此，即使缺页率较低，也可能显著拉高平均访存时间。

#### 简化公式

若：

- 正常访问耗时 $T_0$；
- 每次缺页在正常访问基线之外额外增加 $C$；
- 缺页率为 $p$。

则：

$$
\boxed{EAT=T_0+pC}
$$

这里明确假设 $C$ 是相对于正常访存的额外开销。

### 3. 2027 王道模拟：最大缺页率

来自第 6 套第 45 题。

题目条件：

- 没有 TLB；
- 单级页表；
- 每次主存访问 10 ms；
- 正常访存需要查页表和访问数据；
- 每次缺页额外增加 25 ms；
- 平均有效访存时间不超过 22 ms。

求最大缺页率。

#### 第一步：正常访存时间

两次主存访问：

$$
T_0=2\times10=20\text{ ms}
$$

#### 第二步：列平均访存时间

$$
EAT=20+25p
$$

#### 第三步：根据限制求解

$$
20+25p\le22
$$

$$
25p\le2
$$

$$
p\le0.08
$$

所以：

$$
\boxed{p_{\max}=8\%}
$$

#### 这里的高频陷阱

如果题目把缺页处理 25 ms 定义为不包含首次查表和重新执行的时间，那么公式就要改变。

所以最稳妥的做法是：

先列出正常访问和缺页访问的完整事件路径，再计算加权平均。

## 二十、工作集与抖动

### 1. 工作集是什么？

工作集表示某个时间窗口内进程访问过的不同页面集合。

记作：

$$
\boxed{W(t,\Delta)}
$$

其中：

- $t$：当前时刻；
- $\Delta$：工作集窗口长度。

工作集不是简单的“当前已经装入内存的页面”。

工作集描述近期活跃访问需求。

驻留集描述当前实际装入内存的页面。

### 2. 2016 年真题：工作集计算

题目给出页面访问序列：

```text
..., 1, 3, 4, 5, 6, 0, 3, 2, 3, 2,
t,
0, 4, 0, 3, 2, 9, ...
```

工作集窗口大小为 6。

求时刻 $t$ 的工作集。

#### 第一步：向前取最近 6 次访问

```text
6, 0, 3, 2, 3, 2
```

#### 第二步：去重

得到：

$$
\boxed{W(t,6)=\{6,0,3,2\}}
$$

因此工作集大小为：

$$
\boxed{|W(t,6)|=4}
$$

注意：

窗口大小为 6，不代表工作集一定包含 6 个不同页面。

因为窗口中可能重复访问同一个页面。

### 3. 抖动 Thrashing

假设某进程近期经常使用：

$$
\{A,B,C,D,E\}
$$

共 5 个页面。

但是操作系统只给它 2 个页框。

结果：

```text
访问A → 装入A
访问B → 装入B
访问C → 淘汰A
访问D → 淘汰B
访问A → 淘汰C
访问B → 淘汰D
...
```

页面频繁换入、换出。

CPU 花大量时间等待外存 I/O。

这种严重情况称为抖动。

#### 抖动的典型表现

```text
分配页框不足
      ↓
活跃工作集不能驻留
      ↓
缺页率急剧升高
      ↓
页面换入换出频繁
      ↓
进程大量等待I/O
      ↓
CPU利用率下降
      ↓
系统吞吐量下降
```

#### 2011 年真题：怎样解决抖动？

题目给出措施：

I. 撤销部分进程。\
II. 增大磁盘交换区。\
III. 提高进程优先级。

正确答案：

$$
\boxed{\text{仅 I}}
$$

原因：

减少同时驻留的进程数量，可以给剩余进程分配更多物理页框。

而仅仅扩大交换区，并不能解决活跃工作集无法驻留的问题。

### 4. 缺页频率 PFF

PFF（Page Fault Frequency）是一种动态调整页框分配的思路。

基本原则：

- 缺页率过高：考虑增加页框；
- 缺页率很低：可以考虑回收部分页框；
- 系统整体内存不足：可能需要减少多道程序度。

真正的优化目标不是给每个进程尽可能多的页框，而是让有限内存尽可能覆盖活跃工作集。

## 二十一、2012 年第 45 题：页面缓冲与回收链

这道题和普通 FIFO、LRU 不一样。

它考查的是：

页面虽然已经从驻留集被回收，但原物理页框中的内容可能还保留着。

### 1. 题目条件

系统每隔 5 个时间单位扫描一次驻留集。

如果某页面在本轮没有被访问，就回收其页框并加入空闲链尾。

但页框内容在重新分配之前不会立即清空。

初始空闲页框链：

```text
32 → 15 → 21 → 41
```

访问序列：

$$
(1,1),(3,2),(0,4),(0,6),(1,11),(0,13),(2,14)
$$

每个二元组表示：

$$
(\text{页号},\text{访问时刻})
$$

### 2. 初始页面分配

时刻 1：

页面 1 使用页框 32。

时刻 2：

页面 3 使用页框 15。

时刻 4：

页面 0 使用页框 21。

因此：

| 页面 | 页框 |
| -- | -- |
| 1  | 32 |
| 3  | 15 |
| 0  | 21 |

空闲链剩下：

```text
41
```

### 3. 时刻 5 扫描

页面 1、3、0 在前一轮都被访问过。

所以全部保留。

### 4. 时刻 6

访问页面 0。

因此页面 0 在时刻 5～10 期间被访问。

### 5. 时刻 10 扫描

页面 1、3 在当前扫描周期没有被访问。

因此：

- 页框 32 被回收；
- 页框 15 被回收。

空闲链变为：

```text
41 → 32 → 15
```

注意，页框中的旧内容没有立刻被清除。

### 6. 时刻 11

再次访问页面 1。

页面 1 已不在驻留集，但其旧内容仍保存在空闲链中的页框 32 内。

因此可以重新取回页框 32。

不需要重新从磁盘读入原页面内容。

### 7. 时刻 14

访问从未装入过的页面 2。

当前空闲链首为页框 41。

因此页面 2 使用页框 41。

#### 最终答案

| 问题             | 答案 |
| -------------- | -- |
| 时刻 4 页面 0 的页框  | 21 |
| 时刻 11 页面 1 的页框 | 32 |
| 时刻 14 页面 2 的页框 | 41 |

#### 本题的核心意义

不要认为：

> 页面一离开驻留集，它在物理内存中的内容就一定立即被销毁。

有些页面缓冲、回收策略会暂时保留旧内容，利用时间局部性降低后续重新调入的成本。

## 二十二、跨页访问与指令所需页框数

### 1. 一条指令能不能跨页？

能。

例如页面大小为：

$$
4096\text{ B}
$$

某条指令从当前页偏移：

$$
4093
$$

处开始。

指令长度为 6 B。

当前页还剩：

$$
4096-4093=3\text{ B}
$$

所以：

- 前 3 B 在当前页；
- 后 3 B 在下一页。

因此一条指令横跨两个虚拟页面。

### 2. 跨页对象占多少页？

设：

- 起始虚拟地址为 $A$；
- 长度为 $L>0$；
- 页面大小为 $P$。

则：

$$
\boxed{ N= \left\lfloor\frac{A+L-1}{P}\right\rfloor - \left\lfloor\frac{A}{P}\right\rfloor +1 }
$$

该公式非常实用。

可用于：

- 指令跨页；
- 数组跨页；
- 代码段跨页；
- 非页对齐对象的占页数计算。

### 3. 一级间接寻址与最少页框

假设题目规定：

- 一条机器指令跨越两个页面；
- 间接地址位于另一页面；
- 最终操作数又位于一个不同页面；
- 执行过程中这些相关页面需要同时驻留。

那么最少可能需要：

$$
2+1+1=\boxed{4\text{ 个页框}}
$$

但是不能不看条件就认为所有一级间接寻址机器都必须使用 4 个页框。

还需要检查指令是否跨页、操作数是否跨页、页面能否重合及系统执行约束。

## 二十三、2024 年第 45 题：4 MiB 大页综合计算

这道题是近年非常有代表性的地址计算大题。

### 1. 题目条件

- 虚拟地址：32 位；
- 物理地址：32 位；
- 页面大小：4 MiB；
- 页表项大小：4 B；
- 页表起始虚拟地址：`B8C00000H`；
- 页表装入的物理起始地址：`65400000H`。

访问虚拟地址：

```text
12345678H
```

缺页处理完成后，得到物理地址：

```text
BAB45678H
```

要求计算：

1. 对应 PTE 的虚拟地址；
2. 对应 PTE 的物理地址；
3. 更新后的数据页框号；
4. 页表自身所在的虚页号及其映射信息。

### 2. 确定地址结构

因为：

$$
4\text{ MiB}=2^{22}\text{ B}
$$

所以：

```text
页号10位 | 页内偏移22位
```

页号：

$$
VPN=VA\gg22
$$

### 3. 求目标页号

$$
VPN=0x12345678\gg22
$$

得到：

$$
\boxed{VPN=0x48}
$$

### 4. 求 PTE 的虚拟地址

页表起始虚拟地址：

```text
B8C00000H
```

每项 4 B。

目标是第 `48H` 项。

偏移：

$$
0x48\times4=0x120
$$

所以：

$$
PTE_{VA}=0xB8C00000+0x120
$$

$$
\boxed{PTE_{VA}=0xB8C00120}
$$

### 5. 求 PTE 的物理地址

页表装载到：

```text
65400000H
```

对应表项偏移保持为：

```text
120H
```

所以：

$$
PTE_{PA}=0x65400000+0x120
$$

$$
\boxed{PTE_{PA}=0x65400120}
$$

### 6. 求数据页的页框号

物理地址：

```text
BAB45678H
```

页大小：

$$
2^{22}
$$

因此：

$$
PFN=PA\gg22
$$

$$
\boxed{PFN=0x2EA}
$$

### 7. 页表自身也需要被映射

页表的虚拟起始地址：

```text
B8C00000H
```

所在虚页号：

$$
0xB8C00000\gg22
$$

$$
\boxed{VPN_{\text{table}}=0x2E3}
$$

描述该页的页表项虚拟地址：

$$
0xB8C00000+0x2E3\times4
$$

$$
\boxed{0xB8C00B8C}
$$

页表实际位于物理地址：

```text
65400000H
```

所以对应页框号：

$$
0x65400000\gg22
$$

$$
\boxed{PFN_{\text{table}}=0x195}
$$

#### 本题最终答案

| 求解对象             | 结果          |
| ---------------- | ----------- |
| 目标页号             | `048H`      |
| 目标 PTE 虚拟地址      | `B8C00120H` |
| 目标 PTE 物理地址      | `65400120H` |
| 目标数据页框号          | `2EAH`      |
| 页表自身所在虚页号        | `2E3H`      |
| 描述页表自身的 PTE 虚拟地址 | `B8C00B8CH` |
| 页表所在物理页框号        | `195H`      |

#### 这道题的核心考点

必须分清：

- 页表的虚拟地址；
- 页表的物理地址；
- 页表项的虚拟地址；
- 页表项的物理地址；
- 数据页面的页框号；
- 数据页面的物理地址。

这六个量不能混为一谈。

## 二十四、2027 王道模拟：大小页混合管理

来自第 1 套第 46 题。

### 1. 题目背景

一个 32 位系统支持：

- 4 KiB 普通页；
- 4 MiB 大页。

对于普通页：

```text
10位目录号 | 10位页表索引 | 12位偏移
```

对于大页：

```text
10位目录号 | 22位偏移
```

页目录项中的 `Page_Size` 用来判断采用哪种页面大小。

### 2. 访问次数

若没有 TLB，且相关页面已驻留：

普通 4 KiB 页：

```text
页目录 → 二级页表 → 数据
```

需要：

$$
\boxed{3\text{ 次主存访问}}
$$

大页：

```text
页目录 → 数据
```

需要：

$$
\boxed{2\text{ 次主存访问}}
$$

因为大页绕过二级页表。

### 3. 大页物理地址

题中访问虚拟地址：

```text
015F123DH
```

根据对应页目录项：

- 采用 4 MiB 大页；
- 大页物理页框号为 `163H`。

大页偏移为低 22 位：

```text
1F123DH
```

所以：

$$
PA=(0x163\ll22)+0x1F123D
$$

$$
\boxed{PA=0x58DF123D}
$$

#### 这类题最大陷阱

普通页框号要左移：

$$
12\text{ 位}
$$

大页页框号要左移：

$$
22\text{ 位}
$$

绝对不能统一按 4 KiB 的偏移长度处理。

## 二十五、2027 王道模拟：缺页、脏页与进程调度

来自第 5 套第 46 题。

这是跨章节综合题，需要联系操作系统第二章的进程管理。

### 1. 题目条件

高优先级进程 P 访问：

```text
0x00405ABC
```

页面大小为 4 KB。

页面状态：

| 虚页号      | 最近访问时刻      | 驻留 | 脏页 |
| -------- | ----------- | -- | -- |
| `00120H` | $t_0-9$ | 是  | 是  |
| `00405H` | —           | 否  | —  |
| `00A10H` | $t_0-3$ | 是  | 否  |
| `00B00H` | $t_0-7$ | 是  | 否  |

采用局部 LRU。

没有空闲页框。

P 缺页等待磁盘时，低优先级进程 Q 运行。

系统使用可抢占优先级调度。

### 2. 求虚页号与偏移

4 KB 页面：

$$
P=2^{12}
$$

所以：

$$
VPN=0x00405
$$

$$
d=0xABC
$$

### 3. LRU 淘汰哪个页面？

候选页面：

- `00120H`：9 个时间单位前访问；
- `00A10H`：3 个时间单位前访问；
- `00B00H`：7 个时间单位前访问。

最久未访问：

$$
\boxed{00120H}
$$

该页面是脏页。

因此必要时必须先写回后备存储，才能安全复用其页框。

### 4. 进程状态怎样变化？

典型过程：

```text
P运行
  ↓
P发生缺页异常
  ↓
CPU进入内核
  ↓
选择牺牲页并提交相关I/O
  ↓
P阻塞
  ↓
调度Q运行
  ↓
目标页调入完成
  ↓
磁盘中断
  ↓
唤醒P进入就绪态
  ↓
P优先级高，抢占Q
  ↓
P重新执行访存指令
```

对应状态变化：

$$
\boxed{ 运行\rightarrow阻塞\rightarrow就绪\rightarrow运行 }
$$

#### 两个关键区分

缺页异常：

由 P 当前执行的指令触发，是同步异常。

磁盘 I/O 完成中断：

由外部设备通知，是异步中断。

二者不是同一种事件。

同时，P 被唤醒后通常先进入就绪态，只有重新获得 CPU 才进入运行态。

## 二十六、2025 年第 46 题：进程虚拟地址空间

这是另一种近年重要综合题型。

它不是只考页表和缺页次数，而是考查程序对象在虚拟地址空间中的布局。

### 1. 典型进程地址空间

现代常见进程地址空间可以概念性地理解为：

```text
高地址
┌──────────────────┐
│ 内核空间或受保护映射 │
├──────────────────┤
│ 用户栈             │
│ 通常向低地址增长    │
├──────────────────┤
│ 内存映射区域        │
├──────────────────┤
│ 堆                 │
│ 典型情况下向高地址增长│
├──────────────────┤
│ BSS               │
├──────────────────┤
│ 已初始化数据段      │
├──────────────────┤
│ 代码段 text        │
└──────────────────┘
低地址
```

这是教学示意，不代表所有系统中的实际地址布局完全相同。

### 2. 题目涉及的 C 程序

```c
char *ptr;

void main() {
    int length;
    ptr = (char *)malloc(100);
    scanf("%s", ptr);
    length = strlen(ptr);
    printf("length=%d\n", length);
    free(ptr);
}
```

#### 问题一：PCB 在哪里？

PCB 是操作系统管理进程的数据结构。

通常位于：

$$
\boxed{\text{内核管理的内存区域}}
$$

不是用户堆，也不是用户栈。

#### 问题二：`main()` 的机器指令在哪里？

通常位于：

$$
\boxed{\text{代码段 text}}
$$

#### 问题三：全局指针 `ptr` 在哪里？

```c
char *ptr;
```

它是文件作用域、未显式初始化的全局变量。

通常放在：

$$
\boxed{\text{BSS}}
$$

#### 问题四：`ptr` 指向的内存在哪里？

```text
ptr = malloc(100);
```

`malloc` 分配的对象通常位于：

$$
\boxed{\text{堆}}
$$

所以：

指针变量本身在 BSS，指向的动态对象在堆。

#### 问题五：`length` 在哪里？

```c
int length;
```

这是自动局部变量。

如果没有被优化到寄存器中，通常位于：

$$
\boxed{\text{用户栈}}
$$

#### 问题六：`scanf()` 等待键盘输入时，进程是什么状态？

如果输入尚未到达，进程通常进入：

$$
\boxed{\text{阻塞态}}
$$

#### 额外注意

原程序中：

```c
scanf("%s", ptr);
```

存在缓冲区越界风险。

因为 `malloc(100)` 只有 100 B，字符串终止符 `\0` 也需要空间。

若采用该缓冲区且确认分配成功，读取字符串时可使用限定宽度的格式，例如：

```c
scanf("%99s", ptr);
```

这属于 C 语言安全性知识，但与虚拟地址空间、内存分配和程序运行环境都有联系。

## 二十七、内存映射文件 mmap

这是第三章与文件管理章节之间的重要连接点。

### 1. 什么是内存映射文件？

传统文件读取通常使用：

```text
read(...)
```

概念上：

```text
文件数据
   ↓
内核页缓存
   ↓
复制到用户缓冲区
   ↓
程序访问缓冲区
```

而使用：

```text
mmap(...)
```

可以在进程虚拟地址空间中建立文件映射。

```text
文件某个区域
      ↕
物理页面 / 页缓存
      ↕
进程虚拟地址空间
```

之后程序可以通过普通内存访问指令访问映射内容。

### 2. mmap 的关键特点

- 将文件内容关联到进程虚拟地址区间；
- 通常支持按需调页；
- 不必在建立映射时立刻读取全部文件内容；
- 可以减少某些传统文件读取路径中的数据复制；
- 可以用于进程间共享；
- 仍然涉及页表、缺页异常和页面管理。

#### 高频判断

`mmap` 创建映射时，是否一定立即把整个文件装入物理内存？

不一定。

通常可以采用按需调页。

### 3. 共享映射与私有映射

#### 共享映射

```text
进程A虚页10 ──┐
              ├── 同一物理文件页
进程B虚页20 ──┘
```

两个进程的虚页号不必相同。

它们可以指向相同物理页框。

#### 私有映射

私有映射通常可以利用写时复制机制。

开始时：

```text
A ──┐
    ├── 共享物理页
B ──┘
```

当 A 写入时：

```text
A → 私有物理页
B → 原物理页
```

这样 A 的私有写入不会直接修改 B 所看到的原共享副本。

## 二十八、写时复制 COW

COW 全称：

Copy-on-Write。

核心思想：

先共享，真正发生写入时再复制。

### 1. 为什么需要 COW？

例如：

```text
fork();
```

父进程创建子进程时，父子进程初始拥有相似的虚拟地址空间内容。

如果立即复制所有物理页面，会产生很大的开销。

所以典型实现可以先共享物理页面，并利用访问权限等机制捕获写入。

### 2. 发生写入时

假设：

```text
父进程：
虚页5 → 物理页框10

子进程：
虚页5 → 物理页框10
```

两个进程最初共享页框 10。

子进程试图修改数据时，触发写时复制处理。

系统可以：

1. 分配新物理页框；
2. 复制原页面内容；
3. 修改子进程页表；
4. 让子进程写入自己的私有页。

结果：

```text
父进程：
虚页5 → 物理页框10

子进程：
虚页5 → 物理页框20
```

因此：

相同虚拟地址也不代表父子进程永久共享同一个物理页。

## 三十、所有重要公式汇总

### 1. 连续分配

动态重定位：

$$
\boxed{PA=Base+LA}
$$

合法性检查：

$$
\boxed{0\le LA<Limit}
$$

### 2. 基本分页

页面大小：

$$
\boxed{P=2^k}
$$

页号：

$$
\boxed{VPN=\left\lfloor\frac{VA}{P}\right\rfloor}
$$

页内偏移：

$$
\boxed{d=VA\bmod P}
$$

物理地址：

$$
\boxed{PA=PFN\times P+d}
$$

### 3. 单级页表

完整页表最大大小：

$$
\boxed{S=2^{n-k}E}
$$

其中 $n$ 为虚拟地址位数，$k$ 为偏移位数，$E$ 为页表项字节数。

页表项地址：

$$
\boxed{PTEAddr=PTBR+VPN\times E}
$$

### 4. 多级页表

每页可容纳的页表项数：

$$
\boxed{N=\frac{PageSize}{PTEsize}}
$$

在一张页表恰占一页的经典模型中：

$$
\boxed{\text{索引位数}=\log_2N}
$$

无 TLB 等优化时：

$$
\boxed{k\text{ 级页表通常需要 }k+1\text{ 次主存访问}}
$$

### 5. 分段

$$
\boxed{PA=SegmentBase+Offset}
$$

前提：

$$
\boxed{0\le Offset<SegmentLength}
$$

### 6. TLB 有效访存时间

单级页表、串行查询、无缺页：

$$
\boxed{EAT=\varepsilon+(2-\alpha)t}
$$

多级页表：

$$
\boxed{ EAT=\alpha(\varepsilon+t) +(1-\alpha)[\varepsilon+(k+1)t] }
$$

### 7. 缺页率

$$
\boxed{p=\frac{\text{缺页次数}}{\text{总页面访问次数}}}
$$

如果 $C$ 表示相对于正常访问的额外缺页开销：

$$
\boxed{EAT=T_0+pC}
$$

### 8. 缺页和置换次数

固定 $m$ 个初始空闲页框，之后不增减页框的经典模型：

$$
\boxed{R=\max(0,F-m)}
$$

其中：

- $F$：缺页次数；
- $R$：置换次数。

### 9. 跨页对象

$$
\boxed{ N= \left\lfloor\frac{A+L-1}{P}\right\rfloor - \left\lfloor\frac AP\right\rfloor +1 }
$$

### 10. 工作集

$$
\boxed{W(t,\Delta)}
$$

工作集大小：

$$
\boxed{|W(t,\Delta)|}
$$

### 11. 伙伴系统

分配块大小：

$$
\boxed{B=2^{\lceil\log_2S\rceil}}
$$

需同时遵守系统最小块等限制。

伙伴地址：

$$
\boxed{Buddy(A)=A\oplus2^k}
$$

## 三十一、408 第三章高频易错点

这部分建议在做完真题以后反复检查。

| 易错说法               | 正确理解                   |
| ------------------ | ---------------------- |
| 虚拟地址一定比物理地址大       | 不一定，取决于地址体系结构          |
| 基本分页就是虚拟存储         | 错，基本分页可以要求全部页面驻留       |
| 分页没有任何碎片           | 错，仍可能有内部碎片             |
| 分段没有碎片             | 错，可能有外部碎片              |
| Best Fit 总体一定最优    | 错，容易产生极小外部碎片           |
| 相邻且等大的块一定是伙伴       | 错，必须满足伙伴关系             |
| 页表项地址就是数据物理地址      | 错，二者是不同层次的地址           |
| 多级页表使地址转换更快        | 不一定，主要改善页表空间组织         |
| TLB 未命中就是缺页        | 错，页面可能已经驻留             |
| TLB 命中就一定 Cache 命中 | 错，二者缓存内容不同             |
| 缺页一定需要页面置换         | 错，有空闲页框可以直接使用          |
| 缺页一定需要读磁盘          | 不一定，例如零页、COW 或特定缓冲恢复情形 |
| FIFO 命中要刷新队列顺序     | 错，FIFO 只看装入顺序          |
| LRU 命中不需要更新状态      | 错，必须更新最近使用关系           |
| LRU 在每组数据上都优于 FIFO | 错，没有这个保证               |
| CLOCK 的指针每次命中都移动   | 通常不会                   |
| 工作集就是驻留集           | 错，二者定义不同               |
| 工作集窗口大小等于工作集大小     | 不一定，窗口内可以重复访问          |
| 页框越多总是越好           | 对单个进程可能减少缺页，但会消耗其他进程资源 |
| 虚拟地址相同，物理地址一定相同    | 错，不同进程可以独立映射           |
| mmap 一定立即读入整个文件    | 错，通常支持按需调页             |
| malloc 一定立即分配物理页面  | 错，可能先分配虚拟空间            |
| PCB 位于用户堆区         | 错，通常是内核管理的数据结构         |
| 缺页唤醒后直接变成运行态       | 通常先进入就绪态，再由调度器决定       |

## 三十三、考场上如何快速解决本章综合大题？

建议把第三章所有计算题归为以下五种模板。

### 模板一：地址转换题

拿到题目后：

1. 确定地址位数。
2. 确定页面大小。
3. 确定页内偏移位数。
4. 计算虚页号。
5. 根据页表寻找页框号。
6. 检查映射是否有效、访问是否合法。
7. 计算物理地址。

一定先写：

$$
VPN=\left\lfloor\frac{VA}{P}\right\rfloor
$$

$$
d=VA\bmod P
$$

最后写：

$$
PA=PFN\times P+d
$$

### 模板二：多级页表题

1. 确定页面大小与偏移位数。
2. 计算每张页表容纳的表项数。
3. 分解各级页表索引。
4. 找到最高级页表的物理基址。
5. 逐级定位下级页表。
6. 计算对应 PDE/PTE 的地址。
7. 最后根据数据页的 PFN 计算数据物理地址。

必须区分：

PDE 地址、PTE 地址、数据物理地址。

### 模板三：页面置换题

建议始终列出：

| 访问次序 | 访问页 | 驻留页 | 是否缺页 | 淘汰页 | 额外状态 |
| ---- | --- | --- | ---- | --- | ---- |

根据算法维护：

- FIFO：装入时间；
- OPT：未来访问位置；
- LRU：过去访问位置；
- CLOCK：访问位与指针；
- 改进型 CLOCK：访问位、修改位及扫描过程。

最后分别统计：

- 缺页次数；
- 页面置换次数；
- 需要写回的脏页次数。

三者不可混淆。

### 模板四：有效访存时间题

首先把访问事件分类：

1. TLB 命中；
2. TLB 未命中、页面已驻留；
3. 发生缺页；
4. 如果有 Cache，再细分 Cache 命中和未命中。

分别列出每条路径的时间。

然后用概率加权：

$$
\boxed{EAT=\sum_i p_iT_i}
$$

必须保证所有分支互斥、覆盖全部可能，并且各分支计时口径一致。

### 模板五：内存分区题

始终维护：

```text
起始地址 | 分区大小 | 当前状态
```

分配时：

1. 找候选空闲块；
2. 按算法选择；
3. 根据题目规定从高地址端或低地址端分配；
4. 更新空闲块的地址和大小。

回收时：

1. 写出释放的地址范围；
2. 检查前后是否相邻；
3. 合并；
4. 必要时重新排序空闲链表。

## 三十四、最终复习建议

本章建议分三个阶段复习。

#### 第一阶段：先彻底掌握地址和内存分配

依次学习：

连续分配 → 内外碎片 → 动态分区 → 伙伴系统 → 分页 → 分段 → 段页式。

这一阶段最重要的目标是：

看见一个虚拟地址，能够准确拆出各个地址字段，明确它们分别代表什么。

对应真题优先做：

- 2010 年动态分区选择题；
- 2017 年动态分区选择题；
- 2013 年第 46 题；
- 2015 年第 46 题；
- 2020 年第 46 题。

#### 第二阶段：重点突破虚拟存储和页面置换

依次学习：

请求分页 → 缺页异常 → 驻留集 → FIFO → OPT → LRU → CLOCK → 改进型 CLOCK → 工作集 → 抖动。

这一阶段要做到：

不依赖直觉判断淘汰页面，而是能够完整、准确地模拟算法运行。

建议重点复做：

- 2019 年页面置换选择题；

#### 第三阶段：突破跨章节综合题

最后再做：

- 2009 年 TLB + 缺页 + LRU；
- 2018 年 PDBR + 地址构造 + 改进型 CLOCK；
- 2020 年数组 + 二级页表；

这一阶段要做到：

即使一道大题同时考查操作系统、计算机组成原理、C 语言和进程调度，也能拆成独立的小步骤完成。

### 全章最终总结

408 操作系统第三章，表面上有大量零散概念，但实际上只有一条核心逻辑：

```text
进程需要内存
      ↓
操作系统分配内存
      ↓
连续分配产生碎片问题
      ↓
分页、分段实现离散组织
      ↓
程序使用逻辑地址
      ↓
通过页表、段表转换物理地址
      ↓
使用TLB加速地址转换
      ↓
虚拟存储允许部分页面驻留
      ↓
访问未驻留页面产生缺页
      ↓
有空闲页框则直接装入
      ↓
页框不足则执行页面置换
      ↓
FIFO / OPT / LRU / CLOCK
      ↓
根据工作集调整页框数量
      ↓
控制缺页率、避免抖动
      ↓
提高系统整体运行效率
```

最终必须形成的六项能力：

1. 能算地址： 从虚拟地址、页大小和页表信息推导物理地址。
2. 能算页表： 求页表容量、多级页表结构、PDE/PTE 地址。
3. 能模拟置换： 独立完成 FIFO、OPT、LRU、CLOCK 的完整过程。
4. 能算时间： 严格区分 TLB 命中、未命中、缺页与指令重新执行的时间。
5. 能分析性能： 从工作集、驻留集和局部性解释缺页、抖动与访存性能。
6. 能解决综合题： 把地址转换、页面置换、内存布局、异常、中断和进程调度联系起来。

第三章最值得反复训练的三类题是：多级页表地址计算、页面置换完整模拟、TLB 与缺页有效访存时间计算。再补齐内存分配、分段、工作集与 mmap 等概念，便能覆盖本章主要考法。
