## 二、3.1 栈——本章第一个核心

### 1. 栈到底是什么？

栈（Stack）是一种操作受限的线性表。

限制是：

只允许在线性表的同一端插入和删除元素。

允许操作的一端叫栈顶（Top），另一端叫栈底（Bottom）。

```text
           栈顶
             ↓
          ┌─────┐
          │  5  │ ← 最后入栈
          ├─────┤
          │  4  │
          ├─────┤
          │  3  │
          ├─────┤
          │  2  │
          ├─────┤
          │  1  │ ← 最先入栈
          └─────┘
           栈底
```

栈最核心的性质：

$$
\boxed{\text{LIFO：Last In First Out}}
$$

即后进先出。

假设依次执行：

```text
Push(1)
Push(2)
Push(3)
Push(4)
```

如果现在连续执行四次 `Pop()`，输出顺序必然是：

```text
4 3 2 1
```

但这里有一个极重要的考点：

固定入栈顺序，不代表出栈顺序唯一。

因为入栈和出栈可以交替执行。

例如输入：

```text
1 2 3
```

可以得到：

```text
1 2 3
```

操作是：

```text
Push(1) → Pop()
Push(2) → Pop()
Push(3) → Pop()
```

也可以得到：

```text
2 1 3
```

操作是：

```text
Push(1)
Push(2)
Pop()   // 2
Pop()   // 1
Push(3)
Pop()   // 3
```

所以考场中不能简单认为：栈的输出必然是输入的完全逆序。

完全逆序只是其中一种情况。

### 2. 栈的基本操作

| 操作                | 含义       |
| ----------------- | -------- |
| `InitStack(S)`    | 初始化      |
| `StackEmpty(S)`   | 判断是否为空   |
| `Push(S,x)`       | 元素入栈     |
| `Pop(S,x)`        | 弹出栈顶元素   |
| `GetTop(S,x)`     | 读取栈顶但不删除 |
| `DestroyStack(S)` | 销毁栈      |

其中必须区分：

- `Pop`：读取并删除栈顶。
- `GetTop`：读取栈顶，不改变栈。

对于标准顺序栈和链栈，栈顶操作通常都是：

$$
T(n)=O(1)
$$

因为不需要查找或移动其他元素。

### 3. 顺序栈——最容易考的是 top 指针

顺序栈使用连续存储空间，通常由一个数组和一个栈顶指针组成。

```c
#define MaxSize 100

typedef struct {
    int data[MaxSize];
    int top;
} SqStack;
```

考试中最危险的问题：

`top` 到底指向当前栈顶元素，还是指向栈顶元素之后的空位置？

这会直接影响入栈、出栈、判空和判满。

#### 3.1 第一种约定：top 指向当前栈顶元素

这是非常常见的教材写法。

初始化：

```c
S.top = -1;
```

为什么是 $-1$？

因为数组第一个有效下标是 0。

空栈没有栈顶元素，因此用 $-1$ 表示。

此时：

| 状态或操作 | 条件或代码                |
| ----- | -------------------- |
| 栈空    | `top == -1`          |
| 栈满    | `top == MaxSize - 1` |
| 元素个数  | `top + 1`            |
| 入栈    | `data[++top] = x`    |
| 出栈    | `x = data[top--]`    |
| 读栈顶   | `x = data[top]`      |

观察入栈：

```c
S.data[++S.top] = x;
```

为什么先自增？

假设初始：

```text
top = -1
```

第一个元素应放入：

```text
data[0]
```

所以必须：

```text
top: -1 → 0
然后写入 data[0]
```

出栈恰好相反：

```c
x = S.data[S.top--];
```

先取当前栈顶，再向下移动指针。

#### 3.2 第二种约定：top 指向下一空位置

此时：

```text
空栈 top = 0
```

入栈：

```c
S.data[S.top++] = x;
```

出栈：

```c
x = S.data[--S.top];
```

判空：

```text
S.top == 0
```

判满：

```text
S.top == MaxSize
```

两种约定对照：

| 项目   | top 指栈顶元素       | top 指下一空位       |
| ---- | --------------- | --------------- |
| 空栈   | -1              | 0               |
| 入栈   | `data[++top]=x` | `data[top++]=x` |
| 出栈   | `x=data[top--]` | `x=data[--top]` |
| 满栈   | `top==n-1`      | `top==n`        |
| 元素数量 | `top+1`         | `top`           |

考研结论：先看指针含义，再写公式。

这也是后面循环队列解题时最重要的原则。

### 4. 高频考点：合法出栈序列

这部分必须完全掌握。

假设输入顺序固定：

$$
1,2,3,4,5
$$

要求判断目标出栈序列：

$$
3,2,1,5,4
$$

是否合法。

#### 4.1 最可靠的方法：模拟

想输出 3，就必须先将 1、2、3 入栈。

```text
Push(1)
Push(2)
Push(3)
```

此时：

```text
栈底 → [1,2,3] ← 栈顶
```

弹出 3：

```text
栈：[1,2]
输出：3
```

下一目标是 2，刚好为栈顶，继续弹出。

```text
栈：[1]
输出：3,2
```

下一目标为 1，继续弹出。

```text
栈：[]
输出：3,2,1
```

接下来想输出 5：

```text
Push(4)
Push(5)
Pop()   // 5
Pop()   // 4
```

最后：

```text
3 2 1 5 4
```

所以合法。

#### 4.2 非法序列怎么判断？

例如：

$$
3,1,2,5,4
$$

先输出 3，必须：

```text
Push 1
Push 2
Push 3
Pop 3
```

现在：

```text
栈底 → [1,2] ← 栈顶
```

但下一目标是 1。

1 已经在栈中，却被 2 压在下面。

无论继续入栈什么元素，都不能绕过 2 输出 1。

因此：

$$
\boxed{\text{不合法}}
$$

#### 4.3 通用算法

```c
#include <stdlib.h>

int IsStackPermutation(const int P[], int n) {
    if (n < 0 || (n > 0 && P == NULL))
        return 0;

    if (n == 0)
        return 1;

    int *S = (int *)malloc(n * sizeof(int));
    if (S == NULL)
        return 0;

    int top = -1;
    int next = 1;

    for (int i = 0; i < n; i++) {
        int x = P[i];

        // 输入必须是1到n的排列
        if (x < 1 || x > n) {
            free(S);
            return 0;
        }

        // x尚未入栈：依次压到x
        while (next <= x) {
            S[++top] = next++;
        }

        // 当前栈顶必须等于目标值
        if (top == -1 || S[top] != x) {
            free(S);
            return 0;
        }

        top--;
    }

    free(S);
    return 1;
}
```

这里的输入假设是 $1\sim n$ 的一个候选排列。

时间复杂度：

每个元素最多入栈一次、出栈一次，所以：

$$
\boxed{O(n)}
$$

空间复杂度：

辅助栈最坏需要保存 $n$ 个元素：

$$
\boxed{O(n)}
$$

注意，虽然程序中有 `for` 和 `while` 两层循环，但不是 $O(n^2)$。

因为内层 `while` 的总入栈次数最多为 $n$。

### 5. 真题精讲：2009 年最小栈容量

题型：栈 + 队列综合

已知：

```text
入栈顺序：
a b c d e f g
```

元素从栈弹出后立即进入队列。

最终队列输出：

```text
b d c f e a g
```

问栈的最小容量。

#### 第一步：分析队列作用

队列遵循 FIFO。

所以队列最终出队顺序，就是元素从栈中弹出的顺序。

问题转化为：

> 产生指定出栈序列，栈的最大同时占用空间是多少？

#### 第二步：模拟

| 操作阶段     | 栈内元素（底→顶） | 最大栈深 |
| -------- | --------- | ---- |
| a、b 入栈   | a,b       | 2    |
| b 出栈     | a         | 2    |
| c、d 入栈   | a,c,d     | 3    |
| d、c 出栈   | a         | 3    |
| e、f 入栈   | a,e,f     | 3    |
| f、e、a 出栈 | 空         | 3    |
| g 入栈并出栈  | 空         | 3    |

整个过程中的最大栈深为：

$$
\boxed{3}
$$

因此最小栈容量为 3。

#### 这一类题的统一结论

设每一步操作后栈中的元素个数为：

$$
s_1,s_2,\ldots,s_m
$$

则：

$$
\boxed{C_{\min}=\max_{1\le i\le m}s_i}
$$

注意：前提是目标序列本身合法。

如果目标序列不合法，再大的栈也无法产生它。

### 6. 真题精讲：2010 年带操作限制的出栈问题

题目规定：

- 元素 `a,b,c,d,e,f` 依次入栈。
- 入栈和出栈可以交错。
- 不允许连续三次出栈。

考查序列：

```text
a f e d c b
```

是否可以产生。

首先要输出 a：

```text
Push(a)
Pop(a)
```

接下来必须输出 f。

所以要把剩下的元素全部入栈：

```text
Push(b)
Push(c)
Push(d)
Push(e)
Push(f)
```

然后只能：

```text
Pop(f)
Pop(e)
Pop(d)
Pop(c)
Pop(b)
```

这意味着连续执行了五次 `Pop`。

题目只允许最多连续两次 `Pop`。

因此：

$$
\boxed{\text{该序列不可能}}
$$

这类题的核心是增加状态约束。

例如增加一个变量：

```text
连续出栈次数 cnt
```

每次 Push：

```text
cnt = 0
```

每次 Pop：

```text
cnt++
```

若：

```text
cnt >= 3
```

就违反题意。

以后遇到“不允许连续若干次入栈或出栈”的题，也按这个思路处理。

### 7. 真题精讲：2013 年指定出栈位置的取值

$$
1,2,\ldots,n
$$

依次入栈。

$$

$$

规定：

$$

$$

求 $p_3$ 可能取多少个不同值。

<Step>

</Step>
<Step>

### 8. Catalan 数——合法出栈序列共有多少种？

如果有 $n$ 个互不相同的元素，按照固定次序各入栈一次、出栈一次，那么所有合法出栈序列的数量是：

$$
\boxed{C_n=\frac{1}{n+1}\binom{2n}{n}}
$$

这叫 Catalan 数（卡特兰数）。

前几个值：

| $n$ | 合法出栈序列数 |
| ------- | ------- |
| 1       | 1       |
| 2       | 2       |
| 3       | 5       |
| 4       | 14      |
| 5       | 42      |
| 6       | 132     |

#### 为什么会出现 Catalan 数？

把入栈记为左括号 `(`，出栈记为右括号 `)`。

例如：

```text
Push
Push
Pop
Push
Pop
Pop
```

对应：

```text
(()())
```

注意，合法的入栈出栈操作必须满足：

任何一个操作前缀中，出栈次数不能超过入栈次数。

否则就相当于对空栈执行 `Pop`。

所以合法栈操作与合法括号序列存在一一对应关系。

这正是 Catalan 数出现的原因。

Catalan 数还满足递推式：

$$
C_0=1
$$

$$
\boxed{C_n=\sum_{i=0}^{n-1}C_iC_{n-1-i}}
$$

这个公式在二叉树计数等章节还会再次出现。

### 9. 2026 年第 42 题：出栈序列与 Catalan 数综合

这道综合题值得重点研究。

它把前面的知识组合为：

- 判断指定出栈序列的合法性；
- 发现非法序列的特征；
- 统计以指定元素开头的合法序列数量；
- 推导 Catalan 数之间的关系。

#### 9.1 判断两组序列

输入固定为：

$$
1,2,\ldots,9
$$

第一组：

$$
2,3,1,6,4,7,5,9,8
$$

不合法。

原因在于输出 6 后，栈中仍有：

```text
4,5
```

而下一个要求输出 4。

此时栈顶是 5，无法越过 5 输出 4。

第二组：

$$
2,3,1,5,6,7,4,9,8
$$

合法。

其中先输出 5、6、7 后，可以继续弹出 4，因为 4 一直位于此前栈中尚未弹出的部分的栈顶。

#### 9.2 什么样的三元组意味着不合法？

对于输入 $1,2,\ldots,n$，若输出序列中存在下标：

$$
i<j<k
$$

并且：

$$
\boxed{P_j<P_k<P_i}
$$

那么该序列不可能由一个栈产生。

因为先输出较大的 $P_i$ 时，较小的 $P_j$ 与 $P_k$ 已经按升序压入过栈。

其中 $P_k$ 会位于 $P_j$ 上方。

不可能先弹出 $P_j$，再弹出 $P_k$。

这种模式称为 312 禁形。

对于固定升序输入的单栈排列：

$$
\boxed{\text{合法}\iff\text{不存在 312 禁形}}
$$

实际做题时，直接模拟通常更省事；312 禁形更适合解释不合法的根本原因。

#### 9.3 $n=4$，以 2 开头有多少种？

合法序列是：

```text
2134
2143
2314
2341
2431
```

共有：

$$
\boxed{5}
$$

种。

#### 9.4 进一步推广

若：

$$
C_{k-1}=M
$$

则长度为 $k$ 的合法出栈序列中：

以 1 开头的数量：

$$
\boxed{M}
$$

以 2 开头的数量：

$$
\boxed{M}
$$

全部合法序列数：

$$
\boxed{C_k=\frac{2(2k-1)}{k+1}M}
$$

更深入的拓展是：

设 $T(n,r)$ 表示 $n$ 个元素中，第一个出栈元素为 $r$ 的合法序列数量。

则：

$$
\boxed{ T(n,r)= \frac{r}{2n-r}\binom{2n-r}{n} }
$$

例如 $n=5$：

| 首个出栈元素 | 合法序列数量 |
| ------ | ------ |
| 1      | 14     |
| 2      | 14     |
| 3      | 9      |
| 4      | 4      |
| 5      | 1      |
| 合计     | 42     |

这里不必在第一轮复习就熟记推广公式，但一定要理解：固定第一个出栈元素后，剩下的栈状态受到约束，不能直接用阶乘计算。

### 10. 共享栈

共享栈是指两个栈共用一块数组空间。

```text
数组下标：

0                              n-1
↓                               ↓

┌───────────────────────────────┐
│ 栈1 →→→     空闲     ←←← 栈2 │
└───────────────────────────────┘
```

两个栈从两端向中间增长。

#### 为什么共享空间？

如果为两个栈各分配 50 个位置：

```text
栈1需要60个位置
栈2只使用10个位置
```

那么栈1仍然会溢出。

而共享栈可以动态利用另一个栈暂时不需要的空间。

#### 10.1 栈顶指向当前元素

假设：

```text
top1 = -1
top2 = n
```

第一个栈向右增长，第二个栈向左增长。

当：

$$
\boxed{top_2-top_1=1}
$$

时，两栈之间没有空余位置。

#### 10.2 栈顶指向下一可用位置

另一种常见约定：

```text
top1 = 0
top2 = n-1
```

两个指针分别指向各自增长方向上的下一空位。

两栈判满：

$$
\boxed{top_1=top_2+1}
$$

即：

$$
\boxed{top_1-top_2=1}
$$

注意：两种定义不相同，不能混用判满公式。

共享栈的本质是动态共享存储空间，不是改变 LIFO 规则。

### 11. 链栈

链栈是使用链表实现的栈。

通常直接使用单链表头部作为栈顶。

```text
top
 ↓
[30] → [20] → [10] → NULL
```

入栈：

```c
p->next = top;
top = p;
```

出栈：

```c
Node *p = top;

x = p->data;
top = p->next;

free(p);
```

注意必须先判断栈非空。

#### 顺序栈和链栈比较

| 比较项目 | 顺序栈        | 链栈         |
| ---- | ---------- | ---------- |
| 存储方式 | 连续数组       | 链表结点       |
| 入栈   | $O(1)$ | $O(1)$ |
| 出栈   | $O(1)$ | $O(1)$ |
| 空间分配 | 通常固定容量     | 动态分配       |
| 附加空间 | 无结点指针      | 每结点需要指针    |
| 主要问题 | 容量不足可能溢出   | 动态分配可能失败   |

本节最重要的是理解：栈的逻辑规则与底层存储方式是两回事。

## 三、3.2 队列——本章第二个核心

### 1. 什么是队列？

队列（Queue）也是一种操作受限的线性表。

与栈不同，队列规定：

- 只能在队尾插入元素。
- 只能在队头删除元素。

其核心性质为：

$$
\boxed{\text{FIFO：First In First Out}}
$$

即先进先出。

```text
                队列

出队 ← [1] [2] [3] [4] [5] ← 入队
        ↑               ↑
      front            rear
```

例如：

```text
EnQueue(1)
EnQueue(2)
EnQueue(3)
```

那么依次出队必然得到：

```text
1 2 3
```

普通队列不能直接删除队尾元素。

这是模拟选择题中一个非常基础的考点。

### 2. 队列的基本操作

| 操作                | 作用     |
| ----------------- | ------ |
| `InitQueue(Q)`    | 初始化    |
| `QueueEmpty(Q)`   | 判断是否为空 |
| `EnQueue(Q,x)`    | 从队尾插入  |
| `DeQueue(Q,x)`    | 从队头删除  |
| `GetHead(Q,x)`    | 读取队头   |
| `DestroyQueue(Q)` | 销毁     |

标准队列中的入队、出队通常都可实现为：

$$
O(1)
$$

需要注意：这是具体实现满足条件时的复杂度，不是任意队列实现都必然如此。

### 3. 顺序队列为什么会发生假溢出？

假设使用一个长度为 5 的数组实现队列：

```text
下标： 0  1  2  3  4

       A  B  C  D  E
```

此时队列已满。

现在连续执行三次出队：

```text
DeQueue()
DeQueue()
DeQueue()
```

逻辑队列变成：

```text
下标： 0  1  2  3  4

       ×  ×  ×  D  E
```

可以看到：

- 前三个存储单元已经空闲；
- 队尾指针却已经移动到末尾。

如果队尾只允许继续向右移动，那么它无法利用前面的空间。

这种现象叫：

假溢出。

它不是数组真的没有空间，而是顺序队列的空间使用方式不合理。

解决方案：

把数组首尾逻辑上连接起来，构成循环队列。

## 四、循环队列——必须完全掌握

这是本章最典型的高频计算题之一。

### 1. 循环队列为什么要使用取模运算？

假设数组长度：

$$
m=5
$$

下标为：

```text
0 1 2 3 4
```

如果当前指针位置为 4，下一步应返回位置 0。

数学上：

$$
(4+1)\bmod5=0
$$

因此统一使用：

$$
\boxed{next=(current+1)\bmod m}
$$

这样就实现了循环移动。

### 2. 最经典的循环队列模型

这里明确采用以下约定：

- `front` 指向队头元素所在位置；
- `rear` 指向队尾元素之后的下一个空位置；
- 数组长度为 $m$；
- 牺牲一个存储单元以区分队空和队满。

这个模型是 408 中最常见的模型之一。

#### 2.1 判空

当队列为空时，队头与队尾后一位置重合：

$$
\boxed{front=rear}
$$

#### 2.2 判满

当 `rear` 再前进一个位置，就会与 `front` 重合时，说明队列已经没有可继续使用的存储单元。

所以：

$$
\boxed{(rear+1)\bmod m=front}
$$

#### 2.3 为什么必须牺牲一个存储单元？

假设没有牺牲存储单元。

当整个数组装满时，`rear` 绕回以后也可能满足：

$$
front=rear
$$

这样队空和队满就无法区分。

于是规定：

始终保留一个未使用的位置。

此时最多存储：

$$
\boxed{m-1}
$$

个元素。

注意：

> 数组长度为 $m$，不意味着队列容量一定为 $m$。

#### 2.4 队列长度公式

这是必须熟练掌握的公式：

$$
\boxed{L=(rear-front+m)\bmod m}
$$

我们来理解它。

情况一：未发生回绕

假设：

$$
front=2,\qquad rear=6
$$

那么：

$$
L=6-2=4
$$

情况二：发生回绕

假设：

$$
m=8,\quad front=6,\quad rear=2
$$

逻辑队列占用的位置是：

```text
6 → 7 → 0 → 1
```

共四个元素。

套用公式：

$$
L=(2-6+8)\bmod8
$$

所以：

$$
\boxed{L=4}
$$

公式的本质是计算环形数组中，从 `front` 到 `rear` 的正向距离。

### 3. 循环队列完整操作

```c
#define MaxSize 100

typedef struct {
    int data[MaxSize];
    int front;
    int rear;
} SqQueue;
```

初始化：

```c
void InitQueue(SqQueue *Q) {
    Q->front = 0;
    Q->rear = 0;
}
```

判空：

```c
int QueueEmpty(SqQueue *Q) {
    return Q->front == Q->rear;
}
```

判满：

```c
int QueueFull(SqQueue *Q) {
    return (Q->rear + 1) % MaxSize
           == Q->front;
}
```

入队：

```c
int EnQueue(SqQueue *Q, int x) {
    if (QueueFull(Q))
        return 0;

    Q->data[Q->rear] = x;

    Q->rear =
        (Q->rear + 1) % MaxSize;

    return 1;
}
```

出队：

```c
int DeQueue(SqQueue *Q, int *x) {
    if (QueueEmpty(Q))
        return 0;

    *x = Q->data[Q->front];

    Q->front =
        (Q->front + 1) % MaxSize;

    return 1;
}
```

这个实现有一个很重要的细节：

入队时先存数据，再移动 rear；出队时先取数据，再移动 front。

因为我们采用的指针约定是：

```text
front 指向队头元素
rear  指向队尾后一空位置
```

如果改变约定，操作顺序也可能改变。

### 4. 2014 年真题：循环队列判空与判满

题目规定：

- 数组为 `A[0...M-1]`；
- `end1` 指向队头；
- `end2` 指向队尾之后的位置；
- 最多保存 $M-1$ 个元素。

求队空、队满条件。

直接根据指针含义：

队空：

$$
\boxed{end1=end2}
$$

队满：

$$
\boxed{end1=(end2+1)\bmod M}
$$

这道题的重点不是计算，而是检查是否理解指针的含义。

### 5. 2011 年真题：为什么初始化不是 front=rear=0？

2011 年真题规定：

- 队列非空时，`front` 指向队头元素；
- `rear` 指向队尾元素；
- 第一个进入队列的元素必须存储在 `A[0]`。

题目采用入队时先将 `rear` 加一再存储的约定。

因此要让第一次入队写入 `A[0]`，必须：

$$
(rear+1)\bmod n=0
$$

得到：

$$
rear=n-1
$$

同时令：

$$
front=0
$$

所以答案：

$$
\boxed{front=0,\qquad rear=n-1}
$$

这是一个非常典型的易错点。

不要将这里的指针定义与前面的经典循环队列模型混用。实际实现时，还需要根据题目约定使用额外状态或适当的空满判定机制。

### 6. 循环队列如何不浪费一个位置？

除了牺牲一个存储单元，还有两种经典方案。

#### 方案一：增加 size

额外记录当前队列中的元素数量：

```text
int size;
```

队空：

$$
\boxed{size=0}
$$

队满：

$$
\boxed{size=m}
$$

此时所有 $m$ 个数组单元都可以保存数据。

即使：

$$
front=rear
$$

也可以通过 `size` 判断队列到底是空还是满。

#### 方案二：增加 tag

使用一个标记变量。

例如规定：

```text
tag = 0：最后一次改变队列状态的操作为出队
tag = 1：最后一次改变队列状态的操作为入队
```

当：

$$
front=rear
$$

时：

- `tag=0`：队空；
- `tag=1`：队满。

这里需要保证标记与入队、出队操作同步更新，并且初始化时将队列状态设置为空。

#### 三种循环队列方案比较

| 方案      | 判空            | 判满                  | 最大容量      |
| ------- | ------------- | ------------------- | --------- |
| 牺牲一格    | `front==rear` | `(rear+1)%m==front` | $m-1$ |
| 增加 size | `size==0`     | `size==m`           | $m$   |
| 增加 tag  | 指针相等且 tag=0   | 指针相等且 tag=1         | $m$   |

复习结论：

凡是循环队列题，第一步必须判断它采用哪一种方案。

## 五、链式队列与双端队列

### 1. 链式队列

链式队列通常使用单链表实现。

比较常见的是带头结点的链式队列。

```text
front
  ↓
[头结点] → [10] → [20] → [30] → NULL
                                ↑
                               rear
```

空队列时：

```text
front == rear
```

二者都指向头结点。

#### 1.1 入队操作

假设新结点为 `s`。

```c
s->next = NULL;
Q->rear->next = s;
Q->rear = s;
```

本质是单链表尾插。

时间复杂度：

$$
O(1)
$$

#### 1.2 出队操作

```c
Node *p = Q->front->next;

Q->front->next = p->next;

x = p->data;
```

但是存在一个特别重要的边界情况。

如果队列原来只有一个数据结点：

```text
头结点 → [10] → NULL
          ↑
         rear
```

删除之后，必须：

```c
Q->rear = Q->front;
```

否则队尾指针仍然指向已经删除的结点。

完整核心代码：

```c
int DeQueue(LinkQueue *Q, int *x) {
    if (Q->front == Q->rear)
        return 0;

    Node *p = Q->front->next;

    *x = p->data;
    Q->front->next = p->next;

    if (Q->rear == p)
        Q->rear = Q->front;

    free(p);
    return 1;
}
```

其中 `LinkQueue` 和 `Node` 使用常规的带头结点链队定义。

这类题经常考查的不是算法思想，而是最后一个结点删除后，指针是否处理正确。

### 2. 只保存 rear 的循环链式队列

这是一个很经典的选择题考点。

如果使用不带头结点的循环单链表：

```text
       ┌─────────────────────┐
       ↓                     │
      [A] → [B] → [C] → [D]
       ↑                 ↑
      队头              rear
```

只保存 `rear`。

那么：

```text
rear->next
```

就可以直接获得队头。

因此：

- 入队：在 `rear` 后插入结点，并更新 `rear`；
- 出队：删除 `rear->next` 指向的队头结点。

均可做到：

$$
\boxed{O(1)}
$$

注意删除唯一结点时，还需要把 `rear` 设置为空指针。

这一技巧说明：

循环链表中保存尾指针，可以同时快速访问队头和队尾。

### 3. 双端队列

双端队列（Deque）允许在两端操作。

```text
          双端队列

左端                         右端
 ↓                            ↓
[A] [B] [C] [D]

两端都可以插入和删除
```

但考试还会考两种受限模型。

输入受限双端队列： 只允许在一端插入，但两端可以删除。

输出受限双端队列： 两端可以插入，但只允许在一端删除。

不要仅凭名称判断能否输出某个序列，一定要看题目具体允许哪些操作。

### 4. 2010 年真题：受限双端队列

已知元素依次到来：

```text
a b c d e
```

允许：

- 两端插入；
- 只能从固定的一端删除；
- 所有元素先入队，再开始出队。

问哪个出队序列不可能。

考虑候选：

```text
d b c a e
```

这道题有一个非常实用的方法：

逆序删除法。

因为最后一个进入的是 `e`。

既然 e 只能从两端之一插入，那么在最终队列排列中，e 必须处于一端。

从：

```text
d b c a e
```

删除 e，剩下：

```text
d b c a
```

接下来考虑 d。

d 是此前最后进入的元素，也必须位于剩余序列的一端。

删除 d：

```text
b c a
```

接下来检查 c。

但 c 位于中间：

```text
b [c] a
```

它不可能作为当时最后插入的元素同时位于两端之一。

所以：

$$
\boxed{\text{d b c a e 不可能}}
$$

注意：逆序删除法在这里适用，是因为题目规定所有元素先入队，再统一出队。

如果允许入队和出队交替进行，就不能直接照搬这一方法。

### 5. 2018 年真题：队列与栈综合

初始队列：

```text
1 2 3 4 5 6
```

另有一个空栈。

允许三种操作：

1. 队头元素直接输出；
2. 队头元素取出并入栈；
3. 栈顶元素出栈并输出。

问能否输出：

```text
3 4 5 6 1 2
```

#### 逐步分析

为了先输出 3，必须先从队列中取走 1 和 2。

但它们不能直接输出，否则目标序列就错了。

所以只能：

```text
1 入栈
2 入栈
```

此时：

```text
栈底 → [1,2] ← 栈顶
```

然后队列可以直接输出：

```text
3 4 5 6
```

最后只剩栈中的 1、2。

但弹出顺序必然是：

```text
2 1
```

不能是：

```text
1 2
```

因此：

$$
\boxed{\text{不可能}}
$$

这类综合题的核心：

队列决定原始元素的取出顺序，栈决定暂存元素的后进先出关系。

## 六、2019 年第 42 题——本章最重要的算法设计大题之一

这道题是空间复用队列的典型算法设计模型。

### 1. 题目要求

设计一个队列，使其满足：

1. 初始化时队列为空；
2. 入队时可以增加存储空间；
3. 出队后，原来申请的空间可以重复利用；
4. 队列已申请的空间只增不减；
5. 每次入队、出队始终保持 $O(1)$ 时间复杂度。

题目要求说明：

- 选择链式还是顺序存储；
- 初始状态；
- 判空、判满；
- 第一个元素入队后的状态；
- 入队、出队的基本过程。

### 2. 为什么选择循环单链表？

普通固定数组不能按需增长。

动态数组虽然能够扩容，但如果需要重新申请更大的连续空间并搬移元素，一次扩容可能需要：

$$
O(n)
$$

不满足题目要求的每次操作始终 $O(1)$。

而循环单链表可以：

- 需要空间时只申请一个新结点；
- 不必搬移已有元素；
- 出队时不释放结点；
- 后续直接复用空闲结点。

因此选择：

$$
\boxed{\text{循环单链表}}
$$

### 3. 设计指针约定

这里使用大题详细解析中的一种实现约定：

- `front` 指向当前队头元素所在结点；
- `rear` 指向下一个可写入的空闲结点；
- 整个链表构成一个环；
- 始终保留一个空闲结点。

这个约定要与普通链式队列区分。

#### 初始状态

只申请一个结点 `N0`。

```text
         front,rear
             ↓
            N0
             ↺
```

即：

```c
front = rear = N0;
N0->next = N0;
```

此时队列为空。

#### 判空

$$
\boxed{front=rear}
$$

#### 什么时候需要扩容？

当：

```c
rear->next == front
```

说明当前已经申请的结点中没有足够空间再容纳一个元素，同时还保留空位。

此时必须申请一个新结点。

注意：这里所谓“满”，是指当前已分配的存储空间需要扩容，不是队列永久无法再插入。

### 4. 第一个元素入队

初始只有 `N0`：

```text
N0 → N0
```

要插入 10。

因为：

```c
rear->next == front
```

需要先申请一个结点 `N1`。

建立循环关系：

```text
N0 → N1
↑     ↓
└─────┘
```

然后：

```text
N0.data = 10
rear = N1
front = N0
```

逻辑状态：

```text
front           rear
  ↓               ↓
[10] → [空闲结点]
 ↑              │
 └──────────────┘
```

此时队列中有一个元素 10。

### 5. 入队和出队代码

先定义结点：

```c
typedef struct Node {
    int data;
    struct Node *next;
} Node;

typedef struct {
    Node *front;
    Node *rear;
} ReuseQueue;
```

入队：

```c
int EnQueue(ReuseQueue *Q, int x) {
    // 当前已分配空间需要扩容
    if (Q->rear->next == Q->front) {
        Node *p = (Node *)malloc(sizeof(Node));

        if (p == NULL)
            return 0;

        p->next = Q->rear->next;
        Q->rear->next = p;
    }

    // 在当前空闲结点写入
    Q->rear->data = x;

    // rear移动到下一空位置
    Q->rear = Q->rear->next;

    return 1;
}
```

出队：

```c
int DeQueue(ReuseQueue *Q, int *x) {
    if (Q->front == Q->rear)
        return 0;

    *x = Q->front->data;

    // 不释放结点，只移动队头
    Q->front = Q->front->next;

    return 1;
}
```

这套代码假定队列已经完成上述单结点自环初始化。

为什么出队不调用 `free()`？

因为题目明确要求：

> 出队元素原来占用的空间应当可以重复使用。

如果直接释放结点，就无法保证维持一个只增不减的已分配结点环。

#### 复杂度分析

一次入队最多：

- 申请一个结点；
- 修改常数个指针；
- 写入一个元素。

一次出队：

- 读取一个元素；
- 修改一个指针。

按考研通常采用的单结点分配复杂度模型：

$$
\boxed{T_{\text{EnQueue}}=O(1)}
$$

$$
\boxed{T_{\text{DeQueue}}=O(1)}
$$

需要强调，实际系统内存分配器的严格最坏耗时未必保证常数，但在本题算法分析模型下按 $O(1)$ 处理。

### 6. 这道大题最容易失分的地方

第一，只回答“链式存储”不够。

必须进一步说明如何复用已经申请的结点。

第二，不能直接套用普通链式队列的 `rear->next=NULL`。

本题采用循环单链表，最后一个结点需要指回环中的某个结点。

第三，不能把队空与“当前容量需要扩容”混为一谈。

第四，不能出队后直接释放结点。

第五，必须明确 `front` 和 `rear` 的定义。

补充说明：知识库的历年选择真题解析还使用了另一种等价约定，即 `front` 指向队头前驱、`rear` 指向当前队尾。两种约定都能完成本题，但必须使用各自一致的指针操作，不能混用。

这一题值得完整手写一次。

## 七、3.3 栈和队列的应用

这一部分最重要的是表达式求值，同时还需要理解括号匹配、递归和遍历。

### 1. 括号匹配

考虑：

```text
{ [ ( ) ] }
```

为什么使用栈？

因为最后出现的未匹配左括号必须最先被匹配。

例如：

```text
{
[
(
```

接下来必须先出现：

```text
)
```

再出现：

```text
]
```

最后出现：

```text
}
```

这正好符合：

$$
\boxed{\text{LIFO}}
$$

#### 1.1 基本算法

扫描字符串。

遇到左括号：

```text
入栈
```

遇到右括号：

```text
栈为空？        → 不合法
栈顶类型不匹配？ → 不合法
否则弹出栈顶
```

扫描结束后：

```text
栈为空 → 合法
栈非空 → 不合法
```

#### 1.2 三种失败情况

情况一：右括号太多

```text
())
```

扫描到最后一个右括号时，栈已经空了。

情况二：左括号太多

```text
((())
```

扫描结束时，栈中仍有未匹配的左括号。

情况三：括号类型或顺序错误

```text
([)]
```

数量虽然匹配，但嵌套关系不合法。

#### 1.3 C 语言算法

```c
int Match(char str[]) {
    char stack[1000];
    int top = -1;

    for (int i = 0; str[i] != '\0'; i++) {
        char ch = str[i];

        if (ch == '(' || ch == '[' || ch == '{') {
            if (top == 999)
                return 0;

            stack[++top] = ch;
        }
        else if (ch == ')' ||
                 ch == ']' ||
                 ch == '}') {

            if (top == -1)
                return 0;

            char left = stack[top--];

            if ((ch == ')' && left != '(') ||
                (ch == ']' && left != '[') ||
                (ch == '}' && left != '{'))
                return 0;
        }
    }

    return top == -1;
}
```

这里假设字符串只包含括号字符，且栈的固定容量足够；代码也进行了栈满检查。

时间复杂度：

$$
O(n)
$$

空间复杂度：

$$
O(n)
$$

## 八、表达式求值——本章第三个大重点

### 1. 中缀、前缀、后缀表达式

例如：

$$
A+B\times C
$$

#### 中缀表达式

运算符在两个操作数中间。

```text
A + B * C
```

#### 前缀表达式

运算符在操作数前面。

```text
+ A * B C
```

#### 后缀表达式

运算符在操作数后面。

```text
A B C * +
```

前缀与后缀表达式的重要优势是：

在运算符元数固定且表达式合法的条件下，不需要通过括号来确定运算顺序。

### 2. 中缀转后缀表达式

这是必考级别的题型。

考虑：

$$
A+B\times(C-D)-E/F
$$

#### 方法一：人工转换

首先分析运算顺序。

第一步：

$$
C-D
$$

后缀表达式：

```text
C D -
```

第二步：

$$
B(C-D)
$$

后缀：

```text
B C D - *
```

第三步：

$$
A+B(C-D)
$$

后缀：

```text
A B C D - * +
```

第四步：

$$
E/F
$$

后缀：

```text
E F /
```

最后：

$$
A+B(C-D)-E/F
$$

得到：

```text
A B C D - * + E F / -
```

即：

$$
\boxed{\texttt{ABCD-*+EF/-}}
$$

这是手工转换最稳的方法：

先确定计算顺序，再把每个运算符放到对应操作数之后。

### 3. 计算机如何用栈完成转换？

需要一个运算符栈。

从左到右扫描中缀表达式。

#### 规则一：遇到操作数

直接输出。

#### 规则二：遇到左括号

直接入栈。

#### 规则三：遇到右括号

不断弹出栈顶运算符并输出，直到遇到对应左括号。

最后丢弃左括号。

#### 规则四：遇到普通运算符

对于本章常见的左结合二元运算符：

```text
+ - * /
```

不断检查栈顶。

如果栈顶运算符的优先级高于或等于当前运算符，则先弹出栈顶。

直到：

- 栈为空；
- 栈顶为左括号；
- 栈顶优先级低于当前运算符。

然后当前运算符入栈。

注意：如果题目包含乘方等右结合运算符，不能机械地对所有等优先级运算符使用同一弹栈规则，还要考虑结合性。

### 4. 完整例题：中缀转后缀

表达式：

$$
A+B\times(C-D)
$$

| 扫描元素 | 运算符栈（底→顶） | 后缀输出     |
| ---- | --------- | -------- |
| A    | 空         | A        |
| +    | +         | A        |
| B    | +         | AB       |
| \*   | +,\*      | AB       |
| (    | +,\*,(    | AB       |
| C    | +,\*,(    | ABC      |
| -    | +,\*,(,-  | ABC      |
| D    | +,\*,(,-  | ABCD     |
| )    | +,\*      | ABCD-    |
| 扫描结束 | 空         | ABCD-\*+ |

最终：

$$
\boxed{\texttt{ABCD-*+}}
$$

如果考试问：

> 扫描过程中运算符栈最大深度是多少？

观察表格：

```text
+ * ( -
```

最多同时保存 4 个运算符。

因此：

$$
\boxed{4}
$$

### 5. 2012 年真题：运算符栈最大深度

真题给出：

$$
a+b-a\times((c+d)/e-f)+g
$$

要求转换为后缀表达式时，运算符栈中同时最多有多少个符号。

答案：

$$
\boxed{5}
$$

关键状态出现在扫描括号中的加号时。

运算符栈自底向顶包含：

```text
-
*
(
(
+
```

共五个符号。

#### 这类题最快的做法

如果只问栈深，不必完整写出最终后缀表达式。

直接建立：

```text
扫描位置
当前运算符栈
当前栈深
最大栈深
```

只记录最大值。

### 6. 2014 年真题：扫描到指定字符时的栈内容

表达式：

$$
a/b+(c\times d-e\times f)/g
$$

问扫描到操作数 $f$ 时，运算符栈中有什么。

按照运算符优先级和括号规则：

1. `a/b` 中的 `/` 遇到 `+` 后先弹出；
2. `+` 入栈；
3. `(` 入栈；
4. 第一个 `*` 入栈；
5. 遇到 `-`，先弹出 `*`；
6. `-` 入栈；
7. 第二个 `*` 入栈；
8. 扫描到 f 时，它是操作数，不改变运算符栈。

此时栈底到栈顶：

```text
+ ( - *
```

即：

$$
\boxed{\texttt{+(-*}}
$$

这类题尤其要注意：

扫描到操作数时，操作数直接进入后缀输出，不会改变运算符栈。

### 7. 后缀表达式求值

后缀表达式求值使用的是操作数栈。

注意与中缀转后缀时的运算符栈区别。

规则：

从左向右扫描。

遇到数字：

```text
Push
```

遇到运算符：

```text
弹出右操作数
弹出左操作数
进行计算
结果入栈
```

最重要的细节：

假设第一次弹出的是 $a$，第二次弹出的是 $b$。

那么应当计算：

$$
\boxed{b\ \mathrm{op}\ a}
$$

而不是：

$$
a\ \mathrm{op}\ b
$$

对于减法与除法尤其重要。

### 8. 完整例题：计算后缀表达式

给定：

```text
6 2 3 + * 4 -
```

#### 第一步

扫描：

```text
6 2 3
```

全部入栈：

```text
栈底 → [6,2,3] ← 栈顶
```

#### 第二步

遇到 `+`。

弹出：

```text
a = 3
b = 2
```

计算：

$$
2+3=5
$$

将 5 入栈：

```text
[6,5]
```

#### 第三步

遇到 `*`。

弹出：

```text
a = 5
b = 6
```

计算：

$$
6\times5=30
$$

入栈：

```text
[30]
```

#### 第四步

扫描到 4，入栈：

```text
[30,4]
```

遇到 `-`：

$$
30-4=26
$$

最终结果：

$$
\boxed{26}
$$

对应的中缀表达式为：

$$
6(2+3)-4
$$

### 9. 2018 年真题：两个栈求值

已知操作数栈从栈底到栈顶为：

```text
5 8 3 2
```

运算符栈为：

```text
* - +
```

每次从操作数栈弹出两个数，并计算：

$$
b\ \mathrm{op}\ a
$$

连续调用三次。

第一次：

$$
3+2=5
$$

操作数栈变成：

```text
5 8 5
```

第二次：

$$
8-5=3
$$

变成：

```text
5 3
```

第三次：

$$
5\times3=15
$$

最终：

$$
\boxed{15}
$$

这道题本身不难，但特别容易把减法的操作数顺序弄反。

### 10. 运算符栈和操作数栈千万别混淆

| 比较   | 运算符栈     | 操作数栈         |
| ---- | -------- | ------------ |
| 用途   | 中缀转后缀    | 后缀求值         |
| 栈中元素 | 运算符与括号   | 数值或操作数       |
| 入栈规则 | 由优先级决定   | 遇到操作数入栈      |
| 出栈规则 | 优先级、括号触发 | 遇到运算符弹出操作数   |
| 最大深度 | 统计暂存运算符  | 统计尚未完成运算的操作数 |

模拟题很喜欢考：

> 栈容量只有 3，哪个表达式计算时会发生上溢？

例如：

```text
A B C D - * - E +
```

前四个操作数：

```text
A B C D
```

尚未遇到运算符。

因此操作数栈必须同时保存四个元素：

$$
\boxed{\text{最大栈深至少为 }4}
$$

容量为 3 必然发生上溢。

## 九、递归、DFS、BFS 与系统应用

### 1. 递归为什么使用栈？

考虑函数：

```c
int f(int n) {
    if (n == 0)
        return 0;

    return f(n - 1) + n;
}
```

调用：

```text
f(3)
```

调用顺序：

```text
f(3)
 ↓
f(2)
 ↓
f(1)
 ↓
f(0)
```

返回顺序恰好相反：

```text
f(0)
 ↓
f(1)
 ↓
f(2)
 ↓
f(3)
```

即：

最后调用的函数最先返回。

符合：

$$
\boxed{\text{LIFO}}
$$

所以递归通常依靠系统调用栈保存：

- 返回地址；
- 参数；
- 局部变量；
- 调用现场等信息。

#### 2015 年真题

若：

```text
main() 调用 s(1)
s(1) 调用 s(0)
```

那么最深处调用栈的顺序是：

```text
栈底
main()
s(1)
s(0)
栈顶
```

答案：

$$
\boxed{main\rightarrow s(1)\rightarrow s(0)}
$$

需要注意：

把递归改写为非递归，不一定必须显式使用栈。

例如简单的尾递归或递推问题，有时可以直接改写成循环。

### 2. DFS 与 BFS

#### DFS：深度优先搜索

特点：

```text
沿着一条路径不断深入
走不动以后再回退
```

通常使用：

$$
\boxed{\text{栈}}
$$

递归 DFS 使用系统调用栈。

#### BFS：广度优先搜索

特点：

```text
先发现的结点
先被扩展
```

通常使用：

$$
\boxed{\text{队列}}
$$

以后学习二叉树层序遍历、图的广度优先遍历时，都会用到队列。

#### 实际场景

| 场景     | 常用结构 | 原因        |
| ------ | ---- | --------- |
| 函数调用   | 栈    | 后调用先返回    |
| 括号匹配   | 栈    | 最近的左括号先匹配 |
| DFS    | 栈    | 深入和回溯     |
| BFS    | 队列   | 先发现先扩展    |
| 树的层序遍历 | 队列   | 按层次顺序处理   |
| 打印缓冲区  | 队列   | 按到达次序处理   |
| 表达式求值  | 栈    | 保存暂未完成的运算 |

2009 年真题曾直接考查打印缓冲区应使用什么逻辑结构，答案是队列。

### 3. 2016 年火车轨道题

输入次序：

```text
8 4 2 5 3 9 1 6 7
```

要求最终按照：

```text
1 2 3 4 5 6 7 8 9
```

输出。

每条轨道中的列车只能保持其驶入后的相对先后顺序。

问至少需要多少条轨道。

#### 核心转化

同一条轨道中的列车应形成递增子序列。

例如：

```text
4 5 6 7
```

可以放在同一条轨道。

但：

```text
8 4
```

不能放在同一条轨道后仍按要求递增输出。

因此问题转化成：

> 最少用多少个递增子序列覆盖原序列？

经典结论：

$$
\boxed{ \text{最少递增子序列数} = \text{最长严格下降子序列长度} }
$$

原序列中存在：

```text
8 4 2 1
```

长度为 4。

因此至少需要 4 条轨道。

另一方面可以划分为：

```text
轨道1：8 9
轨道2：4 5 6 7
轨道3：2 3
轨道4：1
```

所以 4 条足够。

答案：

$$
\boxed{4}
$$

这道题说明，栈和队列的应用题有时会结合序列划分等算法思想，而不仅仅考查基本操作。

## 十、3.4 数组——重点是存储地址计算

### 1. 数组的基本概念

数组是一组类型相同的数据元素构成的有序集合。

数组具有两个重要特点：

- 元素通过下标定位；
- 顺序存储的数组元素按一定规则占据连续存储空间。

对于数组：

```text
int A[5];
```

假设：

```text
A[0] A[1] A[2] A[3] A[4]
```

每个元素占 4 字节。

那么相邻元素的起始地址相差 4 字节。

数组访问指定下标元素的时间复杂度通常是：

$$
\boxed{O(1)}
$$

因为可以直接计算地址，而不需要依次遍历前面的元素。

### 2. 二维数组如何存储？

二维数组在逻辑上是一个表格。

例如：

$$
A_{3\times4}
$$

```text
a00 a01 a02 a03
a10 a11 a12 a13
a20 a21 a22 a23
```

但内存是线性排列的。

因此必须把二维下标转换为一维偏移量。

主要有：

- 行优先；
- 列优先。

### 3. 行优先存储

设：

$$
A[m][n]
$$

表示：

- $m$ 行；
- $n$ 列；
- 下标从 0 开始；
- 每个元素占 $w$ 字节。

数组基址为：

$$
Base
$$

求：

$$
A[i][j]
$$

的地址。

#### 推导

在第 $i$ 行之前，有 $i$ 个完整的行。

每行有 $n$ 个元素。

因此前面完整行共有：

$$
in
$$

个元素。

在当前行内，$A[i][j]$ 前面又有：

$$
j
$$

个元素。

所以总偏移量：

$$
in+j
$$

因此：

$$
\boxed{ LOC(A[i][j]) = Base+(in+j)w }
$$

记忆方式：

行优先：先数完整的行，再数当前行中的列。

### 4. 列优先存储

仍然设：

$$
A[m][n]
$$

按列优先存储时：

在第 $j$ 列之前，有 $j$ 个完整列。

每列有 $m$ 个元素。

因此：

$$
jm
$$

当前列内再偏移：

$$
i
$$

所以：

$$
\boxed{ LOC(A[i][j]) = Base+(jm+i)w }
$$

记忆方式：

列优先：先数完整的列，再数当前列中的行。

### 5. 行优先与列优先公式对比

| 存储方式 | 偏移量        |
| ---- | ---------- |
| 行优先  | $in+j$ |
| 列优先  | $jm+i$ |

这里：

- $m$ 是行数；
- $n$ 是列数；
- $i$ 是当前行号；
- $j$ 是当前列号。

特别注意：

行优先公式乘的是列数，列优先公式乘的是行数。

因为一个完整行包含 $n$ 个元素，一个完整列包含 $m$ 个元素。

### 6. 2021 年真题：反推二维数组列数

已知数组按行优先存储。

每个元素占一个存储单元。

$$
LOC(A[0][0])=100
$$

$$
LOC(A[3][3])=220
$$

求：

$$
LOC(A[5][5])
$$

<Steps>
<Step>

### 第一步：设每行有 n 列

行优先公式：

$$
LOC(A[i][j])=100+in+j
$$

</Step>
<Step>

### 第二步：代入已知条件

$$
100+3n+3=220
$$

所以：

$$
3n=117
$$

得到：

$$
n=39
$$

</Step>
<Step>

### 第三步：求目标地址

$$
LOC(A[5][5]) = 100+5\times39+5
$$

因此：

$$
\boxed{300}
$$

这道题的重要思路是：

如果题目没有给出数组维度，可以利用两个已知元素的地址反推维度。

</Step>
</Steps>
### 7. 带非零下界的数组

考试也可能给：

$$
A[L_1\ldots U_1][L_2\ldots U_2]
$$

此时不能直接使用 $in+j$，因为下标不是从 0 开始。

设总列数：

$$
N=U_2-L_2+1
$$

行优先：

$$
\boxed{ LOC(A[i][j]) = Base+ \left[(i-L_1)N+(j-L_2)\right]w }
$$

这个公式更加通用。

如果：

$$
L_1=L_2=0
$$

就退化为：

$$
Base+(iN+j)w
$$

**矩阵压缩无需死记大量公式**

统一先数**前面完整行（列）的存储元素个数**，再加上**当前行（列）中的偏移**。对称矩阵先把下标映射到实际保存的三角区域，再代入公式。

## 十一、特殊矩阵压缩存储——本章第四个大重点

特殊矩阵的核心不是公式，而是：

$$
\boxed{ \text{存储下标} = \text{前面完整部分的元素数量} + \text{当前部分偏移} }
$$

建议每一道矩阵压缩题都按照这个原则推导。

### 1. 为什么要压缩矩阵？

考虑一个对称矩阵：

$$
A= \begin{bmatrix} 1&2&3\\ 2&4&5\\ 3&5&6 \end{bmatrix}
$$

观察：

$$
a_{12}=a_{21}
$$

$$
a_{13}=a_{31}
$$

$$
a_{23}=a_{32}
$$

上下两部分信息重复。

如果存储全部 $n^2$ 个元素，就会存在冗余。

所以只保存上三角或下三角即可。

### 2. 对称矩阵

对称矩阵满足：

$$
\boxed{a_{ij}=a_{ji}}
$$

只保存一个三角区域，包括主对角线。

元素数量：

$$
1+2+\cdots+n
$$

因此：

$$
\boxed{\frac{n(n+1)}2}
$$

例如 10 阶对称矩阵：

$$
\frac{10\times11}{2}=55
$$

只需要存储 55 个元素，而不是 100 个。

### 3. 下三角矩阵按行优先

假设原矩阵下标从 1 开始：

$$
1\le j\le i\le n
$$

只保存下三角。

存储次序：

```text
a11

a21 a22

a31 a32 a33

a41 a42 a43 a44

……
```

现在求：

$$
a_{ij}
$$

在从 0 开始的一维数组中的下标。

<Steps>
<Step>

### 第一步：计算前面完整行

第 1 行有 1 个元素。

第 2 行有 2 个。

一直到第 $i-1$ 行。

所以前面共有：

$$
1+2+\cdots+(i-1)
$$

得到：

$$
\frac{i(i-1)}2
$$

</Step>
<Step>

### 第二步：计算当前行偏移

当前行从：

$$
a_{i1}
$$

开始。

因此：

$$
a_{ij}
$$

在当前行内部的偏移是：

$$
j-1
$$

</Step>
<Step>

### 第三步：合并

$$
\boxed{ k=\frac{i(i-1)}2+j-1 }
$$

这个公式适用于：

- 下三角按行优先；
- 原矩阵下标从 1 开始；
- 压缩数组下标从 0 开始。

</Step>
</Steps>
### 4. 上三角矩阵按列优先

存储次序：

```text
a11

a12 a22

a13 a23 a33

a14 a24 a34 a44

……
```

求：

$$
a_{ij},\qquad i\le j
$$

前 $j-1$ 列共有：

$$
1+2+\cdots+(j-1)
$$

个元素。

即：

$$
\frac{j(j-1)}2
$$

当前列内偏移为：

$$
i-1
$$

因此：

$$
\boxed{ k=\frac{j(j-1)}2+i-1 }
$$

同样假定原矩阵从 1 开始编号，压缩数组从 0 开始编号。

### 5. 上三角矩阵按行优先

这是 2018 年真题涉及的模型。

上三角按行存储：

```text
第一行：n个
第二行：n-1个
第三行：n-2个
……
```

要求：

$$
a_{ij},\quad i\le j
$$

#### 前面完整行的元素数

$$
n+(n-1)+\cdots+(n-i+2)
$$

共有 $i-1$ 项。

因此：

$$
\frac{(i-1)(2n-i+2)}2
$$

#### 当前行偏移

因为第 $i$ 行从：

$$
a_{ii}
$$

开始，所以：

$$
j-i
$$

#### 合并

$$
\boxed{ k= \frac{(i-1)(2n-i+2)}2+j-i }
$$

### 6. 2018 年真题：12 阶对称矩阵

设：

$$
n=12
$$

只存上三角，按行优先。

求：

$$
a_{6,6}
$$

的一维数组下标。

第 6 行之前：

```text
第1行：12个
第2行：11个
第3行：10个
第4行：9个
第5行：8个
```

合计：

$$
12+11+10+9+8=50
$$

而：

$$
a_{6,6}
$$

正好是第 6 行第一个被保存的元素。

所以：

$$
\boxed{k=50}
$$

这个例子很能说明：

不背公式，直接数每一行，也能快速做对。

### 7. 2020 年真题：对称矩阵列优先

10 阶对称矩阵，只存上三角，并且按列优先。

求：

$$
a_{7,2}
$$

的压缩数组下标。

首先利用：

$$
a_{7,2}=a_{2,7}
$$

因为只存上三角，所以实际查找：

$$
a_{2,7}
$$

前 6 列存储元素数量：

$$
1+2+3+4+5+6=21
$$

第 7 列中：

```text
a17
a27
a37
……
```

目标是第二个元素。

偏移：

$$
1
$$

因此：

$$
k=21+1
$$

答案：

$$
\boxed{22}
$$

这是对称矩阵最经典的易错点：

如果所求元素不在实际存储的三角区域内，要先交换行列下标。

### 8. 下三角按列优先

这是模拟题中非常典型的变式。

设矩阵下标从 0 开始：

$$
0\le j\le i<n
$$

第 0 列有 $n$ 个元素。

第 1 列有 $n-1$ 个元素。

第 2 列有 $n-2$ 个元素。

所以第 $j$ 列之前共有：

$$
n+(n-1)+\cdots+(n-j+1)
$$

个元素。

化简：

$$
\frac{j(2n-j+1)}2
$$

当前列偏移为：

$$
i-j
$$

因此：

$$
\boxed{ k= \frac{j(2n-j+1)}2+i-j }
$$

这个公式对应的是：

原矩阵下标从 0 开始。

不能直接与前面的 1 基下标公式混用。

### 9. 四种三角存储的公式总表

以下统一采用：

- 原矩阵下标从 1 开始；
- 一维压缩数组下标从 0 开始；
- 矩阵阶数为 $n$。

| 存储方式   | 元素位置 $k$                    |
| ------ | ------------------------------- |
| 下三角行优先 | $\frac{i(i-1)}2+j-1$        |
| 上三角列优先 | $\frac{j(j-1)}2+i-1$        |
| 上三角行优先 | $\frac{(i-1)(2n-i+2)}2+j-i$ |
| 下三角列优先 | $\frac{(j-1)(2n-j+2)}2+i-j$ |

这些公式必须在元素位于对应存储区域内时使用。

对称矩阵可以先交换下标，把元素映射到所保存的半边。

对于真正的上、下三角矩阵，另一侧通常是常量零，可能不会逐个存储。

#### 三角矩阵额外注意

真正的上三角或下三角矩阵，如果非存储区域中的元素都是同一个常量，例如 0，那么有的压缩方案会：

- 保存三角区域的 $\frac{n(n+1)}2$ 个元素；
- 再额外保存一个常量位置。

总存储量为：

$$
\boxed{\frac{n(n+1)}2+1}
$$

而对称矩阵只需要：

$$
\boxed{\frac{n(n+1)}2}
$$

这两种情况一定要区分。

## 十二、三对角矩阵

### 1. 三对角矩阵的定义

三对角矩阵只有：

- 主对角线；
- 主对角线上方紧邻的一条对角线；
- 主对角线下方紧邻的一条对角线；

上的元素可能非零。

即：

$$
\boxed{|i-j|\le1}
$$

其他位置均为 0。

例如：

$$
A= \begin{bmatrix} a_{11}&a_{12}&0&0\\ a_{21}&a_{22}&a_{23}&0\\ 0&a_{32}&a_{33}&a_{34}\\ 0&0&a_{43}&a_{44} \end{bmatrix}
$$

### 2. 三对角矩阵需要存储多少个元素？

对于 $n\ge2$：

第一行：

$$
2
$$

个。

最后一行：

$$
2
$$

个。

中间有：

$$
n-2
$$

行，每行 3 个元素。

所以总量：

$$
2+3(n-2)+2
$$

得到：

$$
\boxed{3n-2}
$$

例如：

$$
n=100
$$

需要：

$$
3\times100-2=298
$$

个存储单元。

相比原来的：

$$
100^2=10000
$$

大幅节约空间。

### 3. 三对角矩阵压缩下标公式

假设：

- 原矩阵下标从 1 开始；
- 只存储 $|i-j|\le1$ 的位置；
- 按行优先；
- 压缩数组从 0 开始；
- $n\ge2$。

则可以推导：

$$
\boxed{k=2i+j-3}
$$

其中：

$$
|i-j|\le1
$$

例如：

$$
a_{30,30}
$$

位置：

$$
k=2\times30+30-3
$$

所以：

$$
\boxed{87}
$$

### 4. 2016 年真题：100 阶三对角矩阵

题目要求计算：

$$
a_{30,30}
$$

的压缩数组下标。

不背公式也能完成。

第 1 行：

$$
2
$$

个元素。

第 2 行到第 29 行：

$$
28
$$

行，每行 3 个元素。

所以第 30 行前已有：

$$
2+28\times3=86
$$

个元素。

第 30 行保存：

```text
a30,29
a30,30
a30,31
```

所以：

$$
a_{30,30}
$$

位于第 30 行的第二个位置。

偏移为 1。

因此：

$$
86+1=87
$$

答案：

$$
\boxed{87}
$$

#### 关键理解

所有压缩矩阵题都可以使用：

$$
\boxed{\text{完整行元素数}+\text{当前行偏移}}
$$

这个方法比单独记忆大量公式更可靠。

## 十三、稀疏矩阵

### 1. 什么是稀疏矩阵？

稀疏矩阵指绝大多数元素都是 0 的矩阵。

例如：

$$
A= \begin{bmatrix} 0&0&0&8\\ 0&0&0&0\\ 0&5&0&0\\ 0&0&0&0 \end{bmatrix}
$$

一共有 16 个位置，但非零元素只有两个。

如果按普通二维数组存储，会浪费大量空间。

所以考虑只保存非零元素。

### 2. 三元组表

三元组表对每个非零元素保存：

$$
\boxed{(row,column,value)}
$$

例如上述矩阵可以表示为：

```text
(0,3,8)
(2,1,5)
```

这里只展示非零元素三元组。

为了完整描述原矩阵，还需要保存：

- 总行数；
- 总列数；
- 通常还记录非零元素个数。

#### 2023 年真题

题目问：采用三元组表存储稀疏矩阵时，除三元组信息外，还必须保存什么？

正确答案：

$$
\boxed{\text{矩阵总行数和总列数}}
$$

为什么不能仅根据非零元素的最大行号、列号推断？

因为矩阵末尾可能有全部为 0 的行或列。

这些行列在三元组中根本不会出现。

所以必须额外保存矩阵的实际维度。

### 3. 十字链表

十字链表也是稀疏矩阵的重要压缩存储结构。

它的核心思想：

一个非零元素同时属于所在行的链表和所在列的链表。

结点通常包含：

```c
typedef struct OLNode {
    int row;
    int col;
    int value;

    struct OLNode *right;
    struct OLNode *down;
} OLNode;
```

其中：

- `right`：连接同一行的下一个非零元素；
- `down`：连接同一列的下一个非零元素。

因此可以沿行或沿列访问非零元素。

#### 三元组表和十字链表比较

| 项目     | 三元组表     | 十字链表         |
| ------ | -------- | ------------ |
| 基本存储单位 | 行、列、值    | 行、列、值和两个方向指针 |
| 存储形式   | 顺序表      | 链式结构         |
| 实现复杂度  | 较低       | 较高           |
| 按行访问   | 可按行排序实现  | 方便           |
| 按列访问   | 可能需要额外处理 | 方便           |
| 动态修改   | 可能需要移动元素 | 主要修改指针       |

2017 年真题考过：

> 适合稀疏矩阵压缩存储的两种结构是什么？

答案：

$$
\boxed{\text{三元组表和十字链表}}
$$

### 4. 稀疏矩阵空间计算

模拟题给定：

- 矩阵大小为 $1000\times850$；
- 非零元素有 1000 个；
- 每个整数占 2 B；
- 每个矩阵元素占 4 B。

如果使用三元组表，一个三元组需要：

行号：

$$
2B
$$

列号：

$$
2B
$$

元素值：

$$
4B
$$

因此每个三元组：

$$
2+2+4=8B
$$

1000 个非零元素：

$$
1000\times8=8000B
$$

答案：

$$
\boxed{8000B}
$$

这是仅计算三元组数据区的空间，不包含额外的矩阵元数据或具体实现可能产生的对齐开销。

## 十四、408 综合算法拓展

以下内容属于知识库中的相关算法专题，以及本章知识的自然延伸。它们值得掌握，但不应挤占核心真题的复习时间。

### 1. 两个栈实现一个队列

目标：

使用两个 LIFO 的栈，实现 FIFO 队列。

定义：

```text
S1：输入栈
S2：输出栈
```

#### 入队

直接压入：

```text
S1
```

#### 出队

如果 `S2` 不为空：

```text
从S2弹出
```

如果 `S2` 为空：

```text
把S1中的全部元素依次弹出
再压入S2
然后从S2弹出
```

例如：

```text
依次入队：1 2 3
```

输入栈：

```text
栈底 → [1,2,3] ← 栈顶
```

倒入输出栈后：

```text
栈底 → [3,2,1] ← 栈顶
```

此时弹出：

```text
1
```

正好符合 FIFO。

#### 复杂度

单次出队最坏可能需要转移：

$$
O(n)
$$

个元素。

但每个元素至多：

- 进入输入栈一次；
- 从输入栈转移一次；
- 进入输出栈一次；
- 从输出栈弹出一次。

因此多次操作的均摊时间复杂度为：

$$
\boxed{O(1)}
$$

辅助空间：

$$
\boxed{O(n)}
$$

这个结论需要区分单次最坏复杂度与均摊复杂度。

### 2. 一个队列实现栈

使用一个普通队列也可以模拟栈。

例如队列当前为：

```text
1 2 3
```

希望执行：

```text
Push(4)
```

先将 4 入队：

```text
1 2 3 4
```

再把前面三个元素依次从队头取出并放回队尾：

```text
4 1 2 3
```

现在队头就是最新插入的元素 4。

所以：

```text
DeQueue()
```

就相当于栈的：

```text
Pop()
```

对于这种实现：

- Push 最坏 $O(n)$；
- Pop $O(1)$。

也可以选择在 Pop 时轮转队列，使 Push 为 $O(1)$、Pop 为 $O(n)$。

### 3. 单调栈

这是算法专题中的高频模型。

典型问题：

> 对数组中的每一个元素，找到其右侧第一个比它大的元素。

例如：

```text
数组：  2 1 4 3 5
```

答案：

```text
4 4 5 5 不存在
```

可以使用单调栈。

从左向右扫描，把下标入栈，并维护栈对应的值从栈底到栈顶单调不增。

如果当前元素比栈顶对应的值更大，就不断弹出栈顶，并确定它右侧第一个更大元素的位置。

因为每个下标最多入栈、出栈各一次：

$$
\boxed{O(n)}
$$

典型题：

[每日温度](https://fumadocscf.any1.tech/docs/algorithm/12-monotonic-stack/01-%E6%AF%8F%E6%97%A5%E6%B8%A9%E5%BA%A6/)

这类算法可以理解为：

使用栈保存尚未得到答案的元素。

### 4. 单调队列与滑动窗口最大值

典型题：

[滑动窗口最大值](https://fumadocscf.any1.tech/docs/algorithm/07-stack-queue/07-%E6%BB%91%E5%8A%A8%E7%AA%97%E5%8F%A3%E6%9C%80%E5%A4%A7%E5%80%BC/)

给定：

```text
nums = [1,3,-1,-3,5,3,6,7]
k = 3
```

要求求出每个长度为 3 的连续窗口的最大值。

答案：

```text
[3,3,5,5,6,7]
```

暴力方法每个窗口遍历一次：

$$
O(nk)
$$

使用单调队列可以做到：

$$
\boxed{O(n)}
$$

核心是维护一个双端队列，保存仍可能成为当前或未来窗口最大值的下标。

从队头到队尾，对应元素值单调不增。

每次加入一个新元素时：

1. 删除已经离开窗口的队头下标；
2. 从队尾删除不大于新元素的旧元素下标；
3. 将新元素下标加入队尾；
4. 当前窗口形成后，队头就是最大值的位置。

每个元素最多进入、离开队列一次，所以总复杂度是：

$$
O(n)
$$

这里真正有用的思想是：

可以删除那些在未来也不可能成为最优答案的候选元素。

## 十九、考前必须记住的核心公式

### 1. 栈

Catalan 数：

$$
\boxed{ C_n=\frac{1}{n+1}\binom{2n}{n} }
$$

最小栈容量：

$$
\boxed{ C_{\min}=\max(\text{运行过程中的栈深}) }
$$

### 2. 循环队列

采用 `front` 指队头、`rear` 指队尾后一空位、牺牲一格的模型。

队空：

$$
\boxed{front=rear}
$$

队满：

$$
\boxed{(rear+1)\bmod m=front}
$$

队列长度：

$$
\boxed{(rear-front+m)\bmod m}
$$

最大容量：

$$
\boxed{m-1}
$$

### 3. 二维数组地址

行优先：

$$
\boxed{ LOC(A[i][j])=Base+(in+j)w }
$$

列优先：

$$
\boxed{ LOC(A[i][j])=Base+(jm+i)w }
$$

其中数组下标从 0 开始，矩阵为 $m$ 行 $n$ 列。

### 4. 对称矩阵

压缩元素数量：

$$
\boxed{\frac{n(n+1)}2}
$$

### 5. 三角矩阵

原矩阵从 1 编号，压缩数组从 0 编号。

下三角按行：

$$
\boxed{k=\frac{i(i-1)}2+j-1}
$$

上三角按列：

$$
\boxed{k=\frac{j(j-1)}2+i-1}
$$

上三角按行：

$$
\boxed{k=\frac{(i-1)(2n-i+2)}2+j-i}
$$

下三角按列：

$$
\boxed{k=\frac{(j-1)(2n-j+2)}2+i-j}
$$

### 6. 三对角矩阵

存储元素总数：

$$
\boxed{3n-2}
$$

下标映射：

$$
\boxed{k=2i+j-3}
$$

这里要求原矩阵从 1 编号、压缩数组从 0 编号、按行存储，且目标元素位于三条对角线上。

## 二十、本章应该如何复习才能真正掌握？

结合知识库的真题分布，建议分成三个层次。

### 第一层：必须形成条件反射

以下题型最好达到看到题目就能立即开始计算：

- 合法出栈序列：直接模拟。
- 最小栈容量：记录最大栈深。
- 循环队列：先确认指针定义。
- 表达式：区分运算符栈和操作数栈。
- 对称矩阵：先定位存储区域。
- 三对角矩阵：数前面的行和当前行偏移。

这些是本章得分的基础。

### 第二层：能够独立完成代码

建议至少手写以下六种算法：

1. 顺序栈入栈与出栈；
2. 循环队列入队与出队；
3. 链式队列入队与出队；
4. 合法出栈序列判断；
5. 括号匹配；
6. 两个栈实现队列。

然后再完整写一遍 2019 年空间复用队列大题。

写代码时，必须特别检查空结构、满结构、只有一个元素以及动态分配失败等边界情况。

### 第三层：掌握综合变式

这一层主要准备：

- 受限双端队列；
- 栈和队列组合；
- 递归调用栈；
- 多维数组地址；
- 不同方向的对称矩阵压缩；
- 指定首元素的栈序列计数；
- 单调栈和单调队列等拓展模型。

这部分是区分“会做常规选择题”和“能解决综合题”的关键。

## 最终总结：第 3 章其实只有三条底层思想

第一条：栈和队列的本质是操作顺序受到约束。

栈：

$$
\boxed{\text{后进先出}}
$$

队列：

$$
\boxed{\text{先进先出}}
$$

无论题目是出栈序列、受限双端队列，还是栈与队列综合，最终都是研究哪些操作顺序可以实现。

第二条：所有指针公式都依赖于指针的定义。

包括：

```text
top
front
rear
end1
end2
```

做题时必须先明确指针究竟指向元素还是空位，然后才判断空、满、长度和更新顺序。

第三条：所有数组地址与特殊矩阵压缩题，本质上都是计算偏移量。

统一思想：

$$
\boxed{ \text{位置} = \text{前面完整部分的元素数} + \text{当前部分的偏移} }
$$

这条原则可以解决普通二维数组、对称矩阵、三角矩阵、三对角矩阵以及更复杂的多维数组问题。

本章最值得反复练习的三道大题模型，是合法出栈序列的线性时间判断、2019 年可复用空间的循环链式队列设计，以及 2026 年第 42 题中的出栈序列与 Catalan 数综合。

如果能不看答案独立推导这三类题，并熟练完成循环队列、表达式转换和矩阵压缩计算，那么第 3 章的主要知识点和常见 408 考法就基本掌握了。
