## 第二部分：栈
### 三、栈的基本概念
#### 3.1 什么是栈？
栈（Stack）是一种只允许在线性表一端进行插入和删除的受限线性表。

允许操作的一端称为栈顶。

另一端称为栈底。

两个基本操作：

- Push：入栈。
- Pop：出栈。

栈的特点：

**后进先出，LIFO。**

例如：

    Push(1)
    Push(2)
    Push(3)

此时：

    栈顶
      ↓
    ┌───┐
    │ 3 │
    ├───┤
    │ 2 │
    ├───┤
    │ 1 │
    └───┘
    栈底

连续执行三次 Pop：

    3、2、1

这里要区分两个概念：

- 栈的逻辑结构仍然是线性结构。
- 栈的操作受到严格限制。

因此：

<Callout type="idea" title="核心结论">

**栈是操作受限的线性表，不是一种非线性结构。**

</Callout>

#### 3.2 栈的基本操作
| 操作 | 作用 | 常见时间复杂度 |
|---|---|---|
| InitStack | 初始化 | $O(1)$ |
| StackEmpty | 判断是否为空 | $O(1)$ |
| Push | 入栈 | $O(1)$ |
| Pop | 出栈 | $O(1)$ |
| GetTop | 读取栈顶 | $O(1)$ |

注意：

读取栈顶和弹出栈顶不同。

例如：

    栈：[1,2,3]

执行 GetTop：

    返回 3
    栈仍然是 [1,2,3]

执行 Pop：

    返回 3
    栈变为 [1,2]

#### 3.3 栈的基本应用
常见场景：

1. 函数调用。
2. 递归。
3. 括号匹配。
4. 表达式转换。
5. 表达式求值。
6. 深度优先搜索。
7. 回溯。

一个很重要的认识：

这些应用都利用了某种“后出现的信息需要先处理”的性质。

例如递归：

    main()
       ↓
      f(3)
       ↓
      f(2)
       ↓
      f(1)

运行到 f(1) 后，返回过程是：

    f(1) → f(2) → f(3) → main()

这就是栈。


### 四、顺序栈
#### 4.1 顺序栈的存储结构
顺序栈用数组保存数据。

例如：

```c
#define MAXSIZE 100

typedef struct {
    int data[MAXSIZE];
    int top;
} SqStack;
```

最重要的是：

**top 到底表示什么？**

通常有两种约定。

##### 约定一：top 指向当前栈顶元素
假设数组下标为：

    0  1  2  3  4

栈中存放：

    10 20 30

则：

    data[0] = 10
    data[1] = 20
    data[2] = 30

    top = 2

因此：

空栈：

$$
top=-1
$$

栈满：

$$
top=MaxSize-1
$$

元素数量：

$$
n=top+1
$$

入栈：

```c
S.data[++S.top] = x;
```

出栈：

```c
x = S.data[S.top--];
```

为什么入栈要先加一？

因为 top 当前指向旧栈顶。

新元素应放在旧栈顶的后一格。

为什么出栈要先取值？

因为应先读取当前栈顶元素，再让 top 下移。

##### 约定二：top 指向下一个可插入的位置
此时：

空栈：

$$
top=0
$$

元素数量：

$$
n=top
$$

栈满：

$$
top=MaxSize
$$

入栈：

```c
S.data[S.top++] = x;
```

出栈：

```c
x = S.data[--S.top];
```

两种约定总结：

| top 语义 | 空栈 | 栈满 | 入栈 | 出栈 |
|---|---|---|---|---|
| 当前栈顶 | -1 | MaxSize-1 | ++top 后写 | 先读后 top-- |
| 下一空位 | 0 | MaxSize | 先写后 top++ | --top 后读 |

**考试重点：不能只背代码，必须先看题目如何定义 top。**

#### 4.2 顺序栈完整实现
以下采用 top 指向当前栈顶元素的约定。

```c
#include <stdbool.h>

#define MAXSIZE 100

typedef struct {
    int data[MAXSIZE];
    int top;
} SqStack;

void InitStack(SqStack *S) {
    S->top = -1;
}

bool StackEmpty(SqStack *S) {
    return S->top == -1;
}

bool StackFull(SqStack *S) {
    return S->top == MAXSIZE - 1;
}

bool Push(SqStack *S, int x) {
    if (StackFull(S))
        return false;

    S->data[++S->top] = x;
    return true;
}

bool Pop(SqStack *S, int *x) {
    if (StackEmpty(S))
        return false;

    *x = S->data[S->top--];
    return true;
}

bool GetTop(SqStack *S, int *x) {
    if (StackEmpty(S))
        return false;

    *x = S->data[S->top];
    return true;
}
```

所有基本操作时间复杂度均为：

$$
O(1)
$$

注意：

这里说的是固定容量顺序栈。

如果使用动态数组扩容，单次扩容可能达到 $O(n)$，但按倍数扩容的 Push 可以具有均摊 $O(1)$ 时间复杂度。


### 五、共享栈
#### 5.1 为什么需要共享栈？
假设有两个栈：

- 栈 1 经常存储很多元素。
- 栈 2 通常只存几个元素。

如果分别分配固定大小数组：

    Stack1：[满满满满满]
    Stack2：[少量元素 + 大量空闲]

可能出现：

栈 1 已满，但栈 2 还有大量未使用空间。

解决思路：

让两个栈共享一个数组。

#### 5.2 共享栈的基本结构
例如数组长度为 8：

    下标：
    0 1 2 3 4 5 6 7

    S1 →         ← S2

两个栈从两端向中间增长。

常见约定：

- top1 指向左侧栈的当前栈顶。
- top2 指向右侧栈的当前栈顶。

初始化：

$$
top_1=-1
$$

$$
top_2=MaxSize
$$

左侧入栈：

```c
data[++top1] = x;
```

右侧入栈：

```c
data[--top2] = x;
```

当两个栈的栈顶相邻时，数组已满。

判满条件：

$$
top_1+1=top_2
$$

#### 5.3 另一个高频约定
2027 王道模拟卷涉及另一种定义：

两个 top 都指向各自增长方向上的下一可用位置。

初始化：

$$
top_1=0
$$

$$
top_2=MaxSize-1
$$

入栈：

```c
data[top1++] = x;

data[top2--] = y;
```

这时判满条件变为：

$$
\boxed{top_1=top_2+1}
$$

为什么？

假设数组下标为 0 到 5。

当左栈占用 0、1、2，右栈占用 3、4、5 时：

    左侧下一位置：top1 = 3
    右侧下一位置：top2 = 2

已经没有空位。

因此：

$$
top_1=top_2+1
$$

而：

$$
top_1=top_2
$$

表示还剩最后一个位置。

##### 模拟题总结
共享栈的考题通常不会直接问“什么是共享栈”。

而是给定：

- 初始指针。
- 指针增长方向。
- 入栈操作形式。

再要求判断：

- 哪个判满公式正确。
- 某个入栈语句是否正确。
- 剩余空间数量。

解题步骤：

1. 写出每个 top 的语义。
2. 画出两个栈占用的区间。
3. 判断两个指针之间有多少空位。
4. 再写判满条件。


### 六、链栈
#### 6.1 链栈的基本思想
链栈采用链式存储。

最自然的方案：

**让链表的头部作为栈顶。**

例如：

    top
     ↓
    [30] → [20] → [10] → NULL

入栈：

在链表头部插入新结点。

出栈：

删除链表第一个结点。

两者都是：

$$
O(1)
$$

#### 6.2 为什么通常不把单链表尾部作为栈顶？
如果将尾部作为栈顶：

    10 → 20 → 30 → NULL
               ↑
              top

入栈可以通过尾指针快速完成。

但出栈时：

必须找到 30 的前驱 20。

普通单链表不能直接找到前驱。

需要从表头遍历：

$$
O(n)
$$

所以通常选择链头作为栈顶。

#### 6.3 链栈实现
采用不带头结点的单链表。

```c
typedef struct StackNode {
    int data;
    struct StackNode *next;
} StackNode;
```

入栈：

```c
bool Push(StackNode **top, int x) {
    StackNode *p = malloc(sizeof(StackNode));

    if (p == NULL)
        return false;

    p->data = x;
    p->next = *top;
    *top = p;

    return true;
}
```

出栈：

```c
bool Pop(StackNode **top, int *x) {
    if (*top == NULL)
        return false;

    StackNode *p = *top;

    *x = p->data;
    *top = p->next;

    free(p);

    return true;
}
```

重点是指针修改顺序。

先保留原栈顶结点。

再读取数据。

然后移动 top。

最后释放原结点。

#### 6.4 模拟题：链栈出栈语句
假设：

    top → [A] → [B] → [C]

要求删除 A 并将值保存到 x。

核心操作为：

```c
x = top->data;
top = top->next;
```

但这两行只是逻辑操作。

完整程序还要：

```c
StackNode *p = top;
x = p->data;
top = p->next;
free(p);
```

常见错误：

```c
top = top->next;
x = top->data;
```

这样取得的是 B，不是 A。

如果原栈只有一个结点，还可能解引用 NULL。


## 第三部分：出栈序列——全章最重要的考点之一
### 七、固定入栈顺序与合法出栈序列
#### 7.1 核心问题
假设输入顺序固定：

    1,2,3,4

允许入栈、出栈交替进行。

哪些出栈序列合法？

合法示例：

    1,2,3,4

每次入栈后立即出栈。

合法示例：

    4,3,2,1

全部入栈后再出栈。

合法示例：

    2,3,1,4

操作过程：

    Push 1
    Push 2
    Pop  → 2
    Push 3
    Pop  → 3
    Pop  → 1
    Push 4
    Pop  → 4

不合法示例：

    3,1,2,4

原因：

为了首先输出 3：

    Push 1
    Push 2
    Push 3
    Pop → 3

剩余栈：

    栈底 [1,2] 栈顶

下一目标是 1。

但栈顶为 2。

不能越过 2 取出 1。

因此不合法。

#### 7.2 一种能够应对所有普通出栈序列题的方法
**栈模拟。**

对于每个目标输出元素：

1. 如果该元素还没有入栈，依照固定输入顺序不断入栈，直到它入栈。
2. 检查它是不是栈顶。
3. 如果是，弹出。
4. 如果不是，序列不合法。

时间复杂度：

$$
O(n)
$$

因为每个元素最多入栈一次、出栈一次。

#### 7.3 标准算法模板
输入：

    1,2,...,n

目标出栈排列：

    P[0],P[1],...,P[n-1]

```c
#include <stdbool.h>

bool CheckPopOrder(const int P[], int n) {
    int stack[n > 0 ? n : 1];

    int top = -1;
    int next = 1;

    for (int i = 0; i < n; i++) {
        int x = P[i];

        if (x < 1 || x > n)
            return false;

        while (next <= x) {
            stack[++top] = next;
            next++;
        }

        if (top == -1 || stack[top] != x)
            return false;

        top--;
    }

    return true;
}
```

说明：

代码假设输入长度为 n，要求目标是 1 到 n 的排列。

对合法排列而言，上述模拟足以完成判定。

如果要编写完全通用的函数，还可额外检查目标值是否重复。

#### 7.4 算法为什么正确？
如果目标元素 x 尚未入栈：

必须先把它前面的所有元素依次入栈。

否则无法取到 x。

如果 x 已经在栈内：

继续入栈只能把新元素压在它上面。

如果 x 此时不是栈顶，就不可能通过继续入栈让它变成栈顶。

因此：

**当目标元素已入栈，但不在栈顶时，可以立即判定失败。**

这也是贪心模拟正确的原因。


### 八、真题：2009 年最小栈容量
#### 8.1 题目
元素：

    a,b,c,d,e,f,g

依次进入栈 S。

每个元素出栈后立即进入队列 Q。

队列最终出队顺序为：

    b,d,c,f,e,a,g

问：

栈 S 的最小容量是多少？

#### 8.2 第一步：理解队列的作用
队列是 FIFO。

从栈出来的元素按顺序进入队列。

因此：

队列的输出顺序与栈的输出顺序一致。

目标栈输出序列就是：

    b,d,c,f,e,a,g

#### 8.3 第二步：模拟
| 操作 | 栈内状态 | 当前深度 |
|---|---|---|
| Push a | a | 1 |
| Push b | a,b | 2 |
| Pop b | a | 1 |
| Push c | a,c | 2 |
| Push d | a,c,d | 3 |
| Pop d | a,c | 2 |
| Pop c | a | 1 |
| Push e | a,e | 2 |
| Push f | a,e,f | 3 |
| Pop f | a,e | 2 |
| Pop e | a | 1 |
| Pop a | 空 | 0 |
| Push g | g | 1 |
| Pop g | 空 | 0 |

最大深度：

$$
3
$$

答案：

$$
\boxed{3}
$$

#### 8.4 这道题真正教会我们什么？
题目求的是：

**产生某个出栈序列时，栈中同时存放元素的最大数量。**

不是：

- 入栈总次数。
- 元素总数。
- 最后一次出栈时栈内的数量。

同类题的通用公式：

$$
\text{最小所需栈容量}
=
\max_t \{\text{时刻 }t\text{ 的栈深}\}
$$

对固定输入和完整目标输出序列，采用“尽早弹出当前所需元素”的模拟即可求出最小所需容量。


### 九、模拟题：栈容量限制
#### 9.1 题目
栈最多容纳 3 个元素。

输入：

    1,2,3,4,5

下面哪个输出合法？

A：

    3,2,1,5,4

B：

    1,5,4,3,2

C：

    5,4,3,2,1

D：

    4,3,2,1,5

#### 9.2 分析
##### A
先入：

    1,2,3

然后输出：

    3,2,1

栈空。

再入：

    4,5

输出：

    5,4

最大深度为 3。

合法。

##### B
先输出 1。

然后希望输出 5。

此时必须依次压入：

    2,3,4,5

需要同时保存 4 个元素。

超过容量 3。

不合法。

##### C
第一个输出 5。

必须先将：

    1,2,3,4,5

全部压入。

需要容量 5。

不合法。

##### D
第一个输出 4。

至少需要同时压入 1、2、3、4。

需要容量 4。

不合法。

答案：

$$
\boxed{A}
$$

#### 9.3 做题技巧
如果输出序列开头出现较大的编号：

应首先检查为了输出该元素，必须同时压入多少个尚未弹出的元素。

这是判断容量是否足够的最快方法之一。


### 十、真题：2010 年禁止连续三次出栈
#### 10.1 题目
输入：

    a,b,c,d,e,f

允许入栈和出栈交替进行。

但不允许连续执行三次出栈操作。

问哪个输出不可能？

A：

    d,c,e,b,f,a

B：

    c,b,d,a,e,f

C：

    b,c,a,e,f,d

D：

    a,f,e,d,c,b

答案：

$$
\boxed{D}
$$

#### 10.2 为什么 D 不可能？
要先输出 a：

    Push a
    Pop a

接着希望输出 f。

必须把剩余元素：

    b,c,d,e,f

依次入栈。

因为已经没有后续输入元素，想输出：

    f,e,d,c,b

只能不断出栈。

这会连续出栈 5 次。

违反“不允许连续三次出栈”。

#### 10.3 新题应该怎么处理？
普通栈模拟只检查能否输出。

如果题目增加限制：

- 不能连续出栈三次。
- 栈容量最多为 k。
- 某些元素必须相邻出栈。
- 某些位置只能入栈。
- 某些操作顺序被指定。

就需要把这些约束同时加入模拟。

特别注意：

**题目不是只要求输出顺序合法，还要求整个操作序列合法。**


### 十一、出栈排列的 312 禁形
这是 2026 年综合大题的关键理论。

#### 11.1 什么叫 312 禁形？
固定入栈顺序：

$$
1,2,\ldots,n
$$

如果某个输出排列中存在三个位置：

$$
i<j<k
$$

满足：

$$
\boxed{P_j<P_k<P_i}
$$

那么该输出序列不合法。

这三个元素按出现顺序呈现：

    大、小、中

即相对大小关系：

    3、1、2

称为 312 型禁形。

#### 11.2 为什么 312 不合法？
考虑输出序列：

    3,1,2

为了先输出 3：

必须已经依次压入：

    1,2,3

弹出 3 后：

    栈底 [1,2] 栈顶

下一步要求输出 1。

但 2 压在 1 上面。

因此不合法。

#### 11.3 推广证明
假设输出依次出现：

$$
a,b,c
$$

并且：

$$
a>c>b
$$

由于 a 最先出栈：

输入过程中必须已经将 1 到 a 全部压入过栈。

所以 b 和 c 一定已经入过栈。

因为：

$$
b<c
$$

固定递增输入意味着 b 比 c 更早入栈。

而在 b 出栈之前，c 尚未出栈。

因此 c 仍然压在 b 上面。

于是 b 无法先于 c 出栈。

产生矛盾。

#### 11.4 312 禁形是否也是充分条件？
是。

对于固定递增输入的单个普通栈：

$$
\boxed{
\text{合法出栈排列}
\iff
\text{不存在 312 禁形}
}
$$

可以从模拟失败反过来证明。

如果模拟第一次在目标元素 b 处失败：

说明 b 已经在栈中，但它上面还有某个更大的元素 c。

由于 c 已经入过栈，之前必然存在某个更大的输出元素 a，使输入至少推进到了 a。

于是：

$$
a>c>b
$$

对应一个 312 禁形。

#### 11.5 考试怎么用？
判断具体序列时：

优先使用 $O(n)$ 栈模拟。

解释某个序列为什么不合法时：

指出第一次栈顶冲突。

如果题目要求总结数学条件：

写出 312 禁形。

不要真的枚举所有三元组来判断一个排列，因为直接枚举会增加不必要的时间复杂度。


### 十二、卡特兰数
#### 12.1 为什么会出现卡特兰数？
输入：

    1,2,...,n

每个元素必须：

- 入栈一次。
- 出栈一次。

允许两种操作交替进行。

因此总共：

$$
2n
$$

次操作。

把入栈记为：

    (

把出栈记为：

    )

合法操作序列必须满足：

任意前缀中的入栈次数不少于出栈次数。

即：

$$
\#Push\ge\#Pop
$$

并且最后：

$$
\#Push=\#Pop=n
$$

这与合法括号序列计数完全一致。

因此得到卡特兰数。

#### 12.2 卡特兰数公式
$$
\boxed{
C_n=\frac{1}{n+1}\binom{2n}{n}
}
$$

等价形式：

$$
C_n=\frac{(2n)!}{n!(n+1)!}
$$

前几个值：

| n | $C_n$ |
|---|---|
| 0 | 1 |
| 1 | 1 |
| 2 | 2 |
| 3 | 5 |
| 4 | 14 |
| 5 | 42 |
| 6 | 132 |
| 7 | 429 |
| 8 | 1430 |
| 9 | 4862 |
| 10 | 16796 |

#### 12.3 卡特兰数递推式
$$
C_0=1
$$

$$
\boxed{
C_n=\sum_{i=0}^{n-1}C_iC_{n-1-i}
}
$$

另一种重要递推：

$$
\boxed{
C_n=\frac{2(2n-1)}{n+1}C_{n-1}
}
$$

第二个公式非常适合处理“已知 $C_{n-1}$，求 $C_n$”的问题。

#### 12.4 用 n=3 理解卡特兰数
输入：

    1,2,3

全部合法输出排列：

    123
    132
    213
    231
    321

共：

$$
C_3=5
$$

唯一不合法的排列：

    312

它恰好是 312 禁形本身。

#### 12.5 卡特兰数的适用条件
必须注意：

普通卡特兰数适用于：

- n 个不同元素。
- 固定输入顺序。
- 一个普通栈。
- 每个元素入栈一次、出栈一次。
- 没有额外容量或操作限制。

如果增加：

    栈容量不超过 2

或者：

    第一个出栈元素必须是 3

就不能直接把答案写成 $C_n$。

必须进一步分类、建立递推或利用动态规划。


### 十三、真题：2011 年固定第一个出栈元素
#### 13.1 题目
输入：

    a,b,c,d,e

问：

以 d 开头的合法出栈序列共有多少个？

#### 13.2 分析
因为 d 是第一个出栈元素。

首先必须：

    Push a
    Push b
    Push c
    Push d
    Pop d

剩余栈：

    [a,b,c]

尚未入栈：

    e

此后可以在不同阶段压入 e。

分别得到：

    d,c,b,a,e

    d,c,b,e,a

    d,c,e,b,a

    d,e,c,b,a

因此共有：

$$
\boxed{4}
$$

#### 13.3 为什么不直接用卡特兰数？
虽然共有 5 个元素：

$$
C_5=42
$$

但题目固定了第一个出栈元素。

而且该元素是第 4 个输入元素。

原来的一部分操作已经被强制确定。

因此需要考虑剩余栈状态。

**固定首元素类问题的核心是：先锁定被迫发生的操作，再分析剩余状态。**


### 十四、真题：2013 年第三个出栈元素的取值
#### 14.1 题目
输入：

$$
1,2,\ldots,n
$$

输出：

$$
p_1,p_2,\ldots,p_n
$$

已知：

$$
p_2=3
$$

问：

$$
p_3
$$

可能有多少种取值？

#### 14.2 分析
由于 3 已经在第二次出栈时弹出：

$$
p_3\ne3
$$

接下来考察其他元素。

##### p3 能否为 1？
可以。

操作：

    Push 1
    Push 2
    Pop 2
    Push 3
    Pop 3
    Pop 1

输出：

    2,3,1

##### p3 能否为 2？
可以。

操作：

    Push 1
    Pop 1
    Push 2
    Push 3
    Pop 3
    Pop 2

输出：

    1,3,2

##### p3 能否大于 3？
可以。

例如：

    Push 1
    Pop 1
    Push 2
    Push 3
    Pop 3
    Push 4
    Pop 4

输出前三个：

    1,3,4

同理，4 到 n 都可以。

于是：

$$
p_3\in\{1,2,4,5,\ldots,n\}
$$

共有：

$$
\boxed{n-1}
$$

种。

#### 14.3 推广：如果 p2=k 呢？
模拟题中给出：

$$
p_2=k,\qquad k>3
$$

则：

$$
p_3\in
\{k-2,k-1,k+1,\ldots,n\}
$$

所以数量：

$$
\boxed{n-k+2}
$$

为什么？

比 k 小的可取值只有：

$$
k-2,\quad k-1
$$

其余更小的元素会被尚未出栈的元素挡住。

而大于 k 的元素：

$$
k+1,\ldots,n
$$

都可以在弹出 k 后继续入栈，再作为第三个出栈元素。

故：

$$
2+(n-k)=n-k+2
$$

这类题不能简单套卡特兰数，而要分析栈中剩余元素的相对位置。


## 第四部分：队列
### 十五、队列的基本概念
#### 15.1 什么是队列？
队列（Queue）是一种：

- 队尾插入。
- 队头删除。

的受限线性表。

特点：

**先进先出，FIFO。**

例如：

    入队顺序：

    A → B → C

最终出队：

    A → B → C

基本操作：

| 操作 | 作用 |
|---|---|
| InitQueue | 初始化 |
| EnQueue | 入队 |
| DeQueue | 出队 |
| GetHead | 读取队头 |
| QueueEmpty | 判空 |

#### 15.2 栈与队列的区别
| 项目 | 栈 | 队列 |
|---|---|---|
| 插入位置 | 栈顶 | 队尾 |
| 删除位置 | 栈顶 | 队头 |
| 特性 | LIFO | FIFO |
| 常见应用 | DFS、递归、回溯 | BFS、层序遍历、任务调度 |
| 基本操作 | Push/Pop | EnQueue/DeQueue |

#### 15.3 真题：打印机缓冲区
2009 年真题考查：

计算机主机和打印机处理速度不同，需要设置缓冲区。

主机不断向缓冲区写入打印数据。

打印机依次取出数据。

应该选择：

$$
\boxed{\text{队列}}
$$

因为：

先进入缓冲区的数据通常应该先被处理。

这属于 FIFO。


### 十六、顺序队列与假溢出
#### 16.1 普通顺序队列
用数组实现：

    A[0..5]

假设初始入队：

    10,20,30,40

占用：

    [10][20][30][40][ ][ ]

然后出队两次：

    [ ][ ][30][40][ ][ ]

此时数组前两个位置已经空闲。

但如果 rear 只允许向右移动：

当 rear 最终移动到数组末尾时，就可能不能继续插入。

即使前面的数组位置仍然空闲。

这种现象称为：

**假溢出。**

#### 16.2 解决方案
让数组逻辑上首尾相连。

即：

循环队列。

下标移动：

$$
\boxed{
next(x)=(x+1)\bmod MaxSize
}
$$

例如：

    MaxSize = 6

    0 → 1 → 2 → 3 → 4 → 5
    ↑                   ↓
    └───────────────────┘

当指针到达 5：

下一位置：

$$
(5+1)\bmod6=0
$$


### 十七、循环队列
这是队列部分最重要的考点。

#### 17.1 首先规定指针语义
以下采用：

- front 指向当前队头元素。
- rear 指向队尾元素的下一个可插入位置。

假设：

    数组：

    0 1 2 3 4 5

    当前元素：

      A B C

那么：

    front = 1
    rear  = 4

队头是 A。

真正队尾是 C。

rear 指向下一空位置，不是 C。

#### 17.2 队空
初始化时：

$$
front=rear=0
$$

因此：

$$
\boxed{front=rear}
$$

表示队空。

#### 17.3 为什么队满不能直接用 front=rear？
假设数组长度为 5。

如果允许存满全部 5 个位置：

rear 绕一圈后可能重新等于 front。

于是：

    front == rear

既可能表示：

- 队空。
- 队满。

这产生了状态歧义。

解决方法有三种：

1. 牺牲一个数组单元。
2. 添加 size 记录元素数量。
3. 添加 tag 记录状态。

408 中最常考第一种。


### 十八、循环队列方案一：牺牲一个存储单元
#### 18.1 队满条件
规定：

队列中必须保留一个位置不使用。

数组长度为：

$$
MaxSize
$$

队列最多保存：

$$
\boxed{MaxSize-1}
$$

个元素。

判满：

$$
\boxed{
(rear+1)\bmod MaxSize=front
}
$$

解释：

如果 rear 再前进一步就追上 front：

说明不能继续插入。

#### 18.2 队列长度公式
$$
\boxed{
L=(rear-front+MaxSize)\bmod MaxSize
}
$$

为什么？

分两种情况。

##### 情况一：rear 没有绕回
例如：

    front = 2
    rear  = 5

元素下标：

    2,3,4

长度：

$$
L=5-2=3
$$

##### 情况二：rear 已经绕回
例如：

    MaxSize = 8
    front = 6
    rear = 2

元素下标：

    6,7,0,1

长度：

$$
L=(8-6)+2=4
$$

统一写成：

$$
L=(2-6+8)\bmod8=4
$$

#### 18.3 真正队尾元素位置
rear 指向下一可插入位置。

真正队尾在 rear 前一格。

因此：

$$
\boxed{
tail=(rear-1+MaxSize)\bmod MaxSize
}
$$

例如：

    MaxSize = 8
    rear = 0

实际队尾：

$$
(0-1+8)\bmod8=7
$$

注意：

不能直接写 rear-1。

否则在 rear=0 时会得到 -1。

#### 18.4 入队操作
```c
bool EnQueue(SqQueue *Q, int x) {
    if ((Q->rear + 1) % MAXSIZE == Q->front)
        return false;

    Q->data[Q->rear] = x;

    Q->rear = (Q->rear + 1) % MAXSIZE;

    return true;
}
```

先写入 rear 所指位置。

再移动 rear。

#### 18.5 出队操作
```c
bool DeQueue(SqQueue *Q, int *x) {
    if (Q->front == Q->rear)
        return false;

    *x = Q->data[Q->front];

    Q->front = (Q->front + 1) % MAXSIZE;

    return true;
}
```

先读取队头。

再移动 front。

#### 18.6 完整结构
```c
#define MAXSIZE 100

typedef struct {
    int data[MAXSIZE];
    int front;
    int rear;
} SqQueue;
```

基本条件汇总：

| 条件 | 公式 |
|---|---|
| 队空 | `front == rear` |
| 队满 | `(rear+1)%MAXSIZE == front` |
| 队长 | `(rear-front+MAXSIZE)%MAXSIZE` |
| 最大元素数 | `MAXSIZE-1` |
| 实际队尾 | `(rear-1+MAXSIZE)%MAXSIZE` |


### 十九、循环队列方案二：使用 size
如果要利用全部数组单元：

添加：

```c
int size;
```

初始化：

    front = 0
    rear  = 0
    size  = 0

队空：

$$
size=0
$$

队满：

$$
size=MaxSize
$$

入队：

```c
data[rear] = x;
rear = (rear + 1) % MAXSIZE;
size++;
```

出队：

```c
x = data[front];
front = (front + 1) % MAXSIZE;
size--;
```

这时：

队列能够保存全部：

$$
MaxSize
$$

个元素。

注意：

如果队满时也允许：

$$
front=rear
$$

那么仅凭两指针的模差无法区分长度 0 和长度 MaxSize。

必须使用 size。


### 二十、循环队列方案三：使用 tag
定义：

    tag = 0：最近一次状态改变是出队
    tag = 1：最近一次状态改变是入队

当：

$$
front=rear
$$

时：

如果：

$$
tag=0
$$

表示队空。

如果：

$$
tag=1
$$

表示队满。

这里的标志编码只是某一种约定。

题目也可能使用反向编码。

所以考试时要以题目定义为准。

#### 20.1 三种方案综合比较
| 方案 | 判空 | 判满 | 最大元素数 |
|---|---|---|---|
| 牺牲一格 | front=rear | rear 下一位置为 front | $M-1$ |
| size | size=0 | size=M | $M$ |
| tag | front=rear 且空标志 | front=rear 且满标志 | $M$ |


### 二十一、真题：2011 年循环队列的特殊指针定义
#### 21.1 题目
数组：

$$
A[0],A[1],\ldots,A[n-1]
$$

规定非空时：

- front 指向队头元素。
- rear 指向当前队尾元素。

要求：

第一个入队的元素存储在 A[0]。

问初始化时 front 和 rear 分别为多少？

#### 21.2 分析
这里的 rear 不再表示下一空位。

而是表示：

**当前队尾元素。**

入队需要：

先让 rear 前移，再写入。

即：

```c
rear = (rear + 1) % n;
A[rear] = x;
```

要让第一次入队时：

$$
rear=0
$$

初始化必须满足：

$$
(rear+1)\bmod n=0
$$

所以：

$$
rear=n-1
$$

而第一个元素成为队头：

$$
front=0
$$

答案：

$$
\boxed{front=0,\quad rear=n-1}
$$

#### 21.3 核心提醒
循环队列题最危险的错误：

把不同题目中的 rear 当成同一种指针。

有的题目：

    rear = 下一空位置

有的题目：

    rear = 当前队尾元素

两者入队语句、初始状态和长度公式可能完全不同。


### 二十二、双端队列
#### 22.1 基本定义
双端队列允许在两端插入和删除。

四种操作：

- 左端插入。
- 右端插入。
- 左端删除。
- 右端删除。

常见受限形式：

##### 输入受限双端队列
只允许从某一固定端入队。

但允许从两端出队。

##### 输出受限双端队列
允许从两端入队。

但只允许从某一固定端出队。

#### 22.2 和普通队列的区别
普通队列：

    队尾进入
    队头出去

输出受限双端队列：

    两端都可进入
    只有一端可出去

因此它可以产生的输出顺序比普通队列多。


### 二十三、真题：2010 年输出受限双端队列
#### 23.1 题目
元素：

    a,b,c,d,e

依次入队。

允许从两端入队。

但只能从一端出队。

全部入队完成后再依次出队。

问下面哪个输出不可能？

A：

    b,a,c,d,e

B：

    d,b,a,c,e

C：

    d,b,c,a,e

D：

    e,c,b,a,d

答案：

$$
\boxed{C}
$$

#### 23.2 最好的方法：逆向还原
因为元素按照：

    a,b,c,d,e

依次从两端插入。

如果逆向考虑：

最后插入的 e，必然位于最终双端序列的一端。

移除 e 后：

d 必须位于剩余序列的一端。

继续移除：

    e,d,c,b

如果某一步目标元素不在两端：

说明原来的插入过程不可能完成。

#### 23.3 分析 C
最终排列：

    d,b,c,a,e

逆向：

先删除 e：

    d,b,c,a

再删除 d：

    b,c,a

接下来必须删除 c。

但 c 位于中间。

不能通过删除某一端得到。

因此 C 不合法。

#### 23.4 推广
凡是题目出现：

- 两端插入。
- 单端删除。
- 所有元素先插入再删除。

都可以考虑：

**逆向删除法。**

它比正向枚举所有插入操作更直接。

注意：如果允许插入和删除交替执行，就不能不加分析地使用“全部插入完成后逆向删除”的简化模型。


### 二十四、链式队列
#### 24.1 基本结构
通常使用：

- front 指向头结点。
- rear 指向最后一个数据结点。

例如：

    front
      ↓
    [head] → [10] → [20] → [30]
                              ↑
                             rear

头结点不保存有效数据。

有效队头为：

```c
front->next
```

#### 24.2 空队列
空队列：

    front → [head] ← rear

因此：

$$
\boxed{front=rear}
$$

#### 24.3 入队
新结点 p：

```c
p->data = x;
p->next = NULL;

Q->rear->next = p;
Q->rear = p;
```

时间：

$$
O(1)
$$

#### 24.4 出队
```c
Node *p = Q->front->next;

*x = p->data;

Q->front->next = p->next;
```

如果 p 就是最后一个数据结点：

必须执行：

```c
Q->rear = Q->front;
```

然后：

```c
free(p);
```

完整代码：

```c
bool DeQueue(LinkQueue *Q, int *x) {
    if (Q->front == Q->rear)
        return false;

    Node *p = Q->front->next;

    *x = p->data;

    Q->front->next = p->next;

    if (Q->rear == p)
        Q->rear = Q->front;

    free(p);

    return true;
}
```

#### 24.5 为什么必须更新 rear？
原来：

    head → A
            ↑
           rear

删除 A 后：

    head → NULL

如果 rear 仍指向 A：

但 A 已经 free。

rear 就成为：

**悬空指针。**

后续入队可能访问无效内存。

这是一类很容易出现在算法设计题中的边界错误。


### 二十五、模拟题：只有 rear 的循环单链队列
假设使用不带头结点的循环单链表。

只维护一个 rear 指针。

例如：

    A → B → C
    ↑       ↓
    └───────┘

rear 指向 C。

那么：

```c
rear->next
```

指向 A。

也就是队头。

因此：

入队：

- 把新结点插入 rear 后面。
- 更新 rear。

出队：

- 删除 rear->next。
- 保持 rear 指向原队尾。

两者都不需要遍历链表。

所以：

$$
\boxed{T_{\text{入队}}=O(1)}
$$

$$
\boxed{T_{\text{出队}}=O(1)}
$$

注意：

只有一个结点时，删除该结点后必须将：

```c
rear = NULL;
```

否则仍会留下无效指针。

这说明：

**循环单链表只保留尾指针，也能高效实现队列。**


## 第五部分：2019 年第 42 题——循环链式队列设计
### 二十六、2019 年综合大题
这是本章非常重要的算法设计题。

#### 26.1 题目要求
设计一个队列，满足：

1. 初始为空。
2. 入队时允许增加存储空间。
3. 出队后不释放原来申请的结点，空间可重复使用。
4. 整个队列占用空间只增不减。
5. 入队、出队始终保持 $O(1)$。

要求：

- 选择存储结构。
- 设计初始状态。
- 给出判空和当前空间已满的条件。
- 设计入队、出队操作。
- 分析复杂度。

#### 26.2 第一步：选择存储结构
优先选择：

$$
\boxed{\text{循环单链表}}
$$

原因：

普通固定数组不支持无限动态增长。

动态数组虽然可以扩容，但扩容通常需要申请更大的连续空间并复制元素。

因此不能保证每次入队都是最坏情况 $O(1)$。

链表可以一次增加一个结点。

在标准算法分析中，将一次结点申请视为 $O(1)$。

所以可以保证每次入队只执行常数次链接操作。

#### 26.3 第二步：明确指针定义
这里采用一种符合题目要求的设计：

- front 指向当前队头数据位置。
- rear 指向下一个准备写入的空闲结点。
- 已申请结点组成一个循环单链表。
- 环内始终保留至少一个空闲结点。
- 出队只移动指针，不释放结点。

特别注意：

<Callout type="idea" title="核心结论">

**此处 rear 不是当前队尾元素，而是下一空位置。**

</Callout>

#### 26.4 初始化
申请一个结点 N0。

让它指向自身：

    N0.next = N0

同时：

    front = N0
    rear  = N0

示意：

    ┌───────────┐
    ↓           │
    [N0] ───────┘
     ↑
    front
    rear

队列为空。

判空：

$$
\boxed{front=rear}
$$

#### 26.5 当前申请空间已满
规定：

rear 指向空闲结点。

如果：

$$
\boxed{rear\to next=front}
$$

说明当前只剩 rear 自身这一格空闲位置。

再入队前必须增加一个结点。

因此这是：

**当前已申请空间不足，需要扩容的条件。**

不是整个队列永久无法入队。

#### 26.6 第一个元素入队
初始：

    N0 → N0

准备入队 10。

先申请 N1。

形成：

    N0 → N1 → N0

把 10 写到 N0。

然后 rear 前移：

    front = N0
    rear  = N1

此时：

    [N0:10] → [N1:空]
       ↑          ↑
      front      rear

#### 26.7 第二个元素入队
要入队 20。

此时：

    rear = N1
    rear.next = N0
    front = N0

满足：

    rear.next == front

所以需要扩容。

新增 N2：

    N0 → N1 → N2 → N0

然后：

    N1.data = 20
    rear = N2

有效队列：

    10,20

#### 26.8 出队操作
如果出队 10：

读取：

    front.data

然后：

    front = front.next

得到：

    front = N1
    rear  = N2

逻辑队列：

    20

原 N0 仍保留在环中。

它以后可以再次使用。

这恰好满足题目要求：

**空间只增不减。**

#### 26.9 继续入队 30
此时：

    front = N1
    rear  = N2

且：

    rear.next = N0

因为：

    N0 != N1

说明还有可用空间。

因此不需要新申请结点。

直接：

    N2.data = 30
    rear = N0

有效队列：

    20,30

这就是“重复使用出队元素原来占用的空间”。

#### 26.10 完整状态追踪
执行：

    EnQueue(10)
    EnQueue(20)
    DeQueue()
    EnQueue(30)
    DeQueue()
    DeQueue()
    EnQueue(40)

| 操作 | front | rear | 有效队列 | 累计结点 |
|---|---|---|---|---|
| 初始化 | N0 | N0 | 空 | 1 |
| 入队10 | N0 | N1 | 10 | 2 |
| 入队20 | N0 | N2 | 10,20 | 3 |
| 出队10 | N1 | N2 | 20 | 3 |
| 入队30 | N1 | N0 | 20,30 | 3 |
| 出队20 | N2 | N0 | 30 | 3 |
| 出队30 | N0 | N0 | 空 | 3 |
| 入队40 | N0 | N1 | 40 | 3 |

结论：

三次出队返回：

    10,20,30

总共申请：

    3 个结点

最后一次入队无需扩容。

#### 26.11 C 语言实现
```c
#include <stdlib.h>
#include <stdbool.h>

typedef struct Node {
    int data;
    struct Node *next;
} Node;

typedef struct {
    Node *front;
    Node *rear;
} CircleQueue;

bool InitQueue(CircleQueue *Q) {
    Node *p = malloc(sizeof(Node));

    if (p == NULL)
        return false;

    p->next = p;

    Q->front = p;
    Q->rear = p;

    return true;
}

bool QueueEmpty(CircleQueue *Q) {
    return Q->front == Q->rear;
}

bool EnQueue(CircleQueue *Q, int x) {
    if (Q->rear->next == Q->front) {
        Node *p = malloc(sizeof(Node));

        if (p == NULL)
            return false;

        p->next = Q->rear->next;
        Q->rear->next = p;
    }

    Q->rear->data = x;
    Q->rear = Q->rear->next;

    return true;
}

bool DeQueue(CircleQueue *Q, int *x) {
    if (QueueEmpty(Q))
        return false;

    *x = Q->front->data;

    Q->front = Q->front->next;

    return true;
}
```

注：完整程序结束后仍应提供销毁整个环并释放全部结点的函数；题目限制的是正常入队、出队期间不释放结点。

#### 26.12 时间复杂度证明
入队时：

最多执行一次结点申请和常数次指针操作。

因此：

$$
O(1)
$$

出队时：

读取一个元素并移动一次 front。

因此：

$$
O(1)
$$

整个过程中没有遍历链表。

若历史最大队列长度为 H：

始终保留一格空闲位置。

因此最多申请：

$$
H+1
$$

个结点。

#### 26.13 另一种正确设计
同一题也可以采用另一种约定：

- front 指向队头的前驱结点。
- rear 指向当前队尾数据结点。

此时：

队空仍然可以定义为：

$$
front=rear
$$

现有空间不足仍可以定义为：

$$
rear\to next=front
$$

但入队、出队代码会改变。

入队：

    如果无空闲结点：
        在 rear 后面增加结点

    rear = rear.next
    rear.data = x

出队：

    如果 front == rear：
        队空

    front = front.next
    x = front.data

注意：

两种方案可以得到同样的逻辑队列。

但不能把方案一的 front/rear 定义和方案二的代码混用。

#### 26.14 这道题最值得掌握的方法
算法设计题经常提出多个约束：

    支持动态扩容
    不释放历史空间
    能复用已有空间
    每次操作 O(1)

正确思路不是直接套普通链队代码。

而是：

1. 将要求转换成结构约束。
2. 选择合适的存储结构。
3. 定义清楚每个指针。
4. 写出结构的不变量。
5. 设计操作以保持不变量。
6. 分析时间与空间复杂度。
7. 检查空队列、单元素和需扩容等边界。

这种方法对其他 408 算法设计题同样适用。


## 第六部分：栈与队列的应用
### 二十七、括号匹配
#### 27.1 为什么用栈？
例如：

```text
{ [ ( ) ] }
```

最先出现的左括号：

```text
{
```

最后匹配。

最后出现的左括号：

    (

最先匹配。

因此符合：

**后进先出。**

#### 27.2 算法
从左到右扫描。

遇到左括号：

入栈。

遇到右括号：

检查栈顶。

若匹配：

出栈。

否则：

不合法。

扫描结束：

只有栈为空才合法。

#### 27.3 伪代码
```text
for ch in expression:
    if ch 是左括号:
        push(ch)

    else if ch 是右括号:
        if stack 为空:
            return false

        if top 与 ch 不匹配:
            return false

        pop()

return stack 为空
```

时间复杂度：

$$
O(n)
$$

空间复杂度：

$$
O(n)
$$

最坏情况下全部字符都是左括号。

#### 27.4 易错点
例如：

    ((()

虽然扫描过程中没有发生“右括号与左括号不匹配”。

但结束时栈不为空。

所以仍然不合法。

必须同时检查：

1. 扫描过程未失配。
2. 最终栈为空。


### 二十八、表达式的三种表示
#### 28.1 中缀表达式
运算符位于操作数中间。

例如：

    (A+B)*C

这是人类最熟悉的表达式。

#### 28.2 前缀表达式
运算符位于操作数前面。

例如：

    *+ABC

表示：

    (A+B)*C

#### 28.3 后缀表达式
运算符位于操作数后面。

例如：

    AB+C*

同样表示：

    (A+B)*C

三者对比：

| 类型 | 表达式 |
|---|---|
| 中缀 | `(A+B)*C` |
| 前缀 | `*+ABC` |
| 后缀 | `AB+C*` |

#### 28.4 为什么后缀表达式不需要括号？
中缀表达式：

    A+B*C

必须依靠运算符优先级判断：

    A+(B*C)

后缀表达式：

    ABC*+

已经明确：

先计算：

    B*C

再计算：

    A + 结果

运算顺序由运算符和操作数的位置直接表达。

因此，在运算符元数明确且记号无歧义时，不需要括号。


### 二十九、中缀表达式转后缀表达式
#### 29.1 核心工具
只需要：

- 一个运算符栈。
- 一个输出序列。

注意：

操作数直接输出。

**不是把所有记号都放入运算符栈。**

#### 29.2 规则一：遇到操作数
直接输出。

例如：

    A+B

读到 A：

    输出：A
    运算符栈：空

#### 29.3 规则二：遇到左括号
直接入栈。

例如：

    A+(B

此时：

    栈底：+ (
    输出：AB

#### 29.4 规则三：遇到右括号
不断弹出运算符并输出。

直到遇到左括号。

然后删除左括号。

注意：

**左右括号都不会进入最终后缀表达式。**

#### 29.5 规则四：遇到普通运算符
考虑：

1. 运算符优先级。
2. 运算符结合性。

对普通二元：

    + - * /

它们都是左结合运算符。

当栈顶运算符优先级：

- 高于当前运算符。
- 或等于当前运算符。

必须先弹出栈顶运算符。

再考虑当前运算符入栈。

#### 29.6 为什么相同优先级也需要弹栈？
例如：

    A-B-C

按照左结合：

    (A-B)-C

后缀：

    AB-C-

不能把它解释成：

    A-(B-C)

所以遇到第二个减号时：

必须先输出前一个减号。

#### 29.7 右结合运算符的例外
例如：

    A^B^C

若 ^ 表示通常右结合的幂运算：

应解释为：

    A^(B^C)

后缀：

    ABC^^

对于右结合运算符：

遇到同优先级运算符时通常不能直接弹出旧运算符。

因此：

**优先级相同是否弹栈，要看当前运算符的结合性。**


### 三十、真题：2014 年中缀转后缀过程中的栈状态
#### 30.1 题目
表达式：

    a/b+(c*d-e*f)/g

转为后缀表达式。

问：

扫描到 f 时，运算符栈中的内容是什么？

#### 30.2 过程
| 当前记号 | 运算符栈（底→顶） | 已输出 |
|---|---|---|
| a | 空 | a |
| / | / | a |
| b | / | ab |
| + | + | ab/ |
| ( | + ( | ab/ |
| c | + ( | ab/c |
| * | + ( * | ab/c |
| d | + ( * | ab/cd |
| - | + ( - | ab/cd* |
| e | + ( - | ab/cd*e |
| * | + ( - * | ab/cd*e |
| f | + ( - * | ab/cd*ef |

所以：

从栈底到栈顶：

    + ( - *

即：

$$
\boxed{+\;(\;-\;*}
$$

完整后缀表达式：

    ab/cd*ef*-g/+

#### 30.3 高频陷阱
题目问：

**扫描到 f 时。**

不是问：

扫描完整个表达式以后。

所以不能提前处理：

    )

以及后面的：

    /g

做这类题一定要停在题目指定时刻。


### 三十一、真题：2012 年运算符栈最大深度
#### 31.1 题目
表达式：

    a+b-a*((c+d)/e-f)+g

进行中缀转后缀。

问：

运算符栈中同时保存的运算符最大个数是多少？

#### 31.2 关键过程
扫描时：

    a+

栈：

    [+]

扫描：

    a+b-

由于 + 与 - 同级，先弹出 +。

之后：

    [-]

扫描乘号：

    [-,*]

遇到第一层左括号：

    [-,*,(]

遇到第二层左括号：

    [-,*,(,(]

再遇到 c+d 中的加号：

    [-,*,(,(,+]

此时最大栈深为：

$$
\boxed{5}
$$

注意：

这里左括号也占用运算符栈空间。

#### 31.3 模拟题变式
表达式：

    a-(b*c+d/e)

运算符栈最大深度是多少？

过程：

| 记号 | 栈状态 | 栈深 |
|---|---|---|
| - | - | 1 |
| ( | - ( | 2 |
| * | - ( * | 3 |
| + | - ( + | 3 |
| / | - ( + / | 4 |

所以最大为：

$$
\boxed{4}
$$

#### 31.4 栈深题的通用方法
不要只统计表达式中有多少运算符。

因为某些旧运算符在新运算符入栈之前已经弹出。

正确方法：

逐个扫描记号。

记录：

    当前栈深
    历史最大栈深

最后返回最大值。


### 三十二、后缀表达式求值
#### 32.1 算法
从左到右扫描。

遇到操作数：

入栈。

遇到二元运算符：

连续弹出两个操作数。

设：

    b = 第一次 Pop
    a = 第二次 Pop

则计算：

    a op b

并把结果重新入栈。

#### 32.2 为什么弹栈顺序重要？
例如：

    8 3 -

操作数栈：

    [8,3]

第一次弹出：

    3

第二次弹出：

    8

应该计算：

$$
8-3=5
$$

不能计算：

$$
3-8=-5
$$

同样：

    8 2 /

应该得到：

$$
8/2=4
$$

不是：

$$
2/8
$$

#### 32.3 完整例题
后缀表达式：

    3 5 2 * 8 - +

过程：

| 当前记号 | 操作 | 栈 |
|---|---|---|
| 3 | 入栈 | 3 |
| 5 | 入栈 | 3,5 |
| 2 | 入栈 | 3,5,2 |
| * | 5×2=10 | 3,10 |
| 8 | 入栈 | 3,10,8 |
| - | 10-8=2 | 3,2 |
| + | 3+2=5 | 5 |

最终答案：

$$
\boxed{5}
$$

时间复杂度：

$$
O(n)
$$

辅助空间复杂度：

$$
O(n)
$$


### 三十三、真题：2018 年两栈表达式求值
#### 33.1 题目
操作数栈 S1：

    栈底 → 5,8,3,2 ← 栈顶

运算符栈 S2：

    栈底 → *,-,+ ← 栈顶

每次执行：

1. 从 S1 弹出 a。
2. 再弹出 b。
3. 从 S2 弹出运算符 op。
4. 计算 b op a。
5. 将结果压入 S1。

连续执行 3 次。

问 S1 栈顶是什么？

#### 33.2 第一次
弹出：

    a = 2
    b = 3
    op = +

计算：

$$
3+2=5
$$

S1：

    5,8,5

#### 33.3 第二次
弹出：

    a = 5
    b = 8
    op = -

计算：

$$
8-5=3
$$

S1：

    5,3

#### 33.4 第三次
弹出：

    a = 3
    b = 5
    op = *

计算：

$$
5\times3=15
$$

答案：

$$
\boxed{15}
$$

#### 33.5 题目本质
这道题并不难。

它考察的是：

**对一个给定算法严格执行，不要凭习惯改变操作数顺序。**

特别是减法、除法必须注意先后次序。


### 三十四、前缀表达式求值
前缀表达式通常从右向左扫描。

例如：

    - * 8 2 3

表示：

    (8*2)-3

扫描：

    3 → 入栈
    2 → 入栈
    8 → 入栈
    * → 8*2=16
    - → 16-3=13

结果：

$$
13
$$

与后缀求值的关键区别：

后缀从左向右扫描时：

第一次弹出的是右操作数。

前缀从右向左扫描时：

第一次弹出的是左操作数。


### 三十五、表达式树
#### 35.1 什么是表达式树？
例如：

    (A+B)*C

对应：

         *
        / \
       +   C
      / \
     A   B

叶结点：

    A,B,C

内部结点：

    +,*

#### 35.2 前序、中序、后序的关系
前序：

    * + A B C

即前缀表达式。

中序：

    A + B * C

如果不加括号，可能丢失原表达式的语义。

正确中缀应为：

    (A+B)*C

后序：

    A B + C *

即后缀表达式。

因此：

| 遍历 | 表达式 |
|---|---|
| 前序 | 前缀 |
| 中序 | 中缀，必要时补括号 |
| 后序 | 后缀 |

#### 35.3 模拟题：表达式树的叶结点数量
如果表达式树只有二元运算符：

每个运算符结点都有两个孩子。

设运算符结点数量为 n。

操作数叶结点数量为 m。

树中总边数：

$$
2n
$$

总结点数：

$$
n+m
$$

树的边数等于结点数减一：

$$
2n=n+m-1
$$

所以：

$$
\boxed{m=n+1}
$$

即：

**二元表达式树有 n 个运算符结点，就有 n+1 个操作数叶结点。**

注意：

若包含一元运算符，这个结论就不能直接套用。


### 三十六、两个栈实现队列
这也是非常值得掌握的扩展算法。

#### 36.1 基本思想
使用：

- 输入栈 S1。
- 输出栈 S2。

入队：

直接压入 S1。

出队：

如果 S2 非空：

直接从 S2 弹出。

如果 S2 为空：

将 S1 所有元素依次弹出并压入 S2。

然后从 S2 弹出。

#### 36.2 为什么正确？
例如入队：

    1,2,3

S1：

    栈底 [1,2,3] 栈顶

全部倒入 S2：

    栈底 [3,2,1] 栈顶

从 S2 出栈：

    1,2,3

满足 FIFO。

#### 36.3 复杂度
EnQueue：

$$
O(1)
$$

DeQueue 最坏情况下需要转移 n 个元素：

$$
O(n)
$$

但每个元素：

- 进入 S1 一次。
- 从 S1 移到 S2 一次。
- 从 S2 弹出一次。

因此每个元素只参与常数次栈操作。

所以摊还出队复杂度：

$$
\boxed{O(1)}
$$

注意：

**摊还 $O(1)$ 不等于每次最坏情况 $O(1)$。**

#### 36.4 一个队列实现栈
也可以。

在队列中插入新元素后：

将原先已有的元素依次出队并重新入队。

例如：

原队列：

    1,2

入队 3：

    1,2,3

将前两个元素依次移动到队尾：

    3,1,2

此时从队头出队：

首先得到 3。

因此：

可以使用一个普通队列实现 LIFO 栈。

这种实现方式：

- Push 为 $O(n)$。
- Pop 为 $O(1)$。

也可以采用其他操作安排，在 Push 和 Pop 的复杂度之间进行取舍。


## 第七部分：数组与矩阵
### 三十七、数组的基本概念
数组由一组类型相同的数据元素组成。

在通常的顺序存储实现中：

数组元素占用连续的存储空间。

特点：

- 可以通过下标直接访问。
- 元素大小固定时可以计算地址。
- 按下标随机访问通常为 $O(1)$。

一维数组：

    A[0],A[1],...,A[n-1]

假设：

- 首地址为 $A_0$。
- 每个元素占 B 字节。

则：

$$
\boxed{
Addr(A[i])=A_0+iB
}
$$

如果下标从 1 开始：

$$
Addr(A[i])=A_0+(i-1)B
$$

最重要的不是公式本身。

而是：

**目标元素之前有多少个元素？**


### 三十八、二维数组地址计算
#### 38.1 行优先存储
设：

$$
A[R][C]
$$

有：

- R 行。
- C 列。
- 下标从 0 开始。
- 每个元素占 B 字节。

行优先：

先存完整的第 0 行。

再存第 1 行。

例如：

    A[0][0] A[0][1] A[0][2]
    A[1][0] A[1][1] A[1][2]

实际线性顺序：

    A00,A01,A02,A10,A11,A12

对 A[i][j]：

前面已经经过 i 个完整行。

每行 C 个元素。

所以：

$$
iC
$$

个元素。

当前行前面还有 j 个元素。

因此偏移量：

$$
\boxed{iC+j}
$$

地址：

$$
\boxed{
Addr(A[i][j])=A_0+(iC+j)B
}
$$

#### 38.2 列优先存储
列优先：

先存第 0 列。

再存第 1 列。

元素 A[i][j] 前面：

有 j 个完整列。

每列 R 个元素。

共：

$$
jR
$$

个。

当前列前面有 i 个元素。

所以偏移量：

$$
\boxed{jR+i}
$$

地址：

$$
\boxed{
Addr(A[i][j])=A_0+(jR+i)B
}
$$

#### 38.3 行优先与列优先对比
| 存储方式 | 偏移量 |
|---|---|
| 行优先 | $iC+j$ |
| 列优先 | $jR+i$ |

其中：

- R 是总行数。
- C 是总列数。

不要将两者混淆。


### 三十九、真题：2021 年二维数组地址计算
#### 39.1 题目
二维数组按行优先存储。

每个元素占 1 个存储单元。

已知：

$$
Addr(A[0][0])=100
$$

$$
Addr(A[3][3])=220
$$

求：

$$
Addr(A[5][5])
$$

#### 39.2 第一步：设每行有 n 个元素
行优先：

$$
Addr(A[i][j])=100+in+j
$$

代入：

$$
220=100+3n+3
$$

所以：

$$
3n=117
$$

得到：

$$
n=39
$$

#### 39.3 第二步：求目标地址
$$
Addr(A[5][5])
=100+5\times39+5
$$

所以：

$$
\boxed{300}
$$

#### 39.4 这一类题的关键
题目没有直接告诉你每行有多少元素。

但给出两个元素地址。

因此可以：

1. 建立地址公式。
2. 利用地址差求出维长。
3. 再计算目标元素地址。

遇到未知数组维数，不要认为无法求解。


### 四十、三维数组与多维数组
#### 40.1 三维数组
设：

$$
A[X][Y][Z]
$$

按行优先存储。

下标从 0 开始。

则：

$$
\boxed{
offset=iYZ+jZ+k
}
$$

地址：

$$
Addr(A[i][j][k])
=A_0+(iYZ+jZ+k)B
$$

#### 40.2 为什么这样计算？
对于：

$$
A[i][j][k]
$$

前面完整经过：

i 个二维块。

每个块：

$$
YZ
$$

个元素。

贡献：

$$
iYZ
$$

然后经过 j 个一维行块。

每块：

$$
Z
$$

个元素。

贡献：

$$
jZ
$$

最后当前行前面还有 k 个元素。

所以：

$$
iYZ+jZ+k
$$

#### 40.3 一般 d 维数组
设：

$$
A[n_1][n_2]\cdots[n_d]
$$

元素：

$$
A[i_1][i_2]\cdots[i_d]
$$

行优先偏移：

$$
\boxed{
offset=
\sum_{r=1}^{d}
i_r\prod_{s=r+1}^{d}n_s
}
$$

最后一个空乘积取 1。

例如三维：

$$
offset=i_1n_2n_3+i_2n_3+i_3
$$

列优先则相反：

第一维变化最快。

三维列优先偏移为：

$$
\boxed{
offset=i+jX+kXY
}
$$

其中 X 是第一维长度，Y 是第二维长度。

#### 40.4 解题技巧
行优先：

最后一维变化最快。

列优先：

第一维变化最快。

看到多维数组时：

先判断哪一维变化最快。

再依次计算跨过的完整存储块。


## 第八部分：特殊矩阵压缩存储
### 四十一、为什么要压缩特殊矩阵？
一个 n 阶普通矩阵有：

$$
n^2
$$

个元素。

但有些矩阵：

- 大量元素重复。
- 大量元素为固定值。
- 只有少数位置可能非零。

如果仍保存全部元素：

浪费存储空间。

因此可以只保存：

**独立、有效、必须单独记录的元素。**

核心任务：

建立二维下标到一维压缩下标的映射：

$$
(i,j)\longrightarrow k
$$

全章矩阵压缩题统一遵循：

**先确定存储区域，再数目标元素之前有多少个有效元素。**


### 四十二、对称矩阵
#### 42.1 定义
对于 n 阶矩阵：

$$
a_{ij}=a_{ji}
$$

称为对称矩阵。

例如：

    1 2 3
    2 4 5
    3 5 6

上三角和下三角相互重复。

因此：

只保存其中一个三角区域即可。

#### 42.2 需要保存多少个元素？
按下三角计数：

第一行：

    1 个

第二行：

    2 个

第三行：

    3 个

……

第 n 行：

    n 个

总数：

$$
1+2+\cdots+n
$$

所以：

$$
\boxed{
\frac{n(n+1)}{2}
}
$$

#### 42.3 下三角按行优先
设：

- 原矩阵下标从 1 开始。
- 压缩数组下标从 0 开始。
- 只保存下三角。
- 按行优先。

对：

$$
i\ge j
$$

第 i 行之前保存：

$$
1+2+\cdots+(i-1)
$$

即：

$$
\frac{i(i-1)}{2}
$$

当前行前面有：

$$
j-1
$$

个元素。

所以：

$$
\boxed{
k=\frac{i(i-1)}{2}+j-1
}
$$

#### 42.4 如果 i&lt;j 怎么办？
因为对称：

$$
a_{ij}=a_{ji}
$$

所以先交换 i、j。

例如：

$$
a_{2,7}=a_{7,2}
$$

再计算下三角位置。

统一公式：

$$
\boxed{
k=
\begin{cases}
\dfrac{i(i-1)}2+j-1,&i\ge j\\[6pt]
\dfrac{j(j-1)}2+i-1,&i<j
\end{cases}
}
$$

#### 42.5 上三角按行优先
如果保存上三角：

第 1 行：

    n 个

第 2 行：

    n-1 个

第 3 行：

    n-2 个

……

第 i 行：

    n-i+1 个

目标元素：

$$
a_{ij},\qquad i\le j
$$

前 i-1 行元素数：

$$
n+(n-1)+\cdots+(n-i+2)
$$

化简：

$$
\frac{(i-1)(2n-i+2)}2
$$

当前行前面：

$$
j-i
$$

个元素。

所以：

$$
\boxed{
k=
\frac{(i-1)(2n-i+2)}2+j-i
}
$$

#### 44.3 第二步：按列统计

### 四十五、对称矩阵四种压缩公式总表
以下统一约定：

- 原矩阵下标从 1 开始。
- 压缩数组下标从 0 开始。
- 目标已经转换到实际存储区域。

| 存储方式 | 条件 | 压缩下标 |
|---|---|---|
| 下三角按行 | $i\ge j$ | $\frac{i(i-1)}2+j-1$ |
| 上三角按行 | $i\le j$ | $\frac{(i-1)(2n-i+2)}2+j-i$ |
| 上三角按列 | $i\le j$ | $\frac{j(j-1)}2+i-1$ |
| 下三角按列 | $i\ge j$ | $\frac{(j-1)(2n-j+2)}2+i-j$ |

不要一次性死记四个公式。

理解：

- 下三角按行：1、2、3、……。
- 上三角按行：n、n-1、n-2、……。
- 上三角按列：1、2、3、……。
- 下三角按列：n、n-1、n-2、……。

即可现场推导。


### 四十六、模拟题：反向求压缩矩阵坐标
#### 46.1 题目
10×10 对称矩阵。

上三角按行压缩。

已知：

    B[0] = A[1][1]
    B[1] = A[1][2]

问：

    B[35]

对应哪个矩阵元素？

#### 46.2 分析
上三角每行长度：

    第1行：10
    第2行：9
    第3行：8
    第4行：7
    第5行：6

因此压缩数组分段：

| 行 | 下标范围 |
|---|---|
| 第1行 | 0～9 |
| 第2行 | 10～18 |
| 第3行 | 19～26 |
| 第4行 | 27～33 |
| 第5行 | 34～39 |

所以：

    B[35]

位于第 5 行。

第 5 行：

    B[34] = A[5][5]
    B[35] = A[5][6]

因此：

$$
\boxed{A[5][6]}
$$

由于对称：

$$
A[5][6]=A[6][5]
$$

如果矩阵存储顶点之间的无向距离：

就是顶点 5 与 6 之间的距离。

#### 46.3 反向定位的通用方法
给定 k 求 i、j：

1. 先计算每行开始的下标。
2. 找到 k 落在哪一行。
3. 用 k 减去该行起始下标。
4. 得到该行内部的相对位置。
5. 还原原矩阵的列下标。


### 四十七、三角矩阵
#### 47.1 三角矩阵与对称矩阵的区别
对称矩阵：

另一侧是重复信息。

三角矩阵：

另一侧是固定常量，通常为 0。

例如上三角矩阵：

    1 2 3 4
    0 5 6 7
    0 0 8 9
    0 0 0 10

非零区域在主对角线及其上方。

#### 47.2 存储规模
有效三角区：

$$
\frac{n(n+1)}2
$$

如果另一侧统一为固定常量 c：

可以额外保存一个单元记录 c。

因此可能需要：

$$
\boxed{
\frac{n(n+1)}2+1
}
$$

个单元。

但如果题目规定固定常量无需额外保存：

则仍然是：

$$
\frac{n(n+1)}2
$$

#### 47.3 和对称矩阵最大的区别
对于对称矩阵：

访问另一侧元素时可以交换下标。

对于三角矩阵：

另一侧元素是统一常量。

不能通过交换下标获取另一侧元素值。

例如上三角矩阵：

$$
a_{4,1}=0
$$

不能错误地写成：

$$
a_{4,1}=a_{1,4}
$$

这属于把三角矩阵误当成对称矩阵。


### 四十八、三对角矩阵
#### 48.1 定义
三对角矩阵只允许：

- 主对角线。
- 主对角线上方一条对角线。
- 主对角线下方一条对角线。

上的元素可能非零。

例如：

    a11 a12  0   0   0
    a21 a22 a23  0   0
     0  a32 a33 a34  0
     0   0  a43 a44 a45
     0   0   0  a54 a55

有效位置满足：

$$
\boxed{|i-j|\le1}
$$

#### 48.2 非零区域元素总数
主对角线：

$$
n
$$

上方一条：

$$
n-1
$$

下方一条：

$$
n-1
$$

总数：

$$
n+(n-1)+(n-1)
$$

所以：

$$
\boxed{3n-2}
$$

#### 48.3 三对角矩阵压缩下标
规定：

- 原矩阵 1 基。
- 压缩数组 0 基。
- 按行优先。

对有效元素：

$$
|i-j|\le1
$$

有：

$$
\boxed{
k=2i+j-3
}
$$

#### 48.4 为什么是这个公式？
例如：

第 1 行：

    a11 a12

下标：

    0,1

第 2 行：

    a21 a22 a23

下标：

    2,3,4

第 3 行：

    a32 a33 a34

下标：

    5,6,7

第 i 行的第一个有效元素：

$$
a_{i,i-1}
$$

在非首行时，它之前有：

$$
2+3(i-2)
$$

个有效元素。

即：

$$
3i-4
$$

当前行的列偏移：

$$
j-(i-1)=j-i+1
$$

所以：

$$
k=(3i-4)+(j-i+1)
$$

化简：

$$
\boxed{k=2i+j-3}
$$

对第一行的合法位置，该公式也成立。


### 四十九、真题：2016 年三对角矩阵
#### 49.1 题目
100 阶三对角矩阵。

有效元素按行优先压缩。

原矩阵下标：

    1～100

压缩数组下标：

    0 开始

求：

$$
a_{30,30}
$$

对应的压缩下标。

#### 49.2 方法一：公式
$$
k=2i+j-3
$$

代入：

$$
k=2\times30+30-3
$$

得到：

$$
\boxed{87}
$$

#### 49.3 方法二：直接计数
第 1 行：

    2 个

第 2～29 行：

每行 3 个。

总共 28 行。

因此第 30 行之前：

$$
2+28\times3=86
$$

第 30 行：

    a30,29
    a30,30
    a30,31

a30,30 是第二个。

其相对偏移：

    1

所以：

$$
86+1=87
$$

答案：

$$
\boxed{87}
$$

#### 49.4 反向公式
如果已知压缩下标 k：

可以先求行号：

$$
\boxed{
i=\left\lfloor\frac{k+1}{3}\right\rfloor+1
}
$$

再由：

$$
k=2i+j-3
$$

得到：

$$
\boxed{
j=k-2i+3
}
$$

前提仍然是：

矩阵 1 基、数组 0 基、按行优先存储。


## 第九部分：稀疏矩阵
### 五十、稀疏矩阵的基本概念
#### 50.1 什么叫稀疏矩阵？
当一个矩阵中绝大多数元素为 0：

只有很少一部分元素非零。

就称为稀疏矩阵。

例如：

    0 0 0 5
    0 0 0 0
    3 0 0 0
    0 0 7 0

普通二维数组需要：

    16 个元素位置

但非零元素只有：

    3 个

因此可以考虑压缩。

#### 50.2 典型存储结构
两种重要结构：

1. 三元组表。
2. 十字链表。


### 五十一、三元组表
#### 51.1 基本思想
每个非零元素记录：

    行号
    列号
    元素值

例如：

    0 0 0 5
    0 0 0 0
    3 0 0 0
    0 0 7 0

三元组：

    (0,3,5)
    (2,0,3)
    (3,2,7)

还需保存矩阵：

- 总行数。
- 总列数。
- 非零元素数量。

#### 51.2 为什么必须保存行数和列数？
例如三元组：

    (0,0,5)
    (1,2,7)

它可能来自：

    2×3 矩阵

也可能来自：

    100×100 矩阵

仅根据非零元素坐标无法确定原矩阵整体规模。

所以必须额外记录：

$$
rows,\ cols
$$

#### 51.3 真题：2023 年三元组表
题目问：

除了三元组，还需要保存：

I. 矩阵总行数

II. 含非零元素的行数

III. 矩阵总列数

IV. 含非零元素的列数

答案：

$$
\boxed{\text{I、III}}
$$

原因：

必须明确原矩阵规模。

而含非零元素的行数、列数不属于恢复矩阵规模所必需的额外元数据。

#### 51.4 三元组表的结构
```c
typedef struct {
    int row;
    int col;
    int value;
} Triple;

typedef struct {
    int rows;
    int cols;
    int nums;
    Triple data[MAXSIZE];
} TSMatrix;
```

其中：

    nums

记录非零元素数量。

#### 51.5 时间复杂度特点
三元组表通常节省空间。

但是：

查找某个具体位置：

    A[i][j]

不一定能直接 $O(1)$ 定位。

如果三元组无辅助索引：

可能需要顺序搜索：

$$
O(t)
$$

其中 t 为非零元素数量。

即使三元组按行、列有序，也需要根据存储组织方式选择适当的查找方法。

所以：

**压缩空间不代表随机访问一定更快。**


### 五十二、模拟题：三元组表空间计算
#### 52.1 题目
一个：

$$
1000\times850
$$

的稀疏矩阵。

有：

    1000 个非零元素

每个行号、列号占：

    2 B

每个元素值占：

    4 B

求存储所有三元组需要多少字节。

不计表头和额外管理信息。

#### 52.2 分析
一个三元组包括：

    行号：2B
    列号：2B
    元素值：4B

总共：

$$
2+2+4=8B
$$

1000 个非零元素：

$$
1000\times8=8000B
$$

答案：

$$
\boxed{8000B}
$$

#### 52.3 易错点
不能只算元素值：

$$
1000\times4
$$

因为还要保存行号和列号。

也不能按照整个矩阵：

$$
1000\times850
$$

个元素计算。

因为使用的是压缩存储。

如果题目要求整个数据结构实际占用空间：

还需要考虑：

- 总行数。
- 总列数。
- 非零元素数。
- 结构体填充。
- 动态数组容量等额外空间。

但本题明确不计这些额外开销。


### 五十三、十字链表
#### 53.1 为什么需要十字链表？
三元组表适合保存比较稳定的稀疏矩阵。

但如果需要频繁：

- 按行访问非零元素。
- 按列访问非零元素。
- 插入非零元素。
- 删除非零元素。

三元组顺序表可能需要移动很多记录。

因此可以使用十字链表。

#### 53.2 结点结构
每个非零元素结点包含：

    row
    col
    value
    right
    down

其中：

    right

指向同行的下一个非零元素。

    down

指向同列的下一个非零元素。

结构：

```c
typedef struct CrossNode {
    int row;
    int col;
    int value;

    struct CrossNode *right;
    struct CrossNode *down;
} CrossNode;
```

#### 53.3 核心性质
每个非零元素同时属于：

- 一条行链表。
- 一条列链表。

例如非零元素：

    A[2][3]

在行链表中：

通过 right 链接。

在列链表中：

通过 down 链接。

#### 53.4 三元组表与十字链表对比
| 项目 | 三元组表 | 十字链表 |
|---|---|---|
| 存储方式 | 顺序 | 链式 |
| 保存对象 | 非零元素 | 非零元素 |
| 行遍历 | 较方便 | 方便 |
| 列遍历 | 可能需要额外处理 | 方便 |
| 插入删除 | 可能移动大量记录 | 主要修改指针 |
| 附加开销 | 行列坐标 | 行列坐标和链接指针 |
| 适合 | 较稳定矩阵 | 动态稀疏矩阵 |

#### 53.5 真题：2017 年稀疏矩阵存储结构
问：

适用于压缩存储稀疏矩阵的两种典型结构是什么？

答案：

$$
\boxed{\text{三元组表和十字链表}}
$$


## 第十部分：2026 年第 42 题——出栈序列综合大题
### 五十四、题目
输入序列：

$$
1,2,3,\ldots,n
$$

按顺序进入同一个栈。

允许入栈与出栈交替进行。

主要考查四类问题：

1. 给定两个序列，判断能否得到。
2. 总结非法输出的三元素大小关系。
3. 统计固定首元素的出栈序列。
4. 利用卡特兰数求总数及递推关系。


### 五十五、第一问：判断两个输出序列是否合法
当：

$$
n=9
$$

序列一：

    2,3,1,6,4,7,5,9,8

序列二：

    2,3,1,5,6,7,4,9,8

#### 55.1 序列一
目标：

    2,3,1,6,4,7,5,9,8

先执行：

    Push 1
    Push 2
    Pop 2

剩余：

    [1]

然后：

    Push 3
    Pop 3
    Pop 1

栈空。

接下来目标是：

    6

因此必须：

    Push 4
    Push 5
    Push 6
    Pop 6

剩余：

    [4,5]

下一目标：

    4

但当前栈顶为：

    5

不能越过 5 取出 4。

因此：

$$
\boxed{\text{序列一不合法}}
$$

也可以指出三元素：

    6,4,5

满足：

$$
4<5<6
$$

形成 312 禁形。

#### 55.2 序列二
目标：

    2,3,1,5,6,7,4,9,8

操作：

    Push 1
    Push 2
    Pop 2

    Push 3
    Pop 3
    Pop 1

    Push 4
    Push 5
    Pop 5

    Push 6
    Pop 6

    Push 7
    Pop 7
    Pop 4

    Push 8
    Push 9
    Pop 9
    Pop 8

最终输出完全符合目标。

因此：

$$
\boxed{\text{序列二合法}}
$$

#### 55.3 本问的通用算法
对每一个目标输出元素：

- 尚未入栈：继续按输入顺序压入。
- 已经入栈且处于栈顶：弹出。
- 已经入栈但不在栈顶：不合法。

复杂度：

$$
\boxed{O(n)}
$$


### 五十六、第二问：非法出栈序列的数学条件
给定输出：

$$
P_1,P_2,\ldots,P_n
$$

若存在：

$$
i<j<k
$$

且：

$$
\boxed{P_j<P_k<P_i}
$$

就出现 312 禁形。

这是固定递增输入、一个普通栈条件下合法出栈排列的禁止模式。

注意：

三个位置按输出顺序排列。

但是元素数值满足：

    第一项最大
    第二项最小
    第三项居中

考场写法：

“若输出序列中存在三个按先后顺序出现的元素 a、b、c，满足 $a>c>b$，则 b 在 c 尚未出栈时不可能越过 c 先出栈，因此该序列不合法。”


### 五十七、第三问：n=4，以 2 开头的输出有多少种？
输入：

    1,2,3,4

要求第一个输出是：

    2

必须先：

    Push 1
    Push 2
    Pop 2

此时：

    栈：[1]

剩余未入栈：

    3,4

所有合法序列：

    2,1,3,4

    2,1,4,3

    2,3,1,4

    2,3,4,1

    2,4,3,1

所以：

$$
\boxed{5}
$$

即：

$$
C_3=5
$$

注意：

    2,4,1,3

不合法。

因为 4 出栈后：

    3

仍压在 1 上面。

所以不能先弹 1 再弹 3。


### 五十八、第四问：已知 C(k-1)=M，求 C(k)
#### 58.1 以 1 开头
如果第一个输出元素是 1：

必须：

    Push 1
    Pop 1

之后剩余：

    2,3,...,k

等价于：

    k-1 个元素的普通出栈问题

因此：

$$
\boxed{M}
$$

种。

#### 58.2 以 2 开头
如果第一个输出元素是 2：

必须：

    Push 1
    Push 2
    Pop 2

之后：

栈底保留 1。

剩余过程对应一个与规模 $k-1$ 的合法栈操作路径等价的计数问题。

所以：

$$
\boxed{M}
$$

种。

#### 58.3 所有合法序列
卡特兰数：

$$
C_k=\frac{1}{k+1}\binom{2k}{k}
$$

而：

$$
C_{k-1}
=\frac{1}{k}\binom{2k-2}{k-1}
=M
$$

计算比值：

$$
\frac{C_k}{C_{k-1}}
=
\frac{2(2k-1)}{k+1}
$$

所以：

$$
\boxed{
C_k=\frac{2(2k-1)}{k+1}M
}
$$

#### 58.4 本题最终答案
| 问题 | 结果 |
|---|---|
| 序列一是否合法 | 不合法 |
| 序列二是否合法 | 合法 |
| 非法禁形 | $P_j<P_k<P_i,\ i<j<k$ |
| n=4，以2开头 | 5 |
| k个元素以1开头 | M |
| k个元素以2开头 | M |
| k个元素总数 | $\frac{2(2k-1)}{k+1}M$ |


## 第十一部分：高价值拓展——应对新题
### 五十九、固定第一个出栈元素为 m 的一般计数
这属于比普通卡特兰数更深入的变式。

输入：

$$
1,2,\ldots,n
$$

要求第一个出栈元素是：

$$
m
$$

#### 59.1 强制前缀
必须先：

    Push 1
    Push 2
    ...
    Push m
    Pop m

此时：

已经压入 m 个元素。

已经弹出 1 个元素。

当前栈深：

$$
m-1
$$

剩余：

- 入栈 $n-m$ 次。
- 出栈 $n-1$ 次。

并且过程中不能发生空栈出栈。

#### 59.2 一般计数公式
利用满足下界约束的路径计数，可以得到：

$$
\boxed{
N(n,m)
=
\frac{m}{2n-m}\binom{2n-m}{n}
}
$$

其中：

$$
1\le m\le n
$$

这个公式不是普通卡特兰数公式，而是固定首个出栈元素后的计数。

#### 59.3 n=4 的结果
分别求：

以 1 开头：

$$
N(4,1)=5
$$

以 2 开头：

$$
N(4,2)=5
$$

以 3 开头：

$$
N(4,3)=3
$$

以 4 开头：

$$
N(4,4)=1
$$

总数：

$$
5+5+3+1=14
$$

正好：

$$
C_4=14
$$

#### 59.4 应该如何掌握？
408 常规复习重点是：

- 栈模拟。
- 卡特兰数。
- 固定首元素后的状态分析。

一般公式属于提高部分。

更重要的是会将问题转化成：

**在已知初始栈深的情况下，剩余入栈和出栈操作有多少种合法安排。**

这样即使题目改变首元素条件，也能分析。


### 六十、限制栈容量的合法序列计数
#### 60.1 问题
输入：

$$
1,2,\ldots,n
$$

但栈容量最多为：

$$
c
$$

问有多少种合法出栈排列？

普通卡特兰数允许栈深最高达到 n。

但现在额外要求：

$$
\text{栈深}\le c
$$

所以不能直接使用：

$$
C_n
$$

#### 60.2 动态规划
定义：

$$
f(p,q)
$$

表示：

已经入栈 p 次。

已经出栈 q 次。

满足所有限制的合法操作前缀数量。

当前栈深：

$$
p-q
$$

必须满足：

$$
0\le q\le p\le n
$$

以及：

$$
p-q\le c
$$

初始状态：

$$
f(0,0)=1
$$

#### 60.3 入栈转移
如果：

$$
p<n
$$

且：

$$
p-q<c
$$

则可以继续入栈。

转移：

$$
f(p+1,q)\mathrel{+}=f(p,q)
$$

#### 60.4 出栈转移
如果：

$$
q<p
$$

说明栈非空。

可以出栈：

$$
f(p,q+1)\mathrel{+}=f(p,q)
$$

最终答案：

$$
\boxed{f(n,n)}
$$

#### 60.5 特例：容量为 1
如果：

$$
c=1
$$

每次只能：

    Push 1
    Pop 1

然后：

    Push 2
    Pop 2

……

输出只能等于输入顺序。

所以只有：

$$
\boxed{1}
$$

种。

#### 60.6 特例：容量为 2
对于：

$$
c=2
$$

合法出栈序列数量为：

$$
\boxed{2^{n-1}}
$$

例如：

$$
n=4
$$

得到：

$$
2^3=8
$$

而普通卡特兰数：

$$
C_4=14
$$

说明容量限制排除了一部分需要更深栈空间的合法序列。

#### 60.7 为什么容量为 2 得到 2 的幂？
将一次入栈记为左括号。

一次出栈记为右括号。

容量为 2 表示：

合法括号路径高度不超过 2。

这样的路径可以分解为若干个不可再分的完整块。

每个块的括号对数是正整数。

因此等价于：

把 n 拆成若干个正整数的有序拆分。

n 个单位之间有：

$$
n-1
$$

个间隙。

每个间隙有两种选择：

- 切开。
- 不切开。

所以：

$$
\boxed{2^{n-1}}
$$

这也是卡特兰类问题中常见的“增加容量限制后改用状态计数”的思路。


### 六十一、队列与树的层序遍历
2027 王道模拟卷还涉及队列在层序遍历中的空间分析。

#### 61.1 问题
一个二叉树有：

$$
31
$$

个结点。

采用队列进行层序遍历。

问遍历过程中队列长度最大可能达到多少？

#### 61.2 分析
层序遍历：

1. 队头结点出队。
2. 访问该结点。
3. 将其非空左孩子、右孩子入队。

每处理一个结点：

出队 1 个。

最多入队 2 个。

所以队列长度最多增加 1。

#### 61.3 最大队列长度
如果是一棵满二叉树：

31 个结点可以构成：

    1
    2
    4
    8
    16

五层。

最后一层：

    16 个叶结点

处理完上一层后：

这些叶结点全部进入队列。

因此队列长度可以达到：

$$
\boxed{16}
$$

#### 61.4 推广
对于 N 个结点的二叉树：

层序遍历队列长度最大可能为：

$$
\boxed{
\left\lfloor\frac{N+1}{2}\right\rfloor
}
$$

这一上界可以通过适当形状的二叉树达到。

但不是说所有 N 个结点的二叉树都会达到该最大值。

例如单支链状二叉树：

层序队列长度最多只有 1。

#### 61.5 本题的考点
它不是简单地考“层序遍历使用队列”。

而是考：

**算法运行过程中辅助结构的最大空间占用。**

这类题以后还可能与：

- BFS。
- 树的宽度。
- 最坏辅助空间。
- 最大活跃结点数量。

结合。


### 六十二、队列与火车轨道问题

$$

可以划分为：

轨道 1：

    8,9

轨道 2：

    4,5,6,7

轨道 3：

    2,3

轨道 4：

    1

每条轨道都递增。

所以：

$$
\boxed{4}
$$

条足够。

#### 62.5 新题迁移
如果题目出现：

- 多条 FIFO 通道。

- 要求整体输出有序。
- 每条通道内部不可逆序。

### 六十七、必须避免的 20 个错误
#### 错误 1：认为栈不是线性结构
正确：

栈是操作受限的线性表。

#### 错误 2：认为入栈顺序确定后，出栈顺序唯一
错误。

允许 Push、Pop 交替执行。

所以可以产生多种输出。

#### 错误 3：认为固定 n 个元素只有 n 种输出
错误。

普通单栈合法输出总数是：

$$
C_n
$$

#### 错误 4：没有考虑栈容量限制
一个出栈序列即使满足 LIFO：

也可能要求的最大栈深超过给定容量。

#### 错误 5：混淆 top 的含义
top 指当前栈顶：

    data[++top] = x

top 指下一空位：

    data[top++] = x

#### 错误 6：共享栈判满公式乱套
指向当前元素：

$$
top_1+1=top_2
$$

指向各自下一空位的常见方案：

$$
top_1=top_2+1
$$

前提和初始化方式不同。

#### 错误 7：链栈出栈时先移动指针再取值
可能取得错误元素。

正确：

先取旧栈顶的数据。

#### 错误 8：链队删除最后一个结点后忘记更新 rear
会留下悬空指针。

#### 错误 9：以为循环队列长度永远是 rear-front
只有在没有绕回等特定情况下才成立。

标准模公式：

$$
(rear-front+M)\bmod M
$$

#### 错误 10：以为循环队列一定浪费一个存储单元
不一定。

使用 size 或 tag 时可以利用全部数组单元。

#### 错误 11：混淆 rear 指向队尾和下一空位置
这是队列题中最常见的错误之一。

#### 错误 12：以为双端队列一定遵循普通 FIFO
双端队列可以在两端操作。

需要根据具体限制判断。

#### 错误 13：后缀表达式求值时反转减法顺序
正确：

第一次弹出右操作数。

第二次弹出左操作数。

#### 错误 14：中缀转后缀时不考虑结合性
对左结合运算符：

同优先级通常需要先弹旧运算符。

对右结合运算符：

不能机械套用。

#### 错误 15：以为中缀表达式中的括号也要输出到后缀式
错误。

括号用于控制转换过程。

不会出现在标准后缀表达式中。

#### 错误 16：把三角矩阵误当成对称矩阵
对称矩阵可以交换下标。

三角矩阵另一侧通常是固定常量。

#### 错误 17：矩阵 1 基与压缩数组 0 基混用
会产生典型的差 1 错误。

#### 错误 18：三对角矩阵元素数写成 3n
正确：

$$
3n-2
$$

#### 错误 19：认为三元组表只保存元素值
还必须记录：

- 行号。
- 列号。

#### 错误 20：认为节省空间就一定提高随机访问速度
错误。

三元组表可能需要遍历或查找才能获得某个元素。

## 全章最终总结
这一章可以浓缩为四条主线。

### 第一条：栈的本质是 LIFO
所有栈序列题：

都要遵守：

**只能弹出当前栈顶。**

普通合法性判断使用模拟。

容量限制记录最大栈深。

计数问题考虑卡特兰数及其推广。

### 第二条：队列的本质是 FIFO
所有循环队列题：

都要先弄清：

**front、rear 到底指向什么。**

随后推导：

- 判空。
- 判满。
- 长度。
- 入队。
- 出队。

不要死记某一组公式。

### 第三条：表达式问题的本质是运算依赖关系
中缀表达式：

依靠优先级、结合性和括号。

后缀表达式：

依靠记号顺序和栈。

表达式树：

直接描述运算依赖关系。

因此：

**先理解谁应该先算，再选择如何用栈实现。**

### 第四条：矩阵压缩的本质是二维到一维的映射
对于任何压缩存储：

核心问题永远是：

**目标元素之前已经存储了多少个有效元素？**

确定：

- 存储区域。
- 存储顺序。
- 下标起点。
- 当前行列偏移。

就能推导公式。

本章最终要建立的能力，不是记住几十道题的答案，而是能够将一道陌生题快速归入以下模型：

    出栈合法性 → 栈模拟

    最小栈容量 → 最大栈深

    栈序列总数 → 卡特兰数

    特殊栈限制 → 状态模拟或动态规划

    循环队列 → 模运算与指针语义

    链队设计 → 指针维护与结构不变量

    表达式转换 → 运算符栈

    表达式求值 → 操作数栈

    多维数组地址 → 线性偏移

    矩阵压缩 → 有效元素计数

    稀疏矩阵 → 非零元及其位置信息

掌握这些模型及其适用前提后，即使未来考研题改变数字、指针约定、操作限制或者矩阵存储顺序，也能够重新推导，而不是依赖记忆中的固定答案。
