## 二、栈：从 LIFO 到完整的存储与操作

### 2.1 什么是栈？为什么是后进先出？

栈（Stack）是只允许在一端插入和删除的线性表。

允许操作的一端叫栈顶（Top），另一端叫栈底（Bottom）。

例如依次压入：

```text
Push(1)
Push(2)
Push(3)
Push(4)
```

栈的状态是：

```text
       栈顶
        ↓
      ┌───┐
      │ 4 │ ← 最后进入，最先出去
      ├───┤
      │ 3 │
      ├───┤
      │ 2 │
      ├───┤
      │ 1 │ ← 最先进入
      └───┘
       栈底
```

因此连续出栈的顺序是：

```text
4 → 3 → 2 → 1
```

这就是：

$$
\boxed{\text{LIFO：Last In First Out}}
$$

这里有一个非常重要的区分：

<Callout type="warn" title="LIFO 不等于出栈序列必须完全逆序">

栈的 LIFO 特性，不代表出栈序列一定是入栈序列的完全逆序。

</Callout>

因为入栈和出栈可以交替进行。

例如：

```text
Push(1)
Push(2)
Pop()    → 2
Push(3)
Pop()    → 3
Pop()    → 1
```

输出为：

$$
2,3,1
$$

它既不是正序，也不是完全逆序，但仍然合法。

这也是 408 出栈序列题的理论基础。

### 2.2 栈的基本操作

| 操作             | 含义       | 时间复杂度      |
| -------------- | -------- | ---------- |
| `InitStack`    | 初始化      | $O(1)$ |
| `Push(x)`      | 入栈       | $O(1)$ |
| `Pop()`        | 出栈       | $O(1)$ |
| `GetTop()`     | 查看栈顶、不删除 | $O(1)$ |
| `StackEmpty()` | 判空       | $O(1)$ |

在常见顺序栈、链栈实现中，这些都是常数时间操作；不包含动态扩容时整体搬移元素的情况。

考试中必须区分：

- `Pop`：删除元素，栈顶发生变化。
- `GetTop`：只读取元素，栈顶不变化。

### 2.3 顺序栈：最重要的是 `top` 的定义

顺序栈用数组存储元素。

假设：

```c
#define MaxSize 100

typedef struct {
    int data[MaxSize];
    int top;
} SqStack;
```

最常见的教材约定是：

> `top` 指向当前栈顶元素。

此时：

初始空栈

```text
top = -1
```

压入第一个元素

```text
data[0] = x
top = 0
```

压入第二个元素

```text
data[1] = y
top = 1
```

所以栈中元素数量为：

$$
\boxed{L=top+1}
$$

队空和队满条件分别为：

$$
\boxed{top=-1}
$$

$$
\boxed{top=MaxSize-1}
$$

对应操作：

```c
// 入栈
bool Push(SqStack *S, int x) {
    if (S->top == MaxSize - 1)
        return false;

    S->data[++S->top] = x;
    return true;
}

// 出栈
bool Pop(SqStack *S, int *x) {
    if (S->top == -1)
        return false;

    *x = S->data[S->top--];
    return true;
}
```

为什么入栈是 `++top`，出栈是 `top--`？

因为栈顶下标表示已经存放元素的位置。

- 入栈：先移动到新的可用位置，再写入。
- 出栈：先读取旧栈顶，再向下移动。

另一种约定也很常见。

若 `top` 指向下一个可插入位置，则：

| 项目   | 指向当前栈顶           | 指向下一空位置         |
| ---- | ---------------- | --------------- |
| 空栈   | `top=-1`         | `top=0`         |
| 元素数量 | `top+1`          | `top`           |
| 判满   | `top==MaxSize-1` | `top==MaxSize`  |
| 入栈   | `data[++top]=x`  | `data[top++]=x` |
| 出栈   | `x=data[top--]`  | `x=data[--top]` |

考场原则：不要在读清楚 `top` 的定义前直接套公式。

### 2.4 共享栈：两个栈共用一个数组

共享栈是一个很容易考查边界条件的知识点。

设数组：

```text
A[0 ... n-1]
```

让栈 1 从左端向右增长，栈 2 从右端向左增长：

```text
数组下标：
 0    1    2    3    4    5    6    7

┌────┬────┬────┬────┬────┬────┬────┬────┐
│ S1 │ S1 │ S1 │ 空 │ 空 │ 空 │ S2 │ S2 │
└────┴────┴────┴────┴────┴────┴────┴────┘
           →                ←
```

#### 第一种定义：两个指针指向已占用的栈顶

令：

```text
top1 = -1
top2 = n
```

栈 1 入栈：

```text
A[++top1] = x;
```

栈 2 入栈：

```text
A[--top2] = x;
```

当二者相邻：

$$
\boxed{top_1+1=top_2}
$$

说明数组所有位置已被占用。

#### 第二种定义：两个指针指向下一可用位置

令：

```text
top1 = 0
top2 = n-1
```

栈 1 入栈：

```text
A[top1++] = x;
```

栈 2 入栈：

```text
A[top2--] = x;
```

这时：

$$
\boxed{top_1=top_2+1}
$$

才表示已经没有空位。

注意：当 `top1==top2` 时，中间还剩一个可用单元。

#### 模拟题：共享栈判满

模拟题：

> `top1=0`、`top2=n-1`，两个指针均指向下一可用位置，问双栈判满条件。

答案为：

$$
\boxed{top_1-top_2=1}
$$

原因是两个指针已经交错，中间不再存在任何未使用的数组单元。

这道题的真正考点并不是共享栈本身，而是：

相同的数据结构，只要指针语义改变，判满公式就会改变。

### 2.5 链栈：为什么通常在链表头部操作？

链栈使用单链表实现栈。

一种不带头结点的结构如下：

```text
top
 ↓
[A] → [B] → [C] → NULL
```

栈顶是 A。

入栈 X：

```text
top
 ↓
[X] → [A] → [B] → [C] → NULL
```

对应代码：

```c
bool Push(LinkNode **top, int x) {
    LinkNode *p = malloc(sizeof(LinkNode));
    if (p == NULL)
        return false;

    p->data = x;
    p->next = *top;
    *top = p;

    return true;
}
```

出栈：

```c
bool Pop(LinkNode **top, int *x) {
    if (*top == NULL)
        return false;

    LinkNode *p = *top;
    *x = p->data;
    *top = p->next;
    free(p);

    return true;
}
```

为什么不把单链表尾结点作为栈顶？

因为普通单链表只能从某个结点快速找到其后继，不能直接找到其前驱。

如果栈顶位于链尾，删除尾结点时通常要遍历寻找前驱，可能需要：

$$
O(n)
$$

如果栈顶位于链头，则头插、头删都只需：

$$
O(1)
$$

#### 模拟题：链栈出栈代码

对于非空链栈，题目给出：

```text
x = top->data;
top = top->link;
```

这是正确的取值与指针更新顺序。

但如果结点由 `malloc` 分配，完整实现还必须用临时指针保存旧栈顶并释放旧结点。

否则虽然逻辑上完成了出栈，却会发生内存泄漏。

### 2.6 2017 年真题：栈的概念判断

题目判断以下四个说法：

I. 非递归方式重写递归程序时必须使用栈。

II. 函数调用时，系统要用栈保存必要的信息。

III. 确定入栈次序，就能确定出栈次序。

IV. 栈允许在其两端进行操作。

答案：I、III、IV 错误，即 C。

逐项分析：

I 错。 递归改写为非递归不一定需要显式栈。例如：

```c
int sum(int n) {
    if (n == 0) return 0;
    return n + sum(n - 1);
}
```

可以改写成：

```c
int sum(int n) {
    int ans = 0;

    for (int i = 1; i <= n; i++)
        ans += i;

    return ans;
}
```

没有显式使用栈。

II 对。 常规函数调用中，运行时栈可保存返回地址、局部变量以及调用现场等必要信息。

III 错。 因为入栈与出栈可以交替发生。

IV 错。 栈只能在栈顶一端执行插入和删除。

这道题还说明一个命题规律：

题干中出现“必须”“一定”“只能”等绝对化说法时，要检查是否存在合法反例。

## 三、栈序列：本章最重要的综合考点之一

这一节是整个第 3 章最值得认真训练的内容。

### 3.1 如何判断一个出栈序列是否合法？

设固定入栈顺序：

$$
1,2,3,4,5
$$

判断以下输出是否合法：

$$
2,3,1,5,4
$$

正确方法是按目标序列强制模拟。

| 目标输出 | 必须进行的操作   | 栈底→栈顶 |
| ---- | --------- | ----- |
| 2    | 入 1、2，出 2 | `[1]` |
| 3    | 入 3，出 3   | `[1]` |
| 1    | 出 1       | `[]`  |
| 5    | 入 4、5，出 5 | `[4]` |
| 4    | 出 4       | `[]`  |

所有元素恰好入栈和出栈一次，因此：

$$
\boxed{\text{合法}}
$$

再看：

$$
3,1,2,5,4
$$

为了先输出 3，必须：

```text
Push(1)
Push(2)
Push(3)
Pop() → 3
```

此时：

```text
栈顶 → 2
       1
```

下一个目标是 1。

但是 1 被 2 压在下面。

继续压入 4、5 也不会让 1 出现在栈顶，所以不合法。

判定不合法的关键：一个待输出元素已经在栈中，却不是栈顶。

### 3.2 合法出栈序列的标准算法

对于固定输入 $1,2,\ldots,n$，可用下面的算法判断候选输出序列 `P`：

```c
// 假设 P 是 1..n 的一个排列
bool IsValidPop(const int P[], int n) {
    int *S = malloc((size_t)n * sizeof(int));
    if (n > 0 && S == NULL)
        return false;

    int top = -1;
    int next = 1;

    for (int i = 0; i < n; i++) {
        // 若目标元素还未入栈，就压到目标元素
        while (next <= P[i]) {
            S[++top] = next;
            next++;
        }

        // 目标必须恰好位于栈顶
        if (top == -1 || S[top] != P[i]) {
            free(S);
            return false;
        }

        top--;
    }

    free(S);
    return true;
}
```

每个元素最多入栈一次、出栈一次，所以：

$$
T(n)=O(n)
$$

辅助栈最多保存 $n$ 个元素：

$$
S(n)=O(n)
$$

考试要求算法设计时，除了代码，还应写出这两项复杂度。

### 3.3 2009 年真题：最小栈容量

题目：

元素依次进入栈：

```text
a b c d e f g
```

出栈后立即进入队列，最终出队顺序为：

```text
b d c f e a g
```

问栈容量至少是多少？

答案：3。

因为队列 FIFO，所以最终出队次序就是栈的出栈次序。

按目标模拟：

| 操作      | 栈底→栈顶   | 已输出           | 栈深 |
| ------- | ------- | ------------- | -- |
| 入 a、b   | `a b`   | —             | 2  |
| 出 b     | `a`     | b             | 1  |
| 入 c、d   | `a c d` | b             | 3  |
| 出 d、c   | `a`     | b d c         | 1  |
| 入 e、f   | `a e f` | b d c         | 3  |
| 出 f、e、a | 空       | b d c f e a   | 0  |
| 入 g、出 g | 空       | b d c f e a g | 1  |

最大同时占用 3 个位置。

因此：

$$
\boxed{\text{最小栈容量}=3}
$$

这类题务必区分：

- 总共处理多少个元素；
- 栈中最多同时存在多少个元素。

最小栈容量只与过程中的最大栈深有关，不等于总元素个数。

### 3.4 2010 年真题：增加操作限制

题目规定：

- 入栈顺序为 `a,b,c,d,e,f`；
- 入栈、出栈允许交替；
- 不允许连续三次出栈。

问哪个输出序列不可能？

A. `dcebfa`

B. `cbdaef`

C. `bcaefd`

D. `afedcb`

答案为：

$$
\boxed{D}
$$

为什么？

要先输出 a，就必须先入 a、出 a。

为了第二个输出 f，需要把 b、c、d、e、f 全部压入。

此时所有元素都已经入过栈：

```text
栈顶 → f
       e
       d
       c
       b
```

之后只能连续出栈：

```text
f → e → d → c → b
```

连续进行了 5 次出栈，违反题目的额外限制。

这道题告诉我们：

栈序列本身合法，不代表满足附加条件后仍然合法。

题目可能附加栈容量、连续操作次数、某个元素的出栈位置等限制。

遇到这些题，不能只检查普通 LIFO。

### 3.5 2013 年真题：某个出栈位置的可能取值

固定入栈次序：

$$
1,2,\ldots,n
$$

已知：

$$
p_2=3
$$

求 $p_3$ 的可能取值个数。

答案：$n-1$。

第三个出栈元素不可能再次是 3。

但其他值都可能。

例如：

第三个出栈是 1

```text
入 1、2 → 出 2
入 3 → 出 3
出 1
```

出栈前三项：

$$
2,3,1
$$

第三个出栈是 2

```text
入 1 → 出 1
入 2、3 → 出 3、2
```

出栈前三项：

$$
1,3,2
$$

第三个出栈是任意 $k\ge4$

先出 1，再出 3，然后继续入栈直到 $k$，出 $k$。

所以：

$$
p_3\in\{1,2,4,5,\ldots,n\}
$$

共有：

$$
\boxed{n-1}
$$

种。

这类题不要只猜排列组合公式。

应采用：

构造可能情况 → 排除不可能值 → 证明没有遗漏。

### 3.6 模拟题：栈容量限制

模拟题常见这一模型：

栈容量为 3，元素按：

$$
1,2,3,4,5
$$

依次入栈，允许入栈和出栈交替进行。

哪一个输出可能？

A. `3,2,1,5,4`

B. `1,5,4,3,2`

C. `5,4,3,2,1`

D. `4,3,2,1,5`

答案为 A。

- A：先压入 1、2、3，再依次弹出；之后压入 4、5，再依次弹出。最大深度为 3。
- B：先输出 1，再输出 5，必须同时压入 2、3、4、5，深度达到 4。
- C：首元素是 5，必须先压入所有 5 个元素。
- D：首元素是 4，必须先压入前 4 个元素。

因此只有 A 满足容量限制。

一个非常实用的技巧：

如果目标出栈序列以一个较大的元素开始，先数它之前有多少元素被迫留在栈中。

### 3.7 2026 年第 42 题：栈序列禁形与卡特兰数

这是一道重点综合题。

它将栈的模拟、排列结构、计数和数学证明结合在一起。

#### 第 1 问：判断两个出栈序列是否合法

输入顺序：

$$
1,2,\ldots,9
$$

第一组：

$$
P=(2,3,1,6,4,7,5,9,8)
$$

判断：不合法。

先完成：

```text
入 1、2 → 出 2
入 3 → 出 3
出 1
入 4、5、6 → 出 6
```

此时栈中剩余：

```text
栈顶 → 5
       4
```

下一目标是 4。

4 被 5 压住，所以不合法。

第二组：

$$
Q=(2,3,1,5,6,7,4,9,8)
$$

判断：合法。

可以构造：

```text
入 1、2 → 出 2
入 3 → 出 3、1

入 4、5 → 出 5
入 6 → 出 6
入 7 → 出 7、4

入 8、9 → 出 9、8
```

每个元素都符合固定入栈顺序。

#### 第 2 问：什么是 312 禁形？

这是一个很重要的理论结论。

对于输入次序：

$$
1,2,\ldots,n
$$

如果某个输出序列存在三个位置：

$$
i<j<k
$$

使得：

$$
\boxed{P_j<P_k<P_i}
$$

那么这个序列不可能由单栈产生。

这种相对大小关系称为 312 型禁形。

例如：

$$
3,1,2
$$

三个数字的相对大小为：

```text
第一个：最大（3）
第二个：最小（1）
第三个：中间（2）
```

为什么不合法？

为了先输出 3，必须先压入：

```text
1 → 2 → 3
```

弹出 3 后：

```text
栈顶 → 2
       1
```

输出要求先弹出 1，再弹出 2。

可是 2 压住了 1。

因此违反 LIFO。

更一般地，设三个数为 $a,b,c$，按输出顺序出现，并满足：

$$
b<c<a
$$

要先输出 $a$，输入过程中 $b,c$ 必然已经入栈；由于 $b<c$，$c$ 会压在 $b$ 上面。

但输出要求 $b$ 先于 $c$。

矛盾。

因此：

$$
\boxed{ \text{升序入栈的排列合法} \iff \text{不存在 312 禁形} }
$$

这里特别注意：

312 是输出位置上的相对大小模式，不是说必须出现数字 3、1、2。

例如：

$$
8,2,5
$$

同样满足：

$$
2<5<8
$$

因此也是一个 312 禁形。

实际考场判断单个序列时，通常仍推荐用栈模拟；312 禁形更适合用于证明。

#### 第 3 问：$n=4$，以 2 开头有多少种？

输入：

$$
1,2,3,4
$$

第一个出栈元素固定为 2。

此时必须先：

```text
Push(1)
Push(2)
Pop() → 2
```

剩余元素为 1、3、4。

所有合法输出可以列为：

| 序号 | 合法出栈序列  |
| -- | ------- |
| 1  | 2,1,3,4 |
| 2  | 2,1,4,3 |
| 3  | 2,3,1,4 |
| 4  | 2,3,4,1 |
| 5  | 2,4,3,1 |

因此：

$$
\boxed{5}
$$

这是卡特兰数：

$$
C_3=5
$$

#### 第 4 问：为什么会出现卡特兰数？

有 $n$ 个不同元素，固定入栈顺序，允许合法地交替执行入栈和出栈。

把入栈记作 `(`，出栈记作 `)`。

例如：

```text
Push(1)
Push(2)
Pop()
Push(3)
Pop()
Pop()
```

转换成括号序列：

```text
(()())
```

合法操作必须满足：

1. 总入栈次数为 $n$；
2. 总出栈次数为 $n$；
3. 任意时刻，出栈次数不能大于入栈次数。

设某个操作前缀已入栈 $p$ 次，出栈 $q$ 次，则始终需要：

$$
\boxed{0\le q\le p\le n}
$$

这些条件恰好对应合法括号序列计数问题。

因此总数为第 $n$ 个卡特兰数：

$$
\boxed{ C_n=\frac{1}{n+1}\binom{2n}{n} }
$$

等价于：

$$
C_n=\frac{(2n)!}{n!(n+1)!}
$$

可以记住前几个结果：

| $n$ | 合法出栈序列数 |
| ------- | ------- |
| 1       | 1       |
| 2       | 2       |
| 3       | 5       |
| 4       | 14      |
| 5       | 42      |
| 6       | 132     |
| 7       | 429     |
| 8       | 1430    |
| 9       | 4862    |

#### 卡特兰数的递推

$$
C_0=1
$$

$$
\boxed{ C_n=\sum_{i=0}^{n-1}C_iC_{n-1-i} }
$$

为什么是这个形式？

考虑第一个入栈操作与哪个出栈操作配对。

在这对操作所包围的区域中，有 $i$ 对合法操作；在它后面，还有 $n-1-i$ 对合法操作。

两部分独立选择，因此贡献：

$$
C_iC_{n-1-i}
$$

把全部可能的 $i$ 相加，就得到递推式。

#### 如果 $C_{k-1}=M$，如何求 $C_k$？

利用：

$$
\frac{C_k}{C_{k-1}} = \frac{2(2k-1)}{k+1}
$$

得到：

$$
\boxed{ C_k=\frac{2(2k-1)}{k+1}M }
$$

#### 如果限定第一个出栈元素是 1 或 2？

第一个出栈元素是 1 时：

```text
Push(1)
Pop(1)
```

剩余 $k-1$ 个元素构成完整的同类问题。

因此共有：

$$
\boxed{M}
$$

种。

第一个出栈元素是 2 时，强制操作：

```text
Push(1)
Push(2)
Pop(2)
```

此时 1 留在栈底，剩余过程同样能与规模 $k-1$ 的合法栈过程建立一一对应。

因此也有：

$$
\boxed{M}
$$

种。

2026 年这道题需要同时掌握：

操作模拟、312 禁形、卡特兰数计数、限定首元素后的计数。

### 3.8 强化：容量受限的卡特兰数

下面是同类型拓展训练。

问题：

固定输入：

$$
1,2,\ldots,n
$$

但栈最多只能同时保存 $c$ 个元素。

求合法出栈序列数量。

普通卡特兰数只要求：

$$
0\le q\le p\le n
$$

现在还需要：

$$
p-q\le c
$$

其中：

$$
p-q
$$

就是当前栈深。

定义：

$$
f(p,q)
$$

表示已经入栈 $p$ 次、出栈 $q$ 次时的合法操作前缀数量。

初始化：

$$
f(0,0)=1
$$

可以进行两种转移。

继续入栈：

如果：

$$
p<n,\qquad p-q<c
$$

则：

$$
f(p+1,q)\mathrel{+}=f(p,q)
$$

继续出栈：

如果：

$$
q<p
$$

则：

$$
f(p,q+1)\mathrel{+}=f(p,q)
$$

最后答案为：

$$
\boxed{f(n,n)}
$$

只计算有效状态时，时间和表格空间可以做到：

$$
O(n(c+1))
$$

特别地，当容量 $c=2$ 时，存在结论：

$$
\boxed{f(n,n)=2^{n-1}},\qquad n\ge1
$$

例如：

$$
n=4,\quad c=2
$$

答案为：

$$
2^3=8
$$

而没有容量限制时：

$$
C_4=14
$$

为什么容量为 2 时是 $2^{n-1}$？

把合法括号路径分解为若干个从高度 0 出发、第一次回到 0 的基本块。由于高度不能超过 2，每个基本块只能是外层一对括号包着零个或多个连续的 `()`：

```text
()
(())
(()())
(()()())
...
```

每个基本块包含正整数个括号对。把 $n$ 个括号对划分成这些连续基本块，就对应将 $n$ 拆成若干正整数的有序拆分。

$n$ 个单位之间共有 $n-1$ 个间隙，每个间隙都可以选择“切分”或“不切分”，因此共有：

$$
2^{n-1}
$$

种。

如果：

$$
c\ge n
$$

栈容量不再构成限制，结果退化为：

$$
\boxed{C_n}
$$

这是从基本栈知识延伸到动态规划的一条重要思路。

## 四、队列：从 FIFO 到循环队列和链式队列

### 4.1 队列的基本概念

队列（Queue）是只允许在队尾插入、在队头删除的线性表。

```text
                 队列
       ┌───┬───┬───┬───┐
出队 ← │ A │ B │ C │ D │ ← 入队
       └───┴───┴───┴───┘
        队头        队尾
```

依次进入：

```text
A → B → C → D
```

正常情况下必须依次出去：

```text
A → B → C → D
```

因此队列遵循：

$$
\boxed{\text{FIFO：First In First Out}}
$$

普通队列的标准基本操作有：

| 操作           | 功能     |
| ------------ | ------ |
| `InitQueue`  | 初始化    |
| `EnQueue`    | 队尾入队   |
| `DeQueue`    | 队头出队   |
| `GetHead`    | 读取队头   |
| `QueueEmpty` | 判断是否为空 |

注意：普通队列不能直接删除队尾，也不能直接在队头插入。

底层数组或链表能够访问某个位置，不代表队列的抽象操作允许修改该位置。

### 4.2 为什么普通顺序队列会产生假溢出？

假设一个长度为 5 的数组：

```text
下标： 0   1   2   3   4
      ┌───┬───┬───┬───┬───┐
      │ A │ B │ C │ D │ E │
      └───┴───┴───┴───┴───┘
```

队头 A、B 出队以后：

```text
下标： 0   1   2   3   4
      ┌───┬───┬───┬───┬───┐
      │空 │空 │ C │ D │ E │
      └───┴───┴───┴───┴───┘
```

数组前面有两个空位。

但是，如果普通顺序队列的 `rear` 只能向右增长，此时已经走到数组末端，无法继续入队。

这种现象叫：

假溢出（False Overflow）。

解决方法是把数组逻辑上首尾相连，形成循环队列。

### 4.3 循环队列：为什么所有公式都需要取模？

设数组长度：

$$
m=6
$$

下标为：

```text
0  1  2  3  4  5
```

循环移动规则是：

$$
\boxed{next(x)=(x+1)\bmod m}
$$

例如：

```text
0 → 1 → 2 → 3 → 4 → 5 → 0
```

当指针走到下标 5 后，下一个位置回到下标 0。

这并不意味着数组真的变成了环形内存。

实际内存仍然连续，只是程序使用模运算实现逻辑循环。

### 4.4 循环队列的标准指针约定

以下采用《408 知识点总结 2》的约定：

- `front`：指向当前队头元素。
- `rear`：指向下一个待插入位置。
- 牺牲一个数组单元区分队空与队满。

#### 队空条件

$$
\boxed{front=rear}
$$

#### 队满条件

$$
\boxed{(rear+1)\bmod m=front}
$$

#### 最大可用容量

$$
\boxed{m-1}
$$

#### 当前队列长度

$$
\boxed{L=(rear-front+m)\bmod m}
$$

#### 队尾元素下标

对于非空队列：

$$
\boxed{(rear-1+m)\bmod m}
$$

为什么容量是 $m-1$，而不是 $m$？

假设把全部 $m$ 个位置装满，`rear` 就可能绕一圈重新等于 `front`。

但我们已经使用：

$$
front=rear
$$

表示队空。

为了避免两种状态混淆，必须牺牲一个存储单元，或者额外保存其他状态信息。

### 4.6 循环队列三种判空判满方案

这部分是非常经典的选择题考点。

| 实现方式      | 判空            | 判满                  | 可存元素数     |
| --------- | ------------- | ------------------- | --------- |
| 牺牲一格      | `front==rear` | `(rear+1)%m==front` | $m-1$ |
| 增加 `size` | `size==0`     | `size==m`           | $m$   |
| 增加 `tag`  | 指针相等且为空标志     | 指针相等且为满标志           | $m$   |

方案一：牺牲一格

无需其他状态变量，但浪费一个数组单元。

方案二：维护元素数量

每次入队：

```text
size++;
```

每次出队：

```text
size--;
```

所以可以直接区分队空和队满。

方案三：增加状态标志

当：

```text
front == rear
```

时，使用标志判断上一次导致指针相遇的是入队还是出队。

例如规定：

```text
tag=0：最近一次改变队列状态的是出队
tag=1：最近一次改变队列状态的是入队
```

则指针相等时：

- `tag=0`：队空；
- `tag=1`：队满。

具体编码必须服从题目规定。

### 4.7 循环队列的 C 语言实现

```c
#define MaxSize 100

typedef struct {
    int data[MaxSize];
    int front;
    int rear;
} SqQueue;
```

初始化：

```c
void InitQueue(SqQueue *Q) {
    Q->front = 0;
    Q->rear = 0;
}
```

判空：

```c
bool QueueEmpty(SqQueue *Q) {
    return Q->front == Q->rear;
}
```

判满：

```c
bool QueueFull(SqQueue *Q) {
    return (Q->rear + 1) % MaxSize
           == Q->front;
}
```

入队：

```c
bool EnQueue(SqQueue *Q, int x) {
    if (QueueFull(Q))
        return false;

    Q->data[Q->rear] = x;
    Q->rear = (Q->rear + 1) % MaxSize;

    return true;
}
```

出队：

```c
bool DeQueue(SqQueue *Q, int *x) {
    if (QueueEmpty(Q))
        return false;

    *x = Q->data[Q->front];
    Q->front = (Q->front + 1) % MaxSize;

    return true;
}
```

所有基本操作的时间复杂度：

$$
\boxed{O(1)}
$$

这里一个非常容易考的细节是：

入队先写 `rear` 指向的位置，再移动 `rear`；出队先读取 `front` 指向的位置，再移动 `front`。

### 4.8 2011 年真题：`rear` 指向队尾元素时怎么办？

题目规定：

- 队列非空时，`front` 指向队头元素。
- `rear` 指向队尾元素。
- 第一个元素必须放在 `A[0]`。

问初始化时 `front` 和 `rear` 的值。

选项中正确的是：

$$
\boxed{front=0,\quad rear=n-1}
$$

为什么？

因为这次的 `rear` 不是下一空位置，而是当前队尾元素的位置。

入队时先执行：

$$
rear=(rear+1)\bmod n
$$

然后才写入：

```text
A[rear] = x;
```

为了让第一次入队的位置为 0：

$$
(n-1+1)\bmod n=0
$$

所以初始化：

$$
rear=n-1
$$

队头初始化为 0。

这一题和上一节公式不同，并不矛盾，因为题目改变了 `rear` 的含义。

这是整个循环队列部分最需要注意的事情。

### 4.9 链式队列

普通链式队列可以使用带头结点的单链表。

```text
front
  ↓
[头结点] → [A] → [B] → [C] → NULL
                              ↑
                             rear
```

这里约定：

- `front` 指向头结点；
- `rear` 指向最后一个有效结点；
- `front->next` 才是真正队头；
- 空队列时 `front==rear`。

入队时执行尾插：

```text
p->next = NULL;
Q->rear->next = p;
Q->rear = p;
```

出队时删除首元结点：

```text
p = Q->front->next;
Q->front->next = p->next;
```

但还要处理一个特殊情况。

如果队列原来只有一个有效结点，删除后必须让 `rear` 重新指向头结点。

即：

```c
if (Q->rear == p)
    Q->rear = Q->front;
```

否则 `rear` 会指向已经被释放的结点。

### 4.10 模拟题：只保留一个尾指针，能否实现队列？

如果使用循环单链表，并且只保存：

```text
rear
```

实际上也可以实现 $O(1)$ 的入队和出队。

因为：

```text
rear->next
```

就是队头。

```text
        rear
         ↓
[A] → [B] → [C]
 ↑           │
 └───────────┘
```

入队新结点 `p`：

```text
p->next = rear->next;
rear->next = p;
rear = p;
```

出队时删除：

```text
rear->next
```

指向的队头结点。

单结点时还要特别处理：

```text
rear = NULL;
```

所以入队、出队均为：

$$
\boxed{O(1)}
$$

注意：

- 普通非循环单链表只有尾指针，不方便直接找到队头；
- 循环单链表只有尾指针，可以通过 `rear->next` 直接找到队头。

这就是它们复杂度可能不同的原因。

## 五、2019 年第 42 题：完整的队列算法设计

这是一道重要算法设计题。

### 5.1 题目要求

设计一个队列，满足：

1. 初始为空。
2. 入队时允许增加空间。
3. 出队以后，原空间能够重复使用。
4. 已申请的空间只增不减。
5. 每次入队和出队始终为 $O(1)$。

同时要求说明存储结构、画初始状态图、写出判空判满条件及操作过程。

<Steps>

<Step>

    ### 5.2 第一步：为什么选链式存储？

如果使用固定数组，容量达到上限就无法继续入队。

如果使用动态数组，扩容时可能需要分配更大的连续空间，并复制原有元素。

单次扩容可能需要：

$$
O(n)
$$

题目要求每次操作都必须保持：

$$
O(1)
$$

因此采用循环链式队列更合适。

每次需要扩容时，只新增一个结点，并修改常数个指针。

</Step>

<Step>

    ### 5.3 第二步：设计存储结构

这里采用一种常见的循环链队列实现约定：

- `front` 指向当前队头数据结点；
- `rear` 指向下一个空闲位置；
- 所有已申请结点组成循环单链表；
- 始终保留至少一个空闲结点。

初始化时只申请一个结点：

```text
       ┌─────────┐
       │   N0    │
       └────┬────┘
            │
            └────→ 自己

front = rear = N0
```

因此：

$$
\boxed{\text{队空：}front=rear}
$$

当：

$$
\boxed{rear\rightarrow next=front}
$$

表示当前已分配空间中只剩 `rear` 这一空闲位置，再入队之前需要扩容。

注意：这个“满”并不是无法继续入队，而是当前空间已用尽，需要新增结点。

</Step>

<Step>

    ### 5.4 第三步：第一次入队

假设要入队：

```text
EnQueue(10)
```

由于初始只有一个结点，必须新增 `N1`。

```text
front                 rear
  ↓                     ↓
[N0:10] ───────────→ [N1:空]
   ↑                     │
   └─────────────────────┘
```

此时：

```text
front = N0
rear  = N1
```

有效队列内容为：

```text
10
```

已经申请两个结点，但只有一个有效数据元素。

</Step>

<Step>

    ### 5.5 第四步：写出入队操作

```c
typedef struct QNode {
    int data;
    struct QNode *next;
} QNode;

typedef struct {
    QNode *front;
    QNode *rear;
} CircleQueue;
```

初始化：

```c
bool InitQueue(CircleQueue *Q) {
    QNode *p = malloc(sizeof(QNode));
    if (p == NULL)
        return false;

    p->next = p;
    Q->front = Q->rear = p;
    return true;
}
```

入队：

```c
bool EnQueue(CircleQueue *Q, int x) {
    if (Q->rear->next == Q->front) {
        QNode *p = malloc(sizeof(QNode));

        if (p == NULL)
            return false;

        p->next = Q->rear->next;
        Q->rear->next = p;
    }

    Q->rear->data = x;
    Q->rear = Q->rear->next;

    return true;
}
```

理解代码时要分成两种情况。

情况一：有空闲结点

直接在 `rear` 指向的空结点写入数据，然后移动 `rear`。

情况二：已经没有额外空闲结点

先在 `rear` 后面插入一个新结点，再写入数据并移动 `rear`。

无论哪种情况，都只修改常数个指针。

</Step>

<Step>

    ### 5.6 第五步：写出出队操作

```c
bool DeQueue(CircleQueue *Q, int *x) {
    if (Q->front == Q->rear)
        return false;

    *x = Q->front->data;
    Q->front = Q->front->next;

    return true;
}
```

注意这里没有 `free()`。

因为题目要求已申请空间只增不减。

旧队头结点虽然不再属于有效队列，但仍留在物理环中，等待今后复用。

</Step>

</Steps>

### 5.7 强化训练：完整状态追踪

拓展题要求执行：

```text
EnQueue(10)
EnQueue(20)
DeQueue()
EnQueue(30)
DeQueue()
DeQueue()
EnQueue(40)
```

结果如下：

| 操作   | front | rear | 有效内容  | 已申请结点数 |
| ---- | ----- | ---- | ----- | ------ |
| 初始   | N0    | N0   | 空     | 1      |
| 入 10 | N0    | N1   | 10    | 2      |
| 入 20 | N0    | N2   | 10,20 | 3      |
| 出 10 | N1    | N2   | 20    | 3      |
| 入 30 | N1    | N0   | 20,30 | 3      |
| 出 20 | N2    | N0   | 30    | 3      |
| 出 30 | N0    | N0   | 空     | 3      |
| 入 40 | N0    | N1   | 40    | 3      |

最后：

- 三次出队结果是 10、20、30；
- 队列保存 40；
- 历史累计申请结点数仍然为 3。

原因是结点被重复利用了。

#### 2019 年题目的关键辨析

原题还有另一种等价的指针设计：

- `front` 指向当前队头的前驱结点；
- `rear` 指向当前队尾数据结点；
- 队空仍可以使用 `front==rear`；
- 当前环内没有可复用结点仍可由 `rear->next==front` 判断。

两种方案都可以正确实现，但入队、出队时指针移动顺序不同。

考场作答必须先声明采用哪种指针定义，再使用对应代码。

这道大题真正考查的是：

$$
\boxed{\text{逻辑上的有效队列}\ne\text{物理上已经申请的结点集合}}
$$

## 六、双端队列：输入受限与输出受限

### 6.1 普通双端队列

双端队列（Deque）允许：

- 队头插入；
- 队尾插入；
- 队头删除；
- 队尾删除。

因此，它比普通队列具有更灵活的操作方式。

### 6.2 两种受限双端队列

输入受限双端队列：

只允许从一端插入，但可以从两端删除。

输出受限双端队列：

允许从两端插入，但只能从固定的一端删除。

要记住：

| 类型       | 入队 | 出队  |
| -------- | -- | --- |
| 普通队列     | 单端 | 另一端 |
| 输入受限双端队列 | 单端 | 两端  |
| 输出受限双端队列 | 两端 | 单端  |
| 普通双端队列   | 两端 | 两端  |

### 6.3 2010 年真题：输出受限双端队列

题目：

元素按：

```text
a b c d e
```

依次入队。

可以从两端插入，但只能从固定的一端出队。

所有元素入队完成后，哪个输出序列不可能得到？

A. `bacde`

B. `dbace`

C. `dbcae`

D. `ecbad`

答案为：

$$
\boxed{C}
$$

这道题可以使用反向删除法。

因为元素按 a、b、c、d、e 依次从两端插入。

构造完成后，最后插入的 e 必然位于队列的某一端。

删除 e 后，d 也必须位于剩余序列的某一端。

继续反推。

对于 C：

```text
d b c a e
```

先删除 e：

```text
d b c a
```

再删除 d：

```text
b c a
```

接下来需要删除 c。

但 c 位于中间，既不是左端，也不是右端。

因此不可能通过依次从两端插入形成这个排列。

所以选 C。

技巧：当题目规定所有元素先入队、之后统一出队时，反向分析“每次删除的元素是否在两端”常比正向构造更简单。

但是如果允许入队和出队交替进行，就需要按照完整操作规则模拟，不能无条件套用这个逆向方法。

## 七、栈和队列的应用：表达式、递归、遍历与括号匹配

### 7.1 为什么括号匹配使用栈？

例如：

```text
{ [ ( ) ] }
```

判断括号是否合法时，应从左向右扫描。

遇到左括号：

```text
(、[、{
```

就将其入栈。

遇到右括号，就弹出栈顶的左括号进行匹配。

例如扫描：

```text
{ [ ( ) ] }
```

过程如下：

| 当前字符 | 操作        | 栈底→栈顶   |
| ---- | --------- | ------- |
| `{`  | 入栈        | `{`     |
| `[`  | 入栈        | `{ [`   |
| `(`  | 入栈        | `{ [ (` |
| `)`  | 匹配并弹出 `(` | `{ [`   |
| `]`  | 匹配并弹出 `[` | `{`     |
| `}`  | 匹配并弹出 `{` | 空       |

最后栈为空，整个过程没有失配，因此合法。

如果扫描：

```text
{ [ ( ] ) }
```

遇到 `]` 时，栈顶是 `(`，不匹配，立即判定非法。

核心原因：

最近出现但尚未匹配的左括号，必须最先得到匹配。

这正是 LIFO。

时间复杂度：

$$
O(n)
$$

辅助栈最坏空间：

$$
O(n)
$$

### 7.2 前缀、中缀和后缀表达式

考虑：

$$
(A+B)\times C
$$

三种表示如下：

| 类型 | 表达式         |
| -- | ----------- |
| 前缀 | `* + A B C` |
| 中缀 | `(A+B)*C`   |
| 后缀 | `A B + C *` |

可以通过表达式树理解：

```text
        *
       / \
      +   C
     / \
    A   B
```

- 前序遍历：`* + A B C`
- 中序遍历：`A + B * C`，需要根据树结构补充必要括号才能明确原运算优先级
- 后序遍历：`A B + C *`

所以：

$$
\boxed{\text{前序}\leftrightarrow\text{前缀}}
$$

$$
\boxed{\text{后序}\leftrightarrow\text{后缀}}
$$

中序访问顺序对应中缀表达式的符号次序，但直接中序遍历得到的字符序列不一定保留全部必要括号。

### 7.3 后缀表达式为什么只需要一个栈？

考虑后缀表达式：

```text
3 5 2 * 8 - +
```

算法：

- 遇到数字，压栈。
- 遇到运算符，弹出两个操作数。
- 计算后重新压入结果。

完整过程：

| 扫描字符 | 运算                | 栈底→栈顶  |
| ---- | ----------------- | ------ |
| 3    | 入栈                | 3      |
| 5    | 入栈                | 3,5    |
| 2    | 入栈                | 3,5,2  |
| \*   | $5\times2=10$ | 3,10   |
| 8    | 入栈                | 3,10,8 |
| -    | $10-8=2$      | 3,2    |
| +    | $3+2=5$       | 5      |

最终：

$$
\boxed{5}
$$

其中最重要的代码是：

```text
b = Pop();
a = Pop();

result = a op b;
```

第一次出栈的是右操作数。

如果运算符是减法或除法，颠倒顺序会直接算错。

### 7.4 2018 年真题：两个栈执行表达式求值

题目规定：

操作数栈 S1 自栈底到栈顶为：

```text
5, 8, 3, 2
```

运算符栈 S2 自栈底到栈顶为：

```text
*, -, +
```

每次调用函数：

1. 从 S1 弹出 `a`；
2. 从 S1 弹出 `b`；
3. 从 S2 弹出 `op`；
4. 计算 `b op a`；
5. 结果重新压入 S1。

问连续执行 3 次后的栈顶值。

第一次：

$$
3+2=5
$$

S1 变成：

```text
5,8,5
```

第二次：

$$
8-5=3
$$

S1 变成：

```text
5,3
```

第三次：

$$
5\times3=15
$$

最终：

$$
\boxed{15}
$$

这一题不复杂，但很容易因为弹栈顺序出错。

### 7.5 中缀转后缀：为什么必须有运算符栈？

中缀表达式中存在：

- 运算符优先级；
- 括号；
- 左结合与右结合。

因此扫描到某个运算符时，可能不能马上输出它。

例如：

```text
a + b * c
```

读到 `+` 时，还不知道右边完整的操作数结构。

之后出现 `*`，就必须优先计算：

```text
b * c
```

所以：

```text
a + b * c
```

转换成：

```text
a b c * +
```

运算符栈正是用来保存暂时不能确定输出位置的运算符。

### 7.6 中缀转后缀的完整规则

从左到右扫描：

**遇到操作数：**&#x2060;直接输出。

**遇到左括号：**&#x2060;压入运算符栈。

**遇到右括号：**&#x2060;连续弹出并输出运算符，直到左括号；最后删除左括号，但不输出它。

遇到普通运算符：

先比较栈顶运算符与当前运算符的优先级和结合性。

对于左结合的 `+ - * /`，当栈顶优先级高于或等于当前运算符时，先弹出栈顶并输出。

处理完成后，再将当前运算符压栈。

**全部扫描结束：**&#x2060;弹出剩余运算符。

特别注意：

```text
a - b - c
```

由于减法是左结合的，应理解为：

$$
(a-b)-c
$$

后缀表达式：

```text
ab-c-
```

不是：

```text
abc--
```

后者对应：

$$
a-(b-c)
$$

如果涉及右结合运算符，例如通常数学表达式约定下的幂运算 `^`，则同优先级运算符的处理规则不同。

### 7.7 2014 年真题：判断运算符栈状态

中缀表达式：

```text
a/b+(c*d-e*f)/g
```

当扫描到 `f` 时，运算符栈中有什么？

按顺序模拟：

| 扫描阶段    | 运算符栈      |
| ------- | --------- |
| `a/`    | `/`       |
| 遇 `+`   | `+`       |
| 遇 `(`   | `+ (`     |
| 遇 `c*d` | `+ ( *`   |
| 遇 `-`   | `+ ( -`   |
| 遇 `e*`  | `+ ( - *` |
| 遇 `f`   | `+ ( - *` |

因此自栈底到栈顶为：

```text
+ ( - *
```

答案是：

$$
\boxed{\text{+、(、-、*}}
$$

为什么右括号不出现？

因为扫描到 `f` 时，还没有遇到右括号。

为什么之前的 `*` 已经消失？

因为读到减号时，必须先弹出优先级更高的乘号。

### 7.8 2024 年真题：中缀转后缀

题目：

$$
x+y\times(z-u)/v
$$

第一步，处理括号：

```text
z u -
```

第二步，乘以 y：

```text
y z u - *
```

第三步，除以 v：

```text
y z u - * v /
```

第四步，加上 x：

```text
x y z u - * v / +
```

最终：

$$
\boxed{\texttt{xyzu-*v/+}}
$$

原题答案为 A。

做这类题时可以先利用运算结构确定子表达式，再用栈算法检验。

### 7.9 表达式题的另一个考法：最大栈深

模拟题给出：

```text
a-(b*c+d/e)
```

要求在中缀转后缀过程中，运算符栈最多同时保存多少个元素。

运算符栈依次出现以下状态：

```text
-
- (
- ( *
- ( +
- ( + /
```

最大状态：

```text
- ( + /
```

共 4 个元素。

因此答案为：

$$
\boxed{4}
$$

这里左括号也占一个栈位置。

运算符栈的最大深度，不等于表达式中运算符的总数。

另外，后缀表达式的操作数栈最大深度是另一个问题，不能与中缀转后缀时的运算符栈深度混为一谈。

例如：

```text
A B C D - * - E +
```

前四个操作数连续入栈，操作数栈最大深度至少为 4。

如果题目限制操作数栈容量为 3，就会发生上溢。

### 7.10 栈和队列与 DFS、BFS、递归

| 场景      | 典型结构 | 原因           |
| ------- | ---- | ------------ |
| 函数调用    | 栈    | 最后进入的调用层最先返回 |
| 递归回溯    | 栈    | 保存待恢复的调用状态   |
| 括号匹配    | 栈    | 最近的未匹配括号先匹配  |
| 表达式求值   | 栈    | 暂存操作数或运算符    |
| DFS     | 栈    | 深入后再回退       |
| BFS     | 队列   | 按发现顺序逐层扩展    |
| 二叉树层序遍历 | 队列   | 先处理上一层的结点    |
| 打印缓冲    | 队列   | 先进入的数据先处理    |

#### 2015 年递归调用栈真题

程序：

```c
int s(int n) {
    return (n <= 0) ? 0 : s(n - 1) + n;
}

int main() {
    s(1);
}
```

调用过程：

```text
main()
  ↓
s(1)
  ↓
s(0)
```

最深时，栈底到栈顶保存的调用层次：

```text
main → s(1) → s(0)
```

这说明递归调用栈保存的是尚未完成的调用过程，而不是只保存最终计算结果。

### 7.11 2016 年真题：火车轨道与最长下降子序列

这是一道值得掌握的跨知识点应用题。

题目给出列车进入顺序：

$$
8,4,2,5,3,9,1,6,7
$$

要求最终按：

$$
1,2,\ldots,9
$$

的顺序驶出。

每条轨道上的列车只能从左向右运动，因此同一条轨道内，驶出顺序与进入该轨道的顺序相同。

那么每条轨道必须保存一个递增子序列。

问题转化为：

至少需要多少个递增子序列，才能覆盖原序列中的全部元素？

根据序列划分性质，答案等于原序列最长严格下降子序列的长度。

观察：

$$
8,4,2,1
$$

构成长度为 4 的下降子序列。

所以至少需要 4 条轨道。

另一方面，可以构造：

| 轨道 | 保存的列车   |
| -- | ------- |
| 1  | 8,9     |
| 2  | 4,5,6,7 |
| 3  | 2,3     |
| 4  | 1       |

每条轨道内均递增。

因此 4 条足够：

$$
\boxed{n_{\min}=4}
$$

这说明第 3 章的知识不仅用于栈和队列直接操作题，还可能转化为序列划分、贪心算法或动态规划问题。

## 八、数组：二维和多维地址计算

### 8.1 为什么二维数组也能用一个地址公式表示？

二维数组逻辑上有行和列，但存储器地址仍是一维连续的。

设：

```c
int A[R][C];
```

每个元素占 $B$ 字节，首地址为 $A_0$。

那么：

$$
\boxed{ Addr(A[i][j])=A_0+\text{offset}(i,j)\times B }
$$

关键就是求偏移量。

<Tabs items={['行优先存储', '列优先存储']} defaultIndex={0}>

<Tab value="行优先存储">

行优先意味着：

```text
A[0][0] A[0][1] A[0][2]
A[1][0] A[1][1] A[1][2]
```

实际存储：

```text
A00 A01 A02 A10 A11 A12
```

对于 `A[i][j]`：

- 前面有 $i$ 个完整的行；
- 每行有 $C$ 个元素；
- 当前行前面有 $j$ 个元素。

所以：

$$
\boxed{ Addr(A[i][j])=A_0+(iC+j)B }
$$

注意是列数 $C$，不是行数 $R$。

因为每跳过一行，需要跨过整行的元素数量。

</Tab>

<Tab value="列优先存储">

列优先意味着：

```text
A00 A10 A01 A11 A02 A12
```

对于 `A[i][j]`：

- 前面有 $j$ 个完整的列；
- 每列有 $R$ 个元素；
- 当前列前面有 $i$ 个元素。

因此：

$$
\boxed{ Addr(A[i][j])=A_0+(jR+i)B }
$$

行优先和列优先可以对照记忆：

| 存储方式 | 0 基偏移量     |
| ---- | ---------- |
| 行优先  | $iC+j$ |
| 列优先  | $jR+i$ |

但考试更推荐现场推导，而不是只记这个表。

</Tab>

</Tabs>

### 8.4 2021 年真题：由地址反推列数

题目：

已知二维数组按行优先存储，每个元素占一个存储单元。

$$
Addr(A[0][0])=100
$$

$$
Addr(A[3][3])=220
$$

求：

$$
Addr(A[5][5])
$$

设每行有 $C$ 个元素。

行优先地址公式：

$$
Addr(A[i][j])=100+iC+j
$$

代入已知条件：

$$
220=100+3C+3
$$

因此：

$$
3C=117
$$

$$
C=39
$$

继续求：

$$
Addr(A[5][5])=100+5\times39+5
$$

得到：

$$
\boxed{300}
$$

原题答案为 B。

这类题最常见的错误是把 `A[3][3]` 中的两个 3 都理解为维度大小。

实际上，一个表示行下标，一个表示列下标。

数组有多少列，是需要根据地址条件反推的未知量。

### 8.5 三维数组的地址计算

设：

$$
A[n_1][n_2][n_3]
$$

采用行优先存储，三维下标都从 0 开始。

则：

$$
\boxed{ \text{offset} =i_1n_2n_3+i_2n_3+i_3 }
$$

为什么？

固定第一维下标时，后面包含一个大小为：

$$
n_2n_3
$$

的二维子数组。

因此第一维每增加 1，就跨过：

$$
n_2n_3
$$

个元素。

第二维每增加 1，跨过：

$$
n_3
$$

个元素。

第三维每增加 1，只跨过 1 个元素。

例如：

```text
A[2][3][4]
```

求：

```text
A[1][2][3]
```

的行优先偏移量：

$$
1\times3\times4+2\times4+3
$$

$$
=12+8+3
$$

$$
\boxed{23}
$$

如果每个元素占 4 字节，则相对首地址偏移：

$$
23\times4=92\text{ 字节}
$$

### 8.6 多维数组统一公式

对于 $d$ 维数组：

$$
A[n_1][n_2]\cdots[n_d]
$$

行优先偏移量：

$$
\boxed{ \begin{aligned} \text{offset} ={}&i_1n_2n_3\cdots n_d\\ &+i_2n_3\cdots n_d\\ &+\cdots+i_{d-1}n_d+i_d \end{aligned} }
$$

它的规律是：

每一维下标，乘以后续所有维度大小的乘积。

列优先则相反，由前面的维度决定每一步的跨度。

## 九、特殊矩阵压缩存储：从公式理解到真题计算

### 9.1 压缩存储的共同思想

正常 $n\times n$ 矩阵需要：

$$
n^2
$$

个存储单元。

但是某些矩阵存在特殊规律：

- 对称矩阵有重复元素；
- 三角矩阵存在统一常量区域；
- 三对角矩阵只有少量对角线上的元素需要保存；
- 稀疏矩阵的非零元素很少。

因此可以只保存必要信息。

这类题的统一思路：

$$
\boxed{ \text{一维下标} = \text{前面完整存储的元素数} + \text{当前行或列内的偏移} }
$$

### 9.2 对称矩阵

如果：

$$
a_{ij}=a_{ji}
$$

那么只需要保存上三角或下三角。

一个 $n\times n$ 对称矩阵独立元素数量为：

$$
1+2+\cdots+n
$$

即：

$$
\boxed{\frac{n(n+1)}2}
$$

例如：

```text
a11 a12 a13 a14
a12 a22 a23 a24
a13 a23 a33 a34
a14 a24 a34 a44
```

只保存下三角：

```text
a11
a21 a22
a31 a32 a33
a41 a42 a43 a44
```

一共：

$$
1+2+3+4=10
$$

个元素，而不是 16 个。

### 9.3 下三角按行优先压缩

假设：

- 原矩阵使用 1 基下标；
- 压缩数组使用 0 基下标；
- 按行保存下三角。

则：

```text
第 1 行：1 个
第 2 行：2 个
第 3 行：3 个
...
第 i 行：i 个
```

对于：

$$
i\ge j
$$

第 $i$ 行之前存了：

$$
1+2+\cdots+(i-1) =\frac{i(i-1)}2
$$

个元素。

本行前面有：

$$
j-1
$$

个元素。

所以：

$$
\boxed{ k=\frac{i(i-1)}2+j-1 }
$$

如果要求上三角元素，也就是：

$$
i<j
$$

则先通过对称性：

$$
a_{ij}=a_{ji}
$$

交换下标，再计算。

### 9.4 上三角按行优先压缩

还是假设原矩阵 1 基、压缩数组 0 基。

对于：

$$
i\le j
$$

前面完整行的元素数为：

$$
n+(n-1)+\cdots+(n-i+2)
$$

所以：

$$
\boxed{ k= \frac{(i-1)(2n-i+2)}2+j-i }
$$

这个公式容易记错。

因此建议先计算每一行的起始位置。

例如 12 阶矩阵：

```text
第 1 行：12 个
第 2 行：11 个
第 3 行：10 个
第 4 行：9 个
...
```

这样往往比直接套公式更稳。

### 9.5 2018 年真题：上三角按行压缩

题目：

一个 $12\times12$ 对称矩阵，将上三角按行优先保存到从 0 开始的一维数组。

求：

$$
m_{6,6}
$$

对应的压缩数组下标。

由于保存上三角：

- 第 1 行存 12 个；
- 第 2 行存 11 个；
- 第 3 行存 10 个；
- 第 4 行存 9 个；
- 第 5 行存 8 个。

因此第 6 行之前已有：

$$
12+11+10+9+8=50
$$

个元素。

而 $m_{6,6}$ 是第 6 行保存的第一个元素。

所以：

$$
\boxed{k=50}
$$

原题答案为 A。

### 9.6 2020 年真题：上三角按列压缩

题目：

一个 $10\times10$ 对称矩阵，上三角元素按列优先压缩到 0 基数组。

求：

$$
m_{7,2}
$$

对应下标。

第一步，利用对称性：

$$
m_{7,2}=m_{2,7}
$$

第二步，由于上三角按列优先存储：

```text
第 1 列：1 个
第 2 列：2 个
第 3 列：3 个
...
第 7 列：7 个
```

第 7 列之前已有：

$$
1+2+\cdots+6=21
$$

个元素。

第三步，$m_{2,7}$ 位于第 7 列的第二个有效位置。

零基偏移量是 1。

所以：

$$
k=21+1
$$

$$
\boxed{k=22}
$$

原题答案为 C。

这一题同时考查了：

对称性、列优先存储、三角数求和、0 基和 1 基下标转换。

### 9.7 四种三角压缩公式汇总

统一约定：

- 矩阵下标从 1 开始；
- 压缩数组下标从 0 开始；
- 包含主对角线。

| 保存区域 | 存储顺序 | 一维下标 $k$                    |
| ---- | ---- | ------------------------------- |
| 下三角  | 行优先  | $\frac{i(i-1)}2+j-1$        |
| 上三角  | 行优先  | $\frac{(i-1)(2n-i+2)}2+j-i$ |
| 上三角  | 列优先  | $\frac{j(j-1)}2+i-1$        |
| 下三角  | 列优先  | $\frac{(j-1)(2n-j+2)}2+i-j$ |

上三角要求：

$$
i\le j
$$

下三角要求：

$$
i\ge j
$$

对于对称矩阵，不在存储区域内的元素先交换下标。

对于三角矩阵，不在存储区域内的元素如果属于统一常量区域，则不需要寻找独立存储位置。

四种公式是重点，但推导方法比记忆公式更重要。

### 9.8 三角矩阵

考虑上三角矩阵：

```text
a11 a12 a13 a14
 0  a22 a23 a24
 0   0  a33 a34
 0   0   0  a44
```

如果下三角全部为 0，则只需存储上三角。

存储单元数为：

$$
\boxed{\frac{n(n+1)}2}
$$

如果下三角全部为某个相同的常量 $c$，并且该常量需要额外保存，那么可以使用一个公共位置记录它。

总存储单元数为：

$$
\boxed{\frac{n(n+1)}2+1}
$$

这个额外位置记录的是所有相同的常量，而不是给每个位置分别分配空间。

### 9.9 三对角矩阵

三对角矩阵只保存满足：

$$
\boxed{|i-j|\le1}
$$

的元素。

例如：

```text
a11 a12  0   0   0
a21 a22 a23  0   0
 0  a32 a33 a34  0
 0   0  a43 a44 a45
 0   0   0  a54 a55
```

其有效存储元素数为：

- 主对角线：$n$ 个；
- 上方相邻对角线：$n-1$ 个；
- 下方相邻对角线：$n-1$ 个。

总数：

$$
n+(n-1)+(n-1)
$$

所以：

$$
\boxed{3n-2}
$$

当矩阵使用 1 基下标，压缩数组使用 0 基下标，并且按行优先保存时：

$$
\boxed{k=2i+j-3}
$$

其中：

$$
|i-j|\le1
$$

### 9.10 2016 年真题：100 阶三对角矩阵

题目：

100 阶三对角矩阵，按行优先压缩到 0 基数组。

求：

$$
m_{30,30}
$$

的下标。

方法一：直接代入公式。

$$
k=2\times30+30-3
$$

$$
\boxed{k=87}
$$

方法二：数元素。

第 1 行有 2 个元素。

第 2 行到第 29 行，共 28 行，每行有 3 个：

$$
28\times3=84
$$

所以第 30 行之前共有：

$$
2+84=86
$$

个元素。

第 30 行依次保存：

```text
m30,29
m30,30
m30,31
```

其中 $m_{30,30}$ 是第 2 个，零基行内偏移为 1。

因此：

$$
k=86+1=87
$$

原题答案为 B。

### 9.11 三对角矩阵的逆向定位

如果已经知道压缩数组下标 $k$，也可能要求反推出原矩阵下标。

在前面约定下：

$$
k=2i+j-3
$$

可以先得到：

$$
\boxed{ i=\left\lfloor\frac{k+1}{3}\right\rfloor+1 }
$$

再求：

$$
\boxed{j=k-2i+3}
$$

例如：

$$
k=87
$$

则：

$$
i=\left\lfloor\frac{88}{3}\right\rfloor+1 =29+1=30
$$

$$
j=87-60+3=30
$$

得到：

$$
\boxed{(i,j)=(30,30)}
$$

正好与前面的结果相互验证。

### 9.12 模拟强化：三维数组与二维对称压缩组合

另有一道综合题：

已知：

$$
A[10][10][10]
$$

前两维构成对称矩阵：

$$
A[i][j][k]=A[j][i][k]
$$

仅保存前两维的下三角部分，采用列优先存储；每个元素占 4 个存储单元。

已知：

$$
Addr(A[2][3][4])=3000
$$

求：

$$
Addr(A[5][5][5])
$$

按照题目预期的存储约定：

- 第一维下标变化最快；
- 第二维其次；
- 第三维最慢；
- 每个固定第三维下标对应一个独立压缩的二维对称矩阵。

第一步，利用对称性：

$$
A[2][3][4]=A[3][2][4]
$$

第二步，每个二维压缩层存储：

$$
\frac{10\times11}{2}=55
$$

个元素。

第三步，对于下三角按列优先存储的 0 基下标：

$$
f(i,j)=\frac{j(2n-j+1)}2+i-j
$$

计算：

$$
f(3,2)=20
$$

$$
f(5,5)=40
$$

第三维从 4 变为 5，需要跨越完整的 55 个压缩元素。

再加上二维层内偏移差：

$$
40-20=20
$$

总偏移：

$$
55+20=75
$$

乘以每个元素的存储大小：

$$
75\times4=300
$$

因此：

$$
Addr(A[5][5][5])=3000+300
$$

最终：

$$
\boxed{3300}
$$

这道题最值得学习的地方是：

多维数组与特殊矩阵压缩存储可以联合考查，不能先用普通未压缩的二维数组大小计算。

## 十、稀疏矩阵：三元组表与十字链表

### 10.1 什么是稀疏矩阵？

假设一个矩阵有：

$$
1000\times1000
$$

个元素。

总位置数：

$$
10^6
$$

但实际只有 1000 个非零元素。

那么绝大多数存储位置都保存 0。

这时可以只存储非零元素及其位置。

注意，稀疏矩阵并没有要求非零元素必须集中在某条对角线或某个三角区域。

所以它不像三对角矩阵那样可以直接使用固定的下标公式。

### 10.2 三元组表

每个非零元素保存三个信息：

```text
(row, col, value)
```

例如：

```text
0  0  7  0
0  5  0  0
0  0  0  9
```

三元组为：

```text
(0,2,7)
(1,1,5)
(2,3,9)
```

因此三元组表可以表示为：

```c
typedef struct {
    int row;
    int col;
    int value;
} Triple;
```

假设矩阵共有 $t$ 个非零元素。

主体存储空间与 $t$ 成正比：

$$
\boxed{O(t)}
$$

但还需要保存矩阵的整体信息，例如：

```text
rows
cols
nums
```

分别表示：

- 矩阵总行数；
- 矩阵总列数；
- 非零元素个数。

### 10.3 2023 年真题：三元组表还需要保存什么？

题目问：

若使用三元组表保存稀疏矩阵，除三元组表外，还需要保存：

I. 总行数

II. 包含非零元素的行数

III. 总列数

IV. 包含非零元素的列数

答案：

$$
\boxed{\text{I、III}}
$$

也就是矩阵总行数与总列数。

为什么？

三元组记录的只是实际非零元素的位置和值。

例如：

```text
(1,2,5)
(3,4,7)
```

并不能唯一确定原矩阵是：

```text
4×5
```

还是：

```text
100×100
```

因为其余位置完全可以全部为零。

因此需要保存总行数、总列数。

而包含非零元素的行数和列数，可以通过统计三元组得到，并非恢复矩阵规模所必需。

### 10.4 模拟题：三元组表空间计算

一个：

$$
1000\times850
$$

的稀疏矩阵有 1000 个非零元素。

每个整数占 2B，每个矩阵元素值占 4B。

求三元组记录所需空间。

每个三元组包含：

| 字段  | 字节 |
| --- | -- |
| 行号  | 2B |
| 列号  | 2B |
| 元素值 | 4B |

合计：

$$
2+2+4=8\text{B}
$$

1000 个非零元素：

$$
1000\times8
$$

得到：

$$
\boxed{8000\text{B}}
$$

注意题目按标准答案只统计三元组记录，不额外计入表头、内存对齐以及动态数组剩余容量。

如果要求整个数据结构实际占用的字节数，还需要按题目给定的实现细节增加相应开销。

### 10.5 三元组表为什么不能保证 $O(1)$ 随机访问？

普通二维数组要访问：

```text
A[i][j]
```

可以通过地址公式直接定位。

时间复杂度：

$$
O(1)
$$

但是三元组表只保存非零元素。

假如要查询：

```text
A[500][600]
```

必须先判断是否存在对应的三元组。

如果逐项扫描：

$$
O(t)
$$

如果三元组已经按行、列有序排列，可以使用二分查找等方式降低查询复杂度，但仍不能一般性地直接当作 $O(1)$ 数组访问。

因此：

压缩存储节省空间，不代表任意元素访问也一定更快。

### 10.6 十字链表

十字链表让每个非零元素同时位于：

- 一条行链表；
- 一条列链表。

结点结构可以表示为：

```c
typedef struct OLNode {
    int row;
    int col;
    int value;

    struct OLNode *right;
    struct OLNode *down;
} OLNode;
```

其中：

```text
right → 同行下一个非零结点
down  → 同列下一个非零结点
```

还需要：

```text
rhead[] → 每一行的链表入口
chead[] → 每一列的链表入口
```

十字链表特别适合：

- 按行遍历；
- 按列遍历；
- 动态插入非零元素；
- 动态删除非零元素。

### 10.7 2017 年真题：稀疏矩阵压缩结构

题目：

适用于压缩存储稀疏矩阵的两种存储结构是什么？

答案：

$$
\boxed{\text{三元组表和十字链表}}
$$

要区分：

- 三元组表：结构简单，适合保存较稳定的非零元素集合。
- 十字链表：行列双向组织，适合动态变化较多的稀疏矩阵。

## 十一、进一步掌握本章算法设计套路

这部分把本章的知识转化为可以用于 408 算法设计题的模型。

### 11.1 用两个栈实现一个队列

使用：

```text
S_in
S_out
```

入队时：

```text
Push(S_in, x);
```

出队时：

如果 `S_out` 非空，直接弹出。

如果 `S_out` 为空，就把 `S_in` 的所有元素依次弹出并压入 `S_out`，再从 `S_out` 弹出一个元素。

例如：

```text
入队：1 2 3
```

先保存在 `S_in`：

```text
栈顶 → 3
       2
       1
```

转移到 `S_out` 后：

```text
栈顶 → 1
       2
       3
```

于是依次弹出：

```text
1 → 2 → 3
```

实现了 FIFO。

单次出队在需要转移时可能花费：

$$
O(n)
$$

但每个元素最多经历：

- 入 `S_in`；
- 从 `S_in` 出；
- 入 `S_out`；
- 从 `S_out` 出。

所以每个元素总共只被操作常数次。

对于一系列入队、出队操作，平均到每次操作的摊还时间复杂度为：

$$
\boxed{O(1)}
$$

注意这里是摊还复杂度，不代表每一次出队的最坏时间都为 $O(1)$。

### 11.2 用一个队列实现一个栈

可以在每次入栈时调整队列内部顺序。

例如原队列为：

```text
3 → 2 → 1
```

其中队头是 3，代表当前栈顶。

现在希望压入 4。

先将 4 入队：

```text
3 → 2 → 1 → 4
```

然后把此前的 3 个元素依次出队并重新入队：

```text
4 → 3 → 2 → 1
```

此时队头为 4。

所以：

```text
PopStack()
```

就可以通过队头出队实现。

在队列基本操作为 $O(1)$ 的前提下：

- 这种实现的入栈为 $O(n)$；
- 出栈为 $O(1)$。

也可以采用入栈 $O(1)$、出栈 $O(n)$ 的实现方案。

关键是通过队列循环调整元素相对位置。

### 11.3 共享空间与结点复用

2019 年队列真题还可以进一步推广。

如果有两个队列：

```text
Q1
Q2
```

都需要重复利用出队后释放的逻辑空间，可以维护：

```text
freeList
```

作为共享空闲结点池。

出队时：

```text
有效队列 → freeList
```

入队时：

```text
先检查 freeList
有空闲结点 → 直接取出
没有空闲结点 → malloc
```

只要空闲链表可以从表头常数时间插入、删除，每次操作仍然可以做到：

$$
O(1)
$$

这里最重要的是维护一个不变量：

每个物理结点只能属于某个有效队列或空闲结点池，不能同时属于多个结构。

这是链式结构设计与正确性证明中的常见思路。

| 链栈出栈   | 只修改 `top` 即可              | 动态分配结点还要适当释放         |
| 普通队列   | 能删除队尾                     | 只能从队头删除              |
| 循环队列容量 | 长度为 $m$ 就能存 $m$ 个 | 牺牲一格时只能存 $m-1$ 个 |
| 循环队列队长 | 永远是 `rear-front`          | 绕回时需要取模              |
| 链式队列   | 删除最后一个结点后不用管尾指针           | 要维护正确的空队列状态          |
| 两栈实现队列 | 每次出队都是最坏 $O(1)$       | 典型实现为摊还 $O(1)$   |
| 中缀转后缀  | 只要比较优先级                   | 还要考虑结合性              |
| 后缀求值   | 第一次弹出的数是左操作数              | 二元运算通常第一次弹出右操作数      |
| 表达式栈深  | 等于运算符数量                   | 必须逐步模拟               |
| 卡特兰数   | 所有受限排列都可以直接套              | 必须满足相应模型条件           |
| 数组地址   | 行优先用行数相乘                  | 行优先跨过的是完整的列数         |
| 对称矩阵   | 任意一边都直接计算                 | 先判断实际保存的三角区域         |
| 三对角矩阵  | 有 $3n$ 个有效元素          | 实际为 $3n-2$       |
| 稀疏矩阵   | 只需保存非零值                   | 还要保存非零元素的位置          |
| 三元组表   | 任意访问都是 $O(1)$         | 一般需要搜索               |

</Accordion>

## 十三、考前综合训练：10 道典型题

以下是基于本章考法整理的训练题，主要用于检查是否真正理解公式和算法。

### 题目

第 1 题：顺序栈

一个顺序栈容量为 20，`top` 指向当前栈顶元素。

当前：

```text
top=7
```

栈中有多少个元素？还可以再压入多少个元素？

第 2 题：共享栈

共享数组长度为 12。

两个栈的指针分别指向各自下一个可用位置，初始：

```text
top1=0
top2=11
```

如果：

```text
top1=6
top2=6
```

此时栈满了吗？

第 3 题：合法出栈序列

入栈顺序：

```text
1,2,3,4,5
```

判断：

```text
3,2,5,4,1
```

是否合法。

第 4 题：卡特兰数

固定 5 个元素的入栈顺序。

不限制容量时，合法出栈序列共有多少个？

第 5 题：循环队列

数组长度为 10。

采用牺牲一格方案，`front` 指向队头，`rear` 指向下一插入位置。

已知：

```text
front=8
rear=3
```

求当前队长。

第 6 题：队满判断

仍使用长度为 10 的循环队列。

已知：

```text
front=4
rear=3
```

问是否队满。

第 7 题：后缀表达式

计算：

```text
8 2 / 3 4 + *
```

第 8 题：二维数组

一个二维数组 `A[10][20]`，行优先存储，首地址为 1000，每个元素占 4B。

求：

```text
A[3][5]
```

的首地址。

第 9 题：对称矩阵

一个 $8\times8$ 对称矩阵，按下三角行优先压缩。

矩阵下标从 1 开始，压缩数组下标从 0 开始。

求：

$$
a_{3,6}
$$

的存储下标。

第 10 题：三对角矩阵

一个 50 阶三对角矩阵，按行优先压缩。

矩阵 1 基、压缩数组 0 基。

求：

$$
a_{20,21}
$$

的压缩下标。

### 答案与解析

| 题号 | 答案          | 关键计算                                          |
| -- | ----------- | --------------------------------------------- |
| 1  | 8 个，剩余 12 格 | $L=top+1=8$                               |
| 2  | 未满          | `top1==top2`，还剩一个空位                           |
| 3  | 合法          | 入 1,2,3，出 3,2；入 4,5，出 5,4,1                   |
| 4  | 42          | $C_5=42$                                  |
| 5  | 5           | $(3-8+10)\bmod10=5$                       |
| 6  | 已满          | $(3+1)\bmod10=4$                          |
| 7  | 28          | $(8/2)\times(3+4)=28$                     |
| 8  | 1260        | $1000+(3\times20+5)\times4$               |

## 十四、408 第 3 章最终复习方法

学完本章后，建议用以下标准检查自己是否真正掌握，而不只是记住答案。

### 第一层：基础概念

需要做到：

- 能说清栈与队列的操作限制。
- 能区分顺序栈、链栈、顺序队列、循环队列、链式队列。
- 理解共享栈为什么能够提高空间利用率。
- 理解 DFS、BFS、递归及括号匹配为什么使用不同辅助结构。

### 第二层：公式推导

不看答案也应能推导出：

$$
\text{循环队列长度}=(rear-front+m)\bmod m
$$

$$
\text{循环队列满}\iff(rear+1)\bmod m=front
$$

$$
\text{行优先偏移}=iC+j
$$

$$
\text{对称矩阵独立元素数}=\frac{n(n+1)}2
$$

$$
\text{三对角矩阵有效元素数}=3n-2
$$

$$
\text{合法出栈序列数}=C_n
$$

但所有公式都必须带着相应的指针、下标和模型前提使用。

### 第三层：过程模拟

应该能够独立完成：

- 给定操作序列，画出栈和队列每一步的状态。

针对综合应用题，至少应该做到：

1. 明确结构与指针含义。
2. 给出初始化及边界条件。
3. 写出完整算法。
4. 解释关键操作为什么正确。

## 十五、全章核心结论

### 全章最重要的五句话

1. 栈题： 每次只能从栈顶出栈，判断序列时按固定输入顺序模拟。
2. 队列题： 先定义 `front/rear`，再推导判空、判满和长度，绝不能脱离指针含义套公式。
3. 表达式题： 运算符优先级、结合性和弹栈顺序必须同时考虑。
4. 矩阵题： 先确认下标起点、存储区域与行列顺序，再数目标元素之前已有多少元素。
5. 算法大题： 不仅要写出能运行的代码，更要说明边界条件、数据结构不变量和复杂度。

本章复习的核心顺序是：先理解存储结构与操作约束，再掌握状态模拟与公式推导，最后用 2019、2026 年的大题训练完整的算法设计和数学证明。
