### 2. 理解所有查找算法的一条主线

以查找关键字 35 为例：

- 顺序查找： 逐个检查，可能检查全部元素。
- 折半查找： 利用有序性，每次排除约一半元素。
- BST： 利用左小右大的结构，只走一条搜索路径。
- AVL： 在 BST 基础上保持高度平衡，防止退化。
- 红黑树： 用颜色规则限制高度，兼顾动态插删。
- B 树： 一个结点存储多个关键字，减少树的层数。
- B+ 树： 将实际数据集中在叶层，方便单点定位和范围扫描。
- 散列表： 通过散列函数直接计算候选地址，再处理冲突。

这些方法的差异，本质上来自三个问题：

1. 数据具有什么性质？ 例如有序性、哈希映射、树的平衡性。
2. 如何利用性质排除不可能的结果？
3. 为了维护这种性质，插入和删除需要付出什么代价？

理解这三个问题，比单纯背复杂度更重要。

## 二、查找的基本概念与 ASL

这是整章计算题的基础。

### 2.1 什么是查找表？

查找表是由同一类型的数据元素构成的集合。

例如：

```text
学生记录：
<学号, 姓名, 成绩>

1001 张三 85
1002 李四 90
1003 王五 78
```

如果通过学号查询学生信息，那么学号就是查找关键字。

按操作特点，可以区分：

| 类型    | 特点           | 适合的结构               |
| ----- | ------------ | ------------------- |
| 静态查找表 | 主要进行查询       | 有序数组、折半查找           |
| 动态查找表 | 查询之外还频繁插入、删除 | BST、AVL、红黑树、B 树、散列表 |

注意，静态与动态描述的是允许进行的操作，而不直接规定物理存储结构。

### 2.2 平均查找长度 ASL

ASL 是 Average Search Length 的缩写。

它表示：

在某种查找概率分布下，完成一次查找平均需要多少次关键操作。

计算公式：

$$
\boxed{ASL=\sum_{i=1}^{n}P_iC_i}
$$

其中：

- $P_i$：第 $i$ 种查找情况发生的概率。
- $C_i$：该情况下的查找长度。

如果所有情况等概率：

$$
\boxed{ASL=\frac{C_1+C_2+\cdots+C_n}{n}}
$$

例如，四个关键字的成功查找次数分别为：

$$
1,\ 2,\ 3,\ 4
$$

等概率时：

$$
ASL=\frac{1+2+3+4}{4}=2.5
$$

但是，如果它们的查找概率分别为：

$$
0.4,\ 0.3,\ 0.2,\ 0.1
$$

则：

$$
ASL=0.4\times1+0.3\times2+0.2\times3+0.1\times4
$$

$$
\boxed{ASL=2}
$$

这说明，ASL 不仅与算法有关，还与关键字的查找概率有关。

### 2.3 成功 ASL 与失败 ASL

这是本章最容易失分的地方。

成功 ASL： 在关键字存在的条件下，统计找到它所需的平均代价。

失败 ASL： 在关键字不存在的条件下，统计确认它不存在所需的平均代价。

二者的平均对象不同。

| 查找方式 | 成功 ASL 的平均对象 | 失败 ASL 的平均对象   |
| ---- | ------------ | -------------- |
| 顺序查找 | 已存关键字        | 题设规定的失败情况      |
| 折半查找 | 判定树成功结点      | 失败区间           |
| BST  | 已存结点         | 失败搜索路径         |
| 散列表  | 已存关键字        | 可能的失败散列初址或查询情况 |

必须先确认“查找长度”数什么。

例如，开放定址散列表通常统计探测槽位次数。即使最后探测到的是空槽，这次探测也需要计入失败长度。

## 三、顺序查找

### 3.1 基本算法

顺序查找就是从一端开始逐个比较。

```c
int SequentialSearch(int A[], int n, int key) {
    for (int i = 0; i < n; i++) {
        if (A[i] == key)
            return i;
    }
    return -1;
}
```

特点：

- 不要求关键字有序。
- 顺序表、链表都能使用。
- 实现简单。
- 最坏情况下需要检查整个表。

时间复杂度：

$$
T_{\text{best}}=O(1)
$$

$$
T_{\text{worst}}=O(n)
$$

$$
T_{\text{average}}=O(n)
$$

### 3.2 顺序查找成功 ASL

假设有 $n$ 个元素，所有元素被查询的概率相等。

第一个元素需要比较 1 次。

第二个元素需要比较 2 次。

依此类推，最后一个元素需要比较 $n$ 次。

因此：

$$
ASL_{\text{成功}} =\frac{1+2+\cdots+n}{n}
$$

利用等差数列求和：

$$
1+2+\cdots+n=\frac{n(n+1)}2
$$

得到：

$$
\boxed{ASL_{\text{成功}}=\frac{n+1}{2}}
$$

这道公式必须熟记。

例如有 100 个元素：

$$
ASL=\frac{101}{2}=50.5
$$

### 3.3 顺序查找失败 ASL

对于普通无哨兵顺序查找，若关键字不存在，必须检查全部 $n$ 个元素。

因此：

$$
\boxed{ASL_{\text{失败}}=n}
$$

但这不是对所有顺序查找实现都成立。

### 3.4 带哨兵的顺序查找

经典教材中会把关键字放在数组的额外位置，作为哨兵。

假设数组采用从 1 开始的下标：

```c
int SearchSeq(int A[], int n, int key) {
    A[0] = key;

    int i = n;
    while (A[i] != key)
        i--;

    return i;
}
```

这样不需要每轮检查数组是否越界。

但注意：

如果查找失败，最后仍要比较到哨兵 `A[0]`。

若把这一次也计入关键字比较，则：

$$
\boxed{ASL_{\text{失败}}=n+1}
$$

所以：

普通顺序查找失败为 $n$ 次，经典哨兵法计入哨兵比较时为 $n+1$ 次。

考试必须按照题目给出的算法和统计口径判断。

### 3.5 有序顺序查找

假设：

```text
10 20 30 40 50
```

要查找 25。

从左向右比较：

```text
10 < 25
20 < 25
30 > 25
```

遇到 30 后可以立即失败，因为后面的关键字只会更大。

这种方法可以减少部分失败查找的比较次数，但最坏时间复杂度仍为：

$$
O(n)
$$

另外，有序顺序查找失败 ASL 需要根据不同失败区间的查找长度与概率计算，不能一律套 $n$。

## 四、折半查找——本章重点

折半查找又称二分查找。

核心思想：

通过关键字有序性，每次排除大约一半候选元素。

### 4.1 使用前提

必须满足：

1. 关键字按照一定顺序排列。
2. 能够高效访问中间位置。

因此：

| 数据结构   | 是否适合标准折半查找    |
| ------ | ------------- |
| 有序数组   | 适合            |
| 无序数组   | 不适合           |
| 有序单链表  | 不适合直接实现高效折半   |
| 无序单链表  | 不适合           |
| 有序静态链表 | 通常不适合直接实现高效折半 |

为什么有序链表不适合？

因为数组可以通过下标在 $O(1)$ 时间定位中间元素，而普通链表需要沿指针移动。

因此，有序链表虽然具有有序性，但无法直接获得数组折半查找的高效随机访问能力。

### 4.2 折半查找算法

```c
int BinarySearch(int A[], int n, int key) {
    int low = 0;
    int high = n - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;

        if (A[mid] == key)
            return mid;

        if (A[mid] < key)
            low = mid + 1;
        else
            high = mid - 1;
    }

    return -1;
}
```

关键是三个下标：

$$
low,\quad mid,\quad high
$$

中间位置：

$$
mid=\left\lfloor\frac{low+high}{2}\right\rfloor
$$

程序中建议写成：

```text
mid = low + (high - low) / 2;
```

避免直接相加可能发生的整数溢出。

### 4.3 手工模拟折半查找

考虑有序数组：

```text
下标： 1  2  3  4  5  6  7
元素：10 20 30 40 50 60 70
```

查找 60。

第一次：

$$
mid=\left\lfloor\frac{1+7}{2}\right\rfloor=4
$$

比较 40。

因为：

$$
60>40
$$

因此进入右半区：

```text
50 60 70
```

第二次：

$$
mid=\left\lfloor\frac{5+7}{2}\right\rfloor=6
$$

比较 60，查找成功。

所以：

$$
\boxed{\text{比较次数}=2}
$$

### 4.4 折半查找判定树

折半查找可以表示成一棵判定树。

对于：

```text
10 20 30 40 50 60 70
```

判定树如下：

```text
            40
          /    \
        20      60
       /  \    /  \
     10   30  50  70
```

结点所在层数就是成功查找时的关键字比较次数。

| 关键字         | 层数 | 成功比较次数 |
| ----------- | -- | ------ |
| 40          | 1  | 1      |
| 20、60       | 2  | 2      |
| 10、30、50、70 | 3  | 3      |

因此成功 ASL：

$$
ASL_{\text{成功}} =\frac{1+2\times2+4\times3}{7}
$$

$$
\boxed{ASL_{\text{成功}}=\frac{17}{7}}
$$

### 4.5 判定树的重要性质

折半查找判定树是按区间中点递归划分得到的，因此任意结点的左右子树结点数相差不超过 1。

但是：

它并不一定是完全二叉树。

特别是在偶数长度区间中，选择左中点或右中点可能形成不同树形。

例如：

```text
10 20 30 40 50 60
```

若每次取下中点，根为 30。

若每次取上中点，根为 40。

两种方法都可以实现折半查找，但判定树形状不同。

考试必须服从题目规定的 `mid` 计算规则。

### 4.6 折半查找最坏比较次数

对于 $n\ge1$ 个元素：

$$
\boxed{C_{\max}=\lfloor\log_2n\rfloor+1}
$$

等价于：

$$
\boxed{C_{\max}=\lceil\log_2(n+1)\rceil}
$$

因此最坏时间复杂度：

$$
\boxed{O(\log n)}
$$

#### 历年真题：2010 年

题目：长度为 16 的有序顺序表，采用折半查找查找不存在的元素，最多进行多少次关键字比较？

$$
C_{\max}=\lfloor\log_2 16\rfloor+1
$$

$$
=4+1=5
$$

答案：5 次，选 B。

#### 历年真题：2023 年

题目：600 个元素的有序顺序表，折半查找最多比较多少次？

因为：

$$
2^9=512<600<1024=2^{10}
$$

所以：

$$
\boxed{C_{\max}=10}
$$

答案：B。

这类题无需真正画出整棵判定树。

### 4.7 折半查找失败 ASL

这是比成功 ASL 更容易出错的考点。

对于 $n$ 个互异关键字，有：

$$
\boxed{n+1\text{ 个失败区间}}
$$

例如：

```text
10 20 30
```

查找失败可能落在：

```text
(-∞,10)
(10,20)
(20,30)
(30,+∞)
```

共有 4 个区间。

注意：

失败区间不是已经存储的关键字，而是查找最终结束的区间。

对于前面的 7 个元素：

```text
            40
          /    \
        20      60
       /  \    /  \
     10   30  50  70
```

恰好是一棵 3 层满二叉判定树。

所有失败搜索都需要比较 3 个实际关键字，之后才到达空区间。

因此：

$$
\boxed{ASL_{\text{失败}}=3}
$$

不能因为补画了外部失败结点，就把失败比较次数误算为 4。

外部结点只是表示查找失败的位置，不意味着又进行了一次关键字比较。

### 4.8 历年真题：2015 年折半查找路径

题目要求判断下列哪个序列不可能是折半查找的比较序列：

A. 500，200，450，180

B. 500，450，200，180

C. 180，500，200，450

D. 180，200，500，450

答案：A。

分析 A：

首先比较 500，说明目标小于 500。

然后比较 200，说明目标大于 200。

因此目标位于：

$$
200<x<500
$$

接着比较 450，说明：

$$
200<x<450
$$

下一次却比较 180。

显然：

$$
180<200
$$

它已经不在允许区间中。

所以不可能出现这样的比较路径。

这类题的核心方法是不断维护上下界，而不是死记某一种判定树形状。

### 4.9 模拟题：12 个元素的成功 ASL

模拟题给出：

长度为 12 的有序顺序表，各元素等概率，求折半查找成功 ASL。

反复选取中点，可以得到判定树各层结点数：

$$
1,\ 2,\ 4,\ 5
$$

因此：

$$
ASL=\frac{1\times1+2\times2+4\times3+5\times4}{12}
$$

$$
=\frac{1+4+12+20}{12}
$$

$$
\boxed{ASL=\frac{37}{12}}
$$

答案：C。

这类题应优先统计每一层有几个结点，而不是逐个关键字重新模拟查找。

## 五、分块查找

分块查找又称索引顺序查找。

它结合了索引检索与块内顺序查找。

### 5.1 基本思想

将元素划分成若干块。

例如：

```text
块1： 3  8  1  6
块2：18 12 15 20
块3：25 30 27 35
```

虽然块内不完全有序，但满足：

```text
块1所有元素 < 块2所有元素 < 块3所有元素
```

建立索引：

| 块号 | 最大关键字 |
| -- | ----- |
| 1  | 8     |
| 2  | 20    |
| 3  | 35    |

查找 27 时：

第一步：通过索引确定它属于第 3 块。

第二步：在第 3 块内顺序查找。

因此：

$$
\boxed{ASL=ASL_{\text{索引}}+ASL_{\text{块内}}}
$$

### 5.2 最优块长

假设总共有 $n$ 个元素，每块有 $s$ 个元素。

块数为：

$$
b=\frac ns
$$

若索引表采用顺序查找，且各元素等概率、块长相同，则：

$$
ASL_{\text{索引}}=\frac{b+1}{2}
$$

块内成功 ASL：

$$
ASL_{\text{块内}}=\frac{s+1}{2}
$$

于是：

$$
ASL=\frac{b+1}{2}+\frac{s+1}{2}
$$

代入 $b=n/s$：

$$
ASL=\frac{n/s+s}{2}+1
$$

利用基本不等式：

$$
\frac ns+s\ge2\sqrt n
$$

当：

$$
s=\sqrt n
$$

时取最小值。

因此：

$$
\boxed{s_{\text{opt}}\approx\sqrt n}
$$

#### 例题

有 144 个元素，采用等长分块，索引和块内均使用顺序查找。

理论最优块长为：

$$
s=\sqrt{144}=12
$$

共 12 块。

成功 ASL：

$$
ASL=\frac{12+1}{2}+\frac{12+1}{2}
$$

$$
\boxed{ASL=13}
$$

重要：只有在索引顺序查找、块内顺序查找等前提下，才能直接使用最优块长约为 $\sqrt n$ 的结论。

如果索引改为折半查找，复杂度模型变成：

$$
O(\log b+s)
$$

最优块长就不能继续机械地套 $\sqrt n$。

## 六、二叉搜索树 BST

BST 是 Binary Search Tree 的缩写，也叫二叉排序树。

这是树形查找的基础。

### 6.1 BST 的定义

对于任意结点：

$$
\boxed{\text{左子树关键字}<\text{根关键字}<\text{右子树关键字}}
$$

并且左右子树也必须分别是 BST。

例如：

```text
           50
         /    \
       30      70
      /  \    /  \
    20   40  60  80
```

它是一棵合法的 BST。

注意，BST 要求的是：

整个左子树的所有关键字都小于根，不仅仅是左孩子小于根。

例如：

```text
       40
      /  \
     20   60
       \
        50
```

虽然 50 大于它的双亲 20，但它位于 40 的左子树中。

因此必须满足：

$$
50<40
$$

显然不成立，所以不是 BST。

### 6.2 BST 的中序遍历

对于关键字互异的 BST：

$$
\boxed{\text{中序遍历序列严格递增}}
$$

例如上面的 BST：

```text
20 30 40 50 60 70 80
```

这是判断 BST 是否正确的常用方法。

反过来，对于关键字互异的二叉树，只要其中序遍历严格递增，也可以判定它是 BST。

### 6.3 BST 查找

假设查找 60：

```text
50
 ↓
70
 ↓
60
```

因为：

$$
60>50
$$

进入右子树。

然后：

$$
60<70
$$

进入左子树，找到 60。

C 语言：

```c
typedef struct BSTNode {
    int key;
    struct BSTNode *left, *right;
} BSTNode;

BSTNode *SearchBST(BSTNode *root, int key) {
    while (root != NULL) {
        if (root->key == key)
            return root;

        if (key < root->key)
            root = root->left;
        else
            root = root->right;
    }
    return NULL;
}
```

查找复杂度取决于树高 $h$：

$$
\boxed{T(n)=O(h)}
$$

平衡时：

$$
O(\log n)
$$

最坏退化时：

$$
O(n)
$$

### 6.4 BST 为什么可能退化？

假设依次插入：

```text
10 20 30 40 50
```

得到：

```text
10
  \
   20
     \
      30
        \
         40
           \
            50
```

这棵 BST 实际上已经接近链表。

因此，即使数据结构名字中含有 Tree，也不意味着查找一定是对数复杂度。

普通 BST 不保证平衡。

### 6.5 BST 插入

插入过程与查找类似。

例如：

```text
           50
         /    \
       30      70
      /  \    /  \
    20   40  60  80
```

插入 65：

```text
50 → 70 → 60
```

因为：

$$
65>60
$$

所以 65 插入为 60 的右孩子。

最终：

```text
           50
         /    \
       30      70
      /  \    /  \
    20   40  60  80
               \
                65
```

结论：

普通 BST 新结点通常插入在查找失败的位置。

### 6.6 BST 删除——重点

删除分三种情况。

#### 情况一：删除叶结点

```text
      50
     /  \
    30   70
   /
  20
```

删除 20：

直接删除即可。

#### 情况二：删除只有一个孩子的结点

```text
      50
     /  \
    30   70
      \
       40
```

删除 30：

让 40 直接成为 50 的左孩子。

```text
      50
     /  \
    40   70
```

#### 情况三：删除有两个孩子的结点

这是重点。

例如：

```text
           50
         /    \
       30      70
      /  \    /  \
    20   40  60  80
```

删除 50。

有两种常用方法：

方法一：中序前驱替换。

50 的中序前驱是其左子树最大值 40。

用 40 替换根，再删除原来的 40。

方法二：中序后继替换。

50 的中序后继是其右子树最小值 60。

用 60 替换根，再删除原来的 60。

结果：

```text
           60
         /    \
       30      70
      /  \       \
    20   40       80
```

记忆：

$$
\boxed{\text{前驱}=\text{左子树最大值}}
$$

$$
\boxed{\text{后继}=\text{右子树最小值}}
$$

如果题目明确要求用中序后继，就必须使用中序后继。

历年真题与模拟题非常喜欢考这个知识点。

### 6.8 模拟题：BST 前序序列是否合法？

模拟题给出：

A. `4,2,3,5,6,7`

B. `4,3,2,7,6,5`

C. `6,5,4,2,3,7`

D. `6,5,3,4,2,7`

问：哪个不可能是 BST 的前序遍历？

答案：D。

分析 D：

第一个关键字 6 是根。

5、3 都小于 6，属于左子树。

进入 3 后，出现 4，说明遍历已经进入 3 的右子树。

但后面又出现 2。

由于：

$$
2<3
$$

它应该属于 3 的左子树。

而前序遍历已经进入右子树，不可能再回到原来的左子树。

所以 D 不合法。

## 七、AVL 平衡二叉树——四种旋转必须熟练

普通 BST 可能退化。

AVL 通过旋转维护平衡，从而保证树高为：

$$
O(\log n)
$$

### 7.1 AVL 的定义

AVL 首先必须是一棵 BST。

同时，任意结点满足：

$$
\boxed{|h_L-h_R|\le1}
$$

定义平衡因子：

$$
\boxed{BF=h_L-h_R}
$$

因此合法 AVL 结点的平衡因子只能是：

$$
\boxed{BF\in\{-1,0,1\}}
$$

| 平衡因子   | 含义         |
| ------ | ---------- |
| 1      | 左子树比右子树高 1 |
| 0      | 左右子树等高     |
| -1     | 右子树比左子树高 1 |
| 2 或 -2 | 结点失衡，需要调整  |

### 7.2 四种旋转

| 类型 | 失衡路径      | 调整方式   |
| -- | --------- | ------ |
| LL | 左孩子的左子树增高 | 右旋     |
| RR | 右孩子的右子树增高 | 左旋     |
| LR | 左孩子的右子树增高 | 先左旋再右旋 |
| RL | 右孩子的左子树增高 | 先右旋再左旋 |

LL、RR 表示失衡路径，不是旋转方向。

### 7.3 LL 型

依次插入：

```text
30 20 10
```

得到：

```text
      30
     /
    20
   /
  10
```

结点 30 的左子树过高。

对 30 右旋：

```text
      20
     /  \
    10   30
```

### 7.4 RR 型

依次插入：

```text
10 20 30
```

得到：

```text
10
  \
   20
     \
      30
```

对 10 左旋：

```text
      20
     /  \
    10   30
```

### 7.5 LR 型

依次插入：

```text
30 10 20
```

得到：

```text
      30
     /
    10
      \
       20
```

先对 10 左旋：

```text
      30
     /
    20
   /
  10
```

再对 30 右旋：

```text
      20
     /  \
    10   30
```

### 7.6 RL 型

依次插入：

```text
10 30 20
```

得到：

```text
10
  \
   30
  /
 20
```

先对 30 右旋，再对 10 左旋。

最终：

```text
      20
     /  \
    10   30
```

### 7.7 为什么旋转不会破坏 BST？

例如右旋：

```text
       A
      /
     B
    / \
   X   Y
```

原来的关键字关系为：

$$
X<B<Y<A
$$

右旋后：

```text
       B
      / \
     X   A
        /
       Y
```

关键字关系仍然是：

$$
X<B<Y<A
$$

所以中序遍历的关键字顺序保持不变。

这就是旋转能够维护搜索树性质的关键。

### 7.8 最低失衡祖先

AVL 插入后，应从新插入结点沿祖先链向上检查。

遇到的第一个：

$$
|BF|=2
$$

的结点，就是最低失衡祖先。

例如插入：

```text
27,16,75,38,51
```

插入后：

```text
       27
      /  \
     16   75
         /
        38
          \
           51
```

从 51 向上检查：

结点 38：

$$
BF(38)=-1
$$

仍然平衡。

结点 75：

$$
BF(75)=2
$$

首先失衡。

因此：

$$
\boxed{\text{最低失衡祖先}=75}
$$

属于 LR 型，需要先对 38 左旋，再对 75 右旋。

这也是模拟题中的考法。

### 7.9 AVL 最少结点数公式

这是计算题重点。

定义：

$$
N_h=\text{高度为 }h\text{ 的 AVL 树最少结点数}
$$

约定：

$$
N_0=0,\quad N_1=1
$$

要让高度达到 $h$，同时结点尽可能少：

一侧子树高度应为 $h-1$。

另一侧子树高度应为 $h-2$。

所以：

$$
\boxed{N_h=N_{h-1}+N_{h-2}+1}
$$

计算结果：

| 高度 $h$ | 最少结点数 |
| ---------- | ----- |
| 1          | 1     |
| 2          | 2     |
| 3          | 4     |
| 4          | 7     |
| 5          | 12    |
| 6          | 20    |
| 7          | 33    |
| 8          | 54    |
| 9          | 88    |
| 10         | 143   |
| 11         | 232   |

### 2012 年真题

高度为 6，且所有非叶结点平衡因子均为 1，问结点总数。

应用递推：

$$
N_2=2
$$

$$
N_3=4
$$

$$
N_4=7
$$

$$
N_5=12
$$

$$
N_6=20
$$

答案：20，选 B。

#### 模拟题：15 个结点的 AVL 能否出现 6 次成功比较？

因为：

$$
N_6=20
$$

高度达到 6 至少需要 20 个结点。

而题目只有 15 个结点。

所以：

$$
15<20
$$

不可能出现长度为 6 的成功查找路径。

这也是判断 AVL 查找序列是否可能的重要技巧：

先检查 BST 的上下界，再检查 AVL 的高度限制。

## 八、2027 王道第 5 套第 41 题：AVL 综合大题
题目给出插入序列：

$$
30,20,10,25,28,27
$$

要求构造 AVL，然后删除 10、28。

### 8.1 插入过程

| 插入关键字 | 最低失衡结点 | 类型 | 调整            |
| ----- | ------ | -- | ------------- |
| 30    | 无      | —  | 不旋转           |
| 20    | 无      | —  | 不旋转           |
| 10    | 30     | LL | 对 30 右旋       |
| 25    | 无      | —  | 不旋转           |
| 28    | 30     | LR | 先左旋 25，再右旋 30 |
| 27    | 20     | RL | 先右旋 28，再左旋 20 |

全部插入完成后：

```text
           25
         /    \
       20      28
      /       /  \
    10       27   30
```

这里最容易出错的是最后插入 27。

它大于 25，但整个失衡路径要相对于最低失衡祖先 20 判断。

从 20 出发，先向右进入 28，再向左进入 25 所在的分支。

所以是 RL 型，而不是 RR 型。

### 8.2 删除关键字 10

原树：

```text
           25
         /    \
       20      28
      /       /  \
    10       27   30
```

10 是叶结点，直接删除：

```text
           25
         /    \
       20      28
              /  \
             27   30
```

此时：

$$
BF(25)=1-2=-1
$$

仍然合法，不需要旋转。

### 8.3 删除关键字 28

28 有两个孩子。

题目要求用中序后继替换。

28 的后继是 30。

所以先用 30 替换 28，再删除原来的 30。

最终：

```text
        25
       /  \
     20    30
          /
         27
```

各结点平衡因子仍然合法。

因此这道题中：

删除 10 和删除 28 都不需要旋转。

### 8.4 从这道题需要掌握什么？

AVL 题不能只关心插入和旋转。

还必须理解：

- 插入后从下向上寻找最低失衡祖先。
- 一次 AVL 插入最多需要两次基本旋转。
- 删除后不一定发生旋转。
- AVL 删除的失衡可能继续向祖先传播。
- 删除有两个孩子的结点时，需要严格执行前驱或后继替换规则。

## 九、红黑树

红黑树是另一种自平衡二叉搜索树。

与 AVL 相比，红黑树的平衡约束较宽松，但仍能保证对数级高度。

### 9.1 红黑树的五条性质

1. 每个结点要么是红色，要么是黑色。
2. 根结点是黑色。
3. 所有 NIL 空叶结点都是黑色。
4. 红色结点不能有红色孩子。
5. 从任意结点到其所有后代 NIL 叶结点的路径，黑结点数相同。

其中第 4、5 条尤其重要。

### 红色结点不能连续

例如：

```text
       20(R)
       /
     10(R)
```

两个红色结点连续出现，违反红黑树性质。

但：

```text
       20(B)
       /
     10(B)
```

两个黑色结点连续出现并不违反颜色相邻规则；整棵树是否合法还需要检查黑高。

注意：

红色结点的孩子必须是黑色，但黑色结点的孩子不一定是红色。

### 9.2 黑高

黑高描述从某结点到后代 NIL 叶结点的路径上黑结点的数量。

常见定义不计起始结点本身。

不同教材对于是否计入当前结点、是否计入 NIL 的口径可能有所差异。

但是核心条件始终是：

$$
\boxed{\text{同一结点到各后代 NIL 的路径黑高相同}}
$$

### 9.3 红黑树为什么不会退化？

红黑树要求：

- 红色结点不能连续。
- 各路径具有相同黑高。

因此，较长路径可以穿插红色结点，但不可能无限延长而不增加黑结点。

可以证明红黑树高度满足：

$$
\boxed{h\le2\log_2(n+1)}
$$

这里采用常见的按边数计高度的约定；若按结点层数计算，常数项需要相应调整。

所以：

$$
\boxed{h=O(\log n)}
$$

从而保证：

$$
T_{\text{查找}}=O(\log n)
$$

$$
T_{\text{插入}}=O(\log n)
$$

$$
T_{\text{删除}}=O(\log n)
$$

### 9.4 红黑树插入的调整

标准方法是先按照 BST 规则插入新结点，并将新结点初始染成红色。

为什么通常先染红？

因为插入红结点不会直接增加原有路径的黑结点数量。

之后分情况处理。

| 情况           | 处理方式      |
| ------------ | --------- |
| 新结点成为根       | 染成黑色      |
| 父结点为黑色       | 通常直接结束    |
| 父结点为红色、叔叔为红色 | 变色并继续向上修复 |
| 父结点为红色、叔叔为黑色 | 根据位置旋转并变色 |

红父、红叔时，常见操作是：

```text
父结点：红 → 黑
叔结点：红 → 黑
祖父结点：黑 → 红
```

随后继续检查祖父是否引发更高层的冲突。

红父、黑叔时，需要结合 LL、RR、LR、RL 关系进行旋转与变色。

### 9.5 模拟题：红黑树插入

按标准红黑树插入规则，依次插入：

$$
41,38,31,12,19,8
$$

最终可以得到：

```text
          38(B)
         /     \
      19(R)    41(B)
      /   \
   12(B) 31(B)
   /
 8(R)
```

其中 B 表示黑色，R 表示红色。

检查：

- 根是黑色。
- 红结点没有红色孩子。
- 所有根到 NIL 的路径黑高相同。

因此是一棵合法红黑树。

### 9.6 AVL 与红黑树比较

| 比较项目     | AVL             | 红黑树             |
| -------- | --------------- | --------------- |
| 是否满足 BST | 是               | 是               |
| 平衡方式     | 左右子树高度差         | 颜色和黑高           |
| 平衡程度     | 更严格             | 相对宽松            |
| 最坏查找     | $O(\log n)$ | $O(\log n)$ |
| 最坏插入     | $O(\log n)$ | $O(\log n)$ |
| 最坏删除     | $O(\log n)$ | $O(\log n)$ |
| 查询路径     | 通常较短            | 可能稍长            |
| 插入旋转     | 最多两次基本旋转        | 最多两次基本旋转        |
| 删除旋转     | 可能沿祖先路径多次调整     | 标准算法旋转次数有常数上界   |
| 常见选择     | 读多写少            | 频繁动态更新          |

注意：

红黑树更新时旋转次数较少，并不代表整个更新过程只有 $O(1)$。

因为寻找插入或删除位置、向上变色修复等仍可能需要：

$$
O(\log n)
$$

## 十、B 树——第 7 章最重要的多路查找结构

B 树是一种多路平衡查找树。

它特别适合外存查找。

原因是：

一次磁盘 I/O 的代价通常远高于在内存中比较几个关键字的代价。

如果一个结点可以存储多个关键字，并拥有很多孩子，就可以显著降低树高。

### 10.1 $m$ 阶 B 树的定义

$m$ 阶 B 树中的 $m$ 表示：

$$
\boxed{\text{每个结点最多有 }m\text{ 棵子树}}
$$

因此最多含有：

$$
\boxed{m-1\text{ 个关键字}}
$$

设：

$$
t=\left\lceil\frac m2\right\rceil
$$

对于非根结点，关键字数量满足：

$$
\boxed{t-1\le k\le m-1}
$$

即：

$$
\boxed{ \left\lceil\frac m2\right\rceil-1 \le k\le m-1 }
$$

根结点具有特殊规则：

若根不是叶结点，则至少有两个孩子。

如果整棵树只有根一个结点，则根可以含 1 至 $m-1$ 个关键字。

### 阶数速查

| 阶数 | 非根结点最少关键字 | 最多关键字 | 最多孩子 |
| -- | --------- | ----- | ---- |
| 3  | 1         | 2     | 3    |
| 4  | 1         | 3     | 4    |
| 5  | 2         | 4     | 5    |
| 6  | 2         | 5     | 6    |
| 7  | 3         | 6     | 7    |

例如，5 阶 B 树：

$$
t=\left\lceil\frac52\right\rceil=3
$$

非根结点最少：

$$
t-1=2
$$

个关键字。

最多：

$$
5-1=4
$$

个关键字。

### 10.2 B 树结点结构

一个含有三个关键字的内部结点可以写成：

```text
P0 | 20 | P1 | 40 | P2 | 60 | P3
```

其中：

- $P_0$ 指向小于 20 的子树。
- $P_1$ 指向 20 到 40 之间的子树。
- $P_2$ 指向 40 到 60 之间的子树。
- $P_3$ 指向大于 60 的子树。

因此，具有 $k$ 个关键字的内部结点有：

$$
\boxed{k+1\text{ 个孩子}}
$$

这相当于把 BST 的两个搜索方向推广成多个搜索方向。

### 10.3 B 树高度公式——必考

设 B 树高度为 $h$，根在第 1 层，最底层含关键字结点在第 $h$ 层。

### 最大关键字数

为了让高度为 $h$ 的 B 树容纳尽量多的关键字，每层都尽可能满。

各层最多结点数：

$$
1,m,m^2,\ldots,m^{h-1}
$$

每个结点最多 $m-1$ 个关键字。

因此：

$$
N_{\max}=(m-1)(1+m+\cdots+m^{h-1})
$$

利用等比数列求和：

$$
\boxed{N_{\max}=m^h-1}
$$

### 最小关键字数

为了让高度为 $h$ 的 B 树含有尽量少的关键字：

根最少 1 个关键字、2 个孩子。

其他非根结点最少：

$$
t-1
$$

个关键字。

非根内部结点最少有 $t$ 个孩子。

可推导：

$$
\boxed{N_{\min}=2t^{h-1}-1}
$$

其中：

$$
t=\left\lceil\frac m2\right\rceil
$$

于是：

$$
\boxed{ 2\left\lceil\frac m2\right\rceil^{h-1}-1 \le N\le m^h-1 }
$$

对非空树采用上述高度约定时成立。

### 由关键字数求树高

最小可能高度：

$$
\boxed{ h_{\min}=\left\lceil\log_m(N+1)\right\rceil }
$$

最大可能高度：

$$
\boxed{ h_{\max}= \left\lfloor 1+\log_t\frac{N+1}{2} \right\rfloor }
$$

其中通常要求 $m\ge3$。

#### 历年真题：2013 年

题目：

高度为 2 的 5 阶 B 树，最少有多少个关键字？

$$
m=5
$$

$$
t=\left\lceil\frac52\right\rceil=3
$$

$$
N_{\min}=2\times3^{2-1}-1
$$

$$
=6-1=5
$$

答案：5，选 A。

#### 历年真题：2018 年

高度为 5 的 3 阶 B 树，至少含多少个关键字？

$$

$$

$$

$$

$$
=32-1
$$

$$
\boxed{N_{\min}=31}
$$

求最多和最少关键字数。

$$

$$

最少：

$$
N_{\min}=2\times2^2-1=7

最多：

$$
\boxed{7\le N\le63}

### 10.4 B 树查找

B 树查找分两步：

第一步：在当前结点内部比较关键字。

第二步：根据目标值进入相应子树。

例如：

```text
             [30 | 60]
            /    |    \
     [10|20] [40|50] [70|80]
```

查找 50：

首先访问根：

```text
[30 | 60]
```

因为：

$$
30<50<60
$$

进入中间子树：

```text
[40 | 50]
```

找到 50。

注意一个关键性质：

B 树查找可以在内部结点直接成功。

例如查找 30，在根结点就可以结束。

这与 B+ 树不同。

<Tabs items={['插入：上溢与分裂', '删除：下溢与修复']} defaultIndex={0}>

<Tab value="插入：上溢与分裂">

B 树插入遵循：

```text
找到插入位置
    ↓
向叶结点插入
    ↓
检查是否上溢
    ↓
若上溢则分裂
    ↓
中间关键字上移
    ↓
必要时继续向上分裂
```

### 什么是上溢？

例如 4 阶 B 树，一个结点最多有：

$$
m-1=3
$$

个关键字。

如果插入后出现 4 个关键字，就发生上溢。

### 2020 年真题：4 阶 B 树插入

依次插入：

$$
5,6,9,13,8,2,12,15
$$

求最终根结点关键字。

先插入：

```text
5 6 9
```

根结点：

```text
[5 | 6 | 9]
```

继续插入 13：

```text
[5 | 6 | 9 | 13]
```

出现 4 个关键字，超出容量。

按该题采用的分裂口径，将 6 提升为新根：

```text
         [6]
        /   \
      [5]  [9|13]
```

继续插入 8、2：

```text
         [6]
        /   \
    [2|5] [8|9|13]
```

再插入 12：

右侧叶结点变成：

```text
[8|9|12|13]
```

再次上溢。

把 9 提升到父结点，得到：

```text
           [6|9]
          /  |   \
       [2|5][8][12|13]
```

最后插入 15：

```text
           [6|9]
          /  |      \
       [2|5][8] [12|13|15]
```

所以最终根结点是：

$$
\boxed{[6,9]}
$$

答案：B。

注意：偶数个关键字的上溢结点如何选取分裂提升位置，需要遵守题目给出的规则，同时保证分裂后两侧结点满足容量限制。

</Tab>

<Tab value="删除：下溢与修复">

B 树删除比插入更复杂。

核心问题是：

删除之后，某个结点的关键字数量可能低于合法下限。

这种情况称为下溢。

处理方式：

```text
删除关键字
    ↓
是否下溢？
    ├── 否：结束
    └── 是
         ↓
      兄弟能否借？
         ├── 能：借关键字
         └── 不能：合并结点
                    ↓
                 父结点下溢？
                    ↓
                 继续向上修复
```

#### 情况一：直接删除

例如某个 5 阶 B 树叶结点含：

```text
[10|20|30]
```

删除 20：

```text
[10|30]
```

非根结点仍有 2 个关键字，合法。

直接结束。

#### 情况二：向兄弟借

假设当前结点只有 1 个关键字，但至少需要 2 个。

如果相邻兄弟拥有 3 个或更多关键字，就有可能借出一个。

注意借位的实际过程：

兄弟的边界关键字上移到父结点，父结点的分隔关键字下移到缺少关键字的结点。

不是简单地把兄弟结点中的关键字直接搬过去。

#### 情况三：合并

如果兄弟本身也只有最少关键字，不能再借。

则：

```text
当前结点
+
父结点分隔关键字
+
兄弟结点
=
新的合并结点
```

父结点因此少一个关键字。

如果父结点下溢，继续向上处理。

### 根结点收缩

当根结点因合并而不再含关键字，且只剩一个孩子时：

让唯一孩子成为新根。

此时：

$$
\boxed{\text{树高减少 1}}
$$

因此 B 树中：

插入导致根分裂，树高可能增加；删除导致根收缩，树高可能减少。

一道典型模拟题：

在一棵 3 阶 B 树中删除关键字 78，调整后最右叶结点保存什么关键字？

题目图示中，删除 78 后最右叶结点下溢。

它的左兄弟含有：

父结点的分隔关键字为 65。

由于左兄弟可以借关键字：

- 左兄弟中的 62 上移到父结点。

因此最右叶结点最终为：

$$

### 10.8 B 树易错点

最重要的几个判断：

| 说法                            | 正误 |
| ----------------------------- | -- |
| $m$ 阶 B 树最多有 $m$ 个关键字 | 错  |
| $m$ 阶 B 树最多有 $m$ 个孩子  | 对  |

| B 树内部结点的关键字也可以成为成功查找结果        | 对  |

## 十一、B+ 树

B+ 树与 B 树都属于多路平衡搜索结构。

但是 B+ 树更适合范围查询与索引组织。

### 11.1 B+ 树的核心特点

最重要的两个特点：

第一，内部结点主要保存索引项。

第二，实际记录或记录指针集中在叶结点，叶结点之间按关键字顺序链接。

示意：

```text
              [30 | 60]
             /    |    \
            /     |     \
     [10|20] → [30|40|50] → [60|70|80]
```

其中实际数据位于最下面的叶层。

内部结点帮助决定搜索方向。

### 11.2 B 树与 B+ 树的查找区别

在 B 树中：

```text
访问内部结点
    ↓
如果找到关键字
    ↓
直接成功
```

在 B+ 树中：

```text
访问内部索引
    ↓
根据索引继续下降
    ↓
到达叶结点
    ↓
定位实际记录
```

因此：

$$
\boxed{\text{B 树查找可以提前结束}}
$$

$$
\boxed{\text{B+ 树记录查找最终到达叶层}}
$$

### 11.3 为什么 B+ 树适合范围查询？

假设数据库需要：

```text
SELECT *
FROM student
WHERE score BETWEEN 80 AND 90;
```

B+ 树可以先定位到第一个满足分数不小于 80 的叶结点。

然后沿着叶结点的顺序链表向后扫描。

直到分数大于 90 为止。

过程：

```text
通过索引定位 80
       ↓
访问包含 80 的叶结点
       ↓
沿叶链扫描
       ↓
81 → 82 → 85 → 88 → 90
       ↓
超过 90，停止
```

不需要对范围内的每一条记录都重新从根查找。

这就是 B+ 树适合数据库索引的重要原因。

### 11.4 B+ 树阶数的口径问题

这是非常值得注意的易错点。

B+ 树内部结点的索引关键字与孩子指针之间，存在不同教材约定。

例如：

| 表示方式     | 关键字与子树的关系                    |
| -------- | ---------------------------- |
| 分隔关键字式   | $k$ 个关键字对应 $k+1$ 棵子树 |
| 子树代表关键字式 | $k$ 个关键字对应 $k$ 棵子树   |

因此，B+ 树容量题需要先阅读题目给出的结点定义。

不能不看约定，就把 B 树的所有关键字数量公式直接照搬过去。

### 11.5 B 树与 B+ 树全面对比

| 项目             | B 树     | B+ 树          |
| -------------- | ------- | ------------- |
| 类型             | 多路平衡查找树 | 多路平衡索引树       |
| 内部结点           | 可保存记录   | 主要保存索引        |
| 叶结点            | 保存记录    | 保存全部实际记录或记录指针 |
| 内部结点能否直接完成记录查找 | 可以      | 通常不可以         |
| 是否必须查到叶层       | 不一定     | 是             |
| 叶结点有序链         | 通常不强调   | 通常有           |
| 范围查找           | 可以      | 更适合           |
| 磁盘 I/O         | 较少      | 通常更有优势        |
| 典型应用           | 外存查找    | 数据库和文件系统索引    |

#### 历年真题：2017 年

题目问：下列哪个应用适合使用 B+ 树？

A. 编译器中的词法分析

B. 关系数据库系统中的索引

C. 网络中的路由表快速查找

D. 操作系统磁盘空闲块管理

答案：B。

原因是数据库索引往往需要同时支持精确查询、范围查询以及有序扫描。

B+ 树的多路结构和叶层有序链非常适合这些操作。

## 十二、散列表 Hash Table——最重要的计算题专题

散列表与前面的查找方法思路明显不同。

前面的折半查找与搜索树依靠关键字之间的大小关系。

散列表则尝试通过一个函数，直接确定候选存储位置。

### 12.1 散列函数

一般写成：

$$
\boxed{address=H(key)}
$$

例如：

$$
H(key)=key\bmod 7
$$

那么：

$$
H(15)=1
$$

$$
H(22)=1
$$

两个不同关键字映射到同一个地址。

这就产生散列冲突。

### 12.2 散列冲突

如果：

$$
key_1\ne key_2
$$

但：

$$
H(key_1)=H(key_2)
$$

那么两个关键字发生冲突。

这两个关键字称为同义词。

散列表的两个关键设计：

散列函数决定初始地址，冲突处理方法决定后续地址。

### 12.3 开放定址法

所有元素都保存在散列表数组槽位中。

发生冲突后，按照一定规则继续探测空地址。

统一公式：

$$
\boxed{H_i=(H_0+d_i)\bmod m}
$$

其中：

- $H_0$：初始散列地址。
- $d_i$：探测偏移。
- $m$：散列表长度。

### 线性探测

线性探测的偏移：

$$
d_i=i
$$

因此：

$$
\boxed{H_i=(H_0+i)\bmod m}
$$

例如：

$$
H(key)=key\bmod7
$$

依次插入：

```text
7,14,21
```

三个关键字的初始地址都为 0。

插入：

```text
7  → 0
14 → 0 冲突 → 1
21 → 0 冲突 → 1 冲突 → 2
```

最终：

| 地址  | 0 | 1  | 2  | 3 | 4 | 5 | 6 |
| --- | - | -- | -- | - | - | - | - |
| 关键字 | 7 | 14 | 21 | 空 | 空 | 空 | 空 |

成功比较次数：

```text
7：1
14：2
21：3
```

所以：

$$
ASL_{\text{成功}}=\frac{1+2+3}{3}
$$

$$
\boxed{ASL_{\text{成功}}=2}
$$

### 12.4 平方探测

平方探测通过平方偏移减轻线性探测中的聚集。

常见形式之一：

$$
H_i=(H_0+i^2)\bmod m
$$

另一种常见形式为正负平方交替：

$$
d_i=0,+1^2,-1^2,+2^2,-2^2,\ldots
$$

这两种探测规则不能混用。

另外，平方探测并不保证在任意表长下都能访问所有槽位。

即使表中存在空槽，也可能因探测地址发生循环或重复而无法找到它。

### 12.5 双散列

双散列使用两个散列函数：

$$
\boxed{H_i=(H_1(key)+iH_2(key))\bmod m}
$$

其中第二个散列函数决定步长。

若要探测完整表空间，通常要求：

$$
\boxed{\gcd(H_2(key),m)=1}
$$

例如：

$$
m=12,\quad H_2(key)=4
$$

则：

$$
\gcd(12,4)=4
$$

从同一个初始地址出发，实际只能访问：

$$
\frac{12}{4}=3
$$

个不同地址。

因此无法访问全部 12 个槽位。

### 12.6 拉链法

拉链法使用链表等容器保存映射到同一地址的关键字。

例如：

$$
H(key)=key\bmod7
$$

插入：

```text
7,14,21
```

则：

```text
地址0：7 → 14 → 21
地址1：空
地址2：空
...
```

成功查找次数：

$$
1,2,3
$$

因此：

$$
ASL_{\text{成功}}=2
$$

若失败查找从地址 0 开始，且只统计与链内实际关键字的比较次数，则需要比较 3 次。

若查找落在空桶，按关键字比较次数统计可以是 0 次。

这一点与开放定址法不同：

拉链法失败时到达空指针，通常不额外算一次关键字比较；开放定址法失败时访问空槽，通常需要把最后一次槽位探测计入。

### 12.7 装填因子

装填因子表示散列表的拥挤程度。

$$
\boxed{\alpha=\frac nm}
$$

其中：

- $n$：实际存储的有效关键字数量。
- $m$：散列表槽位或桶的数量。

例如：

$$
n=7,\quad m=10
$$

则：

$$
\alpha=\frac7{10}=0.7
$$

一般而言，装填因子越大，冲突越容易发生。

但是平均性能并不只由装填因子决定。

还取决于散列函数、关键字分布和冲突处理方式。

### 开放定址与拉链法

| 项目         | 开放定址法     | 拉链法      |
| ---------- | --------- | -------- |
| 每槽保存关键字数   | 最多 1 个    | 可以多个     |
| 是否使用额外链表   | 不需要       | 通常需要     |
| 装填因子能否大于 1 | 不能        | 可以       |
| 删除处理       | 通常需要墓碑或重排 | 可直接删除链结点 |
| 一次聚集       | 线性探测比较明显  | 不存在同类聚集  |
| 缓存局部性      | 通常更好      | 通常较弱     |

<Callout type="warn" title="先辨认 ASL 的统计口径">

成功 ASL 对已存关键字的实际探测次数求期望；失败 ASL 对题设规定的失败初址或查询事件求期望。**散列表长度与散列函数模数不一定相同**，不能机械地用表长做失败 ASL 的分母。

</Callout>

### 12.8 散列表成功 ASL

假设已经保存 $n$ 个关键字，且各关键字等概率被成功查询。

则：

$$
\boxed{ ASL_{\text{成功}}=\frac{\sum_{i=1}^{n}L_i}{n} }
$$

这里 $L_i$ 是查找第 $i$ 个关键字需要的实际探测次数。

### 散列表失败 ASL

若散列函数产生 $r$ 个等概率初始地址，则：

$$
\boxed{ ASL_{\text{失败}}=\frac{\sum_{j=1}^{r}F_j}{r} }
$$

这里 $F_j$ 是从第 $j$ 个可能初始地址出发，直到确认查找失败的探测次数。

特别注意：

分母是题目指定的失败查找情况数，而不一定是散列表长度。

例如：

$$
H(key)=key\bmod7
$$

即使散列表长为 10，初始散列地址也只有：

$$
0,1,2,3,4,5,6
$$

共 7 种。

如果题目规定这些初始地址等概率，失败 ASL 的分母就是 7，而不是 10。

## 十五、散列表删除与墓碑——2023 年真题

开放定址法删除元素时，不能简单地将槽位置为普通空槽。

为什么？

例如：

```text
地址3：A
地址4：B
```

假设：

$$
H(A)=H(B)=3
$$

B 因冲突被插入地址 4。

删除 A 后，如果直接把地址 3 设为 `EMPTY`，以后查找 B：

```text
地址3为空
    ↓
提前判定失败
```

但是 B 实际在地址 4。

因此开放定址法通常需要墓碑。

### 15.1 三种槽位状态

| 状态       | 含义         | 查找处理     |
| -------- | ---------- | -------- |
| EMPTY    | 从未使用       | 可以结束失败查找 |
| OCCUPIED | 存放有效关键字    | 比较关键字    |
| DELETED  | 曾有关键字，现已删除 | 必须继续探测   |

记忆：

遇到墓碑继续，遇到真正空槽才能停止。

### 15.2 2023 年真题

题目：

散列表长度：

散列函数：

然后删除 25。

## 十六、2013 年 408 第 42 题：加权 ASL 与最优 BST

这是整章理解查找效率的重要综合题。

对于第二问，“链式存储”可能有不同的结构约定，需要分别讨论。

### 16.1 题目

给定：

$$
S=\{\text{do},\text{for},\text{repeat},\text{while}\}
$$

成功查找概率：

$$
0.35,\ 0.15,\ 0.15,\ 0.35
$$

采用折半查找时：

$$
ASL=2.2
$$

要求设计更高效的存储组织与查找方式。

### 16.2 顺序表：按概率从大到小排列

对于顺序查找，越靠前的元素，比较次数越少。

因此应该把查找概率高的关键字放在前面。

例如：

```text
do → while → for → repeat
```

对应：

$$
0.35,\ 0.35,\ 0.15,\ 0.15
$$

所以：

$$
ASL=0.35\times1+0.35\times2+0.15\times3+0.15\times4
$$

$$
\boxed{ASL=2.1}
$$

比原来的 2.2 更低。

### 16.3 如果采用普通单链表

如果“链式存储”限定为普通单链表：

```text
do → while → for → repeat
```

仍然只能逐结点顺序查找。

此时：

$$
\boxed{ASL=2.1}
$$

不能因为改为链式存储，就自动获得更低的查找复杂度。

### 16.4 如果允许二叉链式存储

可以构造最优 BST。

注意关键字字典序：

$$
\text{do}<\text{for}<\text{repeat}<\text{while}
$$

构造：

```text
          for
         /   \
       do    while
             /
          repeat
```

对应成功比较次数：

| 关键字    | 概率   | 比较次数 |
| ------ | ---- | ---- |
| for    | 0.15 | 1    |
| do     | 0.35 | 2    |
| while  | 0.35 | 2    |
| repeat | 0.15 | 3    |

因此：

$$
ASL=0.15\times1+0.35\times2+0.35\times2+0.15\times3
$$

$$
\boxed{ASL=2.0}
$$

所以：

| 结构和算法     | ASL |
| --------- | --- |
| 题设折半查找    | 2.2 |
| 最优顺序查找    | 2.1 |
| 普通单链表顺序查找 | 2.1 |
| 最优二叉搜索树   | 2.0 |

**口径说明：**&#x2060;若“链式存储”指普通单链表，平均代价可为 2.1；若允许构建二叉链式 BST，则可得到 2.0。考场须以题目限定的数据结构为准，不能混用这两个结果。

### 16.5 最优 BST 的动态规划思想

设：

$$
C(i,j)
$$

表示第 $i$ 到第 $j$ 个有序关键字构造 BST 的最小加权查找代价。

定义：

$$
W(i,j)=\sum_{k=i}^{j}p_k
$$

对于一个区间，如果选择第 $r$ 个关键字作为根：

- 左侧关键字构成左子树。
- 右侧关键字构成右子树。
- 整个区间的关键字都会因为经过当前根而多承担一次比较。

于是：

$$
\boxed{ C(i,j)=W(i,j)+ \min_{i\le r\le j} \left[ C(i,r-1)+C(r+1,j) \right] }
$$

空区间代价为 0。

对于这道题，可得到：

$$
\boxed{C(1,4)=2.0}
$$

该递推适用于只计算成功查找概率的最优 BST 模型。

朴素区间动态规划的时间复杂度为：

$$
O(n^3)
$$

空间复杂度为：

$$
O(n^2)
$$

这一部分属于更深入的算法理解，掌握递推思想的价值高于死记某个树形。

## 十七、2022 年 408 第 41 题：判断二叉树是否为 BST

这道题是典型的数据结构算法设计题。

### 17.1 题目背景

二叉树采用数组顺序存储。

定义：

```c
typedef struct {
    int SqBiTNode[MAX_SIZE];
    int ElemNum;
} SqBiTree;
```

其中 `-1` 表示空结点，实际关键字都是正整数。

要求判断这棵树是否为 BST。

### 17.2 方法一：中序遍历

对于关键字互异的 BST：

$$
\boxed{\text{中序遍历必须严格递增}}
$$

所以可以在中序遍历过程中只记录前一个关键字。

不需要将整个中序序列复制到新数组。

每访问一个结点，检查：

$$
current>previous
$$

如果不满足，立即返回 `false`。

### 17.3 方法二：上下界递归——推荐掌握

对于任意结点，维护允许的关键字范围：

$$
(low,high)
$$

根结点：

$$
(-\infty,+\infty)
$$

进入左子树：

$$
(low,root)
$$

进入右子树：

$$
(root,high)
$$

如果某个结点不在允许范围内，直接判定不是 BST。

例如：

```text
       40
      /  \
     20   60
       \
        50
```

当进入 40 的左子树时，所有关键字必须小于 40。

继续进入 20 的右子树时，允许区间变成：

$$
20<x<40
$$

但结点值为 50。

违反范围约束，因此不是 BST。

### 17.4 C 语言实现

```c
#include <stdbool.h>
#include <limits.h>

#define MAX_SIZE 1000

typedef struct {
    int SqBiTNode[MAX_SIZE];
    int ElemNum;
} SqBiTree;

bool CheckBST(const SqBiTree *T, int i,
              long long low, long long high) {

    // 超出数组有效范围，视为空子树
    if (i >= T->ElemNum)
        return true;

    int x = T->SqBiTNode[i];

    // -1 表示不存在该结点
    if (x == -1)
        return true;

    // 必须满足所有祖先给出的范围
    if (x <= low || x >= high)
        return false;

    // 左孩子编号：2*i+1
    // 右孩子编号：2*i+2
    return CheckBST(T, 2*i+1, low, x) &&
           CheckBST(T, 2*i+2, x, high);
}

bool IsBST(const SqBiTree *T) {
    if (T == NULL || T->ElemNum <= 0 ||
        T->ElemNum > MAX_SIZE)
        return false;

    return CheckBST(T, 0, LLONG_MIN, LLONG_MAX);
}
```

这段代码假设输入已经是合法的顺序存储二叉树表示；若题目还要求检查是否存在不可达结点等存储合法性问题，则需要增加相应验证。

### 17.5 复杂度分析

设实际可达的非空结点数为 $n$，树高为 $h$。

每个实际结点只检查一次。

因此：

$$
\boxed{T(n)=O(n)}
$$

递归调用栈最多为树高：

$$
\boxed{S(n)=O(h)}
$$

对于一般二叉树：

$$
h\le n
$$

最坏辅助空间为：

$$
O(n)
$$

对于平衡树则为：

$$
O(\log n)
$$

### 17.6 本题需要掌握的三个关键思想

第一：BST 判断必须满足全局大小关系。

不能只比较父结点和直接孩子。

第二：顺序存储二叉树的孩子编号与数组下标有关。

从 0 开始编号：

$$
left(i)=2i+1
$$

$$
right(i)=2i+2
$$

第三：算法应尽量只遍历一次。

中序检查或上下界递归都能够在线性时间内完成。

## 十八、2026 年 408 第 41 题：BST 最近关键字

这道题体现了查找章节算法设计的核心：利用数据结构性质减少搜索范围。

### 18.1 题目

给定一棵 BST 和整数 $K$。

要求找到树中所有与 $K$ 的绝对差最小的关键字，并输出最小差值。

假设 BST 中关键字互异。

### 18.2 最直接的办法

遍历整棵树。

计算每个结点与 $K$ 的距离：

$$
d=|x-K|
$$

保留最小距离及对应关键字。

这种做法时间复杂度：

$$
O(n)
$$

但没有充分利用 BST 的有序性。

### 18.3 更高效的方法

对于 BST，如果当前结点值为 $x$：

当：

$$
x<K
$$

时，当前结点左子树所有关键字都小于 $x$。

因此，对于左子树任意关键字 $y$：

$$
y<x<K
$$

得到：

$$
K-y>K-x
$$

也就是说，左子树所有关键字都比当前结点离 $K$ 更远。

所以可以直接排除左子树，转向右子树。

同理：

当：

$$
x>K
$$

时，排除右子树，只查左子树。

当：

$$
x=K
$$

时，最小绝对差已经达到 0，可以直接结束。

### 18.4 为什么答案最多两个？

在关键字互异的 BST 中，如果 $K$ 不存在，最接近 $K$ 的候选只能来自：

$$
p=\max\{x\mid x<K\}
$$

以及：

$$
q=\min\{x\mid x>K\}
$$

也就是：

$K$ 的严格前驱与严格后继。

因此只要比较：

$$
K-p
$$

和：

$$
q-K
$$

就能得到答案。

如果两者相等，则必须同时输出。

例如：

```text
4 7 10 14 18
```

当：

$$
K=12
$$

时：

$$
|10-12|=2
$$

$$
|14-12|=2
$$

因此：

$$
\boxed{\text{最近关键字}=10,14}
$$

$$
\boxed{\text{最小距离}=2}
$$

### 18.5 C 语言实现

```c
#include <stdio.h>
#include <limits.h>

typedef struct BSTNode {
    int data;
    struct BSTNode *left, *right;
} BSTNode;

void FindClosest(BSTNode *root, int K) {
    if (root == NULL)
        return;

    long long best = LLONG_MAX;
    int ans[2];
    int count = 0;

    BSTNode *p = root;

    while (p != NULL) {
        long long delta =
            (long long)p->data - (long long)K;

        long long d =
            delta < 0 ? -delta : delta;

        if (d < best) {
            best = d;
            count = 1;
            ans[0] = p->data;
        }
        else if (d == best && count < 2) {
            ans[count++] = p->data;
        }

        if (p->data == K)
            break;

        if (K < p->data)
            p = p->left;
        else
            p = p->right;
    }

    printf("min distance = %lld\n", best);

    for (int i = 0; i < count; i++)
        printf("%d ", ans[i]);
}
```

### 18.6 复杂度

算法只沿一条 BST 查找路径前进。

因此时间复杂度：

$$
\boxed{T(n)=O(h)}
$$

如果 BST 平衡：

$$
O(\log n)
$$

如果 BST 退化：

$$
O(n)
$$

只使用有限个辅助变量：

$$
\boxed{S(n)=O(1)}
$$

这里还有一个 C 语言易错点：

若直接计算：

```text
abs(p->data - K)
```

当两个整数接近 `INT_MIN`、`INT_MAX` 时，减法可能溢出。

应该先转换为 `long long`，再进行减法。

## 十九、2027 王道第 8 套第 41 题：BST、散列与堆综合

来源同前述王道综合题页面。

给定关键字序列：

$$
24,15,39,26,18,31,5,22
$$

要求分别完成 BST、散列表和大根堆操作。

这道题特别适合练习不同数据结构的性质区别。

### 19.1 构造 BST

依次插入：

```text
           24
         /    \
       15      39
      /  \    /
     5   18  26
           \    \
           22    31
```

前序遍历：

$$
\boxed{24,15,5,18,22,39,26,31}
$$

中序遍历：

$$
\boxed{5,15,18,22,24,26,31,39}
$$

后序遍历：

$$
\boxed{5,22,18,15,31,26,39,24}
$$

注意 BST 中序必须递增。

### 19.2 散列表构造

散列表长：

$$
m=16
$$

初始地址：

$$
H(key)=key\bmod13
$$

探测偏移：

$$
0,+1^2,-1^2,+2^2,-2^2,\ldots
$$

按题目规则，发生冲突后对表长 16 取模。

| 关键字 | 初址 | 探测路径  | 成功次数 |
| --- | -- | ----- | ---- |
| 24  | 11 | 11    | 1    |
| 15  | 2  | 2     | 1    |
| 39  | 0  | 0     | 1    |
| 26  | 0  | 0→1   | 2    |
| 18  | 5  | 5     | 1    |
| 31  | 5  | 5→6   | 2    |
| 5   | 5  | 5→6→4 | 3    |
| 22  | 9  | 9     | 1    |

成功 ASL：

$$
ASL=\frac{1+1+1+2+1+2+3+1}{8}
$$

$$
\boxed{ASL=1.5}
$$

### 19.3 构造大根堆

采用自底向上的调整方法，最后得到：

```text
             39
           /    \
         26      31
        /  \    /  \
      22   18  24   5
     /
    15
```

层序数组：

$$
\boxed{[39,26,31,22,18,24,5,15]}
$$

### 19.4 三种结构有什么不同？

| 结构  | 维护的核心性质           |
| --- | ----------------- |
| BST | 左子树小于根，右子树大于根     |
| 大根堆 | 双亲关键字不小于孩子        |
| 散列表 | 根据散列函数和冲突规则确定存储地址 |

堆不是 BST。

堆只能保证父子之间满足堆序，不能保证左、右子树具有完整的大小关系。

因此，普通二叉堆查找任意关键字最坏仍可能需要：

$$
O(n)
$$

而取堆顶最大值可以为：

$$
O(1)
$$

## 二十、全章算法复杂度与结构选择

### 20.1 查找复杂度总表

| 查找结构   | 典型平均查找          | 最坏查找            | 是否支持动态更新 |
| ------ | --------------- | --------------- | -------- |
| 顺序查找   | $O(n)$      | $O(n)$      | 可以       |
| 折半查找   | $O(\log n)$ | $O(\log n)$ | 更新通常较昂贵  |
| 分块查找   | 与块长有关           | 与索引和块内算法有关      | 可以       |
| 普通 BST | 取决于树形           | $O(n)$      | 可以       |
| AVL    | $O(\log n)$ | $O(\log n)$ | 可以       |
| 红黑树    | $O(\log n)$ | $O(\log n)$ | 可以       |
| B 树    | $O(\log n)$ | $O(\log n)$ | 可以       |
| B+ 树   | $O(\log n)$ | $O(\log n)$ | 可以       |
| 散列表    | 期望接近 $O(1)$ | $O(n)$      | 可以       |

这里散列表的平均复杂度依赖合理的散列函数、装填因子及冲突处理方案。

B 树与 B+ 树在实际外存环境下，还需要特别考虑磁盘页访问次数。

### 20.2 如何根据场景选择结构？

| 场景              | 优先考虑        |
| --------------- | ----------- |
| 数据有序，查询频繁，更新很少  | 折半查找        |
| 数据无序、规模较小       | 顺序查找        |
| 数据动态变化并要求有序     | BST、AVL、红黑树 |
| 查询多、修改少，关注树高    | AVL         |
| 插入删除频繁，要求最坏性能稳定 | 红黑树         |
| 数据存储在外存         | B 树、B+ 树    |
| 大量范围查询          | B+ 树        |
| 只需要快速精确查询       | 散列表         |
| 高频取得最大或最小关键字    | 堆           |

## 本章最后需要真正记住的五件事

第一，ASL 是查找代价的期望。 计算之前，先弄清成功还是失败、比较还是探测、哪些情况等概率。

第二，有序性能够减少查找范围。 折半查找利用有序数组，BST 利用左右子树的大小关系，B 树利用多路关键字划分搜索区间。

第三，树的高度直接影响查找效率。 普通 BST 可能退化；AVL 和红黑树通过平衡约束防止退化；B 树与 B+ 树通过多路分支降低外存索引高度。

第四，散列表的核心是散列函数和冲突处理。 它不依赖关键字的大小顺序，平均性能可以接近常数时间，但必须正确处理探测序列、装填因子、删除和重新散列。

第五，408 算法题考的是利用结构性质进行剪枝。 不论是 BST 合法性判断、最近关键字查找，还是 B 树插删，真正重要的都是明确每一步维持什么性质、为什么能够排除某些情况，以及如何证明最终结果正确。

建议把本章的核心训练目标定为：能独立完成折半查找判定树与 ASL、BST/AVL 构造、B 树插删、散列表成功与失败 ASL，以及 BST 的 C 语言综合算法题。 这些能力掌握后，第 7 章的大多数典型考题都可以从原理推导，而不必依赖死记答案。
