## 二、数据结构的基本概念

### 2.1 数据、数据元素、数据项、数据对象

这一部分概念相近，适合通过一个完整例子理解。

假设学校系统存储了下面的学生信息：

| 学号   | 姓名 | 年龄 | 成绩 |
| ---- | -- | -- | -- |
| 1001 | 张三 | 20 | 90 |
| 1002 | 李四 | 21 | 85 |
| 1003 | 王五 | 19 | 95 |

#### （1）数据 Data

数据是能够被计算机识别、存储和处理的信息的表示。

数据不一定是数字，还可以包括字符、图像、音频等。

例如，上面整张学生信息表中的内容都属于数据。

#### （2）数据元素 Data Element

数据元素是数据的基本单位，通常作为一个整体处理。

例如：

```text
(1001, 张三, 20, 90)
```

这一整条学生记录是一个数据元素。

注意，不是每一个数字都必须单独构成数据元素。

数据元素的划分取决于具体处理的问题。

#### （3）数据项 Data Item

数据项是组成数据元素的、具有独立含义的最小单位。

例如一条学生记录中的：

```text
学号：1001
姓名：张三
年龄：20
成绩：90
```

它们都是数据项。

因此：

```text
数据
 └── 数据元素
       └── 数据项
```

#### （4）数据对象 Data Object

数据对象是性质相同的数据元素的集合。

例如：

- 全班学生的记录集合。
- 所有整数的集合。
- 某学校全部课程记录的集合。

需要区分的是：

数据对象强调元素具有共同性质；数据结构还强调元素之间存在何种关系。

#### 典型概念题

题目： 在学生成绩管理系统中，一条完整的学生记录通常属于什么？

A. 数据项

B. 数据元素

C. 数据类型

D. 存储结构

答案：B。

原因是，学生记录通常作为一个整体参与查找、修改、排序等操作，而学号、姓名、成绩是其中的数据项。

易错点： 数据元素不一定只包含一个简单值，它可以由多个数据项构成。

### 2.2 数据结构的定义与三要素

数据结构可以定义为：

相互之间存在一种或多种特定关系的数据元素的集合。

对于考研而言，比这句话更重要的是理解数据结构的三个要素：

$$
\boxed{ \text{数据结构} = \text{逻辑结构} + \text{存储结构} + \text{数据运算} }
$$

这里的加号表示概念组成关系，并不是数学意义上的加法。

#### 第一要素：逻辑结构

逻辑结构描述数据元素之间的逻辑关系，与它们在内存中的具体地址无关。

通常分为四种。

| 逻辑结构 | 核心关系     | 典型代表     |
| ---- | -------- | -------- |
| 集合结构 | 元素同属一个集合 | 集合       |
| 线性结构 | 一对一      | 线性表、栈、队列 |
| 树形结构 | 一对多      | 树、二叉树    |
| 图结构  | 多对多      | 有向图、无向图  |

##### ① 集合结构

例如：

$$
A=\{1,3,5,7\}
$$

这些元素之间除了属于同一个集合，没有规定其他逻辑关系。

##### ② 线性结构

例如：

```text
A → B → C → D
```

在一个非空的普通线性表中：

- 第一个元素没有直接前驱。
- 最后一个元素没有直接后继。
- 其他元素各有唯一的直接前驱和直接后继。

所以这种结构体现一对一关系。

注意，一对一并不意味着所有元素都有前驱和后继，首尾元素是特殊情况。

##### ③ 树形结构

例如：

```text
          A
        /   \
       B     C
      / \
     D   E
```

父结点可以拥有多个孩子，体现一对多的层次关系。

##### ④ 图结构

例如：

```text
 A ───── B
 │ \     │
 │   \   │
 C ───── D
```

一个顶点可以与多个其他顶点关联，适合描述多对多的关系。

#### 非线性结构

逻辑结构可以从另一个角度分为：

$$
\text{逻辑结构} = \begin{cases} \text{线性结构}\\ \text{非线性结构} \end{cases}
$$

树和图都属于非线性结构。

重点：树和图不是存储结构，而是逻辑结构。

### 2.3 存储结构：数据在内存中如何表示？

逻辑结构描述元素之间是什么关系。

存储结构描述这些关系如何在计算机中实现。

408 中常见的存储结构有四类。

| 存储结构 | 基本思想          | 典型应用   |
| ---- | ------------- | ------ |
| 顺序存储 | 使用连续存储单元      | 数组、顺序表 |
| 链式存储 | 通过指针或链接信息表示关系 | 链表     |
| 索引存储 | 建立额外索引帮助定位    | 索引表    |
| 散列存储 | 根据关键字计算存储位置   | 散列表    |

#### （1）顺序存储

假设有四个数据元素：

```text
逻辑顺序：

A → B → C → D
```

如果采用顺序存储：

```text
地址      内容
1000       A
1004       B
1008       C
1012       D
```

如果每个元素占 4 字节，那么逻辑上相邻的元素在物理存储中也相邻。

顺序存储的重要特点是：

元素地址可以由首地址、元素下标和元素大小计算得到。

设第一个元素的地址为 $\operatorname{LOC}(a_1)$，每个元素占 $L$ 字节。

第 $i$ 个元素的地址为：

$$
\boxed{ \operatorname{LOC}(a_i) = \operatorname{LOC}(a_1)+(i-1)L }
$$

这就意味着，已知合法下标，可以直接访问指定元素。

时间复杂度为：

$$
\boxed{O(1)}
$$

这叫作随机访问。

但是，在普通顺序表中间插入或删除元素，通常需要移动大量元素。

因此其平均时间复杂度一般为：

$$
O(n)
$$

#### （2）链式存储

同样是四个元素：

```text
逻辑顺序：

A → B → C → D
```

链式存储可能如下：

```text
地址       数据      下一结点地址
1000        A          8000
8000        B          3000
3000        C          9000
9000        D          NULL
```

结点在物理地址上不必连续。

元素之间的逻辑关系主要通过指针表示。

例如，要找到第三个结点：

```text
头结点位置
    ↓
    A
    ↓
    B
    ↓
    C
```

对普通单链表而言，通常需要依次访问结点。

因此：

- 已知头指针，按位置查找第 $i$ 个元素，通常需要 $O(i)$ 时间。
- 已知待操作结点的适当指针信息，局部插入或删除可以达到 $O(1)$。
- 链式存储通常需要额外空间保存链接信息。

这里要特别注意：链表的插入和删除并不总是 $O(1)$。

如果必须先从头查找插入位置，那么查找过程本身可能需要 $O(n)$。

#### （3）索引存储

索引存储会建立额外的索引结构，利用索引来查找实际数据的位置。

比如书籍目录：

```text
索引
数据结构 → 第 15 页
操作系统 → 第 92 页
计算机网络 → 第 160 页
```

不需要每次都从第一页开始寻找。

但需要额外空间维护索引。

具体查找效率取决于索引的组织方式，不能笼统认定为 $O(1)$。

#### （4）散列存储

散列存储通过散列函数，将关键字映射到相应的存储位置。

例如：

$$
H(key)=key\bmod 10
$$

如果：

$$
key=123
$$

则：

$$
H(123)=3
$$

可将其映射到散列表中编号为 3 的位置。

散列表在合适的散列函数、装填因子和冲突处理策略下，平均查找复杂度可以接近：

$$
O(1)
$$

但是发生大量冲突时，查找效率可能下降。

所以不能认为散列表在任何情况下都一定是 $O(1)$。

### 2.4 高频辨析：逻辑结构与存储结构

这是第一章最容易考查的概念之一。

例如：

```text
                  线性表
                （逻辑结构）
                   /  \
                  /    \
               顺序表   链表
              （具体存储实现）
```

线性表描述的是元素之间的逻辑关系。

顺序表和链表则体现了这种逻辑关系的不同存储实现。

因此：

同一种逻辑结构可以采用不同的存储结构。

反过来，同一种存储方式也能够用于实现不同的逻辑结构。

例如，顺序存储既能用于实现线性表，也能在适当的下标映射规则下用于实现二叉树。

#### 易错判断题

| 判断                      | 对错 | 解释                   |
| ----------------------- | -- | -------------------- |
| 逻辑结构与存储位置无关             | 正确 | 逻辑结构是抽象关系            |
| 同一种逻辑结构只能有一种存储结构        | 错误 | 线性表可顺序存储或链式存储        |
| 链式存储要求结点地址连续            | 错误 | 结点地址不必连续             |
| 顺序存储支持按下标随机访问           | 正确 | 对普通定长元素顺序表成立         |
| 树形结构属于存储结构              | 错误 | 它属于逻辑结构              |
| 散列存储一定没有冲突              | 错误 | 不同关键字可能映射到相同地址       |
| 链表的所有插入操作都需要 $O(n)$ | 错误 | 已定位位置时可达到 $O(1)$ |
| 存储结构的选择会影响算法效率          | 正确 | 不同实现的操作代价可能不同        |

这里有一句非常重要的话：

> 算法的设计取决于逻辑结构，算法的实现依赖于存储结构。

它强调两个层次：

逻辑结构帮助确定应当完成什么操作，以及如何利用元素之间的关系；存储结构决定这些操作在内存中的具体实现方式和代价。

### 2.5 数据运算

数据运算是数据结构的第三个要素。

常见运算包括：

- 创建与销毁。
- 插入与删除。
- 查找与修改。
- 遍历与排序。

需要区分运算的定义和运算的实现。

例如，在线性表中插入一个新元素：

运算定义只需规定插入的位置、元素以及插入后的逻辑结果。

但具体实现取决于存储结构。

顺序表可能需要移动后续元素，而链表可能需要修改指针。

因此，同一个逻辑操作，在不同存储结构下，其复杂度可能不同。

### 2.6 数据类型与抽象数据类型 ADT

#### （1）数据类型

数据类型描述一个值的集合以及可以在这些值上进行的操作。

例如 C 语言中的 `int`：

它规定了可以表示的整数值，以及相应的算术运算、比较运算等。

所以，数据类型不只是一个取值集合，还包含操作语义。

#### （2）抽象数据类型 ADT

ADT 是 Abstract Data Type 的缩写。

它强调：

规定数据对象及其允许的操作，但不要求指定具体存储实现。

例如，定义一个栈：

```text
ADT Stack

数据对象：
    由若干同类型元素组成的序列

主要操作：
    InitStack()    初始化
    Push(x)        入栈
    Pop()          出栈
    GetTop()       读取栈顶
    StackEmpty()   判断是否为空
```

这个定义没有要求必须使用数组，也没有要求必须使用链表。

因此：

```text
            栈 ADT
              │
       ┌──────┴──────┐
       │             │
     顺序栈         链栈
       │             │
     数组实现       链表实现
```

ADT 强调接口与操作语义，具体存储实现强调如何完成这些操作。

#### 考研易错点

判断下面三个说法：

① ADT 必须规定元素的物理存储地址。

错误。ADT 不必规定存储实现。

② 同一个 ADT 可以有多种具体实现。

正确。例如顺序栈和链栈。

③ 数据类型和数据结构完全相同。

错误。二者密切相关，但关注的抽象层次和内容不同。

## 三、算法的基本概念

### 3.1 算法是什么？

算法是为解决特定问题而规定的一组有限、确定、可执行的步骤。

例如求：

$$
S=1+2+\cdots+n
$$

可以采用循环算法：

```c
int sum(int n) {
    int s = 0;

    for (int i = 1; i <= n; i++) {
        s += i;
    }

    return s;
}
```

也可以采用数学公式：

```c
int sum(int n) {
    return n * (n + 1) / 2;
}
```

两种算法解决相同的问题，但效率不同。

在通常的单位成本模型下，第一种算法为：

$$
T_1(n)=O(n)
$$

第二种算法为：

$$
T_2(n)=O(1)
$$

这也说明：解决同一个问题，可以采用不同算法，而不同算法的效率可能存在明显差异。

需要注意，实际 C 语言计算中还应考虑整数溢出；上述复杂度分析采用教材常见的固定成本算术模型。

### 3.2 算法的五个基本特性

这是必须掌握的概念考点。

| 基本特性 | 具体含义              |
| ---- | ----------------- |
| 有穷性  | 执行有限步骤后必须结束       |
| 确定性  | 每个步骤都有明确含义        |
| 可行性  | 每个操作可以通过有限次基本操作实现 |
| 输入   | 可以有零个或多个输入        |
| 输出   | 至少产生一个输出          |

#### 重点一：输入可以为零个

例如一个固定输出数字 100 的算法：

```c
int getNumber() {
    return 100;
}
```

不需要外部输入。

所以算法可以没有输入。

#### 重点二：输出至少有一个

根据教材采用的经典五特性定义，算法必须有输出。

输出不一定非要通过 `printf()` 打印，也可以是返回值、存储状态或其他可观察结果。

#### 重点三：算法必须有穷

例如：

```c
while (1) {
    printf("Hello");
}
```

这是可以持续运行的程序片段。

但它不符合经典算法定义中的有穷性要求。

因此，程序和算法不能完全画等号。

### 3.3 算法与程序的区别

算法是一种求解问题的步骤描述。

程序则是用某种程序设计语言对算法或其他计算行为的具体表达。

例如：

```text
求两个数的最大值
```

可以使用自然语言描述：

```text
比较 a 和 b
如果 a 较大，输出 a
否则输出 b
```

也可以写成 C 语言：

```c
int max(int a, int b) {
    return a > b ? a : b;
}
```

核心的求解逻辑是算法，而后者是程序实现。

经典教材中的重要区别：算法要求有穷，而程序可以被设计为持续运行。

### 3.4 好算法的评价指标

算法的五个基本特性，与评价一个算法是否优秀的指标，不是同一个概念。

常见评价指标包括：

| 评价指标   | 含义             |
| ------ | -------------- |
| 正确性    | 能够正确解决问题       |
| 可读性    | 逻辑清晰，易于理解维护    |
| 健壮性    | 能妥善处理异常情况和非法输入 |
| 高效率    | 尽可能节省执行时间      |
| 低存储量需求 | 尽可能节省空间        |

#### Fumadocs 模拟题：王道·卷一 Q01

题目： 下列选项中，不属于算法主要特征的是（ ）。

A. 有穷性

B. 可行性

C. 确定性

D. 可读性

答案：D。

解析：

有穷性、确定性、可行性属于算法的基本特性。

可读性属于评价算法质量的重要指标，但不是算法成立所必需的基本特性。

这一题真正考查的是：

$$
\boxed{ \text{算法的基本特性} \neq \text{好算法的评价指标} }
$$

以后遇到正确性、健壮性、可读性等选项，要特别注意题目究竟问的是“基本特性”还是“评价标准”。

**符号约定**

大 $O$ 表示渐近上界、$\Omega$ 表示渐近下界、$\Theta$ 表示同阶。当能精确确定主导增长阶时，优先推导 $\Theta$，再按题目要求选择 $O$ 选项。

## 四、时间复杂度：本章最重要的内容

这是整章的核心，也是后面学习线性表、树、图、查找和排序的基础。

### 4.1 什么是时间复杂度？

时间复杂度描述：

随着输入规模不断增大，算法执行的基本操作次数如何增长。

这里重点关注的是增长趋势，而不是程序实际运行了多少秒。

例如，两个算法的操作次数分别为：

$$
T_1(n)=5n+100
$$

$$
T_2(n)=2n^2+3n+1
$$

当 $n$ 不断增大时，第一个函数主要按照 $n$ 的数量级增长，第二个函数主要按照 $n^2$ 的数量级增长。

因此：

$$
T_1(n)=\Theta(n)
$$

$$
T_2(n)=\Theta(n^2)
$$

408 考试通常使用大 $O$ 记号表示复杂度。

所以一般写为：

$$
\boxed{O(n)}
$$

和

$$
\boxed{O(n^2)}
$$

#### 为什么不直接比较运行时间？

因为实际运行时间会受到多种因素影响，例如 CPU 性能、编译器优化、缓存、内存访问速度等。

复杂度主要衡量算法本身的渐近增长趋势。

不过，不能由此推断 $O(n)$ 算法在所有实际输入上一定比 $O(n^2)$ 算法快。对于很小的输入规模，常数因素仍然可能影响实际运行时间。

### 4.2 大 $O$、大 $\Omega$、大 $\Theta$ 的区别

这部分在教材中经常只简单介绍，但理解之后可以解决很多较难的复杂度题。

#### （1）大 $O$：渐近上界

若存在正常数 $c$ 和 $n_0$，使得对所有 $n\ge n_0$，有：

$$
0\le T(n)\le cf(n)
$$

则：

$$
T(n)=O(f(n))
$$

它表示函数增长速度最终不会超过 $f(n)$ 的某个常数倍。

例如：

$$
T(n)=3n^2+5n+7
$$

显然有：

$$
T(n)=O(n^2)
$$

但严格来说，也有：

$$
T(n)=O(n^3)
$$

因为 $n^3$ 同样可以作为它的上界。

所以，大 $O$ 并不一定表示最精确的数量级。

在考研选择题中，通常希望选择最紧的常见渐近上界。

#### （2）大 $\Omega$：渐近下界

如果存在正常数 $c$ 和 $n_0$，使得：

$$
T(n)\ge cf(n)
$$

则：

$$
T(n)=\Omega(f(n))
$$

例如：

$$
T(n)=3n^2+5n+7
$$

可以得到：

$$
T(n)=\Omega(n^2)
$$

#### （3）大 $\Theta$：渐近紧确界

若：

$$
T(n)=O(f(n))
$$

且：

$$
T(n)=\Omega(f(n))
$$

则：

$$
\boxed{T(n)=\Theta(f(n))}
$$

例如：

$$
3n^2+5n+7=\Theta(n^2)
$$

三个记号的关系：

| 记号                 | 含义    | 记忆方式    |
| ------------------ | ----- | ------- |
| $O(f(n))$      | 渐近上界  | 不会增长得更快 |
| $\Omega(f(n))$ | 渐近下界  | 不会增长得更慢 |
| $\Theta(f(n))$ | 渐近紧确界 | 增长速度同阶  |

考试建议： 分析出精确的主导数量级时，先在心里确认 $\Theta$ 结果，再按题目要求填写 $O$ 形式。

### 4.3 如何化简复杂度？

假设：

$$
T(n)=7n^3+20n^2+100n+800
$$

先忽略常数系数，再忽略低阶项。

当 $n$ 很大时，主要由最高次项决定。

因此：

$$
\boxed{T(n)=\Theta(n^3)}
$$

常见规则：

加法规则

如果两个程序段顺序执行：

$$
T(n)=T_1(n)+T_2(n)
$$

例如：

$$
T_1(n)=\Theta(n)
$$

$$
T_2(n)=\Theta(n^2)
$$

则：

$$
T(n)=\Theta(n+n^2)=\Theta(n^2)
$$

乘法规则

如果一个执行 $n$ 次的循环中，每次又执行一个独立的 $n$ 次循环：

$$
T(n)=n\times n=n^2
$$

于是：

$$
T(n)=\Theta(n^2)
$$

但是要注意，嵌套循环并不总能直接把各层最大循环次数相乘。如果内层循环次数依赖外层变量，必须进一步分析。

### 4.4 常见复杂度大小关系

按渐近增长速度，从慢到快排列：

$$
\boxed{ 1 \prec \log n \prec \sqrt n \prec n \prec n\log n \prec n^2 \prec n^3 \prec 2^n \prec n! }
$$

这里的 $\prec$ 表示前者的渐近增长速度低于后者。

| 复杂度              | 常见算法       |
| ---------------- | ---------- |
| $O(1)$       | 数组随机访问     |
| $O(\log n)$  | 二分查找       |
| $O(\sqrt n)$ | 枚举到平方根     |
| $O(n)$       | 顺序遍历       |
| $O(n\log n)$ | 归并排序       |
| $O(n^2)$     | 冒泡排序、选择排序  |
| $O(n^3)$     | 典型三层矩阵运算循环 |
| $O(2^n)$     | 枚举所有子集     |
| $O(n!)$      | 枚举所有排列     |

考研特别需要区分：

$$
O(\log n),\quad O(\sqrt n),\quad O(n),\quad O(n\log n),\quad O(n^2)
$$

因为第一章的循环分析题主要集中在这些数量级。

## 五、时间复杂度的七种核心计算模型

下面开始真正解决代码分析问题。

### 模型一：常数时间复杂度

观察：

```c
int fun(int n) {
    int a = 10;
    int b = 20;

    int c = a + b;

    return c;
}
```

虽然函数接收了参数 $n$，但执行的基本操作次数不随 $n$ 改变。

因此：

$$
\boxed{T(n)=O(1)}
$$

#### 易错点

$O(1)$ 不意味着只执行一次。

例如：

```c
for (int i = 0; i < 1000; i++) {
    sum++;
}
```

虽然执行了 1000 次，但 1000 是固定常数，与问题规模 $n$ 无关。

因此仍为：

$$
O(1)
$$

### 模型二：单层线性循环

```c
for (int i = 0; i < n; i++) {
    sum++;
}
```

循环执行 $n$ 次。

因此：

$$
T(n)=n
$$

得到：

$$
\boxed{O(n)}
$$

对于：

```c
for (int i = 0; i < n; i += 3) {
    sum++;
}
```

循环次数约为：

$$
\frac n3
$$

忽略常数系数后：

$$
\boxed{O(n)}
$$

基本规律：变量每次增加固定正常数，从常数规模增长到 $n$，一般需要线性次数。

### 模型三：倍增、倍减循环

这是 2011 年真题对应的高频模型。

#### 典型代码

```c
int i = 1;

while (i < n) {
    i *= 2;
}
```

不能因为出现 `while` 就认为复杂度是 $O(n)$。

观察变量变化：

```text
初始：1

第1次：2
第2次：4
第3次：8
第4次：16
第5次：32
......
```

假设循环执行 $k$ 次。

那么：

$$
i=2^k
$$

循环终止时：

$$
2^k\ge n
$$

两边取对数：

$$
k\ge\log_2 n
$$

所以循环次数为：

$$
k=\Theta(\log_2n)
$$

最终：

$$
\boxed{T(n)=O(\log n)}
$$

#### 为什么对数底数可以忽略？

根据换底公式：

$$
\log_a n=\frac{\log_b n}{\log_b a}
$$

其中：

$$
\frac{1}{\log_b a}
$$

是常数。

所以：

$$
\log_2n=\Theta(\log_3n)
$$

因此：

$$
O(\log_2n)=O(\log_3n)
$$

考试通常统一写：

$$
O(\log n)
$$

#### 倍减也是一样

```c
int i = n;

while (i > 1) {
    i /= 2;
}
```

变量变化：

$$
n,\frac n2,\frac n4,\frac n8,\ldots
$$

执行 $k$ 次之后：

$$
i\approx\frac{n}{2^k}
$$

令：

$$
\frac n{2^k}\approx1
$$

得到：

$$
2^k\approx n
$$

所以：

$$
k=\Theta(\log n)
$$

因此：

$$
\boxed{O(\log n)}
$$

### 模型四：平方根级复杂度

这是 2017、2019 年真题对应的核心模型。

#### 情况一：循环终止条件含平方

```c
int i = 0;

while (i * i < n) {
    i++;
}
```

假设执行 $k$ 次。

执行之后：

$$
i=k
$$

循环终止时：

$$
k^2\ge n
$$

因此：

$$
k\ge\sqrt n
$$

得到：

$$
\boxed{T(n)=O(\sqrt n)}
$$

这里最容易犯的错误是：

看到：

```c
i++;
```

就直接判断：

$$
O(n)
$$

这种判断是不正确的。

必须结合循环终止条件。

#### 情况二：累计自然数直到达到 $n$

```c
int i = 0;
int sum = 0;

while (sum < n) {
    i++;
    sum += i;
}
```

执行一次：

$$
sum=1
$$

执行两次：

$$
sum=1+2=3
$$

执行三次：

$$
sum=1+2+3=6
$$

执行 $k$ 次：

$$
sum=1+2+\cdots+k
$$

根据等差数列求和公式：

$$
sum=\frac{k(k+1)}2
$$

循环停止时：

$$
\frac{k(k+1)}2\ge n
$$

忽略低阶项：

$$
\frac{k^2}{2}\approx n
$$

得到：

$$
k\approx\sqrt{2n}
$$

所以：

$$
\boxed{T(n)=O(\sqrt n)}
$$

#### 本类题的通用方法

如果执行 $k$ 次之后，相关变量满足：

$$
k^p\approx n
$$

则：

$$
k\approx n^{1/p}
$$

例如：

$$
k^2\approx n \Rightarrow O(n^{1/2})
$$

$$
k^3\approx n \Rightarrow O(n^{1/3})
$$

这是一种非常有用的推广。

### 模型五：普通嵌套循环

#### 情况一：两层完整循环

```c
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        sum++;
    }
}
```

外层 $n$ 次。

内层每轮 $n$ 次。

因此：

$$
T(n)=n\times n=n^2
$$

所以：

$$
\boxed{O(n^2)}
$$

#### 情况二：内层次数依赖外层变量

```c
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= i; j++) {
        sum++;
    }
}
```

这时不能直接把两个循环的上限相乘。

当：

$$
i=1
$$

内层执行 1 次。

当：

$$
i=2
$$

内层执行 2 次。

当：

$$
i=3
$$

内层执行 3 次。

因此总次数：

$$
T(n)=1+2+3+\cdots+n
$$

根据求和公式：

$$
T(n)=\frac{n(n+1)}2
$$

展开：

$$
T(n)=\frac{n^2+n}{2}
$$

所以：

$$
\boxed{T(n)=\Theta(n^2)}
$$

虽然最终答案还是平方级，但本题应该通过求和得到，而不是直接机械相乘。

### 模型六：倍增循环与求和

这是整章非常重要的进阶模型。

考虑：

```c
int count = 0;

for (int i = 1; i < n; i *= 2) {
    for (int j = 0; j < i; j++) {
        count++;
    }
}
```

外层变量：

```text
1
2
4
8
16
......
```

外层执行：

$$
O(\log n)
$$

次。

但是，内层不是每次都执行 $n$ 次，而是随 $i$ 变化。

第一轮执行：

$$
1
$$

次。

第二轮执行：

$$
2
$$

次。

第三轮执行：

$$
4
$$

次。

因此总次数为：

$$
T(n)=1+2+4+\cdots+2^k
$$

其中 $2^k<n$，且下一项已经达到或超过 $n$。

根据等比数列求和公式：

$$
1+2+4+\cdots+2^k = 2^{k+1}-1
$$

而：

$$
2^k<n\le2^{k+1}
$$

可知：

$$
T(n)=\Theta(n)
$$

因此：

$$
\boxed{O(n)}
$$

#### 为什么不是 $O(n\log n)$？

因为不能将：

$$
\text{外层循环次数}
$$

直接乘以：

$$
\text{内层最大循环次数}
$$

然后就认定这是最紧的复杂度。

那样会得到一个偏松的上界：

$$
O(n\log n)
$$

实际上，内层只有最后几轮工作量较大，前面的工作量很少。

所以应该求和。

#### 和另一段代码对比

```c
for (int i = 1; i < n; i *= 2) {
    for (int j = 0; j < n; j++) {
        count++;
    }
}
```

这段代码中，内层每次固定执行 $n$ 次。

外层执行约 $\log_2n$ 次。

因此：

$$
T(n)=n\log_2n
$$

所以：

$$
\boxed{O(n\log n)}
$$

这两种代码只差一个内层循环条件，但复杂度不同。

| 内层循环条件  | 总工作量               | 时间复杂度            |
| ------- | ------------------ | ---------------- |
| `j < n` | $n+n+\cdots+n$ | $O(n\log n)$ |
| `j < i` | $1+2+4+\cdots$ | $O(n)$       |

这是本章必须彻底掌握的一组对比。

### 模型七：双指针与均摊分析

Fumadocs 的竟成模拟题考查了这一模型。

考虑以下程序片段：

```c
int left = 0;

for (int right = 0; right < n; right++) {

    while (left <= right && condition) {
        left++;
    }
}
```

第一眼看：

```text
for
 └── while
```

容易认为复杂度是：

$$
O(n^2)
$$

但这里有一个决定性的特点：

left 只会增加，不会减少。

外层变量 `right`：

$$
0\rightarrow1\rightarrow2\rightarrow\cdots\rightarrow n-1
$$

总共移动 $n$ 次。

内层变量 `left`：

$$
0\rightarrow1\rightarrow2\rightarrow\cdots
$$

最多也移动 $n$ 次。

因此：

$$
T(n)\le c_1n+c_2n+c_3
$$

于是：

$$
\boxed{T(n)=O(n)}
$$

这里使用的思想叫作均摊分析。

不能只考虑某一轮最坏执行多少次，而应当统计所有轮次中操作的累计次数。

#### 什么时候可以这样判断？

必须同时满足相应条件：

- 指针只朝一个方向移动。
- 不会反复回到起点。
- 每次移动的操作成本通常为常数。
- 每个指针累计移动次数可以控制在线性范围内。

如果内层指针每次外层循环都重新从头开始，那么复杂度就可能重新变成 $O(n^2)$。

## 六、历年 408 真题逐题精讲

以下按所引真题专题的题目顺序分析。

### 真题一：2011 年——倍增循环

题目： 设 $n$ 为描述问题规模的非负整数，求下列程序片段的时间复杂度。

```c
x = 2;

while (x < n / 2) {
    x = 2 * x;
}
```

选项：

A. $O(\log_2n)$

B. $O(n)$

C. $O(n\log_2n)$

D. $O(n^2)$

正确答案：A。

#### 详细推导

初始：

$$
x=2
$$

循环执行一次：

$$
x=4
$$

两次：

$$
x=8
$$

执行 $k$ 次：

$$
x=2^{k+1}
$$

循环停止条件：

$$
x\ge\frac n2
$$

代入：

$$
2^{k+1}\ge\frac n2
$$

两边乘以 2：

$$
2^{k+2}\ge n
$$

取对数：

$$
k+2\ge\log_2n
$$

所以：

$$
k=\Theta(\log n)
$$

最终：

$$
\boxed{O(\log n)}
$$

考点总结： 变量按固定倍数增长，通常转化成对数复杂度。

### 真题二：2012 年——递归求阶乘

题目： 求下列函数的时间复杂度。

```c
int fact(int n) {
    if (n <= 1)
        return 1;

    return n * fact(n - 1);
}
```

正确答案：$O(n)$。

#### 详细分析

当：

$$
n=5
$$

递归调用过程：

```text
fact(5)
  ↓
fact(4)
  ↓
fact(3)
  ↓
fact(2)
  ↓
fact(1)
```

每次参数减少 1。

设时间复杂度为 $T(n)$，则：

$$
T(n)=T(n-1)+O(1)
$$

继续展开：

$$
T(n)=T(n-2)+2O(1)
$$

$$
T(n)=T(n-3)+3O(1)
$$

直到基本情况：

$$
T(n)=T(1)+(n-1)O(1)
$$

因此：

$$
\boxed{T(n)=O(n)}
$$

#### 深入拓展：空间复杂度是多少？

递归过程中的函数调用需要保存活动记录。

最大递归深度与 $n$ 同阶。

因此：

$$
\boxed{S(n)=O(n)}
$$

这道题必须同时记住：

$$
\boxed{ T(n)=O(n),\qquad S(n)=O(n) }
$$

### 真题三：2014 年——对数循环嵌套线性循环

题目：

```c
count = 0;

for (k = 1; k <= n; k *= 2) {
    for (j = 1; j <= n; j++) {
        count++;
    }
}
```

正确答案：$O(n\log n)$。

<Steps>
<Step>

### 第一步：分析外层

变量：

$$
k=1,2,4,8,\ldots
$$

因此外层执行：

$$
\lfloor\log_2n\rfloor+1
$$

次。

</Step>
<Step>

### 第二步：分析内层

每次外层循环，内层执行：

$$
n
$$

次。

</Step>
<Step>

### 第三步：计算总次数

$$
T(n)=n(\lfloor\log_2n\rfloor+1)
$$

因此：

$$
\boxed{T(n)=\Theta(n\log n)}
$$

这里可以直接相乘，因为内层每次的执行次数都相同。

</Step>
</Steps>
### 真题四：2017 年——自然数累计求和

题目：

```c
int func(int n) {
    int i = 0;
    int sum = 0;

    while (sum < n) {
        sum += ++i;
    }

    return i;
}
```

正确答案：$O(\sqrt n)$。

#### 关键是建立累计量

执行 $k$ 次后：

$$
i=k
$$

同时：

$$
sum=1+2+\cdots+k
$$

所以：

$$
sum=\frac{k(k+1)}2
$$

停止时：

$$
\frac{k(k+1)}2\ge n
$$

当 $n$ 很大时：

$$
k^2\approx2n
$$

因此：

$$
k=\Theta(\sqrt n)
$$

得到：

$$
\boxed{O(\sqrt n)}
$$

最重要的启示：不要只看 `i++`，要分析真正决定循环停止的变量。

### 真题五：2019 年——平方条件

题目：

```c
x = 0;

while (n >= (x + 1) * (x + 1)) {
    x = x + 1;
}
```

正确答案：$O(\sqrt n)$。

循环条件：

$$
(x+1)^2\le n
$$

因此：

$$
x+1\le\sqrt n
$$

而 `x` 每次增加 1。

所以执行次数：

$$
k=\lfloor\sqrt n\rfloor
$$

得到：

$$
\boxed{O(\sqrt n)}
$$

#### 与 2017 年真题对比

2017 年：

$$
1+2+\cdots+k\approx n
$$

推出：

$$
k^2\approx n
$$

2019 年直接给出：

$$
k^2\approx n
$$

两道题的本质相同：

$$
\boxed{k=\Theta(\sqrt n)}
$$

因此建议把 2017 和 2019 年真题放在一起掌握。

### 真题六：2022 年——等比数列求和

题目：

```c
int sum = 0;

for (int i = 1; i < n; i *= 2) {
    for (int j = 0; j < i; j++) {
        sum++;
    }
}
```

正确答案：$O(n)$。

#### 分轮分析

外层变量：

$$
1,2,4,8,\ldots
$$

内层每轮分别执行：

$$
1,2,4,8,\ldots
$$

次。

因此：

$$
T(n)=1+2+4+\cdots+2^k
$$

其中：

$$
2^k<n\le2^{k+1}
$$

于是：

$$
T(n)=2^{k+1}-1
$$

而：

$$
n\le 2^{k+1}<2n
$$

因此：

$$
T(n)=\Theta(n)
$$

最终：

$$
\boxed{O(n)}
$$

#### 本题为什么重要？

它直接打破一种常见错误认识：

> 两层循环的复杂度一定是两层循环最大执行次数的乘积。

正确做法是：

$$
\boxed{ T(n)=\sum_{\text{每一轮}}\text{该轮实际工作量} }
$$

### 真题七：2023 年——顺序表的随机访问

题目： 对长度为 $n$ 的顺序存储有序表，下列哪个操作的平均时间复杂度为 $O(1)$？

A. 按指定值查找元素

B. 插入指定值的元素

C. 删除第 $i$ 个元素

D. 获取第 $i$ 个元素

正确答案：D。

#### 为什么获取第 $i$ 个元素是 $O(1)$？

因为顺序表采用连续存储。

第 $i$ 个元素地址：

$$
\operatorname{LOC}(a_i) = \operatorname{LOC}(a_1)+(i-1)L
$$

通过有限次地址计算即可直接定位。

所以：

$$
\boxed{O(1)}
$$

#### 为什么其他三个不对？

A：按值查找。

有序表可以使用二分查找，其最坏和通常的平均时间复杂度为：

$$
O(\log n)
$$

B：插入元素。

即使快速找到位置，仍可能移动大量元素。

平均：

$$
O(n)
$$

C：删除元素。

普通顺序表删除后通常需要移动后续元素。

平均：

$$
O(n)
$$

#### 必背结论

| 顺序表操作   | 典型复杂度           |
| ------- | --------------- |
| 按下标访问   | $O(1)$      |
| 按下标修改   | $O(1)$      |
| 无序表按值查找 | $O(n)$      |
| 有序表折半查找 | $O(\log n)$ |
| 中间插入    | $O(n)$      |
| 中间删除    | $O(n)$      |

这道题也为第二章线性表打下了基础。

## 七、空间复杂度：重点突破递归问题

### 7.1 空间复杂度是什么？

空间复杂度描述算法运行时所需空间随问题规模增长的数量级。

考研算法设计题一般更关注辅助空间复杂度。

也就是算法执行过程中除输入数据本身之外额外使用的空间。

常见情况：

| 使用情况                    | 辅助空间复杂度            |
| ----------------------- | ------------------ |
| 常数个局部变量                 | $O(1)$         |
| 额外开辟长度为 $n$ 的数组     | $O(n)$         |
| 额外开辟 $n\times n$ 数组 | $O(n^2)$       |
| 递归深度为 $n$           | 通常 $O(n)$      |
| 递归深度为 $\log n$      | 通常 $O(\log n)$ |

最后两项默认每层递归仅使用常数额外空间。

### 7.2 为什么递归空间不能直接数调用总次数？

这是重要区别。

观察：

```c
int fib(int n) {
    if (n <= 1)
        return n;

    return fib(n - 1) + fib(n - 2);
}
```

递归树会产生大量重复调用。

例如：

```text
               fib(5)
             /        \
         fib(4)       fib(3)
        /     \       /    \
     fib(3) fib(2) fib(2) fib(1)
      ...
```

其运行时间呈指数增长（经典递归实现为 $\Theta(\varphi^n)$，其中 $\varphi$ 是黄金比例）。

但是，递归执行时并不需要让整棵递归树的所有函数调用同时占据栈空间。

在通常的单线程顺序求值模型中，一个调用返回后，其活动记录会释放，才继续处理其他分支。

最大栈深度为：

$$
O(n)
$$

因此：

$$
\boxed{S(n)=O(n)}
$$

这就说明：

$$
\boxed{ \text{递归总调用次数} \neq \text{最大同时存在的递归栈帧数} }
$$

#### Fumadocs 模拟题：竟成·模拟二

原题对比了两个求斐波那契数的函数。

第一个使用普通递归：

```c
int f1(int n) {
    if (n == 1)
        return 1;

    if (n == 0)
        return 0;

    return f1(n - 1) + f1(n - 2);
}
```

第二个使用动态规划数组：

```c
int f2(int n) {
    int dp[n + 2];

    dp[0] = 0;
    dp[1] = 1;

    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }

    return dp[n];
}
```

问题：两个算法的空间复杂度分别是多少？

答案：

$$
\boxed{O(n),\quad O(n)}
$$

第一个由递归栈决定，第二个由辅助数组决定。

但它们的时间复杂度完全不同：

| 算法             | 时间复杂度      | 辅助空间复杂度    |
| -------------- | ---------- | ---------- |
| 普通递归 Fibonacci | 指数级        | $O(n)$ |
| 动态规划数组         | $O(n)$ | $O(n)$ |
| 迭代保存前两项        | $O(n)$ | $O(1)$ |

因此，一个算法可能占用相对较少的额外空间，却需要非常长的运行时间。

### 7.3 分治递归：时间和空间可能不一样

#### Fumadocs 模拟题：竟成·模拟七

```c
int fun(int *arr, int m, int n) {
    if (m == n)
        return 1;

    int mid = (m + n) / 2;

    return fun(arr, m, mid)
         + fun(arr, mid + 1, n);
}
```

假设初始区间长度为 $N=n-m+1$。

题目询问空间复杂度。

#### 第一步：分析递归深度

每次将区间大致分成两半。

区间长度变化：

$$
N,\frac N2,\frac N4,\frac N8,\ldots,1
$$

设经过 $k$ 次划分：

$$
\frac N{2^k}\approx1
$$

得到：

$$
k=\Theta(\log N)
$$

每层递归只保存常数数量的局部变量。

因此：

$$
\boxed{S(N)=O(\log N)}
$$

#### 第二步：拓展分析时间复杂度

虽然每层递归深度只有对数级，但每次调用会继续产生两个子问题。

所以：

$$
T(N)=2T(N/2)+O(1)
$$

递归树每层调用数近似为：

$$
1,2,4,8,\ldots,N
$$

总调用数：

$$
1+2+4+\cdots+N=\Theta(N)
$$

因此：

$$
\boxed{T(N)=O(N)}
$$

最终：

$$
\boxed{ T(N)=O(N),\qquad S(N)=O(\log N) }
$$

牢记：时间看整个递归树的工作量，空间看最大递归深度及每层额外空间。

## 八、递归时间复杂度的四种经典模型

这部分结合了 Fumadocs 的《递归算法的时间复杂度与快速幂》专题。

### 8.1 递归每次减一

```c
int fun(int n) {
    if (n <= 1)
        return 1;

    return fun(n - 1) + 1;
}
```

递推式：

$$
T(n)=T(n-1)+O(1)
$$

得到：

$$
\boxed{T(n)=O(n)}
$$

最大递归深度：

$$
\boxed{S(n)=O(n)}
$$

### 8.2 递归每次减半，只调用一次

```c
int fun(int n) {
    if (n <= 1)
        return 1;

    return fun(n / 2) + 1;
}
```

递推式：

$$
T(n)=T(n/2)+O(1)
$$

递归深度：

$$
\log_2n
$$

因此：

$$
\boxed{ T(n)=O(\log n),\quad S(n)=O(\log n) }
$$

### 8.3 递归每次减半，但调用两次

```c
int fun(int n) {
    if (n <= 1)
        return 1;

    return fun(n / 2) + fun(n / 2);
}
```

注意，它和上一道题只差一个递归调用。

递推式：

$$
T(n)=2T(n/2)+O(1)
$$

递归树每层结点数：

$$
1,2,4,\ldots,n
$$

总工作量：

$$
\Theta(n)
$$

因此：

$$
\boxed{ T(n)=O(n),\quad S(n)=O(\log n) }
$$

#### 为什么不是 $O(\log n)$ 时间？

虽然每个子问题的规模都减半，但每层会产生两个子问题。

必须将所有分支的工作量加起来。

### 8.4 两个一半规模的子问题，每层还需要线性工作

例如归并排序：

$$
T(n)=2T(n/2)+O(n)
$$

画出递归树。

第一层总工作量：

$$
n
$$

第二层两个子问题：

$$
\frac n2+\frac n2=n
$$

第三层四个子问题：

$$
4\times\frac n4=n
$$

每层总工作量都是：

$$
\Theta(n)
$$

树的高度约为：

$$
\log_2n
$$

因此：

$$
\boxed{T(n)=O(n\log n)}
$$

#### 四类递归速查

| 递推关系                    | 时间复杂度            |
| ----------------------- | ---------------- |
| $T(n)=T(n-1)+O(1)$  | $O(n)$       |
| $T(n)=T(n/2)+O(1)$  | $O(\log n)$  |
| $T(n)=2T(n/2)+O(1)$ | $O(n)$       |
| $T(n)=2T(n/2)+O(n)$ | $O(n\log n)$ |

这些是后续学习树、归并排序和分治算法时最重要的基础模型。

## 九、Fumadocs 模拟题重点精讲

除了前面已经讲过的算法特性、斐波那契和分治递归空间题，知识库里还有几道非常有代表性的题目。

### 模拟题一：王道·卷一 Q02

```c
for (i = 1; i <= n; i++) {
    for (j = 2 * i; j <= n; j++) {
        y += i * j;
    }
}
```

问时间复杂度。

选项：

A. $O(n)$

B. $O(n^2)$

C. $O(n\log n)$

D. $O(\log n)$

答案：B。

#### 解析

固定 $i$，内层从：

$$
j=2i
$$

开始。

当：

$$
2i>n
$$

内层不执行。

因此只有：

$$
i\le\lfloor n/2\rfloor
$$

时才有内层循环。

令：

$$
m=\lfloor n/2\rfloor
$$

则执行次数为：

$$
T(n)=\sum_{i=1}^{m}(n-2i+1)
$$

展开：

$$
T(n)=m(n+1)-2\sum_{i=1}^{m}i
$$

由于：

$$
\sum_{i=1}^{m}i=\frac{m(m+1)}2
$$

得到：

$$
T(n)=m(n+1)-m(m+1)
$$

即：

$$
T(n)=m(n-m)
$$

因为：

$$
m=\Theta(n)
$$

所以：

$$
\boxed{T(n)=\Theta(n^2)}
$$

### 模拟题二：王道·卷二 Q01

```c
int maxFunc(TreeNode *root) {
    if (root == NULL)
        return 0;

    return max(
        maxFunc(root->left),
        maxFunc(root->right)
    ) + 1;
}
```

设二叉树共有 $n$ 个结点，问时间复杂度。

答案：$O(n)$。

#### 解析

这段函数是在计算二叉树高度。

假设左右子树分别有：

$$
n_L,\quad n_R
$$

个结点。

则：

$$
n_L+n_R=n-1
$$

递推关系：

$$
T(n)=T(n_L)+T(n_R)+O(1)
$$

因为每个结点恰好访问一次。

所以：

$$
\boxed{T(n)=O(n)}
$$

#### 空间复杂度拓展

设二叉树高度为 $h$。

递归最大深度为 $h$。

因此：

$$
\boxed{S(n)=O(h)}
$$

如果树近似平衡：

$$
h=O(\log n)
$$

如果退化成链：

$$
h=O(n)
$$

所以，树的具体形状会影响递归空间。

### 模拟题三：王道·卷三 Q01

```c
i = 2;

while (i < n / 3) {
    i = i * 3;
}
```

答案：$O(\log n)$。

执行 $k$ 次之后：

$$
i=2\times3^k
$$

终止时：

$$
2\times3^k\ge\frac n3
$$

因此：

$$
3^k\ge\frac n6
$$

取对数：

$$
k\ge\log_3(n/6)
$$

所以：

$$
\boxed{O(\log n)}
$$

重点在于：

每次乘 2 和每次乘 3 的渐近复杂度相同。

### 模拟题四：王道·卷四 Q01

```c
i = n * n;

while (i != 1) {
    i = i / 2;
}
```

假设 $n$ 为正整数，并按正整数除法计算。

答案：$O(\log n)$。

初始值：

$$
i=n^2
$$

每次除以 2。

循环次数约为：

$$
k=\log_2(n^2)
$$

利用对数性质：

$$
\log_2(n^2)=2\log_2n
$$

忽略常数 2：

$$
\boxed{O(\log n)}
$$

#### 一个严谨性问题

如果允许 $n=0$，则代码中 `i` 初值为 0，之后一直为 0，循环无法结束。

因此，分析这道题时必须明确 $n\ge1$。

这是算法复杂度题中经常被忽略的输入合法性问题。

### 模拟题五：竟成·模拟五

```c
int sum = 0;

for (int i = 2; i <= n; i *= i) {
    for (int j = 1; j <= i; j++) {
        sum++;
    }
}
```

题库给出的选项答案为：

$$
\boxed{O(n)}
$$

#### 第一层分析

外层变量依次为：

$$
2,4,16,256,65536,\ldots
$$

其增长速度非常快。

设：

$$
i_k=2^{2^k}
$$

则满足：

$$
i_k\le n
$$

时：

$$
2^k\le\log_2n
$$

所以：

$$
k=O(\log\log n)
$$

也就是说外层循环只有双对数级的轮数。

#### 第二层分析

但每轮内层执行 $i_k$ 次。

因此总工作量：

$$
T(n)=2+4+16+256+\cdots+i_{\max}
$$

由于这一序列增长极快，总和由最后一项主导：

$$
T(n)=\Theta(i_{\max})
$$

并且：

$$
i_{\max}\le n
$$

因此：

$$
T(n)=O(n)
$$

#### 重要补充

这道题有一个特殊之处：

对于任意 $n$，最后一个 $i_{\max}$ 不一定与 $n$ 同阶。

因此，不能无条件写成：

$$
T(n)=\Theta(n)
$$

但题库选择的：

$$
O(n)
$$

确实是一个有效的渐近上界。

另外，这类包含 `i *= i` 的代码如果严格按照固定宽度 C 整数执行，还需要考虑乘法溢出；教材通常是在理想化整数模型下分析增长规律。

## 十、算法大题专项训练

原资料库未单独收录本章的历年算法大题，以下三题明确为**自拟综合训练题**。

它们不是历年 408 原题，但训练的方法会直接应用到后续真正的算法设计大题中。

### 综合大题一：多层循环混合复杂度

#### 题目

分析下列程序的时间复杂度与辅助空间复杂度。

```c
void fun(int n) {
    int count = 0;

    for (int i = 1; i <= n; i *= 2) {

        for (int j = 0; j < i; j++) {
            count++;
        }

        for (int k = 0; k < n; k++) {
            count++;
        }
    }
}
```

#### 详细解析

这一题综合了 2014 和 2022 年真题的方法。

第一部分：分析第一个内层循环。

外层：

$$
i=1,2,4,8,\ldots
$$

第一个内层循环每轮执行：

$$
i
$$

次。

所以：

$$
T_1(n)=1+2+4+\cdots
$$

最后一项不超过 $n$。

因此：

$$
\boxed{T_1(n)=O(n)}
$$

第二部分：分析第二个内层循环。

第二个内层循环每次固定执行：

$$
n
$$

次。

外层约执行：

$$
\log_2n
$$

次。

因此：

$$
\boxed{T_2(n)=O(n\log n)}
$$

第三部分：合并。

$$
T(n)=T_1(n)+T_2(n)
$$

所以：

$$
T(n)=O(n)+O(n\log n)
$$

保留主导项：

$$
\boxed{T(n)=O(n\log n)}
$$

第四部分：分析空间。

程序仅使用 `count`、`i`、`j`、`k` 等常数个局部变量，没有随着 $n$ 增大而额外分配数组或递归栈。

所以：

$$
\boxed{S(n)=O(1)}
$$

#### 最终答案

$$
\boxed{ T(n)=O(n\log n) }
$$

$$
\boxed{ S(n)=O(1) }
$$

#### 命题陷阱

如果只观察第一个内层循环，很容易错误地写成 $O(n)$。

如果只看代码中存在多个循环，也可能错误地写成 $O(n^2)$。

正确方法是分别计算每部分的总操作次数，然后合并。

### 综合大题二：设计原地逆置算法

#### 题目

给定长度为 $n$ 的顺序表，设计一个算法将其逆置，要求：

$$
T(n)=O(n)
$$

$$
S(n)=O(1)
$$

给出算法、复杂度分析，并说明正确性。

<Steps>
<Step>

### 第一步：理解问题

例如原数组：

```text
1 2 3 4 5 6
```

逆置后：

```text
6 5 4 3 2 1
```

一种不够理想的方法是额外申请数组保存逆序结果。

但是这样需要：

$$
O(n)
$$

辅助空间。

题目要求：

$$
O(1)
$$

所以应该直接在原数组中交换元素。

</Step>
<Step>

### 第二步：设计双指针

设置：

```text
left  指向数组开头

right 指向数组末尾
```

每次交换两端元素。

例如：

```text
原始：

1 2 3 4 5 6
↑         ↑
L         R
```

第一次交换：

```text
6 2 3 4 5 1
  ↑     ↑
  L     R
```

第二次交换：

```text
6 5 3 4 2 1
    ↑ ↑
    L R
```

第三次交换：

```text
6 5 4 3 2 1
```

完成。

</Step>
<Step>

### 第三步：C 语言实现

```c
void Reverse(int A[], int n) {
    int left = 0;
    int right = n - 1;

    while (left < right) {
        int temp = A[left];

        A[left] = A[right];
        A[right] = temp;

        left++;
        right--;
    }
}
```

</Step>
<Step>

### 第四步：分析时间复杂度

每次交换一对元素。

总交换次数：

$$
\left\lfloor\frac n2\right\rfloor
$$

每次交换执行常数次基本操作。

所以：

$$
T(n)=\Theta(n)
$$

因此：

$$
\boxed{O(n)}
$$

</Step>
<Step>

### 第五步：分析空间复杂度

额外使用：

```text
left
right
temp
```

这些变量数量固定。

因此：

$$
\boxed{S(n)=O(1)}
$$

</Step>
<Step>

### 第六步：算法正确性说明

可以使用循环不变式。

循环不变式： 每次循环开始时，`left` 左侧和 `right` 右侧的元素已经处于正确的逆置位置。

初始化时，两端尚无已处理元素，因此不变式成立。

每轮交换 `A[left]` 与 `A[right]`，使这一对元素到达正确的逆置位置，然后左右指针向中间移动，不变式继续成立。

循环结束时：

$$
left\ge right
$$

所有需要交换的元素对均已处理，数组完成逆置。

</Step>
</Steps>
#### 完整结论

$$
\boxed{ \text{时间复杂度 }O(n) }
$$

$$
\boxed{ \text{辅助空间复杂度 }O(1) }
$$

这道题非常值得掌握，因为它训练了后续 408 算法设计题最重要的三个能力：设计正确算法、分析时间复杂度、分析辅助空间复杂度。

### 综合大题三：两种递归快速幂的复杂度差异

#### 题目

分析下列两种递归算法的时间复杂度与空间复杂度，并说明如何优化。

算法 A：

```c
long long powerA(long long x, int n) {
    if (n == 0)
        return 1;

    if (n == 1)
        return x;

    long long a = powerA(x, n / 2);
    long long b = powerA(x, n / 2);

    if (n % 2 == 0)
        return a * b;

    return a * b * x;
}
```

算法 B：

```c
long long powerB(long long x, int n) {
    if (n == 0)
        return 1;

    if (n == 1)
        return x;

    long long half = powerB(x, n / 2);

    if (n % 2 == 0)
        return half * half;

    return half * half * x;
}
```

假设 $n\ge0$，并使用固定成本算术模型。

#### 第一问：分析算法 A

观察：

```text
powerA(x, n / 2);
powerA(x, n / 2);
```

这意味着每一层会产生两个规模约为原来一半的递归调用。

因此：

$$
T_A(n)=2T_A(n/2)+O(1)
$$

递归树总调用次数：

$$
1+2+4+\cdots+n=\Theta(n)
$$

所以：

$$
\boxed{T_A(n)=O(n)}
$$

虽然调用总数为线性数量级，但最大递归深度为：

$$
O(\log n)
$$

所以：

$$
\boxed{S_A(n)=O(\log n)}
$$

#### 第二问：分析算法 B

算法 B 只进行一次递归：

```c
long long half = powerB(x, n / 2);
```

然后重复使用 `half`。

于是递推式变为：

$$
T_B(n)=T_B(n/2)+O(1)
$$

所以：

$$
\boxed{T_B(n)=O(\log n)}
$$

空间仍由递归深度决定：

$$
\boxed{S_B(n)=O(\log n)}
$$

#### 第三问：为什么 B 更快？

因为 A 重复计算了完全相同的子问题。

B 只计算一次，再复用计算结果。

这使时间复杂度从：

$$
O(n)
$$

优化成：

$$
O(\log n)
$$

#### 第四问：进一步优化空间

如果改用迭代快速幂：

```c
long long fastPower(long long x, int n) {
    long long ans = 1;

    while (n > 0) {
        if (n % 2 == 1)
            ans *= x;

        x *= x;
        n /= 2;
    }

    return ans;
}
```

每次将 $n$ 缩小一半。

所以：

$$
T(n)=O(\log n)
$$

只使用常数数量变量。

因此：

$$
S(n)=O(1)
$$

#### 三种算法对比

| 算法       | 时间复杂度           | 辅助空间复杂度         |
| -------- | --------------- | --------------- |
| A：重复递归   | $O(n)$      | $O(\log n)$ |
| B：复用递归结果 | $O(\log n)$ | $O(\log n)$ |
| C：迭代快速幂  | $O(\log n)$ | $O(1)$      |

这道题表明：

算法优化不仅可以减少执行时间，也可以通过消除递归调用降低辅助空间。

## 十一、补充三种容易漏掉的进阶考法

### 11.1 调和级数型循环

考虑：

```c
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= n; j += i) {
        count++;
    }
}
```

固定 $i$，内层执行次数约为：

$$
\frac ni
$$

所以：

$$
T(n)\approx \sum_{i=1}^{n}\frac ni
$$

提出 $n$：

$$
T(n)\approx n\sum_{i=1}^{n}\frac1i
$$

其中：

$$
H_n=\sum_{i=1}^{n}\frac1i
$$

称为调和级数。

它满足：

$$
H_n=\Theta(\log n)
$$

所以：

$$
\boxed{T(n)=\Theta(n\log n)}
$$

这里的关键不是循环层数，而是内层循环步长会随着 $i$ 改变。

### 11.2 外层平方根、内层递增

这是外层平方根级、内层随外层递增的典型组合模型。

```c
for (int i = 0; i * i < n; i++) {
    for (int j = 0; j < i; j++) {
        count++;
    }
}
```

外层执行约：

$$
\sqrt n
$$

次。

但内层次数不是 $n$，而是：

$$
0,1,2,\ldots,\sqrt n-1
$$

因此：

$$
T(n) = 0+1+2+\cdots+(\sqrt n-1)
$$

根据等差数列求和：

$$
T(n)=\Theta((\sqrt n)^2)
$$

于是：

$$
\boxed{T(n)=\Theta(n)}
$$

这类题一定要先算外层次数，再对每轮内层工作量求和。

### 11.3 多变量复杂度

如果题目中有两个独立规模 $m,n$，不要无依据地把它们都替换为 $n$。

例如：

```c
for (int i = 0; i < m; i++) {
    for (int j = 0; j < n; j++) {
        count++;
    }
}
```

总次数：

$$
m\times n
$$

因此：

$$
\boxed{O(mn)}
$$

不能直接写成：

$$
O(n^2)
$$

除非题目明确说明：

$$
m=\Theta(n)
$$

这种思想后面分析图算法时尤其重要，因为图中常常需要分别考虑顶点数 $V$ 和边数 $E$。

## 十三、本章最容易犯的十个错误

| 易错认识                                        | 正确理解                    |
| ------------------------------------------- | ----------------------- |
| 两层循环一定是 $O(n^2)$                        | 应统计全部轮次的实际工作量           |
| 变量 `i++` 就一定是 $O(n)$                    | 还必须分析终止条件               |
| 变量每次除以 2，整个递归就一定是 $O(\log n)$           | 还需考虑递归分支数量              |
| 递归调用很多，空间复杂度就很大                             | 空间通常看最大同时存在的栈帧          |
| 二叉树高度是 $O(\log n)$，遍历也是 $O(\log n)$ | 遍历全部结点通常是 $O(n)$    |
| $O(1)$ 代表只执行一次                          | 代表执行次数不随规模增长            |
| $O(n)$ 在所有情况下都比 $O(n^2)$ 快          | 渐近复杂度不能完全决定实际耗时         |
| 链表插入和删除永远是 $O(1)$                       | 查找操作位置可能需要 $O(n)$   |
| 顺序表中间插入只需要 $O(1)$                       | 通常需要移动元素，平均为 $O(n)$ |
| 算法与程序完全等价                                   | 算法强调有穷性，程序可以持续执行        |

另外还需要记住一个更细的区别：

最好情况、平均情况、最坏情况与均摊复杂度不是同一个概念。

例如，在无序顺序表中按值查找：

最好情况下，第一个元素就命中：

$$
T_{\text{best}}(n)=\Theta(1)
$$

最坏情况下，需要检查全部 $n$ 个元素：

$$
T_{\text{worst}}(n)=\Theta(n)
$$

如果假设目标元素等概率位于任一位置，那么成功查找的平均比较次数为：

$$
\frac{1+2+\cdots+n}{n} = \frac{n+1}{2}
$$

因此：

$$
T_{\text{avg}}(n)=\Theta(n)
$$

而均摊复杂度研究的是一系列操作的总成本如何分配到每次操作上，不等同于对随机输入求期望的平均复杂度。

例如动态数组按容量翻倍扩容时，单次扩容可能需要 $O(n)$ 时间，但连续进行 $n$ 次尾部插入的总成本可以是 $O(n)$，因此每次插入的均摊成本为 $O(1)$。

## 十四、考研 408 时间复杂度万能分析法

面对陌生代码时，可以按照下面六步进行。

<Steps>
<Step>

### 第一步：确定问题规模

首先明确 $n$ 是什么。

是数组长度、结点数量，还是其他输入规模？

如果包含多个独立输入规模，必须分别考虑。

</Step>
<Step>

### 第二步：确定主要操作

重点找循环体、递归调用以及其他重复执行的操作。

比如：

```c
count++;
```

如果能准确求出它的总执行次数，往往就能得到程序的主导复杂度。

</Step>
<Step>

### 第三步：分析循环变量变化

常见变化模型：

| 变化方式            | 数学模型                     |
| --------------- | ------------------------ |
| `i++`           | $i_k=i_0+k$          |
| `i += c`        | $i_k=i_0+kc$         |
| `i *= c`        | $i_k=i_0c^k$         |
| `i /= c`        | $i_k\approx i_0/c^k$ |
| `sum += i`      | $sum=\Theta(k^2)$    |
| `i *= i`，从 2 开始 | $i_k=2^{2^k}$        |

</Step>
<Step>

### 第四步：利用终止条件求次数

例如：

$$
2^k\approx n
$$

得到：

$$
k=\Theta(\log n)
$$

如果：

$$
k^2\approx n
$$

得到：

$$
k=\Theta(\sqrt n)
$$

如果：

$$
k^3\approx n
$$

得到：

$$
k=\Theta(n^{1/3})
$$

</Step>
<Step>

### 第五步：存在嵌套时分析总工作量

不能只看外层有多少次、内层最多有多少次。

应当计算：

$$
\boxed{ T(n)= \sum_{i} \text{第 }i\text{ 轮的实际工作量} }
$$

如果内层每轮都是 $n$ 次，可直接乘法。

如果内层次数为：

$$
1,2,4,8,\ldots
$$

就应采用等比数列求和。

如果内层次数为：

$$
1,2,3,\ldots,n
$$

就应采用等差数列求和。

</Step>
<Step>

### 第六步：递归必须同时分析时间与空间

递归时间关注整棵递归调用树。

递归空间关注最大调用深度，以及每层额外使用的存储量。

最终得到：

$$
\boxed{ \begin{aligned} T(n)&=\text{总工作量的增长阶}\\ S(n)&=\text{最大辅助空间的增长阶} \end{aligned} }
$$

这套方法比单纯背诵复杂度表更可靠。

</Step>
</Steps>

## 十六、本章如何复习到能够稳定做题？

建议分成三个层次。

第一层：准确掌握概念。

能够清晰区分数据元素、数据项、数据对象、逻辑结构、存储结构和 ADT。

能够准确说出算法五个基本特性，以及算法评价指标。

这部分不需要死记非常长的定义，但必须能够排除错误选项。

第二层：独立推导复杂度。

至少要能够不参考答案，重新推导：

- 2011 年：倍增循环为什么是 $O(\log n)$。
- 2017、2019 年：平方根级复杂度从哪里来。
- 2014、2022 年：为什么相似的嵌套循环分别是 $O(n\log n)$ 和 $O(n)$。
- 普通递归与分治递归：为什么时间和空间可能不同。

第三层：能够完成综合算法分析。

对于一段陌生程序，能够说明：

输入规模是什么，哪些操作决定时间成本，各层循环如何累计，递归深度是多少，辅助空间由哪些变量或数据结构组成。

能够将这一套方法应用到线性表、树和排序的算法设计题中。

这才是第一章真正的学习目标。

## 最终总结：这一章最重要的五句话

第一，数据结构的三要素是逻辑结构、存储结构和数据运算。 逻辑结构说明元素之间的关系，存储结构说明这些关系如何在计算机中实现。

第二，算法必须满足有穷性、确定性、可行性、输入和输出五个基本特性。 可读性、健壮性等是评价好算法的重要指标。

第三，时间复杂度的核心是基本操作总次数的增长阶。 不要单纯根据代码行数或循环层数判断。

第四，嵌套循环最重要的方法是求和，递归最重要的方法是建立递推式或分析递归树。 这是第一章历年真题的核心解法。

第五，时间复杂度和空间复杂度必须分别分析。 递归的时间通常由所有调用的总工作量决定，而递归栈空间通常由最大同时存在的调用深度与每层空间决定。

掌握本章的标准，不是能背出 $O(n)$、$O(\log n)$、$O(n^2)$，而是面对一段从未见过的程序，能够独立建立数学关系、推导执行次数、写出复杂度，并解释为什么其他答案不对。

尤其要彻底吃透 2014 年与 2022 年两道真题的对比，以及递归中“调用总次数”和“最大栈深度”的区别。 这两组知识不仅是本章的重点，也是后续整个数据结构算法分析体系的基础。
